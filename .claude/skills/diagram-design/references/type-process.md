# Process

> 上流 cathrynlavery/diagram-design (MIT) を教材向けに改変。上流はパラメトリックなYAML入力+座標計算式による生成を前提にしていたが、教材では viewBox の幅 `1200` 固定(高さは400/480/560/640の4択)・複雑度上限(ノード6/矢印8)の制約が強いため、レイアウト規約だけを抜き出している。

**Best for:** 一連の工程・変換を順番に見せたいとき。「入力 → 処理 → 出力」のように、値やコードが段階を経て変わっていく流れ。教材で `process` を割り当てる図の大半はこの形(直線パイプライン)。

## Layout conventions(主パターン: 直線パイプライン)
- 1本の水平(または垂直)の流れに、3〜5個のノードを並べる。レーン分けは不要。
- ノードは角丸長方形(`rx=12`)。node-name role(Noto Sans JP)の名前 + sublabel role(Geist Mono、muted)の補足(ファイル名・コマンド名など)。
- 矢印はノード間を直線または単一ベンドの直角ルーティングで結ぶ(斜めは禁止)。ノードより先に矢印を描画する(z-order)。
- 複数の入力ノードが1つのノードへ合流する(fan-in)構成も許容する。矢印は各入力から合流先へ個別に引く。
- accent の対象は**1つのノード、または1つの区間(注目させたい変換)**だけ。それ以外の矢印は無ラベル・muted。強調したい対象が1行のテキスト断片(構文の一部など)であれば、ノードを増やさずその部分だけ `<tspan>` で accent 色にしてよい。

## バリアント: スイムレーン
複数の担当者/部門にまたがる業務プロセスで、「誰が」「何を」「どのツールで」行うかを見せたいときだけ使う。横方向のスイムレーン(担当者/部門、上から下)× 縦方向のステップ(工程、左から右)のグリッドにする。各セルは1ノードまたは空(空セルは何も描画しない)。レーンラベルは左端に eyebrow role(Figtree)で並べる。矢印の規約は主パターンと同じ。

データ型やツールが重要でないなら swimlane は使わない(直線パイプラインで足りる)。

## 複雑度上限
**ノード6・矢印8・accent1**。スイムレーンで使う場合も、レーン×ステップの合計セル数にこの上限をそのまま適用する。超えたらトピックを割る。

## Anti-patterns
- 空セルにプレースホルダの箱やテキストを置く(スイムレーン利用時)。
- accent を2つ以上のステップ・ノード・矢印に使う。
- 斜めの矢印。
- すべての矢印を同じスタイルにする(トリガーとデータの受け渡しを区別できない)。
