# Data Flow

> 上流 cathrynlavery/diagram-design (MIT) を教材向けに改変。上流はパラメトリックなYAML入力+座標計算式による生成を前提にしていたが、教材では viewBox の幅 `1200` 固定(高さは400/480/560/640の4択)・複雑度上限(ノード6/矢印8)の制約が強いため、レイアウト規約だけを抜き出している。

**Best for:** データがどの役割(担当者/チーム)を経由して流れるかを見せる — 誰が起点で、誰が処理し、誰が公開・利用するか。役割をまたぐデータパイプラインの図解。

Cross-functional business process(承認フローなど)には process タイプを使う。データ型付きペイロード(生ファイル・テーブル・レポート)が役割をまたいで変換されていく様子を見せたいときに data-flow を使う。

## Layout conventions
- 横方向のスイムレーン(役割、上から下)× 縦方向のステップ(工程、左から右)のグリッド。
- 各セルは1ノードまたは空(空セルは何も描画しない — プレースホルダの箱は置かない)。
- ノードは角丸長方形(`rx=12`)。node-name role(Noto Sans JP)の名前 + sublabel role(Geist Mono、muted)の補足。
- レーンラベルは左端に eyebrow role(Figtree)で縦に並べる。
- 矢印は単一ベンドの直角ルーティング(右辺から出て、上辺または下辺から入る。斜めは禁止)。ノードより先に矢印を描画する(z-order)。
- accent の対象は**1つのノード + そこに入る1本の矢印**だけ(役割をまたぐ最重要のハンドオフ)。矢印にはラベルを付けてよい(paperのマスク付き)。それ以外の矢印は無ラベル・muted。

## 複雑度上限
上流のレーン4×ステップ6という枠は本計画のノード6/矢印8を超えるため使わない。**ノード6・矢印8・accent1**の全体上限を、そのままレーン×ステップの合計セル数に適用する。超えたらトピックを割る。

## Anti-patterns
- 空セルにプレースホルダの箱やテキストを置く。
- accent を2つ以上のノード・矢印に使う。
- 斜めの矢印。
- レーンラベルに node-name role を使う(識別子なのでeyebrow role)。
