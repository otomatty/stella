# 対話の解説動画の絵コンテ (storyboard.json) の書き方

章の要点を「先輩と後輩の掛け合い」と「画面中央の図解ボード」で理解する動画の台本。
朗読の音声 (md-audiobook) が本文の全部を読むので、動画は要点を図で理解することに集中する。

## 目次
1. 役割と分量
2. 構成
3. 話し言葉のルール
4. ボードの選び方
5. JSON の形
6. 見本 (1 場面)
7. 書いたあとの確認

## 1. 役割と分量

| 話者 | 役割 | 声 | 既定の style |
|---|---|---|---|
| 先輩 | 内容を理解していて解説する。たとえ話が得意 | Charon | 落ち着いて、わかりやすく |
| 後輩 | 聞き手。素朴な疑問を挟み、要点を言い直す | Aoede | 明るく、興味を持って |

- 長さは原文の文字数の **25〜35%** が目安 (日本語の読み上げはおよそ毎分 400〜450 字)。
  1 章 5〜10 分、長くても 15 分。利用者の指定 (「5 分で」など) があればそれを優先する。
- 1 行は **72 字まで**。字幕が 3 段に収まる長さで、超えると画面からあふれる。
  先輩の長い説明は、同じ話者の行を続けて分ける (行ごとに音声を作るので、分けても不自然にならない)。

## 2. 構成

1. **イントロ** (`title` ボード、4 行前後)：後輩が本の名前と章を紹介し、素朴な疑問を 1 つ。
   先輩が「この章で何がわかるか」を一言で答え、ボードの要点タグを出す。
2. **本編**：原文の節ごとに 1 場面 (長い節は 2 場面)。`section` は原文の節の見出しをそのまま書く
   (画面右上に出る)。節の中は「要点 → 理由・仕組み → 具体例」の順。
3. **まとめ** (`summary` ボード)：後輩が要点を 3 つ程度で言い直し、先輩が「実践に移す」こと
   (原文にあれば) を一言添える。

## 3. 話し言葉のルール

md-audiobook の `references/dialogue_guide.md` と同じ。特に次を守る。

- **原文にない事実・数値・固有名詞を足さない。** たとえ話は「たとえるなら」と明示する。
  原文の主張・注意・警告は落とさない。曖昧なところは「本では〜と書いてある」と引用調にする。
- 原文の用語をそのまま使う (言い換えるなら最初に原文の用語も添える)。
- コード・記号・URL は読まない。何をするコードかを言葉で説明する。`/`・`->`・括弧などは文章に直す。
- 数字には助数詞を付ける (「600時間」「3つ」)。略語は初出で読み方を添える (「SDLC、つまり…」)。
- **テキストに演技指示 (「（笑いながら）」) やタグ (`<short pause>` など) を書かない。** そのまま読み上げられる。
  演技は行の `style` に短く書く (「少し笑いながら」「驚いたように」)。
- 相づちは 1 分に 1〜2 回まで。指示語 (これ・それ) が何を指すか、耳だけでわかるようにする。

## 4. ボードの選び方

ボードは場面ごとに 1 枚。画面は 1680×654 の白い板で、項目はセリフに合わせて現れる。
文字が多いと読めないので、項目は**名詞句で短く**書く (文章にしない)。

| type | 使うとき | 項目 | 項目の長さの目安 |
|---|---|---|---|
| `title` | イントロ | `items`: 要点のタグ 4 まで | 1 つ 16 字まで |
| `cards` | 並列の要点 (2×2) | `items`: `{head, body}` 4 まで | head 14 字・body 26 字まで |
| `compare` | 2〜3 者の比較 | `columns` 3 まで・`rows`: `{label, cells}` 3 まで | セル 30 字まで |
| `flow` (横) | 段階・時間の流れ | `items`: `{label, note}` 4〜5 まで | label 8 字・note 14 字まで |
| `flow` (`direction: "down"`) | 因果の連鎖 (5 つのなぜなど) | `items`: `{label}` 6 まで | 20 字まで |
| `quote` | 原文の引用句と、それを示す出来事 | `quote`・`by`・`items` 3 まで | quote 40 字・item 30 字まで |
| `summary` | まとめ | `items` 5 まで | 1 つ 30 字まで |

- `title`・`cards`・`compare`・`flow`・`summary` には `title` (ボードの見出し) を付ける。
  最初の項目が出るまで見出しが中央に大きく出るので、問いの形 (「呼び方の違い」) が向いている。
- **`show`** は、その項目に初めて触れる行に付ける。場面の最初の 1〜2 行は付けない (見出しだけの間を作る)。
  出す順番は自由 (例：本番 → テスト → 開発 → 設計 と逆にたどる)。全部の項目を 1 回は出す。
  `compare` の `show` は列の番号、それ以外は `items` の番号。1 行で複数出すなら配列にする。
- 本の図版は切り貼りしない。必要なら要点を上の型で描き直す。実写風の映像は使わない。

## 5. JSON の形

```json
{
  "format": "stella-storyboard",
  "version": 1,
  "book": "本の題名",
  "chapter": { "id": "ch01", "label": "1章", "title": "章の題名" },
  "model": "gemini-3.8-flash-tts",
  "speakers": {
    "先輩": { "voice": "Charon", "style": "落ち着いて、わかりやすく" },
    "後輩": { "voice": "Aoede", "style": "明るく、興味を持って" }
  },
  "scenes": [
    {
      "id": "intro",
      "section": "イントロ",
      "board": { "type": "title", "kicker": "本の題名", "title": "1章 章の題名", "items": ["要点1", "要点2"] },
      "lines": [
        { "speaker": "後輩", "text": "…" },
        { "speaker": "先輩", "text": "…", "show": 0 },
        { "speaker": "先輩", "text": "…", "show": [1] }
      ]
    }
  ]
}
```

- `chapter.id` は book.json の章の id と同じにする。`scenes[].id` は英数字で場面ごとに違う値。
- 行の `style` は省略できる (話者の既定を使う)。気持ちが変わる行だけに付ける。

## 6. 見本 (1 場面)

一般的な題材での例。本の章では、原文の内容と用語で書く。

```json
{
  "id": "s3",
  "section": "2.3 テストを先に書く",
  "board": {
    "type": "flow",
    "title": "テスト駆動開発の流れ",
    "note": "↻ 小さく繰り返す",
    "items": [
      { "label": "レッド", "note": "失敗するテストを書く" },
      { "label": "グリーン", "note": "最小限の実装で通す" },
      { "label": "リファクタ", "note": "動きを保って整える" }
    ]
  },
  "lines": [
    { "speaker": "後輩", "text": "テストって、作り終わってから書くものだと思ってました。" },
    { "speaker": "先輩", "text": "この節は、その順番を逆にしようという話なんだ。" },
    { "speaker": "先輩", "text": "まず、まだ通らないテストを書く。これがレッドの段階だね。", "show": 0 },
    { "speaker": "先輩", "text": "次に、そのテストが通る最小限のコードを書く。グリーンだ。", "show": 1 },
    { "speaker": "後輩", "text": "最後に、動きを変えずにコードを整える、と。", "show": 2 },
    { "speaker": "先輩", "text": "そう。この 3 つを小さく何度も繰り返すのがポイントなんだ。" }
  ]
}
```

## 7. 書いたあとの確認

1. `check_storyboard.py storyboard.json --source chapters/NN.md` で形と分量を確かめる
   (エラーは直す。原文の 20% 未満・40% 超は警告)。
2. 原文と照らして、重要な主張・注意点の抜けや、原文にない事実が混ざっていないかを一度読み直す。
3. `build_video.mjs --layout-only` で画面だけを組み、場面ごとに静止画を撮って見る
   (SKILL.md の手順 4)。見るところ：
   - 項目がボードからはみ出していない (特に `flow` の縦 6 段・`compare` の長いセル)
   - 字幕が 3 段に収まっている
   - 枠が付くのが、いま話している項目になっている
   - 矢印が両隣の項目より先に出ていない
   直すときはボードの文言を短くするのが先。CSS (`scripts/video.css`) を変えるのは最後の手段。
