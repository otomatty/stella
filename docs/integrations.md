# 外部アプリから STELLA を利用する

連携 API の基点は `/api/integrations/v1`。サーバーから呼び出すための API です。
管理者のログイン Cookie・セッショントークンとは独立しています。
この文書へ #205 の書き込み API と #206 の読み取り API を追加します。

## 認証と運用

`platform_admin` が `/admin/integrations` で外部アプリごとにクライアントを作り、
必要な scope だけを選びます。トークンは作成・再発行の応答と、その直後の画面でだけ表示されます。
外部アプリのサーバーの secret に保存し、ブラウザ・ソースコード・ログへ含めないでください。
以後の一覧には先頭の識別部分だけが表示されます。STELLA の DB に保存するのは SHA-256 ハッシュです。

各リクエストに `Authorization: Bearer <トークン>` を付けます。
トークンに期限はありません。停止すると即時に使えなくなり、復帰すると同じトークンを使えます。
再発行すると古いトークンは無効になります。クライアントの最後の利用日時は約5分間隔で更新します。
画面を離れると発行したトークンは再表示できません。失った場合は再発行してください。

| scope | 許可する操作 |
| --- | --- |
| `groups:write` | 自分のグループの作成・更新 |
| `members:write` | グループへの受講者の登録・更新 (#205) |
| `stages:write` | グループの受講者へのステージの案内 (#205) |
| `progress:read` | グループの受講者の進捗の取得 (#206) |
| `events:read` | グループの受講者の出来事の取得 (#206) |

## 疎通確認

`GET /api/integrations/v1/me` は scope を必要としません。
自分のクライアントの名前・scope と、自分のグループのキー・名前・人数だけを返します。
受講者の ID・名前・メールや、ほかのクライアントのグループを含みません。

```json
{
  "client": { "name": "サンプル連携", "scopes": ["groups:write"] },
  "groups": [
    { "key": "sample:term-1", "name": "サンプルのグループ", "memberCount": 0 }
  ]
}
```

## グループの作成・更新

`PUT /api/integrations/v1/groups/{key}` は `groups:write` を必要とします。
Content-Type は `application/json`、本文は `{"name":"サンプルのグループ"}`。
キーは英数字・`:`・`-`・`_` の1〜100文字、名前は前後の空白を除いて1〜200文字です。
同じクライアント・同じキーへの再送は同じグループの名前を更新します。
常に200で `{"group":{"key":"sample:term-1","name":"サンプルのグループ"}}` を返します。
同じキーでもクライアントが異なれば別のグループです。
メンバーの登録は #205 で追加するため、この段階では作ったグループは空です。

## エラーと回数の制限

エラーの本文は `{"error":"説明"}`。HTTPステータスで扱いを分けてください。
認証・scope・入力の順で検査するため、不正な入力でも未認証なら401です。
認証・権限の判定の前に入力を解析しません。

| HTTP | 意味 |
| --- | --- |
| 400 | キーや名前などの入力が不正 |
| 401 | Bearer が無い、不正、停止済み。すべて `Unauthorized` |
| 403 | 必要な scope が無い (`Forbidden`) |
| 404 | 対象が見つからない、または自分のグループ・メンバーの範囲外 |
| 429 | 呼び出しが多すぎる。少なくとも1分待って再試行 |
| 500 | 内部エラー。時間を空けて再試行 |

クライアントごとに約120回/分を上限にします。認証後、scope の確認前に制限します。
Cloudflare のレート制限バインディングを使うため、厳密な全拠点合算の課金上限ではありません。
既存 API と同じく、バインディング未設定のローカル環境・制限サービスの障害時には制限を通します。
認証済みの呼び出しはクライアント ID・操作・対象グループ・応答ステータスを監査に記録します。
本文・トークンを監査に含めません。

## 開発時の境界

後続のルートは `authenticateIntegration` → `requireScope` → `requireOwnGroup` /
`requireOwnGroupMember` を使用し、`errorResponse` でエラーを返してください。
共通部品は `apps/api/src/lib/integrations.ts` にあります。
グループを解決したルートは `c.set("integrationGroupId", group.id)` で監査の対象を指定します。
自分のグループでないキー、グループにいない profile ID は、存在を明かさず404にします。
`PUT` は自分の所有範囲での upsert なので、ほかのクライアントのキーと同じ綴りでも自分のグループを作ります。

staff のユーザー管理・成績台帳・割り当て一覧は `groupId` クエリで絞り込みます。
選択肢は `GET /api/admin/integration-groups` (staff のみ)。
グループでの絞り込みは既存の権限や受講者だけの集計条件に追加します。
クライアント管理の `/api/admin/integrations` とその配下は `platform_admin` のみです。

## 判断したこと (PR 記載用)

- グループは連携クライアントが API で作る。クライアントを持たない管理者作成グループは追加しない。
- 受講者の削除時はメンバー行を外部キーの CASCADE で削除する。次の取得で人数・メンバーに反映する。
- トークンに有効期限を設けず、停止・再発行で無効にする。最後の利用日時を画面に表示する。
- 割り当て一覧のグループ絞り込み中は、全員向けの「案内の内容」の編集を止め、絞り込みの解除を案内する。既存の一括更新がグループ外にも及ぶ誤解を防ぐため。
- #205・#206 の境界確認に使えるよう、この issue に冪等なグループ作成・更新の1ルートを含める。

## ブラウザでの確認

ローカル D1 に0078まで適用し、API `http://127.0.0.1:8787` と Web `http://localhost:5173` を起動します。

1. `platform_admin` でログインし、`http://localhost:5173/admin/integrations` を開く。
2. 名前と `groups:write` を選んで作成する。トークンをコピーし、表示を閉じる。再読み込みで先頭部分だけになることを確認する。
3. コピーしたトークンで `/me` と `PUT /groups/sample:term-1` を呼び、「グループを見る」でキー・名前・人数を確認する。
4. scope を外して保存し、PUT が403になることを確認する。停止で `/me` が401、復帰で200になることを確認する。
5. トークンを再発行し、古いトークンで401、新しいトークンで200になることを確認する。
6. `/admin/users`・`/gradebook`・`/stages` の星から開く割り当て一覧でグループを選ぶ。空グループでは一覧が空になる。
7. `admin` で `/admin/integrations` を直接開き、権限エラーになることを確認する。
8. `/admin/audit` で作成・変更・再発行・API 呼び出しを確認する。

メンバーのいる一覧の比較は #205 の登録 API ができてから手動で行えます。
この issue の自動テストでは架空のメンバーを DB に入れ、3画面の API と削除の連動を検証します。
