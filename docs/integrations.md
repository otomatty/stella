# 外部アプリから STELLA を利用する

連携 API の基点は `/api/integrations/v1`。サーバーから呼び出すための API です。
管理者のログイン Cookie・セッショントークンとは独立しています。
グループ・メンバー・ステージの書き込みに対応しています。#206 の読み取り API は後続です。

## 認証と運用

`platform_admin` が `/admin/integrations` で外部アプリごとにクライアントを作り、
必要な scope だけを選びます。トークンは作成・再発行の応答と、その直後の画面でだけ表示されます。
外部アプリのサーバーの secret に保存し、ブラウザ・ソースコード・ログへ含めないでください。
以後の一覧には先頭の識別部分だけが表示されます。STELLA の DB に保存するのは SHA-256 ハッシュです。

各リクエストに `Authorization: Bearer <トークン>` を付けます。
トークンに期限はありません。停止すると即時に使えなくなり、復帰すると同じトークンを使えます。
再発行すると古いトークンは無効になります。クライアントの最後の利用日時は約5分間隔で更新します。
画面を離れると発行したトークンは再表示できません。失った場合は再発行してください。

| scope | 許可する操作 |
| --- | --- |
| `groups:write` | 自分のグループの作成・更新 |
| `members:write` | グループへの受講者の追加・削除 |
| `stages:write` | グループのステージ設定の取得・置き換え |
| `progress:read` | グループの受講者の進捗の取得 (#206) |
| `events:read` | グループの受講者の出来事の取得 (#206) |

## 疎通確認

`GET /api/integrations/v1/me` は scope を必要としません。
自分のクライアントの名前・scope と、自分のグループのキー・名前・人数だけを返します。
受講者の ID・名前・メールや、ほかのクライアントのグループを含みません。

```json
{
  "client": { "name": "サンプル連携", "scopes": ["groups:write"] },
  "groups": [
    { "key": "sample:term-1", "name": "サンプルのグループ", "memberCount": 0 }
  ]
}
```

## グループの作成・更新

`PUT /api/integrations/v1/groups/{key}` は `groups:write` を必要とします。
Content-Type は `application/json`、本文は `{"name":"サンプルのグループ"}`。
キーは英数字・`:`・`-`・`_` の1〜100文字、名前は前後の空白を除いて1〜200文字です。
同じクライアント・同じキーへの再送は同じグループの名前を更新します。
常に200で `{"group":{"key":"sample:term-1","name":"サンプルのグループ"}}` を返します。
同じキーでもクライアントが異なれば別のグループです。
作成時は空のグループです。以下の API でメンバーを追加できます。

## メンバーの追加

`PUT /api/integrations/v1/groups/{key}/members` (`members:write`)。
本文は `members` 配列で、1回100人まで。空配列は何もしません。
一覧に無い人を外す操作ではありません。同じ一覧を再送しても重複しません。

```json
{
  "members": [
    { "email": "applicant@example.test", "displayName": "応募者の例", "externalId": "applicant-001" }
  ]
}
```

- メールは前後の空白を除き小文字にして、既存の招待と同じ形式検査をします。
- 未登録の人は既存の管理者招待と同じ関数で `student` として招待します。現在の方式では招待メールは送らず、Google ログイン待ちのアカウントを作ります。ログインが先だった人は既存の認証 ID を再利用します。
- `displayName` は省略可能、200文字まで。新規招待時の空欄・省略はメールの `@` より前を名前にします。既存の人の表示名は変更しません。
- `externalId` は省略可能、前後の空白を除いて1〜200文字、同一グループ内で一意です。省略は現在値を保ち、指定は更新、`null` は解除します。別の人が持つ ID を奪うことはできません。
- 無効なアカウントと管理者のアカウントは追加しません。
- 新しく参加した人にも、その時点のグループのステージ設定を適用します。再送でも修復・再適用します。

全体は200、入力順の `index` と各人の結果を返します。失敗した行があっても他の行を処理します。
配列自体が不正、または101人以上なら400です。

```json
{
  "results": [
    { "index": 0, "status": "invited", "id": "stella-profile-id" },
    { "index": 1, "status": "failed", "id": null, "code": "invalid_email" }
  ]
}
```

| status | 意味 |
| --- | --- |
| `invited` | 新規招待しグループへ追加した |
| `existing` | 既存アカウントをグループへ追加した |
| `already_member` | 既にグループにいる (外部 ID の更新もこの結果) |
| `failed` | この行は失敗、`code` を確認 |

| code | 意味 |
| --- | --- |
| `invalid_email` | メールの形式が不正 |
| `invalid_member` | 表示名・外部 ID の形式や長さが不正 |
| `external_id_conflict` | 同じグループの別の人が外部 ID を使用している |
| `not_invitable` | 無効なアカウント、または受講者以外 |
| `invite_failed` | 招待の作成に失敗。時間を空けて再送できる |

## メンバーの削除

`DELETE /api/integrations/v1/groups/{key}/members/{id}` (`members:write`)。
`id` は STELLA のプロフィール ID、`?by=external` を付けると外部 ID です。
成功は200で `{"removed":true}`。不存在・グループ外は同じ404です。
削除後の再送も404ですが、削除済みの状態は変わりません。
STELLA のアカウント・受講登録・進み具合は削除しません。

そのグループが作った割り当てのうち未着手 (受講登録無し) のものだけを削除し、
その際にそのグループが作った前提免除も削除します。
開始済みの割り当てと免除は残し、期限・案内文・案内元名を消します。
手動・他グループの割り当てや免除には触りません。

## グループのステージ設定

`PUT /api/integrations/v1/groups/{key}/stages` (`stages:write`) は一覧全体を置き換えます。
1回100ステージまで。空配列は設定をすべて外します。
`GET` は同じ scope で現在の設定を slug 順に返します。
PUT と GET の応答は、下の本文と同じ形 (省略した項目は `null` / `false`) です。

```json
{
  "stages": [
    {
      "slug": "devlab-ts-prework",
      "due_at": "2026-12-10T09:00:00+09:00",
      "message": "期限までに事前課題に取り組んでください。",
      "exempt": true
    }
  ]
}
```

- `slug` は `audience: granted` のステージだけ。クライアントの `allowedStagePrefixes` のいずれかで始まる必要があります。空の許可一覧は何も指定できません。
- `due_at` は省略・`null`、タイムゾーン付き ISO 日時 (秒必須)、または日付 `YYYY-MM-DD`。日付だけなら、**日本時間のその日の 23:59:59** とし、保存・応答は UTC の ISO 日時に揃えます (例: `2026-12-04` → `2026-12-04T14:59:59.000Z`)。時刻付きは指定された時刻を保ちます。存在しない日付は拒否します。
- `message` は省略・`null` または500文字以内。既存の案内と同じ上限です。
- `exempt` は省略時 `false`。`true` なら既存と同じ `via: staff` の前提免除を作ります。受講登録は作らず、始めるのは本人です。
- いずれかの入力が不正なら **要求全体を400** にし、設定も割り当ても変更しません。

```json
{
  "error": "Invalid stages",
  "errors": [ { "slug": "other-stage", "code": "prefix_not_allowed" } ]
}
```

ステージ別のコードは `invalid_stage` (形式・日時・文字数)、`duplicate_slug`、
`prefix_not_allowed`、`not_granted` (不存在または granted 以外) です。

設定をグループ内の受講者に適用し、`stage_grants` の `due_at`・`message`・`source_name`
(クライアント名) に案内を保存します。ホーム・スキルツリーは既存の読み取り経路で表示します。
割り当ては人とステージで一意です。既に手動または別グループの割り当てがあれば、
その所有元と案内を保護し、上書き・所有権移動・免除の追加をしません。
このグループが作った行は `source_group_id` で区別します。

一覧から外したステージは、未着手の割り当てとそのグループの免除だけを削除します。
開始済みは残し、期限・案内文・案内元名を消します。`exempt` を false に戻す場合も、
そのグループが作った免除だけを解除し、手動や腕試しの免除は保ちます。

設定の置換・割り当て・免除は一つの D1 batch で処理します。
人数に比例する ID 配列を SQL のバインドへ展開せず、INSERT SELECT でまとめて適用します。
メンバー追加は各人の招待を個別に作り、成功した全員のメンバー行と全ステージの反映を一つの batch にまとめます。
招待が済んだあとに反映で内部障害が起きた場合も、再送で同じアカウントに追加を続けられます。

## 管理者の設定

`/admin/integrations` に「指定してよいステージの接頭辞」を追加しています。
カンマか空白で区切り、例として `devlab-` を指定します。設定変更は監査に残ります。
管理 API の作成・変更の項目名は `allowedStagePrefixes`、DB の列名は `allowed_stage_prefixes`。
最大100個、各1〜100文字の小文字英数字とハイフン (先頭は英数字) です。空文字の接頭辞は許しません。
既存クライアントは初期値が空なので、管理者が許可するまではステージを指定できません。
接頭辞の変更は今後の PUT を制限し、既存設定を自動では削除しません。
ステージ管理の割り当て一覧では、グループから作った行にグループ名を表示します。

## エラーと回数の制限

エラーの本文は `{"error":"説明"}`。HTTPステータスで扱いを分けてください。
認証・scope・入力の順で検査するため、不正な入力でも未認証なら401です。
認証・権限の判定の前に入力を解析しません。

| HTTP | 意味 |
| --- | --- |
| 400 | キーや名前などの入力が不正 |
| 401 | Bearer が無い、不正、停止済み。すべて `Unauthorized` |
| 403 | 必要な scope が無い (`Forbidden`) |
| 404 | 対象が見つからない、または自分のグループ・メンバーの範囲外 |
| 429 | 呼び出しが多すぎる。少なくとも1分待って再試行 |
| 500 | 内部エラー。時間を空けて再試行 |

クライアントごとに約120回/分を上限にします。認証後、scope の確認前に制限します。
Cloudflare のレート制限バインディングを使うため、厳密な全拠点合算の課金上限ではありません。
既存 API と同じく、バインディング未設定のローカル環境・制限サービスの障害時には制限を通します。
認証済みの呼び出しはクライアント ID・操作・対象グループ・応答ステータスを監査に記録します。
書き込みでは対象件数・成功件数も記録します。本文・トークン・メールアドレスの一覧を監査に含めません。

## 開発時の境界

後続のルートは `authenticateIntegration` → `requireScope` → `requireOwnGroup` /
`requireOwnGroupMember` を使用し、`errorResponse` でエラーを返してください。
共通部品は `apps/api/src/lib/integrations.ts` にあります。
グループを解決したルートは `c.set("integrationGroupId", group.id)` で監査の対象を指定します。
自分のグループでないキー、グループにいない profile ID は、存在を明かさず404にします。
`PUT` は自分の所有範囲での upsert なので、ほかのクライアントのキーと同じ綴りでも自分のグループを作ります。

staff のユーザー管理・成績台帳・割り当て一覧は `groupId` クエリで絞り込みます。
選択肢は `GET /api/admin/integration-groups` (staff のみ)。
グループでの絞り込みは既存の権限や受講者だけの集計条件に追加します。
クライアント管理の `/api/admin/integrations` とその配下は `platform_admin` のみです。

## 判断したこと (PR 記載用)

- グループは連携クライアントが API で作る。クライアントを持たない管理者作成グループは追加しない。
- 受講者の削除時はメンバー行を外部キーの CASCADE で削除する。次の取得で人数・メンバーに反映する。
- トークンに有効期限を設けず、停止・再発行で無効にする。最後の利用日時を画面に表示する。
- 割り当て一覧のグループ絞り込み中は、全員向けの「案内の内容」の編集を止め、絞り込みの解除を案内する。既存の一括更新がグループ外にも及ぶ誤解を防ぐため。
- #205・#206 の境界確認に使えるよう、この issue に冪等なグループ作成・更新の1ルートを含める。

## 判断したこと (#205、PR 記載用)

- 既存の受講者の追加時に別の同意・通知は求めない。ホームに出る案内を知らせとし、表示名は変更しない。
- グループから外した人の割り当ては未着手だけ削除し、開始済みは残して案内を消す。
- 連携 API は受講者のアカウントを削除できない。削除は引き続き管理者のユーザー管理で行う。
- 手動・別グループの割り当てが先にある場合は保護する。現在の人×ステージの一意制約を維持し、複数元の案内を合成する仕組みは追加しない。
- 手動の staff 免除と区別して安全に削除するため、割り当てに加え `stage_unlocks` にも `source_group_id` を追加する。
- 日付だけの期限は、管理画面と同じ日本時間のその日の 23:59:59 とする。別の時刻を指定したい場合はタイムゾーン付き日時を送る。

## ブラウザでの確認

ローカル D1 に0079まで適用し、API `http://127.0.0.1:8787` と Web `http://localhost:5173` を起動します。

1. `platform_admin` でログインし、`http://localhost:5173/admin/integrations` を開く。
2. 名前と `groups:write` を選んで作成する。トークンをコピーし、表示を閉じる。再読み込みで先頭部分だけになることを確認する。
3. コピーしたトークンで `/me` と `PUT /groups/sample:term-1` を呼び、「グループを見る」でキー・名前・人数を確認する。
4. scope を外して保存し、PUT が403になることを確認する。停止で `/me` が401、復帰で200になることを確認する。
5. トークンを再発行し、古いトークンで401、新しいトークンで200になることを確認する。
6. `/admin/users`・`/gradebook`・`/stages` の星から開く割り当て一覧でグループを選ぶ。空グループでは一覧が空になる。
7. `admin` で `/admin/integrations` を直接開き、権限エラーになることを確認する。
8. `/admin/audit` で作成・変更・再発行・API 呼び出しを確認する。

9. 接頭辞 `sample-` を保存し、トークンの `members:write`・`stages:write` を有効にする。上記のメンバー追加を架空のアドレスで行い、再送が `already_member` になることを確認する。
10. 実在する granted ステージに合う接頭辞を保存し、その slug・期限・案内・免除を PUT する。ステージ管理の割り当てにグループ名が出ることと、対象者のホームに案内が出ることを確認する。
11. 設定から外したときとメンバー削除時に、未着手は割り当てが消え、開始済みは進捗が残ることを確認する。

自動テストは架空の情報だけを使い、再送・権限・既存名の保護・手動割り当ての保護・削除・batch のロールバック・100人時のバインド上限を検証します。
