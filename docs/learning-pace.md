# 学習ペースの自動計算

Issue #40。`docs/curriculum/07-stella-adoption-redesign.md` §10 の実装。

受講者のホーム・設定に「学習のペース」を表示する。週の時間は既定35時間、1〜80時間で変更できる。開始日は `dev-env-basics` の初回受講日 (日本時間)。本人が指定した日を受講開始で上書きしない。空欄で保存すると初回受講日に戻る。まだ始めていなければ目標日は表示しない。

`course.json` の `plannedHours` は教材形式にかかわらず `stages.duration_hours` に入る。未設定の講座には固定の時間を表示しない。標準プログラムの計算対象は、新設計 §3.1 で確定した18講座のうち、同じテナントで公開したカタログ講座。時間の正本は各 `course.json` で、教材を新形式に切り替える前の準備中の講座も計算する。残す旧講座・資格の島・専用教材は含めない。1,260時間の場合、週30時間は42週、35時間は36週、40時間は31.5週。補習の2〜4週間は計算に追加しない。

予定日はDBに保存しない。取得のたびに `@stella/shared/study/pace` が前提順に計算する。単元の予定時間から課題の `estimatedMinutes` を取り、残りをレッスンの表示時間の比率で配分する。完了したレッスン、現行の教材ハッシュで `ai-passed` / `passed` になった課題だけを進んだ予定時間に数える。視聴秒数・滞在時間・手元の合格・提出待ちは使わない。受講登録の修了・有効な修了証は講座全体の完了として数える。教材が未作成の部分も講座の総時間には含めるが、単元やコマを捏造せず、準備中と表示する。

今週は月曜〜日曜。今日から週末までの時間で単元とコマ数の目安を出す。遅れを翌週の負担に上乗せせず、今日から同じペースで残りを引き直す。時間設定の変更履歴は変更前・変更後の時間を残し、過去の期待時間を計算する。最初の変更より前 (開始日を過去へ変更した場合も含む) は保存した変更前の時間を使う。同日の再変更ではその日の最初の変更前の値を保つ。週の時間を変更しても、それ以前の進み具合は書き換わらない。

確認Bが解禁するまでは他の単元を進め、解禁後の時間だけをBに割り当てる。複数のBも同じ時間軸に順番に置き、所要時間を重ねない。未合格Aのある単元は完了・診断済み時間を除いた残りからAの合格時点を予測して7日待つ。ホームでステージを開始したときと、完了進捗がサーバに保存されたときにパネルを再取得する。

確認Bは、同じ単元・パターンの確認Aがすべて合格した7日後に予定する。`task_progress.passed_at` は最初の合格日をDBトリガーで記録し、AI合格から講師の確定へ変わっても動かない。教材ハッシュが変わった合格は使わない。手元の実行結果をAの合格にはしない。今後の提出・レビュー機能も、既存の `task_progress` に合格を記録すれば反映される。

担当講師との最小の連携として `learner_instructors` を持つ。管理者は設定の「受講者の学習ペース」から同じテナントの講師を設定でき、講師のダッシュボードには担当受講者だけが並ぶ。本人と担当講師・同じテナントの管理者が週の時間・開始日を変更できる。担当講師・管理者は開始診断の根拠付きでスキルを確認済みにできる。練習の評価スキルをすべて確認できた場合、その練習時間を計画から除く。確認A・Bと解説時間は除かない。診断を取り消すと再計算される。

既存の15分cronで進捗差を確認する。差が週の時間を超えた受講者の担当講師へ通知し、受講者・担当講師・週ごとに1通にする。担当がない場合は他の講師へ広く通知しない。目標日は受講登録の `due_at` へ書き込まず、期限切れやアクセス制限を発生させない。週次育成メモやその他のつまずき検知は #38 の範囲。

API:

- `GET /api/learning-pace`: 本人の計画。既存のスキルツリーの霧を守り、`full` の講座の名前・ID・単元だけを返す。全体の予定時間と目標日は集計値で返す。
- `POST /api/me`: `weekly_hours` / `learning_start_date` の部分更新。既存の `display_name` 更新も利用可能。
- `GET /api/learning-pace?userId=...`: 担当講師・同じテナントの管理者向けの計画。
- `GET /api/learning-pace/learners`: 講師は担当受講者だけ、管理者は同じテナントの受講者・講師一覧。
- `PATCH /api/learning-pace/:userId`: 本人・担当講師・管理者による設定更新。
- `PUT /api/learning-pace/:userId/instructor`: 管理者による担当登録。`instructor_id: null` で解除。
- `GET` / `PUT /api/learning-pace/:userId/diagnostics`: 担当講師・管理者による診断の参照・登録 (`skill_id`, `evidence`)。
- `DELETE /api/learning-pace/:userId/diagnostics/:skillId`: 診断の取り消し。

マイグレーションは `0044_learning_pace.sql`。既存の初回受講日・合格日を引き継ぐ。計算の境界、日付、権限、実SQLiteの移行・トリガー・通知は `pace.test.ts` と `learning-pace.test.ts` で検証する。
