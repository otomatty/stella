# M01 初心者向けの環境構築とVS Code基本操作

作成日 2026年10月4日\

M01は、VS Codeを初めて使う人が、学習用のフォルダーを開き、HTMLを保存・表示・変更し、次の教材を始められる環境を準備する教材である。手順を見ながら導入できたことと、後日も自分で操作できることを別に記録する。

版2.4の注記(2026-11-09): オーナーの決定により、予定35時間を4時間へ縮めた。STELLAの網羅的な説明より、VS Codeで課題を開く・編集する・保存する・表示する・ファイルを作る・名前を変える・確認して提出する主要な操作を優先する。

18教材パックの合計は1,229時間となる。削った内容は、それを最初に使う後続ステージの冒頭で扱い、具体的なステージは執筆時(#41)に決める。本書は教材制作とSTELLA実装のための設計である。STELLA拡張はVisual Studio Marketplaceで公開済みであり、受講者へVSIXは配布しない。本文と課題の草稿、12トピックの台本は作成済みで、参照元と本文は講師の承認待ちである。

## 1 M01の到達目標

学習者が、次の行動を資料を参照しながら自分で行えることを目標にする。

| 行動 | 完了の証拠 | 後続の教材で使う場面 |
| --- | --- | --- |
| VS CodeとSTELLAを起動する | 教材を開き、閉じた後も同じ単元へ戻れる | 全教材の学習開始 |
| 作業フォルダーを開く | 開いているフォルダーと、保存先を説明できる | 教材やプロジェクトの切替 |
| ファイルを作成・編集・保存し、名前を変える | index.htmlを保存し、テキストファイルを作成・改名できる | HTML・CSS・JSの実装 |
| ブラウザで表示・更新する | 変更した見出しが表示される | 画面の制作と確認 |

課題を開き、手元で確認して提出し、結果を読むところまでを一周する。

用語は行動の直前か直後に説明する。「フォルダー」は作業場所を開くとき、「拡張機能」はSTELLA拡張を入れるときに扱う。キーボードのショートカットを暗記することは進級条件にしない。

## 2 導入前から教材を読めるようにする

VS Code未導入の学習者は、ブラウザーの `/start` でU00・U01のスライドとまとめを読める。ログイン前の進捗は記録しない。導入中もブラウザーの案内と問い合わせ先を開いておける構成にする。

```text
ブラウザーで開始案内を読む
  → PCとOSを確認する
  → VS Codeを導入する
  → 日本語表示とSTELLA拡張を準備する
  → Webにログインし、U02の「VS Code で開く」を押す
  → 学習フォルダーを選び、課題文のパネルから進める
```

WebのレッスンとVS Codeの課題は同じ課題IDで結ぶ。「VS Code で開く」が発行する接続コードで拡張を接続する。認証情報を設定へ貼り付けさせない。閉じた後はWebのレッスンから開き直す。必要な導入ページは配布・印刷用にも出力する。

ブラウザーだけでは、ローカルのソフトウェアやファイルの状態を十分に確認できない。導入前は学習者の確認と講師の支援を使い、課題を開けたことと手元の確認の結果で導入を確かめる。環境診断はNode.js・Gitを初めて要する後続ステージで行う。

## 3 標準環境と導入の順序

Windowsを主教材の初期案とし、macOSは独立した操作手順で用意する。受講者のOSを確定してから、対象OS・CPU・インストール方法と確認画面を制作する。WindowsとmacOSのコマンドや画面を一つの手順へ混在させない。

| 準備するもの | 導入する時点 | 設計上の扱い |
| --- | --- | --- |
| 既存のブラウザ | 開始前 | Google Chrome と Microsoft Edge (Chromium 131 以降) を案内する |
| VS CodeのStable版 | U01 | 1.96 以降。公式配布元を案内する |
| 日本語表示 | U01 | 公式の表示言語手順に沿い、Language Packを確認する |
| STELLA拡張 | U01 | Visual Studio Marketplaceで公開済み。拡張ID `saedgewell.stella-lms`・発行者 `saedgewell` を指定する |
| Node.jsとnpm | Node.jsを初めて要するステージ | 検証したLTSの具体的な版をコース環境へ登録する。既存の適合版は再インストールしない |
| Git | Gitを初めて要するステージ | 採用する版と公式の導入手順を記載する |
| ローカルサーバー用スターター | 最初に使うステージ | 研修側が準備し、起動方法と依存関係を固定する |

最初のHTML表示までは、ブラウザとVS Codeで進める。React、Next.js、DB、Docker、WSL、GitHubへの公開は、それを必要とする後続教材で導入する。最初の単元で用途がまだ分からない設定を大量に行わせない。

WindowsのVS Code導入は、通常の個人用環境では公式のUser setupを入口にする。会社が管理する端末では、研修担当者が認められた導入方法を先に確認する。[VS CodeのWindows向け導入資料](https://code.visualstudio.com/docs/setup/windows)はUser setupとSystem setupを区別している。

学習フォルダーは、学習者が書き込める自分のユーザーフォルダーに`web-training`を作る。講師は実際の端末で場所を確認する。教材に出す絶対パスのユーザー名は例であることを明示し、その文字列をそのまま作らせない。

後続ステージの導入方法と対象版は、そのステージを書くとき(#41)に決める。

## 4 見直しの方針

1. **VS Codeを使った主要な操作を、このステージの中心にする。** 1周目(読む → 問題 → VS Codeで課題 → 確認 → 提出 → 結果 → 星)を、U02までの約2.5時間で自分の手で通す。
2. **機能は、初めて要る場面で教える。** ヒント、講師への相談、今日の復習、類題、確認A・B、腕試し、島は、最初の動画に詰めない。出てくる単元で短い動画と1行の説明を出す(§8)。
3. **動画は「見てから同じことをする」の前振りにする。** 1本1〜3分・1本1操作。見た直後に同じ操作を課題で行う。動画と同じ手順を、画像付きの本文でもたどれるようにする(§7)。
4. **失敗を一度体験させる。** 最初の課題では、何も直さずに「課題を確認する」を押し、通らない結果を読んでから直す。保存し忘れたときは、拡張の「保存して確認する / 保存せずに確認する」の確認が出る。
5. **後続のステージが前提にすることを、修了の条件と記録に入れる。** 学習フォルダー、保存・表示・再開の経験、評価する5個のスキルIDを、M02以降がそのまま使える形で残す(§9)。

## 6 単元ごとの中身

形式はformat 2。1単元に1レッスンを置き、短い操作ごとにトピックを分ける。OSで違う手順は `:::os` で分け、`pdfByOs: true` を残す。

### U00 STELLAで学ぶ流れ(0.5時間・公開)

- **目標:** 読む → VS Codeで課題を開く → 確認 → 提出 → 結果、の流れを知る。
- **内容:** 1トピック。学習の流れを短く案内する。機能の網羅的な説明はしない。
- **課題:** なし。公開の単元には課題を置かない。

### U01 VS CodeとSTELLA拡張の準備(1時間・公開)

- **目標:** VS CodeとSTELLA拡張を入れ、Webから課題を開く準備をする。
- **内容:** 3トピック。「VS Codeを入れる(日本語表示を含む)」「STELLA拡張を入れる」「Webから課題を開く」を扱う。学習フォルダーとWorkspace Trustは操作に必要な範囲で案内する。
- **課題:** なし。接続はU02の最初の課題を開けたことで確かめる。

### U02 はじめての課題を出す(1時間)

- **目標:** HTMLの見出しを編集・保存し、ブラウザーで確かめ、確認して提出し、結果を読む。
- **内容:** 4トピック。編集と保存、ブラウザーでの表示、課題の確認、提出と結果を扱う。
- **課題:** `q01-first-page`。まず変更せず確認して、通らない結果を読み、見出しを変えて保存・確認・提出する。

### U03 ファイルとフォルダーの操作(1時間)

- **目標:** エクスプローラーで新しいファイルを作って保存し、名前を変え、保存先を確かめられる。
- **内容:** 3トピック。「新しいファイルを作る」「ファイルの名前を変える」「保存先を確かめる」を扱う。
- **課題:** `q01-note-file`、`q03-rename`。

### U04 確認A(0.5時間)

- **目標:** 別の題材で編集・保存・ファイル作成・名前の変更・確認と提出を組み合わせる。
- **内容:** 1トピック。確認Aの進め方と確認Bの予告を扱う。
- **課題:** `a01-check-a`、後日の `b01-check-b`。どちらも `static-preview` のファイル操作の課題とし、Gitと相対リンクは含めない。

### 課題IDと操作の対応

| 単元 | 課題フォルダー | 題 | 種別 |
| --- | --- | --- | --- |
| U00・U01 | — | 課題なし | — |
| U02 | `q01-first-page` | 最初のページを作る | `basic` |
| U03 | `q01-note-file` | メモのファイルを作る | `basic` |
| U03 | `q03-rename` | ファイルの名前を変える | `basic` |
| U04 | `a01-check-a` | 確認A: 自己紹介のフォルダーを整える | `assessment-a` |
| U04 | `b01-check-b` | 確認B: 1週間の予定のフォルダーを整える | `assessment-b` |

U02はHTMLの編集・保存・表示と課題の一周、U03はファイルの作成と改名、U04はこれらを別題材で組み合わせて確かめる。

学習の固定IDを保つため、U02のトピックIDは旧見本単元の `0-1-*` のままとする。U00は `00-1-1`、U01は `01-1-*`、U03は `03-1-*`、U04は `04-1-1` とする。

## 7 一つの操作を説明する形式

一つのステップは通常5〜10分の小さな操作にする。インストールのダウンロードや待機は別に扱う。クリックごとに大量の試験を置かず、作業フォルダーを開く、保存する、表示する等の意味のある節目で確認する。

| 画面に載せる項目 | 内容 |
| --- | --- |
| 今回すること | 「学習用のフォルダーを開く」等、一つの行動 |
| 始める状態 | どのアプリを開き、どの画面から始めるか |
| 操作 | メニュー名、クリックする場所、入力する文字。最初はメニュー操作を主にする |
| 操作例の画像 | 対象OS・表示言語・確認した版で撮影し、操作箇所を示す |
| こうなれば完了 | 保存先、表示された文字、URL、版等の観察できる結果 |
| よくある違い | 想定と異なる画面と、元の状態へ戻る方法 |
| 小さな練習 | ファイル名や文章を変え、同じ操作を再度行う |
| 参照元 | 公式ページの該当節、確認日、教材独自の判断 |

画像の中だけに操作内容を書かず、本文にもメニュー名と入力内容を記載する。小さい画面では画像を拡大できるようにする。動画を付ける場合も、静止画と短い手順で同じ操作をたどれるようにする。

コードやコマンドにはコピー用のボタンを付ける。コピーする範囲へプロンプト記号や実行結果を混ぜない。実行結果は別の枠へ置き、版やパスが学習者によって違う箇所を説明する。最初は一つのコマンドを実行し、結果を読んでから次へ進む。

### 保存と更新のステップ例

| 項目 | 学習者に見せる内容 |
| --- | --- |
| 今回すること | 見出しの変更を保存し、ブラウザで確かめる |
| 始める状態 | VS Codeでindex.htmlを開き、同じファイルをブラウザでも表示している |
| 操作1 | 見出しの文章を「今日の学習予定」に変更する |
| 操作2 | VS Codeの「ファイル」メニューから「保存」を選ぶ |
| 操作3 | ブラウザへ移り、更新ボタンを押す |
| 完了条件 | ブラウザの見出しが「今日の学習予定」になっている |
| 変わらない場合 | 保存したか、ブラウザのURLが同じファイルかを確認する |
| 次の練習 | 見出しを別の文章へ変更し、同じ操作を行う |

この例は教材独自の操作課題である。保存操作は[VS Code Editor tutorial](https://code.visualstudio.com/docs/editing/getting-started/editor-tutorial)、文書構造はMDN HTMLを参照する。OS・表示言語別の実画面を撮影して操作箇所を追加する。

### 最初のページの例

U02では、次の教材独自のひな形を課題のスターターとして渡す。各タグの詳しい説明はM02で扱い、ここでは保存と表示の操作を練習する。

```html
<!doctype html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>はじめてのページ</title>
</head>
<body>
  <h1>Web学習を始めました</h1>
  <p>この文章を変更して、保存と表示を確かめます。</p>
</body>
</html>
```

1. Webの「VS Code で開く」から課題を開き、配られたindex.htmlを確かめる。
2. 何も変えずに「課題を確認する」を押し、通らない結果を読む。
3. OSのファイル操作から、保存したindex.htmlをブラウザで開く。
4. 見出しを変更し、保存してからブラウザを更新する。
5. 「課題を確認する」で合格を確かめ、提出して結果を読む。
6. VS Codeを閉じ、Webから同じ課題を開き直す。

ここではHTMLをローカルファイルとして表示する。ローカルサーバーを最初に使う後続ステージでサーバー経由の表示を追加し、ファイルの表示とHTTPでの取得の違いを確認する。ひな形は独自制作、要素と文書構造の参照元は[MDN HTML](https://developer.mozilla.org/en-US/docs/Web/HTML)と[HTML Living Standard](https://html.spec.whatwg.org/multipage/)とする。

環境確認のコマンドとOS別のターミナル操作は、Node.js・Gitを最初に要する後続ステージで扱う。

## 9 後続のステージへの引き継ぎ

### 9.1 修了したときに受講者の手元にあるもの

| もの | 状態 | 使うステージ |
| --- | --- | --- |
| VS Code(日本語表示)とSTELLA拡張 | 接続済みで、Webから課題を開ける | 全ステージ |

Node.js・npm・Gitとローカルサーバーの経験は前提にしない。

### 9.2 スキルID

このステージで評価するスキルは次の5個とする。後続の課題は習得済みのスキルを `skills.uses` から参照する。

| スキルID | 題 |
| --- | --- |
| `stella-task-loop` | 課題を開き、確認して提出し、結果を読む |
| `open-learning-folder` | 作業フォルダーを開き、保存先を説明する |
| `file-save-reopen` | ファイルを作成・編集・保存し、閉じて開き直す |
| `html-document` | HTMLの文書を作る |
| `preview-changes` | 変更をブラウザーで確認する |

`relative-link`・`terminal-location`・`node-npm-ready`・`git-local-commit`・`local-server-run`・`report-problem` は台帳 `packages/content/skills.json` に残すが、このステージでは評価しない。最初に使うステージで教え、評価する。どのステージかは執筆時(#41)に決める。

### 9.3 環境の版

M01は `static-web-02` を使い、Node.js・npm・Gitの導入や診断を求めない。後続ステージで環境診断を初めて置くときは、診断の要件をそのステージの実行環境の要件と一致させる。既存の環境定義と対象版を確認し、採用する定義は執筆時(#41)に決める。

### 9.4 学習フォルダーとGit

学習フォルダーと配布先の並びは引き継ぐ。Gitを最初に使うステージの冒頭で、このフォルダーのローカルの `init`・`add`・`commit`・`diff`・`log` を扱う。名前とメールはリポジトリだけに設定する。具体的なステージは執筆時(#41)に決める。

- リポジトリのルートは学習フォルダー。ステージや課題ごとには作らない。

### 10.2 Webの収録(A)

Senの `tutorials/` から、次をそのまま持ってくる。

- 台本の書き方: 1ファイル1本の `defineScenario`、操作API(`t.caption`・`t.click`・`t.type`・`t.highlight`・`t.expect`・`t.poster` など)

- ナレーション: Gemini TTS、まとめ読み、キャッシュ、記号の読み替え、`say`
- `t.expect` が1つでも外れたら動画を書き出さない(壊れた画面の動画を出さない)
- `manifest.json` に、チャプターの時刻と、収録したときの画面のハッシュ(`sourceHash`)を残す
- `tutorials:check` で、画面か台本が変わったのに撮り直していない動画を一覧にする

Stellaで変えること:

| 項目 | Sen | Stella |
| --- | --- | --- |
| ログイン | 開発用のサインインAPI | 開発用トークン(`AUTH_JWT_SECRET` で作り、`stella_auth_token_v1` に入れる)。`smoke:core` と同じ |
| データ | シナリオごとに `/api/dev/seed-demo` で初期化 | シナリオごとに一時のD1へ migrate・seed し直す。初めての人は `seed-learner2` を使う |
| 要素の指定 | `data-testid` | 今のWebには `data-testid` が1つも無い。台本が触る要素に足す |
| 置き場所 | `public/tutorials/`(Static Assets) | Senと同じ。台本と仕組みは `apps/web/scripts/tutorials/`、動画・サムネイル・字幕・`manifest.json` は `apps/web/public/tutorials/`(Webの Static Assets。CSPの `media-src 'self'` で読める)。1本あたり数MBで、Static Assetsの1ファイルの上限(25MiB)に収める。リポジトリが重くなったら、教材のR2へ移す |

### 10.3 VS Codeの収録(B)

- Playwrightの `_electron` でVS Codeを起動し、`--extensionDevelopmentPath` でSTELLA拡張を読み込む(VS Code自身の自動テストと同じやり方)。Linuxの収録環境ではxvfbで動かす。

- 画面はメニュー操作を主にする(§7)。キーボードの表記がOSで違うためでもある。
- 実現できるかは最初に試作で確かめる(§18のフェーズ2)。できない場合は、code-server(ブラウザーで動くVS Code)で撮る案に切り替える。

### 10.4 OSとインストールの動画(C)

### 10.5 動画を出す場所

- **A・B(アプリの使い方):** 正本はアプリ側に1つだけ置く。このステージのレッスンは動画のIDで参照し、同じ動画を教材に複製しない。画面を変えて撮り直せば、レッスンの動画も新しくなる。あわせて、各画面のヘルプ(「?」)にもその画面の動画を出す。

## 12 よくあるつまずきと支援

| 現象 | 最初に確認すること | 教材で示す復帰方法 |
| --- | --- | --- |
| VS Codeの画面が例と違う | OS、表示言語、開いているビュー | メニューから必要なビューを開く。色や位置の違いだけで誤操作としない |
| フォルダーが表示されない | 単独ファイルだけ開いていないか | 指定したフォルダーを開き直す |
| 変更がブラウザに出ない | 保存、更新、開いているファイルの場所 | 保存して更新し、URL・保存先を照合する |
| HTMLが文章として開く | ファイル名、拡張子、ブラウザへの関連付け | 保存した名前を確認し、ブラウザで対象ファイルを開く |
| STELLAが起動しない | 拡張ID・版、有効状態、必要なログイン、Workspace Trust | 該当する確認から一つずつ行い、ブラウザ版で案内を読む |
| npmの準備が失敗する | 作業フォルダー、package.json・lockfile、ネットワーク | 準備先と提供スターターの版を確認する。組織の接続条件は講師へ引き継ぐ |
| 端末の設定変更が必要 | 会社の管理方法、操作権限 | 研修担当者の導入支援へ回し、学習スキルの不合格にしない |

Workspace Trustは、自分で作った練習フォルダーや、出所を確認した研修資料を対象に説明する。すべてのフォルダーを一律に信頼させない。Restricted ModeではSTELLA拡張からプロセスを起動しない。[VS CodeのWorkspace Trust](https://code.visualstudio.com/docs/editing/workspaces/workspace-trust)を参照元にする。

相談欄は「何をしようとしたか」「どこまで成功したか」「実行した操作またはコマンド」「表示されたメッセージ」を記入する形式にする。添付する画面やログの範囲を指定し、不要なユーザー名・認証情報等は含めない。相談の記録は支援に使うが、`report-problem` はこのステージでは評価しない。

## 13 完了条件と進級

環境の準備は、VS Code、STELLA拡張、学習フォルダー、Webから課題を開く操作を確認して完了にする。手元の確認と提出後のレビューは記録上で区別する。

操作の確認Aは、導入済みの環境で、初めて見る短いファイル操作の仕様を渡して行う。メニュー、公式資料、操作早見表の参照は許可する。講師が代わりに操作した場合は、環境を整えたことと学習者の自力確認を区別する。

| 確認項目 | 合格の条件 |
| --- | --- |
| 作業場所 | 配布された課題フォルダーを開いている |
| 作成・保存・表示 | 指定した文章のHTMLを保存し、該当するページをブラウザで表示する |
| 変更 | 一箇所の追加要求を実装し、保存・更新して確認する |
| ファイル操作 | 新しいテキストファイルを作成し、既存ファイルの名前を変えて保存する |
| 確認と提出 | 手元の確認を通して、ファイルの場所などの説明を添えて提出する |
| 保存先の確認 | 作ったファイルの場所を説明できる |

確認Bは、VS Codeを閉じた状態から再開する別題材の短い課題にする。確認Aの手順を記憶しただけでは完了できないように、フォルダー名と変更内容を変える。参照や支援の扱いは[反復演習と評価](03-repeated-practice-and-assessment.md)を引き継ぐ。

環境に問題がある場合は環境支援へ回し、ブラウザで読める導入案内を確認する。自力操作の不足は、その操作を使う短い問題を追加し、別の仕様で再確認する。M02は環境準備と確認Aを満たして開始し、遅延確認Bの結果は後続の自力・統合課題の進行へ反映する。

### 標準機能とプレビューの構成

HTML・CSS・JavaScript・TypeScriptの言語支援、Emmet、Gitの基本操作、JavaScriptのデバッグは、VS Codeの標準機能を学習の入口にする。参照元は[HTML](https://code.visualstudio.com/docs/languages/html)、[CSS](https://code.visualstudio.com/docs/languages/css)、[JavaScript](https://code.visualstudio.com/docs/languages/javascript)、[TypeScript](https://code.visualstudio.com/docs/languages/typescript)、[Source control](https://code.visualstudio.com/docs/sourcecontrol/overview)とする。Node.js、Git、コンパイラ等の実行用ソフトウェアは別途準備する。

プレビューは、M01のローカルファイル表示、後続で初めて扱う提供スターター、後続のVite・Next.js等の開発サーバーをSTELLAの実行定義で案内する。採用したVS Code版に応じて、[標準のIntegrated Browser](https://code.visualstudio.com/docs/debugtest/integrated-browser)でローカルHTMLやサーバーのURLを開く構成も使える。STELLAの課題文を表示するWebViewと、学習者が作ったページのプレビューは、画面上で区別する。

静的ページの簡易サーバーが別途必要なら、[MicrosoftのLive Preview](https://marketplace.visualstudio.com/items?itemName=ms-vscode.live-server)を追加候補として検証する。確認時の掲載内容には開発中・プレリリースの説明があるため、Stable版の研修で使うリリースと挙動を確認してから採用する。通常の教材で使うプレビュー経路は一つに決め、起動・停止・表示URLを統一して説明する。

### 教材の推奨一覧と設定例

教材のスターターには、段階ごとの.vscode/extensions.jsonを同梱する。次はM02の公開済み拡張の推薦例であり、STELLA拡張も含める。

```json
{
  "recommendations": [
    "MS-CEINTL.vscode-language-pack-ja",
    "saedgewell.stella-lms",
    "esbenp.prettier-vscode"
  ]
}
```

このファイルは推薦の一覧であり、拡張の自動インストールや版の固定には使えない。採用版の記録、導入手順、実際に有効かの確認を別に用意する。参照元は[VS CodeのWorkspace recommended extensions](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_workspace-recommended-extensions)とする。

M02の.vscode/settings.jsonは次の初期案にする。プロジェクトには.prettierrc.json等のPrettier設定と、実行用の依存関係を用意する。この例は既存の受講者環境へ適用していない。

```json
{
  "files.autoSave": "off",
  "editor.formatOnSave": false,
  "prettier.requireConfig": true,
  "[html]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode"
  },
  "[css]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode"
  }
}
```

M03ではJavaScript、M07ではTypeScript、M08ではReact用の言語設定を追加する。保存時の整形を有効にする変更も、教材の操作として説明する。既存の利用者設定の上書きを避けるため、必要に応じて講師が[研修用Profile](https://code.visualstudio.com/docs/configure/profiles)を準備し、教材のワークスペース設定と使い分ける。

### STELLAとの連携と導入の確認

各教材の環境定義には、拡張ID、採用版、導入目的、必要となる単元、必須・推奨・任意、依存パッケージ、参照元、確認日を登録する。STELLAは現在の課題で必要なものを示し、拡張の導入、有効状態、設定、操作確認を分けて記録する。任意拡張がないことを進級の不合格にしない。

STELLA拡張から別の拡張を操作する場合は、採用版の公開APIや利用可能なコマンドを確認する。対象が変わる内部コマンドの呼出しを当然の前提にせず、通常のTestingビュー、ターミナル、メニューからの操作も用意する。STELLAの学習画面を外部拡張の表示だけに依存させない。

公開前には、研修の標準Profileで整形・診断・プレビュー・テスト・教材表示が同時に使えることを確認する。拡張本体のIDと対象版、プロジェクト内の実行パッケージ、設定ファイル、CLIの結果を照合する。導入する拡張を追加する際は、各教材の参照元にも配布元と利用した節を登録する。
