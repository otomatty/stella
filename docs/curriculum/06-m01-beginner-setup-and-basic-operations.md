# M01 初心者向けの環境構築とVS Code基本操作

作成日 2026年10月4日\
改訂日 2026年11月7日\
版 2.3\
状態 設計(dev-env-basics の見直しで決定)\
[全体設計へ戻る](00-overall-design.md)

M01は、VS Codeを初めて使う人が、学習用のフォルダーを開き、HTMLを保存・表示・変更し、次の教材を始められる環境を準備する教材である。手順を見ながら導入できたことと、後日も自分で操作できることを別に記録する。

ステージ `dev-env-basics` の35時間を見直した決定である。18教材パック・36週間・1,260時間の計画は維持する。本書は教材制作とSTELLA実装のための設計である。STELLA拡張はVisual Studio Marketplaceで公開済みであり、受講者へVSIXは配布しない。本文・動画・画面の変更は§18の順で今後実装する。
## 1 M01の到達目標

学習者が、次の行動を資料を参照しながら自分で行えることを目標にする。

| 行動 | 完了の証拠 | 後続の教材で使う場面 |
| --- | --- | --- |
| VS CodeとSTELLAを起動する | 教材を開き、閉じた後も同じ単元へ戻れる | 全教材の学習開始 |
| 作業フォルダーを開く | 開いているフォルダーと、保存先を説明できる | 教材やプロジェクトの切替 |
| ファイルを作成・編集・保存する | index.htmlを保存し、閉じて開き直せる | HTML・CSS・JSの実装 |
| ブラウザで表示・更新する | 変更した見出しが表示される | 画面の制作と確認 |
| ターミナルを使う | 開いている場所を確認し、指定したコマンドを一つずつ実行できる | JSの実行、依存関係、開発サーバー |
| Node.js・npm・Gitを確認する | 教材で指定した版が使える | M03以降の実行と変更管理 |
| ローカルサーバーを起動・停止する | 表示されたURLでページを開き、停止後に再起動できる | Webアプリの開発 |
| 変更を記録・説明する | Gitの保存と差分を確認し、変更箇所を説明できる | 提出、レビュー、修正 |
| 困った状態を説明する | どこまで成功し、何が起きたかを短く伝えられる | 調査と相談 |

用語は行動の直前か直後に説明する。「フォルダー」は作業場所を開くとき、「拡張機能」はSTELLA拡張を入れるとき、「サーバー」はURLでページを表示するときに扱う。キーボードのショートカットを暗記することは進級条件にしない。

## 2 導入前から教材を読めるようにする

VS Code未導入の学習者は、ブラウザーの `/start` でU00・U01のスライドとまとめを読める。ログイン前の進捗は記録しない。導入中もブラウザーの案内と問い合わせ先を開いておける構成にする。

```text
ブラウザーで開始案内を読む
  → PCとOSを確認する
  → VS Codeを導入する
  → 日本語表示とSTELLA拡張を準備する
  → Webにログインし、U02の「VS Code で開く」を押す
  → 学習フォルダーを選び、課題文のパネルから進める
```

WebのレッスンとVS Codeの課題は同じ課題IDで結ぶ。「VS Code で開く」が発行する接続コードで拡張を接続する。認証情報を設定へ貼り付けさせない。閉じた後はWebのレッスンから開き直す。必要な導入ページは配布・印刷用にも出力する。

ブラウザーだけでは、ローカルのソフトウェアやファイルの状態を十分に確認できない。導入前は学習者の確認と講師の支援を使い、拡張が起動した後に、信頼した学習フォルダーで固定の手順による環境診断を行う。

## 3 標準環境と導入の順序

Windowsを主教材の初期案とし、macOSは独立した操作手順で用意する。受講者のOSを確定してから、対象OS・CPU・インストール方法と確認画面を制作する。WindowsとmacOSのコマンドや画面を一つの手順へ混在させない。

| 準備するもの | 導入する時点 | 設計上の扱い |
| --- | --- | --- |
| 既存のブラウザ | 開始前 | 研修で確認した対応ブラウザを案内する |
| VS CodeのStable版 | U01 | 研修で検証した版を記載し、公式配布元を案内する |
| 日本語表示 | U01 | 公式の表示言語手順に沿い、Language Packを確認する |
| STELLA拡張 | U01 | Visual Studio Marketplaceで公開済み。拡張ID `saedgewell.stella-lms`・発行者 `saedgewell` を指定する |
| Node.jsとnpm | 最初のHTML表示後、U05 | 検証したLTSの具体的な版をコース環境へ登録する。既存の適合版は再インストールしない |
| Git | U06 | 採用する版と公式の導入手順を記載する |
| ローカルサーバー用スターター | U07 | 研修側が準備し、起動方法と依存関係を固定する |

最初のHTML表示までは、ブラウザとVS Codeで進める。React、Next.js、DB、Docker、WSL、GitHubへの公開は、それを必要とする後続教材で導入する。最初の単元で用途がまだ分からない設定を大量に行わせない。

WindowsのVS Code導入は、通常の個人用環境では公式のUser setupを入口にする。会社が管理する端末では、研修担当者が認められた導入方法を先に確認する。[VS CodeのWindows向け導入資料](https://code.visualstudio.com/docs/setup/windows)はUser setupとSystem setupを区別している。

学習フォルダーは、学習者が書き込める自分のユーザーフォルダーに`web-training`を作る。講師は実際の端末で場所を確認する。教材に出す絶対パスのユーザー名は例であることを明示し、その文字列をそのまま作らせない。

Windowsの主教材はPowerShell、macOSは研修で検証したシェルを使う。ターミナルの種類は画面上に表示する。Windowsでnpm.ps1の実行制限が起きる場合に備え、PowerShell向け手順ではnpm.cmdを使う方法を用意する。組織の設定や実行ポリシーを一律に変更させる手順にはしない。

## 4 見直しの方針

1. **Stellaの使い方を、このステージの背骨にする。** 1周目(読む → 問題 → VS Codeで課題 → 確認 → 提出 → 結果 → 星)を、ステージの最初の4〜5時間で自分の手で通す。
2. **機能は、初めて要る場面で教える。** ヒント、講師への相談、今日の復習、類題、確認A・B、腕試し、島は、最初の動画に詰めない。出てくる単元で短い動画と1行の説明を出す(§8)。
3. **動画は「見てから同じことをする」の前振りにする。** 1本1〜3分・1本1操作。見た直後に同じ操作を課題で行う。動画と同じ手順を、画像付きの本文でもたどれるようにする(§7)。
4. **失敗を一度体験させる。** 最初の課題では、何も直さずに「課題を確認する」を押し、通らない結果を読んでから直す。保存し忘れたときは、拡張の「保存して確認する / 保存せずに確認する」の確認が出る。
5. **後続のステージが前提にすることを、修了の条件と記録に入れる。** 学習フォルダー、Gitの学習リポジトリ、Node.js・npm・Gitの版、スキルIDを、M02以降がそのまま使える形で残す(§9)。

## 6 単元ごとの中身

形式はformat 2。1レッスンは60〜90分、1トピックは2〜3分のスライドか動画とする(07 §4.1)。OSで違う手順は `:::os` で分け、`pdfByOs: true` を残す。

### U00 Stellaで学ぶ流れと事前確認(1時間・公開)

- **目標:** 1つの課題がどう進むかを説明できる。自分のPC・OS・ブラウザーを確かめ、読む手順を選べる。
- **レッスン:**
  - Stellaで学ぶ流れ(Web収録の動画。スキルツリー → レッスン → 知識問題 → VS Codeで課題 → 確認 → 提出 → レビュー → 星)
  - 学習のペースと、1日の進め方(週35時間の既定、今日のプラン)
  - PC・OS・ブラウザーの確認(OSの選び方。Windowsは個人用か会社の管理端末か)
  - 困ったときの連絡先(ログイン前でも読める問い合わせ先)
- **課題:** 置けない(公開の単元のため。07 §12.2)。
- **Stellaの機能:** スキルツリー、ガイドの「次にやること」、学習のペース。

### U01 VS CodeとSTELLA拡張の準備(3時間・公開)

- **目標:** VS Codeを入れて日本語で表示し、STELLA拡張を入れ、Webの「VS Code で開く」から課題を開ける状態にする。閉じた後も同じ場所に戻れる。
- **レッスン:**
  - VS Codeを入れる(OS別。インストーラーの画面は自動で撮れないので、手で撮った画面と台本で作る動画。§10.4)
  - 日本語表示と、画面の名前(エクスプローラー、エディター、パネル)
  - STELLA拡張を入れる(マーケットプレイスから。拡張IDと発行者を示す)
  - 「VS Code で開く」で何が起きるか(VS Code収録の動画。ブラウザーの確認 → 拡張 → 学習フォルダーを選ぶ → 信頼の確認 → 課題文のパネル)
  - 学習フォルダー `web-training` の場所と中の並び(`<ステージ>/<単元>/<課題>/`)
  - Workspace Trustの意味(自分の学習フォルダーだけを信頼する。§12)
  - 閉じて再開する(VS Codeを閉じる → Webのレッスンから開き直す)
- **課題:** なし。接続できたかどうかは、U02の最初の課題を開けたかで確かめる。
- **Stellaの機能:** 拡張、接続コード、学習フォルダー、課題文のパネル。

### U02 はじめての課題を出す(3時間)

- **目標:** 配られたHTMLの見出しを変え、保存してブラウザーで確かめ、課題を確認して提出し、結果を読める。
- **レッスン:** 今の0-1(保存して表示を確かめる)を残し、次を足す。
  - 課題文のパネルの「進め方」と「いまここ」の読み方
  - 確認の結果の読み方(通らなかった項目、メッセージ)
  - 提出とAIのレビュー(結果が届く場所: 課題パネル、Webのレッスン画面の下、通知)
  - 星の進捗(レッスンと課題を1件ずつ数え、合格で済みになる)
- **課題:**
  - q01 最初のページ(今の課題を改修): まず何も変えずに確認して、通らない結果を読む → 見出しを変えて保存 → 確認 → 提出 → 結果を読む、の順を課題文に書く。
  - q02 見出しをもう一度変える(反復): 別の見出しで、同じ手順を自分だけで行う。
- **知識問題:** 保存とブラウザーの再読み込み、確認と提出の違い。
- **Stellaの機能:** 確認、提出、AIの一次レビュー、ヒントの段(q01はヒント2段のまま)、星の進捗。

### U03 画面とファイルの操作(5時間)

- **目標:** ファイルを作る・名前を変える・閉じて開き直す。開いているフォルダーと保存先を説明できる。
- **課題:** §6の基礎Q01(note.txtを作る)、Q02(閉じて開き直す)、Q03(名前を変える)、Q04(別のフォルダーを開く)、修正R02(違うフォルダー・ファイルを開いている状態を直す)。
- **Stellaの機能:** 今日の復習(U02の知識問題が翌日から出る)。ガイドの「次にやること」の先頭に出ることを、ここで初めて説明する。

### U04 ページを増やしてつなぐ(4時間)

- **目標:** 2つ目のページを作り、相対パスのリンクでつなぐ。表示結果から保存先と名前を照合して直せる。
- **課題:** 接続C01(U03のフォルダーへページを置く)、C02(2つのページをリンクでつなぐ)、修正R01(保存していない変更)、R03(ファイル名が違うリンク)。
- **Stellaの機能:** 修正課題の種類、ヒントの後の解答例、講師に相談(通らないまま聞く)、類題(合格した課題の別の問題が日を空けて出る)。

### U05 ターミナルとNode.js・npm(4時間)

- **目標:** ターミナルの場所を確かめ、指定したコマンドを1つずつ実行できる。Node.jsとnpmを入れ、教材の指定の版か確かめる。
- **課題:** 基礎Q06(現在の場所を確かめる)、環境診断(`env-diagnose`。Node.js・npmの版を環境定義と照合する。この単元ではGitを要件に入れない)。
- **注意:** WindowsはPowerShellで `npm.cmd` を使う手順を用意する。実行ポリシーを一括で変えさせない(§3)。
- **Stellaの機能:** 環境診断、相談の書き方(何をしようとしたか・どこまでできたか・実行した操作・出たメッセージ。§12)。

### U06 Gitで変更を残す(4時間)

- **目標:** 学習フォルダーをGitで管理し、変更を記録して、前後の差分を説明できる。
- **課題:** Gitを入れて環境診断(Gitを要件に入れる)、学習フォルダーで `git init`、名前とメールを学習リポジトリにだけ設定(`--global` を使わない)、add・commit、diff・logで変更を説明する。
- **注意:** GitHub・push・PRは扱わない(07 §3.5。`ui-integration-basics` で扱う)。
- **Stellaの機能:** 説明を添えた提出(`submit.explanation`)。

### U07 ローカルサーバーで開く(3時間)

- **目標:** 提供スターターを起動し、表示されたURLで開き、停止・再起動できる。ファイルを直接開くこととURLで開くことの違いを説明できる。
- **課題:** 提供スターターを起動し、ページを変えて表示を確かめ、停止する。動作は機械で確かめにくいので、確認の結果に加えて説明を添えて出す。
- **Stellaの機能:** 手元の確認と、説明・レビューで見る部分の分担。

### U08 まとめと確認A(4時間)

- **目標:** 新しい練習フォルダーで、初めて見る短いページの仕様を、保存・表示・変更・実行・記録まで自分で行える(§13)。
- **課題:** 自力S01(別の練習フォルダーで「学習予定」のページ)、S02(閉じた状態から再開して変更)、統合T01(スターターを起動し、ページを変えて差分を残す)、確認A。
- **Stellaの機能:** 確認A(未見の課題、参照してよいもの)、確認Bの予告(合格の7日後)、修了と修了証、次の星と島が現れること、腕試し。

### 横断(4時間)

OSとファイル(拡張子、パス)、Webのしくみ(ファイルとHTTPの入口)、記録の残し方(学習記録、相談)、復習。知識問題を中心にし、単元の間に置く。

### 課題IDと操作の対応

M01にも、基礎課題、接続練習、自力演習、修正演習を用意する。OS上の削除や移動の演習は、作り直せる練習ファイルに限定する。

| 種類 | 課題の例 | 今回確かめること |
| --- | --- | --- |
| 基礎Q01 | note.txtを作り、一行書いて保存する | 作成・入力・保存 |
| 基礎Q02 | 閉じたnote.txtを再度開く | タブを閉じることとファイルの削除の違い |
| 基礎Q03 | 練習ファイルの名前を変える | ファイル名と拡張子 |
| 基礎Q04 | practice-aとpractice-bを別々に開く | 作業フォルダーの切替 |
| 基礎Q05 | 見出しだけを変え、保存・更新する | 編集・保存・表示の関係 |
| 基礎Q06 | ターミナルの現在の場所を確認する | ファイルの保存場所とコマンドの実行場所 |
| 接続C01 | U03で作ったフォルダーへU02のページを置く | ファイル操作とHTML表示 |
| 接続C02 | 二つのページをリンクでつなぐ | 名前・位置・相対パス |
| 自力S01 | 別の練習フォルダーで「学習予定」のページを表示する | 手順を組み合わせて再現する |
| 自力S02 | アプリを閉じた状態から作業を再開し、内容を変更する | 翌日の再開 |
| 修正R01 | 保存されていない変更を表示させる | 未保存とブラウザ更新 |
| 修正R02 | 違うフォルダー・違うファイルを開いている状態を直す | 対象の確認 |
| 修正R03 | ファイル名が違うリンクを直す | 表示結果から保存先・名前を照合する |
| 統合T01 | 提供スターターを起動し、ページを変更して差分を残す | フォルダー、実行、表示、変更管理 |

ファイル名や文章を変える小さな反復から始める。反復で扱った操作を、別題材の自力演習と後日の確認へつなぐ。すべてのインストールを繰り返すことは求めない。

## 7 一つの操作を説明する形式

一つのステップは通常5〜10分の小さな操作にする。インストールのダウンロードや待機は別に扱う。クリックごとに大量の試験を置かず、作業フォルダーを開く、保存する、表示する等の意味のある節目で確認する。

| 画面に載せる項目 | 内容 |
| --- | --- |
| 今回すること | 「学習用のフォルダーを開く」等、一つの行動 |
| 始める状態 | どのアプリを開き、どの画面から始めるか |
| 操作 | メニュー名、クリックする場所、入力する文字。最初はメニュー操作を主にする |
| 操作例の画像 | 対象OS・表示言語・確認した版で撮影し、操作箇所を示す |
| こうなれば完了 | 保存先、表示された文字、URL、版等の観察できる結果 |
| よくある違い | 想定と異なる画面と、元の状態へ戻る方法 |
| 小さな練習 | ファイル名や文章を変え、同じ操作を再度行う |
| 参照元 | 公式ページの該当節、確認日、教材独自の判断 |

画像の中だけに操作内容を書かず、本文にもメニュー名と入力内容を記載する。小さい画面では画像を拡大できるようにする。動画を付ける場合も、静止画と短い手順で同じ操作をたどれるようにする。

コードやコマンドにはコピー用のボタンを付ける。コピーする範囲へプロンプト記号や実行結果を混ぜない。実行結果は別の枠へ置き、版やパスが学習者によって違う箇所を説明する。最初は一つのコマンドを実行し、結果を読んでから次へ進む。

### 保存と更新のステップ例

| 項目 | 学習者に見せる内容 |

## 10 使い方動画(Sen方式)

### 10.1 3種類の動画

| 種類 | 作り方 | 例 |
| --- | --- | --- |
| A Webの操作 | Senと同じ。本番と同じビルドを、台本(シナリオ)どおりにヘッドレスのChromiumで操作して撮る | Stellaで学ぶ流れ、結果を見る、今日の復習 |
| B VS Codeの操作 | Aと同じ台本の書き方で、VS Code(Electron)をPlaywrightで操作して撮る | 課題を開く、確認と提出、環境診断 |
| C OSとインストール | 自動では撮れない。手で撮った画面と台本(`narration.json`)から、今の `build-video.ts` で作る | VS Codeを入れる(Windows・macOS)、Node.jsを入れる |

ナレーションは3種類とも同じTTS(Gemini)と声にそろえる。

### 10.2 Webの収録(A)

Senの `tutorials/` から、次をそのまま持ってくる。

- 台本の書き方: 1ファイル1本の `defineScenario`、操作API(`t.caption`・`t.click`・`t.type`・`t.highlight`・`t.expect`・`t.poster` など)
- 画面に重ねる表示: カーソル、クリックの波紋、押したキー、ステップ番号付きの字幕
- 録画: CDPのスクリーンキャスト → ffmpegでH.264
- ナレーション: Gemini TTS、まとめ読み、キャッシュ、記号の読み替え、`say`
- `t.expect` が1つでも外れたら動画を書き出さない(壊れた画面の動画を出さない)
- `manifest.json` に、チャプターの時刻と、収録したときの画面のハッシュ(`sourceHash`)を残す
- `tutorials:check` で、画面か台本が変わったのに撮り直していない動画を一覧にする

Stellaで変えること:

| 項目 | Sen | Stella |
| --- | --- | --- |
| ログイン | 開発用のサインインAPI | 開発用トークン(`AUTH_JWT_SECRET` で作り、`stella_auth_token_v1` に入れる)。`smoke:core` と同じ |
| データ | シナリオごとに `/api/dev/seed-demo` で初期化 | シナリオごとに一時のD1へ migrate・seed し直す。初めての人は `seed-learner2` を使う |
| 要素の指定 | `data-testid` | 今のWebには `data-testid` が1つも無い。台本が触る要素に足す |
| 置き場所 | `public/tutorials/`(Static Assets) | Senと同じ。台本と仕組みは `apps/web/scripts/tutorials/`、動画・サムネイル・字幕・`manifest.json` は `apps/web/public/tutorials/`(Webの Static Assets。CSPの `media-src 'self'` で読める)。1本あたり数MBで、Static Assetsの1ファイルの上限(25MiB)に収める。リポジトリが重くなったら、教材のR2へ移す |

### 10.3 VS Codeの収録(B)

- Playwrightの `_electron` でVS Codeを起動し、`--extensionDevelopmentPath` でSTELLA拡張を読み込む(VS Code自身の自動テストと同じやり方)。Linuxの収録環境ではxvfbで動かす。
- ローカルのAPI(`dev:api`)と開発用トークンで接続し、一時の学習フォルダーを使う。
- ブラウザーの「VS Codeを開きますか」の確認はOSの画面なので撮れない。その場面は静止画と字幕にする。
- 画面はメニュー操作を主にする(§7)。キーボードの表記がOSで違うためでもある。
- 実現できるかは最初に試作で確かめる(§18のフェーズ2)。できない場合は、code-server(ブラウザーで動くVS Code)で撮る案に切り替える。

### 10.4 OSとインストールの動画(C)

- 今の `build-video.ts`(スライドの見た目に読み上げを付ける)を使う。スライドに、各OSで手で撮った画面を載せる。
- 台本は `narration.json` と `NARRATION_GUIDE.md` の決まりで書く。TTSはGeminiに切り替え、A・Bと声をそろえる。
- 対象のOS・表示言語・版を画面ごとに記録し、VS Codeの版を変えたら撮り直す(§14)。

### 10.5 動画を出す場所

- **A・B(アプリの使い方):** 正本はアプリ側に1つだけ置く。このステージのレッスンは動画のIDで参照し、同じ動画を教材に複製しない。画面を変えて撮り直せば、レッスンの動画も新しくなる。あわせて、各画面のヘルプ(「?」)にもその画面の動画を出す。

### 11.3 最初のステージの到達リスト

共通の定数は `@stella/shared/study/first-steps` の `FIRST_STAGE_SLUG` と `FIRST_TASK_ID` (`dev-env-basics/u02-first-task/q01-first-page`)。

| 項目 (key) | 付ける根拠・日時 |
| --- | --- |
| 最初のレッスンを読む (`read-first-lesson`) | `dev-env-basics` のいずれかのレッスンの `lesson_progress.completed`。完了した行の最初の `updated_at` (完了専用の日時列はない) |
| VS Code とつなぐ (`connected-vscode`) | 本人の `auth_vscode_links.used_at` の最初の日時。使用済み・期限切れ行の定期削除はなく、現在はユーザー削除時に削除する |

| 最初の課題を提出する (`submitted-first-task`) | 最初の課題の本人の `submissions.task_id`。最初の `submitted_at` |
| 結果を受け取る (`got-result`) | 最初の課題の本人の提出に `verdict` があること (受講者向け提出 API と同じ確定条件。AI・人の合格・再提出・不合格)。最初の `reviewed_at`。判定日時がない旧記録は日時だけ null |

未達の最初の項目に「次はここ」と手順を1文で示す。全て済んだら「STELLA の使い方はひととおり済みました」の1行に畳む。取得に失敗したらカードを隠す。Web は達成を保存せず、API の結果をそのまま表示する。

講師・管理者は既存の「受講者の学習ペース」 (`LearningPaceManager`) で受講者を選ぶと、最初のステージの受講登録がある人だけの5項目を小さく確認できる。`GET /api/onboarding/first-steps/:userId` は `requirePaceLearner` で担当講師か管理者に限定する。つまずきの自動通知への追加は行わない。

### 11.4 初めの間は見せるものを絞る(試行後に判断)

07 §12.1の試行の結果を見てから決める。最初の課題に合格するまで、ホームのレベル・XP・集中・島・キュー・腕試しを隠すか小さくする。

## 12 よくあるつまずきと支援

| 現象 | 最初に確認すること | 教材で示す復帰方法 |
| --- | --- | --- |
| VS Codeの画面が例と違う | OS、表示言語、開いているビュー | メニューから必要なビューを開く。色や位置の違いだけで誤操作としない |
| フォルダーが表示されない | 単独ファイルだけ開いていないか | 指定したフォルダーを開き直す |
| 変更がブラウザに出ない | 保存、更新、開いているファイルの場所 | 保存して更新し、URL・保存先を照合する |
| HTMLが文章として開く | ファイル名、拡張子、ブラウザへの関連付け | 保存した名前を確認し、ブラウザで対象ファイルを開く |
| nodeやgitが見つからない | 導入状態、PATH、導入前から開いているVS Code | 保存してVS Codeを再起動し、採用版を再確認する |
| npm.ps1を実行できない | WindowsのPowerShellでどのコマンドを実行したか | 検証済みのnpm.cmd手順へ案内する。制限の一括解除を求めない |
| STELLAが起動しない | 拡張ID・版、有効状態、必要なログイン、Workspace Trust | 該当する確認から一つずつ行い、ブラウザ版で案内を読む |
| npmの準備が失敗する | 作業フォルダー、package.json・lockfile、ネットワーク | 準備先と提供スターターの版を確認する。組織の接続条件は講師へ引き継ぐ |
| サーバーを開けない | 起動したターミナル、表示されたURL、停止、ポート競合 | 実際のURLを開き、登録した停止・再起動手順を使う |
| 端末の設定変更が必要 | 会社の管理方法、操作権限 | 研修担当者の導入支援へ回し、学習スキルの不合格にしない |

Workspace Trustは、自分で作った練習フォルダーや、出所を確認した研修資料を対象に説明する。すべてのフォルダーを一律に信頼させない。Restricted ModeではSTELLA拡張からプロセスを起動しない。[VS CodeのWorkspace Trust](https://code.visualstudio.com/docs/editing/workspaces/workspace-trust)を参照元にする。

相談欄は「何をしようとしたか」「どこまで成功したか」「実行した操作またはコマンド」「表示されたメッセージ」を記入する形式にする。添付する画面やログの範囲を指定し、不要なユーザー名・認証情報等は含めない。相談できることもM01の到達目標として扱う。

## 13 完了条件と進級

環境の準備は、VS Code、STELLA、作業場所、Node.js・npm・Git、提供スターターの起動を確認して完了にする。手動確認と自動診断は記録上で区別する。

確認Bは、VS Codeを閉じた状態から再開する別題材の短い課題にする。確認Aの手順を記憶しただけでは完了できないように、フォルダー名と変更内容を変える。参照や支援の扱いは[反復演習と評価](03-repeated-practice-and-assessment.md)を引き継ぐ。

環境に問題がある場合は環境支援へ回し、可能なブラウザ上の用語・歴史の学習を進める。自力操作の不足は、その操作を使う短い問題を追加し、別の仕様で再確認する。M02は環境準備と確認Aを満たして開始し、遅延確認Bの結果は後続の自力・統合課題の進行へ反映する。

### STELLAとの連携と導入の確認

各教材の環境定義には、拡張ID、採用版、導入目的、必要となる単元、必須・推奨・任意、依存パッケージ、参照元、確認日を登録する。STELLAは現在の課題で必要なものを示し、拡張の導入、有効状態、設定、操作確認を分けて記録する。任意拡張がないことを進級の不合格にしない。

STELLA拡張から別の拡張を操作する場合は、採用版の公開APIや利用可能なコマンドを確認する。対象が変わる内部コマンドの呼出しを当然の前提にせず、通常のTestingビュー、ターミナル、メニューからの操作も用意する。STELLAの学習画面を外部拡張の表示だけに依存させない。

公開前には、研修の標準Profileで整形・診断・プレビュー・テスト・教材表示が同時に使えることを確認する。拡張本体のIDと対象版、プロジェクト内の実行パッケージ、設定ファイル、CLIの結果を照合する。導入する拡張を追加する際は、各教材の参照元にも配布元と利用した節を登録する。
