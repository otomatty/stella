# 教材分割と学習順序

版 2.2  
[全体設計へ戻る](00-overall-design.md)

各パックの参照資料は[情報源と参照元の記載](05-sources-and-attribution.md)の対応表で選び、単元・課題ごとに読む箇所と利用目的を登録する。

カリキュラムは18の教材パックで構成する。各パックには前提、単元、繰り返す実装パターン、統合課題、自力確認を用意する。パックは個別に配信・改訂できるようにする一方、学習の依存関係と習得記録はコース全体で共有する。

## 1 教材の階層

| 単位 | 意味 | 例 |
| --- | --- | --- |
| コース | 卒業までの目標と評価基準 | Webフルスタック育成 |
| 教材パック | 配信と進級の単位 | JavaScript制御、React UI部品 |
| 単元 | 一つの主要な考え方を学ぶ単位 | 条件抽出、入力部品、削除確認 |
| 課題セット | 一単元内の例題、反復、接続、確認 | ボタンの状態を6問で実装する |
| 課題 | 仕様と評価が一組になった単位 | 送信中のボタンを実装する |

単元の想定時間は通常3〜6時間、画面・APIとの統合では6〜10時間を初期案とする。各パックの時間には基礎知識、読書、調査、評価も含む。単元数と全問題数は、前提スキルと初回試行の所要時間から決める。

## 3 各教材の単元と接続

### M01 開発環境とWebの入口

VS Code未経験者を対象に、ブラウザで読める導入案内から始める。単元は、事前確認、VS CodeとLXPの準備、画面とファイル、最初のHTML、ターミナルとNode.js・npm、Git、提供サーバー、統合と自力確認へ分ける。最初にページの保存・表示・変更を体験し、その後に必要な環境を準備する。

ファイルの作成・保存・再開、フォルダー切替、表示更新、現在の場所の確認を繰り返す。修了確認は、新しい練習フォルダーで提示されたページを作り、表示・変更・実行して差分を説明すること。環境の導入完了と、自力操作の確認A・後日の確認Bを区別する。時間、操作例、支援、LXPの要求は[M01の詳細設計](06-m01-beginner-setup-and-basic-operations.md)に定める。

### M02 HTML CSSとデザイン基礎

単元は、見出しと情報構造、リンク・画像・一覧、フォーム、ボックスモデルとカスケード、Flexbox・Grid、画面幅への対応、余白・文字・色の規則とする。

ボタン、入力欄、カード、通知、表を静的な見本から繰り返し作る。文章量や画面幅を変え、崩れを直す。統合課題は案内サイトで、確認課題は別の画面仕様を提示する。部品の意味とデザイン規則をM05、M06、M09で使い直す。

### M03 JavaScriptの値と制御

単元は、値・変数・型、演算と変換、比較と条件、条件の組合せ、ループ、文字列、処理の追跡とデバッグとする。一つの実装パターンを8〜12問で練習し、境界と例外的な入力を変える。

料金、送料、点数、件数、コードの検査など、小さい入力・出力の問題を使う。DOMやReactを使わず、処理を自分で組み立てられることを確認する。次にM04のデータ処理とM05の画面条件へ接続する。

### M04 JavaScriptのデータ 関数 状態

単元は、配列の走査・抽出・集計、オブジェクト、引数と戻り値、スコープと参照、純粋な計算と副作用、状態更新、探索・整列・計算量の入口とする。

前に学んだ条件とループを使い、得点、購入明細、貸出データ等を扱う。検証関数と検索関数を成果物として残し、M05〜M10のフォーム・画面で再利用する。自力確認には別データと別の集計条件を使う。

### M05 DOMと画面操作

単元は、要素の取得、表示更新、イベント、入力の取得、配列から一覧を描画、入力検証、状態と表示の同期、モジュールと単体テストとする。

表示する値、入力欄、絞り込み条件を変えた基礎課題を繰り返す。接続課題でM04の検索・検証関数を使う。統合課題はタスク一覧または備品検索とし、修正演習でイベントの重複、古い表示、空データの問題を扱う。

### M06 HTMLとJavaScriptのUI部品

単元は、操作ボタン、入力とエラー、チェック・選択、開閉、確認ダイアログ、通知・空状態、部品を組み合わせたフォームとする。

HTML標準要素を土台に、DOMイベントと状態を付ける。まず同期処理のフォームを完成させ、M07で実際の通信待ちと失敗を加える。複雑な操作では標準要素や適切な実装を使い、操作とフォーカスの確認を学ぶ。

### M07 HTTP 非同期 TypeScript

単元は、HTTP契約、JSON、Promiseとasync/await、fetch、待機・成功・失敗、応答競合、型と絞り込み、外部データの実行時検証とする。

提供APIとローカルの疑似応答を使う。取得、送信、空データ、失敗、再試行を小課題で繰り返し、M06のフォームを通信に接続する。環境の不具合と学習者のコードの失敗を区別して評価する。

### M08 Reactの基礎と状態

単元は、JSX、props、一覧とkey、state、イベント、制御された入力、状態共有、導出値、必要な副作用とする。

既知のHTMLや関数を再利用して、カウンター、検索、入力、選択等を繰り返し作る。M05の画面をReactへ移す演習と、別題材の自力演習を両方行う。データと状態を持つ場所を説明して確認する。

### M09 ReactのUI部品とデザイン規則

単元は、Button、TextField、Select、Checkbox、Card・Badge、通知・空状態、ダイアログ、部品の仕様と状態見本、デザイントークン、ライブラリの利用と調整とする。

単純な部品は自分で作り、props・イベント・状態の変化を練習する。複雑な操作の部品は、標準要素や既存ライブラリを用い、その契約、キーボード操作、テーマとの対応を確認する。Storybook等で部品の状態を一覧にし、他の画面で再利用する。

### M10 UIと既存機能の連携

単元は、既存コードの調査、入力フォームとAPI、編集、削除確認、検索・並び替え・ページ切替、権限による表示、非同期の結果と画面更新、統合テストとする。

提供済みのAPI契約を使用して、部品を既存の一覧や編集画面に組み込む。既存機能が壊れていないことも確認する。権限による表示はここで学び、サーバー側の正式な認可はM13で実装・確認する。

### M11 Node.jsとAPI

単元は、Node.jsとブラウザ、依存関係、ルートとHTTP、検証、ミドルウェア、エラーとログ、APIテストとする。

M10のAPI契約を自分のAPIで実装する。APIを置き換えても、UI部品と主要な画面操作を保つ。Expressを主教材、HonoをM17の比較教材とする初期案を引き継ぎ、採用先に応じて主従を変更できるようにする。

### M12 SQLとデータベース

単元は、ER図、主キー・外部キー・一意制約、CRUD、JOINと集計、索引、トランザクションと更新競合、マイグレーションとする。

SQLの小課題を繰り返した後、M11の保存先をメモリからDBへ置き換える。空データ、重複、更新競合をUIからも確かめ、表示だけでは守れない整合性を説明する。

### M13 認証 認可 セキュリティ

単元は、認証と認可、セッションとCookie、利用者ごとの対象データ、管理操作、脆弱性、秘密情報、権限テストとする。

未ログイン、他の利用者、管理者、権限不足等の組合せを反復する。ボタンを隠すことと、APIが操作を拒否することを別に確認する。UIの失敗表示と、サーバー側の権限検証を結び付ける。

### M14 Next.jsとWebアプリ構成

単元は、ルート、ServerとClient Components、描画とデータ取得、キャッシュ、公開と個人情報の境界、エラー表示とする。

M10のUI部品とM11〜M13のAPI・DB・認可を保って移行する。業務処理を重複実装せず、画面側とサーバー側の責務を説明する。ルートの追加、個人データの表示、更新後の再表示を反復する。

### M15 要件 設計 品質と改善

単元は、受入条件と非機能要件、モデルとADR、変更の影響、リファクタリング、性能測定、レビューとする。このパックだけで設計・テストを初めて教える構成にせず、前の各パックの実践を整理する。

既存画面への仕様変更と、計測した性能問題を題材にする。見た目、部品契約、API、DBに変更がどう波及するかを調べ、既存テストを使って改善する。

### M16 公開 CIと運用

単元は、Linuxとプロセス、設定と秘密情報、ビルドとCI、公開とHTTPS、ログと監視、バックアップと復元、切戻しとする。

新しい環境での起動と公開を繰り返す。UIの実行時設定、API接続、権限、キャッシュも確認する。障害課題では画面の現象からログや通信を追い、原因を特定して復旧する。

### M17 未知のコードと技術の比較

単元は、構成の調査、処理の追跡、不具合の再現、最小の変更、回帰テスト、API実装の比較とする。

初めて触るプロジェクトの画面やUI部品を変更する。複数のフレームワークを使ったAPIでも、契約・検証・認可・テストがどう対応するかを説明する。

### M18 個人でのフルスタック開発

33週目に要件と画面・データ・構成を設計し、34週目に主要フローを通す。35週目に品質、権限、公開、復旧を整え、36週目に未見の追加要求と不具合に対応する。

卒業制作は共通演習と異なる業務を扱う。画面を構成する部品を自分で選び、デザイン規則と状態一覧を作り、API・DBと接続する。必須スキル、別題材への適用、遅延確認と運用の証拠を卒業判定に使う。

## 5 基礎知識 読書 技術史の教材

基本情報の基礎、品質の用語、指定書籍の読書、技術史は、短い関連教材として分割して管理する。必要なパックの単元からリンクし、実装の問題を観察した後に仕組みを説明する。

| 関連教材 | 主に結び付けるパック | 学習の証拠 |
| --- | --- | --- |
| コンピュータとOS | M01、M11、M16 | ファイル、プロセス、権限、実行環境の説明 |
| 数・論理・データ構造 | M03、M04、M12 | 手で追った処理、計算量、検索・整合性の判断 |
| UIと情報設計 | M02、M06、M09、M10 | 利用者の操作、画面規則、状態、改善 |
| ネットワークとWeb | M07、M11、M14、M16 | 通信観察、HTTP契約、Cookie、公開の説明 |
| DBとセキュリティ | M12、M13、M16 | 制約、認可、障害と復旧の確認 |
| 開発・管理・戦略・法務 | 全期間、M15、M18 | 要件、見積り、業務価値、費用、ライセンス等のケース演習 |
| 指定書籍と品質用語 | 各パックとM15 | 自分の実装や設計で考え方を使った記録 |
| 技術の変遷と調査 | M02、M07〜M09、M14、M16、M17 | 過去と現在の方式の比較、一次資料、実験と判断 |

指定書籍と基本情報の参照範囲は初回案を引き継ぐ。公開前に全項目の対応台帳を新しい教材IDで作成し、実装だけでは触れにくい知識は独立した演習で補う。
