# LXPカリキュラム改訂案の全体設計

作成日 2026年10月4日  
版 2.2  
状態 設計案

プログラミング未経験者が、小規模なWebアプリの要件整理、デザイン、実装、テスト、公開、保守を自ら進められることを目標とする。今回の改訂では、UIコンポーネントの実装と既存機能との連携を明示し、基礎演習を繰り返す学習単位にカリキュラムを分割する。

教材は18パックに分ける。それぞれのパックを短い単元に分け、各単元で解説、基礎課題、接続練習、自力演習、修正演習、統合課題、未見の確認、後日の復習を行う。前の教材のスキルとコードを使い、同じ考え方を別の題材でも確認する。

標準案は週35時間、36週間、1,260時間とする。初回案の32週間に対し、JavaScriptの反復とUIの部品・画面統合に時間を追加する。設計と品質の学習は全教材へ分散し、後半の専用週ではそれまでの判断を整理する。時間は計画値として試行で調整し、必須の自力確認が終わったことを進級の条件にする。

## 3 学習の進み方

学習者は、最初に一つの処理や部品を作り、入力や状態を変えた基礎課題を繰り返す。次に既習の処理と接続し、別題材で自力実装する。壊れた実装を直した後に、既存画面へ組み込む。その場で動くことと、後日も使えることを別々に確認する。

```text
解説と小さな例
  → 同じ実装パターンの基礎課題
  → 既習内容との接続練習
  → 自力演習と修正演習
  → 部品や機能の統合
  → 未見の確認A
  → 時間を空けた確認B
```

全期間を一つのアプリだけで学ぶ構成にはしない。配列の集計では得点や購入明細、DOMではタスクや検索、Reactでは備品やイベントなどの小題材を使う。節目には以前作ったアプリを再利用し、別の題材を挟んでも知識がつながるようにする。

## 4 UIの学習を積み上げる例

「登録フォーム」は次のように繰り返し扱う。毎回新しい仕組みを一つずつ増やし、既習の検証関数や表示部品を使う。

| 教材 | 今回実装するもの | 使い直す内容 |
| --- | --- | --- |
| M02 | ラベル、入力、ボタン、説明文と余白 | HTMLの構造、CSSの規則 |
| M03〜M04 | 必須、文字数、数量等の検証関数 | 型、条件、文字列、関数 |
| M05〜M06 | 入力イベント、エラー、確認ダイアログ | フォーム、検証関数、DOM |
| M07 | 送信、待機、成功、失敗 | フォーム状態、HTTP、非同期、型 |
| M08〜M09 | Reactの入力部品とフォーム | 状態モデル、検証関数、表示規則 |
| M10 | 既存の一覧・編集・通知との連携 | props、イベント、API契約、再取得 |
| M11〜M13 | 自分のAPI、DB、利用者の権限 | 画面の操作、入力・出力契約 |
| M14〜M18 | Next.js、公開環境、仕様変更 | 部品、業務処理、テスト、運用 |

単純なHTML要素を使う部分から始め、Reactでは状態を持つ場所と部品間のデータの流れを扱う。[React公式の状態共有の説明](https://react.dev/learn/sharing-state-between-components)を教材制作時の参照先にする。

## 5 到達目標と時間

卒業時には、利用者の目的を画面と操作に落とし込み、部品の仕様、状態、データ、API、DB、認可を結び付けて実装できることを求める。資料を調べ、テストと操作確認を行い、公開後の障害や追加変更にも対応する。

UIについては、見た目の再現、部品単体の実装、既存機能との連携、操作とアクセシビリティの確認をそれぞれ評価する。美的な好みではなく、提示されたデザイン規則、情報の優先度、入力・失敗時の理解しやすさ、操作の成立を判定する。

週35時間の通常配分は、実装20時間、基礎知識5時間、書籍と品質3時間、技術史と調査3時間、確認・レビュー4時間とする。36週間ではそれぞれ720、180、108、108、144時間となり、合計1,260時間になる。卒業制作では配分を調整して制作に結び付ける。

週30時間なら42週間、週40時間なら約32週間が目安となる。補習の2〜4週間は別枠で確保する。過去に確認できたスキルは開始診断で確かめ、重複する説明や支援付きの練習を減らせる。重要な未見・遅延確認は維持する。

## 6 最初に制作して試す範囲

最初の試行は、M01の導入案内からVS Code内のLXPでの学習開始、保存・表示・変更、翌日の再開までを通す。VS Code未経験者の操作と、環境の不具合による支援を分けて観察する。

続いて、JavaScriptの「条件抽出」、HTML・DOMの「入力とエラー」、Reactの「入力部品とフォーム」の代表単元を作る。同じスキルがどこで再利用されるかと、実装パターンを繰り返す問題量を確認する。Reactの学習試行は前提スキルを満たす学習者に行う。

LXPでは、一単元の解説、基礎課題、接続練習、提出、修正、確認A、後日の確認Bまで通す。単一の課題だけの完了率ではなく、別題材への適用、支援量、復習後の実装、既存コードへの接続を観察してから教材制作を広げる。
