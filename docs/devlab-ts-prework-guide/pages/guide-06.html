06章 クラス

q01 クラスの基本

クラスを書きます。クラスは、値（フィールド）と、その値を使う処理（メソッド）をひとまとめにした設計図です。ドリル 1 問（1 つのファイルに 20 個のクラス）を確認して提出してから、応用に進みます。フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。フィールドの値は、constructor の中で this.x = x; のように入れるか、count = 0 のように初期値を書きます。private などの印は q02 で学ぶので、ドリルでは何も付けません。

ドリル20 個のクラスを書く 新しく出てくる書き方：class、export class、new とインスタンス、フィールド、constructor、this、メソッド、フィールドの初期値、.shift()、クラスの名前を型に使う 
// 問1 Point(x, y)。フィールド x と y。label() で "(1, 2)" を返す
//     例: new Point(1, 2).label() → "(1, 2)"
export class Point {}

// 問2 Rect(width, height)。area() で面積を返す
//     例: new Rect(3, 4).area() → 12
export class Rect {}

// …（問20 まで、同じ形で続きます）

1 つのファイルに、クラスを 20 個書きます。ファイルには、export class Point {} のように、中身が空のクラスが並んでいます。{} の中に、フィールド・constructor・メソッドを書き足します。Point(x, y) のように名前の後ろにかっこがあるものは、constructor でその値を受け取ります。かっこがないものは、constructor を書かず、フィールドに初期値を書きます。

フィールド、constructor の引数、メソッドの引数と戻り値には、型注釈を付けます。private などの印（アクセス修飾子）は q02 で学びます。ここでは何も付けません。テストは、値のほかに型も確かめます。

新しい書き方

export class Item { … }

クラスとインスタンス（設計図と、そこから作ったもの）

クラスは、同じ形のオブジェクトをいくつも作るための設計図です。class の後ろにクラスの名前を書き、{ } の中に、持たせる値（フィールド）と、できること（メソッド）を書きます。クラスの名前は、Item のように大文字で始めます。

クラスからオブジェクトを作るには、new クラスの名前(…) と書きます（new は 01章 q04 問8 の new Error() で出ました）。こうして作ったオブジェクトを、そのクラスのインスタンスと呼びます。1 つのクラスから、インスタンスはいくつでも作れます。

前に export を付けると、ほかのファイルからもそのクラスを使えます。export function（00章 q01）と同じ考え方です。テストはクラスを読み込んで new するので、export は消さずに残します。

サンプル 
// クラス Item を作る。ほかのファイルから使えるようにする
export class Item {
  // 文字列のフィールド name を作る
  name: string;
  // 数値のフィールド price を作る
  price: number;

  // constructor を作る。文字列の name と数値の price を受け取る
  constructor(name: string, price: number) {
    // 自分の name に name を入れる
    this.name = name;
    // 自分の price に price を入れる
    this.price = price;
  }
}

// pen を作り、Item に "ペン" と 120 を渡して new で作ったインスタンスを入れる
const pen = new Item("ペン", 120);
// note を作り、Item に "ノート" と 200 を渡して new で作ったインスタンスを入れる
const note = new Item("ノート", 200);
// 結果: pen.name は "ペン"、note.price は 200

インスタンスのフィールドは、オブジェクトのプロパティ（02章 q01 問1）と同じく、pen.name のように . で読めます。

pen.name
"ペン"
note.name
"ノート"
同じクラスでも、値は別々
pen.price + note.price
320

よくある間違いItem("ペン", 120) のように new を付けずに呼ぶと、型の確認でエラーになります。クラスからインスタンスを作るときは、必ず new を付けます。

サバイバルTypeScript「クラス」

name: string;

フィールド（インスタンスが持つ値）

クラスの { } のすぐ内側に 名前: 型; と書くと、フィールドになります。フィールドは、インスタンスが 1 つずつ持つ値の入れ物です。オブジェクトの型（02章 q01 問1）のプロパティと同じ書き方ですが、行の終わりに ; を付けます。

宣言しただけのフィールドには、まだ値が入っていません。値は、次の項目の constructor で入れます。

よくある間違いフィールドを宣言したのに、constructor で値を入れ忘れると、型の確認で Property 'name' has no initializer and is not definitely assigned in the constructor. というエラーになります。「name に初期値がなく、constructor でも値が入っていない」という意味です。

サバイバルTypeScript「フィールド」

constructor(…) { this.name = name; }

constructor（new のときに値を入れる）

constructor は、new でインスタンスを作るときに、1 回だけ自動で呼ばれる特別なメソッドです。new Item("ペン", 120) のかっこの中の値が、constructor の引数に順に入ります。constructor の中では、受け取った値をフィールドに入れます。

const pen = new Item("ペン", 120); は、次の順で進みます。

  1. 空のインスタンスフィールドにまだ値のない、新しいインスタンスが 1 つできます。
  2. constructor を呼ぶ引数の name に "ペン"、price に 120 が入ります。
  3. フィールドに入れるthis.name = name; などで、値がフィールドに入ります。
  4. 変数に入るできあがったインスタンスが pen に入ります。
this. を付けない
class Item {
  name: string;
  constructor(name: string) {
    name = name;
  }
}
✕ 引数に引数を入れ直すだけで、フィールドに値が入りません
this. を付ける
class Item {
  name: string;
  constructor(name: string) {
    this.name = name;
  }
}
○ 受け取った値がフィールドに入ります

コツ引数とフィールドに同じ名前を付けることがよくあります。this. が付いているほうがフィールド、付いていないほうが引数です。

サバイバルTypeScript「コンストラクタ」

label(): string { … }

メソッド（インスタンスができること）

クラスの中に 名前(引数): 戻り値の型 { … } と書くと、メソッドになります。メソッドは、クラスの中に書いた関数です。関数宣言（00章 q01）と同じ形で、前の function だけを書きません。呼ぶときは、インスタンスの後ろに . を付けて pen.label() と書きます。

サンプル 
// クラス Item を作る。ほかのファイルから使えるようにする
export class Item {
  // 文字列のフィールド name を作る
  name: string;
  // 数値のフィールド price を作る
  price: number;

  // constructor を作る。文字列の name と数値の price を受け取る
  constructor(name: string, price: number) {
    // 自分の name に name を入れる
    this.name = name;
    // 自分の price に price を入れる
    this.price = price;
  }

  // メソッド label を作る。何も受け取らず、文字列を返す
  label(): string {
    // 自分の name と自分の price を埋め込んだ「◯（◯円）」の文字列を返す
    return `${this.name}（${this.price}円）`;
  }
}

サバイバルTypeScript「配列」

merge(other: Weight): Weight

クラスの名前を型に使う

クラスを作ると、クラスの名前をそのまま型として使えます。型 Weight は「Weight のインスタンス」という意味です。引数や戻り値に書けば、同じクラスのインスタンスを受け取ったり返したりするメソッドになります。メソッドの中で new Weight(…) と書けば、新しいインスタンスを作れます。

サンプル 
// クラス Weight を作る。ほかのファイルから使えるようにする
export class Weight {
  // 数値のフィールド grams を作る
  grams: number;

  // constructor を作る。数値の grams を受け取る
  constructor(grams: number) {
    // 自分の grams に grams を入れる
    this.grams = grams;
  }

  // メソッド merge を作る。Weight の other を受け取り、Weight を返す
  merge(other: Weight): Weight {
    // Weight に、自分の grams + other の grams を渡して new で作ったインスタンスを返す
    return new Weight(this.grams + other.grams);
  }
}

// 箱 box を作り、Weight に 300 を渡して new で作ったインスタンスを入れる
const box = new Weight(300);
// 合計 sum を作り、box の merge に、Weight に 200 を渡して new で作ったインスタンスを渡して呼んだ結果を入れる
const sum = box.merge(new Weight(200));
// 結果: sum.grams は 500、box.grams は 300

this.grams は呼んだインスタンス（box）の値、other.grams は引数で受け取ったインスタンスの値です。新しいインスタンスを返すので、box の値は変わりません。

型問17 と問18 のテストは、メソッドの型が (other: Money) => Money のように、受け取るものも返すものも、そのクラスであることを確かめます。

// クラス Bottle を作る。ほかのファイルから使えるようにする
export class Bottle {
  // 数値のフィールド amount を作る
  amount: number;
  // 外から読めず、入れ直せない数値のフィールド full を作る
  private readonly full: number;

  // constructor を作る。数値の full を受け取る。省略したら 500
  constructor(full = 500) {
    // 自分の full に full を入れる
    this.full = full;
    // 自分の amount に full を入れる
    this.amount = full;
  }

  // メソッド refill を作る。何も受け取らず、何も返さない
  refill(): void {
    // 自分の amount に自分の full を入れ直す
    this.amount = this.full;
  }
}

// 水筒 bottle を作り、Bottle に 350 を渡して new で作ったインスタンスを入れる

// bottle の amount に 100 を入れ直す
bottle.amount = 100;
// bottle の refill を呼ぶ
bottle.refill();
// 結果: bottle.amount は 350

  private shipped = 0;

q03 インターフェース

インターフェースを書きます。インターフェースは、オブジェクトが持つプロパティとメソッドの形に名前を付けたものです。クラスが形を満たすことは implements で示します。インターフェースは、オブジェクトや関数の引数の型にも使えます。ドリル 1 問（1 つのファイルに 20 問）を確認して提出してから、応用に進みます。インターフェースは export します。引数と戻り値には型注釈を付けます。応用には「説明すること」があり、ファイルの「説明すること」のすぐ下に // のコメントで書きます。

//     例: new Cat("ミケ").meow() → "ミケ: ニャー"
// ここに Named と Cat を書く

// …（問20 まで、同じ形で続きます）

q04 クラスの継承

あるクラスをもとにして、新しいクラスを作ることを継承と呼びます。もとのクラスを親クラス、新しく作るクラスを子クラスと呼びます。子クラスは、親クラスのフィールドとメソッドをそのまま受け継ぎます。そのうえで、違うところだけを書き足したり、書き換えたりします。ドリルは 1 つのファイルに 20 問あり、どの問も親クラスと子クラスを 1 組書きます。ドリルを提出してから、応用問題に進みます。フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。

ドリル親クラスと、それを継承した子クラスを書く 新しく出てくる書き方：extends、super(…)、override、super.メソッド名()、子クラスを親クラスの型で扱う、instanceof で子クラスを見分ける 
// 問1 Animal(name) の speak() は "…"。Animal を継承した Dog の speak() は "ポチ: ワン" を返す（name を使う）
//     例: new Dog("ポチ").speak() → "ポチ: ワン"
// ここに Animal と Dog を書く

子クラスの constructor では、最初に super(…) で親クラスの constructor を呼びます。親クラスのメソッドを書き換えるときは override を付けます。付けないと型エラーになる設定です。

  19. Collection はフィールド items（文字列の配列。最初は空）を持ち、add(item) で後ろに足します。何も返しません。UniqueCollection の add(item) は、すでに items にあるものは足しません。

新しい書き方

class 子 extends 親

親クラスを受け継いで、子クラスを作る

クラスの名前の後ろに extends 親クラスの名前 と書くと、親クラスのフィールドとメソッドをすべて受け継いだクラスになります。06章 q02 問20 で、少しだけ使いました。子クラスの { } に何も書かなくても、親クラスと同じように使えます。constructor も受け継ぐので、子クラスに constructor を書かなければ、親クラスと同じ引数で new します。

サンプル 
// クラス Member を作る
class Member {
  // constructor を作る。文字列の name を受け取り、入れ直せないフィールド name にする
  constructor(readonly name: string) {}

  // メソッド label を作る。文字列を返す
  label(): string {
    // this.name を埋め込んだ「◯ 様」の文字列を返す
    return `${this.name} 様`;
  }
}

// Member を継承したクラス PremiumMember を作る。中身は書かない
class PremiumMember extends Member {}

// premium を作り、名前を "佐藤" にした PremiumMember を入れる
const premium = new PremiumMember("佐藤");
// text を作り、premium の label を呼んだ結果を入れる
const text = premium.label();
// 結果: text は "佐藤 様"、premium.name は "佐藤"

よくある疑問受け継いだ label() の中の this は、呼んだインスタンスです。premium.label() なら、this.name は premium の name の "佐藤" です。

super(…)

子クラスの constructor で、親クラスの constructor を呼ぶ

子クラスに constructor を書くときは、その中で super(…) を呼びます。super は親クラスのことで、super(…) は親クラスの constructor を呼ぶ書き方です。かっこの中には、親クラスの constructor が受け取る引数を渡します。子クラスでは、受け取る引数の数を変えられます。親クラスに、決まった値を渡すこともできます。

サンプル 
// クラス Coupon を作る
class Coupon {
  // constructor を作る。文字列の code と数値の discount を受け取り、どちらも入れ直せないフィールドにする
  constructor(
    readonly code: string,
    readonly discount: number,
  ) {}
}

// Coupon を継承したクラス WelcomeCoupon を作る
class WelcomeCoupon extends Coupon {
  // constructor を作る。文字列の memberName を受け取り、入れ直せないフィールド memberName にする
  constructor(readonly memberName: string) {
    // 親の constructor に "WELCOME" と 500 を渡して呼ぶ
    super("WELCOME", 500);
  }
}

// welcome を作り、会員名を "佐藤" にした WelcomeCoupon を入れる
const welcome = new WelcomeCoupon("佐藤");
// 結果: welcome.code は "WELCOME"、welcome.discount は 500、welcome.memberName は "佐藤"

子クラスで受け取った値を、そのまま親クラスに渡すこともできます。親クラスに渡す引数には readonly を付けません。フィールドを作るのは、親クラスの constructor だからです。子クラスだけが持つ引数に、readonly を付けます。

サンプル 
// Coupon を継承したクラス LimitedCoupon を作る
class LimitedCoupon extends Coupon {
  // constructor を作る。文字列の code と数値の discount と文字列の until を受け取る。until を入れ直せないフィールドにする
  constructor(
    code: string,
    discount: number,
    readonly until: string,
  ) {
    // 親の constructor に code と discount を渡して呼ぶ
    super(code, discount);
  }
}

// limited を作り、"SUMMER" と 300 と "2026-08-31" を渡した LimitedCoupon を入れる
const limited = new LimitedCoupon("SUMMER", 300, "2026-08-31");
// 結果: limited.code は "SUMMER"、limited.discount は 300、limited.until は "2026-08-31"
super(…) を呼ばない
constructor(readonly memberName: string) {}
✕ 子クラスの constructor には super の呼び出しが要る、という型エラーになります
super(…) を呼ぶ
constructor(readonly memberName: string) {
  super("WELCOME", 500);
}

決まりsuper(…) は、constructor の最初の行に書きます。親クラスの constructor が引数を受け取らないときも、super() と、空のかっこで呼びます。

override

親クラスのメソッドを、子クラスで書き換える

子クラスに、親クラスと同じ名前のメソッドを書くと、子クラスのインスタンスではそちらが使われます。これを上書き（オーバーライド）と呼びます。上書きするメソッドの前には override を付けます。この課題の設定（tsconfig.json の noImplicitOverride）では、付けないと型エラーになります。

サンプル 
// クラス Shipping を作る
class Shipping {
  // メソッド fee を作る。数値を返す
  fee(): number {
    // 500 を返す
    return 500;
  }

  // メソッド label を作る。文字列を返す
  label(): string {
    // this.fee() の結果を埋め込んだ「送料 ◯円」の文字列を返す
    return `送料 ${this.fee()}円`;
  }
}

// Shipping を継承したクラス ExpressShipping を作る
class ExpressShipping extends Shipping {
  // 親の fee を上書きするメソッド fee を作る。数値を返す
  override fee(): number {
    // 800 を返す
    return 800;
  }
}

// normal を作り、新しい Shipping の label を呼んだ結果を入れる
const normal = new Shipping().label();
// express を作り、新しい ExpressShipping の label を呼んだ結果を入れる
const express = new ExpressShipping().label();
// 結果: normal は "送料 500円"、express は "送料 800円"

label は、親クラスにしか書いてありません。それでも express は "送料 800円" になります。メソッドを呼ぶと、まずインスタンスの子クラスから探し、なければ親クラスから探すからです。親クラスのメソッドの中の this.fee() も、同じ順に探します。

override を付けない
fee(): number {
  return 800;
}
✕ 親クラスのメンバーを上書きするので override が要る、という型エラーになります
override を付ける
override fee(): number {
  return 800;
}
○ 親クラスの fee を、子クラスで上書きします

決まり親クラスにないメソッドに override を付けても、型エラーになります。名前を打ち間違えたときに、気づけるようにするためです。上書きするメソッドの引数と戻り値の型は、親クラスのメソッドと同じにします。

`合計 ${super.total()}円`

super.total() と書く

const s: Shipping = new ExpressShipping()

子クラスは、親クラスのフィールドとメソッドをすべて持っています。そのため、子クラスのインスタンスは、親クラスの型の変数や配列に入れられます。親クラスの型で扱っても、メソッドを呼ぶと、そのインスタンスのクラスで上書きしたメソッドが使われます。

// 送料の配列 shippings を作る。型は Shipping の配列。Shipping と ExpressShipping を 1 つずつ入れる

// 結果: fees は [500, 800]

.splice()

配列から、位置を決めて要素を取り除く

配列.splice(位置, 個数) は、その位置から個数だけの要素を、配列から取り除きます。取り除いた要素は、新しい配列に入れて返します。元の配列そのものが変わります。.slice()（02章 q05 問3）は、元の配列を変えずに一部を取り出します。.splice() は、元の配列から抜き取ります。

// 待っている人の列 waiting を作り、"佐藤" と "鈴木" と "高橋" を並べた配列を入れる
const waiting = ["佐藤", "鈴木", "高橋"];
// removed を作り、waiting の 1 番目から 1 つを取り除いたものを入れる
const removed = waiting.splice(1, 1);
// 結果: removed は ["鈴木"]、waiting は ["佐藤", "高橋"]

ほかのクラスのインスタンスを、フィールドに持つ

フィールドの初期値には、new で作ったインスタンスも入れられます。こうすると、クラスの中で、ほかのクラスのメソッドを使えます。readonly は、フィールドに入れたインスタンスを入れ替えない、という意味です。インスタンスの中の値は、メソッドを呼ぶと変わります。

class Sequence {
  // 外から読めないフィールド last を作り、0 を入れる
  private last = 0;

  // メソッド next を作る。数値を返す
  next(): number {
    // this.last を 1 増やす
    this.last++;
    // this.last を返す
    return this.last;
  }
}

// クラス OrderBook を作る
class OrderBook {
  // 外から読めず、入れ直せないフィールド numbers を作り、新しい Sequence を入れる
  private readonly numbers = new Sequence();

  newOrderId(): string {
    // this.numbers の next を呼んだ結果を埋め込んだ「ORD-◯」の文字列を返す
    return `ORD-${this.numbers.next()}`;
  }
}

  //     parts の後ろに、this.count を埋め込んだ「LIMIT ◯」の文字列をつなげる
  //   parts の要素を " " でつないだ文字列を返す
}
ヒント 2コードへの直し方

created は、static なフィールドの項目の Ticket の issued と同じ形です。constructor の引数の名前は、getter の celsius とぶつからないように celsiusValue にします。fromFahrenheit は、static なメソッドの項目の Price.fromThousands と同じ形です。new Temperature(…) で作るので、created もそこで 1 増えます。celsius と fahrenheit の読み書きは、getter・setter の項目の Contract の years と同じ形です。計算は、先に掛けてから割る順で書くと、テストの値がちょうどになります。count は、値を入れずに private count: number | undefined; と書くと、最初は undefined が入ります。where と limit は、メソッドチェーンの項目の add と同じ形です。build の最後は .join(" ") です。parts が空なら空の文字列、1 つならその文字列だけになります。
