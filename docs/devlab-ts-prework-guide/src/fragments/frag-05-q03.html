05章 関数

q03 オプション引数

省略できる引数を使う関数を 20 個書きます。引数と戻り値には型注釈を付けます。問題文で「省略できる」と書いた引数は、title?: string のように、名前の後ろに ? を付けます。このような引数を、オプション引数と呼びます。省略された引数の値は undefined になります。そのため、関数の中では ??（02章 q02）か === undefined で扱います。times = 1 のように値を書く形（デフォルト引数）は q04 で学ぶので、ここでは使いません。

問1肩書きがあれば付け、なければ「さん」を付ける 新しく出てくる書き方：オプション引数 title?: string 
export function greetWithTitle() {}

名前 name と、省略できる肩書き title を受け取ります。title があれば、名前の後ろに肩書きを付けて返します。title がなければ、名前の後ろに "さん" を付けて返します。引数は文字列 2 つで、2 つめは省略できます。戻り値は文字列です。

テストで確かめる値
greetWithTitle("山田", "部長")
"山田部長"
greetWithTitle("山田")
"山田さん"
title を省略した

型引数が string と、省略できる string、戻り値が string であることも確かめます。

新しい書き方

days?: number

省略できる引数（オプション引数）

引数の名前の後ろに ? を付けると、呼び出す側がその引数を省略できます。省略されたとき、その引数の値は undefined です。

サンプル 
// 関数 shippingText を作る。文字列 city と、省略できる数値 days を受け取り、文字列を返す
function shippingText(city: string, days?: number): string {
  // city と、days（なければ 3）を埋め込んだ「◯まで◯日」の文字列を返す
  return `${city}まで${days ?? 3}日`;
}
// 結果: shippingText("大阪", 2) は "大阪まで2日"、shippingText("大阪") は "大阪まで3日"
shippingText("大阪", 2)
"大阪まで2日"
shippingText("大阪")
"大阪まで3日"
days は undefined なので、?? の右の 3 を使う

「なければ ◯、あれば ◯」と書き分けたいときは、=== undefined で調べます。条件演算子（01章 q01 問12）で書けます。if で書いてもかまいません。

サンプル 
// 関数 giftLabel を作る。文字列 item と、省略できる文字列 message を受け取り、文字列を返す
function giftLabel(item: string, message?: string): string {
  // message がなければ item、そうでなければ item と message を埋め込んだ「◯（◯）」の文字列を返す
  return message === undefined ? item : `${item}（${message}）`;
}
// 結果: giftLabel("花束") は "花束"、giftLabel("花束", "お祝い") は "花束（お祝い）"
days: number | undefined と書く
function shippingText(city: string, days: number | undefined): string {
  return `${city}まで${days ?? 3}日`;
}
shippingText("大阪");
✕ 型の確認でエラーになります。引数を省略できず、undefined を書いて渡す必要があります
days?: number と書く
function shippingText(city: string, days?: number): string {
  return `${city}まで${days ?? 3}日`;
}
shippingText("大阪");
○ days を省略して呼べます

よくある間違い関数の中で days + 1 のように、そのまま数として使うと、型の確認で「days は undefined かもしれない」というエラーになります。先に ?? か === undefined で、ない場合を扱います。

新しい書き方

{ item }

省略された値は、プロパティごと付けない

省略された引数をそのまま { item, note } に入れると、値が undefined の note というプロパティができます。「プロパティがない」ことと、「値が undefined のプロパティがある」ことは、別のものです。テストの toStrictEqual は、この 2 つを区別します。そこで、省略されたときは、そのプロパティを書かないオブジェクトを返します。

  return note === undefined ? { item } : { item, note };
}

note を付けない
makeOrder("本", "急ぎ")
{ item: "本", note: "急ぎ" }
いつも { item, note } を返す

  return { item, note };
}
// makeOrder("本") は { item: "本", note: undefined }
// Object.keys(makeOrder("本")) は ["item", "note"]
✕ 型の確認は通りますが、toStrictEqual は { item: "本" } と違うと判定します
省略されたら { item } を返す
