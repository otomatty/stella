07章 発展問題（任意）

発展問題

やってもやらなくてもよい、任意の課題です。章の課題とは別に数えます。番号の順に、1 問ずつ確認して提出します。e01 では、型のプロパティを 1 つずつ作り変える Mapped Types を書きます。e02 では、ユニオン型や関数の型から新しい型を作る、組み込みのユーティリティ型を使います。

e01Mapped Types 新しく出てくる書き方：Mapped Types { [K in keyof T]: … }、型アサーション 値 as 型 
export type Nullable = unknown;
export type Flags = unknown;
export type Getters = unknown;

export function allFlags() {}

export function toNullable() {}

型を 3 つと、関数を 2 つ書いて、ほかのファイルから使えるようにします。3 つの型には、型引数 <T> を自分で足します（07章 q06 問8 の Box<T> と同じ書き方）。unknown は書き換えます。

  1. Nullable<T>：T のすべてのプロパティの値の型を、「元の型 | null」にした型です。
  2. Flags<T>：T のすべてのプロパティの値の型を、boolean にした型です。
  3. Getters<T>：T のすべてのプロパティの値の型を、元の型の値を返す関数（() => 元の型）にした型です。
  4. allFlags(obj, value)：obj と同じキーを持ち、値がすべて value（true か false）のオブジェクトを返します。戻り値の型は Flags<T> です。T はオブジェクトに限ります。
  5. toNullable(obj)：obj と同じ中身のコピーを、Nullable<T> として返します。

新しい書き方

{ [K in keyof T]: … }

すべてのプロパティの型を作り変える（Mapped Types）

keyof T（07章 q02）のプロパティ名を 1 つずつ K に取り出し、それぞれの値の型を : の右に書いた型にした型を作ります。K は自分で付ける名前です。: の右では T[K]（元の値の型）も使えます。

サンプル 
// 型 Product を作る。price は数値、stock は数値
type Product = { price: number; stock: number };
// 型 ErrorMessages を作る。型変数 T を使い、T のプロパティ名を 1 つずつ K として、値をすべて文字列にした型
type ErrorMessages<T> = { [K in keyof T]: string };
// 型 Ranges を作る。型変数 T を使い、T のプロパティ名を 1 つずつ K として、値を { min: T[K]; max: T[K] } にした型
type Ranges<T> = { [K in keyof T]: { min: T[K]; max: T[K] } };
// errors を ErrorMessages<Product> として作り、price と stock のメッセージを入れる
const errors: ErrorMessages<Product> = {
  price: "価格を入れてください",
  stock: "在庫は 0 以上です",
};
// ranges を Ranges<Product> として作り、price と stock の下限と上限を入れる
const ranges: Ranges<Product> = { price: { min: 1, max: 99999 }, stock: { min: 0, max: 500 } };
// 結果: errors の型は { price: string; stock: string }、ranges の型は { price: { min: number; max: number }; stock: { min: number; max: number } }
ErrorMessages<Product>
{ price: string; stock: string }
値がすべて string
Ranges<Product>
{ price: { min: number; max: number }; stock: { min: number; max: number } }
T[K] は元の値の型
{ [K in keyof Product]: Product[K] }
Product
値の型を変えなければ、元と同じ型

よくある疑問07章 q03 の Partial<T> は、この書き方で { [K in keyof T]?: T[K] } と作られています。] の後ろの ? で、すべてのプロパティを省略できるようにしています。

サバイバルTypeScript「Mapped Types」

値 as 型

型を言い切る（型アサーション）

03章 発展問題 e02 で読んだ as を、この問で書きます。as は、「この値はこの型だ」と TypeScript に言い切る書き方です。Object.keys(value) の結果は string[] です（02章 q08 問4）。value が T でも、取り出したキーの型は keyof T になりません。そこで key as keyof T と書いて、T のプロパティ名だと言い切ります。

サンプル 
// 関数 keysOf を作る。型変数 T（オブジェクトに限る）を使い、T の value を受け取り、T のプロパティ名の配列を返す
function keysOf<T extends object>(value: T): (keyof T)[] {
  // 結果 result を作り、空の配列を入れる。型は T のプロパティ名の配列
  const result: (keyof T)[] = [];
  // value のキーを並べた配列から 1 つずつ key に取り出してくり返す
  for (const key of Object.keys(value)) {
    // result の最後に、key を T のプロパティ名と言い切ったものを付け足す
    result.push(key as keyof T);
  }
  // result を返す
  return result;
}
// keys を作り、keysOf に { pen: 12, note: 30 } を渡して呼んだ結果を入れる
const keys = keysOf({ pen: 12, note: 30 });
// 結果: keys は ["pen", "note"]。型は ("pen" | "note")[]
as を付けない
result.push(key);
✕ 型の確認でエラーになります。string は keyof T に入りません
as で言い切る
result.push(key as keyof T);
○ key を keyof T として扱えます

プロパティを 1 つずつ入れて作るオブジェクトにも使います。はじめは中身が空なので、Partial（07章 q03 問1）の変数に入れていきます。すべて入れ終えたら、as で元の型だと言い切ります。

サンプル 
// 型 Stock を作る。pen は数値、note は数値
type Stock = { pen: number; note: number };
// 在庫表 draft を作り、空のオブジェクトを入れる。型は Partial<Stock>
const draft: Partial<Stock> = {};
// draft の pen に 12 を入れる
draft.pen = 12;
// draft の note に 30 を入れる
draft.note = 30;
// stock を作り、draft を Stock と言い切ったものを入れる
const stock = draft as Stock;
// 結果: stock は { pen: 12, note: 30 }。型は Stock

よくある間違いas は言い切るだけで、中身は確かめません。上のサンプルで note を入れ忘れても、型のエラーになりません。as を書くのは、中身が合っていると自分で確かめられる所だけにします。

ヒント 2コードへの直し方

Nullable は、1 つ目のサンプルの Ranges と同じ形で、: の右が T[K] | null になります。Flags は ErrorMessages と同じ形で、: の右が boolean です。Getters の右は、引数のない関数の型 () => T[K] です（05章 q07 問1 の関数の型で、かっこの中を空にしたもの）。allFlags は、2 つ目の項目の 2 つのサンプルを合わせた形です。keysOf と同じく Object.keys(obj) を for-of で回し、draft と同じく Partial の変数に入れてから、最後に as Flags<T> で返します。toNullable は { ...obj } を返すだけです。T の値は、値の型に null を足しただけの Nullable<T> に、そのまま入ります。

e02Exclude・Extract・NonNullable・ReturnType・Awaited 新しく出てくる書き方：Exclude、Extract、NonNullable、Awaited 
export type Status = "draft" | "published" | "archived" | "deleted";
export type AppEvent = { type: "click"; x: number; y: number } | { type: "key"; key: string };
export type MaybeName = string | null | undefined;

export function createSession(userId: number) {
  return { userId, token: `t-${userId}`, expiresAt: 0 };
}

export async function fetchUser(id: number) {
  await Promise.resolve();
  return { id, name: "山田" };
}

export type ActiveStatus = unknown;

export type Session = unknown;

型 Status・AppEvent・MaybeName と、関数 createSession・fetchUser は書いてあります。次の 5 つの型を、それぞれのユーティリティ型を使って作ります。型の中身を手で書き並べてはいけません。unknown は書き換えます。

  1. ActiveStatus：Status から "archived" と "deleted" を除いた型です（Exclude）。
  2. ClickEvent：AppEvent のうち、type が "click" のものだけの型です（Extract）。
  3. Name：MaybeName から null と undefined を除いた型です（NonNullable）。
  4. Session：createSession の戻り値の型です（ReturnType、07章 q01 問12）。
  5. FetchedUser：fetchUser の戻り値は Promise（あとで値が届くことを表す値）です。その Promise が解決したあと（値が届いたあと）の値の型です（Awaited と ReturnType）。

最後に関数 isActive(status) を書きます。status が ActiveStatus なら true を返します。戻り値の型は status is ActiveStatus にして、型ガード関数（05章 q09 問1）にします。

新しい書き方

Exclude<T, U>

ユニオン型から、当てはまるものを除く

ユニオン型 T から、U に当てはまるものを除いた型を作ります。除くものが 2 つ以上なら、U にユニオン型を書きます。

サンプル 
// 型 Payment を作る。"card" か "cash" か "bank" か "points"
type Payment = "card" | "cash" | "bank" | "points";
// 型 OnlinePayment を作る。Payment から "cash" を除いた型
type OnlinePayment = Exclude<Payment, "cash">;
// 型 PointPayment を作る。Payment のうち、"points" か "card" に当てはまるものだけを残した型
type PointPayment = Extract<Payment, "points" | "card">;
// 結果: OnlinePayment は "card" | "bank" | "points"、PointPayment は "card" | "points"
Exclude<Payment, "cash">
"card" | "bank" | "points"
Exclude<Payment, "cash" | "bank">
"card" | "points"
2 つを除く

サバイバルTypeScript「Exclude」

Extract<T, U>

ユニオン型から、当てはまるものだけを残す

Exclude の反対で、U に当てはまるものだけを残します。上のサンプルの PointPayment がその例です。判別可能なユニオン型（03章 q04 問1）にも使えます。U に { kind: "post" } と書くと、kind が "post" のオブジェクトの型だけが残ります。

サンプル 
// 型 Shipment を作る。kind が "post" で zip（文字列）を持つものか、kind が "store" で storeId（数値）を持つもの
type Shipment = { kind: "post"; zip: string } | { kind: "store"; storeId: number };
// 型 PostShipment を作る。Shipment のうち、{ kind: "post" } に当てはまるものだけを残した型
type PostShipment = Extract<Shipment, { kind: "post" }>;
// 結果: PostShipment は { kind: "post"; zip: string }

コツ「当てはまる」は、そのプロパティを持っているかで決まります。{ kind: "post"; zip: string } は kind が "post" なので当てはまり、zip も持ったまま残ります。

サバイバルTypeScript「Extract」

NonNullable<T>

null と undefined を除く

型 T から null と undefined を除いた型を作ります。Exclude<T, null | undefined> と同じ型です。

サンプル 
// 型 MaybeStock を作る。数値か null か undefined
type MaybeStock = number | null | undefined;
// 型 StockCount を作る。MaybeStock から null と undefined を除いた型
type StockCount = NonNullable<MaybeStock>;
// 結果: StockCount は number

サバイバルTypeScript「NonNullable」

Awaited<T>

Promise が解決したあとの値の型

async の付いた関数は、戻り値が Promise になります。Promise は、あとで値が届くことを表す値です。Promise<X> は「あとで X が届く」という型です。Awaited<Promise<X>> と書くと、届いたあとの値の型 X を取り出せます。async と await は、ここでは読めれば十分です。くわしくは 08章 q01（Promise）と 08章 q02（async と await）で学びます。

サンプル 
// 関数 loadStock を作る。async の付いた関数で、数値 id を受け取る
async function loadStock(id: number) {
  // Promise.resolve() が終わるのを待つ
  await Promise.resolve();
  // id と、count が 12 のオブジェクトを返す
  return { id, count: 12 };
}
// 型 StockPromise を作る。loadStock の戻り値の型
type StockPromise = ReturnType<typeof loadStock>;
// 型 LoadedStock を作る。StockPromise が解決したあとの値の型
type LoadedStock = Awaited<StockPromise>;
// 結果: StockPromise は Promise<{ id: number; count: number }>、LoadedStock は { id: number; count: number }

ReturnType<typeof 関数> は、07章 q01 問12 で出ました。

まだ届いていない
