q03 インターフェース

インターフェースを書きます。インターフェースは、オブジェクトが持つプロパティとメソッドの形に名前を付けたものです。クラスが形を満たすことは implements で示します。インターフェースは、オブジェクトや関数の引数の型にも使えます。ドリル 1 問（1 つのファイルに 20 問）を確認して提出してから、応用に進みます。インターフェースは export します。引数と戻り値には型注釈を付けます。応用には「説明すること」があり、ファイルの「説明すること」のすぐ下に // のコメントで書きます。

ドリル20 問のインターフェースを書く 新しく出てくる書き方：interface、export interface、メソッドの形 m(): T;、implements、public、インターフェースの extends、オブジェクトのメソッド記法 
// 問1 interface Named（name: string）と、それを実装する class Cat(name) を書く。Cat の meow() は "ミケ: ニャー" を返す
//     例: new Cat("ミケ").meow() → "ミケ: ニャー"
// ここに Named と Cat を書く

// …（問20 まで、同じ形で続きます）

1 つのファイルに、20 問ぶんのインターフェースと、それを使うクラスや関数を書きます。ファイルには // ここに Named と Cat を書く のようなコメントだけがあり、コードは何も書いてありません。コメントの下に、インターフェースから順に書きます。

インターフェースは interface Named { name: string } のように書き、export を付けます。テストはインターフェースも読み込むので、export がないと失敗します。クラスがインターフェースの形を満たすことは、class Cat implements Named { … } で示します。インターフェースは、クラスのほかに、オブジェクトや関数の引数の型にも使えます。引数と戻り値には型注釈を付けます。

新しい書き方

export interface Product { … }

インターフェース（オブジェクトの形に名前を付ける）

interface 名前 { … } と書くと、オブジェクトの形に名前を付けられます。これをインターフェースと呼びます。{ } の中には、プロパティの名前と型を ; で区切って並べます。型エイリアス type Item = { … };（02章 q01 応用）とよく似ていますが、= がなく、最後の } の後ろに ; も付けません。前に export を付けると、ほかのファイルから使えます。

サンプル 
// Product というインターフェースを作る。name は文字列、price は数値。ほかのファイルから使えるようにする
export interface Product {
  name: string;
  price: number;
}

// 関数 priceTag を作る。Product の product を受け取り、文字列を返す
function priceTag(product: Product): string {
  // product の name と product の price を埋め込んだ「◯：◯円」の文字列を返す
  return `${product.name}：${product.price}円`;
}

// 札 tag を作り、priceTag に、name が "ノート"、price が 150 のオブジェクトを渡して呼んだ結果を入れる
const tag = priceTag({ name: "ノート", price: 150 });
// 結果: tag は "ノート：150円"
型エイリアス（02章 q01 応用）
type Product = {
  name: string;
  price: number;
};
インターフェース
interface Product {
  name: string;
  price: number;
}

形が合っていれば、クラスで作ったインスタンスでも、オブジェクトリテラルでも、インターフェースの型として扱えます。名前を付けて「このインターフェースです」と言わなくてもかまいません。問4 と問13 のテストは、オブジェクトリテラルを渡します。

テストの読み方テストには import { type Named, Cat } from … のように、type を付けた読み込みがあります。type は「型として読み込む」という印です。インターフェースは型なので、こう書いて読み込みます。

サバイバルTypeScript「インターフェース」

fee(weight: number): number;

メソッドの形を書く

インターフェースには、メソッドの形も書けます。名前(引数): 戻り値の型; と書きます。クラスのメソッドから、{ … } の中身を取って ; にした形です。「このインターフェースのものは、この形のメソッドを必ず持つ」という約束になります。

サンプル 
// Shipping というインターフェースを作る。fee は、数値の weight を受け取り数値を返すメソッド。ほかのファイルから使えるようにする
export interface Shipping {
  fee(weight: number): number;
}

// 宅配便 courier を作り、型を Shipping にして、fee が weight × 2 + 300 を返すアロー関数のオブジェクトを入れる
const courier: Shipping = { fee: (weight) => weight * 2 + 300 };
// 送料 cost を作り、courier の fee に 100 を渡して呼んだ結果を入れる
const cost = courier.fee(100);
// 結果: cost は 500

オブジェクトリテラルでこの形を満たすときは、サンプルの courier のように、プロパティにアロー関数（01章 q01 問20）を入れて書けます。型が Shipping と決まっているので、アロー関数の weight には型注釈が要りません。

courier.fee(100)
500
courier.fee(0)
300
class Notebook implements Printable

クラスがインターフェースの形を満たす（implements）

クラスの名前の後ろに implements インターフェースの名前 と書くと、「このクラスはインターフェースの形を満たす」と宣言できます。これを、インターフェースを実装すると言います。インターフェースにあるプロパティやメソッドが 1 つでも足りないと、型の確認でエラーになります。

サンプル 
// Printable というインターフェースを作る。print は、何も受け取らず文字列を返すメソッド。ほかのファイルから使えるようにする
export interface Printable {
  print(): string;
}

// クラス Notebook を作る。Printable の形を満たす。ほかのファイルから使えるようにする
export class Notebook implements Printable {
  // 文字列のフィールド title を作る
  title: string;

  // constructor を作る。文字列の title を受け取る
  constructor(title: string) {
    // 自分の title に title を入れる
    this.title = title;
  }

  // メソッド print を作る。何も受け取らず、文字列を返す
  print(): string {
    // 自分の title を埋め込んだ「印刷: ◯」の文字列を返す
    return `印刷: ${this.title}`;
  }
}

// 書類 doc を作り、型を Printable にして、Notebook に "議事録" を渡して new で作ったインスタンスを入れる
const doc: Printable = new Notebook("議事録");
// 結果: doc.print() は "印刷: 議事録"
print を書き忘れる
class Notebook implements Printable {
  title = "";
}
✕ Class 'Notebook' incorrectly implements interface 'Printable'. のエラーになります
print を書く
class Notebook implements Printable {
  title = "";
  print(): string {
    return this.title;
  }
}
○ 形を満たしています

実装したクラスのインスタンスは、インターフェースの型の変数に入れられます。違うクラスでも、同じインターフェースを実装していれば、1 つの配列にまとめて同じように扱えます（問6、問11、問19）。

よくある疑問implements を書かなくても、形が合っていればインターフェースの型として扱えます。それでも書くのは、足りないものがあったときに、クラスを書いたその場でエラーが出て気づけるからです。

サバイバルTypeScript「インターフェースを実装する」

constructor(public label: string) {}

public（どこからでも読み書きできる）

public は、どこからでも読めて、書き換えもできる、という印です。何も付けないフィールドと同じ意味です。それでも書くのは、constructor の引数をフィールドにするとき（q02 の 1 つ目の項目）です。何か印を付けないと引数はフィールドにならないので、制限のないフィールドにしたいときに public を付けます。

サンプル 
// Labeled というインターフェースを作る。label は文字列。ほかのファイルから使えるようにする
export interface Labeled {
  label: string;
}

// クラス Shelf を作る。Labeled の形を満たす。ほかのファイルから使えるようにする
export class Shelf implements Labeled {
  // constructor を作る。文字列の label を受け取り、どこからでも使えるフィールド label にする
  constructor(public label: string) {}
}

// 棚 shelf を作り、Shelf に "A-3" を渡して new で作ったインスタンスを入れる
const shelf = new Shelf("A-3");
// shelf の label に "B-1" を入れ直す
shelf.label = "B-1";
// 結果: shelf.label は "B-1"

よくある間違いインターフェースにある label を、クラスで private label にすると、外から読めなくなり、形を満たせません。型の確認で Property 'label' is private in type 'Shelf' but not in type 'Labeled'. というエラーになります。

サバイバルTypeScript「インターフェースの継承」

add(n: number): void { … },

オブジェクトのメソッド記法

オブジェクトリテラルの中にも、クラスと同じ形でメソッドを書けます。add: (n) => { … } のようにアロー関数を入れる代わりに、add(n) { … } と書く書き方です。クラスと違い、オブジェクトリテラルなので、プロパティとプロパティの間には , を付けます。

サンプル 
// Meter というインターフェースを作る。value は数値、add は数値の n を受け取り何も返さないメソッド。ほかのファイルから使えるようにする
export interface Meter {
  value: number;
  add(n: number): void;
}

// 関数 makeMeter を作る。何も受け取らず、Meter を返す
function makeMeter(): Meter {
  // 次のオブジェクトを返す
  return {
    // value は 0
    value: 0,
    // メソッド add を作る。数値の n を受け取り、何も返さない
    add(n: number): void {
      // 自分の value に n を足す
      this.value += n;
    },
  };
}

// 水道メーター water を作り、makeMeter を呼んだ結果を入れる
const water = makeMeter();
// water の add に 3 を渡して呼ぶ
water.add(3);
// 結果: water.value は 3

メソッド記法で書いたメソッドの中の this は、クラスのときと同じく、メソッドを呼んだオブジェクトです。water.add(3) なら this は water です。戻り値の型が Meter と決まっているので、this も Meter として扱われます。

よくある間違いメソッドの後ろの , を忘れたり、クラスと同じつもりで ; を付けたりすると、型の確認でエラーになります。オブジェクトリテラルの中は、いつも , で区切ります。

図形のインターフェースと、それを実装するクラス 2 つ、図形の配列を受け取る関数 2 つを書きます。

  1. Shape：図形のインターフェースです。name（図形の名前、読み取り専用の文字列）、area()（面積を返すメソッド）、perimeter()（周りの長さを返すメソッド）を持ちます。ファイルには仮の export type Shape = unknown; があるので、書き換えます。
  2. Circle：Shape を実装します（implements Shape）。constructor で半径 radius を受け取ります。name は "円" です。周りの長さは円周（2 × 円周率 × 半径）です。
  3. Rectangle：Shape を実装します。constructor で width と height を受け取ります。name は "長方形" です。周りの長さは（幅 + 高さ）× 2 です。
  4. totalArea(shapes)：面積の合計を返します。引数は readonly Shape[] です。
  5. largest(shapes)：面積がいちばん大きい図形を返します。同じ面積なら、先にあるほうを返します。空なら undefined を返します。

「説明すること」もあります。interface と type のどちらで書いても同じことができる場面で、どちらを選ぶか、その理由を、ファイルの「説明すること」のすぐ下に // のコメントで書きます。

ヒント 2コードへの直し方

export type Shape = unknown; の行は、export interface Shape { … } に書き換えます。中身は、問4 の Figure に、name の readonly（問7）と perimeter の行を足した形です。クラスの name は readonly name = "円"; と書きます。クラスの area と perimeter は、q01 のドリルの問3（Circle）と問2（Rect）と同じ計算です。totalArea はドリルの問5、largest はドリルの問17 と同じ形です。「より大きい」で比べると、同じ面積のときは先の図形が残ります。説明することは、Shape を type Shape = { … }; の形でも書いてみて、テストと型の確認がどうなるかを試してから考えます。教材の「interfaceとtypeの違い」も読みます。試したら、提出する形に戻します。
