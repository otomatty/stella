04章 文と例外

q07 never型と網羅性のチェック

ユニオン型の値で場合分けする関数を 20 個書きます。引数と戻り値には型注釈を付けます。ファイルの上には、関数 assertNever と、型 Fruit・Signal・Op・Shape・LogLevel がもう書いてあります。書き換えずに使います。ユニオン型の値で場合分けするときは、switch で書きます。すべての値の case を書き、default では assertNever(値) を返します。こうしておくと、型に新しい値が増えたとき、書き忘れた case が型の確認のエラーで分かります。この確かめ方を「網羅性のチェック」と呼びます。網羅性とは、場合をもれなく扱っていることです。

問1果物の色を返す 新しく出てくる書き方：never 型、default で assertNever(値) を返す形、ESLint の switch-exhaustiveness-check、JSON.stringify() 
export function assertNever(value: never): never {
  throw new Error(`想定していない値です: ${JSON.stringify(value)}`);
}

export type Fruit = "apple" | "banana" | "cherry";

export function fruitColor() {}

果物を 1 つ受け取り、その色を返します。"apple" は "赤"、"banana" は "黄"、"cherry" は "赤" です。引数の型は Fruit です。switch で書き、default では assertNever(fruit) を返します。

ファイルの上の assertNever と Fruit は、もう書いてあります。この 2 つの読み方を、下の「新しい書き方」で説明します。

新しい書き方

never

never 型（当てはまる値が 1 つもない型）

never は、当てはまる値が 1 つもない型です。string にはどんな文字列も当てはまり、"free" | "standard" には 2 つの値が当てはまります。never に当てはまる値はありません。

スターターの assertNever は、引数の型も戻り値の型も never です。

サンプル 
// 関数 assertNever を作る。never の value を受け取り、決して値を返さない
function assertNever(value: never): never {
  // 「想定していない値です: ◯」というメッセージのエラーを投げる（◯ は value を JSON の文字列にしたもの）
  throw new Error(`想定していない値です: ${JSON.stringify(value)}`);
}
// 結果: assertNever に渡せる値はなく、呼ばれたら必ずエラーを投げる
assertNever("free")
型の確認でエラー
"free" は never に当てはまらない
assertNever(0)
型の確認でエラー
どんな値も never に当てはまらない

値を 1 つも渡せない関数が、なぜ役に立つのでしょうか。switch で場合を全部分けると、最後に「残りの値がない」場所ができます。そこでは値の型が never になるので、assertNever に渡せます。次の項目で説明します。

なぜ戻り値の型が never の関数は、どんな型の値の代わりにもなります。その先に処理が進まないからです。そのため、戻り値が string の関数の中でも return assertNever(fruit); と書けます。

サバイバルTypeScript「never型」

default: return assertNever(plan);

case をすべて書き、default で assertNever を返す

ユニオン型の値を switch で分けると、case の中では値の型が絞り込まれます（03章 q04）。case "free": の中では、plan の型は "free" だけです。

すべての値の case を書くと、default に来る値はもう残っていません。そのため、default の中では plan の型が never になります。never の値なら、assertNever に渡せます。

サンプル 
// 型 Plan を作る。"free" か "standard" か "premium"
type Plan = "free" | "standard" | "premium";
// 関数 planFee を作る。Plan の plan を受け取り、数値を返す
function planFee(plan: Plan): number {
  // plan で場合を分ける
  switch (plan) {
    // "free" の場合
    case "free":
      // 0 を返す
      return 0;
    // "standard" の場合
    case "standard":
      // 980 を返す
      return 980;
    // "premium" の場合
    case "premium":
      // 1980 を返す
      return 1980;
    // それ以外の場合
    default:
      // assertNever に plan を渡して呼んだ結果を返す
      return assertNever(plan);
  }
}
// 結果: planFee("standard") は 980

場所ごとの plan の型です。case を 1 つ通るたびに、残りの値が減っていきます。

場所plan の型
switch (plan) の前"free" | "standard" | "premium"
case "free": の中"free"
case "standard": の中"standard"
case "premium": の中"premium"
default: の中never（残りがない）

この形が役に立つのは、あとで型に値が増えたときです。planFee はそのままにして、Plan に "family" を足してみます。

Plan が 3 つのとき
// 型 Plan を作る。"free" か "standard" か "premium"
type Plan = "free" | "standard" | "premium";
○ default の plan は never なので、assertNever に渡せます
Plan に "family" を足したとき
// 型 Plan を作る。"free" か "standard" か "premium" か "family"
type Plan = "free" | "standard" | "premium" | "family";
✕ assertNever(plan) の行が、型の確認でエラーになります

"family" の case がないので、default に "family" が残ります。"family" は never に当てはまらないので、assertNever に渡せません。型の確認は、Argument of type '"family"' is not assignable to parameter of type 'never'. というメッセージを出します。

「"family" 型の値は、never 型の引数に渡せません」という意味です。メッセージの中の "family" が、書き忘れた case です。

よくある間違いエラーが出るのは assertNever(plan) の行ですが、直す場所は switch の中です。case "family": を足すと、エラーは消えます。assertNever の引数の型を変えて消すのは間違いです。

なぜ型の上では、default に来る値はありません。それでも、型の確認をすり抜けた値が実行中に来ることがあります。たとえば、JSON から読んだ値です（04章 q05 問5）。そのときは assertNever がエラーを投げて、おかしな値が来たことを知らせます。

サバイバルTypeScript「never型」

switch-exhaustiveness-check

ESLint で case の書き忘れを見つける

この課題の ESLint の設定には、switch-exhaustiveness-check という規則が入っています（04章 q02）。ユニオン型の値の switch に、すべての値の case があるかを確かめる規則です。書き忘れがあると、switch の行で Switch is not exhaustive. Cases not matched: "family" というエラーになります。

「switch がすべての場合を扱っていません。"family" の case がありません」という意味です。

型の確認と ESLint は、別々に書き忘れを見つけます。default の書き方によって、型の確認が見逃すことがあります。次の 2 つは、どちらも Plan に "family" を足したのに、case を足し忘れた例です。

default で 0 を返す
// それ以外の場合
default:
  // 0 を返す
  return 0;
✕ 型の確認は通ってしまいます。書き忘れに気づけるのは ESLint だけです
default で assertNever を返す
// それ以外の場合
default:
  // assertNever に plan を渡して呼んだ結果を返す
  return assertNever(plan);
○ 型の確認と ESLint の両方が、書き忘れを知らせます

default で決まった値を返すと、"family" は黙って 0 になります。型の確認から見ると、おかしなところはありません。assertNever を返す形なら、ESLint を動かさなくても、型の確認だけで気づけます。

書き方ごとに、どこでエラーになるかをまとめました。

すべての case と、default の assertNever
どちらも通る
この課題で書く形
case の書き忘れと、default の assertNever
どちらもエラー
型の確認は assertNever の行、ESLint は switch の行
case の書き忘れと、default で 0 を返す
ESLint だけエラー
型の確認は通ってしまう
case の書き忘れと、default なし
どちらもエラー
型の確認は「関数の最後に return がない」というエラー

決まりcase をすべて書けば、default がなくても型の確認と ESLint は通ります。それでもこの課題では、default で assertNever(値) を返します。型の確認でも気づけるうえに、実行中におかしな値が来たときにエラーで知らせてくれるからです。

typescript-eslint「switch-exhaustiveness-check」

JSON.stringify(value)

値を JSON の文字列にする

JSON.stringify() は、受け取った値を JSON の形の文字列にします。JSON の文字列を値に戻す JSON.parse()（04章 q05 問5）の逆です。assertNever は、エラーのメッセージに来た値を入れるために使っています。

サンプル 
// 注文 order を作り、{ id: "A-102", qty: 2 } を入れる
const order = { id: "A-102", qty: 2 };
// text を作り、order を JSON の文字列にしたものを入れる
const text = JSON.stringify(order);
// 結果: text は '{"id":"A-102","qty":2}'
JSON.stringify(order)
'{"id":"A-102","qty":2}'
オブジェクトの中身が文字列になる
JSON.stringify("family")
'"family"'
文字列は、前後に " が付く
JSON.stringify(3)
"3"
数は、そのまま文字列になる

実行中に "family" が assertNever に届くと、メッセージが 想定していない値です: "family" のエラーを投げます。

なぜテンプレートリテラルに ${value} とそのまま書かないのは、2 つの理由からです。1 つめは、型が never の値を埋め込むと、ESLint がエラーにすることです（Invalid type "never" of template literal expression）。2 つめは、オブジェクトをそのまま埋め込むと "[object Object]" になり、中身が分からないことです。
