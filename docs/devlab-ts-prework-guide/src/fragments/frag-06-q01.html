06章 クラス

q01 クラスの基本

クラスを書きます。クラスは、値（フィールド）と、その値を使う処理（メソッド）をひとまとめにした設計図です。ドリル 1 問（1 つのファイルに 20 個のクラス）を確認して提出してから、応用に進みます。フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。フィールドの値は、constructor の中で this.x = x; のように入れるか、count = 0 のように初期値を書きます。private などの印は q02 で学ぶので、ドリルでは何も付けません。

ドリル20 個のクラスを書く 新しく出てくる書き方：class、export class、new とインスタンス、フィールド、constructor、this、メソッド、フィールドの初期値、.shift()、クラスの名前を型に使う 
// 問1 Point(x, y)。フィールド x と y。label() で "(1, 2)" を返す
//     例: new Point(1, 2).label() → "(1, 2)"
export class Point {}

// 問2 Rect(width, height)。area() で面積を返す
//     例: new Rect(3, 4).area() → 12
export class Rect {}

// …（問20 まで、同じ形で続きます）

1 つのファイルに、クラスを 20 個書きます。ファイルには、export class Point {} のように、中身が空のクラスが並んでいます。{} の中に、フィールド・constructor・メソッドを書き足します。Point(x, y) のように名前の後ろにかっこがあるものは、constructor でその値を受け取ります。かっこがないものは、constructor を書かず、フィールドに初期値を書きます。

フィールド、constructor の引数、メソッドの引数と戻り値には、型注釈を付けます。private などの印（アクセス修飾子）は q02 で学びます。ここでは何も付けません。テストは、値のほかに型も確かめます。

新しい書き方

export class Item { … }

クラスとインスタンス（設計図と、そこから作ったもの）

クラスは、同じ形のオブジェクトをいくつも作るための設計図です。class の後ろにクラスの名前を書き、{ } の中に、持たせる値（フィールド）と、できること（メソッド）を書きます。クラスの名前は、Item のように大文字で始めます。

クラスからオブジェクトを作るには、new クラスの名前(…) と書きます（new は 01章 q04 問8 の new Error() で出ました）。こうして作ったオブジェクトを、そのクラスのインスタンスと呼びます。1 つのクラスから、インスタンスはいくつでも作れます。

前に export を付けると、ほかのファイルからもそのクラスを使えます。export function（00章 q01）と同じ考え方です。テストはクラスを読み込んで new するので、export は消さずに残します。

サンプル 
// クラス Item を作る。ほかのファイルから使えるようにする
export class Item {
  // 文字列のフィールド name を作る
  name: string;
  // 数値のフィールド price を作る
  price: number;

  // constructor を作る。文字列の name と数値の price を受け取る
  constructor(name: string, price: number) {
    // 自分の name に name を入れる
    this.name = name;
    // 自分の price に price を入れる
    this.price = price;
  }
}

// pen を作り、Item に "ペン" と 120 を渡して new で作ったインスタンスを入れる
const pen = new Item("ペン", 120);
// note を作り、Item に "ノート" と 200 を渡して new で作ったインスタンスを入れる
const note = new Item("ノート", 200);
// 結果: pen.name は "ペン"、note.price は 200

インスタンスのフィールドは、オブジェクトのプロパティ（02章 q01 問1）と同じく、pen.name のように . で読めます。

pen.name
"ペン"
note.name
"ノート"
同じクラスでも、値は別々
pen.price + note.price
320

よくある間違いItem("ペン", 120) のように new を付けずに呼ぶと、型の確認でエラーになります。クラスからインスタンスを作るときは、必ず new を付けます。

サバイバルTypeScript「クラス」

name: string;

フィールド（インスタンスが持つ値）

クラスの { } のすぐ内側に 名前: 型; と書くと、フィールドになります。フィールドは、インスタンスが 1 つずつ持つ値の入れ物です。オブジェクトの型（02章 q01 問1）のプロパティと同じ書き方ですが、行の終わりに ; を付けます。

宣言しただけのフィールドには、まだ値が入っていません。値は、次の項目の constructor で入れます。

よくある間違いフィールドを宣言したのに、constructor で値を入れ忘れると、型の確認で Property 'name' has no initializer and is not definitely assigned in the constructor. というエラーになります。「name に初期値がなく、constructor でも値が入っていない」という意味です。

サバイバルTypeScript「フィールド」

constructor(…) { this.name = name; }

constructor（new のときに値を入れる）

constructor は、new でインスタンスを作るときに、1 回だけ自動で呼ばれる特別なメソッドです。new Item("ペン", 120) のかっこの中の値が、constructor の引数に順に入ります。constructor の中では、受け取った値をフィールドに入れます。

const pen = new Item("ペン", 120); は、次の順で進みます。

  1. 空のインスタンスフィールドにまだ値のない、新しいインスタンスが 1 つできます。
  2. constructor を呼ぶ引数の name に "ペン"、price に 120 が入ります。
  3. フィールドに入れるthis.name = name; などで、値がフィールドに入ります。
  4. 変数に入るできあがったインスタンスが pen に入ります。
this. を付けない
class Item {
  name: string;
  constructor(name: string) {
    name = name;
  }
}
✕ 引数に引数を入れ直すだけで、フィールドに値が入りません
this. を付ける
class Item {
  name: string;
  constructor(name: string) {
    this.name = name;
  }
}
○ 受け取った値がフィールドに入ります

コツ引数とフィールドに同じ名前を付けることがよくあります。this. が付いているほうがフィールド、付いていないほうが引数です。

サバイバルTypeScript「コンストラクタ」

label(): string { … }

メソッド（インスタンスができること）

クラスの中に 名前(引数): 戻り値の型 { … } と書くと、メソッドになります。メソッドは、クラスの中に書いた関数です。関数宣言（00章 q01）と同じ形で、前の function だけを書きません。呼ぶときは、インスタンスの後ろに . を付けて pen.label() と書きます。

サンプル 
// クラス Item を作る。ほかのファイルから使えるようにする
export class Item {
  // 文字列のフィールド name を作る
  name: string;
  // 数値のフィールド price を作る
  price: number;

  // constructor を作る。文字列の name と数値の price を受け取る
  constructor(name: string, price: number) {
    // 自分の name に name を入れる
    this.name = name;
    // 自分の price に price を入れる
    this.price = price;
  }

  // メソッド label を作る。何も受け取らず、文字列を返す
  label(): string {
    // 自分の name と自分の price を埋め込んだ「◯（◯円）」の文字列を返す
    return `${this.name}（${this.price}円）`;
  }
}

// pen を作り、Item に "ペン" と 120 を渡して new で作ったインスタンスを入れる
const pen = new Item("ペン", 120);
// 表示 text を作り、pen の label を呼んだ結果を入れる
const text = pen.label();
// 結果: text は "ペン（120円）"

何も返さないメソッドは、戻り値の型を void にします（04章 q05 問13）。メソッドは何個でも書けます。メソッドとメソッドの間には、, も ; も要りません。

コメントの読み方このページのコメントでは、this を「自分の」と書きます。「自分の price」は this.price です。

サバイバルTypeScript「メソッド」

this

this（メソッドを呼んだインスタンス）

メソッドの中の this は、そのメソッドを呼んだインスタンスを指します。warehouseA.ship(3) なら this は warehouseA、warehouseB.ship(3) なら warehouseB です。そのため、同じメソッドでも、呼んだインスタンスのフィールドだけが変わります。

サンプル 
// クラス Stock を作る。ほかのファイルから使えるようにする
export class Stock {
  // 数値のフィールド count を作る
  count: number;

  // constructor を作る。数値の count を受け取る
  constructor(count: number) {
    // 自分の count に count を入れる
    this.count = count;
  }

  // メソッド ship を作る。数値の n を受け取り、何も返さない
  ship(n: number): void {
    // 自分の count から n を引く
    this.count -= n;
  }
}

// 倉庫A warehouseA を作り、Stock に 10 を渡して new で作ったインスタンスを入れる
const warehouseA = new Stock(10);
// 倉庫B warehouseB を作り、Stock に 10 を渡して new で作ったインスタンスを入れる
const warehouseB = new Stock(10);
// warehouseA の ship に 3 を渡して呼ぶ
warehouseA.ship(3);
// 結果: warehouseA.count は 7、warehouseB.count は 10

フィールドの宣言に = 値 を続けると、インスタンスを作ったときに、はじめからその値が入ります。これをフィールドの初期値（初期化子）と呼びます。どのインスタンスも同じ値から始めるなら、constructor を書かずに済みます。constructor がないクラスは、new Visitors() のように、空のかっこで作ります。

  enter(name: string): void {

    this.total++;
    // 自分の names の最後に name を足す
    this.names.push(name);
  }

サバイバルTypeScript「配列」

merge(other: Weight): Weight

クラスの名前を型に使う

クラスを作ると、クラスの名前をそのまま型として使えます。型 Weight は「Weight のインスタンス」という意味です。引数や戻り値に書けば、同じクラスのインスタンスを受け取ったり返したりするメソッドになります。メソッドの中で new Weight(…) と書けば、新しいインスタンスを作れます。

サンプル 
// クラス Weight を作る。ほかのファイルから使えるようにする
export class Weight {
  // 数値のフィールド grams を作る
  grams: number;

  // constructor を作る。数値の grams を受け取る
  constructor(grams: number) {
    // 自分の grams に grams を入れる
    this.grams = grams;
  }

  // メソッド merge を作る。Weight の other を受け取り、Weight を返す
  merge(other: Weight): Weight {
    // Weight に、自分の grams + other の grams を渡して new で作ったインスタンスを返す
    return new Weight(this.grams + other.grams);
  }
}

// 箱 box を作り、Weight に 300 を渡して new で作ったインスタンスを入れる
const box = new Weight(300);
// 合計 sum を作り、box の merge に、Weight に 200 を渡して new で作ったインスタンスを渡して呼んだ結果を入れる
const sum = box.merge(new Weight(200));
// 結果: sum.grams は 500、box.grams は 300

this.grams は呼んだインスタンス（box）の値、other.grams は引数で受け取ったインスタンスの値です。新しいインスタンスを返すので、box の値は変わりません。

型問17 と問18 のテストは、メソッドの型が (other: Money) => Money のように、受け取るものも返すものも、そのクラスであることを確かめます。

応用数を数える Counter と、温度の Temperature 新しく出てくる書き方：private、readonly（クラスのフィールド） 
export class Counter {}

export class Temperature {}

クラスを 2 つ書きます。フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。

  1. Counter：数を数えるクラスです。フィールド count（数値）に今の値を持ちます。constructor は始めの値 start を受け取ります。省略したら 0 です。メソッドは 3 つです。increment() は 1 増やして、増やした後の値を返します。decrement() は 1 減らして、減らした後の値を返します。ただし 0 より小さくはしません。reset() は、count を始めの値に戻します。何も返しません。始めの値を覚えておくフィールドが、もう 1 つ要ります。

型Counter の constructor の引数が省略できる数値 1 つ（[start?: number]）、count が number、increment と decrement が数値を返し、reset が何も返さないことも確かめます。Temperature は、constructor の引数が数値 1 つ、celsius が number、3 つのメソッドがそれぞれ数値・boolean・文字列を返すことを確かめます。

新しい書き方

private readonly full: number;

外から読めないフィールド、入れ直せないフィールド

フィールドの前に印を付けると、使える場所を決められます。private を付けたフィールドは、クラスの中（メソッドや constructor）からだけ使えます。readonly を付けたフィールドは、constructor で値を入れたあとは入れ直せません。readonly は、02章 q02 問7 のオブジェクトの型の readonly と同じ考え方です。

サンプル 
// クラス Bottle を作る。ほかのファイルから使えるようにする
export class Bottle {
  // 数値のフィールド amount を作る
  amount: number;
  // 外から読めず、入れ直せない数値のフィールド full を作る
  private readonly full: number;

  // constructor を作る。数値の full を受け取る。省略したら 500
  constructor(full = 500) {
    // 自分の full に full を入れる
    this.full = full;
    // 自分の amount に full を入れる
    this.amount = full;
  }

  // メソッド refill を作る。何も受け取らず、何も返さない
  refill(): void {
    // 自分の amount に自分の full を入れ直す
    this.amount = this.full;
  }
}

// 水筒 bottle を作り、Bottle に 350 を渡して new で作ったインスタンスを入れる
const bottle = new Bottle(350);
// bottle の amount に 100 を入れ直す
bottle.amount = 100;
// bottle の refill を呼ぶ
bottle.refill();
// 結果: bottle.amount は 350

このサンプルの full は、あとで refill() で使うために覚えておく値です。外から書き換えられると困るので private、作ったあとは変えないので readonly を付けています。

bottle.full（クラスの外で）
型の確認でエラー
private なので外から読めない
this.full = 0;（refill の中で）
型の確認でエラー
readonly なので入れ直せない

constructor の引数 full = 500 は、デフォルト引数（05章 q04 問1）です。引数を省略して new Bottle() と書くと、full は 500 になります。型注釈を書かなくても、full の型は number になります。

よくある疑問この応用のテストは、始めの値を覚えるフィールドに private や readonly が付いているかは確かめません。付けなくても通ります。付けておくと、間違えて書き換えたときに型の確認で気づけます。
