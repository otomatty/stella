09章 発展問題（任意）

発展問題

やってもやらなくてもよい、任意の課題です。章の課題とは別に数えます。番号の順に、1 問ずつ確認して提出します。e01 では、外から来た JSON の形を確かめて読み、JSON の文字列に書き出します。e02 では、正規表現で文字列を調べ、取り出し、置き換えます。どちらにも「説明すること」があり、ファイルの「説明すること」のすぐ下に // のコメントで書きます。引数と戻り値には型注釈を付けます。

e01JSON の読み書き 新しく出てくる書き方：JSON.stringify() の字下げ、Date と JSON、new Date(文字列) 
export type User = { id: number; name: string; tags: string[] };
export type AppEvent = { title: string; at: Date };

export function parseUser() {}

export function toJson() {}

export function parseEvent() {}

export function eventToJson() {}

JSON.parse の戻り値の型は any です。外から来た JSON は、形を確かめてから使います。any を使わずに、読んだ値を unknown の変数に入れて（04章 q05 問5）、次の 4 つの関数を書きます。型 User と AppEvent は、ファイルに書いてあります。

  1. parseUser(json)：JSON の文字列を読み、{ id: number; name: string; tags: string[] } の形なら User として返します。JSON として読めなければ "JSON として読めません"、形が違えば "ユーザーの形が違います" というメッセージのエラーを投げます。
  2. toJson(user)：User を、2 つの空白で字下げした JSON の文字列にします。
  3. parseEvent(json)：{ "title": "勉強会", "at": "2026-04-01T10:00:00.000Z" } の形の JSON を読み、AppEvent（{ title: string; at: Date }）を返します。JSON には Date がないので、日時は文字列で入っています。title が文字列でないときや、at が日時として読めないときは、"イベントの形が違います" というメッセージのエラーを投げます。
  4. eventToJson(event)：AppEvent を、字下げのない JSON の文字列にします。at は "2026-04-01T10:00:00.000Z" の形になります。

説明すること：JSON.stringify で、値が undefined のプロパティや、関数のプロパティはどうなるか。試した結果を書きます。

新しい書き方

JSON.stringify(値, null, 2)

字下げした JSON の文字列にする

JSON.stringify()（04章 q07 問1）は、値を JSON の文字列にします。かっこに 1 つだけ渡すと、空白も改行もない 1 行の文字列になります。3 つ目の引数に数を渡すと、その数の空白で字下げし、改行を入れた、人が読みやすい文字列になります。

サンプル 
// 注文 order を作り、id が 7、items が ["ペン", "ノート"] のオブジェクトを入れる
const order = { id: 7, items: ["ペン", "ノート"] };
// 文字列 oneLine を作り、order を JSON の文字列にしたものを入れる
const oneLine = JSON.stringify(order);
// 文字列 indented を作り、order を 2 つの空白で字下げした JSON の文字列にしたものを入れる
const indented = JSON.stringify(order, null, 2);
// 結果: oneLine は '{"id":7,"items":["ペン","ノート"]}'。indented は '{\n  "id": 7,\n  "items": [\n    "ペン",\n    "ノート"\n  ]\n}'（\n は改行）

indented を画面に出すと、次のようになります。

{
  "id": 7,
  "items": [
    "ペン",
    "ノート"
  ]
}
new Date(文字列)

JSON の中の日時を Date にする

new Date(文字列) は、"2026-05-10T09:30:00.000Z" のような日時の文字列を読んで、Date（09章 q03）を作ります。日時として読めない文字列を渡しても、例外は投げません。代わりに、無効な日時（Invalid Date）ができます。無効な日時の時刻の数 getTime() は NaN なので、Number.isNaN()（01章 q04 問11）で見分けます。

サンプル 
// 日時 start を作り、"2026-05-10T09:30:00.000Z" を日時として読んだものを入れる
const start = new Date("2026-05-10T09:30:00.000Z");
// 日時 wrong を作り、"来週" を日時として読んだものを入れる
const wrong = new Date("来週");
// isWrong を作り、wrong の時刻の数が NaN か（true か false）を入れる
const isWrong = Number.isNaN(wrong.getTime());
// 結果: start.getTime() は 1778405400000。isWrong は true

JSON には Date の値がありません。JSON.stringify() に Date を渡すと、toISOString()（03章 q03 問20）と同じ形の文字列になります。読み直しても、文字列のままです。読み直した値は、new Date(文字列) で Date に戻します。

サンプル 
// 予約 booking を作り、room が "A"、at が "2026-05-10T09:30:00.000Z" を日時として読んだもののオブジェクトを入れる
const booking = { room: "A", at: new Date("2026-05-10T09:30:00.000Z") };
// 文字列 text を作り、booking を JSON の文字列にしたものを入れる
const text = JSON.stringify(booking);
// 読み直した値 data を作り、型を unknown にして、text を JSON として読んだものを入れる
const data: unknown = JSON.parse(text);
// 結果: text は '{"room":"A","at":"2026-05-10T09:30:00.000Z"}'。data の at は Date ではなく、文字列の "2026-05-10T09:30:00.000Z"

よくある間違い無効な日時でも、instanceof Date は true です。Date かどうかだけでは、読めたかどうかはわかりません。

ヒント 2コードへの直し方

isUser は、ファイルの中だけで使う型ガード関数（05章 q09 問1）です。戻り値の型を value is User にすると、parseUser の if の後ろで data が User として扱われ、そのまま返せます。「プロパティを持たない」は !("id" in value && "name" in value && "tags" in value) です（04章 q05 問16）。Array.isArray() で確かめた値は any[] になるので、const tags: readonly unknown[] = value.tags; と unknown として受け取ります（04章 q06 問17）。「すべて〜か」は .every()（02章 q04 問20）です。JSON を読む前半は、04章 q05 問16 の readOrder と同じ形です。parseUser と parseEvent で同じなので、関数にまとめてもかまいません。parseEvent の後半は、e01 の 2 つ目の項目のサンプルの isWrong と同じ確かめ方です。toJson と eventToJson は 1 行で書けます。Date は JSON.stringify が自動で文字列にします。説明することは、ターミナルで node と打って試します。JavaScript を 1 行ずつ実行できます（終えるときは .exit）。値が undefined のプロパティと、関数のプロパティを持つオブジェクトを JSON.stringify に渡し、出てきた文字列を見てから書きます。

次の 5 つの関数を、正規表現を使って書きます。型 LogLine は、ファイルに書いてあります。引数と戻り値には型注釈を付けます。

  1. isPostalCode(text)："123-4567" の形（数字 3 つ、ハイフン、数字 4 つ）だけなら true を返します。前後に余計な文字があれば false です。
  2. extractHashtags(text)：文章の中の "#" で始まるハッシュタグを、"#" を除いて、出てきた順に配列で返します。ハッシュタグは "#" の後ろから、空白か次の "#" の手前までです。
  3. maskPhone(text)：文章の中の "090-1234-5678" の形（数字 3 つ-4 つ-4 つ）の電話番号を、すべて "090-****-5678" のように、真ん中だけ隠します。
  4. parseLogLine(line)："[ERROR] 2026-04-01 09:00:00 接続できません" の形の 1 行を読み、{ level: "ERROR", time: "2026-04-01 09:00:00", message: "接続できません" } を返します。level は INFO・WARN・ERROR のどれかです。形が違えば null を返します。名前付きグループ（(?<level>…)）を使います。
  5. camelToKebab(name)："userName" を "user-name" にするように、大文字の前に "-" を入れて、小文字にします。

正規表現の書き方のまとめ

正規表現は、文字の並びの形を表す書き方です。01章 q05 から少しずつ使い、そのたびに「まねて書ければ十分」としてきました。ここで、書き方をまとめます。

サンプル 
// 予約番号 reserveNo を作り、"AB-1234" を入れる
const reserveNo = "AB-1234";

const isReserveNo = /^[A-Z]{2}-\d{4}$/.test(reserveNo);
// 結果: isReserveNo は true

サバイバルTypeScript「正規表現 (RegExp)」

.matchAll()

合った部分を、すべて取り出す

.exec()（04章 q08 問6）は、最初に合った 1 つだけを取り出します。.matchAll() は、文字列の中で合った部分を、すべて順に取り出します。正規表現には g を付けます。取り出した結果は、1 つずつが .exec() の結果と同じ形の配列です。0 番目が合った部分の全体、1 番目からが ( ) で囲んだ部分です。

サンプル 
// 明細 receipt を作り、"ペン 120円、ノート 250円" を入れる
const receipt = "ペン 120円、ノート 250円";
// matches を作り、receipt の中で /(\d+)円/g に合った結果をすべて並べた新しい配列を入れる
const matches = [...receipt.matchAll(/(\d+)円/g)];
// prices を作り、matches の要素を 1 つずつ m として、m の 1 番目を数値にしたものに変えた新しい配列を入れる
const prices = matches.map((m) => Number(m[1]));
// 結果: matches[0] は ["120円", "120"]、prices は [120, 250]

.matchAll() の結果は、for-of で 1 つずつ取り出せるものです。配列のメソッドを使うために、[... ]（02章 q05 問1 の配列のスプレッド）で新しい配列にしています。

$1

置き換える文字列に、グループで合った部分を入れる

.replace()（01章 q05 問18）の 2 つ目の引数の中で、$1、$2 … と書くと、そこに 1 つ目、2 つ目 … の ( ) に合った部分が入ります。合った部分の一部だけを残して、ほかを書き換えるときに使います。

サンプル 
// 日付 date を作り、"2026-05-10" を入れる
const date = "2026-05-10";
// usDate を作り、date の中の「数字 4 つ、-、数字 2 つ、-、数字 2 つ」を、2 つ目のグループ、/、3 つ目のグループ、/、1 つ目のグループの順に並べ替えたものを入れる
const usDate = date.replace(/(\d{4})-(\d{2})-(\d{2})/g, "$2/$3/$1");
// 結果: usDate は "05/10/2026"

番号の一部だけが合ってしまうのを防ぐには、\b（単語の境目）を前後に付けます。

"090-1234-56789".replace(/(\d{3})-\d{4}-(\d{4})/g, "$1-****-$2")
"090-****-56789"
最後の 5 けたの途中で合ってしまう
"090-1234-56789".replace(/\b(\d{3})-\d{4}-(\d{4})\b/g, "$1-****-$2")
"090-1234-56789"
\b があると、数字の途中では合わない
(?<名前>…).groups

グループに名前を付けて取り出す

( ) の始まりを (?<名前> にすると、そのグループに名前を付けられます。.exec() の結果の .groups から、groups.名前 の形で取り出せます。番号で数えるより、何を取り出したのかがわかりやすくなります。

サンプル 
// 在庫の行 line を作り、"SKU-0042:12" を入れる
const line = "SKU-0042:12";
// groups を作り、line を /^(?<code>[A-Z]+-\d+):(?<qty>\d+)$/ に合わせた結果の名前付きグループ（合わなければ undefined）を入れる
const groups = /^(?<code>[A-Z]+-\d+):(?<qty>\d+)$/.exec(line)?.groups;
// 商品コード code を作り、groups の code（groups が undefined なら undefined）を入れる
const code = groups?.code;
// 結果: code は "SKU-0042"。groups の qty は "12"

型.exec() は、合わなければ null を返します。?.（03章 q03 問1）を付けると、null のときは groups が undefined になります。groups?.code の型は string | undefined です。使う前に undefined でないことを確かめます。

.replace(正規表現, 関数)

合った部分ごとに、関数で置き換える

.replace() の 2 つ目の引数には、関数（02章 q04 問5 のコールバック）も渡せます。合った部分が見つかるたびに、その部分の文字列を引数にして関数が呼ばれます。関数が返した文字列で置き換えます。合った部分を、大文字にするなど、変えてから入れたいときに使います。

// 名前 guest を作り、"sato taro" を入れる
const guest = "sato taro";

const title = guest.replace(/\b[a-z]/g, (c) => c.toUpperCase());
// 結果: title は "Sato Taro"
"a-b".replace(/[a-z]/g, (c) => c.toUpperCase())
"A-B"

ヒント 2コードへの直し方

isPostalCode は、1 つ目の項目のサンプルの isReserveNo と同じ形です。extractHashtags の「空白でも # でもない文字」は [^\s#] で、2 つ目の項目のサンプルの matches と prices の形を使います。maskPhone は、3 つ目の項目のサンプルと同じく $1 と $2 を使います。parseLogLine の正規表現は、level が (?<level>INFO|WARN|ERROR)、time が (?<time>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})、message が (?<message>.+) です。[ と ] は \[ と \] と書きます。groups.level の型は string なので、isLevel を型ガード関数（05章 q09 問1）にして、"INFO" | "WARN" | "ERROR" に絞り込みます。戻り値の型は value is LogLine["level"] と書けます。LogLine["level"] は、LogLine の level の型です（03章 q07 問10 のインデックスアクセス型）。camelToKebab は、4 つ目の項目のサンプルと同じく、.replace() に関数を渡します。説明することは、ターミナルで node と打って試します。g を付けた正規表現を変数に入れ、同じ文字列で .test() を何度か続けて呼び、結果と、変数の lastIndex の値がどう変わるかを見てから書きます。
