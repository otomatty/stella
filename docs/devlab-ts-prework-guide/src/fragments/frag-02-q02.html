02章 オブジェクト・配列・タプル

q02 オプションプロパティと readonly

オブジェクトのプロパティに印を付ける書き方を使って、関数を 20 個書きます。なくてもよいプロパティには、名前の後ろに ? を付けます（nickname?: string）。書き換えさせないプロパティには、前に readonly を付けます。なくてもよいプロパティの値は undefined のことがあります。そのときの扱いは、?? や !== undefined で書きます。引数と戻り値の型注釈は、これまでと同じく自分で書きます。

問1nickname があれば nickname で、なければ name であいさつする 新しく出てくる書き方：オプションプロパティ ? ?? 
export function greetUser() {}

利用者のオブジェクトを 1 つ受け取ります。name（名前）はいつもあり、nickname（ニックネーム）はないこともあります。nickname があれば nickname を、なければ name を使って、「こんにちは、◯◯さん」を返します。引数の型には、nickname がなくてもよいことを書きます。

テストで確かめる値
greetUser({ name: "山田太郎", nickname: "たろう" })
"こんにちは、たろうさん"
nickname を使う
greetUser({ name: "佐藤花子" })
"こんにちは、佐藤花子さん"
nickname がない

型引数が { name: string; nickname?: string }、戻り値が string であることも確かめます。

新しい書き方

名前?: 型

なくてもよいプロパティ

オブジェクトの型（q01 問1）で、プロパティの名前の後ろに ? を付けます。そのプロパティは、なくてもよくなります。これをオプションプロパティと呼びます。ないプロパティを読むと undefined（01章 q03 問12）になります。そのため、値の型は string | undefined です。

サンプル 
// 関数 deliveryNote を作る。オブジェクト order（item は文字列、note はなくてもよい文字列）を受け取り、文字列を返す
function deliveryNote(order: { item: string; note?: string }): string {
  // もし order の note がなければ
  if (order.note === undefined) {
    // "備考なし" を返す
    return "備考なし";
  }
  // order の note を返す
  return order.note;
}
// 結果: deliveryNote({ item: "米" }) は "備考なし"、deliveryNote({ item: "米", note: "置き配" }) は "置き配"
deliveryNote({ item: "米" })
"備考なし"
note は書かなくてよい
deliveryNote({ item: "米", note: "置き配" })
"置き配"
deliveryNote({ note: "置き配" })
型の確認でエラー
item は省けない
ないときを考えない
function deliveryNote(order: { item: string; note?: string }): string {
  // order の note を返す
  return order.note;
}
✕ 型の確認でエラーになります。note は undefined かもしれません
ないときを先に返す
function deliveryNote(order: { item: string; note?: string }): string {
  if (order.note === undefined) {
    return "備考なし";
  }
  return order.note;
}
○ if の後ろでは、note は string として扱われます

値があるかどうかは、!== undefined（01章 q01 問17）で調べます。結果は true か false です。

サンプル 
// 関数 hasNote を作る。オブジェクト order（item は文字列、note はなくてもよい文字列）を受け取り、true か false を返す
function hasNote(order: { item: string; note?: string }): boolean {
  // order の note があるかどうか（true か false）を返す
  return order.note !== undefined;
}
// 結果: hasNote({ item: "米", note: "置き配" }) は true、hasNote({ item: "米" }) は false

よくある間違いnote: string | undefined と書くと、「なくてもよい」になりません。note は書く必要があり、{ item: "米" } を渡すと型の確認でエラーになります。この番号のテストは、? を付けた形を確かめます。

??

なければ、代わりの値を使う

左の値が undefined なら右の値を、そうでなければ左の値を使います。左が null のときも右の値を使います。null は 03章 q03 で学びます。

サンプル 
// 関数 shippingFee を作る。オブジェクト item（name は文字列、fee はなくてもよい数値）を受け取り、数値を返す
function shippingFee(item: { name: string; fee?: number }): number {
  // item の fee（なければ 500）を返す
  return item.fee ?? 500;
}
// 結果: shippingFee({ name: "本", fee: 300 }) は 300、shippingFee({ name: "本" }) は 500
shippingFee({ name: "本", fee: 300 })
300
shippingFee({ name: "本" })
500
fee がない
shippingFee({ name: "本", fee: 0 })
0
0 は値があるので、そのまま使う
|| で書く
function shippingFee(item: { name: string; fee?: number }): number {
  return item.fee || 500;
}
✕ fee が 0 のときも 500 になります。lint もエラーにします
?? で書く
function shippingFee(item: { name: string; fee?: number }): number {
  return item.fee ?? 500;
}
○ fee が 0 なら 0 を返します

よくある疑問||（01章 q01 問15）は、0 や "" も「ない」と同じに扱います。?? が右に切り替えるのは、undefined と null のときだけです。

コツ?? の式は、テンプレートリテラルの ${ } の中にもそのまま書けます。

新しい書き方

readonly

書き換えさせないプロパティ

オブジェクトの型で、プロパティの名前の前に readonly を付けます。そのプロパティに値を入れ直そうとすると、型の確認でエラーになります。読むことはこれまでどおりできます。

サンプル 
// 関数 createOrder を作る。数値 id と数値 quantity を受け取り、オブジェクト（id は読み取り専用の数値、quantity は数値）を返す
function createOrder(id: number, quantity: number): { readonly id: number; quantity: number } {
  // id と quantity を入れたオブジェクトを返す
  return { id, quantity };
}
// 注文 order を作り、createOrder に 10 と 2 を渡して呼んだ結果を入れる
const order = createOrder(10, 2);
// order の quantity に 3 を入れ直す
order.quantity = 3;
// 結果: order は { id: 10, quantity: 3 }
quantity を入れ直す
const order = createOrder(10, 2);
// order の quantity に 3 を入れ直す
order.quantity = 3;
○ quantity には印がないので、入れ直せます
id を入れ直す
const order = createOrder(10, 2);
// order の id に 11 を入れ直す
order.id = 11;
✕ 型の確認でエラーになります（Cannot assign to 'id' because it is a read-only property）

よくある疑問テストにある // @ts-expect-error は、「次の行は型の確認でエラーになるはず」という印です。readonly を付け忘れると、次の行がエラーになりません。そのときは、この印のほうがエラー（Unused '@ts-expect-error' directive）になります。

決まりreadonly は型の確認のための印です。JavaScript に変換したあとのコードには残りません。

新しい書き方

{ ...元, 名前: 値 }

プロパティを写して、新しいオブジェクトを作る

オブジェクトの前に ... を付けて { } の中に書くと、そのプロパティをすべて写した新しいオブジェクトができます。この書き方をスプレッド構文と呼びます。後ろに書いたプロパティは、写した値を上書きします。元のオブジェクトは変わりません。ここでは、まねて書ければ十分です。くわしくは q03（分割代入とスプレッド構文）で学びます。

サンプル 
// 関数 upgrade を作る。オブジェクト member（id は読み取り専用の数値、rank は文字列）を受け取り、同じ形のオブジェクトを返す
function upgrade(member: { readonly id: number; rank: string }): {
  readonly id: number;
  rank: string;
} {
  // member のプロパティをすべて写し、rank を "ゴールド" にしたオブジェクトを返す
  return { ...member, rank: "ゴールド" };
}
// 会員 before を作り、id が 5、rank が "一般" のオブジェクトを入れる
const before = { id: 5, rank: "一般" };
// 会員 after を作り、upgrade に before を渡して呼んだ結果を入れる
const after = upgrade(before);
// 結果: after は { id: 5, rank: "ゴールド" }、before は { id: 5, rank: "一般" } のまま
{ ...before, rank: "ゴールド" }
{ id: 5, rank: "ゴールド" }
後ろの rank が残る
{ rank: "ゴールド", ...before }
{ rank: "一般", id: 5 }
写した rank で上書きされる。型の確認もエラーにする

よくある間違い受け取ったオブジェクトの done に true を入れ直して、そのまま返すこともできます。型の確認は通りますが、元の ToDo まで変わります。この問題のテストは、元の ToDo が変わっていないことを確かめます。
