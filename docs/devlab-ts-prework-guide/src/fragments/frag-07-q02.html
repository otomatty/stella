07章 型の再利用とジェネリクス

q02 keyof 型演算子

型からキーの名前を取り出す keyof を使って、型と関数を 20 個書きます。型 User・Product と、定数 SETTINGS・COLOR_CODES は、ファイルに書いてあります。keyof 型 と書くと、その型のプロパティ名を | でつないだユニオン型になります。定数から作るときは keyof typeof 定数 と書きます。型を作る問題では、プロパティ名を手で書き並べずに、keyof を使います。関数の引数と戻り値には、型注釈を付けます。

問1型 UserKey を keyof User で作る 新しく出てくる書き方：型に付ける keyof 型 
export type User = { id: number; name: string; email: string; age: number };

// ここに型 UserKey を書く

型 UserKey を作り、export を付けます。UserKey は、User のプロパティ名のどれかを表す型です。"id" などを手で並べずに、keyof で作ります。

テストで確かめる値
UserKey の型
"id" | "name" | "email" | "age"
と同じ型であること

新しい書き方

keyof Member

型から、キーの名前のユニオン型を作る

keyof は、型からキーの名前を取り出す型演算子です。型演算子は、型から別の型を作る書き方です。オブジェクトの型の前に keyof を付けると、その型のキー（プロパティ名）を | でつないだユニオン型になります。03章 q07 問12 では、keyof typeof 定数 の形を読みました。ここでは、型に直接付ける形から整理します。

サンプル 
// 会員 Member という型を作る。name は文字列、points は数値、active は真偽値
type Member = { name: string; points: number; active: boolean };
// MemberKey という型を作る。Member のキーのどれか
type MemberKey = keyof Member;
// 並べ替える項目 sortField を作る。型は MemberKey。"points" を入れる
const sortField: MemberKey = "points";
// 結果: MemberKey は "name" | "points" | "active"、sortField は "points"
keyof Member
"name" | "points" | "active"
キーのどれか
Member["points"]
number
キーを 1 つ決めて取り出したプロパティの型
Member[keyof Member]
string | number | boolean
キーのどれかで取り出したプロパティの型

表の 2 行目と 3 行目は、q01 で学んだインデックスアクセス型です（q01 問4、問8）。[ ] にキーを 1 つ書くと、そのプロパティの型になります。keyof で作ったユニオン型を書くと、それぞれのプロパティの型を | でつないだ型になります。

型に keyof を付ける
// MemberKey という型を作る。Member のキーのどれか
type MemberKey = keyof Member;
○ Member は型なので、そのまま keyof を付けられます
定数に keyof だけを付ける
// 定数 DEFAULT_MEMBER を作り、{ name: "ゲスト", points: 0, active: false } を入れる
const DEFAULT_MEMBER = { name: "ゲスト", points: 0, active: false };
// DefaultKey という型を作る。DEFAULT_MEMBER のキーのどれか
type DefaultKey = keyof DEFAULT_MEMBER;
✕ 型の確認でエラーになります（'DEFAULT_MEMBER' refers to a value, but is being used as a type here. Did you mean 'typeof DEFAULT_MEMBER'?）

DEFAULT_MEMBER のような定数は値です。keyof は型にしか付けられません。値からキーを取り出すときは、03章 q07 問12 と同じく、先に typeof で型にしてから keyof を付けます。

keyof Member
"name" | "points" | "active"
Member は型
keyof typeof DEFAULT_MEMBER
"name" | "points" | "active"
DEFAULT_MEMBER は値

よくある間違いsortField に "email" を入れると、型の確認でエラーになります（Type '"email"' is not assignable to type 'keyof Member'）。Member にないキーだからです。

コツMember にプロパティを足すと、MemberKey にもそのキーが入ります。キーの名前を書くのは、型の 1 か所だけで済みます。

新しい書き方

(keyof Member)[]

キーの名前を並べた配列の型

キーの名前を並べた配列の型は、keyof Member をかっこで囲み、後ろに [] を付けます。要素がユニオン型の配列を、かっこでまとめるのと同じです（03章 q03 問12）。readonly を付けると、読み取り専用の配列になります（02章 q04 問1）。

サンプル 
// 会員 Member という型を作る。name は文字列、points は数値、active は真偽値
type Member = { name: string; points: number; active: boolean };
// 表に出す項目 columns を作る。型は Member のキーのどれかの読み取り専用の配列。"name"、"points" を並べた配列を入れる
const columns: readonly (keyof Member)[] = ["name", "points"];
// 結果: columns は ["name", "points"]
かっこで囲む
const columns: (keyof Member)[] = ["name", "points"];
○ 要素が Member のキーのどれかの配列です
かっこを付けない
const columns: keyof Member[] = ["name", "points"];
✕ 型の確認でエラーになります（Type 'string[]' is not assignable to type 'keyof Member[]'.）

かっこがないと、keyof は後ろの Member[] 全体に付きます。Member[] は配列の型なので、length や push のような配列のプロパティ名と番号のどれか、という型になってしまいます。

よくある間違いかっこを付けずに readonly keyof Member[] と書くと、別のエラーも出ます（'readonly' type modifier is only permitted on array and tuple literal types.）。readonly は、(keyof Member)[] のような配列の型の前にだけ付けられます。
