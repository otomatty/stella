08章 非同期処理

q01 Promise

Promise を使った関数を 20 個書きます。Promise は「あとで結果が届く値」です。この番号では async と await は使いません（q02 で学びます）。使うのは new Promise、then・catch・finally、Promise.resolve・Promise.reject・Promise.all・Promise.race・Promise.allSettled です。引数と戻り値には型注釈を付けます。戻り値の型は Promise<number> のように、Promise の中身の型まで書きます。失敗させるときは、文字列を使わずに Error を使います。

問1value ですぐに解決する Promise を返す 新しく出てくる書き方：Promise<T> Promise.resolve() 
export function resolveWith() {}

文字列を 1 つ受け取り、その文字列ですぐに解決する Promise を返します。「解決する」は、Promise に結果の値が届くことです。戻り値の型は、文字列で解決する Promise（Promise<string>）です。

テストで確かめる値
resolveWith("a")
"a" で解決する

型引数が string、戻り値が Promise<string> であることも確かめます。

新しい書き方

Promise<T>

あとで結果が届く値（Promise）

ここまでの関数は、呼ぶとすぐに結果を返しました。サーバーからデータを取る処理や、決まった時間を待つ処理は、結果が出るまで時間がかかります。このような処理を非同期処理といいます。非同期処理の関数は、結果の代わりに Promise を返します。Promise は「あとで結果が届く入れ物」です。

Promise には 3 つの状態があります。作られたときは「待ち」です。あとで結果が届くと「解決」か「失敗」のどちらか 1 つに決まります。解決は、値が届いて成功したことです。失敗は、エラーが届いたことです。失敗は「拒否」（reject）ともいいます。一度決まった状態は、もう変わりません。

型は Promise<number> のように、< > の中に「解決したときに届く値の型」を書きます。07章 q06 問8 の Page<T> と同じく、型に型引数を渡す書き方です。

サンプル 
// 送料 shipping を数値で解決する Promise として作り、500 ですぐに解決する Promise を入れる
const shipping: Promise<number> = Promise.resolve(500);
// 結果: shipping は 500 で解決する Promise

よくある間違いPromise の中の値は、そのままでは使えません。shipping + 100 と書くと、Promise<number> と数は足せないという型のエラーになります。届いた値を受け取る書き方は、問5 の then で学びます（q02 では await も学びます）。

Promise.resolve()

すぐに解決する Promise を作る

Promise.resolve(値) は、かっこの中の値ですぐに解決する Promise を作ります。待つ処理がなくても、Promise の形で返したいときに使います。中身の型は、渡した値から決まります。

サンプル 
// 予約の状態 status を作り、"予約済み" ですぐに解決する Promise を入れる
const status = Promise.resolve("予約済み");
// 結果: status は "予約済み" で解決する Promise。型は Promise<string>
Promise.resolve(500)
500 で解決する Promise
型は Promise<number>
Promise.resolve("予約済み")
"予約済み" で解決する Promise
型は Promise<string>

新しい書き方

Promise.reject()

すぐに失敗する Promise を作る

Promise.reject(理由) は、かっこの中の理由ですぐに失敗する Promise を作ります。理由には new Error("…") を渡します（01章 q04 問8）。

必ず失敗する Promise は、解決の値が届きません。「ありえない値」を表す never（04章 q07 問1）を使って、型を Promise<never> と書きます。

サンプル 
// 関数 outOfStock を作る。文字列 name を受け取り、必ず失敗する Promise を返す
function outOfStock(name: string): Promise<never> {
  // name を埋め込んだ「◯は在庫がありません」というメッセージのエラーで失敗する Promise を返す
  return Promise.reject(new Error(`${name}は在庫がありません`));
}
// 結果: outOfStock("ノート") は "ノートは在庫がありません" のエラーで失敗する Promise

よくある間違いPromise.reject("在庫がありません") のように文字列を渡すと、ESLint が「理由は Error にする」と知らせます。Error にしておくと、受け取る側が .message でメッセージを読めます。

new Promise()

Promise を自分で作る

new Promise(関数) で、新しい Promise を作れます。かっこの中には、Promise を作るときに 1 回だけ呼ばれる関数を渡します。その関数は、引数に resolve を受け取ります。resolve は「この Promise を解決させる関数」です。resolve(値) を呼んだときに、Promise がその値で解決します。呼ぶまでは「待ち」のままです。

サンプル 
// 手数料 fee を作り、新しい Promise を入れる。作るときに、解決する関数 resolve を受け取り、次のことをする
const fee = new Promise<number>((resolve) => {
  // resolve に 300 を渡して呼ぶ
  resolve(300);
});
// 結果: fee は 300 で解決する Promise

よくある疑問<number> を書かずに変数へ入れると、TypeScript は中身の型を決められず、Promise<unknown> になります。関数の戻り値として return するときは、戻り値の型注釈（: Promise<void> など）から決まるので、< > は書かなくてかまいません。値なしで解決するときは、resolve() とかっこの中を空にして呼びます。

then の中でエラーを投げる

then に渡した関数の中でエラーを投げると、then が返す Promise は、そのエラーで失敗します。投げたエラーで関数が止まるのは 01章 q04 問8 と同じです。違うのは、エラーが Promise の失敗として届くことです。

関数の中に文を何行も書くときは、=> の後ろを { } にして、値は return で返します（01章 q01 問20）。

サンプル 
// 関数 checkedQuantity を作る。数値で解決する Promise の quantity を受け取り、数値で解決する Promise を返す
function checkedQuantity(quantity: Promise<number>): Promise<number> {
  // quantity の値を n として受け取り、次のことをする関数が返した値で解決する Promise を返す
  return quantity.then((n) => {
    // もし n が 1 より小さいなら
    if (n < 1) {
      // "数量は 1 以上にしてください" というメッセージのエラーを投げる
      throw new Error("数量は 1 以上にしてください");
    }
    // n を返す
    return n;
  });
}
// 結果: checkedQuantity(Promise.resolve(3)) は 3 で解決する
// 結果: checkedQuantity(Promise.resolve(0)) は "数量は 1 以上にしてください" のエラーで失敗する

.catch()

.then().catch()

then と catch をつなげる

then も catch も Promise を返すので、続けて書けます。上から順に、届いた結果が流れていきます。成功は then の関数を通り、catch は飛ばされます。失敗は then を飛ばして、catch の関数に届きます。

catch の関数は、引数に失敗の理由を受け取ります。理由には、Error でない値が届くこともあります。そのため、引数の型は unknown と書きます。型を書かないと、ESLint が「: unknown にする」と知らせます。instanceof で確かめてから使うのは、04章 q05 問10 の catch (error) と同じです。

サンプル 
// 関数 orderStatus を作る。数値で解決する Promise の order を受け取り、文字列で解決する Promise を返す

  // order の値を id として受け取り、id を埋め込んだ「注文 ◯ を受け付けました」の文字列で解決する Promise にする
  // それが失敗したら、理由を error で受け取り、error が RangeError から作った値なら "数量が多すぎます"、そうでなければ "受け付けできません" で解決する Promise を返す
  return order
    .then((id) => `注文 ${id} を受け付けました`)
    .catch((error: unknown) =>
      error instanceof RangeError ? "数量が多すぎます" : "受け付けできません",
    );
}
// 結果: orderStatus(Promise.resolve(7)) は "注文 7 を受け付けました" で解決する
// 結果: orderStatus(Promise.reject(new RangeError("数量は 10 個までです"))) は "数量が多すぎます" で解決する
// 結果: orderStatus(Promise.reject(new Error("在庫がありません"))) は "受け付けできません" で解決する

要素を配列に変え、それらをつなげる

.flatMap(関数) は、.map()（02章 q04 問5）と同じく要素を 1 つずつ関数に渡します。違うのは、関数が配列を返すことです。返した配列の中身を、順につなげた 1 つの配列が結果になります。

新しい書き方

(resolve, reject) =>

new Promise の中で失敗させる

new Promise に渡す関数は、2 つ目の引数に reject を受け取れます。reject は「この Promise を失敗させる関数」です。reject(new Error("…")) を呼んだときに、Promise がそのエラーで失敗します。

サンプル 
// 関数 reserveSeat を作る。数値 left を受け取り、文字列で解決する Promise を返す
function reserveSeat(left: number): Promise<string> {
  // 新しい Promise を作って返す。作るときに、解決する関数 resolve と失敗させる関数 reject を受け取り、次のことをする
  return new Promise((resolve, reject) => {
    // もし left が 0 と等しいなら
    if (left === 0) {
      // reject に、"満席です" というメッセージのエラーを渡して呼ぶ
      reject(new Error("満席です"));
    } else {
      // そうでなければ、resolve に "予約できました" を渡して呼ぶ
      resolve("予約できました");
    }
  });
}
// 結果: reserveSeat(3) は "予約できました" で解決する
// 結果: reserveSeat(0) は "満席です" のエラーで失敗する

// 関数 expireAfter を作る。数値 ms を受け取り、必ず失敗する Promise を返す
function expireAfter(ms: number): Promise<never> {
  // 新しい Promise を作って返す。作るときに、使わない 1 つ目の引数を _、失敗させる関数を reject として受け取り、次のことをする
  return new Promise((_, reject) => {
    // ms ミリ秒たったら、reject に "予約の期限が切れました" というメッセージのエラーを渡して呼ぶ関数を呼ぶように予約する
    setTimeout(() => {
      reject(new Error("予約の期限が切れました"));
    }, ms);
  });
}
// 結果: expireAfter(3000) は、3000 ミリ秒たったら "予約の期限が切れました" のエラーで失敗する

expireAfter は resolve を使いません。引数は並びで受け取るので、2 つ目の reject を受け取るには 1 つ目も書く必要があります。使わない引数には _ という名前を付けておきます。
