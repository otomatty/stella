06章 発展問題（任意）

発展問題

やってもやらなくてもよい、任意の課題です。章の課題とは別に数えます。番号の順に、1 問ずつ確認して提出します。e01 には「説明すること」があり、ファイルの「説明すること」のすぐ下に // のコメントで書きます。フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。

e01抽象クラス 新しく出てくる書き方：abstract class、abstract なメソッド 
export class Report {}

export class SalesReport {}

export class TodoReport {}

抽象クラスは、それ自体からは new できず、継承して使うためのクラスです。中身を子クラスに任せたいメソッドには abstract を付け、本体を書かずに形だけを決めます。レポートを表す抽象クラス Report と、それを継承したクラスを 2 つ書きます。

  1. Report は抽象クラスにします。title()（文字列を返す）と body()（文字列の配列を返す）は abstract にして、子クラスで書きます。render() は Report に書きます。"# タイトル" の行と、body() の各行の前に "- " を付けた行を、改行（"\n"）でつないだ文字列を返します。
  2. SalesReport は、売上の配列 sales（readonly number[]）を受け取ります。title() は "売上レポート"、body() は ["件数 3", "合計 600"] の形の配列を返します。
  3. TodoReport は、ToDo の配列 todos（readonly string[]）を受け取ります。title() は "ToDo"、body() は todos をそのまま並べた配列を返します。todos が空なら ["なし"] を返します。

説明すること：インターフェースではなく抽象クラスを使うとよいのは、どんなときか。

テストで確かめる値
new Report()
型エラー
抽象クラスからは new できない

sales は new SalesReport([100, 200, 300])、todos は new TodoReport(["買い物", "掃除"])、empty は new TodoReport([]) です。

sales.render()
"# 売上レポート\n- 件数 3\n- 合計 600"
todos.render()
"# ToDo\n- 買い物\n- 掃除"
empty.render()
"# ToDo\n- なし"
空なら "なし" の 1 行

reports は、型を Report[] にした配列 [new SalesReport([100]), new TodoReport([])] です。

reports.map((r) => r.title())
["売上レポート", "ToDo"]
子クラスは Report として扱える

sales.render() の結果を画面に出すと、次の 3 行になります。

- 件数 3
- 合計 600

新しい書き方

abstract class

new できない、継承するためだけのクラス

class の前に abstract を付けると、抽象クラスになります。抽象クラスからは new できません。extends（06章 q04）で子クラスを作り、子クラスから new します。子クラスに共通の処理を、親の抽象クラスに書いておけます。

サンプル 
// 継承するためだけのクラス Notice を作る
abstract class Notice {
  // 子クラスで書くメソッド subject を決める。文字列を返す
  abstract subject(): string;

  // メソッド header を作る。文字列を返す
  header(): string {
    // this.subject() の結果を埋め込んだ「件名: ◯」の文字列を返す
    return `件名: ${this.subject()}`;
  }
}

// Notice を継承したクラス ShippingNotice を作る
class ShippingNotice extends Notice {
  // メソッド subject を作る。文字列を返す
  subject(): string {
    // "発送のお知らせ" を返す
    return "発送のお知らせ";
  }
}

// header を作り、新しい ShippingNotice の header を呼んだ結果を入れる
const header = new ShippingNotice().header();
// 結果: header は "件名: 発送のお知らせ"
抽象クラスから new する
const notice = new Notice();
✕ 抽象クラスのインスタンスは作れない、という型エラーになります
子クラスから new する
const notice = new ShippingNotice();
○ subject を書いた子クラスなので、作れます

抽象クラスも、型として使えます。const notices: Notice[] = [new ShippingNotice()]; のように、抽象クラスの型の配列に、子クラスのインスタンスを入れられます（06章 q04 の、子クラスを親クラスの型で扱う項目）。

サバイバルTypeScript「抽象クラス」

abstract subject(): string;

中身を子クラスに任せるメソッド

抽象クラスの中で、メソッドに abstract を付けると、名前と引数と戻り値の型だけを決めたメソッドになります。{ } の本体は書かず、最後に ; を付けます。インターフェースのメソッドの書き方（06章 q03）と同じ形です。

子クラスは、abstract なメソッドをすべて書かないと、型エラーになります。書き忘れたメソッドがあれば、型の確認で気づけます。親の header() の中の this.subject() は、06章 q04 の override の項目と同じく、子クラスで書いたメソッドが呼ばれます。

subject を書かない
class EmptyNotice extends Notice {}
✕ 継承した abstract なメンバー subject を書いていない、という型エラーになります
subject を書く
class ShippingNotice extends Notice {
  subject(): string {
    return "発送のお知らせ";
  }
}
○ 型エラーになりません

決まりabstract なメソッドを子クラスで書くときは、override を付けなくても型エラーになりません。親に本体がないので、書き換えにはあたらないからです。付けてもかまいません。

ヒント 2コードへの直し方

Report は、abstract class の項目のサンプルの Notice と同じ形で、abstract なメソッドが 2 つになります。render の改行は "\n" で、.join("\n") でつなぎます（04章 q08 問20、02章 q04 問11）。「◯ と lines の要素すべてをこの順に並べた配列」は、配列のスプレッド [`# …`, ...lines] です（02章 q05 問1）。SalesReport と TodoReport は、スターターの export class の後ろに extends Report を書き足します。constructor は、06章 q04 ドリル問17 の EmailNotifier と同じく super() を呼びます。TodoReport の body は戻り値が string[] なので、読み取り専用の this.todos はそのまま返せません。[...this.todos] でコピーして返します。説明することは、Report を 06章 q03 の interface で書き直そうとしてみて、render をどこに書くことになるかを確かめてから書きます。試したあとは、抽象クラスの形に戻してから提出します。

e02static、getter・setter、メソッドチェーン 新しく出てくる書き方：static なフィールド、static なメソッド、getter get、setter set、戻り値の型 this

温度を表すクラス Temperature と、文字列を組み立てるクラス QueryBuilder を書きます。

  1. Temperature は、constructor で摂氏 celsius を受け取り、private なフィールドに持ちます。
    • fahrenheit：読むと華氏を返します（摂氏 × 9 ÷ 5 + 32）。temperature.fahrenheit のように、() なしで読めるようにします。
    • fahrenheit に代入すると、華氏で受け取った値を摂氏に直して持ちます（(華氏 − 32) × 5 ÷ 9）。
    • celsius：読むと摂氏を返します。
    • Temperature.fromFahrenheit(value)：華氏から Temperature を作って返します。new しなくても、クラスの名前から呼べるようにします。
    • Temperature.created：これまでに作られた Temperature の数です。クラスそのものに持たせ、constructor で 1 増やします。
  2. QueryBuilder は、メソッドをつなげて条件の文字列を組み立てます。
    • where(condition)：条件を足して、自分（this）を返します。戻り値の型も this にします。
    • limit(n)：件数を決めて、自分を返します。
    • build()："WHERE age > 20 AND active LIMIT 10" の形の文字列を返します。条件が 2 つ以上なら " AND " でつなぎます。条件がなければ WHERE の部分を、件数がなければ LIMIT の部分を付けません。

新しい書き方

static issued = 0;

クラスそのものに持たせるフィールド

フィールドの前に static を付けると、クラスに 1 つだけのフィールドになります。インスタンスが持つフィールドとは別のものです。読み書きするときは、クラス名.フィールド名 と書きます。いくつインスタンスを作っても、同じ 1 つのフィールドを使います。

サンプル 
// クラス Ticket を作る
class Ticket {
  // クラスそのものに持たせるフィールド issued を作り、0 を入れる
  static issued = 0;

  // constructor を作る。文字列の seat を受け取り、入れ直せないフィールド seat にする
  constructor(readonly seat: string) {
    // Ticket の issued を 1 増やす
    Ticket.issued++;
  }
}

// first を作り、座席を "A1" にした Ticket を入れる
const first = new Ticket("A1");
// second を作り、座席を "A2" にした Ticket を入れる
const second = new Ticket("A2");
// 結果: Ticket.issued は 2、first.seat は "A1"、second.seat は "A2"
インスタンスから読む
const count = first.issued;
✕ Ticket のインスタンスに issued はない、という型エラーになります
クラスの名前から読む
const count = Ticket.issued;
○ count は 2 です

サバイバルTypeScript「静的フィールド」

static fromThousands(…)

new しないで、クラスの名前から呼べるメソッド

メソッドの前に static を付けると、クラス名.メソッド名() で呼べるメソッドになります。インスタンスを作る前に呼べるので、別の単位の値から、インスタンスを作って返すときによく使います。

サンプル 
// クラス Price を作る
class Price {
  // constructor を作る。数値の yen を受け取り、入れ直せないフィールド yen にする
  constructor(readonly yen: number) {}

  // new しないで呼べるメソッド fromThousands を作る。数値の thousands を受け取り、Price を返す
  static fromThousands(thousands: number): Price {
    // thousands × 1000 を渡した、新しい Price を返す
    return new Price(thousands * 1000);
  }
}

// price を作り、Price の fromThousands に 3 を渡して呼んだ結果を入れる
const price = Price.fromThousands(3);
// 結果: price.yen は 3000

よくある疑問static なメソッドの中では、this はインスタンスを指しません。インスタンスのフィールドを使うときは、サンプルのように new で作ってから使います。

サバイバルTypeScript「静的メソッド」

get total(): number

() なしで読める、読むときに動くメソッド（getter）

メソッドの前に get を付けると、フィールドと同じく () なしで読めるメソッドになります。これを getter と呼びます。読むたびに、中の処理が動いて値を返します。ほかのフィールドから計算して出す値に使います。

サンプル 
// クラス Cart を作る
class Cart {
  // constructor を作る。数値の読み取り専用の配列 prices を受け取り、外から読めず、入れ直せないフィールド prices にする
  constructor(private readonly prices: readonly number[]) {}

  // 読むときに動くメソッド total を作る。数値を返す
  get total(): number {
    // 合計 sum を入れ直せる変数として作り、0 を入れる
    let sum = 0;
    // this.prices から 1 つずつ price に取り出してくり返す
    for (const price of this.prices) {
      // sum に price を足す
      sum += price;
    }
    // sum を返す
    return sum;
  }
}

// total を作り、[300, 500] を渡した Cart の total を読んだ値を入れる
const total = new Cart([300, 500]).total;
// 結果: total は 800

決まりgetter と同じ名前のフィールドは、同じクラスに作れません。celsius という getter を作るなら、中で持つフィールドは celsiusValue のように別の名前にします。

MDN「get」

set years(value: number)

代入したときに動くメソッド（setter）

メソッドの前に set を付けると、インスタンス.名前 = 値 と代入したときに動くメソッドになります。これを setter と呼びます。代入した値が、引数に入ります。同じ名前の getter と組みにすると、外からはふつうのフィールドのように読み書きできます。

サンプル 
// クラス Contract を作る
class Contract {
  // 外から読めないフィールド months を作り、12 を入れる
  private months = 12;

  // 読むときに動くメソッド years を作る。数値を返す
  get years(): number {
    // this.months ÷ 12 を返す
    return this.months / 12;
  }

  // 代入したときに動くメソッド years を作る。数値の value を受け取る
  set years(value: number) {
    // this.months に value × 12 を入れ直す
    this.months = value * 12;
  }

  // メソッド label を作る。文字列を返す
  label(): string {
    // this.months を埋め込んだ「契約 ◯か月」の文字列を返す
    return `契約 ${this.months}か月`;
  }
}

// contract を作り、新しい Contract を入れる
const contract = new Contract();
// contract の years に 3 を入れる
contract.years = 3;
// 結果: contract.years は 3、contract.label() は "契約 36か月"

決まりsetter には、戻り値の型を書きません。書くと型エラーになります。値を返さないことが決まっているからです。

MDN「set」

add(line: string): this

自分を返して、メソッドをつなげる（メソッドチェーン）

メソッドの最後で return this; と書くと、そのメソッドは呼んだインスタンス自身を返します。そのため、結果に続けて、同じインスタンスのメソッドを呼べます。このつなげ方をメソッドチェーンと呼びます。戻り値の型には this と書きます。「自分と同じ型」という意味です。

サンプル 
// クラス MailBuilder を作る
class MailBuilder {
  // 外から読めないフィールド lines を作り、空の文字列の配列を入れる
  private lines: string[] = [];

  // メソッド add を作る。文字列の line を受け取り、自分と同じ型を返す
  add(line: string): this {
    // this.lines の後ろに line をつなげる
    this.lines.push(line);
    // this を返す
    return this;
  }

  // メソッド build を作る。文字列を返す
  build(): string {
    // this.lines の要素を "／" でつないだ文字列を返す
    return this.lines.join("／");
  }
}

// mail を作り、新しい MailBuilder に "ご注文ありがとうございます" と "発送しました" を順に add し、build した結果を入れる
const mail = new MailBuilder().add("ご注文ありがとうございます").add("発送しました").build();
// 結果: mail は "ご注文ありがとうございます／発送しました"

サンプルの最後の行は、左から順に動きます。

順番呼ぶもの返すもの
1new MailBuilder()新しいインスタンス
2.add("ご注文ありがとうございます")同じインスタンス（lines は 1 行）
3.add("発送しました")同じインスタンス（lines は 2 行）
4.build()"ご注文ありがとうございます／発送しました"

よくある疑問戻り値の型を MailBuilder と書いても動きます。this と書くと、MailBuilder を継承した子クラスで呼んだときに、戻り値の型が子クラスになります。子クラスにだけあるメソッドも、続けて呼べます。

ヒント 2コードへの直し方

created は、static なフィールドの項目の Ticket の issued と同じ形です。constructor の引数の名前は、getter の celsius とぶつからないように celsiusValue にします。fromFahrenheit は、static なメソッドの項目の Price.fromThousands と同じ形です。new Temperature(…) で作るので、created もそこで 1 増えます。celsius と fahrenheit の読み書きは、getter・setter の項目の Contract の years と同じ形です。計算は、先に掛けてから割る順で書くと、テストの値がちょうどになります。count は、値を入れずに private count: number | undefined; と書くと、最初は undefined が入ります。where と limit は、メソッドチェーンの項目の add と同じ形です。build の最後は .join(" ") です。parts が空なら空の文字列、1 つならその文字列だけになります。
