08章 非同期処理

q03 fetch

サーバー（API）と通信する関数を 20 個書きます。通信には fetch を使い、待つところは async と await（q02）で書きます。引数と戻り値には型注釈を付けます。定数 API、型 User・Todo、型ガード関数 isUser・isTodo は、問題のファイルに定義済みです。テストでは fetch を差し替えるので、本物の通信はしません。fetch に渡した URL や設定（2 つ目の引数）も、テストで確かめます。res.json() の結果は、unknown の変数に入れてから、型ガード関数で確かめて使います。「HTTP 404 の Error」は、数字の部分を res.status にしたメッセージの Error のことです。

問1url を fetch して、ステータスコードを返す 新しく出てくる書き方：fetch() res.status 
export const API = "https://api.example.com";

export function getStatus() {}

URL を 1 つ受け取り、そのサーバーに fetch で取得を頼みます。サーバーが返したステータスコード（結果を表す 3 桁の数）を返します。引数は文字列 1 つ、戻り値は数値で解決する Promise（Promise<number>）です。テストでは本物のサーバーには通信しません。fetch を、決まった応答を返す偽物に差し替えてから、関数を呼びます。

テストで確かめる値
サーバーが 404 を返したとき、getStatus(`${API}/a`)
404 で解決する
  • fetch に、`${API}/a` だけを渡して呼んだことも確かめます。

型引数が string、戻り値が Promise<number> であることも確かめます。

新しい書き方

fetch(url)

URL のサーバーに取得を頼む

fetch は、ブラウザや Node.js に組み込まれた関数です。かっこの中の URL のサーバーに、リクエスト（頼みごと）を送ります。戻り値は Promise です。サーバーから応答が届くと、応答のオブジェクト（Response）で解決します。await（q02 問1）で待つと、応答を受け取れます。

サンプル 
// 非同期の関数 stockStatus を作る。文字列 itemId を受け取り、数値で解決する Promise を返す
async function stockStatus(itemId: string): Promise<number> {
  // 応答 res を作り、itemId を埋め込んだ在庫の URL を fetch して、その結果を待って入れる
  const res = await fetch(`https://shop.example.com/stock/${itemId}`);
  // res のステータスコードを返す
  return res.status;
}
// 結果: サーバーが 200 を返したとき、stockStatus("A-100") は 200 で解決する
res.status

ステータスコードを読む

応答の status には、サーバーが返したステータスコードが数値で入っています。結果を表す 3 桁の数で、よく出るのは次のものです。

成功

201

見つからない
その URL のものがない

よくある疑問テストは本物のサーバーに通信しません。テストは vi.stubGlobal で fetch を偽物に差し替えます。偽物の fetch は、テストが用意した応答（たとえばステータスコード 404 の Response）をそのまま返します。そのため api.example.com が実在しなくても、テストは毎回同じ結果になります。偽物は渡された引数も覚えているので、どの URL を頼んだかもテストで確かめられます。

新しい書き方

res.ok

成功したかどうかを読む

応答の ok は、ステータスコードが 200 から 299 のとき true、それ以外のとき false です。数を比べなくても、成功したかどうかが分かります。

サンプル 
// 非同期の関数 reserveMessage を作る。文字列 date を受け取り、文字列で解決する Promise を返す
async function reserveMessage(date: string): Promise<string> {
  // 応答 res を作り、date を埋め込んだ予約の URL を fetch して、その結果を待って入れる
  const res = await fetch(`https://shop.example.com/reservations/${date}`);
  // もし res が ok でないなら
  if (!res.ok) {
    // "予約できません" を返す
    return "予約できません";
  }
  // "予約できます" を返す
  return "予約できます";
}
// 結果: サーバーが 200 を返したとき "予約できます"、409 を返したとき "予約できません" で解決する

ステータスコードが 201 のときの res.ok
true
200 から 299 は true
ステータスコードが 404 のときの res.ok

ステータスコードが 500 のときの res.ok

よくある間違いfetch の Promise は、サーバーが 404 や 500 を返しても失敗しません。応答が届けば、その応答で解決します。失敗するのは、サーバーにつながらないなど、通信そのものができなかったときです（問20）。そのため、成功したかどうかは res.ok で確かめます。

新しい書き方

res.text()

本文を文字列として読む

応答の中身を、本文（ボディ）と呼びます。res.text() は、本文を文字列として読みます。本文を読むのにも時間がかかるので、戻り値は文字列で解決する Promise です。await で待ってから使います。

サンプル 
// 非同期の関数 noticeText を作る。文字列で解決する Promise を返す
async function noticeText(): Promise<string> {
  // 応答 res を作り、お知らせの URL を fetch して、その結果を待って入れる
  const res = await fetch("https://shop.example.com/notice");
  // res の本文を文字列として読み、その結果を待って返す
  return await res.text();
}
// 結果: サーバーが本文 "本日は全品 10% 引きです" を返したとき、noticeText() は "本日は全品 10% 引きです" で解決する

よくある間違い本文は 1 回しか読めません。res.text() のあとで、同じ res の res.text() や res.json() を呼ぶと、TypeError で失敗します。読んだ結果は変数に入れて使い回します。

新しい書き方

res.json()

本文を JSON として読む

res.json() は、本文を JSON として読み、値にします。JSON.parse()（04章 q05 問5）と同じ働きです。戻り値は Promise で、中身の型は any（型の確認をしない型）です。any のまま使うと、型の確認が効きません。そこで、unknown（02章 q01）の変数に入れてから、確かめて使います。

サンプル 
// 非同期の関数 memberData を作る。数値 id を受け取り、型の分からない値で解決する Promise を返す
async function memberData(id: number): Promise<unknown> {
  // 応答 res を作り、id を埋め込んだ会員の URL を fetch して、その結果を待って入れる
  const res = await fetch(`https://shop.example.com/members/${id}`);
  // 値 data を作り、型を unknown にして、res の本文を JSON として読んだ結果を待って入れる
  const data: unknown = await res.json();
  // data を返す
  return data;
}
// 結果: サーバーが本文 {"id":7,"name":"佐藤"} を返したとき、memberData(7) は { id: 7, name: "佐藤" } で解決する
型を書かない
const data = await res.json();
✕ lint で「Unsafe assignment of an `any` value」というエラーになります
unknown にする
const data: unknown = await res.json();
○ 確かめてから使う値になります

新しい書き方

.every(isProduct)

.every() に型ガード関数を渡すと、配列の型が狭まる

Array.isArray()（04章 q06 問2）で確かめると、unknown の値は any[] になります。配列だとは分かっても、要素の型は分からないままです。そのまま返すと、lint の「Unsafe return of a value of type `any[]`」というエラーになります。続けて .every()（02章 q04 問20）に型ガード関数の名前を渡して確かめると、配列の型がその型の配列に狭まります。名前の渡し方は .filter(isBook)（05章 q09 問11）と同じです。

サンプル 
// Product という型を作る。name は文字列、price は数値
type Product = { name: string; price: number };
// 関数 isProduct を作る。型の分からない value を受け取り、true か false を返す。true のときは value を Product に絞り込む
function isProduct(value: unknown): value is Product {
  // value の型を表す文字列が "object" と等しい、かつ value が null でない、かつ value に "name" というキーがある、かつ value の name の型が文字列、かつ value に "price" というキーがある、かつ value の price の型が数値かどうか（true か false）を返す
  return (
    typeof value === "object" &&
    value !== null &&
    "name" in value &&
    typeof value.name === "string" &&
    "price" in value &&
    typeof value.price === "number"
  );
}
// 関数 totalPrice を作る。型の分からない data を受け取り、数値を返す
