q04 Error

エラーを扱う関数とクラスを 20 個書きます。エラーの基本（throw、try / catch、instanceof Error、RangeError）は 04章 q05 で学びました。ここでは、TypeError などのほかの種類のエラーと、自分で作るエラーのクラスを使います。いくつかの問題のファイルには、HTTP の通信の失敗を表すエラーのクラス HttpError と、それを継承した NotFoundError が書いてあります。引数と戻り値には型注釈を付けます。catch で受け取る値や、引数の error の型は unknown です。エラーの種類は、name や message の文字列ではなく、instanceof で見分けます。子のクラス（NotFoundError）は、親のクラス（HttpError）より先に確かめます。エラーのクラスを作るときは、extends Error で継承します。constructor の中で super(message) を呼んでから、this.name を設定します。

メッセージの文字列を受け取り、そのメッセージのエラーを必ず投げます。値を返すことはないので、戻り値の型は never にします。

テストで確かめる値

エラーを投げる
メッセージは "失敗"
fail("x")
Error を投げる

型引数が string、戻り値が never であることも確かめます。

TypeError は、値の型が思っていたものと違うことを表すエラーです。RangeError（04章 q05 問14）と同じく、Error の仲間です。作り方も new Error() と同じで、かっこにメッセージを渡します。

// 関数 requireQuantity を作る。unknown 型の value を受け取り、数値を返す
function requireQuantity(value: unknown): number {

  if (typeof value !== "number") {

instanceof SyntaxError

読めない書き方のエラーかを調べる

SyntaxError は、文字列の書き方（文法）が決まりに合わないことを表すエラーです。JSON.parse()（04章 q05 問5）や BigInt()（04章 q05 問12）は、読めない文字列を渡すと SyntaxError を投げます。catch (error)（04章 q05 問18）で受け取った値が SyntaxError かは、instanceof SyntaxError で調べます。

サンプル 
// 関数 toOrderNo を作る。文字列 text を受け取り、bigint か null を返す
function toOrderNo(text: string): bigint | null {
  // 次の中を試す。例外が投げられたら、catch の中に飛ぶ
  try {
    // text を bigint にしたものを返す
    return BigInt(text);
  } catch (error) {
    // （例外が投げられたら、投げられたものを error で受け取る）もし error が SyntaxError から作った値なら
    if (error instanceof SyntaxError) {
      // null を返す
      return null;
    }
    // error をそのまま投げ直す
    throw error;
  }
}
// 結果: toOrderNo("1024") は 1024n、toOrderNo("A-1") は null
BigInt("1024")
1024n
BigInt("A-1")
SyntaxError を投げる
数として読めない
JSON.parse("{a:1}")
SyntaxError を投げる
JSON ではキーを " で囲む
JSON.parse("")
SyntaxError を投げる
空の文字列も JSON として読めない

思っていた種類でないエラーを受け取ったら、throw error; でそのまま外に投げ直します。思っていない失敗まで null に変えてしまうと、何が起きたのかがわからなくなるからです。

型throw error; の error は unknown 型のままですが、そのまま投げられます。

新しい書き方

instanceof TypeError

エラーの種類を順に見分ける

TypeError、RangeError、SyntaxError は、どれも Error の仲間です。instanceof TypeError は、値が TypeError から作ったエラーなら true です。if を並べると、種類ごとに分けられます。

サンプル 
// 関数 failureLabel を作る。unknown 型の reason を受け取り、文字列を返す
function failureLabel(reason: unknown): string {
  // もし reason が TypeError から作った値なら
  if (reason instanceof TypeError) {
    // "数量の型が違います" を返す
    return "数量の型が違います";
  }
  // もし reason が RangeError から作った値なら
  if (reason instanceof RangeError) {
    // "数量が範囲の外です" を返す
    return "数量が範囲の外です";
  }
  // もし reason が Error から作った値なら
  if (reason instanceof Error) {
    // "注文に失敗しました" を返す
    return "注文に失敗しました";
  }
  // "不明な失敗です" を返す
  return "不明な失敗です";
}
// 結果: failureLabel(new TypeError("x")) は "数量の型が違います"、failureLabel(new Error("x")) は "注文に失敗しました"、failureLabel(1) は "不明な失敗です"

TypeError で作った値は、instanceof Error も true になります。そのため、instanceof Error を先に書くと、すべてのエラーがそこに入ってしまいます。Error は最後に確かめます。

Error を先に確かめる
if (reason instanceof Error) {
  return "注文に失敗しました";
}
if (reason instanceof TypeError) {
  return "数量の型が違います";
}
✕ TypeError も先の if に入り、"注文に失敗しました" になります
Error を最後に確かめる
if (reason instanceof TypeError) {
  return "数量の型が違います";
}
if (reason instanceof Error) {
  return "注文に失敗しました";
}
○ TypeError は "数量の型が違います" になります

06章 q02 で、extends でクラスを継承しました。Error も継承できます。Error を継承したクラスから作った値は、message と name を持ちます。throw で投げられ、instanceof で見分けられます。そのうえで、自分で決めたフィールドも持たせられます。

サンプル 
// Error を継承したクラス StockError を作る。ほかのファイルから使えるようにする
export class StockError extends Error {
  // 読み取り専用の文字列のフィールド itemId を作る
  readonly itemId: string;

  // constructor を作る。文字列の itemId と数値の stock を受け取る
  constructor(itemId: string, stock: number) {
    // 親の constructor に、itemId と stock を埋め込んだ「◯ の在庫は ◯ 個です」を渡して呼ぶ
    super(`${itemId} の在庫は ${stock} 個です`);
    // 自分の name に "StockError" を入れる
    this.name = "StockError";
    // 自分の itemId に itemId を入れる
    this.itemId = itemId;
  }
}

// 失敗 failure を作り、StockError に "A-1" と 0 を渡して new で作ったインスタンスを入れる
const failure = new StockError("A-1", 0);
// 結果: failure.message は "A-1 の在庫は 0 個です"、failure.name は "StockError"、failure.itemId は "A-1"

true
failure instanceof Error
true
Error を継承しているので

  for (const q of quantities) {
    // もし q が 10 より大きいなら
    if (q > 10) {
      // problems の最後に、q を埋め込んだ「◯ 個は多すぎます」というメッセージの RangeError を足す
      problems.push(new RangeError(`${q} 個は多すぎます`));
    }
  }
  // もし problems の要素の数が 0 より大きいなら
  if (problems.length > 0) {
    // problems をまとめた、"数量に問題があります" というメッセージの AggregateError を投げる
    throw new AggregateError(problems, "数量に問題があります");
  }
}

// 個数 count を入れ直せる変数として作り、0 を入れる
let count = 0;
// 次の中を試す。例外が投げられたら、catch の中に飛ぶ
try {
  // checkCart に [3, 12, 20] を渡して呼ぶ
  checkCart([3, 12, 20]);
} catch (error) {
  // （例外が投げられたら、投げられたものを error で受け取る）もし error が AggregateError から作った値なら
  if (error instanceof AggregateError) {
    // count に、error の errors の要素の数を入れ直す
    count = error.errors.length;
  }
}

入力のチェックで使うエラーのクラスと、チェックの関数を書きます。型 User と ValidationResult は、ファイルに書いてあります。引数と戻り値には型注釈を付けます。

  1. ValidationError：問7 と同じクラスです。Error を継承し、constructor(field, message) で作ります。field（文字列）を readonly で持ち、name は "ValidationError" です。
  2. validateEmail(email)："@" をちょうど 1 つ含み、"@" の前と後ろが空でなければ、email をそのまま返します。そうでなければ ValidationError("email", "メールアドレスの形が違います") を投げます。引数も戻り値も文字列です。
  3. validateAge(age)：age の型は unknown です。0 以上 150 以下の整数なら、その数を返します。そうでなければ ValidationError("age", "年齢は0〜150の整数にしてください") を投げます。
  4. validateUser(input)：input は { email: string; age: unknown } です。validateEmail と validateAge の両方を試します。どちらも通れば { ok: true, user: { email, age } } を返します。通らなければ、投げられた ValidationError を email、age の順に集めて { ok: false, errors } を返します。ValidationError 以外のエラーが投げられたら、そのまま投げ直します。戻り値は ValidationResult です。
  5. describeError(error)：error の型は unknown です。ValidationError なら `${field}: ${message}`、それ以外の Error なら `エラー: ${message}`、Error でなければ "不明なエラー" を返します。

ヒント 2コードへの直し方

ValidationError は問7 をそのまま書きます。validateEmail の「区切った文字列の配列」は .split()（02章 q06 問12）です。validateAge の「整数でない」は !Number.isInteger(age)（01章 q04 応用）です。typeof の確かめを先に書くと、そのあとの条件では age が number として扱えます。validateUser の「文字列か undefined を入れ直せる変数」は let email: string | undefined; です。catch の中で、ValidationError でないものを先に投げ直すと、そのあとの error は ValidationError に絞り込まれ、errors に足せます。if の後ろでは、email と age が undefined でないことがわかっているので、そのまま user に入れられます。describeError は問12 と同じく、子のクラスから確かめる形です。説明することは、describeError の 2 つの if を入れ替えて テストを走らせ、どのテストがどう失敗するかを見てから書きます。試したあとは、元の順番に戻してから提出します。
