02章 発展問題（任意）

発展問題

やってもやらなくてもよい、任意の課題です。章の課題とは別に数えます。番号の順に、1 問ずつ確認して提出します。e01 には「説明すること」があり、ファイルの「説明すること」のすぐ下に // のコメントで書きます。

e01入れ子のオブジェクトと readonly 新しく出てくる書き方：入れ子のオブジェクトの readonly、入れ子のオブジェクトをスプレッド構文で作り直す 
export type Config = unknown;

export function addOrigin() {}

export function setMaxUsers() {}

アプリの設定を表す型 Config と、設定を変えた新しい Config を返す関数を 2 つ書きます。関数の引数と戻り値には型注釈を付けます。

  1. Config：次の 3 つのプロパティを持つ型です。どのプロパティも、中まで読み取り専用にします。 name は文字列です。allowedOrigins は文字列の配列で、配列そのものも読み取り専用です。limits は maxUsers（数値）と maxRooms（数値）を持つオブジェクトで、中のプロパティも読み取り専用です。
  2. addOrigin(config, origin)：allowedOrigins の最後に origin を加えた、新しい Config を返します。origin がもう含まれているときは、受け取った config をそのまま返します。
  3. setMaxUsers(config, maxUsers)：limits.maxUsers だけを変えた、新しい Config を返します。中の limits も、スプレッド構文で作り直します。

説明すること：const で宣言した変数と、readonly のプロパティは、それぞれ何を変えられなくするのか。

テストでは、次の config を使います。

  • どちらの関数も、呼んだあとで元の config が変わっていないことを確かめます。
  • setMaxUsers が返す limits が、元の config.limits とは別のオブジェクトであることを確かめます。
  • config.allowedOrigins を string[] の変数に入れる行と、config.limits.maxUsers に値を入れる行が、型のエラーになることを確かめます。テストのファイルでは、この 2 行に @ts-expect-error（次の行が型のエラーになるはず、という印）が付いています。Config が中まで読み取り専用になっていないと、エラーが起きないので、型の確認で「Unused '@ts-expect-error' directive」というエラーになります。

型Config が上の 3 つのプロパティをすべて読み取り専用で持つことを確かめます。addOrigin は引数が Config と string、setMaxUsers は引数が Config と number で、どちらも戻り値が Config です。

新しい書き方

readonly

入れ子のオブジェクトと readonly

readonly（02章 q02 問7）は、付けたプロパティそのものにだけ効きます。プロパティの値がオブジェクトのとき、その中のプロパティまでは読み取り専用になりません。

サンプル 
// 型 Shop を作る。name は読み取り専用の文字列、hours は読み取り専用の { open: 数値; close: 数値 }
type Shop = { readonly name: string; readonly hours: { open: number; close: number } };
// 店舗 shop を Shop として作り、{ name: "渋谷店", hours: { open: 10, close: 20 } } を入れる
const shop: Shop = { name: "渋谷店", hours: { open: 10, close: 20 } };
// shop の hours の close に 22 を入れる
shop.hours.close = 22;
// 結果: エラーにならず、shop.hours.close は 22 になる

中まで読み取り専用にするには、中のオブジェクトの型のプロパティにも readonly を付けます。

サンプル 
// 型 Shop を作る。すべて読み取り専用。name は文字列、hours は { open: 数値; close: 数値 }
type Shop = {
  readonly name: string;
  readonly hours: { readonly open: number; readonly close: number };
};

配列も同じです。readonly tags: string[] では、tags に別の配列を入れることはできませんが、.push() で中身は変えられます。配列そのものも読み取り専用にするには、readonly string[]（02章 q04 問1）にします。

shop.hours = { open: 9, close: 21 }
型のエラー
hours に readonly がある
shop.hours.close = 22

中の close にも readonly を付けたとき
shop.tags.push("駅前")
型のエラー
tags が readonly string[] のとき
const list: string[] = shop.tags;
型のエラー
読み取り専用の配列は、書き換えられる配列の変数に入れられない

{ ...a, b: { ...a.b } }

入れ子のオブジェクトをスプレッド構文で作り直す

オブジェクトのスプレッド構文（02章 q02 問8）が写すのは、1 段目のプロパティだけです。中のオブジェクトは写されず、元と同じオブジェクトを指したままになります。中のプロパティを変えた新しいオブジェクトを作るときは、中のオブジェクトもスプレッド構文で作り直します。

サンプル 
// 型 Shop を作る。すべて読み取り専用。name は文字列、hours は { open: 数値; close: 数値 }
type Shop = {
  readonly name: string;
  readonly hours: { readonly open: number; readonly close: number };
};
// 店舗 shop を Shop として作り、{ name: "渋谷店", hours: { open: 10, close: 20 } } を入れる
const shop: Shop = { name: "渋谷店", hours: { open: 10, close: 20 } };
// lateShop を Shop として作り、shop を広げて、hours を「shop.hours を広げて、close を 22 にしたもの」にしたものを入れる
const lateShop: Shop = { ...shop, hours: { ...shop.hours, close: 22 } };
// 結果: lateShop.hours.close は 22、shop.hours.close は 20 のまま

オブジェクトどうしを === で比べると、同じオブジェクトかどうかが分かります（02章 q03 問11）。

lateShop.hours === shop.hours
false
中も作り直したので、別のオブジェクト
{ ...shop }.hours === shop.hours
true
1 段目だけを写すと、中は同じオブジェクトのまま

ヒント 2コードへの直し方

Config は、e01 の 1 つ目の項目の 2 つ目のサンプル（中まで読み取り専用の Shop）と同じ形で、allowedOrigins には readonly string[] を使います。「含まれるなら」は .includes() です（02章 q04 問9）。読み取り専用の配列には .push() が使えないので、新しい配列は [...config.allowedOrigins, origin] のように作ります（02章 q05 問1）。setMaxUsers は、2 つ目の項目のサンプルの lateShop の行と同じ形です。maxUsers: maxUsers は、省略記法で maxUsers とだけ書きます（02章 q01 問3）。説明することは、ファイルの下に「const の変数に別の値を入れ直す行」と「readonly のプロパティに値を入れる行」を書いて、型の確認のエラーを見比べてから考えます。試した行は、提出する前に消します。

e02オブジェクトをループする 新しく出てくる書き方：配列の分割代入で要素を飛ばす [, b] 
export type Scores = { [name: string]: number };

export function totalScore() {}

export function topScorer() {}

export function passedNames() {}

名前と得点の組を表す型 Scores は、もう書いてあります。キーが名前、値が得点のインデックス型です（02章 q08 問1）。この型の値を受け取る関数を 3 つ書きます。引数と戻り値には型注釈を付けます。

  1. totalScore(scores)：得点の合計を返します。
  2. topScorer(scores)：最高得点の人の名前を返します。同点なら、先に出てきた人です。scores が空なら undefined を返します。
  3. passedNames(scores, border)：border 点以上の人の名前を、出てきた順に配列で返します。

ファイルのヒントにあるとおり、Object.keys、Object.values、Object.entries を使います（02章 q08）。

新しい書き方

[, b]

配列の分割代入で、要素を飛ばす

配列の分割代入（02章 q06 問2）で、変数の名前を書かずに , だけを書くと、その位置の要素を飛ばせます。使わない要素のために、変数を作らずに済みます。

サンプル 
// 注文 order を [文字列, 数値, 数値] のタプルとして作り、["ORD-001", 3, 4500] を入れる
const order: [string, number, number] = ["ORD-001", 3, 4500];
// order の 0 番目は飛ばし、1 番目を quantity、2 番目を total として取り出す
const [, quantity, total] = order;
// 結果: quantity は 3、total は 4500

Object.entries() の [キー, 値] の組を、.filter() や .map() に渡す関数の引数の位置で取り出すときにも使えます（02章 q06 問9）。値だけを使うなら [, count]、キーだけを使うなら [code] と書きます。

サンプル 
// 型 Stock を作る。キーは自由な文字列で、値は数値
type Stock = { [code: string]: number };
// 在庫 stock を Stock として作り、{ A01: 5, B02: 0, C03: 0 } を入れる
const stock: Stock = { A01: 5, B02: 0, C03: 0 };
// soldOut を作り、stock のキーと値の組を並べた配列から、値が 0 のものだけを残し、それぞれキーだけにした新しい配列を入れる
const soldOut = Object.entries(stock)
  .filter(([, count]) => count === 0)
  .map(([code]) => code);
// 結果: soldOut は ["B02", "C03"]

よくある疑問Object.entries() は、キーが名前のような文字列なら、オブジェクトに書いた順に組を返します。そのため「出てきた順」は、Object.entries() の順に見ていけば守れます。

ヒント 2コードへの直し方

totalScore の「scores の値を並べた配列から 1 つずつ取り出してくり返す」は、Object.values(scores)（02章 q08 問5）を for-of で回します。topScorer は 02章 q08 問10 と同じ形です。top は let top: string | undefined; と書くと、最初は undefined が入ります。同点なら先に出てきた人なので、比べるのは「より大きい」の > です。>= にすると、同点の後の人に入れ替わってしまいます。passedNames は、e02 の 2 つ目のサンプルの soldOut と同じ形で、残す条件が「border 以上」になります。
