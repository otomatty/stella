03章 ユニオン型とそのほかの型

q06 インターセクション型

小さな型を & でつないで使う問題を 20 問解きます。Named & Aged のように & でつないだ型を、インターセクション型と呼びます。つないだ型のプロパティを、すべて持つ型です。Named、Aged、Priced、Timestamped、Identified の 5 つの型は、ファイルにもう書いてあります。問1〜13 は、引数や戻り値に Named & Aged のような型をそのまま書きます。問14〜20 は、インターセクション型に type で名前を付けて export し、その型を使って関数を書きます。引数と戻り値には型注釈を付けます。

問1「山田（30）」を返す 新しく出てくる書き方：インターセクション型 A & B 
export type Named = { name: string };

export type Aged = { age: number };

export function introduce() {}

name と age を両方持つオブジェクトを受け取り、"山田（30）" の形の文字列を返します。引数の型は Named & Aged、戻り値は文字列です。かっこは全角の「（」と「）」です。

テストで確かめる値
introduce({ name: "山田", age: 30 })
"山田（30）"

型引数が Named & Aged、戻り値が string であることも確かめます。

新しい書き方

A & B

2 つの型を合わせる

オブジェクトの型を & でつなぐと、両方のプロパティをすべて持つ型になります。この型をインターセクション型と呼びます。小さな型を組み合わせて使えるので、同じプロパティを何度も書かずに済みます。

サンプル 
// Coded という型を作る。code は文字列
type Coded = { code: string };
// Stocked という型を作る。stock は数値
type Stocked = { stock: number };
// 関数 stockLabel を作る。Coded と Stocked を合わせた型の item を受け取り、文字列を返す
function stockLabel(item: Coded & Stocked): string {
  // item の code と item の stock を埋め込んだ「◯：在庫◯個」の文字列を返す
  return `${item.code}：在庫${item.stock}個`;
}
// 結果: stockLabel({ code: "A-01", stock: 12 }) は "A-01：在庫12個"

戻り値の型にも書けます。code と stock を両方持つオブジェクトを返せば、Coded & Stocked になります。

サンプル 
// 関数 makeStock を作る。文字列 code と数値 stock を受け取り、Coded と Stocked を合わせた型のオブジェクトを返す
function makeStock(code: string, stock: number): Coded & Stocked {
  // code と stock を持つオブジェクトを返す
  return { code, stock };
}
// 結果: makeStock("B-02", 0) は { code: "B-02", stock: 0 }

3 つ以上の型も、Coded & Stocked & Shelved のように & を続けてつなげます。どの値が入るかを、ユニオン型の |（03章 q01）と比べると、違いが分かります。

{ code: "A-01", stock: 12 } を Coded & Stocked に
入れられる
両方のプロパティがある
{ code: "A-01" } を Coded & Stocked に
型のエラー
stock がない
{ code: "A-01" } を Coded | Stocked に
入れられる
ユニオン型は、どちらか一方でよい

よくある疑問同じ名前のプロパティを、違う型でつなぐとどうなるでしょうか。{ id: string } & { id: number } の id は、文字列でも数値でもある値になります。そんな値はないので、id の型は never（入る値が 1 つもない型）になり、どんな値も入れられません。

新しい書き方

{ ...x, id }

プロパティを写して、新しいプロパティを足す

スプレッド構文（02章 q02 問8）の後ろに、元のオブジェクトにないプロパティを書くと、そのプロパティが加わります。元の型と、足したプロパティの型を合わせたものが、できたオブジェクトの型です。そのため、戻り値をインターセクション型で書けます。

サンプル 
// Coded という型を作る。code は文字列
type Coded = { code: string };
// Stocked という型を作る。stock は数値
type Stocked = { stock: number };
// 関数 withStock を作る。Coded の item と数値 stock を受け取り、Coded と Stocked を合わせた型のオブジェクトを返す
function withStock(item: Coded, stock: number): Coded & Stocked {
  // item を広げて、stock を stock にしたものを返す
  return { ...item, stock };
}
// 結果: withStock({ code: "A-01" }, 12) は { code: "A-01", stock: 12 }

よくある間違い受け取った item の型は Coded なので、item.stock = stock と書くと型のエラーになります。Coded に stock はないからです。新しいオブジェクトを作って返します。

新しい書き方

(A & B)[]

インターセクション型の配列

インターセクション型の配列は、& でつないだところをかっこで囲んでから [] を付けます。読み取り専用にするときは、その前に readonly（02章 q04 問1）を付けます。

サンプル 
// Coded という型を作る。code は文字列
type Coded = { code: string };
// Stocked という型を作る。stock は数値
type Stocked = { stock: number };
// 関数 soldOutCount を作る。Coded と Stocked を合わせた型の読み取り専用の配列 items を受け取り、数値を返す
function soldOutCount(items: readonly (Coded & Stocked)[]): number {
  // 数 count を入れ直せる変数として作り、0 を入れる
  let count = 0;
  // items から 1 つずつ item に取り出してくり返す
  for (const item of items) {
    // もし item の stock が 0 と等しいなら
    if (item.stock === 0) {
      // count を 1 増やす
      count++;
    }
  }
  // count を返す
  return count;
}
// 結果: soldOutCount([{ code: "A-01", stock: 12 }, { code: "B-02", stock: 0 }]) は 1
かっこあり
readonly (Coded & Stocked)[]
○ 「Coded と Stocked を合わせた型」の配列になります
かっこなし
readonly Coded & Stocked[]
✕ 型の確認でエラーになります

よくある間違いかっこがないと、[] は後ろの Stocked だけに付きます。Coded & Stocked[] は「Coded と、Stocked の配列を合わせた型」という別の型です。readonly まで付けると「'readonly' type modifier is only permitted on array and tuple literal types.」という型のエラーになります。
