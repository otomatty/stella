08章 非同期処理

q04 非同期のエラー処理

失敗するかもしれない非同期の処理を扱う関数を 20 個書きます。使うのは、async・await と、04章 q05 で出た try / catch / finally です。Promise が値を持って終わることを「解決する」、エラーで終わることを「失敗する」と書きます。型 Task は「呼ぶたびに処理を始め、数値で解決するか失敗する関数」の型で、ファイルに書いてあります。呼んだ回数だけ処理が走るので、やり直すときは task をもう一度呼びます。catch で受け取る値の型は unknown です。message を使う前に、instanceof Error で確かめます。try の中で Promise を返すときは、return await と書きます。引数と戻り値には型注釈を付けます。テストは、返す値のほかに、引数と戻り値の型も確かめます。

新しい書き方

失敗した Promise を catch で受け止める

08章 q01 問10 では、失敗した Promise を .catch() で受け止めました。async 関数の中では、04章 q05 問5 の try / catch でも受け止められます。await で待った Promise が失敗すると、その行で例外が投げられたのと同じになるからです。catch に届くのは、Promise を失敗させたエラーです。

サンプル 
// 関数 fetchStock を作る。文字列の code を受け取り、数値で解決する Promise を返す
function fetchStock(code: string): Promise<number> {
  // もし code が "A-1" と等しいなら
  if (code === "A-1") {
    // 12 で解決する Promise を返す
    return Promise.resolve(12);
  }
  // "商品がありません" というメッセージのエラーで失敗する Promise を返す
  return Promise.reject(new Error("商品がありません"));
}

// 非同期の関数 orderLabel を作る。文字列の code を受け取り、文字列で解決する Promise を返す
async function orderLabel(code: string): Promise<string> {
  // 次の中を試す。例外が投げられたら、catch の中に飛ぶ
  try {
    // fetchStock に code を渡して呼び、終わるのを待つ
    await fetchStock(code);
    // "注文できます" を返す
    return "注文できます";
  } catch {
    // （例外が投げられたら）"在庫を確かめられません" を返す
    return "在庫を確かめられません";
  }
}
// 結果: orderLabel("A-1") は "注文できます" で解決し、orderLabel("B-9") は "在庫を確かめられません" で解決する
await fetchStock("A-1")

投げられるのは "商品がありません" のエラー

よくある疑問orderLabel は、失敗を catch で受け止めて文字列を返します。そのため、orderLabel("B-9") が返す Promise は失敗しません。"在庫を確かめられません" で解決します。

サバイバルTypeScript「await」

return await

try の中で Promise を返すときは await を付ける

async 関数では、Promise をそのまま return しても、呼んだ側はその値を受け取れます。ただし、try の中では違いが出ます。await がないと、関数は Promise の結果を待たずに try を抜けます。あとで Promise が失敗しても、もう catch は動きません。失敗は、そのまま呼んだ側に届きます。return await と書くと、try の中で結果を待つので、失敗が catch に届きます。

サンプル 
// 非同期の関数 stockOrZero を作る。文字列の code を受け取り、数値で解決する Promise を返す
async function stockOrZero(code: string): Promise<number> {
  // 次の中を試す。例外が投げられたら、catch の中に飛ぶ
  try {
    // fetchStock に code を渡して呼び、待った値を返す
    return await fetchStock(code);
  } catch {
    // （例外が投げられたら）0 を返す
    return 0;
  }
}
// 結果: stockOrZero("A-1") は 12 で解決し、stockOrZero("B-9") は 0 で解決する

fetchStock は、1 つ目の項目のサンプルの関数です。

  return 0;
}
✕ stockOrZero("B-9") は 0 にならず、"商品がありません" で失敗します

新しい書き方

throw error;

受け取った失敗を、そのまま投げ直す

catch で受け取ったものは、throw でもう一度投げられます。これを「投げ直す」と言います。記録を残してから、失敗は呼んだ側に伝えたいときに使います。受け取った値は unknown 型のままで投げられます。

サンプル 
// 非同期の関数 stockWithLog を作る。文字列の code と文字列の配列 log を受け取り、数値で解決する Promise を返す
async function stockWithLog(code: string, log: string[]): Promise<number> {
  // 次の中を試す。例外が投げられたら、catch の中に飛ぶ
  try {
    // fetchStock に code を渡して呼び、待った値を返す
    return await fetchStock(code);
  } catch (error) {
    // （例外が投げられたら、投げられたものを error で受け取る）log の最後に、code を埋め込んだ「取得に失敗: ◯」を足す
    log.push(`取得に失敗: ${code}`);
    // error を投げ直す
    throw error;
  }
}
// 結果: stockWithLog("B-9", log) は "商品がありません" で失敗し、log は ["取得に失敗: B-9"] になる

新しい書き方

何もしない catch には、わけをコメントで書く

失敗したら何もせずに先へ進みたいときは、catch の中に処理を書きません。ただし、中身がまったくない { } は、ESLint の no-empty がエラーにします。書き忘れと見分けがつかないからです。中に、なぜ何もしないのかをコメントで書きます。コメントがあれば、エラーになりません。

サンプル 
// 非同期の関数 countInStock を作る。文字列の読み取り専用の配列 codes を受け取り、数値で解決する Promise を返す
async function countInStock(codes: readonly string[]): Promise<number> {
  // 数 count を入れ直せる変数として作り、0 を入れる
  let count = 0;
  // codes から 1 つずつ code に取り出してくり返す
  for (const code of codes) {
    // 次の中を試す。例外が投げられたら、catch の中に飛ぶ
    try {
      // fetchStock に code を渡して呼び、終わるのを待つ
      await fetchStock(code);
      // count に 1 を足す
      count += 1;
    } catch {
      // 取得できない商品は数えない
    }
  }
  // count を返す
  return count;
}
// 結果: countInStock(["A-1", "B-9", "A-1"]) は 2 で解決する

新しい書き方

try { } finally { }

catch を書かずに、最後の処理だけを付ける

04章 q05 問19 では、try / catch の後ろに finally を付けました。catch を書かずに、try のすぐ後ろに finally を書くこともできます。このときは、失敗を受け止めません。finally の中を実行してから、失敗はそのまま呼んだ側に届きます。成功のときは、finally の中を実行してから値を返します。

サンプル 
// 非同期の関数 loadStockLabel を作る。文字列の code と文字列の配列 screen を受け取り、文字列で解決する Promise を返す
async function loadStockLabel(code: string, screen: string[]): Promise<string> {
  // screen の最後に "読み込み中を表示" を足す
  screen.push("読み込み中を表示");
  // 次の中を試す
  try {
    // 在庫 stock を作り、fetchStock に code を渡して呼び、待った値を入れる
    const stock = await fetchStock(code);
    // stock を埋め込んだ「在庫 ◯ 個」を返す
    return `在庫 ${stock} 個`;
  } finally {
    // （最後に、例外があってもなくても）screen の最後に "読み込み中を消す" を足す
    screen.push("読み込み中を消す");
  }
}
// 結果: loadStockLabel("B-9", screen) は "商品がありません" で失敗し、screen は ["読み込み中を表示", "読み込み中を消す"] になる

fetchStock は、問1 のサンプルの関数です。

loadStockLabel("A-1", screen)
"在庫 12 個" で解決する
screen は ["読み込み中を表示", "読み込み中を消す"]
loadStockLabel("B-9", screen)
失敗する
screen は ["読み込み中を表示", "読み込み中を消す"]

よくある間違いtry の中を return fetchStock(code); のように await なしで書くと、Promise の結果を待たずに finally が実行されます。読み込みが終わる前に「読み込み中を消す」が足されてしまいます。ここでも return await と書きます。

新しい書き方

new Promise<never>((_, reject) => …)

時間がたったら失敗する Promise を作る

08章 q01 問3 では、new Promise((resolve) => { … }) で、時間がたったら解決する Promise を作りました。new Promise に渡す関数は、2 つ目の引数で「失敗させる関数」も受け取れます。名前は reject がよく使われます。reject(エラー) を呼ぶと、その Promise はそのエラーで失敗します。

サンプル 
// 関数 deadline を作る。数値の ms を受け取り、解決しない Promise（Promise<never>）を返す
function deadline(ms: number): Promise<never> {
  // 新しい Promise を返す。1 つ目の引数は使わず、失敗させる関数を reject で受け取る
  return new Promise<never>((_, reject) => {
    // ms ミリ秒たったら、次の関数を呼ぶ
    setTimeout(() => {
      // "締め切りを過ぎました" というメッセージのエラーで、この Promise を失敗させる
      reject(new Error("締め切りを過ぎました"));
    }, ms);
  });
}
// 結果: deadline(100) は、100 ミリ秒たつと "締め切りを過ぎました" で失敗する

よくある間違い<never> を書かずに new Promise((_, reject) => …) とすると、中身の型が unknown の Promise になります。それを数値の Promise と Promise.race に並べると、結果の型も unknown になります。Promise<number> を返す関数では、型の確認でエラーになります。

ヒント 2コードへの直し方

04章 q05 問19 の try / catch / finally に、問7 のサンプルの投げ直しを合わせた形です。"成功" は task を待ったあとに足すので、値をいったん value に入れてから足し、そのあとで返します。throw error; のあとでも、finally の中は実行されます。

問20全部を同時に呼び、成功の値と失敗のメッセージに分ける 新しい書き方はありません。 
export function settleAll() {}

Task の配列 tasks を受け取ります。全部の task を同時に呼び、全部が終わるのを待ちます。成功した値を values に、失敗のメッセージを errors に集めて、{ values, errors } を返します。どちらも元の順に並べます。Error でないもので失敗したときのメッセージは "不明なエラー" です。

ヒント 2コードへの直し方

1 行目は問10 と同じです。status で絞り込むと、成功のほうでは result.value、失敗のほうでは result.reason を読めます（08章 q01 問17〜問19）。reason の型は any なので、const reason: unknown = result.reason; のように unknown の変数に入れてから確かめます。最後は { values, errors }（02章 q01 問3 の省略記法）を返します。

応用結果にする・やり直す・最初の成功・全部呼ぶ 新しく出てくる書き方：Error 型 
export type Result<T> = { ok: true; value: T } | { ok: false; error: Error };

export function tryAsync() {}

export function withRetry() {}

export function firstSuccessful() {}

export function runAll() {}

失敗するかもしれない非同期の処理を扱う関数を、4 つ書きます。引数の fn や tasks の要素は、呼ぶたびに新しく処理を始める関数です。ドリルでは数値で解決する Task でしたが、ここでは型引数 T（07章 q06 問1）を使い、どんな型で解決する関数でも受け取れるようにします。

  1. tryAsync(fn)：fn() を待ち、成功なら { ok: true, value: 値 }、失敗なら { ok: false, error: エラー } を返します（Result<T>）。Error でないものが投げられたときは、String(値) をメッセージにした Error を作って入れます。
  2. withRetry(fn, attempts)：fn() が成功するまで、全部で attempts 回まで呼び、成功したらその値を返します。attempts 回とも失敗したら、最後の失敗をそのまま投げます。attempts が 1 より小さいときは、fn を呼ばずにエラーを投げます。
  3. firstSuccessful(tasks)：tasks を前から順番に 1 つずつ呼び、最初に成功した値を返します。成功したら、後ろの task は呼びません。すべて失敗したら（tasks が空のときも）、"すべて失敗しました" というメッセージのエラーを投げます。
  4. runAll(tasks)：tasks を前から順番に 1 つずつ呼びます。失敗しても止めずに最後まで呼び、{ values: 成功した値の配列, errors: 失敗のメッセージの配列 } を返します。どちらも呼んだ順です。Error でないものが投げられたときのメッセージは "不明なエラー" です。

説明すること：withRetry で、try の中を return fn(); と書くと何が起きるか。試した結果を、ファイルの「説明すること」のすぐ下に、// のコメントで書きます。試すときは、withRetry が通ってから、try の中の return await fn(); を一時的に return fn(); に書き換えます。テストを動かして、どのテストが通らなくなったか、fn が何回呼ばれたかを見ます。ESLint の結果も見ます。試したら、return await fn(); に戻します。

新しい書き方

error: Error

Error を型として書く

new Error() で作った値の型は Error です。型注釈やオブジェクトの型の中にも、Error と書けます。RangeError（04章 q05 問14）のような Error の仲間も、Error 型の場所に入れられます。文字列などの Error でない値は入れられません。

サンプル 
// 型 SaveResult を作る。ok が true なら id は数値、ok が false なら error は Error
type SaveResult = { ok: true; id: number } | { ok: false; error: Error };
// 結果 failed を作り、ok が false で、error に "保存できません" というメッセージのエラーを持つ SaveResult を入れる
const failed: SaveResult = { ok: false, error: new Error("保存できません") };
// 結果 tooMany を作り、ok が false で、error に "在庫数が範囲外です" というメッセージの RangeError を持つ SaveResult を入れる
const tooMany: SaveResult = { ok: false, error: new RangeError("在庫数が範囲外です") };
// 結果: failed の error の message は "保存できません"、tooMany の error の message は "在庫数が範囲外です"
const e: Error = new RangeError("範囲外です");
通る
RangeError も Error の仲間
const e: Error = "失敗";
型の確認でエラー
文字列は Error ではない
new Error(String(404)).message
"404"
Error でない値も、文字列にすれば Error のメッセージにできる

コツcatch で受け取る値は unknown なので、そのままでは error: Error の場所に入れられません。instanceof Error で確かめて、Error ならそのまま、そうでなければ new Error(String(値)) で Error を作ってから入れます。

ヒント 2コードへの直し方

tryAsync は問4 と同じ形で、失敗のほうに、上の「コツ」のとおりに作った Error を入れます。withRetry は問7 の形の前に、attempts を確かめる if を足します。firstSuccessful は問9、runAll は問15 と同じ形です。どれも関数名の後ろに <T> を付け、ドリルの number のところを T にします。readonly (() => Promise<T>)[] は、「T で解決する Promise を返す関数」の読み取り専用の配列です。関数の型をかっこで囲んでから [] を付けます。かっこがないと、型の確認で文法のエラーになります。values の型注釈は const values: T[] = [] です。
