e01同時に実行する数を制限する 新しく出てくる書き方：非同期のアロー関数 async () => { }、取り出し口を分け合う .values() 
export function mapWithLimit() {}

Promise.all で 100 件の取得を一度に始めると、相手のサーバーに負担をかけたり、回数の制限に引っかかったりします。同時に実行する数を limit 個までにして、すべての要素を処理する関数 mapWithLimit(items, limit, fn) を書きます。

  1. items のそれぞれについて fn(要素) を呼び、結果の配列を items の順で返します。
  2. 実行中（呼んだが、まだ終わっていない）の fn が、同時に limit 個を超えないようにします。
  3. 1 つ終わったら、すぐに次の要素の fn を始めます。limit 個ずつ区切って、全部が終わるのを待ってから次の区切りに進む書き方では、テストが通りません。
  4. fn が 1 つでも失敗したら、その失敗をそのまま投げます。
  5. limit が 1 より小さいときは、エラーを投げます。

説明すること：「limit 個ずつ区切って Promise.all で待つ」書き方と比べて、どんなときに速くなるか。試すときは、区切って待つ書き方を別の関数で書いてみて、テストと同じ時間の組み合わせで、全部が終わるまでの時間を比べます。

非同期のアロー関数

アロー関数（01章 q01 問20）の前にも async を付けられます。中で await を使え、呼ぶと Promise を返します。async function と同じ働きです。関数の中で小さな関数を作るときや、変数に入れておくときに使います。

サンプル 
// 関数 wait を作る。数値の ms を受け取り、値を持たずに解決する Promise（Promise<void>）を返す
function wait(ms: number): Promise<void> {
  // 新しい Promise を返す。解決させる関数を resolve で受け取る
  return new Promise((resolve) => {

    setTimeout(resolve, ms);

}

取り出し口を分け合って、作業を同時に進める

配列の .values() は、要素を前から 1 つずつ取り出すもの（取り出し口）を返します。for-of に渡すと、配列を渡したときと同じように、要素を 1 つずつ取り出してくり返します。取り出した要素は、もう取り出し口に残りません。同じ取り出し口を 2 つの for-of で使うと、2 つで要素を分け合います。取り出し口が空になると、どちらのくり返しも終わります。04章 q03 問9 の .entries() も同じ取り出し口で、こちらは番号と要素の組を取り出します。

async 関数は、呼ぶとすぐに動き始め、await のところで止まって、呼んだ側に Promise を返します。止まっている間は、ほかの関数が動けます。そのため、いくつか呼んでから Promise.all（08章 q01 問13）で待つと、それぞれが同時に進みます。

サンプル 
// 非同期の関数 packAll を作る。何も受け取らず、文字列の配列で解決する Promise を返す
async function packAll(): Promise<string[]> {
  // 注文の列 orders を作り、["注文1", "注文2", "注文3"] を入れる
  const orders = ["注文1", "注文2", "注文3"];
  // 記録 packLog を作り、空の配列を入れる
  const packLog: string[] = [];
  // 取り出し口 queue を作り、orders の要素を前から 1 つずつ取り出すもの（.values()）を入れる
  const queue = orders.values();
  // 関数 staff を作る。文字列の name を受け取り、値を持たずに解決する Promise を返す（非同期のアロー関数）
  const staff = async (name: string): Promise<void> => {
    // queue から 1 つずつ order に取り出してくり返す
    for (const order of queue) {
      // packOrder に order を渡して呼び、終わるのを待つ
      await packOrder(order);
      // packLog の最後に、name と order を埋め込んだ「◯: ◯」を足す
      packLog.push(`${name}: ${order}`);
    }
  };
  // staff に "佐藤" を渡して呼んだ Promise と、"鈴木" を渡して呼んだ Promise を並べて Promise.all に渡し、終わるのを待つ
  await Promise.all([staff("佐藤"), staff("鈴木")]);
  // packLog を返す
  return packLog;
}
// 結果: packAll() は ["佐藤: 注文1", "鈴木: 注文2", "佐藤: 注文3"] で解決する

packOrder は、1 つ目の項目のサンプルの関数で、1 件に 10 ミリ秒かかります。2 人が同時に動くので、全部が終わるのは 20 ミリ秒後です。

ヒント 2コードへの直し方

2 つ目のサンプルの staff が worker に当たります。取り出し口は .values() の代わりに .entries() を使い、番号も一緒に取り出します。番号の位置に結果を入れるので、終わった順に関係なく、items の順に並びます（添字への代入は 02章 q05 問16）。results の型注釈は const results: R[] = [] です。小さいほうは Math.min()（01章 q04 問9）、「worker を workerCount 回呼んだ Promise の配列」は Array.from({ length: workerCount }, () => worker())（02章 q05 問19）で作れます。どれかの fn が失敗すると、その worker の Promise が失敗し、Promise.all もその失敗で失敗します。

e02同じ取得を 1 回にまとめる（キャッシュ） 新しく出てくる書き方：Map、Promise を覚えておく、.catch() の中で投げ直す 
export function dedupe() {}

画面のあちこちから、同じユーザーの取得が同時に呼ばれると、同じ通信が何度も走ってしまいます。非同期の関数 fn を包んで、同じ key の取得を 1 回にまとめる関数 dedupe を書きます。取得した結果を覚えておいて使い回すことを、キャッシュと呼びます。dedupe(fn) は、fn と同じ形の関数 get(key) を返します。

  1. get(key) を呼ぶと、fn(key) の結果を返します。
  2. 同じ key の fn がまだ終わっていないうちに get(key) が呼ばれたら、fn を呼ばずに、同じ Promise を返します。
  3. 成功した結果は覚えておき、次からは fn を呼ばずに、その値を返します。
  4. 失敗した結果は覚えません。次に get(key) が呼ばれたら、もう一度 fn を呼びます。
  5. key は string か number です。覚えておく場所には Map を使います。

説明すること：失敗した結果も覚えてしまうと、どんな困りごとが起きるか。試すときは、失敗しても覚えたままにする書き方に一時的に変えて、どのテストが通らなくなるかを見ます。試したら元に戻します。

key ごとに値を覚えておく Map

Map は、key と値の組を覚えておく入れ物です。new Map<key の型, 値の型>() で空の Map を作ります。.set(key, 値) で覚えさせ、.get(key) で取り出します。覚えていない key を .get() すると undefined です。.has(key) は覚えているかを返し、.delete(key) は消します。ここでは、まねて書ければ十分です。くわしくは 09章 q01 で学びます。

サンプル 
// 値段の表 prices を作り、文字列の key と数値の値を持つ空の Map を入れる
const prices = new Map<string, number>();
// prices の "A-1" に 1200 を覚えさせる
prices.set("A-1", 1200);
// 値段 a を作り、prices の "A-1" の値を入れる
const a = prices.get("A-1");
// 値段 b を作り、prices の "B-9" の値を入れる
const b = prices.get("B-9");
// hasBefore を作り、prices が "A-1" を持っているか（true か false）を入れる
const hasBefore = prices.has("A-1");
// prices から "A-1" を消す
prices.delete("A-1");
// hasAfter を作り、prices が "A-1" を持っているか（true か false）を入れる
const hasAfter = prices.has("A-1");
// 結果: a は 1200、b は undefined、hasBefore は true、hasAfter は false

型.get() の結果は、覚えていないかもしれないので、値の型 | undefined になります。このサンプルの a と b の型は number | undefined です。使う前に !== undefined で確かめます。

const pricePromise = loadPrice();

Promise を変数に入れて、何度でも待つ

Promise は、ふつうの値と同じように、変数や Map に入れておけます。同じ Promise は何度でも await できます。待つたびに処理がやり直されることはありません。まだ終わっていなければ終わるまで待ち、終わっていればすぐに同じ結果になります。

サンプル 
// 呼んだ回数 calls を入れ直せる変数として作り、0 を入れる
let calls = 0;
// 関数 loadPrice を作る。何も受け取らず、数値で解決する Promise を返す（アロー関数）
const loadPrice = (): Promise<number> => {
  // calls に 1 を足す
  calls += 1;
  // 1200 で解決する Promise を返す
  return Promise.resolve(1200);
};

// 非同期の関数 waitTwice を作る。何も受け取らず、数値の配列で解決する Promise を返す
async function waitTwice(): Promise<number[]> {
  // 値段の Promise pricePromise を作り、loadPrice を呼んだ Promise を入れる
  const pricePromise = loadPrice();
  // 1 回目 first を作り、pricePromise を待った値を入れる
  const first = await pricePromise;
  // 2 回目 second を作り、pricePromise を待った値を入れる
  const second = await pricePromise;
  // first、second、calls を並べた配列を返す
  return [first, second, calls];
}
// 結果: waitTwice() は [1200, 1200, 1] で解決する

calls が 1 のままなので、loadPrice は 1 回しか呼ばれていません。2 回目の await は、同じ Promise の結果をもう一度受け取っただけです。

.catch((error: unknown) => { …; throw error; })

失敗したときだけ何かをして、失敗はそのまま伝える

.catch()（08章 q01 問10）は、新しい Promise を返します。.catch() に渡した関数の中で投げると、新しい Promise はそのエラーで失敗します。受け取った失敗を投げ直せば（08章 q04 問7）、失敗したときだけ記録や後片付けをして、失敗はそのまま呼んだ側に伝えられます。成功したときは、.catch() に渡した関数は呼ばれず、新しい Promise も同じ値で解決します。

サンプル 
// 記録 failLog を作り、空の配列を入れる
const failLog: string[] = [];

// 関数 withFailLog を作る。数値で解決する Promise の promise を受け取り、数値で解決する Promise を返す
function withFailLog(promise: Promise<number>): Promise<number> {
  // promise が失敗したら次の関数を呼ぶ、新しい Promise を返す。関数は失敗の理由を error で受け取る
  return promise.catch((error: unknown) => {
    // failLog の最後に "取得に失敗" を足す
    failLog.push("取得に失敗");
    // error を投げ直す
    throw error;
  });
}
// 結果: withFailLog(Promise.reject(new Error("在庫なし"))) は "在庫なし" で失敗し、failLog は ["取得に失敗"] になる
withFailLog(Promise.resolve(5))
5 で解決する
failLog は変わらない
withFailLog(Promise.reject(new Error("在庫なし")))
失敗する
失敗の理由は "在庫なし" のエラーそのもの

決まり.catch() に渡す関数の引数には、(error: unknown) と型注釈を付けます。付けないと any になり、このガイドの設定では ESLint がエラーにします。

ヒント 2コードへの直し方

「key を受け取り、次のことをする関数を返す」は、05章 q08 の関数を返す形で、return (key) => { … }; です。key の型は、dedupe の戻り値の型注釈から推論されます。覚えておくのは、fn が返した Promise そのものです。2 つ目のサンプルのように、同じ Promise は何度でも待てます。まだ終わっていないうちに呼ばれても、終わったあとに呼ばれても、同じ Promise を返せば足ります。promise の右側は、3 つ目のサンプルの withFailLog の return の後ろと同じ形で、記録を足す代わりに cache.delete(key) を呼びます。fn(key) の Promise をそのまま覚えると、失敗しても消されずに残ります。async を使わないので、関数の前に async は付けません。
