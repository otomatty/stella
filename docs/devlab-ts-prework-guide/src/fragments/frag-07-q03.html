07章 型の再利用とジェネリクス

q03 Partial・Required・Readonly

もとの型から、プロパティの付け方だけを変えた型を作る 20 問です。型 Options と Profile は、各ファイルに定義済みです。Partial<T> はすべてのプロパティを省略できる型、Required<T> はすべてのプロパティを省略できない型、Readonly<T> はすべてのプロパティを読み取り専用にした型です。型を書く問題では、プロパティを手で書き並べずに、この 3 つで作ります。関数を書く問題では、引数と戻り値に型注釈を付けます。

問1型 PartialOptions を Options から作る 新しく出てくる書き方：ユーティリティ型、Partial<T> 
export type Options = { size: number; color: string; bold: boolean };

// ここに型 PartialOptions を書く

Options は、文字の大きさ size、色 color、太字かどうか bold を持つ設定の型です。Options をもとに、すべてのプロパティを省略できる型 PartialOptions を作り、export します。プロパティを手で書き並べずに、ユーティリティ型で作ります。

テストで確かめる値
PartialOptions
{ size?: number; color?: string; bold?: boolean }
この型と同じであること

新しい書き方

ユーティリティ型

もとの型から新しい型を作る組み込みの型

ユーティリティ型は、もとの型から新しい型を作る型です。TypeScript に最初から入っています。名前の後ろの < > の中に、もとの型を書きます。07章 q01 問12 の ReturnType<typeof makeItem> も、ユーティリティ型の 1 つです。

この番号では、プロパティの付け方をまとめて変える 3 つを使います。

サンプル 
// 予約の型 Booking を作る。date は文字列、note はなくてもよい文字列
type Booking = { date: string; note?: string };
// BookingDraft という型を作る。Booking のすべてのプロパティを省略できるようにした型
type BookingDraft = Partial<Booking>;
// BookingFull という型を作る。Booking のすべてのプロパティを省略できないようにした型
type BookingFull = Required<Booking>;
// BookingFixed という型を作る。Booking のすべてのプロパティを読み取り専用にした型
type BookingFixed = Readonly<Booking>;
// 結果: BookingDraft は { date?: string; note?: string }
//       BookingFull は { date: string; note: string }
//       BookingFixed は { readonly date: string; readonly note?: string }
ユーティリティ型することBooking から作った型
Partial<T>すべてのプロパティに ? を付けます。どれも省略できます。{ date?: string; note?: string }
Required<T>すべてのプロパティから ? を外します。どれも省略できません。{ date: string; note: string }
Readonly<T>すべてのプロパティに readonly を付けます。? はそのまま残ります。{ readonly date: string; readonly note?: string }

コツもとの型を直すと、作った型も一緒に変わります。Booking にプロパティを足せば、3 つの型にも同じプロパティが入ります。手で書き並べた型は、直し忘れることがあります。

Partial<T>

すべてのプロパティを省略できる型

Partial<T> は、T のすべてのプロパティを、なくてもよいプロパティ（02章 q02 問1）にした型です。「変えたいところだけを書いたオブジェクト」の型によく使います。

サンプル 
// 商品の型 Product を作る。name は文字列、price は数値、stock は数値
type Product = { name: string; price: number; stock: number };
// 商品の変更 ProductPatch という型を作る。Product のすべてのプロパティを省略できるようにした型
type ProductPatch = Partial<Product>;
// 値下げ sale を作り、型を ProductPatch にして、price が 980 のオブジェクトを入れる
const sale: ProductPatch = { price: 980 };
// 何も変えない none を作り、型を ProductPatch にして、空のオブジェクトを入れる
const none: ProductPatch = {};
// 結果: sale は { price: 980 }、none は {}
const p: ProductPatch = { price: 980 }
入れられる
1 つだけでもよい
const p: ProductPatch = {}
入れられる
何もなくてもよい
const p: ProductPatch = { price: "980" }
型の確認でエラー
値の型は number のまま
const p: ProductPatch = { color: "red" }
型の確認でエラー
Product にないプロパティは書けない
手で書き並べる
type Product = { name: string; price: number; stock: number };
type ProductPatch = { name?: string; price?: number; stock?: number };
✕ 型は同じでも、Product を直したときに追いつきません。この番号では使いません
ユーティリティ型で作る
type Product = { name: string; price: number; stock: number };
type ProductPatch = Partial<Product>;
○ Product に合わせて、ProductPatch も変わります

新しい書き方

Required<T>

すべてのプロパティを省略できない型

Required<T> は、T のすべてのプロパティから ? を外した型です。値の型からも undefined がなくなります。もとの型は変わりません。

サンプル 
// 予約の型 Booking を作る。date は文字列、seats はなくてもよい数値、note はなくてもよい文字列
type Booking = { date: string; seats?: number; note?: string };
// 確定した予約 FullBooking という型を作る。Booking のすべてのプロパティを省略できないようにした型
type FullBooking = Required<Booking>;
// 予約 booking を作り、型を FullBooking にして、date が "2025-04-01"、seats が 2、note が "窓側" のオブジェクトを入れる
const booking: FullBooking = { date: "2025-04-01", seats: 2, note: "窓側" };
// 席の数 seats を作り、booking の seats を入れる
const seats = booking.seats;
// 結果: seats は 2。型は number で、undefined にはならない
const b: Booking = { date: "2025-04-01" }
入れられる
もとの Booking では seats と note を省ける
const b: FullBooking = { date: "2025-04-01" }
型の確認でエラー
seats と note が足りない

よくある疑問エラーの文は Type '{ date: string; }' is missing the following properties from type 'Required<Booking>': seats, note です。足りないプロパティの名前が、最後に並びます。

Readonly<T>

すべてのプロパティを読み取り専用にした型

Readonly<T> は、T のすべてのプロパティに readonly（02章 q02 問7）を付けた型です。プロパティを読むことはできますが、値を入れ直すと型の確認でエラーになります。

サンプル 
// 注文の型 Order を作る。id は数値、quantity は数値
type Order = { id: number; quantity: number };
// 確定した注文 FixedOrder という型を作る。Order のすべてのプロパティを読み取り専用にした型
type FixedOrder = Readonly<Order>;
// 注文 order を作り、型を FixedOrder にして、id が 10、quantity が 2 のオブジェクトを入れる
const order: FixedOrder = { id: 10, quantity: 2 };
// 数 count を作り、order の quantity を入れる
const count = order.quantity;
// 結果: count は 2。order の id と quantity は、読めるが入れ直せない
読む
const order: FixedOrder = { id: 10, quantity: 2 };
// 数 count を作り、order の quantity を入れる
const count = order.quantity;
○ 読むことはできます
入れ直す
const order: FixedOrder = { id: 10, quantity: 2 };
// order の quantity に 3 を入れ直す
order.quantity = 3;
✕ 型の確認でエラーになります（Cannot assign to 'quantity' because it is a read-only property）

決まりReadonly<T> も、readonly と同じく型の確認のための印です。JavaScript に変換したあとのコードには残りません。実行しているときにも書き換えを止めるには、問8 の Object.freeze() を使います。

新しい書き方

Object.freeze()

オブジェクトを凍らせて、書き換えられないようにする

Object.freeze() は、渡したオブジェクトを凍らせて（書き換えられないようにして）、そのオブジェクトを返します。export を書いたファイル（モジュール）では、凍ったオブジェクトのプロパティに値を入れると、TypeError というエラーが投げられます。戻り値の型は Readonly<渡したものの型> になります。

サンプル 
// 送料の型 Shipping を作る。base は数値、free は数値
type Shipping = { base: number; free: number };
// 元の送料 source を作り、型を Shipping にして、base が 500、free が 5000 のオブジェクトを入れる
const source: Shipping = { base: 500, free: 5000 };
// 送料表 fees を作り、source を広げた新しいオブジェクトを Object.freeze したものを入れる
const fees = Object.freeze({ ...source });
// 結果: fees は { base: 500, free: 5000 }。型は Readonly<{ base: number; free: number }>
Object.isFrozen(fees)
true
凍っているかを調べる
Object.isFrozen(source)
false
凍ったのはコピーだけ
fees.base = 0
TypeError
Cannot assign to read only property 'base' of object
書き方型の確認実行したとき
Readonly<T> の型注釈だけ代入はエラー止まりません。値が入れ直されます
Object.freeze() の戻り値代入はエラー（型が Readonly<T>）TypeError が投げられます

よくある間違いObject.freeze(source) と書くと、元の source そのものが凍ります。呼んだ側のオブジェクトまで書き換えられなくなります。コピーを凍らせるときは、先に { ...source } で広げます（02章 q03 問11）。

決まり凍るのは、そのオブジェクトのプロパティだけです。プロパティの中にある配列やオブジェクトまでは凍りません。
