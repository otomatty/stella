06章 クラス

q02 アクセス修飾子と readonly

フィールドに印（アクセス修飾子）を付けて、使える場所を決めます。外から読んだり書き換えたりさせたくないフィールドは private、作ったあとに変えないフィールドは readonly にします。constructor の引数に印を付けると、フィールドの宣言と代入を 1 行で書けます。ドリル 1 問（1 つのファイルに 20 個のクラス）を確認して提出してから、応用に進みます。フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。テストは、private にしたフィールドが外から見えないことも確かめます。

ドリル印を付けた 20 個のクラスを書く 新しく出てくる書き方：constructor の引数に印を付けてフィールドにする書き方、protected、extends（継承） 
// 問1 Account(id)。id は読み取り専用
//     例: new Account("A-1").id → "A-1"
export class Account {}

// 問2 Secret(value)。value は private。matches(guess) で value と同じなら true
//     例: new Secret("abc").matches("abc") → true
export class Secret {}

// …（問20 まで、同じ形で続きます）

1 つのファイルに、クラスを 20 個書きます。q01 と同じく、フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。この番号では、フィールドに印（アクセス修飾子）を付けます。外から読んだり書き換えたりさせたくないフィールドは private、作ったあとに変えないフィールドは readonly にします。

テストは、private にしたフィールドが外から見えないことも確かめます。テストが調べるフィールドの名前は、問題ごとに書いておきます。JavaScript の # を使った書き方でもテストは通りますが、ここでは TypeScript の private を使います。

新しい書き方

constructor(readonly orderId: string) {}

constructor の引数をそのままフィールドにする

constructor の引数の前に readonly や private などの印を付けると、その引数は同じ名前のフィールドになります。受け取った値も、自動でフィールドに入ります。フィールドの宣言と this.orderId = orderId; を、1 か所にまとめて書けます。教材では、この書き方を constructor shorthand（コンストラクタの省略記法）と呼びます。

サンプル 
// クラス Order を作る。ほかのファイルから使えるようにする
export class Order {
  // 外から読めない数値のフィールド shipped を作り、0 を入れる
  private shipped = 0;

  // constructor を作る。文字列の orderId を受け取り、入れ直せないフィールド orderId にする。数値の quantity を受け取り、外から読めないフィールド quantity にする
  constructor(
    readonly orderId: string,
    private quantity: number,
  ) {}

  // メソッド ship を作る。数値の n を受け取り、数値を返す
  ship(n: number): number {
    // 自分の shipped に n を足す
    this.shipped += n;
    // 自分の quantity − 自分の shipped を返す
    return this.quantity - this.shipped;
  }
}

// 注文 order を作り、Order に "O-7" と 5 を渡して new で作ったインスタンスを入れる
const order = new Order("O-7", 5);
// 残り left を作り、order の ship に 2 を渡して呼んだ結果を入れる
const left = order.ship(2);
// 結果: order.orderId は "O-7"、left は 3
q01 の書き方
class Ticket {
  readonly code: string;

  constructor(code: string) {
    this.code = code;
  }
}
引数に印を付ける書き方
class Ticket {
  constructor(readonly code: string) {}
}

どちらも同じクラスになります。引数が 2 つ以上あって 1 行に収まらないと、Prettier が引数を 1 行ずつに並べ直し、最後にも , を付けます。サンプルの Order がその形です。

よくある間違い印を 1 つも付けない引数は、ただの引数です。フィールドにはなりません。constructor(code: string) {} のあとでメソッドから this.code を読むと、型の確認で Property 'code' does not exist on type 'Ticket'. というエラーになります。

コツ初期値のあるフィールド（shipped）は、これまでどおり { } のすぐ内側に書きます。1 つのクラスに両方を書いてかまいません。

サバイバルTypeScript「constructor shorthand」

private / readonly

2 つの印でできること・できないこと

private と readonly は、q01 の応用で出ました。どちらも、フィールドの使い方を型の確認で止める印です。2 つ合わせて付けることもできます。

印クラスの中で読むクラスの中で入れ直す外から読む外から入れ直す
なし○○○○
readonly○constructor の中だけ○✕
private○○✕✕
private readonly○constructor の中だけ✕✕

選び方の目安です。外から読んでもらいたい値で、あとから変えないものは readonly（問1 の口座番号）。外に見せたくないもの、勝手に変えられると困るものは private にして、読んだり変えたりする役のメソッドを用意します（問8 の setTarget と getTarget）。

よくある疑問readonly が止めるのは、フィールドに別の値を入れ直すことだけです。private readonly items: string[] = []; のフィールドでも、this.items.push("a") で中の要素を足すことはできます。this.items = []; と入れ直す行だけがエラーになります。

テストの読み方テストには // @ts-expect-error count は private の行があります。これは「次の行は型の確認でエラーになるはず」という印です。フィールドが private になっていないと、次の行がエラーにならず、型の確認で失敗します。

サバイバルTypeScript「アクセス修飾子」

class Cashier extends Staff

protected と extends（受け継いだクラスからだけ使う）

class 子 extends 親 と書くと、親のクラスのフィールドとメソッドを受け継いだ、新しいクラスを作れます。これを継承と呼びます。constructor も受け継ぐので、子のクラスに constructor を書かなければ、new Cashier("佐藤") の "佐藤" は親の constructor に渡ります。

protected を付けたフィールドは、そのクラスと、それを受け継いだクラスの中からだけ使えます。private だと、受け継いだクラスの中からも使えません。

サンプル 
// クラス Staff を作る。ほかのファイルから使えるようにする
export class Staff {
  // constructor を作る。文字列の name を受け取り、子のクラスからだけ読め、入れ直せないフィールド name にする
  constructor(protected readonly name: string) {}
}

// Staff を継承したクラス Cashier を作る。ほかのファイルから使えるようにする
export class Cashier extends Staff {
  // メソッド callOut を作る。何も受け取らず、文字列を返す
  callOut(): string {
    // 自分の name を埋め込んだ「◯さん、レジへお願いします」の文字列を返す
    return `${this.name}さん、レジへお願いします`;
  }
}

// レジ係 cashier を作り、Cashier に "佐藤" を渡して new で作ったインスタンスを入れる
const cashier = new Cashier("佐藤");
// 呼び出し message を作り、cashier の callOut を呼んだ結果を入れる
const message = cashier.callOut();
// 結果: message は "佐藤さん、レジへお願いします"
this.name（Cashier の callOut の中で）
読める
受け継いだクラスの中
cashier.name（クラスの外で）
型の確認でエラー
protected なので外からは使えない

よくある間違いStaff の name を private にすると、Cashier の中の this.name が Property 'name' is private and only accessible within class 'Staff'. というエラーになります。

ここでは、まねて書ければ十分です。

q04（クラスの継承）

[...this.dishes]

private の配列を守るコピー

配列を private にしても、受け取った配列や返した配列が、外の配列と同じものだと守れません。配列を変数に入れたり、引数で渡したりしても、配列は 1 つのままだからです（02章 q04 問1 のメモ）。受け取るときと返すときに、配列のスプレッド [...a]（02章 q05 問1）でコピーを作ります。

サンプル 
// クラス Menu を作る。ほかのファイルから使えるようにする
export class Menu {
  // 外から読めず、入れ直せない文字列の配列のフィールド dishes を作る
  private readonly dishes: string[];

  3. constructor は id と、はじめの残高 initial を受け取ります。initial は省略でき、省略したら 0 です。initial が負ならエラーを投げます。
  4. deposit(amount)：入金して、入金後の残高を返します。amount が 0 以下ならエラーを投げます。履歴の最後に "入金 1000" の形で足します。
  5. withdraw(amount)：出金して、出金後の残高を返します。amount が 0 以下ならエラー、残高より多ければ "残高が足りません" というメッセージのエラーを投げます。履歴の最後に "出金 300" の形で足します。
  6. getBalance()：残高を返します。
  7. getHistory()：履歴の配列のコピーを返します。

「残高が足りません」のほかのエラーのメッセージは、自由に決めてかまいません。テストは、エラーを投げることだけを確かめます。

ヒント 2コードへの直し方

constructor は、constructor(readonly id: string, initial = 0) { のように、印を付けた引数とふつうの引数を並べて書けます（1 つ目の項目のサンプルの Order）。initial は確かめてから入れるので、印は付けず、中で this.balance = initial; と入れます。history は readonly でも、push で足すことはできます（2 つ目の項目のメモ）。deposit と withdraw は、ドリルの問11（Prepaid）に履歴を足す行を加えた形です。getHistory は、ドリルの問15（Journal）の lines と同じ形です。
