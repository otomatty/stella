e01satisfies 演算子 新しく出てくる書き方：satisfies 
export type Route = { path: string; auth: boolean };

export const ROUTES: { [name: string]: Route } = {
  home: { path: "/", auth: false },
  settings: { path: "/settings", auth: true },
  admin: { path: "/admin", auth: true },
};

export type RouteName = keyof typeof ROUTES;

export function pathOf() {}

export function protectedPaths() {}

画面の一覧 ROUTES には、型注釈 { [name: string]: Route }（キーが自由な文字列のインデックス型、02章 q08 問1）が付いています。このせいで、home・settings・admin というキー名が型から消えています。RouteName も string | number になっています。次の 3 つを書きます。関数の引数と戻り値には型注釈を付けます。

  1. ROUTES：型注釈をやめ、satisfies を使って書き直します。{ [name: string]: Route } の形になっているかは確かめたまま、キー名が型に残るようにします。RouteName の行は変えません。RouteName が "home" | "settings" | "admin" になれば成功です。
  2. pathOf(name)：name の画面の path を返します。引数の型は RouteName です。
  3. protectedPaths()：auth が true の画面の path を、ROUTES に書いた順に配列で返します。

説明すること：型注釈で書いた場合と satisfies で書いた場合で、ROUTES の型はどう違うか。

新しい書き方

値 satisfies 型

型に合っているかだけを確かめる

型注釈 const 名前: 型 = 値 を付けると、変数の型はその型に決まります。値に書いたキー名は、型から消えます。値 satisfies 型 と書くと、値がその型の形に合っているかを確かめるだけです。変数の型は、値から推論された型（01章 q03）のまま残ります。

サンプル 
// Plan という型を作る。price は数値、seats は数値
type Plan = { price: number; seats: number };
// 料金表 PLANS を作り、basic と pro の 2 つのプランを入れる。キーが自由な文字列で値が Plan の形になっているかを確かめる
const PLANS = {
  basic: { price: 1000, seats: 1 },
  pro: { price: 3000, seats: 5 },
} satisfies { [name: string]: Plan };
// 席数 proSeats を作り、PLANS の pro の seats を入れる
const proSeats = PLANS.pro.seats;
// 結果: proSeats は 5
型注釈で書く
const PLANS: { [name: string]: Plan } = {
  basic: { price: 1000, seats: 1 },
  pro: { price: 3000, seats: 5 },
};
✕ キー名が型から消えます
satisfies で書く
const PLANS = {
  basic: { price: 1000, seats: 1 },
  pro: { price: 3000, seats: 5 },
} satisfies { [name: string]: Plan };

よくある疑問型注釈のときに keyof が string | number になるのは、インデックス型 { [name: string]: Plan } の keyof がそうなると決まっているからです。数値のキー PLANS[1] も、文字列の "1" として読めるので number も入ります。

ヒント 2コードへの直し方

ROUTES は、e01 のサンプルの PLANS と同じ形です。ROUTES の後ろの : { [name: string]: Route } を消し、同じ型を、閉じる } の後ろの satisfies の右に移します。中の 3 行はそのままです。pathOf の「ROUTES の name の値」は ROUTES[name] です（02章 q08 問1）。キー名が型に残ったので、undefined を確かめずに .path を続けられます。protectedPaths は、Object.values()（02章 q08 問5）・.filter()（02章 q04 問7）・.map()（02章 q04 問5）を左から順につなげます。auth はもともと true か false なので、.filter() に渡す関数はそれをそのまま返せます。説明することは、書き直す前と後で、VS Code で ROUTES と RouteName にマウスを載せ、表示される型を見比べてから考えます。

e02enum をユニオン型に置き換える 新しく出てくる書き方：enum（読めれば十分）、型アサーション as（読めれば十分） 
export enum Color {
  Red = "red",
  Green = "green",
  Blue = "blue",
}

export const COLOR_HEX = {
  [Color.Red]: "#ff0000",
  [Color.Green]: "#00ff00",
  [Color.Blue]: "#0000ff",
};

export function toHex(color: Color): string {
  return COLOR_HEX[color];
}

export function isColor(text: string): boolean {
  return Object.values(Color).includes(text as Color);
}

ファイルのコードは enum を使っています。サバイバルTypeScript では、enum の代わりにユニオン型を使うことを勧めています。次のように書き直します。

  1. enum Color を消し、Color を "red" | "green" | "blue" のユニオン型にします。ほかのファイルから使えるようにします。
  2. COLOR_HEX を、as const（03章 q07 問1）を付けたオブジェクトにします。キーは色の名前、値は "#ff0000" などです。
  3. toHex(color) と isColor(text) を、新しい Color と COLOR_HEX を使って書き直します。呼び出す側は、toHex("red") のように文字列をそのまま渡せるようになります。

新しい書き方

enum

名前の付いた定数の集まり（読めれば十分）

enum は、名前と値の組をまとめる書き方です。enum Size { … } と書くと、値の Size（Size.Medium のように使うオブジェクト）と、型の Size が両方できます。export enum と書くと、ほかのファイルから使えます。自分で書くときはユニオン型を使い、enum は読めれば十分です。

サンプル 
// enum Size を作る。Small は "S"、Medium は "M"、Large は "L"
enum Size {
  Small = "S",
  Medium = "M",
  Large = "L",
}
// 大きさ size を Size として作り、Size の Medium を入れる
const size: Size = Size.Medium;
// 結果: size は "M"
Size.Large
"L"
Object.values(Size)
["S", "M", "L"]
値の Size は、ふつうのオブジェクトとして読める

サバイバルTypeScript「列挙型 (enum)」

値 as 型

型アサーション（読めれば十分）

値 as 型 は、「この値はこの型だ」と TypeScript に言い切る書き方です。型アサーションと呼びます。TypeScript は、本当にその型かを確かめません。ファイルの isColor の text as Color は、文字列の text を Color だとみなしています。

サンプル 
// Size という型を作る。"S" か "M" か "L"
type Size = "S" | "M" | "L";
// 関数 toSize を作る。文字列 text を受け取り、Size を返す
function toSize(text: string): Size {
  // text を Size とみなしたものを返す
  return text as Size;
}
// 結果: toSize("XL") はエラーにならず、"XL" を返す

よくある間違い戻り値の型は Size なのに、"XL" が返ってきます。as は型の確認をすり抜けるので、自分のコードでは使わずに、=== などで本当に確かめます。この課題の ESLint の設定でも、ファイルの text as Color の行はエラーになります。書き直すと、この行もなくなります。

ヒント 2コードへの直し方

enum Color { … } の 5 行を消し、e02 の 2 つ目の項目のサンプルの Size と同じ形で Color を書きます（03章 q02）。COLOR_HEX のキーの [Color.Red] などは、Color.Red がなくなるので red のように名前を直接書きます。閉じる } の後ろに as const を付けます。toHex は、中身も型注釈も今のままで動きます。isColor は、Object.keys()（02章 q08 問4）の結果に .includes()（02章 q04 問9）を続けます。text === "red" || text === "green" || text === "blue" と書いてもかまいません。説明することは、書き直す前のファイルの下に toHex("red"); の 1 行を書いて、型の確認のエラーを見てから考えます。書き直したあとにも同じ行を書いて、見比べます。試した行は、提出する前に消します。
