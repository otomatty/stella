03章 ユニオン型とそのほかの型

q01 型エイリアスとユニオン型

「文字列か数値」のように、どちらかの値が入る引数を扱う関数を 20 個書きます。引数と戻り値には型注釈を付けます。問1〜9 は、string | number のようなユニオン型を、引数の型注釈にそのまま書きます。問10〜20 は、type でユニオン型に名前を付けて export し、その名前を型注釈に使います。ユニオン型の値は、typeof v === "number" や v === "欠席" で場合を分けてから使います。これを絞り込みと呼びます。

問1文字列か数値を、文字列にして返す 新しく出てくる書き方：引数の型注釈にユニオン型 string | number を書く 
export function toId() {}

文字列か数値の ID を 1 つ受け取り、文字列にして返します。文字列なら、そのまま同じ文字列になります。

テストで確かめる値
toId(42)
"42"
数値を文字列にする
toId("a-1")
"a-1"
文字列はそのまま

型引数が string | number、戻り値が string であることも確かめます。

新しい書き方

(id: string | number)

引数にユニオン型を書く

02章 q04 問4 では、戻り値の型注釈に string | undefined を書きました。引数の型注釈にも、同じようにユニオン型を書けます。string | number と書いた引数には、文字列も数値も渡せます。

サンプル 
// 関数 orderLabel を作る。文字列か数値の orderNo を受け取り、文字列を返す
function orderLabel(orderNo: string | number): string {
  // orderNo を埋め込んだ「注文番号 ◯」の文字列を返す
  return `注文番号 ${orderNo}`;
}
// 結果: orderLabel(1024) は "注文番号 1024"、orderLabel("A-77") は "注文番号 A-77"

よくある間違いorderLabel の中で orderNo.toUpperCase() と書くと、型の確認でエラーになります。orderNo は数値のときもあり、数値には .toUpperCase() がないからです。ユニオン型の値は、どの型でも使える書き方でだけ、そのまま使えます。型ごとに分ける書き方は、問3 で出てきます。

新しい書き方

typeof

値の種類を調べる

typeof 値 と書くと、その値の種類を表す文字列になります。数値なら "number"、文字列なら "string"、true や false なら "boolean" です。

サンプル 
// 数量 quantity を作り、型を数値か文字列にして、12 を入れる
const quantity: number | string = 12;
// kind を作り、quantity の型を表す文字列を入れる
const kind = typeof quantity;
// 結果: kind は "number"
typeof 120
"number"
数値
typeof "ペン"
"string"
文字列
typeof true
"boolean"
真偽値

よくある間違いtypeof の結果は文字列です。比べるときは typeof fee === "number" のように " で囲みます。typeof fee === number と書くと、型の確認でエラーになります。

if (typeof fee === "number")

型を絞り込む

if の条件に typeof fee === "number" を書くと、その { } の中では、fee を数値として扱えます。TypeScript が条件を読んで、型を狭めてくれるからです。これを型の絞り込みと呼びます。

サンプル 
// 関数 feeText を作る。数値か文字列の fee を受け取り、文字列を返す
function feeText(fee: number | string): string {
  // もし fee の型が数値なら
  if (typeof fee === "number") {
    // fee を埋め込んだ「送料◯円」の文字列を返す
    return `送料${fee}円`;
  }
  // fee を返す
  return fee;
}
// 結果: feeText(500) は "送料500円"、feeText("要見積もり") は "要見積もり"

fee の型は、場所によって次のように変わります。

関数に入ったところ
number | string
まだどちらか分からない
if の { } の中
number
条件で数値だと分かった
if の後ろ
string
数値のときは { } の中で return したので、残りは文字列だけ

よくある間違い絞り込む前に fee.toFixed(1) と書くと、型の確認でエラーになります。fee が文字列のときもあり、文字列には .toFixed() がないからです。

よくある疑問if の後ろに else を書かなくてよいのは、return した時点で関数が終わるからです。else { return fee; } と書いても同じ結果になります。

新しい書き方

type Stock = number | "入荷待ち";

ユニオン型に名前を付ける

02章 q01 の応用では、オブジェクトの型に type で名前を付けました。ユニオン型にも、同じように名前を付けられます。| の両側には、number のような型も、"入荷待ち" のようなリテラル型（01章 q07 問1）も書けます。

サンプル 
// Stock という型を作る。数値か "入荷待ち"。ほかのファイルから使えるようにする
export type Stock = number | "入荷待ち";
// ペンの在庫 pen を作り、型を Stock にして、12 を入れる
const pen: Stock = 12;
// ノートの在庫 note を作り、型を Stock にして、"入荷待ち" を入れる
const note: Stock = "入荷待ち";
// 結果: pen は 12、note は "入荷待ち"

よくある間違いconst eraser: Stock = "入荷まち"; のように、決めた文字列と少しでも違う文字列を入れると、型の確認でエラーになります。"入荷待ち" 以外の文字列は Stock に入りません。

stock === "入荷待ち"

決めた値と等しいかで絞り込む

問3 では typeof で絞り込みました。=== でリテラル型の値と比べても、絞り込めます。stock === "入荷待ち" が成り立つ { } の中では、stock は "入荷待ち" です。そうでない側では、残りの number になります。

サンプル 
// 関数 stockLabel を作る。Stock の stock を受け取り、文字列を返す
function stockLabel(stock: Stock): string {
  // もし stock が "入荷待ち" と等しいなら
  if (stock === "入荷待ち") {
    // stock を返す
    return stock;
  }
  // stock を埋め込んだ「在庫◯個」の文字列を返す
  return `在庫${stock}個`;
}
// 結果: stockLabel(12) は "在庫12個"、stockLabel("入荷待ち") は "入荷待ち"

条件演算子（01章 q01 問12）の条件に書いても、同じように絞り込めます。: の右側では、stock は数値です。

if で書く
// もし stock が "入荷待ち" と等しいなら
if (stock === "入荷待ち") {
  // stock を返す
  return stock;
}
// stock を埋め込んだ「在庫◯個」の文字列を返す
return `在庫${stock}個`;
○ stockLabel(12) は "在庫12個"
条件演算子で書く
// stock が "入荷待ち" と等しいなら stock、そうでなければ stock を埋め込んだ「在庫◯個」の文字列を返す
return stock === "入荷待ち" ? stock : `在庫${stock}個`;
○ 同じ結果になります

よくある間違いstock === "入荷まち" のように打ち間違えると、型の確認でエラーになります。Stock にない値とは、比べても等しくならないからです。リテラル型を使うと、打ち間違いを実行する前に見つけられます。

コツ数値のほうを調べて、typeof stock === "number" で分けてもかまいません。どちらで分けても、絞り込みは同じように働きます。

応用ID の型 Id と、ID を整える関数・つなぐ関数 新しい書き方はありません。 
export type Id = unknown;

export function normalizeId() {}

export function joinIds() {}

ID を表す型を作り、その型を使う関数を 2 つ書きます。引数と戻り値には型注釈を付けます。

  1. Id：「文字列か数値」を表す型です。unknown を書き換えます。export は残します。
  2. normalizeId：Id を 1 つ受け取ります。数値なら、6 桁になるように前を "0" で埋めた文字列にして返します。文字列なら、前後の空白を取り除き、英字を大文字にして返します。
  3. joinIds：Id の読み取り専用の配列を受け取ります。要素をそれぞれ normalizeId で整え、", " でつないだ文字列を返します。
テストで確かめる値
Id の型
string | number
と同じ型であること
normalizeId(42)
"000042"
6 桁になるように 0 で埋める
normalizeId(123456)
"123456"
もう 6 桁
normalizeId(" ab-01 ")
"AB-01"
空白を取り除いて大文字にする
normalizeId("Z9")

型normalizeId は引数が Id、戻り値が string であることも確かめます。normalizeId(true) のように真偽値を渡すと、型の確認でエラーになることも確かめます。joinIds は引数が readonly Id[]、戻り値が string であることも確かめます。
