e01ラベル付き break 新しく出てくる書き方：ラベル outer:、ラベル付き break break outer; 
export function findPair() {}

export function findInGrid() {}

2 重のくり返しを途中で抜けたいとき、break だけでは内側のくり返ししか抜けられません。外側のくり返しにラベル（名前）を付けると、外側まで一度に抜けられます。次の 2 つの関数を、ラベル付き break を使って書きます。

  1. findPair(numbers, target)：足すと target になる 2 つの要素を探し、その番号の組 [i, j] を返します。i は j より小さい番号です。組がいくつかあるときは、最初に見つかった組を返します。なければ undefined を返します。引数の配列は readonly number[]、戻り値は [number, number] | undefined です。
  2. findInGrid(grid, value)：2 次元の配列（配列の中に配列が並んだもの）から value を探し、最初に見つかった位置 [行, 列] を返します。なければ undefined を返します。引数の grid は readonly (readonly number[])[] です。中の配列も外の配列も、読み取り専用という意味です。

説明すること：ラベル付き break を使わずに書くなら、どう書くか。

新しい書き方

outer: for (…)

くり返しにラベルを付ける

くり返しの文の前に 名前: と書くと、そのくり返しに名前を付けられます。この名前をラベルと呼びます。ラベルは、次の項目の break 名前; で、どのくり返しを抜けるかを指すために使います。

サンプル 
// 買い物かご carts を作り、[[1200, 800], [0, 500], [700]] を入れる
const carts: number[][] = [[1200, 800], [0, 500], [700]];
// 合計 total を入れ直せる変数として作り、0 を入れる
let total = 0;
// carts から 1 つずつ cart に取り出してくり返す。このくり返しに outer という名前を付ける
outer: for (const cart of carts) {
  // cart から 1 つずつ price に取り出してくり返す
  for (const price of cart) {
    // もし price が 0 と等しいなら
    if (price === 0) {
      // outer のくり返しを抜ける
      break outer;
    }
    // total に price を足す
    total += price;
  }
}
// 結果: total は 2000

このサンプルでは、値段が 0 の商品を、おかしなデータとして扱います。0 が出たら、その先は 1 つも足さずに集計をやめます。

決まりラベルを付けただけで break 名前; で使わないと、ESLint がエラーにします（no-unused-labels）。使わないラベルは書きません。

MDN「ラベル付き文」

break outer;

ラベル付き break で、外側のくり返しまで抜ける

break（04章 q04 問11）は、いちばん内側のくり返しだけを抜けます。break の後ろにラベルを書くと、そのラベルを付けたくり返しまで、まとめて抜けます。

ヒント 2コードへの直し方

どちらも、2 つ目の項目のコツと同じ形です。「見つけた組 found を、◯ か undefined を入れ直せる変数として作る」は let found: [number, number] | undefined; です。値を入れずに作ると、最初は undefined が入ります（02章 発展問題 e02）。findPair の j は i + 1 から始めるので、for (;;) で番号を数えます（01章 q01 問5）。numbers[i] の型は number | undefined になるので（02章 q04 問3）、numbers[i] ?? 0 のように ?? で 0 にしてから足します。findInGrid の「番号と要素の組」は .entries() です（04章 q03 問9）。for (const [row, cells] of grid.entries()) と書くと、要素が undefined にならずに取り出せます。説明することは、ラベルを使わない書き方を実際に書いて、テストが通るかを確かめてから書きます。試したあとは、ラベル付き break の書き方に戻してから提出します。

e02finally 新しく出てくる書き方：try-catch の入れ子と、内側の catch で投げたエラーを外側の catch で受け取る流れ 
export function processAll() {}

try-catch に finally を付けると、エラーが起きても起きなくても、最後に必ず実行される処理を書けます（04章 q05 問19）。開いたファイルを必ず閉じる、のような「後片付け」に使います。

processAll(inputs) を書きます。引数は文字列の読み取り専用の配列 readonly string[] です。1 つずつ JSON.parse で読み、読んだ結果が数値なら合計に足します。

  • 読めたけれど数値でなければ、"数値ではありません: <input>" というメッセージのエラーを投げます。それを catch で受け取り、その message を errors に足します。
  • JSON として読めなければ、"読めません: <input>" を errors に足します。
  • 読めても読めなくても、finally で log に "done: <input>" を足します。

<input> のところには、読もうとした文字列がそのまま入ります。戻り値は { total: number; errors: string[]; log: string[] } です。

テストで確かめる値
processAll(["1", "x", '"a"', "2"])
{ total: 3, errors: ["読めません: x", '数値ではありません: "a"'], log: ["done: 1", "done: x", 'done: "a"', "done: 2"] }
"x" は JSON として読めない。'"a"' は読めるが、文字列の "a" になる
processAll([])
{ total: 0, errors: [], log: [] }
空の配列

型引数が readonly string[]、戻り値が { total: number; errors: string[]; log: string[] } であることも確かめます。

新しい書き方

try { try { … } catch { throw … } } catch (error) { … }

try-catch を入れ子にする

try の { } の中に、もう 1 つ try-catch を書けます。内側の catch でエラーを投げると（04章 q05 問16）、そのエラーは外側の catch に届きます。エラーの種類ごとにメッセージを決めてから、外側の 1 か所でまとめて受け取れます。

サンプル 
// 記録 log を作り、空の文字列の配列を入れる
const log: string[] = [];
// 次の中を試す
try {
  // 次の中を試す
  try {
    // "x" を JSON として読む
    JSON.parse("x");
  } catch {
    // 読めなかったら、"在庫を読めません" というメッセージのエラーを投げる
    throw new Error("在庫を読めません");
  }
} catch (error) {
  // もし error が Error なら
  if (error instanceof Error) {
    // log の後ろに error の message をつなげる
    log.push(error.message);
  }
} finally {
  // 最後に必ず、log の後ろに "確認しました" をつなげる
  log.push("確認しました");
}
// 結果: log は ["在庫を読めません", "確認しました"]

動く順に並べました。

順番動く場所すること
1内側の tryJSON.parse("x") がエラーを投げる
2内側の catch"在庫を読めません" のエラーを投げる
3外側の catcherror.message を log の後ろにつなげる
4finally"確認しました" を log の後ろにつなげる

外側の try の中で投げたエラーも、同じ外側の catch に届きます。内側の try-catch の後ろに throw を書いても、行き先は同じです。

よくある疑問finally は、外側の catch が終わったあとに動きます。エラーが起きなかったときは、try の { } が終わったあとに動きます。どちらの道を通っても、finally は 1 回だけ動きます。

ヒント 2コードへの直し方

くり返しの中身は、e02 の項目のサンプルと同じ形です。「例外が投げられたら、投げられたものを error で受け取る」は外側の catch (error)、「最後に必ず」は finally です。「値 value を、型を unknown にして、入れ直せる変数として作る」は let value: unknown; です。内側の try の { } の中で const を作ると、{ } の外で使えません。そのため、先に外で作っておきます。「読めなかったら」の行は内側の catch で、JSON.parse のエラーを「読めません」のエラーに投げ直します。「value の型が数値でないなら」は typeof value !== "number" です（04章 q06）。この if を通ったあとは、value が number に絞り込まれるので、total に足せます。どちらのエラーも外側の catch に届くので、errors に足すのは 1 か所で済みます。最後の行は、省略記法の { total, errors, log } で書きます（02章 q01 問3）。
