07章 型の再利用とジェネリクス

q05 Record

キーと値の型を決めたオブジェクトの型 Record を使って、型と関数を 20 個書きます。型 Category と Weekday は、問題のファイルに用意してあります。Record<Keys, Type> は、キーが Keys、値が Type のオブジェクトの型です。Keys に Category のようなユニオン型を渡すと、そのすべてのキーを持つ型になります。1 つでも欠けると型エラーです。Keys を string にすると、02章 q08 のインデックス型と同じ型になります。関数の引数と戻り値には、型注釈を付けます。

問1型 CategoryCount を Record で作る 新しく出てくる書き方：Record<K, V> の形と、インデックス型との違い（Record は q02 問19 で出ました） 
export type Category = "food" | "drink" | "other";

// ここに型 CategoryCount を書く

型 CategoryCount を作ります。キーは Category の 3 つ（food・drink・other）、値は数値のオブジェクトの型です。Record を使って書き、ほかのファイルから使えるようにします。

新しい書き方

Record<K, V>

キーと値の型を決めたオブジェクトの型

q02 問19 で、Record<keyof User, string> を使いました。ここで形を整理します。Record は、TypeScript に最初から用意されている型です。< > の中に、キーの型と値の型を , で区切って書きます。キーの型にユニオン型を書くと、そのすべてのキーを持つオブジェクトの型になります。

サンプル 
// 配送方法 Delivery という型を作る。"normal" か "express" のどれか
type Delivery = "normal" | "express";
// 送料表 ShippingFees という型を作る。キーは Delivery、値は数値の Record
type ShippingFees = Record<Delivery, number>;
// 送料表 fees を作る。型は ShippingFees。normal は 500、express は 1200
const fees: ShippingFees = { normal: 500, express: 1200 };
// 送料 fee を作り、fees の express の値を入れる
const fee = fees.express;
// 結果: fee は 1200
Record<Delivery, number>
{ normal: number; express: number }
同じ型
Record<Delivery, string[]>
{ normal: string[]; express: string[] }
値の型を変えた
キーが 1 つ欠けている
const fees: ShippingFees = { normal: 500 };
✕ express がない、というエラーになります
すべてのキーがある
const fees: ShippingFees = { normal: 500, express: 1200 };
○ normal と express の両方があります

よくある間違いDelivery にないキーを書いても、エラーになります。{ normal: 500, express: 1200, cool: 800 } は、cool が ShippingFees にない、というエラーです。

Record<string, V>

インデックス型との違い

キーの型を string にすると、02章 q08 のインデックス型 { [key: string]: V } と同じ型になります。どんな文字列もキーにでき、決まったキーはありません。キーで取り出した値には、02章 q08 と同じく undefined が付きます。

サンプル 
// 在庫表 stock を作る。型は Record<string, number>
const stock: Record<string, number> = { ノート: 12, ペン: 0 };
// 空の注文表 orders を作る。型は Record<string, number>
const orders: Record<string, number> = {};
// 商品名 item を作り、"消しゴム" を入れる
const item = "消しゴム";
// orders の item に 3 を入れる
orders[item] = 3;
// left を作り、stock の item の値を入れる。なければ 0 を入れる
const left = stock[item] ?? 0;
// 結果: left は 0。orders は { 消しゴム: 3 }

キーの型をユニオン型にすると、決まったキーがすべてあることを型が保証します。そのため、キーの型の値で取り出すと、undefined は付きません。

サンプル 
// 配送方法 Delivery という型を作る。"normal" か "express" のどれか
type Delivery = "normal" | "express";
// 送料表 fees を作る。型は Record<Delivery, number>。normal は 500、express は 1200
const fees: Record<Delivery, number> = { normal: 500, express: 1200 };
// 配送方法 way を作る。型は Delivery。"express" を入れる
const way: Delivery = "express";
// fee を作り、fees の way の値を入れる
const fee = fees[way];
// 結果: fee は 1200。型は number で、undefined は付かない
型キー決まったキーがすべて要るかキーで取り出した値の型
{ [key: string]: number }どんな文字列でもよい要らない。空の {} も入るnumber | undefined
Record<string, number>どんな文字列でもよい要らない。空の {} も入るnumber | undefined
Record<Delivery, number>normal と express だけすべて要るnumber

上の 2 行は、書き方が違うだけで同じ型です。インデックス型のキーには、Delivery のようなリテラル型のユニオンを書けません。決まったキーの表を作るときは Record を使います。

インデックス型のキーに Delivery を書く
type Fees = { [way: Delivery]: number };
✕ インデックス型のキーにリテラル型は書けない、というエラーになります
Record のキーに Delivery を書く
type Fees = Record<Delivery, number>;
○ normal と express の 2 つのキーを持つ型になります

使い分けキーが前もって決まっているときは、Record<ユニオン型, 値の型> にします。点数表のようにキーが決まらないときは、Record<string, 値の型> かインデックス型にします。

新しい書き方

const ways: Delivery[] = [ … ]

キーの並びを、キーの型の配列として作る

Object.keys()（02章 q08 問4）の結果は、どんなオブジェクトでも string[] です。Record<Delivery, number> から string 型のキーで値を取り出すと、型エラーになります。決まったキーを順に調べるときは、キーを並べた配列を、キーの型の配列として自分で作ります。並べた順に取り出せるので、どのキーから調べるかも決められます。

サンプル 
// 配送方法 Delivery という型を作る。"normal" か "express" のどれか
type Delivery = "normal" | "express";
// 送料表 fees を作る。型は Record<Delivery, number>。normal は 500、express は 1200
const fees: Record<Delivery, number> = { normal: 500, express: 1200 };
// 配送方法の並び ways を作る。型は Delivery の配列。"normal"、"express"
const ways: Delivery[] = ["normal", "express"];
// 高い配送方法 expensive を作り、空の配列を入れる。型は Delivery の配列
const expensive: Delivery[] = [];
// ways から 1 つずつ way に取り出してくり返す
for (const way of ways) {
  // もし fees の way の値が 1000 以上なら
  if (fees[way] >= 1000) {
    // expensive の最後に way を足す
    expensive.push(way);
  }
}
// 結果: expensive は ["express"]
Object.keys() から取り出す
for (const way of Object.keys(fees)) {
  if (fees[way] >= 1000) {
    expensive.push(way);
  }
}
✕ way が string 型になり、fees[way] と expensive.push(way) で型エラーになります
Delivery の配列から取り出す
for (const way of ways) {
  if (fees[way] >= 1000) {
    expensive.push(way);
  }
}
○ way が Delivery 型なので、fees[way] は number です

よくある間違いlet で作った変数に "normal" を入れると、型は string に推論されます。Delivery 型の値として返したい変数は、let best: Delivery = "normal"; のように型注釈を付けます。

新しい書き方

Partial<T>（q03 問1）は、すべてのプロパティを省略できる型にします。Record<Delivery, number> を Partial に渡すと、キーは normal と express だけのまま、どちらも省略できる型になります。型の中に型を書くときは、内側の型から読みます。

// 配送方法 Delivery という型を作る。"normal" か "express" のどれか
type Delivery = "normal" | "express";
// 割引表 discounts を作る。型は Partial<Record<Delivery, number>>。express だけ 200
const discounts: Partial<Record<Delivery, number>> = { express: 200 };
// 配送方法 way を作る。型は Delivery。"normal" を入れる
const way: Delivery = "normal";
// off を作り、discounts の way の値を入れる。なければ 0 を入れる
const off = discounts[way] ?? 0;
// 結果: off は 0
Record<Delivery, number>
{ normal: number; express: number }
どちらのキーも要る
Partial<Record<Delivery, number>>
{ normal?: number; express?: number }
どちらのキーも省略できる

省略できるキーなので、discounts[way] の型は number | undefined です。数値として使う前に、??（02章 q02 問1）で代わりの値を決めます。

よくある間違いPartial<Record<Delivery, number>> でも、Delivery にないキーは書けません。{ cool: 100 } はエラーになります。
