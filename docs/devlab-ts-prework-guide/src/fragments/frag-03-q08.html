03章 ユニオン型とそのほかの型

q08 状態の切り替え

ドア、照明、タイマー、チケットの状態を扱う関数を 20 個書きます。4 つの型は定義済みです。どれも、state か status の値で今の状態を見分ける判別可能なユニオン型です（03章 q04）。状態を変える関数は、受け取ったオブジェクトを書き換えません。次の状態の新しいオブジェクトを作って返します。今の状態では変えられないときは、受け取ったものをそのまま返します。引数と戻り値の型注釈は自分で書きます。最後の総合問題では、注文の状態を表す型も自分で書きます。

問1開いているドアを閉める 新しく出てくる書き方：今の状態を受け取り、次の状態を返す関数、戻り値の型 : Door で返すオブジェクトを確かめる 
export type Door = { state: "open" } | { state: "closed" } | { state: "locked"; key: string };

export function closeDoor() {}

ドア door を受け取ります。開いているドア（state が "open"）なら、閉まっているドア { state: "closed" } を返します。それ以外のドアは、受け取ったものをそのまま返します。

テストで確かめる値
closeDoor({ state: "open" })
{ state: "closed" }
closeDoor({ state: "locked", key: "A" })
{ state: "locked", key: "A" }
鍵がかかっていればそのまま

型引数が Door、戻り値が Door であることも確かめます。

新しい書き方

(door: Door): Door

今の状態を受け取り、次の状態を返す

ドアの型 Door は、開いている・閉まっている・鍵がかかっている、の 3 つの状態のどれかです。どの状態かは state の値で見分けます。鍵がかかっているときだけ、鍵 key を持ちます。

状態を切り替える関数は、今の状態を受け取り、次の状態を返します。引数も戻り値も同じ Door です。問1〜4 の関数は、下の図の矢印 1 本ずつにあたります。

書き方は、予約の例で見てみます。仮予約を確定にする関数です。仮予約でないときは、受け取った予約をそのまま返します。

サンプル 
// 予約の型 Reservation を作る。state は "tentative"（仮予約）、"confirmed"（確定）、"cancelled"（取り消し）のどれか
type Reservation = { state: "tentative" } | { state: "confirmed" } | { state: "cancelled" };

// 関数 confirmReservation を作る。Reservation の reservation を受け取り、Reservation を返す
function confirmReservation(reservation: Reservation): Reservation {
  // reservation の state が "tentative" なら、state が "confirmed" のオブジェクトを、そうでなければ reservation を返す
  return reservation.state === "tentative" ? { state: "confirmed" } : reservation;
}
// 結果: confirmReservation({ state: "tentative" }) は { state: "confirmed" }、confirmReservation({ state: "cancelled" }) は { state: "cancelled" }
受け取った reservation の stateconfirmReservation が返すもの

"cancelled"受け取った reservation（そのまま）
受け取ったオブジェクトを書き換える

新しい書き方

状態を確かめてから、その状態だけが持つプロパティを使う

key を持つのは、鍵がかかったドアだけです。door.key とそのまま書くと、「Door に key はない」というエラーになります。開いているドアには key がないからです。先に状態を確かめると、その後ろでは型が絞り込まれ、key が使えます。

サンプル 
// 会員の型 Member を作る。state は "guest"（ゲスト）か "member"（会員）。会員だけが memberId（文字列）を持つ
type Member = { state: "guest" } | { state: "member"; memberId: string };

// 関数 isSameMember を作る。Member の member と文字列 id を受け取り、true か false を返す
function isSameMember(member: Member, id: string): boolean {
  // member の state が "member"、かつ member の memberId が id と等しいかどうか（true か false）を返す
  return member.state === "member" && member.memberId === id;
}
// 結果: isSameMember({ state: "member", memberId: "M-01" }, "M-01") は true、isSameMember({ state: "guest" }, "M-01") は false
状態を確かめずに使う
return member.memberId === id;
✕ Member に memberId はない、というエラーになります
&& の左で状態を確かめる
return member.state === "member" && member.memberId === id;
○ && の右では、member は会員だと分かっています

&&（01章 q02 問16）は、左が false なら右を調べません。そのため、右に進むのは会員のときだけです。if で確かめたときも同じです。if の中で先に return すると、その後ろの行では、残りの状態に絞り込まれます。

サンプル 
// 会員の型 Member を作る。state は "guest"（ゲスト）か "member"（会員）。会員だけが memberId（文字列）を持つ
type Member = { state: "guest" } | { state: "member"; memberId: string };

// 関数 memberLabel を作る。Member の member を受け取り、文字列を返す
function memberLabel(member: Member): string {
  // もし member の state が "guest" なら
  if (member.state === "guest") {
    // "ゲスト" を返す
    return "ゲスト";
  }
  // member の memberId を埋め込んだ「会員番号 ◯」の文字列を返す
  return `会員番号 ${member.memberId}`;
}
// 結果: memberLabel({ state: "member", memberId: "M-01" }) は "会員番号 M-01"、memberLabel({ state: "guest" }) は "ゲスト"

新しい書き方

switch (x.state)

状態ごとに場合を分け、すべての状態を書く

状態が 3 つ以上あるときは、03章 q04 で出た switch で場合を分けると読みやすくなります。case ごとに return すれば、switch の後ろに return は要りません。すべての状態の case を書いてあることを、TypeScript が分かっているからです。

サンプル 
// 予約の型 Reservation を作る。state は "tentative"（仮予約）、"confirmed"（確定）、"cancelled"（取り消し）のどれか
type Reservation = { state: "tentative" } | { state: "confirmed" } | { state: "cancelled" };

// 関数 reservationText を作る。Reservation の reservation を受け取り、文字列を返す
function reservationText(reservation: Reservation): string {
  // reservation の state で場合を分ける
  switch (reservation.state) {
    // "tentative" の場合
    case "tentative":
      // "仮予約" を返す
      return "仮予約";
    // "confirmed" の場合
    case "confirmed":
      // "確定" を返す
      return "確定";
    // "cancelled" の場合
    case "cancelled":
      // "取り消し" を返す
      return "取り消し";
  }
}
// 結果: reservationText({ state: "confirmed" }) は "確定"

よくある間違いcase を 1 つ書き忘れると、2 つのエラーが出ます。TypeScript は「関数の最後に return がない」、ESLint は「switch で扱っていない場合がある（Switch is not exhaustive）」です。どちらも、足りない case を書き足せば消えます。

問10タイマーを動かす 新しい書き方はありません。 
export type Timer =

タイマー timer と今の時刻 now（数値）を受け取り、タイマーを動かします。

  • "paused" なら、止まっていた分を引いて "running" にします。startedAt は now - elapsed です。
  • "running" なら、そのまま返します。

export type PendingOrder = unknown;
export type PaidOrder = unknown;
export type ShippedOrder = unknown;

ネットショップの注文を判別可能なユニオン型で表し、状態を進める関数を書きます。状態遷移は、状態が決まった矢印に沿って移り変わることです。どの関数も、元の注文オブジェクトは変えません。新しいオブジェクトを作って返します。

  1. 次の型を書いて export します。unknown を書き換えます。
    • PendingOrder（未払い）：status が "pending"、id（数値）、amount（金額。数値）
    • PaidOrder（支払済み）：status が "paid"、id、amount、paidAt（支払日時。Date）
    • ShippedOrder（発送済み）：status が "shipped"、id、amount、paidAt、shippedAt（Date）、trackingNumber（追跡番号。文字列）
    • CancelledOrder（キャンセル）：status が "cancelled"、id、amount、reason（理由。文字列）
    • Order：上の 4 つのユニオン型
    • Transition：状態を進めた結果。成功は { ok: true; order: Order }、失敗は { ok: false; error: string }
  2. pay(order, paidAt) は、未払いの注文だけを支払済みにします。それ以外は失敗を返します。
  3. ship(order, shippedAt, trackingNumber) は、支払済みの注文だけを発送済みにします。それ以外は失敗を返します。
  4. cancel(order, reason) は、未払いか支払済みの注文だけをキャンセルにします。発送済みとキャンセル済みは失敗を返します。
  5. statusText(order) は、状態ごとに "注文1: 未払い（1,200円）"・"注文1: 支払済み（1,200円）"・"注文1: 発送済み（追跡番号 ABC123）"・"注文1: キャンセル（在庫切れ）" の形の文字列を返します。金額は 3 桁ごとにカンマで区切ります。

型は、オブジェクトの型（02章 q01）を 4 つ書き、Order で | につなぎます。status の型は "pending" のようなリテラル型、Date は 03章 q03 問20 で出た型です。Transition の ok: true と ok: false は、03章 q04 問16 の ApiResponse と同じ形です。pay と ship は、問4 のサンプルの memberLabel と同じく、先に失敗を return します。その後ろでは order が未払い（または支払済み）に絞り込まれるので、{ ...order, status: "paid", paidAt }（02章 q02 問8）で次の状態を作れます。cancel では、支払済みの注文から paidAt を残さないように、スプレッドを使わずに要るプロパティだけを書きます（問14）。返す結果は { ok: true, order: … } のように、オブジェクトの中にオブジェクトを書きます。金額の区切りは .toLocaleString("ja-JP") です（01章 q02 問12）。statusText は問5 と同じ switch の形です。
