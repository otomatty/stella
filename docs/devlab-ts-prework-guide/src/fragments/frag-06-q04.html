06章 クラス

q04 クラスの継承

あるクラスをもとにして、新しいクラスを作ることを継承と呼びます。もとのクラスを親クラス、新しく作るクラスを子クラスと呼びます。子クラスは、親クラスのフィールドとメソッドをそのまま受け継ぎます。そのうえで、違うところだけを書き足したり、書き換えたりします。ドリルは 1 つのファイルに 20 問あり、どの問も親クラスと子クラスを 1 組書きます。ドリルを提出してから、応用問題に進みます。フィールド、constructor の引数、メソッドの引数と戻り値には型注釈を付けます。

ドリル親クラスと、それを継承した子クラスを書く 新しく出てくる書き方：extends、super(…)、override、super.メソッド名()、子クラスを親クラスの型で扱う、instanceof で子クラスを見分ける 
// 問1 Animal(name) の speak() は "…"。Animal を継承した Dog の speak() は "ポチ: ワン" を返す（name を使う）
//     例: new Dog("ポチ").speak() → "ポチ: ワン"
// ここに Animal と Dog を書く

ファイルには、問1 から問20 までの問題文がコメントで書いてあります。「ここに ◯ を書く」の行の下に、クラスを書きます。テストがクラスを読み込めるように、どのクラスにも export を付けます（06章 q01）。問題文の Animal(name) は、constructor が name を受け取る、という意味です。

子クラスの constructor では、最初に super(…) で親クラスの constructor を呼びます。親クラスのメソッドを書き換えるときは override を付けます。付けないと型エラーになる設定です。

  1. Animal は名前 name を受け取り、speak() が "…" を返します。Dog は Animal と同じく名前を受け取り、speak() が "ポチ: ワン" の形で返します。ポチ のところには name が入ります。
  2. Shape は引数なしで作り、area() が 0 を返します。Square は一辺の長さ size を受け取り、area() が size × size を返します。
  3. Staff は名前 name と給料 salary を受け取り、pay() が salary を返します。PartTimer は名前・時給 hourly・働いた時間 hours を受け取り、親の constructor には名前と 0 を渡します。pay() は hourly × hours を返します。name は外から読めるようにします。
  4. Vehicle は車輪の数 wheels を受け取り、describe() が "車輪 4つ" の形で返します。Bicycle は引数なしで作り、親の constructor に 2 を渡します。
  5. Wallet は残高 balance を受け取ります。withdraw(n) は残高から n を引き、引いた後の残高を返します。n が残高より大きければ、"残高が足りません" というメッセージのエラーを投げます。OverdraftAccount は残高と、残高を超えて引き出せる額 limit を受け取ります。残高が -limit になるまでは引き出せて、それより下になるときは同じエラーを投げます。balance は protected にします（06章 q02 問20）。
  6. Logger の prefix() は "[LOG]" を返し、format(message) は prefix() の結果と message を半角スペースでつないで返します。ErrorLogger は prefix() だけを書き換えて、"[ERROR]" を返すようにします。
  7. Greeter の greet(name) は "こんにちは、山田さん" の形で返します。PoliteGreeter の greet(name) は、親の greet の結果の後ろに "。よろしくお願いします" をつなげて返します。親の結果は super.greet で受け取ります。
  8. Counter はフィールド value を 0 から始め、increment() で 1 増やして、増やした後の値を返します。DoubleCounter の increment() は 2 増やして、増やした後の値を返します。
  9. Product は名前 name と価格 price を受け取り、priceWithTax() が税率 10% の税込み価格を返します。1 円未満は切り捨てます。Food は税率を 8% にします。
  10. Point2D は x と y を受け取り、label() が "(1, 2)" の形で返します。Point3D は x・y・z を受け取り、label() が "(1, 2, 3)" の形で返します。
  11. Creature は名前 name を受け取ります。Fish と Bird は Creature を継承するだけで、中に何も書きません。関数 kindOf(creature) は、Fish なら "魚"、Bird なら "鳥"、それ以外は "その他" を返します。instanceof を使います。
  12. User は名前 name を受け取り、role() が "一般" を返します。Admin の role() は "管理者" を返します。関数 roles(users) は、それぞれを "山田: 一般" の形にした配列を返します。引数は readonly User[]、戻り値は string[] です。
  13. Rectangle は幅 width と高さ height を受け取り、area() が面積を返します。SquareRect は一辺の長さ size だけを受け取り、親の constructor に size を 2 回渡します。
  14. Message は文字列 text を受け取り、format() が text をそのまま返します。UrgentMessage の format() は、親の結果の前に "【至急】" を付けて返します。
  15. Timer は秒数 seconds を受け取り、label() が "60秒" の形で返します。Countdown の label() は、親の結果の前に "残り" を付けて返します。
  16. Character は体力 hp を受け取ります。hp は外から読めるようにします。damage(n) は hp を n だけ減らします。ただし 0 より小さくはしません。何も返しません。Warrior の damage(n) は、n の半分（1 未満は切り捨て）だけ減らします。
  17. Notifier の send(message) は "通知: 完了" の形で返します。EmailNotifier はメールアドレス address を受け取り、send(message) が "メール(a@example.com): 完了" の形で返します。
  18. AdmissionTicket は価格 price を受け取り、finalPrice() が price を返します。ChildTicket の finalPrice() は、親の結果の半額を返します。1 円未満は切り捨てます。
  19. Collection はフィールド items（文字列の配列。最初は空）を持ち、add(item) で後ろに足します。何も返しません。UniqueCollection の add(item) は、すでに items にあるものは足しません。
  20. Polygon は辺の数 sides を受け取り、describe() が "5角形" の形で返します。Triangle は引数なしで作り、親の constructor に 3 を渡します。

新しい書き方

class 子 extends 親

親クラスを受け継いで、子クラスを作る

クラスの名前の後ろに extends 親クラスの名前 と書くと、親クラスのフィールドとメソッドをすべて受け継いだクラスになります。06章 q02 問20 で、少しだけ使いました。子クラスの { } に何も書かなくても、親クラスと同じように使えます。constructor も受け継ぐので、子クラスに constructor を書かなければ、親クラスと同じ引数で new します。

サンプル 
// クラス Member を作る
class Member {
  // constructor を作る。文字列の name を受け取り、入れ直せないフィールド name にする
  constructor(readonly name: string) {}

  // メソッド label を作る。文字列を返す
  label(): string {
    // this.name を埋め込んだ「◯ 様」の文字列を返す
    return `${this.name} 様`;
  }
}

// Member を継承したクラス PremiumMember を作る。中身は書かない
class PremiumMember extends Member {}

// premium を作り、名前を "佐藤" にした PremiumMember を入れる
const premium = new PremiumMember("佐藤");
// text を作り、premium の label を呼んだ結果を入れる
const text = premium.label();
// 結果: text は "佐藤 様"、premium.name は "佐藤"

よくある疑問受け継いだ label() の中の this は、呼んだインスタンスです。premium.label() なら、this.name は premium の name の "佐藤" です。

サバイバルTypeScript「クラスの継承」

super(…)

子クラスの constructor で、親クラスの constructor を呼ぶ

子クラスに constructor を書くときは、その中で super(…) を呼びます。super は親クラスのことで、super(…) は親クラスの constructor を呼ぶ書き方です。かっこの中には、親クラスの constructor が受け取る引数を渡します。子クラスでは、受け取る引数の数を変えられます。親クラスに、決まった値を渡すこともできます。

サンプル 
// クラス Coupon を作る
class Coupon {
  // constructor を作る。文字列の code と数値の discount を受け取り、どちらも入れ直せないフィールドにする
  constructor(
    readonly code: string,
    readonly discount: number,
  ) {}
}

// Coupon を継承したクラス WelcomeCoupon を作る
class WelcomeCoupon extends Coupon {
  // constructor を作る。文字列の memberName を受け取り、入れ直せないフィールド memberName にする
  constructor(readonly memberName: string) {
    // 親の constructor に "WELCOME" と 500 を渡して呼ぶ
    super("WELCOME", 500);
  }
}

// welcome を作り、会員名を "佐藤" にした WelcomeCoupon を入れる
const welcome = new WelcomeCoupon("佐藤");
// 結果: welcome.code は "WELCOME"、welcome.discount は 500、welcome.memberName は "佐藤"

子クラスで受け取った値を、そのまま親クラスに渡すこともできます。親クラスに渡す引数には readonly を付けません。フィールドを作るのは、親クラスの constructor だからです。子クラスだけが持つ引数に、readonly を付けます。

サンプル 
// Coupon を継承したクラス LimitedCoupon を作る
class LimitedCoupon extends Coupon {
  // constructor を作る。文字列の code と数値の discount と文字列の until を受け取る。until を入れ直せないフィールドにする
  constructor(
    code: string,
    discount: number,
    readonly until: string,
  ) {
    // 親の constructor に code と discount を渡して呼ぶ
    super(code, discount);
  }
}

// limited を作り、"SUMMER" と 300 と "2026-08-31" を渡した LimitedCoupon を入れる
const limited = new LimitedCoupon("SUMMER", 300, "2026-08-31");
// 結果: limited.code は "SUMMER"、limited.discount は 300、limited.until は "2026-08-31"
super(…) を呼ばない
constructor(readonly memberName: string) {}
✕ 子クラスの constructor には super の呼び出しが要る、という型エラーになります
super(…) を呼ぶ
constructor(readonly memberName: string) {
  super("WELCOME", 500);
}
○ 親クラスの constructor が動き、code と discount が入ります

決まりsuper(…) は、constructor の最初の行に書きます。親クラスの constructor が引数を受け取らないときも、super() と、空のかっこで呼びます。

サバイバルTypeScript「クラスの継承」

override

親クラスのメソッドを、子クラスで書き換える

子クラスに、親クラスと同じ名前のメソッドを書くと、子クラスのインスタンスではそちらが使われます。これを上書き（オーバーライド）と呼びます。上書きするメソッドの前には override を付けます。この課題の設定（tsconfig.json の noImplicitOverride）では、付けないと型エラーになります。

サンプル 
// クラス Shipping を作る
class Shipping {
  // メソッド fee を作る。数値を返す
  fee(): number {
    // 500 を返す
    return 500;
  }

  // メソッド label を作る。文字列を返す
  label(): string {
    // this.fee() の結果を埋め込んだ「送料 ◯円」の文字列を返す
    return `送料 ${this.fee()}円`;
  }
}

// Shipping を継承したクラス ExpressShipping を作る
class ExpressShipping extends Shipping {
  // 親の fee を上書きするメソッド fee を作る。数値を返す
  override fee(): number {
    // 800 を返す
    return 800;
  }
}

// normal を作り、新しい Shipping の label を呼んだ結果を入れる
const normal = new Shipping().label();
// express を作り、新しい ExpressShipping の label を呼んだ結果を入れる
const express = new ExpressShipping().label();
// 結果: normal は "送料 500円"、express は "送料 800円"

label は、親クラスにしか書いてありません。それでも express は "送料 800円" になります。メソッドを呼ぶと、まずインスタンスの子クラスから探し、なければ親クラスから探すからです。親クラスのメソッドの中の this.fee() も、同じ順に探します。

override を付けない
fee(): number {
  return 800;
}
✕ 親クラスのメンバーを上書きするので override が要る、という型エラーになります
override を付ける
override fee(): number {
  return 800;
}
○ 親クラスの fee を、子クラスで上書きします

決まり親クラスにないメソッドに override を付けても、型エラーになります。名前を打ち間違えたときに、気づけるようにするためです。上書きするメソッドの引数と戻り値の型は、親クラスのメソッドと同じにします。

サバイバルTypeScript「クラスの継承」

super.メソッド名()

子クラスの中で、親クラスのメソッドを呼ぶ

上書きしたメソッドの中で、親クラスの同じメソッドの結果を使いたいことがあります。super.メソッド名() と書くと、親クラスのメソッドを呼べます。親クラスの結果に書き足すだけなら、同じ計算を子クラスにもう一度書かずに済みます。

サンプル 
// クラス Invoice を作る
class Invoice {
  // constructor を作る。数値の amount を受け取り、入れ直せないフィールド amount にする
  constructor(readonly amount: number) {}

  // メソッド total を作る。数値を返す
  total(): number {
    // this.amount を返す
    return this.amount;
  }
}

// Invoice を継承したクラス ShippedInvoice を作る
class ShippedInvoice extends Invoice {
  // 親の total を上書きするメソッド total を作る。数値を返す
  override total(): number {
    // 親の total を呼んだ結果に 500 を足した数を返す
    return super.total() + 500;
  }
}

// total を作り、金額を 3000 にした ShippedInvoice の total を呼んだ結果を入れる
const total = new ShippedInvoice(3000).total();
// 結果: total は 3500

親クラスのメソッドが引数を受け取るときは、super.メソッド名(引数) のように渡します。結果は、ふつうの値と同じように、テンプレートリテラルに埋め込むこともできます。

super.total() + 500
3500
親の total の 3000 に 500 を足す
`合計 ${super.total()}円`
"合計 3000円"
親の結果を埋め込む
this.total() と書く
override total(): number {
  return this.total() + 500;
}
✕ 子クラスの total が、自分自身を呼び続けます。型エラーにはならず、実行すると RangeError になります
super.total() と書く
override total(): number {
  return super.total() + 500;
}
○ 親クラスの total を 1 回だけ呼びます

const s: Shipping = new ExpressShipping()

子クラスのインスタンスを、親クラスの型で扱う

子クラスは、親クラスのフィールドとメソッドをすべて持っています。そのため、子クラスのインスタンスは、親クラスの型の変数や配列に入れられます。親クラスの型で扱っても、メソッドを呼ぶと、そのインスタンスのクラスで上書きしたメソッドが使われます。

サンプル 
// 送料の配列 shippings を作る。型は Shipping の配列。Shipping と ExpressShipping を 1 つずつ入れる
const shippings: Shipping[] = [new Shipping(), new ExpressShipping()];
// fees を作り、shippings の要素を 1 つずつ s として、s の fee を呼んだ結果に変えた新しい配列を入れる
const fees = shippings.map((s) => s.fee());
// 結果: fees は [500, 800]

このサンプルは、override の項目の Shipping と ExpressShipping を使います。配列の型は Shipping[] ですが、2 つめの要素では ExpressShipping の fee が呼ばれます。

よくある疑問親クラスの型で扱っているときは、子クラスだけが持つフィールドやメソッドは使えません。Coupon の型の変数に WelcomeCoupon を入れると、memberName は読めません。使うには、次の項目の instanceof で、子クラスかどうかを先に確かめます。

x instanceof ExpressShipping

どのクラスから作ったインスタンスかを調べる

instanceof（04章 q05 問10）は、自分で書いたクラスにも使えます。値 instanceof クラス名 は、値がそのクラスか、その子クラスから作ったものなら true です。if の条件に使うと、{ } の中では値の型がそのクラスに絞り込まれます。

サンプル 
// 関数 shippingName を作る。Shipping の shipping を受け取り、文字列を返す
function shippingName(shipping: Shipping): string {
  // もし shipping が ExpressShipping から作ったものなら
  if (shipping instanceof ExpressShipping) {
    // "速達" を返す
    return "速達";
  }
  // "通常" を返す
  return "通常";
}

// kind を作り、新しい ExpressShipping を渡して shippingName を呼んだ結果を入れる
const kind = shippingName(new ExpressShipping());
// 結果: kind は "速達"
new ExpressShipping() instanceof ExpressShipping
true
new ExpressShipping() instanceof Shipping
true
子クラスのインスタンスは、親クラスのインスタンスでもある
new Shipping() instanceof ExpressShipping
false
親クラスのインスタンスは、子クラスのインスタンスではない

コツ親クラスと子クラスを両方調べるときは、子クラスを先に調べます。instanceof Shipping を先に書くと、ExpressShipping のインスタンスもそこで true になってしまいます。

応用社員と管理職 新しい書き方はありません。 
export class Employee {}

export class Manager {}

export function payroll() {}

export function countManagers() {}

社員を表すクラス Employee と、それを継承した管理職のクラス Manager を書きます。そのあと、社員の配列を受け取る関数を 2 つ書きます。

  1. Employee は、名前 name と月給 salary を受け取ります。どちらも入れ直せないフィールドにします。describe() は "山田（月給 300,000円）" の形の文字列を返します。月給は 3 桁ごとにカンマで区切ります。annualSalary() は年収（月給 × 12）を返します。
  2. Manager は Employee を継承します。名前・月給・部下の人数 teamSize を受け取り、teamSize をフィールドにします。describe() は、親の describe() の結果の後ろに "・部下 5人" の形でつなげて返します。annualSalary() は、親の年収に、賞与として月給 × 2 を足して返します。どちらも super で親のメソッドを呼びます。
  3. payroll(employees) は、全員の年収の合計を返します。Manager が混ざっていても、それぞれのクラスの annualSalary で数えます。
  4. countManagers(employees) は、Manager の人数を返します。instanceof を使います。

3. と 4. の引数は readonly Employee[]、戻り値は number です。
