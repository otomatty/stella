07章 型の再利用とジェネリクス

q07 型引数の制約

型引数（07章 q06）を使った関数を 20 個書きます。この番号では、型引数に「制約」を付けます。制約は、型引数に渡せる型を限る書き方です。<T extends { length: number }> は「length を持つ型だけ」、<K extends keyof T> は「T のプロパティ名だけ」、<T extends object> は「オブジェクトだけ」に限ります。制約を付けると、関数の中でその型のプロパティを使えるようになります。any や unknown は使いません。テストは、制約に合わない呼び出しが型のエラーになることも確かめます。制約の要らない問題もあります。

問1obj の key のプロパティを返す 新しく出てくる書き方：型引数の制約 T extends 型、K extends keyof T 
export function getProp() {}

オブジェクト obj と、プロパティ名 key を受け取ります。obj の key のプロパティの値を返します。key に渡せるのは、obj が持つプロパティ名だけにします。obj の型を T、key の型を K とすると、戻り値の型は T[K] です。

テストで確かめる値

テストでは、次の user を使います。

const user = { name: "山田", age: 30 };
getProp(user, "age")
30
getProp(user, "email")
型のエラー
email は user のプロパティではない

型getProp(user, "age") の戻り値の型が number、getProp(user, "name") の戻り値の型が string であることも確かめます。

印テストの getProp(user, "email") の行には、@ts-expect-error（次の行が型のエラーになるはず、という印）が付いています。制約がないとエラーが起きないので、型の確認で「Unused '@ts-expect-error' directive」というエラーになります。この番号のほかの問題も同じです。

新しい書き方

T extends 型

型引数に渡せる型を限る（制約）

07章 q06 の <T> には、どんな型でも渡せます。そのため関数の中では、T の値がどんなプロパティを持つか分かりません。<T extends { price: number }> と書くと、T に渡せるのは「price（数値）を持つ型」だけになります。これを型引数の制約といいます。制約を付けると、関数の中で item.price を使えます。

サンプル 
// 型 Item を作る。name は文字列、price は数値
type Item = { name: string; price: number };
// 関数 cheapItems を作る。型変数 T（price（数値）を持つ型に限る）を使い、読み取り専用の T の配列 items と数値 limit を受け取り、T の配列を返す
function cheapItems<T extends { price: number }>(items: readonly T[], limit: number): T[] {
  // items の要素を 1 つずつ item として、item の price が limit 以下のものだけを集めた新しい配列を返す
  return items.filter((item) => item.price <= limit);
}
// 商品の一覧 items を Item の配列として作り、ノートと万年筆を入れる
const items: Item[] = [
  { name: "ノート", price: 180 },
  { name: "万年筆", price: 3200 },
];
// cheap を作り、cheapItems に items と 500 を渡して呼んだ結果を入れる
const cheap = cheapItems(items, 500);
// 結果: cheap は [{ name: "ノート", price: 180 }]。型は Item[]
制約を付けない
function cheapItems<T>(items: readonly T[], limit: number): T[] {
  return items.filter((item) => item.price <= limit);
}
✕ 型の確認でエラーになります。T が price を持つか分からないからです（Property 'price' does not exist on type 'T'）
制約を付ける
function cheapItems<T extends { price: number }>(items: readonly T[], limit: number): T[] {
  return items.filter((item) => item.price <= limit);
}
○ T は必ず price を持つので、item.price を使えます

○ T には渡した配列の要素の型（Item）が入るので、戻り値の型は Item[] のままです
cheapItems(items, 500)
[{ name: "ノート", price: 180 }]
型は Item[]
cheapItems([{ name: "ノート" }], 500)

price を持たない

サバイバルTypeScript「型引数の制約」

K extends keyof T

T のプロパティ名だけに限る

keyof T は、T のプロパティ名を並べたユニオン型です（07章 q02）。<K extends keyof T> と書くと、K に渡せるのは T のプロパティ名だけになります。型引数を 2 つ並べるときは、07章 q06 の <A, B> と同じく , で区切ります。後ろの型引数の制約には、前の型引数 T を使えます。

サンプル 
// 型 Order を作る。id は数値、status は文字列、total は数値
type Order = { id: number; status: string; total: number };
// 関数 beforeAfter を作る。型変数 T と、型変数 K（T のプロパティ名に限る）を使い、T の before と T の after と K の key を受け取り、T[K] と T[K] を並べたタプルを返す
function beforeAfter<T, K extends keyof T>(before: T, after: T, key: K): [T[K], T[K]] {
  // before の key の値、after の key の値の順に並べたタプルを返す
  return [before[key], after[key]];
}
// 変更前の注文 oldOrder を Order として作り、{ id: 1, status: "受付", total: 3000 } を入れる
const oldOrder: Order = { id: 1, status: "受付", total: 3000 };
// 変更後の注文 newOrder を Order として作り、{ id: 1, status: "発送済み", total: 3000 } を入れる
const newOrder: Order = { id: 1, status: "発送済み", total: 3000 };
// statuses を作り、beforeAfter に oldOrder と newOrder と "status" を渡して呼んだ結果を入れる
const statuses = beforeAfter(oldOrder, newOrder, "status");
// 結果: statuses は ["受付", "発送済み"]。型は [string, string]

T と K には、呼び出したときに渡した値の型が入ります。T[K] は、T の K のプロパティの型です（インデックスアクセス型、03章 q07 問10）。

呼び出しTKT[K]
beforeAfter(oldOrder, newOrder, "status")Order"status"string
beforeAfter(oldOrder, newOrder, "total")Order"total"number

keyof Order で受け取る

  return target[key];

✕ orderValue(oldOrder, "total") の型は string | number です。数値だと分かっていても、数値として使えません

○ orderValueOf(oldOrder, "total") の型は number です
制約を付けない
function beforeAfter<T, K>(before: T, after: T, key: K): [T[K], T[K]] {
  return [before[key], after[key]];
}
✕ 型の確認でエラーになります。K が T のプロパティ名か分からないからです（Type 'K' cannot be used to index type 'T'）
制約を付ける
function beforeAfter<T, K extends keyof T>(before: T, after: T, key: K): [T[K], T[K]] {
  return [before[key], after[key]];

T extends object

オブジェクトだけに限る

object は、オブジェクトや配列の型です（07章 q02 問16）。文字列・数値・true / false・null・undefined は入りません。<T extends object> と書くと、T に渡せるのはオブジェクトだけになります。

サンプル 
// 型 Member を作る。id は数値、name は文字列
type Member = { id: number; name: string };
// 関数 snapshot を作る。型変数 T（オブジェクトに限る）を使い、T の value を受け取り、読み取り専用の T を返す
function snapshot<T extends object>(value: T): Readonly<T> {
  // value を広げたオブジェクトを、書き換えられないようにしたものを返す
  return Object.freeze({ ...value });
}
// 会員 member を Member として作り、{ id: 7, name: "佐藤" } を入れる
const member: Member = { id: 7, name: "佐藤" };
// saved を作り、snapshot に member を渡して呼んだ結果を入れる
const saved = snapshot(member);
// 結果: saved は { id: 7, name: "佐藤" }。型は Readonly<Member>

Readonly は 07章 q03 問3、Object.freeze() は 07章 q03 問8 で出ました。

snapshot(member)
{ id: 7, name: "佐藤" }
型は Readonly<Member>
snapshot(5)
型のエラー
数値はオブジェクトではない
snapshot("佐藤")
型のエラー
文字列もオブジェクトではない
制約を付けない
function snapshot<T>(value: T): Readonly<T> {
  return Object.freeze({ ...value });
}
✕ 関数の中はエラーになりません。そのかわり snapshot(5) も型のエラーにならずに通ります
制約を付ける

  return Object.freeze({ ...value });
}
○ snapshot(5) が型のエラーになります

よくある間違いスプレッド構文 { ...value } は、制約のない T にも書けます。そのため制約を付け忘れても、関数の中ではエラーが出ません。テストの「数値は渡せない」の確かめで、初めて気づくことになります。

応用プロパティを取り出す・長い方・値を並べる・id を足す 新しい書き方はありません。 
export function getProperty() {}

export function longest() {}

export function pluck() {}

export function withId() {}

4 つの関数を、型引数と制約を使って書きます。

  1. getProperty(obj, key)：obj[key] を返します。key は obj のプロパティ名に限ります。戻り値の型は T[K] です。
  2. longest(a, b)：length が長い方を返します。同じなら a を返します。length を持つ型に限ります。
  3. pluck(items, key)：それぞれの要素の key の値を並べた配列を返します。戻り値の型は T[K][] です。
  4. withId(value, id)：オブジェクトに id を足した新しいオブジェクトを返します。オブジェクトに限ります（T extends object）。戻り値の型は T & { id: number } です。

テストでは、次の user を使います。

30
getProperty(user, "name")
"山田"
getProperty(user, "email")

email は user のプロパティではない

数値には length がない
