# 書き方ガイドの断片を書く担当への指示書

TypeScript の選考の事前課題（STELLA の `devlab-ts-ch00`〜`devlab-ts-ch09` ステージ。発展問題は 01〜09章の最後の単元 `u100-extra`）に、応募者が読む「書き方ガイド」を章ごとの HTML ページで作っている。あなたは、ある章のある番号（q01 など、約 21 問）を担当し、HTML の断片ファイルを 1 つ書いて終わる。ページへの組み込みとハイライトの焼き込みは `npm run build` で行う。公開は claude.ai の Artifact で手作業で行う。

## 触ってよいもの

- 書いてよいのは、担当の断片ファイルと、リポジトリの外に作る自分専用の確認フォルダー `probe-<章>-<番号>`（下記）だけ。
- 担当の断片以外は読むだけ。ほかの断片、`docs/devlab-ts-prework-guide/src/template.html`、`docs/devlab-ts-prework-guide/pages/` は手で直さない。断片を書く作業では Artifact は公開しない。

## 置き場所

- 断片：`docs/devlab-ts-prework-guide/src/fragments/`。以下のパスはリポジトリのルートからの相対パス。
- 課題：`packages/content/stages/devlab-ts-ch<章2桁>/modules/u99-problems/tasks/chapter/`（発展問題は `packages/content/stages/devlab-ts-ch<章2桁>/modules/u100-extra/tasks/extra/`）
  - `README.md`：番号ごとのルールと、教材（サバイバルTypeScript）のリンク
  - `starter/src/<id>.ts`：問題文とスターター（応募者が見るもの）
  - `tests/<id>.test.ts`：テストの値
  - `private/solution/src/<id>.ts`：解答例。**手順をつかむためだけに読む。ページには出さない**
- 初出の確認：既存の断片と `src/template.html` の 01章 q01、課題のスターターとテストを、章・番号・問題の順に読む。
  - 以前の作業用の `first.json` は、このフォルダーには含めない。
  - 必要なら、担当の問題で初めて出る書き方の一覧を、リポジトリの外の確認フォルダーに作る。
  - **自分の担当より前の問題に出たものは、すべて既出**として扱う。前の章も含む。

## まず読む見本

1. `docs/devlab-ts-prework-guide/src/fragments/frag-01-q05.html`：完成した断片の見本。形はこれに合わせる。
2. `docs/devlab-ts-prework-guide/src/template.html`：01章 q01 の部分（`id="q1"` 〜 `id="qa"`）。CSS クラスの一覧も、この `<style>` にあるものがすべて。
3. `docs/devlab-ts-prework-guide/src/fragments/frag-01-q02.html`：スターターに型が書いてない問題の書き方の見本。

## 断片の形（厳守）

- ファイル：`docs/devlab-ts-prework-guide/src/fragments/frag-<章2桁>-<番号>.html`（例：`frag-02-q03.html`。発展問題は `frag-02-extra.html`）
- ファイル全体が `<section class="sec" id="c<章2桁>-<番号>">` … `</section>` の 1 つだけ（例：`id="c02-q03"`）。`<style>`・`<script>`・見本にない CSS クラスは使わない。
- 先頭は `<div class="sec-h"><span class="eyebrow"><章の名前></span><h2><番号> <題></h2><p>…</p></div>`。
  - 章の名前は stage.json の modules の値。例：「02章 オブジェクト・配列・タプル」
  - p は、README のこの番号の説明（ルール）を応募者向けにやさしく言い直したもの。
- 問題ごとに `<section class="q" id="c02-q03-1">` 〜 `-20`、応用は `id="c02-q03-a"`。
  - 見出しは見本と同じ。
  - 応用は `<span class="q-n">応用</span>`、★総合問題は `<span class="q-n">総合</span>`。
  - 応用・総合が複数あるときは `-a`、`-b`… と続け、見出しに「総合 1」のように番号を付ける。
- 発展問題の断片は `id="c02-extra"`、問題は `id="c02-e01"`、見出しは `<span class="q-n">e01</span>`。sec-h の eyebrow は「02章 発展問題（任意）」、h2 は「発展問題」。
- 06章（クラス）のように、ドリルが 1 ファイルで 1 問のものは、その 1 ファイルを 1 つの問題として扱う。
  - id は `c06-q01-1`、見出しは「ドリル」。
  - 1 ファイルの中に小問が複数あれば、`.task` の中で小問ごとに説明し、ヒントも小問ごとに分けてよい。
- 各問題の中身の並びと markup は見本とまったく同じにする。
  1. `.q-h`：題と、「新しく出てくる書き方：…」または「新しい書き方はありません。」
  2. `.task`：次の 3 つを入れる。
     - スターターの関数の形の pre。問題によってはスターターのコード全体。
     - 問題のやさしい説明。
     - 「テストで確かめる値」の `dl.eg`。値は tests/ の実物から写す。型・例外・非同期を確かめるテストは、言葉で書く（例：「◯のとき、エラーを投げる」「Promise が ◯ で解決される」）。
  3. 新しい書き方があれば、`<h3 class="sub">新しい書き方</h3>` と `.item`。
     - `.item` には tok・h4・説明・`.sample` のコードを入れる。
     - 必要なら dl.eg、anat（番号付きの部品図）、cmp（対比）、trace 表、chars 図、SVG 図（.fig、見本のクラスだけ）、memo、more も使う。
  4. `.hints`：ヒント 1 とヒント 2。markup は見本と同じ。
     - ヒント 1「日本語の手順」：説明の p と、関数の中身を日本語コメントだけで書いた骨組みの pre。
     - ヒント 2「コードへの直し方」：p。
- コードは `<pre><code class="language-typescript">` に HTML エスケープして入れる（ハイライトは build で焼き込む）。anat の `.seg` の中は素のテキストだけ（入れ子のタグなし）。幅の狭い区間（`=` や `{` 1 文字など）には `class="seg c"` を使う。

## 内容のルール

- **応募者向け。** 解答例は出さない。
  - 「説明すること」（自分の言葉で説明する課題）の答えも書かない。試し方だけ案内する。
  - バグを直す問題では、`.task` でバグの場所を言わない。場所はヒント 2 に回す。
- **文体**：です・ます調で、1 文は短くする。
  - ダッシュは使わない。
  - 「〜ではなく〜」の飾りや、コロンのあとで明かす書き方はしない。
  - 専門用語は、初めて出たときに一言で説明する。
- **新しく出てくる書き方**：
  - 課題のスターターとテストを正とし、前の問題と既存のガイドを読んで初出を確かめる。細かい項目は、意味のある書き方だけ取り上げてよい。
  - テストが求めていて、つまずきやすい所は、初出の一覧になくても項目にしてよい。足した項目は返事に書く。
  - 既出のものは、「01章 q05 で出た」のように参照してよい。
  - 後の章で詳しく学ぶものは「ここでは、まねて書ければ十分。くわしくは ◯章 ◯」と書く。
- **サンプル**：
  - 問題の答えにならない別の題材にする。在庫、送料、注文、会員、商品、予約などの業務っぽい例を使い、foo/bar は使わない。
  - 各行の上に、その行がすることを日本語のコメントで書き、最後に `// 結果: …` を置く。
  - サンプルに使う構文は、その問題までに出たものと、その項目だけにする。
- **ヒント 1 の骨組み**：
  - サンプルと同じ言い回しで書く。01章の断片の言い回しを辞書として使う。たとえば「◯ を作り、◯ を入れる」(const)、「◯ を入れ直せる変数として作り、◯ を入れる」(let)、「◯ に ◯ を入れ直す」、「◯ を返す」、「もし ◯ なら」、「そうでなければ」、「◯ から 1 つずつ ◯ に取り出してくり返す」、「◯ の間くり返す」、「◯ の後ろに ◯ をつなげる」、「◯ というメッセージのエラーを投げる」、「関数 ◯ を作る。数値の ◯ を受け取り、◯ を返す」。
  - 字下げしたコメントは `{ }` の中の行。
  - 新しい言い回しが要るときは、サンプルのコメントで先に同じ言い回しを使っておく。
  - 型やクラスの宣言そのものが答えの問題は、「◯ という型を作る。◯ は文字列、◯ は数値」のように、宣言を日本語で書く。
- **ヒント 2**：日本語のどの部分がどの書き方になるか、どのサンプルと同じ形かを短く書く。

## 確かめること（終える前に必ず）

1. **確認フォルダーを作る。** 次のコマンドで、自分専用のフォルダーを用意する。`modules/u99-problems/tasks/chapter/starter/` の設定をコピーし、`npm ci` してから使う。ほかの担当の probe には触らない。

   ```bash
   # リポジトリのルートで実行する。モジュール名は担当に合わせる。
   GUIDE_STARTER="$PWD/packages/content/stages/devlab-ts-ch02/modules/u99-problems/tasks/chapter/starter"
   GUIDE_PROBE=$(mktemp -d -t probe-02-q03-XXXXXXXX)
   mkdir -p "$GUIDE_PROBE/src"
   cp "$GUIDE_STARTER"/{package.json,package-lock.json,tsconfig.json,eslint.config.js,.prettierrc.json,.prettierignore} "$GUIDE_PROBE/"
   cd "$GUIDE_PROBE"
   npm ci
   ```

2. **サンプルを通す。** サンプルのコードをすべて取り出して `src/` に置く。名前がぶつかるときは、関数で包むかファイルを分ける。次の 3 つがエラーなしになるまで直す。
   - `npx tsc --noEmit -p tsconfig.json`
   - `npx eslint src`
   - `npx prettier --check src`

   エラーを見せるための例は除くが、その例が本当にエラーになることは確かめる。
3. **値を合わせる。** `// 結果:` の値、dl.eg の値、表の値は node で計算して合わせる（非同期は実際に await して確かめる）。
4. **書いた事実を確かめる。** 「型を直すとエラーになる」「推論される型は ◯」のように書いた事実は、実際に tsc で確かめる。
5. **形を確かめる。** 断片が well-formed かを見る。section・div・details・article・pre・code・figure・table・dl・ol・ul の開閉の数が合っていること。

## 返事（短く。断片の中身は貼らない）

- 書いた問題の数と id の範囲
- 新しい書き方の項目の数（初出の一覧にない項目を足したなら、その名前）
- 確認の結果
- 迷った点（ヒントが答えそのものになる問題、初出の扱い、見本に合わない形にした所など）
