# 画面連動ヘルプドロワー + 空状態ガイダンス 設計

日付: 2026-08-20
対象: 受講者（学習者）ロールのみ

## 背景 / 目的

アプリの使い方を、必要なユーザーが必要な画面で参照できるようにする。
ローディングがほとんど発生しないため「待機中 Tips」は使えず、独立したドキュメント
ページは読まれにくい。そこで「現在の画面に応じたヘルプを、能動的に開いたときだけ
表示する」方式を採る。

- 完全オンデマンド。自動表示・初回誘導・既読管理（localStorage）は行わない。
- 対象は受講者向け画面のみ。講師・管理者画面にはヘルプを定義しない
  （フォールバックの汎用ヘルプが出るだけ）。

## 構成

### 1. HelpDrawer（メイン）

- Topbar の既存ヘルプボタン（`HelpCircle`、現在は `/support` を別タブで開くリンク。
  `apps/web/src/components/shell/Topbar.tsx`）を、`HelpDrawer` の開閉ボタンに変更する。
- ドロワーは既存の `apps/web/src/components/ui/drawer.tsx` を `direction="right"` で使う
  （追加依存なし）。
- 開いたとき、TanStack Router で現在のパスを取得し、対応するヘルプコンテンツを
  表示する。
- `/` や `/courses` はロールで描画内容が変わる共有ルートのため、ロール
  （Topbar が props で受けている `Role`）が `learner` 以外のときはパスに
  関わらず汎用ヘルプを表示する（ヘルプ定義は受講者向け文言のみのため）。

### 2. ヘルプコンテンツ定義

- `apps/web/src/components/shell/helpContent.tsx` に静的定義としてまとめる。

```ts
interface HelpTopic {
  /** TanStack Router のルートパスパターン（例: "/courses/$courseId"） */
  route: string;
  title: string;
  sections: { heading: string; body: ReactNode }[];
}
```

- マッチングは「定義済みパターンのうち現在のパスに一致するもの」。動的セグメント
  （`$courseId` など）は任意の 1 セグメントとして扱う。一致が無ければ汎用ヘルプ
  （アプリ全体の概要 + 主要画面への案内）にフォールバックする。
- ドロワー末尾には常に「解決しない場合はサポートページへ」リンク（`/support`、別タブ）を置く。

### 3. 対象画面（初期セット）

| ルート | 主な説明内容 |
|---|---|
| `/` | ダッシュボードの見方（今日の進捗 KPI、続きから学習） |
| `/courses` | コース一覧・受講開始の流れ |
| `/courses/$courseId` | コース詳細・レッスンの進め方・進捗の見方 |
| `/courses/$courseId/lessons/$lessonId` | 動画 / ドキュメント / クイズの操作、「VS Code で開く」（コード演習）の流れ |
| `/submissions/$submissionId` | 提出物とレビューの見方 |
| `/certificates` | 修了証の発行条件・検証リンク |
| `/settings` | プロフィール・テーマなど設定項目 |

上記以外（講師・管理者画面含む）はフォールバック表示。

### 4. 空状態ガイダンス（サブ）

- 新規コンポーネントは作らない。受講者画面の既存 empty state の文言を
  「次にやること + 遷移ボタン」に強化するだけ。
- 対象: ダッシュボード（受講コースなし）、修了証一覧（修了なし）など、
  受講者画面に既に存在する空状態のみ。実装時に現物を確認して文言を当てる。

## やらないこと（YAGNI）

- スポットライトツアー / coach marks
- 既読管理・初回自動表示（localStorage 不使用）
- ヘルプ内容の D1 / CMS 管理（コード内定数で十分。非エンジニアが頻繁に編集する
  必要が出たら移行を検討）
- ヘルプ内検索（既存の ⌘K 検索があるため不要）
- 講師・管理者向けヘルプコンテンツ

## エラーハンドリング

- 静的定義のみでネットワーク・非同期処理が無いため、失敗モードは
  「定義が見つからない」だけ。これはフォールバック表示で吸収する。

## テスト

- ルート実在の保証: `route` フィールドを `routeTree.gen.ts` の
  `FileRouteTypes["to"]` 型に制約する。ルート改名は `bun run typecheck`（CI 済み）
  が検出するため、実在チェックの実行時テストは書かない。
- Vitest 1 本: `findHelpTopic` のマッチングロジック（完全一致・動的セグメント・
  末尾スラッシュ・フォールバック null・全トピック到達可能）を検証する。
- ドロワーの開閉・表示内容は手動確認（`bun run dev` で各画面の「?」を開いて確認）。
