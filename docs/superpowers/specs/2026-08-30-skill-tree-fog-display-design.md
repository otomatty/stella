# スキルツリーの霧 (未解放カリキュラムの見せ方) の仕様

- Issue: #271 (本番で霧の星の名前がぼかされない) / #272 (霧の星の名前の開示範囲)
- 前提の設計: `2026-08-30-skill-tree-parent-edge-design.md` (線 = `parent` 1 本)
- 対象: `packages/shared/src/skill-map/evaluate.ts` / `apps/api/src/routes/skill-map.ts` /
  `apps/web/src/components/learner/tree/*`

## 何を決めたか

スキルツリーは「いま手が届く星」からの距離で見せ方を段に分ける。段は 4 つで、
**距離が 1 増えるごとに 1 段ぶん情報が減る**。

| 距離 | 視界 (`SkillMapVisibility`) | 星 | 名前 | 解放条件 | 到達説明 | 線 |
|---|---|---|---|---|---|---|
| 0〜1 | `full` | 描く | 出す | ロック星だけ出す | 解放済みだけ出す | 実線 |
| 2 | `fog` | 描く (薄い) | **ぼかす** | 出さない | 出さない | 実線 |
| 3 | `edge` | **描かない** | — | — | — | **外へ向かって薄くなる線だけ** |
| 4 以上 | `hidden` | 応答に載せない | — | — | — | — |

距離の起点は `cleared ∪ active ∪ unlocked`、辺は**親 1 本**の無向グラフ
(線が引かれていない前提は視界に数えない)。距離 1 以上の星は定義上すべて `locked`
なので、段と状態は独立に読める。

### 変更前との差分

| | 変更前 | 変更後 |
|---|---|---|
| 距離 1 | `full` | `full` (据え置き) |
| 距離 2 | `name-only` — 名前と**解放条件**を出す | `fog` — 名前をぼかすだけ |
| 距離 3 以上 | `fog` — 名前をぼかして全部出す | 距離 3 = `edge` (線だけ) / 4 以上 = 応答に載せない |
| 腕試し (飛び級) | `full` / `name-only` の星 | `full` の星だけ |

`name-only` は廃止した。「ぼかした名前」と「解放条件つきの名前」の 2 段が隣り合うと、
受講者からは *どこまでが「もう調べてよい先」なのか* が読めない。段の意味を
「**中身が読める → 名前だけ滲む → 道があることだけ分かる → 何も無い**」の 1 本にする。

## なぜこの形か

### 解放条件を見せるのは 1 次まで

解放条件 (`lock_reasons`) は「この星を開けるために次に何をクリアするか」の案内で、
**いま行動できる相手にしか意味がない**。2 歩先の星の解放条件は「1 歩先の星をクリアせよ」
としか書けず、1 歩先の星の存在を 2 通りの経路で伝えているだけになる。

秘匿の面でも、2 歩先まで解放条件を出すと、そこに並ぶ前提の名前から**さらに先の星の
名前が読めてしまう**面が増える (API が `maskedLockReasons` で霧の前提をテーマ名へ
伏せているのはこのため)。段を 1 次で切ると、**線 (親) を辿って出てくる前提**は必ず
距離 0〜1 の星 = 既に名前が見えている星になる。

ただし**伏せ字そのものは無くならない**。解放は `prerequisites` 全部の AND なので、
線に使わない 2 本目以降の前提は視界の外にあり得る (Git の解放条件には JS と Node の
両方が並ぶが、線は片方だけ)。`maskedLockReasons` は距離 1 に絞ったあとも必要で、
「`full` でない前提はテーマ名 / 伏せ字へ落とす」規則として残す。

### 霧は 2 次だけ

霧 = 「そこに何かがある。名前は滲んでいて読めない」という**予告**。予告が効くのは、
手前の星をひとつ片づければ読めるようになる距離 = 2 次まで。それより先まで霧にすると、
盤面の大半が「読めない名前の星」で埋まり、予告ではなく壁になる。

霧の星の名前 (`title`) は API がそのまま返し、画面が CSS でぼかす。**ぼかしは演出であって
秘匿ではない** (#272 の論点 1 の判断) — 公開済みの講座名は隠すべき情報ではなく、隠したい
名前の教材はそもそも公開しない、が線引き。そのうえで、霧の星から**行動できる情報**
(slug・アイコン・受講登録の有無・解放条件・到達説明) は返さない。開始・腕試し・
フォーカス切り替えも `full` 以外は断る。

ぼかしが演出である以上、**読み上げに実名を流さない**のは a11y の一貫性のため
(#272 の論点 2)。見た目が読めない相手にだけ実名が届くのは、演出としても情報設計としても
ちぐはぐなので、`aria-label` は「まだ見えないスキル」に差し替える。

### 3 次は線だけ

3 次に星を描くと「読めない星」が増えるだけで、2 次の霧と区別がつかない。一方で
**そこで道が途切れて見える**のも嘘になる (実際には続きがある)。そこで星を描かず、
2 次の星から伸びる線だけを残し、**外へ向かって徐々に透明にする**。

- 「まだ道は続く」= 線がある
- 「その先は今の自分には関係ない」= 名前も星も無い
- 「どこまで続くかは分からない」= 端が消えていく

線の終点は、その星が置かれるはずだった座標 (レイアウトは 3 次の星を**幽霊ノード**として
配置し、描画だけ省く)。座標を捨てて線の長さを決め打ちにすると、扇の広がりと線の向きが
合わなくなる。幽霊ノードには扇 (`category`) だけ載せる — どの扇のどの島に置くかが
決まらないと、線がまったく違う方向へ伸びるため。

**幽霊の線は、描かれる星 (1〜2 次) にしか繋がない。** 幽霊どうしを結ぶと、どちらの端にも
星の無い線が宙に浮く。複製 (`appearances`) では実際に起きる — Git はフロントエンド扇では
JS (霧) の次だが、バックエンド扇では Node (幽霊) の次なので、その扇の線は「見えない星から
見えない星へ」になる。**線を張れない扇は `appearances` から落とし**、どの扇にも張れない
なら複製そのものを止める (星は自分の `category` の扇に 1 つだけ)。落とした結果、線が
1 本も引けなくなった幽霊は**応答からも落とす** — 星も線も描かないのに、盤面では扇の角度
だけ取って空白の楔を残すため。

### 4 次以上は応答に載せない

線も星も出ないものを応答に載せる理由がない。id を返すだけでも「この先に星が n 個ある」
という情報になるので、**API の配列から落とす** (`hidden`)。これで DevTools / `curl` からも
遠い星は見えなくなり、視界制限が演出でなくなる。

盤面のヘッダーに出す「修了 x / y」の分母は、応答の星数ではなく新設の `stage_count`
(そのテナントで配信対象の全ステージ数) を使う。分母が進捗につれて増えると、
「全体のどこまで来たか」が読めなくなるため。

**脅威モデルの例外として明記する**: `stage_count - stages.length` から「まだ見えない星が
何個あるか」は正確に読める。これは進捗表示のために**意図して許容する集約開示**で、
伏せているのは *どの星が* あるか — id・名前・カテゴリ・トポロジ・受講登録 — の方。
全ステージ数はもともと講座一覧やカタログから分かる値でもある。

## 段を増やしたことを知らない画面へは幽霊を配らない

`visibility` に `edge` / `hidden` を足したのは **wire の後方非互換な変更**。それを知らない
画面は `fog` 以外を普通の星として描く (旧 `describeStar()` は `visibility === "fog"` の
ときだけ操作を隠す) ので、線だけのはずの幽霊ノードが「？？？」のロック星になり、押すと
必ず 400 になる腕試しボタンまで出る。

デプロイは `deploy:api` → `deploy:web` の順で、しかも**開いたままのタブは古い bundle の
まま**なので「新 API + 旧画面」は必ず起きる。そこで画面が段の版を申告する
(`GET /api/skill-map/mine?tiers=2`)。**申告の無いクライアントには `edge` を配らない** —
旧画面は今までどおり名前のある星 (`full` / `fog`) だけを描き、失敗する導線も出ない。

逆向き (新しい画面 + 旧 API の `name-only`) は安全側に倒れる。新しい画面は `full` 以外を
まとめて「ぼかす・操作を出さない」と扱うので、見える情報が減るだけで壊れない。

**申告はヘッダではなくクエリ引数で行う。** 独自ヘッダはサーバの CORS 許可リスト
(`index.ts` の `allowHeaders`) に載っていないとプリフライトで弾かれ、その API 呼び出しが
丸ごと失敗する。API をロールバックして「新しい画面 + 古い API」になった瞬間、古い API は
そのヘッダを知らないので、意図した緩やかな縮退どころか**全ての API 呼び出しが落ちる**。
クエリ引数なら CORS の対象外で、知らないサーバは黙って無視する。
(この PR でも、ヘッダ版を作ったところ CORS 許可リストの追加を忘れて全 API が落ちた。
`apps/api/src/lib/cors-headers.test.ts` はその再発を止めるためのもの。)

画面が全部入れ替わったら、この引数ごと落としてよい (移行用の足場)。

## 開発者モード (`DEV_MODE`)

`DEV_MODE=1` のサーバに、FAB でオンにしたクライアントからだけ、**全部の段を素通し**で
返す (`edge` / `hidden` も名前つきで載せる)。画面はぼかさず、幽霊ノードも普通の星として
描く。解放条件は変わらない — 見えるだけで、開始も腕試しもサーバが断る。

### 既定はオフ (#271 の修正)

`revealDev` は **ローカルの設定 AND サーバが確認した開発モード** (`skill_map.dev_mode`)
から導く。サーバの応答が来るまでは false = ぼかす側に倒す。あわせて localStorage
未保存時の既定も false にした (`parseDevModeStored(null)`)。

変更前は localStorage 未保存 = オンだったため、**本番の新規セッションで霧の星の実名が
ぼかされずに出ていた** (FAB は `dev_mode_available` が false で出ないので、受講者に
戻す手段もない)。ローカルの既定を直すだけだと「クライアントの値だけでぼかしが外れる」
形はそのまま残るので、サーバ確認との AND を本線にし、既定はその保険として直す。

## 意図的に変えないこと

- **線と解放条件は別物**のまま (`parent` 1 本 / 前提は AND)。霧の段は視界だけを決める
- 島の表示条件 (`@falcon/shared/skill-map/islands`) は視界より手前のフィルタ。
  条件を満たさない島は距離を測る前に応答から落ちる
- 発見教材 (`discoveries`) の公開条件 (源流が `active` / `cleared`) は据え置き
