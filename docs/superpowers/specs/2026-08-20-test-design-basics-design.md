# テスト設計と品質保証 入門 — 設計書

新講座 `test-design-basics` のカリキュラム設計。`packages/content/THEME_TO_COURSE.md` の STEP 0〜3 に相当する。
本書の承認後、STEP 4(`CURRICULUM.md` の takeaway 一覧)を実装計画として作成する。

## 狙い

どんな現場でもテストを設計→実装でき、「何をどのレベルで自動化するか」を提案できる人材を育てる。
資格対策講座ではないが、網羅性と用語の基準として JSTQB Foundation Level シラバス
(Version 2023V4.0.J02、一次情報で確認済み)を使い、受講後に FL 受験も狙える状態を副産物として残す。

既存講座との住み分け: 「Python テスト自動化と CI 入門」(`python-testing-ci-basics`)が pytest の
**書き方**を教えるのに対し、本講座は**何をテストすべきかの設計**を教える。

- M3 では技法ごとのレッスン末尾に「設計したケースを pytest のパラメタライズドテストに落とす」トピックを
  置き、設計→実装を毎回接続する(`pytest.mark.parametrize` はここで本講座の語彙として導入)
- スライド・ハンズオンのコード例は Python に統一する
- M6 の題材は Python の小さな仮想案件(例: 料金計算関数 + 会員登録バリデーション)。
  capstone が到達目標③を直接測る成果物になる

## 評価とハンズオンの形

- 各レッスン: スライド → まとめ(doc.md) → 確認クイズ(practice.md、選択式 3〜5 問、合格 80)
- ハンズオンは 2 段構え(practice.md の「手元で試す」方式、自動採点なし):
  1. 仕様からテストケース表を書く(全技法レッスン)
  2. 書いたケース表を手元の Python + pytest でテストコードにする
- 模擬試験モジュールは置かない(実務講座のため)。M6 capstone が総合評価を担う

## 実装時の決め事(ADDING_COURSE.md / THEME_TO_COURSE.md 準拠)

- slug `test-design-basics` は確定後変更しない(コース UUID・進捗が切れる)
- `course.json` に `exercises` を書かない(コード演習なし)
- サムネイルは `scripts/build_thumbnails.py` の SPECS に 1 件追加して生成(手描き・外部ロゴ禁止)
- クイズは雛形(`### Q1.` / `- A.` / `<details>` / `**B** — 解説`)から丸ごとコピーし、
  seed 後に LMS 上で全レッスンにクイズが出ることを目視確認(0 問レッスンは黙って素通りするため)
- 図解は `.claude/skills/diagram-design/` 準拠。技法モジュール(M3〜M4)は表・遷移図が主役なので
  図解の優先度が高い
- STEP 4(CURRICULUM.md の takeaway 一覧)のレビューを通すまで本文(slides.md)を書かない
