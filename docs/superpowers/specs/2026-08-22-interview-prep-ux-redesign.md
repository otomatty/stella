## 目的

面談対策機能のユーザーフローを再設計する。現状は「175問の質問バンクを絞り込んで読む/ランダムに引く」という**参照ツール**であり、受講者が「面談当日までに準備を完了させる」ための**フロー**になっていない。本提案は、機能の組織単位を「質問バンク」から「受講者の次の面談(イベント)」へ移し、準備を 3 ステップのフローとして設計し直す。

## 現状のフローと課題

### 現状

- 受講者: `/interview-prep` に「一覧」(優先度・カテゴリ・検索で絞り込み + アコーディオン)と「ランダム出題」(タイマー付きフラッシュカード)の 2 タブ。初期表示は優先度 A。
- 講師: 割当画面で受講者ごとに案件種別チップをトグルするのみ。

### 課題

1. **ゴールと「終わり」が見えない。** 割当後の初期表示でも A 必修が約 40 問並ぶが、「どこまでやれば準備完了か」を示すものがない。フィルタは状態であってフローではなく、受講者は毎回「今日は何をやるか」を自分で決める必要がある。
2. **進捗が残らない。** アコーディオンの開閉もランダム出題の位置もリロードで消える。「できた/まだ」の記録がなく、ランダム出題は毎回全プールから引き直すため、同じ得意問題が繰り返し出て、苦手が放置される。
3. **面談という実イベントに紐付いていない。** 面談準備は本来締切駆動の活動だが、機能は無期限のブラウズになっている。面談日を知っているのは講師と営業だけで、システムは知らない。
4. **「自分の回答」を書く場所がない。** 回答の型は穴埋め表示だが読むだけで、穴に入れた自分の経験を保存できない。作った回答が残らないので、講師の添削にも AI のフィードバックにもつながらない。
5. **講師は割当したら終わり。** 割当画面から受講者の準備状況が一切見えず、「この受講者を面談に出せる状態か」を判断する材料がない(現状は口頭確認頼み)。
6. **練習が独白で終わる。** データには深掘り①〜③・NG 回答・評価軸まで揃っているのに、使い方は「自分で開いて読む」のみ。面談本番の形式である「対話」の練習に接続していない。

## 再設計の方針

| 転換 | Before | After |
|---|---|---|
| 組織単位 | 質問バンク(175 問) | 受講者の次の面談(日付を持つイベント) |
| 受講者の行動 | 絞り込んで読む | ①型を知る → ②自分の回答を作る → ③声に出して練習する |
| 進捗 | なし(毎回ゼロ) | 質問ごとのステータス → 準備率として可視化 |
| 出題 | 全プールからランダム | 「今日の練習セット」(要練習を優先。デイリー復習の SM-2 実装を流用) |
| 練習形式 | 質問文を黙読して独り言 | **面接官との音声のやり取り**(質問も深掘りも音声で流れ、録音で答える対話ログ UI。テキストは振り返り用) |
| 回答の記録 | なし(読むだけ) | **受講者専用の「回答の型」**(スキルシートから AI 生成・全ロール編集可・自由記述) + **改善点メモ**(振り返りで書き、次回の練習直前に再表示) + 録音・文字起こしの練習ログ |
| 講師の役割 | 割当のみ | 割当 + 準備状況モニタ + 回答添削 |
| 営業の役割(新ロール) | なし | 面談日の登録 + スキルシート登録 + 割当 + 準備状況の閲覧(面談対策まわりに限定) |

実装は既存インフラの流用を最優先する: 進捗の間隔反復はデイリー復習(SRS)の SM-2、添削は submissions + `/api/review-draft`、通知は notifications、AI 模擬面談は `/api/chat`(SSE) の `ChatContext` union 拡張(初期設計書で拡張点として確保済み)。音声まわりもスタック内で完結させる: 質問読み上げは Grok TTS (AI Gateway Unified Billing) を **admin が事前生成して R2 に登録**する方式(同じ質問文を受講者のリクエストごとに合成するとコストが線形に増えるため。受講者向け配信は R2 読み出しのみで AI を呼ばない)、録音は MediaRecorder → 文字起こしは Workers AI の Whisper(`@cf/openai/whisper-large-v3-turbo`、日本語対応)。

> **実装メモ (2026-08-22 実装済み)**: TTS・文字起こしは Workers AI の **REST API** で呼ぶ(`apps/api/src/lib/workers-ai.ts`)。`[ai]` バインディングは `wrangler dev` が非対話環境(CI / クラウド開発)で Cloudflare 認証を要求して起動に失敗するため使わない。設定は `CLOUDFLARE_ACCOUNT_ID`(wrangler.toml [vars])+ `AI_GATEWAY_ID` / `AI_GATEWAY_CF_API_TOKEN`(既定の Grok TTS は Gateway 必須)。Workers AI 自前モデル(Whisper など)は `WORKERS_AI_API_TOKEN` での直叩きにもフォールバックする。未設定でも API は起動し、音声エンドポイントのみ 503。

## 提案ユーザーフロー

### 受講者

質問ごとに 4 状態のステータスを持つ: `未着手 → 型を読んだ → 回答作成済み → 練習OK`。準備率 = 割当範囲の A 問題のうち `練習OK` の割合。

**Flow 0 — 着手(オンボーディング)**
講師が割当 + 面談日を保存 → 受講者に通知 → 面談対策を開くと「あなたの面談: 9/10 ・ PHP/Laravel 案件 ・ 必修 38 問中 0 問 準備済み」のヘッダー → CTA「準備を始める」。以後ダッシュボードにも同カード(カウントダウン + 準備率)を常設する。

**Flow 1 — 作る(受講者専用の「回答の型」)** *(改訂: マイ回答メモは廃止し個別の型に統合)*
一覧をチェックリスト化する(優先度 A が先頭、ステータスバッジ付き)。質問を開く → 意図と**自分専用の回答の型**を読む。個別の型はスキルシート登録時に AI が自動生成(割当 A 必修のみ。詳細は issue ドラフト参照)し、**自由記述テキストとして全ロール(本人・講師・営業・管理者)が編集できる**。直したい受講者はここを直接編集 → ステータスが「回答作成済み」へ。個別の型がそのまま練習の見比べ・添削・模擬面談の入力になる。個別の型が無い質問は共通の型をプレーン表示(穴埋め装飾は廃止)。

**Flow 2 — 練習する(音声セッション = メイン体験)**
練習は**面接官との音声のやり取り**を主役にする。画面は読む UI ではなく対話ログ(音声メッセージのスレッド)で、テキストは補助・振り返り用に格下げする。「セッションを始める」→ 10 問のセット(要練習・未練習を優先、`練習OK` は低頻度で再出題 = SM-2 流用)。1 問のやり取り:

1. **聞く** — 面接官バブルとして質問音声が自動再生(admin が TTS で事前生成。深掘り①〜③も同様に事前生成)。**質問文は既定で非表示**(「質問文を表示」トグルで開ける)。答える直前に、**前回の改善点メモが 1 行で表示**される。
2. **答える** — 大きな録音ボタンで録音(MediaRecorder) + 経過タイマー(目安時間超過で色)。停止すると自分のバブルに録音 + 文字起こし(Whisper)が積まれ、**深掘りが音声で続く**。パス(スキップ)可。
3. **振り返る(改善点メモ)** — 質問のやり取りを終えるごとに振り返り画面: 自分の回答(録音 + 文字起こし)と回答の型・NG・評価軸を並べ、**気づいた改善点をメモ**する(「結論から先に」などの定型チップ + 自由入力)。メモは質問に紐付いて溜まり、次回この質問に答える直前に再表示される(= 改善ループ)。
4. **自己評価** — 「できた / もう一度」の 2 ボタン → 次の質問へ。録音と文字起こしは質問に紐付く練習ログとして残る(最新 n 件)。

マイクを使えない環境(電車内など)向けに、録音をスキップして回答例を読むだけの**サイレントモード**を残す。「全問からランダム」も現行どおりサブ導線として残す。音声部品(読み上げ再生・録音 → 文字起こし)・**対話ログ UI・改善点メモ・自己評価**は**実装済み**(Issue #234)。練習ログ(録音そのもの)の永続化は Phase 2。深掘り①〜③の音声も質問文と同じ事前生成の仕組みに載せた(R2 キーは `interview-tts/<no>-deep1.mp3`)。

**Flow 3 — 添削を受ける(Phase 2)**
個別「回答の型」(+ 必要なら練習の文字起こし)を「添削依頼」で提出 → 講師キューへ → AI 下書き(`/api/review-draft`) → 講師が編集して返却 → 受講者に通知 → 修正して再保存。既存の課題添削と同じ心的モデル。文字起こしが付くことで「書けるのに話すと崩れる」箇所も添削対象になる。

**Flow 4 — AI 模擬面談(Phase 3)**
セット内または質問単位で「模擬面談」→ AI が質問を TTS で読み上げ → 受講者が**録音で回答 → 文字起こしがそのまま AI への入力になる**(テキスト入力もフォールバックとして可) → AI が `deep1〜3` に沿って深掘りを読み上げ → `ng`(避けたい回答)と `criteria`(評価軸)に基づくフィードバック → ログ保存(講師も閲覧可)。`ChatContext` に `{ kind: "interview", questionNo, myAnswer?, transcript? }` を追加するだけで既存のレート制限・認証・SSE に載り、音声は Flow 2 で作る録音・文字起こしの部品をそのまま使う。

**Flow 5 — 直前チェック**
面談 3 日前に通知 → 「直前モード」: `もう一度` が付いた A 問題だけの最終セット + 逆質問(聞く質問)の最終確認リスト。

### 講師

**Flow A — 割当** *(改訂: 面談日の write は営業・管理者のみ)*
受講者を選ぶ → 案件票どおり案件種別を選ぶ(講師・営業・管理者) → **面談予定日(任意) + メモは営業または管理者が追加**(講師は閲覧のみ) → 保存 → 受講者へ通知。

**Flow B — モニタリング** *(実装済み 2026-08-25 / Issue #236)*
割当一覧に「準備率 / 最終練習日 / 面談日」列を追加し、面談日が近い順に並べる → 行を開くと詳細(質問ごとのステータス、マイ回答メモ、練習の録音と文字起こし、模擬面談ログ) → 添削依頼が来ていればその場でレビュー(Flow 3 の講師側)。録音を聞けることで「話し方」まで含めて「面談に出せるか」を画面で判断できるようにする。

> **実装メモ (2026-08-25 / Issue #236)**: 面談対策画面のタブを「**モニタリング** / 割当 / 質問音声(admin)」にし、モニタリングを既定にした。一覧は受講者 / 面談日 (+ カウントダウン) / 案件・割当 / 準備率バー / 最終練習日で、面談日の昇順 (未設定は表示名順で末尾)。上部に「面談予定 n 件(今月) / 練習なし n 件 / 要フォロー n 件」のチップを出し、**面談まで 7 日以内で準備率 60% 未満**の行を `要フォロー` (14 日以内で 80% 未満は `気になる`) として色で立てる。判定・並び順・日付表示は `@falcon/shared/interview/monitoring` の純ロジックで、API と web が共有する。集計は `GET /api/interview-prep/assignments` が同梱し (`prepRate` / `prepTotal` / `breakdown` / `lastPracticedAt`)、質問・進捗・個別の型をテナント単位で 1 回ずつ読んで JS 側で割り当てる (N+1 を作らない — 準備率の分母は受講者ごとの割当で変わるので SQL の GROUP BY では出せない)。行クリックで開く詳細ドロワーは質問ごとのステータスピル・個別回答の型 (#206)・改善点メモ (#234) を並べ、スキルシート (#233) はここにタブとして移した (割当タブの列は廃止)。練習の録音そのものは Phase 2 (永続化が未実装) のため未対応。

**Flow C — 面談後の記録(Phase 4・任意)**
結果(通過/見送り)と現場からのフィードバックをメモ → 次の割当時に参照。質問バンク改善の入力にもなる。

**Flow D — 質問音声の管理(admin・実装済み)**
面談対策画面の「質問音声」タブ(admin のみ)で、質問ごとに読み上げ音声を生成 / 再生成 / 試聴する。「未登録をまとめて生成」で全問を 10 問ずつ直列生成。生成は監査ログ(`interview_tts_generate`)に残る。受講者への配信は R2 から読むだけで、生成コストは admin の操作回数に固定される。

```
interview_prep_assignments   -- 既存テーブルに追加
  + interview_date TEXT NULL    -- 面談予定日 (YYYY-MM-DD)
  + note TEXT NULL              -- 講師メモ(案件名など)

interview_progress           -- 新規
  id TEXT PK
  tenant_id TEXT
  profile_id TEXT
  question_no INTEGER          -- interview_questions.no
  status TEXT                  -- 'read' | 'drafted' | 'confident'(未着手は行なし)

  UNIQUE(tenant_id, profile_id, question_no)

interview_practice_sets      -- 実装済み (Issue #235)。「今日の練習セット」

  -- 進行中は受講者ごとに 1 つだけ (status='active' の部分ユニーク索引)

interview_fix_notes          -- 実装済み (Issue #234)。改善点メモ (振り返りで受講者が書く)
  id TEXT PK
  tenant_id TEXT
  profile_id TEXT
  question_no INTEGER
  text TEXT                    -- 「結論から先に言い切る」など。定型チップも自由入力も同じ行
  created_at TEXT
  resolved_at TEXT NULL        -- 克服したらチェックで消し込み (任意)
  -- 次回その質問に答える直前に未解決分を表示する

interview_recordings         -- 新規(Phase 2)。練習の録音 + 文字起こしログ
  id TEXT PK
  tenant_id TEXT
  profile_id TEXT
  question_no INTEGER
  r2_key TEXT                  -- 録音本体は R2(教材と同じバケット運用)
  duration_sec INTEGER
  transcript TEXT NULL         -- Workers AI Whisper の結果(非同期で埋まる)
  created_at TEXT
  -- 質問ごとに最新 n 件だけ保持(古いものは R2 ごと削除)
```

添削(Phase 2)は既存 submissions パターン、模擬面談ログ(Phase 3)は既存チャット履歴の方式に合わせる。質問読み上げ音声は D1 ではなく R2 (`interview-tts/<no>.mp3`、深掘りは `interview-tts/<no>-deep1.mp3`) が正本で、質問一覧 API が登録済み番号 (`audioNos`) とセグメント (`audioSegments` = `<no>:question` / `<no>:deep1`) を同梱する(実装済み)。

## API(スケッチ)

実装済み(2026-08-22):

> **更新 (一問一答化)**: 深掘り①〜③の読み上げ・出題は廃止した。受講者の回答に応答しない固定の追い質問は面談の再現になっておらず、`deep1`〜`deep3` はデータごと落としてある。以下の API のうち音声セグメント (`audioSegments` / `<no>:deep1` / `?part=`) に関する記述は現行ではない — 音声は 1 質問 1 本 (`audioNos` / `audioStaleNos`、R2 キー `interview-tts/<tenant>/<no>.mp3`) で、生成 API の body は `{ nos: number[] }` のみ。

- `GET /api/interview-prep/questions` — レスポンスに `audioNos`(音声登録済み質問番号)/ `audioSegments`(深掘りを含むセグメント)/ progress (SM-2 の `srs_due_date` / `last_result` を含む)/ 改善点メモ (`fix_notes`)/ 中断中のセット (`activeSet`) を同梱。
- `GET /api/interview-prep/questions/:no/audio?part=` — 登録済み読み上げ音声(MP3)の配信。`part` は `question`(既定)/ `deep1`〜`deep3`。AI は呼ばない。未登録 404 / 割当範囲外 403。
- `POST /api/interview-prep/audio/generate` — admin 専用。`{ nos: number[] }`(質問文のみ)/ `{ segments: [{ no, part }] }`(深掘り込み)を合計 10 件まで TTS モデル(既定 Grok TTS)で生成し R2 へ登録(再生成は上書き)。監査ログあり。
- `PUT /api/interview-prep/progress/:no` — `{ event: "read" | "practiced" | "confident", setId? }`。自己評価と「型を読んだ」の記録。 `practiced` / `confident` は SM-2 を進め(誤答 / 正解)、 `setId` があればセットの消化としても記録する (Issue #235)。
- `POST /api/interview-prep/fix-notes/:no` ・ `PUT /api/interview-prep/fix-notes/:id` — 改善点メモの追加・消し込み(受講者本人のみ)。
- `POST /api/interview-prep/transcribe?no=` — 録音バイナリを Whisper で文字起こし。`no` があれば質問文を `initial_prompt` に渡す(可視性検査を兼ねる)。上限 8MB。

- `GET /api/interview-prep/practice-set` — 今日のセット 10 問(SM-2 選定)。 進行中のセットがあればそれを返す(= 中断からの再開)。 レスポンスは `{ set, resumed, rows, prepPercent }` で、 `rows` は出題順の質問(個別の型・進捗・改善点メモ込み)。 実装済み (Issue #235)。
- `PUT /api/interview-prep/practice-set/:id` — `{ status: "done" }` でセットを終了し、 終了サマリ(できた n/10・準備率の伸び)を返す。 実装済み (Issue #235)。
- `GET /api/interview-prep/assignments` — 受講者ごとの準備率 (`prepRate` / `prepTotal` / 4 状態の `breakdown`) と最終練習日 (`lastPracticedAt`) を同梱(モニタリング一覧用)。 実装済み (Issue #236)。

今後(Phase 1〜):

- `POST /api/interview-prep/recordings/:no` — 録音を R2 に永続化して練習ログにする(現状の transcribe は保存しない)。
- `GET /api/interview-prep/recordings/:no` — その質問の練習ログ(録音 URL + 文字起こし)。講師詳細も同じ形を使う。
- `PUT /api/interview-prep/assignments/:profileId` — body に `interviewDate` / `note` を追加。

## 決めたいこと(レビュー観点)

1. **面談日を LMS が正とするか** — 営業/人事側の管理と二重になる。まずは講師の手入力(参考情報)で始めるのが安全。
2. **自己評価の粒度** — 2 択(できた/もう一度)を提案。SM-2 の 4 段階に合わせるかは デイリー復習の実装に従う。
3. ~~**マイ回答メモの対象範囲**~~ — **解消**: マイ回答メモは廃止。個別「回答の型」の生成範囲は割当カテゴリの A 必修と決定(issue ドラフト参照)。
4. ~~**TTS のモデル選定**~~ — **決定・実装済み: Grok TTS (xAI) を AI Gateway の Unified Billing で呼ぶ**。経路は admin が事前生成し R2 に登録、受講者への配信は R2 のみ(REST を使う理由は上の実装メモ参照)。

   > **なぜ Workers AI 自前モデルではないか**: Workers AI の TTS に日本語で使えるものが無い。`@cf/myshell-ai/melotts` は非英語で `8002 Invalid input`、CJK は音声が返っても意味不明([cloudflare/cloudflare-docs#23308](https://github.com/cloudflare/cloudflare-docs/issues/23308) とコミュニティ報告)。`@cf/deepgram/aura-1` は英語話者のみ、`aura-2-en` / `aura-2-es` はモデル ID のとおり英語 / スペイン語専用。
   >
   > **Grok TTS を選んだ理由**: 日本語を含む 20 言語対応、声は eve / ara / rex / sal / leo の 5 種。AI Gateway の Unified Billing で呼べるので xAI 側の API キーは不要で、チャット / 添削の Grok(Issue #204)と請求もログも同じ経路に乗る。$4.20 / 1M 文字 = 全 175 問を 1 度生成しても $0.04 程度(生成は 1 回きりで以降は R2 読み出し)。
   >
   > 差し替えはコード変更不要 — `INTERVIEW_TTS_MODEL` / `INTERVIEW_TTS_VOICE` / `INTERVIEW_TTS_LANG` を env で指定し、入力スキーマは `buildTtsInput()` がモデルごとに組み立てる。Unified Billing のモデルは Gateway 未構成だと 503 で明示的に落ちる(直叩き REST には存在しないため)。admin 画面には未登録時に 1 問試聴を促す警告を出している。
5. ~~**文字起こしの方式**~~ — **決定・実装済み**: Workers AI Whisper large-v3-turbo のバッチ方式(全ブラウザ対応、停止後数秒待ち)。リアルタイム字幕(Web Speech API `SpeechRecognition`)は Chrome 系限定のため採らない。
6. **録音データの取扱い** — 現実装は録音をサーバに保存しない(文字起こしにのみ使用)。練習ログとして永続化する際(Phase 2)は、講師が聞けることの初回明示・質問ごとの保持件数(最新 3 件を仮案)・保持期間(面談後 n 日で削除か)を決める。
