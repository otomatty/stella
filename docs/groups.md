# グループ機能

## 1. 目的

グループに登録した受講者へ、Extra (`audience: granted`) ステージをまとめて設定します。
所属している間は、現在のグループ設定に従って割り当てを保ちます。一回限りの一括操作ではありません。

同じグループのメンバーは、公開設定に応じて互いの進捗や節目のタイムラインを見られます。
選考用のグループでも使います。

連携クライアントが API で作るグループ (#204) と、管理者が画面で作るグループを同じ仕組みで扱います。
既存の連携 API の仕様は [外部アプリから STELLA を利用する](integrations.md) を参照してください。変更点は本書で定めます。

## 2. 割り当ては実体化せず、そのつど求める

- 実効の割り当ては、手動の割り当て (`stage_grants`) と「所属グループ × `group_stages`」の和集合です。
- 実効の前提免除は、手動の免除 (`stage_unlocks`) と「所属グループ × `exempt = 1` の `group_stages`」の和集合です。`stage_unlocks` に残る旧腕試しの解放も引き続き使います。

実効の割り当てと免除を調べるときは、D1 のビューを読みます。

| ビュー | 列 |
| --- | --- |
| `effective_stage_grants` | `stage_id`, `profile_id`, `due_at`, `message`, `source_name`, `group_id` |
| `effective_stage_unlocks` | `stage_id`, `user_id`, `via`, `group_id` |

手動の行の `group_id` は `NULL` です。グループ由来の免除は `via = 'staff'` です。
旧画面の一括置換 (`PUT /api/stage-grants/:stageId`) は、グループ由来だけの割り当てを既存の割り当てとして扱い、手動の割り当て・前提免除・先行ステージの割り当ては追加しません。
グループ由来の行は `profiles.role = 'student'` かつ `profiles.disabled = 0` のメンバーだけから求めます。
ビューは `UNION ALL` を使うので、1人×1ステージに複数行ありえます。
割り当てと免除はそれぞれ、出どころが一つでも残る限り有効です。人数やステージ数を数えるときは重複を除きます。

メンバーやステージ設定を外すとき、または管理者作成のグループを削除するときは、無効化中も含め、受講者の開始済みの割り当てを同じ D1 batch で手動に引き継ぎます。読める受講登録 (`active` / `completed`) が対象です。
作成する手動の行に期限・案内文・案内元は入りません。既存の手動の行はそのまま使います。別のグループの割り当てが残る場合も手動に引き継ぎます。割り当て画面では「手動」と表示され、不要なら外せます。
`learnerCanSeeGrantedStage` は引き続き「実効の割り当てがある、または読める受講登録がある」で判定します。
スキルマップとホームの案内には実効の割り当てがある Extra を載せます。割り当てをすべて外すと、受講登録で教材を読める場合もマップと案内からは消えます。

期限・案内文・案内元は同じ1行から取ります。手動の行があれば、その行を使います。
手動の行が無ければ、グループ由来の行から期限の近いものを選びます。期限なしは最後、同じ期限はグループ ID の昇順です。
案内元 (`source_name`) は、手動の行では `stage_grants.source_name`、連携グループの行では `integration_clients.name`、管理者作成のグループの行では `NULL` です。
出どころがすべて無くなれば案内も消えます。ホームに案内元は表示しません (#201)。

## 3. データの形

### `groups`

| 列 | 意味・制約 |
| --- | --- |
| `id` | グループ ID。主キー |
| `name` | グループ名。必須 |
| `client_id` | `integration_clients.id`。クライアントの削除で CASCADE。管理者作成は `NULL`、連携クライアント作成は値あり |
| `external_key` | 連携 API のグループキー。`client_id` と両方が `NULL` か、両方が非 `NULL` になるよう CHECK |
| `share_progress` | 仲間への進捗公開。必須、`0` / `1`、既定は `0` |
| `share_activity` | 節目のタイムラインの公開。必須、`0` / `1`、既定は `0` |
| `created_by` | 作成した管理者の `profiles.id`。連携グループは `NULL`。プロフィールの削除で `NULL` |
| `created_at` | 作成日時 |
| `updated_at` | 更新日時 |

`UNIQUE(client_id, external_key)` で、同じクライアント内のキーの重複を防ぎます。

### `group_members`

| 列 | 意味・制約 |
| --- | --- |
| `group_id` | `groups.id`。グループの削除で CASCADE |
| `profile_id` | `profiles.id`。受講者の削除で CASCADE |
| `external_id` | メンバーの外部 ID。`NULL` 可。値があればグループ内で一意 |
| `peer_name` | グループ内の呼び名。`NULL` 可。値があれば1〜50文字 |
| `joined_at` | 参加日時 |

主キーは `(group_id, profile_id)` です。有効な受講者だけを追加できます。
管理者と無効なアカウントは追加しません。

### `group_stages`

| 列 | 意味・制約 |
| --- | --- |
| `group_id` | `groups.id`。グループの削除で CASCADE |
| `stage_id` | `stages.id`。ステージの削除で CASCADE |
| `due_at` | 期限。UTC の ISO 日時、または `NULL` |
| `message` | 案内文。500文字以内、または `NULL` |
| `exempt` | 前提免除。必須、`0` / `1`、既定は `0` |

主キーは `(group_id, stage_id)` です。

`stage_grants` と `stage_unlocks` は手動の分を持ちます。
`stage_unlocks` には旧腕試しの行 (`via = 'skill_check'`) も残します。
両表から `source_group_id` を落とします。`stage_grants.source_name` は手動の案内元として残します。

## 4. 編集の権限と書き込みの入口

グループ名・所属・ステージ設定は持ち主だけが編集できます。

| グループの持ち主 | 書き込みの入口 |
| --- | --- |
| 連携クライアント | 持ち主のクライアントが連携 API で編集します。管理画面では読み取りのみです |
| 管理者 | 管理者が管理画面 (管理 API) で編集します |

公開設定と呼び名は STELLA 側の方針です。管理者はどちらの種類のグループでも `share_progress`、`share_activity`、`peer_name` を変更できます。
公開設定の変更には管理 API を使います。呼び名は、持ち主の連携クライアントもメンバー追加の任意項目 `peerName` で指定できます。
省略時は現在値を保ち、`null` で解除します。

作成・名前変更、メンバーの追加・削除、ステージ一覧の置き換えと検査は `apps/api/src/lib/groups.ts` にまとめます。
連携 API と管理 API は共通処理を呼びます。入口でそれぞれの認証と持ち主の確認を行います。

- 指定できるのは `granted` のステージだけです。
- 親の鎖にある `granted` の祖先も、すべて同じ一覧に含めます。不足する祖先の slug を `parent_not_included` で返します。
- 表示条件のないコースで前提が無いステージは、従来どおり配置用の親をたどりません。
- 接頭辞の制限 (`allowedStagePrefixes`) は連携クライアントのグループだけに当てます。祖先にも同じ制限がかかります。
- 管理画面は必要な Extra の祖先を一覧に自動で含めて送ります。
- 一覧を検査してから、1回の D1 batch で置き換えます。どれかが不正なら設定は更新しません。

管理者向けの API はすべて管理者のみ利用できます。

| API | 応答・操作 |
| --- | --- |
| `GET /api/admin/groups` | 管理者作成と連携のグループ一覧 (`shareProgress`、`shareActivity` を含む)。 `clientId` で連携クライアントを絞り込めます |
| `POST /api/admin/groups` | `{ name }` で管理者のグループを作成します |
| `GET /api/admin/groups/:id` | グループの概要 (`shareProgress`、`shareActivity` を含む)・メンバー・ステージ設定を返します |
| `PATCH /api/admin/groups/:id` | `{ name?, shareProgress?, shareActivity? }` で名前・進捗公開・タイムライン公開を変更します |
| `DELETE /api/admin/groups/:id` | 管理者のグループを削除します |
| `PATCH /api/admin/groups/:id/members` | `{ add?, remove? }` にプロフィール ID を合計 100 件まで指定し、所属を変更します |
| `PATCH /api/admin/groups/:id/members/:profileId` | `{ peerName }` で呼び名を設定します。 `null` で解除します |
| `PUT /api/admin/groups/:id/stages` | `{ stages: [{ slug, due_at?, message?, exempt? }] }` でステージ設定を置き換えます |
| `GET /api/admin/groups/:id/progress` | 連携 API と同じ詳しい進捗を返します。 `stage` と `cursor` に対応し、進捗は現在の記録から求めます |

連携のグループの名前・所属・ステージ設定を変更する操作と、グループを削除する操作には 403 を返します。

## 5. 仲間の進捗 (受講者向け)

管理者がグループごとに `share_progress` をオンにしたときだけ公開します。
既定はオフです。既存の連携グループも移行時はオフです。

| API | 応答 |
| --- | --- |
| `GET /api/groups/mine` | 所属するグループのうち、進捗かタイムラインの公開がオンのものの ID・名前・有効な受講者の人数・公開設定 (`shareProgress`、`shareActivity`) |
| `GET /api/groups/:id/peers` | 自分が所属する `share_progress = 1` のグループの仲間の進捗。所属外・公開オフ・不存在はすべて同じ404 |

有効な受講者が利用できます。メンバーは本人を含む有効な受講者だけです。
`stages` は、そのグループの `group_stages` にある公開中のステージのうち、見ている本人のスキルツリーで見えるものだけです。
見えるのは、本人が修了したステージ、受講中のステージ（評価の `active`）、始められるステージ（前提を満たしたか、前提を免除されたもの）です。
ロックされて名前がぼかされるステージは含めません。
開発ラボG のように一度に 1 つずつ見せるコース（`revealOneAtATime`）は、スキルツリーと同じ評価（`loadSkillMapSource` と `evaluateSkillMapFor`）で視界が `full` の範囲に合わせます。次の章が見えるのは、そのコースの前の章を終えたあとです。
並びは `stages.parent` で親を先にし、同じ段は題名順です。

```json
{
  "group": { "id": "sample-group", "name": "サンプルのグループ" },
  "hasHiddenStages": true,
  "stages": [{ "id": "sample-stage", "title": "はじめのステージ" }],
  "members": [
    {
      "name": "すばる",
      "isMe": true,
      "ahead": false,
      "stages": [{ "id": "sample-stage", "percent": 100, "cleared": true }]
    },
    {
      "name": "ひかり",
      "isMe": false,
      "ahead": true,
      "stages": [{ "id": "sample-stage", "percent": 42, "cleared": false }]
    }
  ]
}
```

- 名前は `peer_name ?? profiles.display_name` です。名前順に並べ、同名は内部 ID 順です。進捗順には並べません。
- メンバーが200人を超えるときは、この並び順の先頭200人だけを返します。
- 各メンバーの `stages` は、見えるステージだけの `percent` と `cleared` です。`cleared` は受講登録の修了記録で判定します。
- `hasHiddenStages` は、公開中のグループステージのうち見えないものが 1 つ以上あるとき `true` です。見えないステージが無ければ `false` です。
- `ahead` は、見えないステージのどれかに受講登録がある、レッスンを 1 つ以上完了している、または課題に合格しているとき `true` です。見ている本人は常に `false` です。見えないステージの ID・題名・数・割合・修了は応答に含めません。
- メール、外部 ID、プロフィール ID、最後の活動日、未着手と開始済みの区別、課題ごとの状態、提出、確認待ち、支援付きかどうか、ヒントを開いたかどうかは返しません。

`percent` は本人のステージ画面と同じ式で求めます。
式は `@stella/shared` の純関数 (例 `stageProgressPercent`) に置き、Web の `deriveStageProgress` でも使います。

1. 受講登録に修了記録があれば100です。
2. レッスンが0件なら0です。
3. それ以外は、`done` を完了したレッスン数と合格した課題数 (課題数を上限とする) の合計、`total` をレッスン数と課題数の合計とします。`done ≥ total` なら100です。それ以外は `done ÷ total × 100` の小数点以下を切り捨て、99を上限とします (丸めで100に届かせないためです)。

レッスンも課題もすべて済んでいても、修了の記録が無ければ `cleared` は `false` のままです。

サーバーは `GET /api/cms/stages/:id` のステージ詳細と同じレッスンを対象に、`lesson_progress` の完了記録と課題の合格数をメンバー全員分まとめて集計します。
課題の合格は `GET /api/enrollments/mine` の `tasks_passed` と同じ数え方 (`passed` / `ai-passed`) です。
分母・分子ともに、有効な通常課題だけを数えます。

仲間の進捗画面には公開範囲の説明文を出しません (2026-11 オーナー決定)。
管理者は管理画面で、公開のオン・オフにかかわらず、従来 (#206) と同じ詳しい進捗を見られます。

## 6. 画面

| 画面 | 表示と操作 |
| --- | --- |
| `/admin/groups` の一覧 | 管理者作成と連携の両方を表示します。連携のグループには「連携: クライアント名」を表示します |
| `/admin/groups/$groupId` の詳細 | メンバーの追加・削除・呼び名の編集、ステージ設定、公開の切り替え、管理者向けの詳しい進捗を出します。ステージ設定には Extra の祖先を自動で含めます。連携のグループでは、所属とステージ設定は読み取りのみで、呼び名と公開は編集できます |
| `/admin/integrations` | クライアントを管理します。「グループを見る」は、そのクライアントで絞り込んだ `/admin/groups` を開きます |
| ステージ詳細の割り当て画面 | 割り当ての出どころを「手動」と「グループ: 名前」のバッジで表示します。グループ名から管理者向けの詳細を開けます。グループ由来だけの割り当ては外せず、「グループで管理しています」と表示します。手動分もある場合は手動分を外せます |
| `/groups` | 受講者が所属する公開中のグループの名前と人数を表示します |
| `/groups/$groupId` | 進捗共有と活動共有が両方オンの場合は、左から「タイムライン」「進捗」のタブを表示し、既定では「タイムライン」を開きます。仲間の進捗を段の帯で、API の名前順のまま表示します。見出しはグループ名だけで、人数と説明文は出しません。列はメンバー（200px）、いま（200px）、帯です。「いま」は割合を出さずステージ名だけを出します。受講中のステージ、無ければ最後に修了したステージの次のステージ (未着手なら最初のステージ) です。修了の印と緑の文字はグループのステージをすべて修了したときだけです。先に進んでいる人と、見えるステージをすべて修了して次が見えないステージの人は、ステージ名と同じ見た目で「まだ開いていないステージ」と出します (見えないステージの題名は API から来ません)。帯は見えるステージを同じ幅の段で並べ、見えないステージがあるときだけ末尾に通常の半分の長さの「その先」を置きます。「その先」は先に進んでいれば右へ薄くなるグラデーション、そうでなければ斜線です。段に触れると題名と割合（修了なら「修了」）を出します。「その先」は「まだ開いていないステージ」または「先に進んでいます」だけです。本人の行には印を付け、順位や集計は出しません。一覧の下に色の凡例を出し、番号とステージの対応は出しません。スマホ幅では名前といまを 1 行目、帯を 2 行目にし、段のラベルは一覧の上に 1 つだけ出します |

受講者のサイドバーには、`GET /api/groups/mine` で公開中の所属グループが1件以上返ったときだけ、修了証の前に「グループ」を表示します。

## 7. タイムラインとスタンプ

タイムラインの公開 (`share_activity`) は進捗公開と独立しており、既定はオフです。
受講者は `POST /api/me` で `hide_group_activity` をオンにすると、すべてのグループで自分の節目を非表示にできます。

- 現在所属する有効な受講者について、参加時刻以降に起きた、グループで設定した公開中のステージの開始 (`stage_start`)・修了 (`stage_clear`)・課題合格 (`task_pass`) を既存の記録から求めます。合格は有効な通常課題が対象で、手で済みにしただけの合格は除きます。
- ステージの公開範囲は「仲間の進捗」と同じです。見えないステージの節目は、他のメンバー 1 人・日本時間の 1 日につき 1 件の `ahead` にまとめます。その日の最後の節目で並べ、ステージ・課題・元の種類・件数は返しません。本人の `ahead` は表示しません。
- 日付は日本時間の `YYYY-MM-DD` です。節目は新しい順に 30 件ずつ返し、過去の期間に上限は設けません。名前にはグループの呼び名 (`peer_name`) があれば使い、無ければ表示名を使います。
- 節目の `key` は `<kind>:<memberHandle>:<ref>` です。ハンドルはグループ ID とプロフィール ID を NUL で連結した値の SHA-256 の先頭 24 桁です。`ref` は対象のステージ ID、課題 ID、または `ahead` の日付です。

| API | 応答・操作 |
| --- | --- |
| `GET /api/groups/:id/timeline?cursor=...` | グループ・節目の一覧・次のカーソルを返します。カーソルは初回省略し、続きは `nextCursor` をそのまま渡します |
| `POST /api/groups/:id/timeline/reactions` | `{ key, emoji }` でスタンプを押し、最新の `reactions` を返します |
| `DELETE /api/groups/:id/timeline/reactions` | 本文またはクエリの `key` と `emoji` でスタンプを外し、最新の `reactions` を返します |

いずれも公開中のグループに所属する有効な受講者が使えます。
押せるのは共有の絵文字一覧から、自分のタイムラインに出ている他のメンバーの節目に対して 1 人 1 件につき最大 10 種類です。同じ絵文字の追加は冪等です。
スタンプは最初に押された順に、現在所属する有効な受講者の人数と名前、自分が押したかを返します。グループやプロフィールを削除すると対応するスタンプも削除されます。

15 分ごとの cron が、日本時間の昨日・一昨日に届いたスタンプを受け取った本人に日ごとに 1 通にまとめ、1 回で最大 200 通ずつ送ります。
タイムラインが公開中で、双方が現在も所属する有効な受講者であり、受け取った人が節目を非表示にしていない場合、残っているスタンプを数えます。
本文には合計と件数の多い絵文字を最大 5 種類出し、同数なら最初に押された順に並べます。
通知データには日付・合計・最も多く届いたグループの ID を入れ、本文と通知データのどちらにも押した人の名前や ID は含めません。

## 8. 連携 API への影響

既存の URL・本文の形・scope を保ちます。`PUT /api/integrations/v1/groups/{key}/members` の各メンバーに、任意の `peerName` を足します。

- 手動・別グループの割り当てと重なっても、グループの割り当てと前提免除が和集合で効きます。
- 所属またはステージ設定を外すと、そのグループの割り当てと前提免除が消えます。開始済みのステージは手動の割り当てとして残り、割り当て画面では「手動」と表示されます。未着手のステージは、手動や別グループの割り当てがあれば残ります。
- 外れたグループの案内は消え、残った割り当てから2節の順で案内を選び直します。
- `integration_events` のトリガーは、連携クライアントのグループ (`groups.client_id IS NOT NULL`) に所属する人を対象にします。管理者作成のグループにだけ所属する人のための書き込みは増やしません。
- `progress` と `events` は、呼び出した連携クライアント自身のグループだけを返します。`share_progress` は受講者向けの公開だけを制御します。

## 9. グループの統合 (migration 0094)

1. 新しい3表を作ります。`integration_groups` / `integration_group_members` / `integration_group_stages` の行を同じ ID で写します。`share_progress = 0`、`peer_name = NULL`、`created_by = NULL` とします。
2. グループの設定と期限・案内文のいずれかが違う割り当ては、管理者が上書きした案内とみなし、期限・案内文・案内元を保って手動の割り当てに変えます。所属やステージ設定がすでに無い場合は、その受講者に同じステージの受講登録がある行、または期限か案内文に値がある行を手動に変えます。割り当て画面では「手動」と表示され、不要なら画面で外せます。
   残りのグループ由来の割り当てと、グループ由来の前提免除 (`source_group_id IS NOT NULL`) は削除します。移行後は「所属 × 設定」から割り当てと前提免除を求めます。手動や別グループと重なって旧方式では作られなかった分にも、現在の設定が効きます。開始済みのステージは受講登録で引き続き読めます。
3. `stage_grants` と `stage_unlocks` を作り直し、残した行と既存の制約・索引を引き継ぎます。どちらも `source_group_id` を省き、手動の案内元 `stage_grants.source_name` は引き継ぎます。SQLite は外部キー付きの列を `DROP COLUMN` できないためです。
4. `integration_events` のトリガーを、新しい `groups` と `group_members` を参照する形で作り直します。記録済みのできごとはそのまま使います。
5. 旧3表を落とし、`effective_stage_grants` と `effective_stage_unlocks` を作ります。

デプロイでは migrate が API のデプロイより先に走ります。
その間の数分間は、旧コードが旧グループ表を読む処理で失敗し、500を返します。
0032 の改名時と同じ扱いとし、連携クライアントは時間を空けて再送します。

## 10. 判断したこと

- 割り当てと前提免除は実体化せず、所属と設定からそのつど求めます。
- グループから割り当てを外すときは、開始済みの分を手動の割り当てとして残します。
- 手動の案内元は保存し、連携グループの案内元はクライアント名を使います。期限・案内文・案内元は、手動を優先し、グループ間では期限の近い順に選んだ1行から取ります。
- 旧版で上書きした期限・案内文は、移行時に手動の割り当てとして引き継ぎます (2026-11-24 オーナー決定)。
- 連携と管理者作成のグループは同じ表に置き、グループ名・所属・ステージ設定は持ち主だけが編集します。
- 公開は管理者がグループごとにオンにします。既定はオフで、選考のグループでも使います。
- 仲間の進捗で公開する情報は、表示名・修了したステージ・進捗の割合です。
- 選考で本名を見せずに使えるよう、グループ内の呼び名 `peer_name` を設けます。
- 対象はグループに設定したステージだけです。
- メンバーは名前順に並べ、順位表にはしません。
- #204 の「管理者作成グループは追加しない」という方針を、この設計で改めます (2026-11 オーナー決定)。
