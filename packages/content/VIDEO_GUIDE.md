# 教材動画ガイド (video.json)

教材動画 (トピック 1 つ = 動画 1 本) の絵コンテ `video.json` の書き方です。動画は、場面ごとのクリップをつないで作ります。スライドは映しません。

## 何を映すか

**コードやテキストだけで説明する場面は作りません。** 実際の画面のキャプチャを優先し、画面に映らない内容は概念図・イラストを動かして見せます。コードを出すときは、必ず概念図と並べます (2026-11-20、オーナー決定)。

1. **実際の画面のキャプチャ**。画面の操作・手順・どこを見るかは `view` + `clip:` で見せます。動かない画面には `view` + `shot:` を使います
2. **概念図・イラストのアニメーション**。一つの画面に映らない関係・流れ・ルールを `board` や `code` の横の図で見せます

既存のスライド版は、素材がそろい次第 `video.json` に置き換えます。

| 場面の種類 (`kind`) | 映すもの | 使うところ |
| --- | --- | --- |
| `view` + `clip:` | STELLA の Webアプリ・VS Code を実際に操作している動画 | 画面の操作・手順・見る場所 |
| `view` + `shot:` | 実際の画面の静止画。囲む・寄る・札を付ける | 動かない画面で見る場所 |
| `board` | ノード・矢印・印が動く概念図 | 一つの画面に映らない関係・流れ・ルール |
| `code` | コードと概念図を並べ、対応する部分を文ごとに見せる | プログラミングの書き方と値の動き |
| `view` + `art:` | 受講者の状況を描いたイラスト 1 枚 | つかみ |

つかみのイラストはこの順位の対象外です。これまでどおり、受講者の状況を絵にして要点の説明につなげます。

## 書く順番

**内容 → 絵 → 言葉** の順で書きます。言葉から書き始めないでください。

1. **学習設計 (`brief`) を書く。** その課題・トピックで、受講者に何を学んでほしいかを先に決めます。
   - `goal`: 見終えた受講者ができるようになること。1 文。「〜を説明できる」「〜の順番を言える」のように、確かめられる形で書く
   - `stuck`: 初学者がつまずく点。この動画が要る理由
   - `points`: 伝えること。schema 2 は **1 つ**、schema 1 は **3 つまで**。1 つは 1 文
   - `leaveOut`: あえて言わないこと。仕組みの詳細・アプリの内部の話・例外の扱い・その動画の要点に要らない画面の部品は、まずここに入れる
2. **素材を決める。** `points` ごとに、優先順位に従って何を映すかを決めます。使える操作は `packages/content/clips/`、静止画は `packages/content/shots/` にあります。必要な画面が無ければ撮ります (下の「素材を作る」)。
3. **場面 (`scenes`) に分け、最後に読み上げの文 (`say`) を書く。**

`points` に書いていないことは、正しくても動画に入れません。手順の細部は `doc.md` と操作の収録 (`screen.mp4`) に任せます。

## 場面の並び

動画の最初に、トピックのタイトルだけの場面が自動で入ります。`slides.md` の front-matter の `title` と、あれば `header` を表示し、0.6 秒から `title` を読み上げます。小さい字の `header` は読みません。長さは最低 2.6 秒で、読み上げに合わせて伸びます（読み上げの長さ + 前 0.6 秒 + 後 0.8 秒）。最初と最後の 0.4 秒でフェードし、字幕は重ねません。`video.json` には書かず、場面の id に `title` は使いません。schema 1 の文と文の間は 1.2 秒です。

動画は絵コンテの最後の場面で終わります。最後の文を読み終え、通常の余韻を置いたあと、0.8 秒で背景色 `#FFFFFF` へフェードアウトし、音声も同じ区間で 0 へ下げます。長さは 30fps のフレーム境界へ切り上げます。`takeaway` の文字だけの場面や読み上げは追加しません。ポスターには最後の場面のフェード開始直前のコマを使います。場面の id に `summary` は使いません。

タイトルの長さも 30fps のフレーム境界へ切り上げます。読みは `speechOf` と `narration/readings.json` を通し、音声の合成・キャッシュ・無音の切り落とし・長さの検査・無音対策のノイズ・音量の正規化はほかの場面と共通です。Gemini の合成はタイトルぶんだけ動画 1 本につき 1 回増えます。`--refresh-audio title` でタイトルの音声を作り直せます。廃止した `summary` の指定はエラーになります。

場面の `title` は執筆時のメモで、静止画の一覧や検査・推敲で使います。背景は白で、場面の見出しやコードを囲う外側のカードは表示しません。図のノードやコードの横の図のカードは表示します。

### 画面操作の動画 (schema 1)

| 場面 | `role` | すること |
| --- | --- | --- |
| つかみ | `hook` | 受講者が迷う点を問いにする。答えはまだ言わない |
| 要点 | `point` | `points` の 1 つを、優先順位に従って選んだ手段で説明する。`point` に番号を書く |
| ふりかえり（recap） | `recap` | 全体を 1 枚で見せて、`points` を言い直す。新しいことを足さない |

- 動画 1 本は 3〜6 場面、合計 **90〜180 秒**。急がないでください。文と文の間・操作の終わりの間は自動で入ります

## レッスン型の動画 (schema 2)

書き方・考え方を教える新しい解説動画は `"schema": 2` で作ります。画面の操作だけを見せる動画は schema 1 のままでかまいません。既存の schema 1 の解説動画は順に置き換えます。

**動画 1 本 = 要点 1 つ** です。`brief.points` は 1 つだけ書きます。要点が 2 つあればトピックを分けます。

| `role` | すること | 使える場面の種類 |
| --- | --- | --- |
| `goal` | この動画で何を学び、見終えると何ができるかを伝えます | `view`・`board` |
| `example` | 初心者が思い浮かべやすい実例を、イラストの図で動かします | `view`・`board` |
| `syntax` | 初めて出る書き方を 1 つずつ説明します | `view`・`board`・`code` + `figure` |
| `apply` | 最初の例をその書き方で表し、値の動きを見せます | `view`・`board`・`code` + `figure` |
| `note` | それまでの課題に出ていない用語・考え方を、出てきたところで説明します | `view`・`board`・`code` + `figure` |
| `quiz` | 受講者に問題を出し、最後に考える時間を置きます | `view`・`board`・`code` + `figure` |
| `answer` | 答えを見せます | `view`・`board`・`code` + `figure` |
| `explain` | なぜその答えになるかを、図とコードでたどります | `view`・`board`・`code` + `figure` |
| `usage` | どんな場面で使うかを、例を挙げて見せます | `view`・`board` |
| `next` | このあと取り組む課題で最初に見るコードを、そのまま見せます | `view`・`board`・`code` + `figure` |

- `goal` から `usage` までの役割は、`note` を除いて表の順にすべて入れます。`goal`・`quiz`・`answer` は各 1 場面です。`note` は必要なだけ入れます。最初・最後・`quiz` の直後は避けます。`next` は任意で、`usage` のあとにまとめて置きます。場面に `point` は書きません
- 絵コンテは 9〜18 場面、合計 **3〜8 分 (180〜480 秒)** にします。推定時間が範囲外なら警告、600 秒を超えるとエラーになります
- 文と文の間は **1.6 秒**、場面の終わりは **2.4 秒** が自動で入ります。初めての用語を言った文や値が動いた文のあとには、`pause` (0.5〜8 秒) で間を足せます
- `quiz` の最後は `think` (3〜15 秒、既定 6 秒) だけ待ちます。その間は右上に「考える時間」と残り秒数が出ます
- 場面の間はフェードせず、そのまま切り替わります。冒頭と末尾のフェードや、画面の場面どうしの画像の切り替えは入ります
- その動画で初めて出る重要な用語を言う文には `term` を書きます。画面を暗くして用語を中央に大きく出し、読み終わってから最低 1.5 秒保ちます。`pause` はそのあとに足します。用語は 1 文に 1 つ、動画 1 本で 3〜5 個まで。出したあと、図やコードのどこに当たるかを必ず見せます
- 関数名・引数名・変数名は自分で考えて付ける名前だと説明し、例の名前の英語の意味は `part.note` で見せます
- 初めてコードを読む動画では、書き方の説明が一通り済んだところで、言語で決まっている書き方 (キーワード・型の名前・記号) と、書く人が自分で決めるところ (関数名・引数名・値) を `classify` で色分けして見せます (2026-11-20、オーナー決定)
- 「次の課題」でも、課題の答えのコードは書きません

動画を作るときの方針です (2026-11-21、オーナー決定)。

- **話し方**。読み上げ文は丁寧な説明にします。「〜ですね」「〜ですよ」「〜なんです」のようなくだけた文末は使いません (検査でエラーになります)。同じ文末が続かないよう、「〜です」「〜ます」「〜ました」「〜ません」「〜ましょう」「〜ください」「〜でしょうか」を使い分けます。
- **最初のイラスト**。「この動画で学ぶこと」の場面は、その動画の具体例がひと目で伝わる絵にします。カウンターの奥にロボットを置き、左右に物を 1 つずつ並べる構図を使い回しません。スマートフォンの画面・台所・自動販売機・伝票など、見る人が思い浮かべやすい場面を動画ごとに選びます。
- **トピックの番号**。動画 1 本で要点を 1 つにするため、トピックは細かく分けます。増えたトピックには枝番 (`1-1-1a` など) を付けず、通し番号を付けて後ろのトピックの番号 (`id`・フォルダー名・`doc.md` の見出し) をずらします。
- 動画内の問題は、その動画のために新しく作ります。以前の動画で出した問題の関数名・題材・数は使い回しません。
- 以前の動画で説明した用語は、そのまま使えます。たとえ話で「係」と呼んだものも、用語を教えたあとは「関数」と呼べます。
- イラストと図は、その動画の説明にいちばん合うものを用意します。同じイラストや図を使うのは、同じ関数・色分けの図・課題のコードなど、前の動画で出たものをもう一度説明するときだけです。
- 新しい考え方は、名前とその意味を先に説明してから、書き方を見せます。たとえば、変数を説明してから `const` を見せます。
- 音声と映像は場面ごとに再利用します。文を変えていない場面の音声や、絵を変えていない場面の映像は作り直す必要がないので、直すときは必要な場面だけを変えます。

```json
{ "say": "受け取る値を、引数と呼びます。", "term": { "text": "引数", "ruby": "ひきすう", "note": "関数が受け取る値" }, "pause": 1 }
```

`term.text` は 1 行・10 字まで、任意の `note` は 1 行・16 字までです。フリガナは用語の表示だけに付けます。字幕・図・コードには付けません。用語に漢字があれば `term.ruby` は必須です。読みはひらがな・カタカナ・長音 (ー) だけで 1〜30 字にします。

### コードのダイアログ (`dialog`)

コードのダイアログは、書き終えたコードなどをまとめて見せるときに使います。動画 1 本につき 1〜2 回までにします。ここではコードの説明はせず、「書き方」の場面で図と並べて説明します。

```json
{
  "say": "書き終えたコードは、次のとおりです。",
  "dialog": {
    "title": "書き終えたコード",
    "code": [
      "// 本の値段を受け取り、支払う金額を返す関数",
      "function addShipping(price: number): number {",
      "  return price + 500;",
      "}"
    ]
  }
}
```

- 『この動画で学ぶこと』の場面では、コードのダイアログを出しません。具体例の絵と要点の文で終えます (2026-11-22、オーナー決定)
- 身近な例や使う場面などでは文に 1 つ書けます。同じ文に `term` は書けません
- `dialog.title` は空でない 1 行・24 字まで、`dialog.code` は 1 要素 1 行で 1〜8 行、各行は全角換算 40 字までです。字下げにタブは使わず、実際のコードを 1 行以上入れます
- 文の開始から画面を暗くし、窓の中にコードを全行まとめて出します。読み終わってから最低 2.5 秒保ち、`pause` はそのあとに足します

### 動き

- 出てくる要素は小さめ（0.94 倍）から等倍へフェードインし、表示する大きさより大きくなりません。バウンドしません（2026-11-20、オーナー決定）。消えるときは大きさはそのままで、不透明度だけ下がります。考える時間と幕は不透明度だけです
- `pulse` は枠の色（#E62F9A、太さ 4px）で強調し、地の色は変えません。矢印は線と矢じりを同じ色にします。文が終わっても続き、次に `pulse` を書いた文で入れ替えます。`pulse: []` で外します。場面をまたぎません。`hide` した要素の強調も外れます
- 書き方: 説明している要素が変わる文ごとに、その要素を `pulse` に書きます。図の話から離れる文では `pulse: []` で外します。同じ要素を続けて書いても絵は変わりません

## 画面の場面 (`view`) のルール

- 場面の `image` に `"clip:web/read-lesson#open-lesson"` と書くと、mark の最初のコマを止めて出します
- 操作を進める文には `"clip": "web/read-lesson#open-lesson"` と書きます (`clip:` は付けない)。**1 文 = 1 操作 (mark 1 つ)**。mark はクリップの JSON にある開始秒と終了秒の組です
- `speed` は 0.5〜3、既定は 1。`"speed": 1.5` なら 1.5 倍速です。同じ文に `image` と `clip` は書けません
- 文より操作が長ければ、そのぶん動画が待ちます。操作が終わったら最後のコマで止まり、次の文もそのコマを引き継ぎます
- `spot`・`zoom`・`label`・`click` の領域はクリップの `regions` を使います。再生中に寄る・囲むこともできます
- Webアプリ ↔ VS Code の切り替えは、窓が入れ替わる 0.9 秒のつなぎが自動で入ります。同じアプリどうし・イラストとの切り替えは 0.4 秒のクロスフェードです

- 画面の文字は動画では小さくなります。**見せたい場所には必ず寄る (`zoom`) か、囲む (`spot`)**。画面全体を映したまま話し続けない
- 1 文で見せる場所は 1 つ。次の文で次の場所へ移る
- 囲み (`spot`) は画面全体を暗くし、囲んだ領域だけを明るく残します。囲み・札 (`label`)・押す場所 (`click`) は次の文が始まるまで残り、最後の文では場面の終わりまで残ります。指定した文は、読み終わってから 1.5 秒は次へ進みません
- 静止画で押す場所は `click` で見せる (カーソルが動いて押す)。押したあとの画面は、次の文で `image` を切り替えて見せる
- 札 (`label`) は 12 字まで。画面に書いてある言葉を繰り返さず、「ここで書く」のように意味を足すときだけ使う
- `view` で見せるアプリやページの画面は実際に撮ったものだけを使う。画面を描き直した絵や、加工した画面は使わない
- Windows のウィンドウの見た目で出ます。Web はブラウザーの枠、VS Code は収録したタイトルバーにキャプションボタンが付きます。寄るときも Web の枠は同じ位置・大きさで残り、VS Code のボタンは画像と一緒に拡大されます。イラストには付きません

## 動くイラストの場面 (`motion`)

値を受け取って処理し、結果を返す流れなど、順に動かすと分かりやすい説明に使います。手書きの SVG を Remotion と GSAP で動かします。

`video.json` の schema 2 で、場面に `kind: "motion"` と、使う動きの ID を `motion` に書きます。たとえば `"motion": "vending-change"` は自動販売機のお釣りを見せる動きです。この動きでは、`beats` に通常の読み上げを順に 5 文書きます。`term` や `dialog` を出す文は、この 5 文とは別に足せます。各文に書ける項目は `say`・`speech`・`pause`・`term`・`dialog` です。

新しい動きを加えるときは、`remotion/motions/manifest.ts` に ID・題名・通常の読み上げ文の数を書きます。`seconds` には、通常の読み上げ文ごとに設計上の長さを秒で並べます。動きの開始時刻は `beatClock` で求めると、短い文に合わせて開始時刻の間隔が縮まります。同じ ID で `remotion/motions/index.ts` に部品と、その絵に出る文字を登録します。部品は `beats`（文の開始と終了）と `duration`（場面の長さ）を秒で受け取り、1920×1080 の SVG を返します。

- 文の開始に合わせて動かし、0 秒より前に始まる動きは 0 秒からにします。GSAP のタイムラインは `useTimeline` で指定のコマの時刻に止めます。増減する数は時刻から直接計算します。
- 要素を出すときは 0.94 倍から等倍へ動かします。絵は y=960 までに収め、流れを表す線は絵の上に描きます。
- 字幕は Web のプレイヤーが重ねます。用語とコードのダイアログは場面の共通処理で描きます。

リポジトリのルートで `bun run --filter=@stella/content video:studio` を実行します。Remotion Studio で動きの ID を選び、タイムラインのつまみを動かすと、仮の読み上げ時刻で絵を確かめられます。`motion` の描画は Node.js で実行するため、動画を書き出す環境に Node.js が必要です。Remotion は個人と 3 人以下の会社は無料で使えます。

## コードの場面 (`code`)

プログラミングの書き方と値の動きを、コードとその横の概念図で見せます。文ごとにコードの部分と対応する図のノードや矢印を動かします。

場面の共通項目 `id`・`role`・`point`（schema 1 の要点の場面だけ）・`title` に、`kind: "code"` と次の項目を足します。

| 項目 | 内容 |
| --- | --- |
| `code` | 1要素1行の文字列配列。最大14行、各行は全角換算40字（半角80字）まで。字下げは空白 |
| `show` | `true` は全行を、行番号の配列は指定行だけをはじめから表示します。行番号は 0 始まりで、重複は書けません。省略時は空です |
| `panel: { "kind": "figure", "board": "shop" }` | `boards.shop` の概念図。schema 2 のコード場面には必須です |
| `reset` | `figure` パネルだけに指定できます。`true` なら図を空から始めます |
| `panel: { "kind": "values", "items": ["price", "total"] }` | schema 1 の名前の付いた値の箱。はじめは空 |
| `panel: { "kind": "calls", "rows": [{ "call": "addTax(980)", "result": "1078", "note": "税額は98円" }] }` | schema 1 の呼び出しと結果の表。`note` は任意。はじめは空 |

schema 1 ではパネルを省略できます。数の位置で示すと分かりやすい切り捨て・切り上げ・四捨五入・大小の比較には、`panel: { "kind": "numberLine", "from": 18, "to": 21, "items": ["points"] }` を使えます。整数の目盛りは2〜8個。任意の `items` は線の下の値の箱で、`set`・`calc` も使えます。
数直線だけの動きは、`plot: { "at": 19.8, "label": "19.8" }` で点と札を出す、`range: [19, 20]` で整数間を薄紫に塗る、`snap: { "to": 19, "label": "切り捨て" }` で前の文の点を1秒で整数へ動かして矢印を残す、`tick: [{ "at": 20, "kind": "cross" }]` で目盛りに赤い✕（`check` は緑の○）です。位置は範囲内で指定します。

`figure` はノード 2〜4 個、囲みなしの図解を使います。ノードは `at` の行、同じ行では列の順に、上からカードとして並びます。矢印は隣り合うカードを上から下へ 1 本ずつ結べます。同じ図解を続けて使うと、`board` と `code` を行き来しても、出ているノード・矢印、印、値の札を引き継ぎます。

各 `beat` は `say`（必要なら `speech`）と、次の動きを書きます。行番号・表の番号は0始まりです。**1文で見せる動きは1つか2つ**に絞り、どの文でも絵が変わるようにします。

強調はまず行を選び、ほかの行を暗くします。その行の中でさらに示したい部分には `part` で下線を引きます。schema 2 では `part` を書くと、その行以外が自動で暗くなります。行全体を見せたいときや、明るくする行を指定したいときは `focus` を使います。

| 動き | 内容 |
| --- | --- |
| `figure: { "pulse": ["price"] }` | 横の概念図を動かします。`show`・`hide`・`focus`・`pulse`・`mark`・`unmark`・`tag`・`untag`・`travel` は `board` と同じ書き方です。図だけが変わる文も書けます |
| `type: [0, 1]` | 指定順に1文字ずつ打つ。行の文字数に比例し、読み上げの長さの7割までに終える。出していない行は見せない |
| `focus: [1]` | 指定した行を明るく、ほかを少し暗くする。次の文で解除 |
| `part: { "line": 1, "text": "add", "note": "足す" }` | 最初に一致する部分に下線を引き、任意の `note` (1 行・8 字まで) を吹き出しで出す。schema 1 で `note` を省略したときだけ丸い番号を出す。次の文で解除 |
| `classify: { "fixed": [{ "line": 1, "text": "const" }], "free": [{ "line": 1, "text": "price" }] }` | schema 2 専用。`fixed`・`free` の片方か両方に、出ている行 (同じ文で打つ行を含む) の部分を各 1〜12 個指定する。行内の重ならない一致を左からすべて色分けし、凡例を自動で出す。色は場面の終わりまで積み重なり、あとの指定で上書きできる。同じ文で同じ文字に両方の色は指定できない |
| `set: { "price": "1200" }` | valuesの箱に値を入れる。すでに値があれば古い値を消して入れ替える |
| `calc: { "on": "total", "expr": "1200 + 500", "result": "1700" }` | valuesの箱に式を出し、少しあとに矢印と結果を出す。次の文には結果を引き継ぐ |
| `row: [0]` | callsの表の行を出す |
| `mark: [{ "line": 1, "kind": "cross" }]` | 行の右端に赤い✕。`check` は緑の○。印は引き継ぐ |
| `clear: [1]` | 行とその印・色分けを消す。よくある間違いから戻すときに使う |

強調と印は、出ている行（同じ文で打つ行を含む）に付けます。同じ行を同じ文で `type` と `clear` に指定したり、同じ箱を `set` と `calc` に指定したりしません。値や結果は文字列として書き、コードそのものは実行しません。

コードは教材のサンプルと同じ規則で、**各コード行の上に日本語のコメント**を書きます。コメント行だけの場面は作りません。操作・ルール・進め方の説明に `code` を使いません。課題の答えのコードは書きません。

身近な例の場面で出した `boards.shop` の価格のノードを、書き方の場面でも使う例です。

```json
{
  "id": "names",
  "kind": "code",
  "role": "syntax",
  "title": "値に名前を付ける",
  "code": ["// 価格に名前を付ける", "const price = 1200;"],
  "show": [0],
  "panel": { "kind": "figure", "board": "shop" },
  "beats": [
    { "say": "価格に名前を付けます。", "type": [1], "figure": { "pulse": ["price"] } },
    { "say": "価格は千二百です。", "part": { "line": 1, "text": "1200" }, "figure": { "tag": { "price": "1200" } } }
  ]
}
```

## 概念図 (`board`) とイラストのルール

- ノードは 6 個まで、矢印は 8 本まで、囲みは 3 個まで
- ノードにはイラスト (`art`) を付ける。小さなアイコン (`icon`) だけのノードは、イラストを用意できないときの代わりです
- ノードに `tag: { "price": "1200" }` で値の札を付け、`untag: ["price"]` で外します。値は 1 行で 8 字まで。札は次の文・同じ図解の次の場面に引き継ぎ、ノードを隠すと消えます
- ラベルはノード 10 字・囲み 12 字・矢印 6 字まで。画面で受講者が目にする言葉に合わせる
- 矢印にラベルを付ける図解は、ノードの間を 1 列空ける。たとえばイラストのノード 3 個なら `cols: 5` にして 1・3・5 列目に置く。3 列に 3 個を詰めると、カードの間が狭く、矢印のラベルがカードに隠れる
- 囲みの `tone` (`blue` / `violet`) で場所を色分けする。画面の場面の窓の色とそろえる (Webアプリ = `blue`、VS Code = `violet`)
- イラストに文字・ロゴは入れない。絵柄は `narration/art-style.md` でそろえる
- 食べ物と飲み物は、配色の決まりにかかわらず自然な色で描く (青や紫のカレーにしない。2026-11-22、オーナー決定)
- schema 2 の `pulse` は枠の色（#E62F9A、太さ 4px）で強調し、地の色は変えません。次の `pulse` まで続き、`pulse: []` で外し、場面をまたぎません

## 読み上げ 1 文 (`beats`) のルール

- **1 文ごとに絵が変わること。** 画面の場面は 操作する (`clip`)・切り替える (`image`)・囲む (`spot`)・寄る (`zoom`)・札 (`label`)・押す (`click`)、概念図は 出す (`show`)・目立たせる (`focus` / `pulse`)・印 (`mark`)・値の札 (`tag` / `untag`)・たどる (`travel`)・寄る (`zoom`) のどれかを必ず書く。schema 2 の `term` も動きに数えます。`motion` は部品が文ごとの動きを決めます。絵が変わらない文は、要らない文です。schema 2 の `pulse` が絵を変える条件は、[動き](#動き) を見てください
- 1 文は 40 字まで。です・ます調の話し言葉。画面のボタンの名前は「」で引用してよい。ほかの括弧・記号 (「→」「/」「…」) は使わない
- schema 2 では、同じ場面で同じ文末を続けると検査でエラーになります。句点や疑問符を除いた末尾の 2 文字で判定します。「です」で終わる文を並べないようにします。
- schema 2 では、「〜ですね」「〜ですよ」「〜なんです」のようなくだけた文末も検査でエラーになります。
- 言い方の例は、〜です／〜ます／〜ました／〜でしょうか／〜ましょう／〜ません／〜ください／〜になります。意味を保って言い換え、無理に体言止めにしません。
- 1 文で伝えることは 1 つ。「A は B で、C は D です」のように、二つのことを一文につなげない
- 用語の定義だけの文を続けない。定義は、その語が画面に出た文で 1 回だけ言う
- 人に話すときの語順で書く。主語と述語を近づけ、名詞を「の」で 3 つ以上つながない
- 「〜することができます」は「〜できます」に、「〜を行います」は「〜します」にする
- 声に出して読み、言いよどむ文は直す
- 1 場面は 1〜5 文（コードの場面は6文まで）
- 字幕は `captions.vtt` に文ごとの `say` と読み上げ時刻を書き、プレイヤーが動画に重ねます。用語・ダイアログ・`spot` で画面が暗い文には `<c.on-dark>` を付けます。通常は黒い太字に白いふち、暗い文は白い太字に黒いふちを使います
- 音声には無音対策の小さいノイズが入ります。文と文の間に再生機器が出力を止め、次の音の頭が途切れるのを防ぎます
- 見れば分かることを言葉で繰り返さない。絵が出るのに合わせて、その意味を言う
- 次のトピックの名前・ステージの中の位置は言わない
- 読みを変えたい語は、まず読み辞書 (`narration/readings.json`) に足す。一回きりなら `speech`
- タイトルと Web アプリ・VS Code の窓の切り替えで、小さな効果音が自動で鳴ります。クリックやキー入力の音は入りません。効果音はコードで合成し、読み上げの音量を正規化したあとに、ピーク約 -24 dBFS で混ぜます。
- レッスン型 (schema 2) では次の音も自動で鳴ります。絵コンテに効果音の指定は不要です。

| タイミング | 効果音 |
| --- | --- |
| 場面の頭 | 問題は上がる 3 音 (`quiz`)。ほかの場面は短い木琴のような 1 音 (`scene`)。窓が切り替わる場合は窓の音 |
| 文の開始 | 用語 (`term`)、ダイアログ (`pop`)、新しい正解・不正解・疑問の印 (`correct` / `wrong` / `question`)、値の札の追加・変更、意味の吹き出し、色分けの追加・変更 (`pop`、開始の 0.1 秒後)、図の移動 (`move`) の順に、当てはまる最初の 1 音。窓が切り替わる文では窓の音を優先 |
| 考える時間 | 開始から 1 秒おきに時計の音 (`tick`)、終了時に鐘 (`timeup`) |

## 素材を作る

```bash
# Webアプリの操作: ローカルで STELLA を起動してクリップを撮る
bun run --filter=@stella/web tutorials:clips

# VS Code の画面: 操作の収録 (screen.mp4) からコマを取り出す。定義は shots/frames.json
bun run --filter=@stella/content video:shots

# Webアプリの静止画: ローカルで STELLA を起動して撮る。定義は apps/web/scripts/tutorials/shots/*.ts
bun run --filter=@stella/web tutorials:shots

# イラスト: video.json の art の prompt から Gemini で作る
bun run --filter=@stella/content video:art -- <トピックのパス>
bun run --filter=@stella/content video:art -- <トピックのパス> --only read,write   # 選んで作り直す
bun run --filter=@stella/content video:art -- <トピックのパス> --only write --ref read   # 絵柄の手本を指定する (既存の画像・作成対象と別の名前)
```

- クリップは `packages/content/clips/<組>/<名前>.json` に書きます。`video` は `packages/content` からの相対パス (`stages/` または `clips/` の下だけ)、`width`・`height` は 1600×1000、`fps` は 30、`duration` は秒数、`marks` は `{ "open": [開始秒, 終了秒] }`、`regions` はピクセルの `[x, y, 幅, 高さ]` です。`source` に収録元を残します。任意の `browser: { tab, address }` は web の枠のタブ名とアドレスです。tab は 1〜20 字、address は 1〜70 字で、vscode のクリップには書けません
- 既存の収録の区間を使うときは、`video` に元の `screen.mp4` のパスを指定し、`marks` に使う区間を書きます。動画をコピーする必要はありません
- VS Code の新しい操作は **Windows の手元で撮ります**。撮り方と未撮影の操作は [手元での収録の手引き](../../docs/video-local-recording.md) を参照してください
- ショットは `packages/content/shots/<組>/<名前>.png` と同名の `.json` (領域 `regions`)。絵コンテからは `shot:web/task` のように指す
- 領域は、Webアプリの画面はセレクタから自動で決まります。収録のコマは `frames.json` にピクセルで書きます
- イラストはトピックの `assets/art/<名前>.png`。絵コンテからは `art:<名前>` で指す。イラストの領域は `art` の `regions` に割合 (0〜1) で書きます
- 作ったイラストは必ず目で確かめます。文字・ロゴ・不自然な手や顔があれば作り直します
- 画面が変わったら撮り直します。素材を足す・作り直すと単元の内容指紋が変わるので、`references.json` を更新します

## Gemini で読み上げ文を磨く

文を書いたら、音声を作る前に `video:polish` を通します。Gemini 4 Neon が、不自然な言い回し・冗長な文・書き言葉・難しい語・絵の繰り返し・学習設計に無い話を文ごとに指摘し、言い換え案を返します。Neon の応答には 3〜4 分かかることがあり、通信は 1 回につき 600 秒で打ち切ります。

```bash
bun run --filter=@stella/content video:polish -- <トピックのパス>            # 案を取得して読む
bun run --filter=@stella/content video:polish -- <トピックのパス> --apply    # 保存済みの案を反映する
bun run --filter=@stella/content video:polish -- <トピックのパス> --apply --only hook#2,places#4
bun run --filter=@stella/content video:polish -- <トピックのパス> --apply --skip hook#2
```

- まず API で案を取得し、画面か `dist/video-polish/<stage>/<topicId>.md` で読みます。JSON の報告には、そのときの読み上げ文の `sayHash` も保存されます
- `--apply` は API を呼ばず、保存済みの案のうち受け入れ可能なものを反映します。`--only` は反映する文を選び、`--skip` は外します。両方同時には使えません。知らない id はエラーになります
- 報告がない場合や、取得後に文や `speech` を直した場合は反映しません。先に `video:polish` で案を取り直してください。反映後に残りの案を使う場合も取り直します
- 案は提案です。数字や新しい用語を足した案・長すぎる案は、自動では反映されません。文を削る案 (`cut`) も反映されないので、絵の動きごと見直します
- 反映したら、必ず自分で読み直します。画面の言葉とそろっているか、`points` から外れていないかを見ます
- 案を取得すると現在の文で、反映すると反映後の文で、`video.json` の `polish` に記録が残ります。そのあと文を直すと `video:check` が警告するので、もう一度通します
- `--dry-run` は API を呼ばず、ファイルも更新しません。取得に使うモデルは `VIDEO_POLISH_MODEL` で変更できます。`--model` を指定すると環境変数より優先されます

## 確かめ方

手元の `video:scenes`・`content:video`・`video:sync` は、`--tts` を省くと Open JTalk の合成音声で作ります。最初に `bun run --filter=@stella/content video:tts:setup` を 1 回実行してください。Python 3.10〜3.13 と `pyopenjtalk-plus` の wheel を使います。読み上げなしの確認では `--tts fake` で仮の音を作れます。本番の声で確かめるには `--tts gemini` を指定します。

`video.json` のあるトピックは `video:check` で検査し、使わない `narration.json` は `narration:check` の検査から外します。コメントと空行だけの `code` はエラーにします。`narration.json` があり、`video.json` も `screen.mp4` も無いトピックは、置き換えの対象として警告します。

```bash
bun run --filter=@stella/content video:check                                   # 絵コンテの検査
bun run --filter=@stella/content video:scenes -- <トピックのパス> --stills      # 文ごとの静止画 (API を呼ばない)
bun run --filter=@stella/content video:scenes -- <トピックのパス>               # Open JTalk で動画まで
bun run --filter=@stella/content video:scenes -- <トピックのパス> --burn-captions  # 字幕付きの確認用動画も作る
bun run --filter=@stella/content video:scenes -- <トピックのパス> --tts fake    # 仮の音で動画まで
bun run --filter=@stella/content video:scenes -- <トピックのパス> --tts gemini  # 本番の音声
bun run --filter=@stella/content video:scenes -- <トピックのパス> --tts gemini --tts-model gemini-3.8-flash-lite-tts  # 別の音声モデル
bun run --filter=@stella/content video:scenes -- <トピックのパス> --tts gemini --refresh-audio hook,check  # 指定した場面の音声を作り直す
```

静止画の一覧で、囲みの位置・寄ったときに文字が読めるか・札のはみ出しを見てから音声を作ります。一覧の各コマの下には対応する文を載せます。

`--burn-captions` を付けると、同じ出力先に `video.captions.mp4` を追加します。Web プレイヤーと同じ CSS と Noto Sans JP の太字で、Chromium が字幕を透明な PNG に描きます。ffmpeg が読み上げの時刻に合わせて重ね、音声はそのままコピーします。配信では `video.mp4` と `captions.vtt` を使います。

1 日の上限に達したら、`--tts-model` で別のモデルを指定して書き出せます。環境変数 `VIDEO_TTS_MODEL` でも指定でき、`--tts-model` が優先します。公開する版は、上書き指定を外して `narration/voice.json` のモデルで作り直してください。

## 公開のされ方

`main` に入ると、CI の `video:sync --remote --tts gemini` が `video.json` のあるトピックを新方式で作り、R2 と seed を通して公開します。同じ内容ハッシュの動画・字幕・ポスターが台帳にあれば作らず、変わった動画だけを作ります。`brief`・`polish`・イラストの `prompt` だけの変更では作り直しません。使う素材 (ショット・クリップ・イラスト) の中身を変えると作り直します。場面ごとの音声と映像は CI のキャッシュで使い回します。

手元で配信まで確かめる場合は、リポジトリのルートで次を実行します (ffmpeg・Playwright Chromium と local R2 が必要)。`video:sync --remote` の既定は Gemini です。公開用の音声モデルは `narration/voice.json` で決まり、`video:sync` では `--tts-model`・`VIDEO_TTS_MODEL` を使えません。

```bash
bun run --filter=@stella/content video:sync dev-env-basics
VIDEO_MANIFEST=$PWD/packages/content/dist/video-manifest.json bun run db:seed
```
