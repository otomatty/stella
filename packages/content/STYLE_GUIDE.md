# 執筆スタイルガイド

本教材の全レッスン(スライド・LMSドキュメント)に適用するルールです。トーンと構成を統一し、複数人で改訂しても品質が揃うようにします。

## 対象者像(常に意識する)

- プログラミング未経験〜経験数ヶ月の社内エンジニア
- JavaScriptの前提知識も仮定しない(Module 1で基礎から扱う)
- 専門用語は初出時に必ず一言で定義する(例:「コンパイル(プログラムを実行できる形に変換すること)」)
- 「実務でどう役立つか」を必ず添える。抽象的な説明だけで終わらせない

## 文体

- です・ます調
- 1文は60文字以内を目安に短く
- カタカナ語の表記はサバイバルTypeScript準拠(例: インターフェース、コンパイラー)
- 煽らない・脅さない(「これを知らないと恥ずかしい」等は禁止)

## トピックスライド(slides.md)のルール

1トピック = ショート動画1本 = **覚えることが1つ**。2〜3分、4〜6スライドに収めます。

- front-matter に語彙台帳(`id` / `title` / `takeaway` / `introduces` / `requires` / `header`)を書く。詳細は `CLAUDE.md` 参照
- **`takeaway` が1文で書けなければ、そのトピックは分割する**。タイトルに「と」が入ったら分割のサイン
- 必須の流れ(4〜6枚):
  1. タイトル(`_class: lead`) — トピックIDとタイトル
  2. なぜ必要か — 実務のあるあるで15秒。**ここで結論を言わない**
  3. 結論 — `takeaway` をそのまま。動画のサムネになるスライド
  4. 最小のコード — 5行以内。**`takeaway` 以外の新要素をゼロにする**
  5. 図解 または 対比・失敗例 — `takeaway` を強化する材料**だけ**。任意
  6. まとめ(`_class: summary`) — `takeaway` の再掲だけ。**新情報を足さない**
- 5番の枠は1つだけ。「関連情報」を足したくなったら、それは別トピックにする合図
- 各スライドに `<!-- ノート: ... -->` で講師の読み上げメモを書く(動画のナレーション台本を兼ねる)
- **次トピックのタイトルをスライドに書かない**。順序を入れ替えたり単体で公開したりしたときに嘘になるため。次への引きが要る場合は「まとめ」のナレーションで口頭のみ
- 「なぜ必要か」で他トピックの結論を先出ししない

## LMSドキュメント(doc.md)のルール

レッスン単位で1本。トピックの解説を通読できる読み物として再構成します。

- 必須セクション(この順序):
  1. `# レッスンX-Y 【レッスンタイトル】`
  2. `## このレッスンの目標` — チェックボックス形式で3点以内
  3. `## X-Y-1 【トピックタイトル】` — **トピックと1:1**。見出しに必ずトピックIDを付ける
     - 冒頭に `> **takeaway**` を引用形式で置く
     - 以降は動画の内容を読み物として再構成(動画を見なくても一応わかる粒度)
  4. `## もっと知りたい人へ` — 参考リンク集
  5. 末尾に `practice.md` へのリンク
- 図解は該当トピックの `assets/` を相対パスで参照する(例: `t2-const-and-let/assets/let-vs-const.svg`)
- コードブロックには必ず言語指定(`ts`または`js`)を付ける
- 実行結果やエラーメッセージはコメントで示す(`// => 結果` / `// エラー: ...`)

## OS別の手順(`:::os`)のルール

WindowsとmacOSで操作が違う手順は、OS別のブロックに分けます(新設計07 §11)。受講者の画面ではOSのタブになり、既定は受講者のOSです。

````markdown
:::os windows
PowerShellで次を実行します。

```powershell
npm.cmd --version
```
:::

:::os macos
ターミナルで次を実行します。

```sh
npm --version
```
:::
````

- 書けるのは、まとめ(`doc.md`)と課題文(`tasks/<課題>/README.md`)だけ。スライド・動画・知識問題・ヒントはOSに依存しない説明にする
- 開始は行頭の `:::os windows` / `:::os macos`、終わりは行頭の `:::` だけの行。OS名は小文字で、この2つだけ
- 空行だけを挟んで続くブロックが1組(タブ1つ)になる。1組には必ずWindowsとmacOSの両方を書く
- 入れ子にしない。リスト・引用・表の中には書けない。手順の番号はブロックの中で振り直す
- ブロックの中には見出し・リスト・コードブロック・画像を書ける。コードブロックの中の `:::` は記法として扱わない
- WindowsはPowerShell、macOSはターミナル(06 §3)。1つのブロックに両方のOSのコマンドを混ぜない。PowerShellのnpmは `npm.cmd` と書く(実行ポリシーで `npm.ps1` が止まることがあるため)
- OSごとの画像は `<名前>.windows.png` / `<名前>.macos.png` の対にしてトピックの `assets/` に置き、それぞれのOSのブロックの中で `![説明](t1-…/assets/<名前>.windows.png)` の形で参照する。ブロックの外やスライドでは使わない。課題文には教材内の画像を使えない(配布されないため)
- 配布PDFは、`course.json` に `"pdfByOs": true` を書いた講座(`dev-env-basics`)ではOSごとに別のPDFになる。それ以外は1つのPDFに「Windows の場合」「macOS の場合」の見出しで両方を並べる
- VS Codeの拡張は画像を表示できない。画像だけに頼らず、操作は文でも書く

`bun run content:check` が、記法の誤り・片方のOSしか無い組・書けない場所のブロック・対になっていない画像を検出します。

## 演習(practice.md)のルール

レッスン単位で1本。動画に収まらない手を動かす要素をここへ集約します。

- 必須セクション(この順序):
  1. `## ハンズオン` — TypeScript Playgroundで写経→改造する手順。Playgroundリンクを含める
  2. `## 演習問題` — 2〜4問。難易度を「基本」「応用」で明示
  3. `## 解答例と解説` — `<details>`で折りたたむ
  4. `## 確認クイズ` — 選択式3〜5問。解答は`<details>`で折りたたむ
- 出題範囲はそのレッスンのトピックに限る。後のレッスンの構文を答えに使わない

## コード例のルール

- 変数名・題材は業務っぽい例を優先(user, price, order, task など)。foo/barは使わない
- `console.log`で結果が確認できる形にする(Playgroundで完結させる)
- セミコロンあり、インデント2スペース、文字列はダブルクォート
- **まだ導入していない語・構文を例に混ぜない**。判断は front-matter の語彙台帳で行い、`bun run --filter=@stella/content materials` の検査で担保する
- そのトピックの `takeaway` に関係しない要素をコード例に入れない(5行以内が目安)

## 図解のルール

図解が必要なトピックには、図解を**1枚だけ**入れます(4〜6スライドの「図解 または 対比・失敗例」の枠)。

作図の規約は `.claude/skills/diagram-design/` にすべてあります。型の選び方は `SKILL.md`、配色・書体・寸法は `references/style-guide.md` が正本です。**このファイルに配色やサイズを書き足さないでください。**

- 正本は `assets/<名前>.html`。`slides.md` / `doc.md` からは `assets/<名前>.svg` を参照する(ビルドで生成される)
- 図解が向くもの: 概念の関係、対比、絞り込みのフロー、処理の時系列。コードそのものは図にしない

## 参照元と外部素材

[新設計05](../../docs/curriculum/05-sources-and-attribution.md)と [SOURCE_GUIDE.md](SOURCE_GUIDE.md)に従います。解説・参考例・図・課題のどこに使った資料かを単元の `references.json` に記録し、教材の近くにも出典を表示します。講座末尾の参考リンクだけでは対応の記録になりません。

- `slides.md`・`doc.md`・`knowledge.md`・旧形式の `practice.md` は front-matter の `sourceRefs: [SRC-…]`、課題は `task.json` の `sources` にIDを書きます。IDは `sources/registry.json` に登録します。
- 資料名・作成者・個別ページと節・資料の版または確認日・環境・利用方法を残します。技術のトップページだけを根拠にしません。
- 独自の問題・コード・図は教材用に作成したことを明示し、概念や受入条件の背景資料を結び付けます。架空の原作を付けません。
- コピー・引用・改変と概念の参照を分けます。再利用する場合は条件を確認し、必要な帰属表示を利用する公開教材に残します。「書き直したので不要」と一律に判断しません。
- 自動検査に加え、講師が資料と説明・受入条件の対応を確認し、台帳と使用箇所を `approved` にします。AIの調査やJSONの形式検査だけを講師承認にしません。

新形式は初回公開から、残す旧形式は新規・内容改訂した単元から必須です。未改訂単元の不足は警告として記録します。誤字・表記・レイアウトだけの差分は確認記録を残して区別します。
