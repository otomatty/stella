# ステートメントカバレッジ

テスト設計入門 — Module 4 / レッスン4-1

<!-- ノート: 一番素朴なカバレッジです。分母はコードの文。 -->

---

## なぜ必要か

- 送料計算のテストを 1 件だけ書いて、通った
- コードのどこを踏み残しているのか、目で追うしかない
- 4 行の関数ならまだしも、200 行では追いきれない

<!-- ノート: つかみ。「踏んでいない場所はどこか」を機械が指してくれると、次に書くケースが決まります。 -->

---

## 結論

**ステートメントカバレッジは全部の行を少なくとも 1 回実行したかを測る**

- **ステートメントカバレッジ** — 実行した文 ÷ 全部の文
- 分母は関数の本体にある実行される文(`def` の行や空行は数えない)
- 100% = すべての文が最低 1 回は動いた、という意味だけ

<!-- ノート: 結論を言い切る。定義はこれだけです。「最低 1 回」がこのあと効いてきます。 -->

---

## 4 つの文を数える

```python
def shipping_fee(total):
    fee = 500          # 文1
    if total >= 3000:  # 文2
        fee = 0        # 文3
    return fee         # 文4
```

- 2,999 円で 1 件だけテストすると、**文3 を踏まない** → 3/4 = **75%**
- 3,000 円のケースを足すと 4/4 = **100%**

<!-- ノート: コードの枠。境界値分析で選んだ 2 件が、そのままカバレッジ 100% になっています。技法が先、測定はあと。 -->

---

## 分かること・分からないこと

| | ステートメントカバレッジ |
| --- | --- |
| 分かる | `fee = 0` が一度も動いていない = 穴の位置 |
| 分からない | その文の結果が正しいかどうか |
| 落とし穴 | `assert` を書かずに関数を呼ぶだけでも 100% になる |

<!-- ノート: 対比の枠。カバレッジは「実行したか」しか見ません。期待結果を確かめているのは assert です。 -->
