# 4-3-2
# Given-When-Then

テスト設計入門研修 — Module 4 / レッスン4-3

<!-- ノート: 受け入れ基準の書き方の型です。テストケースの 3 点セットと同じ構造だと気づけるのが狙い。 -->

---

## なぜ必要か

- 受け入れ基準を「3,000 円以上なら送料無料」と 1 行で書いた
- 実装者から質問が来る。「カート画面? 注文確認画面? 送料はどこに出す?」
- 期待だけがあって、前提と操作が書かれていなかった

<!-- ノート: つかみ。1 行で書くと、必ずどれかが抜けます。抜けたぶんは読む人が想像で埋めます。 -->

---

## 結論

**受け入れ基準は前提(Given)・操作(When)・期待(Then)の 3 部で書ける**

- **Given-When-Then** — 受け入れ基準を 3 部に分けて書く型
- Given = そのときの状態、When = 利用者の操作、Then = 観測できる結果
- 3 つの欄が埋まらなければ、まだ決まっていないところがある

<!-- ノート: 結論を言い切る。型の価値は「埋まらない欄が見える」ことです。抜けを検出する道具として使います。 -->

---

## 送料無料を 3 部で書く

| 部 | 内容 |
| --- | --- |
| Given | カートに 3,000 円ぶんの商品が入っている |
| When | 注文確認画面を開く |
| Then | 送料が「0 円」と表示される |

- 境界のもう一方は Given の数字を 2,999 円に変えてもう 1 本書く

<!-- ノート: 具体例の枠。1 本の基準に条件を詰め込まず、Given を変えて本数を増やします。境界値分析と同じ数え方です。 -->

---

## テストケースの 3 点セットと同じ形

| Given-When-Then | テストケース |
| --- | --- |
| Given | 入力・事前の状態 |
| When | 手順 |
| Then | 期待結果 |
