# 表からテストコードへ

テスト設計入門研修 — Module 3 / レッスン3-3

## なぜ必要か

- 6 列の表を作り、テストコードも 6 件書いた
- 半年後、仕様が変わって列が 8 本に戻った
- 表は更新されたが、コードのどれが表のどの列か分からない

<!-- ノート: つかみ。設計とコードの対応が切れると、表は飾りになります。 -->

---

## 結論

**デシジョンテーブルのルール 1 列が、テスト 1 ケースになる**

- 条件の行 → 引数
- ルールの列 → parametrize の 1 組
- アクションの行 → 期待結果

<!-- ノート: 結論を言い切る。境界値の表と写し方は同じです。違うのは、列が縦向きだという点だけ。 -->

---

## R3 と R6 を写す

```python
import pytest
from discount import discount_rate

@pytest.mark.parametrize("premium, coupon, valid, rate", [
    (False, True, True, 5),    # R3: 一般 + 有効クーポン
    (True, True, True, 15),    # R6: プレミアム + 有効クーポン
])
def test_discount_rate(premium, coupon, valid, rate):
    assert discount_rate(premium, coupon, valid) == rate
```

<!-- ノート: コードの枠。コメントの `# R3` が表との対応です。この 4 文字があるだけで、表を直したときにどこを直すかが分かります。 -->

---

## 「−」の列をどう書くか

- 「−」は Y でも N でもよいので、**どちらか一方を選んで書く**
- 選んだ値は表には無い情報なので、コメントに残す
- 迷ったら、実務で起きやすいほう(期限切れより「期限内」など)を選ぶ

<!-- ノート: 対比の枠。「−」のままではコードにできません。ここで値を決めるのはテスト実装者の判断です。判断した記録を残すのが大事。 -->
