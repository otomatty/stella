# 3-2-3
# 3 値の境界値

テスト設計入門 — Module 3 / レッスン3-2

<!-- ノート: 2 値には「どの値を境界と呼ぶか」という判断が残ります。それを消す形です。 -->

---

## なぜ必要か

- 「3,000 円以上で無料」の境界とは、2,999 と 3,000 のどちらの値か
- 有料側の端と読んだ人は、2,998 と 2,999 の 2 件を選んだ
- 判定が切り替わるのは 2,999 と 3,000 の間なので、その組を試していない

<!-- ノート: つかみ。期待結果は仕様から引くので 2 件とも 500 円。実装が `> 3000` でも通ってしまいます。ここで結論は言わない。 -->

---

## 結論

**境界そのものと両隣を試すと、境界の取り違えをより確実に捕まえられる**

- 境界の値・その 1 つ下・その 1 つ上、の 3 件を試す
- どちらの値を境界と考えても、2,999 と 3,000 の組が必ず入る

<!-- ノート: 結論を言い切る。2 値が 1 境界 2 件、3 値が 1 境界 3 件です。 -->

---

## 送料計算の境目で比べる

| 選び方 | 試す値 | 2,999 と 3,000 の組が入るか |
| --- | --- | --- |
| 2 値(境界を 2,999 と読む) | 2,998 / 2,999 | × |
| 2 値(境界を 3,000 と読む) | 2,999 / 3,000 | ○ |
| 3 値(境界を 2,999 と読む) | 2,998 / 2,999 / 3,000 | ○ |
| 3 値(境界を 3,000 と読む) | 2,999 / 3,000 / 3,001 | ○ |

<!-- ノート: 具体例の枠。3 値はどちらの読み方でも、判定が切り替わる組を必ず含みます。増える 1 件が、境界の特定への保険です。 -->

---

## どちらを使うか

| | 件数 | 使いどころ |
| --- | --- | --- |
| 2 値 | 1 境界あたり 2 件 | 既定。まずはこれで全境界を埋める |
| 3 値 | 1 境界あたり 3 件 | 仕様の言葉が曖昧な境界、壊れると影響が大きい境界 |

<!-- ノート: 対比の枠。全部を 3 値にすると件数が 1.5 倍になります。厚くする場所は選びます。選び方はモジュール5のリスクの話につながります。 -->
