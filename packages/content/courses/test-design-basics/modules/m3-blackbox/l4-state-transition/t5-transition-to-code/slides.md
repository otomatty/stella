## なぜ必要か

- 「支払済からキャンセルできる」をテストしたい
- しかし、いきなり支払済の注文は作れない
- 受付から始めて、支払ってから、キャンセルする必要がある

<!-- ノート: つかみ。1 回呼ぶだけでは足りません。そこに至るまでの操作が要ります。 -->

---

## 結論

**状態遷移テストでは、遷移の 1 本が「操作の列+期待する状態」の 1 ケースになる**

- 手順の列が、そこへ至るまでの操作の並び
- 期待結果が、最後のイベントのあとの状態

<!-- ノート: 結論を言い切る。テストケースの 3 点セットのうち「手順」が長くなるのが状態遷移テストの特徴です。 -->

---

## 支払済 → 発送済 を確かめる

```python
from order import Order

def test_pay_then_ship_reaches_shipped():
    order = Order()
    order.handle("支払う")
    assert order.handle("発送する") == "発送済"
```

<!-- ノート: コードの枠。`Order()` が受付、1 行目の `handle` が前提を作る操作、最後の行が確かめたい遷移です。 -->

## 無効な遷移のテスト

```python
import pytest
from order import Order

def test_cannot_ship_before_payment():
    order = Order()
    with pytest.raises(ValueError):
        order.handle("発送する")
```

<!-- ノート: 対比の枠。表の「−」のマスは、この形で書きます。何も起きないのではなく、エラーになることを確かめます。 -->
