# 6-1-1
# テスト観点出し

テスト設計入門研修 — Module 6 / レッスン6-1

<!-- ノート: 総合演習の 1 歩目です。ここまでの 5 モジュールを、1 つの案件に総動員します。 -->

---

## なぜ必要か

- 仕様書を渡され、いきなりケース表を書き始めた
- 送料の境界値は 12 件そろったが、パスワードの長さを 1 件も見ていない
- レビューで「なぜこの機能だけ厚いのですか」と聞かれ、答えられない

<!-- ノート: つかみ。書きやすいところから書くと、網の形が偏ります。ここで結論は言わない。 -->

---

## 結論

**仕様を読んだら、ケースを書く前に「何をテストすべきか」の観点一覧を作る**

- **テスト観点** — 「どこの、何を確かめるか」を 1 行で表した、ケースより粗い単位
- 観点は値を持たない。「パスワードの長さ」までで、「7 文字」はまだ書かない
- 一覧が先にあると、抜けは「行が無いこと」として目に見える

<!-- ノート: 結論を言い切る。ケース表は縦に長くなるので、全体の形は見えません。観点一覧は 20 行程度に収まるので、俯瞰できます。 -->

---

## 案件の仕様(この 1 枚で通す)

| 対象 | 仕様 |
| --- | --- |
| 会員登録フォーム | メール(`@` を含む 1〜254 文字)/ パスワード(8〜32 文字)/ 生年月日(18 歳以上) |
| 料金計算 API | 購入額(1 円以上の整数)・会員区分(一般 / プレミアム)・クーポン(あり / なし) |
| 割引と送料 | プレミアムは 10%、有効クーポンで +5%。**割引後**が 3,000 円以上なら送料 0 円、未満は 500 円 |
| 注文ステータス | 受付 / 支払済 / 発送済 / キャンセル の 4 状態 |
| 制約 | 応答 1 秒以内 / テスト期間 5 営業日・2 名 / クーポンは今回の新規実装 |

<!-- ノート: 具体例の枠。オンラインストアはモジュール2から使ってきた題材です。この 1 枚が、このモジュールの全課題の入力になります。 -->

---

## 観点の粒度をそろえる

| 書き方 | 良し悪し |
| --- | --- |
| パスワードの長さ | ○ 場所と性質がある |
| 会員登録 | × 粗すぎて技法が決まらない |
| パスワードが 7 文字ならエラー | × それはもうテストケース |
| 料金計算 API の応答時間 | ○ 非機能の観点も同じ列に並べる |

<!-- ノート: 対比の枠。粗すぎる行は割り、細かすぎる行はまとめます。目安は「1 行から技法が 1 つ決まる」粒度です。 -->
