# 6-1-3
# ケース表からテストスイートへ

テスト設計入門研修 — Module 6 / レッスン6-1

<!-- ノート: 割り当てた技法どおりに作ったケース表を、実行できる形にまとめます。 -->

---

## なぜ必要か

- 技法ごとにケース表を 4 枚作り、表計算ソフトに保存した
- リリースのたびに 34 件を手で流し、毎回 2 時間かかる
- 3 か月後、表と実装のどちらが正しいのか誰も分からなくなる

<!-- ノート: つかみ。表のままでは、置いた瞬間から古くなっていきます。ここで結論は言わない。 -->

---

## 結論

**ケース表を parametrize に写すと、そのままリグレッション資産になる**

- **テストスイート** — まとめて実行される、テストのひとかたまり
- 観点 1 つ = テスト関数 1 つ、ケース表の 1 行 = 組 1 つ、と対応を決めて写す
- 写した瞬間から、変更のたびに全件が自動で流れる

<!-- ノート: 結論を言い切る。表を保存するのではなく、実行できる形に置き換えるのが最後の一手です。 -->

---

## 観点をテスト関数の単位にする

```python
# 観点4: 割引率の決まり方(デシジョンテーブル)
@pytest.mark.parametrize("rank, coupon, discounted", [
    ("一般", False, 3000),        # R1: 割引なし
    ("プレミアム", True, 2550),    # R4: 会員 10% + クーポン 5%
])
def test_discount_rules(rank, coupon, discounted):
    assert billing(3000, rank, coupon)["discounted"] == discounted
```

<!-- ノート: コードの枠。関数名の上のコメントが観点、組のコメントが技法上の位置づけです。この 2 種類のコメントで、表を捨ててもたどれます。 -->

---

## 表のまま持つ・スイートにする

| | 表計算ソフトの表 | テストスイート |
| --- | --- | --- |
| 実行 | 人が 2 時間 | 機械が数秒 |
| 変更のたび | 流さない回が出る | 毎回全件 |
| 仕様変更に気づく | 気づかない | 落ちて教えてくれる |
| 観点との対応 | 表の題名 | 関数名とコメント |

<!-- ノート: 対比の枠。表が消えるのではなく、表が実行可能な形に移ります。観点の情報だけはコメントで持ち込みます。 -->
