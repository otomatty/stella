# 非機能テスト

テスト設計入門研修 — Module 2 / レッスン2-2

<!-- ノート: 機能テストの合格だけでは足りない部分を扱います。 -->

---

## なぜ必要か

- 料金計算 API は正しい金額を返すが、応答に 8 秒かかる
- 「動いています」と報告したのに、利用者からは「使えない」と言われる

<!-- ノート: つかみ。結果は正しいのに、使えない。機能の合否だけを見ていると説明できない。ここで結論は言わない。 -->

---

## 結論

**非機能テストは性能や使いやすさなど「どう振る舞うか」を確かめる**

- **非機能テスト** — 結果の正しさではなく、その出しかたの性質を見るテストタイプ

<!-- ノート: 結論を言い切る。機能テストが「何を返すか」、非機能テストが「どう返すか」。品質は両方で決まる。 -->

---

## 料金計算 API の非機能テスト

| 見る性質 | 確かめること |
| --- | --- |
| 性能 | 同時 100 件でも 1 秒以内に返るか |
| 使いやすさ | エラー文で利用者が次の操作を選べるか |
| セキュリティ | 他人の会員 ID の金額を引けないか |
| 移植性 | 主要なブラウザーで表示が崩れないか |

<!-- ノート: 具体例の枠。どれも「返す金額が正しいか」とは別の問い。数値の基準を先に決めないとテストにならない点を強調する。 -->

---
