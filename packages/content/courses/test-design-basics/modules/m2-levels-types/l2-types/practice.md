# レッスン2-2 演習 — テストタイプ

対象トピック: 2-2-1 〜 2-2-4

## 手元で試す

引き続き、実行するコードはありません。同じファイルに書き足してください。

題材はオンラインストアの **料金計算 API** です。仕様は次のとおりとします。

- 購入額と会員区分(一般 / 会員)を受け取り、割引額・送料・請求額を返す
- 会員は購入額の 10% を割引する。一般は割引なし
- 送料は 500 円。ただし割引後の金額が 3,000 円以上なら 0 円
- 購入額が 0 円以下のときはエラーを返す

まず、この仕様だけを見て機能テストの表を 5 行ぶん作ります。コードは見ません(見られる状況でも見ないでください)。

| 入力(購入額, 会員区分) | 期待する結果 | 根拠にした仕様の文 |
| --- | --- | --- |
| | | |

根拠の列が埋まらない行があったら、それは仕様から作れていない行です。消すか、根拠にできる文を仕様の中から探してください。

次に、同じ API について非機能テストを 3 つ書きます。ここでは **基準の数値まで書く** のが課題です。

| 見る性質 | 確かめること | 合格の基準 |
| --- | --- | --- |
| 性能 | | |
| 使いやすさ | | |
| セキュリティ | | |

書けたら、次を確かめてください。

- 基準の欄に「速いこと」「分かりやすいこと」と書いていませんか。それでは合否が判定できません
- 使いやすさの基準は数えられる形になっていますか(例: 「エラー文に次に取るべき操作が書かれている」など、あるか無いかで判定できる形)

最後に、いま作った 8 行のテストがブラックボックスとホワイトボックスのどちらであるかに印を付けてください。そのうえで、「仕様には書かれていないが、実装にはありそうな道」を 1 つ想像して書き出してください。それがホワイトボックスの出番です。

## 演習問題

### 問1(基本)

次のうち、非機能テストはどれですか。すべて選んでください。

1. 会員区分が会員のとき、割引額が購入額の 10% になる
2. 同時に 100 件の要求が来ても、応答が 1 秒以内に返る
3. 購入額が 0 円のとき、エラーが返る
4. エラーの文面を読んだ利用者が、次に何をすればよいか分かる

### 問2(基本)

テストレベルとテストタイプが「別の軸」であるとは、どういう意味ですか。例を 1 つ挙げて説明してください。

### 問3(応用)

ある担当者は、実装を読みながらテストケースを作りました。テストは全件合格しましたが、リリース後に「割引後の金額ではなく、割引前の金額で送料を判定していた」という不具合が見つかりました。この作り方の何が問題だったか説明してください。

### 問4(応用)

「ブラックボックステストだけを厚くすれば十分ではないか」という意見に対して、反論を 1 つ書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

2 と 4 が非機能テストです。1 と 3 は「決められた入力に対して決められた結果になるか」を見ているので機能テストです。2 と 4 は結果の正しさではなく、その出しかたの性質(速さ、伝わりやすさ)を見ています。

</details>

<details>
<summary>問2の解答例</summary>

「どこで」テストするかと「何を」確かめるかは、それぞれ独立に決められるという意味です。たとえば割引額の計算関数に値を渡して結果を見るのはコンポーネントテストの機能テスト、その関数を 1 万回呼んで実行時間を測るのはコンポーネントテストの非機能テストです。レベルは同じでもタイプが違います。

</details>

<details>
<summary>問3の解答例</summary>

実装を根拠にテストを作ったため、実装者の解釈をそのまま写してしまったことが問題です。「割引後の金額で判定する」という仕様の文を根拠にしていれば、この食い違いはテストを作る段階で見つかりました。仕様を根拠にするブラックボックスの立場なら、実装がどう書かれていても期待結果は変わりません。

</details>

<details>
<summary>問4の解答例</summary>

ブラックボックスは仕様に書かれていることしか根拠にできません。実装にだけ存在する分岐(例外処理や、後から足された特別扱いの条件)は、仕様を何度読んでも出てきません。そこは一度も実行されないまま本番に出ます。両方を重ねて初めて、見つけられない欠陥の種類を減らせます。

</details>

## 確認クイズ

### Q1. 機能テストが確かめるものはどれですか。

- A. 仕様どおりに動くか
- B. どれくらいの速さで応答するか
- C. コードの分岐をすべて通したか

<details>
<summary>答え</summary>

**A** — 決められた入力に対して、決められた結果になるかを見るテストタイプです。

</details>

### Q2. 非機能テストの説明として正しいものはどれですか。

- A. 仕様書に書かれた機能の一覧を確かめる
- B. 発注者が受け取ってよいかを判断する
- C. 性能や使いやすさなど「どう振る舞うか」を確かめる

<details>
<summary>答え</summary>

**C** — 結果の正しさではなく、その出しかたの性質を見ます。合否を判定するには、基準の数値を先に決めておく必要があります。

</details>

### Q3. ブラックボックステストの根拠になるものはどれですか。

- A. コードの分岐
- B. 仕様
- C. 過去の障害の件数

<details>
<summary>答え</summary>

**B** — 中身を見ず、入力と出力だけで確かめます。根拠が仕様なので、実装を書き換えてもテストは生き残ります。

</details>

### Q4. ホワイトボックステストが得意なものはどれですか。

- A. 実装されていない機能に気づくこと
- B. 発注者の業務が回るかを判断すること
- C. まだ一度も通っていない分岐を見つけること

<details>
<summary>答え</summary>

**C** — コードの構造を根拠にするので、通っていない道を探せます。逆に、コードに書かれていない機能の欠落には気づけません。

</details>

### Q5. テストレベルとテストタイプの関係として正しいものはどれですか。

- A. 別々の軸なので、組み合わせて考える
- B. レベルが決まるとタイプは自動的に決まる
- C. タイプはシステムテストにだけ存在する

<details>
<summary>答え</summary>

**A** — 「どこで」と「何を」は独立に決めます。コンポーネントテストでも機能テストと非機能テストの両方ができます。

</details>
