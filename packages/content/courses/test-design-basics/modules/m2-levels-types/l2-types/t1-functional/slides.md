# 機能テスト

テスト設計入門 — Module 2 / レッスン2-2

## なぜ必要か

- 「テストの一覧を出して」と言われて、操作の手順だけが並んだ表を出した
- 何を確かめたテストなのかが、読む人に伝わらない

<!-- ノート: つかみ。手順は書けても、確かめたい性質で分類できていない状態。ここで結論は言わない。 -->

---

## 結論

**機能テストは「仕様どおりに動くか」を確かめる**

- **テストタイプ** — 何を確かめたいかで分けたテストのまとまり
- **機能テスト** — 決められた入力に対して、決められた結果になるかを見るテストタイプ

<!-- ノート: 結論を言い切る。テストレベルと直交する軸。どのレベルでも機能テストはできる。 -->

---

## 会員登録フォームの機能テスト

| 確かめること | 期待する結果 |
| --- | --- |
| 正しい入力で登録する | 会員が 1 件登録される |
| メールアドレスを空で送る | エラーが表示され、登録されない |
| 登録済みのメールアドレスを送る | 重複エラーが表示される |

<!-- ノート: 具体例の枠。どれも「そうなると決めてあること」を確かめている。1 行が 1 テストケースに対応する。 -->
