# ホワイトボックステスト

テスト設計入門研修 — Module 2 / レッスン2-2

<!-- ノート: 外から見るブラックボックスに対して、中を見る立場です。 -->

---

## なぜ必要か

- 仕様から作ったテストは全部通ったが、コードには一度も通らない行が残っていた
- そこに書かれていた例外処理が、本番で初めて実行されて落ちた

<!-- ノート: つかみ。仕様だけを根拠にすると、実装にしか存在しない道を踏み損ねる。ここで結論は言わない。 -->

---

## 結論

**ホワイトボックステストはコードの構造を見てテストを作る**

- **ホワイトボックス** — 内部の分岐や処理の流れを根拠にテストを作る考え方

<!-- ノート: 結論を言い切る。目的は「まだ通していない道を探す」こと。コンポーネントテストと相性がよい。 -->

---

## 2 つの立場の使い分け

| | ブラックボックス | ホワイトボックス |
| --- | --- | --- |
| 根拠 | 仕様 | コードの構造 |
| 得意 | 仕様の見落とし | 通っていない分岐 |
| 苦手 | 実装だけにある道 | 書かれていない機能 |

<!-- ノート: 対比枠。どちらが上ということはなく、見つけられない欠陥の種類が違う。だから両方を重ねる。 -->
