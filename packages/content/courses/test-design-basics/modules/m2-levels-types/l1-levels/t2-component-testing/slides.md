# コンポーネントテスト

テスト設計入門研修 — Module 2 / レッスン2-1

<!-- ノート: テストレベルの一番下。関数 1 つを相手にする、最も小さいテストです。 -->

---

## なぜ必要か

- 画面から操作して確かめるので、1 パターン試すのに 3 分かかる
- 割引の計算が合わないが、画面・API・DB のどこが原因か分からない

<!-- ノート: つかみ。大きい単位でしかテストしていないと、遅いうえに原因の切り分けができない。ここで結論は言わない。 -->

---

## 結論

**関数やクラスの単位で、小さく速いテストを数多く回す**

- **コンポーネントテスト** — 単体で切り離せるモジュール 1 つを対象にするテストレベル

<!-- ノート: 結論を言い切る。対象が小さいほど、失敗したときに疑う場所が狭い。速いので数を打てる。 -->

---

## 料金計算 API の割引関数を単体で試す

| 入力(購入額, 会員区分) | 期待する割引額 |
| --- | --- |
| 1,000 / 一般 | 0 円 |
| 1,000 / 会員 | 100 円 |
| 0 / 会員 | 0 円 |

<!-- ノート: 具体例の枠。画面も DB も通さず、関数に値を渡して戻り値を見るだけ。1 テストケースが 1 行の表になっている点に注目させる。 -->
