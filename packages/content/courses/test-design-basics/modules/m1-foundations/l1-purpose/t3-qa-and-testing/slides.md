# 品質保証とテスト

テスト設計入門研修 — Module 1 / レッスン1-1

<!-- ノート: 3本目。「QA担当」という肩書きの中身を、テストとの関係で整理します。 -->

---

## なぜ必要か

- 不具合が出るたびに「テストが甘い」と言われる
- テストを増やしても、同じ種類の不具合が翌月また出る

<!-- ノート: つかみ。出口だけを厚くしても入口が変わらない状態。ここで結論は言わない。 -->

---

## 結論

**品質保証(QA)はプロセス全体を良くする活動で、テストはその一部である**

- **品質保証** — 良いものが出来上がる作り方そのものを整える活動
- テストは、その作り方が機能しているかを確かめる手段のひとつ

<!-- ノート: 結論を言い切る。QA = テスト担当、という誤解をここで解く。 -->

---

## 品質保証の打ち手、テストはそのひとつ

| 打ち手 | 効く場所 |
| --- | --- |
| 仕様のレビュー | 作る前 |
| コーディング規約 | 作っている最中 |
| **テスト** | 出来上がったもの |
| ふりかえり | 次の周回 |

<!-- ノート: 具体例の枠。テストは4つのうちの1つ。テストだけを厚くしても、他の3つが弱いままなら同じ不具合が戻ってくる。 -->
