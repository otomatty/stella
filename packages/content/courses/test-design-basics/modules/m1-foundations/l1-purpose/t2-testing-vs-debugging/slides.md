# テストとデバッグ

テスト設計入門研修 — Module 1 / レッスン1-1

<!-- ノート: 2本目。現場で最も混ざりやすい2つの作業を、最初に切り分けます。 -->

---

## なぜ必要か

- テストの途中で気になった箇所を追いかけ始め、半日が消える
- 「テストに時間がかかった」と報告するが、中身は原因調査だった

<!-- ノート: つかみ。時間の使い道が説明できなくなるあるある。ここで結論は言わない。 -->

---

## 結論

**テストは欠陥を見つける活動で、デバッグは原因を探して直す別の活動である**

- **欠陥** — コードや設計に埋め込まれた、正しくない箇所
- **デバッグ** — その欠陥の位置と原因を突き止めて修正する作業

<!-- ノート: 結論を言い切る。見つけるのがテスト、直すのがデバッグ。担当者が同じでも作業は別物。 -->

---

## 同じ不具合を、2つの作業で追う

| | テスト | デバッグ |
| --- | --- | --- |
| 目的 | 欠陥があることを示す | 欠陥を取り除く |
| 出力 | 「この操作で結果が違う」 | 「この行の条件が逆だった」 |
| 終わり方 | 報告した時点 | 直って再確認できた時点 |

<!-- ノート: 対比枠。テストの出力は現象、デバッグの出力は原因と修正。報告の粒度がここで変わる。 -->
