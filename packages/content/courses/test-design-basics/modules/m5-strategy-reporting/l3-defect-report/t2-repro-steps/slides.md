# 再現手順

テスト設計入門研修 — Module 5 / レッスン5-3

<!-- ノート: 4 つの部品のうち、いちばん差が出るところです。 -->

---

## なぜ必要か

- 「カートで送料がおかしくなります」と報告した
- 開発者が同じ画面を開いても、送料は正しい
- あとで分かったのは、**クーポンを適用したあとに商品を追加したとき**だけの故障だった

<!-- ノート: つかみ。書いた本人は「カートを開いた」としか覚えていません。ここで結論は言わない。 -->

---

## 結論

**再現手順には環境と操作を、読んだ人がそのままなぞれる粒度で書く**

- **再現手順** — 故障を起こすまでの操作を、順番に並べたもの
- 粒度の基準は「その機能を知らない人が、迷わず同じ操作をできるか」
- 使ったデータ(商品名・金額・アカウント)は**具体値で書く**

<!-- ノート: 結論を言い切る。「適当な商品を入れる」は手順ではありません。どの商品かで結果が変わるからです。 -->

---

## 書き直しの例

| | 書き方 |
| --- | --- |
| 悪い | カートで送料がおかしくなる |
| 良い | 1. 一般会員でログイン(test-user01) / 2. 商品「マグカップ 2,000 円」をカートに入れる / 3. クーポン `SEND100` を適用 / 4. 商品「ノート 1,500 円」を追加 / 5. カート画面の送料欄を見る |

<!-- ノート: 具体例の枠。番号付きで、1 行 1 操作。5 行あれば大抵の故障は再現できます。 -->

---

## 環境も手順の一部

- ブラウザーと版(Chrome 126 / Safari 17)
- OS と端末(Windows 11 / iPhone 15、画面幅)
- アカウントとデータ(一般会員か、プレミアム会員か)
- いつ起きたか(日時。時間帯で変わる不具合があるため)

<!-- ノート: 対比の枠。「私の環境では再現しません」の半分は、ここが書かれていないことが原因です。 -->
