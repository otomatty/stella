# Claude チャット入門 カリキュラム

Claude をチャットで使うときの「進め方」を扱う講座です。claude.ai の会話・Projects・Artifacts までが範囲です。
1 トピック = 覚えることが 1 つ(takeaway 1 文)の粒度で、**対話の場を知る → 依頼を書く →
文脈と成果物を置く → 次に進む先を選ぶ** の順に通します。Claude 研修シリーズの 2 本目にあたり、
1 本目(AI駆動開発の考え方)で学んだ 4D を、実際の画面の上で使う位置づけです。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- 手を動かす部分: `practice.md` の「手元で試す」。claude.ai を開いて、会話・Project・Artifact を自分で作ります
- **アカウントが無くても完走できます。** 「手元で試す」は任意で、スライド・まとめ・確認クイズだけで修了条件を満たします
- コード演習(VS Code 拡張の採点)は **この講座にはありません**。学習対象が画面上の進め方であってコードではないため、
  `course.json` に `exercises` を持ちません
- 前提講座: **AI駆動開発の考え方(`ai-fluency-basics`)**。4D(任せる / 伝える / 見極める / 責任を持つ)を
  一度通していることを想定します。ただし語彙台帳は講座をまたがないため、必要な語はこの講座で導入し直します
- 対象外:
  - Cowork / Claude Code の操作手順・インストール・画面説明(M3 は「次に何があるか」の紹介だけ)
  - API・SDK・課金・管理者設定
  - モデルの選び方、価格、上限値などの当日値
  - プロンプトのテクニック集(定型文・呪文の一覧)
  - LLM の内部構造(1 本目の講座で扱う範囲)

## 到達目標

1. 新しい会話を始め、目的を伝えて返答を **取れる**
2. 成果物・手順・できの基準を入れた依頼を **書ける**
3. Project に文脈を置き、会話ごとに説明し直さない使い方を **選べる**
4. Artifact に残すものとチャットに残すものを **分けられる**
5. チャット / Cowork / Claude Code のどれに進むかを **説明できる**(操作は後続講座)

表の `introduces` はそのトピックで新しく導入する語、`requires` は前提として使う語です。
**この表が語彙台帳の正本**で、各 `slides.md` の front-matter にそのまま写します。並びは学習順(パスの自然順)で、
`requires` の語はすべて、それより上の行の `introduces` に現れます(`check_vocab.mjs` が検査します)。

## この講座の進め方

- 各レッスンは **スライド → まとめ → 確認クイズ** の順で並びます
- `practice.md` の「手元で試す」は claude.ai を開いて行います。目的を書いた会話を 1 本作る、丸投げの依頼を書き直す、
  Project に前提を置いて会話を 2 本作る、Artifact を持ち出す形に直す、といった課題で、自動採点はありません
- **アカウントが無い受講者は「手元で試す」を飛ばして構いません。** その場合もスライドと確認クイズだけで完走できます。
  クイズは操作の再現ではなく判断を問うため、画面を触っていなくても解けます
- 画面の並びやボタンの名前は変わります。困ったら製品のドキュメントを見る前提で、本文は「何のための機能か」だけを扱います
- スマートフォンからでも、スライドとまとめと確認クイズだけで最後まで進められます

## 設計メモ(申し送り)

- **語彙台帳は講座をまたぎません。** `ai-fluency-basics` で説明済みの語も、この講座で `introduces` し直しています。
  再導入した語は 生成AI / プロンプト / 4D / 任せる / 伝える / 見極める / 責任を持つ / 依頼 / 成果物 / できの基準 /
  手順 / 制約 / 材料 / コンテキスト / 機密情報 / 仮説 の 16 語です。**再導入は 1 行の復習で済ませ、初出のような
  長い説明にしないでください。** スライドでは「講座1で扱った語です」と一言添え、残りの時間を画面の上での使い方に使います
- **4D の 5 語(4D と 4 つの日本語名)は M1 の 1-1-1 にまとめました。** M1 は講座1の Description(伝える)を
  画面の上でやるレッスンなので、ここで 4D を配ると台帳の上でも接続が見えます。1-1-1 は導入語が 6 語と多いので、
  スライドでは 4D の一覧図 1 枚に集約し、任せる / 見極める / 責任を持つ は 1 語 1 行に抑えてください
  (中身は M2・M3 の該当トピックで使います)
- **M0-1-4「渡していない事情は知らない」は、M2 の Project と対になる伏線です。** 会話ごとに材料を渡し直す不便を先に
  体感させ、M2-1-1 で「だから置き場がある」に着地させます。M0 の側で Project を先出ししないでください
- **M2-1-4「置く前に機密情報かを確かめる」は、材料を貼る話の締めです。** M0・M1 では「渡すほど当たる」を教え、
  ナレッジという「ためる場所」が出てから「ただし渡してよいものに限る」で締めます。M0・M1 側で機密の話を先出ししないでください
- **画面の名称に寄りかからないでください。** ボタン名・メニューの位置・画面の並びは変わる前提です。
  takeaway は「何のためにその機能があるか」に置き、**ボタン名だけが takeaway のトピックは作りません**。
  `ナレッジ` / `指示の固定` / `Artifact` は画面上の呼び名が変わりうる語ですが、takeaway 側(貼り直さない・書かずに済む・
  持ち出して使う)は変わりません。スライドでは呼び名を 1 行で紹介し、残りは目的の説明に使ってください
- **M3 で操作を書かないでください。** Cowork と Claude Code は「次に何があるか」の予告です。インストール手順・
  画面写真・コマンド・料金は書きません。3-2-3 の使い分けまでで止め、操作は後続講座に置きます
- **1 年後も通用する範囲に絞りました。** モデル名・価格・添付できる上限値・無料枠の条件は本文に書きません。
  「上限がある」ことは概念として扱い、実際の値は製品のドキュメントを見る、という書き方にします
- **評価は確認クイズと手元ハンズオンだけです。** 到達目標 1〜5 はすべて判断を問うため、クイズは用語の暗記ではなく
  「この依頼に足りない要素はどれか」「この材料は Project とチャットのどちらに置くか」「この仕事はどれで進めるか」という
  選択問題にしてください。アカウントの有無で有利不利が出る設問(画面の色・ボタンの位置)は作りません
- **コード演習は配線しません。** 学習対象が画面上の進め方なので、`course.json` に `exercises` を持ちません
- **サムネイルは生成済みです。** `packages/content/scripts/build_thumbnails.py` の `SPECS` に `claude-chat-basics` を
  登録してあり、出力は `thumbnail.webp` です。モチーフは「依頼と返答の吹き出しの往復」で、この講座の中身(チャットは対話)を
  1 つだけ図にしています。文言やモチーフを変えたときは
  `python packages/content/scripts/build_thumbnails.py claude-chat-basics` で再生成してください。手描きはしません。
  既存講座と 1 つのシリーズに見えることが前提なので、色や版面はスクリプトに任せ、外部ロゴは使いません
- **シリーズの続きは別 slug です。** Cowork / Claude Code の操作講座はこの講座に足さず、後続講座に置きます。
  この講座を大きくしないことが、シリーズ 2 本目としての役割です
