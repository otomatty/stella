# レッスン0-1 チャットは対話

## このレッスンの目標

- [ ] Claudeに何をどう頼めるかを説明できる
- [ ] claude.aiの会話がどういう単位かを説明できる
- [ ] チャットを検索ではなく対話として扱える

## 0-1-1 Claudeは文章で頼める相手

> **Claudeは、文章のやり取りで仕事を頼める生成AIです**

まず、この講座で使う言葉をそろえます。

- **生成AI** — 文章やコードなど、新しい内容を作り出すAIです。講座1で扱った語です
- **Claude** — Anthropic が提供している生成AIです
- **チャット** — 文章を送り、返ってきた文章を読む形式のやり取りです

新しい道具を前にすると、まず操作を覚えなければと身構えます。ところがチャットで頼むときに覚えることは、画面の手順ではありません。渡すのも受け取るのも、ふつうの文章だからです。

実務では、たとえば次のような頼み方ができます。

```text
長い議事録    → 要点を3行にまとめてもらう
仕様の下書き  → 抜けている観点を挙げてもらう
エラーの文面  → 考えられる原因を並べてもらう
```

3つに共通しているのは、**入力欄に決まった項目が無い** ことです。用途ごとに専用の画面があるのではなく、文章で書ける範囲がそのまま頼める範囲になります。

| | 専用の道具 | チャット |
| --- | --- | --- |
| 覚えること | 画面と手順 | どう頼むか |
| 入力するもの | 決まった項目 | ふつうの文章 |
| 頼める幅 | 用途ごとに固定 | 文章で書ける範囲 |

学ぶ対象が操作ではなく頼み方である、というのがこの講座全体の前提です。画面の並びやボタンの名前は変わりますが、頼み方の考え方は変わりません。

## 0-1-2 claude.aiは会話を置く場所

> **claude.aiは、Claudeとのやり取りを会話という単位で置いておく場所です**

**claude.ai** は、ブラウザーからClaudeにチャットで頼むためのサービスです。ここで扱う中心の単位が **会話** です。会話とは、1つの話題についてのやり取りをひとまとめにした入れ物を指します。

文章を送って返ってきたら終わり、ではありません。送った文章と返ってきた文章が順番に積まれ、1本の会話として残ります。別の話題を始めれば、別の会話ができます。

```text
claude.ai
├ 会話1: 障害チケットの一次調査
├ 会話2: 週次報告の下書き
└ 会話3: 新しいライブラリの調査
```

この形になっていることで、2つのことができます。1つは、後から同じ会話を開き直して続きを頼めることです。もう1つは、話題ごとに置き場を分けられることです。

| | 使い捨ての入力欄 | claude.aiの会話 |
| --- | --- | --- |
| 送った後 | 消える | 残る |
| まとまり | 1回ぶん | 1つの話題ぶん |
| 後から | 探せない | 開き直せる |

「いまどの会話に書いているか」を意識するだけで、後から探せないという状態は起きにくくなります。

## 0-1-3 チャットは検索窓ではない

> **チャットは一度で正解を引く検索ではなく、やり取りを重ねて近づける対話です**

置き場所が分かったところで、その中でどう振る舞うかに移ります。ここが最初のつまずきどころです。

多くの人は、無意識に検索と同じ手つきでチャットを使います。**検索** とは、一度の入力で目的の情報を1発で引き当てる使い方です。うまくいかなければ、言葉を変えて引き直します。

チャットで扱うのは **対話** です。対話とは、こちらと相手が交互に補い合って、ほしいものへ近づけていく進め方を指します。1回目は答えではなく、たたき台として受け取ります。

```text
検索のつもり
  自分「テストの観点を教えて」
  → 一般的な観点が並ぶ。閉じる

対話のつもり
  自分「テストの観点を教えて」
  → 一般的な観点が並ぶ
  自分「対象は入会フォームです。入力値に絞って」
  → 絞られる
  自分「異常系だけ、表で」
  → ほしい形になる
```

2つを比べると、送った文章の総量はそれほど変わりません。違うのは、**返ってきたものを見てから足している** 点です。

| | 検索 | 対話 |
| --- | --- | --- |
| 1回目の位置づけ | 答え | たたき台 |
| ずれたとき | 言葉を変えて引き直す | ずれた点を伝えて続ける |
| 前の入力 | 関係ない | 引き継がれる |

いちばん効いてくるのは3行目です。同じ会話の中では、前のやり取りが土台として残ります。だから2回目以降は短い一言で足りるのです。1回で当てようとして長い文章を練るより、短く投げて寄せていくほうが早く着きます。

## 0-1-4 渡していない事情は知らない

> **Claudeは、この会話に渡していない社内の事情や今回の対象は知りません**

対話の相手が何を知っていて、何を知らないのかを押さえます。判断のもとになる情報を **材料** と呼びます。講座1で扱った語です。

Claudeは、学習した範囲の一般的な知識には何も渡さなくても答えられます。知らないのは、社内の規約や今回のコードのように、**この会話に渡していないもの** のほうです。

「うちのやり方に合わせて」と書いたのに一般論が返ってきた、という経験はよくあります。原因は頼み方の巧拙ではありません。**その会話に材料を渡していない** からです。一般論しか材料が無ければ、返ってくるのも一般論になります。

```text
渡していない
  自分「この関数のテストを書いて」
  → 何の関数か分からず、一般的な例が返る

渡した
  自分「この関数のテストを書いて」+ 関数のコードを貼る
  → その関数に沿ったテストが返る
```

「この」という言葉は、こちらの頭の中でしか指し先が決まっていません。返ってくる内容の質は、言い回しよりも先に、手元に材料があるかどうかで決まります。

ここで、もう1つ性質を確かめておきます。材料が使えるのは、それを渡した会話の中だけです。

| | 同じ会話の中 | 別の会話 |
| --- | --- | --- |
| 前に貼った材料 | 使える | 使えない |
| こちらの手間 | 足すだけ | 一から貼り直す |

つまり、同じ前提をよく使う仕事では、会話を始めるたびに同じ材料を貼り直すことになります。手間ですし、貼り忘れれば返ってくる内容もずれます。この不便は、いまの段階では「そういうものだ」と覚えておいてください。

## もっと知りたい人へ

- 自分が直近でチャットに投げた文章を1つ思い出し、**それだけで相手に伝わるか** を読み返してみてください。「この」「例の」で済ませた箇所が見つかるはずです
- 画面の並びや呼び名は変わります。操作で迷ったときは、使っている製品の公式ドキュメントで最新のものを確認してください
