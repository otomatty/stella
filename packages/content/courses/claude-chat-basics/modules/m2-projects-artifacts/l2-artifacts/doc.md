# レッスン2-2 Artifactに成果物を置く

## このレッスンの目標

- [ ] Artifactが何のための枠かを説明できる
- [ ] 会話に残すものとArtifactに置くものを分けられる
- [ ] 持ち出す前に中身を確かめる手順を言える

## 2-2-1 Artifactは成果物そのものの枠

> **Artifactは、やり取りの流れとは別に成果物そのものを表示する枠です**

前半のレッスンでは、こちらから渡すものの置き場を扱いました。ここからは、出てきたものの置き場です。

長い文書を頼むと、返答の文章の中に本文が混ざって出てきます。「ご要望の手順書は以下のとおりです」という一言のあとに、本文が続く形です。1回で終わるならこれで困りません。困るのは直しを繰り返したときです。

```text
会話の流れ
  返答1: 手順書の全文
  自分:  もう少し短く
  返答2: 手順書の全文(短い版)
  自分:  用語をそろえて
  返答3: 手順書の全文(用語をそろえた版)
```

提出する段になって、上へさかのぼって最新版を探すことになります。しかも、途中の相談と本文が同じ列に並んでいるので、どこからどこまでが成果物なのかも見分けにくくなります。

**Artifact** は、この問題のための枠です。会話の横に開き、成果物だけを入れておきます。画面での呼び名は変わることがありますが、役割は変わりません。

| | 会話の中 | Artifactの枠 |
| --- | --- | --- |
| 並び方 | 発言が下へ流れる | 1つの内容が残る |
| 最新はどれか | さかのぼって探す | 枠を見れば分かる |
| 向くもの | 相談、短い答え | 文書、表、下書き |

要するに、**流れる場所と留まる場所** を分けているだけです。相談は流れて構いません。成果物には留まってほしい。この違いが、枠がある理由です。

## 2-2-2 Artifactは直すたびに版が増える

> **Artifactは直しを伝えるたびに新しい版になり、前の版も残ります**

枠に入れた成果物は、そのまま育てていきます。育て方は、これまでと同じ言い直しです。

直しを頼むとき、多くの人がためらいます。「直してもらったら、前のほうがよかった」という経験があるからです。そうなると、直すたびに別の場所へコピーを取っておく、という手間が増えます。

Artifactではその心配が要りません。直しを伝えるたびに新しい **版** ができ、前の版も残るからです。版とは、直したその時点の内容ひとかたまりのことです。画面での呼び名は変わることがありますが、役割は変わりません。

```text
版1  最初に出てきた下書き
  ↓ 「もっと短く」と言い直す
版2  短くなった下書き
  ↓ 「箇条書きを表にして」と言い直す
版3  表になった下書き

版1と版2も残っている
```

上書きではなく積み上がる、という点が要です。これが分かっていると、頼み方が変わります。**戻れる前提があるので、思い切った直しを試せます。**

うまく育てるこつが1つあります。1回の言い直しで直すのは1か所にすることです。

- まとめて5つ直すと、どの指示が効いたのか分からなくなります
- 気に入らなかったとき、どこまで戻せばよいかも分からなくなります
- 1つずつ直せば、版と版を比べて良し悪しを判断できます

急がば回れで、結果的にはこのほうが早く仕上がります。

## 2-2-3 Artifactに置くのは持ち出すもの

> **Artifactには、会話の外へ持ち出して使うものだけを置きます**

便利な枠ができると、今度は何でも入れたくなります。用語の確認の答えまで枠になり、本命の成果物がどれか分からなくなります。逆に、提出する文書を会話の中に流したままにしてしまうこともあります。

基準を1つ決めておきます。会話の外にある文書やチケットへ内容を移して使うことを **持ち出し** と呼びます。Artifactに置くのは、持ち出すものだけです。

| | 置く(Artifact) | 会話のまま |
| --- | --- | --- |
| 使う場所 | 会話の外 | この会話の中 |
| 例 | 手順書、報告の下書き、比較表 | 用語の確認、方針の相談、考えの整理 |
| 会話を閉じたら | 使い続ける | 用が済んでいる |

判断には、次の一問を使います。

> **この会話を閉じたあとも、これを使いますか**

「はい」なら枠に置きます。「いいえ」なら会話のままで十分です。長さや出来のよさは基準になりません。3行の表でも社内に配るなら持ち出しですし、20行の説明でも自分が納得するためだけのものなら会話のままでよいのです。

なお、この基準はレッスン2-1の基準と形がそろっています。**変わらないものはナレッジへ、持ち出すものはArtifactへ、それ以外は会話の中** です。3つの置き場を、それぞれ一問で振り分けていることになります。

## 2-2-4 仕上がって見えても仮説

> **Artifactは体裁が整って見えても、確かめるまでは仮説です**

最後に、持ち出す前の話をします。

Artifactの中身は、見出しがつき、表が整い、体裁が仕上がって見えます。ここに落とし穴があります。会話の中の文章なら読み直すのに、枠に入った内容は読み飛ばしてしまうのです。そのまま持ち出して、数字の誤りを提出先で指摘される、という失敗が起きます。

**仮説** とは、確かめるまで正しいと決まっていない内容のことです。講座1で扱った語です。Claudeが返したものは、会話の中でもArtifactの中でも、等しく仮説です。

| | 会話の中の返答 | Artifactの中身 |
| --- | --- | --- |
| 見え方 | 途中の話に見える | 完成品に見える |
| 読み手の反応 | 確かめようとする | そのまま使いたくなる |
| 実際の確かさ | 同じ | 同じ |

3行目が要です。**枠に入れても、中身の確かさは1ミリも上がりません。** 上がるのは見た目の説得力だけです。体裁が整うほど確かめたくなくなる、というのがArtifact特有の危うさです。

そこで、持ち出す前に3つを自問します。これは4Dの「見極める」を枠の中身に対して行うことにあたります。

- **数字と固有名詞の出どころを、自分で確かめたか** — 件数、金額、日付、製品名、担当者名
- **手元の資料や実物と、食い違っていないか** — 実際の設定や仕様と突き合わせる
- **自分の名前で出せるか** — 中身を聞かれて説明できる状態か

3つとも「はい」になってから持ち出します。1つでも「いいえ」があるなら、それはまだ仮説のまま外へ出そうとしている状態です。

確かめる手間を惜しまないでください。ここまでの2つのレッスンで、前提を置き、成果物を育てる速さを手に入れました。速くなったぶん、確かめる工程だけは残す。それがこのモジュールの締めです。

## もっと知りたい人へ

- 直しを重ねると版が増えます。増えた版を全部残す必要はありませんが、「これでよい」と決めた版がどれかは、持ち出すときに自分で分かっている必要があります。迷ったら持ち出す前に通しで1回読んでください
- 確かめる作業をClaudeに頼むこともできますが、それも仮説が1つ増えるだけです。事実の確認は、手元の資料や実際の画面に当たるのがいちばん確実です
- 画面の並びや呼び名は変わります。枠そのものの操作で迷ったときは、使っている製品のドキュメントで最新のものを確認してください
