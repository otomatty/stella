# レッスン3-1 Claudeを広げる仕組み

## このレッスンの目標

- [ ] コネクタが何のためにあるかを説明できる
- [ ] Skillsが何のためにあるかを説明できる
- [ ] 仕組みで固定するのはいつかを、順序として説明できる

## 3-1-1 コネクタは外の道具につなぐ

> **コネクタは、会話の外にある道具やデータをClaudeの材料にする仕組みです**

M0で、Claudeはこの会話に渡していない社内の事情や今回の対象を知らない、と扱いました。だからこそ、こちらが **材料** を渡す必要があります。ここまでは、その渡し方が「会話に書く」「会話に貼る」の2つでした。

この形には、運び役が毎回自分になるという弱点があります。予定表を見に行き、必要な部分を写し、会話に貼る。元の資料が更新されれば、また同じことをやり直します。仕事そのものではなく、材料を運ぶ往復に時間が消えていきます。

そこで出てくるのが、次の2つの語です。

- **ツール** — Claudeが会話の外に対して使える道具です
- **コネクタ** — 外の道具やデータの置き場を、Claudeにつなぐ仕組みです

つないでおくと、材料を運ぶのが自分ではなく仕組みの側になります。つなぐ先は、たとえば次のようなものです。

```text
予定表           → 今週の空き時間を材料にする
社内の資料置き場 → 該当ページを材料にする
課題の一覧       → 担当中の項目を材料にする
```

どれも、自分でコピーして貼れば同じ内容を渡せます。違うのは、渡す手間が毎回かかるか、最初だけかかるかです。

| | 会話に貼る | コネクタでつなぐ |
| --- | --- | --- |
| 材料の運び役 | 自分 | 仕組み |
| 更新への追従 | 貼り直す | つないだ先を見る |
| 準備の手間 | 毎回かかる | 最初だけかかる |

いちばん下の行が、このあとの3-1-3につながります。最初だけとはいえ手間はかかるので、つなぐ価値があるかどうかは、その材料を何度使うかで決まります。

なお、何につなげるか、どうつなぐかは製品側の話で、しかも増えていきます。この講座で持ち帰るのは「材料の渡し方には、貼る以外の道がある」という一点です。

## 3-1-2 Skillsは進め方の作り置き

> **Skillsは、毎回説明していた進め方をClaudeが読める形で作り置きする仕組みです**

コネクタが材料の話だとすると、こちらは進め方の話です。

M1で、依頼には成果物・できの基準・必要なら **手順** や制約を書く、と扱いました。ここで起きるのが、同じ説明を何度も書くという状態です。報告書の体裁、見積もりの単位、レビューで必ず見る観点。案件が変わっても、書いている内容はほとんど同じです。

**Skills** は、この「毎回書いていた進め方」を、Claudeが読める形で置いておく仕組みです。置いておくと、依頼のたびに書き直さずに済みます。

```text
報告書の体裁     → 見出しの並びと分量の決まり
見積もりの出し方 → 数える単位と丸め方
レビューの観点   → 毎回見るべき項目の一覧
```

作り置きの効き目は、手間が減ることだけではありません。

| | 依頼に毎回書く | Skillsに置く |
| --- | --- | --- |
| 書く手間 | 依頼のたび | 作るときだけ |
| そろい方 | 書いた人しだい | 読ませた分だけそろう |
| 直したいとき | 次の依頼から直す | 置いたものを直す |

いちばん効くのは、いちばん下の行です。依頼に毎回書く形だと、決まりを変えたときに全員へ周知が要ります。仕組みの側に置いてあれば、置いたものを1か所直すだけで済みます。

置き方や作り方は製品の操作の話なので、この講座では扱いません。ここでは「進め方も、会話の外に置ける」という考え方だけを持ち帰ってください。

## 3-1-3 広げるのは繰り返しが見えてから

> **同じ依頼の繰り返しに気づいてから、仕組みで固定するほうが無駄になりません**

仕組みを2つ知ったところで、順番の話をします。新しい仕組みを知ると、まず環境を整えたくなります。ところが、整え終えたころにはその仕事がもう来ない、ということが起こります。

判断の材料になるのが **繰り返し** です。繰り返しとは、同じ形の依頼を、会話をまたいで何度も書いている状態を指します。

```text
1回目  会話にそのまま書く
2回目  同じことを書いている、と気づく
3回目  会話の外に固定するか決める
```

回数はあくまで目安です。要は、繰り返しが自分の目に見えたかどうかです。見えていないうちは、会話にそのまま書くのがいちばん早い方法です。

繰り返しが見えたら、次は置き場所を決めます。ここでM2の **指示の固定** が効いてきます。

| | 指示の固定(Project) | Skills・コネクタ |
| --- | --- | --- |
| どこに置くか | 会話の中の前提 | 会話の外の仕組み |
| 効く範囲 | そのProjectの会話 | 呼び出したとき |
| 向く場面 | 案件ごとの決まり | 案件をまたぐ決まり |

順番としては、まずProjectで足りるかを考えます。その案件の中だけで繰り返しているなら、Projectに固定すれば十分です。案件をまたいで同じことを書いているなら、そこで初めて仕組みに出す価値が出ます。

この順番を守ると、作ったのに使わなかった、という無駄が減ります。逆に言えば、繰り返しが見えていない段階で仕組みを整えるのは、まだ早いということです。

## もっと知りたい人へ

- 直近1か月に自分が書いた依頼を見返して、同じ説明を何回書いたか数えてみてください。3回を超えていれば、固定を考える段階です
- コネクタでつなげる先や、Skillsの置き方は製品側の機能で、変わっていきます。実際に使うときは、使っている製品のドキュメントで確認してください
- 実際に作って動かす手順は、この講座の範囲外です。後続の講座で扱います
