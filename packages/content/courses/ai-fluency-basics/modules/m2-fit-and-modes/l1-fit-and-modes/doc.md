# レッスン2-1 どこで使い、どう関わるか

## このレッスンの目標

- [ ] 答えの幅と検証コストで、仕事の向き不向きを判断できる
- [ ] 自動化・拡張・委任の3モードを区別できる
- [ ] 主導権を軸に、目の前の仕事でモードを選べる

## 2-1-1 向くのは答えの幅が広い仕事

> **たたき台づくりのように、答えの幅が広い仕事はAIに向きます**

仕事の性質によって決まるAIの得意・不得意を **向き不向き** と呼びます。使い方が上手いかどうかより先に、この相性が結果を決めます。

向く側の目印は **答えの幅** です。正解が1つに決まらず、候補がいくつもあり、そこから選び直せる仕事です。代表が **たたき台** づくり、つまりあとで直す前提の最初の下書きです。

```text
テスト観点の洗い出し → 抜けを見つけたい。数が要る
障害報告の下書き     → 形を整えたい。直す前提でよい
実装案を3つ並べる     → 選択肢がほしい。選ぶのは自分
```

3つに共通するのは、**出力をそのまま使わず、自分が選び直す前提** になっていることです。だからこそ、多少ずれた案が混じっていても損になりません。むしろ、思いつかなかった案が1つ混じれば得です。

| | 幅が広い | 幅が狭い |
| --- | --- | --- |
| 正解 | いくつもある | 1つに決まる |
| 受け取り方 | 直す前提 | そのまま使う前提 |
| 例 | 命名の候補を出す | 締め日の残高を確定する |

幅が狭い仕事がすべて駄目だという話ではありません。判断の軸はもう1つあり、それを次で扱います。

## 2-1-2 向かないのは確かめが重い仕事

> **出力を確かめる手間(検証コスト)が自分でやるより重い仕事は、AIに向きません**

出力が正しいかを確かめるのにかかる手間を **検証コスト** と呼びます。向き不向きの、もう1本の軸です。

「AIに任せたら速くなるはず」と考えて遅くなる場面は、たいていここです。出だしは速いのですが、確認に時間を取られます。判断は、確認まで含めた合計で比べてください。

```text
自分で書く   : 30分
AIに書かせる : 5分 ＋ 確認 60分 ＝ 65分
```

この場合は自分で書いたほうが速い、というだけの話です。逆に、確認が5分で済むなら迷わず渡します。

検証コストが重くなるのは、次のような場面です。

| 場面 | なぜ重いか |
| --- | --- |
| 金額や件数の集計 | 幻覚が1か所混じるだけで、全件を突き合わせることになる |
| 出たばかりの仕様 | 知識の切れ目の外なので、結局こちらが資料を読み直す |
| 前例のない社内の判断 | 正しさを測る基準が手元にしかない |

3つとも、**確かめる側の負担が消えない** 点が共通しています。ここが向かない側の見分け方です。

なお、検証コストは仕事の種類だけで決まるものではありません。自分がその分野に詳しければ、確認は速く終わります。詳しくない分野ほど確認は重くなり、渡す判断は慎重になります。

## 2-1-3 関わり方は3モードに分かれる

> **AIとの関わり方は、自動化・拡張・委任の3モードに分かれます**

使う場所が決まったら、次は関わり方です。関わり方の型は3つに分かれます。これを **3モード** と呼びます。

- **自動化** — 決まった処理を投げ、人は結果を受け取るだけです
- **拡張** — 人とAIが往復しながら、一緒に進めます
- **委任** — 進め方ごと預け、人は目的と結果だけを見ます

```text
自動化: 変更点から定型のリリースノートを作らせる
拡張  : 設計案を出させ、突っ込みながら一緒に固める
委任  : 調査を預け、まとまった報告だけ受け取る
```

3つに優劣はありません。同じ人が、案件ごとに使い分けます。「自分は拡張型だ」と固定するものではなく、仕事ごとに選び直すものです。

ここで、混同しやすい語を1つ整理します。

| 語 | 何を指すか |
| --- | --- |
| **委任**（3モードの1つ） | 進め方ごとAIに預ける、関わり方の型 |
| **任せる**（4Dの1つ） | 何を自分でやり、何をAIに渡すか決める局面 |

「委任」と「任せる」は、日本語としては似ていますが、指しているものが違います。**任せる** は局面の名前で、そこで「渡す」と決めたあと、関わり方として **委任** を選ぶこともあれば、**拡張** を選ぶこともあります。この講座では最後まで別の語として扱います。

## 2-1-4 モードは主導権で選ぶ

> **3モードのどれを選ぶかは、自分がどれだけ主導権を持ちたいかで決めます**

3つ並べただけでは選べません。選ぶ軸を1本に決めます。それが **主導権**、つまり進め方と中身を自分がどれだけ決めるかの度合いです。

```text
中身まで自分が決めたい     → 拡張
やり方が決まりきっている   → 自動化
結果だけ受け取れればよい   → 委任
```

迷ったら「自分が決めたいか」を先に自問してください。決めたいなら拡張です。往復の手間はかかりますが、中身が自分の手に残ります。

一方、やり方がすでに決まりきっていて判断の余地が無い仕事は、自動化に向きます。毎週同じ形で出す報告のような仕事です。ここで拡張を選ぶと、毎回付き合うことになり、時間だけが減ります。

| 場面 | 選び違い | 起きること |
| --- | --- | --- |
| 設計方針を決める | 委任 | レビューで質問されて答えられない |
| 毎週の定型報告 | 拡張 | 毎回付き合って時間を使う |

主導権は、渡しすぎても握りすぎても損をします。しかも、同じ人でも仕事によって「決めたい度合い」は変わります。だからこそ、仕事ごとに選び直します。

ここまでで **どこで使い、どう関わるか** が決まりました。次のモジュールからは、実際に渡す局面に入っていきます。

## もっと知りたい人へ

- 直近で使った場面を1つ選び、「答えの幅」と「検証コスト」の2軸で並べ直してみてください。合わないと感じた場面は、たいていどちらかの軸で説明がつきます
- チームで話すときは「AIを使った」ではなく「この作業を委任した」「ここは拡張で進めた」と言うと、関わり方が伝わります。呼び方をそろえるだけで、レビューの会話が変わります
