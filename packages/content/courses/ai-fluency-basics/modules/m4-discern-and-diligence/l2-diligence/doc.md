# レッスン4-2 Diligence: 責任を持って使う

## このレッスンの目標

- [ ] 貼る前に機密情報かどうかを確かめられる
- [ ] 伏せ字にして相談できる形に直せる
- [ ] 最終責任の所在を説明し、チームの取り決めに合わせて判断できる

## 4-2-1 貼る前に機密情報かを確かめる

> **材料を貼る前に、それが社外に出せない機密情報でないかを確かめます**

このレッスンで 4D の最後、**Diligence(責任を持つ)** に入ります。

前のモジュールで、材料を添えるほど出力が当たると学びました。事故が起きやすいのは、ちょうどその直後です。エラーのログをまるごと貼ったら、顧客名と接続先が入っていた、という形です。悪意はありません。良かれと思ってやった手が、そのまま事故になります。

そこで枠をはめます。添えてよいのは、**渡してよい材料に限られる** ということです。渡してはいけないものを **機密情報** と呼びます。機密情報とは、社外に出せない情報のことです。顧客名、個人情報、APIキーなどの鍵、未公開の仕様、契約の中身などが当てはまります。

現場で回すには、細かい規程を暗記するより、一問を持っておくほうが確実です。

> **「この内容を、社外の人に画面で見せられるか」**

見せられるなら、そのまま材料にできます。ためらいが出たら、何がためらいの原因かを特定します。多くの場合、原因は文章全体ではなく、一部の固有名詞です。

見落としやすいのは、本題ではない部分に混ざるものです。

| 材料 | 紛れ込みやすいもの |
| --- | --- |
| エラーのログ | 顧客名、接続先、利用者のID |
| 設定ファイル | APIキーなどの鍵、パスワード |
| 議事録 | 未公開の予定、契約の条件 |

いずれも、貼る前に一度自分で読めば気づけます。**まるごとコピーして貼らない** ことが最初の一歩です。

## 4-2-2 伏せ字にすれば相談できる

> **固有名詞や鍵を伏せ字にすれば、多くの相談は機密情報を渡さずに済みます**

貼ってよいか迷って止まるのは、正しい反応です。ただし、止まったまま終わると、使わない理由だけが増えていきます。

多くの場合、相談を諦める必要はありません。**伏せ字** にすればよいからです。伏せ字とは、具体名を A社・XXXX のような置き換えにすることです。

- 前: 「株式会社◯◯の請求バッチが、ホスト db-prod-tokyo で失敗します」
- 後: 「ある顧客向けの請求バッチが、あるデータベースへの接続で失敗します」

聞きたいのは失敗の原因であって、顧客名でもホスト名でもありません。伏せ字にしても、相談の中身はほとんど失われていません。むしろ、**何を聞きたいのかが絞られる** という効き目もあります。

ただし伏せ字は万能ではありません。次の2つに当たったときは、相談しないという判断が正解になります。

- **組み合わせから特定できるとき** — 業種・規模・時期がそろうと、名前を伏せても相手が分かってしまう
- **未公開の仕様そのものが相談の中身のとき** — 伏せると何も聞けなくなる

迷ったら、伏せ字にした文を読み返し、「これを社外の人に見せられるか」の一問をもう一度当ててください。

## 4-2-3 最終責任は出した人にある

> **AIが書いたものでも、提出した時点で最終責任は提出した人にあります**

ここまでは、渡すものの話でした。ここからは、出したものの話です。

不具合の原因を聞かれて「AI が書いたので分かりません」と答えてしまう場面があります。この一言が出た時点で、その成果物そのものの信用がなくなります。誰も中身を保証していないからです。

**最終責任** とは、出したものの結果を引き受ける役割のことです。そして最終責任は、渡せません。

ここで、モードを選ぶときに使った主導権と並べておきます。

| | 主導権 | 最終責任 |
| --- | --- | --- |
| 渡せるか | 渡せる | 渡せない |
| 決めるもの | 関わり方の強さ | 誰が結果を引き受けるか |

主導権はどれだけ渡しても構いません。委任を選び、進め方ごと預けてもよいのです。それでも、提出した時点で結果を引き受けるのは提出した人です。**主導権と最終責任は別物** です。ここを混ぜると、「任せたのだから自分の責任ではない」という誤解が生まれます。

提出前に、次の3つを自問してください。

- なぜこの形なのか、自分の言葉で説明できるか
- 事実の部分を確かめたか
- 自分の名前で出せるか

3つとも「はい」でなければ、それはまだ仮説のまま出そうとしている状態です。

## 4-2-4 使い方はチームの取り決めに合わせる

> **AIをどこまで使ってよいかは、チームの取り決めに合わせて判断します**

最後は、個人の判断の外側にある枠の話です。自分の基準では問題ないと思って使ったところ、客先の決まりに反していた、ということが起こります。隣の人は使ってよいと言い、別の人は駄目だと言う、という状態もよくあります。

そこで、**取り決め** に合わせます。取り決めとは、チームや客先で決められた、AI を使ってよい範囲のルールのことです。取り決めは現場ごとに違うので、正解を暗記することはできません。着任したら確かめる、というやり方で対応します。

- **使ってよい道具はどれか**
- **貼ってよい情報の範囲はどこまでか** — 機密情報の扱いに関する決まり
- **使ったことを、どこにどう書くか**

3つとも、聞けば数分で分かります。分からないまま進めるのがいちばん危険です。

3つ目に関わるのが **透明性** です。透明性とは、AI を使ったことを隠さないことです。聞かれてから答えるのではなく、必要な場所に先に書いておきます。書く場所は現場によって違い、コミットのメッセージだったり、レビュー依頼の一言だったり、報告書の脚注だったりします。隠さないでおくと、読む側は確認の深さを自分で決められます。逆に隠すと、あとで分かったときに成果物全体が疑われます。

最後に、この講座で通した 4D を並べておきます。

| D | やること |
| --- | --- |
| 任せる | ゴールを決め、工程ごとに配る |
| 伝える | 成果物・できの基準・材料を渡す |
| 見極める | 仮説として読み、確かめる |
| 責任を持つ | 渡すものを選び、最終責任を負う |

この4つは、道具が変わっても同じ形で使えます。

## もっと知りたい人へ

- 取り決めが明文化されていない現場もあります。その場合は、判断をひとりで抱えずに、リーダーに一度確認して記録を残しておくと、あとから入るメンバーが同じ迷い方をしなくて済みます
- 伏せ字にする作業は、慣れると数十秒で終わります。よく貼る材料については、伏せる箇所をあらかじめ決めておくと速くなります
