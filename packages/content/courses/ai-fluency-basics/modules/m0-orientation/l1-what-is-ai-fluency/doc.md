# レッスン0-1 AI活用力とは何か

## このレッスンの目標

- [ ] AI駆動開発が「進め方を変える働き方」であることを説明できる
- [ ] AI活用力が言い回しの在庫ではないことを説明できる
- [ ] 4Dの4つを、考える順番として並べられる

## 0-1-1 AI駆動開発は進め方を変える

> **AI駆動開発とは、生成AIを開発の進め方そのものに組み込む働き方です**

まず、この講座で使う言葉をそろえます。

- **AI** — 人の判断が要る仕事を、機械にこなさせる技術の総称です
- **生成AI** — 文章やコードなど、新しい内容を作り出すAIです

多くの現場では、生成AIは「行き詰まったときに聞く相手」として使われています。検索窓の代わりです。便利ではありますが、仕事の進め方はこれまでと変わりません。

**AI駆動開発** は、そこから一歩進んだ働き方を指します。作業を始める前の段階で、どこを自分でやり、どこをAIに渡すかを決めておく。渡した結果をどう確かめるかも、あらかじめ織り込んでおく。つまり、進め方そのものにAIが入っている状態です。

実務では、たとえば次のような場面があります。

```text
障害の一次調査 → ログを渡して原因の候補を並べてもらう
コードレビュー → 差分を読ませて見落としを洗い出す
ドキュメント   → 箇条書きを渡して読める文章の下書きにする
```

3つに共通しているのは、思いつきで聞いているのではなく、**始める前から「ここは渡す」と決めている** ことです。

| | 道具として時々使う | AI駆動開発 |
| --- | --- | --- |
| 使う場面 | 行き詰まったときだけ | 始める前から想定する |
| 決めること | 特にない | どこを渡すかを先に決める |
| 出したものの責任 | 自分にある | 自分にある |

いちばん下の行だけは変わりません。進め方が変わっても、出したものの責任は自分にあります。この点は講座の最後まで通して扱います。

## 0-1-2 AI活用力はプロンプト集ではない

> **AI活用力とは、当たりのプロンプトを集めることではなく、AIとの進め方を自分で選ぶ力です**

AIに送る指示の文章を **プロンプト** と呼びます。

生成AIが広まると、まず起きるのが「よく効く言い回し集」の共有です。社内チャットに便利な文が回ってきて、それを自分の案件に貼ってみる。ところが、同じようにはいかないことがよくあります。

理由は単純で、**うまくいった文には、そのときの状況が省略されている** からです。「テストコードを書いて」という文が効いたのは、そのときの相手が対象のコードを知っていたからかもしれません。同じ文を別の案件に貼れば、何のテストか分からないまま、的外れなコードが返ってきます。

```text
借りてきた文: 「テストコードを書いて」
→ 何のテストか分からず、的外れなコードが返る

自分で選んだ進め方: 対象の関数と、確かめたい条件を先に渡す
```

AIと働く力のことを **AI Fluency** と呼びます。この講座では日本語で **AI活用力** と呼びます。AI活用力は、文の在庫の多さではありません。目の前の仕事に対して、どこまで渡すか・何を添えるか・返ってきたものをどう扱うかを **自分で選べること** を指します。

| | 言い回しを集める | AI活用力がある |
| --- | --- | --- |
| 新しい場面 | 当てはまる文を探す | 進め方を自分で決める |
| うまくいかないとき | 別の文を試す | どこがずれたかを言葉にする |
| 身につくもの | 文の在庫 | 判断のしかた |

文の在庫は、場面や道具が変われば使えなくなります。判断のしかたは持ち運べます。この講座が扱うのは後者だけです。

## 0-1-3 4Dがこの講座の地図

> **この講座は、任せる・伝える・見極める・責任を持つという4Dの順に進みます**

判断のしかたを学ぶといっても、順番がなければ身につきません。迷ったときに「いま自分はどこでつまずいているのか」を言えることが大事です。そこでこの講座は、4つの局面を決まった順に並べています。頭文字をとって **4D** と呼びます。

| 英語名 | 日本語 | 何を決めるか |
| --- | --- | --- |
| **Delegation** | **任せる** | 何を自分でやり、何をAIに渡すか |
| **Description** | **伝える** | 渡すものを、どう言葉にするか |
| **Discernment** | **見極める** | 返ってきた内容を、どう確かめるか |
| **Diligence** | **責任を持つ** | 出したものに、どう責任を持つか |

この4つは並列ではなく、考える順番です。渡すものが決まっていないのに伝え方を工夫しても、うまくいきません。返ってきたものを確かめる前に、そのまま提出することもできません。

うまくいかなかったときは、この4つのどこでつまずいたかを探してください。「そもそも渡すべきでない仕事だった」のか、「渡し方の言葉が足りなかった」のか、「確かめずに使った」のか。原因の置き場所が4つに整理されているだけで、次の一手が決めやすくなります。

各段階の中身は、このあとのモジュールで1つずつ扱います。いまは4つの名前と順番だけ持ち帰ってください。

## もっと知りたい人へ

- 自分のチームが生成AIをどう使っているかを、一度言葉にして並べてみてください。「行き詰まったときだけ聞いている」のか「進め方に組み込んでいる」のかが見えます
- AIの機能や制限は製品ごとに違い、時期によっても変わります。具体的な値が必要になったときは、使っている製品の公式ドキュメントで最新のものを確認してください
