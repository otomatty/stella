# 1-1-3
# 一度に読める量には上限がある

AI駆動開発の考え方 — Module 1 / レッスン1-1

<!-- ノート: 限界の2つ目。量の壁です。長く使うほど効いてきます。 -->

---

## なぜ必要か

- 長いやりとりを続けたら、最初に伝えた条件を守らなくなった
- 長いログを丸ごと貼ったのに、肝心の行を見ていない

<!-- ノート: つかみ。どちらも「読んだのに忘れた」ように見えますが、そもそも読めていない可能性があります。ここで結論は言わない。 -->

---

## 結論

**モデルが一度に読めるコンテキストには上限があり、あふれた分は出力に反映されません**

- **コンテキスト** — モデルが一度に読む文章のまとまり
- **コンテキストウィンドウ** — 一度に読める枠。その大きさが **コンテキスト上限**
- 上限はトークンの数で決まります

<!-- ノート: 結論を先に言い切る。実際の値は製品やモデルごとに違い、変わるので、本文では扱いません。 -->

---

## あふれると何が起きるか

```text
1回目 : 「返事は日本語で」と伝える
… 長いやりとりが続く …
20回目: 英語で返ってくる
理由  : 最初の条件が枠からあふれ、読まれていない
```

<!-- ノート: 「忘れた」のではなく「枠の外に出た」だけです。もう一度伝えれば戻ります。 -->

---

## 丸ごと貼る vs 要る所だけ貼る

| | ログを丸ごと貼る | 該当時刻の前後だけ貼る |
| --- | --- | --- |
| 枠 | あふれる | 収まる |
| 読まれ方 | 肝心の行が落ちる | 全部読まれる |
| 出力 | 的外れになりやすい | 焦点が合う |

<!-- ノート: 対比枠。多く渡すほど良いわけではない、と押さえます。枠は有限です。 -->
