# 1-1-5
# 出力はプロンプトしだいで変わる

AI駆動開発の考え方 — Module 1 / レッスン1-1

<!-- ノート: 道具側の性質から、自分側の書き方に視点を移す回です。 -->

---

## なぜ必要か

- 同僚と同じことを聞いたのに、返ってきた内容の質が違った
- 昨日うまくいった聞き方が、今日は外した

<!-- ノート: つかみ。道具のせいにしたくなる場面ですが、手元に動かせるものがあります。ここで結論は言わない。 -->

---

## 結論

**同じモデルでも、プロンプトの書き方が変われば出力は変わります**

- 同じプロンプトでも出力が毎回同じにならない性質を **揺らぎ** と呼びます
- 揺らぎがあるぶん、書き方でぶれ幅を狭められます

<!-- ノート: 結論を先に言い切る。揺らぎはここで定義します。ゼロにはできないが、狭くはできる、が要点です。 -->

---

## 書き方で変わる例

```text
A: このコードをレビューして
B: このコードを、命名と例外処理の観点でレビューして
→ Bは毎回この2観点が返る。Aは回ごとに観点が変わる
```

<!-- ノート: 良い文の型を配っているのではなく、観点を自分で決めて渡しているかどうかの差だと指します。 -->

---

## 曖昧なプロンプト vs 具体的なプロンプト

| | 曖昧 | 具体的 |
| --- | --- | --- |
| 書き方 | いい感じにして | 重複を消し、関数名を動詞から始めて |
| 出力 | 毎回ばらつく | 形がそろう |
| 直すとき | どこを直すか分からない | ずれた条件だけ言い直せる |

<!-- ノート: 対比枠。3行目が実務では効きます。条件を書いてあると、次に何を言えばよいかが決まります。 -->
