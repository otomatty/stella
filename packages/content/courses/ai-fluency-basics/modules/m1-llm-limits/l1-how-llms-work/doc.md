# レッスン1-1 LLMは何をしているのか

## このレッスンの目標

- [ ] LLMが次のトークンを確率で選んでいることを説明できる
- [ ] 知識の切れ目・コンテキスト上限・幻覚という3つの限界を区別できる
- [ ] 出力がプロンプトの書き方で変わることを説明できる

## 1-1-1 LLMは次のトークンを確率で選ぶ

> **LLM(大規模言語モデル)は、次に来るトークンを確率で選び続けて出力を作ります**

生成AIの中身にあたる仕組みを **LLM**(大規模言語モデル)と呼びます。ここでは数式には立ち入らず、何をしているかだけを押さえます。先に語をそろえます。

- **モデル** — 大量の文章から学んだパターンを持つ本体です
- **トークン** — 文章を細かく区切った単位です
- **出力** — AIが返してくる文章です

LLMがやっているのは、次の1つだけです。**いま手元にある文章の続きとして、次に来そうなトークンを確率で選ぶ**。選んだら、それを含めてまた次の1つを選ぶ。これを終わりまで繰り返します。

```text
入力: 「今日はいい」
候補: 「天気」…高い / 「一日」…中くらい / 「魚」…低い
選ぶ: 「天気」
→ 選んだぶんを足して、また次の候補を出す
```

この仕組みから、実務で効いてくる性質が出てきます。

| 思いがちな姿 | 実際 |
| --- | --- |
| 意味を理解して答えている | 次のトークンを確率で選んでいる |
| 正しい答えを探してきている | それらしい続きを作っている |
| 分からなければ黙る | 続きは常に作れてしまう |

いちばん大事なのは3行目です。この仕組みには「分からないので答えない」という状態が、そもそもありません。続きはいつでも作れてしまいます。ここが、このあと扱う限界の共通の根っこです。

## 1-1-2 知識は学習データの時点で止まる

> **LLMの知識は学習データを集め終えた時点(知識の切れ目)で止まっています**

モデルが学ぶために集めた大量の文章を **学習データ** と呼びます。学習データを集める作業には終わりがあり、そこから先の出来事は入っていません。この時点を **知識の切れ目** と呼びます。**カットオフ** という言い方もします。

厄介なのは、切れ目の向こう側を聞かれたときに「知りません」と返るとは限らないことです。

```text
問い : このツールの最新の設定方法を教えて
返り : 数年前の書き方を、いまの書き方として説明する
理由 : その書き方までしか学習データに入っていない
```

嘘をつこうとしているわけではありません。集め終えた時点の世界を、そのまま話しているだけです。

| 聞く内容 | 期待できるか |
| --- | --- |
| 言語の基本的な書き方 | だいたい期待できる |
| 先週出たバージョンの変更点 | 期待できない |
| 自社のコードの決まりごと | 期待できない |

下の2行は、期待できない理由が違います。バージョンの変更点は **切れ目より後だから** 入っていません。自社の決まりごとは、時点にかかわらず **そもそも学習データに入っていない** ためです。

なお、知識の切れ目が具体的にいつなのかは、製品やモデルごとに違います。値も更新されるので、必要になったら使っている製品の公式ドキュメントで確認してください。

## 1-1-3 一度に読める量には上限がある

> **モデルが一度に読めるコンテキストには上限があり、あふれた分は出力に反映されません**

モデルが一度に読む文章のまとまりを **コンテキスト** と呼びます。読み込める枠が **コンテキストウィンドウ**、その枠の大きさが **コンテキスト上限** です。上限はトークンの数で決まります。

コンテキストには、これまでのやりとりも、貼り付けたコードやログも、すべて入ります。枠を超えた分は読まれません。読まれないので、出力にも反映されません。

```text
1回目 : 「返事は日本語で」と伝える
… 長いやりとりが続く …
20回目: 英語で返ってくる
理由  : 最初の条件が枠からあふれ、読まれていない
```

これは「忘れた」のではなく「枠の外に出た」状態です。もう一度伝えれば戻ります。長いやりとりで指示が効かなくなったときは、まずこれを疑ってください。

もう1つ、よくある失敗が「全部貼れば安心」という発想です。

| | ログを丸ごと貼る | 該当時刻の前後だけ貼る |
| --- | --- | --- |
| 枠 | あふれる | 収まる |
| 読まれ方 | 肝心の行が落ちる | 全部読まれる |
| 出力 | 的外れになりやすい | 焦点が合う |

多く渡すほど良くなるわけではありません。枠は有限で、あふれた分は無いのと同じです。コンテキスト上限の実際の値も製品ごとに違うため、本文では扱いません。

## 1-1-4 幻覚はもっともらしい嘘

> **幻覚(ハルシネーション)とは、事実でない内容をもっともらしい文章として出力する現象です**

事実でない内容を、もっともらしい文章として出力する現象を **幻覚** と呼びます。**ハルシネーション** とも言います。

原因は 1-1-1 の仕組みです。LLMは次のトークンを確率で選ぶので、**続きは常に作れてしまいます**。学習データに無いことでも、形の整った文章にはなります。しかも、文体は自信があるように見えます。

```text
問い : このライブラリでCSVを読む関数は？
返り : read_csv_fast() を使います（引数の説明つき）
実際 : そんな関数は存在しない
```

引数の説明まで付いてくるのが、この現象のつらいところです。名前の形が自然なので、実在しそうに見えてしまいます。

幻覚は、いつでも同じ確率で出るわけではありません。出やすい場面には偏りがあります。

| 出やすい | 出にくい |
| --- | --- |
| 関数名・製品名などの固有名詞 | 一般的な考え方の説明 |
| 数値・バージョン・日付 | よく書かれている定番の書き方 |
| もともと情報が少ない話題 | 言い換えや要約 |

左側が出てきたら、いったん止まる。これを目印として覚えてください。幻覚は道具の故障ではなく、仕組みから素直に出てくる性質なので、なくなることは期待できません。

## 1-1-5 出力はプロンプトしだいで変わる

> **同じモデルでも、プロンプトの書き方が変われば出力は変わります**

ここまでは道具側の性質でした。最後に、自分側で動かせるものを1つ押さえます。

同じモデルに同じことを聞いても、書き方が変われば出力は変わります。さらに、まったく同じプロンプトでも出力が毎回同じになるとは限りません。この性質を **揺らぎ** と呼びます。次のトークンを確率で選ぶ仕組みなので、揺らぎはゼロにはできません。

ただし、書き方でぶれ幅を狭めることはできます。

```text
A: このコードをレビューして
B: このコードを、命名と例外処理の観点でレビューして
→ Bは毎回この2観点が返る。Aは回ごとに観点が変わる
```

Bが良いのは、文が上手いからではありません。**何を見てほしいかを自分で決めて渡している** からです。

| | 曖昧 | 具体的 |
| --- | --- | --- |
| 書き方 | いい感じにして | 重複を消し、関数名を動詞から始めて |
| 出力 | 毎回ばらつく | 形がそろう |
| 直すとき | どこを直すか分からない | ずれた条件だけ言い直せる |

実務でいちばん効くのは3行目です。条件を書いてあると、期待とずれたときに「どの条件がずれたか」を指せます。何も書いていないと、言い直す手がかりも残りません。

## もっと知りたい人へ

- コンテキスト上限や知識の切れ目は、製品やモデルごとに違い、更新もされます。具体的な値が必要になったときは、使っている製品の公式ドキュメントで確認してください
- 「なぜ外したのか」を、知識の切れ目・コンテキスト上限・幻覚・書き方の4つのどれかに当てはめる練習をしてみてください。当てはめられると、次にやることが変わります
