# AI駆動開発の考え方 カリキュラム

生成AIを日々の開発に組み込むときに要る「考え方」だけを扱う講座です。製品の操作は教えません。
1 トピック = 覚えることが 1 つ(takeaway 1 文)の粒度で、**LLM の仕組みと限界 → 向き不向きと関わり方 →
任せる → 伝える → 見極める → 責任を持つ** の順に通します。Claude 研修シリーズの 1 本目にあたり、
このあとの講座(製品の操作)を受ける前の共通の土台になります。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- 手を動かす部分: `practice.md` の「手元で試す」。チャット画面や紙の上で、判断だけを練習します
- コード演習(VS Code 拡張の採点)は **この講座にはありません**。学習対象が判断であってコードではないため、
  `course.json` に `exercises` を持ちません
- 前提講座: **ITのきほん(`it-basics`)**(`course.json` の `prerequisites` に対応)。加えて、コードが読めること(関数・引数・戻り値が追える)を前提にします。AI ツールの利用経験は仮定しません
- 対象外:
  - Claude チャット / Claude Code / Cowork / API の操作手順・画面説明・セットアップ
  - プロンプトのテクニック集(定型文・呪文の一覧)
  - 特定モデルのベンチマーク比較、価格・レート制限などの当日値
  - 社内規程・ガイドラインの制定そのもの(規程を「どう読んで従うか」の考え方だけ扱う)
  - モデルの内部構造の数式的な説明(Transformer の実装、学習手法)

## 到達目標

1. 目の前の仕事を「自分でやる / 一緒にやる / 任せる」に分けて **選べる**
2. 依頼を成果物・手順・できの基準の形で **書ける**
3. 出力を仮説として読み、ずれた点を次の指示に **返せる**
4. 出した結果の責任が自分にあることを **説明できる**
5. 幻覚・コンテキスト上限・知識の切れ目という LLM の限界を、具体的な場面で **指摘できる**

## 全体構成(5 モジュール / 7 レッスン / 28 トピック)

表の `introduces` はそのトピックで新しく導入する語、`requires` は前提として使う語です。
**この表が語彙台帳の正本**で、各 `slides.md` の front-matter にそのまま写します。並びは学習順(パスの自然順)で、
`requires` の語はすべて、それより上の行の `introduces` に現れます(`check_vocab.mjs` が検査します)。

## この講座の進め方

- 各レッスンは **スライド → まとめ → 確認クイズ** の順で並びます
- `practice.md` の「手元で試す」は、チャット画面か紙の上で完結します。判断そのものを練習する課題(仕事を工程に割る、
  依頼を書き直す、出力の怪しい箇所に印を付ける、貼ってよい材料を選ぶ)で、自動採点はありません
- Claude Code などの製品操作はこの講座では出しません。手元で試すときは、普段使っているチャット画面で構いません
- スマートフォンからでも、スライドとまとめと確認クイズだけで最後まで進められます

## 設計メモ(要件定義からの申し送り)

- **語彙台帳は講座をまたぎません。** 「AI」「生成AI」「プロンプト」「LLM」「トークン」なども、この講座の M0 / M1 で
  導入し直しています。他講座で説明済みでも前提にはできません
- **4D の 4 語は M0 で先に配りました。** 地図として 4 語を並べるのがモジュール構成そのものだからです。
  各 D の中身(工程に割る・成果物から書く・仮説として読む・機密を渡さない)は M3 / M4 のトピックで導入します。
  M0 の 0-1-3 は導入語が 9 語と多いので、スライドでは 4D の一覧図 1 枚に集約し、語の説明は 1 語 1 行に抑えてください
- **「委任」と「Delegation(任せる)」は別の語です。** 「委任」は 3 モードの 1 つ(手順ごとAIに預ける関わり方)、
  「Delegation / 任せる」は 4D の 1 つ(何を誰がやるか決める局面)を指します。M2-1-3 と M3 の冒頭で必ず対比してください。
  台帳上も別語として登録しています
- **M3-2-4「材料を添える」と M4-2-1「機密情報は貼らない」は意図的な対です。** 先に「渡すほど当たる」を教え、
  あとから「ただし渡してよいものに限る」で締めます。M3 側のスライドで機密の話を先出ししないでください
  (先出しすると M4 の takeaway が薄くなります)
- **1 年後も通用する範囲に絞りました。** モデル名・価格・コンテキスト上限の具体値・製品の画面は本文に書きません。
  「上限がある」ことは概念として扱い、実際の値は各製品のドキュメントを見る、という書き方にします
- **評価は確認クイズと手元ハンズオンだけです。** 到達目標 1〜5 はすべて判断の質を問うため、クイズは用語の暗記ではなく
  「この場面ではどれを選ぶか」「この依頼に足りない要素はどれか」という選択問題にしてください
- **サムネイルとアイコンは設置済みです。** `packages/content/scripts/build_thumbnails.py` の `SPECS` に
  `ai-fluency-basics` があり、`thumbnail.webp` / `icon.svg` を生成済み(手描きしない・既存講座と 1 つのシリーズに見えることが前提)
- **シリーズの続きは別 slug です。** Claude チャット / Claude Code / Cowork の操作は、この講座には足さず後続講座に置きます。
  この講座を大きくしないことが、シリーズ 1 本目としての役割です
