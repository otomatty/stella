# レッスン5-1 非同期処理

## このレッスンの目標

- [ ] Node.jsが1本の流れで動くことを説明できる
- [ ] `await` が何を待っているかを説明できる
- [ ] `try-catch` で失敗を受け止められる

## 5-1-1 Node.jsは1本の流れで動く

> **Node.jsはコードを1本の流れで実行するので、その流れを止めると他の処理も全部止まる**

サーバーは同時に何人ものリクエストを受けます。1人の処理が終わるまで他が待たされる作りでは、使いものになりません。この前提を理解するために、Node.jsの動き方を知っておきます。

- **シングルスレッド** — 処理の流れが1本しかないこと
- **イベントループ** — 次にやる処理を順に取り出して回す仕組み

```text
[やることの列]  → イベントループが1つずつ取り出して実行

  読み込み  →  集計  →  表示
     ↑
  ここで流れを止めたまま待つと、後ろが全部待たされる
```

窓口が1つしかない受付を想像してください。1人の対応中は、他の人は並んで待つしかありません。

ファイルの読み込みやネットワーク通信は、待ち時間が長い処理の代表です。この待ち時間の間ずっと窓口を占有していたら、他のリクエストは何も進みません。だからNode.jsは、**待ち時間の間は窓口を空ける** という工夫をしています。それが次のトピックの非同期処理です。

つまり「待つと止まる」のではありません。**流れを占有したまま待つと止まる**のです。次のトピックで出てくる `await` は、待っている間に窓口を空ける書き方なので、他のリクエストは止まりません。

## 5-1-2 時間のかかる処理は待たずに先へ進む

> **ファイル読み込みや通信は結果を待たずに次の行へ進み、終わってから結果が返る**

読み込んだ内容を表示したいのに空が出る、書いた順に実行されていないように見える。これは初心者が最初に出会う非同期のつまずきです。

- **非同期処理** — 結果を待たずに先へ進む処理の進め方
- **Promise** — 「後で結果を渡す」という約束を表すもの

```js
import { readFile } from "node:fs/promises";

const p = readFile("memo.txt", "utf-8");
console.log(p);        // => Promise { <pending> }  ← まだ中身が無い
```

`readFile` が返すのは、ファイルの中身そのものではなく **Promise** です。クリーニング店の引換券だと考えると分かりやすいでしょう。券は受け取れますが、品物はまだ出来上がっていません。`<pending>` は「処理中」という意味です。

この仕組みのおかげで、Node.jsは待ち時間の間に他の処理を進められます。代わりに、書き手の側は **結果の受け取り方を書く** 必要があります。

## 5-1-3 awaitで結果がそろうまで待つ

> **awaitを付けると、Promiseの結果が返るまで待ってから次の行へ進む**

引換券のままでは、中身を使った処理が書けません。品物を受け取る書き方が `await` です。

- **await** — 結果がそろうまで待つ印
- **async** — `await` を使う関数に付ける印

```js
import { readFile } from "node:fs/promises";

const text = await readFile("memo.txt", "utf-8");   // 待つ
console.log(text);                                   // 中身が使える

async function load() {          // 関数の中で使うには async が要る
  return await readFile("memo.txt", "utf-8");
}
```

モジュール4で「形として覚えてください」と書いた `await` の正体がこれです。

「待つ」と言っても、窓口が完全に止まるわけではありません。`await` している間、Node.jsは他の処理を進められます。**自分の続きだけを待たせる** のが `await` です。

関数の中で `await` を使うときは、その関数に `async` を付けます。ファイルの一番外側(トップレベル)で `await` を書けるのは、ES Modulesの場合だけです。CommonJSでは `async` 関数の中に入れる必要があります。

## 5-1-4 失敗はtry-catchで受け止める

> **awaitの失敗はtry-catchで受け、何が起きたかを自分の言葉で伝える**

ファイルが無い、通信できない。こうした失敗は必ず起きます。何も書かなければ、プログラムはそこで止まって終わります。

- **例外** — 処理を続けられないときに投げられる知らせ
- **try-catch** — 例外を受け止めて、続きを決める書き方

```js
try {
  const text = await readFile("memo.txt", "utf-8");
  console.log(text);
} catch (error) {
  console.error("memo.txt を読めませんでした");
  process.exit(1);          // 失敗として終わる
}
```

`try` の中で起きた例外は `catch` に渡されます。ここで大事なのは、**握りつぶさない** ことです。何も出力せずに処理を続けると、失敗したことに誰も気づけません。

2つの道具を使っています。

- `console.error` — 標準エラー出力へ書き出します(コマンドライン入門4-1-5)。正常な結果とエラーの知らせを混ぜないためです
- `process.exit(1)` — 終了ステータス1(失敗)でプログラムを終えます。コマンドライン入門6-2-4で学んだ `&&` は、この値を見て次に進むかを決めています

つまり、失敗を正しく伝えておくと、**自分のプログラムをシェルスクリプトの部品として安全に組み込める** ようになります。
