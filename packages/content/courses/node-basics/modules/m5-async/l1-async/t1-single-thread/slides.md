# Node.jsは1本の流れで動く

Node.js 入門 — Module 5 / レッスン5-1

## なぜ必要か

- サーバーは同時に何人ものリクエストを受ける
- 1人の処理が終わるまで他が待たされる作りでは、使いものにならない

<!-- ノート: つかみ。窓口が1つしかない受付をイメージさせます。 -->

---

## 結論

**Node.jsはコードを1本の流れで実行するので、その流れを止めると他の処理も全部止まる**

- **シングルスレッド** — 処理の流れが1本しかないこと
- **イベントループ** — 次にやる処理を順に取り出して回す仕組み

<!-- ノート: 結論を先に言い切ります。だから待ち方に工夫が要る、と次につなげます。 -->

---

## 窓口は1つしかない

```text
[やることの列]  → イベントループが1つずつ取り出して実行

  読み込み  →  集計  →  表示
     ↑
  ここで流れを止めたまま待つと、後ろが全部待たされる
```

- ファイル読み込みや通信は、待ち時間が長い代表
- 待つこと自体が問題ではなく、**流れを占有したまま待つ**のが問題
