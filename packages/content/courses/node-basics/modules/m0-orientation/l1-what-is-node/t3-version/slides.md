## なぜ必要か

- 同じコードなのに、自分の環境だけ動かない
- 相手と自分で、動かしている土台の版が違うことがある

<!-- ノート: つかみ。原因の切り分けで最初に確認すべき項目です。 -->

---

## 結論

**node -v で自分の環境の版を確かめ、チームはLTSの版にそろえる**

- **バージョン** — その実行環境の版。`v22.14.0` のように表す
- **LTS** — 長期間サポートされる安定版(long term support)

<!-- ノート: 結論を先に言い切ります。最新版が常に正解ではない、と添えます。 -->

---

## 最初に確かめる1行

```bash
node -v
# => v22.14.0

npm -v
# => 10.9.2
```

- 偶数の版(20・22 など)がLTS。業務では基本的にこちらを選ぶ
