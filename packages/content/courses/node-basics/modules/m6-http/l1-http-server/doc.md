# レッスン6-1 HTTPサーバーを立てる

## このレッスンの目標

- [ ] `node:http` で最小のサーバーを起動できる
- [ ] `req` と `res` の役割を説明できる
- [ ] URLごとに応答を分け、サーバーを止めて起動し直せる

## 6-1-1 node:httpで最小のサーバーを立てる

> **createServerでリクエストの受け口を作り、listenでポートを開くとサーバーになる**

Webアプリのサーバー側が何をしている装置なのかは、大きなフレームワークから入ると見えにくくなります。まず素の状態を見ておきます。

- **サーバー** — 要求を待ち受けて、応答を返し続けるプログラム
- **ポート** — 待ち受ける番号。開発では3000番などを使う

```js
import { createServer } from "node:http";

const server = createServer((req, res) => {
  res.end("hello");
});

server.listen(3000);
console.log("http://localhost:3000 で待機中");
```

これだけでサーバーになります。ブラウザで `http://localhost:3000` を開くと `hello` が表示されます。

`createServer` に渡している `(req, res) => { ... }` は、**その場で書いた関数**です(アロー関数と呼びます)。名前を付けて別に定義した関数を渡すのと同じことで、「要求が来たら、この手順を実行してください」と預けています。

ここまでのスクリプトと違うのは、**実行してもプログラムが終わらない** ことです。これは異常ではありません。要求を待ち続けるのがサーバーの仕事だからです。

## 6-1-2 リクエストを読んでレスポンスを返す

> **受け口の関数は、要求の情報が入ったreqと、応答を書き込むresを受け取る**

`(req, res)` の2つが何なのか分からないまま写している状態から抜け出します。

- **リクエスト**(`req`)— 相手からの要求。どのURLへ、どの方法(GET/POSTなど)で来たか
- **レスポンス**(`res`)— こちらが返す応答。ここに書き込む

```js
createServer((req, res) => {
  console.log(req.method, req.url);      // 読む: GET /about
  res.statusCode = 200;                   // ステータスコード
  res.setHeader("Content-Type", "text/plain; charset=utf-8");
  res.end("こんにちは");                   // 書いて終える
});
```

**req は読む物、res は書く物** と役割で覚えてください。

**ステータスコード** は結果の種類を表す番号です。よく使うのは次の3つです。

| 番号 | 意味 |
|---|---|
| 200 | 成功 |
| 404 | 見つからない |
| 500 | サーバー側でエラーが起きた |

`Content-Type` は返す内容の種類です。日本語を返すときは `charset=utf-8` を付けないと文字化けします。

最後の `res.end()` は必須です。呼ばないと、相手はいつまでも応答を待ち続けます。

## 6-1-3 URLで応答を切り替える

> **req.urlを見て処理を分けると、1つのサーバーで複数の画面や機能を返せる**

前のトピックのサーバーは、どのURLを開いても同じ内容しか返しません。実際のサイトはURLごとに違う内容を返しています。

**ルーティング** は、URLに応じて処理を振り分けることです。

```js
createServer((req, res) => {
  if (req.url === "/") {
    res.end("トップページ");
  } else if (req.url === "/about") {
    res.end("このサイトについて");
  } else {
    res.statusCode = 404;
    res.end("見つかりません");
  }
});
```

該当するURLが無いときは404を返します。**黙って成功(200)を返さない** ことが大切です。呼び出す側は、成功したのに中身が空なのか、そもそも間違ったURLなのかを区別できなくなります。

分岐が増えると読みにくくなるため、実務ではフレームワーク(Express や Hono など)を使います。ただしフレームワークがやっているのは、ここで書いた振り分けを楽に書けるようにすることです。素の形を1度見ておくと、フレームワークの説明が理解しやすくなります。

## 6-1-4 直したら止めて起動し直す

> **起動中のサーバーはコードを直しても変わらないので、Ctrl+Cで止めて起動し直す**

コードを直したのにブラウザの表示が変わらない、というのは初日に必ず出会う現象です。起動中のサーバーは、起動した時点のコードを読み込んで動き続けているためです。

```bash
# Ctrl+C でサーバーを止めてから
node server.js
```

止め忘れたまま起動し直すと、次のエラーが出ます。

```text
Error: listen EADDRINUSE: address already in use :::3000
```

**EADDRINUSE** は「そのポートは既に使われている」という意味です。前に起動したサーバーが残ってポートを握っています。

コマンドライン入門で学んだ手順がそのまま使えます。

```bash
ps aux | grep node      # PID を調べる
kill <PID>              # 止める
ps aux | grep node      # 消えたか確かめる
```

**調べて・止めて・確かめる** の3手順です。実務では、ファイルの変更を検知して自動で再起動する仕組み(`node --watch` など)も使いますが、まずは手で止めて起動し直す流れを身につけてください。何が動いているかを自分で把握できることが先です。
