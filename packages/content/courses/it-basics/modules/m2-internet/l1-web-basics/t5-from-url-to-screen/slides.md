# 2-1-5
# URLを開いてから画面が出るまで

ITのきほん — Module 2 / レッスン2-1

<!-- ノート: この講座のいちばん大事な問いです。Webエンジニアなら、この1問に自分のことばで答えられるようにします。 -->

---

## なぜ必要か

- 「このサイト、開いてるのに真っ白」と言われても、どこで止まったか言えない
- Web の仕事を始める前に、画面の向こうで何が起きているかを1本の流れで持てていない

<!-- ノート: つかみ。結論は言わない。現場では「表示されない」が毎日出ます。原因を言うには、開いてから描くまでの流れが要ります。 -->

---

## 結論

**URLを開くと、ブラウザがサーバーにページを頼み、返ってきたデータを画面に描きます**

<!-- ノート: 結論を先に言い切る。登場人物はブラウザとサーバーの2人だけ。新しいことばは足しません。 -->

---

## 3手の流れ

```text
1. 人が URL を開く (リンクを押す / 住所を入れる)
2. ブラウザが、その住所のサーバーへ「このページをください」と頼む
3. サーバーがデータを返し、ブラウザが画面に描く
```

<!-- ノート: 2-1-2 の3手を、URL を起点に言い直します。この学習サイトも、いま同じ3手で届いています。 -->

---

## 止まった場所の見分け

| いま起きていること | 止まっている場所 |
| --- | --- |
| ぐるぐるが終わらない | サーバーからの返事が届いていない |
| このサイトだけ真っ白 | 返す側 (そのサーバー) かもしれない |
| どのサイトも開かない | 頼む側 (自分の網) かもしれない |

<!-- ノート: 流れが言えると、切り分けができます。新しい用語は足さず、頼む側と返す側だけで見ます。 -->
