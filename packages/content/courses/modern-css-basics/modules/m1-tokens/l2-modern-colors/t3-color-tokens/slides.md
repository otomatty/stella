# 色は役割の名前でトークンにする

モダンCSS入門研修 — Module 1 / レッスン1-2

<!-- ノート: レッスン1-1のカスタムプロパティと、このレッスンの色を組み合わせます。 -->

---

## なぜ必要か

- oklchで色を作れても、宣言のあちこちに数字を書いたら結局ばらばらになる
- 「この色は何のための色か」が、CSSを読んだだけで分かるようにしたい

<!-- ノート: つかみ。道具が増えても、置き場所のルールが無いと散らかります。 -->

---

## 結論

**色は`:root`のカスタムプロパティに役割の名前を付けて、トークンとして使い回す**

- **トークン** = 名前を付けて使い回す、デザインの決めごとの値
- 名前は「何に使う色か」で付ける

<!-- ノート: 結論。デザイントークンという言葉はこの意味です。この講座の中心の考え方になります。 -->

---

## 最小のコード

```css
:root {
  --color-brand: oklch(45% 0.12 250);
  --color-brand-soft: color-mix(in oklch, var(--color-brand) 20%, white);
  --color-text: oklch(25% 0.02 250);
}
```

<!-- ノート: 3つで1組の最小トークンです。soft はブランド色から color-mix で派生させるので、brand を差し替えると付いて変わります。 -->

---

## 名前は役割で付ける

- `--color-navy` のような **見た目の名前** は、色を変えた瞬間に嘘になる
- `--color-brand` のような **役割の名前** なら、値を差し替えても意味が通る

<!-- ノート: 失敗例の枠。navy という名前で crimson を入れたら読み手が混乱します。役割で名付けるのが鉄則です。 -->
