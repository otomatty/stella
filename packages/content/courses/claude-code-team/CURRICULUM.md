# 検証・hooks・MCP カリキュラム

Claude Code に任せた仕事を「チームで仕組み化する」ところまでを扱う講座です。生成した変更を
テスト・lint・自分の目で検証する構えから、繰り返す検証手順の Skill 化、指示では守れない決まりを
自動実行される hook に置く判断、既存の MCP サーバーを設定で繋ぐこと、そして CLAUDE.md / Skill / hook を
リポジトリに載せてチームに配るまでが範囲です。1 トピック = 覚えることが 1 つ(takeaway 1 文)の粒度で、
**検証の構えを持つ → 検証を Skill にする → 決まりを hook にする → 道具を MCP で繋ぐ → チームに配る →
4D に戻して締める** の順に進みます。Claude 研修シリーズの 6 本目(到達点)にあたり、
4 本目(Claude Code 入門)の「差分は自分で読む」と 5 本目(Skills とサブエージェント)の
「必ず守らせたいことは hook へ」の続きから始まる位置づけです。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- 手を動かす部分: `practice.md` の「手元で試す」。VS Code 上の Claude Code で、検証 Skill を書く・
  hook を 1 つ設定する・MCP サーバーを 1 つ繋ぐ、といった課題です
- **Claude Code が使えない環境でも完走できます。** 「手元で試す」は任意で、スライド・まとめ・確認クイズだけで
  修了条件を満たします(Claude Code 入門・Skills とサブエージェントの「手元で試す」と同じ逃げ道)
- コード演習(VS Code 拡張の採点)は **この講座にはありません**。成果物が検証の判断と設定であって
  コードではないため、`course.json` に `exercises` を持ちません
- 前提講座: **Claude Code 入門(`claude-code-basics`)** と **Skills とサブエージェント(`claude-code-skills`)**。
  1 タスクを Explore → Plan → Code → Commit で通す流れと、CLAUDE.md / Skill / サブエージェント / hook という
  4 つの入れ物の地図を一度通っていることを想定します。ただし語彙台帳は講座をまたがないため、
  必要な語はこの講座で導入し直します
- 対象外:
  - MCP サーバーの自作(Python SDK などによる実装)。この講座は「使う側」だけを扱います
  - GitHub の @claude(`claude-code-action`)の本番導入手順(App のインストール・secret の設定などの
    リポジトリ管理者作業)。「何であるか」の紹介だけを扱います
  - API・SDK・課金・管理者設定、Bedrock / Vertex などの実行基盤
  - CI そのものの入門(テスト自動化の講座の範囲。この講座では「hook はローカルで、CI はリポジトリで」の
    対比に触れるだけ)
  - モデルの選び方、価格、上限値などの当日値
  - 画面のボタン名・メニュー配置・設定ファイルの正確な綴りの暗記(製品仕様は変わる前提)

## 到達目標

1. 生成した変更を、テスト・lint・自分の目の 3 つで **確かめられる**
2. 繰り返す検証手順を、参照ファイルとスクリプトに分けた Skill に **落とせる**
3. 「守らせたいルール」を CLAUDE.md ではなく hook に置く判断が **できる**
4. 既存の MCP サーバーを設定で **繋げる**(設定の各項目の意味を説明できる)
5. リポジトリにコミットするもの(CLAUDE.md / Skill / hook)と個人用を **分けられる**
6. GitHub の @claude Action が何かを **説明できる**(導入手順は対象外)

## 全体構成(6 モジュール / 6 レッスン / 25 トピック)

表の `introduces` はそのトピックで新しく導入する語、`requires` は前提として使う語です。
**この表が語彙台帳の正本**で、各 `slides.md` の front-matter にそのまま写します。並びは学習順(パスの自然順)で、
`requires` の語はすべて、それより上の行の `introduces` に現れます(`check_vocab.mjs` が検査します)。

## この講座の進め方

- 各レッスンは **スライド → まとめ → 確認クイズ** の順で並びます
- `practice.md` の「手元で試す」は VS Code 上の Claude Code で行います。自分のプロジェクトの検証手順を
  書き出して Skill にする、整形の hook を 1 つ設定する、公式の MCP サーバーを 1 つ繋いで外す、
  チームに載せるもの・個人用に留めるものを振り分ける、といった課題で、自動採点はありません
- **Claude Code が使えない受講者は「手元で試す」を飛ばして構いません。** その場合もスライドと確認クイズだけで
  完走できます。クイズは操作の再現ではなく判断を問うため、画面を触っていなくても解けます
- hook の例は特定の言語に寄せません。「編集のあとにフォーマッタを走らせる」「危険なコマンドを実行前に
  止める」といった、**どの言語のプロジェクトでも成り立つ決まり**を題材にします
- MCP の例は「公式または社内で用意済みのサーバーを設定に足す」までです。設定の綴りは変わる前提で、
  本文は「名前と繋ぎ方を書く」という意味だけを扱います
- 画面の並びやボタンの名前は変わります。困ったら製品のドキュメントを見る前提で、本文は
  「何のための仕組みか」だけを扱います
- スマートフォンからでも、スライドとまとめと確認クイズだけで最後まで進められます

## 設計メモ(申し送り)

- **語彙台帳は講座をまたぎません。** `claude-code-basics` / `claude-code-skills` までで説明済みの語も、
  この講座で `introduces` し直しています。再導入した語は Claude / Claude Code / テスト / 実行 / 差分 /
  任せる / 繰り返し / 手順 / Skill / 手順書 / SKILL.md / ファイル / description / 名前 / 参照ファイル /
  hook / 指示 / 仕組み / ツール / コマンド / CLAUDE.md / チーム / リポジトリ / コミット / 個人用 / 好み /
  レビュー / プルリクエスト / 4D / 伝える / 見極める / 責任を持つ / 仕組み化 / タスク / 入れ物 です。
  **再導入は 1 行の復習で済ませ、初出のような長い説明にしないでください。** スライドでは
  「講座4で扱った語です」「講座5で扱った語です」(4D の 4 語は「講座1で扱った語です」)と一言添え、
  残りの時間をこの講座の主題(検証と仕組み化)に使います
- **0-1-1 は講座 4 の「差分は自分で読む」からの接続です。** `claude-code-basics` の 3-3-1 で
  「書かせたものほど自分で読む」という構えを通っています。この講座はそれを「生成は仮説」という
  1 語に言い直して出発点にします。0-1-1 では検証のやり方に入らず、「正しそうに見えることと
  正しいことは別」という動機だけを言い切ってください
- **検証の言い切りは「テスト・lint・自分の目」の 3 点セットです。** 0-1-2 のこの 3 語が M0〜M1 の背骨で、
  0-1-3(機械を先に、目を最後に)・1-1-1(この 3 点セットを Skill にする)はすべてこの句に戻ります。
  スライド・doc・クイズでこの言い回しを崩さないでください
- **0-1-4「検証できる範囲だけ任せる」が M0 の締めです。** 任せる範囲の判断基準を「自分が結果を
  検証できるか」に一本化します。「難しいから任せない」ではなく「確かめられないから任せない」という
  理由づけにしてください。講座 1 の Delegation(任せる)をこの講座の言葉で言い直すトピックです
- **M1 は講座 5 の SKILL.md の復習の上に、参照ファイルとスクリプトの分け方を足します。** 1-1-2 は
  再導入(1 行の復習 + 検証 Skill の例)に留め、新しい教えは 1-1-3(長い基準は参照ファイルへ)と
  1-1-4(決まった操作はスクリプトへ)に置きます。分け方の言い切りは「読む資料は参照ファイル、
  叩く操作はスクリプト、選ぶ判断は本文」です
- **hook の言い切りは「指示は読んで従う、hookは設定され有効なら自動実行される」です。** 講座 5 の 5-1-4 で判断だけ
  扱ったので、この講座の M2 が実装側の本編です。hook は最後の防波堤ではなく、無効化・タイムアウト・
  ワークスペース信頼の前提があることを doc・クイズで触れます。設定ファイルの正確な綴り・イベント名の一覧は
  本文に書きません。2-1-2 のイベントは「実行の前・あと」という粒度に留め、例は 2-1-3(あとに整形)と
  2-1-4(前に止める)の 2 つで前後を 1 つずつ示します
- **2-1-5「hook の型と置き分け」が M2 の締めです。** command hook は決定的、prompt/agent hook は
  文脈判断向き(揺れ・費用あり)。「良い設計かどうか」のような判断は指示(CLAUDE.md)と Skill に残す、
  で講座 5 の使い分けに接続します
- **MCP は「使う側」だけです。** 3-1-2 はツール・資料・定型依頼の能力が増えることを述べ、
  ツールがゼロのサーバーもある旨を入れます(この講座ではツールを例に)。3-1-3 は「名前と繋ぎ方を書く」
  に加え、local / project / user スコープ、`claude mcp add` 既定が local、チーム共有は `.mcp.json`、
  初回承認、API キーは `${VAR}` で環境変数参照、を doc に書きます。**MCP サーバーの自作(SDK・実装)は
  この講座の対象外**で、3-1-4 で「自作しない」を明示的に教えます
- **3-1-5「信頼できるものだけ・要るぶんだけ」が M3 の安全の締めです。** MCP サーバーは道具と情報の
  出入口になるため、出どころの分からないサーバーを繋がない・使っていないサーバーは外す、という
  判断を扱います。講座 1〜2 の機密情報の扱いと同じ構えです
- **M4 の線引きは「効かせたい相手」で決めます。** チームの全員に効かせたい仕組み(CLAUDE.md / Skill /
  hook / MCP の設定)はリポジトリにコミットして配り、自分の好みは個人用の置き場に置きます。
  MCP は project スコープの `.mcp.json` をコミットし、local に書いた設定はチームに届かないこと、
  初回承認と `${VAR}` による秘密情報の扱いを 4-1-1 で触れます。
  4-1-3「仕組みの変更もレビューを通す」は、仕組みが全員の作業に効くコードと同じ影響力を持つ、
  という理由づけにしてください
- **@claude(GitHub Action)は 4-1-4 の 1 トピックだけです。** 「Issue やプルリクエストから頼めて、
  結果がプルリクエストで返る」という紹介と、「導入はリポジトリ管理者の作業で、この講座では扱わない」
  という線引きだけを書きます。**App のインストール手順・secret の設定・ワークフロー YAML は
  本文に書きません**
- **M5 は新しい道具を足しません。** 5-1-1 は検証(見極める)・hook と MCP の最小接続(責任を持つ)・
  依頼とSkill(伝える)・範囲の判断(任せる)を 4D の地図に戻すだけ、5-1-2 はシリーズ全体の
  チェックリスト(気づく → 入れ物を選ぶ → 検証を付ける → 配る)、5-1-3 は「小さく始める」という
  締めの言葉です。ここで新概念を導入しないでください

  「関係と流れ」(検証の 3 点セット、hook が割り込むタイミング、MCP サーバーと能力(ツール)の関係、

  本文の takeaway にしません
- **評価は確認クイズと手元ハンズオンだけです。** 到達目標 1〜6 はすべて判断を問うため、クイズは用語の
