# 生成は仮説にすぎない

## なぜ必要か

- Claude Codeの生成した変更は、いつも正しそうに見える
- 「正しそうに見える」と「正しい」は別のこと

<!-- ノート: AIの出力は自信ありげに見えるのが特徴です。見た目のきれいさは正しさの証拠になりません。結論はまだ言いません。 -->

---

## 結論

**Claude Codeが生成した変更は仮説なので、受け取る前に検証します**

- **仮説** — 正しいかもしれないが、まだ確かめていない答え
- **検証** — 仮説が正しいことを、証拠で確かめる作業
- 生成のたびに検証する。この順番がこの講座の主題です

<!-- ノート: Claude / Claude Code / 生成は講座4までで扱った語です。この講座は「作らせ方」ではなく「確かめ方」の講座だと宣言します。 -->

---

## 最小の例

```text
Claude Code 「修正しました。テストも通るはずです」

自分        「はず、はまだ仮説。
             確かめてから受け取る」
```

<!-- ノート: エージェント自身も確認はしますが、最後に受け取る責任は人の側にあります。「通るはず」を「通った」に変えるのが検証です。 -->

---

## 生成と検証はセット

| 生成だけ | 生成 + 検証 |
| --- | --- |
| 速いが、壊れていても気づけない | 一手間かかるが、壊れたら気づける |
| 直した「つもり」で先へ進む | 直った「事実」で先へ進む |

<!-- ノート: 検証は生成のブレーキではなく、安心して速く進むための装置です。このあと、確かめ方を具体的に3つに割っていきます。 -->
