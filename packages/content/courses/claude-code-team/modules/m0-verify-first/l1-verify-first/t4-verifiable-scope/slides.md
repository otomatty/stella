# 0-1-4
# 検証できる範囲だけ任せる

検証・hooks・MCP — Module 0 / レッスン0-1

<!-- ノート: M0の締めです。検証の構えを、任せ方の判断につなげます。 -->

---

## なぜ必要か

- 生成が速いと、つい大きな変更まで一度に任せたくなる
- 任せたものが仮説のまま積み上がると、どこかで崩れる

<!-- ノート: 任せる量の上限をどこで引くか、という判断の話です。 -->

---

## 結論

**任せてよい範囲は、自分が結果を検証できる範囲に合わせて決めます**

- **範囲** — 一度に任せる変更の大きさ・広がり
- **結果** — 任せた仕事の出来上がり
- 「難しいから任せない」ではなく「確かめられないから任せない」

<!-- ノート: 任せるは講座1で扱った語です。判断基準を能力ではなく検証可能性に置くのがポイントです。 -->

---

## 最小の例

```text
テストのある部分の修正   → 検証できる  → 任せられる
テストのない大改修を一括 → 検証できない → 割ってから任せる
```

<!-- ノート: 検証できないから任せない、で終わりではありません。割る・テストを足すなど、検証できる形に変えてから任せます。 -->

---

## 広げ方は段階的に

| 状況 | 任せる範囲 |
| --- | --- |
| テストが充実している | 広く任せて、機械の検査で受け取る |
| テストが薄い | 小さく割って、目の届く単位で受け取る |
