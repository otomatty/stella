# 確かめ方は3つある

検証・hooks・MCP — Module 0 / レッスン0-1

<!-- ノート: 検証しようと決めても、何をすればよいかが曖昧だと続きません。道具を3つに整理します。 -->

## なぜ必要か

- 「ちゃんと確認して」だけでは、何をすれば済みかが分からない
- 検証のやり方が人によってばらつくと、抜けが生まれる

<!-- ノート: 検証を続けるコツは、確かめ方を決まった型にしておくことです。 -->

---

## 結論

**生成した変更は、テスト・lint・自分の目の3つで検証します**

- **テスト** — プログラムを実行して、動きが正しいかを確かめる仕掛け
- **lint** — コードの形の問題を機械的に見つける検査
- **自分の目** — 変更を自分で読んで、意図どおりかを確かめること

<!-- ノート: テストは講座4でも触れた語です。動き・形・意図という守備範囲の違いごと覚えてください。 -->

---

## 最小の例

```text
テスト     動きは正しいか   → テストを実行する
lint       形は整っているか → lintを実行する
自分の目   意図どおりか     → 変更を読む
```

<!-- ノート: 3つは役割が違うので、どれか1つでは代わりになりません。テストが通っても、頼んでいない変更が混ざっていることはあります。 -->

---

## 1つでは足りない

| 抜けた検証 | 見逃すもの |
| --- | --- |
| テストなし | 動きの壊れ |
| lintなし | 形の乱れ・危うい書き方 |
| 自分の目なし | 意図と違う変更・余計な変更 |
