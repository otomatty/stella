# 機械の検査を先に通す

## なぜ必要か

- 自分の目で読むのは、3つの中でいちばん時間がかかる
- 機械で見つかる問題まで目で探すと、疲れて肝心の見落としが出る

<!-- ノート: 人の集中力は有限です。有限な資源をどこに使うかという話です。 -->

---

## 結論

**テストとlintという機械の検査を先に実行し、残った差分を自分の目で読みます**

- **機械の検査** — テストとlintのように、コマンド一発で答えが出る検証
- **差分** — 変更の前後を比べた、増えた行と減った行の一覧
- 機械で落ちたら、直してから読み直す。読むのは最後です

<!-- ノート: 差分は講座4でも扱った語です。順番は「安いものから先に」。機械の検査は何度実行してもコストがほぼゼロです。 -->

---

## 最小の例

```text
1. テストを実行  → 落ちたら差し戻す
2. lintを実行    → 落ちたら差し戻す
3. 差分を読む    → 意図どおりなら受け取る
```

<!-- ノート: 機械の検査で落ちる変更は、読む前に差し戻せます。目に届くのは機械を通り抜けた差分だけ、という流れを作ります。 -->

---

## 逆順にすると

| 順番 | 起きること |
| --- | --- |
| 目 → 機械 | 読んだあとにテストで落ちて、読み直しになる |
| 機械 → 目 | 目は「意図どおりか」だけに集中できる |

<!-- ノート: 機械に任せられる検査を機械に回すほど、自分の目の価値が上がります。この分担の考え方は、あとのhooksにもつながります。 -->
