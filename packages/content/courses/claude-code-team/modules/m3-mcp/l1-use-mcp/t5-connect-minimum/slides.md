# 繋ぐ相手は選んで最小にする

検証・hooks・MCP — Module 3 / レッスン3-1

<!-- ノート: M3の締め、安全の話です。便利さの裏の注意を1トピックで扱います。 -->

---

## なぜ必要か

- MCPサーバーは、道具と情報の出入口になる
- 便利だからと何でも繋ぐと、出入口の管理ができなくなる

<!-- ノート: 繋ぐことは、社内ツールや外部サービスへの通り道を開けることです。 -->

---

## 結論

**MCPサーバーは信頼できるものだけを、いまの仕事に要るぶんだけ繋ぎます**

- **信頼** — 出どころと中身がはっきりしていて、任せてよいと言えること
- **最小** — 要るものだけに絞ること。使っていないものは外す
- 出どころの分からないサーバーは繋がない

<!-- ノート: 講座1〜2でやった機密情報の構えと同じです。渡す相手を選ぶ、要らない通り道は開けない。 -->

---

## 最小の例

```text
繋ぐ前の3問

  1. 出どころは?     公式か、社内の担当が配ったものか
  2. 何に触れる?     読むだけか、書き換えもするか
  3. いま要る?       今の仕事で使うか
```

<!-- ノート: 3問のどれかで詰まったら、繋ぐのを保留して確認します。2の「何に触れるか」は特に、書き換えができるサーバーで慎重になります。 -->

---

## 増やしすぎのサイン

| 状態 | 処方 |
| --- | --- |
| 使っていないサーバーが残っている | 設定から外す |
| 誰が入れたか分からない設定がある | 出どころを確認してから使う |
