# レッスン3-1 既存のサーバーを繋ぐ

## このレッスンの目標

- [ ] MCPが何のための仕組みかを一言で説明できる
- [ ] 既存のMCPサーバーを設定で足せる(設定の各項目の意味を説明できる)
- [ ] 繋ぐ相手を「信頼できるものだけ・要るぶんだけ」で選べる

## 3-1-1 MCPは道具を繋ぐ共通の口

> **MCPは、Claude Codeに社内ツールや外部サービスを繋ぐための共通の口です**

エージェントが最初から触れるのは、手元のファイルとコマンドだけです。しかし仕事の情報は、課題管理・社内DB・チャットのような **社内ツール** や、社外の **外部サービス** にも散らばっています。エージェントがそこへ届かないと、外の情報は毎回人がコピーして貼り付けて渡すことになります。

**MCP** は、エージェントに外の道具を **繋ぐ** ための共通の決まりごとです。道具ごとに専用の繋ぎ込みを作るのではなく、口を1つの規格に揃えています。USBの口のような標準化だと考えると近いです。

```text
MCPなし   課題管理の内容を人がコピーして貼る

MCPあり   「課題123の内容を読んで対応して」
          → エージェントが自分で読みに行く
```

| 専用の繋ぎ込み | 共通の口(MCP) |
| --- | --- |
| 道具ごとに作り込みが要る | 対応した道具はそのまま繋がる |
| 作った人しか保守できない | 同じ形でチームに配れる |

口が共通だからこそ、対応済みの道具が世の中に既にたくさんあります。それを **使う側** が、この講座の範囲です。

## 3-1-2 サーバーを繋ぐとツールが増える

> **MCPサーバーを繋ぐと、Claude Codeが使えるツールがそのぶんだけ増えます**

繋いだ先で何が変わるのかを、1段だけ具体的にします。

MCPの口で道具を提供する側のプログラムを **MCPサーバー** と呼びます。繋ぐ相手はサーバーで、繋いだ結果として増えるのがツールです。エージェントの道具箱に、ファイルを読む・コマンドを実行するといった手持ちの道具に加えて、新しい道具が並ぶ、という絵です。正確には、サーバーはツールのほかに、読み取れる資料や定型の依頼のひな形を提供することもあります。この講座では、いちばん代表的なツールに絞って話します。

```text
繋ぐ前   ファイルを読む / 書く / コマンドを実行する

課題管理のMCPサーバーを繋ぐ

繋いだ後  上に加えて
          課題を検索する / 課題の詳細を読む ...
```

増えたツールの使い方を、人が覚える必要はありません。エージェントが依頼に応じて、必要なツールを自分で選んで使います。

| 人がすること | エージェントがすること |
| --- | --- |
| どのサーバーを繋ぐか決める | 増えたツールから必要なものを選ぶ |
| 依頼を書く | ツールを実行して結果を使う |

人の仕事は選定と依頼、操作はエージェント側。「サーバーを繋ぐと、ツールが増える」という対応を持ち帰ってください。

## 3-1-3 既存のサーバーは設定で足す

> **既存のMCPサーバーは、名前と繋ぎ方を設定に書くだけで足せます**

「繋ぎ込み」と聞くと開発作業を想像して身構えますが、既存のMCPサーバーを使い始めるのにコードは書きません。やることは **設定**(どのサーバーを使うかを書いておくファイル)に、実質2つの情報を書くことだけです。

```text
設定に書くこと(意味だけ)

  名前:    issue-tracker (自分がつける呼び名)
  繋ぎ方:  起動するコマンド、または接続先のURL

→ 次の会話から、そのサーバーのツールが使える
```

| 項目 | 意味 |
| --- | --- |
| 名前 | どのサーバーか区別する呼び名 |
| 繋ぎ方 | 手元で起動するか、どこかへ接続するか |

**繋ぎ方** には2系統あります。手元でサーバーのプログラムを起動する型と、どこかで動いているサーバーへ接続する型です。この区別を知っておくと、各サーバーの説明書が読みやすくなります。

もう1つだけ知っておくと、設定の置き場には「自分だけに効く置き場」と「プロジェクトで共有する置き場」の2系統があります。自分の手元で試すだけなら自分用、チームに配りたい設定は共有用に書きます(この使い分けはM4で扱います)。

設定ファイルの正確な綴りや置き場所は、製品ごと・時期ごとに変わります。執筆時点の例はこの下の「もっと知りたい人へ」から製品のドキュメントで確認するものとして、覚えるのは「名前と繋ぎ方を書く」という各項目の意味だけで十分です。

## 3-1-4 サーバーは自作しない

> **MCPサーバーは自作せず、公式や社内で用意済みのものを探して繋ぎます**

仕組みが分かると、サーバーを自分で作ってみたくなります。この講座の線引きははっきりしています。**自作**(サーバーのプログラムを自分で開発すること)はせず、**用意済み**(公式やコミュニティ、社内の担当が既に作って配っているもの)を探して繋ぎます。

```text
「課題管理と繋ぎたい」

  1. そのサービスの公式サーバーを探す   → あれば繋ぐ
  2. 社内で用意済みのものを探す         → あれば繋ぐ
  3. 無い                              → 担当チームに相談
```

3で自作に走らないのがポイントです。主要なサービスの多くは公式のMCPサーバーを提供しており、社内ツールのサーバーは社内の担当チームが用意して配るのが筋です。

| 観点 | 用意済みを繋ぐ | 自作する |
| --- | --- | --- |
| 保守 | 提供元が続ける | 自分が背負い続ける |
| 安全 | 提供元が直す | 穴も自分持ち |

MCPサーバーは道具と情報の出入口になるため、認証や権限を扱う開発・保守の責任が重いのです。利用者の片手間仕事にせず、使う側に徹する。それがこの講座の到達点です。

## 3-1-5 繋ぐ相手は選んで最小にする

> **MCPサーバーは信頼できるものだけを、いまの仕事に要るぶんだけ繋ぎます**

最後は安全の話です。サーバーを繋ぐことは、社内ツールや外部サービスへの通り道を開けることでもあります。便利だからと何でも繋ぐと、道具と情報の出入口が管理できなくなります。

選び方は2句で覚えます。**信頼**(出どころと中身がはっきりしていて、任せてよいと言えること)できるものだけ。そして **最小**(要るものだけに絞り、使っていないものは外すこと)です。

```text
繋ぐ前の3問

  1. 出どころは?     公式か、社内の担当が配ったものか
  2. 何に触れる?     読むだけか、書き換えもするか
  3. いま要る?       今の仕事で使うか
```

3問のどれかで詰まったら、繋ぐのを保留して確認します。特に2は大切で、読むだけのサーバーと書き換えができるサーバーでは、事故のときの影響が違います。出どころの分からないサーバーは繋ぎません。シリーズ前半で学んだ機密情報の構え(渡す相手を選ぶ)と同じです。

| 状態 | 処方 |
| --- | --- |
| 使っていないサーバーが残っている | 設定から外す |
| 誰が入れたか分からない設定がある | 出どころを確認してから使う |

繋いで終わりではなく、定期的な棚卸しまでがMCPの使い方です。次のモジュールでは、ここまでに作った仕組みをまとめてチームに配ります。

## もっと知りたい人へ

- MCPサーバーの設定の正確な書式・置き場所は、製品のドキュメント(Claude Code の MCP の項)で確認してください。この講座では「名前と繋ぎ方を書く」という意味と、「信頼できるものだけ・要るぶんだけ」という選び方を持ち帰れば十分です
- MCPサーバーを作る側(SDKでの実装)はこの講座の対象外です。社内ツールのサーバーが必要になったら、担当チームへの相談から始めてください
