# 3-1-4
# サーバーは自作しない

検証・hooks・MCP — Module 3 / レッスン3-1

<!-- ノート: この講座の明確な線引きです。使う側に徹します。 -->

---

## なぜ必要か

- 仕組みを知ると、自分で作ってみたくなる
- 作る前に探せば、たいてい用意済みのものがある

<!-- ノート: 作れるかどうかではなく、作るべきかどうかの話です。 -->

---

## 結論

**MCPサーバーは自作せず、公式や社内で用意済みのものを探して繋ぎます**

- **自作** — サーバーのプログラムを自分で開発すること
- **用意済み** — 公式やコミュニティ、社内の担当が既に作って配っているもの
- 探す順番: 公式 → 社内で用意済み → それでも無ければ相談

<!-- ノート: 主要なサービスの多くは公式のMCPサーバーを出しています。社内ツールも、担当チームが用意するのが筋です。 -->

---

## 最小の例

```text
「課題管理と繋ぎたい」

  1. そのサービスの公式サーバーを探す   → あれば繋ぐ
  2. 社内で用意済みのものを探す         → あれば繋ぐ
  3. 無い                              → 担当チームに相談
```

<!-- ノート: 3で自作に走らないのがポイントです。認証や権限を持つサーバーの開発・保守は、利用者の片手間仕事にしないでください。 -->

---

## 自作しない理由

| 観点 | 用意済みを繋ぐ | 自作する |
| --- | --- | --- |
| 保守 | 提供元が続ける | 自分が背負い続ける |
| 安全 | 提供元が直す | 穴も自分持ち |

<!-- ノート: サーバーは道具と情報の出入口なので、品質責任が重いのです。使う側に徹するのがこの講座の到達点です。 -->
