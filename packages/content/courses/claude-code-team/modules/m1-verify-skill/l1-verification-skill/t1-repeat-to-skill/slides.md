# 繰り返す検証はSkillにする

検証・hooks・MCP — Module 1 / レッスン1-1

<!-- ノート: M0で検証の型が決まりました。今度はその型を、毎回手で打たずに済む形にします。 -->

---

## なぜ必要か

- 受け取りのたびに、同じ検証の指示を毎回書くことになる
- 急いでいる日ほど、検証の一部が抜ける

<!-- ノート: 検証は毎回やるからこそ、人の記憶に頼ると抜けます。講座5でやった「繰り返しは仕組みにする」の出番です。 -->

---

## 結論

**毎回くり返す検証の手順は、Skillという手順書にして呼び出します**

- **手順** — 検証を進める1つ1つのステップ
- **Skill** — 特定のタスクのやり方をまとめた手順書。呼び出すと効く
- テスト → lint → 差分を読む、の型をそのまま手順書にします

<!-- ノート: 繰り返し・Skill・手順書は講座5で扱った語です。この講座では検証という題材で実際に使い込みます。 -->

---

## 最小の例

```text
毎回書く   「テストとlintを実行して、
            差分の要約を出して」

Skillにする 「受け取り検証をやって」
            → 決めた手順が毎回同じに走る
```

<!-- ノート: 呼び出す一言だけで、決めた検証が同じ順で走ります。書き忘れによる抜けがなくなるのが狙いです。 -->

---

## Skillにすると変わること

| 毎回指示を書く | 検証Skillを呼ぶ |
| --- | --- |
| 書き方が日によってぶれる | 手順がいつも同じ |
| 急ぐと項目が抜ける | 抜けた項目に気づける |
| 自分しか再現できない | チームの誰でも同じ検証になる |
