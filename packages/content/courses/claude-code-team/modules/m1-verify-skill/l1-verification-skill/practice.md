# レッスン1-1 演習 — 検証を手順書にする

対象トピック: 1-1-1 〜 1-1-4

## 手元で試す

VS Code 上の Claude Code で進めます。使えない場合は、1〜2を紙(またはメモアプリ)で書くだけでも手順書の練習として成立します。

1. レッスン0-1で書き出した検証の手順(テスト・lint・差分)を、SKILL.md の下書きに整える。名前・description・本文の手順の3つを書く
2. 差分を読むときの観点を3つ以上挙げて、チェックリストとして別のメモに分ける。SKILL.md 側には「チェックリストを参照」と1行だけ書く
3. Claude Code が使えるなら、1〜2をリポジトリのSkillの置き場に保存し、小さな修正を任せたあとに呼び出してみる
4. 手順の中で「毎回まったく同じ操作」がどれかに印を付け、スクリプトに切り出すとしたら何をまとめるかを1行で書く

## 演習問題

### 問1(基本)

検証がSkill化に向いている理由を、「繰り返し」「抜け」という語を使って2文以内で説明してください。

### 問2(基本)

検証Skillの本文に「テストの結果をそのまま貼る」と書くのはなぜですか。1〜2文で説明してください。

### 問3(応用)

次の3つを、SKILL.md本文 / 参照ファイル / スクリプト のどこに置くか振り分け、理由を1つずつ1文で書いてください。

```text
1. 差分レビューの観点20項目の一覧
2. テストとlintをまとめて実行し、結果を表にする処理
3. 「失敗があれば直してから再実行する」という流れ
```

### 問4(応用)

「観点が増えてSKILL.mdが80行になった。手順がどこにあるか分からない」という相談への処方を、2文以内で書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

検証は変更を受け取るたびに行う繰り返しの作業だからです。毎回手で指示すると急ぐ日に抜けが出ますが、Skillにすれば同じ手順が毎回同じに走ります。

</details>

<details>
<summary>問2の解答例</summary>

「実行しました」という報告だけでは、それ自体がまだ仮説だからです。結果の出力を貼らせると、検証の証拠が会話に残ります。

</details>

<details>
<summary>問3の解答例</summary>

1は参照ファイル(読む資料なので、要るときだけ読まれる場所に置く)。2はスクリプト(決まりきった操作なので、機械にそのまま実行させるとぶれない)。3はSKILL.md本文(結果を見てどうするかという判断の流れだから)。

</details>

<details>
<summary>問4の解答例</summary>

観点の一覧を参照ファイルに分け、SKILL.mdには「チェックリストを参照」という指し示しだけを残します。本文には手順と判断だけが残り、数行に戻ります。

</details>

## 確認クイズ

### Q1. 変更を受け取るたびに「テストとlintを実行して差分の要約を出して」と書いています。適切な仕組み化はどれですか。

- A. 毎回コピーして貼り付ける
- B. 検証の手順書としてSkillにする
- C. 検証を週に1回にまとめる

<details>
<summary>答え</summary>

**B** — 毎回くり返す検証の手順はSkillにします。呼び出す一言で、同じ手順が毎回同じに走ります。

</details>

### Q2. 検証Skillの報告として、より確かなのはどちらの書かせ方ですか。

- A. 「テストを実行しました」と報告させる
- B. テストの結果の出力をそのまま貼らせる
- C. テストが通ったかどうかを○×で答えさせる

<details>
<summary>答え</summary>

**B** — 「実行しました」はまだ仮説です。結果そのものを貼らせると、検証の証拠が残ります。

</details>

### Q3. 差分レビューの観点が20項目あります。置き場所として適切なのはどれですか。

- A. SKILL.mdの本文に全部書く
- B. 参照ファイルに分けて、SKILL.mdから指し示す
- C. 覚えておいて、そのつど口頭で伝える

<details>
<summary>答え</summary>

**B** — 長い基準は参照ファイルへ分けます。本文に全部書くと手順が資料に埋もれ、口頭ではぶれと抜けが出ます。

</details>

### Q4. 「テストとlintをまとめて実行して結果を表にする」という決まりきった操作の置き場所として適切なのはどれですか。

- A. スクリプトに切り出して、SKILL.mdから実行する
- B. SKILL.mdの本文に文章で細かく説明する
- C. 参照ファイルに操作の説明を書く

<details>
<summary>答え</summary>

**A** — 決まった操作はスクリプトにすると、実行のたびのぶれがなくなります。本文には手順と判断だけを残します。

</details>

### Q5. 検証Skillの3つの置き場の分担として正しいのはどれですか。

- A. 本文に判断、参照ファイルに資料、スクリプトに操作
- B. 本文に資料、参照ファイルに操作、スクリプトに判断
- C. どこに置いても効き方は同じ

<details>
<summary>答え</summary>

**A** — 読む資料は参照ファイル、叩く操作はスクリプト、選ぶ判断は本文です。分担すると、育てても手順書が太りません。

</details>
