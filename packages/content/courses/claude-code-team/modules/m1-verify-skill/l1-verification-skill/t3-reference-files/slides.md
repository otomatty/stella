# 長い基準は参照ファイルへ

検証・hooks・MCP — Module 1 / レッスン1-1

<!-- ノート: 検証Skillを育てていくと必ずぶつかる、「長くなった」問題への答えです。 -->

---

## なぜ必要か

- 検証の観点を足していくと、SKILL.mdがどんどん長くなる
- 長い手順書は、手順と資料が混ざって読みにくくなる

<!-- ノート: 検証Skillは育つものです。育ったときの置き場所を先に決めておきます。 -->

---

## 結論

**観点の一覧のような長い基準は参照ファイルに分けて、SKILL.mdから指し示します**

- **基準** — 良し悪しを判定するものさし。レビュー観点の一覧など
- **チェックリスト** — 確認項目を1行ずつ並べた一覧
- **参照ファイル** — SKILL.mdから指し示す別ファイル。要るときだけ読まれる

<!-- ノート: 参照ファイルは講座5で扱った語です。手順は短く、資料は別ファイルで厚く、が分け方です。 -->

---

## 最小の例

```text
SKILL.md      3. 差分をチェックリストに沿って確認する
              (観点は checklist.md を参照)

checklist.md  - 頼んでいないファイルの変更がないか
              - 消してはいけない処理が消えていないか
              - ...観点が20行続く...
```

<!-- ノート: SKILL.md側は1行の指し示しだけです。観点の一覧は参照ファイルで何行でも育てられます。 -->

---

## 分けると起きること

| 全部SKILL.mdに書く | 参照ファイルに分ける |
| --- | --- |
| 手順が資料に埋もれる | 手順は数行のまま |
| 観点を足すたび手順書が太る | 足すのはチェックリスト側だけ |

<!-- ノート: 手順と資料を分けておくと、観点をいくら育てても手順書は太りません。次は、もう1つの分け先、スクリプトです。 -->
