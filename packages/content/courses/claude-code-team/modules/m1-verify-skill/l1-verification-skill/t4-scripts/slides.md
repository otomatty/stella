# 決まった操作はスクリプトへ

検証・hooks・MCP — Module 1 / レッスン1-1

<!-- ノート: M1の締めです。参照ファイルに続く、もう1つの切り出し先を扱います。 -->

---

## なぜ必要か

- 「テストを実行して、この形式で集計して」を文章で毎回説明するのは長い
- 文章の指示は、実行のたびに少しずつ違うやり方になりうる

<!-- ノート: 決まりきった操作を自然言語で書くのは遠回りです。ぶれてほしくない操作の話です。 -->

---

## 結論

**決まりきった操作はスクリプトに切り出し、SKILL.mdには手順と判断を残します**

- **操作** — コマンドの実行や集計のような、決まった作業
- **スクリプト** — 決まった操作をひとまとめにした実行ファイル
- **判断** — 結果を見てどうするかを選ぶこと。ここは文章で残す

<!-- ノート: 毎回同じ操作は、機械にそのまま実行させるのが確実です。判断まではスクリプトにできません。 -->

---

## 最小の例

```text
SKILL.md   1. verify.sh を実行する
           2. 失敗があれば、直してから 1 に戻る
           3. 全部通ったら、差分の要約を報告する

verify.sh  テストの実行と lint をまとめて実行し、
           結果を1つの表にして出す
```

<!-- ノート: 操作はスクリプト1行で呼び、SKILL.mdには「失敗ならどうするか」という判断の流れだけが残ります。 -->

---

## 3つの置き場の分担

| 置き場 | 置くもの |
| --- | --- |
| SKILL.md 本文 | 手順と判断 |
| 参照ファイル | 読む資料(チェックリスト・基準) |
| スクリプト | 叩く操作(実行・集計) |

<!-- ノート: 読む資料は参照ファイル、叩く操作はスクリプト、選ぶ判断は本文。この3分担が検証Skillの完成形です。 -->
