# レッスン4-1 演習 — リポジトリで配る

対象トピック: 4-1-1 〜 4-1-4

## 手元で試す

VS Code でチームのリポジトリ(または練習用リポジトリ)を開いて進めます。使えない場合は、1〜2を紙の上でやるだけでも線引きの練習として成立します。

1. この講座の演習で作ってきたもの(検証Skill・チェックリスト・hookの案・MCPの設定)を並べ、「リポジトリにコミットする / 個人用に置く」に振り分ける
2. 振り分けの理由を、「他の人が違うやり方をしていたら困るか?」の問いで1行ずつ書く
3. Claude Code が使えるなら、リポジトリ行きに振り分けたものを1つコミットし、チームのレビューに出す(1人チームなら、レビュー依頼文だけ書いてみる)
4. レビュー依頼文に「この仕組みが誰にどう効くか」を1行入れる(仕組みの変更のレビューで最初に見てもらう情報です)

## 演習問題

### 問1(基本)

チームに効かせたい仕組みを「リポジトリにコミットして配る」のが良い理由を、口頭やチャットで伝える場合と比べて2文以内で書いてください。

### 問2(基本)

「他の人が違うやり方をしていたら困るか?」という問いは、何を見分けるための問いですか。1〜2文で書いてください。

### 問3(応用)

「hookの設定はコードじゃないから、レビューなしで直接コミットしていい」という意見への反論を、影響範囲という観点から2〜3文で書いてください。

### 問4(応用)

GitHubの@claudeについて、「何ができる仕組みか」と「この講座で導入手順を扱わない理由」をそれぞれ1〜2文で書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

口頭やチャットの共有は人によって入り方が違い、あとから入る新人には届きません。リポジトリにコミットすれば、取り込んだ全員に同じ仕組みが同じ形で届きます。

</details>

<details>
<summary>問2の解答例</summary>

その設定をチームのリポジトリに載せるか、個人用の置き場に置くかを見分けるための問いです。困るなら全員で揃えるべき仕組み、困らないなら自分の好みです。

</details>

<details>
<summary>問3の解答例</summary>

hookの設定は、チーム全員とエージェントの動きを変えるファイルです。影響範囲で見ればコードと同等かそれ以上なので、コードと同じようにレビューを通すべきです。素通りで入った仕組みは、検証を緩める事故にも素通りで気づけなくなります。

</details>

<details>
<summary>問4の解答例</summary>

@claudeは、GitHubのIssueやプルリクエストのコメントで呼びかけると、Claudeが修正やレビューなどの作業をして結果をGitHub上に返す仕組みです。導入はリポジトリ管理者の作業で、権限や秘密情報の設定を伴うため、この講座では「何であるかを説明できる」までを扱います。

</details>

## 確認クイズ

### Q1. チーム全員に効かせたい検証Skillの配り方として適切なのはどれですか。

- A. チャットでファイルを送って、各自で置いてもらう
- B. リポジトリにコミットして配る
- C. 口頭で手順を説明して覚えてもらう

<details>
<summary>答え</summary>

**B** — 仕組みはファイルなので、リポジトリにコミットすれば取り込んだ全員に同じ形で届きます。チャットや口頭は入り方がばらつき、新人に届きません。

</details>

### Q2. 「説明は箇条書きでほしい」という自分の好みの指定の置き場所はどれですか。

- A. チームのリポジトリのCLAUDE.md
- B. 個人用の置き場
- C. リポジトリのhookの設定

<details>
<summary>答え</summary>

**B** — 他の人が違うやり方でも困らない好みは個人用に置きます。リポジトリに入れると自分の癖を全員に押しつけることになります。

</details>

### Q3. リポジトリのCLAUDE.mdを書き換えるときの進め方として適切なのはどれですか。

- A. 設定ファイルなので直接コミットする
- B. コードと同じようにレビューを通す
- C. 変更を口頭で全員に伝えれば十分

<details>
<summary>答え</summary>

**B** — 仕組みのファイルはチーム全員とエージェントの動きを変えます。コードと同じ扱いでレビューを通します。

</details>

### Q4. GitHubの@claudeの説明として適切なのはどれですか。

- A. Issueやプルリクエストから作業を頼むと、結果がGitHub上に返ってくる仕組み
- B. VS Codeの拡張機能の別名
- C. レビューなしで変更を自動的に取り込む仕組み

<details>
<summary>答え</summary>

**A** — @claudeはGitHubのコメントから呼びかけて作業を頼める仕組みです。結果はプルリクエストなどで返り、最後は人がレビューして取り込みます。

</details>
