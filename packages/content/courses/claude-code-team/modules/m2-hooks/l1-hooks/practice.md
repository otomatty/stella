# レッスン2-1 演習 — 必ず実行される決まり

対象トピック: 2-1-1 〜 2-1-5

## 手元で試す

VS Code 上の Claude Code で進めます。使えない場合は、1と4を紙の上でやるだけでも線引きの練習として成立します。

1. 前の講座の演習でメモした「たまに破られると困る決まり」(なければ今考える)を1つ選び、「イベント(いつ) + 処理(何を)」の組に書き直す
2. Claude Code が使えるなら、製品のドキュメントでhooksの設定方法を確認し、編集のあとにフォーマッタを実行するhookを1つ設定してみる
3. 設定したhookが動くことを、小さな編集を任せて確かめる(整形が自動で走ったかを見る)
4. 自分のプロジェクトの決まりを3つ挙げ、それぞれ「機械的に判定できるか(hookに向くか)」を○×で判定し、×のものの置き先(指示 / Skill)を書く

## 演習問題

### 問1(基本)

指示・Skill・hookの効き方の違いを、それぞれ1行で書いてください。

### 問2(基本)

「実行の前」のイベントと「実行のあと」のイベントに向く処理を、1つずつ例を挙げて説明してください。

### 問3(応用)

「コミット前の整形をCLAUDE.mdに太字で書いているのに、たまに整形漏れが混ざる」というチームへの処方を、hookという語を使って2文以内で書いてください。

### 問4(応用)

次の4つを「hookに向く / 指示・Skillに残す」に振り分け、理由を1つずつ1文で書いてください。

```text
1. 編集のあとにフォーマッタを実行する
2. 変更の設計が既存の方針に合っているか確認する
3. 取り消せない削除コマンドを実行前に止める
4. コミットメッセージの文面を分かりやすく書く
```

## 解答例と解説

<details>
<summary>問1の解答例</summary>

指示は読んで従うもので、破られることがあります。Skillは呼ばれたときに効く手順書です。hookは決めたタイミングで必ず実行される仕組みです。

</details>

<details>
<summary>問2の解答例</summary>

実行の前は、内容を検査してまずいものを通さない処理が向きます(危険なコマンドを止めるなど)。実行のあとは、整える・記録するといった後始末が向きます(編集のあとの整形など)。

</details>

<details>
<summary>問3の解答例</summary>

指示は読んで従うものなので、太字にしても抜けはゼロになりません。編集のあとにフォーマッタを実行するhookにすれば整形が機械的に走り、実行し忘れがなくなります。

</details>

<details>
<summary>問4の解答例</summary>

1はhookに向く(整形は機械的に判定・実行できる後始末)。2は指示・Skillに残す(方針に合うかは文脈の判断で、機械的に判定できない)。3はhookに向く(危険な形かどうかは条件を文字で書き切れる)。4は指示・Skillに残す(分かりやすさは白黒がつかない判断)。

</details>

## 確認クイズ

### Q1. 「たまに破られると事故になる決まり」の置き場所として、最も確実なのはどれですか。

- A. CLAUDE.mdに太字で書く
- B. Skillの手順に書く
- C. 必ず実行されるhookにする

<details>
<summary>答え</summary>

**C** — 指示とSkillは読んで従う道具なので、抜けがゼロになりません。必ず実行されるのはhookだけです。

</details>

### Q2. hookの設定を考えるとき、最初に決める組はどれですか。

- A. イベント(いつ)と処理(何を)
- B. 担当者と締め切り
- C. ファイル名と行数

<details>
<summary>答え</summary>

**A** — hookはイベントに処理を結びつける仕組みです。「実行の前・あと」のどちらに何を差し込むかを決めます。

</details>

### Q3. 「編集のあとにフォーマッタを実行するhook」で得られる効果はどれですか。

- A. コードの設計が良くなる
- B. 整形の実行し忘れという事態がなくなる
- C. テストが自動で書かれる

<details>
<summary>答え</summary>

**B** — 編集のたびにフォーマッタが必ず実行されるので、実行し忘れという概念がなくなります。設計やテストの中身はhookの整形では変わりません。

</details>

### Q4. 取り消せない削除コマンドへの備えとして、hookを使う適切な形はどれですか。

- A. 実行のあとに削除を記録する
- B. 実行の前に内容を検査して止める
- C. 削除のたびに謝罪文を生成する

<details>
<summary>答え</summary>

**B** — 取り消せない操作は、実行されてからでは戻せません。実行前のイベントで検査して止めるのが正しい形です。

</details>

### Q5. hookにしてよいものを見分ける問いとして適切なのはどれですか。

- A. その決まりは重要か
- B. その条件は機械的に判定できるか(文字で書き切れるか)
- C. その決まりは最近できたか

<details>
<summary>答え</summary>

**B** — 重要でも、白黒がつかない判断はhookにできません。機械的に判定できる決まりだけをhookにし、判断は指示とSkillに残します。

</details>
