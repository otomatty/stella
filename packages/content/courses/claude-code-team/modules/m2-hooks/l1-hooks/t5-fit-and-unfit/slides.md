# 2-1-5
# hookに向くのは機械的な決まり

検証・hooks・MCP — Module 2 / レッスン2-1

<!-- ノート: M2の締めです。hookの向き不向きを線引きします。 -->

---

## なぜ必要か

- 「必ず実行される」は強力なので、何でもhookにしたくなる
- 向かないものをhookにすると、誤って止めたり、形だけの検査になったりする

<!-- ノート: 強い道具ほど、使いどころの線引きが要ります。 -->

---

## 結論

**hookに向くのは機械的に判定できる決まりで、判断が要るものは指示とSkillに残します**

- **決まり** — 例外なく守られてほしいルール(講座5で扱った語です)
- **機械的** — 条件に合うかどうかを、迷いなく判定できること
- 「良い設計か」のような問いは機械的に判定できません

<!-- ノート: hookにできるのは、白黒がつく検査だけです。灰色の判断を機械に任せてはいけません。 -->

---

## 最小の例

```text
機械的に判定できる       整形されているか
(hookに向く)           危険な削除の形か

判断が要る              この設計でよいか
(指示とSkillに残す)     この命名は分かりやすいか
```

<!-- ノート: 見分けの問いは「条件を文字で書き切れるか」です。書き切れないものは、人とエージェントの判断の領分です。 -->

---

## 置き場の線引き

| 内容 | 置き先 |
| --- | --- |
| 白黒がつく検査・後始末 | hook |
| 文脈で変わる判断 | 指示 / Skill |

<!-- ノート: 講座5の使い分けの地図に、hookの行が確定で埋まりました。次のモジュールは、外の道具を繋ぐMCPです。 -->
