# 危険なコマンドは実行前に止める

検証・hooks・MCP — Module 2 / レッスン2-1

<!-- ノート: 「実行の前」に結びつけるhookの代表例です。安全装置の話になります。 -->

---

## なぜ必要か

- 消す・上書きするなど、実行したら取り消せないコマンドがある
- 「危ないことはしないで」という指示だけでは、確実とは言えない

<!-- ノート: 講座4の「取り消せない操作は自動承認から外す」の続きです。人の承認に加えて、もう1枚の壁を作れます。 -->

---

## 結論

**実行前のhookで危険なコマンドを見分けて、実行そのものを止められます**

- **コマンド** — ツールとして実行される命令(講座4で扱った語です)
- **危険なコマンド** — 取り消せない削除や上書きなど、事故につながる命令
- **止める** — 条件に合ったら実行させずに終わらせること

<!-- ノート: あとから謝るより、前で止める。実行前イベントだからできる芸当です。 -->

---

## 最小の例

```text
hookの設定(意味だけ)

  イベント:  コマンドの実行の前
  処理:      内容を検査し、危険な削除の形なら止める

→ 該当するコマンドは、そもそも実行されない
```

<!-- ノート: どのコマンドを危険とみなすかはプロジェクトで決めます。綴りではなく、前で検査して止めるという型を持ち帰ってください。 -->

---

## 指示と実行前hookの二段構え

| 層 | 役割 |
| --- | --- |
| 指示「危険な操作は避けて」 | ふだんの行動を方向づける |
| 実行前のhook | 万一のときに機械的に止める |
