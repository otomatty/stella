# hookは必ず実行される

## なぜ必要か

- 指示は読んで従うものなので、読み落としがゼロにならない
- 「たまに破られる」では困る決まりが、プロジェクトにはある

<!-- ノート: CLAUDE.mdに太字で書いても、指示という道具の限界は残ります。講座5で判断だけ通した話の続きです。 -->

---

## 結論

**hookは指示と違って、決めたタイミングで必ず実行される仕組みです**

- **hook** — 決めたタイミングで、決めた処理を自動で実行する仕掛け
- 指示は読んで従うもの、hookは機械的に実行されるもの
- Skillは呼ばれて効く、hookは呼ばなくても効く

<!-- ノート: hook・指示・仕組みは講座5で扱った語です。「守ってもらう」から「守られる状態を作る」への切り替えです。 -->

---

## 最小の例

```text
指示   「コミット前に必ず整形してね」
       → ほぼ守られる。でも、たまに抜ける

hook   コミット前に整形が自動で実行される
       → 抜けようがない
```

<!-- ノート: 講座5でも見た対比です。この講座では、この「自動で実行される」側を実際に作れるようになります。 -->

---

## 3つの入れ物の効き方

| 入れ物 | 効き方 |
| --- | --- |
| 指示(CLAUDE.mdなど) | 読んで従う。破られうる |
| Skill | 呼ばれたとき効く |
| hook | 決めたタイミングで必ず実行される |
