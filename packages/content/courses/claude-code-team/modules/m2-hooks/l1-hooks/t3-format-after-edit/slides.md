# 2-1-3
# 整形はhookで抜けなくする

検証・hooks・MCP — Module 2 / レッスン2-1

<!-- ノート: 「実行のあと」に結びつけるhookの代表例です。 -->

---

## なぜ必要か

- 「整形してからコミットして」という指示は、たまに抜ける
- 整形の抜けは、レビューで人が指摘するには惜しい仕事

<!-- ノート: 整形はどのプロジェクトにもある、機械で片づくのに人が指摘しがちな仕事です。 -->

---

## 結論

**編集のあとにフォーマッタを実行するhookにすると、整形が抜けなくなります**

- **編集** — エージェントがファイルを書き換える操作
- **フォーマッタ** — コードの見た目を決まった形に揃える道具
- **整形** — フォーマッタで形を揃えること

<!-- ノート: 編集というイベントのあとに、フォーマッタという処理を結びつける。前のトピックの組をそのまま使います。 -->

---

## 最小の例

```text
hookの設定(意味だけ)

  イベント:  ファイルの編集のあと
  処理:      そのファイルにフォーマッタを実行する

→ 編集のたびに、フォーマッタが自動で実行される
```

<!-- ノート: 設定の綴りは製品のドキュメントで確認します。覚えるのは「編集のあとに整形」という組だけです。 -->

---

## 指示との違い

| やり方 | 結果 |
| --- | --- |
| 指示「整形を忘れないで」 | 忘れた日は乱れが混ざる |
| 編集のあとのhook | 実行し忘れという概念がなくなる |

<!-- ノート: M0でやった「機械に任せられる検査は機械に」の実践です。保証されるのは実行までで、フォーマッタ自体が失敗したら結果を見て直します。次は反対側、実行の前に止めるhookです。 -->
