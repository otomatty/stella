# 仕組み化は順番で回す

## なぜ必要か

- 道具を全部知っていても、どの順で使うかで迷うと手が止まる
- 迷わない順番を1本持っておくと、現場でそのまま回せる

<!-- ノート: 知識を手順に変えるのがこのトピックです。 -->

---

## 結論

**繰り返しに気づいたら、入れ物を選ぶ・検証を付ける・チームに配るの順で仕組みにします**

- **仕組み化** — 繰り返しの作業や指示を、仕組みとして置くこと(講座5で扱った語です)
- **入れ物** — CLAUDE.md・Skill・サブエージェント・hookの置き先(講座5で扱った語です)

<!-- ノート: 気づく→選ぶ→検証を付ける→配る。4歩のチェックリストです。 -->

---

## 最小の例

```text
仕組み化のチェックリスト

  1. 気づく       同じ指示・同じ確認を繰り返していないか
  2. 選ぶ         いつ効いてほしいかで入れ物を選ぶ
  3. 検証を付ける  その仕組みが正しく動くことを確かめる
  4. 配る         チームに効かせるならリポジトリへ
```

<!-- ノート: 3が今回の講座で足した歩です。仕組み自体も生成と同じで、検証してから配ります。 -->

---

## つまずきやすい所

| 抜けた歩 | 症状 |
| --- | --- |
| 2を飛ばす | 全部CLAUDE.mdに詰め込む |
| 3を飛ばす | 動かない仕組みが配られる |
| 4を忘れる | 自分だけ便利で、チームは変わらない |

<!-- ノート: どの歩が抜けても仕組み化は失敗します。チェックリストとして使ってください。 -->
