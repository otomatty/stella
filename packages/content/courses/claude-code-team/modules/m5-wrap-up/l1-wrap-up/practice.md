# レッスン5-1 演習 — 4Dに戻して締める

対象トピック: 5-1-1 〜 5-1-3

## 手元で試す

シリーズの総仕上げです。VS Code が使えない場合も、紙の上ですべて成立します。

1. この講座で作ったもの(検証Skill・hookの案・MCPの設定・チーム/個人の振り分け)を、4D(任せる・伝える・見極める・責任を持つ)のどれの実践かで分類する
2. 仕組み化のチェックリスト(気づく→選ぶ→検証を付ける→配る)を、自分のメモの見えるところに書き写す
3. 明日の実務から小さなタスクを1本選び、「任せる範囲」「検証のしかた」「終わったら仕組みにする候補」を3行で書く
4. Claude Code が使えるなら、3のタスクを実際に1本通す。通したら、繰り返しに気づいたものを1つだけ仕組みにする

## 演習問題

### 問1(基本)

「テスト・lint・自分の目で確かめる」は4Dのどれの実践ですか。理由とあわせて1〜2文で書いてください。

### 問2(基本)

仕組み化のチェックリストの4歩を、順番どおりに書いてください。

### 問3(応用)

「便利なhookを思いついたので、動作確認せずにすぐリポジトリにコミットして配った」という進め方の問題点を、チェックリストの歩を使って2文以内で指摘してください。

### 問4(応用)

「シリーズを終えたので、まずチームの仕組みを全部整えてからClaude Codeを使い始めたい」という同僚に、この講座の締めに沿った助言を2〜3文で書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

見極める(Discernment)の実践です。生成された変更という仮説を、証拠で確かめて受け取る作業だからです。

</details>

<details>
<summary>問2の解答例</summary>

1. 気づく(同じ指示・確認の繰り返しに気づく) 2. 選ぶ(いつ効いてほしいかで入れ物を選ぶ) 3. 検証を付ける(仕組みが正しく動くことを確かめる) 4. 配る(チームに効かせるならリポジトリへ)です。

</details>

<details>
<summary>問3の解答例</summary>

3の「検証を付ける」を飛ばしているので、動かない仕組みがチーム全員に配られるおそれがあります。仕組みも生成した変更と同じ仮説なので、検証してから配ります。

</details>

<details>
<summary>問4の解答例</summary>

全部整えてから始めようと構えている間は、何も変わりません。まず実務の小さな1タスクに使い、繰り返しに気づいたものを1つずつ仕組みにしていくのがこのシリーズの進め方です。1タスクごとに1つ増えれば十分です。

</details>

## 確認クイズ

### Q1. 「任せてよい範囲を、自分が検証できる範囲で決める」は4Dのどれに最も近いですか。

- A. 任せる(Delegation)
- B. 伝える(Description)
- C. 責任を持つ(Diligence)

<details>
<summary>答え</summary>

**A** — 何をどこまで任せるかの判断はDelegationの実践です。検証可能性がその判断基準になります。

</details>

### Q2. 仕組み化のチェックリストで、「入れ物を選ぶ」の次にやることはどれですか。

- A. すぐにチームへ配る
- B. 仕組みが正しく動くことを検証する
- C. もっと大きな仕組みに育てる

<details>
<summary>答え</summary>

**B** — 選んだら、検証を付けてから配ります。検証を飛ばすと、動かない仕組みが配られます。

</details>

### Q3. 「気づく→選ぶ→検証を付ける→配る」のうち、「配る」を忘れたときの症状はどれですか。

- A. CLAUDE.mdに手順書が詰め込まれる
- B. 動かない仕組みがチームに広がる
- C. 自分だけ便利になり、チームは変わらない

<details>
<summary>答え</summary>

**C** — 配らなければ仕組みは手元に留まります。Aは「選ぶ」を飛ばした症状、Bは「検証を付ける」を飛ばした症状です。

</details>

### Q4. シリーズを終えたあとの始め方として、この講座が勧めるのはどれですか。

- A. チームの仕組みを全部整えてから使い始める
- B. 実務の小さな1タスクに使うことから始める
- C. 大きな改修を任せて一気に効果を出す

<details>
<summary>答え</summary>

**B** — 小さく始めて、1タスクごとに仕組みを1つずつ増やします。全部整うのを待つ間は何も変わらず、大きな改修は検証できる範囲を超えます。

</details>
