# Salesforce 開発 入門 カリキュラム

Salesforce は「アプリを載せる土台」であって、開発者が最初に覚えるのは言語ではなく**土台の作法**です。
この講座は、オブジェクトと項目でできたデータモデルの読み方を軸に、SOQL・Apex トリガ・テストまでを一巡します。
通す考え方は 1 つ、**「設定でできることは設定で、足りないところだけコードで」**です。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- コード演習: なし(自動採点のランナーは JavaScript / TypeScript / SQL のみで、Apex は対象外)
- 手を動かす部分: 各レッスンの `practice.md`「手元で試す」— 無償の Developer Edition 組織で行う
- 図解: 6 枚(下記「図解の入っているトピック」)
- 対象外: Visualforce、Aura コンポーネント、LWC の実装、非同期 Apex(Batch / Queueable / Future)、
  外部システム連携(REST/SOAP コールアウト)、Sales Cloud / Service Cloud の業務機能、
  Salesforce CLI・DevOps Center を使ったリリース作業の実務手順

## 掲載範囲 — ユーザー専用星(`audience: granted`)

この講座は `course.json` に `"audience": "granted"` を持ちます。seed しても全受講者のスキルツリーには出ず、
講師・管理者が「専用教材」画面(`/stage-grants`)で選んだ受講者だけに星が出ます。

- Salesforce 案件は配属が決まった人にだけ必要で、全員のツリーに常設すると入口が散らかるため
- 割当はマップ掲載のみ。受講開始は従来どおり自己開始(`POST /api/stages/:id/start`)
- 開発者モード(FAB)で霧や島を素通ししても、未割り当ての専用星は出ない

仕様は `docs/superpowers/specs/2026-09-01-granted-stage-audience-design.md`。

### 置き場所は「Salesforce案件」島

`category` は新設の島 `Salesforce案件`(`@stella/shared/skill-map/islands` に追加、表示条件は他の島と同じ `it-basics`)です。
本土の扇に混ぜなかった理由は 2 つあります。

- **枝の本数**: 前提の `sql-basics` にはすでに `cli-basics` と `db-design-basics` がぶら下がっていて、
  「1 つの星から出る枝は最大 2 本」(`manifest.test.ts` が検査)に当たる
- **性格**: Salesforce は本土(FE / BE)の続きではなく、資格や AI と同じ「目的別の入り口」。
  島は本土から橋線を引かないので、`sql-basics` の枝を増やさずに前提だけを効かせられる

`prerequisites` の `sql-basics` はハードロックとして効き、未クリアの受講者にはロック理由として名前が出ます。
島には他に catalog の講座を置いていないので、**割り当てのない受講者には島ごと現れません**
(島に残る星が 0 件になるため)。

## 教材要件シート

- 講座名 / slug: Salesforce 開発 入門 / `salesforce-dev-basics`
- 新講座 or 既存講座への追加: 新講座
- 対象者(受講直前の状態): SQL 入門を終え、Salesforce 案件への配属が決まった(または候補になっている)メンバー。
  プログラミング経験は数ヶ月。Salesforce の管理画面は触ったことがない
- 前提講座: `sql-basics`(SOQL は SELECT / WHERE / 並べ替えの語彙をそのまま使う)
- 到達目標(観測可能な動詞で 5 個)
  - [ ] オブジェクト・項目・リレーションの図から、業務データの持ち方を説明できる
  - [ ] 参照関係と主従関係を、要件に合わせて選べる
  - [ ] 欲しいレコードを SOQL で取り出せる(親子をまたぐものを含む)
  - [ ] 一括処理の作法(ループの中で SOQL / DML を呼ばない)を守った Apex トリガを書ける
  - [ ] テストクラスを書き、失敗したときにデバッグログから原因を追える
- スコープ外: 上記「対象外」の行をそのまま
- 評価方法: 確認クイズ **あり**(全 9 レッスン) / コード演習 **なし** / ハンズオン **あり**(Developer Edition 組織)
- 規模: 7 モジュール / 9 レッスン / 34 トピック
- 出典: Salesforce Certified Platform Developer I 試験ガイド(下記「クレジット」)
- クレジットの置き場所: このファイル
- 書く人 / 改訂する人: 教材チーム

### なぜ Platform Developer I の範囲に合わせたか

Salesforce エンジニアに求められる知識は現場ごとにばらけますが、**公式が「開発者に最低限これを求める」と
公表している唯一の範囲**が Platform Developer I の試験ガイドです。ここに合わせておくと、
配属先が変わっても土台が効き、受講者が次に資格を取りにいくときの地図にもなります。

試験ガイドの 5 領域と、この講座のモジュールの対応:

| 試験ガイドの領域(比重) | この講座 |
| --- | --- |
| Salesforce Fundamentals (7%) | M0. オリエンテーション |
| Data Modeling and Management (13%) | M1. データモデル / M2. アクセス権 |
| Process Automation and Logic (38%) | M3. SOQL / M4. Apex / M6-1-2 Flow |
| User Interface (25%) | M6. 画面と自動化 |
| Testing, Debugging, and Deployment Tools (17%) | M5. テストとリリース |

比重どおりの分量にはしていません。入門講座なので、**未経験者がつまずく順**に並べ替えてあります。
比重最大の Process Automation and Logic(38%)は M3 + M4 の 12 トピックで最も厚く、
User Interface(25%)は LWC の実装を対象外にしたぶん 3 トピックに畳んでいます。

## 図解の入っているトピック

図解は「表では伝わらないもの(関係性・流れ・重なり)」だけに入れています。2 列の対比や 3 行以上の分類は
`doc.md` の表のままにしてあります(`.claude/skills/diagram-design/SKILL.md` の「表で足りるなら表にする」)。

| トピック | 型 | 何を見せているか |
| --- | --- | --- |
| 0-1-1 | layers | 土台・標準アプリ・自分たちで足す分の 3 層。下 2 層は最初から在る |
| 1-2-2 | comparison | 親を消したとき / 親が空の子を作るときの、参照関係と主従関係の違い |
| 2-1-1 | layers | オブジェクト → 項目 → レコードの 3 つの関所を順に通る |
| 3-1-4 | tree | 同じ 2 つのオブジェクトでも、たどる向きで使う名前が変わる |
| 4-2-4 | process | 1 トランザクションの中で上限を超えると、成功していた分も巻き戻る |
| 6-1-3 | layers | LWC がデータを取るときに試す順番(標準の部品 → データサービス → Apex) |

正本は各トピックの `assets/<名前>.html`、`slides.md` / `doc.md` が参照するのは同じ名前の `.svg`(生成物)。
作図の規約は `.claude/skills/diagram-design/`、配色・寸法の正本は同ディレクトリの
`references/style-guide.md` です。

## 語彙の順序

`slides.md` の front-matter `introduces` / `requires` が、この講座の中だけで前後関係を作ります
(語彙台帳は講座をまたがないので、`sql-basics` で導入済みの `WHERE` などもこの講座で導入し直しています)。
M0 で「組織」「プラットフォーム」「ガバナ制限」を、M1 で「オブジェクト」「レコード」「項目」を置き、
以降のモジュールはそこから積み上げます。

  (66.0 以前は既定がシステムモード)。トリガはバージョンに関わらず常にシステムモードです。
  2-1-4 と 4-2-1 はこの仕様で書いてあり、**それ以前に書かれた解説記事とは食い違います**。
