# 6-1-1
# レコードページを組み立てる

Salesforce開発入門 — Module 6 / レッスン6-1

<!-- ノート: Module 6の始まりです。画面まわりも「設定が先」であることを、まず見せます。 -->

---

## なぜ必要か

- 「商談の画面に関連する見積を出したい」と頼まれる
- 画面と聞くと、まず HTML を書く場所を探してしまう

<!-- ノート: つかみ。他の基盤の経験がある人ほど、コードから入ろうとする。ここでも順番の話になる。 -->

---

## 結論

**レコードページは、部品を置く設定画面で組み立てる**

- **レコードページ** — 1 件のレコードを表示する画面
- **コンポーネント** — 画面に置ける部品
- **Lightning アプリケーションビルダー** — 部品を並べて画面を作る設定画面

<!-- ノート: 結論を言い切る。標準の部品だけでかなりの要件が満たせる。項目の表示、関連リスト、活動履歴などが最初から在る。 -->

---

## 置ける部品の例

| 部品 | 出るもの |
| --- | --- |
| 項目のセクション | レコードの項目 |
| 関連リスト | 子レコードの一覧 |
| カスタムのコンポーネント | 自作の部品 |

- 並べ替えも、表示条件の設定もクリックでできる

<!-- ノート: 具体例。冒頭の「関連する見積を出したい」は関連リストで済む場合が多い。まず標準の部品を探す、という順番を作る。 -->

---

## 画面はプロファイルごとに変えられる

- 同じオブジェクトでも、割り当てるページを分けられる
- 営業には簡潔な画面、管理者には全項目の画面

<!-- ノート: 対比枠。1つの画面を条件分岐だらけにする前に、割り当てで分ける手がある。コードを書く前に潰せる要件の代表例。 -->
