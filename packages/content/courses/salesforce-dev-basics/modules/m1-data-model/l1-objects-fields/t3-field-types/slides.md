# 1-1-3
# 項目の型

Salesforce開発入門 — Module 1 / レッスン1-1

<!-- ノート: 項目を足すときの最初の分岐です。あとから直しにくいところなので、慎重さの理由まで渡します。 -->

---

## なぜ必要か

- 項目を作る画面は、最初に型を聞いてくる
- 適当にテキストを選ぶと、あとで合計も並べ替えもできない

<!-- ノート: つかみ。型の選択が最初にあるのは偶然ではなく、後戻りしにくいから先に聞かれる、と匂わせる。 -->

---

## 結論

**項目は先にデータ型を決めてから作る**

- **データ型** — その項目に入れてよい値の種類
- 型が決まると、入力チェック・並べ替え・集計のふるまいも決まる

<!-- ノート: 結論を言い切る。型は入れ物の形であり、後続の機能がその形を前提に動くことを補足する。 -->

---

## よく使う型

| 型 | 入るもの |
| --- | --- |
| テキスト | 名前・メモ |
| 数値 / 通貨 | 個数・金額 |
| 日付 | 期日 |
| 選択リスト | 決まった選択肢から 1 つ |
| チェックボックス | はい / いいえ |

<!-- ノート: 具体例。数値と通貨の違い、選択リストとテキストの違いを口頭で補う。選択肢が決まっているならテキストにしない。 -->

---

## 計算した値は持たせない

- **数式項目** — 他の項目から自動で計算される、読み取り専用の項目
- 単価 × 数量のような値は、保存せず数式項目にする
- 保存すると、元の値を直したときに食い違う

<!-- ノート: 失敗例の枠。合計を普通の数値項目で持ってしまい、更新漏れでずれる事故はよくある。計算できるものは計算させる。 -->
