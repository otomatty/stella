# 外部IDで他システムのキーを持つ

Salesforce開発入門 — Module 1 / レッスン1-1

<!-- ノート: レッスン1-1の最後です。連携案件では必ず出てくるので、入門でも触れておきます。 -->

---

## なぜ必要か

- 基幹システムから取引先データを毎晩取り込みたい
- 取り込むたびに新しいレコードが増えて、同じ会社が何件も並ぶ

<!-- ノート: つかみ。連携でいちばん多い事故。名前で突き合わせようとして表記ゆれで失敗する、という現場感を添える。 -->

---

## 結論

**他システムのキーを外部 ID 項目に持たせると、その値でレコードを指定できる**

- **ID** — Salesforce が全レコードに自動で付ける、組織内で一意の値
- **外部 ID** — 他システムの一意なキーを入れておく項目

<!-- ノート: 結論を言い切る。Salesforce側のIDは取り込み元は知らない。だから相手の番号を持っておく、という向きを説明する。 -->

---

## 取引先に社内コードを持たせる

| 取引先名 | 社内コード(外部 ID) |
| --- | --- |
| 富士商事 | `AC-0012` |
| 北星建設 | `AC-0037` |

- 取り込み側は `AC-0012` を指すだけでよい

<!-- ノート: 具体例。外部IDは「重複しない」設定を併せて付けるのが定石。コードを持っていれば、名前が変わっても同じレコードを指せる。 -->

---

## upsert で重複を防ぐ

- **upsert** — 外部 ID に一致するレコードがあれば更新、なければ作成
- 取り込みを何度流しても、レコードは増えない

<!-- ノート: 対比枠。insertだけだと毎回増える。upsertは外部IDを鍵にして探してから決める。Module 4のDMLで再登場すると口頭で触れる。 -->
