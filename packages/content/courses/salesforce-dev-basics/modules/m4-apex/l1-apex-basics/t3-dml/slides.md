# 4-1-3
# DMLでレコードを保存する

Salesforce開発入門 — Module 4 / レッスン4-1

<!-- ノート: 変数を触っただけでは何も保存されない、という区別がこのトピックの肝です。 -->

---

## なぜ必要か

- 変数の項目を書き換えたのに、画面を見ても値が変わっていない
- コードは通っているので、どこが足りないのかわからない

<!-- ノート: つかみ。初学者が必ず一度は踏む。エラーも出ないので気づきにくい。 -->

---

## 結論

**DML(`insert` / `update` / `delete`)がレコードを実際に書き換える**

- **DML** — データベースへの書き込みを指示する命令
- 変数の書き換えは、まだメモリの中の話

<!-- ノート: 結論を言い切る。取り出す(SOQL)と書き込む(DML)は別の命令で、書き込みは明示しないと起きない。 -->

---

## 最小のコード

```apex
Account acc = new Account(Name = '富士商事');
insert acc;
acc.Phone = '03-1111-2222';
update acc;
```

- `insert` で新規作成、`update` で更新、`delete` で削除

<!-- ノート: 最小のコード。insertした時点でIDが割り当てられ、以降のupdateはそのIDのレコードを直す。行ごとに何が起きるか指差す。 -->

---

## 4 つ目の命令

| 命令 | 動き |
| --- | --- |
| `insert` | 必ず新規作成 |
| `update` | 必ず更新 |
| `upsert` | 外部 ID で探して、無ければ作成 |

- 取り込み処理では `upsert` が定石

<!-- ノート: 対比枠。1-1-4の外部IDがここで効いてくる。取り込みでinsertを使うと重複が増える、という流れを再確認する。 -->
