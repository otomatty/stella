# Apexはどこで動くか

Salesforce開発入門 — Module 4 / レッスン4-1

<!-- ノート: Module 4の始まりです。書き方の前に、どこで動くのかを押さえます。動く場所が制限の理由になっています。 -->

---

## なぜ必要か

- JavaScript のようにブラウザで動くのか、サーバーで動くのかが曖昧なまま書き始めてしまう
- 動く場所がわからないと、なぜ制限があるのかも腑に落ちない

<!-- ノート: つかみ。動作場所の曖昧さは、デバッグの方法がわからない原因にもなる。 -->

---

## 結論

**Apex は Salesforce のサーバー上で動く、この基盤専用の言語である**

- **クラス** — Apex のコードを入れるまとまり
- **メソッド** — クラスの中の、処理のまとまり
- **トランザクション** — 1 回の処理のまとまり。制限はこの単位で数える

<!-- ノート: 結論を言い切る。文法はJavaに近いが、動くのは常にSalesforceのサーバー。手元のPCでは動かせない。 -->

---

## 最小のクラス

```apex
public class OrderService {
  public static Integer countOrders() {
    return [SELECT COUNT() FROM Order__c];
  }
}
```

- SOQL をコードの中に直接書ける

<!-- ノート: 最小のコード。クラスとメソッドの入れ物、その中に角かっこ無しでSOQLが書けることを示す。COUNT()は件数だけを返す形。 -->

---

## トランザクションという単位

- ユーザの 1 回の操作 = 1 トランザクション
- ガバナ制限は、このトランザクションごとに数え直される
- 途中で失敗すると、その中の変更は**すべて無かったことになる**

<!-- ノート: 対比枠。制限の数え方と巻き戻しの単位が同じであることを先に置く。4-2-4で詳しくやると口頭で触れる。 -->
