# レッスン2-1 演習 — 誰が何を見られるか

対象トピック: 2-1-1 〜 2-1-4

## 手元で試す

Developer Edition 組織で、アクセス権の 3 つの層を実際に動かします。

**自分のログインだけでは確かめられません。** システム管理者は「すべてのデータの参照」を持っていて、
どの層を閉じても見えてしまいます。まず検証用のユーザを 1 人作り、そのユーザとしてログインして
確かめる形にします(Developer Edition には Salesforce ライセンスが 2 つあります)。

1. **検証用ユーザを作る** — 設定 →「ユーザ」→「新規ユーザ」。ユーザライセンス `Salesforce`、
   プロファイル `標準ユーザ`。メールは自分のアドレスに `+test` を足したもの(`you+test@example.com`)で構いません。
   届いたメールからパスワードを設定しておきます
2. **ユーザとしてログインできるようにする** — 設定 →「ログインアクセスポリシー」で
   「管理者がユーザとしてログインすることを許可」にチェックを入れて保存します。
   以降は ユーザの詳細ページ →「ログイン」で切り替えられます(戻るときは画面上部の「元に戻る」)
3. **オブジェクトの層** — まず検証用ユーザとしてログインし、点検タブが**無い**ことを確かめます。
   管理者に戻って 設定 →「プロファイル」→`標準ユーザ`→ カスタムオブジェクト権限で `点検` の
   「参照」「作成」を許可し、タブ設定を「デフォルトオン」にします。もう一度ログインすると
   タブが現れます
4. **項目の層** — 管理者に戻り、オブジェクトマネージャ →`点検`→「項目とリレーション」→`点検料`→
   「項目レベルセキュリティの設定」で、`標準ユーザ` の「参照可能」のチェックを外します。
   検証用ユーザでログインすると、点検レコードは開けるのに `点検料` の欄だけが無いことを確かめます
5. **権限セットで足す** — 設定 →「権限セット」→「新規」で `点検料の参照` を作り、
   項目権限で `点検料` の「参照」を許可します。**「割り当ての管理」から検証用ユーザに割り当てる**
   のを忘れないでください。ログインし直すと点検料が見えます(プロファイルは触っていません)
6. **レコードの層** — 管理者で点検を 1 件作ってから、設定 →「共有設定」で `点検` の
   既定の内部アクセス権を「非公開」にします。検証用ユーザでログインすると、
   自分が所有していない点検が一覧から消えることを確かめます
7. **元に戻す** — 共有設定を戻し、確認が済んだら検証用ユーザを無効化しておきます

```text
確かめること
- 3 の前は、項目や共有をどう変えてもタブごと出てこない(上の層が閉じている)
- 4 では、項目だけが消えてレコード自体は一覧に残る(層が違う)
- 5 はプロファイルを触らずに 1 人だけへ足せている
- 6 では、レコードごと一覧から消える
```

## 演習問題

### 問1(基本)

次の 3 つの症状について、疑うべき層(オブジェクト / 項目 / レコード)を答えてください。

1. アプリのタブに「点検」が出てこない
2. 点検の一覧は見えるが、点検料の列だけ表示されない
3. 点検の一覧に、自分が作ったレコードしか出てこない

### 問2(基本)

「営業チームの中で、佐藤さんにだけ原価項目を見せたい」と頼まれました。プロファイルと権限セットのどちらをどう使いますか。1〜2 文で答えてください。

### 問3(応用)

自作の Apex が返す一覧に、本来は見えないはずの他人のレコードが混ざっていました。原因として何が考えられ、どう確かめますか。2〜3 文で説明してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

1 はオブジェクトレベル、2 は項目レベル、3 はレコードレベルです。3 つは AND で効くので、上の層が閉じていれば下をいくら広げても変わりません。調査は上から順に確かめます。

</details>

<details>
<summary>問2の解答例</summary>

営業プロファイルは触らず、原価項目を参照できる権限セットを作って佐藤さんにだけ割り当てます。プロファイルを直すと営業全員に見えてしまいます。

</details>

<details>
<summary>問3の解答例</summary>

その Apex の API バージョンが 66.0 以前で、既定がシステムモードになっている可能性があります。まず API バージョンと `with sharing` / `without sharing` の宣言を確かめます。古いバージョンで宣言も無ければ共有を無視するので、`with sharing` を明示します。API バージョンを上げても既定はユーザモードになりますが、そのクラスの検索も更新も一斉に権限の確認を通るようになるため、取得できるレコードが減ったり例外になったりします。**版を上げるなら、そのクラス全体をテストし直してからにしてください。**トリガから呼ばれている場合も、トリガ自体は常にシステムモードなので、呼び出し先の宣言を見ます。

</details>

## 確認クイズ

### Q1. アクセス権の 3 つの層の関係として正しいものはどれですか。

- A. どれか 1 つが許可していれば見える
- B. 3 つすべてが許可して初めて見える
- C. レコードレベルだけが効き、他は補助的なもの

<details>
<summary>答え</summary>

**B** — AND で効きます。オブジェクトが閉じていれば、項目やレコードをいくら広げても見えません。

</details>

### Q2. プロファイルと権限セットの違いとして正しいものはどれですか。

- A. プロファイルは 1 人に 1 つ、権限セットは何枚でも割り当てられる
- B. プロファイルは足すためのもの、権限セットは引くためのもの
- C. どちらも同じもので、名前が違うだけ

<details>
<summary>答え</summary>

**A** — この数の違いが使い分けの根拠になります。差分は権限セットで表現します。

</details>

### Q3. 「特定の 1 人だけに、ある項目を見せなくしたい」という要件への対応として正しいものはどれですか。

- A. その人に「参照を禁止する」権限セットを割り当てる
- B. 土台のプロファイル側を狭くして、見せたい人にだけ権限セットで足す
- C. 共有ルールでその人を除外する

<details>
<summary>答え</summary>

**B** — 権限セットも共有ルールも、広げる方向にしか動きません。狭い既定に足していく向きで設計します。

</details>

### Q4. 組織の共有設定の役割として正しいものはどれですか。

- A. オブジェクトごとに、レコードを所有者以外に見せるかどうかの既定値を決める
- B. ユーザがログインできる時間帯を決める
- C. 項目ごとの入力チェックを決める

<details>
<summary>答え</summary>

**A** — レコードレベルの出発点です。ここから共有ルールで広げていきます。

</details>

### Q5. API バージョン 67.0 以降の Apex について、正しいものはどれですか。

- A. データベース操作は既定でユーザモードになり、実行ユーザの権限に従う
- B. データベース操作は既定でシステムモードのままで、権限を確認しない
- C. Apex からはアクセス権をいっさい制御できない

<details>
<summary>答え</summary>

**A** — 66.0 以前は既定がシステムモードでした。同じ書き方でも API バージョンで意味が変わるので、案件のコードを読むときはまずバージョンを確かめます。

</details>
