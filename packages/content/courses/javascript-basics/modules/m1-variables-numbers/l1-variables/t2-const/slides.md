# 1-1-2
# 基本はconstで宣言する

JavaScript入門研修 — Module 1 / レッスン1-1

<!-- ノート: let一択だと思ったところに、実務の既定であるconstを入れます。 -->

---

## なぜ必要か

- letで宣言した変数は、あとから中身を入れ替えられてしまう
- 「変わらないはずの値」がどこかで書き換わると、追うのが大変
- 入れ替えできない宣言があれば、事故を仕組みで防げる

<!-- ノート: つかみ。消費税率が途中で書き換わっていた、という論理エラーの匂いがする例で話します。 -->

---

## 結論

**変数は基本constで宣言し、後から入れ替えるものだけletにする**

- 変数の中身を入れ替えることを **再代入** という
- **const** = 再代入できない宣言。まずこちらを使う

<!-- ノート: 結論。選び方の既定を先に決めてしまいます。実務のコードもconstが大半です。 -->

---

## 最小のコード

```js
const taxRate = 0.1;
taxRate = 0.2;  // エラー: 再代入できない
```

```js
let count = 0;
count = 1;      // letなら再代入できる
```

<!-- ノート: constへの再代入はTypeError。エラーが「守ってくれている」という見方を伝えます。 -->

---

## 使い分けの目安

| 値の性質 | 宣言 |
| --- | --- |
| 一度決めたら変わらない(税率・名前) | `const` |
| 進行中に変わる(件数・合計) | `let` |

- 迷ったら `const` で書き、再代入が必要になったら `let` に変える

<!-- ノート: 対比枠。「まずconst、必要になったらlet」の順で考えると迷いません。 -->
