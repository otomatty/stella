# レッスン0-2 書いて直す

## このレッスンの目標

- [ ] 少し書くたびに保存・再読み込み・コンソール確認の一周を回せる
- [ ] エラーメッセージから種類と行番号を読み取れる
- [ ] 構文エラーと論理エラーの違いを説明できる

## 0-2-1 少し書いては動かして確かめる

> **一度に書き切らず、少し書くたびに保存して動かして確かめる**

10行書いてから初めて動かして失敗すると、10行のどこが悪いのか分かりません。1〜2行だけ書いて動かして失敗すれば、疑う場所はその1〜2行だけです。

進め方はこの一周の繰り返しです。

1. 1〜2行書く
2. **保存** する
3. ブラウザーを **再読み込み** する
4. コンソールを見る

書きかけの途中に、確認用の1行を置いても構いません。

```js
console.log("ここまで動いた");
```

これが出れば、そこまでは正しく実行されています。この小技は講座全体の「手元で試す」で使っていきます。

表示が変わらないときの確認順はHTML/CSSのときと同じです。

1. 保存したか
2. 再読み込みしたか
3. 開いているのは、いま直したファイルか

コードを疑うのは、この3つを確かめた後で十分です。

## 0-2-2 エラーメッセージは場所を教えてくれる

> **エラーメッセージには、原因の種類と起きた行番号が書かれている**

書き間違いがあると、コンソールに赤い文字が出ます。これが **エラー**(実行できなかった・失敗したという知らせ)です。**エラーメッセージ** は英語ですが、見る場所は2つだけです。

```text
Uncaught ReferenceError: prise is not defined
    at script.js:3
```

- **種類** — `ReferenceError` は「知らない名前を使った」という意味。`is not defined` は「そんな名前は知らない」と訳せます
- **行番号** — `script.js:3` は `script.js` の3行目。コンソールのエラー表示はクリックするとその行へ飛べます

この例の原因は `price` を `prise` と打ち間違えたことです。直すのは「その行」か「その1〜2行上」がほとんどです(閉じ忘れなど、直前の行に原因があるケースもあります)。

エラーは怒られではなく、直すための手がかりです。赤い文字が出たら、閉じずに種類と行番号を読む。この習慣がデバッグの第一歩です。

## 0-2-3 構文エラーと論理エラー

> **エラーには、動かない構文エラーと、動くが結果が違う論理エラーがある**

失敗には2つのタイプがあります。

```js
console.log("合計);        // 構文エラー: 閉じる"が無い
console.log(100 - 20);     // 論理エラー: 足すつもりだった
```

- **構文エラー** — 言葉のルール(**構文**)の違反。実行が止まり、エラーメッセージが出ます。上の行は引用符の閉じ忘れです
- **論理エラー** — 文法としては正しいので実行はされますが、結果が意図と違います。下の行は `80` が出て、静かに間違います

| タイプ | 手がかり | 直し方の入り口 |
| --- | --- | --- |
| 構文エラー | エラーメッセージ | 行番号の周りを直す |
| 論理エラー | 期待と違う結果 | console.logで途中の値を見る |

論理エラーはコンピューターにとって「正しい命令」なので、誰も教えてくれません。だからこそ0-2-1の「少し書くたびに確かめる」進め方が効きます。「エラーが出ていない」と「正しく動いている」は別のことです。

## もっと知りたい人へ

- エラーメッセージの種類は他にも `SyntaxError`(構文エラー)や `TypeError` などがあります。いまは暗記せず、出会うたびに「種類と行番号を読む」だけで十分です
- 英語のメッセージは、そのまま検索するとたいてい解説が見つかります。実務でも最初の一手は「メッセージで検索」です
