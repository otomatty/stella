# 6-1-3
# 関数の中の変数は外から見えない

JavaScript入門研修 — Module 6 / レッスン6-1

<!-- ノート: スコープの初回です。「見えない=安全」というポジティブな枠で伝えます。 -->

---

## なぜ必要か

- 関数の中で作った変数を、外で使ったらエラーになった
- 逆に、関数の中の変数が外を汚さないのはなぜか
- 「どこから見えるか」のルールを知っておきたい

<!-- ノート: つかみ。is not definedに実際に出会う場面を再現してから、ルールの説明に入ります。 -->

---

## 結論

**関数の中で宣言した変数は、その関数の中でしか使えない**

- 変数が見える範囲を **スコープ** という
- 関数の中だけで見える変数を **ローカル変数** という

<!-- ノート: 結論。範囲=スコープの一語だけ新しく覚えます。 -->

---

## 最小のコード

```js
function calcTotal() {
  const total = 1980 * 3;
  console.log(total);   // ここでは使える
}
calcTotal();
console.log(total);      // エラー: total is not defined
```

<!-- ノート: 中はOK、外はReferenceError。エラーメッセージの読み(0-2-2)の復習にもなります。 -->

---

## 見えないことが安全を作る

- 別の関数で同じ名前 `total` を使っても衝突しない
- 関数の外の変数は中から見えるが、頼りすぎない
- 材料は引数で渡すのが、読みやすい関数の基本形

<!-- ノート: 関連枠。「外の変数を直接使う」より「引数で受け取る」方が、関数単体で読めて再利用しやすいという実務の指針です。 -->
