# 6-2-2
# returnは関数をそこで終える

JavaScript入門 — Module 6 / レッスン6-2

<!-- ノート: returnの終了作用と、それを活かした早期リターンのスタイルを扱います。 -->

---

## なぜ必要か

- 「入力が空なら、そこから先はやることがない」
- 条件を満たさないケースをifの入れ子で包むと、どんどん深くなる
- 「ダメなら先に帰る」と書けたら、本筋がまっすぐ読める

<!-- ノート: つかみ。ネストが深いコードのつらさは、breakで打ち切る感覚(5-1-5)と地続きです。 -->

---

## 結論

**returnした時点で関数は終わり、後ろの行は実行されない**

- returnは「値を返す」と同時に「関数を終える」
- 冒頭で条件外を返して終える書き方を **早期リターン** という

<!-- ノート: 結論。ループのbreakの関数版、という対応で覚えられます。 -->

---

## 最小のコード

```js
function buildGreeting(name) {
  if (name === "") {
    return "名前が未入力です";
  }
  return `${name}さん、ようこそ`;
}
console.log(buildGreeting(""));  // => 名前が未入力です
```

<!-- ノート: 空文字のときは最初のreturnで終わり、下の行には到達しません。 -->

---

## elseが要らなくなる

- 早期リターンの後ろは「正常なケースだけ」の世界
- `else` で包まなくても、上で帰った分は流れてこない
- チェック → 本筋、の順に並べるのが読みやすい形

<!-- ノート: 関連枠。同じ関数をif/elseで書いた版と見比べると、インデントが浅くなる利点が伝わります。 -->
