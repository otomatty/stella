# 4-1-4
# 値そのものも真偽として扱われる

JavaScript入門 — Module 4 / レッスン4-1

<!-- ノート: truthy/falsyです。読めることを目標にし、書く方は「明示的な比較」を推奨します。 -->

---

## なぜ必要か

- `if (userName)` のような、比較していない条件を実務のコードでよく見る
- 真偽値でない値が条件に入ったとき、何が起きるのか
- 知らないと、他人のコードが読めない

<!-- ノート: つかみ。「入力が空でなければ」の定番イディオムとして紹介します。 -->

---

## 結論

**条件に値を書くと、空文字・0・NaNなどは偽、それ以外は真として扱われる**

- 真として扱われる値を **truthy**、偽として扱われる値を **falsy** と呼ぶ
- 文字0個の文字列 `""` を **空文字** という。空文字・0・NaNがfalsyの代表

<!-- ノート: 結論。falsyは他に、false自身と「値が無い」ことを表すnull・undefinedを足した数個しかありません。全部の暗記はさせず、「falsyは決まった数個、それ以外は全部truthy」と伝えます。 -->

---

## 最小のコード

```js
const userName = "";
if (userName) {
  console.log(`${userName}さん、こんにちは`);
} else {
  console.log("名前が未入力です");
}
// => 名前が未入力です
```

<!-- ノート: 空文字はfalsyなのでelse側に流れます。"佐藤"に変えるとif側に入る、を実演します。 -->

---

## 読めればよい、書くときは明示的に

- `if (userName)` は「userNameが空でなければ」と読む
- 自分で書くときは `if (userName !== "")` と比較で書いてよい
- 意図が伝わる方を選ぶ。チームの流儀にも合わせる

<!-- ノート: 対比枠。初学者はまず明示比較で書き、truthyの省略形は読解対象、という位置づけです。 -->
