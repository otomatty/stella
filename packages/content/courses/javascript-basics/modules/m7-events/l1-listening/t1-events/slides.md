# 7-1-1
# イベントは画面で起きる出来事

JavaScript入門 — Module 7 / レッスン7-1

<!-- ノート: ここから後半戦。「動きを付ける」という講座冒頭の約束を回収しはじめるモジュールです。 -->

---

## なぜ必要か

- 講座の前半は、読み込んだ瞬間に全部実行されて終わりだった
- 「ボタンを押したら」「キーを打ったら」動くのが本来の目標
- 「押したら」を扱うには、出来事に名前が要る

<!-- ノート: つかみ。0-1-1の「動きを付ける言語」をここで思い出させます。 -->

---

## 結論

**クリックやキー入力といった画面の出来事をイベントと呼ぶ**

- **イベント** = ブラウザーが検知する画面の出来事
- 出来事ごとに名前が決まっている

<!-- ノート: 結論。ブラウザーは常に出来事を検知していて、名前付きで教えてくれる、という世界観です。 -->

---

## 代表的なイベント名

| イベント名 | 起きるとき |
| --- | --- |
| **click** | 要素がクリックされた |
| **keydown** | キーが押された |
| input | 入力欄の中身が変わった |

<!-- ノート: この講座で主に使うのはclickとkeydownです。他にも大量にある、と規模感だけ伝えます。 -->

---

## イベント駆動という考え方

- 前半のコード: 上から順に実行して終了
- 後半のコード: 「出来事が起きたら、この処理」の予約を並べる
- 読み込み後は、出来事が起きるまで待っている

<!-- ノート: 図解の代わりの対比。プログラムの形が「手順書」から「予約表」に変わる、という言い方をします。 -->
