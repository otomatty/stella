# レッスン7-2 伝播と委譲

## このレッスンの目標

- [ ] バブリングとevent.targetの関係を説明できる
- [ ] イベント委譲で並んだ要素をまとめて扱える
- [ ] preventDefaultでフォーム送信などの既定の動作を止められる

## 7-2-1 イベントは親へ伝わる

> **clickなどのイベントは、起きた要素からその親、さらに親へと順に伝わっていく**

ボタンを囲むdivにclickリスナーを付けると、ボタンを押しただけでdivのリスナーも動きます。

```html
<div>
  <button>申請</button>
</div>
<script>
  const box = document.querySelector("div");
  box.addEventListener("click", () => console.log("divが聞いた"));
</script>
```

要素を囲んでいる外側の要素を **親要素** といいます。要素で起きたイベントは、発生した要素から親へ、さらにその親へと、泡が水面に昇るように伝わっていきます。これを **バブリング** といいます。

```text
button で発生 → div → body → document
```

途中の要素にリスナーがあれば順に呼ばれます。言い換えると、**親は自分の中で起きたclickを全部聞ける**ということです。この性質があとで効いてきます。

なお、イベントには親へ伝わらない種類も一部あります(フォーカスの移動など)。この講座で扱うclick・keydown・submitはすべて伝わるので、本講座の範囲では「イベントは親へ昇る」と考えて構いません。

## 7-2-2 event.targetで起きた場所が分かる

> **event.targetには、イベントが実際に起きた要素が入っている**

親で聞くと、子のどれで起きたのか分からなくなるのでしょうか。心配いりません。発生源の情報はイベントオブジェクトに入っています。

```js
const box = document.querySelector("div");
box.addEventListener("click", (event) => {
  console.log(event.target);
});
```

**event.target** には、リスナーを付けた要素ではなく、イベントが**実際に起きた要素**(発生源)が入っています。ボタンを押せば `<button>` が、divの余白を押せば `<div>` が表示されます。

| 情報 | 入っているもの |
| --- | --- |
| リスナーを付けた要素 | コードに書いた要素(聞いた場所) |
| `event.target` | 実際にイベントが起きた要素(起きた場所) |

「聞いた場所」と「起きた場所」は別。この区別ができれば、次の委譲は半分理解できたも同然です。

## 7-2-3 親で聞けばまとめて扱える

> **並んだ要素のイベントは、親に1つのリスナーを置いてevent.targetで見分ける**

リストの項目が20個あって全部クリックに反応させたいとき、20回addEventListenerするのは無駄が多いだけでなく、**あとから追加した項目にリスナーが付いていない**という問題も起きます。

そこで、バブリングとevent.targetを組み合わせます。

```js
const list = document.querySelector("ul");
list.addEventListener("click", (event) => {
  console.log(event.target);
});
```

リスナーは親のulに1つだけ。子のliのどれを押しても、バブリングで親に届き、event.targetで「どのliか」が分かります。この設計を **イベント委譲**(親に聞き役を委ねる)といいます。

利点は3つです。

1. リスナーが1つで済む(登録も解除も1回)
2. **あとから追加された子にも効く**(親が聞いているため)
3. どの子かはevent.targetで判定できる

2つ目が最大の利点です。次のモジュールの買い物リストで「あとから追加した項目も消せる」のは、この設計のおかげです。バブリングは厄介な仕様ではなく、委譲のための仕様だったのです。

## 7-2-4 preventDefaultで既定の動作を止める

> **event.preventDefault()は、送信や移動などブラウザーの既定の動作を止める**

リンクをクリックするとページが移動し、フォームのボタンを押すとページが再読み込みされます。これらはリスナーとは無関係に、ブラウザーが昔から自動でやってくれている仕事です。イベントに元々ひも付いたこの動作を **既定の動作** といいます。

**フォーム**(`form` 要素)はまだ本格的に使っていませんが、入力欄とボタンを囲む要素で、ボタンを押すと **submit**(送信)イベントが起きます。submitの既定の動作は「送信してページを読み込み直す」です。JavaScriptで処理したいだけのときは、この再読み込みが邪魔になります。

```js
const form = document.querySelector("form");
form.addEventListener("submit", (event) => {
  event.preventDefault();
  console.log("ページを移動せずに処理できた");
});
```

イベントオブジェクトの **preventDefault** メソッドを呼ぶと、既定の動作だけを止められます(リスナーの残りの処理は続きます)。

| 要素・イベント | 既定の動作 |
| --- | --- |
| フォーム(form)の submit | 送信してページを再読み込み |
| リンク(a)の click | href先へ移動 |

止めるのは必要なときだけにしてください。理由なくリンクの移動を止めると、ページがただ壊れているように見えます。

## もっと知りたい人へ

- バブリングと逆方向(外から内へ)の伝わり方としてキャプチャリングという段階もあります。通常の実務ではバブリングだけ知っていれば困りません
- `event.stopPropagation()` という「伝わり自体を止める」メソッドもあります。preventDefault(既定の動作を止める)との違いに注意してください。乱用すると委譲が壊れるので、まずは使わない方針で十分です
