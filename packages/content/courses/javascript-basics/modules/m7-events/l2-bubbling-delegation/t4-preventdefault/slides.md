# 7-2-4
# preventDefaultで既定の動作を止める

JavaScript入門研修 — Module 7 / レッスン7-2

<!-- ノート: M8の買い物リストで必須になるpreventDefaultを、フォーム送信を軸に導入します。 -->

---

## なぜ必要か

- リンクをクリックすると、リスナーとは無関係にページ移動してしまう
- フォームのボタンを押すと、ページが再読み込みされてしまう
- 自分の処理だけ動かして、ブラウザーのお仕着せは止めたい

<!-- ノート: つかみ。「せっかくの処理が再読み込みで消える」という体験は、この後の演習で実際に踏みます。 -->

---

## 結論

**event.preventDefault()は、送信や移動などブラウザーの既定の動作を止める**

- イベントに元々ひも付いた動作を **既定の動作** という
- イベントオブジェクトの **preventDefault** メソッドで止められる

<!-- ノート: 結論。「既定の動作 = ブラウザーが昔からやってくれていた仕事」。リンク移動・送信・チェック切り替えなどが該当します。 -->

---

## 最小のコード

```js
const form = document.querySelector("form");
form.addEventListener("submit", (event) => {
  event.preventDefault();
  console.log("ページを移動せずに処理できた");
});
```

<!-- ノート: HTMLにformとbuttonがある前提。**submit**はフォームが送信されるイベントで、既定の動作は「送信してページを読み込み直す」です。 -->

---

## 既定の動作の例

| 要素・イベント | 既定の動作 |
| --- | --- |
| **フォーム**(form)の submit | 送信してページを再読み込み |
| リンク(a)の click | href先へ移動 |

- 止めるのは必要なときだけ。リンクを全部殺さない

<!-- ノート: 関連枠。乱用への注意も一言。「移動させたくない特別な理由があるときだけ」です。 -->
