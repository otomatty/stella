# 7-2-3
# 親で聞けばまとめて扱える

JavaScript入門研修 — Module 7 / レッスン7-2

<!-- ノート: バブリング+event.targetの合体技=委譲です。後続のAPG講座でも使う重要パターンです。 -->

---

## なぜ必要か

- リストの項目が20個。全部クリックに反応させたい
- 20回addEventListenerするのは無駄が多い
- あとから増えた項目には、リスナーが付いていない問題もある

<!-- ノート: つかみ。「あとから追加した要素が反応しない」は、この後の買い物リストで実際に踏む問題です。 -->

---

## 結論

**並んだ要素のイベントは、親に1つのリスナーを置いてevent.targetで見分ける**

- この設計を **イベント委譲** という(親に聞き役を委ねる)
- バブリングするからこそ成り立つ

<!-- ノート: 結論。バブリングは厄介な仕様ではなく、これをやるための仕様だった、という回収です。 -->

---

## 最小のコード

```js
const list = document.querySelector("ul");
list.addEventListener("click", (event) => {
  console.log(event.target);
});
```

- liが何個あっても、リスナーは親のulに1つだけ
- 押したliそのものがコンソールに出る

<!-- ノート: HTMLにはulとliが並んでいる前提です。押した項目ごとに違うliが表示されることで「見分けられている」ことを実感させます。 -->

---

## 委譲の利点

- リスナーが1つで済む(登録も解除も1回)
- **あとから追加された子にも効く**(親が聞いているため)
- 「どの子か」はevent.targetで判定する

<!-- ノート: 2点目が最大の利点です。M8の買い物リストで「追加した項目も消せる」のはこの設計のおかげです。 -->
