# レッスン7-2 演習 — 伝播と委譲

対象トピック: 7-2-1 〜 7-2-4

## 手元で試す

テキストエディタとブラウザーだけで進められます。スマートフォンで受講している場合は、この節は飛ばして「演習問題」から進めてください。

1. `delegation.html` を作り、次を書いて保存する

```html
<body>
  <ul>
    <li>見積作成</li>
    <li>レビュー</li>
    <li>報告書</li>
  </ul>
  <script>
    const list = document.querySelector("ul");
    list.addEventListener("click", (event) => {
      console.log(event.target);
    });
  </script>
</body>
```

2. 各項目をクリックして、押したliがコンソールに出ることを確かめる(リスナーはulに1つだけ)

書けたら、次の改造を試してみましょう。

1. ulの外(ページの余白)をクリックしても何も出ないことを確かめる(ulの中だけが聞こえている)
2. `<form><input><button>追加</button></form>` を足し、submitのリスナーで `console.log("追加します")` する。まずpreventDefaultなしで動かし、一瞬でページが再読み込みされてしまうことを確かめる
3. リスナーの先頭に `event.preventDefault();` を足して、再読み込みされずにログが残ることを確かめる

## 演習問題

### 問1(基本)

buttonがdivの中にあり、divだけにclickリスナーが付いています。buttonをクリックしたとき、divのリスナーは動きますか。理由も一言で書いてください。

### 問2(基本)

親で聞いているリスナーの中で、「実際にクリックされた要素」はどう取得しますか。

### 問3(応用)

項目が100個あるリストの各項目をクリックに反応させたいとき、「各liにリスナーを付ける」案と「ulに1つ付けて委譲する」案を比べ、委譲の利点を2つ挙げてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

動きます。イベントはバブリングで発生源から親へ伝わるため、buttonで起きたclickはdivにも届きます。

</details>

<details>
<summary>問2の解答例</summary>

リスナーの引数のイベントオブジェクトから `event.target` を読みます。リスナーを付けた要素ではなく、発生源の要素が入っています。

</details>

<details>
<summary>問3の解答例</summary>

- リスナーが1つで済み、登録の繰り返しが不要になる
- あとから追加された項目にも自動で効く(親が聞いているため)

判定が必要になる(event.targetでどの子か見分ける)のは委譲側の手間ですが、利点が上回る場面が多いです。

</details>

## 確認クイズ

### Q1. バブリングの説明として正しいものはどれですか。

- A. イベントが発生した要素から親へ、順に伝わっていくこと
- B. イベントが2回ずつ発生すること
- C. リスナーが自動で削除されること

<details>
<summary>答え</summary>

**A** — 泡が昇るように、内側から外側へ伝わります。

</details>

### Q2. event.targetに入っているものはどれですか。

- A. リスナーを付けた要素
- B. イベントが実際に起きた要素
- C. ページ全体

<details>
<summary>答え</summary>

**B** — 「聞いた場所」ではなく「起きた場所」が入ります。

</details>

### Q3. イベント委譲の利点として正しいものはどれですか。

- A. あとから追加された子要素にも効く
- B. イベントの発生が速くなる
- C. HTMLを書かなくてよくなる

<details>
<summary>答え</summary>

**A** — 親が聞いているので、子がいつ増えても拾えます。リスナーも1つで済みます。

</details>

### Q4. フォームのsubmitイベントの既定の動作はどれですか。

- A. 入力欄を空にする
- B. 送信してページを再読み込みする
- C. 何も起きない

<details>
<summary>答え</summary>

**B** — JavaScript側だけで処理したいときは、event.preventDefault()でこれを止めます。

</details>

### Q5. event.preventDefault()が止めるものはどれですか。

- A. ブラウザーの既定の動作
- B. リスナーの残りの処理
- C. バブリングによる伝わり

<details>
<summary>答え</summary>

**A** — 既定の動作だけを止め、リスナーの処理は続きます。伝わりを止める別のメソッドとは役割が違います。

</details>
