# レッスン4-2 ダイアログを開く

## このレッスンの目標

- [ ] `dialog` が既定で閉じていることを説明できる
- [ ] `command` と `commandfor` で開き、名前と閉じるボタンを付けられる
- [ ] モーダルで開いたときに何が付いてくるかを言える

## 4-2-1 dialogは既定で閉じている

> **dialogは既定で閉じていて、開くまでページに表示されない**

削除の確認をページ遷移せずにその場で取りたい、という場面があります。作業をいったん受け止める面が **ダイアログ** です。

```html
<dialog id="confirm">
  <p>この講座の受講を取り消しますか?</p>
</dialog>
```

このまま表示しても、**画面には何も出ません**。`dialog` は閉じているのが既定の状態で、開くまで表示されないからです。「書いたのに出ない」で止まる人が多いので、最初に覚えてください。

`div` で自作した確認画面と比べると、状態の持ち主が違います。

- `div` … 自分で `display: none` にして隠し、自分で出す。閉じ忘れの状態が生まれる
- `dialog` … 閉じているのが既定。開く・閉じるはブラウザーが管理する

状態の初期値がブラウザー側にあるので、うっかり開いたままの HTML を配ってしまう、といった事故が起きません。

## 4-2-2 commandでモーダルに開く

> **command="show-modal"のボタンは、commandforで指すdialogをモーダルで開く**

ダイアログを開くには、これまで JavaScript が必要でした。いまは属性で書けます。

```html
<button command="show-modal" commandfor="confirm">
  受講を取り消す
</button>

<dialog id="confirm">
  <p>この講座の受講を取り消しますか?</p>
</dialog>
```

- **command** … 何をするか
- **commandfor** … 相手の `id`

`command="show-modal"` は **モーダル** で開く指示です。モーダルとは、背面を触れなくして前面に出す開き方を指します。何が起きるかは 4-2-4 で詳しく見ます。

`command` にはほかの値もあります。

| 値 | 何が起きるか |
| --- | --- |
| `show-modal` | ダイアログをモーダルで開く |
| `close` | ダイアログを閉じる |
| `toggle-popover` | ポップオーバーを開閉する |

前のレッスンの `popovertarget` がポップオーバー専用だったのに対して、`command` は **相手と操作を書き分けられる汎用の形** です。

> **この機能も比較的新しく、古いブラウザーでは動きません。** ポップオーバーと同じく、動かない環境では書いた結果の確認までに留め、フォールバックの JavaScript は書きません。

## 4-2-3 中のボタンでcloseする

> **ダイアログの中にcommand="close"のボタンを置くと、そのボタンで閉じられる**

開けたら、閉じ方も必ず用意します。閉じられないダイアログは、利用者をそこから進めなくしてしまいます。

```html
<dialog id="confirm">
  <p>この講座の受講を取り消しますか?</p>

  <form method="post" action="/enrollments/1/cancel">
    <button type="button" command="close" commandfor="confirm">やめる</button>
    <button type="submit">取り消す</button>
  </form>
</dialog>
```

開くときと同じ 2 つの属性で、値が `close` になるだけです。ダイアログの中に置くボタンでも、`commandfor` で相手を明示します。

ここで、レッスン3-1 で学んだ 2 つが効いてきます。

- **`button` は `form` の中に無いと送信できません。** 「取り消す」は実際に取り消しを送る操作なので、`form` で囲みます。囲まないと、押しても何も起きないボタンになります
- **送信しないボタンには `type="button"` を書きます。** `form` の中の `button` は、`type` を省くと送信ボタンとして扱われるためです

2 つ目には補足があります。`command` と `commandfor` を持つボタンは、`type` を省いても送信ボタンにはなりません(コマンドのボタンとして扱われます)。それでも `type="button"` を書くのは、**この仕組みに対応していないブラウザーでは、ただの送信ボタンとして扱われてしまう**からです。書いておけば、どちらの環境でも「閉じるだけ」で済みます。

閉じるだけのダイアログ(お知らせなど)なら `form` は要りません。**送る操作があるときだけ** `form` で囲みます。

### ダイアログに名前を付ける

もう 1 つ、骨格の段階でやっておくことがあります。**ダイアログの名前**です。

`dialog` は「ダイアログ」という役割を持ちますが、中に見出しを置いただけでは、その見出しがダイアログの名前にはなりません。読み上げでは「ダイアログ」としか言われず、何のダイアログなのか分かりません。

見出しに `id` を付け、`aria-labelledby` で指します。

```html
<dialog id="confirm" aria-labelledby="confirm-title">
  <h2 id="confirm-title">受講の取り消し</h2>
  <p>この講座の受講を取り消しますか?</p>
</dialog>
```

これで「受講の取り消し、ダイアログ」と読み上げられます。見出しを置かない小さなダイアログなら、`aria-label="受講の取り消し"` と直接書いても構いません。

パンくずの `aria-label` と同じ考え方です。**同じ役割の要素が複数あるとき、名前が無いと呼び分けられません。**

### 閉じる手段は 2 つ以上

閉じる手段は **2 つ以上** 用意してください。

- 画面に見える「閉じる」ボタン … 誰にでも見つかる
- Esc キー … モーダルなら既定で効く

Esc だけに頼ると、そのキーを知らない利用者が詰まります。逆に見えるボタンだけだと、キーボードで素早く抜けたい人に不便です。押し間違いが怖い操作ほど、逃げ道は広くしておきます。

## 4-2-4 モーダルは背面を止める

> **モーダルで開いたダイアログは、背面を操作できずEscキーで閉じられる**

`show-modal` で開くと、次の 4 つが付いてきます。

1. **背面の要素が操作できなくなる** … クリックもフォーカスも通らない
2. **フォーカスがダイアログの中に留まる** … Tab で背面のリンクへ抜けていかない
3. **Esc キーで閉じる**
4. **背面に暗い面を敷ける** … 見た目は次のレッスンで扱う

自前の確認画面でいちばん漏れるのが 1 と 2 です。見た目は確認画面でも、Tab を押すとフォーカスが後ろのページへ抜けていく、というのはよくある不具合です。モーダルで開けば、これが既定で正しく動きます。

一方で、**何でもモーダルにしない**ことも大切です。モーダルは利用者の作業を止めます。

- 決めてもらわないと先に進めない … モーダルのダイアログ
- 背面を見ながら参照させたい … 重ねて出すポップオーバー

補足の情報を横に出したいだけなら、前のレッスンのポップオーバーのほうが合います。
