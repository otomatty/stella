## なぜ必要か

- それらしく動いていると、中身を見ずに受け取りたくなります
- 自分が書いていないコードほど、知らないまま手元に増えていきます

<!-- ノート: つかみ。速く進むほど、読まないまま積み上がるという実感を共有します。結論はまだ言いません。 -->

---

## 結論

**書かせたコードは、変更点である差分を自分で読んで見極めてから受け取ります**

- **差分** — 変わったところ。足した行と消した行のこと
- **見極める** — 出てきたものを鵜呑みにせず自分で判断すること(講座1で扱った語です)
- **4D** の見極めるを、コードの上でやるのがこの段です

<!-- ノート: 結論です。読むのは相手を疑うためではなく、受け取る側の責任だからだと言い切ります。 -->

---

## 変わった行だけを見る

```text
変更前  更新日をそのまま画面に出す
変更後  更新日を年月日の書式にそろえてから画面に出す

見る点  変わったのがここだけか
        頼んでいない変更が混ざっていないか
```

<!-- ノート: 最小の例です。行の読み方そのものは Git の講座の範囲なので、ここでは前後の対比だけを見せます。 -->

## 読まずに受け取ると

| | 読まずに受け取る | 読んでから受け取る |
| --- | --- | --- |
| 変わった範囲 | 分からない | 自分で言える |
| 余計な変更 | 混ざったまま残る | その場で外せる |
| あとの説明 | できない | 自分の言葉でできる |

<!-- ノート: 対比枠です。受け取った時点でそのコードは自分のものになる、という点を言い添えます。 -->
