# 区切りはブランチの上でコミットする

Claude Code入門 — Module 3 / レッスン3-3

<!-- ノート: 4つの段の最後です。1周を閉じる回になります。 -->

---

## なぜ必要か

- 直したものが、どこで一区切りなのか分からないまま積み上がります
- 戻したくなったときに、戻れる場所がありません

<!-- ノート: つかみ。手が速いぶん、区切りを付けないと収拾がつかなくなる場面を共有します。結論はまだ言いません。 -->

---

## 結論

**動作確認まで済んだ変更は、作業用のブランチの上でコミットとして区切って残します**

- **ブランチ** — 本流から枝分かれさせた作業用の場所(Git入門で扱った語です)
- **コミット** — 変更をひと区切りとしてリポジトリに記録すること(同上)
- これが **Commit の段** です

<!-- ノート: 結論です。Git の2語は復習なので1行ずつで済ませ、段としての置き場所の話に時間を使います。 -->

---

## 1周の閉じ方

```text
1. 作業用のブランチに移ってから直し始める
2. 一段ぶんの差分を読む
3. 動作確認まで通す
4. そこまでをコミットとして区切る → 次の一段へ
```

<!-- ノート: 最小の例です。2から4が一段ごとに繰り返され、そのたびに戻れる場所が増えていきます。 -->

---

## 区切らずに進めると

| | 区切らずに進める | 段ごとに区切る |
| --- | --- | --- |
| 戻れる場所 | 直前しかない | 区切りごとにある |
| 変更のまとまり | 全部で1つ | 意味ごとに分かれる |
| あとで見返すとき | 何をしたか追えない | 区切りごとに追える |

<!-- ノート: 対比枠です。区切りは記録のためだけでなく、戻れる場所を作るためでもあると言い添えます。 -->
