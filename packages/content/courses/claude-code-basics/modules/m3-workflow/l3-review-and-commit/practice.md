# レッスン3-3 演習 — 差分を読んで区切る(Commit)

対象トピック: 3-3-1 〜 3-3-3

## 手元で試す

このレッスンで練習するのは、受け取る前に読んで動かして区切ることです。メモ帳だけでも進められます。

1. レッスン3-2で一段に割った修正を、そのまま使います
2. その一段で変わるはずの箇所を、「変更前」「変更後」の2行で書き出します
3. 受け取る前に見る点を2つ書きます(3-3-1 で挙げた2点で構いません)
4. その修正の動作確認をどうやるかを書きます。テストがあるなら走らせるコマンド、無いなら自分で開く画面を1つ書きます
5. どこまで済んだらコミットとして区切るかを、1文で書きます

余力があれば、VS Code で Claude Code に一段ぶんを書かせ、差分を自分で読み、動作確認まで通してから、作業用のブランチの上でコミットしてみてください。**Claude Code が使えない環境の人は、この段落を飛ばして構いません。** 1〜5 を紙の上で書くだけで演習は成立します。

## 演習問題

### 問1(基本)

書かせたコードを受け取る前に、差分を自分で読む理由を1〜2文で書いてください。

### 問2(基本)

差分を読む、テストを走らせる、自分で動かす。この3つで見つかるずれをそれぞれ1つずつ挙げてください。

### 問3(応用)

差分を読むと、頼んだ1か所のほかに、関係のないファイルの変更が1つ混ざっていました。取る行動を2〜3文で書いてください。

### 問4(応用)

差分を読み終え、筋も通っていました。テストを走らせると1つ落ちています。ここでコミットしてよいですか。理由を添えて答えてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

読まずに受け取ると、自分が書いていないコードが中身を知らないまま増えていくからです。受け取った時点でそのコードは自分のものになるので、見極めてから受け取ります。

</details>

<details>
<summary>問2の解答例</summary>

差分を読むと、頼んでいない変更や筋の通らない直しが見つかります。テストを走らせると、動かすと落ちる失敗や別の場所の壊れが見つかります。自分で動かすと、画面や出力の見た目のずれが見つかります。

</details>

<details>
<summary>問3の解答例</summary>

その変更を外してもらってから受け取ります。今回の一段に必要ないことを伝え、頼んだ1か所だけの差分にしてもらいます。外したあとにもう一度差分を読み直し、変わったのがそこだけになっているかを確かめます。

</details>

<details>
<summary>問4の解答例</summary>

コミットしません。読んで筋が通っていることと、動くことは別だからです。落ちているテストの出力を見せてもらって原因を直し、動作確認が通ってから区切ります。

</details>

## 確認クイズ

### Q1. Codeの段で書かせたコードを受け取る前にすることはどれですか。

- A. 変更点である差分を自分で読んで見極める
- B. 動いていそうなら、そのまま受け取る
- C. 変わった行数だけを数える

<details>
<summary>答え</summary>

**A** — 読むのは相手を疑うためではなく、受け取る側として責任を持つためです。エージェントに書かせたものほど自分で読みます。

</details>

### Q2. 差分を読むと、頼んでいないファイルの変更が混ざっていました。適切な行動はどれですか。

- A. 動くなら残しておく
- B. その変更を外してもらってから受け取る
- C. 差分ごと全部捨てて、依頼から作り直す

<details>
<summary>答え</summary>

**B** — 見る点は「頼んだことができているか」「頼んでいないことが混ざっていないか」の2つです。混ざっていたらその場で外します。

</details>

### Q3. 差分を読んで筋が通っていました。次にすることはどれですか。

- A. テストを走らせるなどして、実際に動くところまで動作確認する
- B. そのままコミットして区切る
- C. 何もせず次の一段を頼む

<details>
<summary>答え</summary>

**A** — 読んで納得したコードが動くとは限りません。読むと動かすでは、見つかるずれが違います。

</details>

### Q4. テストが1つ落ちています。この状態でコミットして区切ってよいですか。

- A. よい。あとでまとめて直せばよい
- B. よくない。原因を直して動作確認が通ってから区切る
- C. よい。テストは参考なので気にしなくてよい

<details>
<summary>答え</summary>

**B** — 区切りは「ここまでは通っている」という印です。落ちたまま区切ると、戻れる場所として使えません。

</details>

### Q5. 動作確認まで済んだ変更の残し方として適切なものはどれですか。

- A. 変更したまま置いておき、記録は残さない
- B. すべての段が終わるまで、一度も区切らない
- C. 作業用のブランチの上で、コミットとして区切る

<details>
<summary>答え</summary>

**C** — 一段ごとに区切ると、戻れる場所がそのぶん増えます。まとめて1つにすると、あとで何をしたか追えません。

</details>
