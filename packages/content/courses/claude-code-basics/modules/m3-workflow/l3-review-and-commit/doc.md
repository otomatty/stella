# レッスン3-3 差分を読んで区切る(Commit)

## このレッスンの目標

- [ ] 書かせたコードの差分を自分で読んで見極められる
- [ ] 読んだあとに動作確認まで通せる
- [ ] ブランチの上でコミットとして区切って残せる

## 3-3-1 差分は自分で読む

> **書かせたコードは、変更点である差分を自分で読んで見極めてから受け取ります**

Code の段で一段ぶんが書けたら、受け取る前にやることがあります。変わったところ、つまり **差分** を自分で読むことです。差分とは、足した行と消した行のことです。

それらしく動いていると、中身を見ずに受け取りたくなります。しかし読まずに受け取ると、自分が書いていないコードが、知らないまま手元に増えていきます。ここで効かせるのが、講座1で扱った **見極める** です。出てきたものを鵜呑みにせず、自分で判断することを指します。4D の見極めるを、コードの上でやるのがこの段です。

差分の読み方そのもの(行の記号の意味など)は Git の講座の範囲なので、ここでは深入りしません。この講座で身に付けたいのは、**エージェントに書かせたものほど自分で読む**という構えだけです。

```text
変更前  更新日をそのまま画面に出す
変更後  更新日を年月日の書式にそろえてから画面に出す

見る点  変わったのがここだけか
        頼んでいない変更が混ざっていないか
```

見る点は Plan の段と同じ2つです。頼んだことができているか、頼んでいないことが混ざっていないか。混ざっていたら、その場で外してもらいます。

| | 読まずに受け取る | 読んでから受け取る |
| --- | --- | --- |
| 変わった範囲 | 分からない | 自分で言える |
| 余計な変更 | 混ざったまま残る | その場で外せる |
| あとの説明 | できない | 自分の言葉でできる |

受け取った時点で、そのコードは自分のものになります。読むのは相手を疑うためではなく、受け取る側として責任を持つためです。

## 3-3-2 読んだら動かして確かめる

> **差分を読んだあとは、テストを走らせて実際に動くところまで動作確認します**

差分を読んで筋が通っていた。それで十分かというと、足りません。読んで納得したコードが、動かすとあっさり落ちることがあります。直したところは良くても、別のところが動かなくなることもあります。

そこで、読んだあとに動かします。期待どおり動くかを自動で調べる仕組みが **テスト**、実際に動かして目で結果を確かめることが **動作確認** です。

```text
1. テストを走らせるコマンドを実行してもらう
2. 通らなければ、出力ごと見せてもらって直す
3. テストが無いところは、自分で画面を開いて確かめる
```

3行目が要点です。テストが用意されていない場所では、自分の目が動作確認になります。画面を開く、出力を1つ見る。それだけでも、読むだけよりずっと確かです。

| 確かめ方 | 見つかるずれ |
| --- | --- |
| 差分を読む | 頼んでいない変更・筋の通らない直し |
| テストを走らせる | 動かすと落ちる失敗・別の場所の壊れ |
| 自分で動かす | 画面や出力の見た目のずれ |

3つとも見つかるものが違います。だから片方では足りず、上から順に通します。テストが1つでも落ちている状態は、まだ区切ってよい状態ではありません。原因を直してから先に進みます。

## 3-3-3 区切りはブランチの上でコミットする

> **動作確認まで済んだ変更は、作業用のブランチの上でコミットとして区切って残します**

読んで、動かして、通った。ここまで来たら、変更を残して区切ります。これが **Commit の段** です。

Git の2語を1行ずつ思い出しておきます。

- **ブランチ** — 本流から枝分かれさせた作業用の場所です(Git入門で扱った語です)
- **コミット** — 変更をひと区切りとしてリポジトリに記録することです(同上)

作業用のブランチに移ってから直し始める、というのが出発点です。そのうえで、一段ごとに区切っていきます。

```text
1. 作業用のブランチに移ってから直し始める
2. 一段ぶんの差分を読む
3. 動作確認まで通す
4. そこまでをコミットとして区切る → 次の一段へ
```

2から4が一段ごとに繰り返され、そのたびに戻れる場所が1つ増えていきます。エージェントは手が速いので、区切りを付けずに進めるとあっという間に収拾がつかなくなります。

| | 区切らずに進める | 段ごとに区切る |
| --- | --- | --- |
| 戻れる場所 | 直前しかない | 区切りごとにある |
| 変更のまとまり | 全部で1つ | 意味ごとに分かれる |
| あとで見返すとき | 何をしたか追えない | 区切りごとに追える |

これで4つの段が1周しました。調べさせる → 計画を読む → 一段ずつ書かせる → 差分を読んで区切る。この1周が、Claude Code で修正を1本進めるときの型です。

## もっと知りたい人へ

- 差分の読み方そのもの(行の記号の意味、まとまりの単位)は、Git 入門の範囲です。読むのに慣れていない人は、そちらを先に一度通しておくと楽になります
- テストの書き方・そろえ方は、テスト設計と品質保証 入門や Python テスト自動化と CI 入門で扱っています
- ブランチ名やコミットの区切り方には、チームごとの決まりがあることが多いです。自分のチームの決まりを一度確認しておいてください
