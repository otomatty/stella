# レッスン3-1 まず調べさせる(Explore)

## このレッスンの目標

- [ ] 1つの修正を4つの段に分けて説明できる
- [ ] 直させる前に現状を読ませる依頼が書ける
- [ ] 探す範囲を指し示して狭められる

## 3-1-1 1タスクは4つの段で進める

> **1つの修正は、Explore → Plan → Code → Commitという4つの段のワークフローで進めます**

ここからがこの講座の中心です。Claude Code に手元のコードを直させるとき、毎回同じ順でたどる段取りがあります。それが **ワークフロー** です。

段は4つで、順番は入れ替えません。

```text
Explore   調べさせる
Plan      計画を読む
Code      一段ずつ書かせる
Commit    変わったところを読んで区切る
```

特別なタスクのための大がかりな手順ではありません。ふだんの小さな修正1本が、そのままこの4行に割れます。

```text
依頼      商品一覧の更新日の表示が崩れているので直したい

Explore   更新日をどこで組み立てているか読ませて説明させる
Plan      直し方の計画を出させて、自分で読んで直す
Code      計画の一段ぶんだけ書かせる
Commit    変わったところを読んで、区切りとして残す
```

なぜわざわざ4つに割るのか。一言で「直して」と頼むと、依頼から結果までのあいだに自分の出番がありません。段に割る目的は、手間を増やすことではなく、途中に自分が見る場所を作ることです。

| | 一言で「直して」 | 4つの段で進める |
| --- | --- | --- |
| 触る場所 | 任せきり | 進む前に分かる |
| 進み方 | 一気に最後まで | 段ごとに止まれる |
| 直しの費用 | できてからやり直す | 段の切れ目で直せる |

このレッスンでは、1つめの Explore の段を扱います。

## 3-1-2 直させる前に読ませる

> **修正を頼む前に、対象のコードを読ませて現状を説明させます**

**Explore の段** でやることは1つだけです。直させる前に、対象のコードを読ませて **現状** を説明させます。現状とは、いま手元のコードがどうなっているかという事実のことです。

いきなり「直して」と頼むと、どこを触るかは相手の推測で決まります。直ったように見えて別の場所を触っていた、ということが起きます。手元のコードは、書いた本人でも数か月経てば覚えていません。自分の記憶も推測のうちです。

Explore の依頼は、次の3行で足ります。

```text
まだ直さないでください。

商品一覧の更新日は、どのファイルで組み立てていますか。
関係する箇所を読んで、いまの作りを3行で説明してください。
```

1行目で書くことを止め、2行目で探す対象を伝え、3行目で返してほしい形を指定しています。「3行で」と長さを添えておくと、読み切れる量で返ってきます。

先に読ませると、変わるのはコードだけではありません。

| | いきなり「直して」 | 先に読ませる |
| --- | --- | --- |
| 触る場所 | 相手の推測で決まる | 自分が確かめてから決まる |
| 前提のずれ | 書かれたあとに分かる | 説明の時点で分かる |
| 自分の理解 | 増えない | 現状を言えるようになる |

説明が返ってきた時点で、自分の理解も更新されています。地味ですが、あとの段すべてがこの理解の上に乗ります。

## 3-1-3 探す範囲は指し示して狭める

> **関係するファイルやフォルダを指し示すと、Exploreは速く正確になります**

Explore を頼むときのもう一手が、探す範囲を狭めることです。作業の範囲はリポジトリ全体なので、当てもなく探させると広すぎます。似た名前のファイルが並んでいれば、別物を読んで話が噛み合わないこともあります。

そこで、見てほしいファイルやフォルダを名前や場所で示します。これが **指し示す** です。

```text
広い  更新日の表示を直したい

狭い  src/pages/product-list/ のあたりを見てください。
      商品一覧ページの「更新日」の欄です。
      無ければ、書式をそろえる共通の処理も探してください。
```

場所・画面上の名前・外れたときの逃げ道、の3行構成になっています。

大事なのは、**正確に当てる必要はない**という点です。当たりを付けて渡すだけで十分で、外れていれば「そこには無かった」と返ってきます。それ自体が収穫です。「たぶんこのあたり」で構わないので、手がかりを1つ足してください。

| | 指し示さない | 指し示す |
| --- | --- | --- |
| 読む量 | 手当たりしだい | 挙げたあたりから |
| 当たり | 運任せ | 高い |
| 外したとき | 気づきにくい | 「そこには無い」と返る |

逆に、Explore の説明が「たぶんこのあたりだと思います」と推測のまま返ってきたときは、まだ次の段に進む頃合いではありません。指し示す手がかりを足して、もう一度読ませて確かめてください。

## もっと知りたい人へ

- 人に調査を頼むときも、「まだ手を付けないで、現状だけ調べて報告して」と切り分けます。この段の頼み方は、それと同じ形です
- 探す範囲の指し示し方は、リポジトリの構成をどれだけ知っているかで変わります。ふだんから自分の担当まわりのフォルダ構成を眺めておくと、この一手が速くなります
- 画面の並びや操作のしかたは変わっていきます。実際に使うときは、製品のドキュメントで確認してください
