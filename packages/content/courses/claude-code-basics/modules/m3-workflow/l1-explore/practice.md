# レッスン3-1 演習 — まず調べさせる(Explore)

対象トピック: 3-1-1 〜 3-1-3

## 手元で試す

このレッスンで練習するのは、直させる前に読ませることです。メモ帳だけでも進められます。

1. 自分の担当しているリポジトリから、直したい小さな箇所を1つ選びます(表示のずれ、項目が1つ足りない、など)
2. その修正を、Explore / Plan / Code / Commit の4行に割って書き出します
3. Explore の依頼文を3行で書きます。1行目は「まだ直さないでください」、2行目は探す対象、3行目は返してほしい形です
4. その依頼文に、指し示す手がかりを1つ足します(フォルダの場所、画面上の名前、再現の手順のどれか)
5. 返ってきた説明が推測のままだったら何と書き足すかを、1行考えておきます

余力があれば、VS Code で Claude Code を開き、3と4で書いた依頼を実際に出して、返ってきた現状の説明を読んでみてください。**Claude Code が使えない環境の人は、この段落を飛ばして構いません。** 1〜5 を紙の上で書くだけで演習は成立します。

## 演習問題

### 問1(基本)

1つの修正を進める4つの段を、順番どおりに並べ、それぞれ一言で説明してください。

### 問2(基本)

「商品一覧の更新日の表示が崩れている」を直したいとき、Explore の段で出す依頼文を3行で書いてください。

### 問3(応用)

問2の依頼文に、指し示す手がかりを1つ足してください。当てずっぽうで構いません。なぜ当てずっぽうでよいのかも1文で書いてください。

### 問4(応用)

Explore の説明が「おそらくこのファイルだと思いますが、確認していません」と返ってきました。このあと取る行動を、2〜3文で書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

Explore(調べさせる)、Plan(計画を読む)、Code(一段ずつ書かせる)、Commit(変わったところを読んで区切る)の順です。順番は入れ替えません。

</details>

<details>
<summary>問2の解答例</summary>

まだ直さないでください。商品一覧の更新日は、どのファイルで組み立てていますか。関係する箇所を読んで、いまの作りを3行で説明してください。

1行目で書くことを止め、2行目で探す対象を伝え、3行目で返してほしい形と長さを指定しています。

</details>

<details>
<summary>問3の解答例</summary>

「src/pages/product-list/ のあたりだと思います。商品一覧ページの『更新日』の欄です」と足します。当てずっぽうでよいのは、外れていれば「そこには無かった」と返ってきて、それ自体が範囲を狭める収穫になるからです。

</details>

<details>
<summary>問4の解答例</summary>

まだ次の段には進みません。心当たりのあるフォルダや画面上の名前を指し示して、もう一度読ませます。確認したうえで現状を説明し直してもらい、推測ではない説明が返ってきてから先に進みます。

</details>

## 確認クイズ

### Q1. 1つの修正を進める4つの段の順として正しいものはどれですか。

- A. Explore → Plan → Code → Commit
- B. Plan → Explore → Commit → Code
- C. Code → Explore → Plan → Commit

<details>
<summary>答え</summary>

**A** — 調べさせる、計画を読む、一段ずつ書かせる、変わったところを読んで区切る、の順です。入れ替えません。

</details>

### Q2. 「商品一覧の更新日を直したい」と思ったとき、Exploreの段で最初に出す依頼として適切なものはどれですか。

- A. 更新日の表示を直してください
- B. まだ直さずに、更新日を組み立てている箇所を読んで、いまの作りを説明してください
- C. リポジトリの全ファイルを1つずつ読み上げてください

<details>
<summary>答え</summary>

**B** — Exploreは調べる段です。書くことを先に止め、現状を説明させます。Cは範囲が広すぎて手がかりになりません。

</details>

### Q3. 探す範囲の指し示し方として、いちばん役に立つものはどれですか。

- A. どこかにあるはずなので探してください
- B. なるべく速く探してください
- C. src/pages/product-list/ のあたりです。商品一覧ページの「更新日」の欄です

<details>
<summary>答え</summary>

**C** — 場所と画面上の名前という手がかりがあります。正確に当たっていなくてもよく、外れれば「そこには無い」と返ります。

</details>

### Q4. Exploreの説明が「たぶんこのあたりだと思います」と推測のままでした。次の行動として適切なものはどれですか。

- A. そのままCodeの段に進ませる
- B. 心当たりのフォルダを指し示して、もう一度読ませて確かめる
- C. 依頼を取り下げて、自分で全部書く

<details>
<summary>答え</summary>

**B** — 推測のままの現状の上に計画を立てると、あとの段がまとめてずれます。手がかりを足して確かめ直します。

</details>

### Q5. Exploreの段を挟む目的として正しいものはどれですか。

- A. 依頼の文章を短くするため
- B. Claude Codeに読む練習をさせるため
- C. 触る場所を、自分が確かめてから決められるようにするため

<details>
<summary>答え</summary>

**C** — 読ませずに頼むと、触る場所は相手の推測で決まります。先に読ませると、自分の理解も同時に更新されます。

</details>
