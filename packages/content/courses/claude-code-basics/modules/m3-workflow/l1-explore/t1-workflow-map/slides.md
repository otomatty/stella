# 3-1-1
# 1タスクは4つの段で進める

Claude Code入門 — Module 3 / レッスン3-1

<!-- ノート: ここからが講座の中心です。1つの修正を、毎回同じ順で通す型を覚えます。 -->

---

## なぜ必要か

- 「直して」と一言で頼むと、どこを触られたか分からないまま終わります
- 毎回の進め方がその場任せだと、うまくいった回を次に再現できません

<!-- ノート: つかみ。日々のあるあるを2つ並べます。ここでは結論を言いません。 -->

---

## 結論

**1つの修正は、Explore → Plan → Code → Commitという4つの段のワークフローで進めます**

- **ワークフロー** — 毎回同じ順でたどる決まった段取り
- **Explore の段** — 調べさせる
- **Plan の段** — 計画を読む
- **Code の段** — 一段ずつ書かせる
- **Commit の段** — 変わったところを読んで区切る

<!-- ノート: 結論です。4つの段の名前と、それぞれの一言を読み上げます。順番は入れ替えません。 -->

---

## 小さな修正を1本、段に割る

```text
依頼      商品一覧の更新日の表示が崩れているので直したい

Explore   更新日をどこで組み立てているか読ませて説明させる
Plan      直し方の計画を出させて、自分で読んで直す
Code      計画の一段ぶんだけ書かせる
Commit    変わったところを読んで、区切りとして残す
```

<!-- ノート: 最小の例です。特別なタスクではなく、ふだんの小さな修正1本がこの4行になる、という見せ方をします。 -->

---

## 一言で頼むときとの違い

| | 一言で「直して」 | 4つの段で進める |
| --- | --- | --- |
| 触る場所 | 任せきり | 進む前に分かる |
| 進み方 | 一気に最後まで | 段ごとに止まれる |
| 直しの費用 | できてからやり直す | 段の切れ目で直せる |

<!-- ノート: 対比枠です。段に割る目的は手間を増やすことではなく、途中に自分の出番を作ることだと言い添えます。 -->
