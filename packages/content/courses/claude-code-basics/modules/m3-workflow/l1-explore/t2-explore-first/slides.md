# 3-1-2
# 直させる前に読ませる

Claude Code入門 — Module 3 / レッスン3-1

<!-- ノート: 4つの段のうち、1つめの中身です。 -->

---

## なぜ必要か

- 直ったように見えて、まったく別の場所を触っていたことがあります
- 手元のコードは、書いた本人でも数か月経てば覚えていません

<!-- ノート: つかみ。思い込みで頼んで外した経験を思い出してもらいます。結論はまだ言いません。 -->

---

## 結論

**修正を頼む前に、対象のコードを読ませて現状を説明させます**

- **現状** — いま手元のコードがどうなっているかという事実
- この「先に読ませる」一手が **Explore の段** です

<!-- ノート: 結論です。Explore は情報を集める段であって、直す段ではないと言い切ります。 -->

---

## Exploreの依頼を書く

```text
まだ直さないでください。

商品一覧の更新日は、どのファイルで組み立てていますか。
関係する箇所を読んで、いまの作りを3行で説明してください。
```

<!-- ノート: 最小の例です。1行目で書くことを止め、2行目で探す対象、3行目で返してほしい形を指定しています。 -->

---

## 読ませてから頼むと何が変わるか

| | いきなり「直して」 | 先に読ませる |
| --- | --- | --- |
| 触る場所 | 相手の推測で決まる | 自分が確かめてから決まる |
| 前提のずれ | 書かれたあとに分かる | 説明の時点で分かる |
| 自分の理解 | 増えない | 現状を言えるようになる |

<!-- ノート: 対比枠です。説明が返ってきた時点で自分の理解も更新されている点が、地味ですが大きい効果です。 -->
