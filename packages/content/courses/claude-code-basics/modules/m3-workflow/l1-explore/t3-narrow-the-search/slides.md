# 3-1-3
# 探す範囲は指し示して狭める

Claude Code入門 — Module 3 / レッスン3-1

<!-- ノート: Exploreを上手に頼むための、もう一手です。 -->

---

## なぜ必要か

- 作業の範囲はリポジトリ全体なので、当てもなく探させると広すぎます
- 似た名前のファイルが並んでいると、別物を読んで話が噛み合いません

<!-- ノート: つかみ。手がかりゼロで探させたときの遠回りを思い出してもらいます。結論はまだ言いません。 -->

---

## 結論

**関係するファイルやフォルダを指し示すと、Exploreは速く正確になります**

- **指し示す** — 見てほしいファイルやフォルダを、名前や場所で示すこと
- 正確に当てる必要はありません。当たりを付けて渡すだけで十分です

<!-- ノート: 結論です。狭めるのは相手を縛るためではなく、探す量を減らすためだと言い切ります。 -->

---

## 手がかりを1つ足すだけ

```text
広い  更新日の表示を直したい

狭い  src/pages/product-list/ のあたりを見てください。
      商品一覧ページの「更新日」の欄です。
      無ければ、書式をそろえる共通の処理も探してください。
```

<!-- ノート: 最小の例です。場所・画面上の名前・外れたときの逃げ道、の3行構成になっています。 -->

---

## 指し示さないときとの違い

| | 指し示さない | 指し示す |
| --- | --- | --- |
| 読む量 | 手当たりしだい | 挙げたあたりから |
| 当たり | 運任せ | 高い |
| 外したとき | 気づきにくい | 「そこには無い」と返る |

<!-- ノート: 対比枠です。外れたときに「そこには無かった」と分かること自体が収穫だと言い添えます。 -->
