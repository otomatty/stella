# レッスン3-2 計画してから書かせる(Plan → Code)

## このレッスンの目標

- [ ] Planで出た計画の過不足を自分で直せる
- [ ] Code の段を一段ずつ進める頼み方ができる
- [ ] ずれに気づいたときに中断して戻せる

## 3-2-1 計画は着手の前に読む

> **Planで出てきた計画は、Codeに進む前に自分で読んで過不足を直します**

Explore で現状が分かったら、次は直し方を決める **Plan の段** です。ここで最初に区別しておきたい言葉が2つあります。

- **Planモード** — ファイルを変更させずに計画だけ出させるための選び方。道具です
- **Plan の段** — ワークフローの2番目。出てきた計画を自分で読む場面です

Planモードを選ぶだけでは、この段は終わりません。出てきた **計画** を自分で読むところまでが Plan の段です。

読むときに見るのは2点だけです。頼んだことが入っているか(不足)、頼んでいないことが混ざっていないか(余計)。この2つをまとめて **過不足** と呼びます。

```text
計画  1. 更新日を組み立てている処理の書式を直す
      2. 商品一覧ページの呼び出し側を合わせる
      3. ついでに周辺の関数名を分かりやすく変える

読む  1と2は依頼どおり → そのまま
      3は頼んでいない  → 「3は今回やめてください」
```

計画が長いほど、読み飛ばして「それで進めて」と言いたくなります。しかし、ここで一行消しておくのと、書かれたあとにコードを消すのとでは、手間がまるで違います。

| | 読まずにCodeへ | 読んでからCodeへ |
| --- | --- | --- |
| 直す対象 | 書かれたコード | 計画の1行 |
| 余計な変更 | できてから気づく | 進む前に外せる |
| 進む向き | 決まらないまま | 決まってから |

計画に頼んでいない項目が混ざっている状態は、まだ Code に進む頃合いではありません。その一行を外してから進みます。

## 3-2-2 頼むのは一度に一段だけ

> **Codeでは一度に全部ではなく一段ずつ書かせて、そのつど確かめます**

計画が固まったら **Code の段** です。ここでやりがちなのが「計画どおり全部やって」と一度に頼むことです。すると、大量の変更がまとめて返ってきます。読む気は失せ、どこで話がずれたのかも切り分けられません。

そこで、計画のうちの1項目ぶん、つまり **一段** だけを頼みます。

```text
まとめて  計画の1から3まで、まとめて進めてください

一段ずつ  まず1だけ書いてください。2はまだ書かないでください
          → 出てきたものを確かめる
          → では2をお願いします
```

要点は「2はまだ書かないでください」と書き添えることです。これが無いと、勢いのまま先へ進みます。Code の段は一往復ではなく、小さな往復の繰り返しになります。

| | まとめて書かせる | 一段ずつ書かせる |
| --- | --- | --- |
| 確かめる単位 | 全部まとめて | 一段ぶん |
| ずれの場所 | 探し回る | 直前の一段 |
| やり直し | 大きい | 一段ぶん |

一段ずつは遅そうに見えますが、やり直しの量を含めると結局こちらが速く済みます。

## 3-2-3 ずれたら途中で止めて戻す

> **進み方がずれたら最後まで待たずに中断して、計画のところまで戻して直します**

一段ずつ確かめていると、途中でずれに気づくことがあります。頼んでいないファイルまで書き換え始めた、計画の順番を飛ばしている、といった場面です。

このとき「最後まで見てから言おう」と待つのは損です。待っているあいだ、ずれた土台の上に次の一段が積み上がるからです。

進んでいる途中で止めることを **中断**、向きを直してから続けることを **軌道修正** と呼びます。

```text
気づく  頼んでいないファイルまで書き換え始めた
中断    いったん止める
戻す    計画の2に戻ってください。触るのは商品一覧ページだけです
続ける  直した向きで、その一段をやり直してもらう
```

戻すときは、計画のどこへ戻るのかを番号で示すと伝わります。戻る先は最初ではなく、計画のところまでです。

| 思い込み | 実際 |
| --- | --- |
| 途中で止めるのは失礼 | 相手は人ではないので遠慮は要らない |
| 止めたら最初からやり直し | 戻すのは計画のところまで |
| 最後まで見てから言うほうが早い | ずれた上に積み上がるぶん遅くなる |

中断はワークフローの想定内の操作です。見て、止めて、戻して、続ける。この動きが Code の段の真ん中にあります。

## もっと知りたい人へ

- 計画を読んで過不足を直す作業は、人に仕事を頼むときの段取り合わせと同じです。着手前の一言が、いちばん割のよい確認になります
- 一段の大きさに正解はありません。「出てきたものを一目で読み切れるか」を目安にすると、ちょうどよい大きさに落ち着きます
- 画面上の止め方や、モードの切り替え方は変わっていきます。実際に使うときは、製品のドキュメントで確認してください
