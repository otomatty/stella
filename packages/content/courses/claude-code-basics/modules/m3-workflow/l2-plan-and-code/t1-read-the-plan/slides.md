# 3-2-1
# 計画は着手の前に読む

Claude Code入門 — Module 3 / レッスン3-2

<!-- ノート: 2つめの段の中身です。計画が出てきたあと、自分が何をするかの話です。 -->

---

## なぜ必要か

- 計画が長いほど、読み飛ばして「それで進めて」と言ってしまいます
- できあがってから「そこは触ってほしくなかった」と言うのがいちばん高くつきます

<!-- ノート: つかみ。読まずに通した経験を思い出してもらいます。結論はまだ言いません。 -->

---

## 結論

**Planで出てきた計画は、Codeに進む前に自分で読んで過不足を直します**

- **過不足** — 足りないところと、余計なところ
- **Planモード** は書かせずに計画を出させる選び方、**Plan の段** はその計画を読む場面です

<!-- ノート: 結論です。モードは道具、段はワークフロー上の位置だと分けて言い切ります。読むのは自分の仕事です。 -->

---

## 計画の読み方

```text
計画  1. 更新日を組み立てている処理の書式を直す
      2. 商品一覧ページの呼び出し側を合わせる
      3. ついでに周辺の関数名を分かりやすく変える

読む  1と2は依頼どおり → そのまま
      3は頼んでいない  → 「3は今回やめてください」
```

<!-- ノート: 最小の例です。見る点は2つだけ。頼んだことが入っているか、頼んでいないことが混ざっていないかです。 -->

---

## 読んでから進めるかどうか

| | 読まずにCodeへ | 読んでからCodeへ |
| --- | --- | --- |
| 直す対象 | 書かれたコード | 計画の1行 |
| 余計な変更 | できてから気づく | 進む前に外せる |
| 進む向き | 決まらないまま | 決まってから |

<!-- ノート: 対比枠です。計画の1行を消すのと、書かれたコードを消すのとでは手間が違うと言い添えます。 -->
