# 実行の前に承認を求められる

Claude Code入門 — Module 2 / レッスン2-1

<!-- ノート: 手元を触らせるときに、最初に出会う仕組みの話です。 -->

---

## なぜ必要か

- 手元のコードは自分の持ち物です。勝手に書き換わっては困ります
- かといって、1つずつ自分の手で動かすなら任せた意味がありません

<!-- ノート: つかみ。任せたいけれど全部は任せたくない、という当たり前の板挟みから入ります。ここではまだ答えを言いません。 -->

---

## 結論

**Claude Codeは、書き換えやコマンド実行の前に、権限の確認として承認を求めてきます**

- **権限** — そのツールを実行してよいかどうかの範囲
- **承認** — 実行してよい、と自分が返事をすること
- 読むだけの操作は、手元が変わらないため聞かれずに進むことが多いです

<!-- ノート: 結論を先に言い切ります。板挟みの答えは、手元に影響する実行の直前に一度止まる仕組みです。権限は範囲、承認はその場の返事だと言い分けます。読むだけなら止まらない、という線も添えます。 -->

---

## 承認を求められる場面

```text
依頼    「一覧ページの見出しの誤字を直して」
確認     ファイルを1つ書き換えます。実行してよいですか
返事     はい(承認する) / いいえ(断る)
```

<!-- ノート: 最小の例です。何をするかが先に示され、返事をするまで実行されません。断る選択肢が常にあることも読み上げます。 -->

---

## 止まる場所が変わる

| | 承認がないと | 承認があると |
| --- | --- | --- |
| 手元の変化 | 気づかないうちに起きる | 起きる前に自分が知る |
| 決める人 | エージェント任せ | 自分 |
| 止められる時点 | 終わったあと | 実行の前 |

<!-- ノート: 対比枠です。承認は速さを落とす関門ではなく、止められる時点を前に動かす仕組みだと押さえます。 -->
