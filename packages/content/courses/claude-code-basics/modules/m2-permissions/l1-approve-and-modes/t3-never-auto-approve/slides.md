# 取り消せない操作は自動承認から外す

Claude Code入門 — Module 2 / レッスン2-1

## なぜ必要か

- 手が止まらないのは快適で、確認をもっと減らしたくなります
- 一方で、あとから「そこは聞いてほしかった」と思う操作もあります

<!-- ノート: つかみ。前のトピックの快適さが、そのまま線引きの動機になります。ここでは線引きの中身は言いません。 -->

---

## 結論

**消す・送るといった取り消せない操作は自動承認に入れず、毎回自分で止めて確かめます**

- **取り消せない操作** — 実行したあと、元の状態に戻せない操作
- **責任を持つ** — 結果の責任は依頼した自分にあるという構え(4Dの1つで、講座1で扱った語です)

<!-- ノート: 結論です。責任を持つは講座1の復習なので、一言で流します。判断の物差しは、戻せるかどうかの1点だけです。 -->

---

## 判断の分かれ目

```text
自動承認に入れてよい   読む / 調べる(手元の状態が変わらない)
毎回止めて確かめる     消す / 外に送る / 環境を変える
分かれ目               間違っていたとき、元に戻せるか
```

<!-- ノート: 最小の例です。操作の名前を覚えるのではなく、戻せるかを毎回自分に聞く、という形で覚えてもらいます。 -->

---

## 権限を渡してよいか

| 操作 | 元に戻せるか | 自動承認 |
| --- | --- | --- |
| ファイルを読む | 変化しない | 入れてよい |
| ファイルを消す | 戻せない | 入れない |
| 外部に送る | 送った事実は消せない | 入れない |
| 外から取り込んで入れる | 手元の環境が変わる | 入れない |

<!-- ノート: 対比枠です。権限を先に渡してよいのは、渡し間違えても戻せる範囲だけだと押さえます。 -->
