# レッスン2-1 許可の出し方を決める

## このレッスンの目標

- [ ] 実行の前に承認を求められる仕組みを説明できる
- [ ] ある操作を自動承認に入れてよいか判断できる
- [ ] Planモードを選ぶ場面を言える

## 2-1-1 実行の前に承認を求められる

> **Claude Codeは、書き換えやコマンド実行の前に、権限の確認として承認を求めてきます**

手元のコードは自分の持ち物です。知らないうちに書き換わっていては困ります。かといって、1つずつ自分の手で動かすなら、任せた意味がありません。

この板挟みに、Claude Code は「手元に影響する実行の直前に一度止まる」という形で答えます。ファイルの書き換えやコマンドの実行など、手元に影響が残る操作の前に **権限** の確認が入り、あなたの **承認** を待ちます。権限はそのツールを実行してよい範囲、承認はその場での返事です。一方で、中身を読む・探すといった手元が変わらない操作は、聞かれずに進むことが多いです。

どの操作で止まるかは、許可の出し方のまとまりとして選べます。既定でも、読むだけの操作は聞かれずに進み、影響の残る操作で止まる、という線が基本です。既定の位置や切り替え方、それぞれの呼び名は製品側で変わるので、実際の画面は製品のドキュメントで確かめてください。覚えておくのは「どこで止めるかは自分で選べる」という仕組みのほうです。

```text
依頼    「一覧ページの見出しの誤字を直して」
確認     ファイルを1つ書き換えます。実行してよいですか
返事     はい(承認する) / いいえ(断る)
```

大事なのは、何をするかが先に示される点です。読んでから決められますし、断る選択肢は常にあります。

| | 承認がないと | 承認があると |
| --- | --- | --- |
| 手元の変化 | 気づかないうちに起きる | 起きる前に自分が知る |
| 決める人 | エージェント任せ | 自分 |
| 止められる時点 | 終わったあと | 実行の前 |

承認は、進み方を遅くするための関門ではありません。止められる時点を、終わったあとから実行の前へ動かす仕組みです。

## 2-1-2 繰り返す操作は自動承認にできる

> **毎回同じ確認が続く安全な操作は、自動承認にして手を止めずに進められます**

実際に使い始めると、同じ確認が続くことに気づきます。「このコマンドを実行してよいですか」に、十回続けて「はい」と答えている、といった状態です。返事のたびに手が止まり、何を頼んでいたか思い出し直しになります。

そこで使えるのが **自動承認** です。この種類の操作は聞かずに実行してよい、と先に決めておく仕組みです。承認をやめるのではなく、返事の内容が毎回同じものだけを、先にまとめて答えておくのだと考えてください。

```text
繰り返される確認   表示を確かめるコマンドを実行してよいですか(何度も)
先に決めておく     この確認用のコマンドは、聞かずに実行してよい
その後             エージェントループが止まらずに進む
```

向いているのは、実行しても手元の状態を変えないと分かっている操作です。読むだけの操作がはじめから聞かれないのと同じ扱いを、安全だと自分で確かめた操作へ広げていくのが自動承認です。

| | 毎回承認する | 自動承認にする |
| --- | --- | --- |
| 確認用のコマンド | 何十回も返事する | 返事は不要 |
| 表示を作り直すコマンド | そのつど止まる | そのまま続く |
| 自分の集中 | 途切れる | 続く |

自動承認にしても、進む中身は変わりません。減るのは返事の回数だけです。調べものが長く続くような依頼ほど、この差が効いてきます。

## 2-1-3 取り消せない操作は自動承認から外す

> **消す・送るといった取り消せない操作は自動承認に入れず、毎回自分で止めて確かめます**

手が止まらないのは快適です。快適だからこそ、確認をもっと減らしたくなります。ところが操作の中には、あとから「そこは聞いてほしかった」と思うものがあります。

分かれ目は1つです。間違っていたときに、元の状態へ戻せるかどうか。戻せない操作を **取り消せない操作** と呼びます。ファイルを消す、外へ送る、外から取り込んで手元の環境を変える、といった操作がこれにあたります。

```text
自動承認に入れてよい   読む / 調べる(手元の状態が変わらない)
毎回止めて確かめる     消す / 外に送る / 環境を変える
分かれ目               間違っていたとき、元に戻せるか
```

自動承認は、権限を先に渡しておく約束です。渡してよいのは、渡し間違えても戻せる範囲だけです。

| 操作 | 元に戻せるか | 自動承認 |
| --- | --- | --- |
| ファイルを読む | 変化しない | 入れてよい |
| ファイルを消す | 戻せない | 入れない |
| 外部に送る | 送った事実は消せない | 入れない |
| 外から取り込んで入れる | 手元の環境が変わる | 入れない |

覚えるのは操作の一覧ではなく、問い方のほうです。「これは戻せるか」と毎回自分に聞けば、知らない操作が出てきても判断できます。

なお、結果の責任は依頼した自分にあります。これが **責任を持つ** という構えで、4Dの1つとして講座1で扱った語です。承認の返事は、その責任を引き受ける場面そのものです。取り消せない操作で毎回止まるようにしておくのは、引き受ける場面を自分の手元に残しておくためです。

## 2-1-4 Planモードは書かせずに考えさせる

> **Planモードは、ファイルを変更させずに計画だけを出させたいときに選びます**

止めたいものが、1つ1つの実行ではなく「書くこと自体」であることもあります。どう直すか決まっていないうちに書き始められると、あとからの直しが増えるからです。とはいえ「まだ書かないで」と毎回添えるのも、承認で1つずつ止めるのも手間です。

このための状態が **Planモード** です。ファイルの変更を止めたまま、どう進めるつもりかを答えさせます。返ってくるのは変更ではなく、どう直すつもりかの見取り図、つまり **計画** です。

```text
選ぶとき     直し方がまだ決まっていない / 作業の範囲が広そう
頼むこと     「どう直すつもりか、先に出して」
返るもの     ファイルの変更ではなく、進め方の計画
```

| | ふつうに頼む | Planモードで頼む |
| --- | --- | --- |
| 手元のファイル | 変わりうる | 変わらない |
| 返ってくるもの | 変更 | 計画 |
| 向く場面 | 直し方が決まっている | まだ決まっていない |

承認とPlanモードは、どちらも止める仕組みですが、止める対象が違います。承認は1つの実行を直前で止めます。Planモードは、変更そのものを最初から起こさせません。誤字を1文字直すだけと分かっている依頼にPlanモードを使う必要はありませんし、影響の見えない修正をいきなり書かせる必要もありません。

呼び名や切り替え方は製品の画面とともに変わっていきます。覚えておくのは、書かせずに考えさせるという役割のほうです。

## もっと知りたい人へ

- 人に作業を頼むときも、「読むだけなら任せる」「消すときは一声かけて」と線を引きます。自動承認はその線を先に文章化したものだと考えると、迷いにくくなります
- 取り消せない操作を見分ける練習は、Git 入門研修の「戻せる操作・戻せない操作」の整理が参考になります
- モードの呼び名・切り替え方・自動承認の設定画面は変わっていきます。実際に使うときは、製品のドキュメントで確認してください
