# 2-1-4
# Planモードは書かせずに考えさせる

Claude Code入門 — Module 2 / レッスン2-1

<!-- ノート: 承認とは別に、もう1つある止め方の話です。 -->

---

## なぜ必要か

- どう直すか決まっていないうちに書き始められると、直しが増えます
- 「まだ書かないで」と毎回添えるのも、承認で1つずつ止めるのも手間です

<!-- ノート: つかみ。止めたい対象が個々の実行ではなく、書くこと自体だという場面を思い出してもらいます。 -->

---

## 結論

**Planモードは、ファイルを変更させずに計画だけを出させたいときに選びます**

- **Planモード** — ファイルの変更を止めて、進め方を答えさせる状態
- **計画** — どう直すつもりかの見取り図

<!-- ノート: 結論です。書かせずに考えさせるモードだと言い切ります。呼び名や切り替え方は変わりうるので、役割のほうを覚えてもらいます。 -->

---

## 選ぶ場面

```text
選ぶとき     直し方がまだ決まっていない / 作業の範囲が広そう
頼むこと     「どう直すつもりか、先に出して」
返るもの     ファイルの変更ではなく、進め方の計画
```

<!-- ノート: 最小の例です。返ってくるものが変更ではなく文章になる、という点が体感の違いです。 -->

---

## ふつうに頼むときとの違い

| | ふつうに頼む | Planモードで頼む |
| --- | --- | --- |
| 手元のファイル | 変わりうる | 変わらない |
| 返ってくるもの | 変更 | 計画 |
| 向く場面 | 直し方が決まっている | まだ決まっていない |

<!-- ノート: 対比枠です。承認は1回ずつ止める仕組み、Planモードは書くこと自体を止める仕組みだと整理します。 -->
