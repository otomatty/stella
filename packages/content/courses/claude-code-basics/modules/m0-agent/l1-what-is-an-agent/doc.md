# レッスン0-1 エージェントとは何か

## このレッスンの目標

- [ ] Claude Code が何のための相手かを説明できる
- [ ] チャットとコーディングエージェントの違いを説明できる
- [ ] エージェントループの3語を順に言える

## 0-1-1 Claude Codeはコードを直す相手

> **Claude Codeは、手元のコードを読んで直すところまで進めるコーディングエージェントです**

小さな不具合ほど、往復が多くなります。一覧の並びが逆になっている。返している項目が1つ足りない。直す内容そのものは数行でも、まず直す場所を探し、周りを読んで、書き換えて、動かしてみる。この往復が、細切れの時間を埋めていきます。

講座1・講座2では、**Claude** に文章で仕事を頼むやり方を扱いました。この講座で扱うのは、その相手を **コード**(動くソフトウェアのもとになる、書かれた命令)の上に連れてくる話です。頼まれた修正を手元のコードの上で進めるAIを **コーディングエージェント** と呼びます。**Claude Code** は、Claude をコーディングエージェントとして使うための製品です。

頼み方のイメージは次のとおりです。

```text
自分         一覧の日付が古い順に出ている。新しい順にしたい
Claude Code  並び順を決めている場所を手元のコードから探して読む
             そのうえで、新しい順になるよう直す
結果         直したあとのコードが手元に残る
```

「探して読む」と「直す」が、同じ相手の中で続いていきます。ここがこの講座の出発点です。

相手にするのは、あくまで手元のコードです。コードの外側にある判断は、この講座の範囲ではありません。

| 頼みごと | 向き |
| --- | --- |
| 一覧の並び順が逆なのを直す | 向く |
| 返している項目を1つ足す | 向く |
| どの機能を来期に作るか決める | 向かない(コードの話ではない) |

## 0-1-2 チャットは提案、エージェントは変更

> **チャットは提案で止まりますが、コーディングエージェントにはファイルの変更まで任せられます**

これまでの使い方と、何が違うのか。境目は一点だけです。手元が変わるかどうかです。

**チャット**(文章の一往復で相談する使い方。講座2で扱った語です)に修正を相談すると、「こう直すとよい」という案が返ってきます。これが **提案** です。提案は文章なので、手元は変わりません。返ってきたものをコピーして、貼る場所を探して、貼って保存する係が自分に残ります。3行の直しでも、貼り間違いや貼り忘れは起きます。

コーディングエージェントは、この続きまで進みます。コードが書かれて保存されている入れ物、つまり **ファイル** を開いて、その場で書き換えます。**任せる**(何を自分でやり、何を渡すか決めること。講座1で扱った語です)の対象が、案を考えるところから、ファイルを変えるところまで伸びる、と言い換えてもかまいません。

```text
チャット                「並び順のところを次のように書き換えてください」
                        → 場所を探して貼って保存するのは自分

コーディングエージェント  該当するファイルを開いて、その場で書き換える
                        → 手元のファイルがもう変わっている
```

| | チャット | コーディングエージェント |
| --- | --- | --- |
| 返ってくるもの | 提案 | 変更されたファイル |
| 手元の状態 | 変わらない | 変わる |
| 自分に残る作業 | 貼って直す | 変わった結果を見る |

コーディングエージェントはチャットの上位版ではありません。止まる位置が違うだけです。相談で足りる用や、手元を変えたくない調べものは、チャットのほうが早く終わります。

## 0-1-3 エージェントはツールで手元を触る

> **コーディングエージェントは、ファイルを読み書きしたりコマンドを実行したりするツールを使います**

文章を書くAIが、なぜ手元のファイルを変えられるのか。ここが分からないままだと、何をどこまで頼んでよいかも決められません。

答えは、文章を書く力とは別に、手元を触るための口が用意されているからです。この口を **ツール** と呼びます。ファイルを読む、書く、探す、そして **コマンド**(手元の機械に出す1行の命令)を **実行** する。こうした操作が、ツールとしてエージェントに渡されています。

1つの頼みごとの中で、ツールは何度も使われます。

```text
頼みごと  一覧の日付を新しい順にしたい
探す      並び順を決めている場所を手元から探す
読む      見つかったファイルの中身を読む
書く      新しい順になるよう書き換えて保存する
実行      表示を作り直すコマンドを実行する
```

ツールの名前や種類を覚える必要はありません。押さえるのは「手元を触る口がある」という一点です。

| | チャット | ツールを持つエージェント |
| --- | --- | --- |
| できること | 説明・提案 | 探す・読む・書く・実行する |
| 手元への影響 | ない | 実際に変わる |

手元が実際に変わるということは、頼み方を誤れば実際に壊れるということでもあります。だからこそ、勝手に進まない仕組みが要ります。その仕組みは Module 2 でまとめて扱います。

## 0-1-4 エージェントループを回して仕上げる

> **コーディングエージェントは、調べる・変える・確かめるというエージェントループを繰り返して仕上げます**

ツールがどんな順番で使われるのかを見ておきます。

一度書き換えただけで望みどおりになることは、そう多くありません。直したつもりが別の場所を崩すこともあります。これはAIに限った話ではなく、人が手で直すときも同じです。だから、進み方は繰り返しになります。

調べる、変える、**確かめる**(変えたあとの状態を実際に見て、望みどおりかを見ること)。この3つを繰り返す進み方が **エージェントループ** です。順番は固定で、この3語がこの講座の背骨になります。

```text
1周目  調べる    並び順を決めている場所を探して読む
       変える    新しい順になるよう書き換える
       確かめる  表示を作り直して見る → 日付のない行が先頭に来ている

2周目  調べる    日付のない行の扱いを見に行く
       変える    日付のない行は最後に置くよう直す
       確かめる  もう一度見る → 望みどおり
```

1周目の「確かめる」で崩れが見つかり、それがそのまま2周目の入口になります。周を重ねるほど、仕上がりに近づきます。

このループを知っているかどうかで、途中の見え方が変わります。

| | 知らないと | 知っていると |
| --- | --- | --- |
| 途中で崩れたとき | 頼み方を間違えたと思う | 想定内の1周だと分かる |
| 何周も動くとき | 迷走に見える | 仕上げに向かっていると読める |
| 自分が見る先 | 一手ごとの正しさ | 最後の「確かめる」の結果 |

途中の失敗は事故ではなく、手順の一部です。ここまでで、これから付き合う相手の正体はそろいました。コードを相手にすること、提案ではなく変更まで進むこと、ツールで手元を触ること、そしてループを回して仕上げること。この4つが、以降のモジュールの土台になります。

## もっと知りたい人へ

- 自分の直近1週間から「数行で済むのに半日かかった修正」を1つ思い出してください。この講座で通しの練習に使う候補になります
- 「調べる・変える・確かめる」は、人が修正するときの手順とまったく同じです。自分がふだんどこを飛ばしがちかを振り返っておくと、後のモジュールがつながりやすくなります
- 製品の画面や名称は変わっていきます。実際に使うときは、製品のドキュメントで確認してください
