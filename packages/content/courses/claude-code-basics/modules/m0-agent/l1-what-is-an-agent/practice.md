# レッスン0-1 演習 — エージェントとは何か

対象トピック: 0-1-1 〜 0-1-4

## 手元で試す

このモジュールの演習は、紙とペン、または手元のメモ帳だけで進められます。Claude Code は次のモジュールで実際に開くので、ここでは準備も導入もしません。

まず、自分の直近1〜2週間から、コードを直した仕事を3つ書き出します。

```text
例
1. 一覧の日付が古い順に出ていたのを直した
2. 返す項目に「更新日」を1つ足した
3. 設定の値を1か所変えて、動かなくなった原因を探した
```

書き出せたら、次の3つをやってみましょう。

1. 3つそれぞれに「提案をもらえれば足りた」か「ファイルを変えるところまで任せたかった」かの印を付ける
2. 「ファイルを変えるところまで」に印を付けた仕事を1つ選び、その修正で使われそうな **ツール** を、探す・読む・書く・実行 の中から順に並べる
3. 同じ仕事を **エージェントループ** の形に書き直す。1周目の「確かめる」で何が見つかりそうかまで書けたら、2周目も書く

3 が書けたら、そのメモは後のモジュールでそのまま使えます。捨てずに残しておいてください。

## 演習問題

### 問1(基本)

チャットとコーディングエージェントの違いを、「提案」「ファイル」の2語を使って1〜2文で説明してください。

### 問2(基本)

エージェントループの3語を順に挙げ、それぞれが何をする段かを1行ずつ書いてください。

### 問3(応用)

「返している項目に更新日を1つ足す」という修正を、エージェントループの1周として書いてください。調べる・変える・確かめるに、それぞれ何をするかを1行ずつ入れます。

### 問4(応用)

「コーディングエージェントはツールで手元を触れるので、チャットは要らなくなります」という意見の誤りを、1〜2文で指摘してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

チャットは「こう直すとよい」という提案で止まるので、手元は変わりません。コーディングエージェントはファイルを開いて書き換えるところまで進むので、頼んだあとは手元のファイルがすでに変わっています。

</details>

<details>
<summary>問2の解答例</summary>

調べる(直す場所を探して読む)、変える(その場所を書き換える)、確かめる(変えたあとの状態を見て、望みどおりかを見る)の3つです。この順で繰り返して仕上がりに近づきます。

</details>

<details>
<summary>問3の解答例</summary>

調べる: 返す項目を組み立てている場所を探して読む。変える: 更新日を返す項目に足す。確かめる: 実際に返ってくるものを見て、更新日が入っているかを見る。

1周で望みどおりにならなければ、そこが2周目の入口になります。たとえば「更新日が空で返ってくる」と分かれば、次の周は元のデータを調べるところから始まります。

</details>

<details>
<summary>問4の解答例</summary>

止まる位置が違うだけで、上下の関係ではありません。手元を変えたくない調べものや、一言で済む相談は、チャットのほうが早く終わります。手元が変わることは、そのぶん壊れうるということでもあります。

</details>

## 確認クイズ

### Q1. 「この行をこう書き換えるとよいです」という文章が返ってきて、貼るのは自分でした。この使い方はどちらですか。

- A. 提案で止まるチャットの使い方
- B. ファイルの変更まで任せた使い方
- C. ツールを実行した結果

<details>
<summary>答え</summary>

**A** — 返ってきたのが文章で、手元が変わっていないなら提案です。貼る係が自分に残っている点が目印になります。

</details>

### Q2. 「手元を変えずに、直し方の見当だけ先に知りたい」とき、適した進め方はどれですか。

- A. コーディングエージェントに任せて、ファイルを書き換えてもらう
- B. チャットで相談して提案をもらう
- C. どちらでも同じなので、速いほうを選ぶ

<details>
<summary>答え</summary>

**B** — 手元を変えたくないなら、提案で止まる使い方が合っています。上位版・下位版ではなく、止まる位置で選びます。

</details>

### Q3. コーディングエージェントが手元のファイルを変えられるのは、何があるからですか。

- A. 文章を書く力が特別に高いから
- B. ファイルの読み書きやコマンドの実行ができるツールを持っているから
- C. コードを暗記しているから

<details>
<summary>答え</summary>

**B** — 文章を書く力とは別に、手元を触るための口としてツールが渡されています。ツールの名前を覚える必要はありません。

</details>

### Q4. 修正を頼んだところ、1回書き換えたあとに別の場所が崩れ、続けて直し始めました。この動きの理解として適切なのはどれですか。

- A. 頼み方を間違えたので、最初からやり直すしかない
- B. 調べる・変える・確かめるを繰り返すエージェントループの、想定内の動き
- C. 壊れているので、コーディングエージェントには修正を頼めない

<details>
<summary>答え</summary>

**B** — 1周目の「確かめる」で崩れが見つかり、それが2周目の入口になっています。周を重ねて仕上げるのがこの進み方です。

</details>

### Q5. ツールで手元が実際に変わる、ということから言えるのはどれですか。

- A. 頼めば必ず正しく直るので、任せきりでよい
- B. 手元が変わる以上、勝手に進まない仕組みが必要になる
- C. 手元が変わるのは表示だけで、保存はされない

<details>
<summary>答え</summary>

**B** — 実際に変えられるということは、実際に壊れうるということでもあります。その歯止めの仕組みは Module 2 で扱います。

</details>
