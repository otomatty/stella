## なぜ必要か

- 一度書き換えただけで望みどおりになることは、そう多くない
- 直したつもりが別の場所を崩す。人が手で直すときも同じ

<!-- ノート: つかみ。1回で当たらないのは能力の問題ではなく、修正という仕事の性質です。結論はまだ言いません。 -->

---

## 結論

**コーディングエージェントは、調べる・変える・確かめるというエージェントループを繰り返して仕上げます**

- **確かめる** — 変えたあとの状態を実際に見て、望みどおりかを見ること
- **エージェントループ** — 調べる → 変える → 確かめる を繰り返す進み方

<!-- ノート: 結論を先に言い切ります。3語の順番は固定です。調べる・変える・確かめる。これがこの講座の背骨になります。 -->

---

## 2周で仕上がる例

```text
1周目  調べる    並び順を決めている場所を探して読む
       変える    新しい順になるよう書き換える
       確かめる  表示を作り直して見る → 日付のない行が先頭に来ている

2周目  調べる    日付のない行の扱いを見に行く
       変える    日付のない行は最後に置くよう直す
       確かめる  もう一度見る → 望みどおり
```

<!-- ノート: 最小の例です。1周目の「確かめる」で崩れが見つかり、それが2周目の入口になります。周を重ねるほど仕上がりに近づきます。 -->

---

## ループを知っているかどうか

| | 知らないと | 知っていると |
| --- | --- | --- |
| 途中で崩れたとき | 頼み方を間違えたと思う | 想定内の1周だと分かる |
| 何周も動くとき | 迷走に見える | 仕上げに向かっていると読める |
| 自分が見る先 | 一手ごとの正しさ | 最後の「確かめる」の結果 |

<!-- ノート: 対比枠です。ループを前提に見ると、途中の失敗は事故ではなく手順の一部に見えてきます。 -->
