# 通す1本は小さく選ぶ

Claude Code入門 — Module 5 / レッスン5-1

## なぜ必要か

- 初めての1本に、前から気になっていた大きな作り直しを選びがち
- 途中でどこまで直ったのか分からなくなり、練習として終わらない

<!-- ノート: つかみ。題材選びを外すと、進め方の練習ではなく大工事の遭難になります。ここではまだ結論を言いません。 -->

---

## 結論

**通しで練習する1本は、影響範囲が小さくて完了を言い切れる修正を選びます**

- **影響範囲** — その修正が触る範囲。直したところが波及する先の広さ

<!-- ノート: 結論を先に言い切ります。条件は2つです。影響範囲が小さいことと、できの基準を言い切れることです。 -->

---

## 選ぶときの見方

```text
題材の例    一覧画面の日付の表示が崩れているのを直す
            APIのレスポンスに項目を1つ足す
影響範囲    触るのはファイル1〜2本まで
できの基準  その画面が崩れずに表示される / 既存のテストが通る
```

<!-- ノート: 最小の例です。依頼に書くできの基準が1〜2行で書けるなら、その1本は通しに向いています。 -->

---

## 向く1本・向かない1本

| | 通しに向く1本 | 向かない1本 |
| --- | --- | --- |
| 影響範囲 | ファイル1〜2本 | リポジトリ全体 |
| できの基準 | 1〜2行で書ける | 書き出すと切りがない |
| 完了 | 言い切れる | だいたい直った止まり |

<!-- ノート: 対比枠です。向かない1本が悪い仕事なのではなく、ワークフローを覚える題材に向かないという話です。 -->
