# 通した変更はレビューに出す

Claude Code入門 — Module 5 / レッスン5-1

<!-- ノート: 選んだ1本を、4つの段に通してから外に出すところまでの話です。 -->

---

## なぜ必要か

- 差分を読んで動作確認まで済ませても、自分ひとりの目には限界がある
- 「エージェントが書いたので大丈夫です」は、チームに対する説明になっていない

<!-- ノート: つかみ。自分で確かめる工程は済んでいる前提で、その先に何が要るかを考えさせます。結論はまだ言いません。 -->

---

## 結論

**4つの段を通した変更は、プルリクエストに出して人のレビューを受けてから取り込みます**

- **プルリクエスト** — ブランチの変更を、取り込む前に見てもらう場です(Git入門で扱った語です)
- **レビュー** — 取り込む前に、人が変更を読んで見る工程です

<!-- ノート: 結論を先に言い切ります。プルリクエストはGitの復習なので1行で流します。ワークフローの外側に、人の目がもう1枚あるという構図です。 -->

---

## 1本を通す順番

```text
ブランチを切る → Exploreから4つの段を通す → Commitでコミットに区切る
→ プルリクエストを出す(何を直したか / どう確かめたか を書く)
→ レビューで指摘を受けて直す → 取り込む
```

<!-- ノート: 最小の例です。Commitの段で終わりではなく、プルリクエストとレビューまでが1本ぶんだと示します。 -->

---

## 出さない場合との差

| | そのまま取り込む | プルリクエストに出す |
| --- | --- | --- |
| 読む人 | 自分だけ | 自分と、レビューする人 |
| 残るもの | コミットだけ | 直した理由とやり取り |
| 見落とし | そのまま入る | もう一度読まれる |

<!-- ノート: 対比枠です。エージェントに書かせた変更ほど、読む人を増やす価値があります。 -->
