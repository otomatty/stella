# 4-1-3
# /compactで要点だけ残す

Claude Code入門 — Module 4 / レッスン4-1

<!-- ノート: 同じ作業を続けたまま余裕を作る話です。 -->

---

## なぜ必要か

- まだ同じ修正の途中なのに、会話の余裕が減ってきた
- ここまでの経緯は続きに要るので、まるごと捨てたくはない

<!-- ノート: つかみです。「続けたい」と「減らしたい」が同時に立つ場面を作ります。ここでは打つものをまだ言いません。 -->

---

## 結論

**`/compact`は、ここまでの会話を要約して、続きに要る要点だけを残します**

- 役割は **要約して残す** こと。その役割に付いている名前が `/compact` です
- **要約** — 中身を短くまとめ直したもの

<!-- ノート: 結論を先に言い切ります。捨てるのではなく詰める、が要点です。ここでも役割を先に言い、名前を後ろに置きます。 -->

---

## 前と後で何が変わるか

```text
前         依頼 + 読ませたファイル + 試したコマンド + 差分 …
/compact   ここまでを要約に置き換える
後         「どこを直しているか」「決めた方針」+ この先の会話
```

<!-- ノート: 最小の例です。会話そのものは続いています。中身が短い形に入れ替わっただけだ、と伝えてください。 -->

---

## 残るもの・落ちるもの

| 会話にあったもの | 要約のあと |
| --- | --- |
| いま何を直しているか | 残る |
| 決めた方針・できの基準 | 残る |
| 途中で読んだファイルの中身そのもの | 落ちることがある |

<!-- ノート: 対比枠です。要約なので細部は落ちます。落ちて困るものがあるなら、先に自分で書き留めておくか、もう一度伝え直します。ここが「責任を持つ」の出番です。 -->
