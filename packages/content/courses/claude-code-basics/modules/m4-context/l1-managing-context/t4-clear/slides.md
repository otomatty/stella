# 4-1-4
# /clearは話題が変わったら使う

Claude Code入門 — Module 4 / レッスン4-1

<!-- ノート: 作業が変わるときの切り替えの話です。 -->

---

## なぜ必要か

- 午前の修正が終わり、午後はまったく別のファイルに取りかかる
- 前の作業の話が残っていると、関係ない前提を引きずった返事が来る

<!-- ノート: つかみです。前のトピックは「同じ作業の続き」でしたが、ここは作業そのものが変わる場面だと対比させます。結論はまだ言いません。 -->

---

## 結論

**`/clear`は会話を空にするので、前の作業を持ち越したくないときに使います**

- 役割は **空にする** こと。その役割に付いている名前が `/clear` です
- 空にすると、コンテキストは会話を始めたばかりの状態に戻ります

<!-- ノート: 結論を先に言い切ります。要約して残すのではなく、持ち越さないという選択です。ここでも役割を先に、名前を後ろに置きます。 -->

---

## 切り替えの形

```text
午前     表示崩れを直した会話が続いている
区切り   差分を読んでコミットまで済ませる
/clear   会話を空にする
午後     別の修正を、前の作業を持ち越さずに頼める
```

<!-- ノート: 最小の例です。空にする前に、その作業を区切っておくのが順番です。読んでいない差分を残したまま空にすると、経緯だけが消えます。 -->

---

## どちらを使うかの分かれ目

| いまの状況 | 使うもの |
| --- | --- |
| 同じ作業の続き。経緯が要る | 要約して残す(`/compact`) |
| 別の作業に移る。経緯は要らない | 空にする(`/clear`) |

<!-- ノート: 対比枠で、このレッスンの判断を1枚にまとめます。判断の軸は「続きかどうか」の1つだけです。迷ったら、いま出す依頼が前の会話を根拠にするかを考えてもらいます。 -->
