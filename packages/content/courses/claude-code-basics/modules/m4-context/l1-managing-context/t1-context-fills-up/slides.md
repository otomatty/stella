# 4-1-1
# 会話が長いほど余裕が減る

Claude Code入門 — Module 4 / レッスン4-1

<!-- ノート: 長く使った日の午後に起きることの話です。 -->

---

## なぜ必要か

- 朝から同じパネルで頼み続けていると、午後になって返事が噛み合わなくなる
- 何も壊していないのに、朝と同じ頼み方が通らない

<!-- ノート: つかみです。多くの人が「今日は調子が悪い」で片づける現象ですが、原因は会話の長さ側にあります。ここでは結論をまだ言いません。 -->

---

## 結論

**会話はまるごとコンテキストとして読み直されるため、長くなるほどコンテキスト上限に近づきます**

- **コンテキスト** — 判断のもとになる前後の情報。講座1で扱った語です
- **コンテキスト上限** — 一度に読める量の上限。講座1で扱った語です

<!-- ノート: 結論を先に言い切ります。2語とも講座1で扱った語なので、定義は1行の復習で済ませ、Claude Code の上でどう効くかに時間を使います。上限の実際の値は製品ごとに違うので本文では扱いません。 -->

---

## 何が積み上がるのか

```text
1つ目の依頼   依頼 + 読ませたファイル + 出てきた差分
2つ目の依頼   1つ目のぶん + 今回のぶん をまとめて読み直す
3つ目の依頼   1つ目 + 2つ目 + 今回 をまとめて読み直す
```

<!-- ノート: 最小の例です。エージェントループが1周するたびに、読んだファイルやコマンドの結果まで会話に積まれます。自分が打った文字数より、積み上がりはずっと速いという点が要点です。 -->

---

## 始めたばかりの会話との違い

| | 始めたばかり | 長く続いた会話 |
| --- | --- | --- |
| 積まれているもの | いまの依頼だけ | 前の作業ぜんぶ |
| 上限までの余裕 | 大きい | 小さい |
| 関係ない話の混ざり | ほぼない | 増える |

<!-- ノート: 対比枠です。困るのは上限に当たることだけではありません。もう終わった作業の話が混ざり続けること自体が、返事の精度を下げます。 -->

---
