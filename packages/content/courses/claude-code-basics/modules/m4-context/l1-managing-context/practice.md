# レッスン4-1 演習 — 長くなった会話を切る

対象トピック: 4-1-1 〜 4-1-4

## 手元で試す

このレッスンで練習するのは、会話の長さを観察して、切り方を選ぶことです。

1. VS Code で Claude Code のパネルを開き、リポジトリの中の小さな修正を1つ頼みます(例: 表示の文言を1か所直す)
2. 依頼を出す前に `/context` を打ち、いまの使用量を見ておきます
3. 修正を進め、いくつかファイルを読ませたあとで、もう一度 `/context` を打ちます。1回目からどれだけ増えたかを見ます
4. まだ同じ修正の途中であれば `/compact` を使い、そのあとに「いま何を直しているか」を尋ねて、要点が残っているか確かめます
5. その修正を差分まで読んで区切ったら、`/clear` で会話を空にします。そのうえで、まったく別の修正を頼み、前の作業の話が出てこないことを確かめます

**Claude Code が使えない受講者は、この節を飛ばして構いません。** 下の演習問題と確認クイズはすべて紙の上で解けます。

## 演習問題

### 問1(基本)

会話を長く続けると余裕が減るのはなぜですか。**コンテキスト** と **コンテキスト上限** の2語を使って、2文で説明してください。

### 問2(基本)

このレッスンで扱った3つのスラッシュコマンドを、それぞれの役割と組にして書き出してください。役割を先に、名前を後に書いてください。

### 問3(応用)

午前中ずっと同じ修正を進めていて、まだ動作確認が終わっていません。返事が噛み合わなくなってきました。ここで取る行動を、順を追って2〜3文で書いてください。

### 問4(応用)

午前の修正をコミットまで終え、午後は別のファイルの修正に移ります。`/clear` を打つ前に済ませておくことを1つ挙げ、その理由も書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

会話は、それまでのやり取りがまるごとコンテキストとして読み直されます。読める量にはコンテキスト上限があるため、会話が長くなるほど上限までの余裕が減っていきます。

自分が打った文章だけでなく、読ませたファイル・実行したコマンドの結果・出てきた差分も積まれる点を添えられれば十分です。

</details>

<details>
<summary>問2の解答例</summary>

使用量を見る = `/context`、要約して残す = `/compact`、空にする = `/clear` の3つです。

名前は変わることがあります。役割で覚えておくと、名前が変わっても同じ判断ができます。

</details>

<details>
<summary>問3の解答例</summary>

まず `/context` を打ち、噛み合わない原因が会話の長さかどうかを切り分けます。余裕が減っているなら、同じ修正の続きなので `/compact` で要約して残し、経緯を持ったまま続けます。要約のあとに「いま何を直しているか」を尋ね、要点が残っているか確かめてから先に進めます。

作業の途中なので `/clear` は選びません。経緯が消えて、最初から説明し直しになります。

</details>

<details>
<summary>問4の解答例</summary>

その修正の差分を自分で読み、動作確認とコミットまで済ませておきます。空にすると会話の経緯は戻せないので、読んでいない差分が残ったままだと、何をどう変えたかを追う手がかりが消えるためです。

</details>

## 確認クイズ

### Q1. 会話を長く続けたときに起きることの説明として正しいものはどれですか。

- A. 会話の中身は毎回消えるので、長さは影響しない
- B. 会話はまるごと読み直されるため、コンテキスト上限に近づく
- C. 会話が長いほどコンテキスト上限が自動で広がる

<details>
<summary>答え</summary>

**B** — それまでのやり取りがまるごとコンテキストとして読み直されます。読ませたファイルやコマンドの結果も積まれるため、体感より速く上限に近づきます。

</details>

### Q2. いまコンテキストをどれだけ使っているかを確かめたいときに使うのはどれですか。

- A. 使用量を見る `/context`
- B. 要約して残す `/compact`
- C. 空にする `/clear`

<details>
<summary>答え</summary>

**A** — 長いかどうかは見た目で分かりません。勘で判断せず、使用量を見てから次の手を選びます。

</details>

### Q3. 同じ修正の続きをこれから進めますが、余裕が減ってきました。経緯は残したいです。ここで使うのは `/compact` と `/clear` のどちらですか。

- A. `/compact`
- B. `/clear`

<details>
<summary>答え</summary>

**A** — 同じ作業の続きなので、要約して要点を残します。空にすると経緯まで消え、最初から説明し直しになります。

</details>

### Q4. 午前の修正をコミットまで終え、まったく別のファイルの修正に移ります。ここで使うのは `/compact` と `/clear` のどちらですか。

- A. `/compact`
- B. `/clear`

<details>
<summary>答え</summary>

**B** — 作業が変わり、前の経緯を持ち越したくない場面です。要約して残すと、関係ない前提を引きずった返事の原因になります。

</details>

### Q5. `/compact` を使ったあとの会話について、正しいものはどれですか。

- A. ここまでが要約に置き換わり、続きに要る要点が残る
- B. 会話が空になり、前の作業のことは何も残らない
- C. コンテキスト上限そのものが大きくなる

<details>
<summary>答え</summary>

**A** — 捨てるのではなく詰める操作です。ただし要約なので細部は落ちます。残ってほしいものは自分で書き留めるか、伝え直します。

</details>
