# レッスン1-1 VS Codeで開いて頼む

## このレッスンの目標

- [ ] Claude CodeをVS Codeで使い始める形を説明できる
- [ ] どこを開けば作業の範囲が適切になるかを選べる
- [ ] 最初の依頼に成果物とできの基準を書ける

## 1-1-1 VS Codeの拡張として入れる

> **Claude Codeは、VS Codeに拡張機能として入れると、エディターの中から使い始められます**

コードを読み書きする画面を **エディター** と呼びます。**VS Code** は、その中で広く使われているものの1つです。多くの人は、直したいコードをすでにこの画面で開いています。

そこへ別の画面を持ち込むと、コードを貼り付けて、返ってきたものをまた貼り戻す、という往復が生まれます。この往復をなくす入れ方が、**拡張機能** です。拡張機能は、エディターに後から足せる機能のことです。Claude Codeを拡張機能として入れると、いま開いている画面の中から呼び出せるようになります。

```text
入れる場所  VS Code に拡張機能として入れる
入れたあと  エディターの中からClaude Codeを呼び出せる
画面の手順  名前も置き場所も変わる。製品のドキュメントで確かめる
```

3行目は、この講座を通じての方針です。導入の入り口の名前やメニューの位置は変わっていきます。覚えるのは「エディターに足して使う」という仕組みのほうで、画面の手順は、そのときの製品のドキュメントを見てください。

もう1つ知っておくとよいことがあります。同じClaude Codeは、**ターミナル** でも動きます。ターミナルは、文字でコマンドを打って使う画面です。

| | VS Codeの拡張機能 | ターミナル |
| --- | --- | --- |
| 中身 | 同じClaude Code | 同じClaude Code |
| 使う画面 | エディターの中 | 文字だけの画面 |
| この講座 | こちらで進めます | 紹介だけ |

別々のコーディングエージェントが2つあるわけではありません。同じ相手に入り口が2つある、という関係です。この講座はVS Codeの拡張機能のほうで進めるので、ターミナルでの起動のしかたや設定は扱いません。

## 1-1-2 開いたフォルダが作業の範囲

> **手元にクローンしたリポジトリをVS Codeで開くと、そのフォルダの中が作業の範囲になります**

入れたあと、最初に決まるのが「どこまでが相手の見る範囲か」です。手元のパソコンには仕事と関係のないファイルもあります。範囲が分からないままでは、安心して頼めません。

範囲を決めているのは、難しい設定ではありません。**VS Codeで何を開いたか** です。

- **リポジトリ** — プロジェクトのファイル一式です(Git入門研修で扱った語です)
- **クローン** — それを手元にまるごと複製することです(同じく Git入門研修の語です)
- **フォルダ** — ファイルをまとめる入れ物です
- **作業の範囲** — Claude Codeが読み書きの相手にする範囲です

クローンしたリポジトリのフォルダをVS Codeで開くと、その中が **作業の範囲** になります。

```text
手元        ~/work/shop-web       ← クローンしたリポジトリ
VS Codeで開く  shop-web フォルダ
作業の範囲    shop-web の中のファイルとフォルダ
範囲の外      同じパソコンの他のフォルダ
```

開いたフォルダの中と外に、線が1本引かれるだけです。だからこそ、どこを開くかで作業のしやすさが変わります。

| 開いたもの | 作業の範囲 | 起きること |
| --- | --- | --- |
| リポジトリの根っこ | プロジェクト全体 | 関係するファイルにたどり着ける |
| 深い階層のフォルダ1つ | その中だけ | 呼び出し元が見えず、話がかみ合わない |
| パソコンの家フォルダ | 広すぎる | 関係ないファイルまで範囲に入る |

既定は、リポジトリの根っこを開くことです。狭すぎると、直す対象は見えても、それを使っている側が見えません。広すぎると、関係のないものまで範囲に入ります。Gitそのものの話はここでは広げません。「作業の範囲は、クローンしたリポジトリ」とだけ言えれば十分です。

## 1-1-3 パネルで会話しながら進める

> **Claude Codeとのやり取りは、エディターの横のパネルで会話として続いていきます**

範囲が決まったら、次はどこで話しかけるかです。Claude Codeとのやり取りは、エディターの横に開く **パネル** で行います。パネルは、やり取りを表示するための領域です。コードを見ながら、その横で話しかけられる形になります。

パネルの中のやり取りは、一往復で切れません。**会話** として積み上がっていきます。

```text
自分   このリポジトリが何をするものか、3行で説明してください
相手   (説明が返る)
自分   そのうち、注文まわりを扱っているのはどのフォルダですか
相手   (最初の説明を踏まえて答える)
```

大事なのは、2回目に事情を書き直していない点です。頼みごとが一度で決まりきることは、まずありません。会話として続けられると、言い足しが一言で済みます。

| | 一問一答のつもり | 会話として続ける |
| --- | --- | --- |
| 2回目の書き方 | 事情を書き直す | 続きを一言足す |
| 話のかみ合い | 毎回ふりだし | 前を踏まえる |
| こちらの手間 | 増える | 減る |

パネルの位置や見た目の呼び名は変わっていきます。変わらないのは「やり取りが続きとして残る」という性質のほうです。

## 1-1-4 最初の依頼にも完了の形を書く

> **最初の依頼にも、何ができたら完了かという成果物とできの基準を書きます**

パネルが開いたら、1つ目に何を書くか。手元のコードが相手だと、つい「一覧ページが見にくいので、いい感じに直して」と書いてしまいがちです。これだと、返ってきたものが良いのか悪いのか、自分でも判断できません。

ここで使うのは、前の講座で通した型そのままです。

- **依頼** — 相手に渡す頼みごとの文です(講座2で扱った語です)
- **成果物** — 終わったときに手元に残るものです(講座2で扱った語です)
- **できの基準** — どこまでできていれば合格か、の線です(講座2で扱った語です)
- **4D** の「**伝える**」を、画面の上でそのままやるだけです(講座1で扱った語です)

新しい作法は増えていません。書く場所がパネルに変わっただけです。

```text
前: 一覧ページが見にくいので、いい感じに直して

後: 商品一覧の並び順を、追加日の新しい順に直してください。
    直す範囲は、この一覧を作っているファイルだけにしてください。
    完了は、一覧の先頭に最新の商品が来ていることです。
```

後の依頼は3つのことを書いています。1行目が成果物、2行目が作業の範囲のうちどこを触ってよいか、3行目ができの基準です。特定の言語の書き方は1つも入っていません。

| | 書いていない依頼 | 成果物と基準を書いた依頼 |
| --- | --- | --- |
| 返ってくるもの | 毎回変わる | 狙いに近い |
| 確かめ方 | なんとなく | 基準と見比べる |
| 任せられる幅 | 広げにくい | 広げられる |

基準を書くのは、相手を縛るためではありません。返ってきたものを自分で確かめられるようにするためです。最初の1本は、読ませるだけの依頼でも構いません。「このリポジトリの構成を、フォルダごとに1行で説明してください」も立派な依頼で、成果物は説明文、できの基準は「根っこのフォルダが全部並んでいること」です。

## もっと知りたい人へ

- 導入の入り口の名前、パネルの置き場所、メニューの並びは変わっていきます。実際に使うときは、そのときの製品のドキュメントで確かめてください
- クローン・リポジトリの扱いに不安があれば、Git入門研修に戻ると早いです
- 成果物とできの基準の書き分けは、Claudeチャット入門で扱っています。書き方が思い出せないときは、そちらの型がそのまま使えます
