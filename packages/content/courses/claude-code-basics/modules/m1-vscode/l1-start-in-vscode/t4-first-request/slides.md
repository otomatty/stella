# 1-1-4
# 最初の依頼にも完了の形を書く

Claude Code入門 — Module 1 / レッスン1-1

<!-- ノート: レッスンの締めです。前の講座で習った型を、パネルの上でそのまま使う回です。 -->

---

## なぜ必要か

- 手元のコードが相手だと、つい「いい感じに直して」と書いてしまう
- 返ってきたものが良いのか悪いのか、自分でも判断できない

<!-- ノート: つかみ。画面が変わると型が飛ぶ、という失敗を共有します。ここで結論は言いません。 -->

---

## 結論

**最初の依頼にも、何ができたら完了かという成果物とできの基準を書きます**

- **依頼** — 相手に渡す頼みごとの文です(講座2で扱った語です)
- **成果物** — 終わったときに手元に残るものです(講座2で扱った語です)
- **できの基準** — どこまでできていれば合格か、の線です(講座2で扱った語です)
- 要するに **4D** の「**伝える**」をパネルでやるだけです(講座1で扱った語です)

<!-- ノート: 結論を言い切ります。4語はすべて復習なので、1行ずつ読み上げて先へ進みます。新しい作法は増えていないと安心させます。 -->

---

## 最初の1本を書いてみる

```text
前: 一覧ページが見にくいので、いい感じに直して

後: 商品一覧の並び順を、追加日の新しい順に直してください。
    直す範囲は、この一覧を作っているファイルだけにしてください。
    完了は、一覧の先頭に最新の商品が来ていることです。
```

<!-- ノート: このトピックの主役です。2行目が成果物、3行目が範囲、4行目ができの基準です。特定の言語の書き方は入っていません。 -->

---

## 書く前と書いたあと

| | 書いていない依頼 | 成果物と基準を書いた依頼 |
| --- | --- | --- |
| 返ってくるもの | 毎回変わる | 狙いに近い |
| 確かめ方 | なんとなく | 基準と見比べる |
| 任せられる幅 | 広げにくい | 広げられる |

<!-- ノート: 対比の枠です。基準を書くのは相手を縛るためではなく、自分が確かめられるようにするためだと言い添えます。 -->
