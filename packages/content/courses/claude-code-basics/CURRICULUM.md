# Claude Code 入門 カリキュラム

Claude Code に「手元のコードを直させる」ときの進め方を扱う講座です。コーディングエージェントとは何かから、
VS Code での始め方・許可とモード・Explore → Plan → Code → Commit のワークフロー・コンテキスト管理・
1 タスクの完走までが範囲です。1 トピック = 覚えることが 1 つ(takeaway 1 文)の粒度で、
**エージェントを知る → 開いて頼む → 許可を決める → 1 タスクを順に通す → 会話の長さを管理する → 通しで完走する**
の順に進みます。Claude 研修シリーズの 4 本目にあたり、1 本目(AI駆動開発の考え方)の 4D と
2 本目(Claude チャット入門)の依頼の書き方を、**自分のリポジトリの上で**使う位置づけです。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- 手を動かす部分: `practice.md` の「手元で試す」。VS Code で Claude Code を開き、小さな修正を 1 本通します
- **Claude Code が使えない環境でも完走できます。** 「手元で試す」は任意で、スライド・まとめ・確認クイズだけで
  修了条件を満たします(Git 入門・Cowork 入門の「手元で試す」と同じ逃げ道)
- コード演習(VS Code 拡張の採点)は **この講座にはありません**。学習対象がエージェントとの進め方であって
  コードそのものではないため、`course.json` に `exercises` を持ちません
- 前提講座: **AI駆動開発の考え方(`ai-fluency-basics`)** と **Claude チャット入門(`claude-chat-basics`)**。
  4D と、依頼に成果物・できの基準を書く型を一度通していることを想定します。**Cowork 入門は前提にしません**
  (シリーズ 3 本目を飛ばした受講者もこの講座から入れます)。ただし語彙台帳は講座をまたがないため、
  必要な語はこの講座で導入し直します
- 前提知識: Git の clone / branch / commit / PR を一度は触ったことがあること。**この講座の中でも短く再導入します**
- 対象外:
  - `CLAUDE.md` ファイル・Skills・サブエージェント・hooks・MCP・GitHub の @claude Action などの
    **カスタマイズ全般**(後続講座の範囲。M5 の 5-1-3 で「次はそこ」と予告するだけ)
  - CLI(ターミナル)での運用・起動オプション・設定ファイルの書き方(M1 で「同じエージェントがターミナルでも
    動く」と紹介するだけ)
  - JetBrains などの他エディターでの利用
  - API・SDK・課金・管理者設定・チーム展開
  - モデルの選び方、価格、上限値などの当日値
  - 画面のボタン名・メニュー配置の暗記(製品画面は変わる前提)
  - Git そのものの入門(`git-basics` の範囲。この講座では 4 語を 1 行ずつ再導入するだけ)

## 到達目標

1. チャット型 AI とコーディングエージェントの違いを **説明できる**
2. VS Code で Claude Code を開き、最初の依頼を **出せる**
3. 毎回の承認 / 自動承認 / Planモードを状況に応じて **選べる**
4. Explore → Plan → Code → Commit の順で 1 タスクを **進められる**
5. 途中の差分を自分で **読める**
6. `/compact` `/clear` `/context` の使いどころを **選べる**

## この講座の進め方

- 各レッスンは **スライド → まとめ → 確認クイズ** の順で並びます
- `practice.md` の「手元で試す」は VS Code で Claude Code を開いて行います。拡張機能を入れてリポジトリを開く、
  最初の依頼に成果物とできの基準を書く、Plan モードで計画だけ出させる、差分を読んでからコミットする、
  `/compact` と `/clear` を使い分ける、といった課題で、自動採点はありません
- **Claude Code が使えない受講者は「手元で試す」を飛ばして構いません。** その場合もスライドと確認クイズだけで
  完走できます。クイズは操作の再現ではなく判断を問うため、画面を触っていなくても解けます
- 例題は特定の言語に寄せません。小さな Web ページの表示崩れ、API のレスポンス項目の追加、といった
  **どの言語でも成り立つ小さな修正**を題材にします
- 画面の並びやボタンの名前は変わります。困ったら製品のドキュメントを見る前提で、本文は
  「何のための仕組みか」だけを扱います
- スマートフォンからでも、スライドとまとめと確認クイズだけで最後まで進められます

## 設計メモ(申し送り)

- **レッスン数は M3 を 3 レッスンに割って 8 本にしました。** 要件段階の目安(M0 4 / M1 4 / M2 4 / M3 9 /
  M4 4 / M5 3 トピック)はそのまま守り、9 トピックの M3 だけを Explore(3) / Plan → Code(3) /
  Commit(3) の 3 レッスンに分けています。目安では M3 を 2 レッスンとしていましたが、**4 つの段の区切りが
  そのままレッスンの区切りになる**ほうが学習順として自然で、1 レッスン 3〜5 トピックの制約にも余裕をもって
  収まります。M2 を 6 トピック 2 レッスンに広げる案は取りませんでした(許可の話が 6 トピックぶんに薄まるため)
- **語彙台帳は講座をまたぎません。** `ai-fluency-basics` / `claude-chat-basics` で説明済みの語も、この講座で
  `introduces` し直しています。再導入した語は Claude / チャット / 任せる / 4D / 伝える / 依頼 / 成果物 /
  できの基準 / 責任を持つ / 見極める / コンテキスト / コンテキスト上限 の 12 語です。
  **再導入は 1 行の復習で済ませ、初出のような長い説明にしないでください。** スライドでは
  「講座2で扱った語です」(4D と 責任を持つ / 見極める は「講座1で扱った語です」)と一言添え、
  残りの時間を Claude Code の上での使い方に使います
- **Git の 4 語も再導入です。** クローン / リポジトリ(1-1-2)、ブランチ / コミット(3-3-3)、
  プルリクエスト(5-1-2)は `git-basics` の範囲ですが、この講座の中で **1 行ずつ**再導入します。
  Git の入門はしません。「作業の範囲はクローンしたリポジトリ」「区切りはブランチの上のコミット」
  「人に見せるのはプルリクエスト」の 3 点だけ言えれば十分です
- **`Code`(段の名前)と `コード`(直す対象)は別の語として台帳に登録しています。** 検査は文字列で見るため
  衝突しませんが、読み手が混ざります。スライドと `doc.md` では段の名前を必ず「Code の段」と書き、
  対象物は「コード」と書き分けてください。同じ理由で `Plan`(段)と `Planモード`(モード)、
  `Commit`(段)と `コミット`(Git の操作)も書き分けます
- **Planモードは M2 で導入し、M3 で使います。** M2-1-4 は「書かせないという選択肢がある」というモードの話、
  M3-2-1 は「出てきた計画を読んで直す」というワークフローの話です。M2 側で Explore → Plan → Code → Commit
  を先出ししないでください(M3-1-1 の takeaway が薄くなります)
- **M2-1-3「取り消せない操作は自動承認から外す」が、この講座の安全の締めです。** M2-1-2 で
  「止まらずに進める」を教えてから、M2-1-3 で「ただし戻せないものは別」で締めます。M2-1-2 側で
  取り消せない操作の話を先出ししないでください。**機密情報の扱いは前提講座 2 本で扱い済み**なので、
  この講座では繰り返しません(対象がリポジトリの中に限られるため、扱う判断も前提講座と同じです)
- **4 つの段の言い切りは「調べさせる → 計画を読む → 一段ずつ書かせる → 差分を読んで区切る」です。**
  M3 の 9 トピックはこの 1 周を順に割ったものなので、順序を入れ替えないでください。3-3-1
  「差分は自分で読む」が講座全体の締めの型で、M5 でもこの型に戻ります
- **到達目標 5(差分を読める)は 3-3-1 の 1 トピックに集約しています。** 差分の読み方そのもの
  (ハンクの見方、`+` / `-` の意味)は `git-basics` の範囲なので深入りせず、
  **「エージェントに書かせたものほど自分で読む」という構えだけ**を扱います
- **カスタマイズは 5-1-3 の予告だけです。** `CLAUDE.md` ファイル・Skills・サブエージェント・hooks・MCP・
  GitHub の @claude Action は後続講座の範囲で、この講座では **名前を 1 行並べるところまで**にしてください。
  設定手順・ファイルの書き方・画面は書きません。5-1-3 の takeaway は「仕組み化する番だ」という
  判断であって、仕組みの作り方ではありません
- **CLI は 1-1-1 の対比枠 1 枚だけです。** 「同じエージェントがターミナルでも動く」ことを紹介し、
  起動方法・オプション・設定ファイルは書きません。ハンズオンの既定は VS Code 上の Claude Code です。
  JetBrains などの他エディターは対象外なので、本文で選択肢として並べないでください
- **画面の名称に寄りかからないでください。** ボタン名・メニューの位置・パネルの配置は変わる前提です。
  takeaway は「何のためにその仕組みがあるか」に置き、**ボタン名だけが takeaway のトピックは作りません**。
  `パネル` / `自動承認` / `Planモード` は画面上の呼び名が変わりうる語ですが、takeaway 側(会話が続く・
  手を止めずに進む・書かせずに考えさせる)は変わりません。製品のスクリーンショットも貼りません
  (古くなりやすいため)。図解を足すなら「関係と流れ」(エージェントループ、4 つの段の 1 周、
  コンテキストが埋まっていく様子)を `.claude/skills/diagram-design/` の規約で自作してください
- **スラッシュコマンドは 3 つだけ扱います。** `/context` `/compact` `/clear` の使いどころだけが学習対象で、

- **1 年後も通用する範囲に絞りました。** モデル名・価格・コンテキスト上限の具体値・対応 OS・

- **例は特定言語に寄せません。** 小さな Web ページの表示修正、API のレスポンスに項目を 1 つ足す、

- **評価は確認クイズと手元ハンズオンだけです。** 到達目標 1〜6 はすべて判断を問うため、クイズは用語の暗記ではなく
  「この操作を自動承認に入れてよいか」「まだ Code に進んでよいか」「ここで使うのは `/compact` と `/clear` の
  どちらか」という選択問題にしてください。Claude Code が使えるかどうかで有利不利が出る設問

- **コード演習は配線しません。** 学習対象がエージェントとの進め方なので、`course.json` に `exercises` を持ちません
