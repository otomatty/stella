# Skills とサブエージェント カリキュラム

Claude Code を自分のプロジェクトに合わせて「仕組み化する」ときの置き場所の判断を扱う講座です。
毎回書いている指示を仕組みとして置くという出発点から、CLAUDE.md・Skill・サブエージェント・hook という
4 つの入れ物の地図、CLAUDE.md の書き方、Skill(`SKILL.md`)の書き方、サブエージェントに渡す判断、
そして同じ作業をどの入れ物に置くかの使い分けまでが範囲です。1 トピック = 覚えることが 1 つ(takeaway 1 文)の
粒度で、**仕組み化に気づく → 地図を持つ → 毎回効く約束を書く → タスクの手順書を知る → 手順書を書く →
別の文脈に渡す → 置き場所を判断する** の順に進みます。Claude 研修シリーズの 5 本目にあたり、
4 本目(Claude Code 入門)の締め「繰り返しが見えたら仕組み化する」の続きから始まる位置づけです。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- 手を動かす部分: `practice.md` の「手元で試す」。VS Code 上の Claude Code で、CLAUDE.md と
  `SKILL.md` という Markdown を実際に書きます
- **Claude Code が使えない環境でも完走できます。** 「手元で試す」は任意で、スライド・まとめ・確認クイズだけで
  修了条件を満たします(Claude Code 入門の「手元で試す」と同じ逃げ道)
- コード演習(VS Code 拡張の採点)は **この講座にはありません**。成果物が Markdown の文章であって
  コードではないため、`course.json` に `exercises` を持ちません
- 前提講座: **Claude Code 入門(`claude-code-basics`)**。エージェントに 1 タスクを通す流れと、
  「繰り返しが見えたら仕組み化する」という締めを一度通っていることを想定します。ただし語彙台帳は
  講座をまたがないため、必要な語はこの講座で導入し直します
- 対象外:
  - hooks の実装(書き方・イベントの種類・設定ファイル)。この講座では「必ず実行される入れ物がある」
    という地図と、使い分けの判断だけを扱い、本編は次講座に置きます
  - MCP サーバー、GitHub の @claude Action、CI への組み込みの本番手順
  - 実行スクリプト付きの Skill(検証の本編は次講座の範囲)
  - API・SDK・課金・管理者設定
  - モデルの選び方、価格、上限値などの当日値
  - 画面のボタン名・メニュー配置の暗記(製品画面は変わる前提)

## 到達目標

1. CLAUDE.md / Skill / サブエージェント / hook のどれに書くかを **選べる**
2. プロジェクトの CLAUDE.md を、毎回効く約束だけに絞って短く **書ける**
3. 繰り返す手順を Skill(`SKILL.md`)として **書ける**
4. 調査や検証をサブエージェントに渡す理由を **説明できる**
5. チームのリポジトリに載せる範囲と個人用の範囲を **分けられる**

`requires` の語はすべて、それより上の行の `introduces` に現れます(`check_vocab.mjs` が検査します)。

## この講座の進め方

- 各レッスンは **スライド → まとめ → 確認クイズ** の順で並びます
- `practice.md` の「手元で試す」は VS Code 上の Claude Code で行います。自分のリポジトリの CLAUDE.md を
  読み直して削る、繰り返している指示を 1 つ選んで `SKILL.md` に書く、調べものをサブエージェントに
  渡してみる、といった課題で、自動採点はありません
- **Claude Code が使えない受講者は「手元で試す」を飛ばして構いません。** その場合もスライドと確認クイズだけで
  完走できます。クイズは操作の再現ではなく判断を問うため、画面を触っていなくても解けます
- 例の Skill は特定の言語に寄せません。レビュー手順・コミットメッセージの型・リリース前の確認チェックリスト
  といった、**どの言語のプロジェクトでも成り立つ手順**を題材にします
- 画面の並びやボタンの名前は変わります。困ったら製品のドキュメントを見る前提で、本文は
  「何のための仕組みか」だけを扱います
- スマートフォンからでも、スライドとまとめと確認クイズだけで最後まで進められます

## 設計メモ(申し送り)

- **語彙台帳は講座をまたぎません。** `claude-code-basics` までで説明済みの語も、この講座で
  `introduces` し直しています。再導入した語は Claude / Claude Code / 繰り返し / ファイル / 会話 /
  リポジトリ / コンテキスト / タスク / 依頼 / 任せる の 10 語です(0-1-1 の「仕組み」は講座 4 の
  「仕組み化」を名詞に言い換えた語です)。**再導入は 1 行の復習で済ませ、初出のような長い説明に
  しないでください。** スライドでは「講座4で扱った語です」と一言添え、残りの時間をこの講座の
  主題(どこに置くか)に使います
- **0-1-1 は講座 4 の締めからの接続です。** `claude-code-basics` の 5-1-3「繰り返しが見えたら仕組み化する」を
  受けて、この講座は「では、どこに置くのか」から始まります。0-1-1 では仕組みの作り方に入らず、
  「書き忘れの ぶれ を仕組みが消す」という動機だけを言い切ってください
- **4 つの入れ物の言い切りは「毎回効く / タスクのとき / 別の文脈で / 必ず実行」です。** 0-1-3 のこの 4 句が
  講座全体の背骨で、M1(毎回)・M2〜M3(タスクのとき)・M4(別の文脈)・M5(判断)はすべてこの句に
  戻ります。スライド・doc・クイズでこの言い回しを崩さないでください
- **hook は地図と使い分けだけです。** 0-1-3 で「必ず実行される入れ物」として名前を出し、5-1-4 で
  「指示は破られうるが、hook は実行される」という判断を扱います。書き方・イベント名・設定ファイルの
  形式・実行スクリプト付き Skill・MCP は次講座の範囲なので、本文に書かないでください
- **CLAUDE.md の教えの中心は「書くことより削ること」です。** 1-1-3(毎回効く約束だけ)と 1-1-4(短く保つ)が
  この講座の CLAUDE.md 側の芯で、5-1-2(詰め込みが一番の失敗)で同じ型に戻ります。CLAUDE.md に
  手順書を全部書いて Skill を不要にする教え方はしません(1-1-5 で明示的に否定します)
- **Skill の 2 大要素は「description で選ばれる」「本文は使うときだけ読み込まれる(名前+description の一覧は会話に残る)」です。** 2-1-2 と 2-1-3 は
  この 2 点を 1 トピックずつに割ったものです。2-1-2 では「登録・有効化の操作」に踏み込まず、
  「依頼と説明文を照らして選ばれる」という仕組みだけを言い切ってください
- **SKILL.md の書式は frontmatter(name / description)+ 本文だけ扱います。** それ以外のメタデータや
  実行権限の指定は書きません。3-1-2 の例の frontmatter は `name` と `description` の 2 行に留めます
- **サブエージェントの言い切りは「別の会話で進めて、結果だけ返す」です。** 4-1-2 の「メインの文脈を
  汚さない」がこのモジュールの芯で、向き不向き(4-1-3 / 4-1-4)は「読む量と返す量の差」で判断させます。
  並列実行・モデルの指定・ツール制限などの詳細設定は書きません
- **チーム / 個人の線引きは 3-1-5 で導入し、5-1-3 で締めます。** 3-1-5 は「リポジトリに入れると共有になる」
  という置き場所の話、5-1-3 は「何をチームに載せ、何を個人に留めるか」という判断の話です。
  個人用の置き場所のパス(ホームディレクトリ配下)は doc.md の補足に留め、takeaway にしません
- **画面の名称に寄りかからないでください。** ボタン名・メニューの位置・コマンド名は変わる前提です。
  takeaway は「何のためにその入れ物があるか」に置き、製品のスクリーンショットは貼りません。
  図解を足すなら「関係と流れ」(4 つの入れ物と効くタイミング、Skill が選ばれて読み込まれる流れ、
  サブエージェントと結果の往復)を `.claude/skills/diagram-design/` の規約で自作してください
- **1 年後も通用する範囲に絞りました。** モデル名・価格・コンテキスト上限の具体値・ファイルの置き場所の
  当日仕様(パスの綴り)は本文の takeaway にしません。パスの例は doc.md に「執筆時点の例」として置き、
  実際の綴りは製品のドキュメントを見る前提です
- **評価は確認クイズと手元ハンズオンだけです。** 到達目標 1〜5 はすべて判断を問うため、クイズは用語の暗記では
  なく「この指示はどの入れ物に置くか」「この CLAUDE.md から削るのはどれか」「この仕事をサブエージェントに
  渡してよいか」という選択問題にしてください。特に **CLAUDE.md / Skill / サブエージェントの使い分けを問う
  設問を M2・M4・M5 に必ず置きます**。Claude Code が使えるかどうかで有利不利が出る設問は作りません
- **コード演習は配線しません。** 成果物が Markdown の文章なので、`course.json` に `exercises` を持ちません
- **サムネイルは生成済みです。** `packages/content/scripts/build_thumbnails.py` の `SPECS` に
  `claude-code-skills` を登録してあり、出力は `thumbnail.webp` です。モチーフは「1 枚の指示の紙を、
  4 つの入れ物のどれに置くかを選ぶ」で、この講座の中身(使い分けの判断)を 1 つだけ図にしています。
  文言やモチーフを変えたときは `python packages/content/scripts/build_thumbnails.py claude-code-skills` で
  再生成してください。手描きはしません。既存講座と 1 つのシリーズに見えることが前提なので、
  色や版面はスクリプトに任せ、外部ロゴは使いません
- **シリーズの続きは別 slug です。** hooks の実装・検証 Skill の本編・MCP は次講座に置きます。
  この講座を大きくしないことが、シリーズ 5 本目としての役割です
