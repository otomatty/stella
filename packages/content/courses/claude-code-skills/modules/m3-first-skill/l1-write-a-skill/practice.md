# レッスン3-1 演習 — SKILL.mdを書く

対象トピック: 3-1-1 〜 3-1-5

## 手元で試す

この講座の中心のハンズオンです。レッスン2-1の演習で決めた「最初に書くSkill」を、実際にMarkdownで書きます。VS Code が使えない場合は、メモ帳で同じ形の文章を書けば十分です。

1. 次のどちらかのSkill置き場にフォルダを作り、`SKILL.md` を1枚置く。プロジェクト用は `.claude/skills/<名前>/SKILL.md`、個人用は `~/.claude/skills/<名前>/SKILL.md` です(変わりうるので製品のドキュメントでも確認)。紙上で下書きだけなら場所は問いませんが、手順6でClaude Codeを試すなら上記のどちらかに置いてください
2. 先頭にfrontmatterを書く。`name` と、「〜を頼まれたときに使う。」で始まる `description` の2つ
3. 本文に手順を番号付きで書く。1行に1つ、対象と動作をはっきりと。まず5〜8手順を目安に
4. 書けたら「新しく入った同僚がこれだけ読んで同じ作業をできるか」で読み直し、「いい感じ」「丁寧に」を具体的な動作に割る
5. 手順の中に10行を超える一覧(観点表・規則集)があれば、参照ファイルに分けて、SKILL.mdには指し示す1行を残す
6. Claude Code が使えるなら、そのSkillが合うタスクを依頼して、手順どおりに進むかを見る

うまく選ばれない場合は、まずdescriptionを疑ってください(2-1のクイズQ3と同じ判断です)。

## 演習問題

### 問1(基本)

SKILL.mdの構成を、「frontmatter」「本文」の2語を使って1〜2文で説明してください。

### 問2(基本)

次のdescriptionの弱点を指摘し、書き直してください。

```text
description: コミットメッセージについてのメモ
```

### 問3(応用)

「リリース前チェック」のSkillの本文に、観点の詳細一覧(約60行)を直接書くべきかを判断し、理由と代わりの構成を2〜3文で書いてください。

### 問4(応用)

書き上げたSkillを「まず個人用に置き、育ったらリポジトリへ」という進め方の利点を、1〜2文で説明してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

SKILL.mdは、先頭に `---` で挟んだfrontmatter(nameと、いつ使うかが分かるdescription)を書き、その下の本文に手順を順番に書く構成です。

</details>

<details>
<summary>問2の解答例</summary>

いつ使うかが書かれていないので、依頼と照らせず選ばれにくいのが弱点です。書き直しの例:「コミットメッセージを書くときに使う。1行目の形式と本文に書くことをまとめた手順書。」

</details>

<details>
<summary>問3の解答例</summary>

直接は書きません。60行の一覧を本文に入れると、Skillを使うたびに全部が読み込まれます。一覧は参照ファイル(例: checklist.md)に分け、SKILL.mdには「確認項目の詳細は checklist.md を見る」と指し示す1行を残します。

</details>

<details>
<summary>問4の解答例</summary>

実験中の手順書をチーム全員に配らずに済み、自分の会話で効き目を確かめてから共有できます。効くと分かったものだけをリポジトリに入れれば、チームの棚が散らかりません。

</details>

## 確認クイズ

### Q1. Skillを1つ作るとき、最低限用意するものはどれですか。

- A. フォルダと、その中のSKILL.md(frontmatter+本文)
- B. 専用のプログラムと設定画面での登録
- C. CLAUDE.mdへの追記

<details>
<summary>答え</summary>

**A** — Skillの正体はフォルダに置いたMarkdownのファイルです。プログラムを書く必要も、CLAUDE.mdに書く必要もありません。

</details>

### Q2. frontmatterのdescriptionに必ず入れるべき内容はどれですか。

- A. 作った人の名前と日付
- B. いつ使うかと、何の手順書か
- C. 手順の全文

<details>
<summary>答え</summary>

**B** — descriptionは依頼と照らされる背表紙です。「〜を頼まれたときに使う。」で始めると、照らせる文になります。手順の全文は本文に書きます。

</details>

### Q3. 本文の手順に「テストをいい感じに確認する」と書いてありました。適切な直し方はどれですか。

- A. 「しっかり確認する」に言い換える
- B. 「テストを実行し、失敗した項目を一覧にする」のように具体的な動作に割る
- C. その行を太字にする

<details>
<summary>答え</summary>

**B** — 基準は「新しく入った同僚がこれだけ読んで同じ作業をできるか」です。「いい感じ」「丁寧に」は、対象と動作をはっきり書いた文に割ります。

</details>

### Q4. SKILL.mdの中の観点一覧が80行に育ちました。適切な整理はどれですか。

- A. そのまま本文に置き続ける
- B. CLAUDE.mdへ移す
- C. 参照ファイルに分けて、SKILL.mdから指し示す

<details>
<summary>答え</summary>

**C** — 長い資料は参照ファイルに分ければ、要るときだけ読まれます。CLAUDE.mdへ移すと、今度は毎回読み込まれてしまいます(M1の禁じ手です)。

</details>

### Q5. チームの全員に同じレビュー手順を使ってほしいとき、Skillの置き場所はどれが適切ですか。

- A. 各自が自分の個人用の置き場に、それぞれ書く
- B. リポジトリの中のSkill置き場に入れて共有する
- C. チャットで手順書を毎回貼る

<details>
<summary>答え</summary>

**B** — リポジトリに入れれば、クローンした全員に同じ手順書が届きます。直すときもプルリクエストで1か所を直せば揃います。

</details>
