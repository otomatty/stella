# 3-1-4
# 長い資料は参照ファイルへ

Skillsとサブエージェント — Module 3 / レッスン3-1

<!-- ノート: 手順書が育ってきたときの整理の仕方です。Skillの中でも「要るときだけ読む」を効かせます。 -->

---

## なぜ必要か

- 手順に観点表や用語集を足していくと、SKILL.mdが何百行にも育つ
- 毎回のレビューで使うのは、そのうちの一部だけ

<!-- ノート: CLAUDE.mdで見た「詰め込みすぎ」は、SKILL.mdの中でも起きます。結論はまだ言いません。 -->

---

## 結論

**長い資料は参照ファイルに分けてSKILL.mdから指し示すと、要るぶんだけ読まれます**

- **参照ファイル** — SKILL.mdと同じフォルダに置く、補助資料の別ファイル
- SKILL.md側には「どんなときにどれを見るか」の1行を書きます

<!-- ノート: 手順書の本冊と、付録の分冊です。分冊の読み込みは、その付録が要るときだけ起きます。 -->

---

## 最小の例

```text
review-pr/
├── SKILL.md            手順(短い)
│     「命名の判断に迷ったら naming.md を見る」
├── naming.md           命名規則の一覧(長い)
└── checklist.md        観点の詳細一覧(長い)
```

<!-- ノート: SKILL.mdは短い手順に保ち、長い一覧は分冊へ。指し示しの1行があるので、迷ったときだけ分冊が開かれます。 -->

---

## 1枚に全部・分冊に分ける

| | 1枚に全部書く | 参照ファイルに分ける |
| --- | --- | --- |
| Skillを使うときの読み込み | 全部 | 手順+要る分冊だけ |
| 資料の育てやすさ | 育つほど重くなる | 分冊だけ育てられる |

<!-- ノート: 対比枠です。「要るときだけ読む」というSkillの利点を、Skillの中でも入れ子で効かせる考え方です。 -->

---
