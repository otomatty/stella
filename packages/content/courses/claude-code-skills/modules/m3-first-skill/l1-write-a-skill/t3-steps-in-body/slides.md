# 3-1-3
# 本文は手順を順番に書く

Skillsとサブエージェント — Module 3 / レッスン3-1

<!-- ノート: frontmatterの下、手順書の中身の書き方です。 -->

---

## なぜ必要か

- 手順が頭の中にあるうちは書けるのに、いざ書くと「いい感じにやって」になりがち
- 曖昧な手順書は、読んだ相手の解釈次第で結果がぶれる

<!-- ノート: 書き方の心構えが1つあれば、この問題は避けられます。結論はまだ言いません。 -->

---

## 結論

**SKILL.mdの本文には、人に引き継ぐつもりで手順を1つずつ順番に書きます**

- **本文** — frontmatterの下に続く、手順書の中身
- 目安は「新しく入った同僚が、これだけ読んで同じ作業をできるか」

<!-- ノート: 読み手はClaudeですが、書く基準は人への引き継ぎと同じです。人が読んで曖昧な手順は、Claudeが読んでも曖昧です。 -->

---

## 最小の例

```text
## レビューの手順

1. 変更の目的を、プルリクエストの説明から1文で把握する
2. 差分を読み、動きが変わる箇所を先に確認する
3. 細かい書き方の指摘は、動きの確認が終わってから
4. 指摘には、理由と直し方の例を必ず添える
```

<!-- ノート: 番号付きで、1行に1つの手順。動詞で終わる短い文にします。Markdownの見出しと箇条書きだけで書けます。 -->

---

## 引き継げる・引き継げない

| 書き方 | 判定 |
| --- | --- |
| 「差分を読み、動きが変わる箇所を先に確認する」 | 順番と対象が明確 |
| 「差分をいい感じに確認する」 | 解釈が読み手任せ |
| 「レビューは丁寧にやる」 | 手順になっていない |

<!-- ノート: 失敗例枠です。「いい感じ」「丁寧に」が出てきたら、具体的な動作に割る合図です。 -->
