## なぜ必要か

- CLAUDE.mdに太字で書いても、指示は読み落とされることがゼロにならない
- 「たまに破られる」では困る決まりが、プロジェクトにはいくつかある

<!-- ノート: 指示という道具の限界の話です。結論はまだ言いません。 -->

---

## 結論

**破られると困る決まりは、指示ではなく必ず実行されるhookにする道があります**

- **決まり** — 例外なく守られてほしいルール。「コミット前に必ず整形する」など
- 指示は読んで従うもの、hookは決めた操作を機械的に実行するものです

<!-- ノート: M0の地図の「必ず実行」を、使いどころの判断として仕上げます。 -->

---

## 最小の例

```text
指示で書く   「コミット前に整形コマンドを実行してね」
            → ほぼ守られる。でも、たまに抜ける

hookにする   コミット前に整形コマンドが自動で実行される
            → 抜けようがない
```

<!-- ノート: 「ほぼ守られる」で足りるものは指示のままでよいのです。抜けた1回が事故になるものだけ、hookの出番です。 -->

---

## 指示のまま・hookにする

| --- | --- |
| 文体・観点など、ずれても直せるもの | CLAUDE.md / Skill |
| 整形・検査など、抜けた1回が困るもの | hook |
