# レッスン5-1 演習 — どの入れ物に置くか

対象トピック: 5-1-1 〜 5-1-4

## 手元で試す

講座の総仕上げです。VS Code でチームのリポジトリ(または練習用リポジトリ)を開いて進めます。使えない場合は、1と2を紙の上でやるだけでも判断の練習として成立します。

1. これまでの演習で書き出した指示・手順・調べものを全部並べ、1行ずつ「いつ効いてほしいか」で4つの入れ物に振り分ける
2. チームのCLAUDE.mdがあれば読み直し、「毎回の約束」と「手順書」に線を引く。手順書側があればSkillへの引っ越し案を作る
3. Claude Code が使えるなら、引っ越し案を1つ実行する。手順書をSkillにし、CLAUDE.mdから該当行を削る
4. 振り分けた一覧に、もう1本の軸「チームで揃えるか、自分の好みか」の印を付ける
5. 「たまに破られると困る決まり」が自分のプロジェクトにあるか、1つ挙げてメモしておく(次の講座のhooksで使う材料になります)

## 演習問題

### 問1(基本)

置き場所を決める最初の1問と、その4つの答え(入れ物との対応)を書いてください。

### 問2(基本)

「詰め込み」とは何かを説明し、その処方を「移す」という語を使って1〜2文で書いてください。

### 問3(応用)

次の4つを、CLAUDE.md / Skill / サブエージェント / 個人用 のどれに置くか振り分け、1つずつ理由を1文で書いてください。

```text
1. ビルドとテストのコマンド
2. 週次レポートのまとめ手順
3. 「回答はまず結論から書いて」という自分の好みの口調
4. 「このAPIの呼び出し箇所を全部調べる」という仕事
```

### 問4(応用)

「コミット前の整形は、CLAUDE.mdに太字で書けば十分だ」という意見に対して、指示とhookの違いを踏まえた反論を2〜3文で書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

「この指示はいつ効いてほしいか?」です。毎回効くならCLAUDE.md、タスクのときならSkill、別の文脈で進めたい調べものならサブエージェント、必ず実行したいものならhookです。

</details>

<details>
<summary>問2の解答例</summary>

詰め込みは、効くタイミングの違うものを1つの入れ物に全部書くことです。代表例はCLAUDE.mdへの手順書の詰め込みで、処方は消すことではなく、手順書をSkillへ移して毎回の約束だけを残すことです。

</details>

<details>
<summary>問3の解答例</summary>

1はCLAUDE.md(どの作業でも毎回使う)。2はSkill(週次レポートというタスクのときだけ効く手順書)。3は個人用(チームで揃える必要のない好み)。4はサブエージェント(読む量が多く、結果を一覧で短く返せる調査)。

</details>

<details>
<summary>問4の解答例</summary>

CLAUDE.mdの指示は読んで従うものなので、太字にしても読み落としがゼロにはなりません。整形のように抜けた1回が困る決まりは、決めた操作を機械的に実行するhookにすれば、抜けようがなくなります。

</details>

## 確認クイズ

### Q1. 「リリース前チェックの手順」の置き場所を決めるとき、最初に立てる問いはどれですか。

- A. この手順は何行あるか
- B. この手順はいつ効いてほしいか
- C. この手順は誰が書いたか

<details>
<summary>答え</summary>

**B** — 効くタイミングが最初の1問です。リリースのときだけ効けばよいので、答えはSkillに落ちます。

</details>

### Q2. CLAUDE.mdが120行あり、リリース手順・障害調査手順・レビュー観点が同居しています。適切な処方はどれですか。

- A. 全部残したまま、大事な行を太字にする
- B. 手順書をそれぞれSkillへ移し、CLAUDE.mdには毎回の約束だけを残す
- C. CLAUDE.mdを2枚に分ける

<details>
<summary>答え</summary>

**B** — 詰め込みの処方は移すことです。手順書はSkillでこそ要るときだけ効き、CLAUDE.mdの約束は短くなって効きが戻ります。

</details>

### Q3. 「説明は箇条書きでまとめてほしい」という自分の好みの指示の置き場所として適切なのはどれですか。

- A. チームのリポジトリのCLAUDE.md
- B. 自分の個人用の置き場
- C. チームのSkill置き場

<details>
<summary>答え</summary>

**B** — 他の人が違うやり方でも困らない好みは、個人用に置きます。リポジトリに入れると、自分の癖を全員に押しつけることになります。

</details>

### Q4. 「毎回効かせたい約束はどれか」という観点で、CLAUDE.mdに残すべきものはどれですか。

- A. テストの走らせ方のコマンド
- B. 障害調査のときのログの読み方
- C. 週次レポートの見出しの順番

<details>
<summary>答え</summary>

**A** — どの作業でも毎回使うものだけがCLAUDE.mdに残ります。BとCは特定のタスクのときだけ効かせたい手順書なので、Skillへ置きます。

</details>

### Q5. 「機密のフォルダには絶対に触れない」を例外なく守らせたいとき、最も確実な入れ物はどれですか。

- A. CLAUDE.mdに太字で書く
- B. Skillの手順に書く
- C. 必ず実行されるhookにする

<details>
<summary>答え</summary>

**C** — 指示は読んで従うものなので、読み落としがゼロになりません。破られると困る決まりは、機械的に実行されるhookにする道があります。作り方は次の講座で扱います。

</details>
