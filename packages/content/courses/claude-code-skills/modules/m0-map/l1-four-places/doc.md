# レッスン0-1 4つの入れ物

## このレッスンの目標

- [ ] 指示を仕組みとして置く利点を説明できる
- [ ] 4つの入れ物の名前を挙げられる
- [ ] 効くタイミングという見分け方を使える

## 0-1-1 繰り返す指示は仕組みにする

> **Claude Codeへ毎回書いている同じ指示は、仕組みとして置くと書き忘れなく効きます**

前の講座で、**Claude Code**(手元のコードを読んで直すところまで進めるコーディングエージェント。講座4で扱った語です)に1つの修正を通せるようになりました。何本か通すと、依頼のたびに同じ前置きを書いている自分に気づきます。「テストはこのコマンドで走らせて」「コメントは日本語で」「直したら必ずこの手順で確かめて」。

**Claude**(講座1から使ってきた相手)にやり方を伝えるこうした文を、この講座では **指示** と呼びます。そして、依頼のたびに書いている同じ内容の指示が **繰り返し** です。

繰り返しの何が問題なのでしょうか。手間もありますが、本当の問題は別にあります。

```text
月曜  「テストは bun run test で」と書いた   → テストが走った
水曜  書き忘れた                            → テストが走らないまま完了
金曜  「あれ、水曜の変更だけ確認が抜けてる」
```

書いた回はうまくいき、忘れた回だけ結果がぶれる。しかも、どの回で忘れたかは後から思い出せません。

この抜けを消すのが **仕組み** です。同じ指示を先に置いておき、書かなくても効くようにする。置き場所を1か所にすれば、直したいときも1か所を直すだけで済みます。

| | 毎回書く | 仕組みに置く |
| --- | --- | --- |
| 手間 | 依頼のたびに同じ文 | 一度置けば効き続ける |
| ぶれ | 書き忘れた回だけ抜ける | 抜けにくい |
| 直すとき | 全員が自分の書き方を直す | 置いた1か所を直す |

この講座で学ぶのは、指示の内容ではなく **指示の置き場所** です。

## 0-1-2 入れ物は4つある

> **仕組みの入れ物には、CLAUDE.md・Skill・サブエージェント・hookの4つがあります**

仕組みに置くと決めたら、次は「どこに」です。指示を仕組みとして置く場所を、この講座では **入れ物** と呼びます。入れ物は4つあります。

```text
CLAUDE.md      プロジェクトの約束を書いたファイル
Skill          特定の作業のやり方をまとめた手順書
サブエージェント  仕事を切り出して渡す別の相手
hook           決めた操作を必ず実行する仕掛け
```

- **CLAUDE.md** — プロジェクトに置いておく、約束ごとを書いたファイルです。Module 1 で書けるようになります
- **Skill** — 特定の作業のやり方をまとめた手順書です。Module 2 で仕組みを知り、Module 3 で書けるようになります
- **サブエージェント** — 調べものなどの仕事を切り出して渡す、別の相手です。Module 4 で「渡す判断」ができるようになります
- **hook** — 決めた操作を必ず実行する仕掛けです。この講座では名前と使いどころだけを扱い、作り方は次の講座に譲ります

| 入れ物 | この講座で到達するところ |
| --- | --- |
| CLAUDE.md | 書ける(M1) |
| Skill | 書ける(M2〜M3) |
| サブエージェント | 渡す判断ができる(M4) |
| hook | 名前と使いどころだけ(M5) |

4つも覚えられるだろうか、と思うかもしれません。大丈夫です。次のトピックで、4つを1つの軸で見分けられるようにします。

## 0-1-3 効くタイミングで見分ける

> **4つの入れ物は、毎回・タスクのとき・別の文脈で・必ず実行という効くタイミングで見分けます**

名前を4つ覚えても、置きたい指示を前にすると迷います。「これはCLAUDE.mdだろうか、Skillだろうか」。機能の一覧で覚えると、製品の画面や名称が変わったときに迷子になります。

そこで、変わりにくい軸を1本だけ持ちます。**効くタイミング**、つまりその指示がいつ働いてほしいか、です。

```text
毎回効く       CLAUDE.md        どの依頼でも読まれる
タスクのとき    Skill            合う作業のときだけ読まれる
別の文脈で     サブエージェント    切り出した仕事を別で進める
必ず実行       hook             指示ではなくコードとして動く
```

ここで **文脈** という語を導入しておきます。Claudeが作業中に読んでいる、会話や資料のひとまとまりのことです。CLAUDE.mdとSkillは「いまの文脈にいつ読み込まれるか」の違いで、サブエージェントは「そもそも別の文脈で進める」という違いです。

hookだけは毛色が違います。上の3つはどれも「Claudeが読む指示」ですが、hookは読ませるのではなく、決めた操作を機械的に実行します。指示は読み落とされることがありえますが、hookは必ず動きます。だから「必ず実行」です。

同じ1文でも、いつ効いてほしいかで置き場所が変わります。

| 指示の例 | 効いてほしいとき | 入れ物 |
| --- | --- | --- |
| 「コメントは日本語で」 | 毎回 | CLAUDE.md |
| 「リリース前はこの手順で確認」 | その作業のとき | Skill |
| 「このライブラリの使用箇所を調べて」 | 調べる間だけ | サブエージェント |

この「いつ効いてほしいか」という問いが、講座全体の背骨です。以降のモジュールはすべて、この4句に戻ってきます。

## もっと知りたい人へ

- 自分の直近の依頼を3つ思い出して、毎回書いていた前置きがなかったか振り返ってみてください。M1以降の「手元で試す」でそのまま材料になります
- 4つの入れ物の正確な仕様や置き場所のパスは製品側で変わっていきます。実際に使うときは、製品のドキュメントで確認してください
