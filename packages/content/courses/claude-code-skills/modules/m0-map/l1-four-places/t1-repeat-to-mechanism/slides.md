## なぜ必要か

- 依頼のたびに「テストはこのコマンドで」「この書き方に合わせて」と前置きしている
- 書いた回はうまくいくのに、書き忘れた回だけ結果がぶれる

<!-- ノート: つかみです。Claude Code(講座4で扱った語です)を使い込むほど、この前置きが増えていきます。問題は手間ではなく、忘れた回のぶれです。結論はまだ言いません。 -->

---

## 結論

**Claude Codeへ毎回書いている同じ指示は、仕組みとして置くと書き忘れなく効きます**

- **指示** — Claudeにやり方を伝える文。依頼の中に毎回書いてきたもの
- **繰り返し** — 依頼のたびに書いている、同じ内容の指示
- **仕組み** — その指示を先に置いておき、書かなくても効くようにしたもの

<!-- ノート: Claude と Claude Code は講座4までで扱った語です。この講座で学ぶのは指示の内容ではなく、指示の置き場所です。 -->

---

## 最小の例

```text
毎回書く   「テストは bun run test で走らせて」
           → 書いた回だけ効く。忘れた回は効かない

仕組みに置く 同じ1文をプロジェクトに置いておく
           → どの依頼でも効く。忘れようがない
```

<!-- ノート: 同じ1文でも、置き場所が変わると効き方が変わります。紙に書いた約束と、口頭で毎回言う約束の違いです。 -->

---

## 毎回書く・仕組みに置く

| | 毎回書く | 仕組みに置く |
| --- | --- | --- |
| 手間 | 依頼のたびに同じ文 | 一度置けば効き続ける |
| ぶれ | 書き忘れた回だけ抜ける | 抜けにくい |
| 直すとき | 全員が自分の書き方を直す | 置いた1か所を直す |

<!-- ノート: 対比枠です。3行目が仕組みの本当の強みで、直すのが1か所で済みます。ではどこに置くのか。それが次からの話です、と口頭で引きます。 -->
