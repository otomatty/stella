# 向くのは調査と検証

Skillsとサブエージェント — Module 4 / レッスン4-1

## なぜ必要か

- 「別の会話に切り出せる」と知っても、何を切り出すべきかは別の問題
- なんでも渡すと、かえって結果待ちと説明のやり直しが増える

<!-- ノート: 判断の目安が要ります。結論はまだ言いません。 -->

---

## 結論

**サブエージェントに向くのは、読む量が多くて結果を短く言える調査や検証の仕事です**

- **調査** — 現状を調べて報告する仕事。「どこで使われているか」「どう動いているか」
- **検証** — 決めた観点で確かめて合否を報告する仕事。「規約に沿っているか」

<!-- ノート: 共通点は「入りは大きく、出は小さい」。読むのは30ファイル、報告は5行、という形です。 -->

---

## 最小の例

```text
調査  「この関数の使われ方を全部調べて、一覧にして」
      読む: 大量 / 返す: 一覧の数行

検証  「この差分が命名規約に沿っているか確かめて」
      読む: 差分+規約 / 返す: 合否と指摘の数行
```

<!-- ノート: どちらも、メインでやればコンテキストを大きく食う仕事です。結果が短く言えるから、報告だけ受け取る形が成立します。 -->

---

## 見分けの式

| 問い | 向いている答え |
| --- | --- |
| 読む量は多いか | 多い |
| 結果は短く言えるか | 数行で言える |
| 進め方を途中で相談したいか | しなくてよい |
