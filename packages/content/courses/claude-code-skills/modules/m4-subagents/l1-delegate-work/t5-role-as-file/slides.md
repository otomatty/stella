# 4-1-5
# 役割はファイルで定義できる

Skillsとサブエージェント — Module 4 / レッスン4-1

<!-- ノート: M4の締めです。サブエージェントも、ここまでの入れ物と同じ「ファイルに書いて置く」に合流します。 -->

---

## なぜ必要か

- 「規約の検証役」を頼むたびに、観点と報告の形を毎回説明している
- 毎回説明するなら、それはもう繰り返しの指示に戻っている

<!-- ノート: 0-1-1と同じ症状が、任せ方にも出てきます。答えも同じです。結論はまだ言いません。 -->

---

## 結論

**よく任せる役割は、frontmatterにnameとdescriptionを書き、本文に指示を置いたファイルとして定義できます**

- **役割** — 決まった観点で働く係。「検証役」「調査役」のような肩書き
- 定義しておけば、毎回説明しなくても同じ係を呼び出せます

<!-- ノート: Skillと同じ発想です。frontmatterにnameとdescription、本文に係への指示を書きます。指示: キーは使いません。 -->

---

## 最小の例

```text
 .claude/agents/naming-checker.md
 (個人用は ~/.claude/agents/ 配下)

 ---
 name: naming-checker
 description: 差分の命名を規約と照らして確かめたいときに使う
 ---

 規約の一覧と照らし、違反と直し方だけを短く報告する。
```

<!-- ノート: この形をそのままコピーして保存すれば動きます。frontmatterにname/description、指示は本文に書きます。指示: キーは使いません。 -->

---

## 毎回説明する・定義して置く

| | 毎回説明する | ファイルで定義する |
| --- | --- | --- |
| 手間 | 呼ぶたびに観点を書く | 一度書けば呼ぶだけ |
| ぶれ | 説明の抜けで変わる | 揃う |
| 共有 | できない | リポジトリでチームに配れる |

<!-- ノート: リポジトリに入れて配れるのもSkillと同じです。これで4つの入れ物のうち3つが、ファイルとして手元に揃いました。 -->
