# 4-1-4
# 向かないのは対話が要る仕事

Skillsとサブエージェント — Module 4 / レッスン4-1

<!-- ノート: 向き不向きの裏面です。便利さを知った直後に、境界線を引いておきます。 -->

---

## なぜ必要か

- 切り出しが便利だと、本題の設計や修正まで渡したくなる
- 渡してみると、途中で口を挟めないことが急に不便になる

<!-- ノート: 利点の裏返しがそのまま欠点になる、という話です。結論はまだ言いません。 -->

---

## 結論

**途中で相談しながら進めたい仕事は、サブエージェントに渡さずメインの会話で進めます**

- **相談** — 進め方の選択肢を見て、その場で決めるやり取り
- 別の会話で進むとは、途中が見えず口も挟みにくいということです

<!-- ノート: 講座4で「ずれたら途中で止めて直す」を学びました。その舵取りをしたい仕事は、手元に置くべきです。 -->

---

## 最小の例

```text
向かない  「この機能の設計を決めて実装まで進めて」
         → 分かれ道で相談したいのに、途中では口をはさめない

向く     「実装の前に、似た機能の作りを調べて一覧にして」
         → 分かれ道がなく、報告を待つだけでよい
```

<!-- ノート: 同じ本題の中でも、相談が要る部分と要らない部分に割れます。割ってから、要らない側だけを渡します。 -->

---

## 渡す前の3問(再掲+1)

| 問い | 渡してよい答え |
| --- | --- |
| 結果は短く言えるか | 言える |
| 途中の分かれ道はあるか | ない |
| 失敗してもやり直せるか | 調べ直せばよいだけ |

<!-- ノート: 対話が要る仕事は、分かれ道のたびに見極めが要る仕事です。それはメインで、自分の目の届くところで進めます。 -->
