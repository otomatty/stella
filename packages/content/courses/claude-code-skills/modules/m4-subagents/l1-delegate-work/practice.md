# レッスン4-1 演習 — 別の文脈に渡す

対象トピック: 4-1-1 〜 4-1-5

## 手元で試す

VS Code 上の Claude Code で進めます。使えない場合は、1と2を紙の上で分類するだけでも判断の練習になります。

1. 自分の直近の仕事から「調べもの」を3つ書き出す(例: この設定はどこで読まれているか、この関数の使われ方、規約違反がないか)
2. それぞれに、渡す前の3問(結果は短く言えるか / 途中の分かれ道はあるか / 失敗してもやり直せるか)で印を付ける
3. Claude Code が使えるなら、印が全部そろった1つを選び、「◯◯の調査はサブエージェントに任せて、結果だけを一覧で報告して」と依頼する。任せ先を明示しないと、メインの会話で調べて文脈が積もることがあります
4. 報告が返ってきたら、メインの会話に調べ回った途中経過が積もっていないことを確かめる
5. よく頼みそうな役割(検証役・調査役)を1つ選び、frontmatterのname/descriptionと本文の指示をメモ帳に下書きする

## 演習問題

### 問1(基本)

サブエージェントがメインの会話に返すものを、「結果」「途中経過」の2語を使って1文で書いてください。

### 問2(基本)

「メインの文脈を汚さない」とはどういうことかを、「コンテキスト」という語を使って1〜2文で説明してください。

### 問3(応用)

次の3つの仕事のうち、サブエージェントに渡してよいものを1つ選び、残り2つを渡さない理由をそれぞれ1文で書いてください。

```text
1. 新機能の画面設計を決めながら実装する
2. このライブラリの使用箇所を全部調べて一覧にする
3. 障害の原因を、私と相談しながら切り分けていく
```

### 問4(応用)

「検証役」を毎回口頭で説明して呼んでいる状態の問題点と、その解決策を、この講座の言葉で2〜3文で書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

サブエージェントは途中経過を返さず、任せた仕事のまとめである結果だけをメインの会話に返します。

</details>

<details>
<summary>問2の解答例</summary>

調べもので読んだ大量の中身がサブエージェント側の会話に残り、メインの会話のコンテキストには結果の数行しか入らない、ということです。メインは本題のための余裕を保てます。

</details>

<details>
<summary>問3の解答例</summary>

渡してよいのは2です。読む量が多く、結果を一覧の数行で言えて、分かれ道もありません。1は設計の分かれ道で相談が要るので向きません。3は相談しながら進めること自体が仕事なので、メインの会話で進めます。

</details>

<details>
<summary>問4の解答例</summary>

毎回説明するのは繰り返しの指示に戻っており、説明の抜けで検証の観点がぶれます。frontmatterにnameとdescription、本文に指示を書いた定義ファイルを `.claude/agents/` または `~/.claude/agents/` に置けば、呼ぶだけで同じ係になり、リポジトリでチームにも配れます。

</details>

## 確認クイズ

### Q1. サブエージェントに調べものを任せたとき、メインの会話に戻ってくるものはどれですか。

- A. 読んだファイルの中身すべて
- B. まとめの報告である結果だけ
- C. 何も戻ってこない

<details>
<summary>答え</summary>

**B** — 調べた中身はサブエージェント側の会話に残り、メインには結果だけが戻ります。これが「文脈を汚さない」の意味です。

</details>

### Q2. 30ファイルを読む調査をサブエージェントに渡す一番の利点はどれですか。

- A. メインの会話のコンテキストがほぼ減らない
- B. 調査が必ず一瞬で終わる
- C. 結果が必ず正しくなる

<details>
<summary>答え</summary>

**A** — 読む費用を別の会話に払わせるので、メインは本題のための余裕を保てます。速さや正しさが保証されるわけではありません。

</details>

### Q3. サブエージェントに向いている仕事の形はどれですか。

- A. 読む量が多く、結果を数行で言える
- B. 読む量が少なく、結果の説明が長い
- C. 分かれ道のたびに相談が要る

<details>
<summary>答え</summary>

**A** — 「入りは大きく、出は小さい」が向く形です。調査と検証がその代表です。

</details>

### Q4. 「この機能の設計を決めて実装まで全部進めて」をサブエージェントに渡すのが不適切な理由はどれですか。

- A. サブエージェントはファイルを読めないから
- B. 設計の分かれ道で相談したくても、別の会話なので口を挟みにくいから
- C. 実装は必ずメインの会話より遅くなるから

<details>
<summary>答え</summary>

**B** — 別の会話で進むことは、途中が見えず舵取りしにくいことでもあります。相談が要る仕事はメインの会話に置きます。

</details>

### Q5. 「検証役」をチーム全員で同じ観点にしたいとき、適切なのはどれですか。

- A. 各自が毎回、口頭で観点を説明して頼む
- B. frontmatterにnameとdescription、本文に指示を書いた定義ファイルを `.claude/agents/` に入れる
- C. 観点をCLAUDE.mdに全部書く

<details>
<summary>答え</summary>

**B** — 役割はファイルで定義でき、リポジトリに入れれば全員が同じ係を呼べます。Cは毎回読み込まれる場所に、検証のときだけ要る観点を置く置き間違いです。

</details>
