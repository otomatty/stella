# レッスン1-1 演習 — CLAUDE.mdを書く

対象トピック: 1-1-1 〜 1-1-5

## 手元で試す

VS Code で自分のリポジトリ(練習用のリポジトリでも構いません)を開いて進めます。Claude Code が使えない場合は、メモ帳でCLAUDE.mdの下書きだけ作れば十分です。

1. レッスン0-1の演習で書き出した「毎回書いている前置き」から、**どの作業でも効いてほしいもの**だけを選ぶ
2. リポジトリ直下に `CLAUDE.md` を作り、選んだ約束を箇条書きで書く。まずは10行以内に収める
3. よく使うコマンド(テストの走らせ方など)を1つ、書き方の約束を1つ、必ず入れる
4. Claude Code が使えるなら、新しい会話を始めて小さな修正を1つ頼み、書いた約束が守られるかを見る
5. 守られなかった約束があれば、消すのではなくまず言い換えてみる(短く・具体的に)

書き上がったCLAUDE.mdは、チームのリポジトリならそのままプルリクエストに出せます。

## 演習問題

### 問1(基本)

CLAUDE.mdがいつ読み込まれるかを、「会話」という語を使って1文で書いてください。

### 問2(基本)

プロジェクトのCLAUDE.mdをリポジトリの直下に置く利点を、「共有」という語を使って1〜2文で説明してください。

### 問3(応用)

次の4つの文のうち、CLAUDE.mdに書くのが適切なものを2つ選び、残り2つが適切でない理由を1文ずつ書いてください。

```text
1. テストは bun run test で走らせる
2. リリース前の確認手順(全12ステップ)
3. コメントは日本語で書く
4. 障害調査のときのログの読み方(全15ステップ)
```

### 問4(応用)

「約束はたくさん書くほど安心だ」という意見の誤りを、「コンテキスト」「埋もれる」の2語を使って1〜2文で指摘してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

CLAUDE.mdは、作業フォルダとその上位のCLAUDE.mdが、Claude Codeとの会話の始まりに自動で読み込まれます。

</details>

<details>
<summary>問2の解答例</summary>

リポジトリに入れると、クローンしたチーム全員のClaude Codeが同じ約束を読むので、共有の約束になります。直すときも1ファイルを直せば全員に配れます。

</details>

<details>
<summary>問3の解答例</summary>

適切なのは1と3です。どちらも、どの作業のときにも毎回効いてほしい約束だからです。2と4は特定の作業(リリース・障害調査)のときだけ要る手順なので、タスク向けの入れ物(Skill)に置きます。

</details>

<details>
<summary>問4の解答例</summary>

CLAUDE.mdは毎回コンテキストに入るので、書くほどに毎回の消費が増え、大事な約束が他の行に埋もれて効きにくくなります。量はタダではありません。

</details>

## 確認クイズ

### Q1. CLAUDE.mdに書いた約束が効くのはいつですか。

- A. そのファイルを依頼のたびに自分で貼り付けたときだけ
- B. 作業フォルダとその上位のCLAUDE.mdは会話の始まりに読み込まれるので、すべての会話で最初から
- C. Claudeが必要だと判断したときだけ読み込まれる

<details>
<summary>答え</summary>

**B** — 作業フォルダとその上位のCLAUDE.mdは会話の始まりに自動で読み込まれます。「毎回効く」がこの入れ物の性質です。下位フォルダのCLAUDE.mdやSkillのように、要るときだけ読まれる入れ物は別にあります。

</details>

### Q2. 「リリース前の確認手順(12ステップ)」をCLAUDE.mdに書こうとしています。適切な判断はどれですか。

- A. 大事な手順なのでCLAUDE.mdに書く
- B. リリースのときだけ効けばよいので、タスク向けの入れ物に置く
- C. 手順は仕組みにできないので、毎回依頼に書く

<details>
<summary>答え</summary>

**B** — 手順が効くのはその作業のときだけです。毎回読む場所に置くと、毎回のコンテキストを削り、毎回の約束を埋もれさせます。

</details>

### Q3. CLAUDE.mdが100行を超え、「書いてあるのに守られない」約束が増えてきました。最初にやることはどれですか。

- A. 守られない約束を、もっと強い言葉で書き直して太字にする
- B. さらに詳しい説明を足して、誤解の余地をなくす
- C. 毎回効いてほしいもの以外を削って、短く戻す

<details>
<summary>答え</summary>

**C** — 長さが効きを薄めています。足すのではなく削るのが手入れです。「これがないと毎回困るか?」で1行ずつ問い直します。

</details>

### Q4. プロジェクトの約束をチームで揃えたいとき、CLAUDE.mdの置き場所として適切なのはどれですか。

- A. 各自が自分の手元に好きな内容で置く
- B. リポジトリの直下に置いて、変更はレビューを通す
- C. チャットで毎回共有する

<details>
<summary>答え</summary>

**B** — リポジトリに入れればクローンした全員に同じ約束が配られ、変更もコードと同じ流れで揃えられます。

</details>

### Q5. CLAUDE.mdに最初に書くものとして向いている組み合わせはどれですか。

- A. テストの走らせ方・コメントの言語・フォルダの役割1行ずつ
- B. リリース手順・障害調査手順・デプロイ手順
- C. その日の作業のTODOリスト

<details>
<summary>答え</summary>

**A** — どれも、どの作業でも最初に知っていてほしいことです。Bは特定の作業の手順、Cは毎回どころかその日しか効かない内容です。

</details>
