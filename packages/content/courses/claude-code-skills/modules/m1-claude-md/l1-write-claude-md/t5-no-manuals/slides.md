# 1-1-5
# 手順書を書かない

Skillsとサブエージェント — Module 1 / レッスン1-1

<!-- ノート: M1の締めです。CLAUDE.mdを壊す一番の原因を、先に禁じ手として教えます。 -->

---

## なぜ必要か

- 「リリース前の確認手順」を全部CLAUDE.mdに書きたくなる
- 書けば書くほど安心な気がするのに、実際は効きが悪くなっていく

<!-- ノート: 善意の追記がCLAUDE.mdを壊します。結論はまだ言いません。 -->

---

## 結論

**特定の作業のときだけ要る手順は、CLAUDE.mdに書かずタスク向けの入れ物に置きます**

- **手順** — 作業を進める順番を書いたもの。「まずAして、次にB」の形
- 判定は効くタイミング: 手順が効くのは **その作業のときだけ** です

<!-- ノート: 手順が悪いのではありません。毎回は効かないものを、毎回読む場所に置くのが合っていないのです。 -->

---

## 何が起きるか

```text
CLAUDE.mdに手順を足していくと

リリース手順 12行  ← リリースのとき以外は無駄に読む
障害調査手順 15行  ← 調査のとき以外は無駄に読む
毎回の約束    5行  ← 32行の中に埋もれる
```

<!-- ノート: 手順そのものは価値があるのに、置き場所のせいで、毎回のコンテキストを削り、肝心の約束を埋もれさせます。 -->

---

## 置き分けの線

| 書くもの | 置き場所 |
| --- | --- |
| どの作業でも効く約束 | CLAUDE.md |
| 特定の作業の手順 | タスク向けの入れ物(Skill) |

<!-- ノート: M0の地図の通り、タスクのときだけ効く入れ物が別にあります。次のモジュールでそのSkillを正面から扱います。 -->
