# 書くのは毎回効く約束だけ

Skillsとサブエージェント — Module 1 / レッスン1-1

---

## なぜ必要か

- 白紙のCLAUDE.mdを前にすると、思いついたことを何でも書きたくなる
- 書いてよいものの基準がないと、後で見返しても消せない

<!-- ノート: 書き方より先に、選び方です。結論はまだ言いません。 -->

---

## 結論

**CLAUDE.mdに書くのは、どの作業のときにも毎回効いてほしい約束だけです**

- **作業** — 修正・調査・レビューなど、依頼して進めるひとまとまりの仕事
- 判定は効くタイミングの1問だけ:「これはどの作業でも効いてほしいか?」

<!-- ノート: M0の背骨がそのまま採用基準になります。毎回効いてほしければ書く、そうでなければ書かない、です。 -->

---

## 通る例・通らない例

```text
どの作業でも効く       テストは bun run test で走らせる
                     コメントは日本語で書く
                     3つのアプリの役割(1行ずつ)

特定の作業のときだけ    リリース前の確認は…(手順が10行)
                     障害調査のときは、まずログを…
```

<!-- ノート: 下の2つが悪い指示なのではありません。毎回は効かない指示なので、この入れ物ではないというだけです。 -->

---

## よく書かれる3種類

| 種類 | 例 |
| --- | --- |
| よく使うコマンド | テスト・ビルドの走らせ方 |
| 書き方の約束 | コメントの言語、命名の方針 |
| プロジェクトの地図 | フォルダの役割を1行ずつ |

<!-- ノート: 迷ったらこの3種類から始めれば十分です。どれも、どの作業でも最初に知っていてほしいことです。 -->
