## なぜ必要か

- 「リリース前の確認手順」の行き先が、まだ地図の名前しか分かっていない
- 毎回は効かないが、その作業のときには確実に効いてほしい

<!-- ノート: M1の最後に「タスク向けの入れ物に置く」とだけ言いました。今日はその入れ物の性質です。結論はまだ言いません。 -->

---

## 結論

**Skillは、特定のタスクのやり方をまとめた手順書で、そのタスクのときだけ効きます**

- **タスク** — 依頼して進めるひとまとまりの仕事(講座4で扱った語です)
- **手順書** — あるタスクのやり方を、手順として順番にまとめたもの

<!-- ノート: CLAUDE.mdが「約束の紙」なら、Skillは「作業ごとの手順書」です。棚に並べておき、合うタスクのときだけ取り出されます。 -->

---

## 最小の例

```text
Skillの例(どの言語のプロジェクトでも成り立つもの)

レビュー手順          プルリクエストを見るときの観点の順番
コミットメッセージの型  1行目の形式と、本文に書くこと
リリース前チェック     出す前に確かめる項目の一覧
```

<!-- ノート: どれも「毎回ではないが、そのタスクでは毎回同じやり方をしてほしい」ものです。この講座の例はコードに寄せません。 -->

## CLAUDE.mdと並べる

| | CLAUDE.md | Skill |
| --- | --- | --- |
| 中身 | 毎回の約束 | タスクのやり方 |
