# レッスン2-1 演習 — Skillという入れ物

対象トピック: 2-1-1 〜 2-1-4

## 手元で試す

このモジュールもまだ書き始めません。メモ帳だけで、Module 3 で書くSkillの「棚」を設計します。

1. 自分のチームで繰り返されるタスクを3つ挙げる(例: プルリクエストのレビュー、リリース前確認、週次の報告書づくり)
2. それぞれに、1〜2行のdescriptionを下書きする。「〜を頼まれたときに使う。」で始めると書きやすいです
3. レッスン1-1で作った(または下書きした)CLAUDE.mdを見直し、Skillへ移すべき手順が紛れていないか確かめる
4. 3つのうち、Module 3 で最初に書く1つを決める。迷ったら、一番よく繰り返しているタスクを選びます

```text
descriptionの下書きの例
「プルリクエストのレビューを頼まれたときに使う。
 観点の順番と指摘の書き方をまとめた手順書」
```

## 演習問題

### 問1(基本)

CLAUDE.mdとSkillの効くタイミングの違いを、1〜2文で説明してください。

### 問2(基本)

Skillが使われるまでの流れを、「依頼」「description」「読み込み」の3語を使って2〜3文で説明してください。

### 問3(応用)

Skillを10個に増やしても、本文の全文が毎回読み込まれるわけではないのはなぜですか。「背表紙」の比喩を使わずに、仕組みとして1〜2文で説明してください。

### 問4(応用)

次の4つの指示を、CLAUDE.mdに置くものとSkillに置くものに振り分けてください。

```text
1. コミットメッセージは日本語で書く
2. 障害調査のときは、ログの確認から始めて原因候補を3つ挙げる
3. フォルダ構成の説明(3行)
4. 週次報告書は、この見出しの順でまとめる
```

## 解答例と解説

<details>
<summary>問1の解答例</summary>

CLAUDE.mdは作業フォルダとその上位のCLAUDE.mdが会話の始まりに読み込まれ、すべての作業で効きます。Skillは合うタスクのときだけ選ばれて効きます。

</details>

<details>
<summary>問2の解答例</summary>

依頼が来ると、Claudeは各Skillのdescriptionと依頼を照らして、合うSkillを自分で選びます。選ばれたSkillだけ中身の読み込みが起き、その手順に沿ってタスクが進みます。

</details>

<details>
<summary>問3の解答例</summary>

Skillの本文は使うときだけ読み込まれます。ふだんの会話に入るのは各Skillの名前とdescriptionの一覧だけです。本文の長さの費用は、そのSkillが使われるときにしか払いません。

</details>

<details>
<summary>問4の解答例</summary>

CLAUDE.md: 1と3(どの作業でも毎回効いてほしい)。Skill: 2と4(障害調査・週次報告という特定のタスクのときだけ効いてほしい手順書)。

</details>

## 確認クイズ

### Q1. 「リリース前はこの項目を確認する」という手順の置き先として適切なのはどれですか。

- A. 毎回読み込まれるCLAUDE.md
- B. リリースのタスクのときだけ効くSkill
- C. 依頼のたびに全文を貼り付ける

<details>
<summary>答え</summary>

**B** — 効いてほしいのはリリースのときだけです。タスクのときだけ効かせたい手順書はSkillに置きます。

</details>

### Q2. Skillが選ばれるかどうかを決めるのはどれですか。

- A. ファイルの置き場所のフォルダ名だけ
- B. 依頼と、Skillのdescriptionが照らされて合うかどうか
- C. Skillの中身の手順が長いかどうか

<details>
<summary>答え</summary>

**B** — Claudeは依頼とdescriptionを照らして、使うSkillを自分で選びます。だからdescriptionには「いつ使うか」を書きます。

</details>

### Q3. 中身のよくできたSkillが、一度も使われません。まず疑うべきはどれですか。

- A. descriptionが曖昧で、依頼と照らせていない
- B. 手順の中身が長すぎる
- C. CLAUDE.mdが短すぎる

<details>
<summary>答え</summary>

**A** — 選ばれるかどうかは背表紙(description)で決まります。「便利な手順いろいろ」のような書き方では、いつ使うか照らせません。

</details>

### Q4. 「Skillを増やしてもコンテキストを圧迫しない」という理解の誤りはどこですか。

- A. Skillも本文が毎回読み込まれるので誤り
- B. 本文は使うときだけだが、名前とdescriptionの一覧は会話に残り、多いと省略される点を見落としている
- C. 誤りではなく、Skillも10個までしか作れない

<details>
<summary>答え</summary>

**B** — CLAUDE.mdは全文が毎回入ります。Skillは本文は使うときだけですが、名前とdescriptionは一覧としてふだんの会話にも入り、増やすほどその費用が増えます。多すぎるとdescriptionは短く省略されます。

</details>

### Q5. 「タスクによって挙動がぶれる。毎回守ってほしい約束が、レビューのとき以外は効いていない」という症状から疑うべき置き間違いはどれですか。

- A. 毎回効かせたい約束が、レビュー用のSkillの中に書かれている
- B. 手順書がCLAUDE.mdに書かれている
- C. descriptionが長すぎる

<details>
<summary>答え</summary>

**A** — Skillに置いた指示は、そのタスクのときしか効きません。毎回効かせたいものはCLAUDE.mdへ移します。症状から置き間違いに気づく練習です。

</details>
