# 2-1-2
# descriptionが呼び出しの鍵

Skillsとサブエージェント — Module 2 / レッスン2-1

<!-- ノート: 手順書が棚にあるとして、誰が取り出すのか。Skillの一番面白いところです。 -->

---

## なぜ必要か

- 手順書を置いても、使われなければ書かなかったのと同じ
- 「このSkillを使って」と毎回自分で指定するなら、繰り返しが戻ってくる

<!-- ノート: 仕組み化の目的は「毎回言わなくても効く」でした。Skillでもそれを成り立たせる仕掛けがあります。結論はまだ言いません。 -->

---

## 結論

**ClaudeはdescriptionというSkillの説明文と依頼を照らして、使うSkillを自分で選びます**

- **依頼** — タスクを頼むときに書く文(講座4で扱った語です)
- **description** — そのSkillが何のためのもので、いつ使うかを書いた説明文

<!-- ノート: 取り出すのは自分ではなくClaudeです。棚の背表紙にあたるdescriptionを見て、いまの依頼に合う手順書を選びます。 -->

---

## 最小の例

```text
依頼          「このプルリクエストをレビューして」

descriptionの例 「プルリクエストのレビューを頼まれたときに使う。
               観点の順番と指摘の書き方をまとめた手順書」

→ 照らして合う → このSkillが選ばれて使われる
```

<!-- ノート: 依頼の文とdescriptionの文が照らされて、合えば選ばれます。だからdescriptionには「いつ使うか」が書かれている必要があります。 -->

---

## 選ばれる・選ばれない

| descriptionの書き方 | 結果 |
| --- | --- |
| 「レビューを頼まれたときに使う」 | レビューの依頼で選ばれる |
| 「便利な手順いろいろ」 | いつ使うか照らせず、選ばれない |
