# 2-1-3
# 要るときだけ読み込まれる

Skillsとサブエージェント — Module 2 / レッスン2-1

<!-- ノート: Skillが増えても平気な理由です。CLAUDE.mdの「長さの費用」と対になる話です。 -->

---

## なぜ必要か

- CLAUDE.mdでは、書くほどに毎回のコンテキストが削られた
- 手順書をタスクの種類ごとに増やしたら、同じ問題が起きないのか

<!-- ノート: M1-1-4の記憶があるほど、この疑問は自然です。Skillはそこが根本的に違います。結論はまだ言いません。 -->

---

## 結論

**Skillの本文は使うときだけ読み込まれますが、名前とdescriptionは会話に残り、増やしすぎると短く省略されます**

- **読み込み** — ファイルの中身がコンテキストに入ること(本文は使うときだけ)
- 名前とdescriptionは、Skillの一覧としてふだんの会話にも入ります

<!-- ノート: 棚の比喩で言えば、背表紙(名前+description)はいつも一覧に載り、中身が開かれるのは選ばれたときだけです。背表紙も増やしすぎると省略されます。 -->

---

## 最小の例

```text
ふだんの会話       Skill 10個ぶんの名前+description(各1〜2行)

レビューの依頼が来た  レビュー手順のSkillだけ本文が読み込まれる
                   残り9個は一覧の背表紙のまま

Skillが30個に増えた  一覧が長くなり、descriptionが省略され始める
```

<!-- ノート: 本文の長さは使うときにしか払いません。ただし名前+descriptionの一覧は増やすほど費用が増え、多いと短く省略されます。 -->

---

## CLAUDE.mdと費用を比べる

| | CLAUDE.md | Skill |
| --- | --- | --- |
| 毎回入るもの | 全文 | 名前+description(一覧) |
| 本文の読み込み | 毎回 | 使うときだけ |
| 増やしたときの費用 | 全会話に全文が効く | descriptionのぶんが増える(多いと省略) |

<!-- ノート: これで置き分けの理屈がつながります。毎回効くものは全文入りのCLAUDE.mdへ、タスクの手順は要るときだけ開くSkillへ、です。 -->
