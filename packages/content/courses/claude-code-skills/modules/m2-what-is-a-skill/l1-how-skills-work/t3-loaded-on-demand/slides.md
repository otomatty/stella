# 2-1-3
# 要るときだけ読み込まれる

Skillsとサブエージェント — Module 2 / レッスン2-1

<!-- ノート: Skillが増えても平気な理由です。CLAUDE.mdの「長さの費用」と対になる話です。 -->

---

## なぜ必要か

- CLAUDE.mdでは、書くほどに毎回のコンテキストが削られた
- 手順書をタスクの種類ごとに増やしたら、同じ問題が起きないのか

<!-- ノート: M1-1-4の記憶があるほど、この疑問は自然です。Skillはそこが根本的に違います。結論はまだ言いません。 -->

---

## 結論

**Skillの中身が読み込まれるのは使うときだけで、増やしてもふだんの費用は短いdescriptionのぶんだけです**

- **読み込み** — ファイルの中身がコンテキストに入ること
- descriptionはふだんの会話にも入りますが、1〜2行の短さです

<!-- ノート: 棚の比喩で言えば、いつも見えているのは背表紙だけ。中身が開かれるのは、選ばれたときだけです。 -->

---

## 最小の例

```text
ふだんの会話       Skill 10個ぶんのdescription(各1〜2行)だけ

レビューの依頼が来た  レビュー手順のSkillだけ中身が読み込まれる
                   残り9個は背表紙のまま
```

<!-- ノート: 10個に増えても、毎回の費用は背表紙10行ぶんです。中身の長さは、使うときにしか払いません。 -->

---

## CLAUDE.mdと費用を比べる

| | CLAUDE.md | Skill |
| --- | --- | --- |
| 毎回入るもの | 全文 | descriptionだけ |
| 中身の読み込み | 毎回 | 使うときだけ |
| 増やしたときの費用 | 全会話に効く | ほぼ増えない |

<!-- ノート: これで置き分けの理屈がつながります。毎回効くものは全文入りのCLAUDE.mdへ、タスクの手順は要るときだけ開くSkillへ、です。 -->
