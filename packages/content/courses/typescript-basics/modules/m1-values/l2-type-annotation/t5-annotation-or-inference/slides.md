# 1-2-5
# 注釈と推論、どちらを書くか

TypeScript入門 — Module 1 / レッスン1-2

<!-- ノート: 型注釈と型推論、どちらでも同じ結果になることがわかりました。では実際に書くときの方針を1つだけ決めます。 -->

---

## なぜ必要か

- 同じ結果になるなら、毎回どちらにするか迷ってしまう
- チームで揃っていないと、レビューで無用な指摘が増える

<!-- ノート: つかみ。1-1-3のconstファーストと同じ構図。技術的にどちらでもよいからこそ、基準を1つ持っておくと迷わない。 -->

---

## 結論

**初期値がある変数は推論に任せる。書くのは推論できないときだけ**

- 書かないのは手抜きではなく、正しいスタイル
- 同じ情報を2か所に書かない、という考え方

<!-- ノート: 結論を先に言い切る。「300と書いてあるのにnumberとも書く」のは同じ情報の重複であり、値を変えたときに書き換え漏れが起きる。だから推論に任せるほうが安全、という理屈で説明する。 -->

---

## 最小のコード

```ts
const orderCount = 3; // 推論: number ← これでよい
const memberName = "佐藤"; // 推論: string ← これでよい

let deliveryDate: string; // 初期値がない → 推論できないので書く
```

<!-- ノート: 上2つは推論に任せる例、下は初期値がないので推論しようがなく、型注釈が要る例。初期値なしの宣言は後のレッスンでも出てくるので、ここで型注釈の出番として印象づけておく。 -->

---

## 例外: チームの決まりが最優先

- 配属先に「常に型注釈を書く」規約があれば、それに従う
- 本研修のコードは推論に任せるスタイルで統一する

<!-- ノート: 対比枠。研修の方針は絶対のルールではなく、現場の規約が上に来ることを必ず添える。ここを言い忘れると、配属先で混乱するもとになる。 -->
