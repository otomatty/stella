# undefined

TypeScript入門 — Module 1 / レッスン1-6

<!-- ノート: Module 1の最後のレッスンです。テーマは「値がない」。バグの温床であり、TypeScriptがいちばん得意とする領域でもあります。 -->

---

## なぜ必要か

- 実務データには「未入力」「未設定」が必ずある
  - 例: 任意入力の電話番号、まだ発送されていない注文の発送日
- 「値がないのに使ってしまう」のは、いちばん有名な実行時エラー

<!-- ノート: つかみ。「Cannot read properties of undefined」はJavaScript開発で最も見るエラー。TypeScriptはこれを事前に防ぐ道具だと位置づける。 -->

---

## 結論

**undefinedは「値がまだ入っていない」ことを表す値**

- 自然に発生する。プログラマーが書かなくても現れる

<!-- ノート: 結論を先に言い切る。「自然に発生する」がこのトピックのいちばんの特徴。次のトピックのnullと対比するための伏線でもある。 -->

---

## 最小のコード

```ts
let deliveryDate;
console.log(deliveryDate); // => undefined
```

- 初期値なしで宣言した変数には、自動で`undefined`が入っている

<!-- ノート: 誰も代入していないのに値が入っている、という点を確認する。存在しないプロパティへのアクセスや、値を返さない関数からも生まれるが、それらは後のモジュールで扱うと予告だけしておく。 -->
