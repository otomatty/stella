# なぜ既定をconstにするのか

TypeScript入門研修 — Module 1 / レッスン1-1

<!-- ノート: constとletの違いはわかりました。では実際に書くとき、どちらを選べばよいのか。現場で広く使われている判断基準を1つだけ覚えます。 -->

---

## なぜ必要か

- 「どちらでも動く」場面のほうが多い。だから毎回迷う
- 迷いをなくす基準が1つあれば、レビューの指摘も減る

<!-- ノート: つかみ。技術的にはどちらでも動くからこそ、チームで基準を揃える意味がある。基準がないと人によってバラバラになり、読む側の負担になる。 -->

---

## 結論

**まずconstで書き、再代入が必要になったときだけletに変える**

- `const`は「この名前の値は最後まで変わらない」という宣言でもある
- 読む人は、再代入を探さずに済む

<!-- ノート: 結論を先に言い切る。constは制約であると同時に、読み手への情報でもあるという視点を伝える。letが出てきたら「ここは変わるんだな」と身構えられる、という読み手側のメリットが本質。 -->

---

## 最小のコード

```ts
const companyName = "株式会社サンプル"; // 変わらない
const salesTarget = 500000; // 変わらない

let currentSales = 120000; // 日々更新される
currentSales = 135000;
```

<!-- ノート: 業務データで対比して見せる。会社名や目標値は変わらないのでconst、実績値は更新されるのでlet。書く前に「これは変わるか?」と一度だけ自問する習慣を勧める。 -->

---

## 迷ったときの手順

1. とりあえず`const`で書く
2. 再代入したくなってエラーが出たら`let`に変える
3. その前に「本当に再代入が必要か」を一度だけ疑う

<!-- ノート: 対比枠。安易にletへ変えるのではなく、まず設計を疑う癖を紹介する。別の名前の変数を新しく作ったほうが読みやすいことも多い、と実例の匂いだけ添える。 -->
