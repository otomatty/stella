## なぜ必要か

- 「数値か文字列のどちらか」が入る項目は実務にある
  - 例: 会員IDが、旧システムでは数値、新システムでは文字列
- 型が1つしか書けないと、こうした現実を表現できない

<!-- ノート: つかみ。現実のデータは1種類に収まらないことがある。型を諦めてanyにする前に、まず組み合わせを試すという発想を持ってもらう。 -->

---

## 結論

**型を「|」でつなぐと「AまたはB」を表せる**

- この書き方をユニオン型と呼ぶ
- `|` は縦棒(パイプ)。「または」と読む

<!-- ノート: 結論を先に言い切る。ユニオンは「合併・和集合」の意味。縦棒の打ち方(日本語キーボードではShift+￥)も案内する。3つ以上つなぐこともできる。 -->

---

## 最小のコード

```ts
let memberId: number | string = 1001;
memberId = "A-1001"; // OK
memberId = true;
// エラー: Type 'boolean' is not assignable to type 'string | number'.
```

<!-- ノート: numberでもstringでも受け入れるが、booleanは弾かれることを確認する。「なんでも入る」わけではなく、つないだ型だけが入る点が重要。 -->
