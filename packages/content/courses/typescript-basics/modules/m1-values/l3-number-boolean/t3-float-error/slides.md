# 1-3-3
# 小数の計算には誤差がある

TypeScript入門 — Module 1 / レッスン1-3

<!-- ノート: number型は整数も小数も扱えます。ただし小数には、知らないと必ずハマる性質が1つあります。 -->

---

## なぜ必要か

- 実務あるある: 合計金額が1円だけ合わない
- 原因を知らないと、コードを何度見直しても見つからない

<!-- ノート: つかみ。請求や集計の1円ズレは、原因を知っていれば数分、知らなければ半日溶ける類のバグ。ここで免疫をつけておく。 -->

---

## 結論

**小数の計算はぴったりにならないことがある。金額は整数で計算する**

<!-- ノート: 結論を先に言い切る。理由はコンピューターの小数の持ち方(2進数)にあるが、深追いはしない。「そういう性質がある」と「だから金額は整数で」の2点だけ持ち帰ってもらう。 -->

---

## 最小のコード

```ts
console.log(0.1 + 0.2); // => 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // => false
```

- コンピューターの小数の持ち方の都合で、わずかな誤差が出る

<!-- ノート: Playgroundで実際に0.30000000000000004が出るのを見せると強く印象に残る。2行目のfalseがいちばんの衝撃ポイント。三重イコールは「等しいか」を調べる記号だと一言だけ添える。 -->

---

## 実務での回避策

```ts
// 税込価格を「円」ではなく整数のまま計算する
const price = 300;
const taxIncluded = Math.round(price * 1.1);
console.log(taxIncluded); // => 330
```

- 小数を持ち回らず、最後に整数へ丸める

<!-- ノート: 対比枠。Math.roundは四捨五入する命令、とだけ紹介する(詳細は不要)。金額を扱うときは小数を長く持ち回らない、という設計の勘所だけ伝える。 -->

---

## まとめ

**小数の計算はぴったりにならないことがある。金額は整数で計算する**
