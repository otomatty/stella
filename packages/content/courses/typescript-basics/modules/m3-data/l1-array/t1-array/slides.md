## なぜ必要か

- 商品が3つあるだけで、変数を3つ作ることになる
- 10個、100個になったら手に負えない

<!-- ノート: つかみ。item1、item2、item3…と増えていく苦しさを一度想像してもらう。しかも個数が事前にわからない場合は変数を用意しようがない。 -->

## 結論

**配列は、同じ種類の値を順番に並べて1つにまとめたもの**

- 要素 = 配列に入っている1つ1つの値
- 配列リテラル = 角かっこ`[ ]`で値を並べる書き方

<!-- ノート: 結論を先に言い切る。要素と配列リテラルという2つの言葉を定義する。「順番がある」ことが配列の重要な性質で、後のインデックスや繰り返しにつながる。 -->

---

## 最小のコード

```ts
const items: string[] = ["コーヒー", "紅茶", "緑茶"];
console.log(items); // => ["コーヒー", "紅茶", "緑茶"]

const prices = [480, 500, 450]; // 推論: number[]
```

- 型注釈は**要素の型のうしろに`[]`**を付ける

<!-- ノート: string[]は「文字列の配列」と読む。要素の型が先で、角かっこが後。1-2-5で学んだとおり、初期値があれば推論に任せてよい。Array<number>という書き方もあるが、本研修はnumber[]で統一する。 -->

---

## よくある間違い: 型の合わない要素

```ts
const prices: number[] = [480, "500", 450];
// エラー: Type 'string' is not assignable to type 'number'.
```

- 配列は「同じ種類の値」を並べるもの

<!-- ノート: 対比枠。1つでも違う型が混ざるとエラーになる。1-2-3で練習したエラーメッセージの読み方がそのまま使える。混ざった型を入れたい場合の書き方はModule 5で扱う。 -->
