## なぜ必要か

- 商品一覧、注文履歴、検索結果。実務のデータはほぼこの形
- 読めるようになると、APIの応答も設計書も一気に理解できる

<!-- ノート: つかみ。この形が読めるかどうかが、コードを読める人と読めない人の分かれ目になる。Module 3の総仕上げとして位置づける。 -->

---

## 結論

**実務のデータはほぼ「オブジェクトの配列」の形になる**

```
type 型名 = { ... };
const 変数: 型名[] = [ ... ];
```

<!-- ノート: 結論を先に言い切る。3-1-1で学んだ「要素の型のうしろに[]」というルールが、型エイリアスにもそのまま使える。新しい構文は1つも出てこない。 -->

---

## 最小のコード

```ts
type Product = {
  name: string;
  price: number;
};

const products: Product[] = [
  { name: "コーヒー", price: 480 },
  { name: "紅茶", price: 500 },
];
```

<!-- ノート: 型を1つ定義して、その配列を作る。角かっこの中に中かっこが並ぶ形に最初は戸惑うが、外側が配列、内側が1件ぶんのデータ、と分けて読めば難しくない。 -->

---

## 繰り返しと組み合わせる

```ts
let total = 0;

for (const product of products) {
  console.log(`${product.name}: ${product.price}円`);
  total = total + product.price;
}

console.log(total); // => 980
```
