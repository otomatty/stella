TypeScript入門 — Module 3 / レッスン3-2

## なぜ必要か

- カートに商品を足す、状態を更新する。データは動く
- 最初に作ったまま変わらない配列は、実務ではむしろ少ない

<!-- ノート: つかみ。買い物カゴ、TODOリスト、検索結果の絞り込み。配列は増えたり変わったりするのが普通だと伝える。 -->

---

## 結論

**要素はインデックスで書き換え、`push`で末尾に追加する**

<!-- ノート: 結論を先に言い切る。書き換えは1-1-2で学んだ代入と同じ形。pushは「押し込む」の意味で、配列の後ろに1つ足す命令。 -->

---

## 最小のコード

```ts
const items = ["コーヒー", "紅茶"];

items[1] = "ほうじ茶"; // 書き換え
console.log(items); // => ["コーヒー", "ほうじ茶"]

items.push("緑茶"); // 末尾に追加
console.log(items); // => ["コーヒー", "ほうじ茶", "緑茶"]
```

<!-- ノート: 書き換えは変数への代入と同じ見た目で、左辺がitems[1]になるだけ。pushはドットに続けて書き、かっこの中に足したい値を入れる。追加後にlengthが増えることも確認するとよい。 -->

---

## 型はここでも守ってくれる

```ts
const prices: number[] = [480, 500];

prices.push("450");
// エラー: Argument of type 'string' is not
// assignable to parameter of type 'number'.
```

<!-- ノート: 対比枠。number[]の配列に文字列は入れられない。argumentは「引数」、parameterは「受け取り側」。用語はModule 4で正式に扱うが、いまは「渡した型と受け取る型が合わない」と読めれば十分。 -->
