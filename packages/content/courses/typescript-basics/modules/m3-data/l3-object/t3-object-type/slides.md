## なぜ必要か

- エラーメッセージにオブジェクトの型がそのまま出てくる
- 読めないと、何が足りないのか分からない

<!-- ノート: つかみ。読めるようになることが第一目的。書けるようになるのはその次。実務ではエラーメッセージを読む時間のほうが圧倒的に長い。 -->

---

## 結論

**オブジェクトの型は、プロパティ名と型の組を中かっこに並べて書く**

```
{ プロパティ名: 型; プロパティ名: 型 }
```

<!-- ノート: 結論を先に言い切る。値を書くオブジェクトリテラルとよく似た形。違いは、コロンの右が値ではなく型であること。区切りはセミコロンでもカンマでもよいが、本研修はセミコロンで統一する。 -->

---

## 最小のコード

```ts
const user: { name: string; age: number } = {
  name: "田中",
  age: 28,
};
```

- 長くなるときは複数行で書く

```ts
const product: {
  name: string;
  price: number;
} = { name: "コーヒー", price: 480 };
```

<!-- ノート: 型の部分と値の部分が入れ子になって読みにくいことを実感してもらう。この読みにくさが、レッスン3-4の型エイリアスへの動機になる。ここではまだ解決策を出さない。 -->

---

## 推論に任せてよい

```ts
const user = { name: "田中", age: 28 };
// 推論: { name: string; age: number }
```

<!-- ノート: 対比枠。1-2-5の方針どおり、初期値があれば推論に任せる。Playgroundでカーソルを乗せると、いま学んだ形の型が表示されることを確認させると理解が定着する。 -->
