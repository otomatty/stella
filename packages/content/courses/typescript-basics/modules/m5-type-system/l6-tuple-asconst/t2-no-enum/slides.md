# 5-6-2
# enumは使わない

TypeScript入門 — Module 5 / レッスン5-6

<!-- ノート: 既存コードで必ず出会う機能ですが、新しく書く必要はありません。付き合い方を決めます。 -->

---

## なぜ必要か

- 既存のコードや他言語の経験から`enum`を使おうとしてしまう
- TypeScriptでは推奨されない理由がある

<!-- ノート: つかみ。JavaやC#の経験者ほど手が伸びる。1-1-4のvarと同じで「読めるが書かない」というスタンスを先に決めておく。 -->

---

## 結論

**`enum`は読めればよい。定数の集合はリテラルのユニオン型で書く**

- `enum`(イーナム) = 名前付きの定数をまとめる機能

<!-- ノート: 結論を先に言い切る。enumを定義する。禁止ではなく、より良い代替があるという話。TypeScript開発チーム自身も新規利用を勧めていない。 -->

---

## enumの問題: 変換後にコードが残る

```ts
enum Status {
  Todo = "todo",
  Done = "done",
}
```

- 型ではなく**実体のある機能**なので、変換後のJavaScriptに残る
- 0-1-3で学んだ「型は消える」が当てはまらない

<!-- ノート: TypeScriptの型はコンパイル時に消えるのが原則。enumはその例外で、実際のコードが出力される。Playgroundの.JSタブで確認させると効果的。予想外に増えるコードは避けたい。 -->

---

## 代替: リテラルのユニオン型

```ts
type Status = "todo" | "done";

const status: Status = "todo";
```

- 1-5-3で学んだ書き方でそのまま代替できる
- 変換後には何も残らない
