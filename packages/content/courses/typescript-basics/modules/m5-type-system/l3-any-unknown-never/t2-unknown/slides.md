# 5-3-2
# unknown型

TypeScript入門 — Module 5 / レッスン5-3

<!-- ノート: anyが危険なことは分かりました。では、本当に型が分からないときの正しい選択肢です。 -->

---

## なぜ必要か

- 外部から届くデータは、実行するまで形が分からない
- 分からないのに`string`と書くのは、型に嘘を書くことになる

<!-- ノート: つかみ。3-4-2で「型は仕様書だから嘘を書くと後の人が騙される」と話した。分からないことも正直に書ける型が要る。 -->

---

## 結論

**`unknown`は「型がわからない」ことを正直に表す型**

- 何でも**代入できる**
- ただし、そのままでは**何もできない**

<!-- ノート: 結論を先に言い切る。入れるのは自由、使うのは不自由。この非対称さがunknownの本質で、anyとの決定的な違いになる。 -->

---

## 最小のコード

```ts
const value: unknown = "コーヒー";

console.log(value.length);
// エラー: 'value' is of type 'unknown'.
```

- 入れるのは自由。使おうとすると止められる

<!-- ノート: anyなら通っていたコードが、unknownでは止まる。コンパイラーは「型が分からない以上、何も許可できない」という立場。5-1-1のユニオン型と同じ考え方の延長。 -->

---

## 使うには絞り込む

```ts
const value: unknown = "コーヒー";

if (typeof value === "string") {
  console.log(value.length); // => 4
}
```

<!-- ノート: 対比枠。5-2-2で学んだtypeofの型ガードがそのまま使える。「確かめてから使う」という手順を強制されるのがunknownの価値。新しい仕組みは何も出てこない。 -->
