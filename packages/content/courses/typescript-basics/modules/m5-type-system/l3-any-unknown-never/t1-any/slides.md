# 5-3-1
# any型

TypeScript入門 — Module 5 / レッスン5-3

<!-- ノート: レッスン5-3では「型が分からない」場面を扱います。まずは、使ってはいけないほうの選択肢から。 -->

---

## なぜ必要か

- エラーを消したい一心で`any`を使ってしまう場面が必ず来る
- 何が起きるのかを知らないと、悪気なく安全装置を外してしまう

<!-- ノート: つかみ。anyは魅力的に見える。赤い波線が全部消えるので、初学者ほど手が伸びる。だから先に危険性を伝えておく。 -->

---

## 結論

**`any`は全てのチェックを止める。使うとTypeScriptの利点が消える**

- `any`(エニー) = 「何でもよい」という型

<!-- ノート: 結論を先に言い切る。0-1-2で学んだ「実行前に間違いを見つける」という価値そのものが失われる。エラーが消えるのではなく、見えなくなるだけ。 -->

---

## 最小のコード

```ts
const value: any = "コーヒー";

console.log(value.length); // OK
console.log(value.toFixed(2)); // OK(存在しないのに)
console.log(value.foo.bar); // OK(実行時に落ちる)
```

- コンパイラーは何も言わない。**実行して初めて落ちる**

<!-- ノート: 3行ともコンパイルを通る。実際に動かすと2行目以降で実行時エラーになる。0-1-1で見た「気づくのが遅いバグ」に自ら戻る行為だと位置づける。 -->

---

## 付き合い方

- 自分から書かない
- 移行中の古いコードなど、やむを得ない場合だけ
- 型が分からないなら、次のトピックの`unknown`を使う

<!-- ノート: 対比枠。全面禁止ではなく、最後の手段。4-1-2で見た「型注釈の書き忘れ」でも暗黙のanyになるので、noImplicitAnyという設定で防ぐ(Module 9で扱う)。 -->
