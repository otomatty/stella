# 5-2-3
# in演算子による型ガード

TypeScript入門 — Module 5 / レッスン5-2

<!-- ノート: 型ガードの2つ目です。typeofが効かないオブジェクト同士を分ける道具です。 -->

---

## なぜ必要か

- 5-1-2で見たとおり、オブジェクトのユニオンは`typeof`では分けられない
- 目印を付けられない型が、外部から渡ってくることもある

<!-- ノート: つかみ。5-1-3の判別可能なユニオン型は、自分で型を設計できるときの手。ライブラリーや既存コードの型は、目印がないまま渡ってくる。そのときの手段。 -->

---

## 結論

**`in`でプロパティの有無を調べると、オブジェクトのユニオンを絞り込める**

```
"プロパティ名" in オブジェクト
```

<!-- ノート: 結論を先に言い切る。inは「〜の中にあるか」を調べる演算子で、結果はboolean。プロパティ名は文字列で書く(クォートが要る)点に注意する。 -->

---

## 最小のコード

```ts
type Success = { data: string };
type Failure = { message: string };

const result: Success | Failure = { data: "OK" };

if ("data" in result) {
  console.log(result.data); // ここでは Success
} else {
  console.log(result.message); // ここでは Failure
}
```

<!-- ノート: dataというプロパティがあればSuccess、なければFailure。elseの側でもmessageが読めていることを確認する。5-1-2で「読めない」と言っていたものが、ここで読めるようになる。 -->

---

## 限界: プロパティ名に依存している

- 型を変えてプロパティ名が変わると、静かに壊れる
- 自分で型を設計できるなら、5-1-3の目印のほうが安全

<!-- ノート: 対比枠。inは強力だが、型の構造に暗黙に依存する。判別可能なユニオン型なら、目印そのものが型に書いてあるので意図が明示される。使い分けの基準として伝える。 -->
