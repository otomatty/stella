# 交差型

TypeScript入門研修 — Module 5 / レッスン5-5

<!-- ノート: レッスン5-5では型の組み合わせと、TypeScriptの型判定の根っこにある考え方を扱います。まずはユニオン型の相棒から。 -->

---

## なぜ必要か

- 「共通項目 + 個別項目」という形の型は実務に多い
  - 例: すべてのデータが持つIDと作成日時 + 種類ごとの項目
- 同じプロパティを型ごとに書き写すのは、3-4-1で嫌ったのと同じ重複

<!-- ノート: つかみ。3-4-1で型エイリアスを導入した動機と同じ。共通部分を1か所に書いて使い回したい。 -->

---

## 結論

**`&`で型をつなぐと、両方の性質をあわせ持つ型になる**

- ユニオン型`|`が「AまたはB」
- 交差型`&`が「**AかつB**」

<!-- ノート: 結論を先に言い切る。1-5-2で学んだユニオン型と対にして覚える。記号も対になっている。読み方は「かつ」。 -->

---

## 最小のコード

```ts
type Base = { id: string; createdAt: string };
type UserInfo = { name: string; age: number };

type User = Base & UserInfo;

const user: User = {
  id: "U-001",
  createdAt: "2026-08-09",
  name: "田中",
  age: 28,
};
```

- 4つのプロパティすべてが必須になる

<!-- ノート: BaseとUserInfoの両方を満たす必要がある。1つでも欠けると3-3-4で見たmissingエラーになる。共通部分をBaseにまとめておけば、別の型でも再利用できる。 -->

---

## ユニオン型との対比

| | 意味 | 求められるもの |
| --- | --- | --- |
| `A \| B` | AまたはB | どちらか一方を満たす |
| `A & B` | AかつB | **両方を満たす** |

<!-- ノート: 対比枠。記号の見た目が似ているので混同しやすい。プロパティの数で言えば、交差型は増える方向、ユニオン型は共通部分だけに減る方向(5-1-1)。逆になっている点が面白い。 -->
