# 5-5-3
# 余剰プロパティチェック

TypeScript入門研修 — Module 5 / レッスン5-5

<!-- ノート: レッスン5-5の最後です。構造的型付けの唯一の例外を1つ押さえます。ここを知らないと、通ったり通らなかったりする理由が分かりません。 -->

---

## なぜ必要か

- 実務あるある: 変数に入れると通るのに、直接書くとエラーになる
- 理屈を知らないと、場当たり的に変数に逃がしてしまう

<!-- ノート: つかみ。同じ内容なのに書き方で結果が変わる。バグに見えるが、意図した設計。理由を知ると納得できる。 -->

---

## 結論

**オブジェクトを直接書いて渡すときだけ、余分なプロパティが弾かれる**

- この検査を余剰プロパティチェックと呼ぶ
- 目的はタイポの検出

<!-- ノート: 結論を先に言い切る。構造的型付けなら「多い分にはOK」のはずだが、リテラルを直接書く場面だけは別。その場で書いたなら、余分なものはタイポの可能性が高いから。 -->

---

## 直接書くと弾かれる

```ts
type User = { name: string };

const user: User = { name: "田中", age: 28 };
// エラー: Object literal may only specify known
// properties, and 'age' does not exist in type 'User'.
```

<!-- ノート: ageは型にないので弾かれる。メッセージのobject literalは3-3-1で学んだオブジェクトリテラルのこと。「その場で書いたオブジェクトには、知らないプロパティを書けない」という意味。 -->

---

## 変数を経由すると通る

```ts
const data = { name: "田中", age: 28 };
const user: User = data; // OK
```

- 変数経由なら、5-5-2の「形が合えばOK」が適用される

<!-- ノート: 対比枠。data は User の形を満たしているので通る。この違いを知らずに「変数に入れれば通る」とだけ覚えると、タイポの検出をすり抜けてしまう。意図的に多く渡す場合を除き、直接書くほうが安全。 -->
