# ブロックとスコープ

TypeScript入門研修 — Module 2 / レッスン2-1

<!-- ノート: Module 2からは、プログラムの流れを分ける方法に入ります。その前に、これから何度も出てくる中かっこの意味を1つだけ押さえます。 -->

---

## なぜ必要か

- この先、中かっこ`{ }`が大量に出てくる
- 意味を知らないと「なぜかこの変数が見つからない」で手が止まる

<!-- ノート: つかみ。条件分岐も繰り返しも関数もクラスも、すべて中かっこを使う。先に意味を押さえておくと、以降のすべてが読みやすくなる。 -->

---

## 結論

**中かっこの中で宣言した変数は、その外からは見えない**

- ブロック = 中かっこ`{ }`で囲まれた範囲
- スコープ = その変数が使える範囲

<!-- ノート: 結論を先に言い切る。ブロックとスコープという2つの言葉をここで定義する。「箱の中に置いたものは、箱の外からは取れない」というイメージで伝える。 -->

---

## 最小のコード

```ts
{
  const message = "ブロックの中";
  console.log(message); // => "ブロックの中"
}

console.log(message);
// エラー: Cannot find name 'message'.
```

<!-- ノート: 中かっこだけを単独で書くことは実務ではまずないが、仕組みを見せるにはこれがいちばん短い。「名前が見つかりません」というエラーは、変数がなくなったのではなく、外からは見えないという意味だと読み下す。 -->

---

## なぜ見えないほうが嬉しいのか

- 使う範囲が狭いほど、影響が及ぶ範囲も狭い
- 同じ名前を別の場所で安心して使い回せる

<!-- ノート: 対比枠。制約ではなく利点として伝える。どこからでも触れる変数は、どこで壊されたか追えない。1-1-3のconstファーストと同じ「狭くしておく」という考え方だと接続する。 -->
