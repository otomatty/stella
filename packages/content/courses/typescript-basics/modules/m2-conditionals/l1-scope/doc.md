# レッスン2-1 ブロックとスコープ

## このレッスンの目標

- [ ] ブロックとスコープが何を指すか説明できる
- [ ] 変数がどこから見えるかを判断できる
- [ ] シャドーイングによるバグを見分けられる

## 2-1-1 ブロックとスコープ

> **中かっこの中で宣言した変数は、その外からは見えない**

この先、中かっこ`{ }`が大量に出てきます。条件分岐も繰り返しも関数もクラスも、すべて中かっこを使います。意味を先に押さえておくと、以降のすべてが読みやすくなります。

- **ブロック** — 中かっこ`{ }`で囲まれた範囲
- **スコープ** — その変数が使える範囲

```ts
{
  const message = "ブロックの中";
  console.log(message); // => "ブロックの中"
}

console.log(message);
// エラー: Cannot find name 'message'.
```

「名前が見つかりません」というエラーは、変数がなくなったのではなく、**外からは見えない**という意味です。

見えないほうが嬉しい理由は2つあります。使う範囲が狭いほど影響が及ぶ範囲も狭くなること、そして同じ名前を別の場所で安心して使い回せることです。レッスン1-1で「まず`const`」と決めたのと同じ、「狭くしておく」という考え方です。

## 2-1-2 内側からは外の変数が見える

> **スコープは内側からは外が見える。外からは内側が見えない**

見える向きは一方通行です。外は共有スペース、中は個室、とイメージしてください。

```ts
const taxRate = 0.1;

{
  const price = 300;
  console.log(price * (1 + taxRate)); // => 330.00000000000006
}
```

内側から外の`taxRate`が問題なく使えています(結果に誤差が出ているのは、レッスン1-3で学んだ小数の誤差です)。

逆向きは通りません。

```ts
{
  const price = 300;
}

console.log(price);
// エラー: Cannot find name 'price'.
```

共通で使うものは外に、その場限りのものは中に。置き場所の判断はこの規則で決まります。

## 2-1-3 内側で同じ名前を宣言すると外が隠れる

> **内側で同じ名前を宣言すると、そのブロックの中では外の変数が隠れる**

この現象を**シャドーイング**(影で覆う)と呼びます。上書きではなく、別物が手前に立っているイメージです。

```ts
const status = "受付中";

{
  const status = "発送済み"; // 別の変数として作られる
  console.log(status); // => "発送済み"
}

console.log(status); // => "受付中" ← 変わっていない
```

中と外で同じ名前ですが、実体は別の変数です。ブロックを抜けると外のものが再び見えます。

「代入したのに変わっていない」という不可解なバグの正体がこれです。エラーが出ないので、知らないと原因にたどり着けません。

対処は単純で、**そもそも同じ名前にしない**ことです。内側の変数には、より具体的な名前を付けてください(`status`と`newStatus`、`price`と`discountedPrice`など)。
