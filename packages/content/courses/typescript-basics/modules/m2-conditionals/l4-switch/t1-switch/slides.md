## なぜ必要か

- `else if`を4つも5つも重ねると、同じ変数名が何度も出てきて読みにくい
- 「この値がどの候補に当たるか」という形の分岐は業務に多い

<!-- ノート: つかみ。注文の状態、会員ランク、支払い方法。1つの値で多方向に分かれる分岐は実務の定番。それ専用の書き方があると位置づける。 -->

---

## 結論

**`switch`は1つの値を複数の候補と上から順に比べる**

- `case` — 候補。等価比較(`===`)で判定される
- `break` — その`case`で処理を終える合図
- `default` — どの`case`にも当たらなかったとき

<!-- ノート: 結論を先に言い切る。case、break、defaultの3語をここで定義する。判定に使われるのは2-2-1で学んだ===と同じ厳密な比較だと接続する。 -->

---

## 最小のコード

```ts
const status = "shipped";

switch (status) {
  case "received":
    console.log("受付済み");
    break;
  case "shipped":
    console.log("発送済み");
    break;
  default:
    console.log("不明な状態");
}
// => "発送済み"
```

<!-- ノート: statusの値を書き換えて、通る道が変わることを実演する。else ifで書いた場合と見比べると、変数名が1回しか出てこない読みやすさが伝わる。 -->

---

## 使い分けの目安

- **1つの値を、決まった候補と比べる** → `switch`
- **条件がそれぞれ違う(範囲や複数条件)** → `if` / `else if`

<!-- ノート: 対比枠。2-2-3の会員ランクのような「範囲」の分岐はswitchでは書きにくい。逆に状態名のような「候補」ならswitchが読みやすい。道具の使い分けとして整理する。 -->
