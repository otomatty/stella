# 2-2-3
# elseとelse if

TypeScript入門研修 — Module 2 / レッスン2-2

<!-- ノート: ifだけでは「そうでないとき」を書けません。分岐を完成させる2つの道具を押さえます。 -->

---

## なぜ必要か

- 「在庫があれば受注、なければ入荷待ちの案内」のように、両方の道が要る
- 会員ランクのように、3つ以上に分かれることもある

<!-- ノート: つかみ。実務の分岐はほとんどが2つ以上の道を持つ。ifだけを重ねて書くこともできるが、読みにくく漏れも起きやすい。 -->

---

## 結論

**`else`は条件がfalseのとき、`else if`は別の条件を続けて試すときに使う**

- 上から順に判定し、**最初に当たった1つだけ**が実行される

<!-- ノート: 結論を先に言い切る。「最初に当たった1つだけ」がいちばん重要。上から順に見て、当たった時点で残りは見ない。この順序性が次のスライドの落とし穴につながる。 -->

---

## 最小のコード

```ts
const point = 250;

if (point >= 500) {
  console.log("ゴールド会員");
} else if (point >= 100) {
  console.log("シルバー会員");
} else {
  console.log("一般会員");
}
// => "シルバー会員"
```

<!-- ノート: 250は「500以上」ではないので次へ、「100以上」に当たるのでシルバーで確定。3つ目のelseは見に行かない。値を変えて全部の道を通してみせると理解が定着する。 -->

---

## よくある間違い: 条件の順序

```ts
if (point >= 100) {
  console.log("シルバー会員"); // 500点でもここに入ってしまう
} else if (point >= 500) {
  console.log("ゴールド会員"); // 永遠に実行されない
}
```

- 範囲が広い条件を先に書くと、後ろが届かなくなる

<!-- ノート: 対比枠。エラーは出ないので発見しにくい静かなバグ。範囲で分岐するときは、狭い条件から順に書く。これは実務のレビューでもよく指摘される点。 -->
