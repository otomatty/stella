# つなげて書く

TypeScript入門研修 — Module 4 / レッスン4-5

<!-- ノート: レッスン4-5の最後です。mapとfilterの性質から自然に導かれる書き方を1つ押さえます。 -->

---

## なぜ必要か

- 「5000円以上の注文だけを、税込価格にする」のように2段階の処理は多い
- 途中結果に名前を付けるほどでもない場面がある

<!-- ノート: つかみ。中間の変数を作ってもよいが、名前を考える手間が増える。使い捨ての変数が並ぶとかえって読みにくい。 -->

---

## 結論

**`map`も`filter`も新しい配列を返すので、ドットでつなげて書ける**

<!-- ノート: 結論を先に言い切る。戻り値が配列だから、その配列に対してまた配列の操作ができる。新しい仕組みではなく、4-5-2と4-5-3の性質から導かれる当然の結果。 -->

---

## 最小のコード

```ts
const prices = [3000, 8000, 1200, 12000];

const result = prices
  .filter((price) => price >= 5000)
  .map((price) => price * 1.1);

console.log(result); // => [8800.000000000002, 13200.000000000002]
```

<!-- ノート: 改行してドットを行頭に置くと読みやすい。上から順に「絞って、変換して」と日本語で読み下せる。filterを先に置くと、mapで処理する件数が減るので効率もよい。 -->

---

## 順序を間違えると結果が変わる

```ts
const result = prices
  .map((price) => price * 1.1)
  .filter((price) => price >= 5000);
// 税込にしてから絞るので、5500円未満だった商品も残る
```

<!-- ノート: 対比枠。同じ2つの操作でも順序で結果が変わる。エラーにはならないので、意図した順序になっているかは自分で確かめるしかない。3〜4個つなげると読めなくなるので、その場合は途中に変数を置く。 -->
