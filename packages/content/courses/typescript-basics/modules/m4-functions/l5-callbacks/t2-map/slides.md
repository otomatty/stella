## なぜ必要か

- 「全商品の税込価格の配列がほしい」のような変換は頻出
- `for-of`だと、空の配列を用意して`push`する定型文を毎回書くことになる

<!-- ノート: つかみ。3-2-3のfor-ofと3-2-1のpushを組み合わせれば書けるが、毎回4〜5行の同じ形になる。その定型文をなくす道具。 -->

---

## 結論

**`map`は、全要素を変換した新しい配列を作る**

- コールバックが「1要素をどう変換するか」を決める
- 元の配列は変わらない

<!-- ノート: 結論を先に言い切る。mapは「対応づける」の意味。要素数は変わらず、中身だけが変換される。元の配列を書き換えない点も重要で、3-2-1の破壊的な変更とは対照的。 -->

---

## 最小のコード

```ts
const prices = [1000, 500, 300];

const taxIncluded = prices.map((price) => price * 1.1);

console.log(taxIncluded); // => [1100, 550, 330.00000000000006]
console.log(prices); // => [1000, 500, 300] (元は変わらない)
```

<!-- ノート: かっこの中にアロー関数を直接書いている。これが4-5-1で学んだコールバック。4-2-2で省略記法を学んでおいたのは、この形を短く書くため。誤差が出ているのは1-3-3の小数の誤差。 -->
