# 4-4-2
# 戻り値の型を書く理由

TypeScript入門研修 — Module 4 / レッスン4-4

<!-- ノート: 戻り値の型は推論できます。レッスン1-2の方針なら省略してよいはずです。ここだけ例外にしている理由を説明します。 -->

---

## なぜ必要か

- 1-2-5で「推論できるなら任せる」と決めた
- 戻り値の型は推論できる。なのに書くのはなぜか

<!-- ノート: つかみ。既に決めた方針と矛盾して見えるので、ここを説明せずに進むと「言うことが変わった」と受け取られる。理由を1つだけ示す。 -->

---

## 結論

**戻り値の型を書いておくと、実装ミスを関数の中で止められる**

- 書かないと、間違いが呼び出し側まで運ばれてしまう

<!-- ノート: 結論を先に言い切る。変数の推論と決定的に違うのはここ。変数は間違えてもその場で止まるが、関数は間違った型のまま外へ広がる。 -->

---

## 書かない場合: 間違いが外へ漏れる

```ts
const calcTax = (price: number) => {
  return `${price * 0.1}`; // 文字列を返してしまった
};

const tax: number = calcTax(1000);
// エラー: Type 'string' is not assignable to type 'number'.
```

<!-- ノート: 関数の中は素通りして、呼び出し側でエラーになる。しかも原因は関数の中にあるので、エラーの出た場所と直す場所が離れてしまう。呼び出し箇所が10か所あれば10か所で赤くなる。 -->

---

## 書いた場合: その場で止まる

```ts
const calcTax = (price: number): number => {
  return `${price * 0.1}`;
  // エラー: Type 'string' is not assignable to type 'number'.
};
```

<!-- ノート: 対比枠。同じ間違いが、関数の中で止まる。エラーの出た場所と直す場所が一致するので、原因がすぐ分かる。戻り値の型は「この関数はこれを返す」という宣言であり、仕様書としても働く。 -->

---

<!-- _class: summary -->

## まとめ

**戻り値の型を書いておくと、実装ミスを関数の中で止められる**

<!-- ノート: 結論の再掲だけ。関数の入口と出口の型が決まっているなら、それ自体を型として書けるのでは、と引きを作って締める。 -->
