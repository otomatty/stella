## なぜ必要か

- 型エイリアスと書き方が似ているので、混同しやすい
- 初期値をめぐるエラーで最初につまずく

<!-- ノート: つかみ。3-3-3で学んだオブジェクトの型注釈と見た目が近い。違いを先に整理しておくと混乱しない。 -->

---

## 結論

**クラスのプロパティは、名前と型を並べて宣言する**

```
class クラス名 {
  プロパティ名: 型;
}
```

<!-- ノート: 結論を先に言い切る。型エイリアスと違い、classの中に書く。区切りはセミコロン。初期値を書けば型推論も効く。 -->

---

## 最小のコード

```ts
class Product {
  name: string = "";
  price: number = 0;
}

const item = new Product();
item.price = 480;
console.log(item.price); // => 480
```

<!-- ノート: 型注釈と初期値の両方を書いた形。初期値があれば型注釈は省略でき、1-2-5の方針どおり推論に任せてよい。作ったあとの書き換えは3-3-2のドット記法と同じ。 -->

---

## 初期値がないとエラーになる

```ts
class Product {
  name: string;
  // エラー: Property 'name' has no initializer and is not
  // definitely assigned in the constructor.
}
```

<!-- ノート: 対比枠。初期値がないと、インスタンスを作った直後にundefinedが入ってしまう。それを防ぐためのチェック。メッセージの後半にconstructorとあるが、そこで値を入れる方法が次のトピック。 -->
