# オーバーライド

TypeScript入門 — Module 7 / レッスン7-3

## なぜ必要か

- あいさつ文は共通だが、プレミアム会員だけ特典を添えたい
- メソッド名を変えると、使う側が会員種別を意識することになる

<!-- ノート: つかみ。greetとgreetPremiumに分けると、呼び出す側で分岐が必要になる。同じ名前のまま中身だけ変えられれば、使う側は何も変えなくてよい。 -->

---

## 結論

**子クラスで同じ名前のメソッドを書くと、親の実装を上書きできる**

- この上書きをオーバーライドと呼ぶ

<!-- ノート: 結論を先に言い切る。オーバーライドを定義する。overrideは「上書きする」の意味。呼び出し側は同じ名前で呼ぶだけで、インスタンスの種類に応じた処理が動く。 -->

---

## 最小のコード

```ts
class Member {
  constructor(protected name: string) {}

  greet(): string {
    return `${this.name}さん、こんにちは`;
  }
}

class PremiumMember extends Member {
  greet(): string {
    return `${super.greet()} 特典があります`;
  }
}

console.log(new PremiumMember("田中").greet());
// => "田中さん、こんにちは 特典があります"
```

<!-- ノート: super.greet() で親の実装を呼び出し、その結果に足している。丸ごと書き換えることも、親を再利用して足すこともできる。7-3-2のsuper()はコンストラクタ呼び出し、super.メソッド()はメソッド呼び出しで、形が違う点も指摘する。 -->

---

## ハマりどころ: メソッド名のタイポ

```ts
class PremiumMember extends Member {
  greet2(): string { // 上書きしたつもりが別のメソッド
    return "特典があります";
  }
}
```

<!-- ノート: 対比枠。名前が違えばオーバーライドにならず、親の実装がそのまま使われる。エラーにならないので気づきにくい。tsconfigのnoImplicitOverrideという設定でoverrideキーワードを必須にできるが、Module 9で触れる程度でよい。 -->
