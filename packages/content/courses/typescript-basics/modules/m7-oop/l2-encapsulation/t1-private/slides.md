## なぜ必要か

- 実務あるある: 在庫数がマイナスになっている
- 外から誰でも書き換えられると、どこで壊れたのか追えない

<!-- ノート: つかみ。7-1のままだと item.stock = -5 が通ってしまう。2-1-1で学んだ「使う範囲が狭いほど影響も狭い」という考え方が、ここでも効く。 -->

---

## 結論

**`private`を付けたプロパティは、クラスの外から触れなくなる**

- カプセル化 = データを隠し、決まった窓口だけを公開すること
- アクセス修飾子 = 公開範囲を指定するキーワード

<!-- ノート: 結論を先に言い切る。3語を定義する。publicは「公開」で、何も書かないときの既定。privateは「非公開」。 -->

---

## 最小のコード

```ts
class Stock {
  private count = 0;

  add(n: number): void {
    this.count = this.count + n;
  }
}

const stock = new Stock();
stock.add(5); // OK
stock.count = -100;
// エラー: Property 'count' is private and only
// accessible within class 'Stock'.
```

<!-- ノート: メソッド経由なら操作でき、直接の書き換えは弾かれる。addの中に「マイナスは受け付けない」といった検査を書けば、不正な状態を作れなくなる。それが窓口を1つにする価値。 -->
