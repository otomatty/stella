# 7-4-1
# インターフェースとは

TypeScript入門 — Module 7 / レッスン7-4

<!-- ノート: Module 7の最後のレッスンです。7-3-5の抽象クラスより軽い、約束だけを表す仕組みを扱います。 -->

---

## なぜ必要か

- 抽象クラスは継承なので、1つしか親を持てない
- 実装を1つも持たないなら、クラスである必要がない

<!-- ノート: つかみ。「面積を求められる」「名前を持つ」といった性質を複数まとめたいことがある。継承だと1つしか選べない。 -->

---

## 結論

**インターフェースは、実装を持たない「形の約束」を書くもの**

```
interface 名前 {
  プロパティ名: 型;
  メソッド名(引数: 型): 戻り値の型;
}
```

<!-- ノート: 結論を先に言い切る。interfaceを定義する。3-4-1の型エイリアスとよく似ているが、書き方が違う(イコールを書かない)。中身は一切書かず、名前と型だけ。 -->

---

## 最小のコード

```ts
interface Shape {
  name: string;
  area(): number;
}

const circle: Shape = {
  name: "円",
  area: () => 3.14 * 2 * 2,
};

console.log(circle.area()); // => 12.56
```

<!-- ノート: クラスを作らなくても、この形を満たすオブジェクトなら代入できる。5-5-2で学んだ構造的型付けが効いている。型エイリアスでほぼ同じことが書ける点も、後のトピックで整理する。 -->

---

## 抽象クラスとの違い

| | 実装を持てる | いくつ適用できる |
| --- | --- | --- |
| 抽象クラス | 持てる | 1つだけ |
| インターフェース | **持てない** | **いくつでも** |

<!-- ノート: 対比枠。共通の処理も持たせたいなら抽象クラス、約束だけなら軽いインターフェース。実務ではインターフェースのほうが出番が多い。 -->
