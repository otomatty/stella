# レッスン9-1 ローカル環境

## このレッスンの目標

- [ ] WindowsにNode.jsを入れ、ターミナルで確認できる
- [ ] VS Codeでフォルダを開き、型のチェックを見られる
- [ ] `tsc`でコンパイルし、生成された`.js`を実行できる

## 9-1-1 Node.js

> **Node.jsは、ブラウザの外でJavaScriptを動かすための実行環境**

Playgroundは1ファイルしか扱えませんが、実務のプロジェクトは何十何百というファイルでできています。レッスン0-2で「環境構築は後回し」と決めたのは、言語の学習に集中してもらうためでした。ここまで来たので、道具を揃えます。

- **ターミナル** — 文字でコンピューターに命令する画面
- **npm** — 部品を導入するための道具(Node.jsに同梱)

JavaScriptはもともとブラウザ専用でしたが、Node.jsの登場で外でも動くようになりました。TypeScriptのコンパイラー自体もNode.jsの上で動きます。ブラウザは画面向けで、ファイル操作や開発ツールの実行には向きません。

## 9-1-2 インストールを確認する

> **インストール後は、ターミナルで`node -v`と`npm -v`を確認する**

公式サイトから**LTS版**(Long Term Support = 長く保守される安定版)を入れます。入れたあとは、必ず確認コマンドを実行してください。

### Windowsでの入れ方(概要)

1. [Node.js公式サイト](https://nodejs.org/ja) を開く
2. **LTS** と書いてあるボタンからインストーラーをダウンロードする
3. ダウンロードした `.msi` を実行し、画面の指示どおり進める(既定のままでよい)
4. 終わったら、開いていたターミナルを**いったん閉じて**開き直す

Windowsでは「スタート」から **コマンドプロンプト**(`cmd`)を開きます。PowerShellでも確認できますが、実行ポリシーで`npm`が止まることがあるため、本研修ではコマンドプロンプトを正とします(あとでVS Codeの中のターミナルでも同じ確認ができます)。

```bash
node -v
npm -v
```

両方バージョンが表示されれば成功です。数字そのものは環境によって違うので気にしなくて構いません。

**よくあるつまずきは、インストール後にターミナルを開き直していないことです。** 「command not found」や「認識されていません」は、まだ認識されていないだけのことが多くあります。開き直しても駄目なら、いったんPCを再起動してからもう一度試してください。PowerShellで「running scripts is disabled」と出たら、コマンドプロンプトに切り替えてください。

## 9-1-3 VS Code

> **VS Codeは、型のチェック結果をその場で見せてくれるエディター**

メモ帳でも書けますが、型のチェックが見えません。レッスン0-2で学んだ「赤い波線を読む」が手元でできないと、学習効率が落ちます。

**エディター**とはコードを書くための専用ソフトです。VS CodeにはTypeScriptの機能が最初から組み込まれています(どちらもMicrosoft製で相性がよく、無料で使えます)。

[VS Code公式サイト](https://code.visualstudio.com/) からWindows用を入れます。入れたら、作業用フォルダを「フォルダーを開く」で開いてください。ファイル単体ではなく、**フォルダごと**開くのがポイントです。

最初に確認することは2つです。

- ファイルを保存すると、型エラーに赤い波線が出る
- 変数にマウスカーソルを乗せると、推論された型が表示される

Playgroundでやっていた確認が、そのまま手元でできます。特に**カーソルを乗せて型を見る操作**は、学習でも実務でも最も使う機能です。

補完も強力になります。ドットを打つと使えるプロパティやメソッドの候補が出ます。型が分かっているから候補も正確で、タイポが減ります。

## 9-1-4 TypeScriptを入れる

> **TypeScriptは、プロジェクトごとにnpmで入れて使う**

PC全体に1つ入れるやり方もありますが、実務ではプロジェクトごとに版が違います。本研修では、**このフォルダ用**に入れる方法だけを使います。

VS Codeで作業用フォルダを開いた状態で、メニューの「ターミナル」→「新しいターミナル」を開きます。既定がPowerShellのときは、ターミナル右上の「+」の横から **Command Prompt** を選んでください。

そのターミナルで、次を実行します。

```bash
npm init -y
npm install --save-dev typescript
```

- `npm init -y` — このフォルダをプロジェクトとして扱う準備
- `--save-dev` — 開発のときだけ使う部品として記録する
- **`npx`** — このフォルダに入れたコマンドを実行する道具(次のトピックで使います)

設定ファイルの中身の読み方はレッスン9-2で扱います。いまは「入れられた」ことが分かれば十分です。

## 9-1-5 tscでコンパイルする

> **`tsc`はTypeScriptをJavaScriptに変換するコマンド**

レッスン0-1で学んだ「TypeScriptはJavaScriptに変換されてから動く」を、自分の手で実行します。

`tsc`は TypeScript Compiler の略で、0-1-2で定義した「コンパイラー」の実体です。

まずVS Codeで `index.ts` を新規作成し、次を書いて保存します。

```ts
const greet = (name: string): string => `${name}さん、こんにちは`;

console.log(greet("田中"));
```

続けて、同じフォルダのターミナル(Command Prompt)で次を実行します。

```bash
npx tsc index.ts
```

`index.ts`から`index.js`が作られます。中身を開くと、**型注釈が消えている**ことを確認できます。

```bash
node index.js
```

「田中さん、こんにちは」と表示されれば成功です。

**書く(.ts) → 変換する(tsc) → 動かす(node)** という3ステップです。Playgroundでは1つのボタンに隠れていた流れが、手元では明示的になります。

毎回2つのコマンドを打つのは面倒なので、実務では設定ファイルで簡略化します。それが次のレッスン以降の話です。
