# 9-2-2
# 名前付きとデフォルト

TypeScript入門 — Module 9 / レッスン9-2

<!-- ノート: exportの2つ目の書き方です。他人のコードで必ず見かけるので、読めるようにしておきます。 -->

---

## なぜ必要か

- `import React from "react"` のように、波かっこのない`import`を見かける
- 書き方が2つあると、どちらを使うか毎回迷う

<!-- ノート: つかみ。1-1-3のconstファースト、4-2-3のアロー関数と同じ構図。読めるようにしたうえで、基準を1つ決める。 -->

---

## 結論

**本研修は名前付きエクスポートを基本にする。名前が固定されるため**

- 名前付き = `export const 名前`。`import { 名前 }` で取り込む
- デフォルト = `export default`。`import 好きな名前` で取り込む

<!-- ノート: 結論を先に言い切る。2語を定義する。デフォルトは1ファイルに1つだけ置ける。取り込む側が名前を自由に決められるのが特徴で、それが利点でもあり欠点でもある。 -->

---

## 書き方の違い

```ts
// tax.ts
export const calcTax = (p: number): number => p * 0.1; // 名前付き
export default calcTax; // デフォルト
```

```ts
// main.ts
import { calcTax } from "./tax"; // 名前が固定
import anyName from "./tax"; // 好きな名前を付けられる
```

<!-- ノート: 名前付きは波かっこが要る。デフォルトは要らない。この違いで見分けられる。波かっこの有無を取り違えるのが、importで最も多いエラー。 -->

---

## 名前付きを選ぶ理由

- 名前がファイルをまたいで揃うので、検索できる
- タイポは実行前にエラーになる(存在しない名前は取り込めない)

<!-- ノート: 対比枠。デフォルトだと、同じものが人によって違う名前で取り込まれ、検索で追えなくなる。ライブラリー側がデフォルトで公開している場合は、そのまま従う。配属先の規約が最優先である点も添える。 -->
