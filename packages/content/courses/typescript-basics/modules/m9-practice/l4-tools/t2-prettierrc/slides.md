# 9-4-2
# 設定は最小限にする

TypeScript入門 — Module 9 / レッスン9-4

<!-- ノート: 設定ファイルの話ですが、伝えたいのは「設定しない」という方針です。 -->

---

## なぜ必要か

- 設定できると分かると、細かく調整したくなる
- 調整項目が増えるほど、チームで議論する種も増える

<!-- ノート: つかみ。9-4-1で「議論をなくす道具」と言ったのに、設定で議論が生まれては本末転倒。道具の思想を理解しておく必要がある。 -->

---

## 結論

**Prettierの設定項目は意図的に少ない。既定のまま使うのが基本**

- 「議論を終わらせる」ことが道具の目的
- 選べる余地を減らすことで、それを実現している

<!-- ノート: 結論を先に言い切る。他の整形ツールは設定項目が数百あったが、Prettierは意図的に絞っている。これは欠陥ではなく設計思想。 -->

---

## 設定ファイル

```json
// .prettierrc
{
  "semi": true,
  "singleQuote": false
}
```

- プロジェクトの根元に置く
- 書かなければ既定値が使われる

<!-- ノート: semiはセミコロンの有無、singleQuoteはシングルクォートを使うか。どちらも既定と同じ値なので、実際には書かなくてよい。本研修のダブルクォート方針も既定のまま。 -->

---

## 設定より大事なこと

- **プロジェクト全体に一度かける**(部分的だと差分が汚れる)
- チームで**同じバージョン**を使う(`package.json`で固定される)

<!-- ノート: 対比枠。途中から導入すると、整形だけの巨大な差分が1回出る。それを本来の変更と混ぜないよう、単独でコミットするのが定石。バージョンが違うと整形結果が変わり、無限に差分が出る。 -->
