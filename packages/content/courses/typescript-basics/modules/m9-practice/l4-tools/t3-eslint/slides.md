# ESLint

TypeScript入門研修 — Module 9 / レッスン9-4

<!-- ノート: もう1つの道具です。Prettierと混同されやすいので、役割の違いをはっきりさせます。 -->

---

## なぜ必要か

- 見た目が整っていても、危ない書き方は残る
- 型チェックでは拾えない問題がある(使っていない変数、`==`の使用など)

<!-- ノート: つかみ。コンパイラーは型の整合性しか見ない。「動くけれど良くない書き方」は別の道具の仕事。 -->

---

## 結論

**ESLintは書き方の問題を指摘する。Prettierとは役割が違う**

- リンター = コードの品質上の問題を検出する道具

<!-- ノート: 結論を先に言い切る。リンターを定義する。lintは「糸くず」の意味で、コードに紛れた小さな問題を取り除くイメージ。 -->

---

## 見つけてくれる例

```ts
const total = 100;
const tota1 = 200; // 使っていない(タイポ)
// warning: 'tota1' is assigned a value but never used.

if (a == b) { }
// error: Expected '===' and instead saw '=='.
```

<!-- ノート: 対比枠。どちらも型としては正しいのでコンパイラーは通す。2-2-1で「常に===を使う」と決めたが、それを機械に守らせられる。--fix を付ければ自動修正できるものもある。 -->
