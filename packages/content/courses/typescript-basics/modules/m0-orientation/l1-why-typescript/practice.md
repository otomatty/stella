# レッスン0-1 演習 — なぜTypeScriptを学ぶのか

対象トピック: 0-1-1 〜 0-1-3

このレッスンはコードを書く前の回です。演習は読んで考える問題が中心になります。

## ハンズオン

[TypeScript Playground](https://www.typescriptlang.org/ja/play) を開いて、次のコードを入力してください。

```ts
const price = "300";
const total = price + 50;
console.log(total);
```

1. 実行結果を予想してから「Run」を押し、答え合わせをしましょう
2. 1行目を `const price: number = "300";` に書き換えて、赤い波線が出ることを確認しましょう
3. 右側の「.JS」タブを開いて、型注釈が消えていることを確認しましょう

## 演習問題

### 問1(基本)

次のコードは、合計金額として`350`を表示したいのに、そうなりません。何が表示されるかを予想し、その理由を説明してください。

```js
const price = "300";
const shipping = 50;
console.log(price + shipping);
```

### 問2(基本)

同じ間違いをTypeScriptで書いた場合、どの段階で気づけますか。理由も含めて説明してください。

```ts
const price: number = "300";
```

### 問3(応用)

「型は変換時に消える」という性質から、次のうち**TypeScriptにできないこと**はどれですか。理由も説明してください。

- A. コードを書いている最中に、型の取り違えを指摘する
- B. 実行中に外部から届いたデータが、想定した型かどうかを自動で検査する
- C. 変換後のJavaScriptを、ブラウザで動かす

## 解答例と解説

<details>
<summary>問1の解答例</summary>

`"30050"` と表示されます。

`"300"`はダブルクォートで囲まれているため、数値ではなく文字列です。JavaScriptの`+`は、相手が文字列だと足し算ではなく「連結」として働きます。そのため`"300"`と`50`がつながって`"30050"`になります。

エラーが出ないため、画面を見るまで気づけません。これが「気づくのが遅いバグ」の典型です。

</details>

<details>
<summary>問2の解答例</summary>

**書いている最中**に気づけます。

`: number`と宣言してあるので、文字列`"300"`を入れようとした時点でコンパイラーが「Type 'string' is not assignable to type 'number'.」というエラーを出します。実行する必要はありません。

エディター上で赤い波線が出るのは、まだ一度もコードを動かしていない段階です。ここがTypeScriptの中心的な価値です。

</details>

<details>
<summary>問3の解答例</summary>

**B** です。

型はコンパイラーへの指示であり、変換後のJavaScriptには残りません。そのため、実行中に届いたデータを型が自動で検査してくれることはありません。

外部データの検査が必要な場合は、自分でチェックするコードを書きます(その書き方はModule 2以降で少しずつ学びます)。

AとCはどちらもTypeScriptにできることです。

</details>

## 確認クイズ

### Q1. TypeScriptがJavaScriptに対して追加したものは何ですか?

- A. 型
- B. 実行速度
- C. 新しいブラウザ

<details>
<summary>答え</summary>

**A** — TypeScriptはJavaScriptに型を書けるようにした言語です。実行速度は変わりません。

</details>

### Q2. TypeScriptで書いたコードは、そのままブラウザで動きますか?

- A. そのまま動く
- B. JavaScriptに変換してから動く
- C. 専用のブラウザが必要

<details>
<summary>答え</summary>

**B** — コンパイルによってJavaScriptに変換されてから実行されます。

</details>

### Q3. 型が守ってくれるのはどの段階ですか?

- A. コードを書いている段階(実行前)
- B. プログラムを実行している最中
- C. 両方

<details>
<summary>答え</summary>

**A** — 型は変換時に消えるため、実行中には残りません。開発中に間違いを見つけるための道具です。

</details>

### Q4. バグに気づくタイミングとして、直す手間がいちばん小さいのはどれですか?

- A. 本番で顧客が見つけたとき
- B. テストで動かしたとき
- C. 書いている最中

<details>
<summary>答え</summary>

**C** — 気づくのが早いほど手間は小さくなります。TypeScriptはこのタイミングを最も早い側へ寄せる道具です。

</details>
