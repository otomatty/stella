# 6-1-4
# extendsで制約を付ける

TypeScript入門 — Module 6 / レッスン6-1

<!-- ノート: レッスン6-1の最後です。ジェネリクスを実用にするための、最後の一手を押さえます。 -->

---

## なぜ必要か

- `T`は「どんな型か分からない」ので、関数の中で何もできない
- 5-3-2の`unknown`と同じ制約に、また出会うことになる

<!-- ノート: つかみ。Tのままでは.lengthも読めない。何でも入る型は、そのままでは何もできない。この構図はunknownで一度学んでいるので、理解が速い。 -->

---

## 結論

**`T extends 型`と書くと、`T`に入れられる型を限定できる**

- 限定する代わりに、関数の中でその性質を使える

<!-- ノート: 結論を先に言い切る。制約を付けることは自由を減らすことだが、その見返りに中でできることが増える。トレードオフとして説明すると納得しやすい。 -->

---

## 制約なしだと使えない

```ts
const longer = <T>(a: T, b: T): T => {
  return a.length > b.length ? a : b;
  // エラー: Property 'length' does not exist on type 'T'.
};
```

<!-- ノート: Tには何でも入るので、lengthがあるとは限らない。5-1-1のユニオン型、5-3-2のunknownと同じ理屈。コンパイラーは保証できないことを許さない。 -->

---

## 制約を付けると使える

```ts
const longer = <T extends { length: number }>(a: T, b: T): T => {
  return a.length > b.length ? a : b;
};

console.log(longer("コーヒー", "紅茶")); // => "コーヒー"
console.log(longer([1, 2, 3], [1])); // => [1, 2, 3]
```

<!-- ノート: 対比枠。「lengthを持つ型なら何でも」という制約。文字列も配列もlengthを持つので通る。戻り値はTのままなので、渡した型の情報が失われない点も強調する。 -->
