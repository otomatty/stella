# 6-3-3
# Omit

TypeScript入門 — Module 6 / レッスン6-3

<!-- ノート: Pickの裏返しです。使い分けの基準と、1つだけある落とし穴を押さえます。 -->

---

## なぜ必要か

- 「IDだけを除いた型」のように、除く項目のほうが少ない場面がある
- `Pick`で残りを全部並べると、項目が増えるたびに書き足すことになる

<!-- ノート: つかみ。新規登録の入力型は「IDと作成日時以外の全部」。Pickで書くと、項目を足すたびにPickの側も直す必要がある。 -->

---

## 結論

**`Omit<T, K>`は、`T`から指定したプロパティを除いた型を作る**

<!-- ノート: 結論を先に言い切る。omitは「省く」の意味。書き方はPickとまったく同じで、意味だけが逆。 -->

---

## 最小のコード

```ts
type User = {
  id: string;
  name: string;
  age: number;
};

type NewUser = Omit<User, "id">;
// { name: string; age: number }
```

- `User`に項目を足すと、`NewUser`にも自動で増える

<!-- ノート: Pickで書くと "name" | "age" と並べることになり、項目が増えるたびに書き足しが必要。Omitなら追従する。残す項目が多いならOmitが有利。 -->

---

## 落とし穴: タイポを検出しない

```ts
type NewUser = Omit<User, "idd">; // タイポでもエラーにならない
// { id: string; name: string; age: number }
```

<!-- ノート: 対比枠。Pickは存在しないキーを書くとエラーになるが、Omitはならない(「存在しないものを除いた」だけなので成立してしまう)。除いたつもりが残っている、という静かなバグになる。結果の型を必ず確認する習慣を勧める。 -->

---
