# レッスン1-4 演習 — コミットする

対象トピック: 1-4-1 〜 1-4-4

## ハンズオン

前のレッスンの続きです。`~/git-practice` のステージングエリアに practice.txt と memo.txt の下書きが載った状態から、はじめてのコミットを作ります。

1. VS Codeのターミナルで現状を確かめます

    ```bash
    cd ~/git-practice
    git status
    ```

    2つのファイルが「次の記録に入る」欄に載っていることを確認します(載っていなければ `git add .` で載せ直してください)
2. はじめてのコミットを作ります

    ```bash
    git commit -m "練習用のメモと作業メモを追加"
    git status
    ```

    status の表示が静かになれば成功です。下書きが記録に変わり、ステージングエリアが空きました
3. 記録されたことを自分の目で確かめます

    ```bash
    git log
    ```

    ハッシュ・自分の名乗り・日時・コミットメッセージが表示されます。名乗りがレッスン1-1で設定したとおりになっているかも見てください(表示が長ければ q で閉じます)
4. 2つ目のコミットを作ります。VS Codeで practice.txt に1行追記して保存し、2段階を最初から回します

    ```bash
    git status
    git add practice.txt
    git commit -m "メモに練習の記録を1行追記"
    ```

5. もう一度 log で確かめます

    ```bash
    git log
    ```

    コミットが2件に増えています。それぞれ別のハッシュが付いていることを確かめ、どちらかの先頭7桁をメモ帳に書き写してみましょう。それだけでそのコミットを指し示せます

「編集 → add → commit → log で確認」。この一連の流れが、これからの研修すべての土台になります。

## 演習問題

### 問1(基本)

ステージングエリアに price-list.txt が載っています。「価格表を更新」というメッセージを付けて記録を確定するコマンドを書いてください。

### 問2(基本)

「コミットは差分ではなくスナップショット」とはどういう意味ですか。「写真」という言葉を使って説明してください。

### 問3(応用)

チームの先輩に「さっきのコミットどれ?」と聞かれました。コミットを正確に伝えるには何を伝えればよいですか。また、それは何のコマンドで調べられますか。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

```bash
git commit -m "価格表を更新"
```

-m がメッセージをその場で付けるオプションです。記録されるのはステージングエリアに載っていた分だけ、という点も思い出しておきましょう。

</details>

<details>
<summary>問2の解答例</summary>

コミットには「変えた部分のメモ」ではなく、その時点の全ファイルを写した「全体の写真」が入っている、という意味です。

触っていないファイルまで含めた全体の状態を持つので、コミットを1つ選べばその時点の全体がそのまま手に入ります。これが「履歴があれば戻れる」を支えています。

</details>

<details>
<summary>問3の解答例</summary>

コミットのID(ハッシュ)の先頭7桁を伝えます。ハッシュは git log で調べられます。

「3f2a1c9 の件です」のように伝えれば、相手も同じコミットを正確に見られます。40桁全部を伝える必要はありません。

</details>

## 確認クイズ

### Q1. ステージングエリアの内容を「会員一覧を修正」というメッセージ付きで記録するコマンドはどれですか。

- A. git commit -m "会員一覧を修正"
- B. git add -m "会員一覧を修正"
- C. git commit "会員一覧を修正" -status

<details>
<summary>答え</summary>

**A** — git commit -m "メッセージ" で記録が1つ増えます。-m はメッセージをその場で付けるオプションです。

</details>

### Q2. git commit が記録する内容として正しいものはどれですか。

- A. 作業フォルダにあるすべての変更(add していないものも含む)
- B. ステージングエリアに載っていた分だけ
- C. 最後に保存したファイル1つだけ

<details>
<summary>答え</summary>

**B** — commit が確定するのはステージングエリアの下書きだけです。add していない変更は記録に入りません。

</details>

### Q3. コミットの中身の説明として正しいものはどれですか。

- A. 変えた部分のメモだけが入っている
- B. その時点のプロジェクト全体のスナップショットが入っている
- C. コミットメッセージだけが入っている

<details>
<summary>答え</summary>

**B** — コミットは差分ではなく、触っていないファイルも含めた全体の写真(スナップショット)です。だから1つ選べば全体がその時点の状態で手に入ります。

</details>

### Q4. コミットのID(ハッシュ)の説明として正しいものはどれですか。

- A. 自分で好きな番号を付ける必要がある
- B. 自動で付く英数字のIDで、普段は先頭7桁で指し示せる
- C. 同じリポジトリのコミットにはすべて同じIDが付く

<details>
<summary>答え</summary>

**B** — ハッシュは中身から自動で計算される英数字のIDです。コミットごとに異なり、普段は先頭7桁で十分区別できます。

</details>

### Q5. コミットした後に「本当に記録が積み上がったか」を確かめるコマンドはどれですか。

- A. git log
- B. git init
- C. git add .

<details>
<summary>答え</summary>

**A** — git log でコミットの一覧(ハッシュ・名乗り・日時・メッセージ)を確かめられます。読み取り専用なのでいつ打っても安全です。

</details>
