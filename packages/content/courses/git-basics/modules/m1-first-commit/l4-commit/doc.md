# レッスン1-4 コミットする

## このレッスンの目標

- [ ] git commit -m "メッセージ" ではじめてのコミットを作れる
- [ ] コミットが「全体のスナップショット」であることと、ID(ハッシュ)の使い方を説明できる
- [ ] git log で記録が積み上がったことを確かめられる

## 1-4-1 git commitで記録する

> **git commit -m "メッセージ" で、記録が1つ増える**

前のレッスンで、ステージングエリアには下書きが載りました。しかしまだ記録は増えていません。下書きのままでは、後から戻ることも見返すこともできません。2段階の2段目、確定の操作が **commit** です。

```bash
git add practice.txt
git commit -m "練習用のメモを追加"
git status
```

- **-m** は「メッセージをその場で付ける」オプションです
- メッセージは「何をしたか」の一言で、**コミットメッセージ**と呼びます。後から履歴を読む人(未来の自分を含む)への説明文です
- 記録されるのは、ステージングエリアに載っていた分**だけ**です

commit の後に status を打つと、表示が静かになります。下書きが記録に変わり、ステージングエリアが空いた状態です。これがコミット1つ分の完了のサインです。

## 1-4-2 コミットはスナップショット

> **コミットは差分ではなく、その時点のプロジェクト全体のスナップショット**

作ったコミットの中には何が入っているのでしょうか。「変えた部分のメモだけ」と思われがちですが、違います。

- **スナップショット**とは「全ファイルをその瞬間ごと写した写真」のことです
- コミットは、触っていないファイルまで含めた**全体の状態**を持っています

```text
コミット1 = [practice.txt(1行)]                    ← 全体の写真
コミット2 = [practice.txt(2行), memo.txt(1行)]     ← 全体の写真
```

だからコミットを1つ選べば、その時点の全体がそのまま手に入ります。変更点のメモを順にたどって組み立て直す必要はありません。M0で学んだ「履歴があれば戻れる」が成り立つのは、コミットが全体写真だからです。この理解は、この先「戻る」操作を学ぶときの土台になります。

## 1-4-3 コミットにはIDが付く

> **コミットには英数字のID(ハッシュ)が付き、先頭7桁で指し示せる**

コミットが増えてくると、「どのコミットの話?」を正確に伝える手段が要ります。「昨日の3番目のやつ」では指し示せません。

そのための名前が、コミットに自動で付く英数字のID(**ハッシュ**)です。

```text
ID(全体): 3f2a1c9d8e7b6a5f4c3d2e1f0a9b8c7d6e5f4a3b
先頭7桁:  3f2a1c9   ← 普段はこれだけで指し示せる
```

- ハッシュはコミットの中身から自動で計算されます。自分で付ける必要はありません
- 全部で40桁ありますが、普段は**先頭7桁**で十分区別できます

チャットで「3f2a1c9 の件ですが」と書けば、相手も同じコミットを正確に見られます。長い英数字の羅列に見えても、実務で使うのは先頭だけです。

## 1-4-4 git logで確かめる

> **git log で、記録が積み上がったことを確かめられる**

コミットを作っても、フォルダの見た目は何も変わりません。「本当に記録されたのか」を自分の目で確かめる道具が **log** です。

```bash
git log
```

```text
commit 3f2a1c9d8e7b6a5f4c3d2e1f0a9b8c7d6e5f4a3b
Author: Sato Kenta <sato@example.com>
Date:   Wed Aug 19 10:00:00 2026

    練習用のメモを追加
```

- コミットの一覧が、ハッシュ・名乗り・日時・コミットメッセージ付きで並びます
- 何も変更しない読み取り専用のコマンドです。いつ打っても安全です
- 表示が長いときは **q** キーで閉じます(help と同じ操作です)

表示をよく見てください。ハッシュ(1-4-3)、レッスン1-1で設定した名乗り、日時、コミットメッセージ(1-4-1)。バージョン管理が約束していた「いつ・誰が・何を」が、本当に記録されていたことを確認できます。
