# レッスン1-3 ステージに載せる

## このレッスンの目標

- [ ] 記録が「add で選ぶ → commit で確定」の2段階だと説明できる
- [ ] git add でファイルを選び、status で結果を確かめられる
- [ ] ステージングエリアの役割と「add 後の編集は載らない」を説明できる

## 1-3-1 コミットは2段階

> **記録は2段階:add で選んで、commit で記録する**

作業中の変更は、記録したいものばかりとは限りません。試し書きのメモが混ざっていることもあります。「今回の記録に入れる変更」を選べないと、雑多で読み返せない記録になってしまいます。

そこでGitの記録は2段階に分かれています。

```text
変更したファイルたち
  │  git add   … 次の記録に入れる分を選ぶ
  ▼
選ばれた変更
  │  git commit … 選んだ分だけを記録にする
  ▼
コミットが1つ増える
```

- **add** = 次の記録に入れるものを選ぶ
- **commit** = 選んだ分を記録として確定し、コミットを1つ作る

提出書類を封筒に入れてから(=選んでから)ポストに出す(=確定する)、という日常の感覚に近い設計です。1段階ではなく2段階なのは、この「選ぶ」ためです。

## 1-3-2 git addで選ぶ

> **git add ファイル名 で、次の記録に入れるファイルを選ぶ**

前のレッスンで作った practice.txt は Untracked のまま、つまりGitはまだ見ていません。「このファイルを次の記録に入れる」と伝えるのが add です。

```bash
git add practice.txt
git status
```

status の表示で、practice.txt が「次の記録に入る」側の欄に移っていれば、選択が効いています。

- add した瞬間に記録が増えるのではありません。あくまで「選んだ」だけです
- add は成功しても何も表示しません。だからこそ、直後の status で確かめる癖をつけます
- 選ぶファイルを間違えても、まだ記録は増えていないので慌てなくて大丈夫です

## 1-3-3 ステージングエリアとは

> **ステージングエリアは「次のコミットの下書き」置き場**

add で選んだファイルはどこに置かれているのでしょうか。その場所の名前が **ステージングエリア** です。

```text
作業フォルダ            ステージングエリア        履歴
(編集はここで)   ─add→  (次のコミットの下書き) ─commit→ (確定した記録)
```

- add で選んだ変更がここに積まれて、commit を待ちます
- 「下書き」なので、確定前なら差し替えも追加もできます。メールの下書きフォルダのイメージです

変更は「作業フォルダ → ステージングエリア → 履歴」の順に進みます。この3つの場所の区別は、この先の研修全体で繰り返し出てくる土台です。status の表示も、実はこの3つのどこに何があるかを教えてくれています。

## 1-3-4 git add . は全部載せる

> **git add . は変更を全部載せる(載せる前に status で中身を確かめる)**

実務では1回の作業で何個ものファイルを変更します。1つずつ `git add ファイル名` と打つのは大変で、載せ忘れも出ます。そこで使えるのがこの書き方です。

```bash
git status   # 何が変わっているかを先に読む
git add .    # 納得してから、全部ステージングエリアへ
git status   # 意図どおり載ったかをもう一度読む
```

- 「.」は「今いるフォルダ以下ぜんぶ」という意味です
- 便利な分、載せるつもりのないファイルまで一緒に載る危険があります

だから **「status → add . → status」の3点セット**で打つのが安全な型です。確認なしの `git add .` は、試し書きのメモや一時ファイルが記録に紛れ込む定番の事故のもとです。

## 1-3-5 addの後の編集は載らない

> **add した後に編集した分は載っていない(もう一度 add する)**

add した後で「あ、ここも直そう」と編集を続けることはよくあります。ここに落とし穴があります。

```bash
git add practice.txt    # ここまでの内容が載る
# …この後、practice.txt にもう1行追記して保存…
git status              # → 同じファイルが「載った分」と
                        #   「載っていない分」の両方の欄に出る
```

- add は「その瞬間の内容」をステージングエリアに載せる操作です
- その後の編集は作業フォルダ側にあるだけで、下書きは古いままです

status に同じファイル名が2つの欄に出たら、それが目印です。壊れたのではなく、「載せた分」と「その後に直した分」が別々にあるだけです。直した分も記録に入れたいなら、もう一度 `git add practice.txt` を打ちます。

これを知らないまま記録を確定すると、「直したはずの1行が入っていない」という混乱につながります。add の後に編集したら、もう一度 add。これで下書きの準備は完成です。
