# git add . は全部載せる

Git入門研修 — Module 1 / レッスン1-3

<!-- ノート: 毎回ファイル名を打つのは大変、という不満に答える書き方です。便利さと注意をセットで渡します。 -->

---

## なぜ必要か

- 実務では、1回の作業で何個ものファイルを変更する
- 1つずつ git add ファイル名 と打っていくのは大変で、載せ忘れも出る

<!-- ノート: ファイル名指定のaddを覚えた直後だからこそ、まとめて載せたいという動機が自然に出ます。 -->

---

## 結論

**git add . は変更を全部載せる(載せる前に status で中身を確かめる)**

- 「.」は「今いるフォルダ以下ぜんぶ」という意味
- 便利な分、載せるつもりのないものまで載る危険がある

<!-- ノート: ドットの意味を一言で。全部載せは強力なので、必ず確認とセットで使う型にします。 -->

---

## 最小の例

```bash
git status   # 何が変わっているかを先に読む
git add .    # 納得してから、全部ステージングエリアへ
git status   # 意図どおり載ったかをもう一度読む
```

- 「status → add . → status」の3点セットで打つのが安全な型

<!-- ノート: 前後をstatusで挟む型を体に入れます。確認なしのadd .は、余計なファイルが紛れ込む定番の事故のもとです。 -->
