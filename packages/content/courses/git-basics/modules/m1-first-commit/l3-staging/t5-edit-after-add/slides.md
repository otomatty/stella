# 1-3-5
# addの後の編集は載らない

Git入門研修 — Module 1 / レッスン1-3

<!-- ノート: ステージングエリアの仕組みで一番つまずきやすい落とし穴を扱います。 -->

---

## なぜ必要か

- add した後で「あ、ここも直そう」と編集を続けることはよくある
- そのまま記録すると「直したはずの1行が入っていない」事故になる

<!-- ノート: add後の追加編集は誰でも毎日やります。落とし穴と知らずに踏むと、記録の中身が古くて混乱します。 -->

---

## 結論

**add した後に編集した分は載っていない(もう一度 add する)**

- add はその瞬間の内容をステージングエリアに載せる
- その後の編集は作業フォルダ側にあるだけで、下書きは古いまま

<!-- ノート: addは「その時点の内容のコピーを載せる」操作だと言い換えます。だから後から直した分は自動では追いかけてきません。 -->

---

## よくある間違い

```bash
git add practice.txt    # ここまでの内容が載る
# …この後、practice.txt にもう1行追記して保存…
git status              # → 同じファイルが「載った分」と
                        #   「載っていない分」の両方の欄に出る
```

- 直した分も入れたいなら、もう一度 `git add practice.txt`

<!-- ノート: statusに同じファイル名が2つの欄に出るのが目印です。壊れたのではなく、載せた分と直した分が別々にあるだけです。 -->
