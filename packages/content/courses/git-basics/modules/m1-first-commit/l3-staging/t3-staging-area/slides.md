# ステージングエリアとは

Git入門研修 — Module 1 / レッスン1-3

<!-- ノート: addで選んだものが置かれる場所に、正式な名前を付けます。 -->

---

## なぜ必要か

- add で選んだファイルは「どこか」に置かれているはず
- その場所の名前を知らないと、解説やエラーの文章が読めない

<!-- ノート: 概念に名前が付くと、以後の説明が一気に読みやすくなります。ここは用語のトピックです。 -->

---

## 結論

**ステージングエリアは「次のコミットの下書き」置き場**

- add で選んだ変更が、ここに積まれて commit を待つ
- 下書きなので、確定前なら差し替えも追加もできる

<!-- ノート: メールの下書きフォルダのイメージです。送信(=commit)するまでは何度でも直せます。 -->

---

## 最小の例

```text
作業フォルダ            ステージングエリア        履歴
(編集はここで)   ─add→  (次のコミットの下書き) ─commit→ (確定した記録)
```

- 変更は「作業フォルダ → ステージングエリア → 履歴」と進む
- この3つの場所の区別が、Git理解の土台になる

<!-- ノート: 3つの場所を左から右へ指でなぞります。この図はこの先のモジュールでも繰り返し使う土台です。 -->
