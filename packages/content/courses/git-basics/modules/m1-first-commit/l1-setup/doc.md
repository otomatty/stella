# レッスン1-1 準備する

## このレッスンの目標

- [ ] git --version でGitが使える状態かを確かめられる
- [ ] git config でユーザー名とメールを設定し、--global の意味を説明できる
- [ ] git help でコマンドの説明を自分で引ける

## 1-1-1 インストールを確かめる

> **git --version が表示されれば、Gitは使える状態にある**

ここからいよいよ手を動かします。最初の一歩は、自分のPCでGitが使えるかどうかの確認です。現場に入って最初の仕事も、たいていこうした環境の確認から始まります。

ターミナルで次のコマンドを打ちます。

```bash
git --version
```

```text
git version 2.45.1
```

- 表示されたら、数字が **2.23 以上** であることも確かめてください。この研修で使うコマンドの一部は 2.23 で追加されたため、それより古いと後半で「コマンドがない」というエラーになります(余裕があれば 2.30 以上を推奨します)
- 「コマンドが見つからない」というエラーになる場合や、2.23 より古い場合は、公式サイト(git-scm.com)から最新版をインストールしてから先へ進んでください

--version は「バージョンを教えて」というオプションです。何も変更しない読み取り専用のコマンドなので、何度打っても壊れません。迷ったらまずこれ、という安全な確認手段です。

## 1-1-2 名乗りを設定する

> **git config でユーザー名とメールを設定する(すべてのコミットに刻まれる)**

バージョン管理の記録には「いつ・誰が・何を・なぜ」が入るのでした。このうち「誰が」を名乗るのがこの設定です。

ここで大事な言葉を1つ導入します。Gitで作る記録の1件1件を **コミット** と呼びます。これから研修全体で使う言葉です。

**config** は「Gitの設定を読み書きする」コマンドです。名乗りは次の2つを設定します(`--global` という指定の意味は、この次の 1-1-3 で説明します。まずはこの形で打てば大丈夫です)。

```bash
git config --global user.name "Sato Kenta"
git config --global user.email "sato@example.com"
```

- `user.name` は表示名、`user.email` は連絡先です。表記はチームの決まりに合わせます
- 一度設定すれば、以後のすべてのコミットに自動で刻まれます。毎回名乗る必要はありません
- 打ち間違えても、もう一度同じ形で打てば上書きされます

名乗りを設定しないままだと、後から履歴を見ても誰の仕事か分からなくなります。記録を始める前の必須の準備です。

## 1-1-3 globalとローカルの設定

> **--global はPC全体、指定なしはそのリポジトリだけの設定になる**

仕事のPCでは複数のリポジトリを扱うのが普通です。「リポジトリごとに毎回名乗りを設定するの?」という疑問への答えが **--global** オプションです。

| 書き方 | 効く範囲 | 使いどころ |
| --- | --- | --- |
| `git config --global user.name "..."` | PC全体(すべてのリポジトリ) | 普段の名乗り。最初に一度だけ |
| `git config user.name "..."` | 今いるリポジトリだけ | この案件だけ表記を変えたい等の特別な場合 |

```bash
git config --global user.name "Sato Kenta"   # PC全体の設定
git config user.name "Sato K."               # このリポジトリだけの設定
```

- 両方に設定があるときは、**リポジトリだけの設定が優先**されます
- この研修では、--global で一度設定して進めます

なお、指定なしの書き方はリポジトリの中でしか使えません。リポジトリはこの次のレッスンで作るので、ハンズオンでは --global の側を使います。

あわせて、この研修では次の設定も最初に済ませておきます。

```bash
git config --global init.defaultBranch main
```

新しく作るリポジトリの「最初の置き場」の名前を main に統一する設定です。言葉の意味は Module 6 で学ぶので、ここでは打っておくだけでかまいません。この設定が無い環境では、後半の画面表示が main ではなく master という古い名前になることがあります。

## 1-1-4 ヘルプを引く

> **git help(または --help)で、コマンドの説明をいつでも引ける**

Gitのコマンドとオプションはとても多く、全部を暗記するのは無理ですし、その必要もありません。現場で信頼されるのは「その場で正確に調べられる人」です。

```bash
git help config
```

```text
GIT-CONFIG(1)

NAME
       git-config - Get and set repository or global options
...
```

- 説明の開き方は環境で違います。**Windows ではブラウザのタブで開く**のが既定で、Mac や一部の設定ではターミナル内に表示されます
- ターミナル内に表示された場合、閉じるには **q** キーを押します。ここで詰まる人が一番多いので覚えておきましょう(ブラウザで開いた場合はタブを閉じるだけです)
- `git config --help` のように書いても意味は同じです

help も何も変更しない安全なコマンドです。この後の研修で「このオプション何だっけ?」となったら、まず help を引く癖をつけてください。
