# 8-4-2
# pullしてからpush

Git入門研修 — Module 8 / レッスン8-4

<!-- ノート: rejectedへの正しい対処です。手順は2つだけ。型として体に入れてしまいましょう。 -->

---

## なぜ必要か

- rejected されたまま push を繰り返しても、何度でも断られる
- リモートに増えた分を、まず自分が受け取る必要がある

<!-- ノート: 同じpushを連打しても状況は変わらない。順番を変えるだけで通る、というのが今日の話です。 -->

---

## 結論

**先に pull で取り込んでから、push し直せばよい**

- pull で「リモートの先行分」と「自分のコミット」を手元で合流させる
- 合流が済めば、push は素直に通る

<!-- ノート: 先に受け取り、混ぜてから送り直す。rejectedの対処はこの1本道だけ覚えれば十分です。 -->

---

## 最小の例

```bash
git pull
# (リモートの先行分が手元に合流する)
git push
# (今度は成功する)
```

- pull でコンフリクトが出たら、学んだ手順で解決してから push する

<!-- ノート: コンフリクトが出ても合流のモジュールで学んだ、編集してaddしてcommitの手順そのままです。 -->
