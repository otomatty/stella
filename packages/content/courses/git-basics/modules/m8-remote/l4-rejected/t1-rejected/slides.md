# 8-4-1
# rejectedは先行の合図

Git入門研修 — Module 8 / レッスン8-4

<!-- ノート: リモート編で最初に出会う赤いエラーです。意味が分かれば、まったく怖くないことを確かめます。 -->

---

## なぜ必要か

- push したら真っ赤な表示で断られて、焦ってしまう
- チーム開発では誰にでも、それも頻繁に起きる

<!-- ノート: 初めてのrejectedで頭が真っ白になる人は多い。まず「正常な出来事」だと知ることが先決です。 -->

---

## 結論

**rejected はリモートが自分より先へ進んでいる合図(壊れていない)**

- 自分が作業する間に、同僚のコミットがリモートに増えていただけ
- その上書きを防ぐために、Git がわざと止めてくれている

<!-- ノート: rejectedという語をここで定義。エラーではなく安全装置が働いた合図、という捉え方に変えてもらいます。 -->

---

## 最小の例

```text
! [rejected]        main -> main (fetch first)
error: failed to push some refs to
       'https://github.com/sato-dev/daily-report.git'
```

- 「リモートに、あなたの知らないコミットがあります」という意味

<!-- ノート: 実物の表示を見せて免疫をつける。rejectedの単語だけ拾えれば、全文を読み解けなくても大丈夫です。 -->
