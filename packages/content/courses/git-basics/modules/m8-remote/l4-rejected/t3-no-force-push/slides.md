# 8-4-3
# force pushは使わない

Git入門 — Module 8 / レッスン8-4

<!-- ノート: モジュールの締めは、やってはいけない操作の話です。存在と危険性だけを知っておきます。 -->

---

## なぜ必要か

- 調べると「rejected は --force で通せる」という情報が見つかる
- 楽に見えるその一手が、チームの成果を消す事故につながる

<!-- ノート: 検索すると本当に出てきます。なぜ飛びついてはいけないのかを、仕組みで理解してもらいます。 -->

---

## 結論

**強制 push は他人のコミットを消し得る(共有ブランチでは使わない)**

- rejected を無視してリモートを自分の履歴で上書きするのが **強制push**
- リモートにしかなかった同僚のコミットは、上書きで消えてしまう

<!-- ノート: 強制pushという語をここで定義。安全装置を手で外す操作なので、断られた理由ごと踏み潰します。 -->

---

## よくある間違い

```bash
git push --force   # ← 打たない
```

```text
リモート: A - B - C (同僚のC) → A - B - D (Cが消えた)
```

- rejected の正しい対処は、先に pull してから push し直すこと

<!-- ノート: この研修では強制pushは封印です。必要に思えた時点で何かがおかしいので、打つ前に人に相談しましょう。 -->
