# 8-2-4
# pushには認証が要る

Git入門 — Module 8 / レッスン8-2

<!-- ノート: 初回のpushで多くの人が止まる、本人確認の話です。仕組みが分かれば怖くありません。 -->

---

## なぜ必要か

- リモートは共有の置き場。誰でも書き込めたら大事故になる
- だから GitHub は、push してきた相手が本人かを必ず確かめる

<!-- ノート: 会社の建物に入るのに社員証が要るのと同じ。書き込みには本人確認が必須です。 -->

---

## 結論

**GitHub への push は本人確認が要る(パスワードではなくトークンやSSH鍵)**

- この本人確認を **認証** と呼ぶ
- 手段は **トークン**(発行してもらう長い合言葉)か **SSH** 鍵(鍵ペア)

<!-- ノート: 認証・トークン・SSHの3語をここで定義。アカウントのパスワードを直接打つ方式は今のGitHubでは使えません。 -->

---

## よくある間違い

```text
Password: (GitHubのログインパスワードを入力)
remote: Support for password authentication was removed.
fatal: Authentication failed
```

- パスワード入力欄にはトークンを貼る(または最初から SSH を設定する)
- 設定方法は現場のルールに従う。一度設定すれば毎回は聞かれない

<!-- ノート: この失敗が定番です。聞かれているのはトークン。どちらの手段を使うかは配属先の指示に合わせましょう。 -->

---

## まとめ

**GitHub への push は本人確認が要る(パスワードではなくトークンやSSH鍵)**
