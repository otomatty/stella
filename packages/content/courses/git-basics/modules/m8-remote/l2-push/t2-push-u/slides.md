# 8-2-2
# 初回は-uで紐づける

Git入門研修 — Module 8 / レッスン8-2

<!-- ノート: pushの唯一のつまずきポイント、新しいブランチの初回だけに要るひと手間を押さえます。 -->

---

## なぜ必要か

- 手元で新しく作ったブランチは、リモートのどの枝に対応するか未定
- そのまま git push すると「送り先が分からない」と止められる

<!-- ノート: 作業ブランチを初めて送るときに必ず出会うエラー。理由は送り先が未登録なだけです。 -->

---

## 結論

**新しいブランチの初回は git push -u origin 枝名 で紐づける**

- -u は「この枝の送り先はここ」と覚えさせるオプション
- 紐づけは初回の1回だけ。2回目からは git push だけでよい

<!-- ノート: -uはupstreamの頭文字。一度紐づければ以後は素のpushで届く、という1回きりの儀式です。 -->

---

## 最小の例

```bash
git push -u origin fix-typo
# * [new branch]      fix-typo -> fix-typo
```

- リモートに fix-typo 枝が新しくでき、紐づけも済んだ

<!-- ノート: 手元のfix-typoで作業していた想定。なお、cloneでできたmainは最初から紐づいているので-uは不要です。 -->

---
