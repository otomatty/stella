# 8-3-3
# origin/mainは控え

Git入門研修 — Module 8 / レッスン8-3

<!-- ノート: logの表示に出てくるorigin/mainという名前の正体です。読めると履歴の景色が変わります。 -->

---

## なぜ必要か

- git log を見ると、main の他に origin/main という名前が出てくる
- これが何を指しているのか分からないと、表示が読めない

<!-- ノート: HEADの隣にorigin/mainが並ぶ表示を初めて見ると必ず戸惑う。今日はその読み方を1つ覚えます。 -->

---

## 結論

**origin/main は「最後に確認したリモートの位置」の手元の控え**

- リモートの main が「前回 fetch した時点で」どこまで進んでいたかのメモ
- リアルタイムの最新ではない。fetch した瞬間に更新される

<!-- ノート: origin/mainという語をここで定義。あくまで手元にある控えで、常に最新とは限らないのが肝です。 -->

---

## 最小の例

```text
リモートの main:    A - B - C   (いま実際はここまで)
手元の origin/main: A - B       (最後に確認したのはここ)
手元の main:        A - B       (自分の作業位置)
```

- origin/main と C の差は、次に fetch したとき初めて見える

<!-- ノート: 3本の位置関係を対比で。控えが古くなり得るからこそ、こまめに取り寄せる意味があります。 -->
