# 8-3-4
# fetchなら見てから

Git入門 — Module 8 / レッスン8-3

<!-- ノート: pullの部品だったfetchを、単体で使う場面です。慎重に取り込みたいときの選択肢になります。 -->

---

## なぜ必要か

- pull は取り寄せと取り込みを一気にやる。中身を見る間がない
- 「何が来るのか先に確かめてから取り込みたい」ときがある

<!-- ノート: 大きな変更が来ていそうなとき、いきなり手元に混ぜるのは不安。見てから決めたい場面は必ずあります。 -->

---

## 結論

**git fetch なら、取り寄せて中身を眺めてから取り込める**

- fetch 単体は取り寄せるだけ。作業中のファイルは何も変わらない
- 眺めて納得してから、取り込みは pull で行えばよい

<!-- ノート: fetchは何度打っても手元の作業を壊さない安全なコマンド。だから気軽に打ってよい、と伝えます。 -->

---

## 最小の例

```bash
git fetch
git log --oneline origin/main
# f7a8b9c (origin/main) 会員一覧に並び替えを追加
# e4f5a6b 価格表を更新
```

- 控え(origin/main)が更新され、来る予定の変更を先に読める

<!-- ノート: fetchで控えを最新にしてからlogで眺める。この2段構えが、見てから取り込むの正体です。 -->
