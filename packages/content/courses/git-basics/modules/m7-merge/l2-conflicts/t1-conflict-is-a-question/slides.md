# コンフリクトは質問

Git入門 — Module 7 / レッスン7-2

---

## なぜ必要か

- マージすると、CONFLICT という赤い表示が出ることがある
- 初めて見ると「壊してしまった」と思って焦ってしまう

<!-- ノート: 未経験者が一番びっくりする画面です。でも実は、壊れてもいないし失敗でもありません。 -->

---

## 結論

**コンフリクトは「同じ箇所を両方が変えたのでどちらにするか」という質問(故障ではない)**

- Git が勝手に決めずに、人に判断を委ねている状態
- 落ち着いて答えれば、必ず解決できる

<!-- ノート: 同じ行を両方の枝が別々に変えたとき、どちらが正しいかはGitには決められません。だから聞いてきているだけです。 -->

---

## 最小の例

```bash
git merge fix-greeting
# CONFLICT (content): Merge conflict in practice.txt
# Automatic merge failed; fix conflicts and then commit the result.
```

- 「自動では合流できなかった。直してからコミットして」と書いてある

<!-- ノート: failedとありますが、意味は「自動処理はここまで。続きはあなたが決めて」です。次の一手までちゃんと書いてあります。 -->
