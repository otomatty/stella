# 小さくこまめに

Git入門研修 — Module 7 / レッスン7-2

## なぜ必要か

- コンフリクトの解決はできるようになった
- それでも、巨大なコンフリクトは読むだけでひと苦労

<!-- ノート: 数十か所のコンフリクトは、読める人でも消耗します。そもそも大きくしないことが一番の対策です。 -->

---

## 結論

**小さく分けてこまめに取り込むほど、コンフリクトは小さくなる**

- コンフリクトの大きさは「離れていた期間」と「変更量」で決まる
- 起きてから頑張るより、起きにくくする働き方が先

<!-- ノート: 枝が長生きするほど、相手との差は開きます。作業を小さく区切って早く合流するのが、一番効く予防策です。 -->

---

## よくある間違い

```text
数週間ためこんだ大きなブランチ → 何十か所ものコンフリクト
数日で合流する小さなブランチ   → 出てもすぐ答えられる数か所
```

- 「まとめて後で」が、コンフリクトを一番育てる

<!-- ノート: 対比で見せます。同じ仕事量でも、分けて早く取り込めばコンフリクトはほとんど問題になりません。 -->
