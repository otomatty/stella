# 7-2-4
# --abortでやり直す

Git入門 — Module 7 / レッスン7-2

<!-- ノート: コンフリクトの最中の逃げ道です。これがあるからマージは怖くありません。 -->

---

## なぜ必要か

- コンフリクトの数が多いと、どう直すべきか迷うこともある
- 中途半端に直しかけたまま進めると、かえって混乱する

<!-- ノート: 直している途中で分からなくなることは普通にあります。そんなときは一度仕切り直すのが正解です。 -->

---

## 結論

**迷ったら git merge --abort で、マージ前の状態に戻ってやり直せる**

- コンフリクトは無かったことになり、手元は元どおり
- 何度でもやり直せるから、怖がらなくてよい

<!-- ノート: abortは中止という意味です。マージを打つ前の状態にきれいに戻るので、落ち着いて作戦を立て直せます。 -->

---

## 最小の例

```bash
git merge --abort
git status
# On branch main
# nothing to commit, working tree clean
```

- status で「マージ前に戻った」ことを確かめる

<!-- ノート: 戻ったかどうかは思い込みではなくstatusで確かめます。cleanに戻っていれば、もう一度マージから挑戦できます。 -->
