# レッスン7-2 演習 — コンフリクト

対象トピック: 7-2-1 〜 7-2-5

## ハンズオン

手元の VS Code のターミナルで、`~/git-practice` リポジトリにわざと小さなコンフリクトを起こし、--abort と解決の両方を体験します。

### 1. わざとコンフリクトを起こす

1. リポジトリへ移動し、手元がきれいなことを確かめます。

   ```bash
   cd ~/git-practice
   git status
   # nothing to commit, working tree clean なら OK
   ```

2. main で、あいさつ文の行を作ってコミットしておきます。VS Code で `practice.txt` の末尾に `あいさつ: こんにちは` の1行を追記して保存してください。

   ```bash
   git add practice.txt
   git commit -m "あいさつ文を追加"
   ```

3. 作業用ブランチで、その行を書き換えてコミットします。VS Code で practice.txt を開き、最後の行を `あいさつ: おはようございます` に変えて保存してください。

   ```bash
   git switch -c fix-greeting
   # (VS Code で行を書き換えて保存)
   git add practice.txt
   git commit -m "あいさつを朝向けに変更"
   ```

4. main へ戻り、**同じ行**を別の内容に変えてコミットします。今度は `あいさつ: こんばんは` にします。

   ```bash
   git switch main
   # (VS Code で同じ行を書き換えて保存)
   git add practice.txt
   git commit -m "あいさつを夜向けに変更"
   ```

5. main に居るままマージすると、コンフリクトになります。

   ```bash
   git merge fix-greeting
   # CONFLICT (content): Merge conflict in practice.txt
   ```

   `git status` も打って、practice.txt が「both modified」と表示されることを確かめてください。

### 2. まず --abort で戻ってみる

1. 迷ったときの逃げ道を先に体験します。

   ```bash
   git merge --abort
   git status
   # nothing to commit, working tree clean
   ```

2. VS Code で practice.txt を開き、マーカーが消えて `あいさつ: こんばんは` に戻っていることを確かめます。マージ前の状態に完全に戻りました。

### 3. もう一度マージして、今度は解決する

1. 同じマージをやり直します。

   ```bash
   git merge fix-greeting
   ```

2. VS Code で practice.txt を開き、マーカーを読みます。

   ```text
   <<<<<<< HEAD
   あいさつ: こんばんは
   =======
   あいさつ: おはようございます
   >>>>>>> fix-greeting
   ```

   上が今いる main の言い分、下が fix-greeting の言い分です。

3. マーカーの3行ごと消して、あるべき1つの形に編集して保存します。ここでは fix-greeting の案を採用し、`あいさつ: おはようございます` の1行だけを残します。

4. いつもの手順でマージを完了させます。

   ```bash
   git add practice.txt
   git commit -m "あいさつ文をおはようございますに統一"
   ```

5. 履歴の形を確かめます。二股が1点に合流していれば成功です。

   ```bash
   git log --graph --oneline
   ```

## 演習問題

### 問1(基本)

マージで `CONFLICT (content): Merge conflict in price.txt` と表示されました。このとき Git は何を求めていますか。「質問」という言葉を使って説明してください。

### 問2(基本)

コンフリクト中のファイルにある `=======` の行は、何と何の境界ですか。

### 問3(応用)

コンフリクトを直している途中で、どの内容が正しいのか分からなくなりました。中途半端なまま進めずに仕切り直すには、何を打てばよいですか。また、その後どうなりますか。

### 問4(応用)

チームの先輩に「ブランチは長生きさせないでね」と言われました。コンフリクトの観点から、この助言の理由を説明してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

同じ箇所を両方のブランチが変えていたため、「どちらの内容にするか」という質問に人が答えることを求めています。

故障や失敗ではありません。price.txt を編集してあるべき形にし、add して commit すればマージが完了します。

</details>

<details>
<summary>問2の解答例</summary>

今いる枝(HEAD)の内容と、取り込もうとした枝の内容の境界です。

`=======` より上(`<<<<<<< HEAD` から)が今いる枝の言い分、下(`>>>>>>> 枝名` まで)が相手の枝の言い分です。

</details>

<details>
<summary>問3の解答例</summary>

git merge --abort を打ちます。

コンフリクトは無かったことになり、手元はマージを打つ前の状態に戻ります。git status で clean に戻ったことを確かめてから、落ち着いてもう一度マージに挑戦できます。

</details>

<details>
<summary>問4の解答例</summary>

枝が長生きするほど main との差が開き、合流のときのコンフリクトが大きくなるからです。

コンフリクトの大きさは「離れていた期間」と「変更量」で決まります。作業を小さく分けてこまめに取り込めば、コンフリクトは出ても小さく済みます。

</details>

## 確認クイズ

### Q1. マージで CONFLICT と表示されたときの状況として、正しいものはどれですか。

- A. リポジトリが壊れたので、作り直すしかない
- B. 同じ箇所を両方の枝が変えたので、どちらにするか人の判断を待っている
- C. マージは自動で完了しており、何もしなくてよい

<details>
<summary>答え</summary>

**B** — コンフリクトは故障ではなく質問です。Git が勝手に決めずに、作業を止めて人に判断を委ねています。

</details>

### Q2. コンフリクト中のファイルで、<<<<<<< HEAD から ======= までの区間に書かれているのはどれですか。

- A. 今いる枝の内容
- B. 取り込もうとした枝の内容
- C. 両方の枝の共通部分

<details>
<summary>答え</summary>

**A** — ======= を境に、上が今いる枝(HEAD)、下が取り込もうとした枝の内容です。

</details>

### Q3. コンフリクトを解決してマージを完了させる手順として、正しいものはどれですか。

- A. ファイルを編集してマーカーを消し、add して commit する
- B. マーカーを残したまま保存すれば、Git が自動で選んでくれる
- C. 専用の解決コマンドを打つ(add や commit は使わない)

<details>
<summary>答え</summary>

**A** — 特別な解除コマンドはありません。あるべき形に編集してマーカーを消し、いつもの add → commit で完了させます。

</details>

### Q4. コンフリクトの解決中に迷ってしまい、マージ前の状態からやり直したくなりました。次に打つコマンドはどれですか。

- A. git merge --abort
- B. git status
- C. git add .

<details>
<summary>答え</summary>

**A** — git merge --abort でマージ前の状態に戻れます。何度でもやり直せるので、迷ったら仕切り直すのが正解です。

</details>

### Q5. コンフリクトを小さく保つ働き方として、最も効果があるものはどれですか。

- A. 変更をため込み、月末にまとめて一度にマージする
- B. 作業を小さく分けて、こまめに取り込む
- C. コンフリクトが出そうなファイルは編集しない

<details>
<summary>答え</summary>

**B** — コンフリクトの大きさは離れていた期間と変更量で決まります。小さく分けてこまめに合流すれば、出ても小さく済みます。

</details>
