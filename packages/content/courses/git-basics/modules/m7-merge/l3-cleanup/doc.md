# レッスン7-3 ブランチの後始末

## このレッスンの目標

- [ ] マージし終えたブランチを git branch -d で消せる
- [ ] -d が断る理由を説明でき、-D を使う前に中身を確かめられる
- [ ] ブランチの一生を「作る → 積む → 合流 → 消す」で説明できる

## 7-3-1 branch -dで消す

> **マージし終えたブランチは git branch -d で消す(消えるのは付箋だけ)**

マージが済んだ枝を残したままだと、`git branch` の一覧が増え続け、どれが作業中の枝か分からなくなります。役目を終えたブランチは消しましょう。

```bash
git branch -d fix-typo
# Deleted branch fix-typo (was 8e4b7d2).
```

「消す」と聞くと怖く感じますが、心配は要りません。

- ブランチはコミットの連なりに付けた「動く付箋」でした
- 消えるのは付箋(名前)だけで、コミットは履歴に残ったまま
- マージ済みなら、その変更はもう受け皿の枝に入っている

出力の `was 8e4b7d2` は、付箋が最後に指していたコミットの ID です。付箋をはがしても、貼ってあったコミットは消えません。

## 7-3-2 -dは未マージを断る

> **-d は未マージなら断ってくれる(-D の強制は本当によいか確かめてから)**

消そうとした枝に、まだマージしていないコミットが残っていることがあります。このとき -d は、消さずに断ってくれます。

```bash
git branch -d try-layout
# error: the branch 'try-layout' is not fully merged
```

`not fully merged` は「まだ合流していない変更が残っている」という警告です。error とありますが、失敗ではなく安全装置が働いた合図です。断られたら、次の順で考えます。

1. `git log try-layout --oneline` などで、その枝の中身を確かめる
2. 必要な変更なら、マージしてから -d で消す
3. 本当に捨ててよいと確かめられたときだけ、大文字の **-D** で強制削除する

-D は安全装置を外すオプションです。「断られたから -D」と反射的に打つのではなく、必ず中身を見てから判断してください。

## 7-3-3 ブランチの一生

> **「作る → 積む → 合流 → 消す」がブランチの一生**

Module 6 と 7 で、ブランチの操作がひととおり出そろいました。ばらばらに覚えるより、1つの流れとして持つと迷いません。

```bash
git switch -c fix-typo    # 1. 作る
#   (編集してコミットを積む)  2. 積む
git switch main
git merge fix-typo        # 3. 合流
git branch -d fix-typo    # 4. 消す
```

| 段階 | すること |
| --- | --- |
| 作る | main から作業用ブランチを出す |
| 積む | 編集してコミットを重ねる |
| 合流 | 取り込む側へ移ってマージする |
| 消す | マージ済みの枝を -d で消す |

この1周を短く回すのがブランチ運用の基本です。消すところまでやって、1つの作業が完了します。実務では、この1周を小さな作業ごとに何度も繰り返していきます。
