# 7-1-2
# 取り込む側に移ってから

Git入門研修 — Module 7 / レッスン7-1

<!-- ノート: mergeの向きの話です。初回のマージで一番間違えやすいポイントを1つだけ押さえます。 -->

---

## なぜ必要か

- merge には「取り込む側」と「取り込まれる側」がある
- どちらの枝に居て打つかで、結果がまるで変わってしまう

<!-- ノート: 作業用ブランチに居たまま git merge main と打ってしまう間違いが定番です。mainに入れたつもりが、逆にmainを自分の枝へ取り込んでいます。 -->

---

## 結論

**merge は取り込む側で実行する(main へ入れるなら main に居る)**

- 今いる枝が受け皿になる
- 「移ってから merge」を1セットで覚える

<!-- ノート: 受け皿はいつも自分の足元です。だからマージの手順は必ず、行き先への移動から始まります。 -->

---

## 最小の例

```bash
git switch main       # 1. 受け皿になる main へ移る
git merge fix-typo    # 2. fix-typo の変更を main へ取り込む
```

- 打つ前に「自分は今どの枝に居るか」を確かめる

<!-- ノート: switchしてからmerge、の2行で1セット。迷ったらgit branchで今いる場所を見てから打ちます。 -->
