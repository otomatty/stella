# 7-1-1
# git mergeで取り込む

Git入門研修 — Module 7 / レッスン7-1

<!-- ノート: Module 7 の最初のトピックです。枝を分けて積んだ変更を、いよいよ合流させます。 -->

---

## なぜ必要か

- 作業用ブランチに直しをコミットした。でも main はまだ古いまま
- 枝に積んだ変更を、完成の置き場である main へ合流させたい

<!-- ノート: Module 6 で「作業はブランチで」と学びました。作業が終わったら合流させないと、mainはいつまでも完成しません。 -->

---

## 結論

**git merge 枝名 は、その枝の変更を「今いる枝」へ取り込む**

- この合流を **マージ** と呼ぶ
- 取り込み先は、コマンドを打ったときに自分が居る枝

<!-- ノート: mergeは英語で「合流させる」。枝名に書いた側の変更が、今いる枝へ流れ込んでくるイメージです。 -->

---

## 最小の例

```bash
git merge fix-typo
# fix-typo に積んだコミットが、今いる枝に取り込まれる
```

- 枝名に書くのは「取り込みたい変更が載っている枝」

<!-- ノート: 引数の枝は取り込まれる側で、受け皿は今いる枝。この向きが次のトピックの主役になるので、ここでは形だけ覚えます。 -->
