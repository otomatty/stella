# レッスン3-2 演習 — 秘密情報を守る

対象トピック: 3-2-1 〜 3-2-3

## ハンズオン

練習用リポジトリ `~/git-practice` の続きで、「分けて、無視する」の型を体験します。秘密情報は**本物を使わず**、必ずダミーの文字列で試してください。

1. リポジトリへ移動します

   ```bash
   cd ~/git-practice
   git status
   ```

2. VS Code でファイル `.env` を新規作成し、ダミーの鍵を1行書いて保存します

   ```text
   API_KEY=dummy-key-12345
   ```

3. `git status` を打つと、.env が Untracked に出ます。このまま add すれば履歴に載ってしまう状態です

4. .gitignore に `.env` の1行を追記して保存し、もう一度 `git status` を打ちます。.env が消えて、.gitignore の変更(modified)だけが出れば成功です

5. .gitignore の変更をコミットします

   ```bash
   git add .gitignore
   git commit -m ".envを無視する"
   ```

6. 仕上げに `git status` を打って、.env が手元にあるのに Git からは見えていないことを確かめます。これが「最初から混ざらない」置き方です

## 演習問題

### 問1(基本)

次のうち、コミットしてはいけない秘密情報をすべて選んでください。

```text
(ア) データベースのパスワード
(イ) 会員一覧画面のプログラム
(ウ) 外部サービスのAPIキー
(エ) README.md
```

### 問2(基本)

APIキー入りのファイルをコミットしてしまいました。「そのファイルを削除してコミットし直す」だけでは不十分な理由を1文で説明してください。

### 問3(応用)

新しいプロジェクトを始めます。秘密情報の事故を仕組みで防ぐために、最初にやっておく2つのことを答えてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

(ア)と(ウ)です。

どちらも漏れると悪用される秘密情報です。(イ)と(エ)は記録すべき成果物で、むしろ履歴で守る対象です。

</details>

<details>
<summary>問2の解答例</summary>

削除コミットは新しい記録を積むだけで、キー入りの過去のコミットは履歴に残り続けるからです。

履歴をさかのぼれば誰でもキーを見られます。だから一手目は Git の操作ではなく、発行元でのキーの無効化です。

</details>

<details>
<summary>問3の解答例</summary>

1. 秘密情報を .env などの設定ファイルに分けて、コードには書かない
2. プロジェクト開始直後に、.gitignore へ `.env` を書いておく

「分ける」と「無視する」の2段構えにすれば、うっかり add のしようがなくなります。注意力ではなく仕組みで防ぐのがポイントです。

</details>

## 確認クイズ

### Q1. パスワードやAPIキーをコミットしてはいけない理由として正しいものはどれですか。

- A. コミットが履歴に残り、リポジトリを見られる人全員に秘密が渡るから
- B. ファイルの容量が大きくなりすぎるから
- C. Gitがエラーを出してコミットできないから

<details>
<summary>答え</summary>

**A** — コミットは履歴に残って共有相手全員に見えます。公開リポジトリなら世界中から見える状態です。Git は秘密かどうかを判定してくれないので、C のように止まってはくれません。

</details>

### Q2. APIキーをコミットしてしまったとき、最初にすべきことはどれですか。

- A. キーの行を削除して、すぐコミットし直す
- B. 発行元でそのキーを無効化して、使えなくする
- C. リポジトリのフォルダ名を変える

<details>
<summary>答え</summary>

**B** — 削除コミットでは過去の履歴に残ったキーは消えません。まず発行元で無効化すれば、履歴に残っていても悪用できなくなります。

</details>

### Q3. 「削除コミットでは秘密は消えない」の説明として正しいものはどれですか。

- A. 削除コミットは失敗することが多いから
- B. コミットはスナップショットとして履歴に残り、過去の記録を開けば中身が見えるから
- C. 削除したファイルは自動で復元されるから

<details>
<summary>答え</summary>

**B** — 削除コミットは「最新の状態」を変えるだけです。履歴には過去のスナップショットが全部残っていて、さかのぼれば秘密は見えてしまいます。

</details>

### Q4. 秘密情報の事故を最初から防ぐ置き方として正しいものはどれですか。

- A. 秘密を .env に分けて、最初から .gitignore に .env を書いておく
- B. 秘密をコードに書き、コミットの直前に毎回消す
- C. 秘密をファイル名に含めて、目立つようにしておく

<details>
<summary>答え</summary>

**A** — 「分けて、無視する」の2段構えなら、.env は status に現れず、うっかり add のしようがありません。B のような注意力頼みの運用はいつか破られます。

</details>
