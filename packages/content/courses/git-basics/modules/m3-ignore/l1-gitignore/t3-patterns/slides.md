# 3-1-3
# パターンで書く

Git入門研修 — Module 3 / レッスン3-1

<!-- ノート: .gitignoreの書き方の2回目。1件ずつ書くのではなく、まとめて指定する方法を覚えます。 -->

---

## なぜ必要か

- ログは app.log、error.log と増えていく。1行ずつ足すのはきりがない
- 生成物のフォルダは、中身を全部まとめて無視したい

<!-- ノート: ファイル名を毎回足す運用は必ず漏れる。増えても効き続ける書き方が欲しい、という流れ。 -->

---

## 結論

**フォルダは末尾 / 、まとめて指定は * で書ける**

- こうした「形で指定する書き方」をパターンと呼ぶ
- `logs/` はフォルダごと、`*.log` は .log で終わる全ファイルが対象

<!-- ノート: パターンという言葉をここで定義する。この2つだけで実務の.gitignoreの大半は読めるようになる。 -->

---

## 最小の例

```text
# .gitignore の中身
logs/     # logs フォルダを中身ごと無視
*.log     # .log で終わるファイルをすべて無視
dist/     # ビルドの生成物フォルダを無視
```

- 後からファイルが増えても、パターンに当てはまれば自動で無視される

<!-- ノート: 末尾スラッシュが「フォルダ」、アスタリスクが「何でも」の意味。この3行が読めれば、現場の.gitignoreも怖くない。 -->
