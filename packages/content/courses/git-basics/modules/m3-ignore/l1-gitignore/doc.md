# レッスン3-1 .gitignore

## このレッスンの目標

- [ ] .gitignore の役割と書き方を説明できる
- [ ] 「作り直せるもの」という無視対象の判断基準を使える
- [ ] 追跡済みのファイルが無視されない理由と、その対処を説明できる

## 3-1-1 .gitignoreで無視する

> **.gitignore に書いたファイルを、Gitは無いものとして扱う**

リポジトリの中には、記録したくないファイルも生まれます。たとえばプログラムが動くたびに書き出される動作ログです。こうしたファイルは `git status` を打つたびに Untracked として並び、add の候補に毎回混ざって邪魔になります。

そこで使うのが **.gitignore** です。リポジトリ直下に置く、ただのテキストファイルで、ここに書いたファイルを Git は無いものとして扱います。

```text
# .gitignore の中身
app.log
```

保存すると、app.log は `git status` に出なくなり、add の対象にもなりません。

```bash
git status
# app.log が表示されなくなる(.gitignore 自体は Untracked に出る)
```

.gitignore 自体はコミットするのが基本です。チーム全員が同じ無視リストを共有できるので、「自分の環境ではログがコミットに混ざる」といった差がなくなります。

## 3-1-2 無視するのは作り直せるもの

> **無視するのは生成物・ログ・依存フォルダなど「作り直せるもの」**

.gitignore は便利ですが、何でも書いてよいわけではありません。記録すべきファイルまで無視すると、履歴に残らず、消えたときに戻れなくなります。

判断基準は1つだけです。「消えても、また作り直せるか」。

| 無視する(作り直せる) | 記録する(作り直せない) |
| --- | --- |
| ビルドの**生成物**(元のファイルから機械が作り出したもの) | 自分で書いたプログラム |
| 動作ログ | README などの文書 |
| 依存フォルダ(外部から取得し直せる部品置き場) | 設定ファイルの正本 |

生成物・ログ・依存フォルダは、元のファイルや外部のサービスからいつでも再現できます。履歴に入れる価値がないどころか、変更のたびに status をにぎやかにして、本当に読むべき変更を埋もれさせます。

迷ったら「このファイルが消えたら困るか?」と自分に聞いてください。困るなら記録、作り直せるなら無視です。

## 3-1-3 パターンで書く

> **フォルダは末尾 / 、まとめて指定は * で書ける**

ログファイルは app.log、error.log と増えていきます。1行ずつ .gitignore に足していくのはきりがなく、必ず漏れます。そこで、ファイル名を1件ずつ書く代わりに「形」で指定します。この書き方を **パターン** と呼びます。

まず覚えるのは2つだけです。

```text
# .gitignore の中身
logs/     # logs フォルダを中身ごと無視
*.log     # .log で終わるファイルをすべて無視
dist/     # ビルドの生成物フォルダを無視
```

- 末尾に `/` を付けると、そのフォルダを中身ごと無視します
- `*` は「何でも」の意味で、`*.log` は .log で終わる全ファイルに効きます

後からファイルが増えても、パターンに当てはまれば自動で無視されます。この2つが読めれば、現場のプロジェクトにある .gitignore もほとんど読めるようになります。

## 3-1-4 追跡済みは無視されない

> **すでに追跡中のファイルは、.gitignore に書くだけでは無視されない**

うっかりログファイルをコミットしてしまった後で .gitignore に足したのに、編集するたびに status へ出続ける。実務で必ず一度は遭遇するつまずきです。.gitignore が壊れているのではありません。

一度コミットしたファイルは、Git がその変更を見張っている状態になります。これを **追跡** と呼びます。.gitignore が効くのは「まだ追跡していない」ファイルだけです。無視リストは新入りにしか効かない、と覚えてください。

追跡をやめるには `git rm --cached` を使います。

```bash
git rm --cached app.log
# ファイルは手元に残したまま、追跡だけをやめる
git commit -m "app.logを追跡から外す"
```

`rm` はレッスン2-3で学んだ「削除の記録」ですが、`--cached` を付けるとファイル自体は消さず、追跡だけをやめます。手元の app.log は無事です。追跡をやめた後は、.gitignore がいつも通り効きます。

```bash
git status
# app.log が modified に出なくなる
```
