# 3-1-4
# 追跡済みは無視されない

Git入門 — Module 3 / レッスン3-1

<!-- ノート: .gitignoreのつまずきどころ第1位です。書いたのに効かない、という状況の正体を押さえます。 -->

---

## なぜ必要か

- うっかりログファイルをコミットしてしまってから、.gitignore に足した
- それなのに、編集するたびに status に出続ける。「書いたのに効かない?」

<!-- ノート: 実務で必ず一度は遭遇する場面。.gitignoreが壊れているわけではない、が結論への引きになる。 -->

---

## 結論

**すでに追跡中のファイルは、.gitignore に書くだけでは無視されない**

- 追跡 = Gitがそのファイルの変更を見張っている状態(一度コミットすると始まる)
- .gitignore が効くのは「まだ追跡していない」ファイルだけ

<!-- ノート: 追跡という言葉をここで定義する。無視リストは新入りにしか効かない、と言い換えると伝わりやすい。 -->

---

## 最小の例

```bash
git rm --cached app.log
# ファイルは手元に残したまま、追跡だけをやめる
git commit -m "app.logを追跡から外す"
```

- `--cached` を付けると、rm でもファイル自体は消えない
- 追跡をやめた後は、.gitignore がいつも通り効く

<!-- ノート: rmに--cachedを付けると「削除の記録」ではなく「追跡やめの記録」になる。手元のファイルは無事、という安心を添える。 -->
