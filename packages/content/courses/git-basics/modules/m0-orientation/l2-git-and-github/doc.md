# レッスン0-2 GitとGitHub

## このレッスンの目標

- [ ] GitとGitHubの役割の違いを説明できる
- [ ] Gitが「分散型」と呼ばれる理由を説明できる
- [ ] リポジトリ・作業フォルダ・.git フォルダの関係を説明できる

## 0-2-1 GitとGitHubは別物

> **Gitは履歴を記録する道具、GitHubはそれを共有して共同作業する場所**

前のレッスンで学んだ「履歴のしくみ」を実現する道具の代表が **Git** です。名前のよく似た **GitHub** と混同されがちですが、この2つは別物です。

```text
Git    : 自分のPCで動く。変更を記録して履歴を作る
GitHub : Web上のサービス。履歴を置いて、チームで共有する
```

- Git は自分のPCにインストールして使う、バージョン管理の道具です
- GitHub は Git の履歴を置いて共有するための Web サービスです

置き場所の違いで覚えるのが早い方法です。Git は手元で動くソフトウェア、GitHub はブラウザで開くサービスです。GitHub が無くても Git だけで履歴は作れます。実際この研修も、前半は Git だけで進み、共有の場面で GitHub が登場します。

「GitHub なら使ったことがあります」「それは Git の話ですか?」というすれ違いは現場で実際に起きます。役割の違いを一言で言えるようにしておきましょう。

## 0-2-2 Gitは分散型

> **Gitでは全員が完全な履歴のコピーを自分の手元に持つ**

履歴を共有サーバーの1か所だけに置く方式には、弱点があります。

- サーバーが止まった瞬間に、全員が作業できなくなる
- ネットの無い場所では、履歴を見ることすらできない

Git はこの方式を取りません。全員が完全な履歴のコピーを自分のPCに持ちます。このしくみを **分散型** と呼びます。

```text
1か所だけの管理: サーバー1台に履歴 ← 止まると全員が止まる
分散型(Git)   : 佐藤のPC / 田中のPC / GitHub
                 それぞれが完全な履歴を持つ
```

分散型には実務上のうれしさが2つあります。

- 記録も履歴の閲覧も手元だけで完結するので、ネットが無くても作業できる
- 履歴のコピーが複数あるので、どれか1つが失われても復元できる

GitHub も「完全な履歴のコピーを持つ場所の1つ」です。そこだけが本物、というわけではないのが分散型の考え方です。

## 0-2-3 リポジトリとは

> **リポジトリは「作業フォルダ+その履歴」のセット**

Git の解説やエラーメッセージには「リポジトリ」という語が必ず出てきます。この研修全体で使い続ける最重要語なので、ここで定義します。

- **作業フォルダ**: ふだんファイルを編集しているフォルダのこと
- そのフォルダを Git に管理させると、履歴が付いて **リポジトリ** になる

```text
リポジトリ
├─ 作業フォルダ … いま編集している最新のファイルたち
└─ 履歴       … これまでの記録の積み重ね
```

特別な場所を新しく作るのではありません。いつものフォルダに履歴が付いたもの、それがリポジトリです。「企画書のリポジトリ」と言えば、企画書のフォルダとその全記録のセットを指します。

最新のファイルだけでも、記録だけでもなく、両方そろって1つのリポジトリ。この「セットである」という感覚が大切です。

## 0-2-4 履歴は.gitフォルダにある

> **履歴は作業フォルダ直下の .git フォルダに入っている(消すと履歴ごと消える)**

では、履歴の実体はどこに保存されているのでしょうか。答えは作業フォルダの直下にある `.git` という名前のフォルダです。

```text
企画書プロジェクト/      ← 作業フォルダ
├── .git/               ← 履歴の保管庫(隠しフォルダ)
├── 企画書.md
└── 価格表.xlsx
```

- `.git` は隠しフォルダで、ふだんの画面には表示されないことが多い
- 中身を手で開いて編集する必要はない(触らない)

場所を知っておくべき理由は、事故防止です。`.git` を消すと、そのリポジトリの履歴が全部消えます。逆に、作業フォルダのファイル自体は残ります。「不要そうなフォルダ」として消してしまわないよう、正体を知っておきましょう。

もう1つのうれしい性質は、履歴がフォルダの中に同居していることです。作業フォルダごと持ち運べば、履歴も一緒に付いてきます。
