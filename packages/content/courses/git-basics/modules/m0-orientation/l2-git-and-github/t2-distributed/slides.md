# 0-2-2
# Gitは分散型

Git入門研修 — Module 0 / レッスン0-2

<!-- ノート: Gitの履歴の持ち方には特徴があります。「分散型」という語を1つだけ導入します。 -->

---

## なぜ必要か

- 履歴が共有サーバーの1か所にしかないと、止まった瞬間に全員が作業できない
- 外出先などネットが無い場所では、履歴を見ることもできない

<!-- ノート: 履歴を1か所に集める方式の弱点から入る。1か所が単一障害点になる、という感覚を持たせます。 -->

---

## 結論

**Gitでは全員が完全な履歴のコピーを自分の手元に持つ**

- このしくみを **分散型** と呼ぶ
- 記録も履歴の閲覧も、まず自分のPCの中だけで完結する

<!-- ノート: 分散型を定義する。手元に全履歴があるから、ネットが無くても記録でき、サーバーが止まっても作業が続けられます。 -->

---

## 最小の例

```text
1か所だけの管理: サーバー1台に履歴 ← 止まると全員が止まる
分散型(Git)   : 佐藤のPC / 田中のPC / GitHub
                 それぞれが完全な履歴を持つ
```

- どれか1つが失われても、他のコピーから履歴を復元できる

<!-- ノート: 対比で見せる。GitHubも「履歴のコピーを持つ場所の1つ」であって、そこだけが本物というわけではない、が分散型の考え方です。 -->
