# レッスン5-3 コミットを打ち消す

## このレッスンの目標

- [ ] git revert でコミット済みの変更を打ち消せる
- [ ] revert が共有した後でも安全な理由を説明できる
- [ ] 履歴を消す取り消しをこの研修で使わない理由を説明できる

## 5-3-1 git revertで打ち消す

> **git revert ID は「反対の変更」を新しいコミットとして積む**

コミットしてしまった変更を、後から取り消したくなることがあります。そのコミットはもう履歴に積まれています。revert は、これを「消す」のではなく「打ち消す」コマンドです。

```bash
git revert a1b2c3d
# 履歴(新しい順):
#   f9e8d7c Revert "価格表を更新"   ← 反対の変更が積まれた
#   a1b2c3d 価格表を更新            ← 元のコミットは残ったまま
```

- 行を足したコミットなら「その行を消す」コミットが新しくできます
- 元のコミットはそのまま残り、記録が1つ増えるだけです
- ID は打ち消したいコミットのもので、先頭7桁で指定できます

足した変更と反対の変更で差し引きゼロにする、という発想です。ファイルの中身は打ち消したいコミットの前の状態に戻り、いきさつは全部履歴に残ります。

## 5-3-2 revertは履歴を消さない

> **revert は履歴を消さないから、共有した後でも安全に使える**

取り消したいコミットを、他の人がもう受け取っていることがあります。前のレッスンで見た通り、共有した後のコミットに amend は使えません。ここが revert の出番です。

| 取り消し方 | 動き | 使える場面 |
| --- | --- | --- |
| amend | 直前のコミットを作り直す | 共有前だけ |
| revert | 反対の変更を上に積む | 共有後でも安全 |

revert は履歴を消しません。増える一方なので、誰が持っている記録とも食い違いが生まれません。相手のコミットはそのまま有効で、その上に打ち消しのコミットが積まれるだけです。

さらに「いつ・誰が・何を取り消したか」まで記録として残ります。取り消しのいきさつを後から追えることは、チームで働くうえで大きな利点です。

## 5-3-3 履歴を消す取り消しは封印

> **履歴そのものを書き換える取り消し(reset --hard 等)は、この研修では使わない**

取り消し方を検索すると、`reset --hard` というコマンドに必ず出会います。一発で消せて強力そうに見えますが、この研修では封印します。

- reset --hard はコミットや変更を履歴ごと消し、捨てたものを戻せないことがあります
- ネット記事の「これで一発解決」を、消える範囲を理解しないまま実行して作業を失う事故が後を絶ちません
- 「強力」は「失敗したとき大きく壊れる」と同じ意味です

この講座の範囲では、取り消しは revert で足ります。履歴を消す系のコマンドは、現場で Git に慣れて、消える範囲を自分で説明できるようになってから学べば十分です。名前と危険性だけを覚えておいてください。

## 5-3-4 コミット済みなら助かる

> **コミット済みの変更はまず消えない(困ったら壊す前に相談する)**

Git の操作を間違えて「全部消えたかも」と青ざめる日が必ず来ます。そのときのための判断の型が、このモジュールの締めくくりです。

```text
コミット前の変更   → 守られていない(捨てたら戻らない)
コミット済みの変更 → 履歴に残っている(まず消えない)
困ったら           → 壊すコマンドを打つ前に、人に聞く
```

restore で消えるのはコミット前の変更だけでした。裏返せば、コミット済みの変更は履歴に残っていて、まず消えません。「消えたかも」の大半は、履歴のどこかにまだ残っています。

コミットさえしてあれば、詳しい人がほぼ救出できます。だからこそ、パニックのまま強そうなコマンドを打つのが一番危険です。自信のない操作は、打つ前に先輩やチームに相談してください。こまめなコミットが保険になる理由も、ここでつながります。
