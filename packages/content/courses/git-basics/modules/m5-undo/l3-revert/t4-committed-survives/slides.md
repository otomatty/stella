# コミット済みなら助かる

Git入門 — Module 5 / レッスン5-3

## なぜ必要か

- Git の操作を間違えて「全部消えたかも」と青ざめる日が必ず来る
- 本当に消えたのか、それとも助かるのか。落ち着いて考えたい

<!-- ノート: パニックのときほど危険なコマンドに手が伸びます。あらかじめ判断の型を持っておくのが目的です。 -->

---

## 結論

**コミット済みの変更はまず消えない(困ったら壊す前に相談する)**

- restore で消えるのはコミット前の変更だけ。コミット済みは履歴に残る
- 自信のない操作は、打つ前に先輩やチームに相談する

<!-- ノート: このモジュールの学びの裏返しです。こまめなコミットが保険になる理由も、ここでつながります。 -->

---

## 最小の例

```text
コミット前の変更   → 守られていない(捨てたら戻らない)
コミット済みの変更 → 履歴に残っている(まず消えない)
困ったら           → 壊すコマンドを打つ前に、人に聞く
```

- 「消えたかも」の大半は、履歴のどこかにまだ残っている

<!-- ノート: 判断の型を3行で示します。コミットさえしてあれば、詳しい人ならほぼ救出できます。だから相談が先です。 -->
