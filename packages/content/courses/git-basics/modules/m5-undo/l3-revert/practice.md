# レッスン5-3 演習 — コミットを打ち消す

対象トピック: 5-3-1 〜 5-3-4

## ハンズオン

`~/git-practice` リポジトリの続きで試します。手元の VS Code のターミナルで進めてください。

1. `cd ~/git-practice` で移動し、`git status` で手元がきれいなことを確かめます
2. `practice.txt` の末尾に `この行は打ち消しの練習です` と1行追記して保存し、`git add practice.txt` → `git commit -m "打ち消し練習の行を追加"` でコミットします
3. `git log --oneline` で先頭の ID(7桁)をメモします
4. `git revert --no-edit <手順3のID>` を打ちます(`--no-edit` はメッセージ入力画面を開かず、既定のメッセージのまま記録する指定です)
5. `practice.txt` を開き、手順2で足した行が消えていることを確かめます
6. `git log --oneline` を打ちます。`Revert "打ち消し練習の行を追加"` というコミットが増え、手順2のコミットも残っていることを確かめます
7. `git show <手順3のID>` で、打ち消した後も元のコミットの中身をいつでも見られることを確かめます

削除ではなく「反対の変更を積む」ので、いきさつが全部履歴に残っています。これが共有後でも安全な理由です。

## 演習問題

### 問1(基本)

`git log --oneline` に `a1b2c3d 会員一覧の並び順を変更` とあります。このコミットを打ち消すコマンドを書いてください。

### 問2(基本)

問1のコマンドを実行した後、履歴はどうなりますか。「元のコミット」と「コミットの数」の2点に触れて答えてください。

### 問3(応用)

他の人にもう渡したコミットを取り消したいとき、amend ではなく revert を選ぶ理由を1〜2文で説明してください。

### 問4(応用)

先輩ではない知人に「reset --hard で消せば早いよ」と勧められました。この研修の方針ではどう行動すべきですか。理由も添えて答えてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

```bash
git revert a1b2c3d
```

並び順の変更と反対の変更を持つコミットが、新しく1つ積まれます。ID は先頭7桁で指定できます。

</details>

<details>
<summary>問2の解答例</summary>

元のコミット `a1b2c3d` は消えずに履歴に残ったまま、打ち消しのコミットが1つ増えます(コミットの数は1つ増える)。

ファイルの中身は並び順を変える前の状態に戻り、取り消したいきさつも履歴で追えます。

</details>

<details>
<summary>問3の解答例</summary>

amend はコミットを作り直して別物にするため、相手が持つ記録と食い違ってしまうからです。revert は履歴を消さず上に積むだけなので、共有した後でも誰の記録とも矛盾しません。

</details>

<details>
<summary>問4の解答例</summary>

reset --hard は使わず、打ち消しは revert で行います(この研修では履歴を消す取り消しを封印しています)。

reset --hard は履歴ごと消す操作で、消える範囲を理解せずに実行すると作業を失い、戻せないことがあるからです。判断に迷うなら、実行する前に先輩やチームに相談します。

</details>

## 確認クイズ

### Q1. git revert a1b2c3d が行うことの説明として正しいものはどれですか。

- A. コミット a1b2c3d を履歴から削除する
- B. a1b2c3d と反対の変更を、新しいコミットとして積む
- C. a1b2c3d のコミットメッセージを書き換える

<details>
<summary>答え</summary>

**B** — revert は「消す」のではなく「打ち消す」操作です。反対の変更が上に積まれ、元のコミットは履歴に残ったままです。

</details>

### Q2. 他の人にもう渡したコミットを取り消すとき、revert が安全な理由はどれですか。

- A. 履歴を消さず上に積むだけなので、誰の記録とも食い違わないから
- B. revert は相手のパソコンの履歴も自動で書き換えてくれるから
- C. revert したコミットは誰にも見えなくなるから

<details>
<summary>答え</summary>

**A** — 履歴は増える一方で、相手が持つコミットはそのまま有効です。取り消した事実も記録に残るので、後からいきさつを追えます。

</details>

### Q3. reset --hard について、この研修の方針として正しいものはどれですか。

- A. revert より速いので、積極的に使ってよい
- B. 履歴ごと消して戻せないことがあるため、この研修では使わない
- C. コミット前の変更を守ってくれる安全なコマンドである

<details>
<summary>答え</summary>

**B** — reset --hard は履歴そのものを書き換える取り消しです。消える範囲を理解しないまま使う事故が多いため封印し、打ち消しは revert で行います。

</details>

### Q4. 操作を間違えて「変更が全部消えたかも」と思ったときの行動として、このレッスンで学んだ型はどれですか。

- A. コミット済みの変更はまず消えていないので、壊すコマンドを打つ前に相談する
- B. とにかく強力そうな取り消しコマンドを検索して、すぐ実行する
- C. リポジトリのフォルダごと削除して、最初から作り直す

<details>
<summary>答え</summary>

**A** — コミット済みの変更は履歴に残っていて、まず消えません。パニックのまま壊す操作をするのが一番危険なので、先に人に聞きます。

</details>
