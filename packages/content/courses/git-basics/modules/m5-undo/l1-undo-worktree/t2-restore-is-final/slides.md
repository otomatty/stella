# 5-1-2
# restoreは取り戻せない

Git入門研修 — Module 5 / レッスン5-1

<!-- ノート: restoreの一番大事な注意点です。便利さとセットで、必ずこの性質を覚えてもらいます。 -->

---

## なぜ必要か

- restore を打った直後に「やっぱりあの編集は要る」と思うことがある
- 捨てた編集はゴミ箱のようにどこかへ残っているのだろうか?

<!-- ノート: ファイル削除にはゴミ箱がありますが、restoreにも同じ仕組みがあると思い込むのが典型的な誤解です。 -->

---

## 結論

**restore で捨てた変更は取り戻せない(コミット前の変更は守られていない)**

- Git が守っているのは、コミットした変更だけ
- コミット前の編集は履歴のどこにも記録されていない

<!-- ノート: Gitの保険が効くのはコミットしてからです。コミット前の編集はGitの管理の外にある、と言い切ります。 -->

---

## よくある間違い

```text
10:00 日報.md に30分かけて追記(コミットしていない)
10:30 git restore 日報.md   # ← 追記が全部消える
10:31 「元に戻すコマンドは?」 → 無い
```

- 迷う変更なら、捨てる前にコミットして残しておくのが安全

<!-- ノート: 30分の作業が一瞬で消える事故の再現です。消すか迷ったら、まずコミットしてから考えるのが現場の型です。 -->
