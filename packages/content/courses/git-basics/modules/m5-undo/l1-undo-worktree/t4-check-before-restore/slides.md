# 5-1-4
# 戻す前にstatus

Git入門 — Module 5 / レッスン5-1

<!-- ノート: レッスンの締めとして、restoreを安全に使う手順の型を覚えます。 -->

---

## なぜ必要か

- restore で捨てた変更は取り戻せないと分かった
- それでも勢いで打ってしまい、必要な編集まで消す事故が起きる

<!-- ノート: 知識として知っていても、急いでいるときに事故は起きます。打つ前の手順を型にしてしまうのが対策です。 -->

---

## 結論

**どこまで戻るのかを status と diff で確かめてから戻す**

- status で「どのファイルが変わっているか」を見る
- diff で「捨てようとしている変更の中身」を読む

<!-- ノート: 何が消えるのかを自分の目で読んでから捨てる、という順番です。確認の2コマンドはどちらも既に学んだものです。 -->

---

## 最小の例

```bash
git status           # 変わっているファイルはどれか
git diff 日報.md     # 消えるのはこの変更でよいか
git restore 日報.md  # 納得してから戻す
```

- 確認 → 確認 → 実行。この3行をセットで手に覚えさせる

<!-- ノート: 実務でもこの3行は毎回セットです。diffを読んで「消してよい」と言えたときだけrestoreを打ちます。 -->
