# レッスン5-2 演習 — 直前のコミットを直す

対象トピック: 5-2-1 〜 5-2-3

## ハンズオン

`~/git-practice` リポジトリの続きで試します。手元の VS Code のターミナルで進めてください。

1. `cd ~/git-practice` で移動し、`git status` で手元がきれいなことを確かめます
2. `practice.txt` の末尾に `amend の練習` と1行追記して保存し、`git add practice.txt` します
3. わざと誤字のまま `git commit -m "学びを追加w"` でコミットします
4. `git log --oneline` を打ち、先頭の ID とメッセージをメモしておきます
5. `git commit --amend -m "学びを追加"` で作り直します
6. もう一度 `git log --oneline` を打ちます。メッセージが直り、先頭の ID が手順4のメモと変わっていること、コミットの数は増えていないことを確かめます
7. 入れ忘れも体験します。VS Code で `memo.txt` を新しく作り、`git add memo.txt` → `git commit --amend -m "学びを追加"` と打ちます
8. `git show HEAD` で、直前のコミットに `memo.txt` の追加も含まれたことを確かめます。ID がさらに変わっていることも `git log --oneline` で見ておきましょう

このリポジトリはまだ誰にも渡していないので、何度 amend しても安全です。

## 演習問題

### 問1(基本)

`git commit -m "会員一覧を修正しました。。"` と打った直後、句点の重複に気づきました。メッセージを「会員一覧を修正」に直すコマンドを書いてください。

### 問2(基本)

「価格表を更新」というコミットの直後に、一緒に入れるはずだった `単価メモ.md` の入れ忘れに気づきました。直前のコミットに含める手順をコマンド2つで書いてください。

### 問3(応用)

amend の前後で `git log --oneline` の先頭の ID が変わるのはなぜですか。「修正」と「作り直し」という言葉を使って説明してください。

### 問4(応用)

他の人にもう渡したコミットを amend してはいけない理由を、1〜2文で説明してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

```bash
git commit --amend -m "会員一覧を修正"
```

直前のコミットを、新しいメッセージで作り直します。誤字のコミットが正しいメッセージの1つに置き換わり、コミットの数は増えません。

</details>

<details>
<summary>問2の解答例</summary>

```bash
git add 単価メモ.md
git commit --amend -m "価格表を更新"
```

入れ忘れたファイルを add してから `--amend` すると、直前のコミットに一緒に含められます。

</details>

<details>
<summary>問3の解答例</summary>

amend は直前のコミットの「修正」ではなく、新しいコミットを「作り直し」て置き換える操作だからです。コミットの ID は中身から計算されるので、作り直したコミットは必ず別の ID になります。

</details>

<details>
<summary>問4の解答例</summary>

amend するとコミットは別物になるため、相手が持っている記録と自分の記録がずれてしまうからです。同じはずのコミットが2つの姿を持ち、突き合わせたときに話が合わなくなります。

</details>

## 確認クイズ

### Q1. コミット直後にメッセージの誤字に気づきました。直前のコミットを正しいメッセージで作り直すコマンドはどれですか。

- A. git commit -m "正しいメッセージ" をもう一度打つ
- B. git commit --amend -m "正しいメッセージ"
- C. git restore --staged で取り消してから編集し直す

<details>
<summary>答え</summary>

**B** — --amend は直前のコミットを作り直します。A は誤字コミットの上に新しいコミットが積まれるだけで、誤字は履歴に残ります。

</details>

### Q2. amend の前後でコミットの ID はどうなりますか。

- A. 同じコミットを直しただけなので、ID は変わらない
- B. ID が変わる(前とは別のコミットになる)
- C. メッセージを変えたときだけ ID が変わる

<details>
<summary>答え</summary>

**B** — amend は「作り直して置き換え」なので、必ず別のコミットになります。ID は中身から計算されるため、少しの違いでも別の ID になります。

</details>

### Q3. amend で作り直してよいコミットはどれですか。

- A. まだ共有していない、自分の手元だけにあるコミット
- B. 他の人にもう渡したコミット
- C. どんなコミットでも自由に作り直してよい

<details>
<summary>答え</summary>

**A** — 手元だけにあるうちは何度作り直しても安全です。渡した後に作り直すと、相手の持つ記録と食い違いが生まれます。

</details>

### Q4. 「議事録.md を入れ忘れたままコミットしてしまった」ときの正しい手順はどれですか。

- A. git commit --amend だけを打てば、入れ忘れも自動で含まれる
- B. git add 議事録.md してから git commit --amend する
- C. 議事録.md を編集すれば、直前のコミットに自動で入る

<details>
<summary>答え</summary>

**B** — amend が作り直しに使うのは add 済みの内容です。先に入れ忘れたファイルを add してから --amend します。

</details>
