# レッスン5-2 直前のコミットを直す

## このレッスンの目標

- [ ] git commit --amend で直前のコミットを作り直せる
- [ ] amend で ID が変わる(別のコミットになる)ことを説明できる
- [ ] amend を使ってよいのは共有前だけ、と判断できる

## 5-2-1 --amendで作り直す

> **git commit --amend で、直前のコミットを作り直せる(メッセージ修正・入れ忘れ)**

コミットした直後の「あっ」は誰にでもあります。代表的なのはこの2つです。

- コミットメッセージの誤字に気づいた
- 一緒に入れるはずのファイルを add し忘れていた

どちらも `--amend` で、直前のコミットを作り直して解決できます。

```bash
git commit -m "日報を追加w"        # 誤字に気づいた
git commit --amend -m "日報を追加"
# → 直前のコミットが正しいメッセージで作り直される
```

入れ忘れの場合は、忘れたファイルを add してから `--amend` します。

```bash
git add 議事録.md                  # 入れ忘れたファイルを載せる
git commit --amend -m "会議の記録を追加"
# → 直前のコミットに 議事録.md も含まれる
```

どちらの場合もコミットの数は増えません。修正版で置き換えた、きれいな1つのコミットになります。対象は直前の1つだけで、それより古いコミットには使えません。

## 5-2-2 amendはIDが変わる

> **amend すると ID が変わる(=前とは別のコミットになる)**

`--amend` は「直前のコミットを直している」ように見えますが、実際の動きは違います。「修正」ではなく「新しく作り直して置き換え」です。

```text
amend 前: a1b2c3d 日報を追加w
amend 後: f8e9d0a 日報を追加    # ← 先頭のIDが別物になった
```

コミットの ID(ハッシュ)は中身から計算されます。メッセージ1文字でも変われば別の ID になるので、amend 後のコミットは必ず前とは別物です。元のコミットは履歴から外れ、新しいコミットが代わりに立ちます。

`git log --oneline` を amend の前後で見比べると、先頭の ID が入れ替わっているのを自分の目で確かめられます。

## 5-2-3 amendは共有前だけ

> **amend で作り直してよいのは、まだ共有していないコミットだけ**

amend は手軽ですが、使ってよい場面には条件が1つあります。

| コミットの状態 | amend |
| --- | --- |
| 自分の手元だけにある | 何度作り直してもよい |
| 他の人にもう渡した | しない |

理由は前のトピックの通り、amend でコミットが別物になるからです。他の人に渡した後で自分の手元だけ作り直すと、相手が持つ記録と自分の記録がずれます。同じはずのコミットが2つの姿を持ち、突き合わせたときに話が合わなくなります。

自分の手元だけにあるうちは、履歴を整える道具として安心して使えます。迷ったら「作り直さない」方を選んでください。共有した後のやり直し方は、次のレッスンで扱います。
