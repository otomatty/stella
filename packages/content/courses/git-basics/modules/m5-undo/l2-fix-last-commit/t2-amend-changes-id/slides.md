# amendはIDが変わる

Git入門 — Module 5 / レッスン5-2

## なぜ必要か

- --amend は「直前のコミットを直している」ように見える
- 直した後も、同じコミットのままなのだろうか?

<!-- ノート: 「上書き保存」のイメージで捉えると誤解します。実際に何が起きているのかを確かめたい、という問いです。 -->

---

## 結論

**amend すると ID が変わる(=前とは別のコミットになる)**

- 実際の動きは「修正」ではなく「作り直して置き換え」
- 元のコミットは履歴から外れ、新しいコミットが代わりに立つ

<!-- ノート: コミットのID(ハッシュ)は中身から計算されるので、少しでも変われば別のIDになります。だからamend後は必ず別のコミットです。 -->

---

## 最小の例

```text
amend 前: a1b2c3d 日報を追加w
amend 後: f8e9d0a 日報を追加    # ← 先頭のIDが別物になった
```

- git log --oneline を前後で見比べると、入れ替わりが確かめられる

<!-- ノート: 実際にlog --onelineで前後を見比べるのが一番分かりやすいです。演習で手を動かして確かめます。 -->
