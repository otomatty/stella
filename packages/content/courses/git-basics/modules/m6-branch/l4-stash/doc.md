# レッスン6-4 作業の一時退避

## このレッスンの目標

- [ ] 未コミットの変更がブランチ切り替えを止める理由を説明できる
- [ ] git stash / git stash pop で変更を退避して戻せる
- [ ] stash を一時置きに留め、早めにコミットへ昇格できる

## 6-4-1 未コミットは切り替えを止める

> **コミットしていない変更があると、ブランチを切り替えられないことがある**

作業の途中で「急ぎで別ブランチを見てほしい」と頼まれる。実務ではよくある割り込みです。ところが、ファイルを編集途中のまま `git switch` すると、エラーで断られることがあります。

```bash
git switch add-template
# error: Your local changes to the following files
# would be overwritten by checkout:
#   memo.md
```

理由はレッスン6-2で学んだ switch の性質にあります。

- switch は作業フォルダの中身を、移り先のブランチの状態に入れ替える
- コミットしていない変更は、まだどこにも記録されていない
- 入れ替えると未コミットの変更が上書きで消えてしまう場合、Git は切り替えを断る

つまりこのエラーは、**あなたの変更を守るための保護**です。「memo.md の変更が上書きされてしまうから移れない」と読めれば、怖いものではありません。

なお、変更内容が移り先と衝突しない場合は、未コミットのまま切り替えられることもあります。「止まることがある」であって「必ず止まる」ではない点も覚えておきましょう。

## 6-4-2 git stashで退避する

> **git stash で、作業中の変更をいったん退避して手元をきれいにできる**

切り替えを止められたら、どうするか。コミットしてしまえば移れますが、作りかけの中途半端な状態を記録に残したくない場面もあります。そこで使うのが **stash** です。

```bash
git stash
# Saved working directory and index state WIP on main: ...
git status
# nothing to commit, working tree clean
```

- 作業中の変更が、退避場所へしまわれます(消えるのではなく、しまうだけ)
- 手元は最後のコミットの状態に戻り、working tree clean になります
- きれいになったので、ブランチを自由に切り替えられます

出力にある WIP は work in progress(作業中)の意味です。机の引き出しに書きかけの書類をしまって、机の上を空ける——そんなイメージの道具です。

## 6-4-3 stash popで戻す

> **git stash pop で、退避した変更を作業フォルダに戻す**

割り込み作業が済んだら、退避した変更の続きに戻ります。取り出しは `git stash pop` です。

```bash
git stash pop
# Changes not staged for commit:
#   modified:   memo.md
# Dropped refs/stash@{0} (...)
```

- しまった変更が作業フォルダに戻り、編集途中だったファイルがそのままの姿で帰ってきます
- 最後の行の Dropped は「退避場所から取り出した」という報告です(pop = 出して、退避場所からは消す)

戻した後は、普段どおり編集の続き → add → commit と進めばよいだけです。**stash でしまって、pop で出す**。この往復がワンセットです。

## 6-4-4 stashは一時置き

> **stash は一時置き(長居させず、早めにコミットへ昇格させる)**

stash は便利なので、何でもしまいたくなります。しかし、しまったまま日が経つと「何を・なぜ退避したのか」が自分でも思い出せなくなります。stash の中身には、コミットのようなメッセージ付きの記録性がないからです。

```text
×: stash に入れたまま数日放置
   → 何を・なぜ退避したのか分からなくなる

○: 割り込みが済んだらすぐ pop
   → 区切りが付き次第、コミットに昇格させる
```

位置づけを間違えないことが大事です。

- stash は割り込みをしのぐための**机の引き出し**であって、保管庫ではない
- ちゃんとした記録はコミットだけ。「いつ・誰が・何を・なぜ」が残るのはコミットの側
- 用が済んだら pop で出し、区切りが付いたら add して commit で**記録に昇格**させる

「しまう時間は短いほどよい」が stash の使い方のコツです。stash が溜まっている状態は黄色信号だと思ってください。
