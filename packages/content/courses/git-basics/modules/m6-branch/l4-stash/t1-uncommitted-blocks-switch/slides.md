## なぜ必要か

- 作業の途中で「急ぎで別ブランチを見てほしい」と頼まれることがある
- 編集途中のまま switch すると、エラーで断られることがある

<!-- ノート: 割り込み作業は実務の日常。そこで初めてこのエラーに出会うと焦るので、先に仕組みを知っておく。 -->

---

## 結論

**コミットしていない変更があると、ブランチを切り替えられないことがある**

- switch はフォルダの中身を入れ替える。未コミットの変更が上書きで消えそうなとき、Gitは切り替えを断る
- 断るのは、あなたの変更を守るため

<!-- ノート: エラーは意地悪ではなく保護。switchの「中身が入れ替わる」性質と、未コミットの変更は記録されていないことを結びつけて説明する。 -->

---

## 最小の例

```bash
git switch add-template
# error: Your local changes to the following files
# would be overwritten by checkout:
#   memo.md
```

- 「memo.md の変更が上書きされてしまうから移れない」と言っている
