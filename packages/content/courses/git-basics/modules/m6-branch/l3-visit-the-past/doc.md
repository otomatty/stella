# レッスン6-3 過去を見に行く

## このレッスンの目標

- [ ] git switch --detach ID で過去のスナップショットを開ける
- [ ] detached HEAD の表示を見ても、壊れていないと判断できる
- [ ] git switch でブランチへ戻り、いつもの状態に復帰できる

## 6-3-1 過去のコミットを開く

> **git switch --detach ID で、過去のスナップショットをその場で開ける**

「先週の時点では動いていたはず。実物を開いて確かめたい」。実務ではよくある場面です。`git log` や `git show` で差分を読むだけでは分からないことも、当時のファイル一式を丸ごと開けば分かります。

Module 1 で学んだとおり、コミットは差分ではなく**その時点のプロジェクト全体のスナップショット**です。だから、丸ごと開けます。

```bash
git switch --detach 3f2a9c1
# HEAD is now at 3f2a9c1 価格表を追加
```

- `--detach` を付けて、ブランチ名の代わりにコミットIDを指定します
- ID は `git log --oneline` で調べた先頭7桁で十分です
- 実行すると、作業フォルダの中身がそのコミット時点の状態になります

開いた後は、普通にファイルを開いて読めます。「当時どう書いてあったか」を、実物で確かめられるわけです。

## 6-3-2 detached HEADは見学モード

> **detached HEAD は「どの枝にも居ない見学モード」の表示(壊れていない)**

過去のコミットを開くと、「detached HEAD」という見慣れない英語が表示されます。警告のような見た目なので「壊してしまったのでは」と焦りやすいのですが、**エラーでも故障でもありません**。

```bash
git status
# HEAD detached at 3f2a9c1
```

意味を分解するとこうなります。

- HEAD は Module 4 で学んだ「自分が今どこに居るか」を指す印
- 普段の HEAD はブランチ(付箋)を指している
- いまは付箋から外れて(detached)、コミット 3f2a9c1 を直接指している

つまり「どのブランチにも居ない、見学モードです」という現在地の報告にすぎません。過去を眺める分にはまったく問題ありません。

ひとつだけ注意があります。見学モードのままコミットを積むと、どのブランチの付箋も付いていない場所にコミットができて、迷子になりやすくなります。この研修では、**見学モードでは見るだけ**に留めましょう。

## 6-3-3 ブランチに戻る

> **git switch main のようにブランチへ移れば、いつもの状態に戻る**

見学が済んだら、いつもの作業に戻ります。特別な脱出コマンドは要りません。**帰り方は普通のブランチ移動と同じ**です。

```bash
git switch main
# Switched to branch 'main'
git status
# On branch main
```

- ブランチ名を指定して `git switch` すれば、HEAD が付箋に戻り、見学モードは終わります
- `git status` が見慣れた「On branch main」に戻れば、帰ってきた証拠です
- 見学前に作業ブランチに居たなら、そのブランチ名を指定して帰ればよいだけです

「行く(switch --detach ID)・読む・帰る(switch ブランチ名)」の3点セットで、過去の見学は完了です。帰り方が分かっていれば、安心して過去を見に行けます。
