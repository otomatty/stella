# 6-1-3
# 作業はブランチで

Git入門研修 — Module 6 / レッスン6-1

<!-- ノート: mainが完成の置き場だと決めたので、では作業はどこでやるのか、という当然の続きに答えます。 -->

---

## なぜ必要か

- main が完成の置き場なら、作りかけのコミットを main に積むわけにはいかない
- 作業を途中で止めても、main が壊れない場所が欲しい

<!-- ノート: 前トピックの約束から自然に導く。作りかけを本流に積むと「main = 完成」が嘘になる、という筋。 -->

---

## 結論

**作業は main に直接ではなく、作業用ブランチで行う**

- 直しごとに作業用のブランチを作り、コミットはそこへ積む
- できあがったら後で main に取り込む(取り込み方は後のモジュールで)

<!-- ノート: 現場の大原則。作業用ブランチの上なら、失敗しても作りかけでもmainは無傷。取り込みの手順はまだ教えず、後で学ぶとだけ言う。 -->

---

## よくある間違い

```text
×: main の上で直接作業
   → 作りかけのコミットが main に積まれ、完成の置き場が崩れる

○: 作業用ブランチの上で作業
   → main はいつ見ても完成の状態のまま
```

- 「まず作業用ブランチを作る」が、作業を始めるときの合図

<!-- ノート: 対比で押さえる。1人での練習ならmain直でも動くが、チームに入った瞬間に事故になるので、今のうちに型にしておく。 -->
