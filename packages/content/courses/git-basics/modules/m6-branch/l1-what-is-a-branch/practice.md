# レッスン6-1 演習 — ブランチとは

対象トピック: 6-1-1 〜 6-1-4

このレッスンはブランチの概念を押さえる回です。ブランチを操作するコマンドは次のレッスンで学ぶので、ここでは今まで覚えたコマンドで「自分がずっと main に居たこと」を確かめます。

## ハンズオン

手元の VS Code のターミナルで試します。これまでの練習で使ってきた `~/git-practice` リポジトリを使います。

1. 練習用リポジトリへ移動します

```bash
cd ~/git-practice
```

2. `git status` を打ち、先頭の表示を確かめます

```bash
git status
# On branch main   ← 「いま main ブランチに居る」という意味
```

これまで何度も見てきたこの1行が「今いるブランチ」の表示でした。お使いの環境で `main` ではなく `master` と表示される場合は、既定のブランチ名が違うだけなので読み替えてください。

3. `git log --oneline` で履歴を眺めます

```bash
git log --oneline
```

ここに並んでいるコミットの列の先頭に、main という「動く付箋」が貼られている——それがこのリポジトリの正体です。

## 演習問題

### 問1(基本)

「ブランチを作ると、作業フォルダのファイルが複製される」。この説明は正しいですか。理由も添えて答えてください。

### 問2(基本)

main というブランチには、現場でどんな役割の約束が載っていますか。1文で答えてください。

### 問3(応用)

「作業は main に直接ではなく、作業用ブランチで行う」のはなぜですか。main の役割と結びつけて説明してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

正しくありません。ブランチはコミットの連なりに付けた「動く付箋」で、増えるのは目印1枚だけです。

ファイルは1組のまま複製されないので、ブランチを作るのは一瞬で終わります。フォルダのコピーとはまったく別物です。

</details>

<details>
<summary>問2の解答例</summary>

「完成した状態を置く場所」という約束です。

技術的には他のブランチと同じただの付箋ですが、チームの誰が見ても「main = 完成している状態」と信じられるように保ちます。

</details>

<details>
<summary>問3の解答例</summary>

main は完成の置き場なので、作りかけのコミットを直接積むと「main = 完成」という約束が崩れるためです。

作業用ブランチの上なら、失敗しても途中で止めても main は無傷のままです。できあがってから main に取り込みます。

</details>

## 確認クイズ

### Q1. ブランチの説明として正しいものはどれですか。

- A. 作業フォルダを複製したコピーのこと
- B. コミットの連なりに付けた「動く付箋」のこと
- C. コミットを圧縮して保存したファイルのこと

<details>
<summary>答え</summary>

**B** — ブランチの実体はコミットの列に貼った目印です。ファイルは複製されず、新しいコミットを積むと付箋は先頭へ動きます。

</details>

### Q2. main ブランチの説明として正しいものはどれですか。

- A. git init すると最初からある既定のブランチで、完成した状態を置く場所
- B. 自分で作らない限り存在しない特別なブランチ
- C. 一度コミットすると二度と変更できないブランチ

<details>
<summary>答え</summary>

**A** — main は最初から存在する既定のブランチです。「完成した状態を置く場所」という役割の約束を載せて運用します。

</details>

### Q3. 新しい修正作業を始めるときの進め方として適切なものはどれですか。

- A. main の上で直接コミットを積んでいく
- B. 作業用ブランチを作り、コミットはそこへ積む
- C. 作業フォルダをコピーして、コピーの方で作業する

<details>
<summary>答え</summary>

**B** — 作業は作業用ブランチで行います。main は完成の置き場のまま保て、失敗しても main は無傷です。フォルダのコピーは Module 0 で見たとおり破綻します。

</details>

### Q4. 「ブランチを作るのは一瞬」と言えるのはなぜですか。

- A. Git が高性能なPCを必要とするから
- B. 増えるのは付箋1枚だけで、ファイルは複製されないから
- C. ブランチは1つしか作れないから

<details>
<summary>答え</summary>

**B** — ブランチ作成で増えるのは目印1枚だけです。だから気軽に作って、終わったら消す使い方ができます。

</details>
