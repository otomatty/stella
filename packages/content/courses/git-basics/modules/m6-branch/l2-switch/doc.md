# レッスン6-2 ブランチを行き来する

## このレッスンの目標

- [ ] git branch で一覧と現在地(`*`)を確かめられる
- [ ] git switch -c / git switch でブランチを作り、行き来できる
- [ ] コミットが「今いるブランチ」に積まれることを説明できる

## 6-2-1 git branchで一覧する

> **git branch でブランチを一覧でき、今いる場所に * が付く**

ブランチが増えると「いま自分はどのブランチに居るのか」を見失いがちです。ブランチ操作の第一歩は、作ることではなく現在地の確認です。

```bash
git branch
#   add-template
# * main
```

- 引数なしの `git branch` で、このリポジトリのブランチが全部並びます
- 行頭に `*` が付いている行が、いま自分の居るブランチです

この例なら、ブランチは2本あり、いま居るのは main だと読めます。`git status` と同じく、打っても何も変わらない「見るだけ」のコマンドなので、迷ったら何度でも打って構いません。

## 6-2-2 switch -cで作って移る

> **git switch -c 名前 で、新しいブランチを作ってそこへ移る**

レッスン6-1で「作業はブランチで」と決めました。つまり作業を始めるたびに、新しいブランチを作って、そこへ移ることになります。この2手を1コマンドで済ませるのが `git switch -c` です。

```bash
git switch -c add-template
# Switched to a new branch 'add-template'
```

- `switch` はブランチを移るコマンド、`-c` は「作ってから移る」のオプションです(create の c)
- 出力の1行が「新しいブランチを作って移った」ことの確認になっています
- 作った瞬間から、コミットはそのブランチに積めます

ブランチ名は英数字とハイフンで、何の作業か分かる名前にします(例: 日報テンプレートを足す作業なら `add-template`)。実務で作業を始めるときにいちばんよく打つ形なので、「作業開始 = switch -c」で覚えてしまいましょう。

## 6-2-3 switchで移る

> **git switch 名前 で移ると、フォルダの中身がそのブランチの状態になる**

既にあるブランチへ移るときは、`-c` なしの `git switch` です。作業の途中で「main の状態を確認したい」といった場面でよく使います。

```bash
git switch main
# Switched to branch 'main'
```

大事なのは、移った瞬間に起きることです。**Git が作業フォルダのファイルを、そのブランチの最新コミットに合わせて入れ替えます**。

- add-template で作ったファイルは、main に移ると見えなくなります(main にはまだ無い状態だから)
- 見えなくなったファイルも消えてはいません。元のブランチに戻れば、また現れます

初めてこれを見ると「ファイルが消えた!」と焦りますが、正常な動きです。付箋の位置に合わせて手元の世界が切り替わっているだけです。

## 6-2-4 コミットは今いる枝に積まれる

> **コミットは「今いるブランチ」に積まれる(commit の前に branch で確かめる)**

ブランチが複数あると、コミットの行き先が気になります。ルールは1つだけです。

- コミットは**今いるブランチ**に積まれ、そのブランチの付箋が1つ進む
- 行き先を指定する方法はない。今いる場所がすべて
- 別のブランチに積みたければ、先に `git switch` で移ってからコミットする

「main のつもりで作業ブランチに積んでいた」「作業ブランチのつもりで main に積んでいた」は定番の事故です。防ぎ方も1つで、**コミットの前に `git branch` で現在地を確かめる**ことです。

```bash
git branch
#   main
# * add-template   ← いまここ
git commit -m "日報テンプレートを追加"
# → add-template に積まれる。main は動かない
```

「branch で確かめてから commit」をワンセットの習慣にしておくと、この事故はほぼ防げます。
