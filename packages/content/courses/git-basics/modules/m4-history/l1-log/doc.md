# レッスン4-1 logを使いこなす

## このレッスンの目標

- [ ] git log の表示が新しい順であることを前提に履歴を読める
- [ ] --oneline とファイル名指定で、見たい履歴に絞り込める
- [ ] -p で各コミットの差分まで確認できる

## 4-1-1 logは新しい順

> **git log は履歴を新しい順に表示する**

コミットを重ねていくと、履歴は何十件にも育っていきます。「さっき何をコミットした?」「先週は何をした?」と読み返すとき、最初に知っておくべきなのは表示の並び順です。

```bash
git log
# commit a1b2c3d...   ← 一番上が最新
#     価格表に単価を追記
# commit 9e8f7a6...
#     価格表を作成
```

- **一番上が最新のコミット**です
- 下へ読み進めるほど、過去へさかのぼります

直近の仕事ほど確認したい頻度が高いので、この順は理にかなっています。件数が多いとスクロール画面(ページャー)に切り替わりますが、`q` キーで一覧から抜けられます。矢印キーやスペースキーで下へ進めます。

## 4-1-2 --onelineで一覧する

> **git log --oneline で、1行1コミットの一覧になる**

git log は1コミットに数行を使う詳しい表示です。数件を見るには良いのですが、20件30件と増えると全体の流れを見渡せません。そこで `--oneline` オプションを使います。

```bash
git log --oneline
# a1b2c3d 価格表に単価を追記
# 9e8f7a6 価格表を作成
# 4d5e6f7 日報のひな形を追加
```

- 各行は「短いハッシュ + コミットメッセージ」の1行だけ
- 並び順は git log と同じで、一番上が最新

ハッシュは先頭7文字ほどに短縮されますが、コミットを指す目印としてそのまま使えます。2つの表示は次のように使い分けます。

| コマンド | 表示 | 向いている場面 |
| --- | --- | --- |
| `git log` | 1コミット数行の詳細 | 日時や作者まで確かめたいとき |
| `git log --oneline` | 1行1コミット | 全体の流れをざっと見渡すとき |

コミットメッセージを丁寧に書いてきた効果は、この一覧で表れます。1行目だけで「何をしたか」が分かる履歴は、それだけでチームの資産です。

## 4-1-3 ファイルで絞る

> **git log ファイル名 で、そのファイルの履歴だけに絞れる**

履歴には、いろいろなファイルへの変更が混ざって並んでいます。「この価格表、最後に直したのはいつ?」を全履歴から目で探すのは、件数が増えるほどつらくなります。

log の後ろにファイル名を添えると、そのファイルの履歴だけに絞れます。

```bash
git log price.txt
# commit a1b2c3d...
#     価格表に単価を追記
# commit 9e8f7a6...
#     価格表を作成
```

- そのファイルを変えたコミットだけが表示されます
- 日報など、price.txt に関係ないコミットは出てきません

`--oneline` と組み合わせて `git log --oneline price.txt` のようにも書けます。「対象をコマンドの後ろに書いて絞り込む」形は、この先もいろいろな場面で登場する基本の型です。

## 4-1-4 -pで差分ごと読む

> **git log -p で、各コミットの差分も一緒に読める**

log で分かるのは「いつ・誰が・何のためのコミットか」までです。コミットメッセージは要約なので、「実際にどの行が変わったのか」までは書き切れません。細部を知るには、変更の本文である差分を見ます。

`-p`(patch の頭文字)を付けると、各コミットの下にそのコミットの差分が続けて表示されます。

```bash
git log -p
# commit a1b2c3d...
#     価格表に単価を追記
#
# -コーヒー
# +コーヒー 450円
```

- `+` が追加された行、`-` が削除された行。diff の読み方がそのまま通用します
- 全コミット分の差分が続くので長くなります。`q` キーで途中で抜けて構いません

`git log -p price.txt` のようにファイル名と組み合わせれば、「このファイルがどう変わってきたか」を差分で通読できます。一覧は `--oneline`、精読は `-p`。この使い分けが履歴を読む基本の型です。
