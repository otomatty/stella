# レッスン4-2 1つのコミットを調べる

## このレッスンの目標

- [ ] git show で狙ったコミットのメッセージと差分を確認できる
- [ ] HEAD と HEAD~1 を使って、ハッシュを調べずにコミットを指せる
- [ ] git blame で行ごとの変更のいきさつをたどれる

## 4-2-1 git showで中身を見る

> **git show ID で、そのコミットのメッセージと差分を見る**

`--oneline` の一覧で「気になるコミット」が1つ見つかったとします。そのために `git log -p` で全コミットの差分を出すのは大げさです。狙った1つだけを見るには git show を使います。

```bash
git log --oneline
# a1b2c3d 価格表に単価を追記
# 9e8f7a6 価格表を作成

git show a1b2c3d
# commit a1b2c3d...
#     価格表に単価を追記
#
# -コーヒー
# +コーヒー 450円
```

- ID には --oneline で見えた短いハッシュがそのまま使えます
- 表示は「コミットの情報 + メッセージ + 差分」の1コミット分だけ

「一覧(--oneline)で目星を付けて、show で精読する」。これが履歴を調べるときの基本の流れです。

## 4-2-2 HEADは今いる場所

> **HEAD は「自分が今どのコミットに居るか」を指す印**

git log を打つと、一番上のコミットに `HEAD` という表示が付いています。これは Git が持っている「現在地の印」で、**自分が今どのコミットに居るか**を指しています。

- ふだんは、一番新しいコミットを指しています
- コミットするたびに、印は新しいコミットへ自動で進みます
- ハッシュの代わりに `HEAD` と書いてコミットを指せます

```bash
git show HEAD
# commit a1b2c3d...
#     価格表に単価を追記
```

「最新のコミットを確認したい」だけなら、ハッシュを調べる必要はもうありません。`git show HEAD` の一撃で済みます。

なお、log の画面では HEAD の横に別の表示が付いていることがあります。今は「HEAD = 今いるコミットの印」だけ読み取れれば十分です。

## 4-2-3 HEAD~1は1つ前

> **HEAD~1 のように、今いる場所から相対的にコミットを指せる**

「1つ前のコミットと見比べたい」はよくある場面です。そのたびに一覧を開いてハッシュを探すのは手間なので、HEAD を起点にした相対的な指し方を使います。

```bash
git show HEAD~1
# commit 9e8f7a6...
#     価格表を作成
```

- `HEAD~1` は今いる場所の1つ前のコミット
- `HEAD~2` なら2つ前。チルダ(`~`)の後ろの数字が「何個さかのぼるか」

| 書き方 | 指す先 |
| --- | --- |
| `HEAD` | 今いるコミット(ふだんは最新) |
| `HEAD~1` | その1つ前 |
| `HEAD~3` | その3つ前 |

ハッシュは「コミットの番地」、HEAD~1 は「今からの道順」です。どちらでも同じコミットを指せるので、場面に応じて速い方を使ってください。

## 4-2-4 git blameで書いた人を調べる

> **git blame で「その行を最後に変えたコミットと人」を調べられる**

ファイルを読んでいて「この行、なぜこう書いたのだろう?」と思ったとき、事情を知る一番の近道は最後に変えた本人へ聞くことです。その本人を探すのが git blame です。

```bash
git blame price.txt
# a1b2c3d (佐藤花子 2026-08-18) コーヒー 450円
# 9e8f7a6 (佐藤花子 2026-08-10) 紅茶
```

- 行ごとに「ハッシュ・名前・日時」が左側に付きます
- 出てきたハッシュを `git show` に渡せば、コミットメッセージと差分まで読めます

blame は「責める」という意味の物騒な名前ですが、実際には経緯を調べて相談相手を見つけるための道具です。「誰のせいか」ではなく「なぜこうなったか」を知るために使ってください。丁寧なコミットメッセージが残っていれば、聞きに行く前に理由まで分かることも多いです。
