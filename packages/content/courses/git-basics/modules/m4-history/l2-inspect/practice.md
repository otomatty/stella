# レッスン4-2 演習 — 1つのコミットを調べる

対象トピック: 4-2-1 〜 4-2-4

レッスン4-1で使った練習用リポジトリ `~/git-practice` の続きで演習します。price.txt と、その2つのコミット(「価格表を作成」「価格表に単価を追記」)がある前提です。

## ハンズオン

VS Code のターミナルで、コミットを1つずつ狙って調べます。

1. 練習用リポジトリへ移動し、一覧で目星を付けます

   ```bash
   cd ~/git-practice
   git log --oneline
   ```

2. 「価格表に単価を追記」の行の短いハッシュを使って、そのコミットだけを表示します(ハッシュは自分の画面の値に読み替えてください)

   ```bash
   git show a1b2c3d
   ```

   メッセージと差分(`-コーヒー` / `+コーヒー 450円`)が1コミット分だけ出れば成功です。

3. 同じ「最新のコミットを見る」を、ハッシュを調べずにやってみます

   ```bash
   git show HEAD
   ```

   git log の一番上のコミットに `HEAD` の表示が付いていることも確かめてください。

4. 1つ前のコミットを相対的に指して表示します

   ```bash
   git show HEAD~1
   ```

   手順2より1つ古いコミットが出ることを確かめたら、`HEAD~2` も試してみましょう。

5. price.txt を行単位で調べます

   ```bash
   git blame price.txt
   ```

   各行の左に「ハッシュ・名前・日時」が付きます。名前が自分になっているのは、自分がコミットしたからです。

6. blame で見えた「コーヒー 450円」の行のハッシュを `git show` に渡し、その行を変えたコミットのメッセージと差分を確かめます

## 演習問題

### 問1(基本)

最新のコミットのメッセージと差分を、ハッシュを調べずに表示するコマンドを書いてください。

### 問2(基本)

今いる場所から2つ前のコミットを表示するコマンドを書いてください。

### 問3(応用)

`report.txt` の中のある1行について、「最後に変えたのは誰か」と「そのときのコミットメッセージ」を知りたいです。使うコマンドを順番に2つ書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

```bash
git show HEAD
```

HEAD は「自分が今どのコミットに居るか」を指す印で、ふだんは最新のコミットを指しています。show に渡せばハッシュを調べる手間が省けます。

</details>

<details>
<summary>問2の解答例</summary>

```bash
git show HEAD~2
```

チルダの後ろの数字が「何個さかのぼるか」です。HEAD~1 なら1つ前、HEAD~2 なら2つ前を指します。

</details>

<details>
<summary>問3の解答例</summary>

```bash
git blame report.txt
git show a1b2c3d   # blame で見えたその行のハッシュに読み替える
```

まず blame で、その行を最後に変えたコミットのハッシュと人が分かります。次にそのハッシュを show に渡せば、コミットメッセージと差分まで読めます。

</details>

## 確認クイズ

### Q1. git show a1b2c3d で表示されるものとして正しいものはどれですか。

- A. そのコミットのメッセージと差分
- B. リポジトリの全コミットの一覧
- C. まだコミットしていない作業中の変更

<details>
<summary>答え</summary>

**A** — git show ID は、そのコミット1つ分の情報・メッセージ・差分を表示します。一覧を見るのは git log の役割です。

</details>

### Q2. HEAD の説明として正しいものはどれですか。

- A. リポジトリで一番古いコミットを指す印
- B. 自分が今どのコミットに居るかを指す印
- C. まだ記録されていない変更の一覧

<details>
<summary>答え</summary>

**B** — HEAD は「今いるコミット」を指す印で、ふだんは一番新しいコミットを指しています。コミットするたびに新しいコミットへ進みます。

</details>

### Q3. HEAD~1 が指すものとして正しいものはどれですか。

- A. 今いるコミットの1つ前のコミット
- B. リポジトリの最初のコミット
- C. 次にコミットしたら作られる予定のコミット

<details>
<summary>答え</summary>

**A** — チルダの後ろの数字だけ、今いる場所からさかのぼります。HEAD~1 は1つ前、HEAD~2 は2つ前です。

</details>

### Q4. git blame price.txt で分かることとして正しいものはどれですか。

- A. price.txt を次に誰が直すべきかという担当割り
- B. price.txt の各行を最後に変えたコミットと人
- C. price.txt を削除してよいかどうか

<details>
<summary>答え</summary>

**B** — blame は行ごとに「最後に変えたコミットのハッシュ・名前・日時」を表示します。責めるためでなく、いきさつを知って相談するための道具です。

</details>

### Q5. 「気になるコミットを1つ調べる」ときの基本の流れとして適切なものはどれですか。

- A. git log --oneline で目星を付け、そのハッシュを git show に渡す
- B. git log -p の出力を毎回すべて読み通す
- C. ファイルをコピーしてから開いて見比べる

<details>
<summary>答え</summary>

**A** — 一覧で探して show で精読する、が基本形です。log -p の通読は的を絞れず、コピーを増やす管理には戻りません。

</details>
