# git diffで変更を読む

Git入門 — Module 2 / レッスン2-1

<!-- ノート: statusで「変わった」と分かった後、変更の中身を確かめるコマンドを1つ覚えます。 -->

---

## なぜ必要か

- git status で分かるのは「どのファイルが modified か」まで
- 中のどの行をどう変えたのかは、status には出てこない

<!-- ノート: 「昨日どこを直したんだっけ」は毎日起きる。ファイル名だけでは記録してよいか判断できません。 -->

---

## 結論

**git diff で「これから記録しようとしている変更」を読める**

- status がファイル名なら、diff は中身
- 記録する前に、自分の変更を自分で読める

<!-- ノート: diffは差分という意味。statusとdiffは毎日ペアで使う道具になります。 -->

---

## 最小の例

```bash
git diff
# nippou.txt の変わった行が表示される
# 変わっていないファイルは表示されない
```

- 編集した箇所だけが抜き出されて表示される
