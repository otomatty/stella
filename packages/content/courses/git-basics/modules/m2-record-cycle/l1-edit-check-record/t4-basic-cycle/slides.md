# 基本サイクル

Git入門 — Module 2 / レッスン2-1

<!-- ノート: ここまでのコマンドを1本の流れにまとめます。毎日この順で手が動くようになるのがゴールです。 -->

## なぜ必要か

- コマンドを個別に覚えても、実務では「次に何を打つか」で止まる
- 迷わないためには、決まった順番を体に入れてしまうのが早い

<!-- ノート: 未経験者が詰まるのはコマンドの意味より順番です。型として覚えてしまえば迷いが消えます。 -->

---

## 結論

**編集 → status → diff → add → commit が日々の基本サイクル**

- status で「何が変わったか」、diff で「どう変わったか」を確かめる
- 確かめてから add で選び、commit で記録する

<!-- ノート: 確認の2つが真ん中に挟まっているのがポイント。読まずに記録しない、が型の意味です。 -->

---

## 最小の例

```bash
git status                     # 何が変わった?
git diff                       # どう変わった?
git add nippou.txt
git commit -m "日報に進捗を追記"
```

<!-- ノート: 日報を直した日の流れ。この4行を1セットとして、1日に何度も回すのが日常になります。 -->
