# レッスン2-3 削除と移動も変更

## このレッスンの目標

- [ ] git rm でファイルの削除を変更として記録できる
- [ ] git mv で名前の変更・移動を変更として記録できる
- [ ] エクスプローラで消した場合も git add -A で拾えることを説明できる

## 2-3-1 git rmは削除の記録

> **git rm は「このファイルを消した」という変更を記録する**

変更というと「書き換え」を思い浮かべますが、それだけではありません。使い終わった下書きや古い資料を消すことも、「プロジェクトが変わった」の一種です。削除も履歴に残します。

そのためのコマンドが git rm(remove = 取り除く)です。

```bash
git rm draft.txt
git status
# deleted:    draft.txt
git commit -m "古い下書きを削除"
```

git rm は2つのことを同時にやってくれます。

- ファイルを手元から消す
- 「消した」という変更を、次のコミットに入るように載せる

status に `deleted:` と並んだら、削除が変更として載った印です。あとは commit すれば「消した」ことが履歴に残ります。

## 2-3-2 git mvは移動の記録

> **git mv は「名前を変えた・移動した」という変更を記録する**

「ファイル名が分かりにくいから直したい」も実務でよくある整理です。名前の変更や置き場所の移動も、履歴に残したい変更の一種です。

そのためのコマンドが git mv(move = 動かす)です。名前の変更も「別の名前へ動かす」の一種として、同じコマンドで扱います。

```bash
git mv price.txt price-list.txt
git status
# renamed:    price.txt -> price-list.txt
git commit -m "価格表のファイル名を整理"
```

status には `renamed:` として、古い名前と新しい名前が矢印でつながって表示されます。これが「移動が変更として載った」印です。

## 2-3-3 普通に消してもよい

> **エクスプローラで消しても、git add -A が削除を変更として拾ってくれる**

つい VS Code のエクスプローラで右クリック削除してしまい、「git rm を使い忘れた」と気づくことがあります。心配は要りません。

`git add -A` の `-A` は「削除も含めて、変更を全部載せる」オプション(A = All)です。

```bash
# エクスプローラで old-memo.txt を削除した後
git add -A
git status
# deleted:    old-memo.txt
```

add -A の後の status は、git rm を使ったときと同じ `deleted:` になります。あとはいつも通り commit するだけです。

- 消し方は自由(git rm でも、エクスプローラでも)
- 記録の前に add で載せることだけ忘れない

削除・移動・書き換えのどれであっても、「add で載せて commit で記録する」という流れは変わりません。
