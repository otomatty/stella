# 2-3-1
# git rmは削除の記録

Git入門 — Module 2 / レッスン2-3

<!-- ノート: このレッスンでは、書き換え以外の変更を扱います。まずはファイルの削除です。 -->

---

## なぜ必要か

- 使い終わった下書きや古い資料など、消したいファイルは必ず出てくる
- 削除も「プロジェクトが変わった」の一種。履歴に残したい

<!-- ノート: 変更=書き換え、と思い込みがち。消すことも立派な変更だ、という視点の転換がこの回のつかみです。 -->

---

## 結論

**git rm は「このファイルを消した」という変更を記録する**

- ファイルを消すのと同時に、削除を次のコミットに入る変更として載せる
- あとは commit すれば「消した」ことが履歴に残る

<!-- ノート: rmはremove(取り除く)の略。手元から消す作業と、消したという記録の準備を1コマンドでやってくれます。 -->

---

## 最小の例

```bash
git rm draft.txt
git status
# deleted:    draft.txt
git commit -m "古い下書きを削除"
```

<!-- ノート: statusにdeletedと並ぶのが「削除が変更として載った」印。commitまでで削除の記録が完成します。 -->
