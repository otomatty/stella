# コミット前にdiffを読む

Git入門 — Module 2 / レッスン2-2

<!-- ノート: 2つのdiffを覚えた仕上げとして、実務で一番効く使いどころを習慣にします。 -->

---

## なぜ必要か

- 「試し書きの行を入れたまま記録した」は定番の事故
- コミットしてから気づくと、直すのに余計な手間がかかる

<!-- ノート: 動作確認用の書き捨て行や消し忘れは誰にでもある。記録する前に気づけるかが分かれ目です。 -->

---

## 結論

**コミットの直前に diff --staged を読む習慣が、入れ間違いを防ぐ**

- コミットされる内容を、記録の直前に自分の目で最終確認する
- 覚えのない行があれば、コミットする前に直せる

<!-- ノート: 送信前にメールを読み返すのと同じ。数秒の確認で、事故の大半は防げます。 -->

---

## 最小の例

```bash
git diff --staged              # 入る内容を最終確認
# +単価: 1,200円
# +test ← 覚えのない行に気づける
```

- 気づいたら、コミットの前にファイルを直してやり直す

<!-- ノート: 試し書きのtestが紛れ込んだ例。commitを打つ手前で必ずdiff --stagedを1回、を口癖にしてもらいます。 -->
