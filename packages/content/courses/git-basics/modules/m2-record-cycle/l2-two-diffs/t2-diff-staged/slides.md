# --stagedはadd済みの変更

Git入門 — Module 2 / レッスン2-2

<!-- ノート: 素のdiffの守備範囲外だったadd済みの変更を見るオプションを覚えます。 -->

---

## なぜ必要か

- add 済みの変更は git diff では見えなくなる
- でも「次のコミットに何が入るのか」こそ、一番確かめたい内容

<!-- ノート: 前トピックの続きの場面。ステージングエリアの中身を読む手段が要る、という流れです。 -->

---

## 結論

**git diff --staged で、add 済みの変更(コミットされる内容)を見る**

- --staged はステージングエリアの中身を見せるオプション
- ここに出るものが、そのまま次のコミットに入る

<!-- ノート: stagedはステージングエリアに載っている、という意味。「コミットされる内容の試し刷り」と言い換えると伝わります。 -->

---

## 最小の例

```bash
git add price.txt
git diff --staged
# +単価: 1,200円
# ↑ 次のコミットに入る変更が表示される
```

<!-- ノート: 素のdiffでは空だった変更が、--stagedを付けると見える。2つのdiffで見る場所が違うことを実演します。 -->
