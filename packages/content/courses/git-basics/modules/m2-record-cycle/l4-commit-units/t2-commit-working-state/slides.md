# 動く状態でコミットする

Git入門研修 — Module 2 / レッスン2-4

<!-- ノート: 1コミット1目的に続く、単位のもう1つの基準です。「どのタイミングで区切るか」を扱います。 -->

---

## なぜ必要か

- 履歴のうれしさは「壊れる前に戻れる」ことだった
- 戻った先が壊れた状態だったら、履歴の保険が効かない

<!-- ノート: Module 0で学んだ「戻れる」を思い出させます。戻り先の品質、という視点がこの回の切り口です。 -->

---

## 結論

**コミットは「動く状態」で行う(戻り先として使えるように)**

- コミットは1つ1つが「戻り先の候補」になる
- 書きかけでエラーが出る状態は、区切りとして選ばない

<!-- ノート: 動く状態=資料なら読める状態、プログラムならエラーなく動く状態。キリのよさの基準を「動くか」に置きます。 -->

---

## よくある間違い

```text
悪い例: "作業途中(まだ動かない)" ← 戻っても壊れている
良い例: "検索機能を追加"          ← 戻ればそのまま使える
```

- 迷ったら「今この状態に戻って作業を再開できるか?」と自問する

<!-- ノート: 悪い例は戻り先として役に立たない。区切る前にひと呼吸、動く状態まで持っていってからコミットします。 -->
