# 2-4-4
# addで変更を分けられる

Git入門研修 — Module 2 / レッスン2-4

<!-- ノート: 1コミット1目的を実現する具体的な手つきです。addの2段階方式がここで効いてきます。 -->

---

## なぜ必要か

- 気づけば2つの目的のファイルを両方直してしまっていることがある
- 「もう混ざったから1コミットでいいや」と諦めたくなる

<!-- ノート: 作業中に別の直しに気づくのは日常茶飯事。編集が混ざっても記録は分けられる、が救いになります。 -->

---

## 結論

**ファイル単位で add すれば、1回の作業を複数のコミットに分けられる**

- add は「次のコミットに入れるものを選ぶ」道具だった
- 選んで記録、を繰り返せば、目的ごとのコミットに分けられる

<!-- ノート: 2段階記録の意味がここで回収されます。ステージングエリアは、変更を仕分けるための待合室です。 -->

---

## 最小の例

```bash
git add nippou.txt
git commit -m "日報に進捗を追記"
git add price-list.txt
git commit -m "価格表の単価を更新"
```

<!-- ノート: 2ファイルを直した後でも、選んで記録を2回繰り返せば目的ごとの2コミットになります。 -->
