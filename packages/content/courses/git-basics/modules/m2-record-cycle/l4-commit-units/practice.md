# レッスン2-4 演習 — コミットの単位

対象トピック: 2-4-1 〜 2-4-4

## ハンズオン

手元の VS Code のターミナルで試します。これまでのレッスンで使った `~/git-practice` の続きです。`nippou.txt` と `price-list.txt` がある状態から始めます。

1. 練習用リポジトリに移動します

   ```bash
   cd ~/git-practice
   ```

2. VS Code で2つのファイルを両方編集して保存します(わざと2つの目的の変更を混ぜます)

   - `nippou.txt` に `2/18 単価改定の連絡` の行を追記する
   - `price-list.txt` に `セット割: 10%引き` の行を追記する

3. git status で、2つのファイルが両方 modified になっていることを確認します

   ```bash
   git status
   ```

4. 日報の変更だけを選んで、1つ目のコミットにします

   ```bash
   git add nippou.txt
   git diff --staged
   git commit -m "日報に2/18の作業を追記"
   ```

5. git status を打ち、`price-list.txt` の変更がまだ残っていることを確認します

6. 価格表の変更を選んで、2つ目のコミットにします

   ```bash
   git add price-list.txt
   git diff --staged
   git commit -m "価格表にセット割を追記"
   ```

7. git log でコミットの一覧を眺め、2つの変更が目的ごとに分かれて記録されたことを確かめます

   ```bash
   git log
   ```

## 演習問題

### 問1(基本)

「日報追記と価格修正と誤字修正」という1つのコミットには、どんな問題がありますか。

### 問2(基本)

「コミットは動く状態で行う」のはなぜですか。履歴のうれしさと結びつけて答えてください。

### 問3(応用)

半日コミットせずに作業を続けることには、どんなリスクがありますか。「戻れる場所」という言葉を使って説明してください。

### 問4(応用)

日報と価格表の2ファイルを両方編集してしまいました。これを目的ごとの2コミットに分けるには、どんな手順を踏めばよいですか。コマンドの流れで答えてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

目的が3つ混ざっているため、後から「価格の変更だけ見たい」といった追い方ができません。

コミットメッセージも1文で書けなくなります。「〜と〜を直した」と書きたくなったら、コミットを分けるサインです。

</details>

<details>
<summary>問2の解答例</summary>

コミットは1つ1つが「戻り先の候補」になるからです。壊れた状態でコミットすると、戻った先も壊れていて、履歴の保険が効きません。

</details>

<details>
<summary>問3の解答例</summary>

戻れる場所が半日前のコミットしかないため、事故が起きると最大で半日分の作業を失います。

こまめにコミットしていれば、直前の戻れる場所までの数分〜数十分の損害で済みます。戻れる場所の間隔が、失う作業の最大量になります。

</details>

<details>
<summary>問4の解答例</summary>

ファイル単位で add と commit を2回繰り返します。

```bash
git add nippou.txt
git commit -m "日報に作業を追記"
git add price-list.txt
git commit -m "価格表を修正"
```

編集が混ざっても、add で選んでから記録すれば、コミットは目的ごとに分けられます。

</details>

## 確認クイズ

### Q1. コミットの単位として最も適切なものはどれですか。

- A. 1日の作業をまとめて1コミット
- B. 1つの意味のある変更ごとに1コミット
- C. ファイルを保存するたびに必ず1コミット

<details>
<summary>答え</summary>

**B** — 1コミット1目的が基本です。メッセージが1文で書ける単位にすると、後から履歴を追いやすくなります。

</details>

### Q2. コミットするタイミングとして適切なものはどれですか。

- A. エラーが出ていても、時間で区切って必ずコミットする
- B. 動く状態になったところでコミットする
- C. 全部の作業が終わる最後まで、コミットしない

<details>
<summary>答え</summary>

**B** — コミットは戻り先の候補です。動く状態で区切るから、戻ったときにそのまま作業を再開できます。

</details>

### Q3. 「こまめにコミットする」ことの利点はどれですか。

- A. 戻れる場所が増え、事故のときに失う作業が小さくなる
- B. ファイルの容量が節約できる
- C. コミットメッセージを書かなくてよくなる

<details>
<summary>答え</summary>

**A** — 戻れる場所の間隔が失う作業の最大量になります。コミットは無料の保険なので、こまめにかけ直すのが得です。

</details>

### Q4. 日報と価格表の2ファイルを両方編集した後、目的ごとに2つのコミットへ分けたいとき、正しい手順はどれですか。

- A. git add . で全部載せてから、1回のコミットで済ませる
- B. git add nippou.txt → commit、git add price-list.txt → commit の順で繰り返す
- C. 一度ファイルのコピーを作ってから、別々のフォルダでコミットする

<details>
<summary>答え</summary>

**B** — ファイル単位で add して記録、を繰り返せば、編集が混ざっていてもコミットは目的ごとに分けられます。コピーを増やす管理には戻りません。

</details>
