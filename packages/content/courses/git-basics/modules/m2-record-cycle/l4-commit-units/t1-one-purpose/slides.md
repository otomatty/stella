# 1コミット1目的

Git入門研修 — Module 2 / レッスン2-4

<!-- ノート: コマンドは打てるようになったので、このレッスンでは「どの単位で記録するか」という判断を扱います。 -->

---

## なぜ必要か

- 1日の作業をまとめて1コミットにすると、後から中身を追えない
- 「何のための変更か」が混ざった記録は、読む人を困らせる

<!-- ノート: 打ち方の次は積み方。夕方にまとめてコミット、をやりがちなので、その何が困るかから入ります。 -->

---

## 結論

**1コミットには、1つの意味のある変更だけをまとめる**

- 「日報の追記」「価格の修正」は別の目的。別のコミットにする
- 目的が1つなら、コミットメッセージも1文で書ける

<!-- ノート: 判断基準はメッセージが1文で書けるか。「〜と〜を直した」と書きたくなったら混ざっているサインです。 -->

---

## よくある間違い

```text
悪い例: "日報追記と価格修正、ついでに誤字も直した"
        ← 目的が3つ混ざった1コミット

良い例: "日報に2/17の作業を追記"
        "価格表の単価を更新"
```

<!-- ノート: 悪い例は後から「価格の変更だけ見たい」ができない。良い例は1つ1つが独立していて追いやすい、と対比します。 -->
