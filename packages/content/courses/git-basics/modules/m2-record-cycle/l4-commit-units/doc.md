# レッスン2-4 コミットの単位

## このレッスンの目標

- [ ] 「1コミット1目的」の判断基準を説明できる
- [ ] 動く状態・こまめな間隔でコミットする理由を説明できる
- [ ] ファイル単位の add で、1回の作業を複数のコミットに分けられる

## 2-4-1 1コミット1目的

> **1コミットには、1つの意味のある変更だけをまとめる**

コマンドは打てるようになりました。次は「どの単位で記録するか」という判断です。

1日の作業をまとめて1コミットにすると、後から中身を追えなくなります。

```text
悪い例: "日報追記と価格修正、ついでに誤字も直した"
        ← 目的が3つ混ざった1コミット

良い例: "日報に2/17の作業を追記"
        "価格表の単価を更新"
```

悪い例では、後から「価格の変更だけ見たい」ができません。良い例は1つ1つが独立していて、変更のいきさつを追いやすくなります。

判断基準はシンプルです。**コミットメッセージが1文で書けるか**。「〜と〜を直した」と書きたくなったら、目的が混ざっているサインです。

## 2-4-2 動く状態でコミットする

> **コミットは「動く状態」で行う(戻り先として使えるように)**

履歴のうれしさは「壊れる前に戻れる」ことでした。コミットは1つ1つが「戻り先の候補」になります。戻った先が壊れた状態では、履歴の保険が効きません。

```text
悪い例: "作業途中(まだ動かない)" ← 戻っても壊れている
良い例: "検索機能を追加"          ← 戻ればそのまま使える
```

「動く状態」とは、資料なら読める状態、プログラムならエラーなく動く状態のことです。書きかけでエラーが出る状態は、区切りとして選びません。

迷ったら「今この状態に戻って、作業を再開できるか?」と自問してください。答えがはいなら、区切りどきです。

## 2-4-3 こまめなコミットは保険

> **こまめにコミットするほど「戻れる場所」が増える**

「キリのいいところまでやってから」とコミットをためると、事故のときに失う量が大きくなります。

```text
こまめな記録: 記録A → 記録B → 記録C → 事故!
              ← 直前の記録Cまで戻れば10分の損害

ためた記録:   記録A → (半日ぶん作業) → 事故!
              ← 記録Aまで半日巻き戻し
```

戻れる場所の間隔が、そのまま「失う作業の最大量」になります。コミットは無料の保険で、多すぎて困ることはまずありません。小さな一歩でも、動く状態になったらすぐ記録しましょう。

## 2-4-4 addで変更を分けられる

> **ファイル単位で add すれば、1回の作業を複数のコミットに分けられる**

実際の作業では、気づけば2つの目的のファイルを両方直してしまっていることがあります。「もう混ざったから1コミットでいいや」と諦める必要はありません。

add は「次のコミットに入れるものを選ぶ」道具でした。選んで記録、を繰り返せば、編集が混ざっていても記録は目的ごとに分けられます。

```bash
git add nippou.txt
git commit -m "日報に進捗を追記"
git add price-list.txt
git commit -m "価格表の単価を更新"
```

これが Module 1 で学んだ「2段階の記録」の本当の狙いです。ステージングエリアは、変更を目的ごとに仕分けるための待合室として働きます。
