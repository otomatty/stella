# 10-4-3
# 間違った枝でコミットした

Git入門研修 — Module 10 / レッスン10-4

<!-- ノート: 困りごとの具体例を1つ。誰もが一度はやる「枝を間違えたままコミット」の対処です。 -->

---

## なぜ必要か

- 枝を出したつもりが、main のままコミットしていた——は誰にでも起きる
- 焦って「消さなきゃ」と履歴に手を出すと、事故が大きくなる

<!-- ノート: statusを見て青ざめる場面の代表です。でもコミットできているなら、実は作業は1つも失われていません。 -->

---

## 結論

**間違った枝でコミットしても、そこから switch -c すればコミットごと新しい枝に移せる**

- コミットは消えていない。慌てて消す必要もない
- その場で新しい枝を作れば、作業はそのまま正しい名前の枝に乗る

<!-- ノート: switch -c は「今いる場所から枝を出す」でした。直前のコミットごと新しい枝に乗るので、作業を失わずに立て直せます。 -->

---

## 最小の例

```bash
# mainのままコミットしてしまった直後に
git switch -c feature/member-search
# → いま作った枝に、さっきのコミットが乗っている
```

- あとは今までどおり、この枝で作業を続ければよい
