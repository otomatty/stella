# レッスン10-4 困ったときの型

## このレッスンの目標

- [ ] 困ったらまず status・log・diff で現在地を確かめる手順を実行できる
- [ ] エラーメッセージから「次の一手」を読み取れる
- [ ] 間違った枝でのコミットを switch -c で立て直し、履歴を消す操作の前に人に相談できる

このレッスンは研修の総仕上げです。新しいコマンドは出てきません。これまで学んだコマンドだけを使って、「困ったときにどう動くか」を型にします。

## 10-4-1 まずstatus/log/diff

> **困ったらまず status・log・diff の3つで現在地を確かめる**

「なんか変だ」と思ったとき、一番危ないのは、状況が分からないまま当てずっぽうにコマンドを打つことです。焦って打った一手が傷を広げることがあります。

そこで最初の型です。困ったら、まずこの3つを打ちます。

```bash
git status          # 今どの枝にいて、何が変更中か
git log --oneline   # どこまでコミットできているか
git diff            # まだ記録していない変更の中身
```

| コマンド | 分かること | 学んだ場所 |
| --- | --- | --- |
| `git status` | 今いるブランチ、変更中・ステージ済みのファイル | Module 1 |
| `git log --oneline` | コミットの積み重ね(どこまで記録済みか) | Module 4 |
| `git diff` | まだ記録していない変更の中身 | Module 2 |

3つとも**見るだけで何も変更しない**安全なコマンドなので、何度打っても状況は悪化しません。現在地(どの枝で・何が記録済みで・何が未記録か)が分かれば、打つ手はたいてい絞れます。

## 10-4-2 エラーは次の一手を書いている

> **Git のエラーメッセージには、次に打つべき一手が書いてある**

赤い英語のメッセージが出ると、読まずに閉じて検索に走りがちです。しかし検索で出てきたコマンドのコピペは、自分の状況に合わない一手になりやすいです。実は答えはもっと近くにあります。Git のエラーの多くは、原因と対処のヒントをセットで表示します。

たとえば、変更を残したまま枝を切り替えようとして止められたときの実物です。

```text
error: Your local changes to the following files would be overwritten:
        meeting-notes.txt
Please commit your changes or stash them before you switch branches.
```

最後の行に「切り替える前に、変更を **commit** するか **stash** してください」と、次の一手がそのまま書いてあります。どちらも既に学んだコマンドです。英語でも、コマンド名だけ拾えば十分読めます。**まず読む。読んでから動く**ほうが、結局いちばん速く解決します。

## 10-4-3 間違った枝でコミットした

> **間違った枝でコミットしても、そこから switch -c すればコミットごと新しい枝に移せる**

枝を出したつもりが main のままコミットしていた——これは誰にでも起きます。`git status` の表示を見て青ざめる場面ですが、落ち着いてください。コミットできているなら、作業は1つも失われていません。焦って「消さなきゃ」と履歴に手を出すほうが、事故を大きくします。

対処は1行です。

```bash
# mainのままコミットしてしまった直後に
git switch -c feature/member-search
# → いま作った枝に、さっきのコミットが乗っている
```

`switch -c` は「今いる場所から新しい枝を出して移る」でした(Module 6)。直前のコミットごと新しい枝に乗るので、あとは今までどおりこの枝で作業を続けて、PR にして返せます。

なお、手元の main 側にもそのコミットの記録は残っています。main をきれいに戻す操作は履歴に手を入れる作業になるので、この研修では扱いません。次のトピックの型どおり、push する前にチームの詳しい人に相談してください。

## 10-4-4 壊す前に聞く

> **分からなくなったら、履歴を消すコマンドを打つ前に人に聞く**

困って検索すると、`reset --hard`(Module 5)や強制push(Module 8)のような「履歴を消す強いコマンド」が解決策として出てきます。しかしそれが今の自分の状況に合っているかは、検索結果には書いてありません。誰かの状況での正解は、自分の状況での正解とは限りません。

この研修で学んだことを思い出してください。

- コミット済みの変更は、消さない限り残っている(Module 5)
- 打ち消しは `revert` のような「消さないやり直し」で安全にできる(Module 5)
- 履歴を消す操作**だけ**は、取り返しがつかない。共有済みなら影響はチーム全員に及ぶ(Module 8)

だから最後の型はこうです。**分からなくなったら、履歴を消すコマンドを打つ前に人に聞く。** コミットさえしてあれば、相談を待つ間に状況が悪化することはありません。`status` と `log --oneline` の結果を控えて、状況を説明できる形で聞きに行きましょう。聞くのは恥ではなく、チームの損失を防ぐ行動です。

これで Git 入門は修了です。記録する(add / commit)、読む(status / log / diff)、やり直す(restore / revert)、分けて合流する(switch / merge)、共有する(push / pull / PR)。困ったときの型まで含めて、現場で使う道具はそろいました。
