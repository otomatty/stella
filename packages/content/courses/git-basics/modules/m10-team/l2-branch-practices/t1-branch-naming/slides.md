# 10-2-1
# 枝名は種類/内容

Git入門 — Module 10 / レッスン10-2

<!-- ノート: コミットメッセージと同じく、ブランチにも「伝わる名前」の型があります。このレッスンはブランチ運用の型を3つ押さえます。 -->

---

## なぜ必要か

- チームのリポジトリにはブランチがいくつも並ぶ
- `test` や `sato-work` のような名前では、開かないと何の作業か分からない

<!-- ノート: ブランチ一覧は他人も見ます。名前だけが中身を知る手がかりなのはコミットメッセージと同じ構図です。 -->

---

## 結論

**ブランチ名は feature/login-form のように「種類/内容」の型で付ける**

- 種類 = feature(機能追加)や fix(不具合修正)など
- 内容 = 英小文字とハイフンで、作業の中身を短く

<!-- ノート: スラッシュで「種類/内容」と区切るのが定番の型です。ここでもチームの決まりがあればそちらを優先します。 -->

---

## 最小の例

```bash
git switch -c feature/login-form    # ログイン画面を作る作業
git switch -c fix/price-rounding    # 価格の丸め誤差を直す作業
```

- 名前を見ただけで「種類」と「中身」が分かる

<!-- ノート: 作る瞬間に型どおりの名前を付けるだけです。一覧に並んだとき、誰の説明もなしに作業の地図になります。 -->
