# 10-2-2
# 最新のmainから出す

Git入門 — Module 10 / レッスン10-2

<!-- ノート: 名前の次は出発点です。枝をどこから出すか、作業を始めるときの型を1つ覚えます。 -->

---

## なぜ必要か

- チーム開発では、他の人の作業が毎日 main に合流していく
- 手元の main は、pull しない限りどんどん古くなる

<!-- ノート: 昨日 pull した main は、今日はもう古いかもしれません。自分が何もしなくても main は進んでいく、というのがチーム開発の前提です。 -->

---

## 結論

**作業を始める前に main を pull してから、そこで枝を出す**

- 古い main から出た枝は、合流のときに差が大きくなる
- 「pull してから枝を出す」を毎回の始めかたにする

<!-- ノート: 出発点が新しいほど、合流のときの差は小さくなります。作業開始のたびに毎回やる、体で覚える型です。 -->

---

## 最小の例

```bash
git switch main                      # 1. mainに戻る
git pull                             # 2. 最新に追いつく
git switch -c feature/report-search  # 3. そこから枝を出す
```

- この3行が「作業を始めるときの型」

<!-- ノート: 戻る・追いつく・枝を出す、の3ステップです。どれも既に知っているコマンドで、並べる順番だけが新しい知識です。 -->
