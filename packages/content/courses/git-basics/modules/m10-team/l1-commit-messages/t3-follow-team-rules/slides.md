# 10-1-3
# チームの型に従う

Git入門研修 — Module 10 / レッスン10-1

<!-- ノート: 現場のコミットメッセージには、fix: や feat: のような見慣れない書き出しが付いていることがあります。あれが何なのかを押さえます。 -->

---

## なぜ必要か

- 現場の履歴を見ると、`fix:` `feat:` のような記号で始まるコミットメッセージをよく見かける
- チームごとにメッセージの書き方のルールが決まっていることが多い

<!-- ノート: 配属された現場でまず戸惑うのがこれです。書き方が人によってバラバラだと、せっかくの履歴が読みにくくなります。 -->

---

## 結論

**prefix などチームの型があるなら、自分の好みよりそれに従う**

- **prefix**(接頭辞) = 1行目の頭に付ける「変更の種類」のラベル
- 型が揃っていること自体に価値がある(全員が同じ読み方をできる)

<!-- ノート: prefixという言葉をここで導入します。どの型が正しいかより、チームで揃っていることが大事、というのがこのトピックの結論です。 -->

---

## 最小の例

```text
fix: 会員一覧の重複表示を解消
feat: 日報に検索機能を追加
docs: README のセットアップ手順を最新化
```

- fix = 不具合修正、feat = 機能追加、docs = 文書だけの変更(よくある例)

<!-- ノート: これは代表的な一例で、現場によって語彙は違います。参加したらまず過去のコミットを眺めて、チームの型をまねるのが早道です。 -->
