# 10-1-4
# 一覧で読めるかが品質

Git入門研修 — Module 10 / レッスン10-1

<!-- ノート: 要約・本文・prefixと型を見てきました。最後に、自分のメッセージが良いかどうかを自分で確かめる方法です。 -->

---

## なぜ必要か

- 書いた直後は、どんなメッセージでも分かった気になる
- 実際にメッセージが読まれる場面は、ほとんどが一覧表示

<!-- ノート: 品質の判定を「書いたときの気分」ではなく「読まれる場面」でやろう、という話です。読まれる場面はいつでも自分で再現できます。 -->

---

## 結論

**log --oneline で読み返して意味が分かるかが、メッセージの品質**

- コミットしたら一覧で読み返すのを習慣にする
- 一覧だけで「何をしたか」が追えれば合格

<!-- ノート: 判定基準がコマンド1つで手に入る、というのがうれしいところです。読み返して分からなければ、次からの書き方を直せばよいだけです。 -->

---

## 最小の例

```bash
git log --oneline
# 3f2a1c9 feat: 日報に検索機能を追加
# a8d4e07 fix: 会員一覧の重複表示を解消
# 91b6c53 修正   ← これだけ何をしたか分からない
```

- 一覧に混ざると、伝わらないメッセージはすぐ目立つ

<!-- ノート: 自分のコミットを一覧で眺めると、良し悪しが一目で分かります。読み手の視点を毎回体験できるのがこの確認のいいところです。 -->
