# 10-1-1
# 1行目は要約

Git入門研修 — Module 10 / レッスン10-1

<!-- ノート: 最後のモジュールは「現場の型」です。コマンドはもう全部知っているので、ここからはチームで気持ちよく使うための書き方・運び方を押さえます。最初はコミットメッセージの1行目からです。 -->

---

## なぜ必要か

- コミットメッセージを読むのは、未来の自分とチームメイト
- 「修正」「更新」だけのメッセージが並んだ一覧は、開いて中身を見ないと何も分からない

<!-- ノート: メッセージは書く時間より読まれる時間の方が長い、というのがポイントです。読み手は変更の中身をまだ知りません。 -->

---

## 結論

**1行目は「何をしたか」が一目で分かる要約にする(50字目安)**

- 1行目は一覧表示にそのまま出る「見出し」
- 「何を」「どうした」を具体的な言葉で書く

<!-- ノート: 50字はあくまで目安ですが、一覧で切れずに読める長さです。名詞と動詞をはっきり書くだけで、ぐっと伝わるようになります。 -->

---

## よくある間違い

```bash
# 伝わらない例
git commit -m "修正"

# 伝わる例
git commit -m "会員一覧の並び順を入会日順に変更"
```

- 「何を」(会員一覧の並び順)と「どうした」(入会日順に変更)が入ると読める

<!-- ノート: 悪い例が禁止というより、後で読んだときに困るという話です。自分が1週間後にこの一覧を見る、と想像して書きます。 -->
