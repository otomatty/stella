# レッスン10-3 VS CodeでGitを使う

## このレッスンの目標

- [ ] ソース管理ビューから add・commit・push の操作ができる
- [ ] 変更ファイルをクリックして、左右並びの diff で見直しができる
- [ ] マージエディタでコンフリクトを解決し、GUI 操作とコマンドの対応を説明できる

このレッスンは VS Code の画面を文章で説明します。手元の VS Code で同じ場所を開きながら読むと、位置関係がすぐつかめます。

## 10-3-1 ソース管理ビュー

> **VS Code のソース管理ビューから add・commit・push ができる**

ここまでの Git 操作は、すべてターミナルにコマンドを打ってきました。実務で使うエディタには、同じ操作が画面として組み込まれています。VS Code でその入口になるのが **ソース管理ビュー** です。

- 開き方: VS Code の左端に、アイコンが縦に並んだ細い帯(アクティビティバー)があります。その中の**枝分かれした形のアイコン**をクリックすると、ソース管理ビューが開きます
- 画面の構成: 上から順に、コミットメッセージの**入力欄**、「**ステージされている変更**」、「**変更**」という並びです。「変更」には、前回のコミットから変更したファイルが一覧で並びます

基本操作は次のとおりです。

```text
1. 左端の枝分かれアイコンをクリック → ソース管理ビューが開く
2. 「変更」に並ぶファイルの「+」を押す        = add(ステージングエリアへ)
3. 上部の入力欄にメッセージを書いて「コミット」 = commit
4. 「変更の同期」ボタン                        = push(あわせて pull も行う)
```

ファイル名にマウスを載せると出る「+」を押すと、そのファイルが「ステージされている変更」へ移ります。これが `add` です。メッセージを書いて「コミット」ボタンを押せばコミットが1つでき、「変更の同期」を押すとリモートとやり取りします。

## 10-3-2 クリックでdiff

> **変更ファイルをクリックすれば、diff が左右並びで読める**

ターミナルの diff は、`+` と `-` の記号を上下に読んで、頭の中で前後を組み立てる必要がありました。ソース管理ビューでは、一覧の**ファイル名をクリックする**だけで、同じ情報が左右並びの画面で開きます。

- 左半分が変更前、右半分が変更後の同じファイル
- 削除された行は赤、追加された行は緑で色が付く
- 変わっていない行には色が付かない

```text
[左: 変更前]                [右: 変更後]
単価: 1,000円(税込)    |    単価: 1,100円(税込)   ← この行だけ色付き
数量: 20                |    数量: 20               ← 同じ行は色なし
```

左右で行の位置が揃うので、見直しは色の付いた行を追うだけで済みます。コミット前の見直しは毎回やる作業なので、「ステージする前にファイル名をクリックして眺める」を習慣にすると、確認が速く確実になります。

## 10-3-3 コンフリクトはエディタで

> **コンフリクトはマージエディタで「どちらを残すか」を選んで解決できる**

ターミナルでのコンフリクト解決は、ファイルに書き込まれたマーカーを自分で消して、正しい形に直す作業でした。マーカーはただのテキストなので、消し忘れてもGitは止めてくれず、そのまま事故につながります。

VS Code には、この作業の専用画面 **マージエディタ** があります。コンフリクトが起きると、対象のファイルに「マージ エディターで解決」というボタンが表示され、押すと3つの領域を持つ画面が開きます。

```text
上段左: 自分の枝の内容        上段右: 相手の枝の内容
下段:   結果(選んだ内容がここに入る)
```

- 上段の2つが「選択肢」、下段が「答案用紙」というレイアウト
- 残したい側の「取り込む」を選ぶと、その内容が下段の結果に入る(両方を取り込んで組み合わせることも可能)
- 選んだ結果にマーカーは残らないので、消し忘れの事故が起きない

解決を終えたら、いつもどおり `add` して `commit` で確定します。ここはターミナルの手順と同じです。

## 10-3-4 裏では同じGit

> **GUI の操作は裏では同じ Git(意味はこの研修で覚えたコマンドと同じ)**

ボタンを押すだけの操作は、慣れないうちは「何が起きたのか」が見えず不安になります。しかし GUI は別の道具ではなく、**同じ Git の別の入口**です。ボタンの1つ1つが、この研修で学んだコマンドに対応しています。

```text
ソース管理ビューの操作        裏で動いている意味
──────────────────────────────────────────
「+」でステージする        =  git add
「コミット」ボタン          =  git commit
「変更の同期」              =  git pull と git push
```

だから、画面の操作で迷ったらターミナルで `git status` を打てば、同じリポジトリの同じ状態が見えます。画面とコマンドのどちらを使っても、変わるのは入口だけで、記録される履歴は同じです。コマンドから学んだ皆さんは、画面の裏側を説明できる状態でGUIを使い始められます。
