# 9-4-2
# mainは常に動く状態

Git入門研修 — Module 9 / レッスン9-4

<!-- ノート: GitHub Flowを支える約束事の話です。なぜ全員がわざわざPRを経由するのか、その理由がここにあります。 -->

---

## なぜ必要か

- ブランチを切らずに main で直接作業すれば、一見手っ取り早い
- でも main は、全員の作業の出発点になっている
- main が壊れていたら、何が起きるか?

<!-- ノート: 慣れてくるほど「小さい修正だからmainに直接」をやりたくなります。その誘惑を断つ理由を考えさせます。 -->

---

## 結論

**main は常に動く状態に保つ(だから main へ直接 push しない)**

- main に入れてよいのは、レビューを通った変更だけ
- 変更は必ずブランチ + PR を経由させる

<!-- ノート: GitHub Flowで枝を出すのは、mainを守るためです。直接pushしない、はチームの約束として最初に覚える1条です。 -->

---

## よくある間違い

```text
悪い例: 「1行だけだから」と main に直接 push
  → 誤りがあれば全員の出発点が壊れる。気づくのも遅れる

良い例: 1行でもブランチ + PR を経由
  → 取り込む前に人の目が入る。記録も残る
```

<!-- ノート: 壊れたmainから枝を切った全員が巻き込まれます。1行の修正ほど油断が出るので、例外を作らないのがコツです。 -->

---
