# GitHub Flowとは

Git入門研修 — Module 9 / レッスン9-4

## なぜ必要か

- ブランチ・マージ・push・PR と、道具は一通りそろった
- でも実務では「チームとしてどう回すか」の型が要る
- 毎回やり方を相談していたら、進まない

<!-- ノート: 道具の使い方と、チームの仕事の回し方は別の話です。多くの現場が採用している共通の型がある、と投げかけます。 -->

---

## 結論

**GitHub Flow は「main から枝を出し、PR で戻す」の繰り返し**

- ここまで学んだ1周の流れそのものに付いた名前
- シンプルなので、多くのチームがこの型か、その変形で回している

<!-- ノート: GitHub Flowという言葉をここで導入します。新しい操作は何もありません。学んだ1周に名前が付くだけ、と安心させます。 -->

---

## 最小の例

```text
main ──●──────────●──────────●──→
        \        /  \        /
         ●──●──●     ●──●──●
        (枝で作業、PRで戻す) (また枝を出す)
```

- 出発点はいつも main。戻す手段はいつも PR

<!-- ノート: 図のとおり、mainから出てPRで戻る山が繰り返されるだけです。この単純さが、迷いなく回せる理由です。 -->
