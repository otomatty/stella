# 9-2-2
# 指摘には修正pushで応える

Git入門研修 — Module 9 / レッスン9-2

<!-- ノート: レビューで指摘をもらった後の、具体的な手の動かし方です。操作は今まで学んだことの組み合わせで済みます。 -->

---

## なぜ必要か

- レビューで「ここを直してほしい」と指摘をもらった
- 直すのはいいが、直した結果をどうやって PR に届けるのか?
- PR を作り直す? それとも別の操作がある?

<!-- ノート: 初めての人は「PRを閉じて出し直すのかな」と考えがちです。実際はもっと簡単だ、というのがこのトピックです。 -->

---

## 結論

**指摘には同じブランチへ修正コミットを push して応える(PRに自動で反映される)**

- PR はブランチと結びついている。作り直す必要はない
- 新しいコミットを push すれば、PR の差分に自動で追加される

<!-- ノート: PRは「そのブランチの最新状態」を常に映す窓です。だからブランチを更新すれば、PRも勝手に追いつきます。 -->

---

## 最小の例

```bash
# 指摘: 「見出しの表現が分かりにくい」→ 手元で修正して…
git add price-list.md
git commit -m "見出しの表現をレビュー指摘に沿って修正"
git push
# → 開いている PR に新しいコミットが自動で並ぶ
```

<!-- ノート: 打つのはいつもの3つだけです。すでに push -u 済みのブランチなので、2回目からは git push だけで届きます。 -->
