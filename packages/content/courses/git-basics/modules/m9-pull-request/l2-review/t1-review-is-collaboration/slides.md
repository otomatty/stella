# 9-2-1
# レビューは共同作業

Git入門 — Module 9 / レッスン9-2

<!-- ノート: このレッスンではPRのレビューを扱います。最初に、レビューという工程をどういう心構えで受け止めるかを押さえます。 -->

---

## なぜ必要か

- はじめて PR に指摘コメントが付くと、否定された気分になりがち
- 逆に自分が見る側になると、何を言えばいいのか分からない
- レビューとは、そもそも何をする工程なのか?

<!-- ノート: 指摘が怖くてPRを出せない、という悩みは新人に本当に多いです。最初に位置づけをはっきりさせておきます。 -->

---

## 結論

**レビューは粗探しではなく、品質を一緒に上げる工程**

- 指摘は人への評価ではなく、変更をより良くする材料
- 質問や提案も立派なレビュー。悪い所探しだけではない

<!-- ノート: 対象はコードであって人ではありません。見る側も見られる側も、同じ成果物を良くする仲間だという前提を共有します。 -->

---

## 最小の例

```text
「この変数名だと会員数と会員一覧を取り違えそうです。
  memberList はどうでしょう?」          ← 提案
「この条件で0件のときはどうなりますか?」 ← 質問
「この書き方、読みやすいですね」          ← 良い点
```

- 指摘・質問・良い点の共有、どれもレビューのコメント

<!-- ノート: 実際のコメント例です。命令ではなく提案や質問の形が基本で、良い点を伝えるのもチームの品質を上げる行為です。 -->
