# 済んだ枝は消す

Git入門研修 — Module 9 / レッスン9-3

<!-- ノート: レッスン9-3の締めは後片付けです。マージが済んだブランチをどうするかを押さえます。 -->

---

## なぜ必要か

- マージが済んだブランチは、もう役目を終えている
- 消さずに置いておくと、ブランチ一覧が古い枝だらけになる
- 「この枝、まだ作業中?」と毎回考えるのは無駄

<!-- ノート: 済んだ枝が10本溜まったリポジトリを想像させます。どれが生きている作業か分からない状態は、それ自体が事故のもとです。 -->

---

## 結論

**マージ済みのブランチはリモートでも手元でも消して、次の作業へ移る**

- 変更はもう main に入っているので、消しても何も失わない
- ブランチ一覧に「生きている作業」だけが並ぶ状態を保つ

<!-- ノート: 消してよい根拠は「中身はmainに残っている」ことです。ブランチはただの目印なので、惜しまず消してよいのです。 -->

---

## 最小の例

```bash
# リモート側: マージ後の PR 画面で「Delete branch」を押す
# 手元側:
git switch main
git branch -d update-practice-note
```

- `-d` はマージ済みでない枝を守ってくれる安全な削除

<!-- ノート: リモートはPR画面のボタン、手元はM7で学んだbranch -dです。両方消して、次の作業を最新のmainから始めます。 -->
