# 9-3-2
# マージ後は追いつく

Git入門 — Module 9 / レッスン9-3

<!-- ノート: GitHub上でマージした直後の手元の状態と、そこでやるべき1手を押さえます。 -->

---

## なぜ必要か

- GitHub 上でマージした。でもそれはリモートで起きたこと
- 手元の main は、マージ前のまま止まっている
- 古い main のまま次の作業を始めると、ずれが広がる

<!-- ノート: マージボタンを押しても手元は1ミリも変わりません。リモートと手元は別物、というM8の感覚をここで思い出させます。 -->

---

## 結論

**マージ後は手元の main を pull して、リモートに追いつく**

- マージの成果はまずリモートの main に入る
- pull で取り寄せて、手元の main を最新にしてから次へ進む

<!-- ノート: 「マージしたら pull」をセットの動作として体に入れます。次の作業を最新の main から始めるための準備です。 -->

---

## 最小の例

```bash
git switch main
git pull
# → GitHub でマージした結果が手元の main に入る
```

- マージ直後にこの2つを打つのを習慣にする

<!-- ノート: switchでmainに戻ってからpull、の2手です。自分がマージした直後だけでなく、他の人のPRが入った後も同じ動作で追いつけます。 -->
