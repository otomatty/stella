# レッスン9-3 演習 — マージと後片付け

対象トピック: 9-3-1 〜 9-3-3

## ハンズオン

手元の VS Code のターミナルと GitHub の画面で試します。レッスン9-2まで進めた練習用リポジトリ(`~/git-practice-remote`)の PR を、マージして片付けるところまで通します。

1. GitHub で PR を開き、コメントへの返事が済んでいることを確認します
2. PR 画面下部の「Merge pull request」を押し、「Confirm merge」で確定します。1人のリポジトリなので、Approve がなくてもこのボタンは押せます
3. 表示が Merged(紫のラベル)に変わったことを確認します
4. 同じ画面に出る「Delete branch」ボタンを押して、リモートのブランチを消します
5. ターミナルに戻り、手元の main をリモートに追いつかせます

   ```bash
   cd ~/git-practice-remote
   git switch main
   git pull
   ```

6. `practice.txt` を開き、PR で取り込んだ行が手元の main にも入っていることを確認します
7. 役目を終えた手元のブランチを消し、一覧を確認します

   ```bash
   git branch -d update-practice-note
   git branch
   ```

`git branch` の一覧に main だけが残っていれば、後片付け完了です。push → PR → レビュー → マージ → 片付け、の1周を自分の手で回せたことになります。

## 演習問題

### 問1(基本)

レビューが終わった PR を取り込むとき、手元で `git merge` して push するのではなく、GitHub のボタンでマージするのはなぜですか。

### 問2(基本)

GitHub で PR をマージした直後、手元の main はどういう状態ですか。また、最初に打つべきコマンドを2つ挙げてください。

### 問3(応用)

マージ済みのブランチを消しても「何も失わない」と言えるのはなぜですか。1文で説明してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

どの PR がいつ誰の操作で main に入ったかという記録が、レビューのやりとりと紐づいて残るからです。

手元でマージしても結果の main は同じですが、PR と取り込みの紐づけが残りません。後から変更の経緯を PR でたどれることが、チームでの大きな財産になります。

</details>

<details>
<summary>問2の解答例</summary>

手元の main はマージ前のまま止まっています。打つのは `git switch main` と `git pull` の2つです。

マージはリモートで起きた出来事なので、pull で取り寄せるまで手元には反映されません。「マージしたら pull」をセットで習慣にします。

</details>

<details>
<summary>問3の解答例</summary>

変更の中身はすでに main に取り込まれていて、ブランチはただの目印にすぎないからです。

消えるのは目印だけで、コミットの内容は main の履歴に残っています。だからマージ済みの枝は惜しまず消せます。

</details>

## 確認クイズ

### Q1. PR のマージのやり方として、この研修で学んだ手順はどれですか。

- A. 手元で git merge を実行してから push する
- B. GitHub の PR 画面で「Merge pull request」ボタンを押す
- C. リモートのブランチを削除すると自動でマージされる

<details>
<summary>答え</summary>

**B** — PR のマージは GitHub 上のボタンで行います。PR とレビューの記録に取り込みが紐づいて残ることが利点です。削除でマージはされません。

</details>

### Q2. GitHub で PR をマージした直後の手元の main について、正しいものはどれですか。

- A. 自動で最新になっているので、何もしなくてよい
- B. マージ前のまま止まっているので、pull して追いつく必要がある
- C. マージによって手元の main は削除されている

<details>
<summary>答え</summary>

**B** — マージはリモートで起きた変化で、手元の main には自動で届きません。git switch main と git pull で追いつきます。

</details>

### Q3. マージ済みブランチの扱いとして適切なものはどれですか。

- A. リモートでも手元でも消して、ブランチ一覧を生きている作業だけにする
- B. 記念に残すため、消さずに全部ためておく
- C. リモートだけ消せば、手元のブランチは自動で消える

<details>
<summary>答え</summary>

**A** — 中身は main に入っているので、リモートは PR 画面の Delete branch、手元は git branch -d で消します。手元の枝が自動で消えることはありません。

</details>
