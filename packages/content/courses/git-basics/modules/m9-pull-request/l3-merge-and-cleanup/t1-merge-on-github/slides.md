# 9-3-1
# PRのマージはGitHub上で

Git入門 — Module 9 / レッスン9-3

<!-- ノート: このレッスンではPRの締めくくり、マージと後片付けを扱います。まずはマージを「どこで」行うかです。 -->

---

## なぜ必要か

- レビューが終わり、取り込んでよい状態になった
- Module 7 では手元で git merge を打った。今回も同じでいい?
- PR には、やりとりの記録という財産がある

<!-- ノート: 手元のmergeを学んだ人ほど、ターミナルでやりたくなります。PRの世界では置き場所が変わる、というのがこの回です。 -->

---

## 結論

**PR のマージは GitHub 上のボタンで行う**

- 手元で git merge して push するのではなく、PR 画面で完結させる
- どの PR がいつ誰の操作で main に入ったかが、記録として残る

<!-- ノート: ボタン1つでマージされ、PRとレビューのやりとりがそのまま取り込みの記録になります。手元マージではこの紐づけが残りません。 -->

---

## 最小の例

```text
1. PR 画面下部の「Merge pull request」を押す
2. 「Confirm merge」で確定
3. 表示が Merged になり、main に取り込まれる
```

- レビューの完了を確認してから押すのがマナー

<!-- ノート: 操作は2クリックです。押せる状態かどうかはボタンの色でも分かります。押した後の手元の話は次のトピックで扱います。 -->
