## なぜ必要か

- ブランチを push して、自分の変更を GitHub に置けるようになった
- でもチームでは、自分の判断だけで main にマージしてよいのか?
- 取り込む前に、内容を見てもらう場が欲しい

<!-- ノート: M8までで変更を共有するところまで来ました。次の課題は「取り込んでよいか」を誰がどこで判断するか、です。 -->

---

## 結論

**プルリクエストは「このブランチを取り込んでほしい」という依頼と相談の場**

- GitHub 上で開く。略して **PR** と呼ぶ
- 取り込む前に、変更内容を見ながら会話できる

<!-- ノート: プルリクエストとPRという言葉をここで導入します。ただの申請フォームではなく、会話ができる「場」であることが大事です。 -->

---

## 最小の例

```text
会員一覧の並び順を修正            #12
fix-member-sort → main
変更ファイル: 2   コミット: 3   コメント: 4
```

- 「どのブランチを、どこへ」取り込む依頼かが1画面で分かる
- 変更の中身とやりとりが、この1か所に集まる
