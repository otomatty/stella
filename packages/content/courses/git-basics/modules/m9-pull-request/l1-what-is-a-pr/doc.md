# レッスン9-1 PRとは

## このレッスンの目標

- [ ] プルリクエスト(PR)が何のための場かを説明できる
- [ ] push からマージまでの PR の流れを順番に言える
- [ ] レビューされやすい PR の作り方(大きさ・説明)を説明できる

## 9-1-1 PRは取り込みの依頼

> **プルリクエストは「このブランチを取り込んでほしい」という依頼と相談の場**

Module 8 までで、ブランチを push して自分の変更を GitHub に置けるようになりました。次の疑問はこれです。「自分の判断だけで main にマージしてよいのか?」

チーム開発では、取り込む前に内容を見てもらうのが基本です。そのための場が **プルリクエスト** で、略して **PR** と呼びます。GitHub 上で開く機能で、次の要素が1つの画面に集まります。

```text
会員一覧の並び順を修正            #12
fix-member-sort → main
変更ファイル: 2   コミット: 3   コメント: 4
```

- どのブランチを、どこへ取り込む依頼か(`fix-member-sort → main`)
- 変更の中身(変更ファイルとコミットの一覧)
- 内容についてのやりとり(コメント)

PR はただの申請フォームではありません。変更内容を見ながら質問や提案を交わせる「相談の場」であることが、実務でいちばん大事な性質です。

## 9-1-2 PRの流れ

> **流れは、枝を push → PR を開く → レビュー → マージ**

PR を使った作業は、いつも同じ4段階で進みます。

```text
1. ブランチで作業して push     (手元 → GitHub)
2. PR を開く                   (GitHub 上)
3. レビュー                    (内容の確認と相談)
4. マージ                      (main に取り込まれて完了)
```

**レビュー** は、取り込む前に他の人が内容を確認して相談する工程です。ここで質問や修正依頼のやりとりが行われます。

手元とサーバー側の線引きも押さえておきましょう。1 の push までは今まで学んだターミナルの操作で、2〜4 は GitHub の画面上の操作です。ブランチを push すると、GitHub のリポジトリ画面に「Compare & pull request」というボタンが現れ、そこから PR を開けます。

この4段階が頭に入っていれば、「いま自分はレビュー待ちの段階だ」のように、作業の現在地をいつでも言えるようになります。

## 9-1-3 1PR1目的

> **1つのPRには1つの目的だけ(小さいほど早く取り込まれる)**

作業をしていると、直したい所が次々に見つかります。全部まとめて1つの PR にしたくなりますが、これはレビューする側にとってつらい PR になります。

```text
悪い例: 「並び順修正 + 新機能 + 誤字直し」を1つのPRに
  → 誤字は良くても新機能に指摘が付き、全部が止まる

良い例: 「並び順修正」「新機能」「誤字直し」を別々のPRに
  → 問題ない分から先にマージされる
```

小さい PR には、はっきりした利点があります。

- すぐ読めるので、レビューがすぐ返ってくる
- 目的が1つなので、「取り込んでよいか」の判断が1回で済む
- 一部への指摘で無関係な変更まで止まる、ということがない

Module 2 で学んだ「1コミット1目的」と同じ考え方です。粒度をそろえる習慣は、コミットでも PR でも効いてきます。

## 9-1-4 説明には何を・なぜ

> **タイトルと説明には「何を・なぜ」を書く(どう変えたかは差分が語る)**

PR を開くと、タイトルと説明を書く欄が出てきます。空欄や「修正しました」だけの PR では、レビューする人が差分から意図を推理することになり、その時間はまるごと無駄です。

書くべきことは「何を・なぜ」の2点です。

```text
タイトル: 会員一覧の並び順を五十音順に修正

説明:
何を: 会員一覧の並び順を、登録順から五十音順に変更
なぜ: 営業チームから「目的の会員を探しにくい」と要望があったため
```

「どう変えたか」を書かないのは手抜きではありません。どう変えたかは差分そのものに写っているからです。差分に写らないのは目的と背景だけなので、人間が書くのはそこに絞ります。コミットメッセージで学んだ考え方と同じです。

この2行があるだけで、レビューする人は「要望への対応として妥当か」という観点で差分を読めるようになります。
