# Git 入門 カリキュラム

SES 未経験者向けの Git 操作入門講座です。1 トピック = 覚えることが 1 つ(takeaway 1 文)の粒度で、
「なぜ履歴が要るのか」から始めて、記録(commit)→ 読む(log/diff)→ やり直す → ブランチ → マージ →
共有(push/pull)→ プルリクエスト → チーム開発の約束事、までを通します。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)で完走する
- ハンズオン: `practice.md` に「手元の VS Code ターミナルで試す」手順を書く(自動採点はしない)
- Git サンドボックス・コマンド自動採点は対象外(Issue #122 の方針)
- 前提講座: **扇ごと**。フロントエンドの星は **JavaScript 入門 (`javascript-basics`)**、バックエンドの星は **Node.js 入門 (`node-basics`)** をクリアすると開きます (`course.json` の `appearancePrerequisites`)。実体は 1 講座のまま、スキルツリーでは両ルートの扇に星を出します (`appearances`)。クリアは共有です。どちらか一方のルートだけ進んでも Git を始められます (組どうしは OR)。HTML/CSS や ITのきほんだけは前提にしません。フロントの後続は準備中の **npm とビルドツール入門 (`npm-build-basics`)**。

## 設計方針

- **コマンドより先に概念**: `init` を打つ前に「リポジトリ」「スナップショット」が言えること。各コマンドは「何のためか」を takeaway に含める
- **1 トピック 1 系統**: コマンド例は 1 トピックにつき 1 系統。タイトルに「と」が付いたら分割する
- **失敗から救う順序**: 「やり直す」(M5)をブランチより先に置く。未経験者が最初に詰まるのは undo であり、ブランチ以前に単独で必要になるため
- **detached HEAD・stash はブランチの後**: 「枝から離れる」「枝を移る前の退避」はブランチ概念が前提なので M6 に置く(語彙台帳の前後関係もこの順でしか通らない)
- **共有(remote)はローカル操作が全部済んでから**: push が「コミットを送る」だと腹落ちするには、コミット・ブランチ・マージが先に要る
- 語彙台帳は講座内だけで閉じる。コマンド名(`init` / `add` / `commit` ...)は `introduces` に明示する

## 対象外(この講座では扱わない)

| 項目 | 理由 |
| --- | --- |
| rebase / cherry-pick | 履歴の書き換えは入門の失敗コストが高い。revert で足りる(Issue #122 の方針) |
| reset --hard / force push | 同上。存在と危険性だけ M5 / M8 で触れ、操作は教えない |
| Git の内部構造(blob / tree) | 未経験者の完走を優先。スナップショットという語で止める |
| GitHub 固有 UI の深掘り | 「PR を出す」までに留める。Actions・Projects 等は扱わない |
| タグ / リリース、submodule、fork | 現場初期では遭遇頻度が低い。拡張候補(下記)へ |
