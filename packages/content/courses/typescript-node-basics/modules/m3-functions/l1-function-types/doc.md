# レッスン3-1 関数に型を付ける

## このレッスンの目標

- [ ] 引数と戻り値に型を付けられる
- [ ] 省略できる引数を定義し、中で `undefined` を扱える
- [ ] 値を返さない関数を `void` で表せる

## 3-1-1 引数の型は呼び出し側との約束

> **引数に型を書くと、間違った値を渡した呼び出し側の行がエラーになる**

関数の中でエラーが出たのに、原因は呼び出し側の渡し方だった、という経験はよくあります。直すべき場所と壊れた場所が離れていると、調査に時間がかかります。

**引数** は、関数が受け取る値です。ここに型を書くと、状況が変わります。

```ts
function withTax(price: number): number {
  return Math.round(price * 1.1);
}

withTax(1000);      // OK
withTax("1000");    // エラー: ここが赤くなる
```

注目すべきは **エラーが出る場所** です。関数の中ではなく、間違った値を渡した行が指摘されます。原因の場所でそのまま気づけるので、調査が要りません。

前のレッスンで「引数には必ず型を書く」と述べたのは、このためです。関数の入口は、書いた人と使う人との約束の場所です。約束を型として書いておけば、破られた瞬間に分かります。

## 3-1-2 戻り値の型は書いて固定する

> **戻り値の型を書くと、実装を変えたときに約束が崩れたことをその場で気づける**

関数の中を直したら返る値の種類が変わってしまい、呼び出している何十か所がまとめて壊れた。これはサーバー側でよく起きる事故です。

**戻り値** は、関数が返す値です。TypeScriptは戻り値の型を推論できますが、**あえて書きます**。

```ts
function withTax(price: number): number {
  return "1100";        // エラー: number を返すはずが文字列
}
```

型を書いておくと、実装を変えて約束が崩れた瞬間に、**その関数自身が赤くなります**。書いていなければ、推論された型が静かに変わり、呼び出し側が壊れて初めて気づくことになります。

変数の型注釈は「推論できるなら書かない」でしたが、関数の入口と出口は別です。ここは **他人と接する境界** なので、明示しておく価値があります。

## 3-1-3 省略できる引数は?を付ける

> **引数名の後ろに?を付けると省略でき、その中ではundefinedの可能性を扱う**

同じ関数を、引数ありと無しの両方で呼びたい場面があります。呼び出し側に毎回 `undefined` を書かせるのは不便です。

**省略可能な引数** は、名前の後ろに `?` を付けて定義します。

```ts
function greet(name: string, title?: string): string {
  if (title === undefined) {
    return name + " さん";
  }
  return name + " " + title.trim();
}

greet("佐藤");            // OK
greet("佐藤", "部長");     // OK
```

省略できるということは、その引数の型は `string | undefined` になるということです。つまり、**関数の中では値が無い場合を扱う責任が生まれます**。上の例で `if` の確認を消すと、`title.trim()`(前後の空白を落とすメソッド)のところで「`title` は `undefined` の可能性がある」と `strict` が止めます。

注意したいのは、**文字列としてつなぐだけなら型は止めてくれない**ことです。`return name + " " + title;` と書くと検査は通り、実行すると「佐藤 undefined」がそのまま出ます。型に守ってもらえるのは、その値を**値として使う**(メソッドを呼ぶ、数値として計算する)ときです。

便利さと引き換えに責任が増える、という関係を意識してください。省略可能にする前に「本当に省略できる必要があるか」を考えると、設計がすっきりします。

## 3-1-4 返さない関数の型はvoid

> **値を返さない関数の戻り値の型はvoidで、返す値が無いことを明示する**

ログを出すだけ、ファイルに書くだけ、という関数には何と書けばよいでしょうか。

**void** は、返す値が無いことを表す型です。

```ts
function logOrder(id: number): void {
  console.log("注文 " + id + " を受け付けました");
}

const result = logOrder(1);   // result の型は void(使い道が無い)
```

`void` と書くことには、書き手の意図を示す意味があります。**返し忘れているのではなく、意図的に返さない** と宣言できるからです。

呼び出す側も、型を見れば戻り値を使わないことが分かります。うっかり戻り値を使おうとしても、型が `void` なので止まります。
