# レッスン0-1 演習 — なぜサーバーで型を書くのか

対象トピック: 0-1-1 〜 0-1-3

## 手元で試す

このレッスンは環境構築の前の回です。まずは型があるとどう見えるかを、ブラウザ上で確かめます。

[TypeScript Playground](https://www.typescriptlang.org/play) を開いて、次のコードを貼り付けてください。

```ts
const price: number = 1000;
const label: string = price;
```

2行目に赤い波線が出ます。カーソルを乗せて、表示されるメッセージを読んでください。

```text
Type 'number' is not assignable to type 'string'
(number 型は string 型に代入できません)
```

次に、型注釈を外してみます。

```ts
const price = 1000;
const label = price;      // エラーは出ない(推論された型が number になる)
```

最後に、サーバー側にしか無い書き方を確かめます。Playgroundで次を書くと、`document` は使えても `readFile` は使えないことが分かります(型定義が読み込まれていないためです)。

```ts
import { readFile } from "node:fs/promises";
```

環境を作るのは次のレッスンです。ここでは「型があると実行前に赤くなる」ことだけ体験できていれば十分です。

## 演習問題

### 問1(基本)

型を書くことで、間違いに気づける場所はどう変わりますか。1文で説明してください。

### 問2(基本)

ブラウザ向けのTypeScriptとサーバー側のTypeScriptで、扱う対象はどう違いますか。

### 問3(応用)

「型はテストの代わりになる」という意見について、どう答えますか。理由を添えて書いてください。

### 問4(応用)

この講座で扱う3種類の型注釈を、コード例とともに挙げてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

実行して壊れてから気づくのではなく、**実行する前**に、書いているその場で気づけるようになります。

間違いの原因から遠く離れた場所で発覚する、という調査の難しさを減らせます。

</details>

<details>
<summary>問2の解答例</summary>

ブラウザ向けはDOM(画面)を扱い、サーバー側はファイル・引数・環境変数・通信といったNode.jsの機能を扱います。

言語は同じで、型を付ける対象が違います。

</details>

<details>
<summary>問3の解答例</summary>

代わりにはなりません。型が捕まえるのは「値の種類の取り違え」という限られた範囲で、計算結果が正しいかどうかは判定できないためです。

型はテストより手前に置くもう1枚の網であり、両方を使います。

</details>

<details>
<summary>問4の解答例</summary>

```ts
const port: number = 3000;                    // 基本の型
function withTax(price: number): number { }   // 関数の型
type User = { id: number; name: string };      // オブジェクトの型
```

ジェネリクス・クラス・デコレーターはこの講座では扱いません。

</details>

## 確認クイズ

### Q1. TypeScriptの型がもたらす一番の効果はどれですか。

- A. プログラムの実行速度が上がる
- B. 値の種類の取り違えを、実行する前に見つけられる
- C. コードの行数が減る

<details>
<summary>答え</summary>

**B** — 型は実行前の検査です。実行速度は変わりません(型は実行時には残りません)。

</details>

### Q2. サーバー側のTypeScriptについて正しいものはどれですか。

- A. `document` を使って画面を操作できる
- B. DOMは無く、ファイルや通信などNode.jsの機能に型を付けて使う
- C. ブラウザ向けとは別の言語である

<details>
<summary>答え</summary>

**B** — 言語は同じで、型を付ける対象が違います。DOMはブラウザ側のしくみです。

</details>

### Q3. 型定義とは何ですか。

- A. ライブラリや環境の機能に、型の情報を与えるもの
- B. 変数に値を代入すること
- C. 実行時に型を検査するしくみ

<details>
<summary>答え</summary>

**A** — 型定義があるから、`readFile` が文字列を返すことをエディタが知っています。

</details>

### Q4. この講座で扱わないものはどれですか。

- A. 基本の型
- B. 関数の型
- C. ジェネリクス

<details>
<summary>答え</summary>

**C** — ジェネリクス・クラス・デコレーターは扱いません。基本の型・関数の型・オブジェクトの型までが範囲です。

</details>

### Q5. 「型があればテストは要らない」という考えへの評価として適切なものはどれですか。

- A. 正しい。型があればすべての誤りを防げる
- B. 誤り。型は値の種類の取り違えを防ぐもので、計算結果の正しさは判定できない
- C. 誤り。型は実行時に検査されるので遅くなる

<details>
<summary>答え</summary>

**B** — 型は手前の網、テストは結果の確認です。役割が違うので両方を使います。

</details>
