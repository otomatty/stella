# レッスン0-1 なぜサーバーで型を書くのか

## このレッスンの目標

- [ ] 型があると、いつ・どこで間違いに気づけるかを説明できる
- [ ] ブラウザ向けのTypeScriptとの違いを説明できる
- [ ] この講座で扱う範囲と扱わない範囲を言える

## 0-1-1 型は実行前に間違いを見つける

> **TypeScriptは、値の種類の取り違えを実行する前に見つけてくれる**

サーバーのプログラムは、動かしてみるまで間違いに気づけません。気づく場所が本番だと、利用者に影響が出てからの発覚になります。

- **型** — その値がどんな種類かを表す情報(数値・文字列など)
- **実行前** — 動かす前。エディタの表示や検査コマンドで分かる

```ts
const price: number = 1000;
const label: string = price;   // 実行前にエラーになる
// => Type 'number' is not assignable to type 'string'
```

同じことをJavaScriptで書くと、この行は問題なく通ります。そして後の行で、文字列のつもりで数値を扱ったときに初めて壊れます。**間違いの原因から遠く離れた場所で気づく** ことになり、調査に時間がかかります。

型は、テストの代わりではありません。テストより手前に置く、もう1枚の網です。「値の種類の取り違え」という限られた範囲を、実行せずに、書いているその場で捕まえます。

## 0-1-2 サーバーのTypeScriptにはDOMが無い

> **サーバー側のTypeScriptでは、DOMの代わりにNode.jsの機能に型を付けて使う**

ブラウザ向けのTypeScriptの記事をまねすると `document` が出てきますが、サーバー側ではその前提が当てはまりません。Node.js入門で学んだとおりです。

- **DOM** — ブラウザが持つ画面のしくみ。サーバーには無い
- **型定義** — ライブラリや環境の機能に、型の情報を与えるファイル

```ts
// ブラウザ向け
document.getElementById("app");     // サーバーでは使えない

// サーバー向け
import { readFile } from "node:fs/promises";
const text: string = await readFile("memo.txt", "utf-8");
```

言語そのものは同じです。違うのは **型を付ける対象** で、画面ではなくファイル・引数・環境変数・通信になります。

`readFile` が文字列を返すと分かるのは、Node.jsの機能に対する **型定義** が用意されているからです。この型定義をどう用意するかは、モジュール1で扱います。

## 0-1-3 この講座は型の基本と実行環境に絞る

> **この講座では、基本の型・関数の型・オブジェクトの型までを、Node.jsで動かしながら学ぶ**

TypeScriptは機能が多く、全部を学ぼうとすると動かす前に力尽きます。この講座の範囲を先に示します。

```ts
const port: number = 3000;                    // 基本の型
function withTax(price: number): number { }   // 関数の型
type User = { id: number; name: string };      // オブジェクトの型
```

**型注釈** は、変数や引数に「この種類です」と書き添えることです。この3つが書ければ、サーバー側の小さなプログラムは型付きで書けます。

扱わないものも明示しておきます。**ジェネリクス・クラス・デコレーター・高度な型演算** は、この講座では扱いません。他所で見かけても、いま覚える必要はありません。

到達点は「型を付けたプログラムをNode.jsで動かし、型エラーを自分で読んで直せる」ことです。次のモジュールから、実際に動かす環境を作ります。
