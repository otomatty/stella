# 4-1-4
# readonlyで書き換えを禁じる

TypeScript 入門（サーバー） — Module 4 / レッスン4-1

<!-- ノート: 講座の最後のトピックです。型で意図を伝える、という到達点にふさわしい話題です。 -->

---

## なぜ必要か

- 受け取ったデータを、どこかの処理が勝手に書き換えていた
- どこで変わったのかを追うのに時間がかかる

<!-- ノート: つかみ。書き換えの追跡は、規模が大きくなるほど困難になります。 -->

---

## 結論

**readonlyを付けたプロパティは、作った後に書き換えられなくなる**

- **readonly** — 読み取り専用にする印

<!-- ノート: 結論を先に言い切ります。実行時ではなく型検査で止める、という点を添えます。 -->

---

## 変えてはいけないものを守る

```ts
type Order = {
  readonly id: number;
  status: string;
};

const order: Order = { id: 1, status: "受付" };
order.status = "発送";   // OK
order.id = 2;            // エラー: 読み取り専用
```

- 「変えてよいもの」と「変えてはいけないもの」を型で区別できる

<!-- ノート: 識別子は readonly、状態は変更可という設計例です。意図が型に残ります。 -->
