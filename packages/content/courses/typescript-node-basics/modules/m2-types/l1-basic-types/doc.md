# レッスン2-1 基本の型

## このレッスンの目標

- [ ] `string` / `number` / `boolean` で値に型を付けられる
- [ ] 型推論に任せる場所と、自分で書く場所を判断できる
- [ ] 「値が無いかもしれない」をユニオン型で表せる

## 2-1-1 基本の型は3つ覚えれば足りる

> **まずはstring・number・booleanの3つで、扱う値のほとんどを表せる**

型の名前はたくさんありますが、最初に覚えるのは3つで十分です。

- **string** — 文字列
- **number** — 数値(整数も小数も同じ `number` です)
- **boolean** — 真偽値(`true` / `false`)

```ts
const name: string = "佐藤";
const price: number = 1200;
const isActive: boolean = true;

const wrong: number = "1200";   // エラー: 文字列は入れられない
```

書き方は `名前: 型 = 値` です。名前のあとにコロンを置き、型を書きます。

4行目のエラーが、型を書く効果そのものです。JavaScriptならこの行は通ってしまい、後で `price * 1.1` のような計算をしたときに、おかしな結果になって初めて気づきます。

## 2-1-2 推論できるところは書かない

> **初期値から型が分かるところは型注釈を書かず、TypeScriptの推論に任せる**

すべての変数に型を書くと、かえって読みにくくなります。値を見れば分かることを二重に書いているからです。

**型推論** は、値からTypeScriptが型を自動で判断する仕組みです。

```ts
const name = "佐藤";              // 推論に任せる(string になる)
const price = 1200;               // 推論に任せる(number になる)

let total: number;                // 初期値が無いときは書く
function withTax(price: number) { }  // 引数は必ず書く
```

推論に任せても、検査の強さは変わりません。`const name = "佐藤"` に後から数値を入れようとすれば、きちんとエラーになります。

書く場所と書かない場所の線引きは次のとおりです。

| 場所 | 型注釈 | 理由 |
|---|---|---|
| 初期値のある変数 | 書かない | 値から分かる |
| 初期値の無い変数 | 書く | 判断材料が無い |
| **関数の引数** | **必ず書く** | 呼び出し側からは何が渡るか分からない |

引数に書く理由は次のレッスンで詳しく扱いますが、**関数の入口は他人との約束の場所** だから、と覚えておいてください。

## 2-1-3 値が無いかもしれない型を表す

> **string | undefined は「文字列か、値が無いか」を表し、使う前の確認を強制する**

Node.js入門で、環境変数を渡し忘れると `undefined` になると学びました。サーバー側では、これが最も多いバグの形です。

- **ユニオン型** — 「AかB」を `|` で表す書き方
- **undefined** — 値が無い状態

```ts
const port: string | undefined = process.env.PORT;

console.log(port.length);        // エラー: undefined かもしれない

if (port !== undefined) {
  console.log(port.length);      // ここでは string として扱える
}
```

`process.env.PORT` の型は `string | undefined` です。環境変数は渡されないこともあるので、TypeScriptは「文字列か、無いか」のどちらかだと知っています。

そのまま使おうとすると、`strict` が有効な環境ではエラーになります。**「渡されているはず」という思い込みのまま書けなくなる** ということです。これは制約ではなく、障害を1つ減らす仕組みです。

`if` で確認を通すと、その中では `string` として扱えるようになります。TypeScriptが条件を読み取って、型を絞り込んでくれます。

## 2-1-4 配列の型は中身の型で決まる

> **string[] は「文字列だけが入る配列」を表し、別の種類の値は入れられない**

ファイルから読んだ行の一覧のように、同じ種類の値をまとめて扱う場面は頻繁にあります。

**配列** は、値を順番に並べたものです。型は、中身の型の後ろに `[]` を付けて書きます。

```ts
const names: string[] = ["佐藤", "田中"];
const prices: number[] = [1200, 800];

names.push("鈴木");     // 問題なし
names.push(100);        // エラー: 数値は入れられない
```

中身の種類が保証されるので、後の処理が単純になります。「文字列のはずだが、もしかしたら数値かもしれない」と身構える必要がなくなるからです。

なお、初期値がある場合は推論に任せられます。`const names = ["佐藤", "田中"]` と書けば `string[]` と判断されます。
