# 5-1-4
# 確認は境界の1か所に置く

TypeScript 入門（サーバー） — Module 5 / レッスン5-1

<!-- ノート: 設計の話です。確認をどこにでも書くと、コードが確認だらけになります。 -->

---

## なぜ必要か

- あちこちで `undefined` の確認を書き、コードが読みにくい
- 同じ確認を何度も通っていて、どこが本当の入口か分からない

<!-- ノート: つかみ。防御的な確認が散らばった状態を問題として示します。 -->

---

## 結論

**外から来た値は入口で1度だけ確認し、そこから先は型を信じて書く**

- **境界** — 外の世界と自分のコードが接する場所(ファイル・通信・環境変数)

<!-- ノート: 結論を先に言い切ります。型が保証するのは境界の内側だけです。 -->

---

## 入口で確かめ、内側は素直に書く

```ts
// 境界: 確認する
function toUser(value: unknown): User {
  // 形を確かめて、User として返す(確認できなければ例外を投げる)
}

// 内側: 型を信じてよい
function greet(user: User): string {
  return user.name + " さん";
}
```

- 内側で再確認しないから、処理そのものに集中できる
