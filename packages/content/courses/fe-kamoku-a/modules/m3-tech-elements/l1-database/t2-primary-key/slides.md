# 主キーは行を一意に特定する

基本情報 科目A対策 — Module 3 / レッスン3-1

<!-- ノート: テーブルの中から「この1行」を指し示す方法の話です。試験の頻出テーマです。 -->

---

## なぜ必要か

- 社員テーブルに同姓同名の「佐藤」さんが2人いたら?
- 「佐藤さんの部署を直して」では、どちらの行か決まらない
- 間違いなく1行を指し示す目印がほしい

<!-- ノート: つかみ。同姓同名は実際の職場でも普通に起きる。氏名では行を特定できないと体感してもらう。 -->

---

## 結論

**主キーは行を1行に特定できる列(の組)で、重複とNULLが許されない**

- **一意** = 値が重複しないこと
- **NULL** = 値が入っていない状態のこと

<!-- ノート: 結論を言い切る。「重複NG・NULL NG」の2点セットをこのまま暗記してもらう。 -->

---

## 最小の例

社員テーブル(主キー: 社員番号)

| 社員番号 | 氏名 | 部署 |
| --- | --- | --- |
| 1001 | 佐藤 | 営業 |
| 1002 | 佐藤 | 経理 |

- 社員番号は全員違う値なので、1行を必ず特定できる

<!-- ノート: 同姓同名の佐藤さんが2人いても、社員番号1001と言えば1行に決まる。これが一意ということ。 -->

---

## 主キーにできない例

| 候補の列 | 主キーにできるか |
| --- | --- |
| 氏名 | できない(同姓同名で重複しうる) |
| 部署 | できない(同じ部署の行が複数ある) |
| 社員番号が空欄の行 | 許されない(NULLはだめ) |

<!-- ノート: 失敗例の枠。試験では「主キーにふさわしい列はどれか」の形で問われる。重複NG・NULL NGで判定する。 -->
