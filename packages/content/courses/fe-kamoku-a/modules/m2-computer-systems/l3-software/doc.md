# レッスン2-3 OSとソフトウェア

## このレッスンの目標

- [ ] ハードウェア・OS・アプリケーションの3層の関係を説明できる
- [ ] マルチタスクと仮想記憶を、OSによる装置の管理として説明できる
- [ ] 絶対パスと相対パスの違いを、具体例を挙げて説明できる

## 2-3-1 OSはハードとアプリの仲介役

> **OSはハードウェアを管理し、アプリケーションに共通の機能を提供する**

同じPCで表計算もブラウザも動き、どちらも画面に表示できます。CPUや主記憶は1組しかないのに、取り合いになりません。装置の管理を引き受けている存在が **OS** です。

まず全体の地図を描きます。CPUや主記憶などの装置が **ハードウェア** です。コンピュータを動かすプログラムの総称が **ソフトウェア** で、OSと **アプリケーション** の2つに分かれます。

| 層 | 例 | 役割 |
| --- | --- | --- |
| アプリケーション | 表計算、ブラウザ | 利用者の仕事をこなす |
| OS | Windows、Linux | 装置を管理し、共通の機能を提供する |
| ハードウェア | CPU、主記憶 | 実際に動く装置 |

もしOSが無かったら、アプリごとに画面表示や保存の仕組みを自作することになります。装置の種類が変わるたびに、全アプリを作り直す羽目にもなります。OSが間に立って共通の機能を提供するから、アプリは自分の仕事に集中できます。「ソフトウェア = OS + アプリケーション」という分類は、選択肢の問題でそのまま問われます。

## 2-3-2 マルチタスクは切り替えで実現する

> **OSはCPUの割当てを細かく切り替えて、複数のタスクを同時に見せる**

音楽を聴きながら文書を書けます。しかしCPUは、命令を1つずつ順番に実行する装置でした。1つずつしかできないのに同時に動いて見えるのは、OSの管理のおかげです。

実行中の仕事の単位を **タスク** と呼びます。OSはCPUを使うタスクをごく短い時間で切り替えます。

| 時間 | CPUを使うタスク |
| --- | --- |
| 0〜10ミリ秒 | 音楽の再生 |
| 10〜20ミリ秒 | 文書の編集 |
| 20〜30ミリ秒 | 音楽の再生 |

切り替えが人間には速すぎるため、全部が同時に動いて見えます。この仕組みが **マルチタスク** です。本当に同時なのではなく「同時に見せている」点が試験のポイントです。

切り替えのきっかけになるのが **割込み** です。割込みとは、作業を一時中断させる合図のことです。たとえばキーが押されると割込みが発生し、OSはそれを受けてCPUを次のタスクに割り当て直します。

## 2-3-3 仮想記憶はメモリ不足を補う

> **仮想記憶は補助記憶を使って、主記憶より大きなメモリ空間を見せる仕組み**

タスクは主記憶に置かれてから実行されます。しかし主記憶の容量には限りがあり、アプリケーションをたくさん開くと入り切らなくなります。

そこでOSは、いま使っていない部分を補助記憶装置へ退避させます。この仕組みが **仮想記憶** です。タスクから見ると、主記憶より大きな1つのメモリ空間があるように見えます。

| 場所 | 置くもの |
| --- | --- |
| 主記憶 | いま使っている部分 |
| 補助記憶装置 | いま使っていない部分(退避) |

退避した部分は、必要になったら主記憶へ戻します。この出し入れを、固定サイズのページに区切って行う方式が **ページング** です。大きさをそろえて区切ると、出し入れの管理が簡単になります。なお、この出し入れをスワップと呼ぶこともあります。

注意点が1つあります。補助記憶装置は主記憶よりアクセス時間が長い装置です。主記憶が小さすぎるとページの出し入ればかりが起こり、処理が遅くなります。「仮想記憶があれば主記憶は不要」という選択肢は誤りです。

## 2-3-4 ファイルは階層で整理する

> **ファイルはディレクトリの階層で整理し、パスで場所を指定する**

補助記憶装置には、文書や写真などのデータが大量にたまります。全部を1か所に平らに置くと、目的のデータを探せません。そこでOSは、データを階層構造で整理する仕組みを提供します。

- **ファイル** — データのまとまりに名前を付けたもの
- **ディレクトリ** — ファイルを入れる入れ物(フォルダーとも呼びます)
- **パス** — 場所までの道順を書いたもの

ディレクトリの中にディレクトリを入れられるので、全体は木のような階層になります。

```text
/
└── home
    └── user
        └── report.txt
```

report.txt の場所は `/home/user/report.txt` と書けます。先頭の `/` が階層の一番上を表し、`/` 区切りで下へたどります。

パスの書き方には2種類あります。

| 種類 | 起点 | 例 |
| --- | --- | --- |
| 絶対パス | 階層の一番上 | `/home/user/report.txt` |
| 相対パス | 今いるディレクトリ | `../report.txt` |

**絶対パス** は、どこから見ても同じ書き方で1つの場所を指します。**相対パス** は今いるディレクトリが起点なので、短く書けるかわりに、いる場所によって指す先が変わります。`..` は1つ上のディレクトリを表します。たとえば今いる場所が `/home/user` のとき、`../report.txt` は `/home/report.txt` を指します。試験では `..` を含むパスの読み取りが頻出です。

## もっと知りたい人へ

- OSとアプリケーションの間には、多くのアプリが共通で使う機能をまとめたミドルウェアと呼ばれるソフトウェアが入ることがあります。DBMSはその代表例です
- タスクの切り替え順をOSがどう決めるかにも、いくつかの方式があります。まずは「細かく切り替えて同時に見せる」という原理を固めるのが先です
- ページングの出し入れが多発して処理が極端に遅くなる現象にも名前が付いています。仕組みを理解していれば、名前は後からすぐ覚えられます
