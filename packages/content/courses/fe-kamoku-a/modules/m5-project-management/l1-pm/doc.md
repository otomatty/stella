# レッスン5-1 プロジェクトマネジメント

## このレッスンの目標

- [ ] プロジェクトと日常業務の違いを説明できる
- [ ] アローダイアグラムからクリティカルパスと所要日数を計算できる
- [ ] リスクへの4つの対応(回避・軽減・転嫁・受容)を例で説明できる

## 5-1-1 プロジェクトは期限のある活動

> **プロジェクトは、目的と期限が決まった一度限りの活動**

「新しい社内システムを作って」と任されたとします。毎日の伝票処理と同じ進め方でよいのでしょうか。この2つの仕事は性質が違います。目的と期限が決まった一度限りの活動が **プロジェクト** です。

| 観点 | 日常業務 | プロジェクト |
| --- | --- | --- |
| 回数 | 毎日・毎月の繰り返し | 一度限り |
| 終わり | 期限はなく続く | 期限がある |

毎月の給与計算は日常業務、システム導入はプロジェクトです。試験では「一度限りか、繰り返しか」で見分けてください。

プロジェクトを計画し、進みを管理する活動が **プロジェクトマネジメント** です。また、プロジェクトに関わる利害関係者を **ステークホルダ** と呼びます。利用する社員、経理部、開発チームなど、影響を受ける人は全員ステークホルダです。

## 5-1-2 スコープで範囲を決める

> **スコープは、プロジェクトでやること・やらないことの範囲**

プロジェクトの途中で「あれも追加して」と頼まれ、引き受けるほど作業が膨らむ——よくある失敗です。そこで最初に、やること・やらないことの範囲を決めます。この範囲が **スコープ** です。

やることは、作業に分けて洗い出します。作業を階層的に分解して書いた図が **WBS** です。

- システム導入
  - 準備
    - 要望の聞き取り
    - 機能の決定
  - 構築
    - 設定作業
    - 動作確認

大きな仕事を段階的に細かく割ることで、作業の抜けに気づけます。

もう1つ大事なのが「やらないことを決める」ことです。例えば「今回はスマホ対応はやらない」と文書に書いておきます。決めておけば、追加の要望が来ても「範囲外です」と言える根拠になり、期限を守れます。

## 5-1-3 クリティカルパスが納期を決める

> **クリティカルパスは、余裕のない作業のつながりで、遅れが納期に直結する**

スコープで決めた作業には順番の決まりがあります。「設定が終わらないと動作確認できない」といった待ちです。作業の順序を矢印で表した図が **アローダイアグラム** です。

小さな例で考えます。作業A(2日)の後、B(3日)とC(1日)が並行します。Cの後にD(1日)があり、BとDが終わると完了です。開始から完了までの経路を全部書き出し、**所要日数** を足し算します。

| 経路 | 計算 | 所要日数 |
| --- | --- | --- |
| A → B | 2 + 3 | 5日 |
| A → C → D | 2 + 1 + 1 | 4日 |

最長の経路はA→Bの5日です。この最長経路が **クリティカルパス** で、完了まで最短でも5日かかります。

同じ1日の遅れでも、影響は経路によって違います。

| 遅れる作業 | 完了日数 | 理由 |
| --- | --- | --- |
| Bが1日遅れる | 6日 | クリティカルパス上の作業 |
| Cが1日遅れる | 5日のまま | 経路に1日の余裕がある |

クリティカルパス上の作業には余裕がなく、遅れがそのまま納期の遅れになります。試験の計算問題は「経路を全部書き出す→足す→最長を選ぶ」の手順で必ず解けます。

## 5-1-4 ガントチャートで進捗を見える化

> **ガントチャートは、作業ごとの予定と実績を横棒で見える化する図**

計画を立てたら、次は進み具合の把握です。「順調です」という口頭の報告だけでは遅れに気づけません。縦に作業、横に日付を並べ、期間を横棒で表した図が **ガントチャート** です。予定に対する進み具合を **進捗** と呼びます。

| 作業 | 1日 | 2日 | 3日 | 4日 |
| --- | --- | --- | --- | --- |
| 設定(予定) | ■ | ■ | | |
| 設定(実績) | ■ | ■ | ■ | |
| 確認(予定) | | | ■ | ■ |

設定の実績の棒が予定より1日長く伸びています。棒の長さの差が、そのまま進捗の遅れとして読み取れます。

図の使い分けも問われます。

| 図 | 得意なこと |
| --- | --- |
| ガントチャート | 予定と実績の比較、進捗の把握 |
| アローダイアグラム | 作業の依存関係、納期の計算 |

「進捗の見える化はどの図か」と問われたらガントチャートを選んでください。

## 5-1-5 リスクは起きる前に備える

> **リスクマネジメントは、起きる前に洗い出して対応を決めておく活動**

担当者の急な休み、機器の故障、仕様の変更。起きてから慌てると、判断も対応も後手に回ります。まだ起きていないが、起きるかもしれない問題が **リスク** です。リスクを起きる前に洗い出し、対応を決めておく活動が **リスクマネジメント** です。

| リスク | 決めておく対応 |
| --- | --- |
| 担当者が長期で休む | 代わりの担当者を先に決める |
| 機器が故障する | 予備の機器を用意しておく |

キーワードは「事前」です。起きた後の火消しと混同させる選択肢がよく出ます。

リスクへの対応は4種類に整理されます。

| 対応 | 意味 |
| --- | --- |
| 回避 | リスクの原因ごと取り除く |
| 軽減 | 起きる確率や被害を小さくする |
| 転嫁 | 保険などで他者に負担を移す |
| 受容 | 何もせず受け入れると決める |

「保険に入る=転嫁」が定番の出題です。何もしないと決める受容も、検討した上での立派な対応の1つです。

## もっと知りたい人へ

- プロジェクトマネジメントの知識を体系化したガイドとしてPMBOKがあります。スコープやリスクなどの管理分野は、この体系に沿った整理です
- クリティカルパスの計算には、各作業の余裕日数を求める発展形もあります。まずは「最長経路を選ぶ」手順を確実にするのが先です
- 進捗の管理には、費用の面から進み具合を測る手法もあります。興味があればEVMという名前で調べてみてください
