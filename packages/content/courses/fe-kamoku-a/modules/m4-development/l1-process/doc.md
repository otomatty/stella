# レッスン4-1 システム開発の流れ

## このレッスンの目標

- [ ] 要件定義・設計・実装・テストの各工程で何をするかを説明できる
- [ ] ウォーターフォールモデルの特徴と長所・短所を説明できる
- [ ] アジャイル開発とウォーターフォールモデルの違いを説明できる

## 4-1-1 開発は工程を分けて進める

> **システム開発は要件定義・設計・実装・テストの工程に分けて進める**

家を建てるとき、設計図なしにいきなり柱を立てる人はいません。何を建てるか、どう建てるかを先に決めてから工事に入ります。ソフトウェアを作る仕事も同じです。ソフトウェアを作り上げる仕事の全体を **システム開発** と呼び、段階に区切って進めます。

代表的な工程は次の4つです。

| 工程 | 決めること・すること |
| --- | --- |
| **要件定義** | 何を作るかを決める |
| **設計** | どう作るかを決める |
| **実装** | プログラムを書いて作る |
| **テスト** | 正しく動くかを確かめる |

要件定義は「何を」、設計は「どう」とセットで覚えてください。この対応は選択肢の問題でよく問われます。

順序にも意味があります。何を作るか決めずに実装を始めると、望まれない物ができあがります。完成してから「違う」と分かると、作り直しは大きくなります。だから「決める工程」を先に置くのです。

## 4-1-2 ウォーターフォールは後戻りしない前提

> **ウォーターフォールモデルは、工程を順番に進めて後戻りしない前提の開発手法**

大人数で長い期間のシステム開発では、「いつ終わるか」「今どこまで進んだか」に答える必要があります。行き当たりばったりでは、計画も分担も立てられません。

そこで、工程を順番に進める型が生まれました。**ウォーターフォールモデル** です。**工程** とは、開発を区切った1つひとつの段階のことです。

要件定義 → 設計 → 実装 → テスト

水が滝を上から下へ流れて戻らないように、前の工程を終わらせてから次へ進みます。各工程の終わりに成果物を確認し、次の工程へ渡します。「後戻りしない前提」という言葉がポイントです。戻れないのではなく、戻らない想定で計画を立てる手法です。

| 観点 | ウォーターフォールモデル |
| --- | --- |
| 長所 | 工程ごとに区切るので計画や進捗管理がしやすい |
| 短所 | 後から要件の誤りが見つかると手戻りが大きい |

テストの段階で要件定義の間違いに気づくと、ほぼ最初からやり直しになります。この「変化に弱い」という短所が、次の手法が生まれた背景です。

## 4-1-3 アジャイルは短い周期で繰り返す

> **アジャイル開発は、短い期間で動くソフトウェアを作って繰り返し改善する**

作っている途中で、欲しいものが変わることはよくあります。使う人は、動く画面を見て初めて「こうしたい」に気づくからです。完成まで見せないウォーターフォールモデルでは、この声を拾えません。

変化を受け止めるための進め方が **アジャイル開発** です。用語は2つだけ押さえてください。

- **イテレーション** — 繰り返しの単位になる短い開発周期です
- **スクラム** — アジャイル開発の代表的な進め方です

1回のイテレーション(例: 2週間)は、次のように回します。

1. 今回作るものを決める
2. 動くソフトウェアを作る
3. 使う人に見せて意見をもらう
4. 次のイテレーションで改善する

毎回「動くもの」が出てくるのが、ウォーターフォールモデルとの一番の違いです。

| 観点 | ウォーターフォールモデル | アジャイル開発 |
| --- | --- | --- |
| 進め方 | 工程を順番に一度だけ | 短い周期で繰り返す |
| 重視 | 計画どおりに進める | 変化に対応する |
| 動くもの | 最後にまとめて完成 | 周期ごとに少しずつ |

試験では「計画重視ならウォーターフォール、変化対応ならアジャイル」の軸で選択肢を判定できます。どちらが優れているかではなく、開発の性質で使い分けるものです。

## もっと知りたい人へ

- ウォーターフォールモデルの各工程には、対応する検証の工程があります。要件定義にはシステム全体のテスト、設計には部品ごとのテストが対応します。この対応をV字型に並べた図をV字モデルと呼びます
- 実装のことをプログラミング、テストの前半を単体テストと呼ぶなど、工程の呼び名には揺れがあります。まずは本レッスンの4工程の役割を固めるのが先です
- スクラムには、イテレーションをスプリントと呼ぶなど独自の用語があります。興味があれば「スクラムガイド」で検索してみてください
