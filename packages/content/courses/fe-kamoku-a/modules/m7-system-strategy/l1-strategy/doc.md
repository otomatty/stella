# レッスン7-1 システム戦略と企画

## このレッスンの目標

- [ ] 情報システム戦略と経営戦略の関係を説明できる
- [ ] SaaS・PaaS・IaaSを「どこまで自分で管理するか」で区別できる
- [ ] RFIとRFPの違いと、調達の流れを説明できる

## 7-1-1 経営とITを一致させる

> **情報システム戦略は、経営の目標に合わせてITの使い方を決める計画**

流行のITツールを導入したのに現場で誰も使わない。お金と時間をかけたのに、会社の成果につながらない。こうした失敗は、導入の前に決めるべきことを決めていないと起こります。

まず、**経営戦略** とは会社の進む方向を決める計画です。そして、経営の目標に合わせてITの使い方を決める計画が **情報システム戦略** です。順番が大切で、経営戦略が先、ITの計画が後です。

| 計画 | 内容 |
| --- | --- |
| 経営戦略 | 全国に店舗を増やして売上を伸ばす |
| 情報システム戦略 | どの店舗でも使える受注の仕組みを整える |

「店舗を増やす」という経営の目標があるからこそ、「店舗共通の仕組みを整える」というITの方針が決まります。ITは目標を実現するための手段です。

逆に、「話題のツールだから」と目的なしに導入するのが「ITのためのIT」です。経営の目標とつながらないため、現場に定着しません。選択肢の問題では「経営戦略との整合性」が正解を選ぶ軸になります。

## 7-1-2 業務の流れをモデルで描く

> **業務プロセスは、モデル化して描くことで問題点と改善点が見える**

「この業務、なぜか時間がかかる」と感じても、どこに問題があるかは口頭ではあいまいなままです。情報システム戦略を立てるには、まず今の業務を正しく知る必要があります。

仕事が進む一連の流れを **業務プロセス** と呼びます。そして、流れを図や記号で表すことが **モデル化** です。備品購入の流れを描いてみます。

| 順 | 手順 |
| --- | --- |
| 1 | 申請書を書く |
| 2 | 課長が承認する |
| 3 | 部長が承認する |
| 4 | 本部長が承認する |
| 5 | 発注する |

描く前は「なんとなく遅い」でした。描いた瞬間に、同じ内容の承認が3回あるという事実が見えます。これがモデル化の効果です。

問題が見えたら、根本から見直します。業務の流れを根本から見直すことが **BPR** です。承認を1回に減らすなど、流れごと作り直します。部分の手直しではなく全体を設計し直すのが特徴で、「根本から」「抜本的に」がキーワードです。

## 7-1-3 クラウドサービスの使い分け

> **クラウドサービスは、どこまで自分で管理するかで SaaS・PaaS・IaaS に分かれる**

サーバーを自前でそろえると、お金も時間もかかります。そこで、ネットワーク越しにITの機能を借りる **クラウドサービス** が広まっています。区分は複数ありますが、違いは機能の中身ではなく「借りる範囲」です。

| 区分 | どこまで借りるか |
| --- | --- |
| **SaaS** | アプリケーションまで |
| **PaaS** | 実行環境まで |
| **IaaS** | サーバー(ハードウェア)まで |

SaaSはアプリケーションまで全部借りるので、すぐ使えます。PaaSはアプリケーションを動かす実行環境までを借り、アプリケーションは自分で用意します。IaaSはサーバーという機器だけを借り、OSやソフトウェアは自分で用意します。

借りる範囲と、自分で管理する範囲は逆の関係です。

| 区分 | 自分で管理する範囲 |
| --- | --- |
| **IaaS** | 広い(OSやソフトウェアも自分で用意) |
| **PaaS** | 中(アプリケーションだけ自分で用意) |
| **SaaS** | 狭い(ほぼ管理不要で、すぐ使える) |

自分で管理する範囲が広い順は IaaS → PaaS → SaaS です。試験では「利用者の管理範囲が最も広いのはどれか」の形で問われます。

## 7-1-4 調達の流れ(RFI・RFP)

> **システムの調達は、RFIで情報を集めRFPで提案を求める流れで進む**

情報システム戦略で決めた仕組みを、外部の会社に発注したいとします。しかし、どの会社が何をできるのか分かりません。口頭で頼むと、各社の返事がばらばらで比べられません。

システムやサービスを外部から入手することを **調達** と呼びます。調達は決まった流れで進めます。

| 順 | 手順 | やること |
| --- | --- | --- |
| 1 | **RFI**(情報提供依頼) | 各社に情報の提供を依頼する |
| 2 | **RFP**(提案依頼) | 要件を示して提案を依頼する |
| 3 | 提案評価 | 各社の提案を比較して選ぶ |
| 4 | 契約 | 選んだ会社と契約を結ぶ |

まずRFIで広く情報を集め、候補に絞ってからRFPで提案を求めます。RFIのIはインフォメーション、RFPのPはプロポーザル(提案)と覚えると順番を間違えません。

RFPには要件(実現してほしい内容と条件)を書きます。要件がないと、各社の提案の前提がばらばらになるからです。同じ条件で提案させるからこそ、公平に比較して選べます。RFIとRFPの順番を入れ替えた選択肢は定番のひっかけです。

## もっと知りたい人へ

- 経営戦略の立案には、自社の強み・弱みを整理する分析の手法がいくつもあります。まずは「経営戦略が先、ITが後」という順番を固めるのが先です
- クラウドサービスには、この3区分のほかにも派生した区分があります。「どこまで借りるか」の軸で見れば同じ考え方で整理できます
- RFPを受け取った会社側がどう提案を作るかは、開発プロジェクトの進め方の話につながります
