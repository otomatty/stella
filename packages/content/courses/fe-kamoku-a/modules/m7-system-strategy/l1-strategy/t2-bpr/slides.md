# 業務の流れをモデルで描く

基本情報 科目A対策 — Module 7 / レッスン7-1

## なぜ必要か

- 「この業務、なぜか時間がかかる」と感じる
- でも、どこに問題があるかは口頭ではあいまい
- 情報システム戦略を立てる前に、現状を知る方法がほしい

<!-- ノート: つかみ。「あの申請、いつも遅いよね」で止まってしまう場面。原因を特定する方法はまだ言わない。 -->

---

## 結論

**業務プロセスは、モデル化して描くことで問題点と改善点が見える**

- **業務プロセス** = 仕事が進む一連の流れ
- **モデル化** = 流れを図や記号で表すこと

<!-- ノート: 結論を言い切る。頭の中や口頭ではなく、描いて目に見える形にするのがポイント。 -->

---

## 最小の例

備品購入の流れを描いてみます。

| 順 | 手順 |
| --- | --- |
| 1 | 申請書を書く |
| 2 | 課長が承認する |
| 3 | 部長が承認する |
| 4 | 本部長が承認する |
| 5 | 発注する |

- 描いてみると、同じ内容の承認が3回あると分かる

<!-- ノート: 描く前は「なんとなく遅い」だったのが、描いた瞬間に承認3回という事実が見える。これがモデル化の効果。 -->

---

## 見えたら根本から見直す — BPR

- **BPR** = 業務の流れを根本から見直すこと
- 承認を1回に減らすなど、流れごと作り直す
- 部分の手直しではなく、全体を設計し直すのが特徴

<!-- ノート: 補強枠。BPRは「根本から」「抜本的に」がキーワード。既存の流れを前提にした小さな改善とは区別される。 -->
