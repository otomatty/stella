# 5-1-1
# テストしにくさの正体は隠れた依存

Pythonテスト自動化とCI入門 — Module 5 / レッスン5-1

<!-- ノート: 「この関数はテストできない」と言われたときに、何が起きているかを言語化します。 -->

---

## なぜ必要か

- テストを書こうとしたら、そもそも書けない関数がある
- 月が変わったら、昨日まで緑だったテストが赤くなった

<!-- ノート: つかみ。書けないのは腕の問題ではなく、コードの形の問題。ここで結論は言わない。 -->

---

## 結論

**テストしにくさの正体は、現在時刻・乱数・グローバル変数・外部I/Oといった「隠れた依存」である**

- 引数に現れない依存先が **隠れた依存**
- 関数の外に置いた共有の値が **グローバル変数**
- ファイル・通信・画面などのやり取りが **入出力**(I/O)

<!-- ノート: 結論を言い切る。「隠れた」= 呼び出し側から見えない、が定義。 -->

---

## テストできない関数

```python
import datetime


def is_campaign_period():
    today = datetime.date.today()   # 隠れた依存
    return today.month == 12
```

- 12月にしか緑にならないテストになる

<!-- ノート: 引数は0個なのに、結果は日によって変わる。これが隠れた依存の見分け方。 -->

---

## 隠れた依存の見つけ方

| 合図 | 例 |
| --- | --- |
| 現在時刻・乱数 | `date.today()` / `random` |
| 外の値 | グローバル変数 / 環境変数 |
| 入出力 | ファイル読み書き / 通信 |

- 引数が同じでも結果が変わるなら、隠れた依存がある

<!-- ノート: 対比枠。この判定基準1つで、ほぼ全部見つかる。 -->
