## なぜ必要か

- 確認用のコードは書いたが、実行するのに毎回コメントを外している
- 確認コードがあちこちに散らばり、どれが最新か分からない

<!-- ノート: つかみ。「動作確認用のスクリプト」を各自が好きに書いている状態を思い出させる。ここで結論は言わない。 -->

## 結論

**pytestは `test_` で始まる関数を自動で見つけて実行する**

- **pytest** は Python のテストを実行する道具
- 名前の決まりを守った **テスト関数** だけが集められる

<!-- ノート: 結論を言い切る。登録作業はいらない。名前が登録そのものだと伝える。 -->

---

## 最小のコード

```python
# test_order.py
def test_calc_total():
    assert calc_total([100, 200]) == 300
```

- ファイル名は `test_` で始める(**テストファイル**)
- 関数名も `test_` で始める
- 実行はターミナルで `pytest` と打つだけ

<!-- ノート: ファイル名は `_test.py` で終わる形も既定で集められる。この講座は `test_` で始める形にそろえる。 -->

---

## 見つけてもらえない例

```python
# orders.py — ファイル名が名前の決まりから外れている
def check_total():  # 関数名も test_ で始まらない
    assert calc_total([100, 200]) == 300
# => 収集されず、テストは 0 個
```

- 実行しても「0 個」と出たら、まず名前を疑う

<!-- ノート: 失敗例枠。テストが赤にならず「収集されていないだけ」の状態が、最も気づきにくい。 -->
