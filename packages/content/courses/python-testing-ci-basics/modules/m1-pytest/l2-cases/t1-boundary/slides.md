# 境界値と異常系も同じくらい重要

## なぜ必要か

- テストは通っているのに、本番では落ちる
- 落ちた入力は、空だったり、0 だったり、想定外の値だったりする

<!-- ノート: つかみ。うまくいく例だけを試している状態。ここで結論は言わない。 -->

---

## 結論

**境界値と異常系は正常系と同じくらい重要なテスト対象である**

- **正常系**: 想定どおりの入力
- **境界値**: 条件の切り替わり目(0、上限、空)
- **異常系**: 想定外の入力(型違い、負の数)

<!-- ノート: 結論を言い切る。バグは真ん中ではなく端に住んでいる、と伝える。 -->

---

## 最小のコード

```python
def test_returns_sum_of_prices():   # 正常系
    assert calc_total([100, 200]) == 300


def test_returns_zero_for_empty_list():  # 境界値
    assert calc_total([]) == 0
```

- 同じ関数でも、確かめている振る舞いは別

<!-- ノート: 空リストは最も忘れられる境界値。件数0はどの業務にも出てくる。 -->

---

## 端を探す観点

| 観点 | 例 |
| --- | --- |
| 件数 | 0件 / 1件 / たくさん |
| 数値 | 上限 / 下限 / その1つ外 |
| 想定外 | 負の数 / None / 文字列 |

<!-- ノート: 対比枠。全パターンは要らない。この3観点で端を1つずつ拾うだけで、事故はかなり減る。 -->
