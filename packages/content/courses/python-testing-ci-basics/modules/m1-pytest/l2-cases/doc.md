## 1-2-1 境界値と異常系も同じくらい重要

> **境界値と異常系は正常系と同じくらい重要なテスト対象である**

テストは通っているのに本番で落ちる、という経験はよくあります。落ちた入力を見ると、たいてい空だったり、0 だったり、想定していない値だったりします。うまくいく例だけを試していたのです。

テスト対象は、次の3つの観点で分けて考えます。

- **正常系** — 想定どおりの入力。まずここから書く
- **境界値** — 条件の切り替わり目。0件、上限、空など
- **異常系** — 想定外の入力。負の数、`None`、型違いなど

```python
def test_returns_sum_of_prices():   # 正常系
    assert calc_total([100, 200]) == 300


def test_returns_zero_for_empty_list():  # 境界値
    assert calc_total([]) == 0
```

同じ関数に対するテストでも、確かめている振る舞いは別ものです。**バグは真ん中ではなく端に住んでいます。**

端を探すときは、次の観点で1つずつ拾ってください。

| 観点 | 例 |
| --- | --- |
| 件数 | 0件 / 1件 / たくさん |
| 数値 | 上限 / 下限 / その1つ外 |
| 想定外 | 負の数 / None / 文字列 |

全パターンを網羅する必要はありません。この3観点で端を拾うだけで、事故はかなり減ります。

## 1-2-2 parametrize で入力データを並べる

> **parametrizeを使うと、同じ検証を複数の入力データで繰り返せる**

観点を増やしていくと、入力と期待値だけが違う同じ形のテストが並びます。コピーして貼って書き換える書き方だと、検証の仕方を直したくなったときに5か所を同じように直すことになり、1つだけ直し忘れます。

入力と期待値の組を **テストケース** と呼びます。**parametrize** は、このケースを並べて書くための pytest の機能です。

```python
import pytest


@pytest.mark.parametrize("prices, expected", [
    ([100, 200], 300),
    ([], 0),
    ([500], 500),
])
def test_calc_total(prices, expected):
    assert calc_total(prices) == expected
```

1行が1ケースです。ケースを増やす作業が、行を1本足すだけになります。

大事なのは、**テストの本数が減るわけではない** ことです。実行するとこう表示されます。

```text
test_order.py::test_calc_total[prices0-300] PASSED
test_order.py::test_calc_total[prices1-0]   PASSED
test_order.py::test_calc_total[prices2-500] PASSED
```

3件のテストとして数えられ、失敗したときはどのケースが落ちたのかが個別に分かります。減っているのは書く量だけです。

なお、parametrize でまとめてよいのは **検証の内容が同じ** ケースだけです。確かめている振る舞いが違うなら、無理にまとめず別のテスト関数に分けてください。

## 1-2-3 fixture で準備と後片付けを共通化する

> **fixtureを使うと、テストごとの準備・後片付けを共通化できる**

AAA の「準備」が長くなると、どのテストにも同じ10行が並びます。さらに厄介なのは後始末です。作った一時ファイルを消し忘れると、次のテストが前回の結果に影響されます。**実行順によって結果が変わるテスト** は、最も直しにくい部類です。

テストの前に走る処理を **前処理**、後に走る処理を **後片付け** と呼びます。**fixture** は、この両方を1か所に書いておく仕組みです。

```python
import pytest


@pytest.fixture
def sample_prices():
    return [100, 200, 400]


def test_calc_total(sample_prices):
    assert calc_total(sample_prices) == 700
```

テスト関数の引数に fixture の名前を書くと、その戻り値が渡されます。呼び出しコードは書きません。名前で結びつく点が独特なので、最初は戸惑うかもしれません。

後片付けまで書くときは `yield` を使います。

```python
@pytest.fixture
def temp_file(tmp_path):
    path = tmp_path / "orders.csv"
    path.write_text("100,200")
    yield path        # ここまでが前処理
    path.unlink()     # yield の後が後片付け
```

`yield` の前が前処理、後ろが後片付けです。**テストが失敗しても後片付けは実行されます。** だから次のテストが汚れません。fixture の目的は、コードを短くすることではなく、**毎回きれいな状態から始めること** です。

## もっと知りたい人へ

- `tmp_path` は pytest が最初から用意している fixture で、テストごとに使い捨ての一時フォルダを渡してくれます。自分で `/tmp` にファイルを作る必要はありません
- fixture は `conftest.py` というファイルに置くと、同じフォルダ配下のテストから名前だけで使えるようになります
