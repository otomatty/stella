# レッスン2-1 演習 — テストの失敗を読んで直す

対象トピック: 2-1-1 〜 2-1-3

## 手元で試す

`order.py` の `calc_total` を、わざと壊した形に書き換えます。

```python
# order.py
def calc_total(prices):
    total = 0
    for price in prices[:-1]:   # わざと最後の1件を落としている
        total += price
    return total
```

`test_order.py` を次の内容にして実行してください。

```python
from order import calc_total


def test_returns_sum_of_prices():
    prices = [100, 200]
    total = calc_total(prices)
    assert total == 300
```

```bash
pytest
```

赤くなった出力から、次の4つを声に出して読み上げてください。

1. どのテストが失敗したか
2. どのファイルの何行目か
3. 期待値はいくつか
4. 実際に返ってきた値はいくつか

確かめられたら、次もやってみましょう。

1. `calc_total` を正しい形(`prices[:-1]` を `prices` に戻す)に直し、緑になることを確かめる
2. 「注文0件で合計がエラーになる」という報告を受けた想定で、`calc_total([])` の再現テストを先に書く
3. いまの実装ではそのテストが通ってしまうことを確認し、通ってしまうテストは再現テストとして役に立たない理由を考える

## 演習問題

### 問1(基本)

次の失敗出力から、失敗したテスト名・期待値・実際の値を答えてください。

```text
_______________ test_calc_shipping _______________

test_order.py:14: in test_calc_shipping
    assert calc_shipping(5000) == 0
E   assert 500 == 0
E    +  where 500 = calc_shipping(5000)

FAILED test_order.py::test_calc_shipping - assert 500 == 0
```

### 問2(基本)

仕様は「合計金額が5000円以上なら送料0円」です。問1の失敗は、コードのバグとテスト自体の誤りのどちらですか。理由も書いてください。

### 問3(応用)

「注文が1件もないと合計金額の計算でエラーになる」という報告を受けました。直す前にやるべきことを、手順として3つ以上挙げてください。

### 問4(応用)

再現テストを書いたのに、コードを直す前から緑でした。このとき何が起きていると考えられますか。2つ挙げてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

失敗したテストは `test_calc_shipping`、期待値は `0`、実際の値は `500` です。`test_order.py` の14行目で失敗しています。

</details>

<details>
<summary>問2の解答例</summary>

コードのバグです。仕様が「5000円以上で送料0円」なので、`5000` を渡したときに `0` が返るのが正しい振る舞いです。テストの期待値は仕様どおりで、実装が境界の条件を `>` にしている可能性が高いです。

</details>

<details>
<summary>問3の解答例</summary>

1. 空の注文を渡す再現テストを書く
2. 実行して赤くなることを確認する(再現できた証拠)
3. コードを直す
4. 緑になることを確認し、他のテストも巻き込んで壊していないか確認する

</details>

<details>
<summary>問4の解答例</summary>

1つは、報告された条件を正しく再現できていないことです(入力や前提が実際と違う)。もう1つは、そもそもバグがすでに直っている、あるいは別の場所で起きている可能性です。どちらにせよ、赤くならないテストでは直ったことを確認できません。

</details>

## 確認クイズ

### Q1. 失敗出力から拾う4か所の組み合わせとして正しいものはどれですか。

- A. どのテストが・どの行で・何を期待して・何が返ったか
- B. 実行時間・メモリ使用量・CPU 使用率・件数
- C. 作者・作成日・最終更新日・ファイルサイズ

<details>
<summary>答え</summary>

**A** — この4つを拾いに行けば、出力が長くても迷いません。

</details>

### Q2. テストが赤くなったとき、最初にすべきことはどれですか。

- A. 仕様を確認して、実装と期待値のどちらが誤っているか決める
- B. とりあえずコードを書き換えて緑にする
- C. 期待値を実際の値に書き換えて緑にする

<details>
<summary>答え</summary>

**A** — 仕様が先です。緑にすること自体を目的にすると、正しい実装を壊します。

</details>

### Q3. 「テスト自体の誤り」に当たるのはどれですか。

- A. 仕様は5000円以上で送料0円なのに、期待値を500円と書いていた
- B. 実装が5000円ちょうどのときに500円を返していた
- C. 実装が空リストで例外を投げていた

<details>
<summary>答え</summary>

**A** — 期待値の書き間違いはテスト側の誤りです。テストも人が書くので間違えます。

</details>

### Q4. 再現テストは、いつ書きますか。

- A. バグを直す前
- B. バグを直したあと、余裕があれば
- C. リリースの直前にまとめて

<details>
<summary>答え</summary>

**A** — 直す前に書いて赤くなることを確認します。その赤が、再現できた証拠になります。

</details>

### Q5. 再現テストを残しておく理由はどれですか。

- A. 次に同じ場所を壊したとき、その場で赤くなるから
- B. テストの本数が増えて実行時間が延びるから
- C. バグ報告書の代わりになるから

<details>
<summary>答え</summary>

**A** — 直した記憶はコードに残りませんが、テストは残ります。再発をその場で捕まえてくれます。

</details>
