# 失敗出力は決まった順に読む

Pythonテスト自動化とCI入門 — Module 2 / レッスン2-1

---

## なぜ必要か

- 赤い文字が大量に出て、どこを見ればいいのか分からない
- とりあえず先輩に画面を見せて、指さしてもらっている

<!-- ノート: つかみ。読み方さえ決まっていれば、量は関係ない。ここで結論は言わない。 -->

---

## 結論

**失敗出力は「どのテストが・どの行で・何を期待して・何が返ったか」の順に読む**

- 赤い表示のかたまりが **失敗出力**
- 呼び出しの経路をたどった部分が **トレースバック**

<!-- ノート: 結論を言い切る。上から順に読むのではなく、4つを拾いに行く。 -->

---

## 4か所を拾う

```text
_______________ test_calc_total _______________   ← どのテストが

test_order.py:8: in test_calc_total               ← どの行で
    assert calc_total([100, 200]) == 300
E   assert 250 == 300                             ← 何が / 何を期待して
```

<!-- ノート: 実際の画面を出しながら、この4か所を順に指す。1回やれば怖くなくなる。 -->

---

## 最後の1行から読む

- 出力の **いちばん下** に要約が出る
- 件数と失敗したテスト名が並ぶ

```text
FAILED test_order.py::test_calc_total - assert 250 == 300
1 failed, 3 passed
```

<!-- ノート: 対比枠。長い出力は下から読むほうが速い。全部を読む必要はない。 -->
