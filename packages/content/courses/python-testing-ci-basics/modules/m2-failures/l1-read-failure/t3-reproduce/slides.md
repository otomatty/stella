# 再現テストを書いてから直す

---

## なぜ必要か

- 半年前に直したはずのバグが、また同じ形で報告された
- 直したことは覚えているが、何を直したのかは残っていない

<!-- ノート: つかみ。直した記憶はコードに残らない。ここで結論は言わない。 -->

---

## 結論

**再現手順をテストとして書いてから直すと、同じバグの再発を防げる**

- バグを再現させるために書くテストが **再現テスト**
- 直す前に書くので、最初は必ず赤くなる

<!-- ノート: 結論を言い切る。「赤いテストを書く」ことに抵抗が出るので、そこを丁寧に。 -->

---

## 手順

1. 報告された入力で、失敗するテストを書く
2. 赤くなることを確認する(再現できた証拠)
3. コードを直す
4. 緑になることを確認する

<!-- ノート: 2 を飛ばさない。赤くならないテストは、バグを再現できていない。 -->

---

## 最小のコード

```python
def test_returns_zero_for_empty_list():
    # 報告: 注文0件で合計がエラーになる
    assert calc_total([]) == 0
```

- このテストは、直したあともずっと残る
- 次に誰かが壊したら、その場で赤くなる

<!-- ノート: 再現テストは資産。バグの数だけテストが増えるのが、健全な育ち方。 -->
