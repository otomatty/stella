# 2-1-2
# 失敗にはバグとテストの誤りがある

Pythonテスト自動化とCI入門 — Module 2 / レッスン2-1

<!-- ノート: 赤を見たら反射でコードを直す、をやめさせる回です。 -->

---

## なぜ必要か

- 赤くなったのでコードを直したら、別のテストが赤くなった
- 期待値のほうが間違っていて、正しい実装を壊してしまった

<!-- ノート: つかみ。テストを通すこと自体が目的化すると、この事故が起きる。ここで結論は言わない。 -->

---

## 結論

**テストの失敗には「コードのバグ」と「テスト自体の誤り」の2種類がある**

- 実装が仕様どおりでない誤りが **バグ**
- 期待値や準備の書き間違いは、テスト側の誤り

<!-- ノート: 結論を言い切る。直す前に「どちらが正しいか」を決める、が本題。 -->

---

## どちらか決める手順

1. 仕様(何が正しいか)を確認する
2. 実際の値と、仕様が求める値を比べる
3. ずれているのが実装なら、コードを直す
4. ずれているのが期待値なら、テストを直す

- どちらでもない(環境が原因)こともある

<!-- ノート: 仕様が先。仕様が曖昧なら、そこで止めて確認するのが正しい行動。assert の手前で落ちていたら環境を疑う。 -->

---

## テスト側の誤りの例

```python
def test_calc_shipping():
    # 仕様は「5000円以上で送料0円」
    assert calc_shipping(5000) == 500   # 期待値が誤り
```

- 実装は正しいのに赤くなる
- ここでコードを直すと、仕様に反する実装ができあがる

<!-- ノート: 失敗例枠。境界値の期待値ミスは実際によくある。テストも間違える、と覚えさせる。 -->
