# 3-1-2
# 赤のままマージしない

Pythonテスト自動化とCI入門 — Module 3 / レッスン3-1

<!-- ノート: CI を入れたのに効かないチームは、たいていこのルールがありません。 -->

---

## なぜ必要か

- 赤いままマージされ、main を取り込んだ人から順に赤くなる
- 誰が壊したのか分からず、直す人も決まらない

<!-- ノート: つかみ。赤が常態化すると、誰も出力を見なくなる。ここで結論は言わない。 -->

---

## 結論

**CIが赤のままマージしないルールが、mainブランチの品質を守る**

- 作業を枝分かれさせる単位が **ブランチ**
- 本流が **mainブランチ**。全員がここから枝を作る
- テストが全部通った状態が **グリーン**

<!-- ノート: 結論を言い切る。技術ではなくルール。合意しないと機能しない。 -->

---

## 赤を放置すると起きること

1. main が壊れる
2. main を取り込んだ枝から順に赤くなる
3. 自分のせいか判断できず、赤を無視し始める
4. CI が意味を失う

<!-- ノート: 既にある枝が勝手に赤くなるのではなく、main を取り込んだ人から巻き込まれる。4に到達したチームは、CIを止めたのと同じ状態。 -->

---

## 赤いときの選択肢

| 状況 | すること |
| --- | --- |
| 自分の変更が原因 | 直して push し直す |
| 元から赤い | 先に main を直す(自分の PR は待つ) |
| 原因が不明 | 落ちたテスト名を添えて相談する |

<!-- ノート: 対比枠。「とりあえずマージ」が選択肢に無いことが重要。 -->

---

## まとめ
