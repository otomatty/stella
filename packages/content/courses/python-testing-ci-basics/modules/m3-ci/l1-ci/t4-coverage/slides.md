# 3-1-4
# カバレッジは証明ではなく道具

Pythonテスト自動化とCI入門 — Module 3 / レッスン3-1

<!-- ノート: 数字が独り歩きしやすい指標です。使い方を最初に間違えないように。 -->

---

## なぜ必要か

- 「カバレッジ80%を目標に」と言われたが、何のためか分からない
- 数字を上げるために、意味のないテストを書いてしまう

<!-- ノート: つかみ。目標にした瞬間、指標は壊れる。ここで結論は言わない。 -->

---

## 結論

**カバレッジは品質の証明ではなく、テストされていない場所を見つける道具である**

- テスト実行時に通った行の割合が **カバレッジ**
- 「通った」だけで、「正しいと確かめた」ではない

<!-- ノート: 結論を言い切る。通過と検証は別もの、が核心。 -->

---

## 通っても検証していない例

```python
def test_calc_total():
    calc_total([100, 200])   # 呼んだだけ。assert が無い
```

- カバレッジは100%になる
- 壊しても、このテストは赤くならない

<!-- ノート: 失敗例枠。数字を目標にすると、これが量産される。実際に現場で見る形。 -->

---

## 正しい使い方

- 数字を上げに行かない。**低い場所を見に行く**
- 0%のファイルは「まだ誰も守っていない」印
- 落ちた場所が重要なら、そこにテストを足す
