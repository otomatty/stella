# lint は実行前に危ない書き方を指摘する

Pythonテスト自動化とCI入門 — Module 6 / レッスン6-1

<!-- ノート: 最後のモジュールです。テスト以外に CI が守ってくれるものを扱います。 -->

---

## なぜ必要か

- 使っていない変数や、書き間違えた名前がそのまま残っている
- レビューで「ここ typo です」と指摘するのに時間を使っている

<!-- ノート: つかみ。人がやらなくていい指摘に、人の時間を使っている状態。ここで結論は言わない。 -->

---

## 結論

**lintは、バグになりやすい書き方をテスト実行前に機械が指摘する仕組みである**

- 静的に(実行せずに)コードを調べることが **lint**
- それを行う道具が **リンター**

<!-- ノート: 結論を言い切る。テストは動かして確かめる、lintは動かさずに調べる。役割が違う。 -->

---

<!-- ノート: 綴り違いはテストでも見つかるが、テストが無い場所は誰も守っていない。 -->

---

## テストと lint の役割

| | 見つけるもの | 実行 |
| --- | --- | --- |
| テスト | 振る舞いの誤り | 動かす |
| lint | 書き方の危うさ | 動かさない |

- CI では両方を回す

<!-- ノート: 対比枠。どちらかで代用はできない。lintは速いので、CIの最初に置くことが多い。 -->
