# 型チェッカーは実行せずに食い違いを見つける

## なぜ必要か

- 文字列を渡すべき関数に、数値を渡していた
- テストが通っていない経路だったので、本番で初めて落ちた

<!-- ノート: つかみ。テストが無い場所は、テストでは守れない。ここで結論は言わない。 -->

---

## 結論

**型ヒントと型チェッカーは、実行しなくても引数や戻り値の食い違いを検出できる**

- 引数や戻り値の種類を書き添えるのが **型ヒント**
- それを照合して食い違いを指摘する道具が **型チェッカー**

<!-- ノート: 結論を言い切る。Python の型ヒントは実行時には強制されない。照合するのは道具の役目。 -->

---

## 最小のコード

```python
def calc_total(prices: list[int]) -> int:
    return sum(prices)


calc_total("100")   # 型チェッカーが指摘する
```

- 実行しなくても、渡し方の誤りが分かる

<!-- ノート: 型ヒントは注釈。書いただけでは何も起きず、チェッカーを回して初めて効く。 -->

---

## 3つの守り方

| 守り方 | 見つかるもの |
| --- | --- |
| 型チェッカー | 引数・戻り値の食い違い |
| lint | 危うい書き方 |
| テスト | 振る舞いの誤り |

- CI で3つとも回すと、抜けが減る

<!-- ノート: 対比枠。講座全体のまとめにもなる枠。3つは補い合う関係。 -->
