# 3-2-3
# 再帰の呼び出し回数に注意

基本情報 科目B対策 — Module 3 / レッスン3-2

<!-- ノート: 再帰の最後のトピックです。短く書けた再帰が、実は大量の呼び出しをしていることがある、という注意点を扱います。 -->

---

## なぜ必要か

- **フィボナッチ数列**(前2つの和を並べた数列)は 1, 1, 2, 3, 5, 8, … と続きます
- 「前2つの和」は再帰で素直に書けます
- しかし n を少し増やすだけで、急に遅くなるのです。なぜでしょうか

<!-- ノート: つかみ。フィボナッチ数列は前2つの和、と一言で定義する。書きやすさと速さは別物、という問いを立てて答えは言わない。 -->

---

## 結論

**同じ計算を重複して行う再帰は、呼び出し回数が急激に増える**

- 1回の呼び出しが2回の呼び出しを生むと、回数は倍々で膨らみます
- 計算量の視点で、呼び出し回数を数える習慣をつけましょう

<!-- ノート: 再帰そのものが遅いのではありません。同じ引数の計算を何度もやり直す形が遅いのです。 -->

---

## 最小のコード

```text
○fib(整数型: n)
  if (n が 2 以下)
    return 1
  endif
  return fib(n − 1) + fib(n − 2)
```

<!-- ノート: 基底条件は n が 2 以下。それ以外は fib(n − 1) と fib(n − 2)、つまり自分を2回呼び出します。この「2回」が膨らみの原因です。 -->

---

## fib(5) の中で fib(3) は2回計算される

- fib(5) は fib(4) と fib(3) を呼びます
- fib(4) の中でも、また fib(3) が呼ばれます
- 同じ fib(3) を2回、fib(2) は3回計算し、呼び出しは合計9回です

<!-- ノート: 補強枠。fib(3) の答えは1回目も2回目も同じなのに、まるごと計算し直しています。n = 20 では呼び出しが1万回を超えます。 -->
