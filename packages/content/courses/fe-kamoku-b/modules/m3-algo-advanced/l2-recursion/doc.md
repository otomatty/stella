# レッスン3-2 再帰

## このレッスンの目標

- [ ] 再帰の擬似言語を読み、基底条件を指摘できる
- [ ] fact(3) の呼び出しをトレースし、戻り値を求められる
- [ ] 呼び出し回数が急激に増える再帰の形を見分けられる

## 3-2-1 再帰は自分自身を呼び出す

> **再帰は関数が自分自身を呼び出す書き方で、必ず止まる条件を持つ**

**再帰** とは、関数が自分自身を呼び出す書き方のことです。「n 個の場合の答えは、n − 1 個の場合の答えから作れる」という形の処理を、驚くほど短く書けます。

```text
○fact(整数型: n)
  if (n が 1 以下)
    return 1
  endif
  return n × fact(n − 1)
```

読み方のポイントは2つです。

- `n が 1 以下` なら、もう自分を呼ばずに 1 を返します。この止まる条件を **基底条件** と呼びます
- それ以外なら、引数を1つ小さくした `fact(n − 1)` を呼び、その戻り値に n を掛けます

引数が呼び出しのたびに小さくなり、いつか必ず基底条件に届く。これが再帰が止まる仕組みです。

もし基底条件が無いとどうなるでしょうか。

```text
○fact(整数型: n)
  return n × fact(n − 1)
```

fact(3) → fact(2) → fact(1) → fact(0) → … と呼び出しが永遠に続き、プログラムは止まりません。再帰を読むときは、まず基底条件を探してください。科目Bでは「基底条件はどれか」「引数は小さくなっているか」が読解の起点になります。

## 3-2-2 再帰のトレース

> **再帰は呼び出しを深く潜り、基底条件から順に値が戻って確定する**

fact は **階乗**(1 から n までの積)を求める関数です。fact(3) なら 1 × 2 × 3 = 6 が答えです。では、再帰の中で 6 はどう作られるのでしょうか。トレースで確かめます。

再帰のトレースは、2つの段階に分けると迷いません。

まず **潜る段階** です。基底条件に届くまで、呼び出しが続きます。

| 呼び出し | n が 1 以下か | 動き |
| --- | --- | --- |
| fact(3) | 偽 | 3 × fact(2) を求めるため fact(2) を呼ぶ |
| fact(2) | 偽 | 2 × fact(1) を求めるため fact(1) を呼ぶ |
| fact(1) | 真 | 基底条件。return 1 |

次に **戻る段階** です。いちばん深い fact(1) から順に、戻り値が確定します。

| 呼び出し | 確定する戻り値 |
| --- | --- |
| fact(1) | 1 |
| fact(2) | 2 × 1 = 2 |
| fact(3) | 3 × 2 = 6 |

式で書くと、次の流れになります。

```text
fact(3)
→ 3 × fact(2)
→ 3 × (2 × fact(1))
→ 3 × (2 × 1)
→ 6
```

大事なのは、値が確定する順序が fact(1) → fact(2) → fact(3) だという点です。潜る向きと正反対です。科目Bでは「戻り値はいくつか」「値が確定する順序はどれか」の形で問われます。

## 3-2-3 再帰の呼び出し回数に注意

> **同じ計算を重複して行う再帰は、呼び出し回数が急激に増える**

**フィボナッチ数列**(前2つの和を並べた数列)は 1, 1, 2, 3, 5, 8, 13, … と続きます。「前2つの和」という定義は、再帰でそのまま書けます。

```text
○fib(整数型: n)
  if (n が 2 以下)
    return 1
  endif
  return fib(n − 1) + fib(n − 2)
```

fact との違いは、自分を **2回** 呼び出す点です。fib(5) の呼び出しを枝の形で書き出してみます。

- fib(5)
  - fib(4)
    - fib(3) … 1回目
      - fib(2)
      - fib(1)
    - fib(2)
  - fib(3) … 2回目
    - fib(2)
    - fib(1)

同じ fib(3) が2回、fib(2) が3回、fib(1) が2回計算されています。呼び出しは fib(5) 自身を含めて合計9回です。fib(3) の答えは1回目も2回目も同じなのに、まるごと計算し直しているのが無駄の正体です。

1回の呼び出しが2回の呼び出しを生むので、回数は倍々で膨らみます。n = 10 で109回、n = 20 では13529回に達します。計算量の視点で見ると、n が1増えるだけで手間が何倍にもなる、最悪クラスの増え方です。

科目Bでは「fib(5) の計算で fib(3) は何回呼ばれるか」のように、重複の回数を数えさせる問題が出ます。紙に呼び出しの枝を書いて数えるのが確実です。

## もっと知りたい人へ

- 潜る段階の呼び出しは、レッスン3-1で学んだスタックそのものです。呼び出しがプッシュされ、戻るときにポップされる、と考えると2段階の動きが腑に落ちます
- fib の重複は、一度計算した答えを配列に覚えておき、2回目からはそれを返す工夫で消せます。呼び出し回数は n に比例するまで減ります
- fact は for文でも書けます。同じ答えを出す書き方が複数あるとき、どちらが読みやすく、どちらが速いかを比べる目を持つと実務でも役立ちます
