# レッスン3-1 スタックとキュー

## このレッスンの目標

- [ ] スタックのプッシュ・ポップの操作列を紙で追い、取り出される値を答えられる
- [ ] スタックとキューの取り出す順の違いを説明できる
- [ ] 配列とリストの得意・苦手を挿入と参照の観点で説明できる

## 3-1-1 スタックは後入れ先出し

> **スタックは、最後に入れたデータを最初に取り出すデータ構造**

ここからは、データの入れ物そのものを学びます。**データ構造** とは、データの入れ方と取り出し方の決まりのことです。配列は値を並べて添字で参照する入れ物でしたが、出し入れの順番に決まりはありませんでした。

**スタック** は、出し入れの順番に決まりを持たせた入れ物です。入れる操作を **プッシュ**、取り出す操作を **ポップ** と呼び、ポップでは「最後に入れたデータ」が取り出されます。これを後入れ先出しと言い換えます。

洗った皿の山をイメージしてください。皿は山のいちばん上に重ね(プッシュ)、使うときもいちばん上から取ります(ポップ)。最初に置いた皿は、いちばん最後まで残ります。

操作列を1行ずつ追ってみましょう。

```text
push(1)   スタックの中: 1
push(2)   スタックの中: 1, 2
push(3)   スタックの中: 1, 2, 3
pop()     取り出される値: 3
```

プッシュを 1, 2, 3 の順に行うと、いちばん上は 3 です。ポップはいちばん上から取るので、取り出されるのは 3 になります。科目Bでは「この操作列のあとに取り出される値はいくつか」という形でよく問われます。

## 3-1-2 キューは先入れ先出し

> **キューは、最初に入れたデータを最初に取り出すデータ構造**

「届いた順に処理したい」場面ではスタックは使えません。最後に入れたものが先に出てしまい、割り込みになるからです。

**キュー** は、最初に入れたデータを最初に取り出すデータ構造です。入れる操作を **エンキュー**、取り出す操作を **デキュー** と呼びます。これを先入れ先出しと言い換えます。

キューはレジの行列です。先に並んだ人が先に会計し、あとから来た人は列の最後に付きます。

```text
enqueue(1)   キューの中: 1
enqueue(2)   キューの中: 1, 2
enqueue(3)   キューの中: 1, 2, 3
dequeue()    取り出される値: 1
```

同じ 1, 2, 3 を入れても、取り出される値はスタックと逆になります。

| 1, 2, 3 の順に入れて1回取り出す | 取り出される値 |
| --- | --- |
| スタック(ポップ) | 3 |
| キュー(デキュー) | 1 |

試験では、操作列を見て「後入れ先出しか、先入れ先出しか」をまず確認するのがコツです。

## 3-1-3 リストはポインタでつなぐ

> **リストは、各要素が次の要素の場所を指すことでつながるデータ構造**

配列には苦手なことがあります。途中に要素を入れるには、それより後ろの要素をすべて1つずつずらす必要があるのです。要素が1万個あれば、1個入れるだけで大量の移動が起きます。

**リスト** は、要素を隣に並べる代わりに、場所のメモでつなぐデータ構造です。**ポインタ** とは、次の要素の場所を指す値のことです。リストの各要素は「値」と「ポインタ」のペアを持ちます。

```text
要素A(値: 10, 次はB) → 要素B(値: 20, 次はC) → 要素C(値: 30, 次は無し)
```

先頭から、ポインタを順にたどれば全要素に到達できます。末尾の要素のポインタは「次は無し」を表す値にします。

配列と比べると、得意と苦手がちょうど逆になります。

| | 配列 | リスト |
| --- | --- | --- |
| 要素の参照 | 添字で直接参照できる | 先頭からたどる |
| 途中への挿入 | 後ろを全部ずらす | ポインタを付け替えるだけ |

AとBの間に新しい要素を入れるなら、Aのポインタを新要素へ向け、新要素のポインタをBへ向けるだけです。他の要素は動きません。参照が多いなら配列、挿入や削除が多いならリスト、と使い分けます。

## もっと知りたい人へ

- スタックとキューは、擬似言語の問題では配列と変数で作られた形で登場することがあります。「配列に入れて、どの位置から取り出しているか」を読めば、どちらの構造かを見抜けます
- リストには、前の要素を指すポインタも併せて持つ形など、いくつかの変種があります。まずは「次の要素の場所を指す値でつながる」という基本の形を確実にしてください
