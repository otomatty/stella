# レッスン3-4 文字列処理

## このレッスンの目標

- [ ] 文字列を文字型の配列として、添字で1文字ずつ処理できる
- [ ] 単純な文字列探索を、開始位置と照合の2段階でトレースできる
- [ ] 両端から添字を動かす回文判定のコードを読める

## 3-4-1 文字列は文字型の配列

> **文字列の問題は、文字型の配列とみなして1文字ずつ添字で処理する**

「文章の中の特定の文字を数える」「文書から単語を探す」という問題が科目Bに出ます。これまで配列の中身はずっと数値でしたが、文字の並びも同じ道具で処理できるのでしょうか。

できます。1文字だけを入れる型が **文字型** で、文字の並びが **文字列** です。科目Bの問題文では、文字列が文字型の配列として与えられるのが定番の形です。

```text
文字型の配列: moji ← {"E", "X", "A", "M"}
```

宣言の形は整数型の配列と同じで、中身が1文字ずつになるだけです。`mojiの要素数` は 4、つまり文字数です。`moji[1]` は "E"、`moji[4]` は "M" です。添字が1から始まるのも今までどおりです。

文字列を配列として見れば、数値の配列で学んだ道具がすべてそのまま使えます。

| 数値の配列でやったこと | 文字列では |
| --- | --- |
| for で全要素を走査する | 全文字を1文字ずつ見る |
| 値どうしを比較する | `moji[i]` が "A" と等しいか調べる |
| 一致した回数を数える | 特定の文字の出現回数を数える |

たとえば「"A" の個数を数える」は、走査と比較と数え上げの組み合わせで書けます。

```text
整数型: cnt ← 0
for (i を 1 から mojiの要素数 まで 1 ずつ増やす)
  if (moji[i] が "A" と等しい)
    cnt ← cnt + 1
  endif
endfor
```

新しい文法は1つもありません。要素が数値から文字に変わっただけです。

## 3-4-2 文字列探索は開始位置をずらして照合する

> **文字列探索は、比べ始める位置を1つずつずらしながらパターンと1文字ずつ照合する**

「文書からキーワードの出現位置を探す」のは、検索機能そのものです。M2の線形探索で探せたのは値1つでしたが、今回は「文字の並び」を探します。並びの途中まで一致して外れることもあるのが、値1つの探索との違いです。

用語を3つ押さえます。探す側の短い文字列を **パターン**、位置を合わせて1文字ずつ等しいか確かめることを **照合**、この方法での探索を **文字列探索** と呼びます。手順は「開始位置を決める → 1文字ずつ照合する → 外れたら開始位置を1つ進めてやり直す」の繰り返しです。

テキスト "ABABC" からパターン "ABC" を探してみます。

| 開始位置 | 照合の結果 |
| --- | --- |
| 1 | A=A、B=B、A≠C で外れる |
| 2 | B≠A で外れる |
| 3 | A=A、B=B、C=C **全部一致** |

開始位置1では2文字目まで一致してから外れます。この「惜しい」ケースでも、開始位置は1つだけ進めて最初から照合し直します。答えは開始位置 **3** です。

コードは二重の繰返しになります。外側が開始位置 i、内側が照合の j です。

```text
○文字列探索(文字型の配列: text, 文字型の配列: pat)
  整数型: i, j
  for (i を 1 から textの要素数 − patの要素数 + 1 まで 1 ずつ増やす)
    j ← 1
    while (j が patの要素数 以下 かつ text[i + j − 1] が pat[j] と等しい)
      j ← j + 1
    endwhile
    if (j が patの要素数 より大きい)
      return i /* 全部一致した */
    endif
  endfor
  return -1 /* 見つからない */
```

読みどころは2つあります。

- **添字の対応** — 開始位置 i でパターンの j 文字目と比べるのは、テキストの `i + j − 1` 文字目です。i = 3, j = 1 なら text[3]、j = 2 なら text[4] と、実際の数字で確かめてください。この式の穴埋めが試験の定番です
- **開始位置の上限** — 残りの長さがパターンに足りない位置から照合しても、絶対に全部一致にはなりません。だから開始位置は「textの要素数 − patの要素数 + 1」まで試せば十分です

## 3-4-3 回文判定は両端から比べる

> **回文の判定は、先頭と末尾の文字を両端から中央に向かって1組ずつ比較する**

"LEVEL" のように、逆から読んでも同じ文字列を **回文** と呼びます。回文かどうかの判定は、逆順の文字列をもう1本作って比べても書けますが、手間も置き場所も2倍かかります。コピーを作らずに、その場で判定する方法があります。

先頭の添字 i と末尾の添字 j を、両端から1つずつ中央へ動かしながら、その組を比較します。

```text
○回文判定(文字型の配列: moji)
  整数型: i ← 1
  整数型: j ← mojiの要素数
  while (i が j より小さい)
    if (moji[i] が moji[j] と等しくない)
      return false
    endif
    i ← i + 1
    j ← j − 1
  endwhile
  return true
```

戻り値は論理型で、真を true、偽を false と書きます。途中で異なる組が見つかったら、その場で `return false` と確定します。while の条件が「i < j」なので、2つの添字が中央で出会ったら比較は終わりです。"LEVEL"(5文字)でトレースしてみます。

| i | j | moji[i] | moji[j] | 結果 |
| --- | --- | --- | --- | --- |
| 1 | 5 | L | L | 等しい |
| 2 | 4 | E | E | 等しい |
| 3 | 3 | — | — | i < j でないので終了 |

不一致なしで while を抜けたので、戻り値は **true**(回文である)です。奇数文字のときは中央の1文字("LEVEL" の V)が比較されずに残りますが、1文字は必ず自分自身と同じなので判定に影響しません。

添字を2つ同時に逆向きに動かすこの型は、回文以外の問題(配列の逆順への並べ替えなど)でも使われる、科目B頻出の読み筋です。

## もっと知りたい人へ

- 今回の文字列探索は、外れるたびに開始位置を1つだけ戻る最も素朴な方法で、力まかせ法(総当たり法)と呼ばれます。テキストが長くなると照合のやり直しが増えるため、照合済みの情報を活かして開始位置を大きく進める改良アルゴリズム(KMP法・BM法)が考案されています
- 文字はコンピュータの中では文字コードという番号で表されます。文字どうしの比較は、実際にはこの番号の比較です。"A" < "B" のような大小比較で辞書順の並べ替えができるのも、番号の大小を使っているからです
- 実務のプログラミング言語では、文字列の連結・切り出し・置換などが標準機能として用意されています。ただしその内部では、このレッスンで読んだような1文字ずつの処理が動いています
