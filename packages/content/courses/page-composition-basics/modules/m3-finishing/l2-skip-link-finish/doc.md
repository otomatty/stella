# レッスン3-2 skip linkと仕上げ

## このレッスンの目標

- [ ] skip link を置き、最初のフォーカスから `main` へ飛べるようにできる
- [ ] 幅 1 本の `@media` で、狭い画面向けの直しをまとめられる
- [ ] landmark・タブの一巡・トークンの 3 点検でページを完成にできる

## 3-2-1 skip linkでmainへ飛ばす

> **ページの最初にmainへ飛ぶリンクを置くと、キーボードの利用者がナビの繰り返しを飛ばせる**

ページに足す最後の 1 部品です。キーボードでは Tab キーを押すたびに、押せる要素へ先頭から順に **フォーカス**(いま操作が当たる場所)が移ります。このページで本文の最初のリンクへ着くには、毎回スプリットナビのリンクを全部通ることになります。1 ページなら我慢できても、ページを移るたびに同じ回り道が繰り返されます。

そこで、ページの最初に「本文へ飛ぶ」リンクを置きます。これを **skip link** と呼びます。

```html
<header>
  <a class="skip-link" href="#content">本文へ飛ぶ</a>
  <div class="wrapper">…ナビ…</div>
</header>

<main id="content">…</main>
```

- 行き先は `main` に付けた `id`。`href="#content"` のページ内リンクの形です
- 置き場所は文書の先頭近く、`header` の最初の子。**Tab の 1 回目でフォーカスが乗る**位置です

動きを確かめると、次のようになります。

1. ページを開いて Tab を 1 回 → skip link にフォーカスが乗る
2. Enter → フォーカスの続きが `main` の中になる
3. ナビのリンクを 1 度も通らずに本文へ着く

リンク 1 つで、キーボードの利用者の毎ページの Tab 連打が消えます。マウスの利用者には(次のトピックで隠すので)何も変わりません。

## 3-2-2 skip linkは普段は隠す

> **skip linkは画面の外に置いておき、フォーカスされたときだけ見える位置に戻す**

「本文へ飛ぶ」がヘッダに常に見えているのは、マウスの利用者には邪魔です。隠したくなりますが、隠し方を間違えると部品ごと消えます。`display: none` は **存在ごと消す**指定なので、Tab でも止まれなくなり、skip link の意味が無くなります。

正しい隠し方は、消すのではなく **画面の外へ動かす**ことです。見えないだけで存在は残るので、Tab の順番には入ったままです。

```css
.skip-link {
  position: absolute;
  inset-block-start: -100%;
  background-color: var(--accent);
  color: var(--surface);
  padding: var(--space-2) var(--space-3);

  &:focus-visible {
    inset-block-start: 0;
  }
}
```

- 普段は `position: absolute` と `inset-block-start: -100%` で画面の上の外に置く
- フォーカスが当たったら(`:focus-visible`)、`0` に戻して画面内に出す

キーボードで Tab を押した瞬間だけ、画面の左上にリンクが現れる——実在のサイトでもよく見る動きです。「見えない」と「無い」は別もの、というのがこのトピックの覚えどころです。`dialog` は閉じている状態をブラウザーが管理してくれましたが、skip link は自前で隠すぶん、隠し方の選択が問われます。

## 3-2-3 狭い幅は@media 1本で整える

> **狭い画面向けの直しは、幅1本の@mediaにまとめて書くだけに留める**

仕上げの前に、狭い画面での見え方を確かめます。ブラウザーの幅を縮めていくと、直しが要る場所と要らない場所に分かれるはずです。

まず、**直さなくてよい場所**から確認します。

- カードの列数 … `repeat(auto-fill, minmax())` が 1 列まで畳んでくれる
- wrapper の左右 … `padding-inline` が端の逃げになっている
- フォームの幅 … `max-inline-size` は上限の指定なので、狭い幅ではそもそも効いていない

ここまでの作り方が正しければ、残るのはスプリットナビくらいです。横並びのまま狭い幅に入ると窮屈になるので、縦積みに切り替えます。HTML/CSS 入門で覚えた **メディアクエリー** を `@media` の構文で 1 本だけ書きます。

```css
@media (max-width: 600px) {
  .site-nav ul {
    flex-direction: column;
    align-items: flex-start;

    .login {
      margin-inline-start: 0;
    }
  }
}
```

- 境の幅は 1 つだけ決める(ここでは 600px)
- 縦積みでは「ログインを右端へ」の `auto` マージンが意味を失うので、あわせて解除する

複数のブレークポイントを持つ本格的なレスポンシブ設計は、この講座の対象外です。逆に言うと、幅 1 本で足りるのは、カードや wrapper が幅に追従する作りになっているからです。`@media` に書く量の少なさが、ここまでの作りの答え合わせになります。

## 3-2-4 仕上げは骨格の点検で終える

> **仕上げに、landmarkの数・タブでの一巡・トークンが1セットかを点検して完成にする**

最後は完成の判定です。見た目が整っていても、作りの崩れは画面に出ません。直置きの内容や 2 つ目の `:root` は、開発の途中であとから混ざりやすいものです。そこで「完成」を感覚ではなく、3 項目の **点検** で判定します。

1. **landmark の点検** … `main` は 1 つか。`header` / `main` / `footer` の外に直置きの内容が無いか。`nav` が複数あるなら `aria-label` が付いているか
2. **タブでの一巡** … ページを開いて Tab だけで操作する。skip link から本文へ飛べるか。ナビ・カードのリンク・フォーム・ダイアログのボタンまで止まれるか。フォーカスの枠がどの要素でも見えるか
3. **トークンの点検** … `:root` は先頭の 1 セットだけか。部品の CSS に生の値が紛れていないか

新しい知識は 1 つもありません。この講座で決めた原則が守れているかを、手順として確かめるだけです。点検で見つかったときの直し方も、すべて既習です。

- 直置きの内容 → 1-1-3 の 3 択でどれかの landmark へ入れる
- 止まれない部品・見えない枠 → `:focus-visible` を当て直す
- 2 つ目の `:root` → 先頭の 1 セットへ統合する

3 つの点検が通ったら、このページは完成です。部品を 4 段階で作る前講座と、部品を 1 枚に組むこの講座で、静的なページを 1 から仕上げる道具がそろいました。
