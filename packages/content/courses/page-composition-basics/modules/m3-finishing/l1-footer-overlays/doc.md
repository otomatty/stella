# レッスン3-1 フッタとオーバーレイ

## このレッスンの目標

- [ ] 本文が短いページでも、フッタを画面の下端に付けられる
- [ ] `min-height: 100svh` と `grid` の `1fr` の役割分担を説明できる
- [ ] 既習のポップオーバーとダイアログを、ページに 1 つずつ載せられる

## 3-1-1 bodyを画面の高さまで伸ばす

> **本文が短いページでは、まずbodyをmin-height: 100svhで画面の高さまで伸ばす**

ページの下端を仕上げます。いまのページは本文が十分あるので気づきにくいのですが、本文が短いページ(検索結果が 0 件、エラーページなど)では、フッタが画面の途中に浮き、その下に何もない空白が広がります。試しに `main` の区画を 1 つ残して消してみると再現できます。

原因は、`body` の高さが既定では **中身のぶんだけ**しかないことです。フッタは `body` の最後に置かれているだけなので、中身が短ければ途中で終わります。フッタを下端へ動かす前に、まず動かす余地——画面の高さとの「余り」——を作ります。

```css
body {
  min-height: 100svh;
}
```

- `svh` は画面の高さの 1%(スマートフォンでアドレスバーが出ている、**小さい方**の画面基準)。`100svh` で画面 1 枚ぶんの高さです
- `height` ではなく `min-height` なのは、本文が長いページでは今までどおり中身なりに伸びてほしいからです。固定してしまうと長いページがあふれます

`vh` でも近いことはできますが、スマートフォンではアドレスバーのぶん `100vh` が画面からはみ出すことがあります。「確実に収まる方」の `svh` を使います。その代わり、アドレスバーが引っ込んで表示領域が広がった間は、フッタの下に少し空きが残ることがあります。いまの表示領域に常に追従する `dvh` という単位もありますが、スクロールのたびに高さが動いて画面が跳ねるので、この講座では安定を優先して `svh` を選びます。

ここまでやっても、**フッタはまだ浮いたままです**。`body` は伸びましたが、その中の `header` / `main` / `footer` は中身のぶんのままだからです。伸びた高さの配り方は次のトピックで決めます。

## 3-1-2 余った高さはmainの1frに渡す

> **bodyを縦のgridにしてmainの行を1frにすると、余った高さをmainが受け取りfooterが下端に付く**

余りはできたので、あとは **誰に渡すか** を決めるだけです。渡す相手は本文の `main` です。ヘッダとフッタは中身のぶんの高さのまま、余りをすべて `main` が受け取れば、`footer` は自然に画面の下端へ押し出されます。

`body` の直下は骨格の 3 要素だけなので、行が 3 つの縦のグリッドがそのまま使えます。

```css
body {
  min-height: 100svh;
  display: grid;
  grid-template-rows: auto 1fr auto;
}
```

- `grid-template-rows: auto 1fr auto` … 行は上から `header` / `main` / `footer`。`auto` は中身のぶんの高さ
- `fr` は **余りを配る単位**です。カードの列で `minmax(220px, 1fr)` と書いたものの行版で、`1fr` の行が余りを全部受け取ります

本文が短いページでは `main` が余りのぶん高くなってフッタが下端に付き、本文が長いページでは余りが 0 になるだけで、今までどおり下へ伸びます。どちらのページでも同じ CSS で成立するのが、このレシピの価値です。

`footer { margin-block-start: auto; }` で押し下げるやり方もありますが、レシピとして覚えるのはグリッド版にしてください。骨格 3 行の定義に「どの行が余りを受けるか」という意図がそのまま残るので、あとから読んだ人に伝わります。

なお、1-2-2 で `header` に当てた帯の背景はそのまま効きます。グリッドにしたのは並べ方だけで、各 landmark の中身と見た目には触れていません。

## 3-1-3 popoverはページに1つ載せる

> **作ってあるポップオーバーは、開くボタンごとheaderに置いてページに1つ載せる**

次に、重ねて出す部品を載せます。1 つ目は **ポップオーバー**(最前面に重ねて出る小さな面)です。「使い方のヒント」をページ遷移せずにその場で見せる用途で、部品は部品講座で作ってあります。

決めるのは置き場所と数です。ポップオーバーはボタンと面がセットなので、**置き場所はボタンで決めます**。使い方のヒントはどの区画の話でもなくページ全体の補足なので、ボタンは `header` に置き、面もそのそばに書きます。

```html
<header>
  <div class="wrapper">
    <nav class="site-nav" aria-label="メイン">…</nav>
    <button popovertarget="help">使い方</button>
    <div id="help" popover>
      <p>勉強会カードの「詳細を見る」から申し込めます。</p>
    </div>
  </div>
</header>
```

数は **1 枚のページに 1 つ**に留めます。技術的にはいくつでも置けますが、最前面は 1 枚しかありません。あちこちのボタンから面が飛び出すページは、いまどこを操作しているのかを見失わせます。2 つ目が欲しくなったら、その内容を本文の区画として置けないかを先に考えてください。

> **この機能は比較的新しく、古いブラウザーでは動きません。** 部品講座と同じく、動かない環境では書いた結果の確認までに留め、フォールバックの JavaScript は書きません。

## 3-1-4 dialogはページに1つ載せる

> **作ってあるダイアログは、開くボタンと同じ区画に置いてモーダルで開く**

重ねて出す部品の 2 つ目は **ダイアログ**です。申し込みの前にキャンセルの決まりを確認してもらいたい、という場面で使います。ページ遷移させると入力の途中が消えるので、その場で **モーダル**(背面を止めて前面に集中させる開き方)で出します。

ダイアログは開くボタンと `dialog` 本体を **同じ区画に**置きます。閉じている `dialog` は表示されないので、区画の途中に書いても見た目は崩れません。HTML 上でボタンのすぐそばにあれば、どのボタンがどの面を開くのかが読んで分かります。

```html
<section>
  <h2>参加申し込み</h2>
  <button command="show-modal" commandfor="policy">
    キャンセルの決まりを見る
  </button>
  <dialog id="policy" aria-labelledby="policy-title">
    <h3 id="policy-title">キャンセルの決まり</h3>
    <p>開催2日前まではキャンセルできます。それ以降は運営までご連絡ください。</p>
    <button command="close" commandfor="policy">閉じる</button>
  </dialog>
  <form class="signup">…</form>
</section>
```

部品講座で付けた **ダイアログの名前の配線**(見出しの `id` を `aria-labelledby` で指す)は、ページに載せるときも落とさないでください。この配線が無いと、読み上げでは「ダイアログ」としか言われず、何の窓が開いたのか分かりません。ページに組み込んだので、見出しの階層も区画の `h2` に続く `h3` にそろえています。

ポップオーバーとの使い分けも、置いてみると輪郭がはっきりします。

- ちら見のヒント → ポップオーバー。背面はそのまま使える
- 読んでから進んでほしい決まり → モーダルのダイアログ。背面を止める
- どちらも 1 枚のページに **1 つずつ**に留める

迷ったら「背面を触られて困るか」で選んでください。困るならモーダルです。

> **`command` / `commandfor` も比較的新しい機能です。** 動かない環境では書いた結果の確認までに留めます。
