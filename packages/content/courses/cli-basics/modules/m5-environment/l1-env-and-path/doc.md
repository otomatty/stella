# レッスン5-1 環境変数とPATH

## このレッスンの目標

- [ ] 環境変数が何のためにあるかを説明できる
- [ ] `echo $名前` で値を確認できる
- [ ] `command not found` の原因を PATH の観点で説明できる

## 5-1-1 環境変数はシェルが覚えている値

> **環境変数は、シェルが覚えていて、実行するコマンドにも引き継がれる名前つきの値**

接続先のURLやAPIキーを、プログラムの中に直接書きたくない場面があります。環境ごとに値が違いますし、秘密の値をソースコードに残すのは避けたいからです。

**環境変数** は、シェルが持っている名前と値の組です。名前は大文字で書くのが慣習です。

```text
[シェル]  HOME=/Users/sato  LANG=ja_JP.UTF-8  PATH=...
    │
    │ コマンドを実行するとき、この値ごと渡す
    ▼
[コマンド]  受け取った値を見て動きを変える
```

普通の変数と違うのは、**実行するコマンドにも引き継がれる** ことです。だからプログラムの中に書かなくても、外から値を渡せます。設定を外に出すこの考え方は、この先のNode.jsやDockerの研修にもそのまま続きます。

## 5-1-2 echoで環境変数の中身を見る

> **echo $名前 と打つと、その環境変数の中身が表示される**

「環境変数を設定した」はずなのにプログラムが古い値で動く、ということがあります。切り分けの第一歩は、いま何が入っているかを見ることです。

```bash
echo $HOME
# => /Users/sato

echo HOME       # $ を付け忘れると、ただの文字として出る
# => HOME

export API_URL="https://example.com"   # このシェルに設定する
echo $API_URL
```

**echo** は、受け取った文字をそのまま標準出力に出すコマンドです。名前の前に `$` を付けると、シェルが **名前を値に置き換えてから** `echo` に渡します。レッスン3-1の `*` と同じで、ここでもシェルがコマンドの手前で仕事をしています。

`$` の付け忘れは誰もが一度はやります。`HOME` とそのまま表示されたら、`$` が抜けているサインです。

設定するときは **export** を使います。ただし `export` で設定した値は、そのターミナルを閉じると消えます。ずっと使いたい設定はシェルの設定ファイル(`~/.zshrc` など)に書きますが、この研修では扱いません。

## 5-1-3 PATHはコマンドを探す場所の一覧

> **シェルは環境変数PATHに並んだディレクトリを順に見て、打たれたコマンドを探す**

ツールをインストールしたのに `command not found`(そのコマンドは見つかりません)と言われることがあります。ファイルは確かにあるのに、なぜ見つからないのでしょうか。

答えは **PATH** にあります。PATH は、コマンドを探すディレクトリを `:` で区切って並べた環境変数です。

```bash
echo $PATH
# => /usr/local/bin:/usr/bin:/bin

# ls と打ったとき、シェルは順に見る
#   /usr/local/bin/ls  … 無い
#   /usr/bin/ls        … あった → これを実行
```

ここで大事なのは、**コマンド名は魔法の言葉ではなく、ファイルの名前だ** ということです。`ls` は `/bin/ls` という実体のあるファイルで、シェルはそれをPATHの順に探しています。

一覧のどこにも見つからなければ `command not found` になります。つまりこのエラーは「入っていない」とは限らず、「入れた場所がPATHに無い」ことも意味します。

## 5-1-4 whichでどれが実行されるか確かめる

> **whichは、そのコマンド名で実際に実行されるファイルの場所を教えてくれる**

新しいバージョンを入れたのに古いバージョンが動いている、ということがあります。同じ名前のコマンドが複数の場所に入っていて、PATHの並び順で先に見つかった方が使われているためです。

```bash
which ls
# => /bin/ls

which node
# => /usr/local/bin/node      ← このファイルが動いている

which nosuchcmd
# => (何も出ない。PATH のどこにも無い)
```

**which** は、PATHを上から探して最初に見つかった場所を返します。「いま自分が打っているコマンドの正体はどのファイルか」を突き止める道具です。

何も表示されなければ、そのコマンドはPATHのどこにも無いということです。`command not found` と同じ状態を、エラーになる前に確認できます。再インストールを繰り返す前に、まず `which` と `echo $PATH` を見る、という順番を覚えてください。
