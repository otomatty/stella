## なぜ必要か

- 10万行のログから、エラーが出た行だけを見つけたい
- 目で追うのは現実的ではないし、見落とす

<!-- ノート: つかみ。1-2で学んだ tail や less では、量が増えると追いつきません。 -->

## 結論

**grepは、ファイルの中から指定した文字列を含む行だけを取り出す**

- **grep** — 探したい文字列と、探す先のファイルを引数に取る

<!-- ノート: 結論を先に言い切ります。行単位で取り出す道具だという点が肝心です。 -->

---

## 探す文字列が先、ファイルが後

```bash
grep error app.log
# => 2026-04-12 10:03 error: timeout
# => 2026-04-12 10:05 error: connection refused
```

- 一致した行が **そのまま** 出る。行番号や件数はオプションで足せる
- 何も出なければ「一致が無かった」ということ
- ただしシェルには「失敗」と伝わる(終了ステータス 1)。`&&` でつなぐときに効く

<!-- ノート: 出力が空であることも結果の1つだと伝えます。人にとってはエラーではありませんが、シェルにとっては失敗の合図です。M6 の && でつまずく原因になるので、ここで一度触れておきます。 -->
