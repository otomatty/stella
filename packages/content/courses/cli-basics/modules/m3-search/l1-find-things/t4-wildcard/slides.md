# 3-1-4
# 「*」を展開しているのはシェル

コマンドライン入門 — Module 3 / レッスン3-1

<!-- ノート: 「*」をコマンドの機能だと思っていると、find の引数を引用符で囲む理由が分かりません。 -->

---

## なぜ必要か

- `ls *.log` は動くのに、`find . -name *.log` は思ったとおりに動かないことがある
- 同じ「*」なのに結果が違う理由が分からない

<!-- ノート: つかみ。実際に踏む落とし穴を先に見せます。ここで理由は言いません。 -->

---

## 結論

**「*」は、コマンドに渡る前にシェルがファイル名の一覧へ置き換えている**

- **ワイルドカード** — 任意の文字列を表す `*` などの記号
- **展開** — シェルが記号を実際の名前に置き換えること

<!-- ノート: 結論を先に言い切ります。コマンドは展開後の結果しか受け取らない、が核心です。 -->

---

## コマンドが受け取るのは展開後

```bash
# ディレクトリに app.log と db.log がある場合

ls *.log
# シェルが置き換えてから ls が動く → ls app.log db.log

find . -name "*.log"
# 引用符で囲むと展開されず、find 自身が「*.log」として扱う
```

- `find` の条件は引用符で囲む、と覚えておくと事故が減る

<!-- ノート: 引用符はシェルに「展開せずそのまま渡せ」と伝える印です。理由まで言えると応用が効きます。 -->
