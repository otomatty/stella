# レッスン3-1 ファイルと中身を探す

## このレッスンの目標

- [ ] `grep` でファイルの中身から該当行を取り出せる
- [ ] `find` でファイル名からファイルを探せる
- [ ] `*` を展開しているのがシェルであることを説明できる

## 3-1-1 grepで中身の文字列を探す

> **grepは、ファイルの中から指定した文字列を含む行だけを取り出す**

10万行のログから、エラーが出た行だけを見つけたい。目で追うのは現実的ではありませんし、見落とします。レッスン1-2で学んだ `tail` や `less` も、量が増えると追いつきません。

```bash
grep error app.log
# => 2026-04-12 10:03 error: timeout
# => 2026-04-12 10:05 error: connection refused
```

**grep** は、探したい文字列を先に、探す先のファイルを後に書きます。一致した行がそのまま表示されます。

出力が空でも、それはエラーではありません。「一致する行が無かった」という結果です。ログ調査では「エラーが1行も無い」ことの確認にも使えます。

ただし1つ注意があります。`grep` は**一致した行が1つも無いと「失敗」の合図(終了ステータス 1)を残します**。画面には何も出ないので気づきにくいのですが、レッスン6-2で出てくる `&&` はこの合図を見ているため、`grep error app.log && echo "ログを送る"` と書くと、エラーが無かったときに右側が実行されません。**「何も出なかった」と「コマンドが成功した」は別物**だと覚えておいてください。

## 3-1-2 grepのよく使う3つのオプション

> **-i で大文字小文字を無視し、-n で行番号を出し、-r でディレクトリ全体を探せる**

`grep error` では `ERROR` と書かれた行が見つかりません。また、見つけた行が何行目かが分からないと、直しに行けません。`grep` は多機能ですが、実務で使うのはほぼ次の3つです。

```bash
grep -i error app.log       # ERROR も Error も拾う
grep -n error app.log       # => 42:2026-04-12 10:03 error: timeout
grep -r error logs/         # logs 配下のファイルを全部探す
grep -rn error logs/        # 重ねて指定できる
```

- `-i` — ignore case(大文字小文字を区別しない)
- `-n` — number(行番号を付ける)
- `-r` — recursive(**再帰的**、ディレクトリの中のそのまた中までたどる)

`-rn` の組み合わせが最頻出です。「どのファイルの何行目か」が同時に分かるので、そのままエディタで開きに行けます。

## 3-1-3 findで名前からファイルを探す

> **findは、指定したディレクトリの下から、名前の条件に合うファイルを探す**

「どこかにあるはずの設定ファイル」の置き場所が思い出せないことがあります。中身は分かりませんが、名前の一部は覚えている。これは `grep` では解けない探し物です。

```bash
find . -name "config.json"     # いまいる場所の下から探す
find . -name "*.log"           # 拡張子で探す
find logs -type f              # logs 配下のファイルだけ一覧する
```

**find** は、**探す場所を先に**、条件を後に書きます。`grep`(文字列が先)と順番が逆なので、慣れるまで取り違えやすい点に注意してください。

覚え方は「grep は中身、find は名前」です。見つかったものはパス付きで表示されるので、そのまま `cat` や `less` に渡せます。

## 3-1-4 「*」を展開しているのはシェル

> **「*」は、コマンドに渡る前にシェルがファイル名の一覧へ置き換えている**

`ls *.log` は思ったとおりに動くのに、`find . -name *.log` は動かないことがあります。同じ `*` なのに結果が違うのはなぜでしょうか。

`*` のような、任意の文字列を表す記号を **ワイルドカード** と呼びます。そして重要なのは、この記号を処理しているのは **コマンドではなくシェル** だということです。シェルが記号を実際のファイル名に置き換えることを **展開** と呼びます。

```bash
# ディレクトリに app.log と db.log がある場合

ls *.log
# シェルが置き換えてから ls が動く → ls app.log db.log

find . -name "*.log"
# 引用符で囲むと展開されず、find 自身が「*.log」として扱う
```

`ls` の場合は、展開された名前の一覧をそのまま受け取れば目的を果たせます。しかし `find` は「`*.log` という条件」を自分で解釈したいコマンドなので、シェルに先回りされると困ります。だから条件を引用符で囲み、「展開せずそのまま渡せ」と伝えます。

**`find` の `-name` の条件は引用符で囲む**、と覚えておけば事故を防げます。シェルがコマンドの手前で仕事をしているという見方は、次のモジュール(パイプとリダイレクト)にもつながります。
