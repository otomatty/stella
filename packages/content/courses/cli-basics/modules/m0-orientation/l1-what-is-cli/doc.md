# レッスン0-1 コマンドラインとは何か

## このレッスンの目標

- [ ] GUIとコマンドラインの頼み方の違いを説明できる
- [ ] ターミナル・シェル・コマンドの関係を説明できる
- [ ] コマンドを「コマンド名・オプション・引数」に切り分けて読める

## 0-1-1 コマンドラインは名前で頼む道具

> **GUI は画面から探して押す、コマンドラインは道具の名前を打って頼む**

ファイルのコピーも、サーバーの様子を見るのも、ここまでは画面のボタンで済ませてきたはずです。開発の現場に入ると、そこに黒い画面が現れます。

**GUI** は、アイコンやボタンを目で探して操作する画面のことです。いっぽう **コマンドライン** は、やってほしいことの名前を文字で打って頼むやり方です。どちらが優れているという話ではなく、頼み方が違います。

同じ「ファイルをコピーする」を並べると違いがはっきりします。

```text
GUI          : フォルダを開く → ファイルを探す → 右クリック
               → コピー → 移動先を開く → 貼り付け

コマンドライン: cp report.csv backup/
```

手順の数が違いますが、本当の差は別のところにあります。コマンドラインの操作は **文字として残せる** ことです。同じ1行を明日も来月も貼り付ければ、まったく同じ操作が再現できます。手順書に書けますし、後の研修で学ぶように、ファイルにまとめて自動実行させることもできます。

## 0-1-2 ターミナルとシェルは役割が違う

> **ターミナルは文字をやり取りする窓、シェルは打った文字をコマンドとして解釈する係**

現場の手順書には「ターミナルを開いて」「シェルで実行して」「bashで叩いて」という表現が混ざって出てきます。3つは同じものの言い換えではありません。

- **ターミナル** — 文字を表示し、キー入力を受け取るアプリ(窓)
- **シェル** — 受け取った文字を読んで、コマンドを実行するプログラム(中の人)

窓と中の人、と考えると関係がつかめます。

```text
[ターミナル]  Terminal.app / Windows Terminal / VS Codeの統合ターミナル
     ↕ 文字
[シェル]      bash / zsh
     ↕ 実行
[コマンド]    ls / cp / grep ...
```

**bash** と **zsh** は代表的なシェルです。macOSの標準は zsh、Linuxのサーバーでは bash が多く使われています。この研修で扱う範囲は、どちらのシェルでも同じように動きます。

ターミナル(窓)を替えても、打つコマンドは変わりません。VS Codeの中でターミナルを開いても、独立したターミナルアプリを開いても、同じコマンドが同じように動きます。

## 0-1-3 プロンプトは入力待ちの合図

> **プロンプトが出ているときだけ、シェルは次のコマンドを待っている**

コマンドを打っても画面が反応しないとき、固まったのか動いている途中なのかが分からず、Enterを連打してしまう事故がよく起きます。判断の材料になるのが **プロンプト** です。

プロンプトは、入力を待っていることを示す記号です。多くの環境で `$` や `%` が使われます。

```text
user@mac ~ $                 ← プロンプトあり。打ってよい

user@mac ~ $ sleep 10        ← 実行中。プロンプトが戻っていない
                                (ここで打った文字は、終わるまで届かない)
user@mac ~ $                 ← 戻ってきた。次を打ってよい
```

`sleep 10` は10秒待つだけのコマンドです。実行するとプロンプトが消え、10秒後に戻ってきます。この「消えている間は動いている」という読み方が身につくと、固まったのかどうかで悩まなくなります。

プロンプトの左側にはユーザー名や現在の場所が表示されます。表示の形は環境ごとに違ってよく、大事なのは「記号が出ているかどうか」です。

## 0-1-4 コマンドは3つの部品でできている

> **コマンドは「コマンド名・オプション・引数」の3つの部品でできている**

手順書のコマンドを、意味の切れ目が分からないまま写している状態では、自分の環境に合わせて直すことができません。切れ目には決まった型があります。

- **コマンド名** — 何をする道具か
- **オプション** — どう動かすか(`-` で始まる)
- **引数** — 何に対して行うか

3つは半角スペースで区切ります。

```bash
ls -l /var/log
# └┬ └┬ └────┬──
#  │  │      └ 引数    : /var/log を対象にする
#  │  └ オプション     : 詳しい形式で表示する
#  └ コマンド名        : 一覧する道具
```

この型が読めると、`ls -l /var/log` の `/var/log` を自分の見たい場所に差し替えられます。オプションを外せば表示だけが変わり、対象は変わりません。これから出てくるコマンドはすべてこの形なので、暗記する量は思ったより少なくて済みます。

## 0-1-5 打ち間違いはTabと上キーで減らす

> **Tabキーで名前を補完し、上キーで前に打ったコマンドを呼び戻せる**

長いファイル名を手で打つと、1文字違いで `No such file or directory`(そんなファイルはありません)と返されます。シェルには、これを減らす仕掛けが2つあります。

**タブ補完** は、途中まで打ってTabキーを押すと、続きをシェルが埋めてくれる機能です。

```text
$ cat rep⇥            → cat report-2026-04.csv   (候補が1つなら埋まる)

$ cat re⇥⇥            → report-2026-04.csv  results.txt
                        (候補が複数なら一覧が出る。もう1文字足してTab)
```

補完が効いたということは、その名前のファイルが実在するという確認にもなります。補完されないときは、名前が違うか、いま見ている場所にそのファイルが無いということです。

**コマンド履歴** は、上キーで前に実行したコマンドを呼び戻す機能です。長いコマンドを打ち直す必要はありません。呼び戻してから一部だけ直して実行する、という使い方が現場では普通です。

この2つを最初から使う癖をつけると、以降の研修が目に見えて楽になります。
