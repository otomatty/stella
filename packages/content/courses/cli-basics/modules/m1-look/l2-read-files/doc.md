# レッスン1-2 ファイルの中身を見る

## このレッスンの目標

- [ ] `cat` でファイルの中身を表示できる
- [ ] `head` / `tail` で長いファイルの端だけを取り出せる
- [ ] `less` で開いて読み、`q` で抜けられる

## 1-2-1 catでファイルを丸ごと表示する

> **catは、指定したファイルの中身をそのまま画面に出す**

設定ファイルを1行だけ確かめたいときに、エディタを立ち上げるのは重い作業です。うっかり書き換えてしまう危険もあります。読むだけなら、読むための道具を使います。

```bash
cat memo.txt
# => ファイルの中身がそのまま表示される
```

**cat** はファイルの中身を表示するコマンドです。書き換えは行わないので、本番環境の設定を確認するときも安全に使えます。

引数にはパスを書きます。`cat ~/memo.txt` のように、離れた場所のファイルも移動せずに読めます。ファイルが無ければ `No such file or directory` が返ります。名前の打ち間違いが多いので、Tabキーの補完を使ってください。

## 1-2-2 長いファイルは端だけ見る

> **headは先頭から、tailは末尾から、指定した行数だけを取り出す**

10万行のログを `cat` すると、画面が一気に流れて何も読めません。知りたいのは、たいてい「いちばん新しい数行」です。

```bash
head app.log          # 先頭10行
tail app.log          # 末尾10行
tail -n 3 app.log     # 末尾3行だけ
```

- **head** — 先頭から。行数を指定しなければ10行
- **tail** — 末尾から。行数を指定しなければ10行

`-n` の n は number(行数)です。ログは新しい記録が末尾に追加されていくので、障害調査ではまず `tail` で直近を見るのが定石になっています。

## 1-2-3 lessでスクロールして読む

> **lessはファイルを画面に収めて開き、スクロールしながら読める**

エラーの前後を読みたいときは、先頭でも末尾でもなく途中が知りたい場面です。`cat` では流れてしまい、`head` や `tail` では届きません。

**ページャー** は、ファイルを1画面ずつ表示する道具のことです。**less** はその代表です。

```bash
less app.log
```

開いたあとは、キーで操作します。

```text
↓ / ↑     1行ずつ動く
スペース   1画面進む
/error    「error」を検索する(n で次へ)
q         終了してプロンプトに戻る
```

初心者が必ず詰まるのが終了方法です。**`q` で抜ける** ことだけは覚えてください。`less` も読み取り専用なので、開いてもファイルは変わりません。

## 1-2-4 wcで行数を数える

> **wcはファイルの行数・単語数・文字数を数える**

取り込んだCSVが何件あるかを目で数えるわけにはいきません。件数で言えると、報告や確認がぶれなくなります。

```bash
wc users.csv
# =>   120     360    5400 users.csv
#     行数    単語数  文字数

wc -l users.csv
# => 120 users.csv
```

**wc** は word count の略です。名前は単語数ですが、実務でよく使うのは `-l`(行数)です。数えるだけで、ファイルの中身は変わりません。

1つ注意があります。CSVに見出し行があるときは、データの件数は行数から1を引いた数になります。「120行だから120件」と報告して食い違う、という誤りは実際によく起きます。
