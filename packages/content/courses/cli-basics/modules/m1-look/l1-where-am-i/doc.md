# レッスン1-1 いまいる場所と移動

## このレッスンの目標

- [ ] カレントディレクトリを確かめ、中身を一覧できる
- [ ] 絶対パスと相対パスを見分けられる
- [ ] `.` `..` `~` を使って場所を短く書ける

## 1-1-1 いまいる場所はpwdで分かる

> **シェルには「いまいるディレクトリ」があり、pwdで確かめられる**

手順書どおりに打ったのに `No such file or directory`(そんなファイルやディレクトリはありません)と返ってくることがあります。原因の多くは、ファイルが無いことではなく、自分が別の場所にいることです。

コマンドラインでは、フォルダのことを **ディレクトリ** と呼びます。そしてシェルは常に、作業の基準にしている場所を1つ持っています。これが **カレントディレクトリ** です。GUIで「いま開いているフォルダ」に当たるものが、画面に出ないまま存在していると考えてください。

```bash
pwd
# => /Users/sato/projects
```

`pwd` は print working directory の略です。困ったらまずこれを打つ、と覚えておくと事故が減ります。これから学ぶコマンドは、指定がなければすべてこの場所を基準に動きます。

## 1-1-2 lsで中にあるものを一覧する

> **lsはカレントディレクトリの中にあるものを一覧する**

場所が分かっても、その中に何があるかは画面に出ていません。GUIならウィンドウを開けば見えますが、コマンドラインでは自分から尋ねます。

```bash
ls          # 名前だけを並べる
ls -l       # 1行1件。サイズや更新日時も出る
ls -a       # 「.」で始まる隠しファイルも出す
ls -la      # 2つを同時に指定できる
```

`ls` は list の略です。引数を付けなければカレントディレクトリが対象になり、`ls projects` のように引数を付ければ、その中身を(移動せずに)見られます。

`.` で始まる名前のファイルを **隠しファイル** と呼びます。`ls` では表示されず、`-a` を付けたときだけ出てきます。設定ファイルの多くがこの形です(`.gitignore` など)。「あるはずのファイルが見えない」ときは、まず `-a` を試してください。

`ls -la` のように、オプションはまとめて書けます。これは `ls` に限らず、多くのコマンドで共通の書き方です。

## 1-1-3 cdでカレントディレクトリを移す

> **cdはカレントディレクトリを、指定した場所に移す**

作業したいファイルは、たいてい別のディレクトリにあります。遠くのファイルを毎回長い名前で指定するより、その場所へ移ってから作業する方が短く済み、打ち間違いも減ります。

```bash
cd projects     # projects の中へ移る(何も表示されない)
pwd             # => /Users/sato/projects
ls              # 移った先の中身を見る
```

`cd` は change directory の略です。成功したときは何も表示されません。これはコマンドラインの流儀で、**無言は成功のしるし** です。逆に、存在しない場所を指定したときだけエラーが出ます。

不安なときは `cd` のあとに `pwd` を打って確かめてください。慣れるまでは、この2つをセットで使うことをおすすめします。

## 1-1-4 絶対パスと相対パスの違い

> **絶対パスは / から書いた道順、相対パスはいまいる場所からの道順**

同僚に教わったコマンドを貼り付けたら自分の環境では動かなかった、ということがよく起きます。場所の書き方が2通りあり、意味が違うためです。

場所を表す文字列を **パス** と呼びます。パスの書き方は2種類です。

```bash
# いまいる場所が /Users/sato のとき

cd /Users/sato/projects   # 絶対パス: どこにいても同じ場所に着く
cd projects               # 相対パス: いまいる場所の中の projects
```

- **絶対パス** — いちばん外側の `/`(**ルートディレクトリ**)から書いた道順。どこから実行しても同じ場所を指す
- **相対パス** — カレントディレクトリからの道順。いる場所が変われば、指す先も変わる

見分け方は1つだけで、**`/` で始まっていれば絶対パス** です。

手順書に `/Users/tanaka/work` のような絶対パスが出てきたら、それは書いた人の環境の住所です。自分の環境の名前に読み替える必要があります。逆に、どこで実行されるか分からない手順書には、絶対パスで書いておく方が安全です。

## 1-1-5 「.」「..」「~」が指す場所

> **「.」はいまいる場所、「..」は1つ上、「~」はホームディレクトリを指す**

手順書には `cd ..` や `cp file .` のような記号がよく出てきます。記号は検索しにくく、意味を知らないと読み飛ばすこともできません。ここで3つまとめて押さえます。

- `.` — カレントディレクトリ(いまいる場所)
- `..` — **親ディレクトリ**(1つ上)
- `~` — **ホームディレクトリ**(自分専用の作業場所。`/Users/sato` など)

```bash
pwd          # => /Users/sato/projects/app
cd ..        # => /Users/sato/projects   (1つ上へ)
cd ~         # => /Users/sato            (ホームへ)
cp ~/memo.txt .   # ホームのmemo.txtを、いまいる場所へコピー
```

`..` は重ねて書けます。`cd ../..` なら2つ上に移ります。

最後の行の末尾にある `.` は見落としがちですが、「コピー先はいまいる場所」という意味の引数です。記号1文字でも、引数としてきちんと働いています。
