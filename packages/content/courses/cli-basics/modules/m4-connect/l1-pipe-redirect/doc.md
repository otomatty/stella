# レッスン4-1 パイプとリダイレクト

## このレッスンの目標

- [ ] 標準入力・標準出力・標準エラー出力の役割を説明できる
- [ ] `|` でコマンドをつなげられる
- [ ] `>` と `>>` を使い分けてファイルに書き出せる

## 4-1-1 コマンドには入口と出口がある

> **コマンドは標準入力から受け取り、結果を標準出力へ流す**

ここまで学んだコマンドは、結果が必ず画面に出ていました。しかし実務では、結果を別のコマンドに渡したり、ファイルに残したりしたくなります。

そのために、コマンドの入口と出口という考え方を持ちます。

- **標準入力** — コマンドがデータを受け取る入口
- **標準出力** — コマンドが結果を流す出口

```text
                ┌──────────┐
 標準入力  ───► │ コマンド │ ───►  標準出力  ───► 画面(既定)
                └──────────┘                    └► 別のコマンド
                                                └► ファイル
```

大事なのは、**画面に出るのは「既定の行き先」にすぎない** ということです。行き先は差し替えられます。この差し替えが、このレッスンの主題です。

## 4-1-2 パイプで出力を次のコマンドに渡す

> **「|」は、左のコマンドの標準出力を右のコマンドの標準入力につなぐ**

エラー行を `grep` で取り出したあと、その件数が知りたくなったとします。いったんファイルに保存してから `wc` で数えるのは手間です。

**パイプ**(縦棒 `|`)を使うと、コマンドどうしを直接つなげます。

```bash
grep error app.log | wc -l
# => 12          エラー行の件数

grep -r error logs/ | head -n 5
# => 最初の5件だけ表示
```

左のコマンドの出口が、右のコマンドの入口に直結します。管でつなぐ、という名前のとおりのイメージです。

つなぐ数に制限はありません。`grep error app.log | grep timeout | wc -l` のように何段でも重ねられます。1つ1つは単純な道具でも、組み合わせると複雑な集計ができる、というのがコマンドラインの設計思想です。

## 4-1-3 「>」でファイルに書き出す

> **「>」は標準出力をファイルへ向ける。既にあるファイルは中身が置き換わる**

調べた結果を報告に貼りたいとき、画面から手でコピーするのは大変です。出力の行き先を変えることを **リダイレクト** と呼びます。

```bash
grep error app.log > errors.txt   # 結果をファイルに書き出す
cat errors.txt                    # 中身を確認

grep warn app.log > errors.txt    # 前の内容は消え、warn の結果だけになる
```

`>` を使うと画面には何も出ません。失敗ではなく、出力がファイルへ向いたためです。

注意すべきは3行目です。`>` は **既にあるファイルの中身を置き換えます**。確認は出ません。大事なファイルの名前を書いてしまうと、その中身は失われます。書き出し先の名前は、実行前に読み返す習慣をつけてください。

## 4-1-4 「>>」で消さずに追記する

> **「>>」は、既にある内容を残したまま末尾に書き足す**

毎日の実行結果を同じファイルに積み上げたい場合、`>` では昨日までの記録が毎回消えてしまいます。

```bash
echo "1回目" > log.txt    # log.txt は「1回目」だけ
echo "2回目" > log.txt    # 「2回目」に置き換わる(1回目は消える)
echo "3回目" >> log.txt   # 「2回目」の下に足される

cat log.txt
# => 2回目
# => 3回目
```

`>` は置き換え、`>>` は **追記** です。違いは記号が1つか2つかだけで、結果は正反対になります。迷ったら、消えて困るファイルには `>>` を選んでください。

## 4-1-5 エラーは別の口から出ている

> **エラーメッセージは標準出力ではなく標準エラー出力に流れる**

結果をファイルに書き出したのに、エラーだけ画面に出てきた。保存したファイルを見ると、そのエラーが入っていない。これは壊れているのではなく、出口が2つあるためです。

```bash
cat nofile.txt > out.txt
# => cat: nofile.txt: No such file or directory   ← 画面に残る
cat out.txt                                       # 空。エラーは入っていない

cat nofile.txt > out.txt 2> error.txt   # エラーだけ error.txt へ
```

**標準エラー出力** は、異常を知らせるためのもう1つの出口です。`>` が向きを変えるのは標準出力だけなので、エラーは画面に残ります。

出口が分かれているのには理由があります。もし混ざっていたら、`grep ... | wc -l` のような処理にエラーメッセージが紛れ込み、件数がずれてしまいます。**正常な結果と異常の知らせを混ぜない** ための設計です。

エラーの行き先を変えたいときは `2>` と書きます。`2` は標準エラー出力を指す固定の番号です(標準出力は `1`)。まずは `2>` という書き方をそのまま覚えてください。
