# レッスン6-1 プロセスを見る・止める

## このレッスンの目標

- [ ] プロセスが何かを説明できる
- [ ] `ps` と `grep` を組み合わせて目的のプロセスを探せる
- [ ] `Ctrl+C` と `kill` を使い分けてプロセスを止められる

## 6-1-1 実行中のプログラムがプロセス

> **実行中のプログラム1つ1つがプロセスで、psで一覧できる**

「サーバーが重い。何が動いているのか」「起動したはずのアプリは本当に動いているのか」。これらはファイルを見るだけでは答えられません。動いているものを見る道具が必要です。

**プロセス** とは、実行中のプログラム1つ1つのことです。ファイルが「置いてあるもの」なら、プロセスは「動いているもの」です。プロセスには1つずつ番号が振られます。

```bash
ps
# =>   PID TTY          TIME CMD
# =>  4821 ttys000  0:00.03 -zsh

ps aux | grep node     # node で動いているものを絞り込む
```

**ps** は process status の略です。`ps aux` は動いているプロセスを全部表示しますが、数が多すぎて読めません。そこでレッスン4-1で学んだパイプを使い、`grep` で絞り込みます。この組み合わせは実務の定番です。

## 6-1-2 Ctrl+Cで手前のプロセスを止める

> **Ctrl+Cは、いま動いているプロセスに終了を伝えてプロンプトを取り戻す**

開発サーバーを起動すると、プロンプトが戻ってきません。止め方を知らないと、ターミナルの窓ごと閉じることになります。

```bash
tail -f app.log      # ログを流し続ける。プロンプトが戻らない
# Ctrl+C を押す
# => プロンプトが戻る

sleep 100            # 100秒待つ
# Ctrl+C で待たずに終われる
```

**Ctrl+C** は、いま手前で動いているプロセスに「終わってください」と伝えるキーです。強制的に電源を落とすのではなく、終了してくださいと伝える操作である点を覚えておいてください。この違いは次のトピックにつながります。

なお `tail -f` の `-f` は、ファイルへの追記を待ち続けるオプションです(follow)。ログ監視で頻繁に使うので、止め方とセットで覚えると使い始められます。

## 6-1-3 killは番号を指定して止める

> **killは、PIDで指定したプロセスに終了を伝える**

前に起動したサーバーが残っていてポートが使用中になっている、しかしそのターミナルは既に閉じてしまった。こうなると `Ctrl+C` は押せません。手前にいないプロセスを止めるには、番号で指定します。

- **PID** — プロセスに振られた番号(process ID)
- **kill** — 指定したPIDのプロセスに終了を伝えるコマンド

```bash
ps aux | grep node
# => sato  4821  ... node server.js
#           └ PID

kill 4821          # 終了を伝える
ps aux | grep node # 消えたか確かめる
```

**調べて、止めて、確かめる** の3手順で行います。3手順目を省くと、止まったつもりで残っていることに気づけません。

`kill` という名前は物騒ですが、やっていることは `Ctrl+C` と同じ「終了を伝える」操作です。伝えても終わらないプロセスには `kill -9` という強い手段がありますが、これは保存の途中でも問答無用で終わらせるため、データが壊れることがあります。まず `kill` を試し、それでも止まらないときは先輩に相談する、という順番にしてください。
