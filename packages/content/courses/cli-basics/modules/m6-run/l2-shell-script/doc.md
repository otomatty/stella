# レッスン6-2 シェルスクリプトの初歩

## このレッスンの目標

- [ ] コマンドを並べたファイルを作って実行できる
- [ ] `chmod +x` で実行権限を付けられる
- [ ] `$1` で引数を受け取り、`&&` で失敗時に止められる

## 6-2-1 コマンドを並べたファイルがスクリプト

> **シェルスクリプトは、実行したいコマンドを上から順に書いたテキストファイル**

毎朝同じ5行のコマンドを手で打ち直していると、打ち間違いが起き、手順書と実際の作業もずれていきます。打っていたものをファイルに書いておけば、同じ手順を何度でも同じように実行できます。

**シェルスクリプト** は、コマンドを並べたテキストファイルです。拡張子は `.sh` を付けるのが慣習です。

```bash
# backup.sh という名前で保存する
mkdir -p backup
cp config.json backup/
echo "バックアップしました"
```

特別な書き方はありません。中身は、いつもターミナルで打っているコマンドそのものです。上から順に実行されます。

新しい言語を覚えるというより、**打っていた手順をそのまま書き写す** と考えてください。この研修で学んだコマンドは、すべてスクリプトの中でも同じように動きます。

## 6-2-2 実行権限を付けて動かす

> **スクリプトはchmod +xで実行権限を付けると、コマンドとして実行できる**

スクリプトを書いて実行しようとすると `Permission denied`(権限がありません)と言われることがあります。ファイルはあるのに動かないのは、そのファイルに「実行してよい」という印が付いていないためです。

```bash
chmod +x backup.sh    # 実行権限を付ける
./backup.sh           # 実行する(./ が要る)

ls -l backup.sh
# => -rwxr--r--   ← x が実行権限の印
```

- **実行権限** — そのファイルを実行してよいという印
- **chmod** — 権限を変えるコマンド(change mode)

`ls -l` で表示される `-rwxr--r--` の `x` が実行権限です。レッスン1-1で `ls -l` を学んだときに見えていた文字列に、こういう意味がありました。

実行するときの `./` にも理由があります。レッスン5-1で学んだとおり、シェルはコマンドをPATHの中から探します。カレントディレクトリはPATHに含まれていないため、「ここにあるこのファイル」と場所を明示する必要があるのです。

1行目に `#!/bin/bash` と書くこともあります。これは **シバン** と呼ばれ、どのシェルで実行するかを指定する行です。付けておくと、実行環境が違っても意図したシェルで動きます。

## 6-2-3 スクリプトの中では引数は$1

> **スクリプトに渡した引数は、中では $1 $2 の順で受け取れる**

対象のファイル名だけが違う、ほぼ同じスクリプトが増えていくことがあります。名前を変えるたびにファイルを開いて書き換えるのは、コピーを増やすファイル管理と同じ問題を招きます。

レッスン0-1で、コマンドは「コマンド名・オプション・引数」でできていると学びました。自分のスクリプトも同じように、引数を受け取れます。

```bash
# greet.sh
echo "$1 さん、おはようございます"
```

```bash
./greet.sh 佐藤
# => 佐藤 さん、おはようございます
```

**位置パラメータ** は、渡された引数を順番で受け取る名前です。1つ目が `$1`、2つ目が `$2` と続きます。

引数を渡さずに実行すると `$1` は空になります。空のまま処理が進むと予期しない動きをするので、次のトピックの「失敗したら止める」が効いてきます。

## 6-2-4 「&&」で成功したときだけ次へ進む

> **「&&」でつなぐと、左のコマンドが成功したときだけ右が実行される**

スクリプトの1行目が失敗しても、2行目以降はそのまま動きます。移動に失敗したまま削除が走る、といった事故はこれで起きます。自動化は速い分だけ、失敗も速く広がります。

コマンドは実行のたびに、成功したか失敗したかの合図を残しています。これを **終了ステータス** と呼び、成功は `0` です。シェルはこの値を見て、次に進むかどうかを判断できます。

ここで、レッスン3-1の `grep` を思い出してください。`grep` は一致する行が無いと `1`(失敗)を返します。`grep error app.log && echo "エラーあり"` は期待どおり動きますが、`grep error app.log && ./deploy.sh` のように「調べたあと必ず次へ進みたい」つもりで書くと、エラーが無かったときに止まります。**`&&` は「エラーが起きなかったら」ではなく「終了ステータスが 0 だったら」**です。

```bash
cd /backup && rm old.log      # 移動できたときだけ消す
cd /backup ; rm old.log       # 「;」は失敗しても次へ進む(危険)

mkdir -p out && cp data.csv out/
```

`;` は「順に実行する」だけで、成否を見ません。1行目の `cd` が失敗して別のディレクトリにいるまま `rm` が走れば、消すつもりのなかったファイルを消します。

**消す・上書きする操作は `&&` でつなぐ**。これを習慣にしてください。この研修で学んだ道具は、ここまでそろえば日々の作業の多くを自動化できます。
