## なぜ必要か

- スクリプトの1行目が失敗しても、2行目以降が動いてしまう
- 移動に失敗したまま `rm` が走る、といった事故につながる

<!-- ノート: つかみ。自動化は速い分だけ、失敗も速く広がると伝えます。 -->

---

## 結論

**「&&」でつなぐと、左のコマンドが成功したときだけ右が実行される**

- **終了ステータス** — コマンドが残す成功・失敗の合図。成功は0

<!-- ノート: 結論を先に言い切ります。シェルは目に見えない合図で成否を判断していると伝えます。 -->

---

## 失敗したらそこで止める

```bash
cd /backup && rm old.log      # 移動できたときだけ消す
cd /backup ; rm old.log       # 「;」は失敗しても次へ進む(危険)

mkdir -p out && cp data.csv out/
```

- 消す・上書きする操作は `&&` でつなぐ

<!-- ノート: 「;」との違いが要点です。危険な操作ほど && を使う、と締めます。 -->
