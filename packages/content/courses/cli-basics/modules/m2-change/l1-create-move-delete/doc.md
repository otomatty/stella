# レッスン2-1 ファイルを作る・移す・消す

## このレッスンの目標

- [ ] `mkdir` / `touch` でディレクトリとファイルを作れる
- [ ] `cp` / `mv` で複製・移動・改名ができる
- [ ] `rm` が取り消せない操作であることを理解し、確認手順を踏める

## 2-1-1 mkdirでディレクトリを作る

> **mkdirは新しいディレクトリを作る。-p を付けると途中の階層もまとめて作る**

手元のPCならフォルダは右クリックで作れますが、サーバーにはGUIがありません。作業用の置き場所も、コマンドで用意します。

```bash
mkdir logs               # logs を作る
mkdir data/2026/04       # エラー: data も 2026 も無い
mkdir -p data/2026/04    # 途中の階層ごと作る
```

**mkdir** は make directory の略です。2行目が失敗するのは、`data` と `2026` がまだ存在しないためです。`-p`(parents)を付けると、途中の階層をまとめて作ります。

`-p` にはもう1つ性質があります。作ろうとしたディレクトリが既にあってもエラーにならず、黙って何もしません。手順書やスクリプトで `mkdir -p` がよく使われるのは、「無ければ作る、あればそのまま」が1行で書けるからです。

## 2-1-2 touchで空のファイルを作る

> **touchは、中身が空のファイルをその場に作る**

中身は後で書くとして、まず器だけ用意したい場面があります。設定ファイルは「存在すること」自体が条件になっていることも珍しくありません。

```bash
touch notes.md
ls -l notes.md
# => -rw-r--r--  1 sato  staff  0  4 12 10:00 notes.md
#                          サイズ0 = 中身が空
```

**touch** は、指定した名前のファイルが無ければ空の状態で作ります。すでにある場合は中身をそのまま残し、更新日時だけを新しくします。**既存ファイルを壊さない** ので、安心して使えます。

## 2-1-3 cpでファイルを複製する

> **cpは元を残したまま複製を作る。ディレクトリごと複製するには -r が要る**

設定ファイルを直す前に元の状態を残しておく、というのは現場の基本動作です。戻せる状態を作ってから触ります。

```bash
cp config.json config.json.bak   # 同じ場所に別名で複製
cp config.json backup/           # backup の中に同じ名前で複製
cp -r logs/ backup/              # ディレクトリごと複製するには -r
```

**cp** は copy の略で、引数は **「元 → 先」** の順に書きます。この順番を取り違えると、残したかったファイルを消してしまうので注意してください。

ディレクトリを複製するときは `-r`(recursive、中を再帰的にたどる)が必要です。付け忘れると「ディレクトリは省略します」と言われて何も起きません。

そしてもう1つ重要な性質があります。**コピー先に同じ名前のファイルがあると、確認なしで上書きされます**。GUIのような「置き換えますか?」は出ません。

## 2-1-4 mvは移動と改名を兼ねる

> **mvはファイルを移す。同じ場所で名前だけ変えるのにも同じコマンドを使う**

GUIでは「移動」と「名前の変更」は別の操作です。そのためコマンドも別だと思いがちですが、コマンドラインでは同じ1つのコマンドを使います。

```bash
mv draft.md report.md        # 名前を変える(同じ場所)
mv report.md archive/        # 移動する(名前はそのまま)
mv report.md archive/old.md  # 移動しながら名前も変える
```

**mv** は move の略です。`cp` と同じく「元 → 先」の順に書きます。行き先のパスを書き換える操作だと考えると、移動も改名も同じことだと分かります。

`cp` と違い、元のファイルは残りません。移動先に同じ名前があると、こちらも確認なしで上書きされます。

## 2-1-5 rmで消したものは戻らない

> **rmで消したファイルはごみ箱に入らず、そのまま消える**

GUIで消したファイルはごみ箱から戻せます。同じつもりでコマンドを打つと、戻す手段が無いことに後から気づくことになります。

```bash
ls old/            # 1. 何が入っているかを見る
rm old/memo.txt    # 2. ファイルを1つ消す
rm -r old/         # 3. ディレクトリごと消す(-r が要る)

rm -i old/memo.txt # 心配なときは -i。1件ずつ確認してくれる
```

**rm** は remove の略です。確認は出ず、ごみ箱にも入りません。だからこそ、**消す前に `ls` で対象を目で確かめる** 手順を習慣にしてください。

自信がないときは `-i`(interactive)を付けます。1件ずつ「消していいか」を尋ねてくれます。

なお `rm -rf /` のように広い範囲を指定すると、システムごと壊れます。`-f`(force)は確認を抑止するオプションで、`-r` と組み合わせると危険度が跳ね上がります。意味が分からないまま `-rf` を含むコマンドを貼り付けないでください。
