# レッスン2-1 演習 — リレーション

対象トピック: 2-1-1 〜 2-1-4

## 手元で試す

紙の上で、次の業務のテーブルを設計してください。

```text
社内の書籍貸出システム
- 書籍には、書名と著者名がある
- 社員は複数の書籍を借りられる
- 1冊の書籍は、時期を変えて何人にも貸し出される
- 貸出には、貸出日と返却日を記録する
```

次の順に決めます。

1. エンティティ(業務の「もの」「こと」)を書き出す
2. それぞれのテーブルの主キーを決める
3. 関係が1対多か多対多かを判断する
4. 外部キーをどのテーブルに置くかを決める

書けたら、`CREATE TABLE` の形にしてみてください(SQL入門7-1で学んだ書き方です)。

```sql
CREATE TABLE employees (
  id   INTEGER PRIMARY KEY,
  name TEXT
);

-- 続きを自分で書く
```

## 演習問題

### 問1(基本)

外部キーを宣言すると、データベースは何を守ってくれますか。

### 問2(基本)

顧客(1)と注文(多)の関係で、`customer_id` はどちらのテーブルに置きますか。理由も書いてください。

### 問3(応用)

「社員」と「プロジェクト」は多対多の関係です(1人が複数のプロジェクトに参加し、1つのプロジェクトに複数人が参加する)。必要なテーブルを挙げ、それぞれが持つ列を書いてください。

### 問4(応用)

退会した会員の行を物理的に消す設計には、どんな問題がありますか。代わりの方法も書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

参照先に存在しないIDを持つ行が入らないようにしてくれます(参照整合性)。

あわせて、その列がどのテーブルを指しているかという設計の意図が、定義そのものに残ります。

</details>

<details>
<summary>問2の解答例</summary>

多い側である注文テーブルに置きます。

逆にすると、顧客テーブルに複数の注文IDを並べることになり、1マス1値(第1正規形)が守れなくなるためです。

</details>

<details>
<summary>問3の解答例</summary>

```text
employees            projects            assignments(中間)
| id | name |        | id | name |       | employee_id | project_id | role |
```

多対多なので中間テーブルを作ります。`assignments` の主キーは「社員ID + プロジェクトID」の組み合わせにできます。関係に固有の情報(担当役割や参加期間)は中間テーブルに持たせます。

</details>

<details>
<summary>問4の解答例</summary>

- 問題: その会員の過去の注文や履歴から、参照先が失われます。売上の集計で会員名が引けなくなり、外部キーがあれば削除自体ができません。
- 代わりの方法: 行は残したまま「退会済み」の印(状態を表す列)を付けます。履歴はそのまま引け、一覧には表示しない、という運用ができます。

</details>

## 確認クイズ

### Q1. 外部キーの説明として正しいものはどれですか。

- A. 別のテーブルの主キーを指す列
- B. 検索を速くするための設定
- C. テーブルの最初の列

<details>
<summary>答え</summary>

**A** — 宣言すると、存在しない値を持つ行が入らなくなります。

</details>

### Q2. 顧客(1)と注文(多)の1対多を表すとき、外部キーを置くのはどちらですか。

- A. 顧客テーブル
- B. 注文テーブル
- C. どちらでもよい

<details>
<summary>答え</summary>

**B** — 多い側に置きます。逆にすると1マスに複数の値を入れることになります。

</details>

### Q3. 多対多の関係を表す方法はどれですか。

- A. どちらかのテーブルにIDを並べた列を作る
- B. 両方のIDを持つ中間テーブルを作る
- C. 2つのテーブルを1つに統合する

<details>
<summary>答え</summary>

**B** — 関係そのものを行として持ちます。関係に固有の情報も中間テーブルに置けます。

</details>

### Q4. 中間テーブルに「数量」のような列を置けるのはなぜですか。

- A. どちらのテーブルにも属さず、関係にだけ意味がある値だから
- B. 数値は中間テーブルにしか置けないから
- C. 主キーが2列あるから

<details>
<summary>答え</summary>

**A** — 「この注文でこの商品を」という関係に固有の情報です。

</details>

### Q5. 履歴を扱うテーブルで、参照されている行を消したくなったときの扱いとして適切なものはどれですか。

- A. 一緒に履歴も消す
- B. 「削除済み」の印を付けて行は残す
- C. 外部キーの宣言を外して消す

<details>
<summary>答え</summary>

**B** — 履歴が失われると過去の集計ができなくなります。行を残す設計を選びます。

</details>
