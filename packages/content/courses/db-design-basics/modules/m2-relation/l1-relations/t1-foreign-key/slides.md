## なぜ必要か

- 分けたテーブルの列が、どこを指しているのかコードを読まないと分からない
- 存在しないIDを書いた行が、そのまま入ってしまう

<!-- ノート: つかみ。分けた後に起きる新しい問題です。 -->

---

## 結論

**外部キーは、その列が別のテーブルの主キーを指していることをデータベースに教える**

- **外部キー** — 別のテーブルの主キーを指す列
- **参照** — その行が別のテーブルの行を指していること

<!-- ノート: 結論を先に言い切ります。宣言することでデータベースが守ってくれます。 -->

---

## 宣言すると守ってもらえる

```sql
CREATE TABLE orders (
  id          INTEGER PRIMARY KEY,
  customer_id INTEGER REFERENCES customers(id)
);
```

- 存在しない `customer_id` の行は入れられなくなる
- 設計の意図が、定義そのものに残る
- SQLiteは既定で検査がオフ。`PRAGMA foreign_keys = ON` が要る

<!-- ノート: コメントではなく定義に書くから守られる、という点が価値です。 -->
