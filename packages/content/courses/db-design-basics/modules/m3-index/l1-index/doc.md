# レッスン3-1 インデックス

## このレッスンの目標

- [ ] インデックスが無いときの検索の動きを説明できる
- [ ] `CREATE INDEX` でインデックスを作れる
- [ ] どの列に作るべきかを判断できる

## 3-1-1 索引が無いと全行を見る

> **索引が無い列で検索すると、データベースは先頭から全行を調べる**

開発中は一瞬で返っていた検索が、本番のデータ量で急に遅くなることがあります。SQLは同じなのに遅くなるのは、データベースの探し方が変わらないからです。

**全表走査** は、テーブルの全行を先頭から順に調べることです。

```text
SELECT * FROM orders WHERE customer_id = 5;

索引なし: 1行目から順に全部見る    (100万行なら100万回)
索引あり: 目次を引いて該当だけ見る  (数回で届く)
```

本を思い浮かべてください。索引(巻末の見出し一覧)が無ければ、目的の語を探すのに最初のページからめくるしかありません。10ページの本なら平気ですが、1000ページなら現実的ではありません。

開発中のデータが10件で、本番が100万件なら、同じSQLの重さは10万倍違います。**件数に比例して遅くなる** という性質を知っておくと、テスト時に気づけます。

## 3-1-2 インデックスは検索用の目次

> **インデックスは、指定した列の値を並べた目次で、その列の検索を速くする**

テーブルの構造を変えずに検索を速くしたいとき、インデックスを作ります。

```sql
CREATE INDEX idx_orders_customer
ON orders (customer_id);
```

**CREATE INDEX** の書き方は1行です。「どのテーブルの、どの列に」を指定するだけです。

いくつか知っておくとよい性質があります。

- **主キーには自動でインデックスが作られる** — だから `WHERE id = 1` は最初から速い
- **外部キーの列は候補になりやすい** — `JOIN ... ON orders.customer_id = customers.id` のように、結合で繰り返し使われるためです

モジュール2で分けたテーブルは、`JOIN` でつなぎ直して使います。分けるほど結合が増えるので、結合に使う列のインデックスが効いてきます。

## 3-1-3 インデックスは書き込みを遅くする

> **インデックスを増やすと検索は速くなるが、書き込みのたびに更新する負担が増える**

速くなるなら全部の列に作ればよい、と考えたくなります。しかし実際にそうすると、登録処理が目に見えて遅くなります。

**書き込み負荷** は、追加・更新・削除にかかる処理の重さのことです。

```text
INSERT 1件
  → 本体に1行追加
  → インデックスの数だけ、目次も更新

インデックス5個 = 追加のたびに6か所を更新
```

本の索引と同じで、本文を書き換えたら索引も直さなければ意味がありません。データベースはこれを自動でやってくれますが、その分の時間はかかります。

正規化と同じく **トレードオフ** です。判断の既定は「**迷ったら作らない**」でよいでしょう。インデックスは後から追加できますが、不要なインデックスは誰も消せません(消してよいか判断できないため)。

## 3-1-4 検索と結合に使う列に作る

> **インデックスは、WHEREやJOINで繰り返し使われる列に作る**

作ったのに速くならなかった、ということが起きます。インデックスが効くかどうかは、その列で **どれだけ絞り込めるか** で決まります。これを **選択性** と呼びます。

```text
効きやすい   customer_id … WHERE や JOIN でよく使い、よく絞れる
             created_at  … 期間で絞ることが多い

効きにくい   is_active   … 値が2種類しかなく、半分が該当する
             めったに検索しない列
```

`is_active`(有効かどうか)のような列は、値が2種類しかありません。100万行のうち50万行が該当するなら、目次を引いても結局50万行を読むことになり、全部読むのとほとんど変わりません。

判断の順序をまとめると次のようになります。

1. そのSQLは繰り返し実行されるか(たまにしか使わないなら不要)
2. `WHERE` や `JOIN ON` でその列を使っているか
3. その条件で十分に絞り込めるか

最後は実測です。データベースには、SQLがどう実行されたかを見る仕組み(実行計画)があります。読み方はこの講座の範囲外ですが、**推測ではなく実測で確かめる手段がある** ことは覚えておいてください。
