## 講座の概要

- **到達目標 (canDo)**: 正規化とリレーションを踏まえて、業務データのテーブルを設計できる
- **前提講座**: `sql-basics`(クリアしていないと開けない)。SELECT・JOIN・集計に加えて、SQL 入門 M6(書き込み)・M7(CREATE TABLE / データ型 / 主キー)を前提にしており、本文でも「SQL 入門で学んだ〜」として接続します
- **参考にしたロードマップ**: roadmap.sh のバックエンドロードマップ
- **コード演習**: 配線していません。この講座の成果物は SQL 文ではなく**設計の判断**(どう分けるか)で、現在の採点基盤には設計を採点する仕組みがないためです。手を動かす部分は各レッスンの `practice.md`「手元で試す」(紙の上での設計)に置き、LMS 上はスライド → まとめ → 確認クイズだけで完走できます

## 設計の方針

- **正規化を目的にしない。** 全体を貫く問いは「変更が起きたときに直す場所が何か所か」です。第1〜第3正規形は、その問いに答えるための手段として導入します(1-1-5 でトレードオフを明示し、非正規化が正当な場合も扱います)
- **用語より先に操作を見せる。** 1-1-1 で「1マスに複数の値を入れると検索できない」を体験させてから、1-1-2 でそれを第1正規形と呼ぶ、という順にしています。同じ構図を M0(会社名の重複)→ 1-1-4(第3正規形)でも使います
- **判断を手順に落とす。** M4 は「名詞を拾う → 主キーを決める → 多重度を双方向に問う → 4つの観点で見直す」という繰り返せる手順として構成しています。設計に正解が1つ無いからこそ、**説明できること**を品質の基準に置きます
- **SQL 入門との接続を本文に書く。** 1マス1値と `WHERE`/`COUNT`(1-1-1)、主キー(1-1-3)、`JOIN ... ON`(2-1-1)、論理削除(2-1-4)、`CREATE TABLE`(M4 の演習)は、前講座で学んだ内容の再利用として説明します

| ID | Takeaway |

## M1 正規化(1レッスン / 5トピック)

### L1-1 正規化
| ID | Takeaway |
|---|---|
| 1-1-1 | 1つのマスに複数の値を詰めると、検索も集計もできなくなる |
| 1-1-2 | 第1正規形は、すべてのマスに値が1つだけ入っている状態 |
| 1-1-3 | 第2正規形は、主キーの一部だけで決まる列を別のテーブルに分けた状態 |
| 1-1-4 | 第3正規形は、主キー以外の列によって決まる列を別のテーブルに分けた状態 |
| 1-1-5 | 正規化は重複を減らすが、その分だけ取り出すときの結合が増える |

### L2-1 リレーション
| ID | Takeaway |
|---|---|

| ID | Takeaway |

## M4 設計演習(1レッスン / 4トピック)

### L4-1 要件から設計する
| ID | Takeaway |
|---|---|
| 4-1-1 | 設計は、業務の説明に出てくる名詞をエンティティの候補として拾うところから始める |

## 対象外

次の内容はこの講座では扱いません。

- **ER 図の記法(IE 記法・IDEF1X の作図規約)** — 関係の考え方は扱いますが、記法の学習は目的にしません
- **第4正規形以降・ボイスコッド正規形** — 実務の標準である第3正規形までを扱います
- **トランザクション分離レベル・ロック** — 並行性の話は入門の範囲を超えます(SQL 入門 6-1-5 でトランザクションの基本だけ扱っています)
- **実行計画の読み方(EXPLAIN)** — 3-1-4 で「実測する手段がある」と触れるだけに留めます
- **物理設計(パーティション・シャーディング・レプリケーション)** — 規模が要求する話で、入門では扱いません
- **特定の製品固有の機能** — SQLite / PostgreSQL のどちらでも通じる範囲で書いています
