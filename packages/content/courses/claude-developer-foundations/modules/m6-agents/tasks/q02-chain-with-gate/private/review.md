# レビューの観点

- 段の出力を `check` で確かめ、通ったときだけ次の段の入力にしているか
- ゲートを通らないか例外が起きたら、次の段を呼ばずに `failedAt` と `reason` を返しているか
- `retries` の回数までだけやり直し、やり直すときに `attempt` と `feedback` を渡しているか
- やり直しで、前の段の出力(同じ入力)を渡しているか。失敗した出力を次の入力にしていないか
- 例外ではやり直していないか
- `outputs` に、通った段の出力だけを残しているか
- 段の名前の重なりを、どの段も呼ぶ前に確かめているか
- 説明欄が、ゲートで止める理由とやり直しの回数の決め方を、自分のコードに即して述べているか

よくある違反: ゲートを通らなくても次の段へ進む、`retries` を無視して何度もやり直す(または `while (true)`)、やり直しに失敗した出力を渡す、例外を握りつぶして `undefined` を次の段に渡す、`feedback` を渡さない、止めたときに `outputs` を返さない。
