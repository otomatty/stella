# 解説

料金は 100 万トークンあたりの単価で決まっているので、トークン数に単価をかけたあと 1,000,000 で割ります。プロンプトキャッシュを使うと、入力は `input_tokens`(最後の区切りより後ろ)・`cache_creation_input_tokens`(書き込み)・`cache_read_input_tokens`(読み込み)の 3 つに分かれ、それぞれ単価が違います。`input_tokens` だけに入力の単価をかけると、キャッシュの分を数え落とします。

キャッシュの書き込みは通常の入力より高く(5 分の期限で 1.25 倍)、読み込みはずっと安い(多くのモデルで 0.1 倍)ので、1 回しか送らないなら書き込みの分だけ高くなります。2 回目から読み込みが効き、送る回数が増えるほど差が広がります。前半がモデルの最低の長さに届かなければキャッシュされないので、`cache_control` を付けても費用は変わりません。

Message Batches API の割引は、キャッシュの倍率と重なります。そのため、キャッシュの有無にかかわらず合計を半額にすれば足ります。
