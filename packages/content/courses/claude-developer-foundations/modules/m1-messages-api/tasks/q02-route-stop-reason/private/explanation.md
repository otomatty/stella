# 解説

`switch` で `stop_reason` の値ごとに分け、扱いの同じ値は `case` を並べてまとめます。`end_turn` と `stop_sequence` は答えを終えた応答、`max_tokens` と `model_context_window_exceeded` は途中で切れた応答として扱います(公式ドキュメントは、コンテキストウィンドウがいっぱいで止まった応答を途中で切れたものとして扱うよう案内しています)。

`tool_use` の応答では、`content` にテキストのブロックとツールの呼び出しのブロックが並ぶことがあります。`type === "tool_use"` のブロックだけを選び、`{ id, name, input }` にします。

拒否は HTTP 200 の普通の応答として返ります。`stop_details` は `null` のことがあり、`explanation` も `null` のことがあるので、`?.` と `??` で `null` にそろえます。`explanation` の文は変わることがあるので、表示に使うだけで中身では分岐しません。

`default` で表にない値を `unexpected` にするのは、新しい値が増えたときに、ほかの値の扱い(たとえば「答えを終えた」)に黙って混ぜないためです。値をそのまま返せば、開発者が気づいて扱いを足せます。

別解: 値と扱いの対応をオブジェクトの表にして引く書き方もあります。その場合も、表にない値を既定の扱いに混ぜないようにします。
