# 解説

Messages API は会話を覚えないので、リクエストのたびに、それまでのやり取りと新しい発言を `messages` にまとめて送ります。スプレッド構文 `[...history, 新しい発言]` で新しい配列を作ると、呼び出し側の `history` は変わりません。`history.push` は呼び出し側の配列を書き換えるので、同じ発言が 2 回入るなどの不具合のもとになります。

役割の指示は `system` に置きます。`messages` は利用者と Claude のやり取りだけにしておくと、履歴をそのまま次のリクエストに使えます。

応答の `content` はブロックの配列で、テキストのブロックが複数あることも、テキスト以外のブロック(ツールの呼び出しなど)が混ざることもあります。`filter` で `type === "text"` のブロックを選び、`map` で `text` を取り出して `join("")` でつなぎます。`content[0].text` だけを読む書き方は、この 2 つの場合に本文を取りこぼします。
