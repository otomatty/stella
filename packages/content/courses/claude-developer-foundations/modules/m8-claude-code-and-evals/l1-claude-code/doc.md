# レッスン8-1 Claude Code に約束を持たせる

## このレッスンの目標

- [ ] CLAUDE.md に書くことと、置き場所を選べます。
- [ ] 必ず実行したい処理を、フックで決められます。
- [ ] 設定ファイルの置き場所と、強く効く順を説明できます。

## 8-1-1 毎回効かせる約束

> **毎回効かせたいプロジェクトの約束は、CLAUDE.md に短く具体的に書きます。**

Claude Code には、会話の始まりに毎回読み込まれる記憶が 2 つあります。

| | CLAUDE.md | 自動メモリー |
| --- | --- | --- |
| 書く人 | 人 | Claude |
| 中身 | 指示と決まり | 直されたことや覚えた傾向 |
| 使いどころ | コードの書き方の決まり、作業の手順、プロジェクトの構成 | 好み、Claude に伝えた訂正、コードからは分からない背景 |

次のようなときに、CLAUDE.md に書き足します。

- Claude が同じ間違いを 2 回した
- コードレビューで、このコードベースなら Claude が知っているべきことを指摘された
- 前の会話で入力したのと同じ訂正や説明を、また入力した

置き場所によって、効く範囲が違います。

| 範囲 | 置き場所 | 共有する相手 |
| --- | --- | --- |
| 組織の決まり | OS ごとの決まったフォルダー(IT 部門が管理) | 組織の全員 |
| 自分の決まり | `~/.claude/CLAUDE.md` | 自分(全プロジェクト) |
| プロジェクトの決まり | `./CLAUDE.md` か `./.claude/CLAUDE.md` | リポジトリを使うチームの全員 |
| プロジェクトの自分だけの決まり | `./CLAUDE.local.md`(`.gitignore` に入れる) | 自分(このプロジェクト) |

CLAUDE.md は指示として読まれるだけで、必ず守られる設定ではありません。守られやすくするために、確かめられる具体的な書き方にします(「コードを整える」ではなく「インデントは 2 文字の空白」、「変更を試す」ではなく「コミットの前に `npm test` を走らせる」)。1 つのファイルは 200 行より短くし、見出しと箇条書きで整理します。互いに食い違う指示があると、Claude はどちらかを勝手に選ぶことがあるので、ときどき見直します。手順の長いものや、コードベースの一部にしか関わらないものは、スキルやフォルダーごとの決まりに移します。

## 8-1-2 必ず実行する処理

> **必ず実行したい処理は、CLAUDE.md の指示ではなくフックで決めます。**

フックは、Claude Code が決まった時点で必ず動かす、自分で書いたコマンドです。Claude が実行を選ぶかどうかに頼らず、決めた処理を必ず行えます。CLAUDE.md に書いた禁止を確実に守らせたいときも、フックを使います。

| 時点(イベント) | 動くとき | 使い方の例 |
| --- | --- | --- |
| `PreToolUse` | ツールを使う前 | 守りたいファイルの書き換えや、危ないコマンドを止める |
| `PostToolUse` | ツールを使ったあと | 書き換えたファイルを Prettier で整える |
| `Notification` | Claude Code が知らせを出すとき | 入力を待っているときに、デスクトップに通知する |
| `SessionStart` | 会話の始まりと再開 | 作業に要る情報を会話に入れる |

フックは、イベントの情報を JSON で標準入力から受け取り、終了コードで次の動きを伝えます。

- **終了コード 2**: 止める。標準エラーに書いた理由が、Claude に伝わります(Claude は理由を見て、やり方を変えられます)。
- **終了コード 0**: 反対しない。`PreToolUse` で 0 を返しても許可したことにはならず、ふつうの権限の確認に進みます。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }]
      }
    ]
  }
}
```

フックは設定ファイルに書きます。プロジェクトの `.claude/settings.json` に書けば、リポジトリを使う全員に効きます。

## 8-1-3 共有する設定の置き場所

> **チームで共有する設定は、プロジェクトの .claude/settings.json に置いてリポジトリに入れます。**

Claude Code は、4 つの置き場所から設定を読みます。

| 範囲 | ファイル | 効く相手 | 書くもの |
| --- | --- | --- | --- |
| ユーザー | `~/.claude/settings.json` | このマシンの全プロジェクトの自分 | 自分の好み、既定のモデル、自分の権限の決まり |
| 共有するプロジェクト | `.claude/settings.json` | そのフォルダーで作業する全員(リポジトリに入れる) | チームの権限の決まり、フック、プロジェクトに要る環境変数 |
| プロジェクトのローカル | `.claude/settings.local.json` | このプロジェクトの自分だけ(Git に入れない) | このプロジェクトでの自分の上書き、共有する前の試し |
| 管理された設定 | 組織が配る設定 | 組織が配った全員 | セキュリティの方針、守るべき決まり |

同じ項目がいくつかのファイルにあるときは、強いものが使われます。強い順に、管理された設定、コマンドライン(`--settings`)、プロジェクトのローカル、共有するプロジェクト、ユーザーです。管理された設定は、ほかのどのファイルからも上書きできません。

ただし、`permissions.allow` のような一覧の項目は、上書きではなく足し合わされます。どのファイルも、ほかのファイルの項目を消さずに足せます。
