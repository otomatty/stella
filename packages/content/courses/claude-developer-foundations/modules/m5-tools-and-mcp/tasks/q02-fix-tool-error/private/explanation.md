# 解説

原因は、ツールの呼び出しの結果を作る処理が、ツールの失敗を結果に変えずに例外のまま投げていたことです。`await tools[block.name](block.input)` は、ツールが例外を投げるとその場で止まり、`for` の残りの呼び出しも実行されません。定義していない名前では `tools[block.name]` が `undefined` になり、`TypeError` で止まります。ループの呼び出し元まで例外が伝わるので、利用者には定型のエラーしか返りませんでした。

ツールの失敗は、`is_error: true` を付けた `tool_result` として Claude に返します。Claude は失敗を受け取り、「在庫は確認できませんでしたが、値段は 1,980 円です」のように、分かったことと分からなかったことを利用者に伝えられます。結果の文には、何が起きたか(例外の内容)を書きます。

直すのは失敗の扱いだけです。成功したときの結果の形や、結果の順番は変えません。1 つの呼び出しを結果に変える関数に分け、その中だけで失敗を扱うと、差分が原因の範囲に収まります。再発の確認には、例外を投げるツール、定義していないツール、失敗と成功が混ざる応答のテストを使います。
