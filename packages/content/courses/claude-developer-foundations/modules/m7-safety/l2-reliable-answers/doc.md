# レッスン7-2 間違いと漏れを防ぐ

## このレッスンの目標

- [ ] ハルシネーションを減らす指示の書き方を選べます。
- [ ] 長い資料から、根拠の引用を示させて答えさせられます。
- [ ] エージェントに秘密を見せない作りを説明できます。

## 7-2-1 分からないと言わせる

> **分からないときは分からないと答えてよい、と指示に書きます。**

ハルシネーションは、事実と違う内容や、渡した資料と食い違う内容を Claude が作ってしまうことです。最も手軽な対策は、不確かなときは認めてよいと、はっきり許すことです。それだけで、誤った情報が大きく減ります。

```text
<instructions>
報告書に書かれていることだけを根拠に答えてください。
報告書から分からないことは、推測せず「報告書からは分かりません」と答えてください。
</instructions>
```

渡した資料の情報だけを使い、一般の知識で補わないように指示することも効きます。これらの方法でハルシネーションは大きく減りますが、なくなりはしません。大事な判断に使う情報は、人が確かめます。

## 7-2-2 引用から答えさせる

> **長い資料の事実は、先に引用を抜き出させてから答えさせます。**

2 万トークンを超えるような長い資料から答えるときは、先に関係する箇所を一字一句抜き出させ、その引用をもとに答えさせます。答えが資料の実際の文に結びつき、ハルシネーションが減ります。

さらに、答えを確かめられる形にする方法があります。

| 方法 | すること |
| --- | --- |
| 根拠を示させる | 主張ごとに、根拠の引用と出どころを示させる |
| 根拠で見直させる | 答えを作ったあとに主張ごとの根拠の引用を探させ、見つからない主張は取り下げさせる |
| 何回か比べる | 同じプロンプトで何回か答えさせ、食い違いから誤りに気づく |
| 考えた過程を読む | 考える過程の要約を表示させ(`display: "summarized"`)、答えがおかしいときに前提や論理の誤りを探す |
| 続けて確かめる | 前の答えを次のプロンプトに渡し、確かめさせたり補わせたりする |

## 7-2-3 秘密を見せない

> **API キーなどの秘密はエージェントに渡さず、外側のプロキシで付け足します。**

エージェントは、紛れ込んだ指示やモデルの間違いで、思わぬ動きをすることがあります。エージェントから見える秘密は、エージェントが外へ送れてしまいます。そのため、エージェントには要らない秘密を渡しません。

API や外のサービスの鍵が要るときは、プロキシを使う形が勧められています。エージェントは秘密なしでリクエストを送り、エージェントの守りの外にあるプロキシが秘密を足して宛先へ転送します。

- エージェントは本物の秘密を見ません。
- プロキシで、送ってよい宛先だけを通せます。
- プロキシで、すべてのリクエストを監査のために記録できます。
- 秘密を 1 か所で管理でき、エージェントごとに配らずに済みます。

守りは 1 つに頼らず、重ねます(多層防御)。たとえば、悪意のあるファイルの指示で顧客のデータを外へ送ろうとしても、ネットワークの制限があれば、そのリクエスト自体を止められます。ファイルは要るフォルダーだけを、できれば読み取り専用で見せ、ネットワークは決まった宛先だけに絞ります。
