# 解説

この課題は、M1〜M5 で別々に作った部品(リクエストの組み立て・止まった理由の分岐・送り直し・構造化出力・ツール使用のループ)を、1 つのアシスタントにまとめるものです。

## スキーマをかける場所

ツールの入力の形は、ツールの定義に `strict: true` を付けて `input_schema` で決めます。最後の答えの形は、`output_config.format` の JSON スキーマで決めます。構造化出力が決めるのは Claude が答える本文で、ツールの入力には効きません。2 つは同じリクエストで一緒に使えるので、ツールを呼ぶたびの入力も、最後の答えも、スキーマどおりになります(10-1-3)。

## 止まった理由とエラーを分ける

`stop_reason` は成功した応答に入る値で、HTTP のエラーとは別のものです(10-1-4)。`refusal` は HTTP 200 の応答で届くので、例外の処理では拾えません。`max_tokens` と `model_context_window_exceeded` の答えは途中で切れているので、JSON として読むと例外になるか、欠けた答えを使うことになります。構造化出力でも、切れた答えはスキーマに合うとは限りません(4-2-2)。

エラーのほうは、`create` が投げた時点で応答がありません。SDK は 429 や 5xx を、間隔を広げながら `maxRetries` の回数まで送り直してから投げます(1-2-1)。アプリでさらに送り直すと、1 回の問い合わせで送るリクエストが掛け算で増え、混んでいるときにさらに負荷をかけます。アプリは「混んでいる」と分かる結果を返し、画面で時間を置くよう伝えます。400 のようなリクエストの誤りは、送り直しても通らないので、そのまま投げて直します。

## ツール使用のループ

Claude 5 のモデルは、答える前に考える過程を既定で使い、応答の `content` の先頭に `thinking` ブロックが入ります。ツールの結果を返すときは、この `thinking` ブロックを含む `content` を、手を加えずに assistant の発言として返す必要があります。取り除くと、Claude が続きを考えるのに使う推論が失われます。

`tool_result` は `tool_use_id` で呼び出しと結び、1 つの応答の呼び出しの結果は 1 つの user の発言にまとめます(5-1-2)。ツールの失敗は、ループを止めずに `is_error` を付けた結果で返すと、Claude が利用者に説明したり、`needs_human` を true にしたりできます(5-1-3)。

## 別の書き方

`switch` の代わりに、`stop_reason` から扱いを引く表を作る書き方もあります。そのときも、表にない値を `end_turn` と同じに扱わず、`unexpected` として返します。

送り直しの回数は、クライアントを作るときに `new Anthropic({ maxRetries })` で決めることもできます。この課題では、問い合わせごとに回数を変えられるよう、リクエストごとに渡しています。
