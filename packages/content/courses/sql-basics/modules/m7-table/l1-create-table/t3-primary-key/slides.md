## なぜ必要か

- 同姓同名の会員がいると、名前では1人に絞れない
- `UPDATE` や `DELETE` の対象を、確実に1件に決めたい

<!-- ノート: つかみ。書き込み系で WHERE に使ってきた id の意味に立ち返ります。 -->

---

## 結論

**主キーは行を1つに特定するための列で、同じ値を2回入れられない**

- **主キー** — その行を一意に決める列(**PRIMARY KEY**)

<!-- ノート: 結論を先に言い切ります。JOIN の ON で使ってきた列がこれです。 -->

---

## 同じ値は2回入らない

```sql
CREATE TABLE products (
  id    INTEGER PRIMARY KEY,
  name  TEXT,
  price INTEGER
);
```

- 同じ `id` を2回入れようとするとエラーになる
- `JOIN ... ON` でテーブルをつなぐときの目印にもなる
- 空(NULL)も入らない約束だが、**SQLite は例外**。`NOT NULL` も書いておく
