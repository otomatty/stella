# 結合した結果も絞り込める

SQL入門 — Module 4 / レッスン4-1

## なぜ必要か

- JOIN で全部の組み合わせを出しても、見たいのは一部だけということが多い
- 「佐藤さんの注文だけ」「品名の順に並べて」に応えたい

<!-- ノート: つかみ。実務のJOINはほぼ必ず絞り込みや並べ替えとセットで使う。組み合わせられるのか?という不安をここで拾う。 -->

---

## 結論

**JOIN した結果もひとつの表なので、WHERE や ORDER BY がそのまま使える**

- JOIN が作るのは、つながった行が並んだ「ひとつの表」
- 表に使える道具は、その結果にも全部使える

<!-- ノート: 結論。「結局ひとつの表になる」が腹落ちすれば、新しく覚えることは何もないと分かる。 -->

---

## 最小のコード

```sql
SELECT name, item
FROM orders
INNER JOIN customers ON orders.customer_id = customers.id
WHERE name = '佐藤'
ORDER BY item;
```

| name | item |
| --- | --- |
| 佐藤 | クッキー |
| 佐藤 | コーヒー |

<!-- ノート: JOINでつないだ表に対して、WHEREで佐藤さんに絞り、ORDER BYで品名順に並べる。書く場所はJOINのONの後、と型で覚える。 -->

---

## 読み解く順番

| 順 | 書くもの | すること |
| --- | --- | --- |
| 1 | FROM + JOIN | 表をつなぐ |
| 2 | WHERE | 行を絞る |
| 3 | ORDER BY | 並べ替える |

<!-- ノート: 長いSQL文はこの順で読み解く。まず表を作り、絞り、並べる。この読み方はこの先どんなに文が長くなっても通用する。 -->
