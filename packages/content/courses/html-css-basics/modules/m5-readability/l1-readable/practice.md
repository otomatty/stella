# レッスン5-1 演習 — 読める画面にする

対象トピック: 5-1-1 〜 5-1-4

## 手元で試す

仕上げなので、まず `style.css` の掃除をします。レッスン3-2で勝ち負けを試すために書いた次の2つは、ここでは不要なので削除してください。残したままだと、本文の色がこれから書く基準ではなくこちらで決まってしまいます(`p` への直接の指定は、`body` からの継承より強いためです)。

```css
body {
  color: dimgray;
}

p {
  color: navy;
}
```

そのうえで、`style.css` の先頭にページ全体の基準を足します。

```css
body {
  color: #1a1a1a;
  background-color: #ffffff;
  font-size: 16px;
  line-height: 1.6;
}

input,
button {
  font-size: 16px;
}
```

入力欄とボタンは `body` の文字サイズを受け継がないので、別に指定します。保存して再読み込みし、文章が読みやすくなったことを確かめてください。書けたら、次を試してみましょう。

1. `line-height` を `1.0` にして、読みにくくなることを確かめる(確かめたら戻す)
2. `color` を `#aaaaaa` にして、薄い文字が読みにくいことを確かめる(確かめたら戻す)
3. 段落を右クリックして「検証」を選び、開発者ツールを開く。`font-size` の値をその場で書き換えて、表示が変わることを確かめる
4. 再読み込みして、開発者ツールでの変更が消えることを確かめる

## 演習問題

### 問1(基本)

ページ全体の文字サイズを16px、行間を1.6にするCSSを書いてください。セレクタは `body` としてください。

### 問2(基本)

`line-height` を `1.6` のように単位なしで書くのが基本なのはなぜですか。1文で説明してください。

### 問3(応用)

「必須の項目は赤い文字にしています」という案内だけで、必須かどうかを伝えています。この作り方の問題点と、改善案を書いてください。

### 問4(応用)

CSSに書いた `color` の指定が効きません。開発者ツールを使うと、どうやって原因を確かめられますか。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

```css
body {
  font-size: 16px;
  line-height: 1.6;
}
```

どちらも継承されるので、`body` に書けばページ全体に効きます。

</details>

<details>
<summary>問2の解答例</summary>

文字サイズの何倍かで指定されるため、あとから文字サイズを変えても比率が保たれるからです。

</details>

<details>
<summary>問3の解答例</summary>

色の区別が付きにくい人には必須かどうかが伝わりません。色に加えて「必須」という文字を添えます。色だけで情報を伝えないのが原則です。

</details>

<details>
<summary>問4の解答例</summary>

その要素を右クリックして「検証」で開発者ツールを開き、当たっている宣言の一覧を見ます。自分が書いた宣言に取り消し線が付いていれば、別の指定に上書きされています。

</details>

## 確認クイズ

### Q1. 本文の文字サイズの基準として適切なものはどれですか。

- A. 10px前後
- B. 16px前後
- C. 30px前後

<details>
<summary>答え</summary>

**B** — 多くのブラウザーの既定値でもあり、読みやすさの基準になります。

</details>

### Q2. 長い文章の行間の目安はどれですか。

- A. 1.0
- B. 1.5〜1.8
- C. 3.0以上

<details>
<summary>答え</summary>

**B** — 詰まりすぎると次の行に移るときに目が迷子になり、広げすぎると間延びします。

</details>

### Q3. line-height に単位を付けずに数字だけを書くと、何を基準にした値になりますか。

- A. 画面の高さ
- B. 文字サイズ
- C. 親要素の余白

<details>
<summary>答え</summary>

**B** — 文字サイズの何倍かを表します。文字サイズを変えても比率が保たれます。

</details>

### Q4. 読みやすい色の組み合わせを選ぶ基準はどれですか。

- A. 文字色と背景色の明るさの差が十分にあること
- B. 文字色と背景色が同じ系統の色であること
- C. 背景色が必ず白であること

<details>
<summary>答え</summary>

**A** — 明るさの差がコントラストです。薄い灰色と白の組み合わせは差が小さく読みにくくなります。

</details>

### Q5. 開発者ツールで宣言に取り消し線が付いているとき、何が分かりますか。

- A. その宣言の書き方が間違っている
- B. その宣言が別の指定に上書きされて負けている
- C. その宣言がブラウザーで使えない

<details>
<summary>答え</summary>

**B** — 勝ち負けが目で分かります。効かない原因を探すときの近道です。

</details>

### Q6. 開発者ツールで値を書き換えて見た目を調整しました。次にすることはどれですか。

- A. そのまま閉じる。変更は保存されている
- B. 良い値をCSSファイルに書き写す
- C. ブラウザーを再インストールする

<details>
<summary>答え</summary>

**B** — 開発者ツールでの変更は再読み込みで消えます。必ずファイルに戻してください。

</details>
