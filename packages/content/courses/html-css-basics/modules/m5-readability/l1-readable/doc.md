# レッスン5-1 読める画面にする

## このレッスンの目標

- [ ] 本文の文字サイズと行間を基準どおりに設定できる
- [ ] コントラストを理由に色の組み合わせを判断できる
- [ ] 開発者ツールで、効かない指定の原因を5つに切り分けられる

## 5-1-1 本文の文字サイズは16px前後にする

> **本文のfont-sizeは16px前後を基準にし、小さくしすぎない**

文字の大きさを決めるプロパティが **font-size** です。単位の **px** は、画面上の点の数を表します。

```css
body {
  font-size: 16px;
}
```

`font-size` は **継承** されるので、`body` に書けば本文全体に効きます。個別に変えたい要素だけ、あとから指定します。

ただし、入力欄とボタンは例外です。ブラウザーがこれらの部品に独自の文字サイズを持たせているため、`body` の指定を受け継ぎません(Chromium では約13pxになります)。フォームのある画面では、次のように明示してください。

```css
input,
button {
  font-size: 16px;
}
```

入力欄の文字が小さいままだと、端末によっては、タップしたときに画面が勝手に拡大されることがあります。

16pxという数字には根拠があります。多くのブラウザーの既定値がこの大きさで、一般的な画面と距離で読みやすいとされている基準だからです。

| 場所 | 目安 |
| --- | --- |
| 本文・入力欄 | 16px前後 |
| 注釈・補足 | 14px程度まで |
| 本文全体 | 12pxまで下げない |

作る側は画面に近づいて見ているので、小さくても読めてしまいます。しかし利用者の視力も画面も環境もさまざまです。補足を少し小さくするのは許容範囲ですが、本文全体を小さくすると、読める人を選ぶページになります。

## 5-1-2 行間を空けると文章が読みやすい

> **line-heightを1.5〜1.8にすると、長い文章が読みやすくなる**

文字が十分な大きさなのに読みにくい、というときは **行間** を疑います。1行分の高さを決めるプロパティが **line-height** です。

```css
body {
  font-size: 16px;
  line-height: 1.6;
}
```

単位を付けない数字は、文字サイズの何倍かを表します。`1.6` なら16pxの1.6倍です。単位なしで書いておくと、文字サイズを変えたときも比率が保たれます。

行間が詰まっていると、行を読み終えて次の行へ移るときに目が迷子になります。日本語は漢字とかなが混ざって画数の差が大きいため、英語より少し広めが合うことが多く、1.7前後もよく使われます。

| 場所 | 目安 |
| --- | --- |
| 本文の段落 | 1.5〜1.8 |
| 大きな見出し | 1.2前後 |

見出しは1〜2行で終わるので、広げると間延びして見えます。場所によって変えてください。

## 5-1-3 文字色と背景色はコントラストで決める

> **文字色と背景色は、明るさの差が十分にある組み合わせを選ぶ**

文字色は **color**、背景色は **background-color** で指定します。この2つの明るさの差を **コントラスト** と呼びます。

```css
body {
  color: #1a1a1a;
  background-color: #ffffff;
}
```

`#` で始まる6桁の値は、色を数値で指定する書き方です。黒に近い文字と白い背景の組み合わせが、もっとも読みやすくなります。

色を選ぶときは、好みではなく読めるかどうかで判断してください。

| 組み合わせ | 問題 |
| --- | --- |
| 薄い灰色 × 白 | 明るさの差が小さく、読みにくい |
| 黄色 × 白 | 同上 |
| 赤 × 緑 | 色の区別が付きにくい人がいる |

薄いグレーの文字は上品に見えますが、屋外や古い画面では読めなくなります。また、**色だけで情報を伝えない** ことも大切です。「赤い項目は必須です」と色で示すだけでは、色の区別が付きにくい人には伝わりません。「必須」という文字も添えてください。

コントラストが十分かどうかは、目視では判断しきれません。無料のコントラスト判定ツールがWebにあるので、迷ったら数値で確かめるのが確実です。

## 5-1-4 仕上げは開発者ツールで確かめる

> **ブラウザーの開発者ツールを使うと、当たっているCSSをその場で確かめられる**

ここで、この先を自力で進めるための道具を紹介します。**開発者ツール** は、ブラウザーに標準で付いている調査用の画面です。追加のインストールは要りません。調べたい部分を右クリックして「検証」を選ぶと開きます。

できることは大きく3つです。

- その要素に当たっている宣言の一覧を見る
- **上書き** されて負けている宣言に取り消し線が付くので、勝ち負けが目で分かる
- 値をその場で書き換えて、見た目の変化をすぐ試す

レッスン3-2で扱った「書いたのに効かない」の調査が、コードを読んで当てる作業から、画面を見る作業に変わります。取り消し線が見えるだけで、詳細度の理解も一気に進みます。

1つだけ注意があります。開発者ツールでの変更は、再読み込みすると消えます。良い値が見つかったら、必ずCSSファイルに書き写してください。ここで直したつもりになって、そのまま閉じてしまう事故はよく起きます。

## 5-1-5 効かない指定は5つの原因に切り分ける

> **効かない宣言は、書き方・セレクタ・順序・詳細度・継承のどれが原因かを開発者ツールで確かめて直す**

開発者ツールの開き方が分かったので、いちばん時間を溶かす場面での使い方を決めておきます。「書いたはずのCSSが効かない」ときです。

あてずっぽうで書き換えても、直った理由が分からないので次も同じところで止まります。原因の候補を順に消していく **切り分け** の手順を持ってください。候補は5つです。うち3つはモジュール3で学んだ順序・詳細度・継承、残りは「そもそもセレクタが当たっていない」と「宣言の書き方が無効」です。

開発者ツールの「当たっているCSSの一覧」は、見え方で原因を教えてくれます。

- **警告アイコンが付く(灰色で表示される)** — その宣言の書き方が無効で、そもそも読まれていない
- **取り消し線が付いている** — その宣言は別の宣言に負けている
- **一覧に出てこない** — そのセレクタがその要素に当たっていない
- **薄い文字で出る** — 自分では指定しておらず、親から受け継いだ値

見えたものから、直し方が決まります。

| 見えたもの | 原因 | 直し方 |
| --- | --- | --- |
| 警告アイコンが付く | 書き方 | プロパティ名の綴り、値、セミコロンやコロンの書き忘れを直す |
| 一覧に出てこない | セレクタ | セレクタの綴りや `.` の付け忘れを直す |
| 同じ詳細度の宣言に負けている | 順序 | 効かせたい宣言を後ろに書く |
| より細かいセレクタに負けている | 詳細度 | セレクタを絞って詳細度を上げる |
| 指定していない値が付いている | 継承 | その要素自身に値を指定して上書きする |

**上から順に見てください。** 最初の2つはカスケード(勝ち負け)以前の問題です。プロパティ名を打ち間違えた宣言を、順序や詳細度で直そうとしても直りません。

この表で直せないかを先に試してください。`!important` は、ここまで試したうえでどうにもならないときの最後の手段です。

## もっと知りたい人へ

- 開発者ツールには、画面の幅を変えてスマートフォン表示を確認する機能もあります。作ったページが狭い画面でどう見えるかは、公開前に必ず確認してください
- 読みやすさの基準は「アクセシビリティ」という分野としてまとまっています。この講座で扱った文字サイズ・行間・コントラスト・代替テキスト・ラベルは、いずれもその入口です
