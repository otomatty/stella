## なぜ必要か

- 画面に見えているものが「どこから来たのか」が分からないと、直す場所も分からない
- 見た目を直したいのに、サーバーの設定を疑って半日溶かす、が起きる

<!-- ノート: つかみ。実務では「文字を大きくしたい」だけの依頼でも、どこを触ればいいか分からないと動けない、という話をする。ここで結論は言わない。 -->

---

## 結論

**ブラウザーは、受け取ったファイルを読んで画面を組み立てている**

- **ブラウザー** = Chrome や Safari など、ページを見るためのソフト
- **Webページ** = ブラウザーが組み立てて見せている画面

<!-- ノート: 結論を言い切る。ページは「置いてある絵」ではなく、毎回組み立てられている結果だと押さえる。 -->

---

## 材料はファイルで届く

| 届くもの | 役割 |
| --- | --- |
| .html の **ファイル** | ページに何を置くか |
| .css のファイル | それをどう見せるか |
| 画像のファイル | 写真やイラスト |

<!-- ノート: ブラウザーが受け取る材料を3つ見せる。ここではファイルという単位で届く、という点だけ押さえればよい。 -->

---

## だから直す場所が分かる

- 文字や項目を足したい → 中身のファイルを直す
- 色や大きさを変えたい → 見た目のファイルを直す
- どちらもブラウザーが読み直して、組み立て直す
