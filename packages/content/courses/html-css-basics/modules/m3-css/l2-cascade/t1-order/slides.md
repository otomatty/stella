# 3-2-1
# 同じ相手に当たると後の宣言が勝つ

HTML/CSS入門研修 — Module 3 / レッスン3-2

<!-- ノート: ここからは「書いたのに効かない」の原因を潰していきます。 -->

---

## なぜ必要か

- 色を変えたのに、画面の色が変わらない
- 消してもいいのか分からず、古い指定がどんどん残っていく

<!-- ノート: つかみ。CSSでいちばん時間を溶かすのがこれ。ここで結論は言わない。 -->

---

## 結論

**同じ条件で同じプロパティを指定したら、後に書いた宣言が勝つ**

- 指定が重なったときの決め方を **カスケード** と呼ぶ
- 後の宣言が前の宣言を **上書き** する

<!-- ノート: 結論を言い切る。CSSのCはカスケードのC。重なりを前提にした仕組みだと伝える。 -->

---

## 最小のコード

```css
h1 {
  color: navy;
}
h1 {
  color: crimson;
}
```

- 表示は後に書いた深紅
- 前の指定は消えるのではなく、負けている

<!-- ノート: 上書きされているだけで、上の行も読まれている。プロパティが違えば両方効く。 -->

---

## 効かないときの探し方

- 同じプロパティを、後ろでもう一度指定していないか
- スタイルシートを2つ読み込んでいないか(後の方が勝つ)
- そもそも保存と再読み込みをしたか

<!-- ノート: 対比枠。この3点を順に見るだけで、多くの「効かない」は解決する。順番以外の要因は次のトピック。 -->
