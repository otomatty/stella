# レッスン4-1 プラグインで道具を足す

## このレッスンの目標

- [ ] プラグインが何のための仕組みかを説明できる
- [ ] 調査・文書・ブラウザ操作のどれに頼むかを選べる
- [ ] それぞれの受け取りで何を確かめるかを言える

## 4-1-1 プラグインは道具を足す仕組み

> **プラグインは、Coworkに作業向けの道具を足して、頼める幅を広げる仕組みです**

M3までで、任せ方の型は1周そろいました。このモジュールでは、頼める作業の幅を広げる仕組みを扱います。

**道具** は、特定の種類の作業をこなすための機能のまとまりです。**プラグイン** は、その道具をCoworkに後から足す仕組みです。スマートフォンにアプリを足す感覚が近いたとえになります。本体の頼み方(依頼・タスク・確認)は変わらないまま、頼める作業の種類が増えます。

この講座で扱う用途は3つです。

```text
調べもの     Webの情報を集めて比べる
文書づくり   決まった体裁のファイルに仕上げる
画面の作業   Webの画面を開いて進める
```

学ぶ対象に注意してください。このモジュールで扱うのは「どの作業をどの道具に頼むか」という判断だけです。

| | このモジュールで扱う | 扱わない |
| --- | --- | --- |
| 内容 | どの作業をどの道具に頼むか | 導入手順・設定画面 |
| 理由 | 1年後も変わらない判断 | 画面や名称は変わる |

個別の製品名や設定手順は変わっていくため、実際に使うときに製品のドキュメントを見る前提です。ある道具が最初から本体に入っているか、プラグインとして後から足すか、1つのプラグインが何をひとまとめにしているかも、環境と時期で変わります。この講座で持ち帰るのは「どの用途の作業を、どんな道具に頼むか」という判断だけです。プラグインを自作する話も、この講座では扱いません。

## 4-1-2 調べものは調査の道具で

> **資料を広く集めて比べる調べものは、調査向けのプラグインに頼むのが向いています**

1つ目の用途は調べものです。ツール選定の比較、他社事例の下調べ。タブを何十枚も開き、集めたメモの整理にさらに時間がかかる、あの作業です。

**調査** は、情報を集め、比べ、出どころとともにまとめる作業です。「広く集めて比べる」形の調べものが、調査向けのプラグインに向いています。一言で済む検索なら、チャットで聞くほうが早く終わります。

頼み方の型は、M2で学んだものと同じです。

```text
依頼  「勤怠管理ツールの候補を5つ調べて、
       料金・機能・導入実績の比較表にまとめて。
       出どころのリンクも付けて」
```

完了の形(比較表と軸)とできの基準に加えて、出どころを求めるのが調査の作法です。受け取りの確認も、出どころが中心になります。

| 見る点 | やること |
| --- | --- |
| 出どころ | リンク先が実在し、内容が合っているか数件たどる |
| 鮮度 | いつの情報かを見る |
| 網羅 | 比較の軸に抜けがないか |

Webから集めた情報は、正しさも鮮度もまちまちです。突き合わせて確かめるまでが調査の仕事で、それは自分の側に残ります。

## 4-1-3 文書づくりは文書の道具で

> **体裁の決まった文書ファイルに仕上げる作業は、文書向けのプラグインが向いています**

2つ目の用途は文書づくりです。中身は頭の中にできているのに、WordやExcelの体裁を整える作業で時間が溶ける。チャットで作った文章を貼り直して、見出しと表を組み直す二度手間もここに入ります。

**文書** は、報告書・議事録・スライドのように、決まった体裁を持つ成果物のファイルです。文章そのものを考えることではなく、ファイルとしての仕上げが、文書向けの道具の出番です。

```text
依頼  「この材料から月次報告書を作って。
       見本.docx と同じ構成で、
       Wordファイルとして仕上げて」
```

M2の「見本を置いて指す」がそのまま効きます。受け取る形式(Wordファイルなど)まで依頼に書くのがこつです。

| | 中身(何を書くか) | 体裁(どう見せるか) |
| --- | --- | --- |
| 決める人 | 自分が判断する | 見本や書式に従う |
| 頼み方 | 材料と方針を渡す | 見本を指して任せる |

体裁は、正解が見本の形で存在するため、任せやすい仕事の代表です。逆に、何を書くか・何を載せないかという判断は、道具が肩代わりしません。

## 4-1-4 画面の作業はブラウザ操作で

> **Webの画面を開いて進める作業は、ブラウザ操作のプラグインに任せられます**

3つ目の用途は、ファイルにもチャットにも収まらない「画面の上の作業」です。社内システムの繰り返し入力、複数サイトの巡回確認。手作業のまま残りがちな領域です。

**Web** の画面を開き、読み、入力する操作を任せるのが **ブラウザ操作** の道具です。対象がファイルではなく画面のとき、この道具が候補になります。

```text
20件の申請ページを開いて、状態を一覧に写す
複数のサイトの掲載内容を確かめて回る
決まった手順のフォーム入力を繰り返す
```

共通するのは、決まった手順の繰り返しだという点です。1件ごとに判断が変わる操作は向きません。

そして、この用途こそM3の型がいちばん効きます。

| 特徴 | 心がけ |
| --- | --- |
| 操作が実際の画面に及ぶ | 対象と手順を依頼で絞る |
| 入力は相手のシステムに残る | 送信・登録の前に途中経過で確かめる |

画面への入力は、相手のシステムに残ります。取り消しにくい操作ほど、実行される手前の途中経過で確かめてください。この「取り消しにくいものほど手前で見る」という感覚は、次のモジュールの安全の話につながります。

## もっと知りたい人へ

- 自分の1週間から「決まった手順の繰り返し」を探してみてください。調査・文書・画面のどれかに当てはまれば、それが道具に頼む最初の候補です
- どの道具が入っているか、何が足せるかは環境によって違います。実際の一覧は、使う環境のドキュメントや管理者に確認してください
- 3つの用途に収まらない作業は、無理に道具へ寄せず、まずチャットで相談するところから始めると外しません
