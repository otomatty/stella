# 計画を先に見る

Cowork入門 — Module 3 / レッスン3-1

<!-- ノート: タスクの序盤で自分がやることの話です。 -->

---

## なぜ必要か

- 走り出しの向きがずれていると、その後の全ステップがずれる
- 全部終わってから「そういうつもりじゃなかった」と言うのが、いちばん高くつく

<!-- ノート: つかみ。直す費用は早いほど安い、という当たり前を任せる作業に当てはめます。 -->

---

## 結論

**Claudeは作業を手順に分けて進めるので、まず計画を見て任せる範囲を確かめます**

- **手順** — 作業を分けた1つずつのステップ
- **計画** — どんな手順で進めるかの見取り図。作業の前や序盤に示される

<!-- ノート: 結論を先に言い切ります。まとまった作業は一気に終わるのではなく、手順を踏んで進みます。その見取り図が計画です。 -->

---

## 計画の読み方

```text
計画の例  1. 30本の資料を読む
          2. 会社名・担当者・更新日を抜き出す
          3. 一覧表にまとめて並べ替える
見る点    やってほしいことが入っているか / 余計なことが入っていないか
```

<!-- ノート: 最小の例です。見る点は2つだけ。足りないものと、任せたつもりのないものです。 -->

---

## 見るのは序盤がいちばん安い

| 気づく時点 | 直す費用 |
| --- | --- |
| 計画の時点 | 一言直すだけ |
| 途中 | 進んだ分の一部をやり直し |
| 仕上がり後 | 大きくやり直し |

<!-- ノート: 図解の代わりの費用表です。見極めるの最初の出番が、仕上がりではなく計画だという点がこのトピックの要点です。 -->
