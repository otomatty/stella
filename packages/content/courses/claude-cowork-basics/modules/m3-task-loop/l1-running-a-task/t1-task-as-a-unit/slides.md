# 3-1-1
# タスクは任せる単位

Cowork入門 — Module 3 / レッスン3-1

<!-- ノート: ここからM3、この講座の中心です。任せてから受け取るまでの1周を見ていきます。 -->

---

## なぜ必要か

- 依頼を出したあと、自分の作業が「今どういう状態なのか」を指す言葉がない
- 複数の頼みごとを同時に進めると、どれが何をしているのか分からなくなる

<!-- ノート: つかみ。単位に名前が付くと、状態を話せるようになります。ここで結論は言わない。 -->

---

## 結論

**Coworkに依頼したひとまとまりの作業は、タスクという単位で進んでいきます**

- **タスク** — 依頼から仕上がりまでを1つと数える、任せた作業の単位

<!-- ノート: 結論を先に言い切ります。依頼1つがタスク1つになり、始まりと途中と終わりを持ちます。 -->

---

## タスクの一生

```text
依頼を出す → タスクが始まる
           → 進む(途中がある)
           → 終わる(仕上がりを受け取る)
```

<!-- ノート: 最小の流れです。この「途中がある」が、チャットの一往復との大きな違いです。以降のトピックで途中を扱います。 -->

---

## 単位があると数えられる

| | 単位がないと | タスク単位だと |
| --- | --- | --- |
| 状態の把握 | なんとなく待つ | 進行中・完了で見える |
| 同時の頼みごと | 混ざる | 1つずつ並べて追える |
| 振り返り | 記憶頼み | タスクごとに残る |

<!-- ノート: 対比枠。並行して任せられるのもタスク単位があるからです。まず1つずつ確実に回せるようになるのがこのモジュールの目標です。 -->

---
