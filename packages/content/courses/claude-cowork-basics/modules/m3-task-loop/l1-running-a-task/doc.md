# レッスン3-1 タスクを任せて見守る

## このレッスンの目標

- [ ] タスクの始まりから完了までの1周を説明できる
- [ ] 計画と途中経過のどこを見るかを言える
- [ ] ずれに気づいたときに止めて直す判断ができる

## 3-1-1 タスクは任せる単位

> **Coworkに依頼したひとまとまりの作業は、タスクという単位で進んでいきます**

このモジュールは、講座の中心です。任せてから受け取るまでの1周を、順に見ていきます。

依頼を出すと、ひとまとまりの作業が **タスク** として始まります。依頼1つがタスク1つです。タスクには始まりと途中と終わりがあります。

```text
依頼を出す → タスクが始まる
           → 進む(途中がある)
           → 終わる(仕上がりを受け取る)
```

「途中がある」が、チャットの一往復との大きな違いです。単位に名前が付くと、状態を扱えるようになります。

| | 単位がないと | タスク単位だと |
| --- | --- | --- |
| 状態の把握 | なんとなく待つ | 進行中・完了で見える |
| 同時の頼みごと | 混ざる | 1つずつ並べて追える |
| 振り返り | 記憶頼み | タスクごとに残る |

複数のタスクを並行して任せることもできますが、まずは1つを確実に回せるようになるのが、このレッスンの目標です。以降のトピックで、この1周を「計画 → 途中 → 止めて直す → 確認して完了」の順にたどります。

## 3-1-2 計画を先に見る

> **Claudeは作業を手順に分けて進めるので、まず計画を見て任せる範囲を確かめます**

まとまった作業は、一気に終わるのではなく、**手順** を踏んで進みます。どんな手順で進めるかの見取り図が **計画** で、作業の前や序盤に示されます。

タスクの序盤で自分がやることは、この計画を読むことです。見る点は2つだけです。

```text
計画の例  1. 30本の資料を読む
          2. 会社名・担当者・更新日を抜き出す
          3. 一覧表にまとめて並べ替える
見る点    やってほしいことが入っているか / 余計なことが入っていないか
```

なぜ序盤に見るのか。走り出しの向きがずれていると、その後の全ステップがずれるからです。直す費用は、気づくのが早いほど安く済みます。

| 気づく時点 | 直す費用 |
| --- | --- |
| 計画の時点 | 一言直すだけ |
| 途中 | 進んだ分の一部をやり直し |
| 仕上がり後 | 大きくやり直し |

「見極める」の最初の出番は、仕上がりではなく計画です。ここで一言直しておくことが、いちばん割のよい確認です。

## 3-1-3 途中経過はときどき見る

> **タスクの途中経過は画面で追えるので、任せきりにせずときどき確かめます**

タスクが走っている間、自分はどう関わるか。両極端はどちらも失敗します。任せたきり見ないのは放置で、ずれに最後まで気づけません。かといって張り付いて全部見るなら、任せた意味がありません。

Coworkは、いまどの手順まで進み、何をしているかという **途中経過** が画面で見える作りになっています。見えるものは見る。ただし、ときどきで構いません。

```text
見るタイミング  手順の区切り / 席に戻ったとき / 通知が来たとき
見るもの        計画のどこまで進んだか
                いま作られているものが依頼の向きと合っているか
```

| | 放置 | ときどき見る | 張り付き |
| --- | --- | --- | --- |
| ずれへの気づき | 最後まで気づかない | 区切りで気づける | すぐ気づく |
| 自分の時間 | 空くが危険 | ほぼ空く | 空かない |

「ときどき見る」は、任せて空いた時間の自由と、見極めの両立点です。毎秒ではなく、区切りで見る定点観測だと考えてください。

## 3-1-4 途中で止めて直せる

> **ずれに気づいたら、タスクは途中で中断して、軌道修正してから続けられます**

途中経過を見る意味は、見るだけでは半分です。ずれに気づいたら、手を入れられます。

タスクはいったん **中断** できます。止めたところで、M2で学んだ追いの指示を使って向きを直し、続きから進めてもらう。これが **軌道修正** です。最初からやり直しにはなりません。

```text
途中経過  一覧の会社名が略称のまま進んでいる
中断      いったん止める
軌道修正  「会社名は正式名称で。ここまでの分も直して」
続行      直した向きで続きが進む
```

止めることをためらう必要はありません。

| 思い込み | 実際 |
| --- | --- |
| 止めるのは任せ方の失敗 | ループの想定内の操作 |
| 直しは全部やり直し | ずれた分だけ直して続行 |
| 黙って最後まで待つのが礼儀 | 早い軌道修正ほど安い |

相手は人ではないので、途中で口を挟む遠慮は要りません。見て、止めて、直して、続ける。これがタスクループの真ん中の動きです。

## 3-1-5 確認までが自分の仕事

> **タスクの完了は、成果物を自分で確認してから決めるもので、確認は自分の仕事です**

タスクが最後まで進むと、「終わりました」という状態になります。ここで区別したい言葉が2つあります。作業が終わったことと、仕事が **完了** したことです。

作業の終わりは、Claudeの側の表示です。仕事の完了は、成果物を自分で **確認** してから、自分が決めます。体裁の整った成果物ほど中身を見ずに信じたくなりますが、講座2で扱ったとおり、仕上がって見えても確かめるまでは仮説です。

確認の物差しは、すでに自分で書いてあります。M2の依頼に入れた完了の形とできの基準です。

```text
依頼      「列は 会社名・担当者・最終更新日。更新日が新しい順」
確認      列はそろっているか → 並び順は合っているか
          → 数本を元の資料と突き合わせて中身を見る
```

形式だけでなく、抜き取りでよいので中身まで見ます。数本を元の資料と突き合わせれば、系統的なずれはたいてい見つかります。

| | 作業が終わった | 仕事が完了した |
| --- | --- | --- |
| 決める人 | Claude側の表示 | 自分 |
| 根拠 | 手順を終えた | 確認を通った |
| 次の行動 | 確認を始める | 提出・共有する |

「終わりました」の表示は、確認の開始合図であって、提出の許可ではありません。ここが「責任を持つ」の実体です。これでループが1周しました。任せる → 計画を見る → 途中を見る → 止めて直す → 確認して完了。この型は、この先どんな作業を任せるときも変わりません。

## もっと知りたい人へ

- 人に仕事を頼むときの「最初に段取りを合わせ、節目で報告をもらい、納品物を検収する」という流れと、このループは同じ形をしています。人への頼み方がうまい人は、Coworkにもうまく頼めます
- 抜き取り確認のやり方は、講座(テスト設計と品質保証 入門)の考え方が参考になります
- 画面上の表示や通知のしかたは変わっていきます。実際に使うときは、製品のドキュメントで確認してください
