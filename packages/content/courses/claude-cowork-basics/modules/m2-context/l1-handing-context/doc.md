# レッスン2-1 文脈を渡す

## このレッスンの目標

- [ ] 作業の前提になる文脈を自分で選んで渡せる
- [ ] 最初の依頼に完了の形とできの基準を書ける
- [ ] 足りない情報を途中から渡す方法を説明できる

## 2-1-1 使えるのは渡した文脈だけ

> **Claudeが作業に使えるのは渡した文脈だけなので、要る材料は自分で選んで渡します**

M1で作業場所が決まりました。次は、そこに何を入れるかです。

Claudeは、社内の事情も、あなたの部署の慣習も知りません。作業の前提になる情報のまとまりを **文脈** と呼びます。文脈は、依頼の文章と、見える範囲に置いた **材料** でできています。逆に言えば、渡していないものは文脈に入りません。

チャットなら、ずれた返答は一往復で直せました。まとまった作業では、ずれたまま何ステップも進んでから気づくことになります。だから、文脈は最初に選んで渡す価値があります。

```text
頼んだこと   「いつもの形式で報告書にして」
渡した文脈   資料だけ(「いつもの形式」の見本なし)
結果         知らない形式で仕上がってくる
```

頭の中の「いつもの」は、渡さない限り存在しません。作業を任せる前に、次の3つを確かめてください。

| 問い | やること |
| --- | --- |
| 前提を知らない人に渡して伝わるか | 依頼の文章に前提を書き足す |
| 見本・過去の例はあるか | ワークスペースに入れる |
| 社内だけの言葉を使っていないか | 一言の説明を添える |

目安は「新しく来た同僚に引き継ぐつもりで書く」です。人に引き継げる粒度の文脈は、Claudeにも伝わります。

## 2-1-2 最初の依頼に完了の形を書く

> **最初の依頼には、何ができたら完了かという成果物の形とできの基準を書きます**

文脈の中心は、最初の依頼です。書き方の型は講座2と同じで、成果物の形と、良し悪しを分ける軸である **できの基準** を先に書きます。新しい型は増えていません。同じ型の重要度が上がった、というのがこのトピックの話です。

「資料を整理して」という丸投げをチャットですると、ずれても一往復で直せます。任せる作業で同じことをすると、想像で補われた整理が最後まで走ります。

```text
避ける 「顧客資料を整理して」
よい   「顧客資料30本を1枚の一覧表にして。
        列は 会社名・担当者・最終更新日。
        更新日が新しい順に並べる」
```

下の依頼からは、成果物の形(一覧表と列)と、できの基準(並び順)が読み取れます。

| | 完了の形なし | 完了の形あり |
| --- | --- | --- |
| 作業中 | 想像で補われる | 書いた形に向かう |
| 受け取り時 | 良し悪しを言えない | 基準と見比べるだけ |
| ずれたとき | どこからずれたか不明 | どの条件が外れたか指せる |

先に書いた完了の形は、あとで途中経過や仕上がりを確かめるときの物差しにもなります。M3でこの物差しを使います。

## 2-1-3 資料は置いて指し示す

> **参照してほしい資料はワークスペースに置き、依頼の中でどれを見るかを指し示します**

文章で書きにくい材料もあります。報告書の体裁、過去の成果物の構成、作業対象のデータそのものです。こうしたものは **資料** としてファイルの形で渡します。

コツは「置く」と「指す」を1セットにすることです。置いただけでは、どれが見本でどれが対象か伝わりません。逆に、実物を置かずに文章で説明しようとすると、長くなるうえに伝わりません。

```text
ワークスペースに置く   見本.docx / 元データ30本
依頼で指し示す         「『見本.docx』と同じ構成で、
                        『元データ』フォルダの30本をまとめて」
```

形式の説明を100行書くより、見本1つを指すほうが正確です。使い分けの線は次のとおりです。

| 渡したいもの | 向く渡し方 |
| --- | --- |
| 完了の形・並び順・条件 | 依頼の文章に書く |
| 体裁・構成の見本 | 見本ファイルを置いて指す |
| 作業の対象そのもの | フォルダごと置いて指す |

言葉で言える条件は文章で、形そのものは実物で。この2本立てが、文脈の渡し方の基本形です。

## 2-1-4 足りない情報は途中で足す

> **足りない情報は、質問に答えるか追いの指示で、作業の途中からでも渡せます**

ここまでを読むと、完璧な依頼を書き切らないと任せ始められない気がしてきます。実際はその必要はありません。渡し漏れた情報は、途中から渡す道が2つあります。

1つ目は **質問** に答えることです。進めるのに足りない情報があると、Claudeの側から聞いてくることがあります。答えれば、そこから作業が続きます。

2つ目は **追いの指示** です。途中経過を見て気づいたことを、自分から書き足して渡します。

```text
質問に答える   Claude「並び順の指定はありますか?」
               自分  「更新日が新しい順で」
追いの指示     自分  「会社名は正式名称に直して進めて」
```

どちらも、作業を最初からやり直さずに文脈を増やせます。そのうえで、最初に書くべきものと、後で足せばよいものの線引きはこうなります。

| | 最初の依頼に書く | 途中で足せばよい |
| --- | --- | --- |
| 内容 | 完了の形・できの基準 | 細部の選択・例外の扱い |
| 理由 | 作業全体の向きを決める | 進んでから見えてくる |

向きを決める情報だけは最初に書く。細部は進んでから足せる。この線引きがあれば、「書き切れないから出せない」で止まることはなくなります。
