# 2-1-2
# 最初の依頼に完了の形を書く

Cowork入門 — Module 2 / レッスン2-1

<!-- ノート: 講座2で学んだ依頼の型を、任せる作業に持ち込むトピックです。 -->

---

## なぜ必要か

- 「資料を整理して」だけで任せると、想像と違う整理が最後まで進んでしまう
- チャットと違い、ずれたまま何ステップも先まで走ってしまう

<!-- ノート: つかみ。丸投げの被害が、一往復のときより大きくなるのが任せる作業です。ここで結論は言わない。 -->

---

## 結論

**最初の依頼には、何ができたら完了かという成果物の形とできの基準を書きます**

- **できの基準** — 良し悪しを分ける軸。講座2で扱った語です
- 書き方の型は講座2と同じ。任せる量が増えるほど、先に書く価値が上がります

<!-- ノート: 結論を先に言い切ります。新しい型は増えていません。同じ型の重要度が上がった、という話です。 -->

---

## 完了の形まで書いた依頼

```text
避ける 「顧客資料を整理して」
よい   「顧客資料30本を1枚の一覧表にして。
        列は 会社名・担当者・最終更新日。
        更新日が新しい順に並べる」
```

<!-- ノート: 最小の例です。下の依頼は、成果物の形(一覧表と列)とできの基準(並び順)が読めます。 -->

---

## 書いた分だけ確認が楽になる

| | 完了の形なし | 完了の形あり |
| --- | --- | --- |
| 作業中 | 想像で補われる | 書いた形に向かう |
| 受け取り時 | 良し悪しを言えない | 基準と見比べるだけ |
| ずれたとき | どこからずれたか不明 | どの条件が外れたか指せる |

<!-- ノート: 対比枠。先に書いた完了の形は、M3で途中経過や仕上がりを確かめるときの物差しになります。 -->
