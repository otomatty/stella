# レッスン5-1 向き不向きと安全

## このレッスンの目標

- [ ] Coworkに向く仕事と向かない仕事を仕分けられる
- [ ] ファイルアクセスと機密情報の扱いを説明できる
- [ ] コードの作業をClaude Codeへ送る判断ができる

## 5-1-1 向くのは手で回すと重い仕事

> **Coworkに向くのは、完了の形を言えて、手で回すと重いまとまった仕事です**

最後のモジュールは、何を任せ、何を任せないかの線引きです。道具がそろうと何でも任せたくなりますが、向かない仕事に使って「使えない」と結論づけるのが、いちばん多い失敗です。道具の評価は、仕事の選び方で決まります。

**向き不向き** の判定は、条件2つで足ります。

```text
条件1  完了の形が言える   「一覧表になったら完了」と書ける
条件2  手で回すと重い     量が多い / ステップが多い
両方〇 資料30本の一覧化、履歴の分類、見本どおりの文書化
```

条件1は、M2の依頼が書けるかと同じことです。条件2は量の感覚で、一往復で終わる仕事はまとまりに仕立てる価値がありません。

| 条件の状態 | 判断 |
| --- | --- |
| 完了の形が言えない | まず自分で形を決める(任せるのはまだ) |
| 手で回しても軽い | 自分でやるかチャットで済ます |
| 両方満たす | Coworkに任せる候補 |

完了の形が言えない仕事を任せると、丸投げになるだけです。形を決めるのは自分の仕事で、それが済んでから任せます。

## 5-1-2 向かない仕事は無理に任せない

> **一言の相談や、その場の判断が続く仕事は、チャットや自分の手のほうが早く終わります**

覚えた道具は使いたくなります。一言の質問まで、わざわざ任せる形に仕立ててしまう。すると、仕立てる手間のほうが仕事そのものより大きくなります。

向かない形は、大きく2つです。1つは単位が小さい仕事で、答えを一往復でもらえば済む **相談** はチャットが最速です。もう1つは、その場の判断が連続する仕事です。

```text
一言で済む       エラー文の意味を知りたい → チャットで聞く
判断が連続する   相手の出方で変わる交渉・調整 → 自分でやる
形を決める前     何を作るか自体が未定 → まず考える(相談はできる)
```

3行目は補足です。何を作るか決める前の壁打ち相手として、チャットは十分使えます。任せるのは、形が決まってからです。

迷ったら、この順で自分に聞いてください。

| 問い | 答えと行き先 |
| --- | --- |
| 一往復で済むか | はい → チャット |
| 完了の形を言えるか | いいえ → まず自分で決める |
| 両方くぐったか | はい → Coworkの候補 |

任せない判断も、4Dの「任せる」の一部です。

## 5-1-3 渡した範囲がそのまま影響の範囲

> **Coworkはファイルアクセスで実際に読み書きするので、渡した範囲がそのまま影響の範囲です**

ここから安全の話を3つ続けます。まず、チャットとの安全上の一番の違いです。

チャットでは、提案の文章が画面に出るだけで、手元は変わりませんでした。Coworkは **ファイルアクセス** を持ちます。ワークスペースの中のファイルを実際に読み、書き換えます。

```text
チャット   提案の文章が画面に出る(手元は変わらない)
Cowork    ワークスペースのファイルが実際に変わる
          → 便利さと影響は同じ1つの働きから来る
```

成果物をコピーせずそのまま受け取れる便利さと、手元の実物が変わるという影響は、同じ読み書きの力から来ています。だから、影響の側だけ消すことはできません。代わりに、範囲を自分で決められます。

| M1で学んだこと | 安全の言葉で言うと |
| --- | --- |
| 見える範囲はワークスペースの中だけ | 影響もその中に閉じる |
| 置き場所は作業ごとに選ぶ | 巻き込まれる物を減らす |
| 専用フォルダを作る | 影響の上限を自分で決める |

新しい操作は何もありません。M1で身につけた置き場所の習慣が、そのまま安全設計だったという種明かしです。

1つだけ、この閉じ方の例外を押さえてください。「影響がその中に閉じる」のは、ファイルの読み書きについての話です。M4で扱ったブラウザ操作のように、会話の外のWebのシステムへ働きかける作業は、入力や送信が相手のシステムに残るため、フォルダの境界では閉じません。そこでは範囲の代わりに、送信・登録のような取り消しにくい操作の手前で自分の確認を挟むことが境界になります。

範囲のほかに、材料の中身から来る危険も1つ覚えておいてください。Webページやメール、外部から受け取ったファイルには、AIへの指示のように読める文章が混ざっていることがあります(プロンプトインジェクションと呼ばれる手口です)。Claudeは材料を読んで作業するため、こうした文章が作業の向きをゆがめる余地があります。構えは2つです。出どころの分からない材料をワークスペースに入れないこと。そして、送信や削除のような取り消しにくい操作の手前では、任せきりにせず自分の確認を挟むことです。

## 5-1-4 機密情報は入れる前に確かめる

> **ワークスペースに材料を入れる前に、それが社外に出せない機密情報でないかを確かめます**

安全の2つ目は、範囲の中に入れる物の話です。

便利になるほど、フォルダごと渡す動きが習慣になります。事故は悪意からではなく、この習慣の中に **機密情報**(顧客の個人情報・社外秘・パスワードなど)がまぎれ込むことで起きます。

確かめるタイミングが要点です。入れてから気づくのでは遅いので、入れる前に確かめます。

```text
1. 顧客や社員の個人情報が入っていないか
2. 社外秘のラベルが付いた資料ではないか
3. パスワードや鍵のファイルがまぎれていないか
→ 引っかかったら 外して渡す / 消して渡す / 会社のルールを確かめる
```

| 状況 | 行動 |
| --- | --- |
| 機密と分かっている | 入れない。必要なら外して渡す |
| 判断がつかない | 会社のルール・管理者に確かめる |
| 急いでいる | 急ぎは理由にならない。同じ手順 |

何をどこまで渡してよいかのルールは、会社や契約ごとに違います。この講座で型にできるのは「入れる前に確かめる」「迷ったら自分で決めずに確かめる」までです。ここが「責任を持つ」の実践になります。

## 5-1-5 戻せるようにしてから任せる

> **ファイルを直させる前に、バックアップなど元に戻せる手を用意してから任せます**

安全の3つ目は、書き換えられる側の備えです。

既存のファイルを直させる作業では、元の状態が失われると取り返しがつきません。「うまくいくはず」で始めると、うまくいかなかったときの戻り道がありません。そこで、任せる前に **バックアップ** を用意します。順番が大事です。任せてからではなく、先に取ります。

```text
直させる前   元ファイルをワークスペースの外へコピーして退避
依頼の工夫   「元は残して、直した版を別ファイルで作って」
確認のあと   問題なければ置き換え、退避した分を片づける
```

置き場所に1つだけ決まりがあります。退避先は、ワークスペースの **外** に置きます。中に置くと、そこも読み書きの範囲に入るため、まとめて直す作業のずれが退避分まで及びえて、戻り道になりません。そのうえで、コピーを取るか、元を残す依頼にするか。どちらでも戻る道が残ります。備えの重さは、書き換えの深さに合わせます。

| 作業の種類 | 備え |
| --- | --- |
| 読んでまとめる(新しいファイルを作る) | 原則そのまま。代えの利かない原本はコピーを渡す |
| 既存のファイルを直させる | 先にバックアップを取る |
| 置き換え・削除を含む | バックアップ+途中経過を必ず見る |

全部の作業に重装備は要りません。ただし、読むだけの依頼でも、ワークスペースに対する書き込みの力そのものは残ります。代えの利かない原本を扱うときは、原本を外に置いてコピーを材料として渡せば、頼み方によらず戻り道が残ります。深く書き換えるほど、備えを1段ずつ足してください。

## 5-1-6 コードはClaude Codeへ送る

> **コードを書き換える作業はCoworkに混ぜず、開発向けのClaude Codeで進めます**

最後に、向き不向きのもう1本の線を引きます。エンジニアの仕事には、資料と同じ顔をして **コード** の作業がまぎれ込みます。「ファイルを直すのは同じだから」とCoworkに流したくなりますが、ここは分けます。

コードを書き換える作業は、講座2でも登場した **Claude Code** の領分です。手元の開発環境でコードを対象に使う、開発者向けの製品です。

```text
資料・文書・調査・画面の作業   → Cowork
リポジトリの中のコードを直す   → Claude Code
迷う例: 手順書の中のコマンド修正 → 手順書は文書。実コードの変更が要るなら送る
```

分ける理由は、確かめ方の違いです。

| | 文書の作業 | コードの作業 |
| --- | --- | --- |
| 確かめ方 | 見比べて読む | 動かして試す(テスト) |
| 向く製品 | Cowork | Claude Code |
| 学ぶ場所 | この講座 | 次の講座 |

文書は見比べて確かめられますが、コードは動かして確かめる世界で、そのための道具立てを持つのがClaude Codeです。これは、Coworkがコードに一切触れられないという意味ではありません。この研修シリーズでの持ち場の線引きとして、リポジトリの中のコードを直す仕事はClaude Code側に置く、という方針です。開発の任せ方は次の講座で扱います。

これでこの講座は終わりです。任せる仕事を選び、場所と文脈を渡し、タスクの途中を見て、確認して完了を決める。この型は、製品が変わってもそのまま持っていけます。

## もっと知りたい人へ

- 機密情報の扱いは、必ず自分の会社のルールを確かめてください。この講座の3問チェックは最低限の型で、会社のルールが優先します
- バックアップの考え方は、Git 入門で扱う「歴史を残す」につながります。コードの世界では、この備えが仕組みとして組み込まれています
- Claude Code の導入と操作は、後続の講座で扱います。この講座では「送る判断」ができれば十分です
