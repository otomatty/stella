# レッスン1-1 ワークスペースを決める

## このレッスンの目標

- [ ] ワークスペースが何かを説明できる
- [ ] Claudeに見える範囲がどこまでかを説明できる
- [ ] 作業に合わせた置き場所を選べる

## 1-1-1 ワークスペースは作業場所

> **ワークスペースは、Coworkが作業に使うフォルダで、その中が作業場所になります**

チャットには貼り付け欄しかありませんでした。Coworkで最初に出てくる新しい概念が、作業場所です。

**ワークスペース** は、Coworkに「ここで作業してください」と渡す **フォルダ** です。机にたとえると分かりやすくなります。作業のための机を1つ決めて、材料になる **ファイル** をその上に載せる。Claudeはその机の上で資料を読み、その机の上に結果を作ります。

```text
やること   資料30本を一覧に整理してほしい
作業場所   フォルダ「2026-顧客資料」をワークスペースにする
           → この中の資料を読み、この中に一覧を作る
```

依頼と作業場所の2点セットで、作業が始まります。

| | チャット | Cowork |
| --- | --- | --- |
| 材料の渡し方 | 本文に貼る・添付する | フォルダごと渡す |
| 作業の場所 | 会話の画面の中 | ワークスペースの中 |
| 数が多いとき | 貼るほど大変 | 置けば渡る |

なお、作業場所の作り方や呼び名は製品側で変わります。複数のフォルダや、毎回使う指示をまとめて1つの作業場所として束ねられる形になることもあります。変わらないのは、自分が渡した範囲が作業場所になる、という原則です。

貼るという運搬がなくなる代わりに、「どの範囲を渡すか」という判断が生まれます。このモジュールの残りは、その判断の話です。

## 1-1-2 見える範囲はその中だけ

> **Claudeが読めるのも直せるのも、ワークスペースとして渡した見える範囲の中だけです**

「パソコンで作業させる」と聞くと、2つの思い込みが生まれます。1つは不安の側で、パソコンの中を全部見られてしまうのではないか。もう1つは過信の側で、渡していないフォルダの資料まで気を利かせて使ってくれるのではないか。

答えはどちらも同じ1つのルールです。**見える範囲** はワークスペースの中だけ。Claudeがファイルを読めるのも、直せるのも、渡した範囲に限られます。

```text
ワークスペース「2026-顧客資料」を渡した場合
  読める   その中の資料ファイル
  直せる   その中に作る一覧ファイル
  見えない 渡していない「人事評価」フォルダ
```

| 思い込み | 実際 |
| --- | --- |
| パソコン全部を見られてしまう | 見えるのは渡した範囲だけ |
| 入れていない資料も探してくれる | 範囲の外は使えない |

範囲の外は、Claudeにとって存在しないのと同じです。不安に対しては安心の根拠に、過信に対しては「使ってほしい材料は範囲の中に入れる」という段取りの根拠になります。

## 1-1-3 置き場所は作業ごとに選ぶ

> **ワークスペースには毎回、その作業で触ってよいものだけが入った置き場所を選びます**

範囲を自分で決められるなら、どう決めるのがよいか。ありがちな手抜きは、面倒だからといつも同じ大きなフォルダ、極端にはデスクトップ全体を渡すことです。

**置き場所** の基準は1つだけです。その作業で触ってよいものだけが入っているか。

```text
よい   作業ごとの専用フォルダ「2026-08-資料整理」を作って渡す
よい   その作業の材料だけが入った既存フォルダを渡す
避ける デスクトップ全体・個人フォルダごと渡す
```

迷ったら、専用フォルダを1つ作って材料を移すのが確実で速い方法です。

| | 専用の置き場所 | 大きすぎる置き場所 |
| --- | --- | --- |
| 読まれるもの | 作業の材料だけ | 関係ないものまで |
| 作業の精度 | 迷いにくい | 別の資料を拾って的を外す |
| あとの確認 | 変化が見つけやすい | どこが変わったか追いにくい |

広い範囲は、安全の問題になる前に、まず精度と確認のしやすさで損をします。関係ない資料を拾って作業が的を外し、終わったあとも、どこが変わったのかを追いにくくなります。機密の扱いはM5であらためて扱いますが、段取りの面だけでも、専用にする理由は十分です。

## 1-1-4 成果物はファイルで残る

> **仕上がった成果物は、ワークスペースの中にファイルとして残り、そのまま使えます**

チャットでは、もらった結果を自分でコピーしてファイルに移していました。会話の中に埋もれた結果を、あとから探し直した経験もあるはずです。

Coworkでは、**成果物** はワークスペースの中にファイルとして生まれます。

```text
依頼   資料30本を一覧に整理してほしい
結果   ワークスペースに「一覧.xlsx」ができている
       → コピーも貼り直しもせず、そのまま開いて使える
```

| | チャット | Cowork |
| --- | --- | --- |
| 結果の場所 | 会話の画面の中 | ワークスペースの中 |
| 使うまで | コピーして移す | そのまま開く |
| あとから | 会話をさかのぼる | ファイルを開き直す |

受け取るという作業自体が消えて、確かめる作業から始められます。ファイルで残るので、確認も普段使っている表計算や文書の道具でできます。環境によっては、成果物を画面で確かめてから保存する流れになることもありますが、成果物がファイルとして手元に残るという受け取りの形は変わりません。中身をどう確かめるかは、M3のタスクループで扱います。

## もっと知りたい人へ

- 手元のフォルダ構成を1つ見直してみてください。「この作業のためのフォルダ」と言える単位で分かれているほど、ワークスペースは決めやすくなります
- 見える範囲の考え方は、権限という言葉で他の道具にも共通します。渡した範囲だけが対象になる、という原則はCoworkに限りません
- 画面上の名称や操作は変わっていきます。実際に使うときは、製品のドキュメントで確認してください
