# Cowork 入門 カリキュラム

Claude Cowork に「まとまった作業を任せる」ときの進め方を扱う講座です。チャットとの違いから、
ワークスペース・文脈の渡し方・タスクループ・プラグイン・向き不向きと安全までが範囲です。
1 トピック = 覚えることが 1 つ(takeaway 1 文)の粒度で、**チャットとの違いを知る → 作業場所を決める →
文脈を渡す → 任せて途中を見る → 道具を足す → 向き不向きと安全を判断する** の順に通します。
Claude 研修シリーズの 3 本目にあたり、2 本目(Claude チャット入門)で学んだ「依頼の書き方」を、
複数ステップのデスクトップ作業に広げる位置づけです。

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- 手を動かす部分: `practice.md` の「手元で試す」。Cowork を開いて、ワークスペースを決めて小さな作業を任せます
- **Cowork が使えない環境でも完走できます。** 「手元で試す」は任意で、スライド・まとめ・確認クイズだけで
  修了条件を満たします(Git 入門の「手元で試す」と同じ逃げ道)
- コード演習(VS Code 拡張の採点)は **この講座にはありません**。学習対象が任せ方の判断であってコードではないため、
  `course.json` に `exercises` を持ちません
- 前提講座: **Claude チャット入門(`claude-chat-basics`)**。依頼に成果物とできの基準を書く型を
  一度通していることを想定します。ただし語彙台帳は講座をまたがないため、必要な語はこの講座で導入し直します
- 対象外:
  - プラグインの自作・詳細設定、MCP サーバーの自作
  - Claude Code のインストール・操作手順(M5 は「コードは Claude Code へ送る」という判断だけ)
  - API・SDK・課金・管理者設定
  - モデルの選び方、価格、上限値などの当日値
  - 画面のボタン名・メニュー配置の暗記(製品画面は変わる前提)

## 到達目標

1. チャットと Cowork の違いを **説明できる**
2. ワークスペースを決め、渡す文脈を **選べる**
3. 複数ステップの作業を任せて、途中経過を **見られる**
4. 調査・文書・ブラウザ作業のどれをプラグインに頼むかを **選べる**
5. ファイルアクセスと機密情報の扱いを **説明できる**
6. コードを触る作業は Claude Code に送る判断が **できる**

## この講座の進め方

- 各レッスンは **スライド → まとめ → 確認クイズ** の順で並びます
- `practice.md` の「手元で試す」は Cowork を開いて行います。手元のフォルダからワークスペースを決める、
  完了の形を書いた依頼で小さな作業を任せる、途中経過を見て止める、といった課題で、自動採点はありません
- **Cowork が使えない受講者は「手元で試す」を飛ばして構いません。** その場合もスライドと確認クイズだけで完走できます。
  クイズは操作の再現ではなく判断を問うため、画面を触っていなくても解けます
- 画面の並びやボタンの名前は変わります。困ったら製品のドキュメントを見る前提で、本文は「何のための仕組みか」だけを扱います
- スマートフォンからでも、スライドとまとめと確認クイズだけで最後まで進められます

## 設計メモ(申し送り)

- **語彙台帳は講座をまたぎません。** `claude-chat-basics` で説明済みの語も、この講座で `introduces` し直しています。
  再導入した語は Claude / チャット / 任せる / 依頼 / 4D / 伝える / 見極める / 責任を持つ / 成果物 / できの基準 /
  材料 / 機密情報 / Claude Code の 13 語です。**再導入は 1 行の復習で済ませ、初出のような長い説明にしないでください。**
  スライドでは「講座2で扱った語です」(4D は「講座1で扱った語です」)と一言添え、残りの時間を Cowork での使い方に使います
- **4D は M0 の 0-1-3 で再導入します。** この講座の主役は「任せる」で、M2 が伝える、M3 が見極めると責任を持つの
  実践になります。0-1-3 は導入語が 4 語と多いので、スライドでは 4D の一覧 1 枚に集約し、1 語 1 行に抑えてください
- **M1-1-3「置き場所は作業ごとに選ぶ」は、M5 の安全の伏線です。** M1 では「関係ないものが入らない場所を選ぶ」という
  段取りの話に留め、機密情報・バックアップの話は M5 まで先出ししないでください
- **タスクループの言い切りは「任せる → 途中を見る → 止める/続ける → 確認して完了」です。** M3 の 5 トピックは
  この 1 周を順に割ったものなので、順序を入れ替えないでください。3-1-5 の「確認までが自分の仕事」が講座全体の締めの型で、
  M5 でもこの型に戻ります
- **プラグインは用途で 3 つだけ扱います。** 調査・文書・ブラウザ操作の「どれに頼むか」だけが学習対象で、
  導入手順・設定画面・個別製品名は書きません。プラグインの自作・MCP サーバーは対象外です
- **画面の名称に寄りかからないでください。** ボタン名・メニューの位置・画面の並びは変わる前提です。
  takeaway は「何のためにその仕組みがあるか」に置き、**ボタン名だけが takeaway のトピックは作りません**。
  製品のスクリーンショットも貼りません(古くなりやすいため)。図解を足すなら「関係と流れ」(ワークスペースの
  見える範囲、タスクループの 1 周)を `.claude/skills/diagram-design/` の規約で自作してください
- **製品モデルを断定しない書き方にしています。** 作業場所の束ね方(複数フォルダ・常設の指示をまとめる形)、プラグインが何を
  同梱するか、成果物の受け取りの流れ(フォルダ直か、画面で確かめてから保存か)は製品側で変わります。本文は
  「渡した範囲だけが見える」「用途で道具を選ぶ」「成果物はファイルで残る」という原則だけを言い切り、当日の仕様は
  製品ドキュメントを見る前提です。安全面は、機密の確認・バックアップ(退避先はワークスペースの外)に加えて、
  外部由来の材料に混ざる指示(プロンプトインジェクション)への構えを `doc.md`(5-1-3)で扱っています
- **1 年後も通用する範囲に絞りました。** モデル名・価格・扱えるファイル数の上限・対応 OS は本文に書きません。
  「上限がある」ことは概念として扱い、実際の値は製品のドキュメントを見る、という書き方にします
- **評価は確認クイズと手元ハンズオンだけです。** 到達目標 1〜6 はすべて判断を問うため、クイズは用語の暗記ではなく
  「この仕事はチャットと Cowork のどちらか」「このフォルダをワークスペースにしてよいか」「途中経過がずれたら何をするか」
  という選択問題にしてください。Cowork が使えるかどうかで有利不利が出る設問(画面の色・ボタンの位置)は作りません
- **コード演習は配線しません。** 学習対象が任せ方の判断なので、`course.json` に `exercises` を持ちません
- **コード編集の本編はこの講座に混ぜません。** VS Code のエージェント操作・リポジトリの修正は Claude Code 入門の
  範囲です。この講座では 5-1-6 の「送る判断」までで止めます
- **サムネイルは生成済みです。** `packages/content/scripts/build_thumbnails.py` の `SPECS` に `claude-cowork-basics` を
  登録してあり、出力は `thumbnail.webp` です。モチーフは「ワークスペースのフォルダと、進んでいくタスクの列」で、
  この講座の中身(任せて途中を見る)を 1 つだけ図にしています。文言やモチーフを変えたときは
  `python packages/content/scripts/build_thumbnails.py claude-cowork-basics` で再生成してください。手描きはしません。
  既存講座と 1 つのシリーズに見えることが前提なので、色や版面はスクリプトに任せ、外部ロゴは使いません
- **シリーズの続きは別 slug です。** Claude Code の操作講座(#196)はこの講座に足さず、後続講座に置きます。
  この講座を大きくしないことが、シリーズ 3 本目としての役割です
