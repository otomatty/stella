# 7-1-1
# 共有責任モデル

AWS Cloud Practitioner 入門 — Module 7 / レッスン7-1

<!-- ノート: 配点30%のドメイン2の中心概念。前置詞1つの違いを固めるトピックです。 -->

---

## なぜ必要か

- 「クラウドだからセキュリティはAWSにお任せ」は危険な誤解
- 事故のとき「どちらの責任か」が曖昧だと、対策も曖昧になる
- AWSと利用者の分担には、公式の線引きがある

<!-- ノート: つかみ。任せた気になっていた部分の事故、が最悪のパターン。 -->

---

## 結論

**AWSは「クラウド本体の」安全を、利用者は「クラウドの中の」安全を守るのが共有責任モデル**

- **共有責任モデル** = セキュリティの分担を定めた公式の考え方
- 英語では Security **OF** the Cloud(AWS)と Security **IN** the Cloud(利用者)

<!-- ノート: 結論。of=本体、in=中身。前置詞の対で覚えるのが世界共通の定石。 -->

---

## 最小の例

| 担当 | 例 |
| --- | --- |
| AWS(本体) | データセンターの物理警備、ハードウェア、基盤ソフト |
| 利用者(中身) | 自分のデータ、アクセス権の設定、OSやアプリの設定 |

<!-- ノート: 建物の耐震と、部屋の施錠・貴重品管理、の例えを口頭で。 -->

---

## 試験での聞かれ方

- 「物理的なセキュリティは誰の責任?」→ AWS
- 「S3バケットの公開設定ミスは誰の責任?」→ 利用者
- 「顧客データの分類・保護は?」→ 利用者
- 設問の対象が「本体」か「中身」かだけを判定する

<!-- ノート: 補強枠。データと設定は常に利用者側、が最頻出。 -->
