# 7-1-5
# IAMロールは一時的な鍵

AWS Cloud Practitioner 入門 — Module 7 / レッスン7-1

<!-- ノート: ロールとユーザーの違い、キー埋め込みの禁止を固めるトピックです。 -->

---

## なぜ必要か

- EC2上のアプリからS3を読みたい。アプリに権限をどう持たせる?
- ユーザーの**アクセスキー**(プログラム用のID/パスワードに当たる鍵)をコードに書くと
- 漏れたら終わり。書き換えも大変

<!-- ノート: つかみ。キーのハードコードは事故の定番、と実感を込めて。 -->

---

## 結論

**IAMロールは人やサービスに一時的な権限を貸し出す仕組みで、アクセスキーの埋め込みをなくせる**

- **IAMロール** = 「かぶると権限が付く帽子」。特定の人に固定されない
- 引き受けた間だけ、一時的な認証情報が自動発行される

<!-- ノート: 結論。帽子・貸衣装の例え。長期の鍵を持たない、が本質。 -->

---

## 最小の例

| | IAMユーザー+アクセスキー | IAMロール |
| --- | --- | --- |
| 鍵の性質 | 長期に固定 | 一時的・自動更新 |
| コードへの記載 | 必要になりがち | 不要 |
| 漏えい時 | ずっと使われる | すぐ期限切れ |

<!-- ノート: EC2にロールを付ければ、アプリは鍵なしでS3へ、が定番構成。 -->

---

## 試験での聞かれ方

- 「EC2のアプリにS3への権限を安全に与える」→ IAMロールを付与
- 「認証情報をコードに埋め込まない方法」→ IAMロール
- 一時的に他アカウントへ権限を貸す場合もロール

<!-- ノート: 補強枠。「ロール=安全な貸し出し」の1語で締める。 -->
