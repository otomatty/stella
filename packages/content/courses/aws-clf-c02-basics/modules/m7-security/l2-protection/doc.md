# レッスン7-2 防御と情報源

## このレッスンの目標

- [ ] 保存時・転送時の暗号化とKMSの役割を説明できる
- [ ] WAF・Shieldを攻撃の種類、GuardDuty・Inspector・Security Hub・Artifactを役割の1語で区別できる
- [ ] Secrets Manager・ACM・Macieを「守る対象」で選べる

## 7-2-1 保存時と転送時の暗号化

> **データは保存時と転送時の両方で暗号化し、鍵はKMSで管理する**

データが盗まれる場面は2つあります。置いてある間と、運んでいる間です。片方だけ守っても、もう片方から漏れます。

- **保存時の暗号化**(at rest) — ディスクやストレージに置かれた状態の暗号化。S3・EBS・RDSは設定で暗号化でき、多くはチェック1つです
- **転送時の暗号化**(in transit) — ネットワークを流れる間の暗号化。ブラウザーとのHTTPS(TLS)通信が代表です

暗号鍵そのものの作成・管理を担うマネージドサービスが **KMS**(Key Management Service)です。試験では「保存データの暗号化に使う鍵の管理」がKMSの合図です。

注意点を1つ。暗号化してもアクセス権の設定は別問題です。暗号化された S3バケットでも、公開設定を誤れば漏えいします。暗号化と権限管理は両方やる、が正解です。

## 7-2-2 入口を守るWAFとShield

> **WAFはWebアプリを狙う攻撃を、ShieldはDDoS攻撃を防ぐ、入口の防御サービス**

公開したWebサイトには招かれざる通信も届きます。攻撃は大きく2系統に分かれ、系統ごとに専用の盾があります。

| 攻撃 | 例 | 防ぐ |
| --- | --- | --- |
| 中身が悪意 | SQLインジェクションなど不正な内容のリクエスト | **WAF** |
| 量で潰す | 大量アクセスで麻痺させる(**DDoS**攻撃) | **Shield** |

**WAF**(Web Application Firewall)はリクエストの中身を検査して弾く壁で、CloudFrontやELBに取り付けて使います。**Shield** はDDoSへの盾で、標準版はすべての利用者に自動で有効になっています(上位版のAdvancedもあります)。

M4のセキュリティグループとの違いも問われます。セキュリティグループは「どこからどのポートへの通信を許可するか」のフィルター、WAFは「リクエストの中身が攻撃パターンかどうか」の検査で、守っている層が違います。

## 7-2-3 脅威を見つけるサービス

> **GuardDutyは脅威検出、Inspectorは脆弱性診断、Security Hubはその結果の一元管理を担う**

防いでいても、侵入の兆候や設定の穴は生まれます。攻撃や不正アクセスの兆候を見つけることを **脅威検出**、攻撃に使われうる弱点を **脆弱性** と呼びます。検知系の3つは役割の1語で区別します。

| サービス | 一言 | 例え |
| --- | --- | --- |
| **GuardDuty** | ログを機械学習で分析し、怪しい動きを検出 | 警備員 |
| **Inspector** | EC2などの脆弱性を継続的に診断 | 健康診断 |
| **Security Hub** | 各サービスの検出結果を1画面に集約 | 司令室 |

名前は英単語の意味どおりです(guard=見張る、inspect=検査する、hub=集約点)。試験は動詞で選びます。「自動検出」ならGuardDuty、「スキャン・診断」ならInspector、「一元管理・集約」ならSecurity Hubです。

## 7-2-4 コンプライアンスの証明

> **AWS Artifactから第三者の監査レポートを取得して、AWS側の準拠状況を確認できる**

顧客や監査人から「AWSは安全だと証明してほしい」と求められても、データセンターを見学させてもらうことはできません。

法令や業界基準への準拠を **コンプライアンス**、基準を満たしているかの第三者による検査を **監査** と呼びます。**Artifact** は、AWSが受けた第三者監査のレポート(ISO、SOCなどの基準)をダウンロードできる窓口です。

| 求められたもの | やること |
| --- | --- |
| 「AWS側の準拠の証明を出して」 | Artifactからレポートを取得して提出 |
| 「自社側の設定の証明を出して」 | それは共有責任の利用者側(自分の仕事) |

2行目が本質です。Artifactが証明するのは「クラウド本体」の側だけで、「AWSが準拠しているから自社システムも自動で準拠」にはなりません。準拠も共有責任で分担する——ここまでが検知と証明の話です。

## 7-2-5 秘密・証明書・個人情報の守り

> **パスワードはSecrets Manager、証明書はACM、S3上の個人情報の発見はMacieに任せる**

暗号化の「鍵」はKMSに任せました。セキュリティの1日の締めくくりに、守る対象別の専門係を3つ足します。判定はどれも、問題文に出てくる **守る対象の名詞** で行います。

**Secrets Manager** は、データベースのパスワードやAPIキーといった秘密の文字列を預かる金庫です。アプリはコードに書く代わりに、実行時にSecrets Managerへ取りに行きます。しかも定期的な差し替え(ローテーション)を自動化できるため、「漏れたら長期間悪用される」というM7前半(アクセスキー)の問題も小さくできます。KMSとの違いは「KMSは暗号化に使う **鍵** そのもの、Secrets Managerは **秘密の文字列** を丸ごと」です。

**ACM**(AWS Certificate Manager)は、転送時の暗号化(HTTPS)に必要なTLS/SSL証明書を発行し、期限が来る前に自動更新するサービスです。証明書の期限切れはWebサイトが突然警告画面になる定番事故で、それを仕組みで防ぎます。

**Macie** は、S3の中身を機械学習で調べ、個人情報(PII)などの機密データがどこにあるかを発見・警告するサービスです。「気づかないうちに個人情報が置かれていた」を人手の棚卸しではなく自動で見つけます。GuardDuty(怪しい **動き** の検出)との違いは、Macieが見るのは **データの中身** だという点です。

| サービス | 守る対象 | シナリオの言い回し |
| --- | --- | --- |
| **Secrets Manager** | パスワード・APIキー | 「認証情報を安全に保管し自動ローテーション」 |
| **ACM** | TLS/SSL証明書 | 「証明書の発行と更新を自動化」 |
| **Macie** | S3上の個人情報 | 「保存されたPIIを自動で発見」 |

## もっと知りたい人へ

- リソースの設定変更を記録・評価するConfigはM8で、操作の記録(CloudTrail)と一緒に扱います
- アプリの「一般利用者のログイン機能」(会員のサインイン・サインアップ)を作るサービスとしてはCognitoがあります。AWSを操作する人の権限管理(IAM)とは別物、という対比で名前だけ拾っておいてください
