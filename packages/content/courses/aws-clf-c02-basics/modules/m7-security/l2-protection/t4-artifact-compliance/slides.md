# コンプライアンスの証明

AWS Cloud Practitioner 入門 — Module 7 / レッスン7-2

## なぜ必要か

- 顧客や監査人から「AWSは安全だと証明して」と求められる
- AWSのデータセンターを見学させてもらうことはできない
- 代わりに「第三者の証明書」を出す仕組みがある

<!-- ノート: つかみ。監査対応の実務シーン。自分で検査できない部分の証明をどうするか。 -->

---

## 結論

**AWS Artifactから第三者の監査レポートを取得して、AWS側の準拠状況を確認できる**

- **コンプライアンス** = 法令や業界基準への準拠
- **監査** = 基準を満たしているかの第三者による検査
- **Artifact** = その監査レポートのダウンロード窓口

<!-- ノート: 結論。ISOやSOCといった基準名は「そういうものがある」でよい。 -->

---

## 最小の例

| 求められたもの | やること |
| --- | --- |
| 「AWS側の準拠の証明を出して」 | Artifactからレポートを取得して提出 |
| 「自社側の設定の証明を出して」 | それは共有責任の利用者側(自分の仕事) |

<!-- ノート: 2行目が本質。Artifactが証明するのは「本体」の側だけ。 -->

---

## 試験での聞かれ方

- 「コンプライアンスレポート(監査文書)を入手する」→ Artifact
- 業界・地域ごとの要件(医療、金融、データ主権)への対応状況もここから
- 「AWSが準拠 = 自社システムも自動で準拠」ではない
