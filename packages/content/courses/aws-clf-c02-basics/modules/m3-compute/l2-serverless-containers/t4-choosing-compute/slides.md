## なぜ必要か

- EC2・Lambda・コンテナと選択肢が増えた
- 試験は「この用途ならどれ?」を選ばせる
- 判定の1行を用意しておけば迷わない

<!-- ノート: つかみ。ここまでの積み上げを1枚の表に集約する回、と位置づける。 -->

## 結論

**常時動かす自由度ならEC2、イベントごとの短い処理ならLambda、丸ごと任せるならElastic Beanstalkと用途で選ぶ**

- **Elastic Beanstalk** = コードを渡すと、EC2やELBの構成まで面倒を見てくれるPaaS型サービス
- 判定の軸は「何を管理したいか / したくないか」

<!-- ノート: 結論。Beanstalkはここで初出。裏でEC2等を組み立てる「おまかせ係」。 -->

---

## 最小の例

| 用途の一言 | 選ぶ |
| --- | --- |
| OSから自由に、常時稼働 | EC2 |
| きっかけごとの短い処理、管理ゼロ | Lambda |
| コンテナで動かす | ECS / EKS(土台を任せるならFargate) |
| コードを渡して環境は丸ごとおまかせ | Elastic Beanstalk |

<!-- ノート: この表がモジュールの成果物。1行ずつ読み上げる。 -->

---

## 迷ったときの判定順

1. コンテナと書いてある? → ECS / EKS / Fargate
2. 「イベントのたび」「管理なし」? → Lambda
3. 「デプロイを簡単に」「環境ごと任せたい」? → Beanstalk
4. それ以外の自由なサーバー用途 → EC2
