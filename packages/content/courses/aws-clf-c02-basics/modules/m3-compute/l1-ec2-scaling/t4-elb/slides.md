# ELBで負荷を分散

AWS Cloud Practitioner 入門 — Module 3 / レッスン3-1

<!-- ノート: マルチAZ+Auto Scalingと組む「入口の係」を覚えるトピックです。 -->

---

## なぜ必要か

- Auto Scalingで6台に増えた。ではアクセスはどの1台に届く?
- 利用者に「今日は3号機へ」とは頼めない
- 入口でさばく係が要る

<!-- ノート: つかみ。台数が増えると必ず出てくる「配る」問題。 -->

---

## 結論

**ELBは複数のインスタンスへリクエストを振り分け、負荷分散と故障した1台の切り離しを担う**

- **ロードバランサー** = リクエストを複数台へ振り分ける装置
- **ELB** = そのマネージドなサービス(Elastic Load Balancing)
- 振り分け = **負荷分散**

<!-- ノート: 結論。単一の入口の裏に複数台、という構図を絵で意識させる。 -->

---

## 最小の例

| 状況 | ELBの動き |
| --- | --- |
| 通常時 | 6台へ均等に振り分け |
| 3号機が故障 | 3号機を外して残り5台へ |
| Auto Scalingで2台追加 | 新しい2台も振り分け先に加える |

<!-- ノート: 故障の自動切り離し(ヘルスチェック)が高可用性に効く、が2行目。 -->

---

## 定番の組み合わせ

- ELB + Auto Scaling + 複数AZ = 止まりにくいWebの基本形
- ELBが配り、Auto Scalingが台数を保ち、AZが場所を分ける
- この3点セットはシナリオ問題の頻出パターン
