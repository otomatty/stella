# レッスン3-1 EC2と伸縮

## このレッスンの目標

- [ ] EC2がIaaSの仮想サーバーであることと、利用者の管理範囲を説明できる
- [ ] インスタンスタイプの系統を用途から選べる
- [ ] ELB・Auto Scaling・複数AZの3点セットの役割分担を言える

## 3-1-1 EC2は仮想サーバー

> **EC2は数分で起動できる仮想サーバーで、OSから上を利用者が自由に管理する**

アプリを動かすには、まず「計算する場所」(コンピュート)が要ります。その基準になるサービスが **EC2** です。

物理サーバーを仮想的に分割した、ソフトウェア上のサーバーを **仮想サーバー** と呼びます。EC2はAWSの仮想サーバーのサービスで、起動した1台を **インスタンス** と呼びます。

| 操作 | かかる時間 |
| --- | --- |
| インスタンスを起動する | 数分 |
| OSやソフトを選ぶ | 起動時に指定 |
| 使い終わって停止する | 数分。稼働分の課金は止まる |

注意点を1つ。停止で止まるのはインスタンスの「稼働分」の課金です。取り付けたディスク(M5で学ぶブロックストレージ)や確保したパブリックIPアドレスなど、関連リソースの課金は停止中も残ります。完全に支払いを止めるには、関連リソースまで確認して解放(削除)します。

EC2はIaaSの代表です。OSの選択もソフトウェアの導入も自由で、そのぶんOSから上(ミドルウェア・アプリ)の管理は自分の担当です。このモジュールでは、以降のコンピュートをすべて「EC2との比較」で覚えていきます。

## 3-1-2 インスタンスタイプの選び方

> **インスタンスタイプは、汎用・コンピュート最適化・メモリ最適化などの用途の系統で選ぶ**

EC2の起動画面には数百種類の型番が並びますが、全部を覚える必要はありません。CPU・メモリなどの構成の型を **インスタンスタイプ** と呼び、少数の「系統」に分かれています。CLF-C02で問われるのは系統と用途の対応までです。

| 系統 | 向いている用途 |
| --- | --- |
| 汎用 | Webサーバーなど、CPUとメモリのバランス型 |
| コンピュート最適化 | 計算が重い処理(動画変換、科学計算) |
| メモリ最適化 | 大きなデータをメモリに載せる処理(大規模な分析) |
| ストレージ最適化 | ディスクの読み書きが激しい処理 |

選び方は「何がボトルネックか」です。問題文に「メモリを大量に使う」「計算負荷が高い」と資源名がそのまま書いてあることが多く、対応する系統を選べば正解できます。系統選びは、M1で学んだライトサイジングの入口でもあります。

## 3-1-3 Auto Scalingで台数を増減

> **EC2 Auto Scalingは、需要に合わせてインスタンスの台数を自動で増減させる**

M1で「弾力性が大事」と学びましたが、実際に増減させるのは誰でしょうか。深夜のアクセス急増のたびに人が操作するのは現実的ではありません。条件に応じて台数を自動で増減させる仕組みが **Auto Scaling** です。

| 時間帯 | 負荷 | 台数 |
| --- | --- | --- |
| 昼 | 高い | 6台に自動で増える |
| 夜 | 低い | 2台に自動で減る |
| 障害時 | 1台停止 | 代わりを自動で補充 |

見落とされがちなのが3行目です。Auto Scalingは決めた台数を「維持」するので、不調になった1台の置き換えもします。

台数を増やして能力を上げる方法を **水平スケーリング**(スケールアウト)、1台のサイズを大きくする方法を垂直スケーリングと呼びます。Auto Scalingが自動化するのは水平の方です。垂直はインスタンスの再起動を伴いがちで、上限もあります。

## 3-1-4 ELBで負荷を分散

> **ELBは複数のインスタンスへリクエストを振り分け、負荷分散と故障した1台の切り離しを担う**

Auto Scalingで6台に増えても、アクセスをどの1台に届けるかという問題が残ります。リクエストを複数台へ振り分ける装置を **ロードバランサー** と呼び、そのマネージドなサービスが **ELB**(Elastic Load Balancing)です。振り分けること自体を **負荷分散** と呼びます。

| 状況 | ELBの動き |
| --- | --- |
| 通常時 | 6台へ均等に振り分け |
| 3号機が故障 | 3号機を外して残り5台へ |
| Auto Scalingで2台追加 | 新しい2台も振り分け先に加える |

故障した1台を自動で外す動き(ヘルスチェック)が高可用性に効きます。そして試験の頻出パターンが3点セットです。

- **ELB** が配り、**Auto Scaling** が台数を保ち、**複数AZ** が場所を分ける

「止まりにくいWebシステムの基本形を選べ」というシナリオが来たら、この3つの組み合わせが答えの軸になります。

## もっと知りたい人へ

- EC2の購入方法(オンデマンド・リザーブド・スポットなど)はM9「料金」で扱います。ここでは分けて覚えてください
- インスタンスタイプの命名(例: m5.large)は「ファミリー+世代+サイズ」の構造ですが、CLF-C02では個別の型番は問われません
