# 5-2-3
# DynamoDBはNoSQL

AWS Cloud Practitioner 入門 — Module 5 / レッスン5-2

<!-- ノート: RDBとの対比でNoSQLを導入するトピックです。 -->

---

## なぜ必要か

- 表とSQLは万能ではない
- 「ユーザーIDでセッション情報を引くだけ」を秒間数十万回、のような使い方がある
- 単純な出し入れを、どこまでも速く大量に、が欲しい

<!-- ノート: つかみ。使い方が単純で量が膨大、という別種の要件。 -->

---

## 結論

**DynamoDBは、キーと値で引くNoSQLデータベースで、ミリ秒の応答のまま自動でスケールする**

- **NoSQL** = 表とSQLの形にこだわらないデータベースの総称
- **キーバリュー** = キー(鍵)で値を出し入れする最も単純な形
- **DynamoDB** = そのサーバーレスなサービス

<!-- ノート: 結論。ロッカーの番号札の例え。番号で入れて番号で出す。 -->

---

## 最小の例

| | RDS / Aurora | DynamoDB |
| --- | --- | --- |
| データの形 | 表と表の関係 | キーと値 |
| 操作 | SQL | キーで出し入れ |
| 規模の伸ばし方 | サイズ変更が中心 | 自動で水平にスケール |
| 典型用途 | 会計・在庫・注文 | セッション・ゲーム・IoT |

<!-- ノート: 対比表が本体。複雑な集計はRDB、単純高速大量はDynamoDB。 -->

---

## 試験での聞かれ方

- 「ミリ秒の応答」「サーバーレスなNoSQL」「自動スケール」→ DynamoDB
- サーバーやOSの管理は登場しない(フルマネージド)
- 「表同士を結合した複雑な集計」ならRDS側へ
