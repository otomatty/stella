# 5-2-1
# RDSはマネージドなRDB

AWS Cloud Practitioner 入門 — Module 5 / レッスン5-2

<!-- ノート: データベースの日の起点。RDSと「任せる範囲」を固めるトピックです。 -->

---

## なぜ必要か

- 業務データの多くは「表」で管理される(顧客、注文、在庫)
- EC2に自分でデータベースを入れると、パッチもバックアップも自分の仕事
- その運用を任せられないでしょうか

<!-- ノート: つかみ。DB運用の当番作業のつらさを15秒で。 -->

---

## 結論

**RDSは、バックアップやパッチ適用をAWSに任せられるマネージドなリレーショナルデータベース**

- **リレーショナルデータベース**(RDB) = データを表の形で管理し、**SQL** という言語で操作するデータベース
- **RDS** = そのマネージド版(MySQL、PostgreSQLなどを選べる)

<!-- ノート: 結論。エンジン(MySQL等)はそのまま、運用だけAWSへ、が要点。 -->

---

## 最小の例

| 作業 | EC2に自分で構築 | RDS |
| --- | --- | --- |
| インストール | 自分 | 不要 |
| パッチ適用 | 自分 | AWS(設定に応じて自動) |
| バックアップ | 自分 | 自動 |
| SQLの操作・設計 | 自分 | 自分 |

<!-- ノート: 最後の行が大事。中身(データとSQL)は変わらず自分の仕事。 -->

---

## 止めない構成もお任せ

- **マルチAZ配置** = 別のAZに予備を用意し、障害時に自動で切り替える構成
- チェック1つで高可用性の型が手に入る
- 「DBを止めたくない」→ RDSのマルチAZ、が試験の定番

<!-- ノート: 補強枠。M2の複数AZの型のDB版。フェイルオーバーが自動、が効き目。 -->
