# レッスン5-1 ストレージ

## このレッスンの目標

- [ ] S3の特徴(オブジェクト・バケット・耐久性)を説明できる
- [ ] ストレージクラスとライフサイクルでコストを下げる考え方を言える
- [ ] オブジェクト・ブロック・ファイルの3方式を用途で選び分けられる

## 5-1-1 S3はオブジェクトストレージ

> **S3はファイルをオブジェクトとしてバケットに保管し、極めて高い耐久性を持つストレージ**

画像・動画・ログ・バックアップとデータは増える一方で、サーバーのディスクに置くと容量の上限と故障が常につきまといます。

**S3**(Simple Storage Service)は、ファイルを「オブジェクト」の単位で保管する **オブジェクトストレージ** です。オブジェクトの入れ物を **バケット** と呼びます。

| 項目 | S3 |
| --- | --- |
| 容量 | 実質無制限(使った分だけ課金) |
| 保管単位 | バケットの中のオブジェクト |
| 耐久性 | 複数の場所に自動複製して確保 |
| 典型用途 | 画像・動画・ログ・バックアップ・静的サイト |

データが失われにくい性質を **耐久性** と呼びます。S3はデータを複数のAZへ自動的に複製し、「イレブンナイン」(99.999999999%)と呼ばれる極めて高い耐久性で設計されています。数字そのものより「複数の場所への自動複製で守られている」という仕組みを覚えてください。

注意したいのは、S3は「Webから出し入れするファイル置き場」であって、OSから直接マウントするディスクではないことです。ディスクの役はこの後のEBSが担います。

## 5-1-2 ストレージクラスで安くする

> **アクセス頻度に合わせてStandardからGlacierまでのストレージクラスを選ぶと保管コストが下がる**

毎日見るファイルと、年に1度見るかどうかの保管用ファイルを、同じ棚に同じ値段で置くのはもったいない——S3には「棚のグレード」があります。保管単価と取り出し条件が違うグレードを **ストレージクラス** と呼びます。

| クラス | 向くデータ |
| --- | --- |
| Standard | 毎日使うデータ |
| Standard-IA | たまにしか使わない(低頻度アクセス) |
| Glacier系 | ほぼ使わない長期保管(監査ログ・アーカイブ) |
| Intelligent-Tiering | アクセス頻度が読めないデータ(自動で移動) |

原則は「アクセスが少ないほど保管は安く、取り出しに時間や費用がかかる」です。**Glacier** は長期保管(アーカイブ)用の低価格クラスの代表です。

クラス間の移動は **ライフサイクル** ルールで自動化できます。「30日後にStandard-IAへ、90日後にGlacierへ、1年後に削除」のような設定を置けば、手で移す運用は不要です。これはM1で学んだコスト最適化の、ストレージ版の実践です。

## 5-1-3 EBSはブロックストレージ

> **EBSは、EC2にディスクとして取り付けて使うブロックストレージ**

EC2で動くOSやデータベースには「ディスク」が要ります。データを細かいブロック単位で読み書きするディスク型の方式を **ブロックストレージ** と呼び、EC2に取り付けて使うサービスが **EBS**(Elastic Block Store)です。外付けSSDをサーバーに挿すイメージで、取り付けることを「アタッチ」と呼びます。

| | S3 | EBS |
| --- | --- | --- |
| 形 | ファイル置き場 | ディスク |
| つなぎ方 | ネットワーク越しに出し入れ | EC2に取り付ける |
| 典型用途 | 画像・バックアップ | OS・データベースの領域 |

EBSのバックアップは **スナップショット** です。ある時点のEBSの内容の複製で、撮っておけばその時点の状態に戻したディスクを作れます。スナップショットの保存先には裏でS3の仕組みが使われ、高い耐久性に相乗りしています。試験では「EBSのバックアップ = スナップショット」の対応で出ます。

## 5-1-4 EFSは共有ファイルストレージ

> **EFSは、複数のインスタンスから同時にマウントできる共有ファイルストレージ**

EBSは基本的に1台のEC2に取り付けるものですが、複数のWebサーバーから同じアップロード画像を見たい場面があります。フォルダー階層で整理してネットワーク越しに共有する方式を **ファイルストレージ**、ストレージを自分のフォルダーとして接続することを **マウント** と呼びます。**EFS**(Elastic File System)はそのマネージド版で、複数のインスタンスから同時にマウントでき、容量は自動で伸縮します。社内の共有ドライブのAWS版と考えてください。

ストレージ3方式の総まとめです。

| 方式 | サービス | 用途の一言 |
| --- | --- | --- |
| オブジェクト | S3 | Webから出し入れする置き場 |
| ブロック | EBS | 1台に取り付けるディスク |
| ファイル | EFS | 複数台で共有するフォルダー |

迷ったら「1台ならEBS、複数台で共有ならEFS、Webから出し入れならS3」です。なお、Windows環境向けのファイル共有にはFSxという仲間もあります。CLF-C02では名前を見て「ファイル共有の仲間」と分かれば十分です。
