# SNSは通知の一斉配信

AWS Cloud Practitioner 入門 — Module 6 / レッスン6-2

## なぜ必要か

- 「注文が入った」を、メール係にも在庫係にも分析係にも知らせたい
- 1件ずつ個別に送る作りだと、宛先が増えるたびに改修になる
- 「1回置けば、全員に届く」形にしたい

<!-- ノート: つかみ。掲示板・館内放送の例え。 -->

---

## 結論

**SNSは、1つの知らせを複数の宛先へ同時に配るパブリッシュ/サブスクライブ型の通知サービス**

- **パブリッシュ/サブスクライブ** = 発行者はトピックへ置くだけ、購読者は受け取るだけの配信方式
- **SNS** = そのマネージドなサービス

<!-- ノート: 結論。pub/sub。発行者は宛先を知らなくてよい、が要点。 -->

---

## 最小の例

| 手順 | 起きること |
| --- | --- |
| 1 | 発行者が「注文成立」をトピックへ発行 |
| 2 | 購読しているメール・SQS・Lambdaへ同時に配信 |
| 3 | 宛先が増えても発行側は無変更 |

<!-- ノート: 3行目が疎結合の効き目。購読の追加だけで拡張できる。 -->

---

## SQSとの使い分け

- SQS = 依頼を**ためて**、1つの受け手が処理する(1対1)
- SNS = 知らせを**配って**、多くの受け手へ届ける(1対多)
- 「ファンアウト」= SNSの後ろにSQSを複数つなぐ定番構成
