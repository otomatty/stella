# 流れで見る分析サービス

AWS Cloud Practitioner 入門 — Module 6 / レッスン6-1

<!-- ノート: 分析サービスを「受ける→ためる→見せる」の川で覚えるトピックです。 -->

---

## なぜ必要か

- 分析サービスの名前を個別に暗記すると、すぐ混ざる
- データが生まれてからグラフになるまでは、1本の流れ
- 流れの中の持ち場で覚えれば混ざらない

<!-- ノート: つかみ。川の上流・中流・下流、の絵を口頭で。 -->

---

## 結論

**流れ続けるデータはKinesisで受け、蓄積と集計はRedshift、可視化はQuickSightが担う**

- **Kinesis** = 流れ続けるデータ(ストリーム)の受け口
- **Redshift** = 分析専用の大規模DB(**データウェアハウス**)
- **QuickSight** = グラフやダッシュボードにする可視化サービス

<!-- ノート: 結論。DWH=分析のためにデータを集めた倉庫、と定義を添える。 -->

---

## 最小の例

| 持ち場 | サービス | 一言 |
| --- | --- | --- |
| 受ける | Kinesis | 流れ込むデータをリアルタイムに受ける |
| ためる | S3 / Redshift | 置き場 / 分析専用の倉庫 |
| 調べる | Athena / Redshift | 置いたまま / 倉庫で本格集計 |
| 見せる | QuickSight | グラフ・ダッシュボード |

<!-- ノート: 前トピックのAthenaも流れの中に再配置。全員に持ち場がある。 -->

---

## 試験での聞かれ方

- 「リアルタイムのストリーミングデータを取り込む」→ Kinesis
- 「大量データを集計する分析用データウェアハウス」→ Redshift
- 「経営層向けのダッシュボード」→ QuickSight
- 注文処理のRDS(M5)と分析の倉庫Redshiftを混同しない
