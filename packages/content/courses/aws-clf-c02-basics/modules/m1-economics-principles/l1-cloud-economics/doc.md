# レッスン1-1 クラウド経済

## このレッスンの目標

- [ ] 固定費から変動費への置き換えを、オンプレミスとの対比で説明できる
- [ ] 規模の経済とTCOという2つの経済用語を、試験の言い回しで使える
- [ ] 弾力性とライトサイジングの違いを1文ずつで言える

## 1-1-1 固定費から変動費へ

> **クラウドでは、サーバー購入の固定費が使った分だけ払う変動費に置き換わる**

自社で機器を買って持つ形態を **オンプレミス** と呼びます。オンプレミスのサーバー代は、使っても使わなくても先に出ていくお金です。使う量に関係なく発生する費用を **固定費**、使った量に比例して発生する費用を **変動費** と呼びます。

クラウドの従量課金は、この固定費を変動費に置き換えます。

| | オンプレミス | クラウド |
| --- | --- | --- |
| 初期費用 | 数十万円の購入費 | 0円 |
| 毎月の費用 | 使わなくても一定 | 使った分だけ |
| やめるとき | 機材が残る | 解放すれば0円 |

試験では「先行投資(upfront investment)を減らしたい」「初期費用なしで始めたい」という言い回しで出ます。答えの軸は変動費への置き換えです。英語の選択肢では、資本的支出(capital expense)を変動費(variable expense)に置き換える、と表現されます。

## 1-1-2 規模の経済

> **AWSは大量調達による規模の経済で単価を下げ、値下げとして利用者に還元できる**

規模が大きいほど1つあたりのコストが下がる効果を **規模の経済** と呼びます。1台だけ買う会社と数百万台を調達する事業者では仕入れの単価が違い、この差は自社の工夫では埋まりません。

クラウドでは世界中の利用者の需要がまとめて調達されるため、単価は構造的に下がる方向に働きます。利用者は自分の使用量の大小に関係なく、この「まとめ買いの安さ」に相乗りできます。

試験では「多数の顧客の使用量が集約される結果、何が得られるか」という形で出ます。答えは「従量課金の単価が下がる」です。AWS側の一時的な企業努力や、利用者自身の節約と混ぜた選択肢に注意してください。

## 1-1-3 TCOで比べる

> **クラウドとオンプレミスの費用比較は、機器代だけでなく運用まで含めた総所有コスト(TCO)で行う**

「サーバー1台の値段ならオンプレミスの方が安い」という比較には、電気代も人件費も入っていません。持つこと・使うことにかかる費用の総額を **TCO**(Total Cost of Ownership、総所有コスト)と呼び、費用比較はこの物差しで行います。

| 見えやすい費用 | 見えにくい費用 |
| --- | --- |
| サーバー購入費 | 電気代・空調・設置スペース |
| ソフトウェアライセンス | 保守・交換部品・廃棄 |
| 回線費用 | 運用担当者の人件費 |

右の列が抜けた比較が、「オンプレミスの方が安い」という結論の正体になりがちです。試験では「移行の費用対効果を検討したい」というシナリオでTCOが答えの軸になります。事前見積もりの道具(Pricing Calculator)はM9で扱います。

## 1-1-4 使う量に合わせて伸び縮み

> **需要に合わせて容量を増減できる弾力性があるため、ピークに合わせた買い置きが要らない**

セール当日はアクセスが10倍、翌日は元通り——オンプレミスでは、この10倍の日に合わせた台数を年中持つしかありません。需要の増減に合わせてリソースを増やしたり減らしたりできる性質を **弾力性** と呼びます。

| 日 | 需要 | オンプレミス | クラウド |
| --- | --- | --- | --- |
| 平日 | 1倍 | 10台(9台が遊ぶ) | 1台分だけ使う |
| セール日 | 10倍 | 10台でぴったり | 10台分に増やす |
| 翌日 | 1倍 | 10台(9台が遊ぶ) | 1台分に戻す |

増やせることより「減らせる」ことが弾力性の値打ちです。減らした瞬間に支払いも減るからです。

もう1つ、リソースの種類やサイズを実際の需要に合わせて選び直すことを **ライトサイジング** と呼びます。弾力性が「台数」の伸縮なら、ライトサイジングは「1台のサイズ」の見直しです。「大きめを買って安心」はクラウドでは損で、使用状況を見て定期的に見直すのが前提です。台数の増減を自動化する道具(EC2 Auto Scaling)はM3で扱います。
