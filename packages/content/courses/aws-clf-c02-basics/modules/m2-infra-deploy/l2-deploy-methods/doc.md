- [ ] コンソール・CLI・SDKの使い分けを場面で説明できる

## 2-2-1 コンソール・CLI・SDK

> **AWSの操作手段は、画面のマネジメントコンソール・コマンドのCLI・プログラムから呼ぶSDKの3つ**

AWSの操作の入口は3つあります。

- **マネジメントコンソール** — ブラウザーで使う管理画面です。初めての操作や、たまの確認に向きます
- **CLI** — コマンドラインから操作する道具です。繰り返す操作やスクリプト化に向きます
- **SDK** — プログラミング言語からAWSを呼ぶための部品集です。アプリケーションへの組み込みに向きます

3つの裏側は、すべて同じ **API**(サービスを呼び出す共通の窓口)につながっています。だから「コンソールでできてCLIでできない」ことは基本的にありません。「学ぶときはコンソール、繰り返すならCLI、アプリからならSDK」と覚えてください。APIという語は、後の「操作の記録」(M8のCloudTrail)でも前提になります。

## 2-2-2 環境をコードで書く

> **CloudFormationを使うと、環境の構成をコード(テンプレート)として書いて何度でも同じに作れる**

検証環境と本番環境を手作業で「同じに」作るのは、手順書があってもほぼ無理です。人の操作は微妙にずれ、その差異が「検証では動いたのに」を生みます。

インフラ構成をコードで管理する考え方を **IaC**(Infrastructure as Code)と呼び、それを実現するAWSのサービスが **CloudFormation** です。構成を書いたファイルを **テンプレート** と呼びます。

| | 手作業で構築 | CloudFormation |
| --- | --- | --- |
| 2回目の構築 | 手順書を見て再操作 | テンプレートを再実行 |
| 環境の差異 | 人のぶれで発生 | 同じテンプレートなら同じ |
| 構成の記録 | 手順書が古くなる | テンプレートが正本 |

試験では「複数リージョンに同じ環境を繰り返し構築したい」「手作業の構成ミスを減らしたい」というシナリオでCloudFormationが答えの軸になります。テンプレートの文法は出題されません。役割だけ覚えれば十分です。

## 2-2-3 3つの利用形態

> **ITの置き場所には、クラウド・オンプレミス・両者を組み合わせるハイブリッドの3つがある**

「全部をクラウドに移す」が常に正解とは限りません。法規制や既存資産の都合で社内に残すものがあり、残しながらクラウドも使う形態に名前が付いています。オンプレミスとクラウドを接続して併用する形態が **ハイブリッド** です。

| 形態 | 例 |
| --- | --- |
| クラウド | すべてをAWS上で構築・運用 |
| オンプレミス | すべて自社データセンターで運用 |
| **ハイブリッド** | 基幹DBは社内、Webはクラウド、両者を接続 |

ハイブリッドの判定条件は「両方を使い、つないでいる」ことです。クラウド内で複数のサービスを併用しているだけでは、ハイブリッドとは呼びません。社内とクラウドを「つなぐ」道具(VPN・専用線)はM4で扱います。

## 2-2-4 IaaS・PaaS・SaaS

> **IaaS・PaaS・SaaSの違いは、どこまでをサービス提供側に任せるかというマネージドの度合い**

同じクラウドでも、仮想サーバーとWebメールでは「任せている範囲」がまるで違います。この違いを3階建てで整理します。

| | 意味 | 例 | 自分の担当 |
| --- | --- | --- | --- |
| **IaaS** | インフラだけ借りる | 仮想サーバー | OS・ミドルウェア・アプリ |
| **PaaS** | 実行環境まで借りる | アプリ実行基盤 | アプリとデータだけ |
| **SaaS** | ソフトウェアそのものを使う | Webメール | 利用と設定だけ |

運用の面倒(パッチ適用・バックアップなど)を提供側が持つサービスを **マネージドサービス** と呼びます。「マネージドの度合いが上がる = 自分の担当が減る」という軸で3つを並べると、丸暗記が要らなくなります。

この軸はM7の共有責任モデルでそのまま再登場します。任せる範囲が広いほど、セキュリティの責任分担も提供側に寄る——この1行を覚えておくと、M7が半分終わったようなものです。

## もっと知りたい人へ

- CloudFormationの他に、プログラミング言語でIaCを書くAWS CDKもあります(CLF-C02では名前だけ知っていれば十分です)
- IaaS/PaaS/SaaSの分類は、AWS以外のクラウド一般でも使われる言葉です。自社で使っているサービスを3つ、どの階か当てはめてみると定着します
