# 3つの利用形態

AWS Cloud Practitioner 入門 — Module 2 / レッスン2-2

<!-- ノート: デプロイモデル3種。ハイブリッドの判定がゴールのトピックです。 -->

---

## なぜ必要か

- 「全部をクラウドに移す」が正解とは限らない
- 法規制や既存資産の都合で、社内に残すものもある
- 残しながら使う形に、名前が付いている

<!-- ノート: つかみ。ゼロイチではない現実的な選択の話。 -->

---

## 結論

**ITの置き場所には、クラウド・オンプレミス・両者を組み合わせるハイブリッドの3つがある**

- **ハイブリッド** = オンプレミスとクラウドを接続して併用する形態
- 試験は「どの形態か」を判定させる

<!-- ノート: 結論。3択の判定問題として出るので、定義の境界をはっきりさせる。 -->

---

## 最小の例

| 形態 | 例 |
| --- | --- |
| クラウド | すべてをAWS上で構築・運用 |
| オンプレミス | すべて自社データセンターで運用 |
| **ハイブリッド** | 基幹DBは社内、Webはクラウド、両者を接続 |

<!-- ノート: ハイブリッドの判定条件は「両方を使い、つないでいる」こと。 -->

---

## 試験での聞かれ方

- 「規制で一部データを社内に残しつつ、クラウドも使う」→ ハイブリッド
- 社内とクラウドを「つなぐ」道具(VPN・専用線)はM4で扱う
- クラウド内だけで複数サービスを併用しても、ハイブリッドとは呼ばない

<!-- ノート: 補強枠。よくある誤解「複数サービス併用=ハイブリッド」を先回りで潰す。 -->
