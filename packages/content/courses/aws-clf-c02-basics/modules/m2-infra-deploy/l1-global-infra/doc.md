# レッスン2-1 グローバル基盤

## このレッスンの目標

- [ ] リージョン選定の4基準(データ主権・遅延・コスト・サービス対応)を挙げられる
- [ ] リージョン・AZ・データセンターの包含関係を説明できる
- [ ] 「動かす場所」と「配る場所」の違いで、CloudFrontの用途を説明できる

## 2-1-1 リージョンの選び方

> **リージョンは地理的に独立したAWSの拠点で、データ主権・遅延・コスト・サービス対応で選ぶ**

クラウドの実体は世界各地のデータセンターで動いていて、その「どこで動かすか」は利用者が選びます。**リージョン** は、東京・大阪・バージニア北部のように世界各地に置かれた、地理的に独立したAWSの拠点です。

リージョンの選定基準は4つで固定して覚えます。

| 基準 | 問い | シナリオの言い回し |
| --- | --- | --- |
| **データ主権** | データをどの国・地域に置く義務があるか | 「国内法により国外に保存できない」 |
| 遅延(**レイテンシー**) | 利用者に近いか | 「利用者への応答を速くしたい」 |
| コスト | リージョンごとの料金差はどうか | 「最も安い場所で動かしたい」 |
| サービス対応 | 使いたいサービスがそこにあるか | 「新サービスが未対応だった」 |

**データ主権** は、法規制によってデータの置き場所が縛られることです。**レイテンシー** は通信の往復にかかる時間のことです。もう1つ大事な前提として、リージョンに置いたデータは、利用者が明示しない限り他のリージョンへ複製されません。「勝手に他国へ移ることはない」はセキュリティの文脈でも問われます。

## 2-1-2 AZで障害に耐える

> **アベイラビリティゾーンはリージョン内の独立したデータセンター群で、複数に分けると高可用性になる**

サーバーを収容する施設が **データセンター** です。データセンターは火災・停電・水害でまるごと止まることがあり、1か所に全部を置けばその1か所と運命を共にします。

**アベイラビリティゾーン**(AZ)は、リージョンの中にある、電源・空調・ネットワークが独立した1つ以上のデータセンターのまとまりです。AZ同士は互いに影響しない距離に離れつつ、高速な回線で結ばれています。1つのリージョンは複数のAZで構成されます。

| 配置 | AZ-aが停電したら |
| --- | --- |
| 2台ともAZ-a | 全滅。サービス停止 |
| AZ-aとAZ-cに1台ずつ | 1台が生き残り、サービス継続 |

障害が起きてもサービスを提供し続けられる性質を **高可用性** と呼びます。「複数のAZに分けて配置する」がCLF-C02で問われる基本の型で、この形はM3(ELB)やM5(RDS)でも再登場します。覚える階層は「リージョン > AZ > データセンター」の3層です。

## 2-1-3 エッジは利用者の近くで配る

> **エッジロケーションは利用者に近い配信拠点で、CloudFrontがそこからコンテンツをキャッシュ配信する**

東京のサーバーからブラジルの利用者へ画像を配ると、物理的な距離のぶんだけ必ず遅くなります。かといって、配信のためだけに世界中のリージョンでサーバーを動かすのは大げさです。

**エッジロケーション** は、リージョンよりはるかに数が多い、配信専用の小さな拠点です。よく使うデータの写しを手近に置いておくことを **キャッシュ** と呼び、エッジにキャッシュを置いて配信するサービスが **CloudFront** です。このような配信の仕組みを一般に **CDN**(コンテンツ配信ネットワーク)と呼びます。

| | 東京から直接配信 | CloudFrontで配信 |
| --- | --- | --- |
| ブラジルの利用者 | 地球半周ぶん遅い | 近くのエッジから受け取る |
| 東京のサーバーの負荷 | 全アクセスが集中 | エッジが肩代わり |

覚える対比は「リージョン/AZは **動かす** 場所、エッジは **配る** 場所」です。試験で「世界中の利用者に低遅延でコンテンツを配信したい」と来たら、答えの軸はCloudFrontです。
