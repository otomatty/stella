# AZで障害に耐える

AWS Cloud Practitioner 入門 — Module 2 / レッスン2-1

<!-- ノート: 高可用性の物理的な土台。AZという語をここで固めます。 -->

## なぜ必要か

- データセンターは、火災・停電・水害でまるごと止まることがある
- 1か所に全部を置けば、その1か所と運命を共にする
- 「置き場所を分ける」をクラウドではどう実現するのでしょうか

<!-- ノート: つかみ。卵を1つのかごに盛るな、の物理版。 -->

---

## 結論

**アベイラビリティゾーンはリージョン内の独立したデータセンター群で、複数に分けると高可用性になる**

- **データセンター** = サーバーを収容する施設
- **アベイラビリティゾーン(AZ)** = 電源・空調・ネットワークが独立した1つ以上のデータセンターのまとまり
- **高可用性** = 障害が起きてもサービスを提供し続けられる性質

<!-- ノート: 結論。1リージョンは複数のAZで構成される。AZ同士は離れているが高速回線でつながる。 -->

---

## 最小の例

東京リージョンにサーバーを2台置く場合の比較です。

| 配置 | AZ-aが停電したら |
| --- | --- |
| 2台ともAZ-a | 全滅。サービス停止 |
| AZ-aとAZ-cに1台ずつ | 1台が生き残り、サービス継続 |

<!-- ノート: マルチAZ配置が高可用性の基本形。この形はM3のELB、M5のRDSでも再登場する。 -->

---

## 覚える階層

- リージョン > AZ > データセンター の3階層
- 1つのリージョンには複数のAZがある
- 「複数のAZに分けて配置する」がCLF-C02の推奨の型
