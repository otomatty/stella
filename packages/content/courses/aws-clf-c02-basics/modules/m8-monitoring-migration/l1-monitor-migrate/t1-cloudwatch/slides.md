# CloudWatchで測って知らせる

AWS Cloud Practitioner 入門 — Module 8 / レッスン8-1

<!-- ノート: 監視の中核サービス。測る・ためる・知らせるの3役を覚えるトピックです。 -->

---

## なぜ必要か

- 動かし始めたシステムは「今どうなっているか」が見えないと運用できない
- CPUが張り付いても、気づくのが利用者からの苦情では遅い
- 測って、ためて、超えたら知らせる仕組みが要る

<!-- ノート: つかみ。体温計とアラームの無い病棟、の例え。 -->

---

## 結論

**CloudWatchはメトリクスとログを集め、しきい値を超えたらアラームで知らせる**

- **メトリクス** = CPU使用率などの数値の測定値
- **ログ** = 出来事の記録の文章
- **アラーム** = しきい値超えをきっかけに通知や自動対応を出す仕組み

<!-- ノート: 結論。CloudWatch=AWSの計器盤。3語をここで固定。 -->

---

## 最小の例

| 流れ | 例 |
| --- | --- |
| 測る | EC2のCPU使用率をメトリクスとして収集 |
| 判定 | 「5分間80%以上」のしきい値を超えた |
| 知らせる | アラームがSNSへ通知(担当者へメール) |
| 自動対応 | Auto Scalingに台数追加を指示もできる |

<!-- ノート: 通知先がSNS、対応係がAuto Scaling。既習と接続する。 -->

---

## 試験での聞かれ方

- 「リソースの使用状況をモニタリングする」→ CloudWatch
- 「しきい値を超えたら通知する」→ CloudWatchアラーム(+SNS)
- 「アプリのログを集めて調べる」→ CloudWatch Logs
