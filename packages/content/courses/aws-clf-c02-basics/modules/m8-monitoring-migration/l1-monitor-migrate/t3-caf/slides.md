# 8-1-3
# CAFは移行準備の枠組み

AWS Cloud Practitioner 入門 — Module 8 / レッスン8-1

<!-- ノート: ドメイン1タスク1.3。CAFの位置づけと6視点の2分類を覚えるトピックです。 -->

---

## なぜ必要か

- 既存システムのクラウド**移行**(引っ越し)は、技術だけの話ではない
- 人材・体制・お金の決め方が整わないと、道具があっても進まない
- 「組織の準備」を点検するリストが要る

<!-- ノート: つかみ。引っ越しはトラックの手配より荷物と段取り、の例え。 -->

---

## 結論

**クラウド導入フレームワーク(CAF)は、組織の移行準備を6つの視点で点検する枠組み**

- **CAF**(Cloud Adoption Framework) = 移行準備の公式チェック枠組み
- ビジネス面3つ + 技術面3つの6視点

<!-- ノート: 結論。Well-Architectedが「設計」の点検なら、CAFは「組織」の点検。 -->

---

## 最小の例

| 面 | 視点 |
| --- | --- |
| ビジネス面 | ビジネス / 人材 / ガバナンス |
| 技術面 | プラットフォーム / セキュリティ / オペレーション |

<!-- ノート: 6つの個別暗記より「ビジネス3+技術3」の構造が先。 -->

---

## Well-Architectedとの区別

- CAF = **移行の前**、組織の準備を点検する
- Well-Architected = **設計するとき**、システムの良し悪しを点検する
- 「組織・人材・移行計画」の語が見えたらCAF

<!-- ノート: 補強枠。2つのフレームワークの混同がひっかけの定番。 -->
