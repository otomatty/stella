# CloudTrailは操作の記録

AWS Cloud Practitioner 入門 — Module 8 / レッスン8-1

## なぜ必要か

- 「誰がこのサーバーを消したのか」を後から調べたい日が来る
- 監査でも「操作の記録を見せてください」と言われる
- 数値の監視(CloudWatch)とは別の、行動の記録が要る

<!-- ノート: つかみ。犯人捜しではなく事実確認、というトーンで。 -->

---

## 結論

**CloudTrailは「誰が・いつ・何を」操作したかというAPI呼び出しの証跡を記録する**

- **証跡** = 後から検証できる操作の記録
- 既定で記録されるのは**管理イベント**(リソースの作成・変更・削除などの管理操作)

<!-- ノート: 結論。コンソールもCLIもSDKも裏は同じAPI呼び出し(M2)なので、入口によらず同じ形で残る。S3オブジェクトの読み書きのようなデータイベントは既定では記録されず、対象を指定して追加で有効化する。 -->

---

## 最小の例

| 記録される内容 | 例 |
| --- | --- |
| 誰が | IAMユーザー suzuki |
| いつ | 2026-08-27 14:03 |
| 何を | EC2インスタンスの削除を実行 |

<!-- ノート: 5W1Hのうち誰・いつ・何を、が1行で残る。監査対応の第一資料。 -->

---

## 3つの記録係の区別

- CloudWatch = 数値と状態(**どうなっているか**)
- CloudTrail = 操作の証跡(**誰が何をしたか**)
- **Config** = 設定の変遷(**構成がどう変わってきたか**)を記録・評価
