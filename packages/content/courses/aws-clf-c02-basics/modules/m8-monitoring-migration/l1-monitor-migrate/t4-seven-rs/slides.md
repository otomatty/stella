# 8-1-4
# 移行戦略の7R

AWS Cloud Practitioner 入門 — Module 8 / レッスン8-1

<!-- ノート: 移行のやり方の型。代表3Rを深く、残り4Rは名前だけのトピックです。 -->

---

## なぜ必要か

- 「全部クラウド用に作り直す」は時間もお金もかかりすぎる
- 「そのまま運ぶだけ」ではクラウドの旨みが薄い
- システムごとに、やり方を選び分ける型がある

<!-- ノート: つかみ。引っ越しでも家具をそのまま運ぶか、買い替えるか選ぶ。 -->

---

## 結論

**移行のやり方は、そのまま運ぶリホストから作り直すリファクタリングまで、7つのRから選ぶ**

- **7R** = 頭文字Rで始まる7つの移行戦略
- まず代表の3つ(リホスト/リプラットフォーム/リファクタリング)を固める

<!-- ノート: 結論。7つ全部の暗記より、手の入れ方の浅い→深いの並びが大事。 -->

---

## 最小の例

| 戦略 | 一言 | 例 |
| --- | --- | --- |
| **リホスト** | そのまま運ぶ(lift and shift) | サーバーをそのままEC2へ |
| **リプラットフォーム** | 少しだけ調整して運ぶ | DBだけRDSに置き換え |
| **リファクタリング** | クラウド前提に作り直す | サーバーレスに再設計 |

<!-- ノート: 下に行くほど手間は大きく、クラウドの効果も大きい。 -->

---

## 残りの4つのR

- リパーチェス = 買い替える(SaaSへ乗り換え)
- リタイア = 廃止する
- リテイン = 今は残す(移行しない)
- リロケート = 環境ごと移す(仮想化基盤のまま)

<!-- ノート: 補強枠。名前と一言だけ。「廃止・保留も戦略のうち」が意外と問われる。 -->

---
