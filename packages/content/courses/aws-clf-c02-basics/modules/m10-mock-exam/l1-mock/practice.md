# レッスン10-1 演習 — 模擬試験

対象トピック: 講座全範囲(0-1-1 〜 9-2-4)

## 手元で試す

確認クイズの65問を、本番と同じ問題数・時間で解くワークです(出題形式は4択・単一回答のみで、本番にある複数回答形式は含みません)。

1. 紙とペン、90分のタイマーを用意する(解答と印のメモは紙に取る)
2. タイマーを開始し、平均69秒(75分 ÷ 65問)のペースで解き進める。80秒かけても決まらない問題は消去法で1つ選び、問題番号に印を付けて次へ進む(空欄にしない)
3. 全問に触れたら、残り時間で印の問題に戻る
4. 採点し、間違えた問題の解説末尾にあるドメインと復習先をメモする
5. 誤答分析を行う——ドメイン別に誤答数を数え、いちばん多いドメインの該当モジュールを読み直してから、数日後に間違えた問題だけを解き直す

52問(80%)以上が安全圏の目安です。読み直しの戻り先は doc.md のドメイン対応表を使ってください。

## 演習問題

### 問1(基本)

模試を始める前に、90分の時間配分計画を3行で書いてください(1周目に使う時間と1問あたりの平均 / 1問の打ち切り上限 / 見直しに残す時間)。

### 問2(応用)

採点後の誤答分析表(ドメイン / 誤答数 / 戻るモジュール)を作り、自分の「最初に戻るべきモジュール」を1つ決めてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

1周目は約75分で全65問に触れます(平均69秒/問)。80秒かけても決まらない問題は消去法で1つ選んで印を付け、次へ進みます。残り約15分を、印を付けた問題の見直しに残します。

</details>

<details>
<summary>問2の解答例</summary>

例: ドメイン1(概念)=2問 / ドメイン2(セキュリティ)=5問 / ドメイン3(技術)=3問 / ドメイン4(料金)=1問なら、最多のドメイン2が弱点です。戻り先はM7(共有責任とIAM、防御と情報源)で、読み直してから数日後に誤答のみ解き直します。感覚ではなく誤答数で戻り先を決めるのがポイントです。

</details>

## 確認クイズ

### Q1. ある企業のECサイトは、セール時のアクセス数がまったく予測できません。需要に合わせてEC2インスタンスの台数を自動で増減させるサービスはどれですか。

- A. EC2 Auto Scaling
- B. CloudFormation
- C. CloudWatch
- D. ELB

<details>
<summary>答え</summary>

**A** — 「台数を増減」はAuto Scalingです。ELBは増えた台数へ通信を振り分ける係で、台数そのものは変えません。2つはセットで使いますが、役割の動詞(増やす/配る)で区別します。(ドメイン3 / 復習: 3-1-3)

</details>

### Q2. 共有責任モデルにおいて、EC2インスタンスのゲストOSへのセキュリティパッチ適用は誰の責任ですか。

- A. AWSと利用者の両方
- B. OSのベンダー
- C. AWS
- D. 利用者

<details>
<summary>答え</summary>

**D** — EC2はIaaSで、OSから上は利用者の管理範囲です。同じパッチでもRDSのDBエンジンならAWS側になる、という「境界が動く」対比まで覚えておきます。(ドメイン2 / 復習: 7-1-2)

</details>

### Q3. オンプレミスからの移行を計画する際、機器代だけでなく電力・設置場所・運用人員まで含めてクラウドと費用を比較する考え方はどれですか。

- A. 従量課金
- B. ROI
- C. 減価償却
- D. TCO(総所有コスト)

<details>
<summary>答え</summary>

**D** — 「運用まで含めた総額」で比べるのがTCOです。機器の購入費だけを比べると、オンプレミスの見えないコスト(人件費・電力・保守)を見落とします。(ドメイン1 / 復習: 1-1-3)

</details>

### Q4. 世界中の利用者に画像や動画などの静的コンテンツを低遅延で配信したいとき、最も適したサービスはどれですか。

- A. CloudFront
- B. Global Accelerator
- C. 各リージョンへのEC2の複製配置
- D. Direct Connect

<details>
<summary>答え</summary>

**A** — Webコンテンツ(HTTP/HTTPS)の配信はCloudFrontです。Global AcceleratorはHTTP以外のTCP/UDPや固定IP・素早いフェイルオーバーが要るときの選択肢で、2択はキャッシュ可否ではなくプロトコルで切ります(CloudFrontは動的なHTTPも速くします)。(ドメイン3 / 復習: 2-1-3)

</details>

### Q5. 新しく作ったAWSアカウントのルートユーザーの扱いとして、最も適切なものはどれですか。

<details>
<summary>答え</summary>

**B** — ルートは全権を持つため、MFAで守って日常では使わないのが定石です。ルートにしかできない作業が残るため削除という選択肢はなく、アクセスキーを発行してスクリプトから使うのはむしろ避けるべき操作です。(ドメイン2 / 復習: 7-1-3)

</details>

### Q62. 新しいワークロードの構成を組む前に、月額費用がいくらになるかを見積もりたい。使う道具はどれですか。

- A. Cost Explorer
- B. Budgets
- C. Pricing Calculator
- D. Trusted Advisor

<details>
<summary>答え</summary>

**C** — 「使う前の見積もり」はPricing Calculatorです。過去の分析はCost Explorer、超過の見張りはBudgetsで、時間軸(未来/過去/見張り)で3つを使い分けます。(ドメイン4 / 復習: 9-1-3)

### Q63. 用途に対してサイズが大きすぎるEC2や、使われていないEBSなどの改善提案を、ベストプラクティスと照らして受け取れるサービスはどれですか。

- A. Trusted Advisor
- B. Health Dashboard
- C. CloudTrail
- D. Artifact

<details>
<summary>答え</summary>

**A** — コスト・セキュリティ・耐障害性などの「改善の助言」をくれるのがTrusted Advisorです。Health DashboardはAWS側の障害が自分の環境に影響するかの通知で、助言と障害情報の対比で覚えます。(ドメイン4 / 復習: 9-2-2)

</details>

### Q64. メトリクスがしきい値を超えたらアラームを発報し、管理者へ通知やAuto Scalingの起動につなげる監視サービスはどれですか。

- A. Config
- B. GuardDuty
- C. CloudTrail
- D. CloudWatch

<details>
<summary>答え</summary>

**D** — メトリクス・ログ・アラームの監視はCloudWatchです。CloudTrailは「誰が操作したか」の証跡、Configは「設定がどう変わったか」の記録で、見る対象(性能/操作/設定)で3つを区別します。(ドメイン2 / 復習: 8-1-1)

</details>

### Q65. 試験直前の見直しで、正解の確信がない2択が残りました。9-2-4で学んだ「解き方の型」に従うと、最後の決め手にすべきものはどれですか。

- A. 選択肢のサービス名のアルファベット順
- B. 問題文の用途キーワードとサービスの「用途の一言」の一致
- C. より新しく発表されたサービスを選ぶ
- D. より高機能・高価格なサービスを選ぶ

</details>
