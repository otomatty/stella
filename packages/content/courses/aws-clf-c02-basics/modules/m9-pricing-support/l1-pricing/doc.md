# レッスン9-1 料金とコスト管理

## このレッスンの目標

- [ ] 無料利用枠の3つの型を区別できる
- [ ] 4つの買い方(オンデマンド・リザーブド・Savings Plans・スポット)を用途で選べる
- [ ] Cost Explorer・Pricing Calculator・Budgets・Organizationsの役割を言える

## 9-1-1 まず無料利用枠で試せる

> **AWSは使った分だけの従量課金で、無料利用枠の範囲なら費用をかけずに試せる**

「試したいけど、いくらかかるか怖い」が入門の最初の壁ですが、新規アカウントが無料で試せる公式の仕組み——**無料利用枠** が用意されています。この制度は2025年7月15日に刷新され、現行は「プラン + クレジット」の形です(調査日 2026-08-27 時点)。

| 項目 | 現行制度(2025-07-15以降の新規アカウント) |
| --- | --- |
| プラン | 無料プランか有料プランを選んで開始 |
| クレジット | 登録で$100、所定の利用体験の達成で最大あと$100 |
| 無料プランの期限 | 6か月、またはクレジットを使い切るまで |
| 超過したら | 無料プランは課金されず利用が制限される。有料プランはクレジット超過分が従量課金 |

大事なのは超過時の挙動の違いです。無料プランは「気づいたら課金されていた」が起きない設計で、上限に達すると利用が制限されます。有料プランはクレジットを使い切った後は通常の従量課金に戻るので、「超えそうなら知らせる」道具(このレッスン後半のBudgets)を併用します。

旧制度との区別も覚えておいてください。2025-07-15より前に作成したアカウントは、旧制度——12か月無料(作成から1年)・常時無料(期限なし。例: Lambdaの月あたりの無料リクエスト枠)・トライアル(サービスごとの試用)の「3つの型」——のままです。古い教材で見かける3つの型はこの旧制度の説明です。金額や条件は変わりうるので、受験前に公式の無料利用枠ページで最新を確認してください。

## 9-1-2 4つの買い方

> **定価のオンデマンド、約束して安くするリザーブドとSavings Plans、余りを安く使うスポットから選ぶ**

同じEC2でも、買い方しだいで支払いは大きく変わります。切符(定価)・定期券(約束して割引)・当日の空席(激安)の3系統で覚えてください。

| 買い方 | 一言 | 向く用途 |
| --- | --- | --- |
| オンデマンド | 定価。いつでも使える従量課金 | 予測できない・短期の利用 |
| **リザーブドインスタンス** | 1年 / 3年の利用を約束して割引 | 常時稼働が確実なサーバー |
| **Savings Plans** | 使用額を約束して割引(対象が柔軟) | 同上(より柔軟に) |
| **スポットインスタンス** | 空き容量を大幅割引。ただし中断されうる | 中断してよいバッチ・計算処理 |

判定は2つの問いです。「1年以上の約束ができるか」できるならリザーブド / Savings Plans。「中断に耐えられるか」耐えられるならスポット。どちらもnoならオンデマンドです。

ひっかけの定番は「本番データベースをスポットで動かしてコスト削減」という選択肢です。スポットはAWS側の都合で中断されるため、止められないワークロードには使いません。

## 9-1-3 コストを見える化する

> **過去の分析はCost Explorer、事前の見積もりはPricing Calculator、超過の見張りはBudgets**

月末の請求書で驚かないために、3つの問いに対応する道具を時間軸で覚えます。

| 問い | 道具 |
| --- | --- |
| 先月、何にいくら使った?(過去) | **Cost Explorer** — 使用実績をグラフで分析 |
| この構成だと月いくら?(未来) | **Pricing Calculator** — 構築前の見積もり |
| 予算を超えそうなら知らせて(見張り) | **Budgets** — しきい値で通知 |

名前は英単語の意味どおりです(explore=探索する、calculate=計算する、budget=予算)。表の左の言い回しが、試験の問題文にほぼそのまま出ます。

部署別・案件別にコストを分けたいときは **コスト配分タグ** を使います。リソースに「部署」「プロジェクト」のラベルを付けておき、タグで集計して内訳を出します。「どのチームのコストか分けたい」と来たらタグ付けが答えの軸です。

## 9-1-4 Organizationsでまとめる

> **Organizationsは複数のAWSアカウントをまとめて管理し、一括請求でボリューム割引を効かせる**

会社では、部署や環境(本番・検証)ごとにAWSアカウントを分けるのが普通です。分けるのは正しい設計ですが、アカウントが10個あれば請求書も統制もばらばらになります。

**Organizations** は複数アカウントを組織として束ねるサービスです。効き目は3つです。

| 効き目 | 内容 |
| --- | --- |
| 請求 | **一括請求**で全アカウント分を1枚に。使用量が合算され、量による割引(ボリューム割引)に届きやすくなる |
| 統制 | 組織共通のルール(SCP: サービスコントロールポリシー)で、できる操作を制限 |
| 管理 | アカウントの新設・グループ分けを一元化 |

試験では「複数アカウントの請求をまとめたい」(一括請求)、「組織全体で特定の操作を禁止したい」(SCP)が定番です。IAMポリシーは1アカウント内の権限、SCPは組織全体の制限、と効く範囲で区別してください。
