# レッスン4-2 接続と名前解決

## このレッスンの目標

- [ ] VPNとDirect Connectを、回線・品質・費用・速さの4軸で対比できる
- [ ] シナリオのキーワードから接続手段を選べる
- [ ] DNS(Route 53)の役割を「名前から住所を引く」で説明できる

## 4-2-1 VPNは暗号化してつなぐ

> **Site-to-Site VPNは、インターネット越しに自社拠点とVPCを暗号化してつなぐ**

M2で学んだハイブリッドでは、社内ネットワークとVPCをつなぐ必要があります。ただし、インターネット経由の通信は途中で盗み見られるリスクがあります。

内容を第三者に読めない形に変換することを **暗号化** と呼びます。**VPN** は、公衆回線(インターネット)の上に暗号化された専用のトンネルを作る技術です。自社拠点とVPCの間をつなぐ形をSite-to-Site VPNと呼びます。

| 項目 | Site-to-Site VPN |
| --- | --- |
| 使う回線 | 既存のインターネット回線 |
| 安全性 | 暗号化トンネルで確保 |
| 開通まで | 短い(機器設定のみ) |
| 通信品質 | インターネット品質に依存 |

既存回線を使うので「安く、すぐ」つながりますが、通信品質はインターネットの混み具合に左右されます。この弱点が次のトピックへの伏線です。

## 4-2-2 Direct Connectは専用線

> **Direct Connectは自社拠点とAWSを専用線でつなぎ、安定した帯域と品質を得る**

基幹システムの大量データを毎晩安定して流したい場合、インターネット品質に依存するVPNでは不安が残ります。自社だけが使う物理的な通信回線を **専用線** と呼び、AWSへの専用線接続のサービスが **Direct Connect** です。インターネットを経由しないことが最大の特徴です。

| | Site-to-Site VPN | Direct Connect |
| --- | --- | --- |
| 回線 | インターネット(共用) | 専用線 |
| 品質・帯域 | 保証されない | 安定 |
| 開通まで | 短い | 長い(物理工事) |
| 費用 | 安い | 高い |

この対比表がそのまま試験の判定表です。問題文のキーワードで選びます。

- 「安定した帯域」「一貫したネットワーク品質」「インターネットを経由しない」→ **Direct Connect**
- 「すぐに」「安価に」「暗号化して」→ **VPN**

実務では、Direct Connectを本線にしてVPNをバックアップにする併用構成もあります。試験でも「両方使う」選択肢が正解になることがあると知っておいてください。

## 4-2-3 Route 53はDNS

> **Route 53は、ドメイン名をIPアドレスに解決するマネージドなDNSサービス**

利用者は「example.co.jp」という名前でアクセスしますが、コンピュータ同士はネットワーク上の数字の住所である **IPアドレス** でしか会話できません。人が覚えるための名前が **ドメイン名** で、名前から住所を引く仕組みが **DNS** です。この変換を「解決」と呼びます。

**Route 53** は、AWSのマネージドなDNSサービスです。ドメイン名の登録から名前解決までを扱えます。

| 手順 | 起きること |
| --- | --- |
| 1 | 利用者が example.co.jp にアクセス |
| 2 | Route 53が対応するIPアドレスを返す |
| 3 | ブラウザーがそのIPアドレスへ接続 |

Route 53には、接続先の健康状態を見て応答を切り替えるルーティング(フェイルオーバー)もあり、災害対策(DR)構成の部品としても登場します。CLF-C02では「DNSという語が見えたらRoute 53」の対応がまず大事です。

## もっと知りたい人へ

- 4-1の「VPCの絵」に、今日の3つ(VPN・Direct Connect・Route 53)を描き足すと、ネットワークの全体図が完成します(practice.md のワーク)
- 名前の由来: Route 53の「53」は、DNSが使う通信ポートの番号です。由来で覚えると名前が混ざりません
