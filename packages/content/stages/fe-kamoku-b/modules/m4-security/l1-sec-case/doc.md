# レッスン4-1 セキュリティのケース問題

## このレッスンの目標

- [ ] 状況文から資産・脅威・脆弱性を読み取れる
- [ ] 認証と権限を分けて、事例の問題点を説明できる
- [ ] 機密性・完全性・可用性に合わせて対策を選べる

## 4-1-1 状況から資産とリスクを読み取る

> **セキュリティ問題は、状況説明から「どの資産に何のリスクがあるか」を読み取る**

科目Bには、擬似言語のほかにセキュリティ分野の問題が出ます。形式は大きく違い、職場の状況を説明した文章を読み、適切な対応を選びます。コードは出てきません。

状況文は長いので、注目する場所を決めて読みます。手がかりは **情報セキュリティ**(大切な情報を安全に守ること)の基本の3点セットです。

- **資産** — 守る価値のある情報やもの
- **脅威** — 悪いことを起こす原因
- **脆弱性** — 付け込まれる弱点

短い事例で試してみます。

> 営業部の顧客名簿は共有フォルダーにあり、全社員が閲覧できる状態になっている。

- 資産は顧客名簿です。この事例で守るべきものです
- 脅威は、情報の持ち出しやのぞき見です
- 脆弱性は、誰でも閲覧できる設定です

脅威と脆弱性は混同しやすいので、たとえで区別しましょう。脅威は泥棒、脆弱性は開けっ放しの窓です。窓が開いていても泥棒が来なければ被害はありません。両方がそろったときに被害が起きます。

問題文では「〜できる状態だった」が脆弱性の合図です。「〜される恐れがある」が脅威の合図です。この3点セットで整理すると、長い状況文が短く要約できます。

## 4-1-2 誰に何を許すかを決める

> **アクセス制御は、利用者を認証し、必要最小限の権限だけを与える**

資産を守る仕組みの代表が **アクセス制御**(誰に何を許すかを決めて守る仕組み)です。2つの部品に分けて考えます。

- **認証** — 利用者が本人かどうかを確かめること
- **権限** — その利用者ができることの範囲

定番の事例で確かめます。

> 先月退職した社員のIDが削除されておらず、今も共有フォルダーの顧客名簿を開ける状態だった。

この状況には、2つの面から問題があります。

- 認証の面 — 社員でない人が、そのIDを使って入れてしまいます
- 権限の面 — もう不要な人に、閲覧を許したままになっています

適切な対応は「退職時にIDを速やかに削除する」です。本人以外の利用を防ぎ、不要な権限も同時に消せます。

権限の与え方には原則があります。仕事に必要な最小限だけを与えることで、これを **最小権限** と呼びます。営業部の顧客名簿なら、閲覧は営業部の担当者だけに絞ります。「全員に許可」は便利ですが、それ自体が脆弱性になります。選択肢に「全員に許可する」とあれば、最小権限に反しないか疑ってください。

## 4-1-3 対策は目的とセットで選ぶ

> **セキュリティ対策は、守りたいもの(機密性・完全性・可用性)に合わせて選ぶ**

脅威を防ぐ手立てが **対策** です。試験の選択肢には「パスワードを掛ける」「バックアップを取る」など、それ自体は正しい行いが並びます。行いの正しさでは選べません。守りたいものと対策の目的が合っているかで選びます。

守りたいものは、次の3つに整理できます。

- **機密性** — 許した人以外に見せないこと
- **完全性** — 情報が勝手に書き換えられないこと
- **可用性** — 使いたいときに使えること

事例で確かめます。

> 顧客名簿の入ったノートPCを、社員が外出先で紛失した。

紛失で恐れるのは「中身を見られること」なので、守りたいのは機密性です。合う対策は、PCにパスワードを掛けて中身を見られなくすることです。

ここで「名簿のバックアップを取る」を選ぶと誤答です。バックアップは、データが失われても使い続けられるようにする、可用性の対策です。対策としては正しくても、この事例の目的とはずれています。

誤答の多くは、この「対策自体は正しいが、目的とずれている」形で作られます。選ぶ前に「この事例で守りたいものは何か」を必ず確かめてください。

## もっと知りたい人へ

- 実務でも、入社・異動・退職のたびにIDと権限を見直す手順を決めておくことが大切です。事例問題の多くは、この見直しが漏れた場面を題材にしています
- 機密性・完全性・可用性は、情報セキュリティの土台となる3要素です。ニュースで情報漏えいの記事を見たら「どれが損なわれたか」を考えると、よい練習になります
