## 7-1-1 決まった値だけを受け付ける型

> **リテラル型を | でつなぐと、決まった値のどれかだけを受け付ける型になります。**

店のドアに掛ける札は「営業中」と「準備中」の2枚です。関数でも、引数や戻り値の型注釈に候補の値を書けます。

```ts
// 店の状態を受け取り、ドアの札の文字を返す
function signText(state: "open" | "closed"): "営業中" | "準備中" {
  // 開いていれば営業中、それ以外は準備中を返す
  return state === "open" ? "営業中" : "準備中";
}
// 開いている店の札を表示する
console.log(signText("open"));
// => "営業中"
```

引数は `"open" | "closed"`、戻り値は `"営業中" | "準備中"` です。候補にない `signText("maybe")` は、実行する前に型の確認でエラーになります。型は、実行中に値を確かめるものではありません。型のエラーを無視して出力した JavaScript を実行すると、この例では比較が偽になり、`"準備中"` を返します。

`string` はどんな文字列でも受け付けます。値そのものを書くリテラル型とは、受け付ける範囲が違います。型を `|` でつなぐ書き方は、既習のユニオン型です。型の `|` は1本、条件の「または」の `||` は2本です。

数も `1 | 2 | 3` のように候補を決められます。数には引用符を付けません。この型では4を受け付けません。

## 7-1-2 条件に合ったらその場で返す

> **if の中で return すると、関数はそこで終わります。**

ポットの表示を、温度の条件を上から順に確かめて決めます。

```ts
// お湯の温度から表示を決める
function waterLabel(temp: number): "熱い" | "適温" | "ぬるい" {
  if (temp >= 90) {
    return "熱い";
  }
  if (temp >= 60) {
    return "適温";
  }
  return "ぬるい";
}
// 75度のお湯の表示を確かめる
console.log(waterLabel(75)); // => "適温"
console.log(waterLabel(95)); // => "熱い"
console.log(waterLabel(50)); // => "ぬるい"
```

75度は90度以上ではないので、最初の `if` では返しません。次の60度以上に合うため、`"適温"` を返して関数が終わります。後ろの `return "ぬるい";` は実行されません。

最後の行に来るのは、前の二つの条件に合わなかったときだけです。候補が3つ以上でも、`else` を何重にも重ねずに書けます。

95度なら、最初の条件で `"熱い"` を返します。60度以上でもありますが、次の条件には進みません。広い条件を先に置くと返す値が変わるため、条件の順番も確かめましょう。

### 応用 リテラル型

**テストで確かめる値**

- `move(5, "up")` は `6`
- `move(5, "down")` は `4`
- `move(5, "left")` は 型の確認でエラー。`"left"` は渡せないこと
- `START_POSITION` は `0`。型も `0` であること
- `move(START_POSITION, "up")` は `1`

**ヒント 1 日本語の手順**

```ts
// 関数 move を作る。数の position と、"up" か "down" の direction を受け取り、数を返す
export function move() {
  // もし direction が "up" と等しいなら
  //   position に 1 を足した数を返す
  // position から 1 を引いた数を返す
}

// 定数 START_POSITION を作り、0 を入れる（export を付け、型注釈は書かない）
```

**ヒント 2 コードへの直し方**

`move` の引数は、問13 と同じく数と 2 つのリテラル型です。中はこのまとめの `waterLabel` と同じ、`if` の中で返す形です。`START_POSITION` は q03 の問1 と同じ `export const` です。説明することは、`let` と `const` で 1 つずつ変数を作り、マウスを載せて型を見比べてから考えます。違いの理由は、「あとから入れ直せるか」から考えます。
