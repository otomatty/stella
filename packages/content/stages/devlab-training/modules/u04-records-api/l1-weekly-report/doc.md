# 週報の記録を API で返す

## このレッスンの目標

- [ ] HTTP メソッドとパスに応じて、Hono で処理を呼び分けられる
- [ ] 入力を確かめ、結果や失敗の理由を状態コードと JSON で返せる
- [ ] ポートを開かずに、応答と確定後の一覧をテストできる

事前課題の08章「非同期処理」で使った `async` と `await`、09章「組み込みの API とモジュール」で使った `import` と `export` を使います。

## メソッドとパスで処理を決める

> **API では、どの操作をするかをメソッドとパスで決めます。**

API は、別のプログラムから処理を呼び出すための窓口です。Hono では、HTTP メソッドとパスを処理に結び付ける設定をルートと呼びます。週報では一覧を読む処理に `app.get()`、記録の状態を変える処理に `app.post()` を使います。

パスの `:week` や `:id` は、リクエストごとに変わる部分です。たとえば `/weeks/2026-W10/records` が届くと、`c.req.param("week")` で `2026-W10` を読めます。今回、入力はパスで受け取ります。応答には、オブジェクトや配列を伝えられるテキスト形式の JSON を使います。

リクエストの本文に JSON がある API では、`await c.req.json()` で読み取れます。週報のルートを呼ぶときに必要な入力は、パスの週または ID だけです。

## 入力を確かめて状態コードを返す

受け取った週が、年4桁と `-W` と週番号2桁をつないだ形か確かめます。形式が違う場合は `c.json({ error: "対象週の形式が違います" }, 400)` のように、直す手がかりを返します。状態コードは、呼び出し側が処理の結果を判別するための番号です。

| 状態コード | 週報での意味 |
| --- | --- |
| 200 | 一覧を取得できた、または確定できた |
| 400 | 対象週の形式が違う |
| 404 | 指定された ID の記録が見つからない |

有効な週に記録が無ければ、空の一覧を 200 で返します。合計は第2単元の `sumWeek` に任せ、下書きも含めます。

## ポートを開かずに応答を確かめる

`await app.request("/weeks/2026-W10/records")` で、サーバーを起動せずに応答を受け取れます。`response.status` で状態コードを、`await response.json()` で JSON の内容を調べます。確定の動作は、同じアプリに `{ method: "POST" }` を指定してリクエストを渡し、そのあと一覧を読み直すと確かめられます。
