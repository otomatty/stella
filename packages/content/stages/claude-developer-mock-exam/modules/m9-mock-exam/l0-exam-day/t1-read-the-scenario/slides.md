# どれも動きそう
選択肢のどれもが、動く作り方に見えます。機能の名前だけでは決められません。

# 条件を拾ってから比べる
本番の問題は実際の仕事を映すように作られているので、場面の条件を拾ってから選択肢を比べます。
<!-- ノート: 公式の発表では、試験は専門家が実際の仕事を映すように作ったとされています。 -->
---
# 拾う言葉
| 問題文の言葉 | 効く選び方 |
| --- | --- |
| 利用者が待っている | ストリーミング |
| 翌日以降でよく、期限切れも回収できる | バッチ |
| 毎回同じ前半 | キャッシュ |
| 手順が毎回同じ | ワークフロー |
| 手元で動くサーバー | Agent SDK の MCP |
<!-- ノート: 費用・速さ・確実さのどれを優先するかの言葉も拾います。 -->
---
# 外していく
条件に 1 つでも合わない選択肢から外し、残ったものを比べます。
<!-- ノート: 「必ず」「すべて」のような強い言い方の選択肢は、仕様で本当にそうかを確かめます。 -->
