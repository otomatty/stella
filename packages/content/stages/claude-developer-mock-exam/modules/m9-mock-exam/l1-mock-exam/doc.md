# 模擬試験（70問・120分）

## このレッスンの目標

- [ ] 制限時間内に、判断の根拠となる仕様・ログ・業務条件を見つけられます。
- [ ] 採点後に弱い領域を特定し、別の入力で同じ判断を試せます。

## 9-1-1 模擬試験で弱点を見つける

> **模擬試験は時間を計って通しで解き、間違えた問題の単元に戻って直します。**

Claude Certified Developer: Foundations の実務判断を練習する、STELLA のオリジナル模試です。公式ガイドによると、本番は **70 問・120 分** で、採点対象は 60 問です。残り 10 問は試験中に区別できません。STELLA では復習に使えるよう **70 問すべてを採点**します。

### 解く前に

手元にタイマーとメモを用意します。120 分のうち、たとえば最初の 100 分をひと通りの解答に、残り 20 分を見直しに使います。複数選択には選ぶ数を明記しています。迷ったときは「在庫照会でエラー」「根拠不足の 10 件」など、場面を思い出せる言葉と迷った理由を控えます。STELLA では設問と選択肢の表示順が毎回変わります。

### 採点したら、戻る場所を選ぶ

全問に答えて「採点する」を押します。結果が出たら、その場で不正解の解説から「範囲」と「復習」を控えます。正解でも理由を説明できなかったものには「？」を付けます。

| ガイドの領域 | 模試の問題数 | 基礎ステージに戻って確かめること |
| --- | ---: | --- |
| D1 Agents and Workflows | 12 | M6「段に分けてつなぐ」で、中間の検査に落ちたときに次の段が呼ばれないことを確認する |
| D2 Applications and Integration | 14 | M1「止まった理由で処理を分ける」と M2「送り直せるエラーだけを送り直す」で、拒否と過負荷をそれぞれ入力する |
| D3 Claude Code | 6 | M8 のレッスン 8-1 で、常に読む指示・必要なときだけ使う手順・実行前に止めるフックを用途ごとに選ぶ |
| D4 Eval, Testing, and Debugging | 7 | M8「評価のセットで比べる」で全体の正解率と個々の後退を照合し、8-2-4 で人の判定と採点器を比べる |
| D5 Model Selection and Optimization | 8 | M3「費用を見積もる」で入出力を変えて比較し、品質と応答時間の採用条件も確認する |
| D6 Prompt and Context Engineering | 10 | M4「抽出のスキーマを書く」で、デモを希望して日付が空欄の入力と、希望していないのに日付がある入力を比べる |
| D7 Security and Safety | 6 | M7「要るツールだけを許可する」で、読み取りだけの担当が記録を更新できないことを確認する |
| D8 Tools and MCP | 7 | M5「ツールの失敗で止まるのを直す」で、2 件の呼び出しの片方だけが失敗した結果を返す |

各領域の正解数を「問題数 − 不正解数」で求めます。たとえば、D2 が 14 問中 2 問の誤答、D4 が 7 問中 3 問の誤答なら、正解率はそれぞれ約 86% と約 57% です。先に D4 の誤答に取り組みます。総合点が高くても、根拠を説明できなかった「？」は復習に含めます。本番の合否は尺度点で決まります。ここで計算した正解率は復習の優先順位に使います。

### 条件を一つ変えて解き直す

採点で迷った場面ごとに、次の 3 行を残します。例は注文照会のケースです。

1. **判断を分けた事実**　検索は完了したが 0 件だった。
2. **この条件での処理**　「該当なし」を正常な検索結果として返す。
3. **別の入力での処理**　検索先に接続できなかった場合は、0 件と決めず、照会失敗を対応する呼び出しに返す。

戻った単元の課題を開き、手元のメモに「別の入力・期待結果・実装が通る分岐」を 1 行書きます。実装を指で追って、期待した結果に着くか確かめます。翌日は解説を閉じ、メモの「事実」だけを見て処理と理由を説明します。まだ迷う領域は「Claude Developer 実務一問一答」の同じ領域に戻り、条件を変えた一問を解きます。
