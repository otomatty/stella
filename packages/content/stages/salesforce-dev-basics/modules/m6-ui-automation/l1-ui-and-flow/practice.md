# レッスン6-1 演習 — 画面と自動化の作り方

対象トピック: 6-1-1 〜 6-1-3

## 手元で試す

Developer Edition 組織で、コードを書かずに画面と自動化を作ります。

1. **レコードページを編集する** — 点検レコードを 1 件開き、右上の歯車 →「編集ページ」で Lightning アプリケーションビルダーを開きます。左の部品一覧から「関連リスト」を画面に置いて保存し、有効化してください
2. **表示条件を付ける** — 置いた部品を選び、右側の「コンポーネントの表示」から条件を足します。たとえば「結果が要再点検のときだけ表示」のような条件をクリックだけで作れます
3. **Flow を作る** — 設定 →「フロー」→「新規フロー」→「レコードトリガフロー」。オブジェクトに `点検`、トリガを「レコードが作成されたとき」にして、結果が空なら `要再点検` を入れる更新を組み立てます
4. **4-2-1 のトリガと見比べる** — 同じことを Apex トリガで書いたときとの違い(テストの要否、直せる人)を確かめてください

```text
確かめること
- Flow はテストクラスを書かなくても有効化できる
- Apex トリガと同じ結果が、コードなしで作れている
```

## 演習問題

### 問1(基本)

LWC のフォルダに置く 3 つのファイルと、それぞれの役割を答えてください。

### 問2(基本)

「作った LWC が、Lightning アプリケーションビルダーの部品一覧に出てこない」という相談を受けました。まず何を疑いますか。1 文で答えてください。

### 問2-2(基本)

「取引先の名前と電話を表示するだけの LWC を作りたい」と頼まれました。まず何を検討しますか。1〜2 文で答えてください。

### 問3(応用)

「商談を保存したら、金額が 100 万円を超える場合に上長へ通知したい」と頼まれました。Flow と Apex トリガのどちらで作りますか。理由とあわせて 2〜3 文で説明してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

`.html` が見た目、`.js` がふるまい、`.js-meta.xml` がどこに置ける部品かの設定です。3 つを同じ名前のフォルダにまとめて置きます。

</details>

<details>
<summary>問2の解答例</summary>

`.js-meta.xml` が無いか、そこに配置先の指定が書かれていないことを疑います。

</details>

<details>
<summary>問2-2の解答例</summary>

そもそも自作せず、標準の部品(`lightning-record-form` など)や、6-1-1 の項目のセクションで済まないかを確かめます。足りない場合も、まずは Lightning データサービスの wire アダプタで取得できるかを見て、Apex は最後に検討します。

</details>

<details>
<summary>問3の解答例</summary>

Flow で作ります。保存時に条件を判定して通知するだけなので、クリックで組み立てられる範囲に収まります。Apex にするとテストクラスとリリース手順が必要になり、条件の金額を変えるだけでも開発者の作業になってしまいます。

</details>

## 確認クイズ

### Q1. レコードページに部品を並べて画面を作る設定画面はどれですか。

- A. Lightning アプリケーションビルダー
- B. 開発者コンソール
- C. オブジェクトマネージャ

<details>
<summary>答え</summary>

**A** — 標準の部品を並べるだけで、かなりの要件が満たせます。まずここを試します。

</details>

### Q2. 同じオブジェクトで、営業と管理者に別の画面を見せたいときの方法として正しいものはどれですか。

- A. 1 つのページに条件分岐を大量に書く
- B. ページを分けて、プロファイルごとに割り当てる
- C. オブジェクトを 2 つ作る

<details>
<summary>答え</summary>

**B** — 割り当てで分けられます。コードを書く前に潰せる要件の代表例です。

</details>

### Q3. Flow と Apex トリガの違いとして正しいものはどれですか。

- A. Flow にもテストクラスが必要
- B. Apex トリガは管理者でも直せる
- C. Flow はクリックで作れ、テストクラスが不要

<details>
<summary>答え</summary>

**C** — 運用に入ったあとの直しやすさが効いてきます。Apex は些細な変更でもリリース手順が要ります。

</details>

### Q4. Apex を選ぶ理由として適切なものはどれですか。

- A. コードのほうが速く書けるから
- B. 複雑なくり返しや外部システムとの連携など、Flow では表現できないことがあるから
- C. Flow より新しい仕組みだから

<details>
<summary>答え</summary>

**B** — 「Flow では無理だから」と説明できることが選択の基準になります。

</details>

### Q5. LWC でレコードを表示したいとき、最初に検討すべきものはどれですか。

- A. Apex のメソッドを書いて呼び出す
- B. 標準の部品や Lightning データサービスで足りないかを確かめる
- C. LWC の JavaScript から直接データベースに接続する

<details>
<summary>答え</summary>

**B** — ここでも「標準が先」です。レコードの表示・作成・編集は標準の部品とデータサービスでほとんど賄えて、キャッシュも更新の反映もアクセス権の確認も基盤がやってくれます。Apex は、それらで表現できないときの最後の手段です。

</details>
