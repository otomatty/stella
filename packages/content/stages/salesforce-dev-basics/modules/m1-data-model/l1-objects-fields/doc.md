# レッスン1-1 オブジェクトと項目

## このレッスンの目標

- [ ] オブジェクト・レコード・項目を、表・行・列に言い換えられる
- [ ] 標準オブジェクトとカスタムオブジェクトを API 参照名で見分けられる
- [ ] 項目のデータ型を、要件から選べる

## 1-1-1 オブジェクト・レコード・項目

> **オブジェクトが表、レコードが行、項目が列にあたる**

SQL で学んだ表・行・列は、Salesforce では別の名前で呼ばれます。中身は同じです。

| SQL の言葉 | Salesforce の言葉 |
| --- | --- |
| 表(テーブル) | オブジェクト |
| 行 | レコード |
| 列 | 項目 |

取引先オブジェクトを例にすると、表全体が **オブジェクト**、1 行が **レコード**、1 列が **項目** です。

| 取引先名 | 電話 | 従業員数 |
| --- | --- | --- |
| 富士商事 | 03-1111-2222 | 120 |
| 北星建設 | 011-333-4444 | 45 |

現場の会話は「取引先オブジェクトの項目を足して」のように進みます。言い換えができれば、知っている知識のまま会話に乗れます。

## 1-1-2 標準オブジェクトとカスタムオブジェクト

> **はじめから在る標準オブジェクトに足りない分だけ、末尾が `__c` のカスタムオブジェクトを作る**

**標準オブジェクト** は、取引先・取引先責任者・商談など、最初から用意されている箱です。業務でよく使う形があらかじめ整えられていて、関連する機能もそれ前提で作られています。足りないときに自分たちで足す箱が **カスタムオブジェクト** です。

見分けるのは **API 参照名**(コードや設定から指すときの内部の名前)です。

| 名前 | 種類 |
| --- | --- |
| `Account` | 標準オブジェクト |
| `Contact` | 標準オブジェクト |
| `Inspection__c` | カスタムオブジェクト |

画面の表示名は日本語でも、コードから触るのは常に API 参照名です。末尾の `__c` が自作の印になります。

箱を作る前に、次の 2 つを確かめてください。

- 標準オブジェクトで足りないか
- 足りないのは箱ごとか、**項目 1 つ**か

箱を増やすと、画面・権限・レポートが全部ついて回ります。項目を足すだけで済む要件を箱にしてしまう手戻りは多いので、先に一段小さく考えます。

## 1-1-3 項目の型

> **項目は先にデータ型を決めてから作る**

項目を作る画面は、最初に **データ型**(その項目に入れてよい値の種類)を聞いてきます。型が決まると、入力チェック・並べ替え・集計のふるまいも決まるからです。

| 型 | 入るもの |
| --- | --- |
| テキスト | 名前・メモ |
| 数値 / 通貨 | 個数・金額 |
| 日付 | 期日 |
| 選択リスト | 決まった選択肢から 1 つ |
| チェックボックス | はい / いいえ |

選択肢が決まっているものをテキストにすると、表記ゆれで集計できなくなります。金額を数値ではなくテキストにすると、合計も並べ替えもできません。

計算できる値は保存しません。**数式項目**(他の項目から自動で計算される読み取り専用の項目)にします。単価 × 数量を普通の数値項目で持つと、元の値を直したときに食い違います。

## 1-1-4 外部 ID で他システムのキーを持つ

> **他システムのキーを外部 ID 項目に持たせると、その値でレコードを指定できる**

**ID** は Salesforce が全レコードに自動で付ける、組織内で一意の値です。ただし、外部の基幹システムはこの ID を知りません。そこで相手側の一意なキーを入れておく項目が **外部 ID** です。

| 取引先名 | 社内コード(外部 ID) |
| --- | --- |
| 富士商事 | `AC-0012` |
| 北星建設 | `AC-0037` |

外部 ID には「重複しない」設定を併せて付けるのが定石です。コードを持っていれば、社名が変わっても同じレコードを指せます。

取り込み処理では **upsert**(外部 ID に一致するレコードがあれば更新、なければ作成)を使います。何度流してもレコードは増えません。名前で突き合わせようとすると表記ゆれで失敗し、同じ会社が何件も並ぶことになります。
