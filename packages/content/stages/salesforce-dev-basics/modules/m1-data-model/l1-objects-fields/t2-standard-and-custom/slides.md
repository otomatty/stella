# 標準オブジェクトとカスタムオブジェクト

Salesforce開発入門 — Module 1 / レッスン1-1

<!-- ノート: 箱を誰が用意するのかという話です。設定が先という原則が、データモデルにも効いていることを見せます。 -->

---

## なぜ必要か

- 顧客を管理したいとき、まず「顧客オブジェクトを作ろう」と考えてしまう
- 実は同じ用途の箱が最初から用意されていることが多い

<!-- ノート: つかみ。0-1-3の「設定が先」がデータモデルでも同じ形で現れる、という位置づけ。 -->

---

## 結論

**はじめから在る標準オブジェクトに足りない分だけ、末尾が `__c` のカスタムオブジェクトを作る**

- **標準オブジェクト** — 取引先・取引先責任者・商談など、最初から在る箱
- **カスタムオブジェクト** — 自分たちで足す箱

<!-- ノート: 結論を言い切る。標準オブジェクトは業務でよく使う形があらかじめ整えられていて、関連する機能もそれ前提で作られていることを補足する。 -->

---

## API 参照名で見分ける

| 名前 | 種類 |
| --- | --- |
| `Account` | 標準オブジェクト |
| `Contact` | 標準オブジェクト |
| `Inspection__c` | カスタムオブジェクト |

- **API 参照名** — コードや設定から指すときの、内部の名前

<!-- ノート: 具体例。画面の表示名は日本語だが、コードから触るのは常にAPI参照名。末尾の__cが自作の印になる、と指差す。 -->

---

## 作る前に確かめること

- 標準オブジェクトで足りないか
- 足りないのは箱ごとか、**項目 1 つ**か
- 項目 1 つで済むなら、カスタムオブジェクトは作らない

<!-- ノート: 失敗例の枠。箱を増やすと、画面・権限・レポートが全部ついて回る。項目を足すだけで済む要件を箱にしてしまう手戻りが多い。 -->
