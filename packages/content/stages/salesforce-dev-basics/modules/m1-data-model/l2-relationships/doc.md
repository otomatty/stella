# レッスン1-2 リレーション

## このレッスンの目標

- [ ] 参照関係と主従関係の違いを 3 点挙げられる
- [ ] 要件からどちらのリレーションを使うか選べる
- [ ] 子の集計を親に持たせるとき、コードを書かずに済ませられる

## 1-2-1 参照関係でゆるくつなぐ

> **参照関係は、親が消えても子が残るゆるいつながりである**

商談には必ず取引先がひもづきます。取引先名を商談にテキストで書いてしまうと、社名変更のたびに全件を直すことになります。そこで **リレーション**(オブジェクトどうしをつなぐ項目)を使います。

- **親レコード** — 指される側
- **子レコード** — 指す側(リレーションの項目を持つ側)

| 商談名 | 取引先(参照) | 金額 |
| --- | --- | --- |
| 富士商事 4月分 | 富士商事 | 500000 |
| 北星建設 保守 | 北星建設 | 120000 |

参照項目に入っているのは名前ではなく、取引先レコードの ID です。画面には名前が表示されますが、中身は指し先です。

**参照関係** の「ゆるさ」は、次の 3 点に現れます。

- 親を消しても、子は残る(既定では参照が空になる)
- 親が無い子を作ってもよい
- 別のオブジェクトの子から、同じ親を指してもよい

1 点目は既定の動きです。項目の設定で「参照先が削除されるのを許可しない」も選べます。どちらにしても、主従関係のように子が道連れで消えることはありません。

## 1-2-2 主従関係で親に従属させる

> **主従関係は子を親に従属させ、親を消すと子も消える**

![親を消したときと親が空の子を作るときで、参照関係と主従関係の振る舞いを対比した図](t2-master-detail/assets/lookup-vs-master-detail.svg)

注文明細だけが残っても、何の明細かわかりません。親が無ければ意味をなさないデータには **主従関係** を使います。親を削除すると子も一緒に消える **連鎖削除** が起きます。

前のトピックの 3 点が、そのまま反転します。

| | 参照関係 | 主従関係 |
| --- | --- | --- |
| 親を消すと | 子は残る | 子も消える |
| 親が空の子 | 作れる | 作れない |
| アクセス権 | 別々 | 親に従う |

選ぶときの問いは 1 つです。

- その子は、親が無くても意味があるか
- **ある** → 参照関係
- **ない** → 主従関係

注文と明細は主従関係、取引先と商談は参照関係です。迷ったら弱いほう(参照関係)から始めるのが安全です。

## 1-2-3 積み上げ集計項目

> **子の合計や件数を親に持たせる積み上げ集計項目は、主従関係でだけ作れる**

注文の画面に「明細の合計金額」を出したい、という要件はよく来ます。明細が増減するたびに合計を計算するコードを書きたくなりますが、その前に **積み上げ集計項目** を思い出してください。子レコードの件数・合計・最大・最小を、親に自動で持たせる項目です。

| 注文番号 | 明細件数 | 合計金額 |
| --- | --- | --- |
| ORD-001 | 3 | 42000 |
| ORD-002 | 1 | 8000 |

明細を 1 件足せば、この 2 列は自動で変わります。明細側で金額を直したときも追随します。

1-1-3 の数式項目と役割が似ていますが、範囲が違います。

| やりたいこと | まず試すもの |
| --- | --- |
| 同じレコード内の計算 | 数式項目 |
| 子レコードの集計 | 積み上げ集計項目 |
| どちらでも足りない | Apex |

積み上げ集計項目は参照関係のままでは作れません。集計したいのにリレーションが参照関係なら、コードを書く前に**関係の設計に戻る**のが正しい順番です。
