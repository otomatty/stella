## なぜ必要か

- 画面では他人の商談が見えないのに、自作の一覧には全件出ることがある
- 逆に、動いていたコードが権限エラーで止まることもある

<!-- ノート: つかみ。原因が設定側かコード側かを切り分けられないと、設定画面を延々と探すことになる。両方向の事故を先に見せる。 -->

---

## 結論

**いまの Apex は、既定で実行ユーザの権限に従って動く**

- **ユーザモード** — オブジェクト・項目・レコードの 3 つとも確認して動くこと
- **システムモード** — 権限を確認せずに動くこと

<!-- ノート: 結論を言い切る。2-1-1でやった3つの層が、そのままコードにも効く。かつては逆(既定がシステムモード)だったので、古い解説記事とは食い違うと添える。 -->

---

## 最小のコード

```apex
public with sharing class OrderService {
  // 検索も更新も、実行ユーザに許された範囲だけ
}
```

- **with sharing** — レコードの共有に従うことを明示する宣言

<!-- ノート: 最小のコード。いまは宣言しなくてもこの動きになるが、意図を残すために書く。読む人が「わざとそうしている」と分かる。 -->

---

## 古いコードは既定が違う

| | **APIバージョン** 66.0 以前 | 67.0 以降 |
| --- | --- | --- |
| 既定の動き | システムモード | ユーザモード |
| 宣言の無い Apex | 共有を無視 | 共有に従う |

- 案件のコードを読むときは、まずバージョンを見る

<!-- ノート: 対比枠。既存の案件には古いバージョンのコードが必ず残っている。同じ書き方でも意味が違うので、動きを推測する前にバージョンを確かめる、と締める。 -->
