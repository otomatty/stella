# 5-1-2
# テストデータは自分で作る

Salesforce開発入門 — Module 5 / レッスン5-1

<!-- ノート: テストの独立性の話です。理由まで伝えると、面倒な作業ではなく必然だと受け取ってもらえます。 -->

---

## なぜ必要か

- Sandbox では通ったテストが、本番組織へのリリース時に落ちる
- 手元にあったレコードが、向こうには無い

<!-- ノート: つかみ。組織ごとにデータが違う以上、既存データに頼るテストは移した瞬間に壊れる。 -->

---

## 結論

**テストは組織のデータを見ないので、必要なレコードはテストの中で作る**

- **テストデータ** — テストの中で作る、そのテスト専用のレコード
- テストで作ったレコードは、テストが終わると消える

<!-- ノート: 結論を言い切る。既定で組織のデータから遮断されている。だからどの組織で走らせても同じ結果になる、という利点として説明する。 -->

---

## テストの中で用意する

```apex
@isTest
static void countsOrders() {
  Account acc = new Account(Name = 'テスト商事');
  insert acc;
  // ここで対象のコードを動かす
}
```

- 本番組織に `テスト商事` は残らない

<!-- ノート: 最小のコード。insertしてもロールバックされるので、本番のデータは汚れない。安心して作ってよい、と伝える。 -->

---

## 束でも動くことを確かめる

| 作るデータ | 確かめられること |
| --- | --- |
| 1 件 | 動くこと |
| 200 件 | 一括処理になっていること |

- 4-2-2 の事故は、200 件のテストでしか見つからない

<!-- ノート: 対比枠。1件のテストは「書いた」証拠にはなるが、バルク対応の証明にはならない。リストで200件作るテストを1本入れる習慣を勧める。 -->
