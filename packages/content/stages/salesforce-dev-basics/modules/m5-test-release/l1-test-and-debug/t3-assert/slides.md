# 5-1-3
# アサーションで結果を確かめる

Salesforce開発入門 — Module 5 / レッスン5-1

<!-- ノート: 5-1-1で予告した「空テスト」を潰すトピックです。カバー率とテストの価値は別物だと切り分けます。 -->

---

## なぜ必要か

- カバー率は 90% あるのに、バグがそのまま本番に出た
- テストは全部通っていた

<!-- ノート: つかみ。実際に起きる。通ったことと正しいことは違う、という話に持っていく。 -->

---

## 結論

**実行できたことではなく、期待した値になったことをアサーションで確かめる**

- **アサーション** — 「こうなっているはず」を書いて、違えばテストを失敗させる命令

<!-- ノート: 結論を言い切る。アサーションが1つも無いテストは、行を通すだけの装置。カバー率は稼げるが何も守らない。 -->

---

## 最小のコード

```apex
Order__c saved = [SELECT Status__c FROM Order__c WHERE Id = :order.Id];
Assert.areEqual('受付', saved.Status__c, 'Status が初期化されていない');
```

- 期待値・実際の値・失敗時のメッセージを渡す

<!-- ノート: 最小のコード。保存後の値をSOQLで取り直してから確かめる点が大事。変数のままでは、保存されたかどうかを確かめたことにならない。 -->

---

## テストの値打ちが変わる

| テストの中身 | 守れるもの |
| --- | --- |
| 動かすだけ | カバー率 |
| アサーションあり | ふるまい |

- 1 テストにつき、確かめたいことを 1 つ書く

<!-- ノート: 対比枠。カバー率は関門を通るための数字、アサーションは仕様を守るための仕掛け。目的が違う2つだと整理して締める。 -->

---
