# 4-2-2
# トリガは束で呼ばれる

Salesforce開発入門 — Module 4 / レッスン4-2

<!-- ノート: 一括処理が「行儀のよい書き方」ではなく「必須」になる理由です。ここが腑に落ちると4-2-3が自然に入ります。 -->

---

## なぜ必要か

- 画面から 1 件保存するぶんには、何を書いても動いてしまう
- データ取り込みを流した途端に、同じコードが落ちる

<!-- ノート: つかみ。テストは通ったのに本番で落ちる、という典型。1件で試したことが検証になっていない。 -->

---

## 結論

**トリガは 1 件ずつではなく、最大 200 件の束で呼ばれる**

- **バッチサイズ** — 1 回のトリガ実行にまとめて渡される件数
- `Trigger.new` に 200 件入ってくることがある

<!-- ノート: 結論を言い切る。1000件を取り込むと、200件ずつ5回に分けて呼ばれる。1回ぶんの中で200件を扱う覚悟が要る。 -->

---

## 1 件前提の書き方

```apex
trigger OrderTrigger on Order__c (before insert) {
  Order__c order = Trigger.new[0];   // 危ない
  order.Status__c = '受付';
}
```

- 先頭の 1 件しか処理されない

<!-- ノート: 失敗例のコード。動くし、画面から1件保存するテストは通ってしまう。残り199件が無言で処理されない点を指差す。 -->

---

## 束を前提に書き直す

```apex
for (Order__c order : Trigger.new) {
  order.Status__c = '受付';
}
```

- 常にリストとして回す。件数を仮定しない

<!-- ノート: 対比枠。修正形。1件でも200件でも同じコードで正しく動く。この形を既定にしてしまえば、件数を気にしなくてよくなる。 -->

---

## まとめ

**トリガは 1 件ずつではなく、最大 200 件の束で呼ばれる**
