# sObject型の変数

Salesforce開発入門 — Module 4 / レッスン4-1

<!-- ノート: Apexとデータモデルのつなぎ目です。オブジェクトがそのまま型になる、という点が他の言語と違います。 -->

---

## なぜ必要か

- 取り出したレコードを、コードの中で持ち回りたい
- 項目ごとに変数を作ると、レコード 1 件のために何個も変数が要る

<!-- ノート: つかみ。名前・電話・住所…と個別に受ける書き方の面倒さを想像してもらう。 -->

---

## 結論

**sObject 型の変数は、レコード 1 件をそのまま入れられる**

- **変数** — 値に名前を付けて持っておく入れ物
- **sObject** — レコードを表す型。オブジェクトの API 参照名がそのまま型名になる

<!-- ノート: 結論を言い切る。Accountというオブジェクトがあれば、Accountという型が使える。設定で箱を作ると型も増える、という関係を説明する。 -->

---

## 最小のコード

```apex
Account acc = new Account(Name = '富士商事');
acc.Phone = '03-1111-2222';
System.debug(acc.Name);
```

- 項目にはドットで触る

<!-- ノート: 最小のコード。newで作り、ドットで項目に代入する。System.debugはログに出す命令で、Module 5で詳しくやると添える。 -->

---

## クエリの結果を受け取る

```apex
Id target = '001000000000001';
Account acc = [SELECT Name FROM Account WHERE Id = :target];
```

- **バインド変数** — クエリの中で `:` を付けて変数を指す書き方

<!-- ノート: 具体例の枠。角かっこのSOQLは結果をそのまま代入できる。文字列を連結してクエリを組み立てないこと、と口頭で釘を刺す。 -->
