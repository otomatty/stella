# レッスン4-1 Apex の基本

## このレッスンの目標

- [ ] Apex がどこで動き、何を単位に制限が数えられるかを説明できる
- [ ] sObject 型の変数でレコードを扱える
- [ ] DML をリストで 1 回だけ呼ぶ形が書ける

## 4-1-1 Apex はどこで動くか

> **Apex は Salesforce のサーバー上で動く、この基盤専用の言語である**

文法は Java に近いのですが、動くのは常に Salesforce のサーバーです。手元の PC では動かせません。

- **クラス** — Apex のコードを入れるまとまり
- **メソッド** — クラスの中の、処理のまとまり
- **トランザクション** — 1 回の処理のまとまり

```apex
public class OrderService {
  public static Integer countOrders() {
    return [SELECT COUNT() FROM Order__c];
  }
}
```

角かっこで囲むと、SOQL をコードの中に直接書けます。この書き方はこの基盤に固有のものです。

**トランザクション** は制限を数える単位でもあります。ユーザの 1 回の操作が 1 トランザクションで、ガバナ制限はそのたびに数え直されます。そして途中で失敗すると、その中の変更はすべて無かったことになります。数える単位と巻き戻す単位が同じ、と覚えてください。

## 4-1-2 sObject 型の変数

> **sObject 型の変数は、レコード 1 件をそのまま入れられる**

取り出したレコードをコードの中で持ち回るとき、項目ごとに **変数**(値に名前を付けて持っておく入れ物)を作っていては、レコード 1 件のために何個も必要になります。

**sObject** はレコードを表す型です。オブジェクトの API 参照名が、そのまま型名になります。`Account` というオブジェクトがあれば `Account` という型が使えます。設定で箱を作ると型も増える、という関係です。

```apex
Account acc = new Account(Name = '富士商事');
acc.Phone = '03-1111-2222';
System.debug(acc.Name);
```

項目にはドットで触ります。`System.debug` は値をログに出す命令で、5-1-4 で詳しく扱います。

クエリの結果も、そのまま変数で受け取れます。

```apex
Id target = '001000000000001';
Account acc = [SELECT Name FROM Account WHERE Id = :target];
```

クエリの中で `:` を付けて変数を指す書き方が **バインド変数** です。文字列を連結してクエリを組み立てるのではなく、必ずこの形を使ってください。

## 4-1-3 DML でレコードを保存する

> **DML(`insert` / `update` / `delete`)がレコードを実際に書き換える**

変数の項目を書き換えたのに画面の値が変わらない、というのは初学者が必ず一度は踏みます。エラーも出ないので気づきにくいところです。

取り出す(SOQL)と書き込む(**DML**)は別の命令で、書き込みは明示しないと起きません。変数の書き換えは、まだメモリの中の話です。

```apex
Account acc = new Account(Name = '富士商事');
insert acc;
acc.Phone = '03-1111-2222';
update acc;
```

`insert` した時点で ID が割り当てられ、以降の `update` はその ID のレコードを直します。

4 つ目の命令として `upsert` があります。

| 命令 | 動き |
| --- | --- |
| `insert` | 必ず新規作成 |
| `update` | 必ず更新 |
| `upsert` | 外部 ID で探して、無ければ作成 |

1-1-4 で作った外部 ID がここで効いてきます。取り込み処理では `upsert` が定石です。

## 4-1-4 リストにまとめて渡す

> **レコードはリストにまとめて、DML を 1 回だけ呼ぶ**

100 件のレコードを作るのに `insert` を 100 回呼ぶと、上限の 150 回に近づきます。件数が増えれば、いつか必ず超えます。

- **リスト** — 同じ型の値を順番に入れておく入れ物
- **一括処理** — まとめて 1 回で処理する書き方

```apex
List<Account> rows = new List<Account>();
rows.add(new Account(Name = '富士商事'));
rows.add(new Account(Name = '北星建設'));
insert rows;
```

`add` でためていき、最後に 1 回 `insert` します。DML は 1 件でもリストでも 1 回と数えられるので、まとめたほうが常に得です。

| 書き方 | DML の回数 |
| --- | --- |
| 1 件ずつ 100 回 | 100 |
| リストで 1 回 | 1 |

まとめて減らせるのは **回数** のほうです。件数そのものが消えるわけではありません。

| 数えるもの | 上限 |
| --- | --- |
| DML の回数 | 150 |
| DML が触った行数 | 10,000 |

行数には別の上限があり、1 回の `insert` でも 10,000 行を超えれば落ちます。まとめる作法は回数の上限に効く対策で、大量データを流すときは分割も要る、と切り分けて覚えてください。
