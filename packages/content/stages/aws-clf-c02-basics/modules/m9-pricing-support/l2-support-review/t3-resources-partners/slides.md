# 困ったときの情報源

AWS Cloud Practitioner 入門 — Module 9 / レッスン9-2

## なぜ必要か

- すべての困りごとをサポート起票で解決するわけではない
- 調べる・聞く・買う・頼む、で入口が違う
- 試験も「この困りごとはどこへ?」を選ばせる

<!-- ノート: つかみ。動詞4つ(調べる・聞く・買う・頼む)を先に配る。 -->

---

## 結論

**公式ドキュメント・re:Post・Marketplace・パートナーと、困りごとに応じた入口を使い分ける**

- **re:Post** = 公式のQ&Aコミュニティ
- **Marketplace** = 出来合いのソフトウェアを買えるカタログ
- **パートナーネットワーク** = 導入・構築を頼める認定事業者の制度(APN)

<!-- ノート: 結論。3つの名前を動詞に対応させる。 -->

---

## 最小の例

| 困りごと | 入口 |
| --- | --- |
| 仕様を調べたい | 公式ドキュメント |
| 使い方を聞きたい | **re:Post**(Q&Aコミュニティ) |
| 出来合いのソフトを買いたい | **Marketplace** |
| 導入・構築を頼みたい | **パートナーネットワーク** |

<!-- ノート: 表の左の動詞で選ぶ。どれも契約プランと無関係に使える。 -->

---

## 試験での聞かれ方

- 「サードパーティ製ソフトを見つけて導入」→ Marketplace
- 「移行の支援をしてくれる事業者」→ パートナー
- 「コミュニティに質問」→ re:Post
- Professional Services(AWS自身のコンサル部隊)も名前だけ

<!-- ノート: 補強枠。パートナー(社外の認定事業者)とProfessional Services(AWS自身)の区別を一言。 -->
