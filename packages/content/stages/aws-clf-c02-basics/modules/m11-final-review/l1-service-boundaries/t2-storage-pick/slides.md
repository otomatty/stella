# 11-1-2
# ストレージは接続の形で選ぶ

AWS Cloud Practitioner 入門 — Module 11 / レッスン11-1

<!-- ノート: 記録の次はストレージ。3つとも「保存できる」ので、保存という言葉では決まりません。 -->

---

## なぜ必要か

- S3・EBS・EFS はどれも「データを保存する」サービス
- 設問文の「保存したい」だけを読むと3つとも正解に見える
- 決め手は保存できるかどうかではなく、**どう繋いで使うか**

<!-- ノート: つかみ。ここでも名前ではなく用途で切ります。結論はまだ言わない。 -->

---

## 結論

**ストレージは、置くだけならS3・1台に付けるならEBS・複数台で共有するならEFSと接続の形で選ぶ**

- S3 = ネットワーク越しにAPIで読み書きする置き場
- EBS = 1台のEC2に取り付けるディスク
- EFS = 複数のEC2から同時にマウントする共有

<!-- ノート: 結論。「置く・付ける・共有する」の3動詞で言えるようにします。 -->

---

## 最小の例

| 設問の言い回し | 選ぶもの |
| --- | --- |
| 画像・ログ・バックアップを大量に置きたい | S3 |
| EC2のシステムディスクやDBのデータ領域が要る | EBS |
| 複数のEC2から同じファイルを同時に読み書きしたい | EFS |
| Windows向けのSMB共有フォルダーが要る | FSx |
| ほとんど読まないデータを最安で保管したい | S3 Glacier系のクラス |

<!-- ノート: 5行。最後の行だけはサービスではなくクラスの話なので、S3の中の選択だと補足する。 -->

---

## よくある誤り

- 「S3をEC2にマウントして普通のフォルダーとして使う」→ S3はAPIで読み書きするオブジェクトストレージ
- 「EBSを複数のEC2で同時に共有する」→ 共有が要るならEFS
- 「アーカイブ用に安いEBSを選ぶ」→ 長期保管はS3のGlacier系

<!-- ノート: 補強枠。誤答の選択肢はこの3つの形で作られます。言い切りで否定できるようにしておく。 -->
