# 11-1-5
# 移し方は量と中身で決まる

AWS Cloud Practitioner 入門 — Module 11 / レッスン11-1

<!-- ノート: レッスン11-1の最後です。移行の道具は8-1で一度出ていますが、選択肢に並ぶと迷うので改めて切り分けます。 -->

---

## なぜ必要か

- 移行の設問は「オンプレミスからAWSへ移したい」で始まる型が多い
- Snow・DMS・DataSync・Storage Gateway がまとめて選択肢に並ぶ
- 「移す」という言葉だけでは、4つとも当てはまってしまう

<!-- ノート: つかみ。ここも動詞ではなく、運ぶ中身と経路で決まります。 -->

---

## 結論

**データの移し方は、回線で送りきれない量ならSnow、データベースならDMS、回線越しの同期ならDataSyncを選ぶ**

- 決め手は3つ — **量・中身・回線を使うかどうか**
- 移行のやり方の分類(7R)とは別の話

<!-- ノート: 結論。7Rは戦略の名前、ここで扱うのは運ぶ道具、と早めに線を引く。 -->

---

## 最小の例

| 状況 | 選ぶもの |
| --- | --- |
| 数十TB以上あり、回線で送ると数か月かかる | Snowファミリー |
| 稼働中のデータベースを止めずに移したい | DMS |
| オンプレのファイルサーバーからS3やEFSへ回線で転送したい | DataSync |
| 移行後もオンプレからAWSのストレージを使い続けたい | Storage Gateway |

<!-- ノート: 4行。最後の行だけが「移す」ではなく「橋渡し」であることを強調する。 -->

---

## 移行を支える2つ

- **Application Discovery Service** = 移行前にオンプレの資産を棚卸しする
- **Migration Hub** = 複数の移行の進捗を1画面で追う
- 「何を移すか決める前」= Discovery、「移している最中の管理」= Migration Hub
- 移すのは1回きり、Storage Gatewayは移した後も使い続ける道具

<!-- ノート: 補強枠。この2つは正解になる頻度は低いものの、消去法で迷わないために名前と一言を対応づけておく。 -->
