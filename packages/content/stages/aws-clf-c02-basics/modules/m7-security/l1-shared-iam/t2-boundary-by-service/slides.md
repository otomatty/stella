# 7-1-2
# 境界はサービス種別で動く

AWS Cloud Practitioner 入門 — Module 7 / レッスン7-1

<!-- ノート: 到達目標そのもの。「サービス種別に応じて境界を選べる」を作るトピックです。 -->

## なぜ必要か

- 共有責任の線は、1本の固定線ではない
- EC2とS3では、利用者のやることがまるで違う
- 「このサービスのとき、線はどこか」を選べるのが合格ライン

<!-- ノート: つかみ。前トピックの線が「動く」という展開。 -->

---

## 結論

**任せる範囲が広いサービスほどAWSの責任範囲が増え、EC2 → RDS → S3の順で利用者の担当は減る**

- M2のIaaS/PaaS/SaaSの軸が、そのまま責任の軸になる
- ただし、データとアクセス権は**常に利用者**

<!-- ノート: 結論。マネージドの度合い=責任の移り方。最後の1行が絶対例外なし。 -->

---

## 最小の例

| 作業 | EC2 | RDS | S3 / Lambda |
| --- | --- | --- | --- |
| OSのパッチ | 利用者 | AWS | AWS(見えない) |
| ソフトの面倒 | 利用者 | AWS(エンジン) | AWS |
| データと権限 | 利用者 | 利用者 | 利用者 |

<!-- ノート: 表を縦に読む。下の行だけがどの列でも利用者、を強調。 -->

---

## 試験での聞かれ方

- 「EC2のゲストOSのパッチ適用は誰?」→ 利用者
- 「RDSのデータベースエンジンのパッチは誰?」→ AWS
- 「Lambda利用時のサーバー管理は誰?」→ AWS
- パッチの主語(どのサービスの、どの層か)を読み取る
