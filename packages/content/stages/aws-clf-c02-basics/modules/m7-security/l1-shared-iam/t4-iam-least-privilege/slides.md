# 7-1-4
# IAMは最小権限で配る

AWS Cloud Practitioner 入門 — Module 7 / レッスン7-1

<!-- ノート: IAMの3部品と最小権限の原則を固める、ドメイン2の中心トピックです。 -->

---

## なぜ必要か

- ルートは封印した。では日常の権限は誰がどう持つのか
- 「全員に全部の権限」は、事故のときの被害も全部になる
- 権限を人と仕事に合わせて配る道具が要る

<!-- ノート: つかみ。合鍵を全員に配る会社は無い、の例え。 -->

---

## 結論

**IAMはユーザー・グループ・ポリシーで権限を管理し、仕事に必要な最小権限だけを許可する**

- **IAM** = AWSの権限管理サービス
- **最小権限** = 仕事に必要な権限だけを与える原則

<!-- ノート: 結論。3部品は次のスライドで。最小権限=least privilegeは英語ごと。 -->

---

## 最小の例

| 部品 | 役割 |
| --- | --- |
| **IAMユーザー** | 操作する人(またはアプリ)のID |
| **IAMグループ** | ユーザーの束(開発チーム、経理など) |
| **ポリシー** | 「何を許可するか」を書いた文書 |

- ポリシーをグループに付け、ユーザーをグループに入れるのが定石

<!-- ノート: 人・束・許可文書の3点。個人に直接付けず、グループ経由が運用の型。 -->

---

## 試験での聞かれ方

- 「必要最小限のアクセス許可を与える原則」→ 最小権限
- 「部署単位で権限をまとめて管理」→ IAMグループ
- 権限は「役割・仕事」に合わせ、人の偉さに合わせない

<!-- ノート: 補強枠。least privilegeの日本語言い換えを聞く問題が定番。 -->
