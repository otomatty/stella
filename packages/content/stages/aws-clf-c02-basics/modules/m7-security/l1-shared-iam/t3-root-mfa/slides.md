# 7-1-3
# ルートユーザーは金庫にしまう

AWS Cloud Practitioner 入門 — Module 7 / レッスン7-1

<!-- ノート: アカウント防御の第一歩。ルートの扱いとMFAを固めるトピックです。 -->

---

## なぜ必要か

- AWSの契約単位である**AWSアカウント**には、最初から全能のユーザーが1人いる
- そのIDが乗っ取られたら、環境ごと乗っ取られる
- 最初にやるべき守りが決まっている

<!-- ノート: つかみ。マスターキーの管理、の例え。アカウント=契約の器、と定義。 -->

---

## 結論

**ルートユーザーは日常では使わず、MFAを付けて必要なときだけ取り出す**

- **ルートユーザー** = アカウント作成時に生まれる、すべての操作ができるユーザー
- **MFA** = 多要素認証。パスワードに加えてもう1要素で確認する仕組み

<!-- ノート: 結論。全能ゆえに使わない。金庫にしまって鍵(MFA)を掛ける。 -->

---

## 最小の例

最初にやる3点セットです。

| 手順 | やること |
| --- | --- |
| 1 | ルートユーザーにMFAを設定する |
| 2 | 日常作業用のユーザーを別に作る(次トピック) |
| 3 | ルートは解約や請求設定など、ルートにしかできない作業だけに使う |

<!-- ノート: 「ルートにしかできない作業」が存在するので、封印はしても廃棄はしない。 -->

---

## 試験での聞かれ方

- 「ルートユーザーの保護としてまずやること」→ MFAの有効化
- 「日常の管理作業にルートを使う」→ 誤りの選択肢
- MFAはルートに限らず全ユーザーに推奨
