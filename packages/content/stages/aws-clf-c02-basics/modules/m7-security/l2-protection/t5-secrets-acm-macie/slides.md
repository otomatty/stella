# 7-2-5
# 秘密・証明書・個人情報の守り

AWS Cloud Practitioner 入門 — Module 7 / レッスン7-2

<!-- ノート: セキュリティの締め。KMSの周りにいる、守る対象別の3サービスを覚えるトピックです。 -->

---

## なぜ必要か

- DBのパスワードをコードに書けば、漏えいと差し替え作業がついて回る
- HTTPSには証明書が要り、証明書には期限切れ事故がついて回る
- S3のどこかに個人情報が紛れ込んでいないか、人手では見切れない

<!-- ノート: つかみ。暗号化の鍵はKMSに任せました。残る3つの「守る対象」にも専用の係がいます。 -->

---

## 結論

**パスワードはSecrets Manager、証明書はACM、S3上の個人情報の発見はMacieに任せる**

- **Secrets Manager** = パスワード等の秘密情報を保管し、定期的な差し替えも自動化
- **ACM** = HTTPS用の証明書の発行・更新を自動化
- **Macie** = S3の中の個人情報などを機械学習で発見・警告

<!-- ノート: 結論。守る対象の名詞(秘密・証明書・個人情報)がそのまま判定キーワードです。 -->

---

## 最小の例

| サービス | 守る対象 | 向く場面 |
| --- | --- | --- |
| **Secrets Manager** | パスワード・APIキー | DB接続情報の保管と自動ローテーション |
| **ACM** | TLS/SSL証明書 | HTTPS化と証明書の期限切れ防止 |
| **Macie** | S3上の個人情報 | 機密データの所在の棚卸し |

<!-- ノート: KMSとの違い: KMSは「鍵」そのもの、Secrets Managerは「秘密の文字列」を丸ごと預かります。 -->

---

## 試験での聞かれ方

- 「データベースの認証情報を安全に保管し、自動でローテーションしたい」→ Secrets Manager
- 「WebサイトのTLS/SSL証明書を無料で発行・自動更新したい」→ ACM
- 「S3に保存された個人情報(PII)を自動で発見したい」→ Macie

<!-- ノート: 補強枠。ローテーション=Secrets Manager、証明書=ACM、PII=Macieの3対応です。 -->
