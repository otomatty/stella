# 4-2-3
# Route 53はDNS

AWS Cloud Practitioner 入門 — Module 4 / レッスン4-2

<!-- ノート: ネットワークの日の締め。DNSの役割とRoute 53を結びつけます。 -->

---

## なぜ必要か

- 利用者は「example.co.jp」と打つ。数字の住所は覚えていない
- コンピュータ同士は数字の住所でしか会話できない
- 名前と住所を変換する「電話帳」が要る

<!-- ノート: つかみ。電話帳の例え。名前で調べて番号に掛ける。 -->

---

## 結論

**Route 53は、ドメイン名をIPアドレスに解決するマネージドなDNSサービス**

- **IPアドレス** = ネットワーク上の数字の住所
- **ドメイン名** = 人が覚えるための名前(example.co.jp)
- **DNS** = 名前から住所を引く仕組み。**Route 53** はそのAWS版

<!-- ノート: 結論。名前→住所の変換を「解決」と呼ぶ。53はDNSの通信ポート番号にちなむ、と小話。 -->

---

## 最小の例

| 手順 | 起きること |
| --- | --- |
| 1 | 利用者が example.co.jp にアクセス |
| 2 | Route 53が対応するIPアドレスを返す |
| 3 | ブラウザーがそのIPアドレスへ接続 |

<!-- ノート: 3ステップだけ。DNSは接続の前段で毎回働く縁の下の係。 -->

---

## 試験での聞かれ方

- 「ドメイン名の登録と名前解決」→ Route 53
- 健康状態を見て接続先を切り替えるルーティングもできる(DR構成の部品)
- 「DNS」という語が見えたらRoute 53を思い出す
