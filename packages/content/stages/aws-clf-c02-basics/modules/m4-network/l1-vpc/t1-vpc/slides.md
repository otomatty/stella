# VPCは自分専用ネットワーク

AWS Cloud Practitioner 入門 — Module 4 / レッスン4-1

<!-- ノート: ネットワークの日の起点。VPCという「敷地」の概念を作るトピックです。 -->

---

## なぜ必要か

- EC2を起動した。ではそのサーバーは「どこのネットワーク」にいるのか
- 他社のサーバーと同じ場所に無防備に並ぶのは怖い
- 自分専用の区画が要る

<!-- ノート: つかみ。マンションの共用部と専有部の例えを口頭で。 -->

---

## 結論

**VPCは、AWSの中に作る自分専用の仮想ネットワーク**

- **仮想ネットワーク** = 物理配線に縛られず、ソフトウェアで定義するネットワーク
- **VPC**(Virtual Private Cloud) = その自分専用の区画

<!-- ノート: 結論。EC2などのリソースはVPCの中に置く。他の利用者からは論理的に分離される。 -->

---

## 最小の例

| | VPCなしの世界 | VPCあり |
| --- | --- | --- |
| サーバーの場所 | 共有の場所に混在 | 自分の区画の中 |
| 他社からの見え方 | 区別が難しい | 論理的に分離 |
| 通信の制御 | 個別ばらばら | 区画単位で設計 |

<!-- ノート: 「敷地を最初に決めてから建物を置く」という順序を強調。 -->

---

## 覚える構図

- VPCはリージョンの中に作る
- VPCの中を区画に分け(次トピック)、EC2などを配置する
- ネットワークの問題は「VPCの絵のどこか」で起きる
