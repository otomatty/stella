# S3はオブジェクトストレージ

AWS Cloud Practitioner 入門 — Module 5 / レッスン5-1

<!-- ノート: ストレージの日の起点。最重要サービスの1つ、S3を固めます。 -->

---

## なぜ必要か

- 画像・動画・ログ・バックアップ。データは増える一方
- サーバーのディスクに置くと、容量の上限と故障が常につきまとう
- 「入れれば入るだけ入る、壊れない置き場」が欲しい

<!-- ノート: つかみ。置き場問題はどの現場にもある。 -->

---

## 結論

**S3はファイルをオブジェクトとしてバケットに保管し、極めて高い耐久性を持つストレージ**

- **オブジェクトストレージ** = ファイルを「オブジェクト」の単位で保管する方式
- **バケット** = オブジェクトの入れ物
- **耐久性** = データが失われにくい性質

<!-- ノート: 結論。S3=Simple Storage Service。イレブンナイン(99.999999999%)の耐久性設計、と口頭で。 -->

---

## 最小の例

| 項目 | S3 |
| --- | --- |
| 容量 | 実質無制限(使った分だけ課金) |
| 保管単位 | バケットの中のオブジェクト |
| 耐久性 | 複数の場所に自動複製して確保 |
| 典型用途 | 画像・動画・ログ・バックアップ・静的サイト |

<!-- ノート: 容量設計が不要になるのが実務の効き目。データは複数AZに自動複製される。 -->

---

## 覚える対比

- S3は「ファイル置き場」であって、OSから直接マウントするディスクではない
- サーバーのディスクの代わりはEBS(次々トピック)
- 「Webから出し入れする置き場」= S3、と用途で覚える

<!-- ノート: 補強枠。S3とディスクの混同を先回りで防ぐ。 -->
