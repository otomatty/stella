## なぜ必要か

- RDS・Aurora・DynamoDB・ElastiCacheと役者がそろった
- 試験は「このワークロードにどれ?」を選ばせる
- 判定の軸を「データの形と用途」に固定する

<!-- ノート: つかみ。コンピュートの選び分け(3-2-4)と同じ構図の締め回。 -->

---

## 結論

**表のデータを厳密に扱うならRDS、決まったキーで速く引くならDynamoDBと、データの形と用途で選ぶ**

- 形が表で、集計や結合が要る → リレーショナル
- 形がキーと値で、速さと量が要る → NoSQL

<!-- ノート: 結論。まず形、次に用途、の2段判定。 -->

---

## 最小の例

| 用途の一言 | 選ぶ |
| --- | --- |
| 注文・在庫・会計(表と集計) | RDS |
| RDSと同じ用途で、より高性能に | Aurora |
| セッション・IoT(キーで大量高速) | DynamoDB |
| よく読む答えの写しを速く返す | ElastiCache |

<!-- ノート: この表がレッスンの成果物。1行ずつ読み上げる。 -->

---

## 迷ったときの判定順

1. SQL・結合・トランザクションの語がある? → RDS / Aurora
2. キーで引く・ミリ秒・自動スケール? → DynamoDB
3. 読み取りの高速化・DBの負荷軽減? → ElastiCache
4. データ倉庫(分析用)の話は明日のRedshiftへ
