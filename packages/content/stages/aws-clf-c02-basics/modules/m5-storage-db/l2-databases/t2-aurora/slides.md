# 5-2-2
# Auroraはクラウド設計のRDB

AWS Cloud Practitioner 入門 — Module 5 / レッスン5-2

<!-- ノート: RDSファミリーの上位互換としてのAuroraの位置づけだけ覚えるトピックです。 -->

---

## なぜ必要か

- RDSで運用は任せられた。次は性能と可用性をもっと上げたい
- 従来のDBソフトは、クラウド以前の設計を引きずっている
- 「クラウド前提で作り直したRDB」がある

<!-- ノート: つかみ。既存ソフトのマネージド化と、クラウド生まれの違い。 -->

---

## 結論

**Auroraは、MySQL / PostgreSQL互換のままクラウド向けに再設計された高性能データベース**

- **Aurora** = AWSがクラウド前提で設計したリレーショナルデータベース
- 互換性があるので、アプリからはMySQL / PostgreSQLと同じように見える

<!-- ノート: 結論。互換=移りやすい。中身の設計だけがクラウド前提。 -->

---

## 最小の例

| | RDS(MySQL等) | Aurora |
| --- | --- | --- |
| 中身 | 既存のDBソフト | クラウド前提の再設計 |
| 互換性 | それぞれのエンジン | MySQL / PostgreSQL互換 |
| 性能・可用性 | 標準的 | より高い(データを3AZ複製) |

<!-- ノート: 3AZ 6重の複製、という設計は「より壊れにくい」の根拠として一言だけ。 -->

---

## 試験での聞かれ方

- 「MySQL互換で、より高い性能と可用性のマネージドDB」→ Aurora
- AuroraはRDSファミリーの一員として提供される
- サーバーレス版(使った分だけの自動伸縮)もある、と名前だけ

<!-- ノート: 補強枠。Aurora Serverlessは名前だけ触れる。 -->
