# レッスン0-1 試験とクラウドの全体像

## このレッスンの目標

- [ ] CLF-C02の試験形式(時間・問題数・合格ライン)を数字で言える
- [ ] 4つのドメインと配点を挙げ、勉強時間の配分を説明できる
- [ ] クラウドコンピューティングの定義と6つの利点を自分の言葉で言える

## 0-1-1 CLF-C02はどんな試験か

> **CLF-C02は90分65問の選択式で、1000点満点の尺度点700点で合格する試験**

AWS Certified Cloud Practitioner の現行試験コードが **CLF-C02** です。CLFはCloud Practitionerの略記、C02は版番号を表します。試験の形式は次のとおりです。

| 項目 | 数字 |
| --- | --- |
| 試験時間 | 90分 |
| 問題数 | 65問(得点対象50問 + 非得点15問) |
| 点数 | 100〜1000の尺度点 |
| 合格ライン | 700 |

65問のうち15問は、将来の問題を評価するための非得点問題です。どれが非得点かは受験中に分からないので、全問を同じ態度で解きます。

点数は素点ではなく **尺度点** です。尺度点は、試験の回ごとの難易度差をならして100〜1000に換算した点数のことです。「700点 = 70%正解」ではなく、「何問正解で合格」という決まった数もありません。正解率7割を目安にしつつ、余裕を持って仕上げるのが安全です。

なお、試験コードは版の改定で変わることがあります。受験を申し込む前に、認定ページで現行コードを確認してください。

## 0-1-2 配点は4ドメインで決まる

> **試験は4ドメイン構成で、技術とサービス34%・セキュリティ30%の2つで半分を超える**

**ドメイン** は、試験ガイドが定める出題分野の大区分です。CLF-C02は4つのドメインで構成され、配点が公表されています。

| ドメイン | 配点 | この講座での対応 |
| --- | --- | --- |
| 1. クラウドの概念 | 24% | M0・M1(利点・経済・設計原則)、M8(移行) |
| 2. セキュリティとコンプライアンス | 30% | M7(独立した1日)、M8(操作の記録) |
| 3. クラウドテクノロジーとサービス | 34% | M2〜M6(基盤からAI/分析まで5日) |
| 4. 請求・料金・サポート | 12% | M9 |

ドメイン3(34%)とドメイン2(30%)の2つだけで64%になります。配点の重いところから固めるのが定石で、この講座の日割りも配点に合わせています。全体で迷子になったら、この表に戻ってください。

## 0-1-3 スコープ外を知って絞る

> **コーディング・設計・実装は出題されず、問われるのは用途に合うサービスの選択**

試験ガイドは「候補者に求めないタスク」も明記しています。コーディング、アーキテクチャ設計、実装や移行の実作業、障害の切り分け、負荷試験は出題されません。出題は選択式だけで、手を動かす問題はありません。

代わりに問われるのが **用途選択** です。用途選択は、シナリオを読んで目的に合うサービスや考え方を選ぶ出題形式のことです。

| 出ないもの | 代わりに問われるもの |
| --- | --- |
| コーディング | サービス名と用途の対応 |
| アーキテクチャ設計 | 「この用途ならどれ?」の選択 |
| 実装・移行の実作業 | 移行の考え方・進め方 |
| 障害切り分け・負荷試験 | 責任分担と相談先 |

もう1つ大事な公式の明記があります。試験対象のサービス一覧(in-scope)は「網羅的ではなく、変更されることがある」とされています。つまり、200を超える全サービスの暗記は求められていません。この講座では、代表サービスごとに「用途の一言」(例:「静かに保管 → S3」)を作る方針で進めます。

## 0-1-4 クラウドコンピューティングとは

> **クラウドは、ITリソースをインターネット越しにオンデマンドで借りて従量課金で使う仕組み**

サーバーを自前で買うと、届くまで数週間かかり、置き場所・電源・保守も自分持ちです。使わない夜間や、予想が外れて余った分の代金も返ってきません。

**クラウド** は、この「買う」を「借りる」に変えます。定義を3つの語に分解して覚えてください。

- **ITリソース** — サーバー・ストレージ・データベースなど、ITの部品のこと
- **オンデマンド** — 必要になったその場で、すぐに使い始められること
- **従量課金** — 使った量と時間の分だけ支払うこと

| | 自前で買う | クラウドで借りる |
| --- | --- | --- |
| 使えるまで | 数週間 | 数分 |
| 支払い | 先に全額 | 使った分だけ毎月 |
| やめるとき | 廃棄・売却 | 解放すれば課金も止まる |

クラウドの本質は「誰かのコンピュータに置くこと」ではなく、数分で借りて数分で返せるオンデマンド性と、使った分だけ支払う従量課金です。電気や水道と同じ「使った分だけ」のモデルと考えると腑に落ちます。

1つだけ注意があります。「やめれば支払いも止まる」のは、その資源を**解放(削除)した**場合です。サーバーを「停止」しただけでは、取り付けたディスク(ストレージ)や確保したIPアドレスなど、関連リソースの課金が残ることがあります。やめるときは関連リソースまで確認する——この感覚はM3以降で具体的に扱います。

## 0-1-5 クラウドの利点は6つ

> **クラウドの利点は、先行投資なしで始められることと、数分で世界に展開できる俊敏性に集約される**

「クラウドの利点として正しいものを選べ」はドメイン1の定番問題です。公式が挙げる利点は6つに整理されていて、「お金」と「速さ」の2系統に束ねると覚えやすくなります。

| 系統 | 利点 | 一言でいうと |
| --- | --- | --- |
| お金 | 先行投資を従量課金に置き換える | 先にまとめて払わない |
| お金 | 大規模な規模の効果で単価が下がる | 大量調達の安さに相乗りする |
| お金 | データセンターの維持にお金を使わない | 本業に集中する |
| 速さ | 必要な容量を予想しなくてよい | 外れる予想をやめる |
| 速さ | 俊敏性が上がり試行錯誤が速くなる | 思いついたら数分で試す |
| 速さ | 数分で世界中に展開できる | 海外展開も数クリック |

**俊敏性** は、思いついてから使えるまでが速いことです。試験では利点を言い過ぎた選択肢がひっかけとして並びます。「クラウドにすれば障害が起きなくなる」「必ず安くなる」のように、「絶対」「必ず」「ゼロになる」が付く選択肢はまず疑ってください。クラウドは障害が起きる前提で備える世界です。
