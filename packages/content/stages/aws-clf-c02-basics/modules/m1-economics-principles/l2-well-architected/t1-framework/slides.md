# Well-Architectedとは

AWS Cloud Practitioner 入門 — Module 1 / レッスン1-2

## なぜ必要か

- 「この構成で大丈夫?」という不安に、経験者の勘で答えるのは危うい
- 見落としを防ぐには、決まった観点のリストが要る
- AWSはその点検リストを公式に配っている

<!-- ノート: つかみ。チェックリストなしの点検は必ず抜ける、という実務感覚。 -->

---

## 結論

**Well-Architectedフレームワークは、良い設計かどうかを6本の柱で点検するAWS公式の枠組み**

- **Well-Architected** = 「良く設計されている」ことの公式基準
- **柱** = 点検の観点。全部で6本ある

<!-- ノート: 結論。設計の答えを出す道具ではなく、問いのリストである点を強調。 -->

---

## 最小の例

6本の柱の名前だけ、先に一覧します。

| # | 柱 |
| --- | --- |
| 1 | 運用上の優秀性 |
| 2 | セキュリティ |
| 3 | 信頼性 |
| 4 | パフォーマンス効率 |
| 5 | コスト最適化 |
| 6 | 持続可能性 |

<!-- ノート: 名前の一覧まで。中身は次の2トピックで前半・後半に分けて見る。 -->

---

## 試験での聞かれ方

- 「6本の柱に含まれるものはどれか」→ 名前を選ぶだけの問題が出る
- 「俊敏性」「弾力性」は利点の語であって柱の名前ではない
- 柱の数を「5本」とする古い資料に注意(持続可能性が6本目)

<!-- ノート: 補強枠。利点(M0)と柱の混同がひっかけの定番。持続可能性は後から加わった6本目。 -->
