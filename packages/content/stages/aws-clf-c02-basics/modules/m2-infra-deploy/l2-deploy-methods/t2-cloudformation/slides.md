# 環境をコードで書く

AWS Cloud Practitioner 入門 — Module 2 / レッスン2-2

<!-- ノート: IaCの考え方とCloudFormationの名前を結びつけるトピックです。 -->

---

## なぜ必要か

- 検証環境と本番環境を「手作業で同じに」作るのは、ほぼ無理
- 手順書どおりにやっても、人の操作は微妙にずれる
- 「作り方そのもの」を保存して再生する方法はないでしょうか

<!-- ノート: つかみ。環境差異による「検証では動いたのに」が実務あるある。 -->

---

## 結論

**CloudFormationを使うと、環境の構成をコード(テンプレート)として書いて何度でも同じに作れる**

- **IaC**(Infrastructure as Code) = インフラ構成をコードで管理する考え方
- **CloudFormation** = IaCを実現するAWSのサービス
- **テンプレート** = 構成を書いたファイル

<!-- ノート: 結論。考え方の名前(IaC)とサービス名(CloudFormation)を対で覚える。 -->

---

## 最小の例

| | 手作業で構築 | CloudFormation |
| --- | --- | --- |
| 2回目の構築 | 手順書を見て再操作 | テンプレートを再実行 |
| 環境の差異 | 人のぶれで発生 | 同じテンプレートなら同じ |
| 構成の記録 | 手順書が古くなる | テンプレートが正本 |

<!-- ノート: 「もう1つ同じ環境を」という要望に数分で応えられるのが効き目。 -->

---

## 試験での聞かれ方

- 「複数リージョンに同じ環境を繰り返し構築したい」→ CloudFormation
- 「手作業による構成ミスを減らしたい」→ IaC化が答えの軸
- テンプレートの書き方(文法)は出ない。役割だけでよい

<!-- ノート: 補強枠。CLFでは文法の知識は不要。「繰り返し・同じに・自動で」がキーワード。 -->
