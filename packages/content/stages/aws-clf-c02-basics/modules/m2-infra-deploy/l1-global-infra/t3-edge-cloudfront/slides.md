# 2-1-3
# エッジは利用者の近くで配る

AWS Cloud Practitioner 入門 — Module 2 / レッスン2-1

<!-- ノート: グローバル基盤の3層目。エッジとCloudFrontをセットで覚えるトピックです。 -->

---

## なぜ必要か

- 東京のサーバーからブラジルの利用者へ配ると、距離のぶん遅くなる
- 世界中にリージョンを借りて回すのは大げさすぎる
- 「配るだけ」を利用者の近くで済ませる方法はないでしょうか

<!-- ノート: つかみ。物理的な距離は光の速さでも消せない、という前提。 -->

---

## 結論

**エッジロケーションは利用者に近い配信拠点で、CloudFrontがそこからコンテンツをキャッシュ配信する**

- **エッジロケーション** = リージョンより数が多い、配信専用の小さな拠点
- **CloudFront** = エッジから配信するサービス(**CDN**)
- **キャッシュ** = よく使うデータの写しを手近に置いておくこと

<!-- ノート: 結論。CDN=コンテンツ配信ネットワーク。画像や動画の配信が代表例。 -->

---

## 最小の例

| | 東京から直接配信 | CloudFrontで配信 |
| --- | --- | --- |
| ブラジルの利用者 | 地球半周ぶん遅い | 近くのエッジから受け取る |
| 東京のサーバーの負荷 | 全アクセスが集中 | エッジが肩代わり |

<!-- ノート: 速くなる+本体の負荷が減る、の2つの効き目。 -->

---

## 覚える対比

- リージョン/AZ = **動かす**場所(サーバーやDBを置く)
- エッジロケーション = **配る**場所(キャッシュを置く)
- 「世界中の利用者に低遅延で配信」→ CloudFrontが答えの軸

<!-- ノート: 補強枠。動かす場所と配る場所の対比が、選択肢の絞りにそのまま効く。 -->
