# EC2は仮想サーバー

AWS Cloud Practitioner 入門 — Module 3 / レッスン3-1

<!-- ノート: 個別サービスの1つ目。コンピュートの基準点になるEC2を固めます。 -->

---

## なぜ必要か

- アプリを動かすには、まず「計算する場所」が要る
- 物理サーバーを買わずに、サーバーが欲しい
- AWSでその代表がどれかを、まず1つ覚える

<!-- ノート: つかみ。コンピュート=計算する場所、という括りを先に置く。 -->

---

## 結論

**EC2は数分で起動できる仮想サーバーで、OSから上を利用者が自由に管理する**

- **仮想サーバー** = 物理サーバーを仮想的に分割した、ソフトウェア上のサーバー
- **EC2** = AWSの仮想サーバーのサービス
- 起動した1台を **インスタンス** と呼ぶ

<!-- ノート: 結論。EC2はIaaSの代表。OSの選択もソフトの導入も自由、そのぶん管理も自分。 -->

---

## 最小の例

| 操作 | かかる時間 |
| --- | --- |
| インスタンスを起動する | 数分 |
| OSやソフトを選ぶ | 起動時に指定 |
| 使い終わって停止する | 数分。稼働分の課金は止まる(ディスク等は残る) |

<!-- ノート: オンデマンドの実感。買うと数週間、借りると数分、の再確認。 -->

---

## 覚える位置づけ

- EC2 = IaaS。OSから上(ミドルウェア・アプリ)は自分の担当
- 自由度が最も高く、そのぶん管理の手間も最も多い
- 以降のコンピュートは全部「EC2との比較」で覚える

<!-- ノート: 補強枠。EC2を基準点に置く、というこのモジュールの学び方を宣言。 -->
