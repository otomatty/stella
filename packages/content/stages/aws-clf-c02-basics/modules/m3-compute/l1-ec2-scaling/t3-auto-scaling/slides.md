# Auto Scalingで台数を増減

AWS Cloud Practitioner 入門 — Module 3 / レッスン3-1

<!-- ノート: M1の弾力性を「実現する道具」の名前を与えるトピックです。 -->

---

## なぜ必要か

- 弾力性が大事なのは分かった(M1)。でも誰が増減させるのか
- 深夜のアクセス急増のたびに人が起きて操作するのは無理
- 「自動で」増減させる仕組みに名前がある

<!-- ノート: つかみ。考え方(弾力性)と道具(Auto Scaling)を接続する。 -->

---

## 結論

**EC2 Auto Scalingは、需要に合わせてインスタンスの台数を自動で増減させる**

- **Auto Scaling** = 条件に応じた台数の自動増減
- 台数を増やして能力を上げる方法を **水平スケーリング** と呼ぶ

<!-- ノート: 結論。増やすだけでなく、減らして無駄をなくすのも仕事。 -->

---

## 最小の例

| 時間帯 | 負荷 | 台数 |
| --- | --- | --- |
| 昼 | 高い | 6台に自動で増える |
| 夜 | 低い | 2台に自動で減る |
| 障害時 | 1台停止 | 代わりを自動で補充 |

<!-- ノート: 3行目が見落とされがち。台数の維持=不調な1台の置き換えもする。 -->

---

## 縦と横のスケーリング

- 水平スケーリング = 台数を増やす(スケールアウト)
- 垂直スケーリング = 1台を大きくする(サイズ変更)
- Auto Scalingが自動化するのは「水平」の方

<!-- ノート: 補強枠。縦横の対比は選択肢の定番。垂直は再起動を伴いがち、と一言。 -->
