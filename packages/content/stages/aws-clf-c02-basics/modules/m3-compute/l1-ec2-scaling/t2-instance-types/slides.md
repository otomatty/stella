## なぜ必要か

- EC2の起動画面には、数百種類の型番が並ぶ
- 全部を覚えるのは無理だし、覚える必要もない
- 実は、少数の「系統」に分かれている

<!-- ノート: つかみ。型番の海に溺れない、という安心を先に。 -->

---

## 結論

**インスタンスタイプは、汎用・コンピュート最適化・メモリ最適化などの用途の系統で選ぶ**

- **インスタンスタイプ** = CPU・メモリなどの構成の型
- 選ぶ単位は型番ではなく「系統」

<!-- ノート: 結論。CLF-C02で問われるのは系統と用途の対応まで。個別型番は不要。 -->

---

## 最小の例

| 系統 | 向いている用途 |
| --- | --- |
| 汎用 | Webサーバーなど、バランス型 |
| コンピュート最適化 | 計算が重い処理(動画変換など) |
| メモリ最適化 | 大きなデータをメモリに載せる処理 |
| ストレージ最適化 | 読み書きが激しい処理 |

<!-- ノート: 「何がボトルネックか」で系統が決まる、と言い換える。 -->

---

## 試験での聞かれ方

- 「メモリを大量に使う分析処理に適したタイプは」→ メモリ最適化
- 迷ったら、問題文の資源名(CPU・メモリ・ディスク)に対応する系統
- 系統選びはライトサイジングの入口でもある
