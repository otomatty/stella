# 3-2-3
# Fargateはサーバーの面倒を見ない

AWS Cloud Practitioner 入門 — Module 3 / レッスン3-2

<!-- ノート: コンテナ×サーバーレスの交点。Fargateの位置づけだけを覚えるトピックです。 -->

---

## なぜ必要か

- ECSでコンテナを動かすにも、載せる先のEC2は誰かが管理する
- コンテナは軽くなったのに、土台のサーバー管理が残っている
- 土台ごと「見えなく」できないでしょうか

<!-- ノート: つかみ。コンテナ化してもホスト管理は残る、という盲点。 -->

---

## 結論

**Fargateを使うと、コンテナをホストサーバーの管理なしで実行できる**

- **Fargate** = ECS / EKSの実行基盤になる、サーバーレスなコンテナ実行環境
- 「コンテナ版のサーバーレス」と覚える

<!-- ノート: 結論。Fargateは単体で使うものではなく、ECS/EKSの下に敷く実行方式。 -->

---

## 最小の例

| 実行方式 | コンテナの土台 | 土台の管理 |
| --- | --- | --- |
| ECS on EC2 | EC2インスタンス | 自分 |
| ECS on **Fargate** | Fargate | AWS |

<!-- ノート: 同じECSでも土台が2択。管理の主語が変わるだけ、とシンプルに。 -->

---

## 試験での聞かれ方

- 「コンテナを使いたいが、サーバーのプロビジョニングや管理はしたくない」→ Fargate
- コードだけならLambda、コンテナごとならFargate
- どちらも「サーバーレス」の仲間として出る

<!-- ノート: 補強枠。Lambda(コード)とFargate(コンテナ)の使い分けが選択肢で並ぶ。 -->
