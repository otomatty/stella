# コンテナはアプリを箱ごと運ぶ

AWS Cloud Practitioner 入門 — Module 3 / レッスン3-2

## なぜ必要か

- 「自分のPCでは動いたのに、サーバーでは動かない」が起きる
- 原因はアプリの周りの環境(ライブラリやバージョン)の差
- アプリと環境を「まとめて」運べれば、この差は消える

<!-- ノート: つかみ。環境差異あるある。引っ越しの段ボールの例えを口頭で。 -->

---

## 結論

**コンテナはアプリと動作環境をひとまとめに運ぶ技術で、AWSではECSとEKSが実行を管理する**

- **コンテナ** = アプリ+依存する環境を1つに梱包する技術
- **ECS** = AWS独自のコンテナ管理サービス
- **EKS** = **Kubernetes**(コンテナ管理の標準ソフト)のマネージド版

<!-- ノート: 結論。梱包そのものと、多数のコンテナを並べて運用する「管理係」を分けて認識させる。 -->

---

## 最小の例

| | 仮想サーバー | コンテナ |
| --- | --- | --- |
| 梱包の単位 | OSごと | アプリと環境だけ |
| 起動 | 分単位 | 秒単位 |
| 同じ動き | 環境差でずれうる | どこでも同じ |

<!-- ノート: 軽さと再現性がコンテナの利点。OSを含まない分だけ軽い。 -->

---

## ECSとEKSの選び分け

- AWSに閉じてシンプルに → ECS
- Kubernetesの標準に合わせたい・既に使っている → EKS
- どちらも「コンテナをどのサーバーで動かすか」を管理する係
