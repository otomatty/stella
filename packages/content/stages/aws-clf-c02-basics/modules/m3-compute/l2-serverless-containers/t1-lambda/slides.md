# Lambdaはサーバーレス

AWS Cloud Practitioner 入門 — Module 3 / レッスン3-2

<!-- ノート: EC2の対極を1つ覚えるトピック。サーバーレスの定義をここで固めます。 -->

---

## なぜ必要か

- 「画像がアップロードされたら縮小する」だけの処理に、24時間サーバーを飼うのは大げさ
- EC2ならOSの管理も待機中の料金も発生する
- 「処理のときだけ存在するサーバー」は作れないでしょうか

<!-- ノート: つかみ。小さい処理に大きな器、というミスマッチ。 -->

---

## 結論

**Lambdaはサーバーを管理せずにコードを実行でき、課金はリクエスト回数と実行時間で、待機中は0円**

- **サーバーレス** = サーバーの存在を意識せずに使える提供形態
- **Lambda** = コードを置くだけで、きっかけに応じて実行されるサービス

<!-- ノート: 結論。サーバーが無いのではなく「見えない・管理しない」。課金は実行時間ベース。 -->

---

## 最小の例

| | EC2 | Lambda |
| --- | --- | --- |
| 管理するもの | OSから上すべて | コードだけ |
| 課金 | 起動している間ずっと | リクエスト回数 + 実行時間 |
| 向く処理 | 常時稼働のアプリ | きっかけに応じた短い処理 |

<!-- ノート: 3行の対比が全て。呼ばれた回数と動いた時間で払い、待機中0円がLambdaの経済的な効き目。 -->

---

## 試験での聞かれ方

- 「サーバーのプロビジョニング(事前準備)や管理なしで実行したい」→ Lambda
- 「アイドル時間に課金されたくない」→ Lambda
- 実行時間には上限がある。長時間動き続ける処理には不向き

<!-- ノート: 補強枠。provisioningの言い回しに慣れさせる。制限時間の存在は言葉だけ触れる。 -->
