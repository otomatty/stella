# 結合テストはつなぎ目の不具合を捕まえる

Pythonテスト自動化とCI入門 — Module 4 / レッスン4-1

<!-- ノート: 単体テストだけでは届かない領域の話に入ります。 -->

---

## なぜ必要か

- 関数の単体テストは全部緑なのに、つないだら動かない
- 列名の綴り違いや、レスポンスの形の思い込みで落ちている

<!-- ノート: つかみ。部品はどれも正しいのに、組み立てると動かない状態。ここで結論は言わない。 -->

---

## 結論

**結合テストは、部品単体ではなくDBや外部APIとの「つなぎ目」で起きる不具合を検出する**

- 自分のコードが頼っている相手が **依存先**
- 依存先とのやり取りの境目が **つなぎ目**
- 代表的な依存先が **データベース**(DB)や外部の API

<!-- ノート: 結論を言い切る。単体テストは自分の中しか見ていない、と対比させる。 -->

---

## つなぎ目で起きるバグ

| 場所 | よくあるバグ |
| --- | --- |
| DB | 列名の綴り違い / 型の不一致 |
| 外部API | レスポンスの形の思い込み |
| ファイル | 文字コード / 改行の違い |

<!-- ノート: 対比枠。どれも「自分の関数の中」には無い。だから単体テストでは出ない。 -->

---

## どこを確かめているか

- 単体テスト: 関数の中のロジック
- 結合テスト: 関数と依存先の **やり取り**

<!-- ノート: 境界線をはっきりさせる。両方要る、が結論。片方で代用はできない。 -->
