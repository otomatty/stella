# 4-1-3
# 本物かダブルかは不具合の場所で選ぶ

Pythonテスト自動化とCI入門 — Module 4 / レッスン4-1

<!-- ノート: 前のトピックの道具を、どこで使うかの判断基準です。 -->

---

## なぜ必要か

- 全部モックにしたら、テストは緑なのに本番で落ちた
- 全部本物にしたら、テストが遅くて誰も回さなくなった

<!-- ノート: つかみ。どちらの極端も失敗する。ここで結論は言わない。 -->

---

## 結論

**依存先を本物にするかテストダブルにするかは、検証したい不具合がどこで起きるかで選ぶ**

- 不具合が **つなぎ目** に出るなら、本物を使う
- 不具合が自分のロジックに出るなら、代役でよい

<!-- ノート: 結論を言い切る。「速いから」「面倒だから」で決めない、が肝。 -->

---

## 判断の例

| 確かめたいこと | 依存先 |
| --- | --- |
| 保存した行が正しく読めるか | 本物(テスト用のDB) |
| 通信が失敗したときの動き | 代役(例外を投げさせる) |
| 金額の計算ロジック | 依存させない(単体テスト) |

<!-- ノート: 3行目が大事。そもそも依存を持ち込まない選択が最も安い。 -->

---

## 代役にすると消える保証

```python
class FakeRateApi:
    def get_rate(self):
        return 150.0   # 本物のキー名が違っても気づけない
```

- 代役は「自分が思っている相手の姿」でしかない
- 思い込みが間違っていると、そのまま通ってしまう

<!-- ノート: 失敗例枠。モックは自分の理解を映す鏡。だからつなぎ目の検証には使えない。 -->
