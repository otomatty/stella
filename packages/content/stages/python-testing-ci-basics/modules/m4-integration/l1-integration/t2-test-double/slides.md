## なぜ必要か

- テストのたびに外部の API を叩くので、遅いうえに課金される
- 相手が落ちていると、自分のコードは正しいのにテストが赤くなる

<!-- ノート: つかみ。自分の都合で結果を決められない相手がテストに入ると、不安定になる。ここで結論は言わない。 -->

---

## 結論

**テストダブル(モック等)は、本物の依存先の代わりに振る舞いを差し替える部品である**

- 代役そのものが **テストダブル**
- 呼ばれ方も記録できる代役が **モック**
- 本物と入れ替えることを **差し替え** と呼ぶ

<!-- ノート: 結論を言い切る。スタントマン(代役)の比喩がそのまま語源。 -->

---

## 最小のコード

```python
class FakeRateApi:
    def get_rate(self):
        return 150.0


def test_converts_to_yen():
    assert to_yen(10, FakeRateApi()) == 1500.0
```

- 本物の API を呼ばずに、returnする値を固定できる

<!-- ノート: 特別な道具は要らない。同じメソッドを持つクラスを渡すだけでも代役になる。 -->

---

## 代役にできること

| したいこと | 代役の使い方 |
| --- | --- |
| 決まった値を返させる | 固定値を返す |
| エラーを起こさせる | 例外を投げさせる |
| 呼ばれたか確かめる | 呼び出しを記録する |

<!-- ノート: 対比枠。異常系を再現できるのが大きい。本物では起こしにくい失敗を作れる。 -->
