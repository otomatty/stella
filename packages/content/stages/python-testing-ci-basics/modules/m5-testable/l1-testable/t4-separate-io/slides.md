# ロジックと I/O を分ける

Pythonテスト自動化とCI入門 — Module 5 / レッスン5-1

<!-- ノート: 純粋関数を「増やす」ための、実務的な設計の型です。 -->

---

## なぜ必要か

- 1つの関数が、ファイルを読んで、計算して、DB に書いている
- 計算だけ確かめたいのに、ファイルと DB の準備が要る

<!-- ノート: つかみ。混ざっているせいで、全部が重いテストになる。ここで結論は言わない。 -->

---

## 結論

**ロジックと入出力(I/O)を分離すると、単体テストで守れる範囲が広がる**

- 判断や計算の部分と、読み書きの部分を関数として分ける
- これが **ロジックとI/Oの分離**

<!-- ノート: 結論を言い切る。分けた瞬間、計算部分が純粋関数になる。 -->

---

## 混ざっている形

```python
def process(path):
    prices = read_csv(path)              # 入出力
    total = sum(prices) - 100            # 計算
    save_to_db(total)                    # 入出力
```

- 計算だけを確かめる方法がない

<!-- ノート: よくある形。ここを分けるだけでテストの書きやすさが変わる。 -->

---

## 分けた形

```python
def calc_total(prices):        # 純粋関数
    return sum(prices) - 100


def process(path):             # I/O を担当
    save_to_db(calc_total(read_csv(path)))
```

- 計算は単体テストで、つなぎ目は結合テストで守る

<!-- ノート: 対比枠。I/O 側の関数は薄くなり、確かめる中身がほとんど残らない。 -->
