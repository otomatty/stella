# 5-1-3
# 純粋関数が最もテストしやすい

Pythonテスト自動化とCI入門 — Module 5 / レッスン5-1

<!-- ノート: テストしやすい関数の理想形を、名前を付けて覚えます。 -->

---

## なぜ必要か

- テストのたびに、前処理と後片付けが10行必要になる
- 何を確かめているのか、準備コードに埋もれて見えない

<!-- ノート: つかみ。準備が要るのは、関数が外の状態に触れているから。ここで結論は言わない。 -->

---

## 結論

**入力と出力だけで結果が決まる純粋関数は、最もテストしやすい部品である**

- 同じ入力なら必ず同じ出力を返すのが **純粋関数**
- 外の状態を変えてしまう働きが **副作用**

<!-- ノート: 結論を言い切る。純粋 = 隠れた依存も副作用も無い、という意味。 -->

---

## 最小のコード

```python
def calc_discount(total, rate):
    return int(total * (1 - rate))


def test_calc_discount():
    assert calc_discount(1000, 0.2) == 800
```

- 準備も後片付けも要らない
- 何度実行しても同じ結果

<!-- ノート: fixture が1つも要らないのが純粋関数のテスト。これが最も安いテスト。 -->

---

## 副作用がある形

```python
def calc_discount(order):
    order["total"] = int(order["total"] * 0.8)   # 引数を書き換える
```

- 呼んだあと、渡した側の値まで変わっている
- どこで変わったのか追いにくくなる

<!-- ノート: 失敗例枠。戻り値で返せば済む場面で書き換えると、バグの温床になる。 -->
