# レッスン0-1 演習 — テストを書く理由

対象トピック: 0-1-1 〜 0-1-3

## 手元で試す

このレッスンでは、次のレッスンから手を動かせるように準備だけ済ませます。作業用のフォルダを1つ作って、その中で進めてください。

```bash
python -m venv .venv
```

macOS / Linux では `python: command not found` と出ることがあります。Python 3 が `python3` という名前でだけ入っている場合です。そのときは `python3 -m venv .venv` を使ってください。

作った仮想環境を有効にします。使っているシェルで打つものが違います。

| シェル | コマンド |
| --- | --- |
| PowerShell | `.venv\Scripts\Activate.ps1` |
| コマンドプロンプト | `.venv\Scripts\activate.bat` |
| macOS / Linux | `source .venv/bin/activate` |

PowerShell で「このシステムではスクリプトの実行が無効になっている」と出たら、実行ポリシーで `.ps1` の実行が止められています。コマンドプロンプトで `activate.bat` を使うか、実行ポリシーの変更を情報システム部門に相談してください。

有効になるとプロンプトの先頭に `(.venv)` が付きます。ここまで来たら pytest を入れます。

```bash
pip install pytest
```

入ったことを確認します。

```bash
pytest --version
```

バージョンが表示されれば準備完了です。表示されない場合は、仮想環境を有効にし忘れていないか確認してください。

確かめられたら、次も見ておきましょう。

1. いま関わっている(または直近で書いた)コードで、直すたびに手で確かめている作業を1つ挙げる
2. その確認を自動テストにしたら、何回目で得になりそうかを見積もる

## 演習問題

### 問1(基本)

1回の手動確認に3分かかる機能があります。この機能はリリースまでに20回修正される見込みです。手動確認だけを続けた場合、確認にかかる合計時間は何分ですか。

### 問2(基本)

「テストを書いたのに、リリース後にバグが出た。テストは意味がなかった」という意見に、1〜2文で反論してください。

### 問3(応用)

次の3つを、単体テスト・結合テスト・E2Eテストに分類してください。

1. 消費税を計算する関数が、端数を正しく切り捨てるか確かめる
2. ブラウザーでログインし、商品を買い、注文完了画面まで進めるか確かめる
3. 注文を保存する処理が、データベースに正しい行を残すか確かめる

### 問4(応用)

E2Eテストばかりを大量に書いたチームで、どんな問題が起きると予想できますか。2つ挙げてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

60分です。手動確認は変更のたびに同じコストがかかるため、3分 × 20回 = 60分になります。自動テストなら、書く手間は1回だけで、以降は実行するだけです。

</details>

<details>
<summary>問2の解答例</summary>

テストは品質を作る道具ではなく、壊れたことに早く気づくための仕組みです。書いたテストが対象にしていない不具合は当然すり抜けますが、そのテストが守っている範囲のデグレは防げています。

</details>

<details>
<summary>問3の解答例</summary>

1 は単体テスト(関数1つの振る舞い)、2 は E2Eテスト(利用者と同じ手順で通しで確認)、3 は結合テスト(処理とデータベースのつながりを確認)です。

</details>

<details>
<summary>問4の解答例</summary>

1つは、実行にとても時間がかかり、誰も回さなくなることです。もう1つは、E2Eテストは壊れやすく、コードのバグではない理由で赤くなることが増え、失敗が信用されなくなることです。

</details>

## 確認クイズ

### Q1. 手動確認と自動テストのコストの違いとして正しいものはどれですか。

- A. 手動確認は変更のたびに同じコストがかかるが、自動テストは一度書けば実行するだけ
- B. 自動テストは変更のたびに書き直すので、手動確認より必ず高くつく
- C. どちらも1回目から自動テストのほうが必ず安い

<details>
<summary>答え</summary>

**A** — 自動テストは1回目こそ手間がかかりますが、2回目以降は実行するだけです。何度も直す場所ほど得になります。

</details>

### Q2. デグレとは何を指しますか。

- A. 動いていた機能が、別の変更によって動かなくなること
- B. テストの実行時間が少しずつ長くなること
- C. コードの行数が増えていくこと

<details>
<summary>答え</summary>

**A** — 直した場所とは別の場所が壊れる事故を指します。テストは、これに最も早く気づくための仕組みです。

</details>

### Q3. 品質はいつ担保するのが原則ですか。

- A. マージする前
- B. リリースした直後
- C. 障害が報告されたとき

<details>
<summary>答え</summary>

**A** — 気づくのが遅いほど直すコストは跳ね上がります。マージ前に担保するのが原則です。

</details>

### Q4. テストピラミッドで、最も本数を多くするのはどれですか。

- A. 単体テスト
- B. 結合テスト
- C. E2Eテスト

<details>
<summary>答え</summary>

**A** — 速くて安い単体テストを土台にして、上に行くほど本数を減らします。

</details>

### Q5. E2Eテストの説明として正しいものはどれですか。

- A. 利用者と同じ手順で、通しで動くかを確かめる
- B. 関数1つの振る舞いだけを確かめる
- C. コードの書き方の誤りを、実行せずに指摘する

<details>
<summary>答え</summary>

**A** — 最も本物に近い確認ができますが、そのぶん遅く、壊れやすくなります。

</details>
