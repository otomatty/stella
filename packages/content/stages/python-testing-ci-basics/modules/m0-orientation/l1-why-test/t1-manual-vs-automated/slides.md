# 自動テストは一度書けば毎回実行できる

Pythonテスト自動化とCI入門 — Module 0 / レッスン0-1

<!-- ノート: この講座の1本目。テストを書いたことがない人に、まず「なぜ書くのか」から始めます。 -->

---

## なぜ必要か

- 直したあと、画面や実行結果を毎回目で確かめている
- 確認に時間がかかるので、だんだん一部しか見なくなる

<!-- ノート: つかみ。1回3分の確認でも、20回直せば1時間になる。しかも見落とす。ここで結論は言わない。 -->

---

## 結論

**手動確認は変更のたびに同じコストがかかるが、自動テストは一度書けば毎回実行できる**

- 人が目で確かめるのが **手動確認**
- 確認そのものをプログラムにしたものが **自動テスト**

<!-- ノート: 結論を言い切る。テストは「確認作業のプログラム化」だと言い換えると腹落ちしやすい。 -->

---

## 最小のコード

```python
def test_calc_total():
    # 注文の金額を合計できることを確かめる
    assert calc_total([100, 200]) == 300
```

- この1行が、確認作業の代わりになる
- 何度直しても、実行するだけで同じ確認ができる

<!-- ノート: 中身の文法はこのあと扱う。いまは「確認がコードになっている」ことだけ見せる。 -->

---

## 手で確かめる vs テストにする

| | 手動確認 | 自動テスト |
| --- | --- | --- |
| 1回目 | 速い | 書く手間がかかる |
| 10回目 | 10回ぶんかかる | 実行するだけ |
| 見落とし | 増える | 減る |

<!-- ノート: 対比枠。テストは1回目は損をする投資。何度も直す場所ほど得になる、と伝える。 -->
