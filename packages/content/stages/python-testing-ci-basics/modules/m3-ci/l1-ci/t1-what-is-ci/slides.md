# 3-1-1
# CI はテストを共通の環境で自動実行する

Pythonテスト自動化とCI入門 — Module 3 / レッスン3-1

<!-- ノート: 手元で守れるようになったので、ここからチーム全体の話に広げます。 -->

---

## なぜ必要か

- テストを実行し忘れたまま PR を出してしまう
- 「自分の環境では通る」と言われても、確かめようがない

<!-- ノート: つかみ。実行し忘れは意志では防げない。ここで結論は言わない。 -->

---

## 結論

**CIはプッシュやPRを合図に、テストを全員共通の環境で自動実行する仕組みである**

- コードを保管する場所が **リポジトリ**
- 何を合図に何をするかの手順書が **ワークフロー**

<!-- ノート: 結論を言い切る。CI = Continuous Integration。訳語より「自動で毎回回る」ことを押さえる。 -->

---

## 最小のワークフロー

```yaml
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install pytest
      - run: pytest
```

- 合図(`on`)と、やること(`steps`)だけ

<!-- ノート: 最初の checkout はコードを持ってくる手順。これが無いと空の場所で pytest が走る。 -->

---

## 手元と CI の違い

| | 手元 | CI |
| --- | --- | --- |
| 実行 | 人が思い出したとき | 毎回、自動で |
| 環境 | 人によって違う | 全員同じ |
| 結果 | 自分だけが見る | PR に表示される |

<!-- ノート: 対比枠。「自分の環境では通る」がなくなるのが、CIの一番の効能。 -->
