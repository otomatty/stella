# 1つのテストは1つの振る舞いだけ検証する

## なぜ必要か

- 1本のテストが赤いが、どの機能が壊れたのか名前から分からない
- 途中で失敗するので、その先の検証が実行されていない

<!-- ノート: つかみ。assertは最初の1つで止まる。後ろの検証は動いてすらいない。ここで結論は言わない。 -->

---

## 結論

**1つのテストは1つの振る舞いだけを検証する**

- **振る舞い** = 「こういう入力なら、こうなる」という決まりごと1つ
- テストの名前が、その振る舞いの説明になる

<!-- ノート: 結論を言い切る。分けるほど、失敗したときに名前だけで原因が分かる。 -->

---

## 最小のコード

```python
def test_returns_sum_of_prices():
    assert calc_total([100, 200]) == 300


def test_returns_zero_for_empty_list():
    assert calc_total([]) == 0
```

- 名前が違う = 確かめている振る舞いが違う

<!-- ノート: 名前は「どうなるか」を書く。test_1 や test_ok では、失敗しても何も分からない。 -->

---

## 詰め込むと起きること

```python
def test_calc_total():
    assert calc_total([100, 200]) == 300
    assert calc_total([]) == 0          # 上が失敗すると実行されない
    assert calc_total([-1]) == 0        # ここも実行されない
```

- 1つ失敗した時点で終わるので、残りの状態が分からない

<!-- ノート: 失敗例枠。全部直したつもりが、次の実行でまた別の赤が出る、を繰り返す。 -->
