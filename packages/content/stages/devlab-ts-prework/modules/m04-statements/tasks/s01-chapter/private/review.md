# レビューの観点

- 決め打ち: テストの入力の値を if や表で並べて、その入力のときだけ期待値を返す書き方。問題文の規則を計算や処理で実装しているものを通す。
- 説明: 問題文に「説明すること」がある応用問題で、そのすぐ下の // コメントに、なぜそう書くのかを自分の言葉で書いているか。
- 型の逃げ: `as` で戻り値の型を言い切る、`any` を経由する、`@ts-ignore` や `@ts-expect-error` を書く。`as const` は問題文が求めているときは使ってよい。

## この章の書き方

- switch は、引数がユニオン型ならすべての case を書き、数値や文字列なら default を書いているか
- unknown の値を typeof や instanceof などで絞り込んでから使い、any を使っていないか
- ユニオンの場合分けの default で、問題文が指定した assertNever を返しているか
- コマンドの解析で、数値の読み取り・網羅・catch のメッセージに、問題文が指定した前の問題の関数を使っているか
