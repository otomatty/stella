# レビューの観点

- 決め打ち: テストの入力の値を if や表で並べて、その入力のときだけ期待値を返す書き方。問題文の規則を計算や処理で実装しているものを通す。
- 説明: 問題文に「説明すること」がある応用問題で、そのすぐ下の // コメントに、なぜそう書くのかを自分の言葉で書いているか。
- 型の逃げ: `as` で戻り値の型を言い切る、`any` を経由する、`@ts-ignore` や `@ts-expect-error` を書く。`as const` は問題文が求めているときは使ってよい。

## この章の書き方

- async と await を使い、戻り値の型を Promise<...> と書いているか
- 失敗を受け止めるとき try・catch を使い、try の中で Promise を return するときは return await と書いているか
- 待つ必要のない取得を、Promise.all や Promise.allSettled で同時に待っているか
- 時間の制限、成功と失敗の分離、やり直しに、問題文が指定した前の問題の関数を使っているか
