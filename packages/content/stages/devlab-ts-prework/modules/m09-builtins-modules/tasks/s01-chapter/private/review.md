# レビューの観点

- 決め打ち: テストの入力の値を if や表で並べて、その入力のときだけ期待値を返す書き方。問題文の規則を計算や処理で実装しているものを通す。
- 説明: 問題文に「説明すること」がある応用問題で、そのすぐ下の // コメントに、なぜそう書くのかを自分の言葉で書いているか。
- 型の逃げ: `as` で戻り値の型を言い切る、`any` を経由する、`@ts-ignore` や `@ts-expect-error` を書く。`as const` は問題文が求めているときは使ってよい。

## この章の書き方

- 新しい Map を返す問題で、引数の Map を変えていないか。型を Map<...> と書いているか
- Error の種類を instanceof で見分け、子クラスを親より先に確かめているか
- import と export を問題の指定どおりに書き、q05-modules.lib.ts を書き換えていないか
- モジュールに分ける問題で、3 つのファイルに分け、q05-modules.ts には re-export だけを書いているか
- 数量が不正なときは、問題文が指定した ValidationError を投げているか
