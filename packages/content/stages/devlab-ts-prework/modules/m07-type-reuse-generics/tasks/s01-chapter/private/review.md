# レビューの観点

- 決め打ち: テストの入力の値を if や表で並べて、その入力のときだけ期待値を返す書き方。問題文の規則を計算や処理で実装しているものを通す。
- 説明: 問題文に「説明すること」がある応用問題で、そのすぐ下の // コメントに、なぜそう書くのかを自分の言葉で書いているか。
- 型の逃げ: `as` で戻り値の型を言い切る、`any` を経由する、`@ts-ignore` や `@ts-expect-error` を書く。`as const` は問題文が求めているときは使ってよい。

## この章の書き方

- 型変数を使い、any や unknown で逃げていないか。引数の配列を readonly T[] にしているか
- Partial・Required・Readonly・Pick・Omit・Record を、プロパティを手で書き並べずユーティリティ型で作っているか（問題がそう書いているとき）
- typeof と keyof を、問題が指定した値やキーの型の取り方で使っているか
- 渡した型に合わせて戻り値の型が変わる書き方になっているか（型を一つに固定していないか）
