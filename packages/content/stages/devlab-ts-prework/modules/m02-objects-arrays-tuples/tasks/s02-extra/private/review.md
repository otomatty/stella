# レビューの観点

- 決め打ち: テストの入力の値を if や表で並べて、その入力のときだけ期待値を返す書き方。問題文の規則を計算や処理で実装しているものを通す。
- 説明: 問題文に「説明すること」がある応用問題で、そのすぐ下の // コメントに、なぜそう書くのかを自分の言葉で書いているか。
- 型の逃げ: `as` で戻り値の型を言い切る、`any` を経由する、`@ts-ignore` や `@ts-expect-error` を書く。`as const` は問題文が求めているときは使ってよい。

## この章の書き方

- オブジェクトの型を { name: string; age: number } のように書き、{ x: x } ではなく { x } を使っているか
- 配列を壊さない問題で、引数を readonly にし、元の配列を書き換えずに新しい配列を返しているか。sort や reverse はコピーしてから使っているか
- インデックス型を求める問題で、キーが文字列・値が数値の型を export しているか
- 在庫の集計で、元の配列や商品のオブジェクトを変えていないか。在庫金額の合計に、問題文が指定した sum を使っているか
