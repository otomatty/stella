# 状態という見方

テスト設計入門 — Module 3 / レッスン3-4

<!-- ノート: 3 つ目の技法です。時間の軸が入ると、これまでの表では足りません。 -->

---

## なぜ必要か

- 「キャンセルボタンを押すとキャンセルできる」でテストした
- 発送済みの注文でもキャンセルできてしまい、商品だけが届いた
- 押したボタンは同じなのに、正しい結果が違っていた

<!-- ノート: つかみ。入力が同じでも結果が違う。デシジョンテーブルでは表しきれない形です。 -->

---

## 結論

**同じ操作でも状態によって結果が変わる仕様は、状態遷移でとらえる**

- **状態** — 対象が今どうなっているか(受付・支払済・発送済・キャンセル)
- **イベント** — 状態を変えるきっかけの操作(支払う・発送する・キャンセルする)
- **状態遷移** — イベントによって状態が別の状態に移ること

<!-- ノート: 結論を言い切る。「今の状態」を入力の一部として数えるのがこの技法の要点です。 -->

---

## 注文ステータスで見る

| いまの状態 | イベント | 移る先 |
| --- | --- | --- |
| 受付 | 支払う | 支払済 |
| 支払済 | 発送する | 発送済 |
| 受付 | キャンセルする | キャンセル |
| 発送済 | キャンセルする | (できない) |

<!-- ノート: 具体例の枠。3 行目と 4 行目は同じイベントですが、結果が違います。違いを作っているのは「いまの状態」だけです。 -->

---

## これまでの技法との違い

| 技法 | 何を入力と見るか |
| --- | --- |
| 同値分割・境界値分析 | 1 つの値 |
| デシジョンテーブル | 同時に成り立つ条件の組 |
| 状態遷移 | **いまの状態 + イベント** |

<!-- ノート: 対比の枠。状態遷移だけが「そこに至るまでの経過」を持ち込みます。だからテストも操作の列になります。 -->
