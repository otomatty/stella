# レッスン3-2 境界値分析

## このレッスンの目標

- [ ] 仕様の中から境界を漏れなく数え上げられる
- [ ] 2 値と 3 値の境界値を使い分けられる
- [ ] ケース表を `pytest.mark.parametrize` に写して実行できる

## 3-2-1 欠陥は境界に集まる

> **「以上」「未満」の境目は、実装者が最も間違えやすい場所である**

代表値に 1,500 円と 5,000 円を選び、どちらも期待どおりでした。ところが本番で、3,000 円ちょうどの注文だけ送料が 500 円になっています。実装を見ると `total > 3000` と書かれていました。パーティションの真ん中を選ぶ限り、この欠陥は永遠に見つかりません。

**境界** は、隣り合う同値パーティションが接する値です。`>` と `>=` の取り違え、`-1` の付け忘れといった間違いは、ここに集中します。パーティションの真ん中は間違えようがないからです。

| 実装 | 3,000 円のとき | 仕様どおりか |
| --- | --- | --- |
| `total >= 3000` | 送料 0 円 | ○ |
| `total > 3000` | 送料 500 円 | × 1 円ぶんずれている |
| `total >= 3001` | 送料 500 円 | × 同じずれ |

ずれる範囲は 3,000 円という 1 点だけです。だから真ん中を試しても出ません。逆に言えば、境界を 1 件試すだけでこの種の欠陥がまとめて捕まえられます。費用対効果が非常に高い場所です。

境界は実装だけでなく、仕様の日本語にも潜みます。

- 「3,000 円以上」なのか「3,000 円を超えたら」なのか
- 「32 文字まで」は 32 文字を含むのか
- 「営業日 3 日以内」は当日を数えるのか

書いた人の頭の中では決まっていても、文からは決まりません。この曖昧さを見つけて詰めるのは、テスト担当者の仕事です。テストケースを書こうとして初めて気づく、という順序になるのが普通です。

## 3-2-2 2 値の境界値

> **境界の内側と外側を 1 つずつテストするのが境界値分析の基本形である**

境目が危ないことは分かりました。「3,000 円のあたり」を試そうと決めたものの、いくつ試せばよいかが決まりません。基準がないと、2,998・2,999・3,000・3,001・3,002 と 5 件並べる人が出てきます。

**境界値** は、境界をはさんで隣り合う 2 つの値です。各パーティションの境界値をテストケースにする技法を **境界値分析** と呼びます。1 つの境界につき 2 件。これが 2 値の境界値です。

「内側」「外側」の向きは、**その境界が区切っているパーティションのうち、条件を満たすほうを内側**と決めて使います。3,000 円の境界なら条件は「送料無料になる」なので 3,000 が内側、2,999 が外側です。1 円の境界なら条件は「有効な購入額である」なので 1 が内側、0 が外側になります。境界ごとに基準となる条件が違うので、表には「どの境界か」も添えておくと読み違いません。

| # | 入力 | 期待結果 | 位置 |
| --- | --- | --- | --- |
| 1 | 2,999 円 | 送料 500 円 | 3,000 円の境界の外側 |
| 2 | 3,000 円 | 送料 0 円 | 3,000 円の境界の内側 |
| 3 | 0 円 | エラー | 1 円の境界の外側 |
| 4 | 1 円 | 送料 500 円 | 1 円の境界の内側 |

数え方に注意してください。**パーティションの数ではなく、境界の数で数えます**。この仕様には境界が 2 か所(1 円のところと 3,000 円のところ)あるので、2 件 × 2 で 4 件になります。パーティションは 3 つですが、ケースは 4 件です。

同値分割と境界値分析は、順番に使う組です。

- 同値分割 → **どのグループがあるか**が分かる
- 境界値分析 → **各グループのどこを試すか**が決まる

同値分割で切り出したパーティションの端が、そのまま境界になります。代表値を境界値に置き換えれば、件数を増やさずに網が強くなります。1,500 円ではなく 2,999 円を選ぶ、というだけの違いです。

## 3-2-3 3 値の境界値

> **境界そのものと両隣を試すと、境界の取り違えをより確実に捕まえられる**

「3,000 円以上で無料」の境目を 2 値で試すと決めました。ところで、この仕様の「境界」とは 2,999 と 3,000 のどちらの値でしょうか。有料の側の端と読む人もいれば、無料の側の端と読む人もいます。前者は 2,998 と 2,999 を、後者は 2,999 と 3,000 を選びます。判定が切り替わるのは 2,999 と 3,000 の間なので、前者はその組を一度も試していません。

期待結果は仕様から引くので、2,998 も 2,999 も送料 500 円です。実装が `total > 3000` になっていても、この 2 件はどちらも 500 円を返して通ってしまいます。境界の呼び方でつまずいただけで、網が破れる形です。

3 値の境界値は、境界の値・その 1 つ下・その 1 つ上、の 3 件を試します。**どちらの値を「境界」と考えても、判定が切り替わる 2,999 と 3,000 の組が必ず 3 件の中に入る**のが利点です。

| 選び方 | 試す値 | 2,999 と 3,000 の組が入るか |
| --- | --- | --- |
| 2 値(境界を 2,999 と読む) | 2,998 / 2,999 | × |
| 2 値(境界を 3,000 と読む) | 2,999 / 3,000 | ○ |
| 3 値(境界を 2,999 と読む) | 2,998 / 2,999 / 3,000 | ○ |
| 3 値(境界を 3,000 と読む) | 2,999 / 3,000 / 3,001 | ○ |

3 値にすると 1 件増えますが、その 1 件が「境界の特定が正しかったか」への保険になります。

使い分けは件数とのつり合いで決めます。

| | 件数 | 使いどころ |
| --- | --- | --- |
| 2 値 | 1 境界あたり 2 件 | 既定。まずはこれで全境界を埋める |
| 3 値 | 1 境界あたり 3 件 | 仕様の言葉が曖昧な境界、壊れると影響が大きい境界 |

全部を 3 値にすると件数が 1.5 倍になります。まず 2 値で全境界を埋め、危ないと判断した境界だけ 3 値に厚くする、という順序が現実的です。どこを厚くするかの判断軸は、モジュール5のリスクの話でもう一度扱います。

## 3-2-4 ケース表を parametrize へ

> **ケース表の 1 行は pytest.mark.parametrize の 1 組にそのまま写せる**

境界値が 4 件になり、テスト関数を 4 つコピーして書きました。中身は入力と期待結果の数字だけが違います。5 件目を足すとき、コピー元の関数名を直し忘れて、同名の関数で上書きしてしまう。同じ形の関数が並び始めたら、写し方を変える合図です。

**parametrize** は、1 つのテスト関数に値の組を並べ、組の数だけ実行する仕組みです。表の列がそのまま引数名、表の行がそのまま 1 組になります。

```python
# test_shipping.py
import pytest

from shipping import shipping_fee


@pytest.mark.parametrize("total, expected", [
    (2999, 500),   # 3,000 円の境界の外側: 有料
    (3000, 0),     # 3,000 円の境界の内側: 無料
])
def test_shipping_fee(total, expected):
    assert shipping_fee(total) == expected
```

`"total, expected"` が表の列名、タプルが表の 1 行です。実行すると `2 passed` と表示されます。テストとしては 2 件に数えられている、という点が大事です。まとめて 1 件になったわけではありません。

1 件ずつ書いた場合と比べます。

| | 4 件を関数 4 つ | parametrize |
| --- | --- | --- |
| 行を足す | 関数を丸ごとコピー | タプルを 1 行足す |
| 失敗の見え方 | 関数名で分かる | `[3000-0]` と値が出る |
| 表との対応 | 目視で照合 | 行と組が 1 対 1 |

失敗したときに値そのものが表示されるので、どの行が落ちたかがすぐ分かります。また、タプルの右側にコメントで「3,000 円の境界の外側」と書いておくと、**なぜその値を選んだか**という設計の意図がコードに残ります。ケース表を別ファイルで管理すると必ず古くなるので、この形で一緒に置いておくのが実用的です。

## もっと知りたい人へ

- `pytest.mark.parametrize` の詳細: <https://docs.pytest.org/en/stable/how-to/parametrize.html>
- 境界は数値だけではありません。文字列の長さ、リストの要素数(0 件・1 件・上限件数)、日付(月末・年末・うるう日)にも境界があります。「順序のあるもの」には必ず境界があると考えてください
- 境界値分析は同値分割の上に成り立ちます。パーティションを切らずに境界だけ探すと、そもそも境界を数え落とします
