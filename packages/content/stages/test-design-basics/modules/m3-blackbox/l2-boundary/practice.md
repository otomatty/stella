# レッスン3-2 演習 — 境界値分析

対象トピック: 3-2-1 〜 3-2-4

## 手元で試す

前のレッスンと同じ 2 段構えです。**①仕様からケース表を書く → ②表を pytest に写して実行する**。

### ① ケース表を書く

送料計算の仕様に戻ります。

> **仕様**: 購入額 3,000 円以上なら送料は 0 円。3,000 円未満なら 500 円。購入額は 1 円以上の整数で、それ以外はエラー。

まず境界を数えます。この仕様に境界はいくつありますか。数えたら、2 値の境界値でケース表を作ってください。

| # | 入力(購入額) | 期待結果 | どの境界の内側/外側か |
| --- | --- | --- | --- |
| 1 | | | |
| 2 | | | |
| 3 | | | |
| 4 | | | |

埋めたら、次を確かめてください。

- 行数は「境界の数 × 2」になっていますか。パーティションの数と混同していませんか
- 「どの境界の内側/外側か」の列が空の行はありませんか。書けない行は、選んだ理由がない行です
- 3,000 円ちょうどの行がありますか

次に、この 4 件のうち **3 値に厚くする境界を 1 つ選び**、その理由を 1 行書いてください(表は 5 件になります)。

### ② 表を pytest に写す

作業用のフォルダに次の 2 ファイルを置いてください。

```python
# shipping.py
def shipping_fee(total):
    if not isinstance(total, int) or total < 1:
        raise ValueError("購入額は 1 円以上の整数です")
    return 0 if total >= 3000 else 500
```

```python
# test_shipping.py
import pytest

from shipping import shipping_fee


@pytest.mark.parametrize("total, expected", [
    (1, 500),      # 1 円の境界の内側: 有効
    (2999, 500),   # 3,000 円の境界の外側: 有料
    (3000, 0),     # 3,000 円の境界の内側: 無料
    (3001, 0),     # 3,000 円の境界の 1 つ上
])
def test_shipping_fee(total, expected):
    assert shipping_fee(total) == expected


@pytest.mark.parametrize("total", [0, -1, "3000"])
def test_invalid_total_is_rejected(total):
    with pytest.raises(ValueError):
        shipping_fee(total)
```

ターミナルで実行します。

```bash
pytest -v
```

`7 passed`(有効 4 件 + 無効 3 件)と表示されれば成功です。内訳は①の表と次のように対応します。

- `test_shipping_fee` の 4 組 = ①の表の有効側。1 円の境界は、外側(0 円)がエラーになる入力なので `raises` の側へ移し、代わりに 3,000 円の境界を 3 値(2,999 / 3,000 / 3,001)に厚くしています
- `test_invalid_total_is_rejected` の 3 組 = 0 円と、レッスン3-1 の無効同値パーティション(負数・数値でない入力)からの持ち越し

`-v` を付けると、`test_shipping_fee[3000-0]` のように **どの組が実行されたか**が 1 行ずつ出ます。自分の表のどの行に対応するかを目で確かめてください。

確かめられたら、次の改造をしてみましょう。

1. `shipping.py` の条件を `total > 3000` に書き換えて実行し、**どの組が落ちるか**を確かめる(確かめたら戻す)
2. 同じく `total >= 3001` に書き換えて実行し、落ちる組が 1 と同じであることを確かめる(確かめたら戻す)
3. `(1500, 500)` という組を足して実行し、落ちる組が増えないことを確かめる。これは既存のパーティションの真ん中なので、境界の欠陥に対しては無力です

## 演習問題

### 問1(基本)

「会員は 18 歳以上が登録できる」という仕様に対して、2 値の境界値でテストケースを作ってください。

### 問2(基本)

次のケース表は「境界値でテストした」と説明されています。どこが境界値分析になっていないか指摘してください。

| # | 入力(購入額) | 期待結果 |
| --- | --- | --- |
| 1 | 2,000 円 | 送料 500 円 |
| 2 | 4,000 円 | 送料 0 円 |

### 問3(応用)

「予約は 1 件から 10 件までまとめて登録できる」という仕様があります。境界がいくつあるか答え、2 値の境界値でケース表を作ってください。パーティションの数と境界の数がいくつになるかも書いてください。

### 問4(応用)

次の 2 件のテストを `pytest.mark.parametrize` に書き直してください。あわせて、なぜその値を選んだかがコードに残るようにしてください。

```python
def test_2999_costs_500():
    assert shipping_fee(2999) == 500


def test_3000_is_free():
    assert shipping_fee(3000) == 0
```

## 解答例と解説

<details>
<summary>問1の解答例</summary>

境界は 18 歳のところに 1 か所です。

| # | 入力(年齢) | 期待結果 |
| --- | --- | --- |
| 1 | 17 | 登録できない |
| 2 | 18 | 登録できる |

「18 歳以上」の境目は 17 と 18 の間にあります。19 を試しても、17 の側を踏んでいなければ境界のテストにはなりません。

</details>

<details>
<summary>問2の解答例</summary>

2,000 円も 4,000 円も、それぞれのパーティションの真ん中の値です。境界(3,000 円)にもその隣(2,999 円)にも触れていません。同値分割の代表値としては正しいのですが、境界値分析にはなっていません。

境界値にするなら 2,999 と 3,000 です。件数は同じ 2 件のまま、境界の取り違えを捕まえられるようになります。

</details>

<details>
<summary>問3の解答例</summary>

パーティションは 3 つ(0 件以下 / 1〜10 件 / 11 件以上)、境界は 2 か所(1 件のところと 10 件のところ)です。したがって 2 値なら 2 × 2 = 4 件になります。

| # | 入力(件数) | 期待結果 |
| --- | --- | --- |
| 1 | 0 | エラー |
| 2 | 1 | 登録できる |
| 3 | 10 | 登録できる |
| 4 | 11 | エラー |

パーティションが 3 つでケースが 4 件、という食い違いが起きるのが境界値分析の特徴です。数えるのは境界です。

</details>

<details>
<summary>問4の解答例</summary>

```python
import pytest

from shipping import shipping_fee


@pytest.mark.parametrize("total, expected", [
    (2999, 500),   # 3,000 円の境界の外側: 有料
    (3000, 0),     # 3,000 円の境界の内側: 無料
])
def test_shipping_fee(total, expected):
    assert shipping_fee(total) == expected
```

コメントに「境界の外側」「境界の内側」と書いておくと、なぜ 2,999 と 3,000 なのかがコードだけで分かります。値の意図が残っていないと、あとから「2,999 は中途半端だから 2,000 に丸めよう」と直されてしまいます。

</details>

## 確認クイズ

### Q1. 境界とは何ですか。

- A. テストケースの最大件数
- B. 仕様書の章の区切り
- C. 隣り合う同値パーティションが接する値

<details>
<summary>答え</summary>

**C** — 「以上」「未満」の境目です。`>` と `>=` の取り違えがここに集中します。

</details>

### Q2. 2 値の境界値分析で、1 つの境界につき作るテストケースは何件ですか。

- A. 2 件(境界の内側と外側を 1 つずつ)
- B. 1 件(境界の値だけ)
- C. パーティションの数と同じ件数

<details>
<summary>答え</summary>

**A** — 数えるのはパーティションの数ではなく境界の数です。境界が 2 か所なら 4 件になります。

</details>

### Q3. 送料計算(3,000 円以上で無料)で、実装が `total > 3000` になっていました。次のうち、この欠陥を捕まえられるのはどれですか。

- A. 2,000 円を入力するケース
- B. 3,000 円を入力するケース
- C. 5,000 円を入力するケース

<details>
<summary>答え</summary>

**B** — ずれる範囲は 3,000 円という 1 点だけです。パーティションの真ん中(2,000 円・5,000 円)では期待どおりに動いてしまいます。

</details>

### Q4. 3 値の境界値を使う利点はどれですか。

- A. テストの件数が減る
- B. 同値分割をしなくてよくなる
- C. どちらの値を「境界」と考えても、判定が切り替わる組が必ず入る

<details>
<summary>答え</summary>

**C** — 「境界」が 2,999 と 3,000 のどちらを指すのか迷っても、3 値なら 2,999 と 3,000 の組が 3 件の中に必ず含まれます。件数は 1 境界あたり 3 件に増えます。

</details>

### Q5. `pytest.mark.parametrize` で 4 組の値を並べたテスト関数を実行しました。結果は何件として数えられますか。

- A. 4 件
- B. 1 件
- C. 組の数によらず常に 2 件

<details>
<summary>答え</summary>

**A** — 組の数だけテストが実行されます。`-v` を付けると、`[3000-0]` のように値付きで 1 行ずつ表示されます。

</details>
