# レッスン3-1 演習 — 同値分割

対象トピック: 3-1-1 〜 3-1-5

## 手元で試す

このレッスンから 2 段構えになります。**①仕様からケース表を書く → ②表を pytest に写して実行する**、という順です。設計を飛ばしてコードから書き始めないでください。

### ① ケース表を書く

次の仕様を読んで、同値パーティションを列挙してください。

> **仕様**: 会員 1 人あたりのポイント付与率を返す。購入額が 1 円以上 9,999 円以下なら 1%、10,000 円以上なら 2%。購入額が 0 円以下、または数値でない場合はエラー。

まずパーティションの表を埋めます。

| 種別(有効/無効) | パーティション | 代表値 | 期待結果 |
| --- | --- | --- | --- |
| | | | |
| | | | |
| | | | |
| | | | |

埋めたら、次を確かめてください。

- 有効の行と無効の行が両方ありますか。無効が 0 行なら、3-1-4 を読み直してください
- 隣り合うパーティションの境目に、重なりや抜けはありませんか(9,999 と 10,000 のあたりを指でなぞる)
- 期待結果が「正しく動く」になっていませんか。見れば合否が決まる文になっているか確かめます

### ② 表を pytest に写す

作業用のフォルダを作り、次の 2 ファイルを置いてください。

```python
# points.py
def point_rate(total):
    if not isinstance(total, int) or total < 1:
        raise ValueError("購入額は 1 円以上の整数です")
    return 2 if total >= 10000 else 1
```

```python
# test_points.py
import pytest

from points import point_rate


def test_under_10000_gets_1_percent():
    assert point_rate(5000) == 1


def test_10000_or_more_gets_2_percent():
    assert point_rate(50000) == 2


def test_zero_is_rejected():
    with pytest.raises(ValueError):
        point_rate(0)
```

ターミナルで実行します。

```bash
pytest
```

`3 passed` と表示されれば成功です。`pytest.raises` は「この中でその例外が起きること」を期待する書き方で、無効同値パーティションの期待結果を書くときに使います。

確かめられたら、次の改造をしてみましょう。

1. ①の表に書いた 4 つ目のパーティション(数値でない入力)のテストを、4 本目として追加する
2. `test_under_10000_gets_1_percent` の期待値を `2` に書き換えて実行し、失敗の出力に実際の値と期待値が両方出ることを確かめる(確かめたら戻す)
3. 関数名を `check_under_10000_gets_1_percent` に変えて実行し、そのテストが集められなくなることを確かめる(確かめたら戻す)

## 演習問題

### 問1(基本)

次のテストケースには、3 点セットのうち欠けている要素があります。どれが欠けているか答え、補って書き直してください。

> 「注文確認画面を開き、送料の欄を見る。正しい送料が表示されること」

### 問2(基本)

送料の仕様(3,000 円以上で無料、1 円以上が有効)に対して、ある担当者が次の 5 件のケース表を作りました。無駄な行と、足りないパーティションを指摘してください。

| # | 入力 | 期待結果 |
| --- | --- | --- |
| 1 | 100 円 | 送料 500 円 |
| 2 | 500 円 | 送料 500 円 |
| 3 | 1,000 円 | 送料 500 円 |
| 4 | 2,000 円 | 送料 500 円 |
| 5 | 4,000 円 | 送料 0 円 |

### 問3(応用)

「無効な入力はまとめて 1 件のテストにしました。空文字・負数・文字列を順に渡して、全部エラーになることを確かめています」という報告を受けました。どんな問題があるか説明してください。

### 問4(応用)

パスワードの仕様「8 文字以上 32 文字以下。半角英数字のみ」について、同値パーティションを有効・無効に分けて列挙し、それぞれの代表値を挙げてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

欠けているのは **入力** と、判定できる **期待結果** です。手順しか書かれていません。

| 入力 | 手順 | 期待結果 |
| --- | --- | --- |
| 購入額 1,500 円 | 商品をカートに入れ、注文確認画面を開く | 送料が 500 円と表示される |

「正しい送料」は読む人によって解釈が変わるので、期待結果になっていません。金額まで書き切ります。

</details>

<details>
<summary>問2の解答例</summary>

1〜4 はすべて「1〜2,999 円」という同じパーティションの代表値なので、4 件のうち 3 件が無駄です。1 件残せば足ります。

足りないのは **無効同値パーティション** です。0 円以下(代表値 0)と、数値でない入力(代表値 "abc")の 2 件がありません。整理すると、5 件が 4 件になりつつ、網は広がります。

| # | 入力 | 期待結果 |
| --- | --- | --- |
| 1 | 1,500 円 | 送料 500 円 |
| 2 | 4,000 円 | 送料 0 円 |
| 3 | 0 円 | エラー |
| 4 | "abc" | エラー |

</details>

<details>
<summary>問3の解答例</summary>

1 件のケースの中で最初の入力がエラーになった時点で、そのケースの実行は終わります。残りの 2 つは実行されていません。それでも記録の上では「1 件通った」となるので、確かめていない検証を確かめたことにしてしまいます。

無効同値パーティションは、パーティションごとに別のテストケースに分けます。そうすれば、失敗したケースの名前を見るだけで、どの入力の扱いが壊れたのか分かります。

</details>

<details>
<summary>問4の解答例</summary>

長さと文字種という 2 つの観点があるので、それぞれ分けます。

| 種別 | パーティション | 代表値 |
| --- | --- | --- |
| 有効 | 8〜32 文字の半角英数字 | `abcd1234`(8 文字) |
| 無効 | 7 文字以下 | `abc1234`(7 文字) |
| 無効 | 33 文字以上 | 33 文字の英数字 |
| 無効 | 記号を含む | `abcd123!` |
| 無効 | 全角文字を含む | `abcd１２３４` |
| 無効 | 空 | `""` |

空文字は「7 文字以下」に含めることもできますが、実装で特別扱いされやすいので分けておくのが安全です。同値分割はあくまで仕様に基づく分け方なので、こうした判断が入る場面では「なぜ分けたか」をケース表に一言残しておくと、あとで読む人が困りません。

</details>

## 確認クイズ

### Q1. テストケースを構成する 3 つの要素はどれですか。

- A. 入力・手順・期待結果
- B. 目的・担当者・期限
- C. 準備・実行・後片付け

<details>
<summary>答え</summary>

**A** — この 3 つがそろって初めて、書いた本人以外が実行でき、合否を判定できます。

</details>

### Q2. 同値パーティションの説明として正しいものはどれですか。

- A. 同じ人が担当するテストケースの集まり
- B. 仕様の上で同じ結果になる入力の集まり
- C. 同じ画面で実行できるテストの集まり

<details>
<summary>答え</summary>

**B** — 「同じ扱いを受ける」の根拠は仕様です。コードの中身は見ないので、ブラックボックスの技法になります。

</details>

### Q3. 「1〜3,000 円」と「3,000 円以上」という分け方の問題はどれですか。

- A. 3,000 円がどちらにも入っていない
- B. 問題はない
- C. 3,000 円が両方のパーティションに入っている

<details>
<summary>答え</summary>

**C** — 重なっています。同じ入力に 2 つの期待結果が付いてしまうので、分割が成立していません。抜けも重なりも無いことが条件です。

</details>

### Q4. 各パーティションから代表値を 1 つ選んでよい根拠はどれですか。

- A. 同じパーティションの中の入力は同じ扱いを受けるから
- B. テストは早く終わらせたほうがよいから
- C. 代表値はキリのよい数字だから

<details>
<summary>答え</summary>

**A** — 減らしてよい理由は前提にあります。その前提が崩れているなら、そこは別のパーティションとして切り直します。

</details>

### Q5. pytest がテストとして集めて実行するのはどれですか。

- A. `shipping.py` の中の `test_under_3000_costs_500`
- B. `test_shipping.py` の中の `test_under_3000_costs_500`
- C. `test_shipping.py` の中の `check_under_3000_costs_500`

<details>
<summary>答え</summary>

**B** — ファイル名と関数名の両方が名前の決まりを満たす必要があります。集まらなかったときは `no tests ran` と出ますが、これは失敗ではなく「1 件もない」という意味です。

</details>
