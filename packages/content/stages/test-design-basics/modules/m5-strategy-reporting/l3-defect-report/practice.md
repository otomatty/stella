# レッスン5-3 演習 — 欠陥レポート

対象トピック: 5-3-1 〜 5-3-4

## 手元で試す

このレッスンは実行するコードがありません。**悪い欠陥レポートを 1 通、使える形に書き直します**。この講座で身につける文書作成の中心なので、必ず手を動かしてください。

### ① 悪いレポートを読む

課題管理ツールに、次の 1 通が登録されているとします。

> **タイトル**: 検索がおかしい
> **本文**: 検索が動きません。至急直してください。

まず、このレポートを受け取った開発者が最初にする行動を書き出してください。おそらく「どの検索ですか」「どんな操作をしましたか」と聞き返すことになります。その往復のあいだ、欠陥は 1 ミリも直りません。

### ② 4 部に書き直す

調査したところ、実際に起きていたのは次のことでした。ここから、**再現手順・期待した結果・実際の結果・環境**の 4 部でレポートを書き直してください。

> **分かったこと**: EC サイトの商品検索で、検索キーワードに半角スペースを含めると、結果が 0 件になる。「マグ カップ」で 0 件、「マグカップ」なら 12 件。スペースを含む場合は「マグ」と「カップ」の両方を含む商品を出す仕様(仕様書 3.4)。Chrome 126 / Windows 11、一般会員(test-user01)でログイン中、2026 年 8 月 20 日 14 時ごろに確認。エラーメッセージは出ず、「該当する商品はありません」と表示される。

雛形を用意しました。埋めてください。

| 項目 | 書くこと |
| --- | --- |
| タイトル | (1 行で「どこで・何が」が分かる形) |
| 再現手順 | 1. / 2. / 3. / 4. |
| 期待した結果 | (根拠つき) |
| 実際の結果 | (画面に出た文言をそのまま) |
| 環境 | (ブラウザー / OS / アカウント / 日時) |

書けたら、次の 3 点を自分で確かめてください。

- 手順は **1 行 1 操作**になっていますか。「検索する」ではなく、何を入力して何を押したかが書けていますか
- 検索キーワードは **具体値** で書けていますか。「スペースを含むキーワード」ではなく `マグ カップ` と書きます
- 期待した結果に **根拠**(仕様書 3.4)が入っていますか

### ③ 深刻度と優先度を付ける

書き直したレポートに、深刻度と優先度を付け、それぞれ理由を 1 行添えてください。

| 項目 | 値 | 理由 |
| --- | --- | --- |
| 深刻度 | | |
| 優先度 | | |

付け終わったら、「深刻度と優先度が同じ値になった理由を説明できますか」「違う値になった場合、その差はどこから来ましたか」を確かめます。深刻度は事実で、優先度は都合で決まります。

## 演習問題

### 問1(基本)

次の 3 つの記述を、値で書き直してください。

1. 「ページが遅いです」
2. 「登録ボタンが変です」
3. 「金額の表示がおかしい」

### 問2(基本)

1 通の欠陥レポートに、複数の故障をまとめて書くとどうなりますか。困ることを 2 つ挙げてください。

### 問3(応用)

次のレポートの本文には、書かないほうがよい記述が 2 か所あります。指摘して、理由を書いてください。

> 注文完了画面でまた落ちました。前も同じところで落ちていたので、たぶんキャッシュ周りのバグです。担当の方、そろそろ根本から直してもらえませんか。

### 問4(応用)

「トップページの背景色が、指定より少し明るい」という欠陥に、深刻度「軽微」を付けて報告しました。翌日、企画から「今週のテレビ CM と色を合わせる必要があるので、今日中に直してほしい」と連絡が来ました。深刻度を「重大」に上げるべきですか。理由とともに答えてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

| 元 | 値で書くと |
| --- | --- |
| ページが遅い | 商品一覧を開いてから表示されるまで 14 秒(仕様は 3 秒以内) |
| 登録ボタンが変 | 登録ボタンを押しても画面が変わらず、エラー表示も出ない |
| 金額の表示がおかしい | 金額が `¥1,500` ではなく `1500.0` と表示される |

「何秒か」「何が表示されたか」を書くと、期待との差が自動的に見えてきます。テストケースの期待結果を書くときと同じ作法です。

</details>

<details>
<summary>問2の解答例</summary>

- **片方だけ直った状態で閉じられます**。もう片方は誰にも引き継がれずに消えます
- **深刻度と優先度が付けられません**。1 通の中に深刻度の違う故障が混ざると、どちらに合わせても間違いになります

修正の進捗も、1 通単位でしか追えません。故障 1 つにつき 1 通が原則です。

</details>

<details>
<summary>問3の解答例</summary>

- **「たぶんキャッシュ周りのバグです」** — 原因の推測を根拠なく書いています。原因を探して直すのはデバッグの仕事で、テストの仕事は故障を再現できる形で届けることです。推測が外れると、開発者は見当違いの場所を調べます。書くなら「前回 #123 と同じ画面で発生しています」のように、観察した事実にとどめます
- **「担当の方、そろそろ根本から直してもらえませんか」** — 責める調子の記述です。読んだ人の手が止まりますし、レポートの目的(再現できる情報を届ける)に何も足していません

そもそも、このレポートには再現手順・期待・実際・環境が 1 つも書かれていません。書き直しが必要です。

</details>

<details>
<summary>問4の解答例</summary>

深刻度は「軽微」のままにします。上げるのは優先度のほうです。

深刻度は、その故障が製品と利用者に与える影響の大きさを、事実で判断するものさしです。背景色が少し明るいことによる利用者の損害は変わっていません。変わったのは事業の都合(CM との整合)で、これは優先度が決めることです。

「深刻度: 軽微 / 優先度: 最高」という組み合わせは、正常な状態です。深刻度を都合で動かすと、あとから「深刻度 高が何件残っているか」を数えたときの数字が信用できなくなります。終了基準がこの数字を使っている以上、動かしてはいけません。

</details>

## 確認クイズ

### Q1. 欠陥レポートの目的として、最も適切なものはどれですか。

- A. テスト担当者がどれだけ働いたかを記録すること
- B. 欠陥の原因を特定して、修正方法まで提案すること
- C. 直す人が手元で同じ故障を再現できるだけの情報を届けること

<details>
<summary>答え</summary>

**C** — 読み手は開発者で、評価基準は「往復ゼロで再現できるか」です。原因を探して直すのはデバッグの仕事で、レポートの役割ではありません。

</details>

### Q2. 再現手順の書き方として、適切なものはどれですか。

- A. 「適当な商品をカートに入れて、送料を確認する」
- B. 「1. 一般会員(test-user01)でログイン / 2. 商品「マグカップ 2,000 円」をカートに入れる / 3. カート画面の送料欄を見る」
- C. 「カート画面まわりを一通り操作して、送料の異常を確認する」

<details>
<summary>答え</summary>

**B** — 1 行 1 操作、データは具体値。どの商品かで結果が変わるので、「適当な商品」では再現できません。

</details>

### Q3. 「検索が動きません」という報告の何が問題ですか。

- A. 期待した結果と実際の結果が書かれておらず、何が異常なのかが分からない
- B. 表現が丁寧でないため、開発者の心証を害する
- C. 「検索」という機能名が具体的すぎて、範囲が狭すぎる

<details>
<summary>答え</summary>

**A** — 「動かない」が何を指すのかが伝わりません。「該当する商品はありません」と表示された、のように実際の結果を値で書き、期待した結果と並べます。

</details>

### Q4. 深刻度と優先度の関係として、正しいものはどれですか。

- A. 深刻度が高ければ、必ず優先度も高くなる
- B. 深刻度は影響の大きさ、優先度は直す順番で、ずれることがある
- C. 同じものを、テスト担当者と開発者がそれぞれ呼び分けているだけ

<details>
<summary>答え</summary>

**B** — 深刻度は事実で、優先度は事業の都合で決まります。「深刻度 低・優先度 高」(発表前日のロゴ)も「深刻度 高・優先度 低」(誰も使っていない旧画面)もありえます。

</details>

### Q5. 欠陥レポートに書かないほうがよいものはどれですか。

- A. 実際の結果のスクリーンショット
- B. 使用したアカウントとテストデータ
- C. 原因の断定的な推測(「キャッシュのバグです」)
- D. 発生した日時

<details>
<summary>答え</summary>

**C** — 原因を調べるのはデバッグの仕事です。断定が外れると、開発者は見当違いの場所を調べることになります。A・B・D は再現に必要な情報です。

</details>
