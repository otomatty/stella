# レッスン5-1 演習 — 何を自動化するか

対象トピック: 5-1-1 〜 5-1-4

## 手元で試す

自動化の判断は紙の上で終わりません。**選んだ 2 件を実際に自動テストにして、手で流した場合と時間を比べます**。

### ① 送料計算のケースを 2 軸で並べる

EC サイトの送料計算を、ここでも使います。

> **仕様**: 購入額 3,000 円以上なら送料は 0 円。3,000 円未満なら 500 円。購入額は 1 円以上の整数で、それ以外はエラー。

次の 6 件に、繰り返しの多さと判定の機械度を書き入れ、自動化の順番を決めてください。

| # | ケース | 繰り返し | 判定 | 順番 |
| --- | --- | --- | --- | --- |
| 1 | 購入額 2,999 円 → 送料 500 円 | | | |
| 2 | 購入額 3,000 円 → 送料 0 円 | | | |
| 3 | 購入額 0 円 → エラー | | | |
| 4 | 送料欄がカート合計の下に表示される | | | |
| 5 | 「送料無料まであと ◯◯ 円」の文言が読みやすい | | | |
| 6 | 年末キャンペーン集計(年 1 回) | | | |

判定の欄には「値で比較」か「人が目で見る」のどちらかを書きます。両方に当てはまらない行があれば、そこはケースの書き方が曖昧です。

### ② 最優先の 2 件を pytest に写す

順番が「最優先」になった行を 2 つ選び、手元で自動テストにします。同じフォルダーに 2 つのファイルを作ってください。

```python
# shipping.py
def shipping_fee(total):
    if total < 1:
        raise ValueError("購入額は 1 円以上")
    return 0 if total >= 3000 else 500
```

```python
# test_shipping.py
import pytest
from shipping import shipping_fee

@pytest.mark.parametrize("total, expected", [(2999, 500), (3000, 0)])
def test_shipping_fee(total, expected):
    assert shipping_fee(total) == expected
```

そのフォルダーで `pytest` を実行します。

```
2 passed in 0.06s
```

秒数を控えてください。同じ 2 件を画面で手作業で確かめたら何分かかるかを想像すると、40 件・週 2 回のときの差が実感できます。

### ③ 保守コストを体験する

仕様が変わったとします。**送料無料の境目が 3,000 円から 5,000 円に変わりました**。

- `shipping.py` の `3000` を `5000` に変えて `pytest` を実行してください。`1 failed, 1 passed` になります
- 落ちたのは欠陥ではなく、期待結果が古いからです。`parametrize` の 2 行を新しい境界(4,999 と 5,000)に直してください
- **通ったほうの 1 件にも注目してください**。2,999 円は境界の外側でなくなったのに、たまたま緑のままです。古い期待が緑で残るのが、保守を怠ったテストの怖いところです
- 直すのに何分かかりましたか。これが保守コストです。同じ変更が E2E 40 本に及んだ場合を想像してください

## 演習問題

### 問1(基本)

次の 4 つのテストを、自動化の優先度が高い順に並べ替え、それぞれ理由を 1 行で書いてください。

1. 会員登録フォームで、登録済みメールを入力するとエラーになる
2. 会員登録の完了メールが、迷惑メールフォルダーに入らない
3. 料金計算 API が、契約プランごとに正しい金額を返す
4. トップページの新デザインが、デザイン案どおりに見える

### 問2(基本)

「テストを自動化したので、手動テストの担当者は要らなくなります」という発言に対して、反論を 2 点挙げてください。

### 問3(応用)

あるチームが E2E を 300 本持っていて、そのうち 60 本が 3 か月前から赤いまま放置されています。この状態の問題点と、まず何をするかを書いてください。

### 問4(応用)

「自動化率(自動化したケース数 / 全ケース数)を 80% にする」という目標を立てたチームがあります。この目標が引き起こしそうな困った行動を 2 つ挙げ、代わりに何を目標にするか提案してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

順番: 3 → 1 → 2 → 4

| 順 | テスト | 理由 |
| --- | --- | --- |
| 1 | 3. 料金計算 API | 毎回流す + 金額を値で比較できる。2 軸とも満たす最優先 |
| 2 | 1. 登録済みメールでエラー | 毎回流す + エラーになるかを値で判定できる |
| 3 | 2. 完了メールが迷惑メール判定されない | 毎回は流さず、判定に外部の環境が絡む |
| 4 | 4. 新デザインの見た目 | 判定が人の目。しかもデザインは変わるので保守コストが高い |

3 と 1 の順は入れ替えても構いません。理由が書ければ正解です。

</details>

<details>
<summary>問2の解答例</summary>

- **自動テストは既知の確認しかできません**。「まだ誰も試していない操作は何か」に答えられるのは人だけです。探索的テストの担い手が要ります
- **何をテストすべきかを決めるのは人です**。ケース表を書き、期待結果が正しいかを判断する仕事は自動化されません

役割が「実行係」から「設計と探索」に移る、という言い方が実態に近いです。

</details>

<details>
<summary>問3の解答例</summary>

問題点は、赤が意味を失っていることです。60 本が常に赤いと、新しく壊れた 1 本が埋もれて見えません。テストがあるのに、何も守っていない状態です。しかも、赤いテストにも保守コストは掛かり続けます。

まずやることは、60 本を 1 本ずつ次のどれかに仕分けることです。

- 本物の欠陥を指している → 欠陥レポートを出して直す
- 仕様変更で期待結果が古い → テスト側を直す
- もう価値がない・保守コストが利点を上回る → **消す**

消す判断を許可することが肝心です。赤を全部直そうとすると、また 3 か月経ちます。仕分けが終わったら「赤があれば止める」を運用に戻します。

</details>

<details>
<summary>問4の解答例</summary>

困った行動:

- **自動化しやすいケースばかり書く**。判定が機械的な行だけ増え、リスクの高い場所が手つかずのまま率だけ上がります
- **保守コストの高いテストも消せなくなる**。消すと率が下がるので、赤いまま残されます

代わりの目標としては、結果に近い数値を置きます。たとえば「リリース前の手動リグレッションを 3 時間から 1 時間に減らす」「高リスク機能のケースは 100% 自動で流す」。どちらも、率ではなく守りたいものを直接指しています。

</details>

## 確認クイズ

### Q1. 自動テストの利点として、最も本質的なものはどれですか。

- A. 人が手で実行していた繰り返しを機械が担い、人の時間を新しいテストに回せる
- B. テストの実行が速くなるので、テスト担当者の人数を減らせる
- C. 自動テストがあれば、ケース表を書く必要がなくなる

<details>
<summary>答え</summary>

**A** — 速さは手段です。空いた時間の使い先が「まだ書かれていないテストを考える」ことに向いて、初めて価値になります。ケース表を書くのは人の仕事のままです。

</details>

### Q2. 自動テストのコストのうち、見積もりから抜け落ちやすいのはどれですか。

- A. テストコードを設計して書くコスト
- B. 仕様変更のたびにテストを直し続ける保守コスト
- C. テストを 1 回実行するのに掛かる時間

<details>
<summary>答え</summary>

**B** — 作るコストは見積もりに載りますが、保守コストは載りません。テストは書いた瞬間から手入れの対象になります。

</details>

### Q3. 自動化する対象を選ぶ 2 つの基準の組み合わせとして、正しいものはどれですか。

- A. 実装が新しいこと・画面から操作できること
- B. 経験者が担当していること・仕様書に載っていること
- C. 繰り返しが多いこと・合否判定が機械的であること
- D. 実行時間が長いこと・欠陥が多く出ていること

<details>
<summary>答え</summary>

**C** — この 2 軸なら誰が並べても同じ順番になります。説明できる基準であることが大事です。

</details>

### Q4. 次のうち、自動化に最も向かないものはどれですか。

- A. 送料計算の境界値 4 件(毎回のリリースで確認する)
- B. 年に 1 回だけ流す、キャンペーン集計の確認
- C. 会員登録で、登録済みメールがエラーになること

<details>
<summary>答え</summary>

**B** — 繰り返しが年 1 回では、作るコストと保守コストを回収できません。判定が機械的でも、片方だけでは後回しです。

</details>

### Q5. 自動テストと人の探索的テストの役割分担として、適切なのはどれですか。

- A. 自動テストは既知の確認、人の探索的テストは未知の発見に使う
- B. 自動テストで見つからない欠陥は、そもそも重要ではない
- C. 探索的テストを自動化できれば、人の作業は不要になる

<details>
<summary>答え</summary>

**A** — 自動テストが答えるのは「前と同じか」だけです。探索で見つけた欠陥をケース表に足し、自動テストに写す循環を作ってください。

</details>
