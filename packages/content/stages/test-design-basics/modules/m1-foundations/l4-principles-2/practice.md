# レッスン1-4 演習 — テストの 7 原則 II

対象トピック: 1-4-1 〜 1-4-3

## 手元で試す

このレッスンにも実行するコードはありません。Module 1 の締めくくりとして、7 原則を自分の言葉に落とす作業をします。

まず、7 原則を 1 枚に書き出します。レッスン 1-3 と 1-4 で扱った 7 つを、見ないで書けるだけ書いてみてください。思い出せなかったものは、あとで doc.md を見て補います。

| # | 原則 | 自分の言葉での一言 | 心当たりのある場面 |
| --- | --- | --- | --- |
| 1 | 欠陥がないことは示せない | | |
| 2 | 全数テストは不可能 | | |
| 3 | 早期テスト | | |
| 4 | 欠陥の偏在 | | |
| 5 | 殺虫剤のパラドックス | | |
| 6 | テストはコンテキスト次第 | | |
| 7 | 欠陥ゼロの落とし穴 | | |

右端の列がこの演習の本体です。実際に見聞きした場面を 1 つずつ書いてください。書けない原則があれば、それがまだ腹落ちしていない原則です。

次に、殺虫剤のパラドックスを自分の状況で確かめます。

1. いま定期的に実行されているテスト(手動でも自動でも)を 1 つ挙げる
2. そのテストが最後に赤くなったのはいつか思い出す
3. ずっと緑なら、それは「守れている」のか「見つける力を失っている」のかを考え、次に足すべきケースを 1 つ書く

最後に、コンテキストの確認です。いま関わっている案件について、次の 3 つに答えてください。

- この機能が止まると、誰がどれくらい困るか
- どれくらいの頻度でリリースするか
- テストの記録は、どこまで残す必要があるか

## 演習問題

### 問1(基本)

「毎回同じテストを全部回していて、半年ずっと全件通っている。だから品質は高い」という主張に、原則の名前を使って 1〜2 文で反論してください。

### 問2(基本)

前の案件で使っていたテスト計画書を、新しい案件にそのまま流用しようとしています。流用の前に確認すべきことを 2 つ挙げてください。

### 問3(応用)

ある社内システムのリリース判定会で、次の報告が出ました。

> 報告された欠陥 47 件はすべて修正済みです。テストは全件通っています。

この報告に対して、テスト担当者として付け加えるべき情報を 2 つ挙げ、それぞれどの原則に基づくかを書いてください。

### 問4(応用)

7 原則のうち、あなたの現場で最も守られていないと思うものを 1 つ選び、明日から試せる小さな改善を 1 つ提案してください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

殺虫剤のパラドックスにより、同じテストを繰り返すだけでは新しい欠陥は見つからなくなります。全件通り続けているのは「守れている」証拠にはなりますが、「新しい欠陥が無い」証拠にはなりません。加えて、テストは欠陥がないことを証明できないため、品質が高いという結論はこの情報だけでは出せません。

</details>

<details>
<summary>問2の解答例</summary>

1 つは、対象が失敗したときの影響です。人命や金銭に関わるなら、記録の残し方も第三者確認の有無も変わります。もう 1 つは、リリースの頻度と体制です。毎週リリースする案件に、半年に 1 回のリリースを前提とした重い手順を持ち込むと回りません。どちらもコンテキストの確認にあたります。

</details>

<details>
<summary>問3の解答例</summary>

1 つは、テストで確かめた範囲です。「全件通っている」は用意したケースの話であり、テストは欠陥がないことを証明できないため、何をどこまで確かめたかを添えます。もう 1 つは、利用者の目的に照らした所見です。仕様どおりに動いていても業務で使えなければ失敗になるため(欠陥ゼロの落とし穴)、操作の多さや分かりにくさに気づいていれば判定会に出します。

</details>

<details>
<summary>問4の解答例</summary>

たとえば早期テストが守られていない現場なら、「次の機能から、仕様書ができた時点でテストケースの見出しだけを書いてみる」という改善が挙げられます。完全なケースを作る必要はなく、見出しを書こうとするだけで仕様の抜けが見つかります。工数の追加もほとんど要らないため、明日から試せます。

</details>

## 確認クイズ

### Q1. 殺虫剤のパラドックスが言っていることはどれですか。

- A. テストを繰り返すほど、見つかる欠陥が増えていく
- B. 自動化したテストは実行するたびに壊れやすくなる
- C. 同じテストを繰り返すだけでは、新しい欠陥は見つからなくなる

<details>
<summary>答え</summary>

**C** — そのケースが狙っていた欠陥は既に取り除かれています。見つける力を保つには、ケースを足す・見直す必要があります。

</details>

### Q2. 既存のテストケースを毎回回し続ける価値が高いのはどちらの目的ですか。

- A. 動いていたものが壊れていないことを守る
- B. まだ見つかっていない新しい欠陥を見つける
- C. どちらの目的でも価値は下がらない

<details>
<summary>答え</summary>

**A** — 守る力は落ちませんが、見つける力は下がり続けます。この 2 つを分けて考えるのがポイントです。

</details>

### Q3. 「テストはコンテキスト次第」が意味することはどれですか。

- A. テストのやり方には唯一の正解手順があり、どの案件でも同じである
- B. 正しいテストのやり方は、対象と状況によって変わる
- C. テストのやり方は担当者の好みで決めてよい

<details>
<summary>答え</summary>

**B** — 見た目が同じ機能でも、失敗したときの影響が違えばかける厚みは変わります。好みではなく前提条件で決めます。

</details>

### Q4. 欠陥ゼロの落とし穴が指しているのはどれですか。

- A. 欠陥を全部直しても、利用者の役に立たなければ失敗である
- B. 欠陥を全部直せば、必ず利用者に喜ばれる
- C. 欠陥の件数を 0 にすることは技術的に不可能である

<details>
<summary>答え</summary>

**A** — 仕様どおりに動くことと、役に立つことは別です。欠陥ゼロは手段であって目的ではありません。

</details>

### Q5. 「1 件の申請に 15 画面かかり、現場では使われないと思われる」という気づきの扱いとして適切なのはどれですか。

- A. 欠陥ではないので、記録せず捨てる
- B. テストの範囲外なので、気づかなかったことにする
- C. 品質に関する情報なので、関係者に届ける

<details>
<summary>答え</summary>

**C** — テストの目的は品質の情報を届けることです。欠陥として扱われない場合でも、記録に残して次の仕様を決める場に持ち込む価値があります。

</details>
