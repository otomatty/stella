# レッスン1-1 演習 — テストは何のためにあるか

対象トピック: 1-1-1 〜 1-1-4

## 手元で試す

このレッスンには実行するコードがありません。紙かテキストファイルを 1 枚用意して、手を動かしてください。以降のレッスンでも同じファイルに書き足していきます。

まず、いま関わっている(または直近で関わった)システムを 1 つ思い浮かべてください。無ければ、普段使っている社内システムや Web サービスで構いません。

1. その機能について「テストは終わった」と報告する場面を想像し、**開発リーダー宛て** の一文を書く
2. 同じ内容を **発注者宛て** に書き直す。何を削り、何を足したかに印を付ける

次に、直近で不具合を直したとき(または誰かが直したのを見たとき)を思い出して、時間の使い道を 2 つに分けます。

| 作業 | 内容 | かかった時間 |
| --- | --- | --- |
| テスト | | |
| デバッグ | | |

書けたら、次を確かめてください。

- テストの行に書いたのは「現象」ですか。原因を書いてしまっていたら、それはデバッグの行です
- 2 つの合計が、当時「テストに時間がかかった」と報告した時間と合っていますか

最後に、テストプロセスの 6 つの活動(計画・分析・設計・実装・実行・完了報告)のうち、自分がこれまで担当したことのあるものに丸を付けてください。丸が付かなかった活動が、この講座で新しく身につく部分です。

## 演習問題

### 問1(基本)

「テストの目的はバグを見つけることである」という説明は、この講座ではやや狭い言い方になります。どう言い換えるとよいか、1 文で書いてください。

### 問2(基本)

次の 4 つを、テストの作業とデバッグの作業に分けてください。

1. 3,000 円ちょうどで注文したら送料が請求されることを確認した
2. 送料を計算している関数に print を入れて値を追った
3. 条件式が `>` になっていたので `>=` に直した
4. 会員登録の画面で、メールアドレス欄を空にして登録ボタンを押した

### 問3(応用)

ある現場では、リリースのたびにテストの件数を増やしています。それでも「仕様の読み違い」が原因の不具合が毎回出ます。品質保証の観点から、テストを増やす以外にどんな打ち手があるか 2 つ挙げてください。

### 問4(応用)

「テストは 3 日でお願いします」と言われました。テストプロセスの 6 つの活動を踏まえて、この依頼に対して確認すべきことを 2 つ書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

「テストの目的は、ソフトウェアの品質に関する情報を関係者に届けることである」と言い換えられます。欠陥を見つけるのは、その情報を作るための代表的な手段です。目的を情報の提供に置くと、「欠陥は 0 件でした」という結果にも価値があることが説明できます。

</details>

<details>
<summary>問2の解答例</summary>

テストは 1 と 4、デバッグは 2 と 3 です。1 と 4 は「期待と違う結果が出るか」を確かめる操作なので、出力は現象です。2 と 3 は原因の特定と修正なので、出力は「どこがなぜ間違っていたか」になります。

</details>

<details>
<summary>問3の解答例</summary>

1 つは、仕様のレビューにテスト担当者が参加することです。作る前の段階で読み違いの余地を減らせます。もう 1 つは、ふりかえりで「読み違いが起きた仕様の書き方」を洗い出し、仕様書のテンプレートや記述ルールを直すことです。どちらもテストの外側、つまりプロセスを良くする打ち手です。

</details>

<details>
<summary>問4の解答例</summary>

1 つは「3 日は実行だけの日数か、分析・設計を含むのか」です。含まないなら、設計の時間を別に確保する必要があります。もう 1 つは「完了報告をいつ、誰に、どの粒度で出すか」です。報告の形が決まっていないと、何をもって終わりとするかが決まりません。

</details>

## 確認クイズ

### Q1. テストの目的を最もよく表しているのはどれですか。

- A. ソフトウェアに欠陥が 1 つも無いことを証明すること
- B. ソフトウェアの品質に関する情報を関係者に届けること
- C. 見つけた欠陥をその場で修正すること

<details>
<summary>答え</summary>

**B** — 欠陥を見つけるのは情報を作るための手段です。届ける相手によって、伝える粒度は変わります。

</details>

### Q2. テストとデバッグの違いとして正しいものはどれですか。

- A. テストは開発者が行い、デバッグはテスト担当者が行う
- B. テストは手動で行い、デバッグは自動で行う
- C. テストは欠陥を見つける活動で、デバッグは原因を探して直す活動

<details>
<summary>答え</summary>

**C** — 担当者が同じでも作業は別物です。テストの出力は現象、デバッグの出力は原因と修正になります。

</details>

### Q3. 品質保証とテストの関係として正しいものはどれですか。

- A. 品質保証はプロセス全体を良くする活動で、テストはその一部である
- B. テストがプロセス全体を指し、品質保証はその中の実行作業である
- C. 品質保証とテストは同じ活動の別名である

<details>
<summary>答え</summary>

**A** — 仕様のレビューやふりかえりも品質保証の打ち手です。テストだけを厚くしても、同じ種類の不具合は戻ってきます。

</details>

### Q4. テストプロセスに含まれる活動の並びとして正しいものはどれですか。

- A. 実装 → 実行 → 修正 のみ
- B. 計画 → 分析 → 設計 → 実装 → 実行 → 完了報告
- C. 設計 → 実行 のみ

<details>
<summary>答え</summary>

**B** — テストは実行だけでなく、計画から完了報告までを含む一連の活動です。実行はそのうちの 1 つで、分析と設計はコードが完成していなくても始められます。

</details>

### Q5. テストケースの説明として、このレッスンの範囲で正しいものはどれですか。

- A. 発見された欠陥を 1 件ずつ記録した一覧
- B. テストにかかった時間を記録した日報
- C. 確かめることを 1 本の手順として書いたもの

<details>
<summary>答え</summary>

**C** — テストの最小単位です。何をどう書くかという具体的な書式は、技法を扱うモジュールで学びます。

</details>
