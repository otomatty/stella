## なぜ必要か

- 「テストは3日で」と言われて、動かす時間だけを見積もる
- 動かす段になって「何を確かめるんでしたっけ」と手が止まる

<!-- ノート: つかみ。実行だけを工数に数えた結果、設計の時間がどこにも無い。ここで結論は言わない。 -->

---

## 結論

**テストは実行だけでなく、計画・分析・設計・実装・完了報告まで含む一連の活動である**

- この一連の流れを **テストプロセス** と呼ぶ
- 中でも「何をどう確かめるか」を決める作業が **テスト設計**

<!-- ノート: 結論を言い切る。実行はプロセスの一部にすぎない。この講座の中心は設計だと予告する。 -->

---

## テストプロセスの 6 つの活動

| 活動 | やること |
| --- | --- |
| 計画 | どこまでやるか、いつ終わるかを決める |
| 分析 | 仕様から「何をテストすべきか」を洗い出す |
| 設計 | **テストケース**(確かめる手順1本)を作る |
| 実装 | 手順やテストコードを実行できる形にする |
| 実行 | 実装したテストを走らせ、結果を記録する |
| 完了報告 | 結果をまとめ、判断材料として届ける |

<!-- ノート: 具体例の枠。この6つの並びが講座の骨格になる。実行の前に4つの活動があることを強調し、設計から実装への橋渡しをM3で4回反復する、と触れておく。 -->
