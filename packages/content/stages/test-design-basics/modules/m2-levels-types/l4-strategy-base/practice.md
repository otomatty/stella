# レッスン2-4 演習 — テスト戦略の土台

対象トピック: 2-4-1 〜 2-4-4

## 手元で試す

モジュール2 の最後も紙の上の課題です。同じファイルに書き足してください。

いま関わっている(または直近で関わった)プロダクトを 1 つ選んでください。無ければ、この講座で使っているオンラインストア(会員登録フォーム + 料金計算 API)を対象にします。

まず、そのプロダクトでいま行われているテストを、思いつくまま 10 個書き出します。自動でも手作業でも構いません。「リリース前に営業担当が一通り触る」のような、手順書になっていないものも入れてください。

次に、書いた 10 個をピラミッドに置きます。

| 層 | 置いた項目 | 件数 |
| --- | --- | --- |
| E2E(システム) | | |
| 統合 | | |
| コンポーネント | | |

置き終わったら、次を確かめてください。

- 件数の並びは、下へ行くほど多くなっていますか。上が厚ければアイスクリームコーンの形です
- 上の層に置いた項目のうち、「下の層でも捕まえられそうなもの」に印を付けてください。1 つでも見つかれば、それが最初に手を打つ場所です

続いて、同じ 10 個を四象限に置き直します。

| | 支援(作るのを助ける) | 批評(問い直す) |
| --- | --- | --- |
| ビジネス | | |
| 技術 | | |

空欄になった象限について、「意図的にやっていない」のか「思いつかなかった」のかを 1 行で書いてください。

最後に、シフトレフトの課題です。書き出した 10 個のうち、実装の完了を待たずに始められる活動が 1 つはあるはずです。それを選び、いつ・誰と・何を材料に始められるかを 3 行で書いてください。

## 演習問題

### 問1(基本)

シフトレフトで「左へ動かす」のは、テストのどの活動ですか。動かせない活動もあわせて答えてください。

### 問2(基本)

テストピラミッドで、下の層を多く持つのはなぜですか。理由を 2 つ挙げてください。

### 問3(応用)

ある現場の自動テストは、E2E が 200 本、コンポーネントテストが 20 本です。実行に 50 分かかり、毎回 10 本ほどが不安定に落ちます。この状態を四象限やピラミッドの言葉で説明し、最初に打つ手を 1 つ提案してください。

### 問4(応用)

「うちのプロダクトには性能テストも探索的なテストも無いが、問題ない」と言う担当者がいます。この主張が妥当になるのはどんな場合で、危ういのはどんな場合か書いてください。

## 解答例と解説

<details>
<summary>問1の解答例</summary>

左へ動かすのは、分析とテスト設計です。仕様がある時点で始められるため、実装の完了を待つ必要がありません。動かせないのは実行です。動かすものが無ければ実行できないためです。「テストを早くする」ではなく「テストの考える部分を早くする」と読み替えると分かりやすくなります。

</details>

<details>
<summary>問2の解答例</summary>

1 つは速いことです。対象が小さいので実行が一瞬で終わり、変更のたびに気軽に流せます。もう 1 つは壊れにくいことです。対象の内部だけを見ているので、画面の見た目や周辺の都合が変わっても落ちません。この 2 つがあるので、下の層のテストは数を持っても負担になりません。

</details>

<details>
<summary>問3の解答例</summary>

上の層が厚く下の層が薄い、アイスクリームコーンの形です。遅くて壊れやすいテストばかりなので、赤くなっても原因を調べる時間が長く、やがて誰も結果を見なくなります。最初の手としては、毎回落ちる 10 本を調べ、そのうち「割引額の計算」のように関数の単位で確かめられるものをコンポーネントテストへ移すことです。E2E 側は、通しで成立するかを見る数本に絞ります。いきなり全部を作り直す必要はありません。

</details>

<details>
<summary>問4の解答例</summary>

妥当になるのは、それが判断の結果である場合です。利用者が数人の短命な社内ツールなら、性能テストを省くのは合理的な選択です。危ういのは、単に思いつかなかっただけの場合です。四象限に並べて空欄を見つけ、「やらない」と決めたのか「気づいていない」のかを区別しておく必要があります。空欄そのものではなく、空欄が説明できないことが問題です。

</details>

## 確認クイズ

### Q1. シフトレフトの説明として正しいものはどれですか。

- A. テストの実行だけを開発の初日に行う
- B. テスト活動を開発の早い段階へ寄せるほど、手戻りが減る
- C. テスト担当者を開発チームから独立させる

<details>
<summary>答え</summary>

**B** — 左へ動かすのは分析とテスト設計です。仕様の段階で見つかった欠陥は、書き直しだけで済みます。

</details>

### Q2. テストピラミッドの形として正しいものはどれですか。

- A. 下の層(コンポーネント)ほど多く、上の層ほど少なく持つ
- B. すべての層を同じ本数ずつ持つ
- C. 上の層(E2E)ほど多く持つ

<details>
<summary>答え</summary>

**A** — 下の層ほど速くて壊れにくいので、数を持っても負担になりません。同じ欠陥を捕まえられるなら、下の層で捕まえるほうが安く済みます。

</details>

### Q3. アイスクリームコーンの形になったテストの特徴はどれですか。

- A. 実行が速く、原因の絞り込みも簡単
- B. 非機能テストだけで構成されている
- C. 遅くて壊れやすく、変更のたびに多数が落ちる

<details>
<summary>答え</summary>

**C** — 手動テストと E2E に偏った逆ピラミッドです。悪いのは E2E そのものではなく、配分が逆であることです。

</details>

### Q4. テストの四象限の 2 つの軸はどれですか。

- A. 手動/自動 と 早い/遅い
- B. ビジネス/技術 と 支援/批評
- C. 機能/非機能 と 内部/外部

<details>
<summary>答え</summary>

**B** — 誰の言葉で語るかと、何のために行うかの 2 軸です。支援は作る側を助けること、批評は出来上がったものを問い直すことを指します。

</details>

### Q5. 四象限の使い方として、このレッスンで示したものはどれですか。

- A. すべての象限を必ず同じ量だけ埋める
- B. テストレベルの名前を決める
- C. 自分の現場の空欄を探し、やらないと決めたのか気づいていないのかを区別する

<details>
<summary>答え</summary>

**C** — 四象限は「作っていないテストに気づく」ための軸です。空欄そのものではなく、空欄が説明できないことが問題になります。

</details>
