# 受け入れテスト

テスト設計入門 — Module 2 / レッスン2-1

## なぜ必要か

- 仕様書のとおりに動いているのに、「これでは業務が回らない」と言われた
- リリース直前になって、運用の担当者から追加の要望が出てくる

<!-- ノート: つかみ。作った側の合格基準と、使う側の合格基準がずれている状態。ここで結論は言わない。 -->

---

## 結論

**受け入れテストでは発注者や利用者が「使えるか」を判断する**

- **受け入れテスト** — 発注者や利用者が主体となり、受け取ってよいかを決めるテストレベル

<!-- ノート: 結論を言い切る。ほかの 3 レベルは「作ったものが正しいか」、このレベルだけは「求めたものが届いたか」を見る。 -->

---

## 前のレベルとの違い

| | システムテスト | 受け入れテスト |
| --- | --- | --- |
| 主体 | 作る側 | 発注者・利用者 |
| 問い | 仕様どおりに動くか | 業務で使えるか |
| 結論 | 欠陥の一覧 | 受け取る / 受け取らない |

<!-- ノート: 対比枠。同じ操作をしても、判断の基準が違う。ここで出る指摘は「欠陥」ではなく「求めていたものとの差」であることが多い。品質の最終的な物差しは利用者側にある。 -->
