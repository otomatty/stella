# 解説

ルーティングは、最初に入力を分類し、種類ごとに用意した処理へ回すワークフローです。1 つの指示ですべての種類を扱うより、種類ごとに指示を作り込めます。よくある簡単な問い合わせは小さく安いモデルへ、難しい問い合わせは強いモデルへ回すと、費用と性能の釣り合いも取れます。

分類を Claude にさせると、`"Technical"` や `"billing."`、前後に空白の付いた値が返ることがあります。そのまま種類の名前と比べると、正しく分類できていても当てはまらないことになるので、そろえてから比べます。構造化出力の `enum` で絞っても、大文字と小文字までは保証されません。

それでもどの種類にも当てはまらない値(`"refund"` など)は必ずありうるので、行き先を決めておきます(`fallback`)。行き先そのものが `routes` にない設定の誤りは、送る前に止めます。`fellBack` を返しておくと、分類に失敗した問い合わせを数えて、分類の指示や種類の見直しに使えます。
