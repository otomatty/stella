# レビューで見ること

- 応答ごとに `usage` を `priceOf` に渡し、最後の応答の費用も含めているかを確認します。上限に達したあとに送信が残る実装や、上限に達した応答の履歴を捨てる実装がよくある誤りです。
- `pause_turn` の前後で assistant の内容をそのまま残し、user の発言を挟まず、連続した送り直しだけを数えているかを見ます。
- ツールの結果のまとまりと ID の対応を見ます。エラーで発言を分けたり、例外で結果を残さずに終えたりすると、どの呼び出しに何が返ったか追えません。
- 失敗の比較では、ID やエラーメッセージの代わりにツール名と入力を使っているかを見ます。成功や別の入力で連続性が切れることも確認します。
- 説明欄では、失敗時の `null` を回答として扱うと起きる問題と、上限に達したときの画面表示や再開の判断を説明しているかを見ます。
