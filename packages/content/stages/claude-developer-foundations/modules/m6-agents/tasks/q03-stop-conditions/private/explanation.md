# 解説

解答例では、その応答で終わる理由を処理してから、次に送る直前に費用と回数を確かめます。上限と同時に最後の回答が届いた場合も、結果を失わずに返せます。ツールは順に処理し、同じ失敗が続いたことを検出した回も、応答内の結果を1つの user の発言にそろえて残します。

別の書き方として、各停止理由の処理を関数に分け、その関数から終了の種別か続行の印を返す方法があります。停止理由が増えたら処理を分けると見通しがよくなります。この課題の大きさなら、短い分岐を並べると、履歴と回数を更新する位置を追いやすくなります。

呼び出し側は `success` の場合にだけ回答を表示します。上限で止まったときは、消費した回数や費用を知らせます。再開を提供する場合は、履歴をもとに再開できるかを確かめ、上限の追加を決めてから再開します。
