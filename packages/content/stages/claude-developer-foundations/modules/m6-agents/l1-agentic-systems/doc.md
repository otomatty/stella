# レッスン6-1 ワークフローとエージェント

## このレッスンの目標

- [ ] ワークフローとエージェントの違いを説明できます。
- [ ] 1 回の呼び出し・ワークフロー・エージェントのどれから始めるかを選べます。

## 6-1-1 手順を決めるのは誰か

> **手順をコードで決める仕組みがワークフローで、手順を Claude に任せる仕組みがエージェントです。**

「エージェント」という言葉は、長く自律して動く仕組みにも、決まった手順を追う仕組みにも使われます。Anthropic の記事「Building effective agents」は、これらをまとめてエージェント的な仕組み(agentic systems)と呼び、作りの違いで 2 つに分けています。

| 種類 | 手順を決めるもの | 向く仕事 |
| --- | --- | --- |
| ワークフロー | 前もって書いたコード。決めた順に Claude とツールを呼ぶ | 手順がはっきり決まった仕事。動きを予想しやすく、毎回そろう |
| エージェント | Claude 自身。何をどの順でするか、どのツールを使うかを自分で決める | 必要な手順の数を前もって決められない、決まった道筋を書けない仕事 |

エージェントの作りは、見た目より単純です。多くは、ツールの結果(環境からの手応え)を見ながらツールを使い続ける、ループの中の Claude です。そのため、ツールとその説明をていねいに作ることが大切です。エージェントは長く自律して動くので、費用がかかり、間違いが積み重なるおそれもあります。隔離した環境で十分に試し、適切な歯止めを用意します。

どちらの仕組みも、土台は「拡張した LLM」です。検索・ツール・記憶で能力を足した Claude を部品として組み立てます。

## 6-1-2 単純な作りから始める

> **まず単純な作りで試し、効果が確かめられたときだけ複雑にします。**

エージェント的な仕組みは、多くの場合、速さと費用を払って性能を上げるものです。その引き換えに見合うときだけ使います。多くの用途では、資料や例を入れた 1 回の呼び出しを磨けば足ります。

1. 単純なプロンプトで試し、評価のセットで確かめながら磨く
2. それで足りないときに、手順が決まった仕事ならワークフローを足す
3. 柔軟さと Claude の判断が要る仕事なら、エージェントにする

エージェントを作るフレームワークは、Claude の呼び出し・ツールの定義・呼び出しのつなぎを簡単にし、始めやすくします。一方で、中のプロンプトと応答を見えにくくして、問題を追いにくくすることがあります。記事は、まず API を直接使うことを勧めています(多くの形は数行で書けます)。フレームワークを使うなら、その中で何が起きているかを理解しておきます。

記事は、エージェントを作るときの原則として次の 3 つを挙げています。

- 作りを単純に保つ
- 計画した手順を見えるようにして、何をしているかを分かるようにする
- ツールの説明と試験をていねいに行い、エージェントとツールの間の受け渡しを作り込む

この記事は 2024 年 12 月のもので、冒頭に「記事で紹介した道具の状況は、その後大きく変わった」という注記があります。この単元では、個々の道具ではなく、仕組みの分け方と形の考え方を扱います。
