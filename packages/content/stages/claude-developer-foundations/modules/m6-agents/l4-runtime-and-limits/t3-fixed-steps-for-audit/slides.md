# 監査が要るなら手順を固定する
<!-- ノート: 決まった順で処理したことを、あとから説明できる形を選びます。 -->
---
# 同じ申請で確認の順が違った
経費申請で、ある日は領収書を先に照合し、別の日は金額を先に集計しました。担当者は、規程どおりの順で進んだかを説明できません。
<!-- ノート: 監査は、業務が決められた規程どおり進んだかを記録で確かめることです。 -->
---
# 確認の順をコードで決める
監査や誤りの許容度が厳しい業務は、手順を固定したワークフローにします。
<!-- ノート: 確認の順が業務で決まっていれば、実行経路を予測でき、記録とも照合できます。 -->
---
# 経費申請の確認を記録する
| 段 | 記録すること |
| --- | --- |
| 領収書を照合する | 照合した証票と結果 |
| 金額を集計する | 対象の明細と合計 |
| 担当者に報告する | 報告した結果と参照した規程の版 |
<!-- ノート: 各段を実行した記録を残すと、どの証票から合計を出したかまで追えます。 -->
