# レッスン6-6 実行の記録から欠けた設計を見つける

## このレッスンの目標

- [ ] 実行の記録のどこで想定した動きが崩れたかを見つけられます。
- [ ] 終わらないループで、停止の分岐と回数の上限を見直せます。
- [ ] 一時停止したサーバーツールの応答から続きを受け取れます。

## 6-6-1 トレースで原因を探す

> **エージェントの不具合は、実行の記録を順に読み、どの設計が欠けているかで分けます。**

トレースは、呼び出しや応答など、処理を起きた順に残した記録です。たとえば、在庫と価格の照会は両方成功したのに、次のリクエストに 400 が返りました。次のように、ツールが返した結果と、アプリが送った発言を分けて読みます。

| 時点 | 実行の記録 |
| --- | --- |
| Claude が呼び出す | assistant に `tool_use(a)` と `tool_use(b)` |
| アプリが実行する | 在庫 a、価格 b ともに結果あり |
| アプリが送る | 直後の user の発言には `tool_result(a)` だけ |
| API が応答する | 400。呼び出し b に結果が対応していない |

壊れたのは結果を返す段です。6-5 のような文脈の問題も、何が増えた時点で指示を見落としたかを確認してから直します。

| 症状 | 欠けている設計 | 直し方 |
| --- | --- | --- |
| ツール使用のループが終わらない | 停止理由で分ける出口や、回数・費用の上限 | `stop_reason` で出口を選び、再試行・ターン・予算を制限する |
| サーバーツールの途中で完了と表示する | `pause_turn` の処理 | 途中の assistant の内容とツール定義を保って続きを受け取る |
| 結果が無いという 400 が返る | 呼び出し ID と結果を対応させる受け渡し | 5-1-2 の形で、直後の 1 つの user の発言に全結果をテキストより前に並べる |
| 並列でツールを呼ばなくなった | 並列の結果をまとめて返す処理 | 発言を 1 つずつ送っていないか確かめ、全結果を 1 つの発言にまとめる |
| 枠があふれる、最初の指示を見落とす | 枠に残す情報を絞る設計 | 増えたのが会話かツール結果かを見て、圧縮、古い結果の削除、返す項目の絞り込みを選ぶ |
| 調査の途中経過で親の文脈が埋まる | 調べる文脈と報告の分離 | サブエージェントに分け、報告の形式を指定する |
| セッションをまたぐと進捗が消える | 作業状態の引き継ぎ | セッションを再開するか、メモリーやアプリに残した状態を新しい依頼に渡す |
| 多数の定義の中からツールを選び間違える | 必要な定義だけを読み込む設計 | ツール検索で仕事に必要な定義を読み込む |

## 6-6-2 終わらないループ

> **終わらないループには、止まる条件と回数の上限を足します。**

`end_turn` のあとにもリクエストを送っていれば、終了の分岐が抜けています。自分で書く Messages API のクライアントツールのループは、`stop_reason` が `tool_use` の間だけ実行と結果の受け渡しを続けます。

一方、`tool_use` と `is_error: true` が交互に続くときは、失敗の中身と入力を見比べます。廃番の品番を毎回送っても、同じ失敗が続きます。その入力での照会を打ち切り、利用者に品番の確認を求めます。一時的な障害からの再試行にも回数の上限を付けます。ツールが毎回成功しても繰り返す場合に備え、ループ全体にも上限を設けます。Agent SDK なら 6-4-1 の `maxTurns` と `maxBudgetUsd` を使います。

修正したら、回答で終わる場合と、同じ失敗を繰り返す場合の記録を比べます。前者は `end_turn` で抜け、後者は決めた上限より先の呼び出しを記録しません。どの条件で止めたかも残します。

## 6-6-3 途中で返ってきた応答

> **stop_reason が pause_turn の応答は、内容を変えずに送り直して続きを受け取ります。**

サーバーツールを使うターンでは、サーバー側に繰り返しの上限があります。既定では 1 リクエストあたり 10 回です。この上限に達したことを表す停止理由が `pause_turn` です。ウェブ検索の例で、続きのリクエストを考えます。

| 元のリクエストの項目 | 続きのリクエストでの扱い |
| --- | --- |
| `messages` | これまでの発言の末尾に assistant の発言を足す。内容は `pause_turn` で返った `content` をそのまま使う |
| `tools` | 同じ定義を送る。まだ結果のないサーバーツールの呼び出しも assistant の内容に残す |
| 新しい user の発言 | 加えずに続きを受け取る |

たとえば、ウェブ検索を使うリクエストの `request` と、途中で届いた `response` があるとします。

```js
const continuation = {
  ...request,
  messages: [...request.messages, { role: "assistant", content: response.content }],
};
```

元のリクエストをもとに、`messages` だけを組み立て直しています。

`pause_turn` がもう一度返ったら、各回の assistant の内容を順に残したまま、続けるかを判断します。続行の回数にも上限を付けます。コンテナーの情報を含む応答なら、その ID も次に渡してファイルを引き継ぎます。
