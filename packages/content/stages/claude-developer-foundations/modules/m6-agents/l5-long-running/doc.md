# レッスン6-5 長い作業の文脈を保つ

## このレッスンの目標

- [ ] 文脈を使っている情報を見て、減らす手段を選べます。
- [ ] 親に要る情報を決めて、調査の途中経過を切り離せます。
- [ ] 新しいセッションを始める条件と、読み直す記録を決められます。

## 6-5-1 古いツール結果を減らす

> **古いツール結果が溜まったら、コンテキストの編集で古い結果から外します。**

商品を 1 件ずつ照合するたび、候補 50 件の検索結果を受け取るとします。やり取りが短くても、調べ終えた商品の候補が枠を使い続けます。4-3 で学んだように、トークンが増えるほど、最初の指示を正確に思い出す力が落ちます。枠を広げてもこの劣化は起こり、キャッシュで費用を抑えても枠の使用量はそのままです。

コンテキストの編集では、サーバー側が規則に沿って古いツール結果を外します。直近 3 回のツール使用を残すように設定すれば、いま照合中の候補を見ながら進められます。外した結果は要約されません。アプリの履歴には元の結果が残ります。

| 枠を使っているもの | 選ぶ手段 |
| --- | --- |
| 照合の済んだ検索結果 | コンテキストの編集で古い結果を外す |
| 使うか分からない多数のツール定義 | ツール検索で使う定義をあとから読み込む |
| 長い会話のやり取り | 4-3-3 の圧縮で要約して続ける |

## 6-5-2 調べものを切り離す

> **文脈を埋める調べものはサブエージェントに任せ、親は要約だけを受け取ります。**

営業資料を作る途中で三つの地域の統計が要ります。親は資料の構成と採用する数値を持ち、地域ごとの検索や集計表の確認はサブエージェントに頼めます。6-3-2 で学んだとおり、通常は親の会話が渡らないので、集計年や比較したい指標は依頼に書きます。

親に戻るのは最後の報告です。報告に表をすべて写せば、結局親の会話も膨らみます。読み取りだけの調査なら使えるツールを絞り、返す形式を「地域・数値・年・出典を各 1 行」と指定します。詳しい明細が必要なら、合意したファイルに書き、報告では場所だけを返す形も選べます。

子はそれぞれリクエストを送るので、分けるとトークンの消費が増えます。地域別の調査のように、独立した仕事を同時に進められるか、長い途中経過を親の文脈から切り離せるかを見て決めます。

## 6-5-3 新しく始める基準

> **2 回直しても直らないときと、関係のない作業に移るときは、新しいセッションで始めます。**

休業日を除くよう 2 回修正しても、集計結果に同じ行が残りました。3 回目の依頼を足す前に、最新のテストと営業日カレンダーを確認します。そこから分かった条件を入れ、新しいセッションで頼み直します。

> 営業日カレンダーの休日を除いて日別件数を集計してください。5 月 6 日は休日です。この日の行が出力に含まれないことをテストしてください。

別の業務に移るときも、前の会話を引き継ぐ必要がなければ新しく始めます。同じ仕事で以前の判断を使うなら、セッションの再開を選べます。以前の失敗を含む会話を圧縮するより、進捗メモ、テスト結果、Git の履歴から確認済みの条件を拾い、新しく始めるほうが分かりやすいこともあります。

圧縮して続けるときは、4-3-3 の要約に何が残ったかを確かめます。要約された範囲の画像・文書・考える過程や、途中で出した指示の詳細は失われることがあります。次の判断に要る条件を言い直し、参照する資料をもう一度渡します。

## 6-5-4 セッションをまたいで覚える

> **セッションをまたいで要る情報は、ファイルやメモリーに書き出します。**

資料を毎日 20 件ずつ照合します。作業の節目で、次の担当が読み直せる進捗メモを更新します。

| 残すもの | この仕事で書く例 |
| --- | --- |
| 確認した範囲と条件 | 資料 1〜20 を確認、規程 v3 を適用 |
| 根拠の場所 | `records/checks.csv` に照合結果を記録 |
| 次に取り組む範囲 | 資料 21 から確認。資料 18 の版は担当者に確認中 |

新しい会話の冒頭で、進捗メモを読んでから始めるよう頼みます。アプリが作業状態を持つ場合は、その状態を読み取って新しい依頼に含める方法もあります。

| 道具 | 状態の残し方 |
| --- | --- |
| Messages API のメモリーツール | アプリが `/memories` 以下のファイルの読み書きを実装する。コンテキストの編集と組み合わせると、結果を外す前に必要な情報を保存するよう Claude に通知される |
| Agent SDK | 同じ会話を続けるなら、6-3-3 のセッション ID を控えて再開する。別の会話に引き継ぐ要点は、作業ファイルに残す |
| Managed Agents のメモリーストア | 複数のセッションから使う記憶の保存先を用意し、その保存先を新しいセッションにもつなぐ |
