# レッスン3-5 モデルの更新に備える

## このレッスンの目標

- [ ] 同じ入力で出力が揺れるときに、複数回の結果から信頼性を判断できます。
- [ ] 利用中のモデルの廃止予告から、評価と切り替えの期限を決められます。
- [ ] 回帰評価の結果を読み、切り替えに進める条件を説明できます。

## 3-5-1 同じ入力でも出力は変わる

> **同じ入力でも出力は毎回同じとは限らないので、複数回の結果で判断します。**

予約変更のチャットに同じ質問を 3 回送ると、1 回だけ締切の案内が抜けました。言い回しには幅があっても、締切と手順は毎回正しく伝える必要があります。必要な条件を決めて、同じケースを複数回実行します。出力の形をそろえたいときは構造化出力（4-2-1）を使い、値の正しさは評価で確かめます。

案内が毎回正しいことを重視するなら、各ケースで k 回実行して、**k 回すべて成功したケースの割合**を見ます。1 回の成功率が 75% で各回が独立なら、3 回とも成功する確率は `0.75 × 0.75 × 0.75` で約 42% です。1 回の成功率だけでは、同じケースを繰り返して任せられるかを判断しにくいと分かります。

モデル ID が指す重み（モデルの学習で得た値）は固定です。そのモデルを動かす基盤の更新で、振る舞いがわずかに変わることはあります。温度を指定できるモデルでも、`temperature: 0` で応答が毎回同じになる保証はありません。Claude 4.7 以降は、以前の API 版でも `temperature`・`top_p`・`top_k` に既定以外の値を付けると 400 になります。API 版 `2026-10-21` では、既定の値でもこれらを指定すると 400 になるため、リクエストから外します。

## 3-5-2 モデルには終わりがある

> **モデルは予告のあとに廃止されるので、廃止日より前に次のモデルで評価します。**

固定したモデル ID（1-2-3）で帳票を仕分けるサービスに、廃止予告が届きました。固定した ID の参照先は自動では新しくなりません。公開モデルでは、利用中の顧客に廃止の少なくとも 60 日前に予告が届きます。

| 状態 | 意味 |
| --- | --- |
| 現行 | サポートされ、利用が推奨されている |
| レガシー | 更新は終わっており、今後非推奨になることがある |
| 非推奨 | まだ呼び出せる。廃止日と移行先の候補が案内される |
| 廃止 | Claude API の Messages API では、その ID に 404 が返る |

通知が来たら、使っている提供先の廃止日を確かめます。設定と実際の使用量をモデル ID ごとに見て、画面と夜間集計の両方が同じ ID を使っていると分かりました。現行モデルを呼べるうちに評価結果を取り、同じケースで次のモデルを試します。候補の評価と一部の通信での確認を含め、切り替えを廃止日前に終える日程を立てます。

## 3-5-3 替える前に同じ評価を回す

> **モデルを替える前に、同じ評価のセットで品質・速度・費用を比べ直します。**

前の版で通ったケースが、替えたあとも通るかを同じ評価のセットで確かめることを、回帰評価と呼びます。モデル選び（3-1-2）で使った評価から、実際に使うプロンプトとデータ、合否を決める条件をそろえます。まず同じケースを同じ回数試し、旧版と候補の結果を ID ごとに突き合わせます。

納品書の読み取りを各 100 件で比べた例です。手書きの 20 件は、100 件の中に含まれます。この業務では手書き 20 件すべてに正解する必要があります。費用には失敗した試行の分も入れます。

| 項目 | 現行 | 候補 |
| --- | ---: | ---: |
| 正解数 | 92 件 | 95 件 |
| うち手書きの正解数 | 20 件 | 17 件 |
| 約 95% の処理が収まる時間（p95） | 2.4 秒 | 1.9 秒 |
| 100 件を処理した費用 | 4.60 ドル | 3.80 ドル |
| 正解 1 件あたりの費用 | 0.05 ドル | 0.04 ドル |

候補は全体で速く安くなりましたが、手書きの必須 3 ケースが落ちています。失敗した納品書で、今の指示や候補の設定が合うかを確かめます。effort はモデルによって既定が違うため、候補で対応する値を明示し、品質を満たす値を探します。使うプロンプトを直したら、同じケースと合否の基準で再評価します。

費用を見積もるときは対象のモデルで `countTokens` を使います（3-3-1）。新しい数え方では同じ文章でも約 3 割多くなることがあります。採用の判断では、単価の表に加え、実測の使用量から求めた**仕事 1 件を終える費用**と応答時間で比べます。

評価を通ったら、一部の本番リクエストで候補も並行して動かし、利用者への応答には現行の結果を使います。その通信で品質・速度・費用を確かめ、基準に収まれば候補に切り替えます。
