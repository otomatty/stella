## 知識問題

### Q1. 返品窓口のチャットは、同じ質問を 3 回試すと、そのうち 1 回だけ返送先を案内しませんでした。利用者に毎回必要な情報を届けられるかを、どのように測りますか？
<!-- kind: single; skills: claude-model-selection -->

- A. 同じケースを繰り返し、1 回でも案内できればそのケースを合格とする
- B. 同じケースを繰り返し、全回で必要な項目を正しく案内したケースの割合を出す
- C. 返送先を案内できた回の文章を正解とし、文面が一字一句同じかを比べる

<details>
<summary>解答</summary>

**B** — 毎回必要になる項目を合格条件にすると、案内が時々抜けるケースを区別できます。

</details>

### Q2. API を 2026-10-21 版に替えたところ、以前の設定にある temperature: 0 を送る処理が 400 を返しました。一貫した動作を確認するには、どうしますか？
<!-- kind: single; skills: claude-model-selection -->

- A. temperature を外し、同じ入力を複数回試して必要な条件を満たすか確認する
- B. temperature を既定の 1 に替え、最初の成功で切り替えを決める
- C. temperature の代わりに top_p を付け、リクエストを送り直す

<details>
<summary>解答</summary>

**A** — この API 版では、値にかかわらず生成時のこれらの設定を付けると 400 になります。出力を繰り返し確かめて、条件を満たすか判断します。

</details>

### Q3. 請求書を分類するモデルの廃止予告が届きました。モデル ID を固定しており、設定を参照する夜間処理もあります。廃止までに何を済ませますか？
<!-- kind: single; skills: claude-model-selection -->

- A. 画面で使う ID だけをすぐ更新し、残りの呼び出しは廃止後に調べる
- B. 現在の ID を保ち、廃止後に 404 が返ったときの送り直しを追加する
- C. ID の利用箇所を洗い出し、候補の評価と切り替えを廃止日前に終える

<details>
<summary>解答</summary>

**C** — 固定の ID は自動で更新されず、廃止後は 404 になります。夜間処理も含め、廃止前に移行します。

</details>

### Q4. 注文票の読み取りで、候補モデルの正解数が 92 件から 95 件に増えました。一方で、現行モデルが通っていた手書きの必須ケース 3 件を落としました。次はどうしますか？
<!-- kind: single; skills: claude-model-selection -->

- A. 失敗したケースを調べて候補の設定や指示を見直し、同じ評価セットで測り直す
- B. 全体の正解数が増えているため、先に全件を候補へ切り替える
- C. 手書きだけ評価セットから外し、全体の差を確かめる

<details>
<summary>解答</summary>

**A** — 同じケースを残すと、現行で通った必須ケースが候補でも通るようになったかを確認できます。

</details>

### Q5. 候補モデルはトークンあたりの単価が安く、既定の effort が旧版と違います。切り替えて予算と応答時間を守れるか、どのように測りますか？
<!-- kind: single; skills: claude-model-selection -->

- A. 旧版で数えたトークン数に候補の単価を掛けて、価格の差を予算に反映する
- B. 同じデータで候補の effort を明示して試し、仕事 1 件を終える費用と応答時間、品質を測る
- C. 前のモデルと同じ effort を設定し、候補の最初の 1 件が速ければ全体の速度も満たすとみなす

<details>
<summary>解答</summary>

**B** — モデルが変わると同じ入力でもトークン数が変わります。使う設定で同じ仕事を試し、完了までの費用と速度、品質を比較します。

</details>

### Q6. 保存した注文票で新旧モデルを比べ、候補が合格しました。実際の通信でも基準を満たすかを、全面切り替え前に確かめるにはどうしますか？
<!-- kind: single; skills: claude-model-selection -->

- A. 本番では候補のリクエストの成功件数だけを数え、応答の中身は保存した注文票の結果で代用する
- B. 全件を候補に切り替え、問い合わせが増えたら旧版に戻す
- C. 一部の本番リクエストで候補も並行して動かし、現行の結果を利用者に返しながら比較する

<details>
<summary>解答</summary>

**C** — 同じリクエストで品質・速度・費用を確かめられます。基準を満たすことを確認してから、利用者に返す結果を切り替えます。

</details>
