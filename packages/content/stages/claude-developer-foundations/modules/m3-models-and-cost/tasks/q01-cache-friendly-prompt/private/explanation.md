# 解説

キャッシュは、`tools`・`system`・`messages` の順に並べたプロンプトの前半について、`cache_control` を付けたブロックまでが前のリクエストと一致しているかで決まります。書き込まれるのは区切りの位置だけなので、毎回変わる時刻と質問のブロックに区切りを置くと、毎回違う前半を書き込むだけで、読み込みは起きません。

毎回同じ指示と資料を前に置き、その最後のブロックに区切りを置けば、時刻と質問が変わっても前半は一致し、2 回目から読み込みになります。区切りを 1 つにしておけば、ほかの区切りとの関係を考えずに済みます(1 つのリクエストに置けるのは 4 つまで)。

`usage.input_tokens` は、最後の区切りより後ろのトークン数だけです。入力の合計は `cache_read_input_tokens`・`cache_creation_input_tokens`・`input_tokens` の和になります。読み込みも書き込みも 0 なら、キャッシュされていません。前半がモデルの最低の長さに届かないと、エラーにならずにこうなります。
