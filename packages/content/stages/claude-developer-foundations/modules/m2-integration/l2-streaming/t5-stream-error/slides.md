# イベントで失敗を見つける
ストリームの途中のエラーは error イベントで届くので、イベントの種類で分けます。
<!-- ノート: 受信したデータの type が error なら、その中の error.type で原因を分けます。 -->

# 混雑と接続切断を分ける
| 受け取ったもの | 記録すること |
| --- | --- |
| `error` の中の `overloaded_error` | API が混み合った |
| `message_stop` より前に接続が切れた | 応答を受信し切れなかった |
<!-- ノート: 接続が切れたときは error イベントが届きません。どちらの場合も途中の表示に中断の印を付けます。 -->

# SDK で受け取るとき
SDK はストリームの読み取りをエラーにして止めます。アプリは読み取り時のエラーを扱います。
<!-- ノート: ストリームが始まったあとのエラーは、SDK が自動では送り直しません。 -->
