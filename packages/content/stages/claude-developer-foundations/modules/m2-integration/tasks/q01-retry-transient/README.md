# 送り直せるエラーだけを送り直す

API を呼ぶ処理に、送り直しの層を足します。`src/retry.js` の `withRetry(send, options)` を書き直してください。

公式の SDK は、一時的なエラーを既定で 2 回まで自動で送り直します。実務では、まず SDK の `maxRetries` の設定で足りるかを考えます。この課題は、送り直しの考え方を確かめるために、その層を自分で書いてみるものです。

## 作るもの

`withRetry(send, options)` は、リクエストを送る関数 `send` を呼び、成功したらその応答を返します。`send` が投げるエラーは `status`(HTTP ステータス)と `headers`(名前を小文字にしたキーのオブジェクト)を持ちます。

- `status` が 429・500・529 のエラーだけを送り直します。ほかのエラーは、待たずにそのまま投げます。
- 送り直しは `options.maxRetries` 回までです。上限まで送り直しても通らなければ、最後のエラーを投げます。`maxRetries` が 0 なら送り直しません。
- 送り直す前に `options.sleep(ミリ秒)` で待ちます。待つ時間は次のとおりです。
  - エラーの `headers["retry-after"]`(秒)があれば、その秒数
  - なければ、1 回目は `baseDelayMs`、2 回目は 2 倍、3 回目は 4 倍のように、送り直すたびに倍
- 待つときは必ず `options.sleep` を使います(テストが待った時間を記録します)。

```js
// 529 → 529 → 成功 のとき、maxRetries: 3, baseDelayMs: 100 なら
// 100 ミリ秒・200 ミリ秒待って 3 回目で成功し、その応答を返す
await withRetry(() => client.messages.create(request), { maxRetries: 3, baseDelayMs: 100, sleep });
```

## 説明欄に書くこと

提出の説明欄に、送り直すエラーと送り直さないエラーをどう分けたか、回数の上限と待ち時間をどこで決めたかを、自分のコードの箇所に即して書きます。

## 確かめ方

VS Code の「STELLA: 課題を確認する」で、テスト(`tests/`)・ESLint・Prettier を実行します。API キーは要りません(テストは偽の送信の関数を渡します)。テストと設定のファイルは書き換えません。
