# 解説

最初の `content_block_stop` で戻っていたため、記録の 3 番以降を読まず、停止理由も画面に反映できませんでした。解答例は、テキストの差分と最後に届いた停止理由をそれぞれ控えて、`message_stop` で状態を決めます。エラーが届けばその時点の表示用の本文を返します。どちらのイベントも届かずにループを抜けたときは中断です。

停止理由を状態に変えるところは、`Map` の代わりに `switch` でも書けます。区分ごとに `case` を並べると同じ状態になる理由をまとめて読めます。対応表にすると、受信で追いかける値と画面に渡す状態の対応をコード上の一か所で確認できます。
