# 許可は順に判定される
8-7-2
<!-- ノート: 一つの呼び出しに、フックの許可と共有設定の拒否が重なる場面です。 -->
---
# フックは許可を返した
フックは帳票の編集を許可しました。チームの拒否ルールは、監査用の帳票の編集を止めます。
<!-- ノート: 一つの呼び出しに許可と拒否が重なっています。判定はどこで決まるでしょうか。 -->
---
# 判定の順をたどる
ツールの許可は、フック・拒否・確認・権限モード・許可ルール・canUseTool の順に判定します。
<!-- ノート: canUseTool は、承認が必要な呼び出しをアプリが審査する関数です。各段階で、続けるか、その場で止めるかが決まります。 -->
---
# 拒否の段階で止まる
1. フックが `allow` を返す
2. 監査用の帳票の編集が拒否ルールに一致する
3. 呼び出しが拒否される
<!-- ノート: フックの許可があっても拒否と確認のルールを調べます。拒否に一致したら、その場で止まります。 -->
---
# 最後の関数に届く条件
前の段階で自動承認された呼び出しは、`canUseTool` を通りません。
<!-- ノート: すべての呼び出しを調べる必要があるなら、自動承認の前に動く PreToolUse に検査を置きます。 -->
---
