# フックが失敗したとき
8-7-3
<!-- ノート: 操作の許可を調べるフック自体が失敗した場面を考えます。 -->
---
# 確認の途中で例外が出た
帳票を編集する前に、フックが承認記録を読みます。記録を読めず、フックが例外を投げました。
<!-- ノート: 明示的な拒否はまだ返っていません。確認できないとき、編集はどうなるでしょうか。 -->
---
# 失敗したときの動きを決める
フックが失敗しても操作を止めるには、失敗時に遮断する設定を付けます。
<!-- ノート: 既定では、フックの例外だけでは操作を止めません。確認できたときだけ編集したいなら、例外で止まるように設定します。 -->
---
# matcher に遮断を指定する
```ts
query({ prompt: "承認された帳票を更新してください", options: { hooks: {
  PreToolUse: [{ matcher: "Edit", hooks: [checkApproval], onFailure: "block" }],
} } });
```
<!-- ノート: これは options.hooks に渡す設定の抜粋です。checkApproval が例外を投げると、その編集は止まります。 -->
---
# 例外を起こして確かめる
テストでは承認記録を読めない状態を作り、編集前後の帳票が同じかを確かめます。
<!-- ノート: 例外が記録されたことに加えて、ツールが実行されなかったことを確かめます。 -->
---
