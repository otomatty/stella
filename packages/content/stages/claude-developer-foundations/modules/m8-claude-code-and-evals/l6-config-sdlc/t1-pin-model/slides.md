---
# 設定は同じなのに
CI のモデル指定は先週と同じ `opus` です。プロンプトを変えて試したところ、モデルの版も先週から変わっていました。
<!-- ノート: 同時に二つの条件が変わると、何が結果に影響したのかを切り分けにくくなります。 -->
---
# 比較する実行で版をそろえる
再現性が要る実行では、別名ではなく完全なモデル ID で固定します。
<!-- ノート: opus のような短い別名が指す先は変わることがあります。評価で使ったモデル ID を指定すると、比較するモデルの版をそろえられます。 -->
---
# 起動時にモデル ID を渡す
```sh
claude -p "在庫レポートの項目を確認してください" --model claude-opus-5-5
```
<!-- ノート: この例は Anthropic の API を使う場合です。日付が付いていない ID でも、この ID は決まった版を指します。 -->
---
# 実行時に選ばれたモデルを控える
会話中の `/model`、起動時の `--model`、環境変数 `ANTHROPIC_MODEL`、設定の `model` の順で優先されます。
<!-- ノート: 設定ファイルを書き換えても、実行時に強い指定があればそちらが選ばれます。比べるときは実際に使った ID を控えます。 -->
---
