# 採点器の見逃しを調べる

返品規定についての回答を、人と LLM が別々に採点しました。どちらも「5件中4件合格」でしたが、返品期限を作り話で補った回答を LLM だけが通しています。この採点器をリリース判定に使えるか、同じ回答どうしで確かめます。

## 入力と戻り値

`src/judge.js` の `calibrateJudge(labels, judgments)` を実装してください。API キーは使いません。どちらの引数も `{ id, pass }` の配列です。テストは空でない文字列の ID と真偽値の判定を渡します。`labels` は人が確定した判定、`judgments` は採点器の記録で、並び順はそれぞれ異なります。

1. ID で照合します。どちらかで ID が重複する、ID の集合が異なる、人の合格または不合格の例が一つもない場合（空配列を含む）は `Error` を投げます。
2. `agreement` は一致件数を全件数で割った値です。`falsePassIds` に「人は不合格・採点器は合格」、`falseFailIds` にその逆を入れます。両方とも人の記録順で返します。
3. このチームの受入条件は「一致率80%以上、かつ誤合格0件」です。両方を満たすときだけ `ready: true` を返します。

| ID | 人 | 採点器 |
| --- | --- | --- |
| R1 | 合格 | 合格 |
| R2 | 合格 | 不合格 |
| R3 | 合格 | 合格 |
| R4 | 不合格 | 合格 |
| R5 | 合格 | 合格 |

この5件の戻り値は `{ agreement: 0.6, falsePassIds: ["R4"], falseFailIds: ["R2"], ready: false }` です。

## 確認と提出

「課題を確認する」でテストを実行します。説明欄では R4 を通すと誰が困るかを一文で書き、採点指示に追加する条件を一つ挙げます。最後に、指示の調整には使わず、あとで確かめる返品事例を一つ書いてください。
