# 解説

プロンプトやモデルを変えたら、同じ評価のセットで前と比べます。ケースが違えば合格率の上下は変更の効果を表さないので、前と後でケースの集まりが同じかを確かめてから比べます。並びは違ってもよいように、`id` で結びます。

合格率の差だけを見ると、直ったケースと悪化したケースが打ち消し合い、変化がないように見えることがあります(テストの例では、どちらも 0.75 のまま、c3 が直り c4 が悪化しています)。悪化したケースを返せば、大事なケースが落ちていないかを確かめられます。

評価は、すべてのケースを回して初めて意味があります。生成が 1 件失敗しただけで止めると、残りのケースの結果が分かりません。失敗したケースは不合格として理由を残し、回し続けます。採点は、できるだけ速く確かなコードで行います(`exactMatch`)。前後の空白のような、意味のない違いはそろえてから比べます。細かな判断が要るなら、基準をはっきり書いた LLM による採点を `grade` に渡せます。
