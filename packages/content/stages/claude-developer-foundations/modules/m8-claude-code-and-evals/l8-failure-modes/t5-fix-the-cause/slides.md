# 返答が空になるたび送り直している
配送の案内が空で返りました。上限を増やしても再現します。記録には、ツール結果の直後に空の `end_turn` がありました。
<!-- ノート: 出力の長さより先に、空になる手前でアプリが何を送ったかを確かめます。 -->
---
# 原因に合わせて対策を選ぶ
対策は、失敗の原因がある場所に合わせて選びます。
<!-- ノート: トランスクリプトは、入力・ツール呼び出し・応答を順に追える記録です。何が起きた直後に失敗したかを追います。 -->

# メッセージを組み立てる場所を直す
ツール結果のすぐあとにアプリが説明文を追加していました。ツール結果だけを返す形に直します。
<!-- ノート: 送ったメッセージを見れば、変更すべき場所が分かります。今回はツール機能を残したまま、結果の渡し方を直せます。 -->
---
# 合格の表示を実際の結果と照合する
「配送情報を保存しました」という返答があったら、データベースに対象の行が保存されたかを確かめます。
<!-- ノート: 採点が合格でも、行がなければ保存は未完了です。評価器がどの情報を読んで合格にしたかも調べます。 -->
