# 警報が鳴らないのに回答がない
問い合わせの返答が途中で切れました。監視は HTTP の 5xx だけを数えています。
<!-- ノート: 利用者からは失敗に見えても、アプリと API の通信は成功していることがあります。 -->
---
# 応答を二段階で調べる
失敗は、まず HTTP のエラーか、成功した応答の中身かで分けます。
<!-- ノート: 障害モードとは、失敗がどう現れるかを表す種類です。最初に HTTP ステータスを見て、次に成功した応答の中身を見ます。 -->
---
# 記録から調べる場所を選ぶ
| 記録 | 調べる場所 |
| --- | --- |
| HTTP 4xx・5xx | リクエストや API のエラー情報 |
| HTTP 200・`max_tokens` | 出力の上限と切れた位置 |
| HTTP 200・`refusal` | 拒否としての処理 |
<!-- ノート: HTTP 200 でも、止まった理由を一緒に記録すれば、途切れや拒否を見つけられます。 -->
---
# 終了理由を見たあとで中身を読む
`end_turn` でも、回答に資料にない情報が含まれることがあります。
