# 拒否が先に決まる
<!-- ノート: 同じ操作に、チームの拒否と個人の許可が一致する場面です。 -->
---
# 許可を足したのに動かない
チームは公開コマンドを禁止しています。担当者は、試験用の公開だけ個人の設定で許可しました。
<!-- ノート: チームの禁止より、個人が足した条件のほうが細かく書かれています。どちらが効くでしょうか。 -->
---
# 拒否が最優先
権限のルールは拒否・確認・許可の順に判定され、拒否が最優先です。
<!-- ノート: 権限のルールは、ツールの呼び出しに対する決まりです。設定をまたいで集めたルールを、拒否、確認、許可の順で照合します。 -->
---
# 試験用の公開も拒否される
| 設定 | 一致するルール |
| --- | --- |
| 共有 | 拒否 `Bash(npm run publish-*)` |
| 個人 | 許可 `Bash(npm run publish-preview)` |
<!-- ノート: npm run publish-preview は二つに一致します。拒否の条件に先に一致するので、個人の許可を足しても実行できません。 -->
---
# ツール全体を拒否する書き方
`deny` にツール名だけを書くと、そのツールを Claude の候補から外します。
<!-- ノート: コマンドを指定する拒否は、そのツールのうち条件に合う呼び出しを止めます。どちらの拒否も別の場所の許可や権限モードで上書きできません。 -->
---
<!-- _class: summary -->
# まとめ
権限のルールは拒否・確認・許可の順に判定され、拒否が最優先です。
