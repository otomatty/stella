# レッスン4-3 コンテキストを管理する

## このレッスンの目標

- [ ] コンテキストウィンドウに数えるものと、超えたときの動きを説明できます。
- [ ] コンテキストに入れる情報を、結果に効くものに絞れます。
- [ ] 長い会話を続けるために、圧縮とコンテキストの編集を使い分けられます。

## 4-3-1 枠に収める

> **入力と出力は、合わせてコンテキストウィンドウに収めます。**

コンテキストウィンドウは、Claude が応答を作るときに参照できるトークンの全体で、その回に作る出力も含みます。学習に使ったデータとは別の、作業のための記憶にあたります。会話を続けると、それまでのやり取りがすべて積み重なっていきます。

枠に数えるのは、リクエストのすべてです。

- `system` と、`messages` のすべての発言(ツールの結果・画像・文書を含む)
- ツールの定義
- その回に作る出力(考える過程を含む)

プロンプトキャッシュで読み込んだ前半も、枠に数えます。キャッシュで変わるのは料金で、枠の使い方は変わりません。

いまの多くのモデルのコンテキストウィンドウは 100 万トークンで、1 回の出力は最大 12 万 8 千トークン(`max_tokens`)です。モデルごとの大きさは、モデルの比較表で確かめます。

| 超え方 | 起きること |
| --- | --- |
| 入力だけで枠を超える | 400 の `invalid_request_error`(prompt is too long) |
| 入力と `max_tokens` の合計が枠を超える | Claude 4.5 以降のモデルでは受け付け、出力の途中で枠に届くと `stop_reason` が `model_context_window_exceeded` で止まる |

送る前にトークン数を数える API で数えると、枠を超えるかどうかを確かめられます。

## 4-3-2 効く情報だけを入れる

> **コンテキストには、結果に効く情報だけを、できるだけ少なく入れます。**

コンテキストは、Claude が応答を作るときに使うトークンの集まりです。枠が大きくても、入れるほどよいわけではありません。トークンが増えるほど、中の情報を正しく思い出す力は落ちていきます。これをコンテキストの劣化(context rot)と呼びます。人の作業記憶と同じように、注意を向けられる量には限りがあります。

Anthropic の記事は、よいコンテキストを「望む結果に最も効く、できるだけ少ないトークンの集まり」と説明しています。中身ごとの考え方は次のとおりです。

| 中身 | 考え方 |
| --- | --- |
| system | 明確で直接的な言葉で書く。細かな条件分岐を書き込みすぎず、あいまいすぎもしない。節に分けてタグや見出しで区切る |
| ツール | 役割の重ならない、少ない数にそろえる。人がどれを使うか決められないなら、Claude にも決められない |
| 例 | 例外の規則を並べ立てず、種類の違う代表的な例を選ぶ |
| 外の情報 | 全部を先に入れず、ファイルの場所・保存した検索・リンクのような目印だけを持たせ、要るときにツールで読ませる |

最後の「要るときに取りに行かせる」やり方は、先に全部を入れるより時間がかかります。Claude Code は、CLAUDE.md を最初に入れ、ほかのファイルは検索して必要な分だけ読む、両方を組み合わせた形をとっています。

## 4-3-3 長い会話を縮める

> **長い会話は、圧縮で古いやり取りを要約に置き換えて続けます。**

長い会話や長いエージェントの作業は、いずれ枠に近づきます。古いやり取りを先頭から消すと、あとで要る情報まで失うことがあります。

圧縮(compaction)は、会話の古いやり取りを、Claude がサーバー側で書いた要約に置き換える機能です。自分で要約の処理を書かずに、会話を枠の中に保てます。コンテキストを小さく保つので、会話が長くなるほど落ちる応答の質も保ちやすくなります。圧縮には 2 つの始め方があり、どちらもベータの機能です。

| 始め方 | いつ要約するか | 向く場面 |
| --- | --- | --- |
| 自分で頼む(compaction on demand) | アプリがリクエストを送ったとき | 要約の時期を自分で決めたい、最近のやり取りをそのまま残したい |
| しきい値で始める(compaction at a token threshold) | 入力のトークン数が決めた量に届いたとき、API が要約する | ふだんのリクエストのまま、API に任せたい |

公式ドキュメントは、使える環境では自分で頼むほうを勧めています。

要約せずに消してよいものは、コンテキストの編集(context editing)で、決まりに従って消せます。古いツールの結果や、前のやり取りの考える過程を消すのに使います。

圧縮のあとも、あとで要る情報が要約に残っているかを確かめます。足りないときは、要約の指示を自分で書くこともできます。
