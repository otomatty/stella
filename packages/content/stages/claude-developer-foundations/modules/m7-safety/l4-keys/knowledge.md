## 知識問題

### Q1. 倉庫のモバイルアプリから点検メモを要約します。配布するアプリから Claude のキーを読めないようにするには、どう作りますか？
<!-- kind: single; skills: claude-safety -->

- A. 画面がメモを自分のサーバーへ送り、サーバーが保管するキーで Claude を呼ぶ
- B. 検証用の短い期限のキーをアプリに入れ、配布のたびに入れ替える
- C. アプリのビルド時の環境変数にキーを入れ、画面から SDK で直接呼ぶ

<details>
<summary>解答</summary>

**A** — 配布したアプリから読める場所にキーを置くと、利用者も取得できます。サーバーで利用者の操作を受け付け、Claude を呼びます。

</details>

### Q2. 開発のまとめテストで使用量が急増しました。開発の支出やレートを制限し、本番と別々に集計するには、どう構成しますか？
<!-- kind: single; skills: claude-safety -->

- A. 同じワークスペースでキーの名前を分け、組織の上限を下げる
- B. 開発のリクエストに環境名を付け、画面で本番の表示件数だけを絞る
- C. 開発と本番のワークスペースを分け、環境ごとのキーと上限を設定する

<details>
<summary>解答</summary>

**C** — ワークスペースごとにキー・資源・集計を分け、開発に低い上限を設けられます。組織全体の上限も引き続き適用されます。

</details>

### Q3. 本番の夜間集計を担当者の個人キーで動かしています。担当者は来月に組織を離れます。キーを使い続ける構成では、何を選びますか？
<!-- kind: single; skills: claude-safety -->

- A. 担当者の個人キーの期限を延ばし、残るメンバーに共有する
- B. 集計用のサービスアカウントのキーを作り、本番のワークスペースに範囲を絞る
- C. 異動のたびに、その時点の担当者の個人キーへ置き換える

<details>
<summary>解答</summary>

**B** — 自動処理専用の身元にキーをひも付ければ、担当者が組織を抜けても、担当者の個人キーの失効で集計が止まることはありません。

</details>

### Q4. 運用担当者が、保存し忘れた本番キーを取り戻したいと相談しました。組織の Admin キーで一覧は取得できます。どう復旧しますか？
<!-- kind: single; skills: claude-safety -->

- A. 権限のある人が新しい通常のキーを発行して配り、不要になったキーは無効化する
- B. Admin API で古いキーの名前を変更し、一覧に表示される秘密の値を保存する
- C. 集計用の Admin キーを Messages API に設定して運用を再開する

<details>
<summary>解答</summary>

**A** — Admin API はキーを管理できますが、発行済みの秘密の値を取り出せません。本番の要約には、新しく発行した通常のキーを使います。

</details>

### Q5. 本番のキーを期限前に交換します。Web の要約と夜間の集計が同じキーを使います。計画的な入れ替えの順はどれですか？
<!-- kind: single; skills: claude-safety -->

- A. 古いキーを削除し、401 を返す処理の一覧を作ってから順に新しいキーを配る
- B. Web にだけ新しいキーを配り、Web で成功した時点で古いキーを無効化する
- C. 両方に新しいキーを配り、キー別の使用量と各処理の成功を確かめて古いキーを無効化する

<details>
<summary>解答</summary>

**C** — Web が成功しても、夜間の処理が切り替わったかは分かりません。両方を確かめてから古いキーを止めます。

</details>

### Q6. 本番ワークスペースの使用量が昼間に増えました。予定している集計は夜間だけです。調査の最初に何を確かめますか？
<!-- kind: single; skills: claude-safety -->

- A. 組織全体の費用だけを先月と比べ、上限を下げて様子を見る
- B. キーの ID ごとの使用量と、各キーの持ち主・範囲を確認し、予定された処理と照らす
- C. 期限まで日があるキーを調査から外し、期限が近いキーの本数だけを確かめる

<details>
<summary>解答</summary>

**B** — 使用が増えた時間帯とキーを特定すると、予定された処理で説明できるか確認できます。漏れが疑われるキーはすぐに無効化します。

</details>
