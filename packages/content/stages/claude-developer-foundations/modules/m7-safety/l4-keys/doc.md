# レッスン7-4 API キーを守って運用する

## このレッスンの目標

- [ ] 画面・サーバー・Claude API の間で、キーを扱う場所を決められます。
- [ ] 環境と処理の役割に合うワークスペースとキーを選べます。
- [ ] キーの期限と使用量を確認し、サービスを止めずに入れ替える手順を説明できます。

## 7-4-1 キーはサーバーに置く

> **API キーは画面のコードに入れず、自分のサーバーから Claude を呼びます。**

点検メモを要約するアプリでは、画面が自分のサーバーにメモを送ります。サーバーは利用者が操作できるかと入力の内容を確かめ、Claude に要約を頼みます。利用者の画面に返すのは要約です。

| 場所 | 扱うもの |
| --- | --- |
| Web やモバイルの画面 | メモと要約 |
| 自分のサーバー | 操作の許可、Claude へのリクエスト、API キー |
| 秘密を管理する仕組み | 作成時に一度だけ表示される `sk-ant-` で始まるキーの値 |

1-2-2 の環境変数はサーバーの実行環境に渡します。画面の配布物に埋め込まれる変数に入れると、利用者が受け取るファイルからキーを読めます。ブラウザーからの直接呼び出しを許す SDK の `dangerouslyAllowBrowser` は、この問題を解決する設定ではありません。公開する前に、Web とモバイルの配布物にキーが含まれていないことを確かめます。

エージェントを動かす場合も、7-2-3 のように、外側のプロキシでキーを付けます。

## 7-4-2 環境ごとに分ける

> **開発と本番はワークスペースを分け、キーも使用量も別にします。**

ワークスペースは、組織の中でキーや資源をまとめる単位です。開発・検証・本番それぞれに用意し、対応するキーをサーバーに配ります。検証で大量に要約した日に、どの環境で費用が増えたかを分けて追えます。

Files API のファイル、バッチ、プロンプトキャッシュはワークスペースごとに分かれます。たとえば検証でアップロードしたファイルは、そのファイル ID のまま本番からは使えません。検証の月間支出やレートの上限を抑える場合も、組織全体の上限は適用されます。ワークスペースの設定で、実際に使える上限を組織の上限より高くすることはできません。

| API キーの種類 | 誰として使うか | 向く用途 |
| --- | --- | --- |
| 個人のキー | ひも付いた本人。本人が組織を離れると止まる | 個人だけが使う道具 |
| サービスアカウントのキー | 自動処理のために作った身元 | CI や本番のサービス |
| ワークスペースのキー | 個人やサービスアカウントにひも付かない | 以前から動いている連携 |

新しい連携では、個人やサービスアカウントにひも付くキーを選べます。実行環境に信頼できる認証の仕組みがあれば、ワークロード ID 連携で短時間だけ有効なトークンを使う方法もあります。

## 7-4-3 管理用のキーは別物

> **Admin キーは組織の管理のためのキーで、Claude の呼び出しには使いません。**

組織管理者だけが `sk-ant-admin01-` で始まる Admin キーを発行できます。Admin API は、メンバー・招待・ワークスペース・API キーなどを組織として管理する API です。組織の使用量と費用のレポートを取得する集計用の API にも Admin キーを使えます。

| やりたいこと | 使うもの |
| --- | --- |
| 点検メモを要約する | サービス用の API キーで Messages API を呼ぶ |
| キーの一覧を調べる、名前を変える、無効化する | 管理用の処理で Admin API を呼ぶ |
| 失くしたキーを置き換える | 権限のある人が管理画面から新しいキーを発行する |

通常の API キーを新規発行する機能や、発行済みのキーの秘密の値を取り出す機能は Admin API にはありません。要約を処理するサーバーには、要約に使うキーだけを渡します。

## 7-4-4 入れ替えて見張る

> **キーには期限を付けて定期的に入れ替え、使用量をキーごとに見張ります。**

キーを作るときに有効期限を決めます。期限を過ぎたキーでの呼び出しは `401 authentication_error` で失敗します。同じキーで送り直しても復旧しないので、一覧で期限や状態を確かめます。

計画的な入れ替えでは、次の順で切り替えます。

1. 新しいキーを作り、対象の環境に配ります。
2. 画面から受け付ける処理と、夜間などの定期処理を切り替えます。動作とキー別の使用量を見て、新しいキーに移ったことを確かめます。
3. 古いキーを無効化します。期限前の無効化は戻せます。削除すると戻せません。

監視では、キーの一覧で期限・持ち主・範囲・状態を見ます。Claude Console の組織では、集計をワークスペースやキーの ID で分け、使用量と費用を時系列で確かめられます。夜間の処理に使うキーが昼に急に使われ始めたら、予定した処理の記録と照らします。漏れが疑われるキーはすぐに無効化します。

期限を付けたキーも秘密を管理する仕組みに置きます。実行環境の接続元が決まっていれば、許可する IP アドレスを絞って利用できる場所を制限できます。
