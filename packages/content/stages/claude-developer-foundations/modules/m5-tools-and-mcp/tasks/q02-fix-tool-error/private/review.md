# レビューの観点

- ツールの例外を `try`・`catch` で受け、`is_error: true` の `tool_result` にしているか
- 結果の文に、例外の内容(`message` か投げられた値)を入れているか
- 定義していないツールを、実行せずに名前を含む `is_error` の結果にしているか
- 1 つの失敗で残りの呼び出しを止めず、結果を元の順に返しているか
- 成功したときの結果の形(`is_error` を付けない)を変えていないか
- 差分が失敗の扱いに収まっているか。関係のない書き換えをしていないか
- 修正記録の原因が、ログの 2 つのエラー(例外のまま投げていること)と対応しているか。再発の確認が、失敗と成功の両方を確かめているか

よくある違反: 例外を握りつぶして結果を返さない(`tool_use` に結果のないリクエストになる)、失敗したら `for` を `break` してほかの結果を捨てる、`catch` で `"failed"` とだけ返して理由を書かない、成功した結果にも `is_error: false` を足して形を変える、修正記録の原因が「エラーが出たから」で終わっている。
