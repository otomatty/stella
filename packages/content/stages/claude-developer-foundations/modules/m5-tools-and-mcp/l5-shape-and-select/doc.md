# レッスン5-5 結果の返し方と、機能の出し方

## このレッスンの目標

- [ ] Claude が次の判断に使う項目を選び、入力違いと一時的な失敗に合う文を返せます。
- [ ] 取り消せない操作を、人が承認するまでアプリで止められます。
- [ ] 実行場所、保守、見つけ方、コンテキストの使い方で、機能の提供手段を選べます。

## 5-5-1 結果を絞って返す

> **ツールの結果は、次の判断に要る項目だけに絞って返します。**

5-2-4 でツールを仕事の単位にまとめました。今度は、その仕事の結果から何を次の判断に渡すかを決めます。図書館の検索で「今日どこで受け取れるか」を伝えるなら、書名・受取館・貸出可能数を残します。予約に識別子が要るなら、次のツールに渡せる資料番号も残します。更新履歴や館の内部 ID を結果に含める必要はありません。

| 検索の使い方 | 結果に持たせるもの |
| --- | --- |
| 受け取れる候補を数件案内する | 既定で 10 件まで。さらに絞れるよう、受取館や著者を入力で指定できるようにする |
| 条件に合う候補を順に確認する | ページ分割で次のまとまりを取り出せるようにする |
| 選んだ本を詳しく調べる | `response_format` の既定を `concise` にし、`detailed` を指定したときだけ版や刊行年を加える |

検索を上限で打ち切ったら、その旨と絞り方を結果に添えます。「先頭の 10 件を返しました。中央館の候補だけ見るなら受取館を指定してください」とあれば、Claude は結果の続きがあると分かります。ツール結果は検索データとその説明を渡す場所です。アプリ全体の動作を決める指示は `system` に置きます。

## 5-5-2 次の一手が分かるエラー

> **ツールのエラーには、何が違い、どう直せばよいかを書きます。**

宅配の状況を検索するツールに、追跡番号の代わりに受取人の名前が入りました。検索を始める前に形式の検査で止まった場合、結果の「検索失敗」だけを読んだ Claude は、荷物がなかったと解釈するかもしれません。5-1-3 のとおり `is_error: true` を付けたうえで、結果の文を変えます。

```js
{
  type: "tool_result", tool_use_id: block.id, is_error: true,
  content: "追跡番号は P と数字 6 桁です。受取人名が入力されました。利用者に追跡番号を尋ねてください。",
}
```

| 失敗したところ | 結果に入れる情報 |
| --- | --- |
| 検索前の形式検査 | どの項目が違ったか、期待する形式、足りない値を誰に尋ねるか |
| 検索したが有効な形式の番号に該当がない | 検索した番号と、利用者に番号の確認を頼むこと |
| 回数の上限 | いつ再試行できるか。たとえば「回数の上限です。60 秒後にもう一度試してください」 |

5-2-1 で扱った説明にも、追跡番号の意味・形式・`P482631` のような例・番号がなければ尋ねることを足すと、呼び出す前の取り違えを減らせます。実行時にも形式を確かめ、失敗した呼び出しから立て直せるようにします。

## 5-5-3 実行前に承認を取る

> **取り消せない操作のツールは、実行の前にアプリが人の承認を取ります。**

予約を取り消す場合、Claude が `tool_use` を返した段階では、アプリはまだ予約を変更していません。そこで予約番号・日時・取り消し料を画面に表示し、対象と操作を人が承認した場合にだけ取り消しを実行します。

```js
const approved = await confirmCancellation(reservation);
const result = approved
  ? await cancelReservation(reservation.id)
  : "承認されなかったため、取り消しは実行されませんでした。";
```

アプリは、実行した結果か承認されなかった旨を、元の呼び出しに対応する `tool_result` で返します。Claude への指示は確認を促せますが、確実に実行を止める条件はアプリの分岐に置きます。送金や外部への送信でも、承認する人に対象と操作を見せてから実行します。

| 動かす場所 | 実行を待たせる方法 |
| --- | --- |
| Messages API と自作ツール | 5-1 のループをアプリで回し、関数を呼ぶ直前に承認を挟みます |
| Agent SDK | 確認のルールや `canUseTool` で人の判断を受け付けます。自動許可が先に当たると `canUseTool` に届かないため、対象ツールのルールも確かめます |
| Managed Agents | 対象のツールに `always_ask` を設定し、承認が届くまで実行を待たせます |

MCP のツールでも、人が呼び出しを拒否できるようにすることが推奨されています。読み取り専用などの注釈は、信頼できる MCP サーバーのものだけを判断に使います。

## 5-5-4 知識は Skill、接続は MCP

> **手順や知識を足すなら Skill、外のシステムにつなぐなら MCP を選びます。**

学校の事務室で毎週、貸出状況を報告します。集計の順番と書式は Skill として共有し、週ごとに変わる貸出件数は MCP のツールで台帳から取得します。手順と外部システムへの接続は、同じ仕事で組み合わせられます。

Skill は、`SKILL.md` と必要に応じた補助ファイルをまとめたフォルダーです。`SKILL.md` の冒頭に、貸出報告をまとめる場面を `description` に書き、本文に集計の順番を書きます。書式の見本は補助ファイルに置けます。台帳への認証情報は、接続を担当するアプリや MCP サーバーの設定に置きます。

Claude Code で共有した自作 Skill を API や別のアプリでも使う場合は、それぞれの利用先に配置します。手順を変えたときも、共有先ごとに更新を届けます。

## 5-5-5 置き場所と持ち主で選ぶ

> **機能の出し方は、どこで動かし、誰が直し、Claude がどう見つけるかで選びます。**

施設案内のアプリでは、公開サイトの検索をサーバーツールに任せ、施設台帳の検索は複数のアプリから MCP で共有できます。このアプリにだけある案内先の絞り込みなら自分でツールを定義し、どの施設でも使う案内文の書式は Skill に置けます。

| 手段 | どこで動くか | 誰が直すか | Claude がどう見つけて使うか | 文脈をどれだけ使うか |
| --- | --- | --- | --- | --- |
| サーバーツール | Anthropic 側 | Anthropic | `tools` に指定すると、Claude が必要なときに使います | 定義としては種類や名前などの指定だけを渡します |
| 自分で定義するツール | 自分のアプリ | アプリの担当者 | 渡した説明から選び、呼び出しを求めます | 通常は全定義が入ります。ツール検索で後から読み込めます |
| MCP サーバー | 手元の stdio または離れた HTTP のサーバープロセス | サーバーの担当者。複数のアプリから再利用できます | クライアントが一覧を取得し、Claude が必要なツールを選びます | ツールのスキーマが入ります。対応するクライアントでは後から読み込めます |
| Skill | ファイルシステムやコード実行のコンテナー | Skill の作者 | 依頼と説明が合えば選びます。利用先によっては名前で呼べます | 説明を先に読み、本文と補助ファイルは必要になった段階で読みます |

Skill の名前と説明は起動時に読み込まれ、目安は 1 つあたり 100 トークンほどです。本文はその Skill を使うとき、補助ファイルやスクリプトは必要なときだけ読み込まれます。

ツールの定義には説明と入力のスキーマが入ります。使えるツールが 10 個以上に増え、一度に使うのはその一部であれば、ツール検索を検討します。先に全定義を渡す方法に比べ、Claude が必要な定義を探してから読み込む分、使わないツールの説明で文脈を消費せずに済みます。
