# 運用の担当を決める
公開サイトの検索と、社内の施設台帳の検索が必要です。公開サイトの検索も自分たちで実装し、保守する必要があるでしょうか？
<!-- ノート: 必要な機能が同じでも、実行と保守を誰が受け持つかで選択は変わります。 -->
---
# 動かす場所から考える
機能の出し方は、どこで動かし、誰が直し、Claude がどう見つけるかで選びます。
<!-- ノート: 公開サイトの標準的な検索にはサーバーツールが使えます。施設台帳については、使うアプリの数や保守の担当も見ます。 -->
---
# 施設案内で役割を配る
- 公開サイトを検索する → サーバーツール
- このアプリ内の関数を呼ぶ → 自分で定義したツール
- 複数のアプリが施設台帳を読む → MCP サーバー
- 案内文の書式を揃える → Skill
<!-- ノート: サーバーツールは Anthropic が、アプリ内のツールはアプリの担当者が直します。共有する台帳の接続は MCP サーバーの担当者が保守します。案内の手順は Skill の作者が更新します。 -->
---
# 説明を読む量も確かめる
ツールが増えたら、ツール検索で必要な定義を後から読み込めます。Skill は見つけるための説明を先に読み、使うときに本文を読みます。
