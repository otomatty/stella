# 変更を記録して説明する

## 何を作るか

`index.html` の `h1` を「1回目の記録」から「2回目の記録」へ変えます。
変更を保存し、Git にコミットします。
この課題のフォルダーの変更を、2 回以上に分けてコミットします。
開始時点の記録と、見出しを変えたあとの記録を残します。

提出の説明には、`git diff` で見えた変更を自分の言葉で書きます。
次の3点を含めます。

1. 変えたファイル名。
2. 変えた場所と、変更前後の見出しの文字。
3. その変更をした理由。

## 手順

1. q01「学習フォルダーの記録を始める」を終えてから、この課題を開きます。
2. エクスプローラーで `q02-commit-change` を右クリックします。
3. 「統合ターミナルで開く」を選び、場所を確かめます。

```sh
pwd
```

末尾が `dev-env-basics/u06-git/q02-commit-change` か照合します。
この課題の中で `git init` はしません。
すでに学習フォルダーのリポジトリの内側にいます。

4. 配られたままの状態を見ます。

```sh
git status
```

5. まだ記録に入っていなければ、課題フォルダーで選びます。

```sh
git add .
```

6. 配られたままの内容を記録します。

```sh
git commit -m "変更の練習の開始点を残す"
```

この課題の開始時点がすでに記録されていて、記録するものが無ければ次へ進みます。

7. エディターで `h1` の文字だけを、指定の見出しに変えて保存します。
8. add の前に、差分を見ます。

```sh
git diff
```

ファイル名と、`-` の行の変更前、`+` の行の変更後を読みます。
提出に書くため、見えた変更を短くメモします。

9. 課題フォルダーで、変更を選びます。

```sh
git add .
```

10. 選んだ状態を見ます。

```sh
git status
```

11. 何を変えたかを1行で書き、記録します。
下のかっこの部分を、自分の説明に置き換えて実行します。

```sh
git commit -m "（何を変えたかの説明）"
```

12. 記録の一覧を読み、自分の説明が先頭に残ったかを確認します。

```sh
git log --oneline
```

13. 「課題を確認する」を押します。
14. 通ったら「提出する」へ進み、説明の欄に上の3点を書いて提出します。

## うまくいかないとき

差分が空なら、保存したか、すでに add したかを確かめます。
add 後の差分は、次で読めます。

```sh
git diff --cached
```

表示から戻れないときは `q` キーを押します。
ファイルの検査は通るのにコミット済みの検査が通らない場合があります。
`git status` で、保存後の内容を add・commit したかを見直します。
通らないままなら、操作とメッセージを添えて講師に相談します。

参照: [git-diff](https://git-scm.com/docs/git-diff)、[git-log](https://git-scm.com/docs/git-log)、[git-commit](https://git-scm.com/docs/git-commit)
