# レッスン8-1 ここまでの操作を振り返る

## このレッスンの目標

- [ ] 新しい仕様に、これまでの操作を組み合わせられます。
- [ ] 確認Aで参照できるものと、支援の記録を説明できます。

## 8-1-1 課題の流れを使う

> **新しい課題も、開く・保存・確認・記録・提出の同じ流れで進めます。**

仕様は、作るものが満たす条件です。
新しい課題では、ファイルの場所・表示する文字・提出条件を先に読みます。
たとえば「学習予定」の課題でも、保存と表示の操作は同じです。

| 流れ | 見るもの |
| --- | --- |
| 開く | Web の「VS Code で開く」と、課題文のパネル |
| 作って保存する | 編集するファイルの場所と「ファイル > 保存」 |
| 表示・確認する | ブラウザーの表示と「課題を確認する」の各項目 |
| 記録する | Git の指定がある課題では、差分とコミット |
| 提出する | 指定したファイルと説明、提出後のレビューの結果 |

細かな手順がなくても、条件ごとに使う操作を選びます。
画面を確認したことと、手元の検査に通ったことは別です。
サーバーの起動・停止や相談の経緯は、提出の説明でも伝えます。

## 8-1-2 確認Aに取り組む

> **確認Aは、初めて見る仕様を、資料を見ながら自分で仕上げる課題です。**

確認Aは、練習と違う題材で同じ力を使えるか確かめる課題です。
教材・公式資料・VS Code のメニューを参照して構いません。
ヒントはありません。取り組み中に解答例も表示されません。
他の人に作ってもらう代わりに、自分で操作を選びます。

困ったら「講師に相談」で、できたところと試したことを伝えます。
相談した提出は、人が確認します。
講師が代わりに操作した場合は、自力の記録と分けて扱います。
支援を受けたことを隠す必要はありません。
端末の設定や権限の問題は、操作の力の不合格とは分けます。

## うまくいかないとき

### どの操作から始めるか決められない

課題文のファイル名と保存先を、紙やメモに書き出します。
U03 のまとめで作成・保存・再開、U04 でリンクを確かめます。
資料を読んだあと、自分の仕様に合わせて操作します。

### 確認は通ったが、説明を書く内容が分からない

どのフォルダーで何を作ったかを、実際のファイルに合わせて書きます。
困ったことがあれば、現象と試したことを添えます。
問題がなかった場合は、そのことと確認した内容を書きます。
