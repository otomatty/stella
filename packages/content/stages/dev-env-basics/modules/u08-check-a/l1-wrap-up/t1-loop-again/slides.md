# 8-1-1 課題の流れを使う

<!-- ノート: 新しい題材でも、これまで使った保存や確認の操作を組み合わせられます。 -->

---

# なぜ必要でしょうか

「学習予定」のように題材が変わると、操作も違うように感じます。
提出までに何を確かめるかを、これまでの操作から選びます。

<!-- ノート: 課題名の違いに戸惑ったら、まず作るものの条件を読んでください。必要な操作を条件に対応させます。 -->

---

# 覚えること

新しい課題も、開く・保存・確認・記録・提出の同じ流れで進めます。

仕様は、作るものの条件です。
作業の流れは同じでも、作るファイルや文字は仕様に合わせます。

<!-- ノート: すべての課題が Git の記録を求めるわけではありません。課題文に書かれた提出条件を基準にします。 -->

---

# 画面で確かめます

| 順 | 学習予定の課題で行うこと |
| --- | --- |
| 開く・保存 | 課題を開き、作った HTML を保存する |
| 確認 | ブラウザーと「課題を確認する」で確かめる |
| 記録・提出 | Git 指定があれば記録し、提出して結果を読む |

<!-- ノート: 画面を見た確認と、手元の項目の確認は両方行います。提出後のレビューを読むところまでが一周です。 -->

---
