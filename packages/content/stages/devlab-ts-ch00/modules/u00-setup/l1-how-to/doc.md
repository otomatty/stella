# レッスン0-1 進め方とルール

## このレッスンの目標

- [ ] 問題のファイルを見分けられる
- [ ] 確認してから提出する順番を説明できる
- [ ] AI とテスト・設定ファイルのルールを守れる

## 0-1-1 進め方とルール

> **一問ずつ自分で書き、確認が通ったら提出して次へ進みます。**

### 一問につき一つのファイル

ドリルは `src/q01-01-add-tax.ts` のように、一問一ファイルです。
`src/` は問題のファイルを入れるフォルダーです。
`q01` が番号、次の `01` が問の番号、`add-tax` が名前です。
末尾の `.ts` は TypeScript のファイルを表します。
練習や応用、クラス・型をまとめる問題は、問の番号がない名前もあります。

問題の指示を読み、編集する場所だけを書きます。
動画の「ここに書く」は、その場所を表す印です。
関数の形や型などの文法は、このあと学びます。
コメントは、コードの中に書く説明の文です。`//` の後ろに書けます。
次は問題のファイルを見分ける例です。

```ts
// q01 の問1 を開く例。ここではコードの答えは書きません
// src/q01-01-add-tax.ts
// 結果: 番号と問の番号を、ファイル名で見分けられます
```

### 一問ずつ確認し、提出する

1. 一問のコードを書き、保存します。
2. VS Code の「STELLA: 課題を確認する」を実行します。
3. 通らなければ、結果を読んで直し、もう一度確認します。
4. 通ったら、課題のパネルから提出します。
5. 提出してから、次の問題へ進みます。

テストは、期待した結果になるかを調べるものです。
確認と提出は CLI の `stella check` と `stella submit` でもできます。
問題を全部提出すると、この課題は合格になります。
確認と提出は、手元のテストが通ったという申告です。
サーバーではコードを実行しません。

よくある間違いは、確認が通っただけで次の問題へ進むことです。
通ったあとには、提出も行ってください。

### 生成 AI とファイルのルール

- 生成 AI にコードを書かせません。分からないところの説明を聞くのはよいです。
- 始める前に、AI による自動補完を切ります。
- VS Code の設定で `chat.disableAIFeatures` を検索し、チェックを入れます。
- Copilot などの拡張機能は無効にします。
- `tests/` と設定ファイルを書き換えません。書き換えると提出できません。
- 設定ファイルには `package.json`、`tsconfig.json`、`eslint.config.js` などがあります。
- テストが通ったら、なぜそう書くのかを自分の言葉で説明できるか確かめます。
- 「説明すること」は、そのすぐ下に `//` のコメントで書きます。

よくある間違いは、結果を合わせるためにテストの期待値を変えることです。
テストはそのままにし、問題のコードを直してください。
設定や拡張機能を操作するルールは、Windows と macOS で共通です。

### 最初の練習で確かめること

`src/q01-hello.ts` を開きます。練習は選考の判定には含めません。
書き換える前に確認して、テストが失敗することを確かめます。
Expected は期待した値、Received は実際の値です。
`hello()` が `"Hello, TypeScript"` を返すよう、自分で直します。
もう一度確認し、すべての手順が通ったら提出します。
レビューの結果が届くことも確かめます。
