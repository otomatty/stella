# 15-1-3 変更後も全ケースを確かめる
<!-- ノート: 仕様Aに合格したら、変更の課題に取り組みます。新しい条件を満たすかに加え、前の動作が残っているかも確かめます。 -->
---
# 上限は直せたけれど
予約できる人数を3人から4人へ増やしました。
4人だけを試せば、0人を受け付ける誤りにも気づけるでしょうか。
<!-- ノート: 上限の変更が正しくても、編集のときに下限の条件を消してしまうことがあります。 -->
---
# 前のケースも全部実行する
仕様を変更した後は、変更点のケースに加えて、前の全ケースを実行し直します。
<!-- ノート: 期待値を変えるのは、変更文で結果が変わるケースだけです。実装に合わせて表の値を変えないでください。 -->
---
# 上限を4人に変える
```csharp
bool valid = seats >= 1 && seats <= 4;
```
下限は1人のままです。
<!-- ノート: 新しい上限の4人と、その1つ先の5人を試します。前に試した0人や1人、3人も残します。 -->
---
# 変わらない結果も比べる
| 入力・モード | 変更前 | 変更後 |
| --- | --- | --- |
| 4・Preview | 失敗 | 成功、ログなし |
| 4・Register | 失敗 | 成功、ログあり |
| 0・Register | 失敗 | 同じ |
| 3・Register | 成功、ログあり | 同じ |

戻り値だけでなく、ログも比べます。
<!-- ノート: ここでは表示を短くまとめています。実際の表には期待ログと期待戻り値を分けて、正確な文言と順番を書きます。 -->
