# レッスン0-1 このステージの進め方

## このレッスンの目標

- [ ] VS Code で課題を開き、1 問を 1 ファイルに書けます。
- [ ] 1 問確認して提出し、次の問題へ進めます。
- [ ] .NET SDK の 10 系があることを確かめられます。

## 0-1-1 課題を VS Code で開く

> **課題は VS Code で開き、1 問を 1 ファイルに書きます。**

単元の課題一覧から「VS Code で開く」を押します。課題は学習フォルダーの `csharp-foundations/` 以下に用意されます。編集するのは、問題ごとの `src/<id>.cs` です。1 問が 1 ファイルです。クラスは `public static partial class Answers` で、その問題のメソッドを 1 つ書きます。プログラムの入口と、メソッドを呼び出す行は書きません。テストがメソッドを呼びます。

テストはあなたのコードと同じプロジェクトで動くので、ファイルの直下に呼び出しを書いて `dotnet run` する形は使えません。課題文の一覧に、ファイル名とメソッドを書いてあります。

課題は次の順です。

1. 基礎。for で順番に出す、for で集計する、最大と最小。★ の問題を最初に確認し、残りも解きます。
2. 接続。出した値と合計をつなぎます。
3. 自力。問題文から処理を自分で選びます。文法と API は調べてよいです。
4. 修正。誤りのあるコードを、原因を見て直します。
5. 確認 A。未見の問題です。合格したら次へ進みます。確認 B は、A のあと時間を空けた別問題です。

1 問は次の順で解きます。

1. 入力と、求める答えを確認する。
2. 入力例を手で計算し、処理の手順を書く。
3. メソッドを書いて、その問題を確認する。通ったら提出する。
4. 次の問題へ進む。例とは違う入力も、境界や、条件を満たさない場合として見る。

例の読み方です。`→` の左が入力、右が結果です。`/` は改行です。

## 0-1-2 確認してから提出する

> **1 問ずつ確認して提出し、全部提出すると課題が合格になります。**

開いている問題を確認します。拡張が `dotnet test` まで行います。通ってから、その問題を提出します。提出したら、次の問題へ進みます。全部の問題を提出すると、課題が合格になります。合否はテストで決まります。説明欄と修正記録の提出はありません。サーバーはコードを実行せず、手元のテストが通ったという申告を受け取ります。

提出は、VS Code の拡張か、CLI の `stella submit` で行います。CLI には Node.js が要ります。

確認 A と確認 B では、公式ドキュメントと文法の参照はしてよいです。解法と完成コードは見ずに書きます。

修正の課題では、誤りのあるコードが最初から入っています。原因を見て、そのメソッドを直します。ヒントを開いたことと、解答例を開いたことは、STELLA が記録します。支援した問題は練習です。自力でできるかは、別の問題で見ます。

速さや、講師と同じ書き方は、合格の条件にしません。指定の例と、課題のテストに入っている追加のケースに一致すれば合格です。

このステージの前の `dev-env-basics` では、ターミナルと .NET SDK は扱いません。ここでは、その 2 つを入れます。

ターミナルは、VS Code のメニュー「ターミナル」から「新しいターミナル」で開きます。

.NET SDK は 10 系が要ります。10.0.100 以上です。.NET 11 の SDK だけでは、この課題の `net10.0` は動きません。入手先は [.NET のダウンロード](https://dotnet.microsoft.com/ja-jp/download) です。

:::os windows
1. ダウンロードページで、Windows 向けの .NET SDK 10 を入手して、インストーラーを実行します。
2. 終わったら、VS Code のターミナル（PowerShell）で次を実行します。

```powershell
dotnet --version
```
:::

:::os macos
1. ダウンロードページで、macOS 向けの .NET SDK 10 を入手して、インストーラーを実行します。
2. 終わったら、VS Code のターミナルで次を実行します。

```sh
dotnet --version
```
:::

表示が `10.0.` で始まっていれば、このステージのテストを実行できます。

1 回で終わらない課題は、次の回に分けます。できるところの説明は短くして、課題を飛ばさないでください。
