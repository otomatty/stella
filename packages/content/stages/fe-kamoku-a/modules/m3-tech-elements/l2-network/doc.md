# レッスン3-2 ネットワーク

## このレッスンの目標

- [ ] LANとWANの違いを、範囲と管理の観点で説明できる
- [ ] プロトコル・IPアドレス・ポート番号の役割を区別して説明できる
- [ ] DNSがドメイン名をIPアドレスに変換する流れを説明できる

## 3-2-1 拠点の中はLAN、拠点の間はWAN

> **LANは拠点内のネットワーク、WANは拠点間を結ぶネットワーク**

機器どうしをつないでデータをやり取りする仕組みを **ネットワーク** と呼びます。会社のPCは、隣のプリンターとも海外のWebサイトともつながります。同じ「つながる」でも範囲がまるで違うので、範囲で呼び分けます。

- **LAN**(Local Area Network)— オフィスや工場など、1つの拠点の中のネットワーク
- **WAN**(Wide Area Network)— 離れた拠点どうしを結ぶネットワーク

| つながる範囲 | 種類 |
| --- | --- |
| 東京本社の中のPCとプリンター | LAN |
| 東京本社と大阪支社の間 | WAN |

管理のしかたも違います。LANは自社で構築して管理します。一方、拠点の間に自分でケーブルを引くことはできないので、WANは通信事業者の回線を借りて結びます。

そして、世界中のネットワークを相互につないだものが **インターネット** です。世界規模の巨大なWANと捉えると、用語の地図が1枚につながります。

## 3-2-2 プロトコルは通信の約束事

> **通信の手順を決めた約束事がプロトコルで、インターネットの標準はTCP/IP**

ケーブルや電波でつながっても、それだけで会話は成立しません。日本語しか話せない人と、フランス語しか話せない人の電話と同じです。機器どうしにも「共通の言語」にあたるものが要ります。

通信の手順や形式を決めた約束事を **プロトコル** と呼びます。プロトコルは、たとえば次のようなことを決めています。

- データをどんな形式で表すか
- どんな順番で送り、どう受け取ったと知らせるか

送る側と受け取る側の双方が同じプロトコルに従って、初めて通信が成立します。

インターネットの標準プロトコルが **TCP/IP** です。世界中のPCやスマートフォンはメーカーもOSもばらばらですが、全員がTCP/IPという「共通語」に従っているので通信できます。異なるメーカーの機器が相互接続できる理由として、試験でもよく問われます。

## 3-2-3 IPアドレスは機器の住所

> **IPアドレスは、ネットワーク上の機器を特定する番号**

ネットワークにはたくさんの機器がつながっています。データを届けるには「どの機器宛か」を指定する必要があります。住所のない手紙が届かないのと同じです。

ネットワーク上の機器を特定する番号が **IPアドレス** です。`192.168.1.10` のように数値で表し、通信では宛先の機器をIPアドレスで指定します。

| 機器 | IPアドレス |
| --- | --- |
| 自分のPC | 192.168.1.10 |
| 同僚のPC | 192.168.1.11 |
| 社内のプリンター | 192.168.1.20 |

住所と同じで、同じネットワークの中では番号の重複は許されません。重複したら宛先が定まらないからです。

IPアドレスには2種類あります。

| 種類 | 使う場所 | 一意の範囲 |
| --- | --- | --- |
| **グローバルIPアドレス** | インターネット | 世界で一意 |
| **プライベートIPアドレス** | 拠点の中 | その拠点の中だけ |

プライベートIPアドレスは拠点の中だけで通用する住所です。したがって、別々の会社がそれぞれの社内で同じプライベートIPアドレスを使っていても、問題は起きません。

## 3-2-4 ポート番号はアプリの窓口

> **ポート番号は、同じ機器の中のどのアプリに届けるかを区別する番号**

サーバー(サービスを提供する機器)1台に、Webとメールのアプリが同居することがあります。IPアドレスで特定できるのは「どの機器か」までなので、届いたデータをどちらのアプリに渡すかを決める番号が別に必要です。

それが **ポート番号** です。宛先は「IPアドレス + ポート番号」の組で指定します。

| 宛先 | 届く先 |
| --- | --- |
| 203.0.113.10 の 80番ポート | Webのアプリ(HTTP) |
| 203.0.113.10 の別の番号のポート | メールのアプリ |

**HTTP** は、Webページをやり取りするプロトコルです。HTTPの通信には80番ポートを使う、という対応だけまず覚えてください。

比喩で整理すると、IPアドレスが建物(機器)を特定する住所、ポート番号が建物の中の窓口(アプリ)の番号です。住所だけでは、どの窓口宛の用件か分かりません。

## 3-2-5 DNSは名前をIPアドレスに変換する

> **DNSは、ドメイン名とIPアドレスを対応づける仕組み**

通信の宛先指定はIPアドレスです。しかし番号の列は人間には覚えにくく、私たちは普段 `www.example.com` のような名前でサイトを開いています。

`example.com` のような、人が覚えやすい宛先の名前を **ドメイン名** と呼びます。そして、ドメイン名とIPアドレスを対応づける仕組みが **DNS**(Domain Name System)です。電話帳のように対応表を引いて、名前を番号に変換します。

ブラウザでサイトを開くとき、裏では次の流れが起きています。

```text
① 「www.example.com のIPアドレスは?」と DNS に問い合わせる
② 「192.0.2.10 です」と返ってくる
③ 192.0.2.10 宛に通信を始める
```

対応表にないドメイン名では相手にたどり着けません。一方、IPアドレスを直接指定すれば通信そのものはできます。名前でアクセスできるのはDNSに支えられているからだ、と押さえてください。
