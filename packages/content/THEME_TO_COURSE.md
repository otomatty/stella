# 外部テーマの教材化ガイド

外部で見つけたテーマ（公式ドキュメント、書籍、勉強会、資格シラバス、社内で繰り返し発生した質問など）を、
この LMS の教材として出すかどうかを判断し、出すなら要件をどう決めるかをまとめたものです。

**このファイルは「何を教材にするか」を決めるところまでを扱います。** 決まった後の置き場所・手順は
[ADDING_COURSE.md](ADDING_COURSE.md)、書き方は [STYLE_GUIDE.md](STYLE_GUIDE.md) が正本です。

| ドキュメント | 答えるもの |
| --- | --- |
| **THEME_TO_COURSE.md**（これ） | **そのテーマを教材にすべきか。教材の要件（目標・範囲・規模・評価）をどう決めるか** |
| [ADDING_COURSE.md](ADDING_COURSE.md) | どこにどのファイルを置くか。seed / R2 までの導入手順 |
| [STYLE_GUIDE.md](STYLE_GUIDE.md) | 文体・コード例・図解・スライド構成の書き方 |
| [CLAUDE.md](CLAUDE.md) | 粒度の定義、語彙台帳、コマンド、絶対に守るルール |

## 全体の流れ

```text
外部テーマ
   │
   ├─ STEP 1  適格性ゲート ────────► No-Go なら教材にしない（受け皿は §STEP 1）
   │
   ├─ STEP 2  要件定義シートを書く（目標・範囲・受講者・評価・出典）
   │
   ├─ STEP 3  規模を見積もる（トピック数 → レッスン → モジュール）
   │
   ├─ STEP 4  CURRICULUM.md に takeaway 一覧を書く ◄── ここまでがレビュー対象。本文はまだ書かない
   │
   ├─ STEP 5  実装（ADDING_COURSE.md へ）
   │
   └─ STEP 6  検査と受け入れ判定 → seed / R2 で配信
```

**STEP 4 までを先に通すことが、この流れの目的です。** takeaway 一覧が固まる前にスライドを書き始めると、
粒度の作り直しでほぼ全部が書き直しになります。

---

## STEP 0. テーマを持ち帰るときに記録すること

良さそうなテーマを見つけた時点で、次の 5 つだけメモしておきます。ここが空だと STEP 1 が判定できません。

| 記録 | 例 |
| --- | --- |
| 出典（URL / 書名 / 発表） | https://www.sqlite.org/lang.html |
| ライセンス・利用条件 | パブリックドメイン / CC BY-SA 4.0 / 転載不可 |
| 想定読者（原典側の） | DB 実装者向け（＝そのままでは未経験者に重い） |
| 良いと思った理由 | 現場で SELECT が書けず調査タスクが止まる場面が続いた |
| 困っている人 | 配属 3 ヶ月以内のメンバー、直近 4 名 |

## STEP 1. 適格性ゲート（Go / No-Go）

7 問すべてに答えます。**「いいえ」が 1 つでもあれば、そのままの形では教材にしません。**
形を変える（範囲を削る・1 レッスンだけ足す・教材以外の手段にする）か、いいえを解消してから進みます。

| # | 問い | いいえのときにまず疑うこと |
| --- | --- | --- |
| 1 | 受講者の**実務のどの場面**で効くか、1 文で言えるか | 「知っておくと良さそう」止まり。テーマではなく興味 |
| 2 | 前提知識が、想定受講者（未経験〜経験数ヶ月）の**現在地から届く**か | 前提講座が先に必要。順序の問題 |
| 3 | 内容を **takeaway 1 文のトピック**に割れるか（試しに 5 個書いてみる） | 割れないものは概念が大きすぎるか、手順書に近い |
| 4 | **1 年後も同じ内容で通用する**か | ツールのバージョン依存が強いものは改訂コストが乗り続ける |
| 5 | 原典を**転載せずに自分の言葉で書き直せる**か（§外部素材の扱い） | ライセンス上は可でも、書き直すと価値が消えるものは教材化しない |
| 6 | LMS の器（スライド / まとめ / 確認クイズ / コード演習）に**載る**か | 手を動かす環境が要るのに用意できない、など器の外 |
| 7 | 書く人と**改訂を続ける人**がいるか | 単発の情熱で 20 トピック書くと、次の改訂で止まる |

### No-Go のときの受け皿

教材にしない判断は失敗ではありません。次のどれかに落とすほうが合っている場合が多いです。

| 状況 | 落とし先 |
| --- | --- |
| 旬が短い / 一次情報を読めば済む | 社内共有（Slack・Wiki）。教材にしない |
| 内容は良いが分量が 3〜5 トピック | 既存講座の**1 レッスン追加**（[ADDING_COURSE.md](ADDING_COURSE.md) の B） |
| 手順書・環境構築の類 | README / 手順書。学習の単位にならない |
| 対象者が数名で固定 | 勉強会・ペア作業。LMS に載せない |
| 前提が重い | 前提講座を先に定義し、このテーマは後続としてバックログに置く |

## STEP 2. 教材要件を決める（要件定義シート）

Go になったら、**本文を書く前に**次を埋めます。埋まらない欄がある間は、まだ要件が決まっていません。

| 欄 | 決め方 | 落とし穴 |
| --- | --- | --- |
| 講座名 / slug | slug は英小文字ハイフン。**後から変えない**（コース UUID が変わり進捗が切れる） | 表示名とそろえようとして長くしない |
| 対象者 | 「未経験〜経験数ヶ月」だけでなく、**この講座を受ける直前の状態**を書く | 「全社員」は対象者ではない |
| 前提講座・前提知識 | 既存講座（`typescript-basics` など）で満たすものを指定 | 語彙台帳は**講座をまたがない**。前提語は自講座で導入し直す |
| 到達目標 | **観測可能な動詞**で 3〜5 個（書ける・直せる・選べる・説明できる） | 「理解する」「知っている」は測れないので使わない |
| スコープ外 | 扱わないものを**明示的に列挙**する | 書かないと際限なく広がる。SQL 入門は「ウィンドウ関数・トランザクション・INSERT/UPDATE/DELETE」を対象外と宣言している |
| 評価方法 | 確認クイズ（合格点 80 固定）／コード演習の有無 | コード演習は言語制約あり（下記） |
| 規模 | STEP 3 で算出したトピック数 | |
| 出典とライセンス | 原典・ライセンス・クレジットの置き場所 | クレジットは `CURRICULUM.md` に集約し、教材本文には書かない |

### 評価方法の選択肢は 3 つだけ

| 評価 | 実体 | 制約 |
| --- | --- | --- |
| 確認クイズ | `practice.md` の `## 確認クイズ` が LMS の quiz レッスンになる | 選択式 3〜5 問、選択肢 2 つ以上、**合格点は 80 固定**。設問ブロックの書式崩れは throw するが、**見出しが無い・設問が 1 問も無い場合は黙って quiz が作られない**（§STEP 6） |
| コード演習（自動採点） | `course.json` の `exercises` → VS Code 拡張で採点 | **`javascript` / `typescript` / `sql` のみ**（ランナーは QuickJS と sql.js だけ）。さらに **課題本体が `@falcon/shared` に実装済みであること**が前提（下記） |
| ハンズオン・演習問題 | `practice.md` 本文。手を動かす課題と解答例 | 自動採点されない。Assignment 化もされていない |

**ここが外部テーマの採否を左右します。** 例えば Python や Go をテーマにすると、スライド・まとめ・確認クイズは
そのまま作れますが、**コード演習の自動採点は作れません**。その場合は要件段階で「評価は確認クイズ＋手動演習」と
決め切ってください。後から採点を足そうとすると、ランナーの追加という別スコープの開発になります。

**`course.json` に ID を書くだけでは採点されません。** `exercises` の ID は `@falcon/shared` の `Assignment.id` を
指す参照で、manifest はその ID をコピーして `type: "code"` のレッスンを生やすだけです。課題本体（テスト・
スターターファイル）が `@falcon/shared` に無い場合、seed は `-- assignment ... not in shared — skipped` という
コメントを吐くだけで assignment 行を作らず、**LMS にはコード演習レッスンだけが残り、VS Code 拡張で開けません**。
既存の課題を再利用しないなら、**課題の実装は教材執筆とは別作業**として要件・工数に積んでください。

言語が対象内でも、**採点できる対象かどうか**は別問題です。HTML/CSS 入門は、見た目の自動採点が現時点の採点基盤に
無いため、コード演習を配線せず（`course.json` に `exercises` を持たない）、手を動かす部分を `practice.md` の
「手元で試す」に寄せています。**LMS 上はスライド → まとめ → 確認クイズだけで完走できる**ことを要件にした形です。
自動採点が作れないテーマは、この形を先に決めてしまえば教材として成立します。

### コピペ用シート

```markdown
## 教材要件シート — 【テーマ名】

- 講座名 / slug: 【Python 入門研修】 / 【python-basics】
- 新講座 or 既存講座への追加: 【新講座】
- 対象者（受講直前の状態）: 【】
- 前提講座 / 前提知識: 【】
- 到達目標（観測可能な動詞で 3〜5 個）
  - [ ] 【〜を書ける】
  - [ ] 【〜を選べる】
  - [ ] 【〜を直せる】
- スコープ外（扱わないもの）: 【】
- 評価方法: 確認クイズ【あり/なし】 / コード演習【あり(js|ts|sql)/なし】 / ハンズオン【あり/なし】
- 規模: 【N】モジュール / 【N】レッスン / 【N】トピック
- 出典: 【URL】（ライセンス: 【】）
- クレジットの置き場所: courses/<slug>/CURRICULUM.md
- 書く人 / 改訂する人: 【】
```

## STEP 3. 規模を見積もる

規模は「トピック数」で見積もります。トピックが動画 1 本・見積りの最小単位です。

| 層 | 定義 | 目安 |
| --- | --- | --- |
| モジュール | 大テーマ = LMS のセクション | 1 モジュール ＝ 1〜5 レッスン |
| レッスン | 1 回分。`doc.md` / `practice.md` の単位 | 3〜5 トピック |
| トピック | **覚えることが 1 つ**。ショート動画 1 本 | 2〜3 分 / **スライド 4〜6 枚（機械検査あり）** |

見積り手順:

1. 到達目標（3〜5 個）を、達成に必要な「覚えること」に分解して **takeaway を 1 文ずつ**書き出す
2. takeaway 1 文 = 1 トピック。**1 文で書けないものは 2 つに割る**（タイトルに「と」が入るのは分割のサイン）
3. 関連するトピックを 3〜5 個ずつ束ねてレッスンにする
4. レッスンを大テーマで束ねてモジュールにする

| 規模 | トピック数 | 形 | 実例 |
| --- | --- | --- | --- |
| ミニ | 3〜5 | 既存講座に**レッスン 1 本**追加 | — |
| 標準 | 20〜30 | 新講座（5〜6 モジュール） | SQL 入門: 6 モジュール / 6 レッスン / 24 トピック |
| 中 | 25〜75 | 新講座（5〜9 モジュール） | HTML/CSS 入門: 6 / 10 / 35、基本情報 科目B: 5 / 9 / 27、科目A: 9 / 17 / 72 |
| 大型 | 100+ | 新講座。フェーズを分けて着手 | TypeScript 入門: 10 / 42 / 162 |

**初回は標準規模（20〜30 トピック）に収めることを勧めます。** 大型は、完成しないまま放置される確率が最も高い形です。
分割できるなら「入門講座」を先に出し、続編を別 slug の講座にしてください。

## STEP 4. カリキュラムに落とす（レビューはここで受ける）

`courses/<slug>/CURRICULUM.md` に、**全トピックの ID・タイトル・takeaway の表**を書きます。
既存講座（[sql-basics](courses/sql-basics/CURRICULUM.md) / [html-css-basics](courses/html-css-basics/CURRICULUM.md) / [fe-kamoku-a](courses/fe-kamoku-a/CURRICULUM.md)）が実例です。

```markdown
# 【講座名】 カリキュラム

【1〜2 文で講座の狙い。軸になる考え方を書く】

- Web(LMS): スライド視聴・まとめ・確認クイズ(合格点 80)
- コード演習: 【あり(言語)/なし】
- 対象外: 【スコープ外をそのまま書く】

## 全体構成(N モジュール / N レッスン / N トピック)

### M1. 【モジュール名】 — レッスン1-1 【レッスン名】

| ID | トピック | takeaway |
| --- | --- | --- |
| 1-1-1 | 【トピック名】 | 【覚えることを1文で】 |

## クレジット(原典)

【原典・ライセンス。本文には書かない】
```

### 語彙の順序を同時に設計する

各トピックの `slides.md` front-matter が持つ `introduces` / `requires` は、機械検査で守られます
（`check_vocab.mjs`：学習順に並べて、前で `introduces` されていない語が `requires` にあればビルドを落とす）。

- **語彙台帳は講座ごとに独立**して検査されます。他講座で導入済みの語も、前提として使うなら**自講座で導入し直す**
- 未導入の語を使いたくなったら、語を足すのではなく**順序を見直す**。それは構成の問題です
- 台帳が見るのは宣言した依存だけです。**コード例に未導入の語を混ぜても検出されません**（目視で確認）

### ID とディレクトリの決め事

| 決め事 | 理由 |
| --- | --- |
| slug は変えない | コース UUID が変わり、受講者の進捗が切れる |
| トピック `id` は講座内で一意（`1-1-1` 形式） | 衝突するとビルドが落ちる。別講座なら再利用してよい |
| `id` の先頭 2 節がレッスンキー（`1-1-1` → `1-1`） | `doc-1-1` / `quiz-1-1` / `exercises` のキーがこれで決まる |
| **モジュール・レッスン・トピックの並びは辞書順** | `m10` は `m2` より前に来る。10 個以上並べるなら `m01` 形式など命名を先に決める |

## STEP 5. 実装

ここから先は [ADDING_COURSE.md](ADDING_COURSE.md) が正本です。最小の流れだけ再掲します。

```bash
mkdir -p packages/content/courses/<slug>/modules
cp packages/content/templates/course.json packages/content/courses/<slug>/course.json
# templates/topic-slides-template.md / doc-template.md / practice-template.md を配置してから本文を書く
bun run --filter=@falcon/content check:ci
bun run db:seed
bun run --filter=@falcon/content upload     # 図解を足したとき
```

- 1 レッスンにつき `doc.md` と `practice.md` は**必須**（無いと manifest が落ちます）
- 図解の正本は `assets/<名前>.html`、コミットするのは生成された `.svg`
- 図解 SVG は seed ではなく R2。本番は `upload:remote` を別途実行

## STEP 6. 受け入れ基準

### 機械が見るもの — どのコマンドが何を落とすか

検査は 2 か所に分かれています。**教材ファイルの検査（`check:ci` / `materials`）だけでは、クイズ書式や
`course.json` は検証されません。** manifest を組み立てる側（`bun run test` / seed）が落とします。

`bun run --filter=@falcon/content check:ci`（= `materials --check-only`）/ `materials`:

| 検査 | 落ちる条件 |
| --- | --- |
| スライド枚数 | `---` 区切りで 4〜6 枚から外れた |
| 語彙台帳 | 未導入語を `requires` に書いた / 同じ語を二重に `introduces` した |
| 画像リンク | `doc.md` / `practice.md` が存在しない画像を参照している |
| 図解（`materials` のみ） | skin 外のトークン、枠や viewBox からの文字はみ出し、スライドが参照する図解の不在 |

`bun run test`（`manifest.test.ts` が `buildContentManifest()` で `courses/` 全講座を組み立てる）/ `bun run db:seed`:

| 検査 | 落ちる条件 |
| --- | --- |
| front-matter | `id` / `title` / `takeaway` が無い |
| 確認クイズ書式 | `### Q1.` / `- A.` / `<details>` … `**B** — 解説` の形から外れた、選択肢が 1 つ以下 |
| `doc.md` / `practice.md` | レッスンディレクトリに存在しない |
| `course.json` | 無い、`title` が空、`color` が `indigo` / `green` / `amber` / `slate` 以外、`exercises` のキーに対応レッスンが無い |

### 機械が見ないもの（新講座では特に注意）

- **クイズが 0 問のレッスンは、黙って素通りします。** `parseQuiz` は「`## 確認クイズ` の見出しが無い / 綴りが違う」
  ときも、「見出しはあるが `### Q1.` の設問ブロックが 1 つも無い」ときも空配列を返し、manifest は quiz レッスンを
  作らないまま先へ進みます（throw するのは、設問ブロックがあってその中の書式が崩れている場合だけです）。
  「レッスン数ぶんクイズがあるか」を数えるテストは TypeScript 入門にハードコードされているため、**新講座では
  働きません**。見出しと設問は雛形から丸ごとコピーし、seed 後に LMS 上で全レッスンにクイズが出ることを
  目視で確認してください
- **`exercises` に書いた ID が `@falcon/shared` に無くても止まりません。** manifest が検査するのは「対応する
  レッスンがあるキーか」だけです。ID 自体が解決できない場合、seed は `-- assignment ... not in shared — skipped`
  を出して assignment 行を作らず、コード演習レッスンだけが LMS に残ります。**配線した演習は VS Code 拡張で
  実際に開いて解けることを確認してください**
- **コード例に混ざった未導入の語**（語彙台帳は宣言した `requires` しか見ません）

### 人が見るもの

- [ ] 到達目標が、確認クイズと演習で**実際に測れている**
- [ ] 各 takeaway が 1 文で、スライドの「結論」「まとめ」と一字一句そろっている
- [ ] スコープ外に書いたものが本文に紛れ込んでいない
- [ ] コード例に、そのトピックの takeaway と無関係な要素が無い（5 行以内が目安）
- [ ] 教材本文に原典名・クレジットが書かれていない（`doc.md` の「もっと知りたい人へ」のリンクは可）
- [ ] コース一覧に出て、セクション順がディレクトリ順と一致し、各レッスンがスライド → まとめ → 確認クイズの順

## 外部素材の扱い

**原典は「再設計の材料」であって、写す対象ではありません。** この方針は既存の全講座で一貫しています。

| ルール | 具体 |
| --- | --- |
| 翻訳・転載しない | 順序と粒度を対象者向けに設計し直し、文章は自分で書く |
| 問題は自作する | 基本情報の講座では、公式のサンプル問題・公開問題は**難易度と出題形式の校正基準としてのみ**使い、転載していない |
| クレジットは 1 か所に集約 | 講座の `CURRICULUM.md`（TypeScript 入門はリポジトリ README） |
| 教材本文に原典名を書かない | スライド・`doc.md` 本文・講師ノートに書かない。`doc.md` 末尾の参考リンクだけ例外 |
| 図・スクリーンショットを流用しない | 図解は `.claude/skills/diagram-design/` の規約に従って自作する |
| ライセンスを要件シートに残す | 後から確認できないと、公開範囲を広げるときに詰む |

判断に迷う典型例:

- **公式ドキュメントがパブリックドメイン**（SQLite）→ それでも構成を作り直す。コード例は業務っぽい題材に置き換える
- **CC BY-SA**（サバイバル TypeScript）→ 写しではないため教材本文にクレジットを入れず、README に集約
- **公的機関のシラバス**（IPA）→ 分類体系を「モジュール → レッスン」に写像するのは可。**問題文は自作**
- **書籍・有料教材** → 章立てをなぞらない。到達目標だけ参考にし、構成は自分で組む

## 新講座にするか、既存講座に足すか

| 条件 | 判断 |
| --- | --- |
| テーマが独立していて 10 トピック以上 | **新講座**（`courses/<slug>/`。既定の手順） |
| 既存講座の到達目標の一部で、3〜5 トピック | 既存講座に**レッスンを追加** |
| 既存講座の 1 トピックの補足 | トピックを追加。ただし既存トピックへの詰め込みは禁止（1 トピック = 1 takeaway） |
| 言語・題材が既存講座と違う | 新講座。語彙台帳は講座ごとなので、混ぜると前提が壊れる |
| 受講対象が違う（例: 資格対策 vs 実務入門） | 新講座。`category` を分けると一覧で見分けられる |

## よくある失敗

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| スライドが 7 枚を超える | 1 トピックに 2 つ以上の takeaway が入っている | トピックを割る。枚数を削って詰め込まない |
| 語彙台帳の検査が延々と落ちる | トピックの順序が要件段階で決まっていない | STEP 4 の takeaway 一覧に戻って並べ直す |
| クイズが「用語を覚えたか」だけになる | 到達目標が「理解する」で書かれている | 観測可能な動詞に書き換え、目標ごとに測る問題を作る |
| コード演習を作れないと後で気づく | 言語が js / ts / sql 以外 | 要件段階で評価方法を確定する（STEP 2） |
| 講座が完成しない | 初回から大型（100+ トピック）を狙った | 標準規模に切り、続編を別講座に分ける |
| seed 後に図解が表示されない | R2 へのアップロードはデプロイに含まれない | `upload` / `upload:remote` を実行する |
| 進捗が消えた | slug を変更した | slug は変えない。変えるなら移行を別途設計する |
