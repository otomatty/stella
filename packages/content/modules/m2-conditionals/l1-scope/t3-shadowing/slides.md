# 2-1-3
# 内側で同じ名前を宣言すると外が隠れる

TypeScript入門研修 — Module 2 / レッスン2-1

<!-- ノート: レッスン2-1の最後です。内と外に同じ名前があったときの挙動を1つだけ押さえます。デバッグで必ず効いてきます。 -->

---

## なぜ必要か

- 実務あるある: 値を書き換えたつもりが、外側は元のまま
- エラーが出ないので、原因にたどり着きにくい

<!-- ノート: つかみ。この現象を知らないと「代入したのに変わっていない」という不可解なバグに何時間も溶かす。知っていれば数秒で気づける。 -->

---

## 結論

**内側で同じ名前を宣言すると、そのブロックの中では外の変数が隠れる**

- この現象をシャドーイング(影で覆う)と呼ぶ
- 隠れるだけで、外の変数は変わっていない

<!-- ノート: 結論を先に言い切る。シャドーイングという言葉を定義する。「上書き」ではなく「別物が手前に立っている」というイメージが正しい。 -->

---

## 最小のコード

```ts
const status = "受付中";

{
  const status = "発送済み"; // 別の変数として作られる
  console.log(status); // => "発送済み"
}

console.log(status); // => "受付中" ← 変わっていない
```

<!-- ノート: 中と外で同じ名前だが、実体は別の変数。ブロックを抜けると外のものが再び見えるようになる。3つのconsole.logを順に指しながら、どちらのstatusを見ているかを確認する。 -->

---

## 対処: そもそも同じ名前にしない

- 内側の変数には、より具体的な名前を付ける
- 例: `status` と `newStatus`、`price` と `discountedPrice`

<!-- ノート: 対比枠。仕組みを覚えるより、起きない書き方を選ぶほうが安全。名前で意味を分けると、読む人にも意図が伝わる。1-3-4のis○○と同じく、命名で情報を伝えるという考え方。 -->
