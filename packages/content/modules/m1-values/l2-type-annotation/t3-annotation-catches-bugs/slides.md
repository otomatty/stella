# 型注釈が防いでくれるもの

TypeScript入門研修 — Module 1 / レッスン1-2

<!-- ノート: 型注釈の書き方はわかりました。ここでは、それを書くと具体的に何が起きるのかを1つだけ確認します。 -->

---

## なぜ必要か

- JavaScriptでは、間違った値を入れても実行するまで気づけない
- 気づくのは、たいてい本番でおかしな数字を見たとき

<!-- ノート: つかみ。バグに気づくタイミングが「実行時」から「書いている最中」に前倒しされる、というのがTypeScriptの中心的な価値。Module 0の話とここでつながる。 -->

---

## 結論

**型注釈があると、違う種類の値を入れた瞬間に実行前のエラーで気づける**

<!-- ノート: 結論を先に言い切る。「実行前」という言葉を強調する。エディター上で赤い波線が出るのは、まだ一度も動かしていない段階だという点が肝。 -->

---

## 最小のコード

```ts
let price: number = 300;
price = "無料";
// エラー: Type 'string' is not assignable to type 'number'.
```

- 「string型はnumber型に代入できません」という意味

<!-- ノート: assignableは「代入できる」という意味。エラーメッセージに出てくる2つの型名を読み取る練習をここで一度やる。前が入れようとした型、後ろが受け入れ側の型。 -->

---

## エラーメッセージの読み方

```
Type 'string' is not assignable to type 'number'.
     ^^^^^^                          ^^^^^^
     入れようとした型                 受け入れ側の型
```

<!-- ノート: 対比枠。エラーは怖くない、読めば原因が書いてある、と伝える。この形のメッセージは今後いちばん多く出会うので、ここで型の位置を体に入れてもらう。 -->

---
