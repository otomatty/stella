# 1-5-1
# リテラル型

TypeScript入門研修 — Module 1 / レッスン1-5

<!-- ノート: ここまで型は「値の種類」でした。レッスン1-5では、その考え方を一段細かくします。発想の転換が必要なので、ゆっくりいきます。 -->

---

## なぜ必要か

- 業務には「この3つの値しか取らない」項目が山ほどある
  - 例: タスクの状態は「未着手・進行中・完了」だけ
- `string`だと、どんな文字列でも入れられてしまう

<!-- ノート: つかみ。string型は自由すぎる。「完了」と書くべきところに「終わり」と書いても通ってしまう。この緩さを締めるのがリテラル型だと動機づける。 -->

---

## 結論

**値そのものを型にできる。その値しか代入できなくなる**

- これをリテラル型と呼ぶ
- リテラル = コードに直接書いた値そのもの

<!-- ノート: 結論を先に言い切る。「"done"という値の型」ではなく「"done"という型」。型の位置に値を書く、という見た目に最初は驚いてもらってよい。 -->

---

## 最小のコード

```ts
let status: "done" = "done";
status = "todo";
// エラー: Type '"todo"' is not assignable to type '"done"'.
```

- `"done"`という型には`"done"`しか入らない

<!-- ノート: 型注釈の位置にクォート付きの文字列が書いてあることを指して確認する。この時点では不便な型に見えるが、次のトピックで真価が出ると引きを作る。数値やtrue/falseもリテラル型にできると口頭で補足。 -->
