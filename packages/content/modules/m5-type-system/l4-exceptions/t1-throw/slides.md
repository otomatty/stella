# 5-4-1
# throwで異常を投げる

TypeScript入門研修 — Module 5 / レッスン5-4

<!-- ノート: レッスン5-4は例外処理です。5-3でunknownを学んだ直後に置いているのには理由があり、それは最後のトピックで分かります。 -->

---

## なぜ必要か

- 「割る数が0」のような、処理を続けられない状況がある
- 戻り値で異常を伝えると、呼び出し側が確認を忘れる

<!-- ノート: つかみ。-1を返す、nullを返すといった約束事もあるが、確認を忘れると異常な値がそのまま流れていく。強制的に止める仕組みが必要になる。 -->

---

## 結論

**`throw`は処理を中断し、呼び出し元まで異常を伝える**

- 例外 = 処理を続けられない状況
- `Error` = 例外の内容を表す組み込みの型

<!-- ノート: 結論を先に言い切る。例外とErrorを定義する。4-1-3のreturnも処理を終えるが、あちらは正常な出口。throwは非常口で、呼び出し元も巻き込んで止まる。 -->

---

## 最小のコード

```ts
const divide = (a: number, b: number): number => {
  if (b === 0) {
    throw new Error("0では割れません");
  }
  return a / b;
};

console.log(divide(10, 2)); // => 5
console.log(divide(10, 0)); // ここで処理が止まる
```

- `new Error("メッセージ")` で例外を作る

<!-- ノート: newは「新しく作る」という意味の命令で、Module 7のクラスで正式に扱う。いまは「Errorを作るときの決まり文句」として覚えればよい。3行目は実行されない。 -->

---

## returnとの違い

| | 呼び出し元 |
| --- | --- |
| `return` | 値を受け取って続行する |
| `throw` | **一緒に止まる** |

<!-- ノート: 対比枠。throwされると呼び出し元も止まり、さらにその呼び出し元へと伝わっていく。誰も受け止めなければプログラム全体が停止する。だから受け止める仕組みが要る。 -->
