# 6-1-3
# 型引数は推論される

TypeScript入門研修 — Module 6 / レッスン6-1

<!-- ノート: 前のトピックの呼び出しでは、型を1度も書きませんでした。なぜ動いたのかをここで説明します。 -->

---

## なぜ必要か

- ジェネリクスは「呼ぶときも型を書く」と誤解されやすい
- そう思い込むと、必要以上に難しく感じてしまう

<!-- ノート: つかみ。実は普段のコードでも、気づかないうちにジェネリクスを使っている。その事実を伝えると、心理的なハードルが下がる。 -->

---

## 結論

**型引数は渡した値から推論されるので、ふつうは書かなくてよい**

- 1-2-4で学んだ型推論が、型引数にも働く

<!-- ノート: 結論を先に言い切る。新しい仕組みではなく、既に学んだ型推論の適用範囲が広がっただけ。明示もできるが、実務ではほとんど書かない。 -->

---

## 最小のコード

```ts
const wrap = <T>(value: T): T[] => [value];

console.log(wrap<string>("コーヒー")); // 明示もできる
console.log(wrap("コーヒー")); // 推論に任せる(こちらが普通)
```

<!-- ノート: 2行は同じ結果。渡した値がstringなので、Tもstringだと決まる。1-2-5の「推論できるなら任せる」という方針が、ここでもそのまま適用される。 -->

---

## 実は、もう使っていた

```ts
const items = ["コーヒー", "紅茶"];
const upper = items.map((item) => `【${item}】`);
// map の型引数が string に推論されている
```

<!-- ノート: 対比枠。4-5-2で使ったmapはジェネリック関数。だからitemの型が分かり、戻り値もstring[]になっていた。3-1-1で触れたArray<number>という書き方も同じ仕組み。既に恩恵を受けていたと気づいてもらう。 -->
