## なぜ必要か

- `<T>` という記号が何を指しているのか分からないと、読み進められない
- Module 8の `Promise<string>` も、まったく同じ記法

<!-- ノート: つかみ。ジェネリクスを学ぶ最大の実利は、Promiseやユーティリティ型など「既に使われている山かっこ」が読めるようになること。 -->

---

## 結論

**関数名のうしろに`<T>`を書くと、`T`を型として使える**

```
const 関数名 = <T>(引数: T): T => { ... }
```

<!-- ノート: 結論を先に言い切る。この形の関数をジェネリック関数と呼ぶ。山かっこの中が「これから使う型の名前の宣言」。引数のかっこの手前に置く点を強調する。 -->

---

## 最小のコード

```ts
const wrap = <T>(value: T): T[] => [value];

console.log(wrap("コーヒー")); // => ["コーヒー"]
console.log(wrap(480)); // => [480]
```

- 呼び出しごとに`T`が`string`や`number`に決まる

<!-- ノート: 値を配列に包むだけの関数。1回目のTはstring、2回目はnumber。同じ関数なのに、呼び出しごとに型が変わる。名前はTでなくてもよい(要素ならItemなど)が、慣習としてTが多い。 -->
