# レッスン9-1 ローカル環境

## このレッスンの目標

- [ ] Node.jsを導入し、ターミナルで確認できる
- [ ] VS Codeで型のチェックを見られる
- [ ] `tsc`でコンパイルし、生成された`.js`を実行できる

## 9-1-1 Node.js

> **Node.jsは、ブラウザの外でJavaScriptを動かすための実行環境**

Playgroundは1ファイルしか扱えませんが、実務のプロジェクトは何十何百というファイルでできています。レッスン0-2で「環境構築は後回し」と決めたのは、言語の学習に集中してもらうためでした。ここまで来たので、道具を揃えます。

- **ターミナル** — 文字でコンピューターに命令する画面
- **npm** — 部品を導入するための道具(Node.jsに同梱)

JavaScriptはもともとブラウザ専用でしたが、Node.jsの登場で外でも動くようになりました。TypeScriptのコンパイラー自体もNode.jsの上で動きます。

公式サイトからLTS版(Long Term Support = 長く保守される安定版)をインストールし、ターミナルで確認します。

```bash
node -v
npm -v
```

両方バージョンが表示されれば成功です。数字そのものは環境によって違うので気にしなくて構いません。

**よくあるつまずきは、インストール後にターミナルを開き直していないことです。** 「command not found」は、まだ認識されていないだけのことが多くあります。

## 9-1-2 VS Code

> **VS Codeは、型のチェック結果をその場で見せてくれるエディター**

メモ帳でも書けますが、型のチェックが見えません。レッスン0-2で学んだ「赤い波線を読む」が手元でできないと、学習効率が落ちます。

**エディター**とはコードを書くための専用ソフトです。VS CodeにはTypeScriptの機能が最初から組み込まれています(どちらもMicrosoft製で相性がよく、無料で使えます)。

最初に確認することは2つです。

- ファイルを保存すると、型エラーに赤い波線が出る
- 変数にマウスカーソルを乗せると、推論された型が表示される

Playgroundでやっていた確認が、そのまま手元でできます。特に**カーソルを乗せて型を見る操作**は、学習でも実務でも最も使う機能です。

補完も強力になります。ドットを打つと使えるプロパティやメソッドの候補が出ます。型が分かっているから候補も正確で、タイポが減ります。0-1-2で「型があると入力補完が効く」と話した、その実演です。

## 9-1-3 tscでコンパイルする

> **`tsc`はTypeScriptをJavaScriptに変換するコマンド**

レッスン0-1で学んだ「TypeScriptはJavaScriptに変換されてから動く」を、自分の手で実行します。

`tsc`は TypeScript Compiler の略で、0-1-2で定義した「コンパイラー」の実体です。

```bash
npm install --save-dev typescript
npx tsc index.ts
```

`index.ts`から`index.js`が作られます。中身を開くと、**型注釈が消えている**ことを確認できます(`npx`はインストールしたコマンドを実行する命令です)。

```bash
node index.js
```

変換後のJavaScriptを、Node.jsで動かします。

**書く(.ts) → 変換する(tsc) → 動かす(node)** という3ステップです。Playgroundでは1つのボタンに隠れていた流れが、手元では明示的になります。

毎回2つのコマンドを打つのは面倒なので、実務では設定ファイルで簡略化します。それが次のレッスン以降の話です。
