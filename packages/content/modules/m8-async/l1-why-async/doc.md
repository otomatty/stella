# レッスン8-1 なぜ非同期処理が必要か

## このレッスンの目標

- [ ] シングルスレッドという前提を説明できる
- [ ] `setTimeout`で非同期処理を書ける
- [ ] 実行順序を予想でき、コールバック地獄の問題を説明できる

## 8-1-1 JavaScriptはシングルスレッド

> **JavaScriptは一度に1つの処理しかできない。だから待つと全部止まる**

通信やファイル読み込みは、結果が返るまで時間がかかります。待っている間に画面が固まると、使い物になりません。

- **シングルスレッド** — 処理の担当者が1人だけ
- **同期処理** — 上から順に、1つずつ終わらせていく実行の仕方

ワンオペのカフェを思い浮かべてください。店員が1人しかいないので、豆を挽いている間は注文も受けられません。

```ts
const heavy = (): void => {
  // 3秒かかる処理だと思ってください
};

console.log("A");
heavy();
console.log("B"); // heavyが終わるまで表示されない
```

Module 7までに書いてきたコードは、すべて同期処理です。単純で分かりやすい一方、時間のかかる処理が混ざると全体が止まります。

![同期処理と非同期処理の対比図](t1-single-thread/assets/sync-vs-async.svg)

担当者が1人という前提は変わりません。変わるのは**待ち時間に他の仕事をするかどうか**です。

## 8-1-2 setTimeoutで後回しにする

> **非同期処理は、時間のかかる仕事を後回しにして先に進む**

カフェのたとえなら、豆を挽く機械にセットしてから次の注文を受けます。機械が仕事をしている間、店員は空いています。

```ts
setTimeout(() => {
  console.log("3秒たちました");
}, 3000);

console.log("先に進みます");
```

`setTimeout(関数, ミリ秒)`で「あとで実行して」と予約します。第1引数はレッスン4-5で学んだコールバックで、渡した関数が指定時間後に呼び返されます。

**`setTimeout`は予約するだけで、すぐ次へ進みます。** 8-1-1の`heavy()`は終わるまで戻ってこなかったのに対し、`setTimeout`は即座に戻ってきます。この違いが同期と非同期の分かれ目です。

## 8-1-3 実行順序は書いた順ではない

> **非同期処理は、同期処理がすべて終わったあとに実行される**

上から順に読む癖のまま非同期のコードを読むと、必ず誤読します。

```ts
console.log("1");

setTimeout(() => {
  console.log("2");
}, 0); // 0ミリ秒でも後回し

console.log("3");
// => 1
// => 3
// => 2
```

**待ち時間が0でも、順番は変わりません。** 予約された処理は「いま動いている仕事が全部片づいてから」実行されます。担当者が1人なので、手が空くまで着手できないためです。

![予約された処理が列の最後に並ぶことを示す図](t3-execution-order/assets/settimeout-timeline.svg)

この仕組みを「イベントループ」と呼びますが、名前は覚えなくて構いません。**「後回しにされる」という結果だけ**押さえてください。

## 8-1-4 コールバック地獄

> **非同期処理をコールバックでつなぐと、入れ子が深くなって読めなくなる**

実務では「取得してから、加工して、保存する」と順番に進めたいものです。しかし非同期処理は待たないので、素直に並べても順番になりません。順番を保証するには、前の処理の中に次を書くしかありません。

```ts
setTimeout(() => {
  console.log("1件目を取得");
  setTimeout(() => {
    console.log("2件目を取得");
    setTimeout(() => {
      console.log("3件目を取得");
    }, 1000);
  }, 1000);
}, 1000);
```

3段でこれです。5段になると手に負えません。しかもエラー処理を足すと、それぞれの段に書くことになってさらに膨らみます。この状態を**コールバック地獄**と呼びます。

![入れ子の書き方とチェーンの書き方を比べた図](t4-callback-hell/assets/callback-vs-chain.svg)

同じ処理が縦に並ぶだけで、読みやすさがまったく違います。この右側の形を実現するのが、次のレッスンで学ぶ`Promise`です。
