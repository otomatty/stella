# レッスン8-1 演習 — なぜ非同期処理が必要か

対象トピック: 8-1-1 〜 8-1-4

## ハンズオン

[TypeScript Playground](https://www.typescriptlang.org/ja/play) を開いて、次のコードを写経してください。

```ts
console.log("1");

setTimeout(() => {
  console.log("2");
}, 0);

setTimeout(() => {
  console.log("3");
}, 1000);

console.log("4");
```

**実行する前に、出力される順序を予想してください。** 予想できたら「Run」を押して答え合わせをしましょう。

写経できたら、次の改造をしてみましょう。

1. 2つ目の`setTimeout`の待ち時間を`0`に変えて、順序がどうなるか確認しましょう
2. `setTimeout`のかっこの中を`() => console.log("2")`と1行にしても動くことを確認しましょう
3. `setTimeout`を3段に入れ子にして、「1件目」「2件目」「3件目」を1秒ずつ表示してみましょう

## 演習問題

### 問1(基本)

次のコードの出力順序を予想し、理由を説明してください。

```ts
console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
```

### 問2(基本)

1秒後に「準備完了」と表示するコードを`setTimeout`で書いてください。あわせて、予約した直後に「準備中です」と表示してください。

### 問3(応用)

次のコードは、3つの処理を1秒ずつ順番に実行したいものです。書いてみたうえで、この書き方の問題点を2つ挙げてください。

- 1秒後に「注文を受付」
- そのさらに1秒後に「調理開始」
- そのさらに1秒後に「提供完了」

## 解答例と解説

<details>
<summary>問1の解答例</summary>

```
A
C
B
```

`setTimeout`は待ち時間が`0`でも、予約するだけで即座に次の行へ進みます。予約された処理は、**同期処理がすべて終わったあと**に実行されます。

JavaScriptはシングルスレッド(担当者が1人)なので、いま動いている仕事が片づくまで、予約された処理には着手できません。

</details>

<details>
<summary>問2の解答例</summary>

```ts
setTimeout(() => {
  console.log("準備完了");
}, 1000);

console.log("準備中です");
// => "準備中です"
// (1秒後) => "準備完了"
```

`setTimeout`は予約するだけなので、「準備中です」が先に表示されます。この「待たない」性質のおかげで、画面が固まりません。

</details>

<details>
<summary>問3の解答例</summary>

```ts
setTimeout(() => {
  console.log("注文を受付");
  setTimeout(() => {
    console.log("調理開始");
    setTimeout(() => {
      console.log("提供完了");
    }, 1000);
  }, 1000);
}, 1000);
```

問題点は次の2つです。

1. **入れ子が深くなる** — 処理が増えるほど右へずれていき、中かっこの対応を追うのが困難になります(コールバック地獄)
2. **エラー処理が書きにくい** — 失敗したときの処理を、それぞれの段に個別に書くことになり、さらに膨らみます

順番を保証するには「前の処理の中に次を書く」しかないため、この形を避けられません。これを解決するのが次のレッスンの`Promise`です。

</details>

## 確認クイズ

### Q1. JavaScriptが一度に実行できる処理はいくつですか?

- A. 1つ
- B. 2つ
- C. 制限なし

<details>
<summary>答え</summary>

**A** — シングルスレッドなので、担当者は1人だけです。この前提は非同期処理を使っても変わりません。

</details>

### Q2. `setTimeout(fn, 0)` はどのタイミングで`fn`を実行しますか?

- A. すぐその場で
- B. 同期処理がすべて終わったあと
- C. 実行されない

<details>
<summary>答え</summary>

**B** — 待ち時間が0でも「後回し」です。手が空いてから着手されます。

</details>

### Q3. コールバック地獄の問題点はどれですか?

- A. 動作が遅くなる
- B. 入れ子が深くなり、読みにくくエラー処理も書きにくい
- C. 型が付かない

<details>
<summary>答え</summary>

**B** — 動作自体は正しく動きます。問題は書きやすさ・読みやすさです。

</details>
