## なぜ必要か

- ここまで`items.length`や`items.push`を「そういうもの」として使ってきた
- 同じ書き方だと分かると、覚えることが1つ減る

<!-- ノート: つかみ。3-1-3のlengthと3-2-1のpushは、実は配列というオブジェクトのプロパティ。既に使っていたものに名前が付く体験は理解が定着しやすい。 -->

---

## 結論

**プロパティはドットに続けて名前を書くと読み書きできる**

<!-- ノート: 結論を先に言い切る。この書き方をドット記法と呼ぶ。読むときも書き換えるときも同じ形。3-1-2の配列は角かっこと番号、オブジェクトはドットと名前、と対比すると覚えやすい。 -->

---

## 最小のコード

```ts
const user = { name: "田中", age: 28 };

console.log(user.name); // => "田中"

user.age = 29; // 書き換え
console.log(user.age); // => 29
```

<!-- ノート: 読み取りと書き換えの2つを見せる。3-2-2で学んだとおり、constでもプロパティの書き換えはできる。変数そのものを差し替えるのが禁止されているだけ。 -->

---

## よくある間違い: 存在しないプロパティ

```ts
const user = { name: "田中", age: 28 };

console.log(user.nama);
// エラー: Property 'nama' does not exist on
// type '{ name: string; age: number; }'.
```

- 打ち間違いを実行前に止めてくれる

<!-- ノート: 対比枠。JavaScriptならundefinedが返るだけでエラーにならない。TypeScriptはプロパティ名のタイポを実行前に検出する。0-1-1で見た「気づくのが遅いバグ」がここでも潰せる。 -->
