# constの配列でも中身は変えられる

TypeScript入門研修 — Module 3 / レッスン3-2

<!-- ノート: 前のトピックで気づいた人がいるはずです。constで宣言したのに、中身が変わっていました。ここを1つだけ整理します。 -->

---

## なぜ必要か

- `const`は再代入できないはずなのに、`push`は通ってしまった
- ここを曖昧にしたまま進むと、`const`の意味を取り違える

<!-- ノート: つかみ。素朴な疑問をそのまま拾う。ここを説明せずに進むと「constは信用できない」という誤った印象が残る。 -->

---

## 結論

**`const`が禁じるのは変数への再代入だけ。配列の中身は変えられる**

- 変数が指している「配列そのもの」を差し替えるのは禁止
- その配列の中を書き換えるのは自由

<!-- ノート: 結論を先に言い切る。「名札を貼り替えてはいけないが、箱の中身は入れ替えてよい」というイメージで伝える。1-1-2のconstの定義は変わっていない。 -->

---

## 最小のコード

```ts
const items = ["コーヒー"];

items.push("紅茶"); // OK(中身を変えている)

items = ["緑茶"];
// エラー: Cannot assign to 'items' because it is a constant.
```

<!-- ノート: pushは通り、代入は弾かれる。この2行の対比が今回のすべて。エラーメッセージは1-1-2で見たものとまったく同じであることも指摘すると、理解がつながる。 -->
